- **viola-core:**
  - `viola_core::is_code_word` accepts 1 to 64 bytes of `[a-z0-9-]` with a lower-case letter first, held by `code_word_literal_table` (`crates/viola-core/src/lib.rs`).
  - `viola_core::UnreachableCause` holds `StrictModes`, `InstanceDead`, `UnwrappedName`, `EndpointLost` and `ServerVerify` and has no serde path; `unreachable_cause_is_each_its_own_code_word` holds its words (`crates/viola-core/src/lib.rs`).
- **viola-channel:**
  - ndjson frame codec at `MAX_FRAME` − 1, `MAX_FRAME` and `MAX_FRAME` + 1.
  - JSON-RPC error mapping: -32700 / -32600 / -32601 / -32602 with `data:{supported,wrapper}` / -32603 with the exact `"internal error"` and `data:null`.
  - The fault screen `viola_channel::sanitised_fault` (`crates/viola-channel/src/lib.rs`): `sanitised_fault_keeps_each_wire_body`, `sanitised_fault_carries_nothing_of_the_peer_but_closed_values`, `sanitised_fault_keeps_a_wrapper_of_sixty_four_version_characters` and `sanitised_fault_without_an_integer_code_is_nothing`.
  - A fault code outside the five reads `{"code": <code>, "message": "wrapper fault", "data": null}` on `--json` and MCP, held by `sanitised_fault_carries_nothing_of_the_peer_but_closed_values`; the human line reads `error: wrapper fault  <code>` (`src/human/mirror.rs`).
  - `ProtocolError::cause` tells the three `-32602` faults apart and is `None` for the other four: `protocol_error_cause_tells_the_three_invalid_params_apart` (`crates/viola-channel/src/lib.rs`), `answer_invalid_params_names_its_cause_and_no_param` and `answer_faults_other_than_invalid_params_carry_no_detail` (`crates/viola-channel/src/server.rs`) and `reply_from_logs_the_cause_of_each_invalid_params`.
  - FNV-1a endpoint golden vectors: `viola-<12 hex>` of `ViolaName + "\0" + abs home`, with the Windows `\\.\pipe\` form and the Unix per-user 0700 directory forms `$XDG_RUNTIME_DIR/viola/viola-<h12>.sock` (Linux) and `$TMPDIR/viola/viola-<h12>.sock` (macOS), plus the `/tmp/viola-<uid>/viola-<h12>.sock` fallback (security IPC access control, Unix).
  - The peer-credential decision function with injected `(peer_euid, own_euid)`, covering the cross-user rejection boundary from test-scope Sec 1.
  - `#[cfg(windows)]` handle non-inheritance, which backs E2 and the §12 open question. After the `viola-channel` server creates a pipe instance and a client connects, `GetHandleInformation` (windows-sys) on both handles (via `AsRawHandle`) reports `HANDLE_FLAG_INHERIT` clear. This is the only Windows evidence; there is no child-side probe.
  - The connected stream's server pid, `Client::server_pid` and `TokioClient::server_pid` (`peer_creds().pid()`: Linux `SO_PEERCRED`, Windows `GetNamedPipeServerProcessId` on the SQOS-adopted client end, macOS none), asserted on each OS by `client_server_pid_is_the_serving_process` and `client_server_pid_is_none_where_peer_credentials_hold_no_pid` (`crates/viola-channel/src/client.rs`) and their Tokio twins `tokio_client_server_pid_is_the_serving_process` and `tokio_client_server_pid_is_none_where_peer_credentials_hold_no_pid` (`tokio_client.rs`, behind the `tokio` feature); `SERVER_PID_REPORTED` is false on macOS.
- **viola-state:**
  - The ndjson writer does one `write` per line.
  - The reader counts and never panics. `torn_lines`: an over-long line (> `MAX_FRAME`), a terminated line that is not one JSON object, and the unterminated last line of the read, which it neither returns nor rewrites. `unknown_kinds`: a line whose `kind` is absent, not a string or not a known kind; it is not returned. `unknown_fields`: once per line, a known-kind line with a top-level key outside the six or a `data` key outside its kind's list; it is returned (unit cases `three_counts`).
  - The heal is the appender's. An append to a log whose last byte is not LF writes one LF and its line in a single write; `append_event_at` hands its builder and returns the line's real start (L + 1 after a heal, L otherwise); `try_append_event` with the lock held writes and heals nothing; one `state-recovered` line is logged per heal and none without one (unit cases `torn_tail`, the lines read in memory through the crate's `#[cfg(test)]` capture).
  - Snapshot envelope: the classified read tells the snapshot, no file, an unreadable one and an unsupported `v` apart, reading `v` first; an unsupported `v` or a parse failure goes to replay through the read-or-replay function, which logs one `state-recovered` line for each and none for a present or an absent snapshot (unit cases `snapshot_cause`, `replay_recovers`). `viola revive` is the read-or-replay function's first product caller and `viola list`'s `board::read` its second (chunk 2026-10-11-the-board-viola-list, read in `tests/cli_list.rs` `e5_list_reads_a_live_wrapper_through_the_replay`) (revive's in its second preflight reading, the logged session, of four since chunk 2026-10-16-unwrapped-sessions-on-the-board added `session-live` (the strict-modes check ahead of the preflight since chunk 2026-10-10-budget-governor); the one `state-recovered` line on the replay arm is read in `tests/cli_revive.rs`). The four other snapshot readers call it too: `run`'s collision check (it takes the caller's one read, and over a replayed snapshot liveness is the beat alone), `src/cmd/hook.rs` `connect`, its event and dialog paths sharing the one read (a replayed or absent snapshot is `channel-unreachable`, fail open), `src/cmd/hook/statusline.rs` `serve` (a replayed snapshot holds no `statusline_command`) and `viola_state::liveness::live_endpoint` (its reading below), through which the CLI frame verbs and the MCP frame tools read the snapshot, its one read feeding the server check; `revive`'s preflight reads once for both its collision check and its recorded-directory reading. No product reader is left on `read_snapshot` (the rule: `read_snapshot(` under `src/`, outside test modules).
  - The replayed readers' unit cases: `live_endpoint_of_a_replayed_snapshot_is_none_with_its_one_line` (`crates/viola-state/src/liveness.rs`), `connect_over_a_replayed_snapshot_is_unreachable` (`src/cmd/hook.rs`), `statusline_over_a_replayed_snapshot_runs_nothing` (`src/cmd/hook/statusline.rs`) and `collision_check_over_a_replayed_snapshot_reads_the_beat_alone` (`src/cmd/run.rs`).
  - Replay recovers exactly `links`, `agent_session_id`, `wheel`, `budget_paused`, `budget_override_until`, with `dialog_pending:false`. As landed, a field no line gave is absent and the replay writes no file. Since chunk 2026-10-10-session-links the replay derives `links` in its one pass through the public rule `viola_state::replay::apply_link_line`: a `link` line whose `data.driver` and `data.driven` are strings adds `{driver, driven, since}` with `since` that line's `ts` unless the set holds the pair, an `unlink` line removes the pair, and any other line changes nothing (inline cases `link_rule_*`). A `link` line with no string `ts` gets `since: "unknown"`: no input worded that shape, it stands on the operator's word and the founder has not ruled on it.
  - The liveness classifier (live / stale / gone) is the pure `classify(beat_age, same_process)`, fed ages directly (no clock): a pid that is dead or carries another start time is `gone` at any age; for the same process 4.9 s and 5.0 s are live, 5.1 s and an absent beat `stale`; `same_process` compares the snapshot's `started_at` with the pid's OS start time.
  - The server check: `ServerVerdict { Matches, Mismatch, Unverifiable }` from the pure `server_verdict(recorded_pid, started_at, observed_pid, observed_start, peer_pid_reported)`, pinned by the decision table `server_verdict_rows`; where no peer pid is reported (`peer_pid_reported` false, macOS) the verdict is `Matches` with no comparison, the recorded gap. `verify_server_reads_the_observed_start_time_from_the_os` covers the joined `verify_server`'s read of the observed start time from the OS (`process_start_time`, none for a zombie). `live_endpoint` returns `LiveEndpoint { endpoint, pid, started_at }`, all from its one `read_snapshot_or_replay` call: only a present snapshot proceeds, and a replayed or absent snapshot or a read error is `None`, since a replayed snapshot carries no `endpoint`, `pid` or `started_at`.
  - `viola_state::liveness::without_endpoint(instance_dir)` (`crates/viola-state/src/liveness.rs`) reads by `symlink_metadata` a directory as `InstanceDead` and anything else (absent, a regular file, a symlink) as `UnwrappedName`, opening nothing and writing no line; `without_endpoint_maps_the_directory_reading` (`src/cmd/client.rs`) holds the client's mapping of that reading.
  - Strict-modes has two rules, the write rule and the read rule, which holds the content-bearing paths the instance check names below: `unix_read_verdict(mode, uid, euid)` is the write rule plus a refusal of `mode & 0o077` (`unix_read_verdict_needs_the_write_rule_and_no_foreign_bit`), and `windows_read_verdict` is the write rule plus a refusal of any allow ACE granting a right in `READ_RIGHTS` (`0x9000_0001`: `FILE_READ_DATA` | `GENERIC_READ` | `GENERIC_ALL`) to an untrusted SID, inherit-only ACEs included (`windows_read_verdict_refuses_any_read_right_to_another_sid`, `windows_read_verdict_takes_the_trusted_sids_and_keeps_the_write_rule`, and the `cfg(windows)` `read_rights_are_the_named_flags`).
