### Test data bootstrap

- **Strategy:** self-bootstrapping (no developer-seeded data)
- **Mechanism:**
  - a tempfile 3.27.0 home per test or session
  - rstest 0.27.0 `#[fixture]` chain `home → fake_agent_path → stamped_home → booted_wrapper`
  - fake-agent replay of `fixtures/claude/<cli-version>/`
  - `viola verify --home <home>` against the fake agent for stamps
  - generated statusline stdin piped into `viola hook statusline` for `budget.json`
  - proptest 1.11.0 strategies with committed `proptest-regressions/` seeds for randomized inputs
  - Windows x64, root tests only: `tests/support/home.rs` `seed_conpty(home)` places the two ConPTY companions under `<home>/bin/<key>/conpty/` from the per-run `target/conpty-seed/<key>/` copy before the test's `viola run` (the §5 carve-out); the harness `boot`, `run_viola_unseeded` starts and `tests/conpty_sideload.rs` never seed
  - `tests/support/home.rs` `TestHome::outside_scan()`: a home under the system temp dir (`viola-chaos-*`), used only by `tests/chaos_feed_panic.rs` (the §5 second carve-out, the founder's ruling, live, 2026-10-04, relayed by the overseer)
  - `tests/support/home.rs` `prepare_home_base(base)`, called from `TestHome::new`, prepares the root chain's base `target/e2e-home` before the `tempdir_in`, under the contract of the harness keeper `Workspace::ensure_e2e_home` (`boot` step 2): a plain base is created as a directory; on Unix a linked base needs an absolute target, which is made with mode 0700 when it is gone and accepted only when one `lstat` reads a real, owner-only directory; on Windows it is the plain create. A refusal panics with a fixed message that names the failed check and no path. On the Linux dev host the base is an operator-set link to `/tmp/viola-e2e-home-<uid>` (0700, tmpfs), an environment fact outside harness code; the path string is unchanged, and `viola` is given a `--home` under the link and resolves nothing
- **Per-test isolation:**
  - Every test gets a fresh home, so no endpoint, log or `budget.json` is shared: the FNV-1a endpoint hash includes the absolute home path.
  - The few tests touching the default port 47319 run in the nextest test group `fixed-port` (`max-threads = 1`).
- **Cleanup:** a root `TestHome` removes its home on drop through `tests/support/home.rs` `remove_owned`, which deletes the `owner.json` record last: std's `remove_dir_all` stops at the first entry it cannot delete, in listing order, so a removal that stops part-way (a file another process still holds) keeps the record, and a later sweep can still take the dir. A test the runner kills (nextest's slow-timeout kill, or a mutant that kills the test process; the `mutants` profile's `terminate = "wait"` lets every other running test finish) never drops its home, so every root `TestHome` records `owner.json` `{pid, started_at}` beside it, and a new `TestHome`, when no `AGENT_RUN_KEEP_*` is set, first removes, through the same `remove_owned`, only the dirs whose recorded owner process is gone (pid dead, or alive with another start time) — never by age or name, never a dir without a record; a kept home drops its record. Ownerless remnants still appear on runs that fail at the D: dev volume's deadlines, as measured at chunk 2026-10-02-epoch-2b-cleanup `evidence/leaks.md` (0–3 per run, none on a C: copy); their mechanism is recorded, not established (M2, open). Harness sessions are cleared by `cleanup`. A failing root test keeps its home only when `AGENT_RUN_KEEP_FAILED=1`, so that `logs` can inspect the home. viola-e2e's booted lifecycle tests (`crates/viola-e2e/tests/harness_lifecycle.rs`) hold a `Booted` guard instead: on drop, even after a failed assertion, it runs `cleanup(.., keep_homes = true)` (every recorded process stopped, the home kept; the tests' own cleanup calls assert `home_removed:"kept"`) and then removes the home unless `AGENT_RUN_KEEP_FAILED=1` and the thread is panicking — `AGENT_RUN_KEEP_HOMES` is not read there, so a passing test's home is always removed. In CI, `AGENT_RUN_KEEP_HOMES=1` (set by `ci.yml`, overridden to `0` under `run --mutants`) keeps every rstest home, passing or failing, and makes harness `cleanup` keep its home (§3 `cleanup` step 6). The homes then stay under `target/e2e-home/` until obs-plan's G2, G4, secret scan and scan-gated uploads have run; the one `outside_scan()` chaos home is outside those scans by design. On the Linux dev host, through the `target/e2e-home` link, a `TestHome`'s drop and the owner sweep delete outside the working directory, in `/tmp/viola-e2e-home-<uid>`, still only dirs the test side itself created (by `owner.json` record, by its own `TempDir`); the widening is ratified by the founder (live, 2026-10-07T07:25Z, relayed by the overseer). A home kept there (`AGENT_RUN_KEEP_FAILED=1`, `AGENT_RUN_KEEP_HOMES=1`) is on tmpfs: it does not survive a reboot, and `/tmp` ages out what is untouched for ten days, so `logs` can inspect it only until then. After a reboot the link's target is gone and the next start makes it again (the keepers). After `cargo clean` the link is gone and the next start puts a plain directory on the shared volume with no signal: `test -L target/e2e-home && findmnt -n -o FSTYPE -T target/e2e-home/` reads it, and one `ln -s` restores it.
