## Surface: cli

**Tooling context:** Rust stable with clap 4.6.7 (derive). TTY detection uses std `IsTerminal`. Windows VT output is enabled with windows-sys 0.61.2 `SetConsoleMode`, and colour is off if that fails. Styling is a small hand-written SGR module in the `viola` bin, with no colour or table crate. Columns are padded to fixed widths by that same module.

**Token names on this surface:**

| Token name | cli rendering |
|---|---|
| `color-accent` | The design system's attention SGR token (truecolor / 256 / 16-colour fallback row). Only on the `DIALOG` word, always followed by the uncoloured kind word |
| `color-text-muted` | The `stale` token: SGR dim across a whole `stale` row, and never without the word `stale` in LIVE |
| Callsign role | The callsign token: SGR bold on NAME values only |
| `color-text-primary` / `color-text-secondary` | The terminal's default foreground. The terminal owns ink |
| `color-role-handoff` | Not used. Link output is plain |
| `color-surface-*` | Never set. The terminal background belongs to the user |
| Label role | Uppercase column captions (`NAME LIVE STATUS WHEEL DIALOG CLI`) and group labels, plain |
| Data role | Tabular figures and timestamps |
| `space-xs` equivalent | The column gutter: two spaces on the terminal grid. Inside one field, ` - ` is the separator |
| `radius-*` | No terminal analogue. Square brackets `[ ]` keep the ruled-rectangle reading |
| Motion tokens | None. Nothing redraws in place |
One token vocabulary (`color-*`, `space-*`, `radius-*`, the typography roles) resolves on the cli to the SGR tokens, the terminal default foreground or "not used". Its platform mechanics are ANSI depth, the two-space gutter, ASCII `->` / ` - `, and brackets for the ruled box.

**Expression level (this surface):** 0.2 on a human TTY: static fixed-column rows, one static context header, and colour only as a second cue. 0.0 for `--json`, non-TTY, `NO_COLOR`, `TERM=dumb` and the `viola run` / `viola revive` passthrough: no colour, no non-ASCII glyph and no cursor control.

**Signature placement:** the readback mirror `[RB]` / `[  ]` / `[/ ]` is the first column of `viola send` output, in two components:
1. The issue line `[  ] open …`, on stderr and only on a TTY. It is printed when the request goes to the wrapper.
2. The outcome line: `[RB] read back …` on stdout with exit 0 when the send is confirmed, by the matching `prompt-submitted` or, for `/clear` on a verified CLI version, by its new-session post-condition (a `session-start` with cause `clear` and a new session id); `[/ ] unable …` on stderr with exit 13 (or 10/11/12/14) when the wrapper returns a refusal, or with exit 13 when the client itself refuses the text before any frame (`not-delivered` with `control-character` or `empty-text`); `[  ] unconfirmable …` on stdout with exit 0 for an unmeasured local command.

The word half of the box (`unable` plus `reason  detail`) is also the first-word column of every other verb's refusal line (`viola answer`, `viola pause`, `viola release`, and `viola wait` / `viola last` for exit 21). So the struck-box vocabulary is shared, while the glyph itself belongs to `send`. Under `--json` the mirror is replaced by the typed `ok` / `refusal` document. The supporting attention element, the amber `DIALOG` word, appears only in `viola list`.

### Primary screens (commands)

- `viola list` is the board: every session as one strip row, with the BAY context header.
- `viola send <target>` is the readback mirror. It types at a turn boundary and reports read back, unable or unconfirmable.
- `viola wait <target>` / `viola last <target>` return one turn-boundary result or the last assistant message, with no spinner.
- `viola pause` / `release` / `link` / `unlink` / `answer` are the wheel, handoff and dialog verbs. Their output is spoken phraseology.
- `viola verify` stamps a CLI version with a step counter, the project's only progress pattern.
- `viola run <name> -- claude` is passthrough and prints nothing while the child runs.
- `viola mcp` is no screen (chunk 2026-10-17-mcp-server-for-drivers): the hidden, plugin-run stdio MCP server with no human surface. Its five tools `send · wait · last · answer · list` are a driver's machine view of those verbs: each success and refusal is the CLI verb's `--json` document less `v`, a refusal `isError: true` with the text `refused: <code>`, the bodies codes only (`invalid-params` with a closed field word as `detail`), and no tool, description or result names `release`, `pause`, `link` or `unlink`.
- `viola revive <name>` resumes a dead instance in place (its newest logged session, in the recorded directory) and is passthrough like `viola run`. `viola revive <name> --list` prints the instance's logged sessions, one static line each.
- `viola plugin install` writes an MCP-only local marketplace under `<home>/marketplace/` (no hooks) and prints the two `claude plugin` commands that add it; it spawns no `claude` (Output structure — `viola plugin install`).
- `viola --help` is the grouped verb table, built (chunk 2026-10-17-cli-output-discipline) with the served verbs only: the board, traffic, wheel and setup rows, `setup:` holding `plugin install`; the `handoff:` row joins when "Explicit session links" serves its verbs (served verbs only is the Viola overseer's technical answer, `inputs#I1` Q3 of that chunk — PROVISIONAL, the founder's own word owed).

### Output structure — `viola list` (human TTY)

```
$ viola list
BAY  5H 62 %  7D 41 %  read 4m ago  gate open  skipped 0 - 0 - 0                <- context header (Label BAY/5H/7D, Data figures), one static line
NAME          LIVE   STATUS   WHEEL                    DIALOG             CLI    <- captions, Label, plain
builder       live   idle     driver                   none               2.1.280 verified
overseer      live   busy     human                    DIALOG permission  2.1.280 verified     <- DIALOG in color-accent, `permission` plain
scratch       stale  unknown  driver - budget-paused   none               2.1.281 unverified-cli <- whole row color-text-muted (SGR dim)
-- UNWRAPPED - READ-ONLY --                                                      <- rack separator, Heading-equivalent, plain
c1f9e2a4...   live   idle     n/a                      n/a                n/a    <- NAME truncated with `...` only when the width is known
```

- NAME values are bold (Callsign). Rows are ordered by name. Nothing is re-sorted by state.
- A closed budget gate prints `budget-paused` in place of `gate open`. A passed window prints `5H 62 % expired`.
- On a cocked + `stale` row, `DIALOG` stays amber and not dim, and the kind word and the rest of the row stay dim.
- Empty board: `no wrapped sessions  start one: viola run <name> -- claude`.

### Output structure — `viola list` (piped / `NO_COLOR` / `TERM=dumb`)

```
$ viola list | cat
BAY  5H 62 %  7D 41 %  read 4m ago  gate open  skipped 0 - 0 - 0
NAME          LIVE   STATUS   WHEEL                    DIALOG             CLI
overseer      live   busy     human                    DIALOG permission  2.1.280 verified
...
```

These are the same characters with no SGR. The words carry every state, so nothing is lost. Nothing is truncated when the width is unknown.

**As built** (chunk 2026-10-11-the-board-viola-list; the agents read, chunk 2026-10-16-unwrapped-sessions-on-the-board; the colour layer and the width cut, chunk 2026-10-17-cli-output-discipline): `viola list` prints this form as one stdout write: the BAY line, the caption row, then one row per wrapped session in name order, or the BAY line, the caption row and the empty line; then the unwrapped rack when there is one. It is uncoloured under `--json`, a piped stdout, `NO_COLOR` (an empty value included), `TERM=dumb` or a failed Windows VT enable; on a terminal that takes colour it is the styled human-TTY form above: every NAME value bold, the `DIALOG` word of a wrapped row with a pending dialog in the attention token with its kind word plain, a wrapped `stale` row dim from its first byte to its last (NAME dim and bold; on a stale row with a dialog only `DIALOG` amber and not dim), the BAY line, caption, empty line and separator plain, the depth truecolor / 256 / 16 from `COLORTERM` / `TERM`. One `claude agents --json` read follows the board read, its rows joined to the wrapped rows by child pid or agent session id: a joined wrapped row reads STATUS `idle` or `busy`, else `unknown`; every unjoined row prints after the wrapped rows (or after the empty line) under the `-- UNWRAPPED - READ-ONLY --` line, sorted by name, NAME the row's `sessionId` through `escape_row`, LIVE `live`, its STATUS, `n/a` in WHEEL, DIALOG and CLI; with no unwrapped row no separator prints, and a failed, oversize or malformed read prints the board as with no `claude`. NAME is padded to the longer of 4 and the longest name over both racks, counted in characters, LIVE to 5, STATUS to 7, WHEEL to 23 (the widest word `unknown - budget-paused`; implement's decision, confirmed by the founder's own answer, 2026-10-13, relayed verbatim by the Viola overseer), DIALOG to 17, CLI last and unpadded; no line ends in a space. With the terminal's width known (`viola_pty::host_size()`, never `COLUMNS`; a piped stdout reads none; the width source is `inputs#I1` Q2 of chunk 2026-10-17-cli-output-discipline, PROVISIONAL) NAME's column is the largest of 4, the longest wrapped NAME and the longest unwrapped NAME capped at the width less 65, and an unwrapped NAME longer than the column is cut to the column less 3 characters plus `...` (the wireframe's `c1f9e2a4...`), never inside a `\xHH` escape; a wrapped NAME is never cut; with no known width nothing is truncated. A replayed row with no logged holder reads WHEEL `unknown`; a row with no recorded version reads CLI `unknown`; a pending dialog of unknown kind reads `DIALOG unknown`. The planning forms of design-system cli pattern 1 (a figure rounded down, the whole-minute age and `read unknown`, bare skip counts, `human - budget-paused`, the empty board's three lines) are the founder's wording, confirmed as built in the same answer (the operator's word superseded 2026-10-13).

### Output structure — `viola list --json`

```
$ viola list --json
{"v":1,"ok":{"items":[…],"budget":{…},"skipped":{"unknown_kinds":0,"unknown_fields":0,"torn_lines":0}}}
```

One JSON document on stdout, with no header line, no colour and no glyph. The item, `budget` and `skipped` shapes are the `list` payload contract (architecture §Standard Contracts). A failed strict-modes check of the home, `instances/` or any one instance prints instead `{"v":1,"error":"instance-unreachable","detail":null}` with exit 21 and stderr empty, opens no log and leaves the home's mode as found (chunk 2026-10-11-the-board-viola-list; the founder's own answer, 2026-10-13, relayed verbatim by the Viola overseer, the operator's answer superseded 2026-10-13).

### Output structure — `viola send`

```
$ viola send builder < step4.txt
[  ] open           builder  issued 19:45:05.300Z                 <- stderr, TTY only (issue: box open)
[RB] read back      builder  19:45:05.912Z  cursor 48213          <- stdout, exit 0 (SIGNATURE: filled)

$ viola send builder < clear.txt
[  ] open           builder  issued 19:44:31.007Z
[/ ] unable         builder  not-delivered  input-not-ready       <- stderr, exit 13 (SIGNATURE: struck)
hint: builder was not ready for input; send again, and if it repeats a human must look at the session   <- stderr, the last line

$ viola send builder < remote.txt
[  ] open           builder  issued 19:46:12.001Z
[  ] unconfirmable  builder  local command, no measured post-condition   <- stdout, exit 0 (never filled)

$ viola send builder --json < step4.txt
{"v":1,"ok":{"submitted_at":"2026-09-23T19:45:05.912Z","cursor":48213}}   <- stdout; no glyph, no issue line
```

The word column is padded so `open`, `read back`, `unable` and `unconfirmable` line up, and the name always starts in the same column. Lines are appended, never redrawn: the issue line stays and the outcome is printed under it. When stdout is piped, the TTY-only issue line is dropped and the outcome line alone carries the mirror.

### Output structure — `viola wait` / `viola last`

```
$ viola wait builder --after 48213
waiting: builder                                          <- stderr, TTY only, printed once
turn-ended  builder  19:44:10.221Z  cursor 49102          <- stdout
session-end  builder  19:52:03.118Z  cursor 50117         <- stdout (every non-dialog kind takes the turn-ended form)
question  builder  dialog 7  cursor 49310                 <- stdout (DIALOG is not coloured: this is a result, not the board)
timed out  builder  30000 ms                              <- stdout

$ viola last builder
last  builder  turn-ended 19:44:10.221Z                   <- stderr, TTY only
41 passed, 0 failed                                       <- stdout, C0/C1 escaped; `no message` on stderr for null

$ viola wait builder                                      (no live instance: exit 21)
unable  builder  instance-unreachable                     <- stderr
hint: builder is not running; viola list shows the live instances   <- stderr, the last line
```

There is no spinner and no elapsed-time counter. `waiting:` is printed only when stderr is a terminal and `--json` is not set. A dialog line whose event carries no `dialog_id` reads `dialog unknown`. Under `--json` each verb prints exactly one document on stdout (`{"v":1,"ok":…}`, or the exit-21 / wrapper-fault document) and nothing on stderr. A failure or a caught panic prints `error: internal error` once, exit 1, no hint (Primary content block 2).

### Output structure — wheel, handoff and dialog verbs

```
$ viola pause builder
builder  wheel human  manual-pause  I have control
$ viola release builder
builder  wheel driver  you have control
$ viola release builder --budget
builder  budget gate lifted until 21:00:00Z  wheel human   <- a pause stood; `YYYY-MM-DD 21:00:00Z` when the end is on another UTC date
builder  budget gate open  wheel human                     <- no pause stood (the reply holds no `override_until`)
$ viola link overseer builder
link    overseer -> builder  since 19:43:58Z               <- `already linked` for an existing pair
$ viola unlink overseer builder
unlink  overseer -> builder
$ viola answer builder 7 < response.json
answered  builder  dialog 7
unable  builder  not-delivered  unknown-dialog             <- stderr, exit 13, then its hint line
hint: that dialog is not pending; viola list shows the current DIALOG
```

`viola release <name> --budget` prints one of two stdout lines, exit 0, with the wheel left where it is. `<name>  budget gate lifted until <end>  wheel <holder>` when a pause stood: `<end>` is the reply's `override_until` as `HH:MM:SSZ` on the current UTC date and as `YYYY-MM-DD HH:MM:SSZ` on any other date, and a value that is no RFC 3339 instant prints escaped. `<name>  budget gate open  wheel <holder>` when no pause stood. The date form and the `budget gate open` line are the founder's wording: planning forms as built (chunk 2026-10-10-budget-governor, on the operator's word) that he confirmed as they were shown to him, his own answer, 2026-10-13, relayed verbatim by the Viola overseer (the operator's word superseded 2026-10-13) (design-system §Surface: cli, Component Patterns 4).

### Output structure — `viola verify`

```
$ viola verify                                             (a Unix host: 23 relied rows)
[01/23] shim-resolution claude resolves to a real executable  pass
...
[06/23] largest-hook-payload every hook payload fits the frame cap  pass
[07/23] modal-signature an untrusted start shows a compiled modal literal  pass
...
[10/23] confirm-window the typed prompt reaches UserPromptSubmit within the window  pass
[11/23] question-answer a question answered through PreToolUse takes effect  pass
...
[14/23] dialog-concurrency two parallel questions each raise a dialog  pass
[15/23] long-paste-wrapper a long paste unwraps to the text as pasted  pass
[16/23] tag-escaping tag-like text un-escapes to the text as pasted  pass
[17/23] local-command-clear /clear starts a new session and submits no prompt  pass
[18/23] paste-newline an LF inside a paste stays inside the one prompt submitted  pass
[19/23] statusline-override a --settings statusLine runs in the status line's place  pass
[20/23] statusline-shell a statusline command runs through /bin/sh  pass
[21/23] statusline-rate-limits the statusline payload carries two whole-number rate_limits windows  pass
[22/23] resume-session --resume <id> reopens the session under that id  pass
[23/23] agents-join claude agents --json names the live session by pid and session id  pass
stamped 2.1.287  23 pass  0 fail                           <- last stdout line; `fail` is never coloured

$ viola verify
...
stamped 2.1.287  21 pass  2 fail                           <- a failing row: exit 1, the stamp still written

$ viola verify                                             (stopped by Ctrl-C or TERM before its rows are checked)
unable: verify was stopped before it finished              <- stderr; stdout empty, no step line, no summary
hint: run viola verify again to stamp this CLI             <- the last stderr line: exit 1, no stamp written
```

Usage: `viola verify [--record <DIR>] [-- <program> [args…]]` (program default `claude`). One stdout step line per relied ledger row, `[NN/MM] <row id> <row words>  pass|fail`, in ledger order (`shim-resolution` · `spine-hooks` · `session-start-fields` · `prompt-verbatim` · `stop-message` · `largest-hook-payload` · `modal-signature` · `input-box-signature` · `quiet-period` · `confirm-window` · `question-answer` · `plan-approve-revise` · `question-notes` · `dialog-concurrency` · `long-paste-wrapper` · `tag-escaping` · `local-command-clear` · `paste-newline` · `statusline-override` · `statusline-shell` · `statusline-rate-limits` · `resume-session` · `agents-join`; `MM` is the relied count, `LedgerRow::relied()`'s length: 23 on Unix, 20 on Windows, where the relied set skips the three statusline rows because the status line is not wrapped there and ends at `agents-join`; it grows as owning chunks land their rows), then the `stamped <ver>  <n> pass  <m> fail` summary as the last stdout line. Exit 0 when every relied row passes, 1 on a failing row, a refusal (the `unable:`/`hint:` pairs, Primary content block 2) or a stop: a run stopped by Ctrl-C or TERM (Unix `SIGINT` / `SIGTERM`, Windows Ctrl-C / Ctrl-Break) before its rows are checked prints only that plain ASCII pair, with no name, path or pid, and writes no stamp (a planning form on the operator's word, the founder's wording owed, chunk 2026-10-13-interrupted-verify-cleanup). `--record` adds no human line. Plain ASCII, no colour. Each step line is appended once, with no progress bar and no redraw. `viola verify --help` adds one static ASCII paragraph naming no path: run it from a folder you trust in Claude Code (the input-box probe runs in a subfolder there, which inherits that trust), and an unapproved external CLAUDE.md import blocks the probe (its dialog shows in the subfolder, and verify never answers it).

### Output structure — `viola --help`

```
$ viola --help
Usage: viola [--home <dir>] <verb> [args]

board:    list
```

**As built** (chunk 2026-10-17-cli-output-discipline): `viola --help` (and `viola help`) prints exactly `Usage: viola [--home <dir>] <verb> [args]`, a blank line, the four rows `board:    list` · `traffic:  send, wait, last, answer` · `wheel:    pause, release` · `setup:    run, revive, verify, plugin install`, a blank line, `Options:` and clap's options (`--home <HOME>`, `-h, --help`, `-V, --version`); no about line and no clap `Commands:` list; plain ASCII, pinned by the `HELP` literal in `tests/cli_output_plain.rs`. Served verbs only (the Viola overseer's technical answer, `inputs#I1` Q3 of that chunk — PROVISIONAL): the wireframe's `handoff:  link, unlink` row joins with "Explicit session links"; `help_lists_only_served_verbs` reads `plugin install` as one entry of the `setup:` row, a bare `plugin` unserved. The usage line is the override literal on every OS. `viola mcp` (chunk 2026-10-17-mcp-server-for-drivers) is a hidden verb (`#[command(hide = true)]`, no argument but the global `--home`), run only by the plugin (`plugin/.mcp.json` registers it with the absolute pinned path and `["mcp"]`), never by a person: it appears in no row, and the `HELP` literal is unchanged.

`viola <verb> --help` gives clap's per-verb usage, unchanged; its usage line names the program by its executable, `viola.exe` on Windows. Prompt text comes from stdin or `--file`, never from a leading-slash argument, and help says so on `send`.

### Output structure — `viola revive`

```
$ viola revive builder
(nothing: the terminal belongs to the resumed claude TUI until it exits)

$ viola revive builder --list
2026-10-10T14:21:07.512Z  startup  3f2b8c1e-7a4d-4e9b-9c10-5d6e7f8a9b0c    <- stdout, one row per logged session
2026-10-10T14:35:40.118Z  resume  3f2b8c1e-7a4d-4e9b-9c10-5d6e7f8a9b0c

$ viola revive builder
unable: builder's recorded directory is missing           <- stderr, exit 1; no paths, no pids, no logged id
hint: resume it by hand from a directory you choose: viola run builder -- claude --resume <id>, ids from viola revive builder --list
```

Usage: `viola revive <name> [--id <ID>] [--fork] [-- <child args>]`, or `viola revive <name> --list` (`--list` conflicts with `--id`, `--fork` and the trailing arguments), each with `[--json]`. A start that passes its preflight prints nothing of its own while the child holds the terminal, as `viola run`. `--list` prints one stdout row per logged session in log order, `<ts>  <cause>  <id>` with two spaces between fields, no header and no colour, plain ASCII, with an empty stderr; the cause is `startup`, `clear`, `resume` or `compact` as logged, and `unknown` otherwise. Each refusal is exit 1 with one `unable:` line and one `hint:` line last on stderr and an empty stdout:

- `unable: <name>'s state files can be written by another user` / `hint: viola will not read them; make the viola home and its files owner-only`
- `unable: <name> is already live` / `hint: viola list` (`run`'s collision pair, and its stale sibling, unchanged)
- `unable: <name> has no logged session to resume` / `hint: start one: viola run <name> -- claude`
- `unable: <name> has no logged session with that id` / `hint: viola revive <name> --list`
- `unable: <name>'s session is open in another claude` / `hint: close it there first, or start a copy: viola revive <name> --fork` (the founder's wording, his own answer to P4 fork 4 of chunk 2026-10-16-unwrapped-sessions-on-the-board, `inputs#I1`)
- `unable: <name>'s recorded directory is missing` / the hint shown above

The hints are distinct and none names `viola release`. `--list` has two of the refusals (state files, no logged session). The start reads its preflight in a fixed order, the holder, the logged session, `session-live` (one `claude agents --json` read: a row whose `sessionId` is the logged id refuses; skipped under `--fork`; a failed read passes and the start goes on), then the recorded directory. A malformed `--id` is clap's usage error, exit 2.

Under `--json` (both arms; chunk 2026-10-17-cli-machine-contract) each refusal above is one stdout document `{"v":1,"error":"<code>","detail":null}`, exit 1, empty stderr, `<code>` one of `strict-modes-failed`, `already-live`, `no-session` (both of its pairs), `session-live`, `cwd-missing`; `--list --json` prints the rows as one document in log order, fields as the human rows, or the `no-session` document with exit 1. Without `--json` the pairs and the rows stay byte-identical. A refusal `run`'s start makes after a passed preflight (`batch-script-child`, `pinned-hash-mismatch`, `squatted-name`, `internal-error`) prints no document as landed; its document is owed to the working-route entry "Exit-cause code catalogue".

```
$ viola revive builder --list --json
{"v":1,"ok":{"sessions":[{"ts":"2026-10-17T03:12:09Z","cause":"startup","id":"<session id>"}]}}
$ viola revive builder --json
{"v":1,"error":"already-live","detail":null}
```

### Output structure — `viola plugin install`

```
$ viola plugin install
viola@viola  written  <home>/marketplace          <- stdout, one write
run these to add it to Claude Code:
  claude plugin marketplace add <home>/marketplace
  claude plugin install viola@viola

$ viola plugin install --json
{"v":1,"ok":{"marketplace":"viola","plugin":"viola@viola"}}

$ viola plugin install
unable: the viola home is not private to you              <- stderr, exit 21; nothing created, no log opened
hint: the viola home must be readable only by you; viola does not change its permissions
```

Usage: `viola plugin install [--json]`; `viola plugin` alone is a clap usage error (exit 2), and clap serves its own `viola plugin help [install]`. The verb writes the marketplace tree, then prints its four lines in one plain-ASCII stdout write, no SGR, never redrawn: `<dir>` is the canonical home joined with `marketplace`, printed bare unless the host's shell would split it (Unix: single-quoted unless every character is an ASCII letter, a digit or one of `_ - . / :`; Windows: double-quoted when it holds a space). The lines are a planning form as built (chunk 2026-10-17-optional-plugin-install), the founder's wording owed. Under `--json` it prints the `ok` document above, no path. A refused strict-modes check of the home or a `marketplace/` tree dir is exit 21 with the home pair on stderr and stdout empty, or under `--json` `{"v":1,"error":"instance-unreachable","detail":null}` with stderr empty. A failed exe read, dir creation or file write is the `cli` catch site's `error: internal error`, exit 1.

### Component — Header / banner (the BAY context line)

- **The only header on any verb** is the one static BAY line at the top of `viola list`.
- **Cell order:** `BAY`, `5H <n> %`, `7D <n> %` (each followed by `expired` when the window has passed), `read <age> ago`, `gate open` or `budget-paused`, `skipped a - b - c`. Cells are separated by the two-space gutter.
- **Typography:** Label words and Data figures, all in the default foreground. There is no bold, no colour, no box drawing and no rule line under it.
- **No banner anywhere:** no ASCII-art logo, no tagline and no version line on normal output. The version appears only in `--version` / `--help`. `viola run` prints nothing, and `viola hook` / `viola mcp` have no human surface.

### Component — Primary navigation (verb structure)

- **Flat verbs:** one lower-case word each (`plugin install` is the one two-word verb). There is no nested noun hierarchy, no interactive prompt, no TUI mode and no pager.
- **Argument order mirrors the channel `params`:** `viola <verb> <target>` for one strip, `viola link|unlink <driver> <driven>` for a handoff, `viola answer <target> <dialog_id>`. `<target>` is always a `ViolaName`. Unwrapped names are never valid targets.
- **Board vs. strip:** `viola list` shows the whole bay. Every other verb acts on one strip.
- **Global flag `--home`:** the same on every verb. `--json` is the machine view of every data verb, `viola revive` included (both arms: its refusal document and `--list`'s `ok.sessions`; chunk 2026-10-17-cli-machine-contract).
- **Discoverability:** `--help` groups verbs as board / traffic / wheel / handoff / setup; as built (chunk 2026-10-17-cli-output-discipline) it prints board / traffic / wheel / setup over the served verbs, `setup:` holding `plugin install`, the handoff group joining when its route entry serves its verbs (`inputs#I1` Q3, PROVISIONAL). `hint:` lines point to the next verb by name (`viola wait builder`, `viola list`, `viola verify`). They are the CLI's breadcrumbs. No hint names `viola release`: the refusals that carry hints reach drivers, and a driver's `release` is refused (`-32602`, exit 20). `release` is a human verb reached through `--help`.

### Component — Hero / signature output line (the `viola send` readback mirror)

- **Layout:** a fixed first column holding the four-character box (`[RB]`, `[  ]`, `[/ ]`). Then one space, then the padded state word (`open` / `read back` / `unable` / `unconfirmable`). Then the two-space gutter, then NAME, then the outcome fields: time, `cursor`, `reason  detail`, or the unconfirmable note.
- **Issue left, readback right, spread over time:** the TTY issue line on stderr is the open box. The outcome line under it is the closed box. The two lines line up column for column, so the eye reads them as one strip entry.
- **Colour:** none, on purpose. The mirror is words and brackets only. `read back` is never green and `unable` is never red, because colour on the CLI is reserved for `DIALOG` and `stale`.
- **What never happens:** no `Sending…` spinner, no `✓`, no `done`. `turn-ended` is never reported as a send outcome. That is `viola wait`'s result.
- **Machine view:** `--json` prints only the typed document (`ok` with `submitted_at` + `cursor`, `ok` with `confirmed:false` + `unconfirmable`, or `refusal` + `detail`), with the typed exit code and no glyph and no hint.

### Component — Primary content block 1: `viola list` strip rows

- **Columns:** NAME · LIVE · STATUS · WHEEL · DIALOG · CLI. Each column is padded to its widest word (`stale`, `unknown`, `driver - budget-paused`, `DIALOG permission`, `2.1.281 unverified-cli`), with the two-space gutter between columns. There are no box-drawing borders.
- **Styling:**
  - NAME is bold (Callsign).
  - The `DIALOG` word takes `color-accent` and the kind word after it stays default. This is the CLI cocked strip.
  - A `stale` row is `color-text-muted` (dim) from end to end, and the word `stale` is always in LIVE.
  - Nothing else is styled.
- **Rack separator:** `-- UNWRAPPED - READ-ONLY --` on its own line before the unwrapped rows. The WRAPPED rack has no separator, because it is always first and the caption row heads it.
- **Truncation:** only unwrapped NAMEs, with `...`, and only where the terminal width is known. Wrapped names are never clipped. No line ever wraps.
- **Escaping:** every field that comes from `claude agents --json` has C0/C1 controls escaped as hex text, **including** `\n` and `\t` inside a row, so a row never splits and the columns stay fixed-width (T5 ratified; stricter than the security floor, which keeps `\n` / `\t` for `wait` / `last` text).
- **No link column:** the six shared columns stay fixed. Links are visible only as `link` / `unlink` verb output (`overseer -> builder`).
- **As built** (chunk 2026-10-11-the-board-viola-list; the rack, chunk 2026-10-16-unwrapped-sessions-on-the-board): the wrapped rows, then the `-- UNWRAPPED - READ-ONLY --` separator and the unwrapped rows when the agents read lists any; on a terminal that takes colour (chunk 2026-10-17-cli-output-discipline) NAME bold, the `DIALOG` word amber with its kind word plain, a `stale` row dim end to end with only `DIALOG` amber and not dim, nothing else styled, and no SGR when colour is off; only an unwrapped NAME is cut, with `...`, and only on a terminal whose width is known and too narrow for it, never inside an escape; the row escape (`escape_row`) covers every control character, DEL and C1 included, and as built its upstream-derived cells are the recorded CLI version and each unwrapped NAME (a `claude agents --json` `sessionId`). The widths are under Output structure — `viola list` (piped).

### Component — Primary content block 2: refusal lines and the `unable` column

- **Line form (stderr):** `unable  <name>  <reason>  <detail>`, fields separated by two spaces. `viola send` pads `unable` into the mirror's word column after `[/ ]`. The fixed-message exceptions are the exit-1 start refusals of `viola run` (`unable: <name> is already live` and its sibling causes, listed in design-system cli pattern 2), the exit-1 refusals of `viola revive` (the same collision pair, and its own five pairs under Output structure — `viola revive`; under `--json` its `{"v":1,"error":"<code>","detail":null}` document in place of the pair) and `viola verify`'s exit-1 refusals, each an `unable: <text>` line and its own `hint:` line with no name, path or pid: `the claude CLI was not found` / `install Claude Code or put it on PATH`; `the claude CLI is a .cmd or .bat script` / `pass the real executable, not a .cmd or .bat shim`; `the CLI version could not be read` / `run claude --version to check the install`; `a recorded fixture is not clean: <file> <code>` (a screen fixture: `<file> row <n>[ seam] <code>`; codes `home-path` · `absolute-path` · `username` · `email`; it names the fixture file and the check, never the content) / `record with a viola home under your user home`; `verify was stopped before it finished` / `run viola verify again to stamp this CLI` (a run stopped by Ctrl-C or TERM, stdout empty); plus run's pinned-copy refusal; and `viola list`'s exit-21 strict-modes refusal of the whole board (chunk 2026-10-11-the-board-viola-list; the founder's own answer, 2026-10-13, relayed verbatim by the Viola overseer, the operator's answer superseded 2026-10-13), stdout empty: `unable: the viola home is not private to you` / `hint: the viola home must be readable only by you; viola does not change its permissions` for the home or `instances/`, and `unable: <name>'s state files can be written by another user` / `hint: viola will not read them; make the viola home and its files owner-only` (`revive`'s pair) for one instance; and `viola plugin install`'s exit-21 strict-modes refusal, stdout empty, the same home pair for the home or a `marketplace/` tree dir, nothing created and no log opened. A failed or panicked `cli` verb (`send`, `wait`, `last`, `list`, `answer`, `pause`, `release`, `verify`, `revive --list`, `plugin install`; a `revive` start stays outside it) prints exactly `error: internal error` once, from the one catch site, with no hint (for `wait` / `last` exit 1 also covers a refusal reply, an unparseable reply or any other channel error; for `list` an `instances/` that cannot be listed and a log start that fails, while a per-instance read error gives no row — implement's decisions, accepted by the operator; the exit 1 of an `instances/` that cannot be listed is the founder's own answer, 2026-10-13, relayed verbatim by the Viola overseer, and the failed log start and the no-row read error are not ruled by him).
- **Refusals decided before any request:** `viola send` refuses two texts itself, before any frame: one that holds a refused character (`not-delivered  control-character`) and one whose typed text is empty once its trailing CR and LF characters are removed, the empty text included (`not-delivered  empty-text`). Each takes the same `[/ ] unable  <name>  not-delivered  <detail>` line on stderr with exit 13, and its hint as the last stderr line (for `empty-text`: `hint: the text is empty once its trailing newlines are removed; send a text with content`). Under `--json` it is one document on stdout with no stderr line. The wrapper makes the same two refusals for a frame sent straight to it.
- **Hint line:** directly under each refusal, `hint: <one plain instruction>`, keyed by reason (or by reason · detail). Exit 21 and exit 1 each have several causes, and every cause gets its own hint, so an agent can tell the causes apart from the last stderr line (design-system cli pattern 2). The exit-1 start refusal `unable: <name> is already live` takes `hint: viola list`. `wait` / `last`'s exit 21 `unable  <name>  instance-unreachable` takes `hint: <name> is not running; viola list shows the live instances` (`viola send`'s exit 21 keeps its `[/ ] unable` mirror with the same hint). There is no hint for the opaque `unknown` refusal, for `wrapper fault` or for `internal error`. A hint never quotes the sent text or any upstream text, and never names a path or a pid.
- **Exit codes as the typed tail:** 10 `human-typing`, 11 `budget-paused`, 12 `unverified-cli`, 13 `not-delivered`, 14 `unknown`, 20 wrapper fault (`error: wrapper fault  <code>`), 21 `unable  instance-unreachable` (for `viola list` and `viola plugin install` the fixed state pair above instead). Under `--json` the same outcome is one document on stdout, with no stderr line and no hint text. The machine view carries the cause as a detail code once arch names those codes; until then it keeps arch's shape (`"detail":null` for exit 21).
- **Streams:** results go to stdout. `waiting:`, the issue line, refusals, hints and errors go to stderr. The two are never mixed.

### Component — Footer / terminator

- **No terminator word.** No `done.`, no `success`, no summary banner. The exit code is the terminator, and the last printed line always says what happened, to whom and where: `[RB] read back      builder  19:45:05.912Z  cursor 48213`, `answered  builder  dialog 7`, `link    overseer -> builder  since 19:43:58Z`.
- **On a refusal**, the `hint:` line is the last line on stderr.
- **On `verify`**, the summary `stamped <version>  <n> pass  <n> fail` closes a completed run; a run stopped before its rows are checked prints no summary, and its `hint:` line is the last line on stderr.
- **No persistent footer.** Terminal scrollback is the history. The tape lives in `events.ndjson`.

### IA notes

- **Command model:** flat verbs plus a target. The board is `viola list` and the strip-level verbs act on one `ViolaName`. There are no subcommand trees beyond `plugin install`.
- **Deep links:** none, and the CLI has no URL coupling. The shared references are `ViolaName` (never case-transformed) and `cursor` (the byte offset `send` prints and `wait --after` consumes).
- **Output as a contract:** the human columns and words are stable, because LLM drivers may read them. New fields go into `--json` first. Adding a human column is a design change, not an implementation choice.
- **Shared vocabulary:**
  - The six captions, words and slot order are fixed, and a future page reuses them.
  - The readback vocabulary is `open`, `read back`, `unable`, `unconfirmable`. The CLI brackets the box.
  - ` - ` separates inside a CLI field, and an arrow is `->`. There is no CLI inbound `<-` form.
  - Amber means `DIALOG` and nothing else. `stale` is SGR dim in the terminal.
  - The CLI is where every action lives.
