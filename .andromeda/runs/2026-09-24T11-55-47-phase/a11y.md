# a11y extract

## Relevance
Partial. The chunk adds no UI surface and no WCAG criterion. It does edit the CI pipeline, the local gate set and the CLI output modules, and the a11y plan's gates and output-discipline assertions depend on all three, so the chunk must not break them.

## Constraints
- a11y-plan §9 (Pipeline integration) and §3 (CI integration) require the web a11y gate to stay inside the ubuntu leg of the one push/PR workflow `ci.yml`, running through `scripts/agent-run.* run --browser` and then `gate --require playwright`. The new obs steps (G1–G4, secret-scan, the scan-gated uploads, `AGENT_RUN_KEEP_HOMES=1`) must not reorder, skip or replace that leg. Whether `ci.yml` and `e2e-web/` at HEAD already carry the E2E/a11y leg and the a11y lint step (D-A11Y-14) is a question for research.
- a11y-plan §9 (Aggregation row) and §3 (Bootstrap phases, a11y-ci-gate-wire) require the `e2e-web/test-results/` upload and the SC-coverage/budget `jq` step to run with `if: always()`, using SHA-pinned `actions/upload-artifact` v7.0.1. If this chunk adds or restructures upload steps in the §9 obs order, it must not drop or conditionally gate the a11y upload. It must also not route the a11y upload behind the obs `secret-scan` in a way that stops it running after the job has already failed.
- a11y-plan §3 (Structured violation JSON schema) requires a11y rows to live only in `e2e-web/test-results/a11y/*.ndjson`. They are checked against the tests-owned `e2e-web/schemas/a11y-row.v1.json`, never `schemas/diag-line.v1.json` (D-A11Y-09). So the G4 `schema-conformance` globs and the G2 panic scan must never include a11y artifacts, and a11y rows must never appear under `target/e2e-home/**/diagnostics/`.
- a11y-plan §3 (Structured violation JSON schema, Scrubbing) makes the a11y fixture's own scrubber (`scrub-leak` rows) the secret-hygiene control for a11y artifacts. The obs secret-scan paths in this chunk's scope (`target/e2e-home/**/diagnostics/*.ndjson`, `target/agent-run/*`, `target/nextest/ci/junit.xml`) do not cover `e2e-web/test-results/`. Research should decide whether that gap is intended or is a divergence to report (no spec edits in this chunk).
- a11y-plan §4 P6 and §10 (Standard+ invariants) require the CLI output-discipline invariants (a single `waiting:` line, the two-line `viola ui` launch block on stderr printed once and unstyled, no SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json`, C0/C1 escaping) to pass on all three OS legs under the mutation gate. The `#[allow(clippy::print_stdout/print_stderr)]` sites on the `--json`, human-stderr and `ui` launch-line output modules must keep those exact bytes. Moving output only to satisfy the lint must not change them.
- a11y-plan §3 (Keyboard test harness) uses `viola-fake-agent` as the child for the three tui boundary nextest cases (zero viola-originated bytes, keystrokes never blocked, focus/mouse/resize not counted as editing). The crate-level print-lint exemption on `src/bin/viola-fake-agent.rs` must leave its stdout behaviour unchanged, because those byte-for-byte comparisons depend on it.
- a11y-plan §10 (Cross-input parallel) and §11 SLO require any fix for the mutants-timeout fold to use deadlines keyed on logged events and DOM signals, never sleeps, never `retries`, and never skips or quarantine. This matches the chunk's "fix the cause, not the timeout" directive.

## Patterns to follow
- One pipeline and no new suite (a11y-plan §9 Pipeline integration): gates go into the existing `ci.yml` legs and `agent-run.*` run/gate set. No new `suite` enum value, driver or `npm test:*` command.
- `if: always()` on the report and upload steps that must still run after a gate has failed (a11y-plan §9 Aggregation row). The obs secret-scan step follows the same approach.
- Lint-stage steps sit before `run --browser` on the ubuntu leg, alongside clippy and zizmor (a11y-plan §12 D-A11Y-14). New clippy lint-ban steps can follow the same placement.
- SHA-pinned `actions/upload-artifact` v7.0.1, per zizmor (a11y-plan §9 Artifact retention).

## Anti-patterns to avoid
- Never write a11y violation rows into `<home>/diagnostics/`, rename an obs binding field, or write a literal `null` for `corr` / `instance` (per a11y-plan §11 Universal).
- Never skip a11y on CI failure, never add a `suite` value (such as `a11y`), `webServer` or separate driver, and never treat `browser-missing` as a skip (per a11y-plan §11 CI).
- Never use a retry-once policy or `test.skip` / `#[ignore]` / quarantine to get a gate green (per a11y-plan §11 SLO).

## Contract bindings
- a11y ↔ obs: the a11y row shape reuses the obs binding field names but is validated by `e2e-web/schemas/a11y-row.v1.json`, not by G4 (`diag-line.v1.json` / `diag-detail.v1.json`) (a11y-plan §3 Structured violation JSON schema, D-A11Y-09).
- a11y ↔ tests: the web a11y gate runs inside the `playwright` suite of `scripts/agent-run.* run --browser` plus `gate --require playwright`, and the CLI/tui output-discipline checks run inside `nextest-integration` / `nextest-e2e` (a11y-plan §9). Changes this chunk makes to the local gate set and to test timeouts reach both.
- a11y ↔ security: a11y artifact scrubbing (token, `Cookie`, `?t=`, absolute paths, `CLAUDE*`) is the a11y-side counterpart of the obs secret-scan's NEVER-log floor (a11y-plan §3 Scrubbing, §10 failure conditions).
