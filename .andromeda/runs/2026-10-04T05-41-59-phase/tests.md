## Patterns to follow
- Sync E2E and CLI tests go in root `tests/{cli,channel,chaos,tui}_<topic>.rs` over `tests/support/{home,outer_pty,fake,events,ndjson}.rs`. Every live-appended file is read through the one complete-lines reader `ndjson.rs`. The fixture chain is `home → fake_agent_path → stamped_home → booted_wrapper` (test-plan §2 Test directory; §3 `run`).
- The fake agent provides `mute` (`--suppress-prompt-submit`) and `local` (`--local-command-mode`). Receipt `prompt` lines carry `text`, `hex`, `bare_esc` and `submit` `fired|suppressed|local-command`, and they are the delivery oracle. The rendered screen never is (test-plan §7 Fake agent; §11 E2E).
- Table-driven cases use rstest `#[case::<label>]`. Expected refusal order, exit codes and local-command ledger row ids are written as literals, never imported from the product (test-plan §4 Conventions; §11 Unit).
- Waits key on `events.ndjson` byte offsets. The product-owned confirmation window behind `no-prompt-submitted` is the one E2E deadline allowed, on two conditions: the verdict is the product's own exit code, and the same deadline is clock-driven in a §4 unit case (test-plan §2 Agent-runnable invariants; §11 Universal).
- Every send text the tests feed embeds the `tests/support` canary. The canary may reach `events.ndjson` and `instances/<name>/diagnostics/detail-*.ndjson` only, never a home-level `diagnostics/*.ndjson` line (test-plan §6 Error sanitization and secret scan).

## Anti-patterns to avoid
- Never parse the vt100 grid or PTY master output for content. Never `sleep(N)` to synchronise. Never call `assert_cmd .assert()` on the long-lived `viola run` (test-plan §11 E2E).
- Never control the wrapper's confirmation window or the gate's wait from the test process with `MockClock` or any in-process clock. Never write a test-owned timer or elapsed-time verdict (test-plan §11 Universal).
- Never hand-write `ledger/stamps.json` or `snapshot.json`. Never `std::env::set_var`. Never `.env_clear()` without re-adding `LLVM_PROFILE_FILE` (test-plan §11 Test Data / Integration).
