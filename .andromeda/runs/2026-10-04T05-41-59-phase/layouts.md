# layouts extract

## Relevance
partial — the chunk builds the cli surface's signature verb (`viola send`, the `[RB]` readback mirror); the web-spa surface (the readback box on the tower tape, `data-rb`) is out of scope per the chunk's §Boundaries (no `viola-ui` crate).

## Constraints
- The readback mirror is the fixed first column of `viola send` output: the four-character box (`[RB]` / `[  ]` / `[/ ]`), one space, the state word padded so `open` / `read back` / `unable` / `unconfirmable` line up, the two-space gutter, NAME always in the same column, then the outcome fields (time, `cursor N`, `reason  detail`, or the unconfirmable note) — per layout-templates §Component — Hero / signature output line and §Output structure — `viola send`.
- Streams are fixed per line: the issue line `[  ] open … issued <ts>` on stderr and only on a TTY; `[RB] read back … cursor N` on stdout, exit 0; `[/ ] unable … not-delivered <detail>` on stderr, exit 13, with its `hint:` as the last stderr line; `[  ] unconfirmable … local command, no measured post-condition` on stdout, exit 0. When stdout is piped the issue line is dropped and the outcome line alone carries the mirror. Results and refusals are never mixed across streams — per layout-templates §Surface: cli (Signature placement), §Output structure — `viola send`, §Component — Primary content block 2 (Streams).
- Lines are appended, never redrawn: the issue line stays and the outcome is printed under it; no cursor control, no spinner, no elapsed counter — per layout-templates §Output structure — `viola send` and §Surface: cli (Motion tokens "None"; Expression level).
- No colour on the mirror at any expression level (`read back` never green, `unable` never red; CLI colour is reserved for `DIALOG` and `stale`); under `--json`, non-TTY, `NO_COLOR` and `TERM=dumb` the output carries no colour, no non-ASCII glyph and no cursor control — per layout-templates §Component — Hero / signature output line (Colour) and §Surface: cli (Expression level).
- Exit codes are the typed tail of a refusal: 10 `human-typing`, 11 `budget-paused`, 12 `unverified-cli`, 13 `not-delivered`, 14 `unknown`, 20 wrapper fault (`error: wrapper fault  <code>`), 21 `unable  instance-unreachable`; `[/ ] unable` covers exit 13 "(or 10/11/12/14)". Which of these causes this chunk can actually produce (wheel and budget pauses are later entries per the scope's §Boundaries) is P4's to pin — per layout-templates §Component — Primary content block 2 (Exit codes) and §Surface: cli (Signature placement).
- Every refusal cause gets its own `hint:` line, keyed by reason (or reason · detail), naming the next verb by name; no hint for the opaque `unknown` refusal, `wrapper fault` or `internal error`; a hint never quotes the sent text or any upstream text, never names a path or pid, and never names `viola release` — per layout-templates §Component — Primary content block 2 (Hint line) and §Component — Primary navigation (Discoverability).
- `viola send <target>` follows the flat-verb model: `<target>` is a `ViolaName`, `--home` global, `--json` as the machine view; prompt text comes from stdin or `--file`, never a leading-slash argument, and `viola send --help` says so — per layout-templates §Component — Primary navigation (verb structure) and §Output structure — `viola --help`.

## Patterns to follow
- The `input-not-ready` refusal pair is specified verbatim as the worked example: `[/ ] unable         builder  not-delivered  input-not-ready` then `hint: builder was not ready for input; viola wait builder, then send again` — per layout-templates §Output structure — `viola send`.
- The `unable  <name>  <reason>  <detail>` refusal line (two-space separated) is the shared word half of the box across verbs; `send` pads `unable` into the mirror's word column after `[/ ]` — per layout-templates §Component — Primary content block 2 (Line form) and §Surface: cli (Signature placement).
- The footer rule: no terminator word (`done.`, `success`), the exit code is the terminator, and the last printed line states what happened, to whom and where (`[RB] read back      builder  19:45:05.912Z  cursor 48213`) — per layout-templates §Component — Footer / terminator.
- The `--json` machine view prints exactly one typed document on stdout with no glyph, no issue line, no hint and no stderr line, under the same typed exit code: `ok` with `submitted_at` + `cursor`; `ok` with `confirmed:false` + `unconfirmable`; or `refusal` + `detail` — per layout-templates §Component — Hero / signature output line (Machine view) and §Component — Primary content block 2 (Exit codes). Whether `--json` lands here or with `:98` is P4's (scope §4).
- TTY detection through std `IsTerminal`; Windows VT output enabled via `SetConsoleMode`, colour off if that fails; styling and column padding through the one hand-written module in the `viola` bin, no colour or table crate — per layout-templates §Surface: cli (Tooling context). Whether `src/human.rs` already carries a stdout/stderr TTY split to extend is research's question (scope CARRY 4).

## Anti-patterns to avoid
- No `Sending…` spinner, no `✓`, no `done`, and `turn-ended` never reported as a send outcome (that is `viola wait`'s result) — per layout-templates §Component — Hero / signature output line (What never happens).
- No human column or field beyond the specified ones: the human words and columns are a stable contract LLM drivers may read; new fields go into `--json` first — per layout-templates §IA notes (Output as a contract).
- No banner, version line or header on `send` output: the only header on any verb is `viola list`'s BAY line — per layout-templates §Component — Header / banner.

## Acceptance criteria contributions
- (layouts) On a TTY a confirmed send prints `[  ] open  <name>  issued <ts>` on stderr then `[RB] read back  <name>  <ts>  cursor <N>` on stdout, word column padded so both lines align column for column, exit 0; with stdout piped the stdout stream holds only the `[RB]` line and no issue line appears (per layout-templates §Output structure — `viola send` and §Component — Hero / signature output line).
- (layouts) Each refusal the chunk produces (`no-prompt-submitted`, `input-not-ready`, `control-character`, one-in-flight) prints `[/ ] unable  <name>  not-delivered  <detail>` on stderr with exit 13, followed by a per-detail `hint:` line as the last stderr line that quotes no sent text, path or pid and names no `viola release`; nothing is written to stdout (per layout-templates §Component — Primary content block 2).
- (layouts) An unmeasured local command prints `[  ] unconfirmable  <name>  local command, no measured post-condition` on stdout with exit 0 (never `[RB]`) (per layout-templates §Output structure — `viola send` and §Surface: cli Signature placement).
- (layouts) No send output carries an SGR sequence, cursor-control byte, non-ASCII glyph, spinner, `done`/`✓` terminator or `turn-ended` outcome; under `--json` (if landed here) stdout is exactly one typed document with no glyph or hint and stderr is empty (per layout-templates §Component — Hero / signature output line and §Surface: cli Expression level).
