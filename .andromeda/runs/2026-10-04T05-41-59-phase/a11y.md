## Relevance
partial: the chunk builds the cli half of Critical Path 2 (the `viola send` `[RB]` readback mirror and its refusals), plus the tui boundary that the paste, the gate and the bounded tee → feed queue must not cross. The web-spa half (`<viola-readback>`, the `status` announcement, axe states `a11y-p2`) is out of scope here because `viola-ui` is not built (scope §Boundaries).

## Constraints
- The cli surface makes no WCAG conformance claim. a11y-plan §1 (Surface: cli) and §4 P6 rank its checks as output-discipline stand-ins for SC 1.3.2, 1.4.1 and 3.3.1, run with `assert_cmd` / `predicates` / `trycmd` and the portable-pty outer PTY on all three OS legs. They are not a11y-tool evidence.
- a11y-plan §4 P2 (cli bullet) requires the `send` mirror to be `[RB]` plus `unable <reason> <detail>` and a final `hint:`, pinned by trycmd. a11y-plan §8 Error recovery (CLI) requires:
  - `unable  <reason>  <detail>` on stderr, with `hint:` as the LAST stderr line and a typed exit code;
  - no hint for `unknown` (exit 14), and no hint for faults (`error: wrapper fault` / `error: internal error`);
  - `--json` is one document with no hint text.
- a11y-plan §1 (Surface: cli → Notes) and §1 A11y triggers (visual-discrimination) require colour to be only a second cue, always beside the word. They also require no SGR, glyph or cursor control under `--json`, non-TTY, `NO_COLOR`, `TERM=dumb` or `viola run`, and output that is static and linear with no spinner or redraw. The readback states `read back`, `unable · <reason> · <detail>` and `unconfirmable` must be carried by printed words (a11y-plan §3 WCAG criteria mapping, row 1.4.1).
  - Whether `src/human.rs` already gates SGR on `IsTerminal` / `NO_COLOR` / `TERM=dumb` is research's question.
- a11y-plan §1 (`viola run` TUI passthrough entity) and §5 Keyboard Navigation (tui) set two requirements:
  - viola writes zero terminal bytes of its own;
  - a human keystroke is never blocked, refused or delayed past the current atomic paste.
  - So the one bracketed paste + Enter, the readiness gate, the one-in-flight refusal and the bounded tee → feed queue's overflow policy (scope §6) must leave the passthrough untouched. Send outcomes reach the driver's `viola send` process only, never the wrapped terminal.
- a11y-plan §8 Consistency and predictability requires `[RB]` on the CLI to correspond to `data-rb="read"` on the web. It also requires every fixed CLI string to be pinned by trycmd, so a copy change fails CI until it is updated on purpose.
- a11y-plan §5 Keyboard Navigation (cli) and §3 Keyboard test harness (cli) treat cli input as non-interactive: stdin / `--file` only, with no prompt, pager or redraw.
- If any human-mode `send` line echoes upstream or event text, a11y-plan §1 (Surface: cli → Notes) requires C0/C1 in it to be escaped except `\n` / `\t`. Whether any `send` line echoes such text is P4's call against layout-templates :405.

## Patterns to follow
- The §4 P6 output-discipline pattern carries over to `send`. Pin the non-TTY modes with trycmd / assert_cmd. Assert the TTY-only behaviours under the portable-pty outer PTY: the `[  ] open … issued` line appears on stderr exactly once and never when piped, and there is no `\r`, cursor-movement or erase sequence (a11y-plan §4 P6).
- Typed exit codes go through assert_cmd. a11y-plan §8 Error recovery (cli) pins exits `10`–`14`, `20` and `21`; `not-delivered` is 13 per scope §4.
- A refusal is written as the plain word `unable` beside the kebab-case reason/detail code (`not-delivered`, `control-character`, `no-prompt-submitted`, `input-not-ready`), never as the code alone (a11y-plan §8 Plain language, §11 Cognitive).
- Timing assertions key on logged events (`send-refused`, `send-issued`), never on sleeps (a11y-plan §10).

## Anti-patterns to avoid
- NEVER colour CLI `unable`, and NEVER emit SGR under non-TTY, `NO_COLOR`, `TERM=dumb`, `--json` or `viola run` (a11y-plan §11 Visual).
- NEVER end a human-mode CLI refusal without a recovery `hint:` line, except `unknown` / exit 14. NEVER let a Problem URN, stack trace or bare code be the only error text (a11y-plan §11 Cognitive).
- NEVER block, refuse or delay a human keystroke in `viola run` past the current atomic paste. NEVER parse the rendered `claude` screen for content or use it as evidence: only the gate verdict leaves the screen model (a11y-plan §11 Keyboard, §11 Universal (R7)).

## Contract bindings
- a11y ↔ tests: the CLI output-discipline checks run inside `nextest-integration` / `nextest-e2e`. In CI they run inside the per-OS `test` job's single `coverage` suite on all three legs, and the epoch-boundary `run --mutants` audit covers them (a11y-plan §3 CI integration, §10).
- a11y ↔ obs: for cli / tui there are no a11y violation rows. Failures surface only as nextest `suites[].failures[]` (a11y-plan §3 Structured violation JSON schema → cli / tui). The `send-issued` / `send-confirmed` / `send-refused` lines carry `corr` = the send `cursor`, unrenamed (a11y-plan §3 Structured violation JSON schema, the inherited obs fields).
- a11y ↔ design / layout: the refusal copy and per-reason `hint:` text come from design's User-Facing Error Surfaces → CLI refusals and layout-templates :405, and are pinned by trycmd (a11y-plan §8 Error recovery, Consistency and predictability).

## Acceptance criteria contributions
- Each `send` outcome has its own trycmd/assert_cmd case (per a11y-plan §4 P2 and §8 Error recovery):
  - a confirmed send prints `[RB] read back … cursor N` on stdout and exits 0;
  - each refusal (`control-character`, `no-prompt-submitted`, `input-not-ready`, one-in-flight) prints `unable not-delivered <detail>` on stderr with `hint:` as the last stderr line, and exits 13;
  - `send --json`, if it lands here, carries no hint text.
- Under non-TTY, `NO_COLOR`, `TERM=dumb` and `--json`, the `send` streams hold no SGR or cursor control, and the `[  ] open` issue line is absent when stdout is piped. Under the portable-pty outer PTY, `unable` carries no SGR, any SGR sits beside its word, and the stream has no `\r` redraw or erase sequence. These checks run on all three OS legs (per a11y-plan §1 Surface: cli and §4 P6).
- A local command without a measured post-condition yields the printed word `unconfirmable` on stdout with exit 0. A confirmed send yields the word `read back`. Neither state is conveyed by bracket glyph or colour alone (per a11y-plan §3 WCAG criteria mapping row 1.4.1 and §1 A11y triggers → visual-discrimination).
- An outer-PTY boundary test asserts that while a send is in flight, is refused, or the tee → feed queue is full, human keystrokes reach the child undelayed past the atomic paste, and viola writes zero bytes of its own to the terminal (per a11y-plan §1 `viola run` TUI entity and §5 Keyboard Navigation tui).
