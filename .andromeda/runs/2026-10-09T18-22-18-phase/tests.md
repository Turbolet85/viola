## Patterns to follow
- Unit rule cases: rstest `#[case::<label>]` tables, function names `<subject>_<condition>_<expected>`, inline `#[cfg(test)] mod tests` in the source file; proptest blocks at `cases: 512` with `proptest-regressions/` committed (per test-plan §4 Conventions; per test-plan §4 Fixture pattern at unit level). Whether the `typed_text` property has a committed regressions file is research's question.
- Measured live shapes as literal oracles: the two shapes read on `claude` 2.1.287 (`after-inner-crlf`, `after-inner-cr`) go into the table as literals labelled with their measuring chunk, the way the last-newline and wrapped-paste shapes are pinned (per test-plan §4 viola-agent-claude, the `prompt_text_live_shape_normalises_as_measured` precedent).
- Wrapper `send` unit cases in `src/run/send.rs`: the existing trailing-newline tests take LF, CR and CRLF tails as rstest cases under the injected `viola_core::Clock`; the inner shapes extend that pattern (inner text pasted with LF, prompt claimed, send confirmed, wheel left with the driver), and a prompt that still carries the CR claims nothing stays as the negative (per test-plan §4 root bin).
- Driver-visible outcome: a case beside `send_text_ending_in_newlines_is_typed_without_them_and_confirmed` in `tests/cli_send.rs`, on the rstest chain `home → fake_agent_path → stamped_home → booted_wrapper`, waiting on `events.ndjson` byte offsets and reading live-appended files through the complete-lines reader (per test-plan §6 Path 2; per test-plan §3 `run`; per test-plan §2 Test Strategy, Agent-runnable invariants).
- Test commands the implementation must pass: `scripts/agent-run.sh run --unit`; `scripts/agent-run.sh run --integration --filter 'binary(cli_send)'` (or a `test(/…/)` filterset) for the one file; `scripts/agent-run.sh run --coverage` then `gate --require coverage,doctest,playwright` as the per-OS job's shape; the operator's `pre-push` as the local Linux gate (per test-plan §3 `run`; per test-plan §3 `gate`; per test-plan §3 `pre-push`; per test-plan §9 Pipeline structure).

## Anti-patterns to avoid
- NEVER treat a green fake-agent run as proof of real-CLI behaviour, and never run the real `claude` in CI: the chunk's two live starts are a route entry's own local measurement, recorded as evidence, never a suite and never a CI step (per test-plan §11 Test Strategy).
- NEVER import the product's own rule or refusal ordering as the test oracle: the expected typed texts, `text_bytes` values and refusal details are literals in the test, never computed by calling `typed_text` on the input (per test-plan §11 Unit).
- NEVER assert at a higher layer a case a lower layer can hold, and never synchronise with a sleep or a test-owned timer: the rule's shape table belongs in §4, the cross-process case asserts only the cross-process outcome, and the confirmation window is clock-driven at unit tier (per test-plan §11 Test Strategy; per test-plan §11 E2E; per test-plan §11 Universal).

- tests ↔ obs gates: the new cases' homes sit under `target/e2e-home`, inside G2, G4 and the secret scan; the sent texts are synthetic only (per test-plan §5 Setup / teardown lifecycle; per test-plan §7 Fixture hygiene).
- tests ↔ security: validation runs first on the text as received at both the client and the wrapper (Vector 2); the wrapper half is `tests/channel_paste_validation.rs`, the client half `tests/cli_*.rs` (per test-plan §5 Cross-module patterns, Wrapper channel). security-plan §Input Validation owns the rule's wording.
- tests ↔ architecture: the matcher and the typed-text rule are architecture [Delivery Confirmation]'s contract; test-plan §4 and §6 Path 2 restate it and follow its amendment at the wrap.
- tests ↔ capability ledger: test-plan §11 Test Strategy ties a real-CLI behaviour change to a local `viola verify` fixture refresh plus the contract suite. The scope plans no ledger row, no probe and no fake-agent change; whether `contract_fake_agent_drift` or any recorded framing variant is touched by the change is research's question.
