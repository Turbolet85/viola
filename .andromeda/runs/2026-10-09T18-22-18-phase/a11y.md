# a11y extract

## Relevance
partial — the chunk adds no web-spa markup, role, token or announcement; it changes the text `send` types, which sits on the cli half of path P2 and on the cli and tui-boundary halves of path P4 (a11y-plan §1 Critical paths 2 and 4), both carried with no WCAG conformance claim.

## Constraints
- a11y-plan §1 (CLI and terminal entities → `viola run` TUI passthrough, boundary-only) requires that a human keystroke is never blocked, refused or delayed past the current atomic paste. The typed text with its inner CR and CR LF turned to LF must still reach the child as that one atomic paste; whether the paste site stays one write once the typed text is no longer a slice of the received text is research's question.
- a11y-plan §4 (Must-be-accessible path scenarios → P4, tui clause 1) requires zero viola-originated bytes on the outer-PTY stream across a start, a driver `send`, a refused automation send and exit. The rule change may alter only what is written to the child's input; it adds no viola literal, SGR or cursor control to the terminal.
- a11y-plan §8 (Error recovery → CLI) requires every human-mode refusal as `unable <reason> <detail>` on stderr, a `hint:` line last, a typed exit code, and one `--json` document with no hint. The chunk keeps `not-delivered` / `empty-text` (exit 13) for a text of only CR and LF characters; its line layout and hint stay as pinned. Whether a trycmd case already pins that refusal's text is research's question.
- a11y-plan §8 (Plain language → Verification) requires every fixed CLI string to be trycmd-pinned, so a copy change fails CI until the pin is changed on purpose. The chunk plans no refusal detail and no hint change; a doc-comment or message edit that touches a pinned CLI string is a deliberate pin change, not a side effect.
- a11y-plan §4 (Must-be-accessible path scenarios → P6, C0/C1 escaping) requires human-mode `wait` / `last` text to show every C0 and C1 control escaped except `\n` and `\t`, which stay raw. CR is a C0: where a sent text is echoed by any human-mode verb, a CR would print escaped and an LF raw. Whether any human-mode output carries the typed text (so that the change moves a line from the escaped form to a raw newline) is research's question.
- a11y-plan §2 (Agent-runnable invariants) requires that no WCAG conformance claim rests on cli or tui checks: the chunk's tests are output-discipline and boundary assertions only, and its live session is not a11y evidence.
- a11y-plan §3 Structured violation JSON schema (cli / tui) requires that cli and tui checks write no a11y row; a failure surfaces only as a nextest failure in `suites[].failures[]`.

## Patterns to follow
- The tui boundary is three portable-pty outer-PTY nextest cases, one per boundary clause, on all three OS legs, with the tests' fake agent as the child (per a11y-plan §3 Keyboard test harness → Tooling; a11y-plan §4 → P4). A wrapper-tier test for the inner outcome sits beside them, not in a new harness.
- Sequencing in those cases is on the wrapper's `channel-request` line and the `wheel` record, never a timer, and the wheel is probed by an `answer` to no pending dialog (exit 13 driver, 10 human) (per a11y-plan §3 Keyboard test harness → Tooling). A new test that asserts "the wheel left with the driver" reads it the same way.
- CLI refusal text is pinned by trycmd and typed exit codes by assert_cmd, on all three OS legs (per a11y-plan §8 Error recovery → Verification).
- cli and tui checks run inside `nextest-integration` / `nextest-e2e`, in CI the per-OS `coverage` suite, and the epoch-boundary mutation audit covers those that live in crate tests (per a11y-plan §9 Per-pipeline-stage a11y artifacts; a11y-plan §10 Standard+ invariants).
- Manual screen-reader and keyboard passes on cli and tui are supplemental and founder-owned (per a11y-plan §7 Per-surface SR test pattern); the chunk owes none and its headless live session does not stand in for one.

## Anti-patterns to avoid
- NEVER block, refuse or delay a human keystroke in `viola run` past the current atomic paste (per a11y-plan §11 Keyboard): the CR-to-LF rule must not split the paste or add a wait before it.
- NEVER parse the rendered `claude` TUI screen for content or take screenshots as a11y evidence (per a11y-plan §11 Universal): a test or a live reading that checks the typed or submitted text for the absence of a CR reads events, records or the fake agent's own input, not screen content.
- NEVER colour CLI `unable` / `fail`, and never emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run` (per a11y-plan §11 Visual): unchanged by the chunk, and no new send-path output may break it.

## Contract bindings
- **a11y ↔ tests:** the cli and tui checks ride the tests' own suites and tiers, with no `a11y` suite value and no second driver (a11y-plan §9 Pipeline integration ↔ test-plan §3 harness, test-plan §4 tiers, test-plan §10 mutation audit). The chunk's new tests land in those suites.
- **a11y ↔ obs:** the web readback state and its polite refusal announcement are driven by `send-issued` / `send-confirmed` / `send-refused` joined on `corr` (a11y-plan §1 Critical paths 2 → Source; a11y-plan §7 Live regions, message 2 ↔ obs-plan event catalog). After the chunk a send with an inner CR or CR LF is expected to end `send-confirmed`, so the page shows `read back` and announces no refusal for it; no page code changes, and a11y-plan §11 Universal (the page shows only what hooks and the wrapper observed) is the rule that outcome serves.
- **a11y ↔ design / layouts:** the CLI refusal line and hint copy are design's and the layout's (a11y-plan §8 Error recovery ↔ design-system cli, layout-templates cli); the wrap's expected amendment to layout-templates must leave every trycmd-pinned string equal to its master text.
- **a11y ↔ security:** the C0/C1 escaping rule of human-mode CLI output is security's (a11y-plan §4 → P6 ↔ security-plan §Input Validation); `validate_paste_text` stays the gate on the text as received.

- (a11y) The chunk adds no a11y row, no `suite` value and no conformance claim for cli or tui; its failures appear only as nextest failures (per a11y-plan §3 Structured violation JSON schema → cli / tui; a11y-plan §9 Pipeline integration).
