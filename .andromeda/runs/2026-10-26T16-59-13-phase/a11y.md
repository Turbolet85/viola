# a11y extract

## Relevance
partial — the chunk is security hardening, but the strict-modes checks it adds before the home is opened create new human-facing CLI refusals (`send`, `wait`, `last`, `answer`, `pause`, `release`, `verify`, `run`). They also touch the `viola run` TUI boundary and the fail-open plugin path. Viola's own output discipline binds all three.

## Constraints
- a11y-plan §8 Cognitive Accessibility › Error recovery requires every new human-mode refusal to follow one layout: `unable  <reason>  <detail>` on stderr, then `hint:` as the last stderr line, with a typed exit code and stdout empty. Under `--json` it is one document with stderr empty and no hint. The existing strict-modes refusal of `viola link` / `viola unlink` is the precedent: exit 21, the fixed instance-state `unable` / `hint:` pair, and under `--json` exactly `{"v":1,"error":"instance-unreachable","detail":null}`. Research decides whether the six frame verbs already print this on a strict-modes failure. Choosing the refusal code is outside a11y's authority (design and security own it).
- a11y-plan §1 A11y Scope Summary (CLI-verbs entity, scope-surfaces) requires refusal pairs to be plain ASCII. They carry no SGR, glyph, cursor control or ESC byte under `--json`, non-TTY, `NO_COLOR` or `TERM=dumb`. Output is static and linear.
- a11y-plan §1 A11y Scope Summary (tui entity) requires the following for `viola run` and a passed `viola revive`. Once the child holds the terminal, viola writes zero bytes to it except the child's output, and `run`'s diagnostics go to `diagnostics/`, never the terminal. The new checks are the home, `instances/<name>/`, `bin/`, `plugin/` and `ui/` checks, the pinned-binary re-hash, the per-start plugin rewrite and the DACL check before any diagnostics file. Each one must either refuse before the child starts or stay silent.
- a11y-plan §1 A11y Scope Summary (plugin entity, not-assertable) requires a `viola hook` call that meets a refused check to fail open. That means exit 0, empty stdout and stderr, and no human-facing byte, so the entity stays not-assertable. An MCP frame tool returns `isError` with a code only.
- a11y-plan §11 A11y Anti-Patterns § Keyboard requires that no human keystroke in `viola run` (or a passed `viola revive` start) is ever blocked, refused or delayed past the current atomic paste. A strict-modes refusal goes to automation only.
- a11y-plan §8 Cognitive Accessibility › Plain language requires every new fixed CLI string to be pinned by trycmd or by literal, so a copy change fails CI. This covers any new `hint:` copy and any `verify` stamps-read refusal text.
- a11y-plan §11 A11y Anti-Patterns § Cognitive requires every human-mode refusal except `unknown` to end with `hint:`. A kebab-case code never appears without the plain word `unable`, and a stack trace is never the only error text.

## Patterns to follow
- The fixed instance-state pair and its strict-modes witnesses, per a11y-plan §8 Cognitive Accessibility › Error recovery:
  - `link_verbs_refuse_a_widened_instance_before_any_log` (`tests/cli_links.rs`): refused before any log, the mode read back as found.
  - `list_refuses_*` and `plugin_install_refuses_a_widened_home`.
  - The unit `instance_and_home_state_pairs_are_the_fixed_texts`.
- The both-mode CLI negative over many verbs, per a11y-plan §8 Cognitive Accessibility › Error recovery: `security_negative_cli_verb_writes_no_frame_to_a_server_that_is_not_the_recorded_wrapper` (`tests/security_negatives_server_identity.rs`). It checks the hint last with no ESC byte and stdout empty, or under `--json` the exact document with stderr empty, and that no output holds a pid, path or endpoint. A strict-modes negative over the six frame verbs can take the same shape.
- The outer-PTY zero-viola-bytes cases, per a11y-plan §3 Keyboard test harness: `passthrough_with_a_statusline_source_adds_no_viola_bytes` (`tests/tui_passthrough.rs`) and the `tests/chaos_revive.rs` reading that a passed start writes no `unable` or `hint:` line while the child holds the terminal.
- The hook fail-open impostor rows in `tests/hook_fail_open.rs`, per a11y-plan §1 A11y Scope Summary (plugin entity): exit 0, empty stdout and stderr, under 1.0 s.

## Anti-patterns to avoid
- Colouring `unable` / `fail`, or emitting SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run` / a passed `viola revive`, in any new refusal (per a11y-plan §11 A11y Anti-Patterns § Visual).
- Letting a home, DACL or re-hash check block, refuse or delay a human keystroke, or write a viola byte to the terminal the child holds (per a11y-plan §11 A11y Anti-Patterns § Keyboard).
- Adding a `suite` value or a separate driver for these cases outside `scripts/agent-run.* run` (per a11y-plan §11 A11y Anti-Patterns § CI).

## Contract bindings
- a11y §8 Error recovery ↔ design-system §Surface: cli. Design owns the instance-state pair's text; a11y owns its layout (`hint:` last, plain ASCII, empty stdout, hint-free `--json`).
- a11y §8 Error recovery ↔ security-plan §Error Handling. A refusal holds codes and fixed text only, never a path, pid or endpoint.
- a11y §3 Keyboard test harness and §9 CI Integration ↔ test-plan §9. The CLI-refusal and outer-PTY boundary cases run inside the per-OS `test` job's `coverage` suite on all three OS legs.
- The strict-modes witnesses named in a11y §8 are `cfg(unix)`. Whether the Windows DACL refusal gets a CLI-output reading on `windows-2025` is research's question.

## Acceptance criteria contributions
- For each of `send`, `wait`, `last`, `answer`, `pause` and `release` against a home or instance that fails the strict-modes check: exit 21, stdout empty, the fixed `unable` / `hint:` pair on stderr with `hint:` last and no ESC byte, and no output holding a path, pid or endpoint. Under `--json`, the one exact document with stderr empty and no hint. (per a11y-plan §8 Cognitive Accessibility › Error recovery)
- A `viola run` start that passes the new home, `bin/`, `plugin/` and DACL checks adds none of viola's own literals (`unable`, `hint:`, diagnostics) to the outer-PTY stream, and a human key still reaches the child. (per a11y-plan §3 Keyboard test harness)
- `viola hook` against an instance that fails the strict-modes check exits 0 with empty stdout and stderr. (per a11y-plan §1 A11y Scope Summary)
- Every new refusal or hint string this chunk introduces (the `verify` stamps-read refusal included) is pinned by trycmd or by literal. (per a11y-plan §8 Cognitive Accessibility › Plain language)
