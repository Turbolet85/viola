# security extract

## Relevance
relevant — the chunk adds a ledger row that moves the stamp's relied set (what gates dialog answering), widens `viola verify`'s interactive child set or Run B's compiled pastes, records a new fixture, and carries a live plugin round whose trust-dialog method touches `~/.claude.json`.

## Constraints
- The ledger and its stamp are the control that switches on non-`null` dialog decisions: per security-plan §Security Anti-Patterns (Universal), a non-`null` decision flows only when every row of `LedgerRow::relied()` passes on a `viola verify` stamp, and that bullet enumerates the twenty-three rows and the `/23` (Unix) and `/20` (Windows) counters by name. A 24th row relied on every OS therefore means a stamp holding exactly the twenty-three ids of a stamp written before this chunk reads `cli_verified:false` (hook prints nothing, `answer` exits 12 `unverified-cli`). The bullet's row list, counters and pre-chunk stamp shapes are amended in the same chunk, never left at 23.
- `ledger/stamps.json` is written only by `viola verify`, under its `.lock`, at 0600 (per security-plan §Data Protection, Code-bearing artefacts); per security-plan §Security Anti-Patterns (Universal) no other process may write it, and the `/compact` post-condition is gated on the stamp the way `/clear`'s `NewSession` is, never on a runtime reading.
- `viola verify`'s interactive children are enumerated and closed: per security-plan §Threat Model Summary (Child process spawning and PATH resolution), exactly five children (A to E), Run B's five compiled bracketed pastes (each into rows holding the input-box literal and no modal literal, none after a stop), eight spawn pairs on an uninterrupted verify, no byte into any dialog, a modal start killed with no key. A `/compact` paste in Run B or a new start is a widening of that enumerated set and needs the founder's own word before it lands (it is held under `inputs#I1`); the paste, if ruled in, is a compiled literal.
- Per security-plan §Data Protection (Accepted risk, verify's trusted runs), Run B's transcript count under `~/.claude/projects/` is a measured, accepted class (two per real-CLI verify); whether a compaction inside Run B adds a transcript or changes that count is unmeasured, and the accepted-risk text is amended only from a measurement. viola itself writes nothing under `~/.claude` (same section).
- Per security-plan §Data Protection (Dev-host prerequisite), the one `~/.claude.json` edit on the dev host (the external-imports flags) was the founder's amended live ruling; a further write to `~/.claude.json` (a trust record for a plugin rig's root) is not covered by it and is the founder's fork. Per security-plan §Data Protection (Accepted residual, a live round of `viola plugin install`), the plugin round's residual is the CLI's own `~/.claude` writes from a rig under `target/` that is its own git repo, with viola writing nothing under `~/.claude`.
- Per security-plan §Input Validation (Paste text row), the local-command classification reads the typed text (a listed command followed by LF, CR or CRLF is that command), and per security-plan §Security Anti-Patterns (Code Patterns) the local-command list comes only from compiled `viola-agent-claude` ledger rows, never runtime or upstream text, so `/compact`'s post-condition is attached to the compiled list entry.
- Per security-plan §Input Validation (Hook stdin row), hook payloads are parsed tolerantly but fields that decide behaviour map into closed enums in `viola-agent-claude`; the SessionStart cause `compact` and the same-session comparison read upstream payload fields. Whether the cause is already a closed enum member and how the session id is compared (per security-plan §Input Validation, Session id row: the closed `is_session_id` shape) is research's question.

## Patterns to follow
- The `/clear` row's shape: a compiled `LOCAL_COMMANDS` entry, its `NewSession` post-condition gated on the stamp, its probe a compiled Run B paste (security-plan §Threat Model Summary, Child process spawning; §Security Anti-Patterns, Code Patterns).
- Run E's precedent for a widened verify set: a founder's own P4 answer recorded verbatim with the run's bounds (empty input, no key, killed, its own 0700 dir removed by its guard) and the transcript residual measured before the accepted-risk text moves (security-plan §Threat Model Summary; §Data Protection, Accepted risk).
- `--record` fixtures through the scrub: synthetic probe prompts, home prefix and user word rewritten, the whole recording refused with a named file and a closed code (`home-path` · `absolute-path` · `username` · `email`) (security-plan §Data Protection, Repository fixtures).
- A send outcome or refusal leaves the process as a closed code only, no session id, path or upstream text (security-plan §Error Handling, External responses).

## Anti-patterns to avoid
- Typing any byte into a CLI-native dialog (trust, external imports) from `viola verify`, or continuing a probe past a modal by a key (security-plan §Threat Model Summary, Child process spawning; §Security Anti-Patterns, Universal: refusals and controls never bypassed).
- Building the `/compact` entry, its confirm signal or a screen signature from runtime or upstream text (security-plan §Security Anti-Patterns, Code Patterns).
- A logged or captured session id, SessionStart payload or compaction summary reaching an external error, a fixture outside the scrub, or a log line beyond `diagnostics/` (security-plan §Security Anti-Patterns, Logging; §Error Handling).

## Contract bindings
- security ↔ arch: the relied-set count and the pre-chunk stamp shapes appear in architecture.md CLI Version Compatibility as well as security-plan §Security Anti-Patterns (Universal); both move together.
- security ↔ tests: the new `SessionStart.compact-<n>.json`-class fixture under `fixtures/claude/2.1.287/` binds to the fake agent's replay and to the `--record` scrub (security-plan §Data Protection, Repository fixtures).
- security ↔ obs: an uninterrupted verify's spawn-pair count (eight) is enumerated in security-plan §Threat Model Summary; a new start changes the obs spawn-pair expectation.

## Acceptance criteria contributions
- A stamp holding exactly the twenty-three pre-chunk ids, all `pass`, reads `cli_verified:false` on every OS, and the hook prints no decision body for it (per security-plan §Security Anti-Patterns, Universal).
- `viola verify` against the fake agent types no byte into any modal and adds no child, paste or spawn pair beyond the founder's recorded answer (per security-plan §Threat Model Summary, Child process spawning and PATH resolution).
- A recorded fixture for the new row passes the `--record` scrub with no `home-path` / `absolute-path` / `username` / `email` refusal, and its prompt is a compiled synthetic literal (per security-plan §Data Protection, Repository fixtures).
- No viola process writes under `~/.claude` (including `~/.claude.json`) during the chunk's live rounds; any such write stands only on the founder's own word (per security-plan §Data Protection, Dev-host prerequisite and Accepted residual).
