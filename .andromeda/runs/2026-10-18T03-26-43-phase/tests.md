## Relevance
relevant — the chunk adds a ledger row with a `viola verify` probe, a second local-command post-condition and a new confirm window, each with test-plan mandates at the unit, CLI-integration, contract and `--local-live` layers (tier Comprehensive, per test-plan §1 / §10).

## Constraints
- test-plan §1 (multi-version-compat trigger) requires every ledger row to have a `viola verify` probe with a post-condition (local run, exit code plus the `stamped … pass … fail` line). A 24th row with no probe arm does not meet it.
- test-plan §5 (CLI: `tests/cli_verify.rs`, `contract_ledger_probes.rs`) requires one `[NN/MM] <row id> …  pass|fail` step line per relied row, with `MM` the relied count, and the `ROW_IDS` / `STEPS_PASS` arrays as per-OS literals under `cfg(unix)` / `cfg(windows)` (today `[&str; 23]` and `[&str; 20]`). `contract_ledger_probes.rs` must list each relied id exactly once and end `stamped <ver>  <n> pass  0 fail`, `<n>` equal to the literal row count. A relied row moves every one of these literals, along with the documented fail counts for runs without the dialog or framing replay. Which counts move is research's question once the probe's placement is fixed.
- test-plan §3 `run` (`--local-live`) requires the harness literal `LEDGER_ROWS` (`[&str; 23]` under `cfg(unix)`, the 20-id form under `cfg(not(unix))`, spelled so) and `LIVE_PASS` to name each relied row id. Both are unit-proven per OS by `harness::run::tests` `run_local_live_reads_the_relied_rows`. A 24th relied row extends both per-OS forms.
- test-plan §4 (root bin, local-command decision) pins `/compact` as "no measured post-condition → `unconfirmable` with no window". The `send_local_command_*` functions in `src/run/send/classify.rs`, whose `#[case]` rows are the count, cover `/clear`'s post-condition: confirmed only by a `session-start` of cause `clear` with a new id, never by a `prompt-submitted` or another `session-start`, and its window expiry gives `no-prompt-submitted` with the cursor. The compact arm needs its own counterparts: confirmed only by cause `compact` with the SAME id, no claim from another cause or another id, its own window expiry, and an unverified CLI staying `unconfirmable`.
- test-plan §11 Universal allows an E2E case to block on a product deadline only when the verdict is the product's own exit code or status field and the same deadline is clock-driven in a §4 unit case. The new compact confirm window therefore needs a clock-driven unit case at its boundary instants. Following the 8.5 s gate bound, the refusal at the bound stays unit-tier only (test-plan §6 Path 2).
- test-plan §7 (Recorded hook payloads; Fixture hygiene) requires a new variant, such as a `SessionStart` of cause `compact`, to be recorded only by live `viola verify --record`, scrubbed and `unclean`-checked, written only when 0 rows fail, and walked by `tests/contract_fixture_hygiene.rs` against its schema. The fake agent fires it only as a recorded variant, its bytes unchanged (the `--framing` pattern).
- test-plan §10 (Zero-flakiness budget; Coverage thresholds) requires nextest `retries = 0`, with no `#[ignore]` and no quarantine outside the chunk. Per-OS gates are `--fail-under-lines 85 --fail-under-functions 95 --fail-under-regions 80`.

## Patterns to follow
- The `/clear` row end to end: the ledger arm's named cases `check_local_command_clear_fails_on_each_broken_post_condition` (beside `check_framing_rows_pass_on_the_recorded_shape` / `check_paste_rows_fail_without_a_matching_capture`), the send arm `send_clear_on_a_verified_cli_is_confirmed_by_its_new_session` on the recorded 2.1.287 `clear-1` variants, and the classify cases above (per test-plan §4 viola-agent-claude ledger arms; test-plan §6 Path 2 `local` signal).
- A ledger arm's three-way case shape: a pass on the recorded shape, a fail on each broken post-condition, a fail with no capture. Examples are the `check_resume_session_*` cases (five, `test(/check_resume_session_/)`) and `check_agents_join_*` (per test-plan §4 viola-agent-claude).
- The relied-set cases `relied_rows_drop_the_three_statusline_rows_where_the_status_line_is_not_wrapped` and `verified_reads_a_failed_statusline_row_by_the_relied_set`, plus the version gate's older-stamp oracle in `src/run/version_gate.rs`: an all-`pass` stamp of the older ids reads unverified (per test-plan §4 viola-agent-claude).
- If the probe adds a run or start: `verify_stopped_during_the_resume_run_removes_its_dir_and_exits_1` (cfg(unix), `sigint` / `sigterm`) and the eight spawn pairs closed by an uninterrupted verify (per test-plan §5 CLI `tests/cli_verify.rs`). If it adds a Run B paste: `verify_pastes_no_local_command_once_the_tag_turn_screen_shows_a_modal` (also test-plan §5 CLI).
- The contract replay of a recorded variant set, modelled on `fake_agent_resume_replay_matches_every_recorded_resume_set` (per test-plan §1 contract-test-against-sandbox).

## Anti-patterns to avoid
- Never import the product's `LedgerRow::ALL` / `relied()` or row ids as the test oracle; the ids and counts are test literals (per test-plan §11 Unit). Never treat a green fake-agent run as proof of real-CLI `/compact` behaviour, or a Linux-only reading as proof for Windows (per test-plan §11 Test Strategy).
- Never run the real `claude` or a live `viola verify` in CI. The live stamp goes only through `agent-run run --local-live`, which refuses under `CI` (per test-plan §11 Test Strategy; test-plan §3 `run`).
- No test-owned `sleep` or elapsed-time verdict to wait out the compact window, and no hand-written `ledger/stamps.json` or fixture: stamps come from `viola verify` against the fake agent (per test-plan §11 E2E / Universal / Test Data).

## Contract bindings
- tests ↔ security: the probe's placement (a sixth Run B paste or a new start) is bounded by security-plan's verify child set and live-start cap (scope's held forks). Test literals (step counts, spawn-pair count, stop cases) follow whichever is ruled (test-plan §5 CLI `tests/cli_verify.rs`).
- tests ↔ obs: an uninterrupted verify's spawn-pair count (`version-probe`, `verify-probe`, five `verify-pty-probe`, one `agents-probe`) and the role log validated against `schemas/diag-line.v1.json` bind to obs-plan §4 (test-plan §5 CLI). The `send-issued` → `send-confirmed{confirmed}` records the compact arm asserts bind to the events catalog (test-plan §6 Path 2).
- tests ↔ harness: `LEDGER_ROWS` / `LIVE_PASS` in `viola-harness` are the `--local-live` suite's oracle (test-plan §3 `run`).
