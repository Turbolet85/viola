## Relevance
relevant — the chunk lands a second local-command post-condition in `send`, a new compiled confirm bound, a 24th relied ledger row with its `viola verify` probe and fixtures, and takes the two plugin readings arch §Established Decisions names as owed to this very route entry.

## Constraints
- A listed local command whose measured post-condition is met returns `ok` confirmed. A command whose post-condition is "none", or "not yet measured on this CLI version", returns `ok` `{confirmed:false, detail:"unconfirmable"}` at once, with no window. Nothing else may ever be unconfirmable, and the decision rests on the ledger, never on a leading slash. So `/compact` has to stay `unconfirmable` at once on any CLI whose `cli_verified` is false, and the verified bit comes only from the version gate's `cli_verified` handed to `SendSlot::new`; the send path reads no `ledger/stamps.json` (per architecture §Established Decisions [Delivery Confirmation]).
- The `/compact` post-condition is set as a SessionStart of source `compact` carrying the SAME `session_id`, with a confirm window of its own beyond the 10 s `CONFIRM_WINDOW_FALLBACK`. This is the reverse of `/clear`'s rule, where the id must differ from the one the slot remembers (per architecture §Established Decisions [CLI Version Compatibility], Local commands row). The remembered id is the `agent_session_id` of the last `session-start` the tap took, of any cause. It is held in memory under the in-flight send's lock and never persisted. A line with no string id clears it. P3 and P4 must answer what an equality claim does when nothing is remembered (per architecture §Established Decisions [Delivery Confirmation]).
- The confirm window is a compiled constant in `viola_agent_claude::screen`. It never lives in `config.json`, and `run` reads no window number from the stamp (per architecture §Established Decisions [Delivery Confirmation]). `run` also reads no field of the stamp's `measured`, so a compact bound cannot come from a recorded reading at runtime (per architecture §Standard Contracts → Ledger stamps envelope).
- `send` blocks for at most the readiness gate's wait plus the paste plus the window, and returns by the time the window closes. On the MCP surface that total must stay below the MCP client's tool-call timeout, measured above 50 s on claude 2.1.287. A longer compact window has to keep 8.5 s + paste + window under that ceiling (per architecture §Established Decisions [Delivery Confirmation]).
- Any new reliance on an undocumented `claude` behaviour is a ledger row in `viola-agent-claude` with a `viola verify` probe that checks a post-condition. It is never an unconditional assumption. The ruled limit (a shape no `send` relies on needs no probe) is the only reason `/compact` has no row today. Once `send` confirms on the compact SessionStart, that limit no longer covers it (per architecture §Cross-cutting Patterns → Capability ledger as the single gate for CLI-specific behaviour).
- A version counts as verified only when every row of `LedgerRow::relied()` reads `pass`. `rows` maps row id to `pass` or `fail`. A merge replaces only its own version's entry and keeps unknown versions and fields. `measured` stays additive with no `v` bump (per architecture §Standard Contracts → Ledger stamps envelope). The ledger is a closed set in `LedgerRow::ALL` order, and the relied set is `ALL` filtered by `relied_on(row, statusline::WRAPPED_HERE)` (per architecture §Established Decisions [CLI Version Compatibility]).
- `viola verify`'s child set is fixed: one print-mode probe plus Runs A–E, plus Run B's one agents read. Each widening is recorded as the founder's own answer. Run B's pastes are compiled literals typed only into a settled input box. No run types a byte into a CLI dialog, and a start showing a modal is killed with no key. A compacting paste or a new start therefore widens that set (per architecture §Established Decisions [CLI Version Compatibility]; the same run list is in architecture §Established Decisions [Plugin Scope]). Claude-specific shapes (the `compact` source word, the post-condition) stay in `viola-agent-claude`, and the wrapper's slot sees only normalised `session-start` `{cause, agent_session_id}`, where `compact` is already one of the closed causes (per architecture §Conventions → Hook → kind map; architecture §Inherited Defaults → Agent isolation).

## Patterns to follow
- The `/clear` row as the template. It is a `LOCAL_COMMANDS` entry carrying its post-condition and the row `local-command-clear`, probed by Run B's compiled `PROBE_LOCAL_COMMAND` paste. That paste waits one more turn in `ledger::FRAMING_TURNS` (stem `clear-1`), and `--record` writes its `SessionEnd.clear-<n>.json` / `SessionStart.clear-<n>.json` variants through `ledger::framing_variants` (per architecture §Established Decisions [CLI Version Compatibility]).
- The hook-tap claim order. The tap claims the matching `session-start`, appends that line unchanged, and only then settles the send with that line's `ts` as `submitted_at`, so `session-start` precedes `send-confirmed` in `events.ndjson`. A window that closes first ends `not-delivered` / `no-prompt-submitted` with its cursor and no new detail (per architecture §Established Decisions [Delivery Confirmation]).
- CI coverage through the fake agent's `--framing` mode. A probed local command fires its recorded variant, and a new stem is reached through `ledger::framing_stem` with no option added. `--record` writes variants only when 0 rows fail, scrubbed and hygiene-walked, and the committed `2.1.287` set's file count carries its `ls` rule (per architecture §Occupied Resources → Binary, subcommands and exit codes (test-only `viola-fake-agent`); architecture §Occupied Resources → Repository).
- How a row lands. A live round on the Linux dev host records `stamped 2.1.287  N pass  0 fail` in `evidence/live-round.md`, a row relied on every OS says so, and its Windows reading is owed on "Windows-only live measurements". If the probe needs its own start, Run E is the model: its own 0700 `<cwd>/.viola-verify-<pid>-<suffix>/` with a drop guard, reading Run B's first SessionStart capture through `ledger::resume_target`, no key typed (per architecture §Established Decisions [CLI Version Compatibility]; architecture §Cross-cutting Patterns → Capability ledger as the single gate for CLI-specific behaviour).

## Anti-patterns to avoid
- Confirming `/compact` on a CLI not verified for the new row, or on a bare cause match without the same-id check. Both hard-code an unstamped CLI shape (per architecture §Cross-cutting Patterns → Capability ledger as the single gate for CLI-specific behaviour; architecture §Established Decisions [Delivery Confirmation]).
- Making the compact bound a `config.json` key, an env var, or a value read from the stamp's `measured`, or widening the shared `CONFIRM_WINDOW_FALLBACK` for every send instead of a bound for the compact post-condition alone (per architecture §Established Decisions [Delivery Confirmation]; architecture §Standard Contracts → Ledger stamps envelope).
- Adding a verify paste or start, or a keystroke into the folder-trust dialog, as a plan step with no founder ruling. Every existing child carries his named answer (per architecture §Established Decisions [CLI Version Compatibility]; architecture §Established Decisions [Plugin Scope]).

## Acceptance criteria contributions
- On a CLI whose stamp passes the new row, a `send` of `/compact` is confirmed only by a `session-start` of cause `compact` whose `agent_session_id` equals the remembered id. That line comes before `send-confirmed {cursor}`, and no `prompt-submitted` claims it. On an unverified CLI the same `send` still ends `unconfirmable` at once, with no window (per architecture §Established Decisions [Delivery Confirmation]).
- `LedgerRow::ALL` holds 24 rows, and the new row has a `viola verify` probe that checks a post-condition. If the row is relied on every OS, verify's step lines end `[24/24]` on Unix and `[21/21]` on Windows, and an all-`pass` stamp of the twenty-three pre-chunk ids reads unverified on every OS (per architecture §Standard Contracts → Ledger stamps envelope).
- The compact bound is a compiled constant in `viola-agent-claude`, used only by the compact post-condition. `CONFIRM_WINDOW_FALLBACK` stays 10 s for every other send (per architecture §Established Decisions [Delivery Confirmation]).
- `send`'s worst-case blocking total for `/compact` (`GATE_MAX_WAIT` 8.5 s + paste + compact window) stays below the MCP client's tool-call timeout, measured above 50 s on 2.1.287 (per architecture §Established Decisions [Delivery Confirmation]).
