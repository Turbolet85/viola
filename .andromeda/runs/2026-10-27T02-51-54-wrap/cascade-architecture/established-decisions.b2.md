### established-decisions#21.1 · values · dec-budget-governor · ## Established Decisions · lines 172–174
- **[Budget Governor] Soft stop at the turn boundary.** Once a configured threshold is crossed (defaults `five_hour` ≥ 90 %, `seven_day` ≥ 85 %), automated `send` is refused with `budget-paused` through the same refusal path as `human-typing`. Human keys are never blocked, and a running turn finishes. The pause lifts when `resets_at` passes or on `viola release --budget`. `release --budget` leaves the wheel where it is, and a plain `release` returns the wheel to `driver` without lifting a budget pause. `release --budget` is sent to one instance's wrapper and lifts the pause for that instance only, until the crossed window's `resets_at` passes, so the next over-threshold reading does not re-pause it. The wrapper evaluates its gate from `budget.json`, read under `budget.json.lock`, at three points: at start, when a `send` arrives, and at each `turn-ended`. It never polls. A crossed threshold, a passed `resets_at` or an expired override takes effect at the next of these points, and only then is `budget-gate` appended. So a snapshot can still read `budget_paused: true` after the reset, until a `send` arrives or a turn ends, and every surface that shows the snapshot inherits that. The wrapper mirrors its budget-pause state, including any override, to the instance snapshot, where `list` reads it. As landed (chunk 2026-10-10-budget-governor; `src/run/budget.rs`, one `BudgetGate` per wrapper, no thread and no timer): a window is crossed only when its `used_percentage` is known and at or above its threshold and its `resets_at` is known, parses as RFC 3339 and is later than now, so a window whose `resets_at` is `"unknown"`, unparseable or passed never pauses. With both windows crossed the refusal names `five-hour`.
 The `send` point sits after the text refusals and the first `human-typing` read and before the running-turn read, so the order is `control-character` → `empty-text` → `human-typing` → `budget-paused` → `turn-running` → the readiness gate's wait; the gate is read once per `send`, never again after that wait. `answer`, `wait`, `last`, `pause` and `hook.dialog` do not read the gate (read in the diff: its five product call sites; since chunk 2026-10-10-session-links the root case `path6_a_closed_gate_leaves_answer_wait_last_and_pause_alone`, `tests/cli_budget.rs`, drives `answer`, `wait`, `last` and `pause` under one closed gate, each giving the exit code and the document it gives under an open one; no case drives `hook.dialog` under a closed gate). An override covers both windows until its end and is dropped at the next point after that end. It does not outlive its wrapper: every start, a revived one included, evaluates from `budget.json` alone and restores none. `release --budget` with no pause standing records nothing. `budget-gate` is appended, and the snapshot's `budget_paused` and `budget_override_until` are rewritten, only when the triple (paused, window, override end) changes, both before the evaluation returns; a record that cannot land is an error and the recorded state stays as it was. The thresholds are read once, at the wrapper's start, and no value of either switches the gate off. The gate is fail-open: no reading, an `"unknown"` figure, a passed or unparseable `resets_at`, an unreadable or refused `budget.json` and a bad threshold each leave it open or at its default. The decision takes the wall-clock instant as an argument (no clock seam). With figures missing, viola uses the newest reading from any wrapped session and shows its age. With no reading at all it records `unknown` and does not block.
 The statusline is wrapped only for sessions started by `viola run`, through a per-session settings override that then runs the user's own statusline command unchanged. As landed (chunk 2026-10-10-statusline-pass-through) the wrap is Unix only: on Windows no override is written and no command is run, and that half is owed to the working-route entry "Windows-only live measurements" (the founder's word on the cut, live, 2026-10-10, relayed verbatim by the operator). A reading is recorded only when the payload holds `rate_limits`. Rationale: the per-model weekly window is hidden (claude-code#91920), so thresholds are set low.
