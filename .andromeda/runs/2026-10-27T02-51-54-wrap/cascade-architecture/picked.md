### occupied-resources#37.1 · values · res-repository · ## Occupied Resources · lines 245–246 · stale
- `<repo parent>/viola-mutants-scratch/` (outside the repository, a sibling of it): the host mutation scratch. On a Windows host (`HOST_SCRATCH = cfg!(windows)`) `run --mutants` puts cargo-mutants' temp copies there (`TMP`/`TEMP` on the `cargo mutants` command) and its `--output`, so `mutants.out/` is `<scratch>/mutants.out/`. A guard refuses unless the resolved path's final component is exactly `viola-mutants-scratch` and the repository is neither it nor inside it (`scratch-refused`, never a fallback to `%TEMP%` or the repo). The scratch is measured, removed and recreated before every counted, scoped or package run (`scratch-wipe-failed` when the removal fails); the re-creation goes through `viola_state::fs::create_private_dir`, so on Windows the scratch is the topmost folder it creates outside the profile and takes the protected user + SYSTEM DACL, and every temp copy and test home laid inside it inherits owner-only, as one under `%TEMP%` does (a plain-created scratch on the runner's workspace drive inherits BUILTIN\Users write, which the instance check refuses `Writable`). The witness is `wipe_scratch_takes_an_instance_tree_the_check_accepts_where_a_plain_dir_does_not`, on CI's `test (windows-2025)` leg (as measured at ci#38375200217, chunk 2026-10-13-epoch-4-cleanup); whether the root package's Windows mutation baseline then reads green is not yet measured (the next `windows-mutants.yml` dispatch). Its path is never printed: documents carry only the byte count `scratch_bytes`. The dispatch-only `windows-mutants.yml` runs this same arm on the `windows-2025` runner, so there the scratch sits beside the runner's checkout (its parent directory); each job's document carries only `scratch_bytes` (0 on a fresh runner, as read in run 37174673472). Off Windows the harness arm is inert and `mutants.out/` stays at the repository root (gitignored).
 On the Linux dev host the same-named directory is the operator's `TMPDIR` for every mutation run — an environment fact, not harness code — and must be NOCOW (`chattr +C`): cargo-mutants 27.1.0 copies the tree (`target/` included, ~14 GB) into `std::env::temp_dir()`, `/tmp` there is a 32 GB `usrquota` tmpfs (a full viola-e2e run died at 460/709 on `Disk quota exceeded`), and on a COW btrfs dir its reflink copy drops the exec bit of the prebuilt `viola-fake-agent` (as measured at `viola-0.1.0/chunks/2026-10-03-mutation-scoring-completion/evidence/m3.md`); a NOCOW dir makes the reflink fail over to the mode-keeping `fs::copy`. No document prints this path either.
