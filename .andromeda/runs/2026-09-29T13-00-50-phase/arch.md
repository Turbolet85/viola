## Constraints
- **Fake-agent placement:** the fake agent is the test-only `[[bin]]` `viola-fake-agent` of the root package, behind feature `fake-agent`, at `src/bin/viola-fake-agent.rs` (per architecture §Occupied Resources → Binary, subcommands and exit codes; §Infrastructure Patterns → Project directory structure). Matcher evaluation, the resize oracle and the contract hooks all stay inside that bin or the root `tests/`. The bin must stay out of every release build, because target job 6 / `scripts/release-check.sh` refuses any `viola-fake-agent` artifact or `fake-agent` feature record (per architecture §Infrastructure Patterns → CI/CD approach, target job 6).
- **Claude-shape isolation:** Claude-specific payload shapes and the prompt-origin classifier belong only in `viola-agent-claude`. That crate must stay pure: no I/O and no `viola-state` dependency (per architecture §Established Decisions [Agent Coverage]; §Inherited Defaults, "Agent isolation"). The item-5 fix therefore lands in `crates/viola-agent-claude/src/hook.rs`, never in the root bin or the wrapper. A new dependence on an undocumented CLI behaviour, such as a new injected prefix literal, becomes a capability-ledger row with a `viola verify` probe. It is never hard-coded as an unconditional assumption (per architecture §Cross-cutting Patterns, "Capability ledger as the single gate"; §Established Decisions [CLI Version Compatibility], row "Harness prefixes").
- **Classifier ordering and the escaped form:**
  - Classification reads the RAW prefix first. Only after that does the code remove the long-paste wrapper and then un-escape `<\`. An escaped `<\…` tag is by design what the user typed (per architecture §Established Decisions [CLI Version Compatibility], row "Tag escaping"; [Human Takeover / Wheel]).
  - The arch-listed harness prefixes are exactly `<agent-message from=` and `<task-notification>` (per architecture §Established Decisions [Human Takeover / Wheel]).
  - The overseer's "escaped or plain" clause conflicts with this row. If the chunk adopts it, that needs an arch amendment at wrap. Which literal the CLI actually injects, and whether it arrives escaped, is research's question (P3).
- **Origin enum:** `prompt-submitted` `data` is `{text, origin}`, with `origin` from the closed set `driver` · `human` · `harness`. The wrapper re-validates `hook.event` `origin` as `harness` · `human` (per architecture §Standard Contracts → Event `data` per kind; → Channel methods `hook.event`). The fix may change which value a prompt gets, but it must not add a value.
- **Fixture layout:**
  - Recorded fixtures are `fixtures/claude/<cli-version>/<Event>.default.json`: compact JSON plus `\n`, scrubbed (home → `~`, user word → `<user>`), walked by `tests/contract_fixture_hygiene.rs`. They are written only by a local `viola verify --record` in which 0 rows fail (per architecture §Occupied Resources → Repository).
  - The committed fixture schema sits at `schemas/claude-fixture.v1.json` (tolerant; `required: [hook_event_name]`; enum = the fake agent's nine `REGISTERED_EVENTS`).
  - The scope infers a per-version copy under `fixtures/claude/2.1.283/`. Which file exists, and which one a check reads, is research's question.
- **The real `claude` never runs in CI:** the contract suite runs against the fake agent and replays `fixtures/claude/*` (target job 5). Any new recording needed as a witness is local and operator-run (per architecture §Infrastructure Patterns → CI/CD approach; §Established Decisions [CI/CD]).
- **Environment variables:** the fake agent and the suite may add no environment variable read by `viola` beyond `VIOLA_*` and the two ratified seams `FAKE_AGENT_PUMP_DELAY_MS` / `FAKE_AGENT_HOOK_PANIC`. A new seam needs a Decisions Log entry (per architecture §Conventions → Environment variables; §Cross-cutting Patterns → Config management). Harness-only variables use `AGENT_RUN_` and are never read by `viola`.

## Patterns to follow
- **Fake-agent receipt:** `fake/<name>.receipt.ndjson` in test homes only. Each line is `"v":1` plus a kebab `kind`, written with one `write` per line, passed as `--receipt`. `viola` never reads or writes it (per architecture §Occupied Resources → Filesystem, "Test homes only"; §Conventions → ndjson line discipline). A resize-oracle receipt line follows the same shape.
- **Fake-agent print mode:** `-p/--print` writes the start receipts. It then fires the SessionStart, UserPromptSubmit (only the prompt set), Stop and SessionEnd `default` fixtures in that order, prints `ok` and exits 0 without reading stdin (per architecture §Occupied Resources → Binary). The hook-sequence half of the contract can be derived from this recorded order.
- **Tolerant validation:** external payloads and fixtures are parsed with no `deny_unknown_fields`, using `#[serde(default)]` / `Option<T>`, the raw `serde_json::Value` kept, and serde_path_to_error for drift reports. Tolerance also covers viola's own versioned formats (per architecture §Established Decisions [Validation]). A fixture schema check therefore asserts required keys and enums, never a closed field set.
- **Schema tooling:** the committed JSON schemas under `schemas/` are test-side. The pinned validator is jsonschema 0.57.0 behind the harness `schema-check` / G4 (per architecture §Stack and Technologies → Code quality; §Occupied Resources → Repository). `schemas/fake-script.v1.json` over `fixtures/fake-scripts/` is the precedent for a schema-over-fixtures check.
- **Hook registration shape:** the hook tiers and the PreToolUse matcher `AskUserQuestion|ExitPlanMode` define what the fake agent must evaluate (per architecture §Established Decisions [Hook Transport]; §Occupied Resources → Claude Code integration names). Each new module in the fake-agent bin must stay reachable for `scripts/orphans-check.sh`, which runs per bin target with its required features (per architecture §Infrastructure Patterns → Build system, Boundary review).

## Anti-patterns to avoid
- Registering PreToolUse or PermissionRequest in the product `plugin/hooks/hooks.json` just to give matcher evaluation a witness. The dialog tier is registered by the dialog chunk and never earlier with a no-decision body (per architecture §Established Decisions [Deployment / Distribution]). A matcher witness uses a test-side hooks config or fixture instead.
- Hard-coding a new harness prefix as an unconditional assumption, or classifying after the un-escape step. Either one lets a prefix the user typed pass as harness, and a harness turn never flips the wheel, so the human loses the wheel on a spoof (per architecture §Cross-cutting Patterns, "Capability ledger as the single gate"; §Established Decisions [Human Takeover / Wheel], "Tag escaping").
- Tokio or async anywhere on the fake-agent, hook or classifier path (per architecture §Cross-cutting Patterns → Tokio containment).
