## Constraints
- test-plan §6 Contract suite and §2 pyramid Contract row require: for EACH `fixtures/claude/<ver>/` set, the fake agent's emitted hook sequence and payloads, captured in the receipt, equal the recorded fixture order and payloads, pinned with insta 1.48.0 in check mode; the forwarded `annotations` on the question answer path asserted explicitly (S8); jsonschema 0.57.0 over every `fixtures/claude/*/*.json` against a tolerant parser schema (unknown fields allowed, closed enums required). Whether `annotations` names a payload field or a dialog-answer field (§4 viola-agent-claude dialog mapping and §6 Path 4 both place it in the PreToolUse `updatedInput.answers` decision body) is research's question.
- test-plan §2 naming + §3 `run` step 1-2 require contract binaries to be root `tests/contract_<topic>.rs`; the `contract_` prefix routes them to the fake-agent E2E layer (`binary(/^(path|tui|mcp|http|sse|cross|chaos|contract)_/)`), not the integration filterset — they run under `agent-run run --e2e` on all three OSes (§9 E2E / Coverage rows).
- test-plan §7 Fake agent is the binding contract for the fake agent: payload on stdin is the exact bytes of `<fixtures>/<cli-version>/<Event>.<variant>.json`, UserPromptSubmit sets only the top-level `prompt` key, no other payload is built, an absolute `command` is spawned directly and a non-absolute one never runs (`command_absolute:false, ran:false`); §7 names THIS chunk as where hook `matcher` evaluation lands; the receipt `size` kind is specified "at start and again whenever the terminal size changed (the resize oracle)" — code and this wording must reach one truth (a code change or a §7 amendment at wrap).
- test-plan §7 Fixture hygiene requires one run-time directory walk in `tests/contract_fixture_hygiene.rs` (not an rstest `#[files]` case — rstest 0.27 refuses a glob matching no file), checks absolute-path + username + schema per fixture, reports a violation CLASS only (`absolute-path`, `username`, `schema`), and proves each class red with a planted input. §7 names the schema `schemas/claude-fixture.v1.json` (tolerant, `required: [hook_event_name]`, enum = the fake agent's nine `REGISTERED_EVENTS`); the scope's inferred path `fixtures/claude/<ver>/claude-fixture.v1.json` differs — which file exists and whether the walk already runs it is research's question.
- test-plan §4 viola-agent-claude requires `prompt-submitted` normalisation unit cases (M2 prefixes → `origin:"harness"`), inline `#[cfg(test)] mod tests`, rstest `#[case::<label>]` tables; §4 root bin requires the wheel state machine case "harness-origin prompt → no flip"; §6 Path 5 step 8 requires harness-injected turns to log `prompt-submitted{origin:"harness"}` and no `wheel` record. §4/§6 Path 5 name only `<agent-message from=` and `<task-notification>` today — a new cross-session tag extends them via a wrap amendment.
- test-plan §2 Agent-runnable invariants + §10 Zero-flakiness budget require determinism: nextest `retries = 0`, no sleep-based sync (gated steps wait on the `--control` file by byte offset, §7), insta only with `INSTA_UPDATE=no`, no `#[ignore]` / `test.skip` as a parking place.
- test-plan §10 Coverage thresholds apply per OS (lines ≥ 85 %, functions ≥ 95 %, regions ≥ 80 %); `viola-fake-agent` and `tests/support` sit in the `COVERAGE_IGNORE` regex, so the classifier change in `viola-agent-claude` counts toward the gate while fake-agent matcher/receipt code does not. §10 Mutation gate: this is Epoch 2b's last entry, so its diff is judged at the epoch-boundary `/andromeda-code-audit` (`missed == 0`, `timeout == 0`, `unviable <= caught`), not per chunk.

## Patterns to follow
- The run-time fixture walker + class-only checker + planted-red proof (`tests/contract_fixture_hygiene.rs`, `tests/support/hygiene.rs`) per test-plan §7 Fixture hygiene — extend it, do not fork a second walker.
- Per-version iteration as `contract_ledger_probes.rs` does it (test-plan §5 non-path suites, "for each `fixtures/claude/<ver>/` set"), so a second recorded version is covered without an edit.
- Root `tests/` boot chain `home → fake_agent_path → stamped_home → booted_wrapper`, the fake agent resolved via `CARGO_BIN_EXE_viola-fake-agent` (test-plan §3 `run` step 2, §8 Process mocking); stamps only via `viola verify` against the fake agent (§7 seed table).
- Verdicts read from the receipt (`hook` {`event`, `command_absolute`, `ran`, `exit_code`, `stderr_len`, `stdout_hex`}, `prompt` {`origin`}, `step`, `size`) and `events.ndjson`, through the complete-lines reader `tests/support/ndjson.rs` (test-plan §2 directory conventions, §7 receipt kinds, §11 E2E R7).
- insta `assert_json_snapshot!` with redactions for sequences/decision bodies; rstest `#[case::label]` for the classifier prefix table (test-plan §4 Fixture pattern).

## Anti-patterns to avoid
- NEVER import the product's own constants as the oracle (test-plan §11 Unit): the harness-tag literals, the nine registered events and the expected hook order are written as literals in the test, never read from `HARNESS_PREFIXES` / `REGISTERED_EVENTS`.
- NEVER treat a green fake-agent run as proof of real-CLI behaviour, and NEVER run the real `claude` / live `viola verify` in CI (test-plan §11 Test Strategy); snapshots and fixtures change only through the local `viola verify` refresh, never `cargo insta review` or an update mode as a gate step (§11 Universal).
- NEVER sleep for synchronisation or parse the child screen for content (test-plan §11 E2E) — a resize oracle is read from the receipt `size` line, not the vt100 grid.

## Contract bindings
- tests ↔ security: fixture hygiene is the test-side enforcement of the recorder scrub (home → `~`, username → `<user>`, synthetic probe prompts only, test-plan §7) and of error sanitization — the checker reports a class, never offending content.
- tests ↔ arch/events: the `prompt-submitted.origin` field and "harness origin never flips the wheel" are an event-contract behaviour (events.md, arch Standard Contracts) asserted by test-plan §4 root-bin wheel case and §6 Path 5; an undocumented CLI tag behaviour is a capability-ledger row with a `viola verify` probe — if one is added, `contract_ledger_probes.rs`'s literal row ids and `<n> pass` count move with it (test-plan §5 non-path suites).
- tests ↔ obs harness: suites run only through `scripts/agent-run.{sh,ps1} run`, one JSON document + typed exit (test-plan §3); CI ends in `viola-harness gate --require coverage,doctest,playwright` per OS (§9).
- tests ↔ route CARRY: the host's local integration reds are judged against a same-day control with CI as the acceptance leg (scope item 4); test-plan §10 Build failure conditions still count any test failure on any OS in CI as red.

## Acceptance criteria contributions
- `scripts/agent-run.sh run --e2e --filter 'binary(/^contract_/)'` (pwsh `scripts/agent-run.ps1` on Windows) passes on all three CI OSes, with a contract test that, per `fixtures/claude/<ver>/` set, asserts the fake agent's receipt-captured hook sequence and stdin payload bytes equal the recorded fixtures (insta check mode) and asserts `annotations` forwarding explicitly (per test-plan §6 Contract suite).
- The fixture walk validates every `fixtures/claude/*/*.json` against the committed claude-fixture schema, and a planted input per class (`absolute-path`, `username`, `schema`) turns it red with the class name only (per test-plan §7 Fixture hygiene).
- A labelled rstest case table in `viola-agent-claude` classifies a prompt STARTING with the cross-session-message tag as `harness` and the same tag elsewhere as `human`, and fails against the pre-fix classifier; the harness-injected turn logs `prompt-submitted{origin:"harness"}` and no `wheel` record (per test-plan §4 viola-agent-claude and §6 Path 5).
- The fake agent's `matcher` evaluation has a non-vacuous receipt witness (a matching and a non-matching hook, distinguished by `hook` receipt lines), the receipt `size` behaviour equals the §7 wording (or §7 is amended to the code at wrap), and per-OS coverage holds lines ≥ 85 / functions ≥ 95 / regions ≥ 80 with `retries = 0` and no `#[ignore]` (per test-plan §7 Fake agent and §10 Quality Gates).
