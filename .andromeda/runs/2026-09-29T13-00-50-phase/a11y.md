# a11y extract

## Relevance
partial — no UI surface is built. But the fake agent is the trigger source for the a11y harness, and the harness-origin classifier fix feeds the wheel state that the P4 tui/web assertions read.

## Constraints
- The a11y tier is Standard, and it applies to web-spa only. tui is boundary-only and cli is output-discipline only, with no WCAG conformance claim (per a11y-plan §1 A11y Scope Summary; §2 A11y Strategy). Any tui/cli check this chunk touches is an output-discipline stand-in, not a11y-tool evidence (per a11y-plan §11 A11y Anti-Patterns → Strategy).
- Critical Path 4 requires the following on tui (per a11y-plan §1 → Path 4 "Human takes the wheel"; §5 Keyboard Navigation → tui):
  - human keystrokes are never blocked or delayed past the current atomic paste;
  - focus/mouse/resize sequences are ignored for wheel purposes.
  - For item 5 (the harness-origin fix), a prompt that begins with the cross-session-message tag must not count as the human taking the wheel, and genuinely typed input must still count as `human`. Whether the pre-fix `prompt_origin` already honours this for the cross-session tag is research's question.
- The tui boundary harness requires three portable-pty outer-PTY nextest cases on all three OS legs, and it uses the tests' `viola-fake-agent` as the child (per a11y-plan §3 → Keyboard test harness → Tooling; §4 → P4):
  - zero viola-originated bytes: byte-for-byte against an unwrapped fake-agent run on Linux/macOS, and viola literals absent on both Windows ConPTY backends;
  - keystrokes delivered unblocked;
  - `\x1b[I`/`\x1b[O`, mouse and resize sequences do not move the wheel.
- The fake-agent changes (matcher evaluation, receipt `size` resize oracle, payload pass-through) must keep the fake agent's terminal output identical between wrapped and unwrapped runs, so that the byte-for-byte comparison stays meaningful. Whether the receipt is written only to a file, never to the terminal stream, and whether the resize-clause case reads the receipt `size`, are research's questions (per a11y-plan §3 → Keyboard test harness → Tooling).
- The a11y harness drives its state transitions through the harness/fake agent, and it waits on DOM signals, never on timeouts. The fake agent's scripted event sequences must stay able to drive those states (per a11y-plan §3 → Focus management test harness "No focus theft"; §6 → State color tokens; §7 → Live regions). These are:
  - cock/revert, readback refusal, `liveness-changed` stale;
  - dialog pending;
  - state words.
- The P6 C0/C1-escaping case requires a `viola-fake-agent` event whose text carries C0 and C1 bytes (ESC/CSI included) for `viola wait`/`viola last`. Enforcing the recorded-fixture payload equality must not remove the scripted path that produces that event (per a11y-plan §4 → P6).

## Patterns to follow
- Each tui boundary clause is its own nextest case on all three OS legs, driven through the portable-pty `=0.8.1` outer PTY (per a11y-plan §3 → Keyboard test harness → Tooling; Decisions Log D-A11Y-13).
- Assertions use a dual backend on Windows. The default case runs on the sideloaded ConPTY and the tampered-companion case on the inbox fallback. Each checks for viola's own literals, never for host preamble bytes (per a11y-plan §3 → Keyboard test harness → Tooling).
- Triggers go through the harness/fake agent, and the test then waits on a concrete signal (DOM `data-*`, strip text, SSE offset), never a sleep (per a11y-plan §3 → Focus management test harness; §11 → SLO).

## Anti-patterns to avoid
- NEVER block, refuse or delay a human keystroke in `viola run` past the current atomic paste. NEVER count focus/mouse/resize sequences as editing. NEVER let a classifier change reclassify genuine human input so that the human loses the wheel (per a11y-plan §11 → Keyboard).
- NEVER parse the rendered `claude` TUI screen for content (R7). The contract suite compares hook payloads, hook sequences and receipts, never screen content (per a11y-plan §11 → Universal).
- NEVER park a check with skip/fixme/quarantine, and NEVER use a retry-once policy to reach green (per a11y-plan §11 → SLO).

## Contract bindings
- The P4 tui boundary cases bind to the tests plan's E2E driver → tui (the portable-pty outer PTY and the fake agent as child). Their failures surface only as nextest failures in `suites[].failures[]`, and no a11y rows are written (per a11y-plan §3 → Structured violation JSON schema, the cli/tui line).
- The wheel `origin` classification is bound to what a11y reads (per a11y-plan §4 → P4):
  - the web WHEEL `cell` word `human` (`a11y-p4`);
  - the cli `send` refusal `human-typing`.
  - The classifier fix changes which prompts may produce that state. The origin field itself is owned by events/obs.

## Acceptance criteria contributions
- The three P4 tui boundary nextest cases stay green on all three OS legs after the fake-agent changes (per a11y-plan §4 → P4; §3 → Keyboard test harness → Tooling):
  - zero viola bytes;
  - keystrokes unblocked;
  - focus/mouse/resize do not move the wheel.
- The harness-origin witness holds, and a typed prompt still classifies `human` and moves the wheel as before (per a11y-plan §1 → Path 4; §11 → Keyboard). The witness: a prompt that starts with the cross-session-message tag classifies `harness` and does not flip the wheel to `human`, while the same tag anywhere but the start stays `human`.
- The P6 C0/C1 escaping case (`viola wait`/`viola last` over a fake-agent event carrying C0/C1 bytes) still runs and passes on all three OS legs (per a11y-plan §4 → P6).
- The contract suite and the fixture schema check read no rendered screen content. Their only oracles are hook payload bytes, hook sequences and receipts (per a11y-plan §11 → Universal).
