## Relevant amendment history
- **2026-09-24-three-os-ci-headless-harness-skeleton** — The fake agent is a `[[bin]]` of the root `viola` package, so it inherits the root `[lints]`. Its only print-ban exemption is the crate-level `#![allow(clippy::print_stdout, clippy::print_stderr)]` in `src/bin/viola-fake-agent.rs`, and §11 lists that allow. Only `viola-e2e` carries its own lint table. This is the basis for the extract's print-ban constraint. New fake-agent emulation code (matcher evaluation, payload replay, receipt resize) prints under that allow. Contract-suite helpers placed in product crates get no exemption. A new test crate or bin would need its own lint handling and a change to the CI member-list assertion.
- **2026-09-24-diagnostics-plane** — `obs_event!` attaches `event`, `process` and `instance`. `corr` is a caller-supplied typed field. Default-deny is enforced by a top-level `unevaluatedProperties: false` in `diag-line.v1.json`, and `diag-detail.v1.json` is self-contained with the event enum inlined. This is the mechanism G4 uses to fail any new field or `event` value that the classifier fix or matcher work might add. The acceptance criterion "no new event/field without a D-entry" rests on it.
- **2026-09-24-observability-gates** — The raw-tracing ban is enforced by `clippy.toml` `disallowed-macros` (tracing level macros banned by path) plus a fail-closed raw-`event!` grep in `scripts/lint-probes.sh`. A `lint-probes.sh` failure is a build failure (D-33). Any logging added to `viola-agent-claude` `hook.rs` (`prompt_origin`) or `src/cmd/hook` must go through `obs_event!`. An inner `#[allow]` cannot exempt a raw `event!`.
- **2026-09-24-quality-gates** — §8 item 6 admits an upload by content only when its inputs are synthetic: "a non-synthetic seed drops that upload first". This is the same rule the extract applies to the `detail-*.ndjson` upload. If P3 finds the `fixtures/claude/2.1.283/*` payloads are captured real content rather than synthetic, this precedent is the one the upload-path decision follows.
- **2026-09-25-pty-wrapper-on-windows** — The §11 print-macro allow list was narrowed to named local sites. A proposal to make `viola-agent-claude` tracing-free was rejected, because obs §3/§4 require seam spans there. So `viola-agent-claude` may carry `#[instrument(skip_all, …)]` spans. That bears on research's question of whether `prompt_origin` is instrumented. Also, `process-start{claude-child}` logs `env_kept` as names only (D-34), which is the names-never-values precedent for anything the classifier touches.
- **2026-09-26-local-linux-pre-push-gate** — The "env vars are not a configuration channel" restatements were kept on the reasoning that the fake-agent test seams configure nothing. If the chunk wants a new `FAKE_AGENT_*` seam (for example to script tool-bearing or matcher-bearing turns), that reasoning has to still hold. A new seam also needs a Decisions Log entry under security.md.
- **2026-09-27-wrapper-channel** — The `corr` rules are schema-enforced in `diag-line.v1.json`. `hook-invoked` never requires `corr` and may be null before `dialog_id` is known (D-07 fail-open). `hook-decision` requires `corr` for `pre-tool-use`/`permission-request` unless it carries a `detail`. A fake-agent matcher evaluation that fires `pre-tool-use` hooks will produce lines that G4 checks against exactly these rules.
- **2026-09-27-hooks-to-normalised-events** — `session-start{source:"hook"}` is record three through `hook.event`. D-28's concurrent-append check governs `hook-<name>.ndjson` / `detail-hook.ndjson`. The spine gate stays provisionally 1.0 s, with the hook's 750 ms connect deadline below it. The contract suite's hook sequences write into these shared files. The host-reds CARRY ("`viola hook` over its 1.0 s spine bound") is measured against this bound.
- **2026-09-28-hook-perf-gate (uploads)** — `diag-perf-<os>` joined `diag-<os>` in the scan-gated class because its inputs are synthetic (payloads bearing the tests-owned canary). This is the second precedent that detail-file uploads rest on a synthetic-input basis. Replaying recorded fixture payloads through `viola hook` needs the same basis, or the upload has to be dropped.
- **2026-09-28-hook-perf-gate (G2 seam)** — G2 runs as `scripts/g2-zero-panics.sh` in the `test` and `perf` jobs. Its only exemption is a panic whose `panic_location` is exactly `src/cmd/hook/seam.rs:<digits>` (founder-ratified 2026-09-28). The invariant still holds for the seam line. `pre-tool-use` is untimed until the dialog tier, so a matcher-driven `pre-tool-use` adds no perf row. A contract run that uses the panic seam inherits exactly this exemption, and nothing wider.
- **2026-09-28-cli-output-tokens** — §11: an output module may carry a local `#[allow]` only where it actually uses a print macro. `run`'s refusals go through `src/human.rs` with no allow. The `hook` and `viola-agent-claude` code touched by the classifier fix has no such allow and must not gain one.
- **2026-09-28-capability-ledger-and-viola-verify (verify / capture arm)** — The hidden `hook --capture` arm is uninstrumented by design: no `VIOLA_*`, no obs init, no `hook-invoked`/`hook-decision`. It is §10 bounded exemption 5. Verify's outcome goes to stdout. The recorded fixtures the contract suite reads were produced through this arm, and the suite must not route its replay through it. The matching extract constraint rests on this entry.
- **2026-09-28-capability-ledger-and-viola-verify (panic backtrace)** — Panic backtraces are raw, never-symbolised frames, because symbolisation pushed the forced-panic hook to 1.50 s against the 1.0 s spine bound. This precedent matters for the host-reds CARRY's hook-over-spine failures. A spine overrun has had a measured obs-side cause before, so a local red should not be presumed environmental without a same-day control.
- **2026-09-28-mutation-testing-to-the-epoch-boundary** — Mutation testing of obs code moved from CI to `agent-run run --mutants` at the epoch-boundary code audit. This chunk closes Epoch 2b, so its classifier and hook changes will meet cargo-mutants at the audit that follows. A surviving mutant in obs code is a §10 failure there, so the origin fix's witness tests should kill its mutants.
- **2026-09-29-verify-stamped-test-homes-and-harness** — In CI, verify runs only against the fake agent at 2.1.283 (`tests/cli_verify.rs`, `boot` step 4, `stamped_home`). The real-`claude` verify runs only through the local `run --local-live`, which is refused under `CI`. Verify logs `version-probe`/`verify-probe` pairs, and D-35 added `verify-probe` as the template for a new closed value that needs a Decisions Log entry. The contract suite's stamped homes and the fixtures it compares against rest on this setup. Any new spawn subject the suite introduces would need the same D-entry treatment.
- **2026-09-29-sideloaded-conpty** — D-36 added `pty_backend` `conpty-sideload` and the closed `sideload_fallback` field to `process-start{claude-child}`, following D-35. D-36 is the latest obs Decisions Log entry, so any closed value this chunk adds (a `parser`, `detail` code or `event`) would be D-37. On Windows the fake-agent runs of the suite now spawn under the sideloaded ConPTY, and their `process-start` lines carry these fields.
