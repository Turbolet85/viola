# tests extract

## Relevance
Relevant. The chunk adds a harness gate entry and a local ubuntu mutation leg. Both sit inside test-plan §3, §9 and §10, and the scope names §3, §10 and §12 as wrap amendment sites.

## Constraints
- **The new entry must follow the harness contract (per test-plan §3 preamble "Harness implementation" / "Exit codes").** The shims stay thin and all logic lives once in Rust (`viola-harness`). The entry prints exactly one JSON document `{"v":1,"cmd":…,"ok":…}` and exits 0, 1 or 2. A usage error carries `reason:"usage"` plus a `detail`. §3 says the grammar grows per chunk: a flag whose surface is not built is a usage error, never a vacuous pass.
- **A gate that cannot run must be a typed failure (per §3 Bootstrap `ci-tool-install` closing paragraph; §3 `run` `--fuzz-replay` / step 3).** The existing pattern is a tool probe first, then exit 1 with `reason:"tool-missing"` plus a `detail` naming the tool, "never a silent pass". An OS-refused arm exits 2 with its own reason (`fuzz-linux-only`, `browser-linux-only`). A missing Ubuntu distro or an unprovisioned toolchain must take the same shape. §3 Closed enums require every new `reason` / `detail` / `cmd` value to get a §12 Decisions Log entry.
- **The clone must hold the same history the base derivation reads (per §3 `run` step 4 Base).** The base comes from `.andromeda/master-route.md` in HEAD's tree, the `· complete ·` pickaxe, and the oldest `chore({marker}): operator pre-CI commit`. CI needs `fetch-depth: 0` for the same reason. The fallback is `merge-base HEAD origin/main` and then `base-missing`. The output carries `"base":"<sha>"` (§3 `run` Output format), and that is the field to compare against the Windows and CI legs.
- **The sync must reproduce what the mutation diff reads (per §3 `run` step 4 Diff).** `chunk.diff` is the working tree plus every untracked, non-ignored file, against `merge-base(<base>, HEAD)`. So the sync has to carry uncommitted and untracked non-ignored files, and deletions, or the Linux leg mutates a different chunk from the Windows leg.
- **The leg is judged by its verdict, never by counts or the exit code alone (per §3 `run` step 4 Verdict/Classification; §10 Mutation gate; §11 Quality).** The verdict is `missed == 0 && timeout == 0 && unviable <= caught`. `outcomes-missing` and `mutants-exit-<code>` are red. The closed verdicts `counted` / `no-rust-delta` / `test-only-rust-delta` are decided before any build.
- **Watch the `--leg` semantics (per §3 `run` Exit code semantics).** Under `--leg`, survivors are deferred to the `gate` union. Only a tool-arm refusal, `outcomes-missing` or `unviable-exceeds-caught` makes the run itself red. A local `run --mutants --leg ubuntu…` alone would therefore read `ok:true` with missed mutants. The gate must also run `gate --mutants-legs …`, or run the leg without `--leg`, so that a survivor stops the push. Which one, and whether the gate's verdict inputs exist locally, is for research to answer.
  - The leg-family rule in §3 `gate` maps `ubuntu-` to unix + linux, and an unknown family "keeps the leg". A bare leg name like `ubuntu` would not get the Linux family. CI's name is `ubuntu-latest`.
- **Tool pins come from one source (per §9 tool-install paragraph and Matrix builds → Language version; §3 Bootstrap `test-runner-install`).** Rust 1.98.1 is pinned in `rust-toolchain.toml` and installed by `rustup toolchain install` "on every OS, host included". The rustfmt and clippy components come from that file. cargo-nextest 0.9.146, cargo-llvm-cov 0.9.1 and cargo-mutants 27.1.0 are pinned in `ci.yml`, and a local install uses `cargo install --locked`. §9 says "each tool has exactly one version source".
- **Cache size facts the Linux target cap must allow for (per §3 `run` step 1 / step 4 Command).** The harness builds into `CARGO_TARGET_DIR=<root>/target/harness`. `run --mutants` prebuilds the root package and passes `--copy-target=true`, which costs one copy of `target/` per run (2.9 GB measured on the dev host). §3 `--coverage` is never in the default selection. Whether the local gate needs coverage is research's question, not a mandate.

## Patterns to follow
- **Probe plus clean control for self-guarding gates (per §9 Lint / Supply-chain / Release rows).** `scripts/orphans-check.sh --probe` ends `1/1 fired, control clean`, `scripts/deny-probes.sh` ends `13/13 banned, control clean`, and `release-check.sh --probe` ends `3/3 refused, control clean`. The planted `#[cfg(unix)]` red and its removal fit this shape.
- **Test override seam for the base (per §3 `run` step 4 Base).** `AGENT_RUN_CHUNK_BASE` exists for the harness's own tests. Scratch-repo history tests follow the model of `chunk_base_holds_the_flip_across_a_pass`, and literal-oracle tests follow `run_mutants_mixed_src_and_test_delta_without_outcomes_stays_outcomes_missing` (§12 2026-09-25).
- **Child environment is passed per child (per §3 boot step 3; §11 Integration).** Environment goes through `Command::env` on each child, never `set_var`. This covers what is handed to `wsl -d Ubuntu -- …`.
- **Live progress streaming (per §3 `run` step 4 Command).** cargo-mutants' stdout streams live to the harness's stderr, and stdout keeps the single JSON document. A long Linux leg should name the mutant it stalled at.

## Anti-patterns to avoid
- **Do not treat a local Linux run as proof (per §11 Test Strategy).** "NEVER treat a Linux-only local run as proof for Windows or macOS. OS-branch code is verified only on its own runner." CI stays the verdict of record (§9 Mutation row / Quality gates).
- **No silent skip, retry or exit-code trust (per §11 Quality, §11 Universal, §10 Zero-flakiness budget).** No silent skip or green on an unrunnable gate. No retry-once or any retry budget. Never trust the cargo-mutants exit code alone. Never print a human-only message without the JSON document and exit code.
- **Do not count compiled-out tests as skips (per §3 `run` Output format `skipped`).** Tests compiled out by `#[cfg(unix)]` / `#[cfg(windows)]` are never counted as skipped, so the Linux run's counts must not be read as coverage of the Windows-skipped set.

## Contract bindings
- **tests ↔ obs (secret scan).** §3 `secret-scan` Scope covers every file under `target/agent-run/` except exactly `chunk.diff` (obs-plan §9 step order). Any report the gate writes there enters the scan scope and upload contract. The same applies to anything synced back from the clone.
- **tests ↔ operator-pass docs.** The wiring goes "before the push entry" in the leaves re-derived from §3 / §9: `.claude/docs/workflow.md`, `.claude/docs/commands.md`, `rules/verification-harness.md`, `rules/testing.md`. That wiring needs a matching §3 / §10 / §12 amendment at wrap.
- **tests ↔ §12 Decisions Log.** Every new closed value (`cmd`, `reason`, `detail`, leg name) needs a Decisions Log entry (§3 Closed enums).

## Acceptance criteria contributions
- The gate entry prints one `{"v":1,"cmd":…,"ok":…}` document with exit 0/1/2. An absent Ubuntu distro or tool gives exit 1 with a typed `reason` + `detail`, never `ok:true`. Each new closed value has a §12 entry. (per test-plan §3 preamble Exit codes; §3 Bootstrap `ci-tool-install`; §3 Closed enums)
- A planted failing `#[cfg(unix)]` test turns the gate `ok:false` with a non-zero exit and names the test in `suites[].failures[]`. Removing the plant returns `ok:true`, with no retry involved. (per §3 `run` Exit code semantics / Output format; §10 Zero-flakiness budget)
- The local ubuntu mutation reading prints a full-sha `"base"` equal to the Windows leg's `base` on the same tree. It is red on any missed or timed-out mutant or on `unviable > caught`, judged by the verdict and not by the caught/unviable counts. (per §3 `run` step 4 Base / Verdict; §10 Mutation gate)
- A dirty or untracked file edited in the Windows tree shows up in the Linux run's `chunk.diff`. The gate's own new Rust passes the mutation gate: 0 missed, 0 timeout, `unviable <= caught`. (per §3 `run` step 4 Diff; §10 Mutation gate)
