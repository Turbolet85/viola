# security · standing conventions

- S1 · every new recorded fixture is scrubbed or refused whole, held to the closed string allowlist, under the fixture hygiene walk and reviewed before commit · data-protection
  decision/env-fixture-names-only · Recorded env fixture holds names only — The recorded env fixture holds only its version and the CLAUDE names the CLI adds to a hook, never a value; it passes the record scrub and the env-name check, an env name carrying the user word refusing the recording as username with nothing recorded, and the hygiene walk checks it as its own class. · guard: env_fixtures_pass_hygiene; record_refuses_an_env_name_carrying_the_user_word
  decision/verify-screen-read-against-literals · Verify screen read only against compiled literals — verify's children's screens are read only against compiled signatures: the literals, and the compiled shapes over them (a modal label row's option shape; the box's rows below it), and their row text leaves the process only as signature-only record fixtures. · except: On a failed recording verify, a hidden rig-only option writes one first-screen file of whole scrubbed rows per run short of the input box, kept local and git-ignored; an unclean set is refused whole.
  decision/verify-signature-only · Verify reads signatures only — viola verify's interactive children are read only against the compiled signatures: the literals, and the compiled shapes over them (a modal label row's option shape; the box's rows below it), their row text leaving the process only as signature-only record fixtures. · except: On a failed recording verify, a hidden rig-only option writes one first-screen file of whole scrubbed rows per run short of the input box, kept local and git-ignored; an unclean set is refused whole.
  decision/viola-format-fixtures-hygiene · viola-format fixtures under the hygiene walk — Committed viola-format fixtures, the old state shapes and retired words, are held to the same fixture hygiene walk as recorded fixtures: no path, user or email. · guard: viola_format_fixtures_pass_hygiene
- S2 · every new product reader is bounded by MAX_FRAME or a deadline and named in the bounded-readers census with a witness · input-validation
- S3 · every new test seam or test-only binary lives only under the fake-agent feature or test-only targets, compiled out of release · security-anti-patterns
  decision/fake-agent-hook-panic-seam · Hook panic test seam — FAKE_AGENT_HOOK_PANIC exists only in test-feature builds and forces a fixed-payload hook panic only when exactly 1; the hook still fails open; it configures nothing, disables no control and widens no redaction. · why: Ratified.
  decision/fake-agent-pump-delay-seam · Pump delay test seam — FAKE_AGENT_PUMP_DELAY_MS exists only in test-feature builds, a u64 of milliseconds capped at 5 000 that holds the run pump back after the child starts; it configures nothing, disables no control and widens no redaction. · why: Lets a test land a host resize in the spawn-to-pump window; ratified.
- S4 · every new seam or environment read needs a log entry · security-anti-patterns-never-do-these
  decision/new-env-read-needs-log-entry · New seam or environment read needs a log entry — No further test-only seam or environment read is added without its own Decisions Log entry.
- S5 · every new test uses its own home and holds no secret or credential literal · secret-management
  decision/no-credential-literals · No credential literals in code — No token, key or credential literal appears in source or in the embedded plugin files, which carry only exec paths.
  decision/no-hardcoded-credentials · No hardcoded credentials — Credentials are never hardcoded in source or in the include_str! plugin files.
  decision/test-homes-gitignored · Test homes kept out of git — Local --home test directories are git-ignored so recorded state never lands in git.
  decision/tests-use-own-home · Tests use their own home — Development handles secrets as production does, and tests use their own --home directory.
