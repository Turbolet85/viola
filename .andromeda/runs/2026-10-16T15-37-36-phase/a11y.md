Removing the browser pipe from the `test` job must leave that suite and its matrix whole.
- a11y-plan §3 A11y testing tool pick requires cli to be checked with assert_cmd 2.2.2 + predicates 3.1.4 + trycmd 1.2.1, and tui with the portable-pty `=0.8.1` outer-PTY boundary driver, inherited and never re-pinned. - a11y-plan §4 ARIA Patterns & Roles (P4 / P6 path scenarios) requires the three portable-pty outer-PTY tui boundary cases, the readiness-gate key case and the P6 cli output-discipline cases on all three OS legs. Its `run --browser` time budget and its `gate --require playwright` and ESLint / html-validate failure conditions go with the browser leg, and the wrap amends them.
- a11y-plan §3 Structured violation JSON schema says cli / tui emit no a11y rows: output-discipline failures surface only as nextest failures in `suites[].failures[]`. Removing the `playwright` suite therefore leaves no a11y result channel except those suites.

## Patterns to follow
- Per a11y-plan §1 (A11y assertion harness specification → CI integration): add no new `suite` enum value, and route a11y results only through the existing suites of the harness `run` JSON. After the cut the gate is `gate --require coverage,doctest`, with no a11y-specific suite added to replace `playwright`.
- Per a11y-plan §2 A11y Strategy: the Standard-tier depth for cli / tui is SGR discipline, the tui keystroke boundary and the trycmd-pinned `unable … hint:` layout. These are the checks that stay; the cut leaves them as they are.
- Per a11y-plan §9 CI Integration (the Unit / integration row): the cli / tui stage runs on all three OS legs and is consumed by the per-OS `test` job's gate. Only the `playwright` member leaves that row's `gate --require` list.

## Anti-patterns to avoid
- a11y-plan §11 CI bans skipping a11y on CI failure and bans human-only review without machine output. The removal must not mark any cli / tui output-discipline case `#[ignore]` or skip it, and must not move it out of the gated `coverage` suite.
- a11y-plan §11 SLO bans a retry-once policy and soft budgets. No retry or `allow`-to-fail may be introduced while the `test` job's steps are reshaped.
- a11y-plan §11 Strategy bans claiming WCAG conformance for cli / tui. No text written in this chunk (a commit, a comment, the plan's Expected amendments) may recast the remaining assert_cmd / trycmd / portable-pty cases as a11y-tool evidence in place of the removed axe leg.
