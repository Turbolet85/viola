## Patterns to follow
- A ban and its probe travel together: each cargo-deny ban has a throwaway project in `scripts/deny-probes.sh` that must fail with its own diagnostic, and a clean control must pass both configs (per architecture §Infrastructure Patterns → Build system).
- `windows-mutants.yml`'s `matrix.include` file lists are kept equal to the gated sources by `tests/contract_windows_mutation_scope.rs`; dropping `crates/viola-e2e/src/harness/run/browser.rs` from a list must keep that contract test green, and whether the item count (ten `- package:` items) changes is research's question (per architecture §Infrastructure Patterns → CI/CD approach).
- Process-log roles are `run-<name>`, `hook-<name>`, `mcp` and `cli-<name>` only; a `ui` role file name has no place in the plan's role set (per architecture §Cross-cutting Patterns, Diagnostic output channels).
- Readers skip and count unknown kinds and fields, so narrowing a closed vocabulary that has no emitter strands no reader (per architecture §Cross-cutting Patterns, Mixed-version tolerance).

## Anti-patterns to avoid
- Node, npm or a setup action on any runner image as a replacement: the plan admits Node only as the sha256-pinned official build, so after removal no step installs, checks or runs `node` / `npm` / `npx` by any other route (per architecture §Stack and Technologies, Browser e2e row).
- A new or reserved workspace crate (e.g. a placeholder `viola-ui`) or a new `[workspace.dependencies]` entry: the workspace members are the seven the Build system lists, all `publish = false` (per architecture §Inherited Defaults, Publishability).
- A listening TCP port or a port-bound test group kept as live infrastructure: 0.1.0 holds no listening TCP port, so the nextest `fixed-port` group has no subject (per architecture §Occupied Resources).
