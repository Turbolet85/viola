# a11y extract

## Relevance
partial: the chunk builds the cli-surface output-discipline layer that a11y-plan asserts, but no human-output verb and no web surface. The cli carries no WCAG conformance claim, so the checks here are output-discipline stand-ins only.

## Constraints
- Colour is only ever a second cue. The only SGR spans allowed are amber on the `DIALOG` word, dim over a stale row and bold on NAME column values, and each span always sits beside its word. `unable` / `fail` never carry SGR (per a11y-plan §6 Visual Design Verification → State color tokens (not-color-alone), "CLI equivalent"; §4 ARIA Patterns & Roles → P6).
- viola emits zero SGR, glyph or cursor control of its own under `--json`, non-TTY, `NO_COLOR`, `TERM=dumb` or `viola run` (per a11y-plan §1 A11y Scope Summary → Surface: cli → Notes; §6 → State color tokens, "CLI equivalent"). Under `viola run` on Windows, ConPTY's own SGR and cursor bytes reach the stream, so the requirement there is that viola's own literals are absent (per a11y-plan §6 → State color tokens).
- Output is static and linear, with no spinner, no `\r` redraw, no cursor movement and no erase sequence (per a11y-plan §1 → Surface: cli → Notes; §4 → P6; §5 Keyboard Navigation, cli: N/A, no redraw).
- C0/C1 controls in upstream-origin text are escaped, never stripped. `wait` / `last` text keeps raw `\n` / `\t`. `list` table rows escape `\n` / `\t` too (`\x0A`, `\x09`), so each row stays one fixed-width line (per a11y-plan §4 → P6, ratified T5; §12 A11y Decisions Log Z3).
- The stream split must keep refusals readable as text. A human-mode refusal is `unable  <reason>  <detail>` on stderr, and `hint:` is the last stderr line. `unknown` (exit 14) is the one refusal with no hint. Faults (`error: internal error`, `error: wrapper fault`) are not refusals and carry no hint. `--json` is one document and carries no hint text (per a11y-plan §8 Cognitive Accessibility → Error recovery; §11 A11y Anti-Patterns → Cognitive).
- The `viola ui` launch block goes to stderr exactly once as design's two lines, unstyled even on a TTY. The layer's routing must allow this, although the verb itself is out of scope here (per a11y-plan §4 → P6; §12 Decisions Log Z13).
- These CLI checks must pass on all three OS legs `[windows-2025, macos-latest, ubuntu-latest]` (per a11y-plan §1 → Surface: cli → Notes; §10 SLO Invariants & A11y Budgets → Standard+ invariants).

## Patterns to follow
- Output-discipline assertions use the tests' existing CLI drivers: assert_cmd + predicates and trycmd for the non-TTY modes, and the portable-pty outer PTY for TTY-only SGR checks. No a11y tool is added and no a11y violation rows are produced (per a11y-plan §3 A11y Assertion Harness Contract → A11y testing tool pick, cli; Structured violation JSON schema, "cli / tui: no a11y rows").
- The checks run inside `nextest-integration` / `nextest-e2e` locally, and in CI inside the per-OS `test` job's single instrumented `coverage` suite, under the tests' mutation gate where they live in crate tests. No new `suite` value is introduced (per a11y-plan §3 → CI integration; §9 CI Integration; §10 → Standard+ invariants).
- State is always carried by the printed ASCII word, with colour added on top. The words `[RB]`, `DIALOG <kind>`, `stale`, `unable` and `human` must be present in every mode (per a11y-plan §1 → A11y triggers → visual-discrimination; §8 → Consistency and predictability, `[RB]` ↔ `data-rb="read"`).
- A supplemental manual screen-reader pass covers cli steps P4 / P6 (NVDA + Windows Terminal/conhost, VoiceOver, Orca): linear output, refusals read as text, no escape noise. It is never the gating method (per a11y-plan §7 Screen Reader Support → Per-surface SR test pattern, cli row).

## Anti-patterns to avoid
- Never colour CLI `unable` / `fail`, and never emit SGR under non-TTY, `NO_COLOR`, `TERM=dumb`, `--json` or `viola run` (per a11y-plan §11 A11y Anti-Patterns → Visual).
- Never claim WCAG conformance for the cli. assert_cmd, trycmd and portable-pty results stand in for SC 1.3.2, 1.4.1 and 3.3.1 only (per a11y-plan §11 → Strategy).
- Never convey state by colour alone, and never add a spinner or redraw (per a11y-plan §11 → Visual, Motion).

## Contract bindings
- **a11y ↔ design-system:** the token set (amber / dim / bold), the depth table and the colour decision order are design-system §Surface: cli. a11y binds only the not-colour-alone and no-SGR-in-plain-modes outcomes (per a11y-plan §6 → State color tokens; §12 Decisions Log Z12). No contrast token-pair assertion applies to terminal SGR.
- **a11y ↔ security-plan:** C0/C1 escaping follows security-plan §Input Validation, and a11y-plan §4 P6 adds the `list`-row `\n` / `\t` escape. a11y requires `NO_COLOR` and `TERM=dumb` to turn colour off. Whether reading those env vars fits the security-plan env-var sentence is the security/P3 premise, not an a11y decision.
- **a11y ↔ tests:** CLI output-discipline cases live in the tests' nextest suites (CI `coverage` suite) on all three OS legs. They produce no a11y rows and no `@sc-*` tags (per a11y-plan §3 → CI integration; §9 CI Integration).
- **a11y ↔ obs:** the catch-site `error: internal error` line is a fault. It is printed uncoloured with no `hint:` (per a11y-plan §8 → Error recovery), which matches the obs-plan §7 CARRY.

## Acceptance criteria contributions
- (a11y) With each of `NO_COLOR` set, `TERM=dumb`, stdout not a terminal, `--json` and the `viola run` / `viola hook` / `viola mcp` modes, the layer's output contains no ESC/CSI byte and no glyph. In every human mode it still prints the ASCII words (`[RB]`, `[  ]`, `[/ ]`, `->`, `DIALOG`, `stale`) (per a11y-plan §4 → P6; §11 → Visual).
- (a11y) In colour mode, every SGR span the layer emits wraps only its word and ends with a reset: amber only on `DIALOG`, which is followed by the uncoloured kind word; dim only on a whole stale row; bold only on NAME values. A styled `unable` / `fail` is impossible or fails a test. Whether these checks can run through the portable-pty outer PTY before any consuming verb exists, rather than as unit tests over the pure decision function, is research's question (per a11y-plan §6 → State color tokens, "CLI equivalent"; §4 → P6).
- (a11y) The escape function renders every injected C0/C1 byte (including ESC / CSI and DEL) as `\xHH` text. It keeps raw `\n` / `\t` in message mode and escapes them in `list`-row mode, so the row is a single line (per a11y-plan §4 → P6).
- (a11y) The stream split routes a refusal as `unable <reason> <detail>` and then `hint:` as the last stderr line (no hint for `unknown`), and routes a fault as a bare `error: …` line with no hint. Under `--json`, stdout carries exactly one document and stderr carries no `hint:`. These tests run on all three OS legs (per a11y-plan §8 → Error recovery; §10 → Standard+ invariants).
