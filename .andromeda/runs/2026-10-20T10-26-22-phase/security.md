## Relevance
partial — no new product surface, but item (7) commits a recorded live exchange as a fixture and adds an E2E replay over the MCP client, item (5) touches a dependency gate and moves files that hold escaping and probe controls, and item (4)'s kills aim at the liveness pre-check and at harness removal and scratch guards.

## Constraints
- A recorded live `tools/list` exchange committed to the tree is a repository fixture: security-plan §Data Protection (At rest → Repository fixtures) requires a synthetic probe prompt, the home-prefix → `~` and user-word → `<user>` scrub of every string and key before any write, and a whole-recording refusal (nothing written; refusal naming the file and a closed code `home-path` · `absolute-path` · `username` · `email`, never the content) when a home path, drive path, user word or email-shaped token survives. If the capture is made test-side rather than through `viola verify --record`, whether it applies the same scrub and refusal is research's question.
- The recording and every capture made on the way to it must hold no R8-stripped `CLAUDE*` value: security-plan §Bootstrap phases (`logging-redaction-wire`) puts fixtures under the consolidated NEVER-log floor. The live `claude` start that makes it is a direct spawn under the R8 strip, never through a shell, per security-plan §Threat Model Summary (Attack surface → Child process spawning and PATH resolution) and §Secret Management (Storage → Production, the R8 rule).
- The E2E replay case stays inside the MCP transport feature fence: security-plan §API Security requires rmcp features exactly `server` + `transport-io` in `viola`'s release graph (`scripts/rmcp-features.sh`) and the test-only `viola-e2e` taking rmcp `client` only, never `transport-child-process`. Whether the replay can be driven without widening `viola-e2e`'s rmcp features is research's question.
- The `viola-mcp` → `serde` closure (item 5) must leave `cargo deny check` (all four families) and the per-crate bans green: security-plan §Dependency Security (Audit tool, `deny.toml` additions, Pinning) requires `[workspace.dependencies]` pins unchanged in kind and `Cargo.lock` committed. A machete `ignored` entry is a gate-silencing form the plan must name if chosen; whether `serde` has a real use in `viola-mcp` is research's question.
- Kills aimed at `viola_state::liveness::live_endpoint` (rows 15, 16) bind to the liveness-only pre-check that security-plan §Authentication & Authorization (IPC client-side server verification row) requires before the CLI `answer` / `pause` / `release` and `viola mcp` tool frames (else `instance-unreachable`, exit 21 on the CLI). A test kills such a mutant only by observing that refusal or the frame; the dated exceptions stay exactly as recorded and no test may treat the pre-check as server verification.
- The pure moves of `src/human/board.rs` and `src/cmd/verify/typed.rs` (item 5) change no control: security-plan §Bootstrap phases (`logging-redaction-wire`) requires every human-mode `list` row, the unwrapped row's NAME included, printed through `escape_row`; security-plan §Threat Model Summary (Attack surface → Child process spawning and PATH resolution) requires Run B's pastes to stay compiled literals, its screen read only against compiled signature literals, its output capped at `MAX_FRAME`.
- Kills aimed at `HarnessSession::drop` and `mutants/scratch.rs::prepare` (rows 4–9) must not loosen the guards they exercise: security-plan §Security Anti-Patterns (Code Patterns) requires the `run --mutants` wipe to take only `<repo parent>/viola-mutants-scratch` (`scratch-refused` otherwise, no path printed, re-created through `create_private_dir`), and test-side removal under `target/e2e-home` to take only dirs the test side itself created (by `owner.json` record, its own `TempDir`, or the `viola-session-` name), with the 9 GiB `statvfs` headroom refusal intact.

## Patterns to follow
- The `--record` scrub and closed-code refusal of `viola verify` (security-plan §Data Protection, Repository fixtures) as the model for any new committed recording, including the kept `workspace.repo` carve-out and nothing wider.
- `viola_state::fs::replace_private` / `create_private_dir` for any file or dir a test or capture writes under a home (security-plan §Authentication & Authorization, `~/.viola/` access control row): 0700 dirs, 0600 files set explicitly, never the umask.
- Hand-applied mutants over a scratch clone, not a `cargo mutants` run; the clone kept under a fresh, uniquely named test-created dir so its removal falls under the test-side removal rule (security-plan §Security Anti-Patterns, Code Patterns).
- The MCP error shape a replay case asserts against: `isError` codes only, `refused: <code>` text, any other fault `-32603` `internal error` / `data: null` (security-plan §Error Handling, External responses).

## Anti-patterns to avoid
- Committing a recording from a session with a real (non-synthetic) prompt, or before checking it for home paths and usernames (security-plan §Security Anti-Patterns, Data Protection).
- Capturing the live exchange by adding a listener, a tee proxy behind a PATH-resolved or shell-run `command`, or a second shell-out: every exec-form `command` in `.mcp.json` must be an absolute path (security-plan §Security Anti-Patterns, Universal; Code Patterns, `statusline_command` the only shell-out).
- Reaching green on the `serde` reading or the deny gates by an `ignore`, `skip`, `allow` or widened exception without naming it in the plan (security-plan §Dependency Security, `deny.toml` additions and the Decisions Log rule for any new exception).
