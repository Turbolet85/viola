## Relevance
partial: only item (5)'s split of `src/human/board.rs` (the `viola list` human board, a cli a11y entity) reaches an a11y surface. The `src/cmd/verify/typed.rs` split touches one only if it holds `verify`'s printed step or refusal lines, and whether it does is research's question. Item (4)'s survivors (`viola-mcp`, `viola-state` liveness, the `viola-e2e` harness, the ledger and statusline) and item (7)'s MCP `tools/list` recording sit on surfaces the plan marks not-assertable (plugin / MCP / IPC, internal crates), per a11y-plan §1 A11y Scope Summary ("Not-assertable (no UI surface)").

## Constraints
- a11y-plan §4 ARIA Patterns & Roles (P6) names the unit cases in `src/human/board.rs` that pin the board: `board_row_caption_and_default_row_are_the_literals` (the caption-order mirror NAME · LIVE · STATUS · WHEEL · DIALOG · CLI), the `board_row_style_*` cases (dim only on stale rows is proven at this unit tier alone), the `board_row_width_*` cases, `escape_row_shows_every_control_character_as_hex_text` and `board_row_cli_cell`. The M2 split requires every one of them to survive the move with its assertions unchanged. A moved case may change its module path, but no case may be dropped, merged or weakened.
- a11y-plan §8 Cognitive Accessibility (Plain language) requires `viola list`'s fixed strings to stay pinned by literal: the board, the empty-board line and the refusal pairs, through the `src/human/board.rs` units `bay_line_*`, `board_row_*` and `instance_and_home_state_pairs_are_the_fixed_texts`, plus `tests/cli_list.rs`. The split must change no byte of those literals.
- a11y-plan §6 Visual Design Verification requires `viola list`'s colour behaviour to be unchanged:
  - bold only on NAME values, amber only on the `DIALOG` word, and a stale row dim from end to end;
  - no SGR on the BAY line, the caption, the empty-board line or the separator;
  - the `NO_COLOR` / `TERM` / `COLORTERM` / terminal-stdout rungs, and the truncation of an unwrapped NAME only on a terminal that is too narrow, never inside a `\xHH` escape.
  The move must not change any of these. Whether all of them live in `board.rs`, or partly in `src/human/style.rs`, is research's question.
- a11y-plan §1 A11y Scope Summary (cli Notes) requires the board to stay static and linear, with no spinner or redraw, and every C0/C1 control in a `list` row escaped, `\n` / `\t` included. The split moves `escape_row`'s home only, never its behaviour.
- a11y-plan §8 Cognitive Accessibility (Consistency and predictability, SC 3.2.4) requires the `CAPTION` literal in `list_human_board_is_the_literal_rows` (`tests/cli_list.rs`) to keep the caption order that the board's own rendering prints after the split.
- a11y-plan §10 SLO Invariants & A11y Budgets puts the CLI output-discipline invariants that live in crate tests under the epoch-boundary mutation audit (`run --mutants`). So the `board.rs` units have to stay where the root package's audit run reaches them after the move. That means a `#[cfg(test)]` module inside the `viola` package, not one moved to a crate or a test target the unit run does not execute.

## Patterns to follow
- The split precedent the scope names: `src/run/send.rs` → `src/run/send/*`, a module directory with the tests kept beside the concern they pin. Per a11y-plan §8 Cognitive Accessibility (Plain language), the literal-pinning units stay named exactly as the plan cites them.
- Per a11y-plan §9 CI Integration and §3 CI integration: the cli output-discipline cases are ordinary nextest cases that run in the existing suites. A moved case keeps running inside the per-OS `test` job's `coverage` suite under `gate --require coverage,doctest`, with no new suite or driver.
- Per a11y-plan §4 ARIA Patterns & Roles (P6): the board's structural equivalents (the BAY line, the caption line, the wrapped rows, then the `-- UNWRAPPED - READ-ONLY --` separator printed only when unwrapped rows exist) are one concern. If the split cuts by concern, the rendering order stays in one place.

## Anti-patterns to avoid
- a11y-plan §11 A11y Anti-Patterns, Cognitive, bans letting the caption set or order of `viola list` drift from its `CAPTION` literal (SC 3.2.4). A split that re-derives captions in a new module without that literal pin would allow drift.
- a11y-plan §11 A11y Anti-Patterns, Visual, bans conveying state by colour alone and bans SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json`. A moved style path must not lose the word beside its span.
- a11y-plan §11 A11y Anti-Patterns, SLO, bans retry-once policies. A moved case that turns flaky keeps the chunk red until its cause is known; it is never re-run to green.

## Contract bindings
- The cli output-discipline cases bind to the tests harness: a11y-plan §3 CI integration and §9 CI Integration route them through `scripts/agent-run.sh run` and `gate --require coverage,doctest`. They add no `suite` value (per a11y-plan §11 A11y Anti-Patterns, CI).
- The `board.rs` unit witnesses bind to test-plan §10 through a11y-plan §10 SLO Invariants & A11y Budgets, which says the epoch-boundary mutation audit covers crate-test invariants. The split's tests must stay where the root package's `mutants` profile run executes them.
- The board's colour and caption pins bind to design-system cli, through a11y-plan §6 Visual Design Verification and §8 Cognitive Accessibility (Consistency and predictability).
