# a11y extract

## Relevance
Partial. This chunk builds no UI surface, so the web-spa WCAG content (a11y-plan §4–§8) does not apply. The CI matrix, the five-command harness, the `run` suite grammar, the per-role JSON line and nextest are the pieces a11y-plan §3, §9 and §10 plug into later, and those contracts constrain this chunk.

## Constraints
- a11y-plan §3 "CI integration" and §9 "Pipeline integration" require a11y to run only through the five-command harness, via `scripts/agent-run.{sh,ps1} run --browser`. Results must land in the existing `playwright` entry of the `run` JSON `suites[{suite,passed,failed,skipped,artifact}]`, with failures in `suites[].failures[]`. The `run` summary grammar built here must keep that shape.
- a11y-plan §3 "CI integration" and §9 require `--browser` on the Windows and macOS legs to exit 2 with `reason:"browser-linux-only"`. A missing Chromium must be a failure with `reason:"browser-missing"`, never a skip. The scope says `--browser` exists here only as grammar or a clean refusal, so any refusal built now must follow these reasons and exit codes. Whether that refusal is built now or deferred is a P4 decision.
- a11y-plan §9 "Platform" requires one workflow, `ci.yml`, with the matrix `[windows-2025, macos-latest, ubuntu-latest]`. §3 "A11y testing tool pick" and §10 "Standard+ invariants" place the CLI output-discipline checks (assert_cmd / trycmd / portable-pty) inside `nextest-integration` / `nextest-e2e` on all three OS legs, under the tests' mutation gate. This chunk's nextest suites and mutation gate are the home those checks will need.
- a11y-plan §10 "Cross-input parallel" matches a11y's zero-violation invariant to the tests' zero-flakiness rule: `retries: 0`, no `test.skip` or `#[ignore]`. The nextest `[profile.ci]` built here must keep `retries = 0`.
- a11y-plan §3 "Structured violation JSON schema" (Binding fields; D-A11Y-09) has a11y rows mirror the obs binding field names `timestamp`, `level`, `target`, `message`, `event`, `process` without renaming any. `instance` and `corr` are left absent, never a literal `null`. The per-role diagnostics line started here is the first product use of those names. Whether it already writes absent keys rather than `null` is a question for research and testing.
- a11y-plan §9 "Artifact retention" requires `actions/upload-artifact` v7.0.1, pinned by SHA per zizmor. The later a11y-ci-gate-wire phase (§3 "Bootstrap phases") adds an `if: always()` upload of `e2e-web/test-results/` to the ubuntu leg, but only if `ci.yml` lacks one. The upload step built here should use the same action at the same pin.

## Patterns to follow
- A single test entry point. a11y-plan §3 "CI integration" and §9 route every a11y check through the harness `run` and `gate`, with `status` as the readiness precondition and `logs` as the triage read. The a11y plan never names a second driver, so the harness grammar should leave no path for one.
- Harness-side artifacts stay outside `<home>/diagnostics/`. a11y-plan §3 "Structured violation JSON schema" (Emission location) writes a11y rows only under `e2e-web/test-results/a11y/`, validated by a tests-owned schema. That is the same split this chunk makes between `target/agent-run/artifacts/` and the product `diagnostics/*.ndjson` files.
- The ubuntu leg carries the browser-bound and lint stages. a11y-plan §9 (per-stage table) and D-A11Y-14 put a lint stage on the ubuntu leg before `run --browser`, "like clippy/zizmor", and add no harness `suite`. `ci.yml` jobs should be laid out so that a later ubuntu-only step can be inserted before `run --browser`.
- The fake agent as the TUI boundary child. a11y-plan §3 "Keyboard test harness" (Tooling) uses the tests' `viola-fake-agent` as the child for the later zero-viola-bytes boundary cases on all three OS legs. The minimal fake agent built here is the binary those cases will run. Its scripted modes belong to the next chunk.

## Anti-patterns to avoid
- Adding a `suite` value such as `a11y`, a `webServer`, or a separate `npm test:a11y` driver outside `scripts/agent-run.* run --browser`. Treating `browser-missing` as a skip, or running `--browser` on the Windows or macOS legs. (a11y-plan §11 CI)
- A retry-once policy, or parking a check with `test.skip`, `test.fixme` or a quarantine tag. (a11y-plan §11 SLO; §10)
- Writing a11y violation rows into `<home>/diagnostics/`, renaming an obs binding field, or writing a literal `null` for `corr` or `instance`. (a11y-plan §11 Universal)

## Contract bindings
- a11y ↔ tests harness: the `run` JSON `suites[]` shape and the closed `suite` enum (`playwright`, `nextest-integration`, `nextest-e2e`), the `--browser` refusal reasons `browser-linux-only` / `browser-missing`, and `gate --require playwright` as the later a11y gate. (a11y-plan §3 CI integration; §9)
- a11y ↔ obs: a11y harness rows mirror the obs process-log binding field names without renaming them, with absent-means-null. The per-role JSON line built here fixes those names first. (a11y-plan §3 Structured violation JSON schema; D-A11Y-09)
- a11y ↔ security/CI: `actions/upload-artifact` v7.0.1 pinned by SHA per zizmor, in the same `ci.yml` whose `uses:` pins this chunk sets up. (a11y-plan §9 Artifact retention)

## Acceptance criteria contributions
- If `agent-run run --browser` is accepted by the grammar in this chunk, it exits 2 with `reason:"browser-linux-only"` on the Windows and macOS legs. On ubuntu it never reports the `playwright` suite as passed or skipped when the suite did not run. (per a11y-plan §3 CI integration; §11 CI)
- The `run` JSON contains no `suite` value outside the tests-defined enum; in particular there is no `a11y`. Each `suites[]` entry carries `suite`, `passed`, `failed`, `skipped`, `artifact` and `failures[]`. (per a11y-plan §9 Pipeline integration)
- `.config/nextest.toml` `[profile.ci]` sets `retries = 0`, and no test is `#[ignore]`d. (per a11y-plan §10 Cross-input parallel)
- The per-role `<home>/diagnostics/<role>.ndjson` line uses the unrenamed field names `timestamp`, `level`, `target`, `message`, `event`, `process`, and leaves `instance`/`corr` absent rather than writing `null`. (per a11y-plan §3 Structured violation JSON schema)
