# a11y extract

## Relevance
partial. The hold and its record are mostly hook and IPC mechanics, which have no UI surface (per a11y-plan §1 A11y Scope Summary, Not-assertable). The a11y surface is in three places: the human's keyboard during a long hold (the tui boundary), the human-mode `wait` line and the late-`answer` refusal (cli), and the timeout clause the plan states for the dialog deadline.

## Constraints
- The dialog hold must bound the driver only, however long it is or however it is configured. No key may be blocked, refused or delayed by it, the wheel stays untouched, and an expired dialog still renders for the human in the `claude` TUI. a11y-plan §8 Cognitive Accessibility → Timeout extensions requires this. Its current text names `DIALOG_DEADLINE` 60 s PROVISIONAL, the `hooks.json` `timeout` of 75 s, and a late `answer` refused `not-delivered` / `unknown-dialog` (exit 13). Each of these is a value the chunk may move.
- A human key during a held dialog must hand the dialog back and take the wheel at once, past at most the current atomic paste, whatever the hold length (per a11y-plan §1 A11y Scope Summary, tui boundary clauses). Whether `hand_back` already holds for a hold longer than 60 s or for a configured hold is research's question.
- No hold setting may make time a limit on the human. SC 2.2.1's warn-extend pattern is avoided because v1 has no human-facing time limit, and that must stay true (per a11y-plan §11 A11y Anti-Patterns → Cognitive).
- The wrapper must write no bytes of its own to the terminal while a dialog is held, at expiry, or when the expired-hold record is written. viola writes zero bytes except the child's output (per a11y-plan §1 A11y Scope Summary, tui boundary). The record belongs in `events.ndjson` and diagnostics, never on the outer PTY.
- If a new human-mode `wait` line reports an expired hold, it must be static and linear: no spinner or redraw, no SGR under non-TTY, `NO_COLOR`, `TERM=dumb` or `--json`, and colour, if any, only as a second cue beside its word (per a11y-plan §1 A11y Scope Summary, cli Notes). Path P6's `wait` checks cover this line too (per a11y-plan §4 ARIA Patterns & Roles, P6). Whether the human `wait` renderer (`src/human.rs`) already meets this for a new kind is research's question.
- A late `answer` refusal (today `unknown-dialog`, or any new detail code the record introduces) must be printed in human mode as `unable  <reason>  <detail>` with `hint:` as the last stderr line and a typed exit code. Under `--json` it must be one document with no hint (per a11y-plan §8 Cognitive Accessibility → Error recovery).
- Any new kebab-case kind or detail code must always appear beside the plain word `unable`, and any new fixed copy (the `wait` line, a hint) must be pinned by trycmd or a literal, so a copy change fails CI (per a11y-plan §8 Cognitive Accessibility → Plain language).

## Patterns to follow
- A state-specific outer-PTY reading, shaped like `path6_a_reading_over_the_threshold_refuses_the_send` (`tests/cli_budget.rs`): with the state in force, a human key reaches the child and the outer-PTY stream holds none of `unable`, `hint:` or the state's code. Sequence it on the wrapper's log records (`channel-request`, `wheel`), never on a timer (per a11y-plan §3 Keyboard test harness).
- The P6 TTY checks for `viola wait`: no ESC byte and no lone CR on Unix through `tests/support/sgr.rs` `redraws`, and no SGR in the piped, `NO_COLOR`, `TERM=dumb` and `--json` modes, on all three OS legs (per a11y-plan §4 ARIA Patterns & Roles, P6).
- Write each time bound as one sentence saying it "falls on the driver only", and that no key is blocked, refused or delayed and the wheel is untouched. The existing `GATE_MAX_WAIT`, `CONFIRM_WINDOW_FALLBACK`, `COMPACT_CONFIRM_WINDOW` and budget-pause bounds all use this form (per a11y-plan §8 Cognitive Accessibility → Timeout extensions).
- Pin typed exit codes (`10`–`14`) with assert_cmd and refusal pairs with trycmd or a literal, with `--json` carrying no hint text (per a11y-plan §8 Cognitive Accessibility → Error recovery).

## Anti-patterns to avoid
- NEVER block, refuse or delay a human keystroke during a held dialog, and never let a longer hold or a hold setting gate the human's hand-back (per a11y-plan §11 A11y Anti-Patterns → Keyboard).
- NEVER detect a dialog's expiry by parsing the rendered `claude` TUI screen, and never take a screenshot as evidence (per a11y-plan §11 A11y Anti-Patterns → Universal (agent-driven specific)).
- NEVER colour `unable` or emit SGR on the new `wait` line under non-TTY, `NO_COLOR`, `TERM=dumb` or `--json`, and never let colour alone carry the expired state (per a11y-plan §11 A11y Anti-Patterns → Visual).

## Contract bindings
- a11y-plan §8 Cognitive Accessibility → Timeout extensions ↔ architecture's dialog-deadline and Hook Contract values (`DIALOG_DEADLINE`, the `hooks.json` dialog `timeout`) and obs-plan's event catalog. The a11y clause restates the 60 s, 75 s and `unknown-dialog` values and the absence of any expiry record. Once the chunk lands it must be read against the landed hold, the record kind and the late-`answer` refusal, and amended between runs.
- a11y-plan §4 ARIA Patterns & Roles, P6 ↔ the tests harness (a11y-plan §3 CI integration): the new `wait`-line and outer-PTY cases run as ordinary nextest cases inside the per-OS `coverage` suite, under `gate --require coverage,doctest`. They add no `suite` value and no separate driver.
- a11y-plan §8 Cognitive Accessibility → Error recovery ↔ design-system's cli refusal pattern (`unable … hint:` last): a new refusal detail takes that layout.

## Acceptance criteria contributions
- An outer-PTY nextest case, run on all three OS legs, holds a dialog under the new hold, either past the old 60 s or under a configured value, and types a human key. The key hands the dialog back, writes a `wheel` record with holder `human`, and reaches the child. The outer-PTY stream holds none of viola's own literals, either during the hold or at its expiry (per a11y-plan §3 Keyboard test harness).
- The human-mode `viola wait` output for an expired-hold record is one static line. It carries no ESC byte and no lone CR when piped or under `NO_COLOR` / `TERM=dumb`, carries no SGR under `--json`, and is pinned by literal or trycmd (per a11y-plan §4 ARIA Patterns & Roles, P6).
- A late `viola answer` for an expired dialog exits with its typed code (13 today). In human mode stderr is `unable  not-delivered  <detail>` with `hint:` last, and under `--json` one document with no hint (per a11y-plan §8 Cognitive Accessibility → Error recovery).
- The landed hold is stated as a driver-only bound: no key blocked, refused or delayed, the wheel untouched, and the dialog left to the human at expiry. Nothing in the hold or its setting introduces a human-facing time limit (per a11y-plan §8 Cognitive Accessibility → Timeout extensions).
