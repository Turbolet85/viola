# a11y extract

## Relevance
Partial. The chunk has no web-spa surface. Only the `viola run` TUI boundary (tui, boundary-only) and the CLI refusal output on the pre-spawn exit-1 paths (live-name refusal, pinned re-hash mismatch) fall in a11y's domain. The event log, snapshot, heartbeat, `bin/` and the plugin folder are out of domain.

## Constraints
- **viola writes no bytes of its own to the terminal.** Under `viola run` the only bytes on the terminal are the child's. That covers the whole new start sequence: collision check, pinned copy, plugin-folder write, version gate, first snapshot and heartbeat, start events. Diagnostics from these steps go to `diagnostics/`, never the terminal (per a11y-plan §1 tui surface → Notes; §3 Keyboard test harness → Tooling). On Windows the oracle is that viola's own literals are absent, because ConPTY emits its own control bytes. On Linux and macOS the output must match an unwrapped run byte for byte (per a11y-plan §3 Keyboard test harness → Tooling; §6 State color tokens → CLI equivalent).
- **No SGR under `viola run`**, and none under non-TTY, `NO_COLOR` or `TERM=dumb`. `unable` / `fail` are never coloured. This applies to any refusal or fault text the start path writes (per a11y-plan §6 State color tokens → CLI equivalent; §11 Visual).
- **Refusal text shape.** A CLI refusal is `unable  <reason>  <detail>` on stderr, then `hint:` as the last stderr line, with a typed exit code. Faults (`error: wrapper fault`, `error: internal error`) are not refusals and carry no hint (per a11y-plan §8 Error recovery).
  - The plan's typed refusal codes are `10`–`14`, `20` and `21`. The chunk's live-name refusal and pinned re-hash mismatch both exit `1`.
  - Whether exit 1 is a refusal (needs `unable … hint:`) or a fault (`error: …`, no hint) is for research to settle against design cli and the test-plan §6 exit-cause matrix. So is which stderr text the code emits today.
- **Error text must be plain words.** A kebab-case reason/detail code never appears without the plain word `unable`. No stack trace, URN or bare status appears as the only error text (per a11y-plan §8 Plain language; §11 Cognitive).
- **Human keystrokes are never blocked.** Adding snapshot, heartbeat and start-event work before and around the spawn must not block or delay human keystrokes past the current atomic paste (per a11y-plan §1 tui boundary clause; §5 Focus order per layout → tui; §11 Keyboard).
- **No WCAG conformance claim for the cli or the `viola run` TUI.** Any check this chunk adds is an output-discipline stand-in only (per a11y-plan §11 Strategy).

## Patterns to follow
- Terminal-boundary assertions run as portable-pty outer-PTY nextest cases on all three OS legs, with `viola-fake-agent` as the child (per a11y-plan §3 Keyboard test harness → Tooling; §4 P4 tui).
- Refusal layout is pinned with trycmd and exit codes are checked with assert_cmd, on `[windows-2025, macos-latest, ubuntu-latest]` (per a11y-plan §8 Error recovery → Verification).
- These CLI output-discipline checks report under `nextest-integration` / `nextest-e2e` locally and under the `coverage` suite in CI. No new suite enum is added (per a11y-plan §9 Per-pipeline-stage table; §10 Standard+ invariants).

## Anti-patterns to avoid
- NEVER emit SGR or viola-originated diagnostic or refusal text onto the `viola run` terminal stream. Start-sequence diagnostics go to `diagnostics/` (per a11y-plan §11 Visual; §1 tui Notes).
- NEVER block, refuse or delay a human keystroke in `viola run` past the current atomic paste (per a11y-plan §11 Keyboard).
- NEVER parse the rendered `claude` TUI for content as evidence (R7) (per a11y-plan §11 Universal).

## Contract bindings
- **a11y ↔ obs.** The zero-viola-bytes rule requires that the start-sequence process logs (`process-start` etc.) and any refusal diagnostics go to `<home>/diagnostics/run-<name>.ndjson`, not the terminal. The event-line shape `{"v":1,"ts","instance","kind","source","data"}` for `instances/<name>/events.ndjson` is obs/arch-owned; a11y only mirrors it (per a11y-plan §3 Structured violation JSON schema).
- **a11y ↔ tests.** The three tui boundary nextest cases (zero viola bytes, keystrokes unblocked, focus/mouse/resize ignored) cover start through exit. This chunk changes what runs during "start", so those cases, or their precursors, must stay green (per a11y-plan §4 P4 tui).
- **a11y ↔ design (downstream only).** The heartbeat produces the `live` / `stale` state that the web LIVE column later shows as the word `stale`. Stale is never announced and never moves focus (per a11y-plan §7 Live regions; §5 Focus restoration). No web work falls in this chunk.

## Acceptance criteria contributions
- (a11y) With `viola-fake-agent` as the child, the outer-PTY byte stream across `viola run` start (including the new collision check, pinned copy, plugin-folder write, first snapshot and heartbeat, and start events) through exit carries no viola-originated literal on any leg. On Linux and macOS it also carries no SGR or cursor control the child did not emit (per a11y-plan §3 Keyboard test harness → Tooling).
- (a11y) The live-name refusal and the pinned re-hash mismatch each write their message to stderr only, with no SGR under non-TTY / `NO_COLOR` / `TERM=dumb`, and exit 1. The text shape (`unable <reason> <detail>` + final `hint:`, or `error: …` with no hint) follows whichever class research establishes, and is pinned by trycmd / assert_cmd on all three OS legs (per a11y-plan §8 Error recovery; §6 State color tokens → CLI equivalent).
- (a11y) Human keystrokes injected through the outer PTY during and right after start are delivered unblocked (per a11y-plan §4 P4 tui clause 2).
