## Bindings
- **Error Handling's distinct codes ↔ the Threat Model's IPC vector**: a distinct code tells a same-user process which check refused it, read against the boundary of every process of the same OS user and no other, and any widening of that boundary is the founder's live word, (.andromeda/security-plan.md:35).
- **Error Handling's server-verification code ↔ Authentication's client verification**: telling a mismatch, a replayed snapshot and a check that cannot be made apart adds no frame and no default connect, and claims neither dated gap, the client euid check nor macOS's server check, (.andromeda/security-plan.md:114).
- **Error Handling's strict-modes refusals ↔ Authentication's Unix socket directory**: a failed directory check refuses `run`, reports the unreachable refusal to clients and fails `hook` open; it takes a code only if the code holds that refusal, (.andromeda/security-plan.md:110).
- **Error Handling's `revive` document ↔ Input Validation's CLI and session-id rows**: `revive --json`'s new documents print codes, closed words and session-shaped ids only, and no refusal line or hint holds the recorded directory, a pid or a logged id, (.andromeda/security-plan.md:144), (.andromeda/security-plan.md:166).
- **Error Handling's external bodies ↔ Bootstrap's NEVER-log floor**: paths and internal type names stay off `--json`, MCP `isError` and channel `error.data`, a pid staying in `diagnostics/`, so a new code, document or `process-exit` value holds neither, (.andromeda/security-plan.md:346).
- **Error Handling's refusals ↔ the Universal bans**: giving a refusal its code neither widens nor moves it onto the human's path, refusals going only to automation and hooks failing open, (.andromeda/security-plan.md:510).
