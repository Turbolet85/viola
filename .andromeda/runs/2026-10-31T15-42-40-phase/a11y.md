## Constraints
- a11y-plan §1 A11y Scope Summary sets tier Standard (1) with no conformance claim: `tests/cross_exit_causes.rs` cases are output-discipline stand-ins on text and streams, and a11y-plan §11 Strategy bans presenting them as WCAG evidence (stand-ins for SC 1.3.2 / 1.4.1 / 3.3.1 only).
- a11y-plan §8 Cognitive Accessibility › Error recovery requires, for a human-mode refusal, the printed word and plain detail on stderr, `hint:` as the last stderr line and a typed exit code, with `viola revive`'s exit-1 refusals and `viola verify`'s interrupted pair in the one-line `unable:` form. Whether every cause the catalogue names already has its own pair is research's question; the unwrapped-name hint is named not built by the scope's CARRY.
- a11y-plan §8 Cognitive Accessibility › Error recovery requires that `--json` gives one document, stderr empty and no hint text, the `viola answer` / `viola send` exit-2 paths its one named exception. The scope's table line asks for the exit code, the document and a last stderr `hint:` per case; under this rule the hint reading binds the human mode and the document reading the `--json` mode, one invocation never holding both.
- a11y-plan §8 Cognitive Accessibility › Error recovery requires that faults (`error: internal error`, `error: wrapper fault`) are not refusals and carry no hint, and that on Windows an unstattable home stands as the catch-site fault line with no hint. The scope lists `internal error` as an exit-1 cause, a `claude` not on `PATH` among them, and asks every case for a last `hint:` line. This row cannot hold both as written: P3 reads what the code prints, P4 settles the row (a hint-free named exception, or a move out of the fault form), and that decision is design's as well as this plan's.
- a11y-plan §1 A11y Scope Summary marks owed to this entry the missing document for a refusal `run`'s start makes after a passed `viola revive` preflight under `--json`. The same section's TUI boundary requires zero viola bytes on the terminal except the child's output and no SGR, glyph or cursor control under a passed `viola revive`, so the document has to fall before the child holds the terminal; whether each of those refusals does is research's question.
- a11y-plan §8 Cognitive Accessibility › Plain language requires that a kebab-case code never reaches a human without the plain word `unable` beside it, and that no stack trace or bare status number is the only error text; each new closed code shown in human mode falls under it.
- a11y-plan §6 Visual Design Verification requires no SGR of viola's own under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` and `unable` never coloured, so new hint and `unable` text stays plain; a11y-plan §1 A11y Scope Summary requires the same for the revive refusal pairs and `--json` failure documents (no ESC byte).

## Patterns to follow
- Pin each fixed pair by a named literal, the form a11y-plan §8 Cognitive Accessibility › Plain language names (`HINT`, `INSTANCE_PAIR`, `HOME_PAIR`), so a copy change fails CI until updated on purpose.
- Read each refusal in both modes, the shape a11y-plan §8 Cognitive Accessibility › Error recovery names for `security_negative_cli_verb_writes_no_frame_to_a_server_that_is_not_the_recorded_wrapper`: last-line hint, no ESC byte, stdout empty, or the exact document with stderr empty, and no output holding the pid, the home's path or the endpoint.
- Keep the per-OS oracle a11y-plan §8 Cognitive Accessibility › Error recovery names: server-verify cases gated off macOS (no peer pid, the recorded gap, witness owed to "Unix endpoint and home hardening"), strict-modes cases on all three OS legs, and a home under a regular file read per OS.
- Hold new codes and bodies to the checks a11y-plan §8 Cognitive Accessibility › Error recovery names: `is_code_word`'s shape, `cli_error_documents_hold_no_path_or_upstream_text`, the `tests/contract_error_bodies.rs` census and `assert_error_body_clean`.
- Run the table as ordinary nextest cases in the existing suites, per a11y-plan §3 CI integration.

## Anti-patterns to avoid
- A human-mode refusal without a `hint:` line (`unknown`, exit 14, the one exception), or a kebab-case code without the word `unable` (per a11y-plan §11 Cognitive).
- Colouring `unable`, or emitting SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / a passed `viola revive` (per a11y-plan §11 Visual).
- A new `suite` value or a separate driver for the exit-cause table outside `scripts/agent-run.* run` (per a11y-plan §11 CI).
