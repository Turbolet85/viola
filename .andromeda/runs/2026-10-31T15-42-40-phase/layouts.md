# layouts extract

## Relevance
relevant — surface `cli`, the refusal-line, `hint:` and `--json` document output of exits 21 and 1; no new screen, column, focusable element, breakpoint or dialog, and `web-spa` stays deferred.

## Constraints
- Every cause of exit 21 and of exit 1 requires its own hint, as the last stderr line, so an agent can tell causes apart from that line alone; whether the code already holds one hint per cause is research's question (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column, Hint line).
- `unknown`, `wrapper fault` and `internal error` are required to carry no hint, and a failed or panicked `cli` verb is required to print one fixed line from one catch site; this conflicts with the scope's "each case asserts a last stderr `hint:` line" for its `internal error` cause, so P4 must name that row's form (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column, Line form and Hint line).
- The machine view is required to carry the cause as a detail code once architecture names those codes, and to keep `"detail":null` for exit 21 until then; this plan therefore leans to `detail` on the P4 encoding choice, and the choice stays P4's (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column, Exit codes as the typed tail).
- Under `--json` one outcome is required to be one stdout document, with no stderr line and no hint text, and results and refusals are never mixed across streams; the hint and the code are therefore read from two separate runs of a case (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column, Exit codes as the typed tail and Streams).
- `viola revive --json` owes a document for each refusal `run`'s start makes after a passed preflight (`batch-script-child`, `pinned-hash-mismatch`, `squatted-name`, `internal-error`), and non-`--json` pairs and rows are required to stay byte-identical (per layout-templates §Output structure — `viola revive`).
- `viola mcp` is required to mirror the CLI verb's `--json` document less `v`, with `isError: true`, the text `refused: <code>` and code-only bodies, and no tool, description or result naming `release`, `pause`, `link` or `unlink`; any new code reaches this view by the same rule (per layout-templates §Primary screens (commands)).
- The human columns and words are a stable contract, new fields go into `--json` first, and adding a human column is a design change rather than an implementation choice; the catalogue's codes do not widen a human line by default (per layout-templates §IA notes, Output as a contract).

## Patterns to follow
- Two human refusal forms, chosen by verb and exit: the spaced `unable  <name>  <reason>  <detail>` column, and the fixed-message `unable: <text>` pair of the exit-1 start, `verify` and strict-modes refusals, each followed by its `hint:` line (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column, Line form).
- `viola send` keeps the same refusal word inside its `[/ ]` mirror column, so a new hint for a send cause sits under the mirror line and the mirror's layout does not move (per layout-templates §Component — Hero / signature output line (the `viola send` readback mirror); §Output structure — `viola send`).
- Same-exit causes already told apart by hint alone are the model: `instance-unreachable` with a not-running hint and a not-the-recorded-wrapper hint (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column, Hint line).
- Closed kebab-case code words inside the document shape, as the revive refusals name them (per layout-templates §Output structure — `viola revive`).
- Refusal output stays plain ASCII with no SGR, because colour on this surface is reserved for `DIALOG` and `stale`; a refusal line takes no styling (per layout-templates §Component — Hero / signature output line (the `viola send` readback mirror), Colour).

## Anti-patterns to avoid
- A hint that names `viola release`, a path or a pid, or quotes sent or upstream text (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column, Hint line; §Component — Primary navigation (verb structure), Discoverability).
- Printing a code word, a new column or any other new text on a non-`--json` line for causes whose pair is pinned as fixed (per layout-templates §IA notes, Output as a contract; §Output structure — `viola revive`).
- A terminator, summary or extra line after the hint, which would stop the `hint:` line being last on stderr (per layout-templates §Component — Footer / terminator).

## Acceptance criteria contributions
- For each exit-21 and exit-1 cause with a hint, the last stderr line of its non-`--json` run is a `hint:` line that no other cause in the table shares, and the row for `internal error` asserts the fixed line with no hint (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column).
- For each cause, its `--json` run prints exactly one stdout document, holding its closed code and no path or pid, with stderr empty (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column).
- `viola revive --json` prints a document, exit 1 and empty stderr for each of `batch-script-child`, `pinned-hash-mismatch`, `squatted-name` and `internal-error`, and every non-`--json` revive pair and row is byte-identical to the pre-chunk output (per layout-templates §Output structure — `viola revive`).
- A refused MCP tool call for each code reachable there returns the verb's `--json` document less `v`, `isError: true` and the text `refused: <code>`, and no hint text (per layout-templates §Primary screens (commands)).
