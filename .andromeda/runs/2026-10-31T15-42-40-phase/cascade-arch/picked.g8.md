### cross-cutting-patterns#3.1 · procedure · crosscut-bounded-readers · ## Cross-cutting Patterns · lines 27–27
- **Bounded readers at every boundary.** Every product reader of external bytes is bounded in the same statement (`take`) or named in an `EXCEPTIONS` row; none reads an external byte source to its end unbounded. The E2E contract binary `tests/contract_bounded_readers.rs` (a `contract_` binary, run under `run --e2e`) holds it: its `BOUNDARIES` table, one `Boundary {` block per bounded read, names each read and its witness test, and `boundaries_each_name_a_bounded_read_that_stands` checks that each named read still stands; its `EXCEPTIONS` table names the own-executable reads, which are no external input. A census, `product_readers_are_each_bounded_or_named`, walks the product sources and judges each reader call bounded over its statement up to the call, matching an `EXCEPTIONS` needle against the call's whole source line, because the executable argument the needle names lies past the call's `(`; its self-check, `census_finds_an_unbounded_read_and_passes_a_bounded_one`, reads a planted unbounded read as a hit and passes a bounded one, and `serde_json_unbounded_depth_is_banned_in_deny_toml` reads the `deny.toml` feature ban. A new reader therefore lands bounded in its statement or as a named exception, or the census goes red.
### cross-cutting-patterns#4.1 · procedure · crosscut-sanitised-error-surfaces · ## Cross-cutting Patterns · lines 33–36
- **Sanitised error surfaces.** CLI `--json` documents, MCP error results and channel error data carry codes and fixed messages only, no path and no upstream text; a peer's `message`, `data`, `refusal` or `detail` reaches no document or text but as a closed value, and a code word outside the closed list stays visible by design.
  - The E2E contract binary `tests/contract_error_bodies.rs` (run under `run --e2e`, carrying `andromeda:walks-tree`) holds it: its tables `CLI_DOCUMENTS`, `MCP_RESULTS` and `CHANNEL_FAULTS` enumerate the error bodies, and `error_bodies_each_name_a_writer_and_a_witness_that_stand` checks that each body's writer and witness stand; `NOT_ERROR_BODIES` names what is no error body, and `PLUMBING` the census lines that build or route a document a row names, so a row stays one body. A census, `product_error_writers_are_each_named`, covers the product's error writers, and `thiserror_messages_interpolate_nothing` holds that a `thiserror` message interpolates nothing.
