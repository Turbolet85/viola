# viola-pty

_Crate implementation notes. Primary source: `doc:architecture` [PTY], §Crate dependency direction; security §Data Protection (handle inheritance), §Input Validation (child executable resolution). Generated by `/andromeda-setup-project`._

## Responsibility
viola's own PTY seam over portable-pty `=0.9.0`: spawn · read · write · resize · wait · kill. It hosts the unmodified `claude` (or the fake agent) in an openpty (`pty_backend()` is `openpty`). The crate knows no pinned path. It knows no agent and depends on no viola crate. Child exit is detected on the process handle, never on reader EOF. `pump_with_paste` puts the child's input writer in a `PasteHandle` (one `Mutex`) for the pump's life: the human copy thread writes each chunk through it, and `PasteHandle::paste` writes `ESC[200~` + text + `ESC[201~` + CR as one `write_all` under the lock (span `pty.paste_write`), so a key that arrives during a paste waits only for that paste; `NoInput` before the pump opens the input or after it returns. viola never holds, queues or re-orders a human key behind a resize and never answers DA1 itself.

## Key integrations

### Consumes from
portable-pty `=0.9.0`; tracing (the `pty.spawn` span); libc `=0.2.189` (termios raw mode, terminal size). No thiserror: `PtyError` is hand-written with fixed messages.

### Publishes to
The root bin's `run` pump (`src/run/`), `viola verify`'s five interactive PTY runs (`src/cmd/verify/typed/`), `viola list`'s board width (`viola_pty::host_size()`) and the tests' outer-PTY driver (`tests/support/outer_pty.rs`, `viola-harness supervise`).

### Dependencies
No viola crate. Tokio banned in its graph.

## Internal conventions
- The seam is a trait the product defines, so consumers are tested with a mockall double whose reader never returns EOF while `wait()` returns an exit status.
- The Windows and macOS PTY code (ConPTY, the sideload, the `TerminateProcess` kill fallback) is out of the tree, recoverable at the tag `multi-os-final` (`ecbe7ab3`).
- `host_stdin()` is the host stdin the root bin hands the pump: `std::io::stdin()`. The fake agent reads through it too.
- The PTY byte stream is user content — never logged; spans log `pty_backend` (`viola_pty::pty_backend()`: `openpty`), `text_bytes`, `exit_source` (`handle-wait|kill-fallback`).

## Crate-specific gotchas
- Detect child exit only via `wait()` on the process handle, never on reader EOF.
- `portable-pty` is pinned `=0.9.0`: its graph holds neither `pin-utils` (RUSTSEC-2026-0441) nor the `serial` crate family, and `viola-pty` builds and passes its tests on it unchanged.
- The caller passes an absolute program path (viola resolves it itself: a given path as given, a bare name searched on `PATH`) and an explicit cwd.
- `HostTerminal` switches the host terminal to termios raw mode for the run and restores it on Drop.
- Keep the input writer until the child exits (the pump holds it for its life).
- OPEN — whether the real `claude` loses a key typed right after a resize · owner: the open residuals of origin `2026-11-04T23-11-43-wrap` (target `another-os`).
- `PtyError` is hand-written with fixed messages, the one ratified exception to the thiserror rule ([Error Handling]).
- The real-PTY test rig (`mod tests`): the child streams `<temp dir>/viola-pty-watch/<test>.<pid>.report` (`<pid>` the test process's id, so two test processes running the same test never share a report file; `start`, `size` from its watcher thread, `byte`, `restored`) and the test streams `<test>.<pid>.test.report` (`resize-returned`, `key-written`, `key-flushed`, `dsr-cpr {n}` — the drain's count of `ESC [ 6 n`); both are kept on a panic or kill, removed on a pass. Waits are keyed on the exact line asserted, never on a line index. Child modes ride `PTY_SEAM_TEST_MODE` (`run` · `hold` · `block` · `watch`), read only by the test child.

## Entry points for modification
- **Seam trait + portable-pty adapter:** `crates/viola-pty/src/`
- **Pump (`pump_with_paste`, `PasteHandle`):** `crates/viola-pty/src/pump.rs`
- **Host terminal (`HostTerminal`, `host_stdin`, `host_size`, `pty_backend`):** `crates/viola-pty/src/lib.rs`
- **Tests:** the crate's inline `mod tests` (the real-PTY rig) and the root `tests/tui_pty_seam.rs`, which spawns `viola-fake-agent` through a real openpty (no-EOF mode, resize)

## Testing this crate
- **Unit tests:** `cargo nextest run -p viola-pty`
- **Integration:** real openpty spawn of the fake agent; run in CI on `ubuntu-latest`
- **No-EOF:** the `--exit-no-eof` fake mode (`tests/tui_pty_seam.rs`): exit on the handle; the held output outlives the session leader on Linux only for a holder in its own process group, and that half is asserted on Linux
