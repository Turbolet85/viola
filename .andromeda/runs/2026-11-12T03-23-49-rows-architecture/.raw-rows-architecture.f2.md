@row_add n=1 row=decision/separate-lock-files area=established-decisions rec=1,2,3
name: Locks on separate .lock files
rule: State locks are std `File::lock` locks taken on separate `.lock` files, so no file is both appended to and exclusively locked.
why: A layout chosen while Windows, where append plus exclusive lock fails, was a target, and kept.
@row_add n=2 row=decision/tempfile-snapshot-writer area=established-decisions rec=4,5
name: tempfile as the snapshot writer
rule: Every snapshot and private file write goes through the shared helpers built on tempfile `persist` and `persist_noclobber`; no call site carries its own temp-plus-rename code, and a failed write leaves the target as it was.
why: atomic-write-file's BSD-3-Clause licence is outside the `deny.toml` allow list, and tempfile was already locked, MIT OR Apache-2.0.
@row_add n=3 row=decision/no-database-keys area=established-decisions rec=7
name: No database keys
rule: There are no database keys: instances are identified by `ViolaName` and endpoints by its short hash.
why: Identity is by instance, never by location (R5).

@row_add n=11 row=decision/hooks-fail-open area=established-decisions rec=14,15,16
name: Hooks fail open
rule: `viola hook` always exits 0, including on clap parse errors, channel failures and caught panics; a JSON body is a decision, no body no decision; exit 2 is never produced and `hook` never writes to stderr.
why: Exit 2 is a blocking error in Claude Code's contract, and a viola bug must never block the user's session.
except: The hidden `--capture` arm, called only by `viola verify`'s probes, reads no `VIOLA_*` and opens no channel, yet still always exits 0 with empty stderr.
