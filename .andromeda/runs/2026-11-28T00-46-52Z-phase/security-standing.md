# security · standing conventions

- S1 · every test runs under its own home, never the user's home or real Claude home · secret-management
  decision/live-rig-kept-stamp-owner-only · Live rig's kept stamp owner-only, seeded to its own home — The live rig keeps a stamp from a scratch home of its own owner-only and no-clobber, and seeds it only into another scratch home of its own; an arm it seeds refuses with no kept stamp before its ledger line, the one seeded before its scratch also before any scratch.
  decision/live-rig-mb-arm-keeps-no-output · Live rig's MB arm keeps only closed words of the client — The live rig's MB arm runs a print-mode claude -p as the MCP client of viola mcp over the fake agent, in its scratch home and private config, one tool allowed (wait), no key, no dialog; it reads the client's output in memory and keeps only two booleans, one number and one closed word. · why: The shape the operator ratified; a long call counts only with timed-out true beside call-error false, so a result with no is_error key cannot turn a cut call green. · except: The rig reads the credentials file once per start, and the prompt and the tool result go to the model provider; nothing reaches a fixture, stamp or log, or the real ~/.claude* or ~/.viola.
  decision/live-rig-wake-arm-reads-own-wheel-lines · Live rig's R3W arm reads only viola's own wheel lines — The live rig's R3W arm reads from the events log in its own scratch home only viola's own wheel lines and the prompt's origin word, and records the captured prompt's key names, never their values.
- S2 · test homes are kept out of git · bootstrap-phases
  decision/no-secrets-in-git · No secrets or local homes in git — .env files, local --home test directories and signing material are never committed to git.
  decision/test-homes-gitignored · Test homes kept out of git — Local --home test directories are git-ignored so recorded state never lands in git.
- S3 · every new fixture is recorded clean under the fixture hygiene rules and reviewed before commit · security-anti-patterns-never-do-these
  contract/fixture-refusal-codes/absolute-path · verify's unclean-fixture refusal codes · absolute-path — A closed check code of the fixture refusal, for a surviving home, drive-letter or user-folder path.
  contract/fixture-refusal-codes/email · verify's unclean-fixture refusal codes · email — A closed check code of the fixture refusal, for a surviving email-shaped token.
  contract/fixture-refusal-codes/home-path · verify's unclean-fixture refusal codes · home-path — A closed check code of the fixture refusal, for a surviving home path.
  contract/fixture-refusal-codes/username · verify's unclean-fixture refusal codes · username — A closed check code of the fixture refusal, for a surviving user word.
  decision/env-fixture-names-only · Recorded env fixture holds names only — The recorded env fixture holds only its version and the CLAUDE names the CLI adds to a hook, never a value; it passes the record scrub and the env-name check, an env name carrying the user word refusing the recording as username with nothing recorded, and the hygiene walk checks it as its own class. · guard: env_fixtures_pass_hygiene; record_refuses_an_env_name_carrying_the_user_word
  decision/fixture-hygiene · Recorded fixture hygiene — Recorded claude fixtures are never committed from sessions with real prompts, nor before being checked for home paths and usernames.
  decision/fixture-recording-scrubbed · Fixture recordings scrubbed — verify --record scrubs the home prefix and user word before any write and refuses the whole recording when a home, drive-letter or user-folder path, the user word or an email-shaped token survives, naming file and closed code, never content.
  decision/fixture-scrub-and-refusal · Recorded fixtures scrubbed or refused whole — Before any write, verify --record scrubs the home prefix to ~ and the user word to <user>, and refuses the whole recording with exit 1 and nothing written when a home, drive-letter or user-folder path, the user word or an email-shaped token survives.
  decision/fixtures-reviewed-before-commit · Fixtures reviewed before commit — Recorded fixture payloads are reviewed for home paths, usernames and tool input before committing.
  decision/mcp-fixtures-via-test-only-tap · MCP fixtures recorded through a test-only tap — MCP exchange fixtures are recorded by a test-only tap, started live by the standing rig under its private CLI config, that spawns viola mcp directly with no shell, caps each line, keeps its raw capture 0600 in a private directory never committed, and applies the same scrub and closed refusal codes. · guard: schemas/claude-mcp-fixture.v1.json
  decision/probe-prompts-synthetic · Probe prompts are synthetic — Probe prompts used to record committed fixtures must be synthetic; the composed uds address is the one non-literal part of the cross-session sender's prompt.
  decision/screen-fixture-signature-rows-only · Screen fixtures keep only signature rows — A screen fixture keeps only signature rows (a row holding a compiled footer or modal literal whole, a box rule row as its rule chars alone, a prompt row as the prompt char alone), the rest blanked; another box row, a kept row the scrub would rewrite or a username split across a row seam is refused. · except: On a failed recording verify, a hidden rig-only option writes one first-screen file of whole scrubbed rows per run short of the input box, kept local and git-ignored; an unclean set is refused whole.
  decision/viola-format-fixtures-hygiene · viola-format fixtures under the hygiene walk — Committed viola-format fixtures, the old state shapes and retired words, are held to the same fixture hygiene walk as recorded fixtures: no path, user or email. · guard: viola_format_fixtures_pass_hygiene
- S4 · every new third-party crate is pinned exactly and passes the dependency audit tools · dependency-security
- S5 · every new log line holds no secret, CLAUDE value or user content outside diagnostics · bootstrap-phases-derive-for-route-setup-project
  contract/mcp-stdin/parse-rejected · MCP stdin refusal log · parse-rejected — An over-long MCP stdin line is recorded as one parse-rejected line holding no byte of it.
  decision/agents-probe-log-content-free · Agents probe log holds no content — An agents-probe spawn pair is logged only under an open log and holds no row text, id, cwd or path.
  decision/agents-probe-log-redaction · Agents-probe logging redacted — Each agents-probe spawn pair is logged with no row text, id, cwd or path.
  decision/drift-reports-diagnostics-only · Drift reports only in diagnostics — Deserialisation drift reports are written only to the diagnostics directory. · why: drift reports can quote tool input
  decision/hyprland-reply-text-dropped · Hyprland reply text dropped at the parse — Hyprland reply types hold no text field: window titles, classes and every other reply string are dropped at the parse and reach no log line and no error. · guard: contract_hyprland_canary_reaches_no_line_and_no_error
  decision/transcript-path-redacted · Transcript path redacted — The Claude transcript path is a redacted value, carried only as the optional transcript param beside hook.event, and appears in no event data, events log, log line, span, reply or verify record. · guard: session_start_transcript_path_stays_out_of_data
