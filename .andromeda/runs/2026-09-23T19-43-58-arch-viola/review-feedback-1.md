# Review feedback 1 (overseer, founder-delegated)

Review, six items.
1. Tree: remove the prototype/ line. The prototype lives outside the repo in D:\dev\projects\additional\viola-lab and is reference only.
2. The Q9 gap: make the path binding real instead of only stating the v fallback. At start, viola run copies its own exe to <viola home>/bin/<CARGO_PKG_VERSION>-<short content hash>/viola(.exe) if that copy is absent, and writes that path into hooks.json and .mcp.json. The content hash matters: during development CARGO_PKG_VERSION stays 0.1.0 across rebuilds, so the version alone would collide. A rebuild then never changes what a running session calls. Keep v + sender as the second net for the optional user-level install. Drop the rename-aside note from Infrastructure, since the running wrapper no longer holds the installed path.
3. Values: all ten accepted as drafted (port 47319, exit codes, FNV-1a endpoint hash, 5 s heartbeat, edition 2024 / MSRV 1.89, ~/.viola layout, /health /ready /api/info + RFC 9457, hook.dialog / hook.event, last as a subcommand, publish = false).
4. Links are undefined: D5 asks the GUI to show which sessions are linked, and there is an unlink verb and /api/links, but nothing creates a link. Define it: a link driver -> driven is recorded when a send or answer is issued from inside a wrapped session (the caller's VIOLA_NAME) to another instance, and also by an explicit viola link <driver> <driven>. unlink removes it. Links are events in the log, and the snapshot is derived from them.
5. Delivery confirmation has a false-negative class, measured today: a built-in local command typed into the session fires no UserPromptSubmit (/remote-control did not), so the rule would report it not-delivered. /clear matters most, because drivers clear between pipeline skills. Add a ledger row "local commands": each known command gets its own post-condition (for /clear, a SessionStart with source clear and a new session_id; measure it in viola verify). An unknown local command reports detail unconfirmable, never not-delivered.
6. Ledger: add a fourth behaviour measured today. The CLI escapes tag-like text a user typed: a literal <\pasted_content in the text arrives as <\pasted_content. Delivery matching must normalise it.

## Orchestrator note on item 6
The feedback arrived through the CLI, which itself applied the escaping item 6 describes, so both sides of the example read `<\pasted_content`. Interpreted as: a literal `<pasted_content` typed by the user arrives in UserPromptSubmit as `<\pasted_content` (a backslash inserted after `<`). Delivery matching must normalise that escaping before comparing sent text with submitted text.
