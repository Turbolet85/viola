# Quiz I — Product Layer Results

## Core Fields
- Scale Intent: personal — with the founder's explicit amendment that D3 holds: v1 serves the founder on their own subscription (no accounts, no hosting, GUI on 127.0.0.1), but it is cross-platform from the first commit: Windows first, the macOS and Linux code paths built and CI-tested on all three OSes against the fake agent, and the on-disk state parsed defensively from day one. Public distribution (signed binaries, winget/Homebrew/Scoop, a marketplace entry) is a later version, not v1.
- Platform: Hybrid — one native CLI binary (subcommands run · send · wait · hook · mcp · ui) + a Claude Code plugin (hooks + stdio MCP server) that calls that binary + a minimal local web GUI served by the same binary
- Primary Language: Rust
- Target Users: just me for v1 — the founder's own overseer and builder pairs on Pulse, Conductor and viola itself. One boundary from D1 and R4 still binds: viola stays a general bridge, with nothing Andromeda-specific inside it. The Andromeda decision rights (brief Appendix A) belong to the driver's side, never to viola. Individual Claude Code subscribers are the audience of the later public version.
- Growth Model: Modular monolith — one binary with clear internal modules (pty · channel · hook · mcp · ui · state), features grow as subcommands and verbs, no daemon
- Development Style: agent-driven
- Core Functionality: A cross-platform, Windows-first bridge that lets one interactive Claude Code session drive another on the user's own subscription. It wraps the unmodified `claude` CLI in a pseudo-terminal, types at turn boundaries, answers dialogs through hooks, holds a one-driver wheel the human can take at any moment, and shows active and linked sessions in a minimal local GUI.

## Domain-specific Fields
- Viewer Surface and Reach: local web page on 127.0.0.1 only; a phone or remote view later, behind authentication
- Driven-Agent Coverage: Claude-first core with one concrete adapter module and no trait yet. The PTY, channel, wheel and state layers know nothing about any agent; their ndjson uses viola's own normalised events (turn-ended, prompt-submitted, question, permission, plan, session-end). Everything Claude-specific sits in one `agent::claude` module: hook JSON parsing, the dialog answer mapping (S3/S7/S8), stripping the parent's identity (R8), resolving the npm shim, and the CLI version gate. A trait is extracted only once a real second agent exists.
- GUI Control Scope in v1: view-only — GET routes plus an SSE event feed, no state-changing route; the server accepts only requests whose Host header is `127.0.0.1:<port>` or `localhost:<port>`. `ui` stays a pure reader of on-disk ndjson and `claude agents --json`. The wheel moves only when the human types (R2) or runs `viola pause|release|unlink` from the CLI. No token/CSRF until the page can change something. A brake (pause/unlink POSTs with Host+Origin checks and a per-launch token) is the natural v1.x step.
- Human Takeover Behavior (the Wheel): byte-source claim + atomic send window + after-the-fact confirmation, explicit release. `viola run` owns the real stdin, so it knows which bytes came from the human. Any human editing key since the last turn boundary moves the wheel to the human at once, and `send` is refused with `human-typing`; focus, mouse and resize sequences don't count. The bridge writes `ESC[200~…ESC[201~` + CR as one write; human bytes arriving during that write are held in the pump and passed on straight after. A `prompt-submitted` the bridge didn't send confirms and logs the take. The wheel comes back only through `viola release` from the CLI (not MCP). Amended with two facts MEASURED 2026-09-23 on CLI 2.1.280 (this session driven by the prototype): (a) harness-injected turns fire UserPromptSubmit — a subagent hand-back arrives as a prompt starting with `<agent-message from=` and a background-task notice as one starting with `<task-notification>`; the prototype took both for a human take and paused automation twice; the prompt-submitted classifier must file them as harness turns, never a human take. (b) CLI-native modal screens bypass every hook — after a Stop the CLI opened "Teach auto mode about your environment?", status still read idle, and the next paste+Enter answered that modal (picked Yes, opened /auto-mode-setup) instead of reaching the model; so a turn boundary per the hooks is not proof the input box is ready. At minimum, `send` must confirm delivery: no matching prompt-submitted within a short window means the send is reported as not delivered, never assumed.
- Budget Governor Behavior (v1): soft stop at the turn boundary. Automated `send` is refused with the typed reason `budget-paused`, through the same refusal path as `human-typing`, once a configurable threshold is crossed (for example five_hour ≥ 90% or seven_day ≥ 85%, set low because the per-model weekly window is hidden, claude-code#91920). Human keystrokes are never blocked; the turn already running finishes. The pause lifts when `resets_at` passes or on `viola release --budget` from the CLI. When figures are missing, viola uses the newest reading from any wrapped session and shows its age; with no reading at all it records `unknown` and does not block. The statusline (`rate_limits.five_hour` / `seven_day`, `used_percentage`, `resets_at`) is wrapped only for sessions started by `viola run`, through a per-session settings override (to be measured on 2.1.280), which then runs the user's own statusline command unchanged.
- CLI Version Compatibility Posture: per-behaviour capability ledger + degrade to transport-only on unverified builds, with `viola verify` as the re-stamp. `agent::claude` keeps a table of behaviour → CLI versions it was measured on: S3 AskUserQuestion via PreToolUse `updatedInput`; S7 ExitPlanMode approves only through PreToolUse; S7 revise via `deny` + `message`; S8 free text and `annotations`; the R8 `CLAUDE*` strip list; npm-shim → `claude.exe` resolution; statusline `rate_limits.*`; plus three behaviours the founder MEASURED 2026-09-23 on 2.1.280: harness-injected prompt prefixes (`<agent-message from=`, `<task-notification>`); the pasted-content wrapper (`<pasted_content id=…>`) the CLI puts around a long paste (981 bytes wrapped, 749 not); and CLI-native modals that no hook reports. On a version not in the table, viola still types, runs the wheel and emits events, but withholds hook dialog answers (the hook returns no decision, so the dialog renders for the human) and the driver gets an `unverified-cli` refusal. `viola verify` runs the live probe suite (Haiku, local only), stamps the version, and records the hook-payload fixtures the fake agent replays in CI; probes include post-condition checks (confirm, never assume).
- Cross-Platform Release Bar for v1: Windows live-supported; macOS and Linux code paths built and CI-tested on all three OSes against the fake agent (from the Scale Intent amendment)
