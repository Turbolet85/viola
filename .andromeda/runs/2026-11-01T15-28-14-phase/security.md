## Relevance
relevant — the plan names this route entry as the owner of its Unix IPC gaps (client euid, macOS cases, the socket-directory code) and the board's home-check inconsistency.

## Constraints
- The per-user socket directory must pass the owner, mode and not-a-symlink check before a wrapper binds and again before any client connects, with the per-surface outcome the row sets for `run`, CLI/MCP clients and `hook`; whether the code already makes this check is research's question (per security-plan §Authentication & Authorization, IPC access control (Unix)).
- A failure at `bind_endpoint`'s `create_private_dir` must become a refusal with a closed code instead of an anyhow error at the catch site; whether a directory the check refuses and a directory that cannot be created read as one code or two is P4's (per security-plan §Authentication & Authorization, IPC access control (Unix), the failure at bind).
- The server must check the peer's euid on every accept, on both the sync and the Tokio server, and drop a mismatch before reading a frame; whether either server already does so is research's question (per security-plan §Authentication & Authorization, IPC server-side peer check (Unix)).
- Every Unix client must check the connected peer's euid before the first frame of any method, `hook.event` notifications included, after the instance's strict-modes check and its one snapshot read, with no frame on a mismatch or an unmakeable check; the euid check is never skipped, macOS included (per security-plan §Authentication & Authorization, IPC client-side server verification; per security-plan §Security Anti-Patterns › Authentication).
- macOS keeps its recorded gap: its verification is euid plus the verified 0700 directory, with no pid or start-time comparison and no substitute for one; its verdict stays a named carve-out that no test reads as a comparison (per security-plan §Authentication & Authorization, IPC client-side server verification, the verdict and the macOS cases).
- `viola list`'s home check must become one rule across a board with and without instances; the plan's read rule names the home, and a refusal keeps the whole-board shape, no log, no line and the mode as found. Whether `mcp`'s start and `plugin install`, which the plan also records on `check_path` for the home, share the inconsistency is research's question (per security-plan §Authentication & Authorization, `~/.viola/` access control).
- Each new refusal must carry only closed code words, with no absolute path, pid, start time, endpoint or anyhow chain on any surface. Exit 21's `detail` is a closed set of five causes, so a new cause word amends that set and its two client writers, and the euid mismatch's word (`server-verify-failed` or its own) is P3's read and P4's call; the plan records `server-verify-failed` as off macOS, which a macOS euid mismatch would change (per security-plan §Error Handling, External responses and exit 21's causes).

## Patterns to follow
- The one client order, strict-modes check, one snapshot read, liveness pre-check, server check, frame: the euid check joins the server check at the clients' shared seams, never a parallel path; research confirms those seams at HEAD (per security-plan §Authentication & Authorization, IPC client-side server verification).
- Only a matching verdict lets a frame be written, and the closed verdict type with its no-peer-pid constant is where the macOS carve-out stands by name (per security-plan §Authentication & Authorization, the verdict and the observed server pid).
- A refused check runs before anything under the home is created, narrowed or opened, leaving the mode as found and no trace (per security-plan §Authentication & Authorization, `~/.viola/` access control); the socket directory's "never narrowed in place" follows the same order (per security-plan §Security Anti-Patterns › Universal, the check never after what narrows it).
- A new refusal lands in the plan's catalogue: a row of `tests/cross_exit_causes.rs` under its code-word and distinct-hint checks, and a named writer and witness in `tests/contract_error_bodies.rs` (per security-plan §Error Handling, the cause table and the error-body enumeration).

## Anti-patterns to avoid
- No socket directly at a shared temp root, no reliance on the socket's 0600 as the only control, no `ListenerOptionsExt::mode`, no abstract namespace (per security-plan §Security Anti-Patterns › Authentication); no `try_overwrite`, which bears on the leftover-socket takeover, and whether that takeover stays safe beside the new checks is research's question (per security-plan §Security Anti-Patterns › Code Patterns).
- No `config.json`, `VIOLA_*` variable or flag may switch off the socket-directory check or the peer verification, and a new test seam, such as one faking a foreign euid, needs its own Decisions Log entry (per security-plan §Security Anti-Patterns › Universal).
- A refusal of this chunk never blocks the human and never gives `hook` stderr or a non-zero exit (per security-plan §Security Anti-Patterns › Logging; per security-plan §Security Anti-Patterns › Universal).

## Acceptance criteria contributions

- A foreign-euid peer: the server drops it before reading a frame, and a client facing a foreign-euid server writes no frame, on Linux and macOS, with a control showing a same-euid peer served (per security-plan §Authentication & Authorization, IPC server-side peer check (Unix) and IPC client-side server verification).
- A 0750 home reads the same `viola list` verdict with no instance and with one, and a refusal opens no log, writes no line and leaves the mode as found (per security-plan §Authentication & Authorization, `~/.viola/` access control).
- Every refusal this chunk adds has a closed code word and a distinct hint in `tests/cross_exit_causes.rs`, a named writer in `tests/contract_error_bodies.rs`, and no absolute path, pid, euid or endpoint on stdout, stderr or an MCP result (per security-plan §Error Handling, the cause table and the error-body enumeration).
