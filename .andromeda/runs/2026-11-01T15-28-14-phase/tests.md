## Constraints
- Test tier `Comprehensive (2)` sets the breadth; a peer of another euid cannot be driven on hosted runners, so test-plan requires the cross-user rejection asserted at the peer-credential decision with injected `(peer_euid, own_euid)`, and the same-user behaviour over a real endpoint; whether that decision already covers the client side is research's question (per test-plan §1 Test Scope Summary, Entity `viola-channel` and Untestable zones; §4 viola-channel).
- The Unix socket directory refusal requires, with a test-owned `XDG_RUNTIME_DIR`, `viola/` pre-created as a symlink to another 0700 dir and as a 0755 dir: `viola run` exit 1, a CLI client verb against an existing instance exit 21, `viola hook <event>` exit 0 with no body and no frame; the foreign-owner case runs at unit level through an injected `lstat` result. This also answers the scope's inferred "which exit" from the plan's side; whether the code does so is research's question (per test-plan §6 Security control negatives, Unix socket directory refusal).
- Each cause in `tests/cross_exit_causes.rs` requires the exit code, the `--json` document, a last `hint:` line naming that cause, and its `process-exit` line, in both modes where a mode exists; a shared hint fails the table and no driver-facing hint contains `release`. test-plan records exit 21's `detail` as a closed set of five and the socket-directory refusal as having no code; whether a new word or an existing one carries it is research's and P4's question (per test-plan §6 Exit-cause matrix; §6 Security control negatives).
- macOS requires the client euid check and a `#[cfg(target_os = "macos")]` case loosening the verified per-user socket dir to 0755 with exit 21, both recorded as owed to this entry; a same-user impostor inside a valid 0700 dir on macOS is an accepted limitation and is not asserted as a refusal, and the pid/start-time negatives stay `#[cfg(not(target_os = "macos"))]` (per test-plan §6 Exit-cause matrix; §5 Cross-module patterns, Wrapper channel; §6 Security control negatives, Server identity).
- A home, instance directory or `diagnostics/` another user may read must be refused (Unix: a group or other bit), which is the mandate the board's one home rule answers to; test-plan pins `viola list`'s whole-board refusal as exit 21 opening no log. Whether `board::scan` holds that with no instance present is research's question (per test-plan §1 Coverage triggers, security-vector-coverage (filesystem); §6 Security control negatives).
- Each new refusal must read on every surface: for each cause of exit 21 the MCP `isError` body equals the CLI `--json` document less `v`, and the hook stays exit 0 with empty streams and no body, including its fail-open rows on Linux and Windows (per test-plan §6 Cross-surface parity; §6 Security sweep; §5 Cross-module patterns, Hooks).
- Commands the implementation must pass: `scripts/agent-run.sh run --unit`, `run --integration`, `run --e2e`, then `run --coverage` with `gate --require coverage,doctest`. `cross_` binaries sit in the E2E layer (`run --e2e --filter 'binary(cross_exit_causes)'`), `security_negatives_*` in the integration layer. Mutation is no chunk gate, and §10 holds no `Gate: chunk set` record (per test-plan §3 `run`; §3 `pre-push`; §9 Pipeline structure; §10 Mutation gate).

## Patterns to follow
- A negative beside its control in `security_negatives_*.rs`: the server-identity case asserts no frame, no line and no pid or path in output, with a control that reaches the recorded wrapper (per test-plan §6 Security control negatives, Server identity).
- Pure decision functions fed injected values, no clock and no second account: the peer-credential decision, `unix_read_verdict(mode, uid, euid)` and its write-rule pair (per test-plan §4 viola-channel; §4 viola-state).
- Real tempfile home and real endpoint; socket dir 0700 and file 0600 read back with metadata; a squatter created first through the server API; umask-independent modes started under `umask 000` (per test-plan §5 Boundary types covered, Module ↔ IPC; §6 Security control negatives, Umask-independent modes).
- A home made before viola runs goes through `viola_state::fs::create_private_dir`; env set per child with `Command::env`; root suites share `tests/support/` and the `home → fake_agent_path → stamped_home → booted_wrapper` chain (per test-plan §7 Seed strategies; §7 Test data lifecycle; §3 `run`).
- Two endpoint waits, by path: the stop path waits on `wait_endpoint_gone`, the kill path on `holder_gone`, a connect probe, because a killed wrapper's socket file stays; P3 re-derives this at HEAD (per test-plan §3 `run`).

## Anti-patterns to avoid
- NEVER treat a Linux-only local run as proof for macOS: OS-branch code is verified only on its own runner, and macOS is CI-only (per test-plan §11 Test Strategy; §1 Untestable zones).
- NEVER use interprocess `try_overwrite` or reuse an endpoint name across tests, `std::env::set_var`, or `.env_clear()` without re-adding `LLVM_PROFILE_FILE` (per test-plan §11 Integration).
- NEVER synchronise with `sleep(N)`, and never hand-write `snapshot.json` outside the server-identity impostors' named exception (per test-plan §11 E2E; §11 Test Data; §7 Seed strategies).
