## Relevance
partial — tier Standard (1), no WCAG conformance claim (per a11y-plan §1 A11y Scope Summary); the chunk adds no surface, but its new refusals are CLI output under the output-discipline rules and its wrapper-side check runs beside the `viola run` TUI boundary.

## Constraints
- a11y-plan §8 Error recovery requires each new human-mode refusal (a refused socket directory at a wrapper's start and at a client's connect, a peer euid mismatch on either side) to be a printed word, plain detail and a final `hint:` on stderr with a typed exit code; the form differs by path (the frame verbs' `unable  <reason>  <detail>`, `viola revive`'s exit-1 `unable: <text>`, `run`'s fixed home-state or instance-state pair). Which exit and form each new refusal takes is research's question, the scope naming both exit 21 and a `run` refusal.
- a11y-plan §8 Error recovery requires one `--json` document per refusal, on stdout with stderr empty, no hint and no ESC; exit 21's `detail` is a closed word list. Whether the new causes reuse a listed word or extend the list is research's and P4's question, and any new word extends the closed list on purpose.
- a11y-plan §8 Error recovery reads a fault as no refusal (`error: internal error`, no hint). The scope measures the socket directory's failure as an anyhow error at the catch site today, so that refusal has to leave the fault form; whether any leg still lands there at HEAD is research's question.
- a11y-plan §8 Error recovery requires a home-level refusal to take the fixed home-state pair and an instance-level one the instance-state pair. The board's one home rule has to land on the right pair for a 0750 home with and without an instance; what `viola list` prints today in each case is research's question.
- a11y-plan §8 Plain language requires every kebab-case code to sit beside the plain word `unable`, and every fixed CLI string to be pinned by trycmd or literal, so a new or changed hint fails CI until its pin is updated on purpose.
- a11y-plan §11 Keyboard forbids blocking, refusing or delaying a human keystroke in `viola run` or a passed `viola revive`, and a11y-plan §1 A11y Scope Summary (surface tui) requires zero viola bytes on the terminal there, diagnostics going to `diagnostics/`. The wrapper's euid refusal of a connecting client happens while the child holds the terminal, so it has to reach neither the outer terminal nor the keystroke path.
- a11y-plan §8 Error recovery (Verification, cli, macOS) records that the server-verify refusal cannot occur on macOS, its cases compile out there, and its macOS witness is owed to this entry; the chunk has to discharge or explicitly re-place that debt.

## Patterns to follow
- A row per cause in the exit-cause table, `tests/cross_exit_causes.rs`, checking exit, document and hint in human and `--json` modes (per a11y-plan §8 Error recovery, Verification, the exit-cause table). Causes held outside it are named in the comment at its top.
- The both-modes negative with its control: `tests/security_negatives_server_identity.rs` reads the hint as the last stderr line, no ESC byte, stdout empty, the exact `--json` document with stderr empty, and no output holding the recorded pid, the home's path or the endpoint (per a11y-plan §8 Error recovery, Verification, cli).
- The refusal that leaves the widening as found: `frame_verb_refuses_a_widened_instance_before_any_log` in `tests/security_negatives_strict_modes.rs` reads no line added, no frame sent and the mode unchanged, the shape for a directory refused and never narrowed in place (per a11y-plan §8 Error recovery, Verification, strict-modes refusals). Whether the named cases stand at HEAD is research's question.
- A hint literal in `src/human/hints.rs` pinned by a unit and by the exit-cause table, as `send_hint_is_the_design_string` does for `unwrapped-name` and `endpoint-lost` (per a11y-plan §8 Plain language, Verification).

## Anti-patterns to avoid
- Never let a kebab-case code stand without `unable`, show a stack trace as the only error text, or print a human-mode refusal other than `unknown` without a closing `hint:` (per a11y-plan §11 Cognitive); `unable` is never coloured and carries no SGR under non-TTY, `NO_COLOR`, `TERM=dumb` or `--json` (per a11y-plan §11 Visual).
- Never add a `suite` value or a separate a11y driver: new cases are ordinary nextest cases in the existing suites (per a11y-plan §11 CI).
- Never claim WCAG conformance from these assert_cmd, trycmd or portable-pty results; they are output-discipline stand-ins (per a11y-plan §11 Strategy).

## Contract bindings
- a11y ↔ tests: new cases surface only as nextest failures in `suites[].failures[]` of the harness `run` JSON, under `gate --require coverage,doctest` on each leg; `cfg(unix)` cases read on ubuntu-latest and macos-latest only (per a11y-plan §3 CI integration, a11y-plan §3 Structured violation JSON schema).
- a11y ↔ tests census: each new error body needs a writer and a witness in `tests/contract_error_bodies.rs`, and its `--json` failure documents stay clean under `tests/support/events.rs`'s classes, `absolute-path` among them (per a11y-plan §8 Error recovery, Verification, the census of error writers and the body check). Whether a human hint may name the socket directory's path is for P3 to read beside those checks.
- a11y ↔ design-system: the refusal copy and form bind to design-system cli pattern 2 and §Surface: cli (per a11y-plan §8 Error recovery, a11y-plan §8 Plain language).
- a11y ↔ security: the strict-modes and peer euid refusals stay refusals of automation, never of the human's keys (per a11y-plan §1 A11y Scope Summary, Critical path 4's security source).

## Acceptance criteria contributions
- (a11y) For each new refusal, a row of `tests/cross_exit_causes.rs` reads the literal exit, the `hint:` as the last stderr line, no ESC byte and stdout empty in human mode, and under `--json` one exact document with stderr empty and no hint (per a11y-plan §8 Error recovery).
- (a11y) Each new code has its own hint, pinned by literal: `no_two_codes_share_a_hint` and `no_hint_names_release` stay green with the new hints in their set (per a11y-plan §8 Error recovery, Verification, one hint per code).
- (a11y) A wrapper-side refusal of a connecting client leaves the outer-PTY stream free of `unable`, `hint:` and the refusal's code, and a human key written after it still reaches the child; whether a real euid mismatch can be driven on the CI runners is research's question (per a11y-plan §3 Keyboard test harness).
- (a11y) A case running on macos-latest stands as the owed macOS witness, reading the recorded gap as a named carve-out and never as a comparison (per a11y-plan §8 Error recovery, Verification, cli, macOS).
