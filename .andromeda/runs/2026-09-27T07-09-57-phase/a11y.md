## Relevance
Partial. The wrapper IPC channel itself is listed as not-assertable, with no UI surface (per a11y-plan §1 → "Not-assertable (no UI surface)", plugin/IPC entity, and §4 "Per-surface a11y testing tool reach"). The chunk still changes `viola run`, which is the tui boundary-only surface: it adds endpoint bind, serve threads and the start-order loser exit. So the tui boundary clauses and the CLI refusal-output discipline apply.

## Constraints
- The `viola run` terminal must carry no viola-originated bytes. Channel bind, accept, serve, frame refusal, newer-peer refusal, `ChannelError` and the new spans must all go to `diagnostics/`, never to the outer PTY stream. On every leg that means none of viola's own literals. On Linux and macOS it also means no SGR or cursor control the child did not emit (per a11y-plan §1 tui surface Notes, §3 Keyboard test harness → Tooling, as amended 2026-09-25).
- Human keystrokes must never be blocked, refused or delayed past the current atomic paste. The channel's std-thread server (accept loop, `read_line` bounded by `MAX_FRAME`, dispatch) must not sit on the human input path or starve it. Focus, mouse and resize sequences must not count as editing (per a11y-plan §1 tui boundary clauses; §11 Keyboard).
- If the start-order loser (the exit 1 when the exclusive bind loses or a squatted name blocks startup) prints anything to the user, it is a human-mode CLI refusal. §8 requires `unable  <reason>  <detail>` on stderr, `hint:` as the last stderr line and a typed exit code. The only exception is `unknown` (exit 14), which prints no hint. Faults (`error: wrapper fault`, `error: internal error`) are not refusals and carry no hint. `--json` output is one document with no hint (per a11y-plan §8 Error recovery). The scope says "exit 1", while §8 names the typed codes `10`–`14`, `20`, `21`. Research needs to check whether the start-order refusal already has a pinned message and code, and which code it uses.
- No SGR under non-TTY, `NO_COLOR`, `TERM=dumb`, `--json` or `viola run`. `unable` is never coloured (per a11y-plan §11 Visual; §1 cli surface Notes).
- A fixed-`Display` `ChannelError`, or any text that reaches a user, must not show a stack trace, Problem URN or bare status number as the only error text. Kebab-case reason codes always sit beside the word `unable` (per a11y-plan §8 Plain language; §11 Cognitive).
- Make no WCAG conformance claim for the channel, `viola run` or CLI output. Any assert_cmd, trycmd or portable-pty checks added here are output-discipline stand-ins only (per a11y-plan §11 Strategy; §4 per-surface reach table).

## Patterns to follow
- Tui boundary checks are portable-pty outer-PTY nextest cases, one per boundary clause, on all three OS legs. They use `viola-fake-agent` as the child and never inspect `claude` content (per a11y-plan §4 P4 tui bullet; §3 Keyboard test harness → Tooling). If this chunk changes what `viola run` emits or does during start and exit, those cases are where a regression would show.
- Pin CLI refusal text with trycmd (`unable <reason> <detail>` + final `hint:`). Check typed exit codes with assert_cmd on all three OS legs (per a11y-plan §8 Error recovery → Verification).
- CLI output-discipline tests report under `nextest-integration` / `nextest-e2e` locally and inside the per-OS `coverage` suite in CI, gated by `gate --require coverage,doctest`. There are no a11y rows and no new suite value (per a11y-plan §9 Unit / integration row; §10 Standard+ invariants, as amended 2026-09-24-quality-gates).

## Anti-patterns to avoid
- NEVER block, refuse or delay a human keystroke in `viola run` past the current atomic paste (per a11y-plan §11 Keyboard).
- NEVER parse the rendered `claude` TUI screen for content, or use screenshots as evidence. This covers any end-to-end channel witness test (per a11y-plan §11 Universal, R7).
- NEVER write a literal `null` for `corr` / `instance`, and never rename an obs binding field (per a11y-plan §11 Universal).

## Contract bindings
- **a11y §3 Structured violation JSON schema ↔ obs `diag-line.v1.json`.** a11y inherits the obs field names, including `corr` (= the JSON-RPC request `id` for `channel-request` / `channel-response`) and the rule that an absent key means null. The chunk's CARRY 2 makes `corr` required for corr-bearing events. That is compatible only if a11y rows stay harness-only (`event:"a11y-violation"`, validated by the tests-owned `e2e-web/schemas/a11y-row.v1.json`, never in the product enum). The change to `diag-line.v1.json` must not add an a11y value or touch `a11y-row.v1.json` (per a11y-plan §3 Structured violation JSON schema; §12 Resolved questions, as amended 2026-09-24-diagnostics-plane).
- **a11y tui boundary ↔ tests E2E driver (portable-pty outer PTY).** The zero-viola-bytes and unblocked-keystroke cases are shared with the tests harness (per a11y-plan §3 Keyboard test harness → Tooling).

## Acceptance criteria contributions
- (a11y) With the channel endpoint bound and served, the tui zero-viola-bytes check stays green on all three legs: across start, a channel round-trip and exit, the outer-PTY stream has none of viola's literals (including channel or refusal text). It is byte-identical to an unwrapped fake-agent run on Linux and macOS (per a11y-plan §3 Keyboard test harness → Tooling; §4 P4).
- (a11y) The unblocked-keystroke check stays green: human keystrokes are delivered unblocked while the channel serves frames, including a frame near `MAX_FRAME` (per a11y-plan §1 tui boundary clauses; §4 P4).
- (a11y) If the start-order loser prints a human-mode refusal, it has no SGR, has the `unable <reason> <detail>` layout with a final `hint:` line (unless it is `unknown` or a fault), and exits with a typed code. It is pinned by trycmd / assert_cmd on all three legs (per a11y-plan §8 Error recovery; §11 Visual).

## Relevant amendment history
- **2026-09-25-pty-wrapper-on-windows (§3 Keyboard test harness → Tooling; §6 State color tokens → CLI equivalent).** On Windows the zero-viola-bytes oracle means viola's own literals are absent; the byte-for-byte comparison applies only on Linux and macOS. The reason is that ConPTY emits its own `ESC[?9001h ESC[?1004h ESC[?25l ESC[2J ESC[m ESC[H`, an OSC 0 title and `ESC[?25h` on every spawn, and re-renders nested output. This applies directly to whatever the channel-bearing `viola run` emits. The "ConPTY swallows focus reports" claim was not amended and stays a HYPOTHESIS.
- **2026-09-24-diagnostics-plane (§12 Resolved questions).** `a11y-violation` is not a product `event` value. It is a harness-only row validated by `e2e-web/schemas/a11y-row.v1.json`, and the 19-value `diag-line.v1.json` enum carries no a11y value. This matters because this chunk edits `diag-line.v1.json` (`corr` required).
- **2026-09-24-quality-gates (§1 / §9 / §10).** CLI output-discipline tests report under the CI `coverage` suite. That is where any new trycmd / assert_cmd refusal checks from this chunk will land.
