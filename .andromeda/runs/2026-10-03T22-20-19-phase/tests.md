# tests extract

## Relevance
relevant — the chunk is test-strength and test-harness work: mutation scoring, the `run --mutants` arm, the harness `pre-push` gate and the in-repo TUI set (tier Comprehensive, per test-plan §1 Test tier; the mutation trigger is the founder's Direction 1, per §1 Trigger type "mutation testing").

## Constraints
- The mutation verdict is counts-only: `outcomes.json` must show `missed == 0`, `timeout == 0` and `unviable <= caught` (`unviable-exceeds-caught` otherwise). Exit codes 1/4/5/6/70 are `mutants-exit-<code>` reds whose zero counts never read as a pass. This applies to the viola-e2e unit score (M3) and to the 12 cfg(unix) mutants alike (per test-plan §10 Mutation gate; §3 `run` step 4 Verdict; §11 Quality "NEVER trust the cargo-mutants exit code alone").
- Test scope stays cargo-mutants' default (no `--test-workspace`). Each mutant must be killed by the tests of the package that owns the mutated file. For M3, viola-e2e harness mutants must be killed by viola-e2e's own tests; root-bin mutants (`src/panic_frames.rs`, `src/cmd/run.rs`) by root-package tests; viola-pty and viola-channel mutants by those crates' tests (per §3 `run` step 4 Test scope; §11 Test Strategy layer rule). The viola-e2e no-op `fake-agent` feature exists because cargo-mutants passes `--features fake-agent` to package-scoped runs, and §3 `run` step 4 Test scope says a missing feature surfaces as exit 4. Whether a viola-e2e-scoped run keeps it working is research's question.
- The §3 `run` step 4 Command requires the root-only prebuild (`cargo build --package viola --features fake-agent`) and `--copy-target=true`, both under `MUTANTS_TARGET` (`target/mutants`), so each copied tree carries the root bins. It also requires `--build-timeout-multiplier=5`, `AGENT_RUN_KEEP_HOMES=0` / `AGENT_RUN_KEEP_FAILED=0`, and live stdout. Off Windows there is no `HOST_SCRATCH`: the inherited temp dir is used and `mutants.out/` goes at the repository root (per §3 `run` step 4 Command; §2 Agent-runnable invariants). The plan already records a measured cost of 2.9 GB of `target/` per copy on the former dev host (§3 `run` step 4 Command), and the scope requires re-measuring it on this host first. Whether the 32-of-246 baseline failure reproduces on Linux, and whether the current prebuild reaches viola-e2e-only runs, are research's questions.
- Diff classification reads `diff --git a/… b/…` headers (per §3 `run` step 4 Classification). The plan's contract assumes the default `a/`/`b/` prefixes. C3's `--src-prefix=a/ --dst-prefix=b/` pin is what makes that contract hold against a host `diff.mnemonicprefix=true` (`i/`/`w/`). Whether every header-parsing harness `git diff`/`git log -p` caller already pins its prefixes is research's question.
- `pre-push` as the plan specifies it is Windows-host-only. Its `host` stage exits 2 `pre-push-windows-only` off Windows; the plan routes the Linux leg through WSL `Ubuntu` under `env -i HOME=… PATH=<constants>` and ends with `vm-release` and `windows-tests` (per §3 `pre-push`). On the Linux host, that contract refuses outright. The re-shape must keep `env -i` HOME+PATH with every PATH component a constant and no host value; any wider PATH is the founder's live call. The `tools` stage pins come from `rust-toolchain.toml`, the §9 `test`-job `tool:` line and ci.yml's `NODE_PIN_VERSION`, and it keeps the cargo-mutants pin because `run --coverage` runs the real-cargo-mutants harness tests. No stage runs mutation (per §3 `pre-push` Stages; §9 Mutation row).
- Closed enums: the `pre-push` `stage` / `reason` / `detail` values and the `run` `reason` values are closed, and a new value needs a Decisions Log entry (per §3 Closed enums). Retiring `vm-release` / `windows-tests` / `pre-push-windows-only` or adding a native-stage value is an enum change. It reconciles at wrap with the spec bodies (scope item 4) but must be recorded, never silently invented.
- OS-branch code is verified only on its own runner. The Linux host's TUI run proves openpty cases only, and the ConPTY cases and the `cfg(all(windows, not(x86_64)))` 13th mutant cannot be witnessed on this host (per §11 Test Strategy "NEVER treat a Linux-only local run as proof for Windows or macOS"; §10 Stack adjustments, per-OS cfg compilation). Root TUI integration binaries carry the `tui_` prefix (per §2, binary prefix rule).
- No skip as a parking place: a survivor or a host-red test is fixed or disposed with its argument, never `#[ignore]`d. The macOS compile-out of the two real-cargo-mutants harness tests is `#[cfg(not(target_os = "macos"))]`, the documented precedent; there is no `#[ignore]` and `retries = 0` stays (per §10 Zero-flakiness budget; §10 Mutation gate, last sentences).

## Patterns to follow
- Harness self-tests use stand-in seams: the `Runner` / `run_with` runner seam (per §3 `run` step 3 and `--local-live`) lets harness tests avoid real external tools where the behaviour under test is the harness's own parsing. The two real-cargo-mutants harness tests (`run_mutants_passes_when_the_change_is_tested`, `run_mutants_reports_survivors_of_an_untested_change`) are the precedent for an end-to-end cargo-mutants self-test (per §10 Mutation gate).
- Nested cargo in harness self-tests runs through `test_support::uninstrumented`, which removes cargo-llvm-cov's four env names so a throwaway crate writes no profile into the outer coverage run (per §10 Stack adjustments). It applies to any new viola-e2e seam that builds what it spawns.
- rstest `#[case]` tables for matrices (per §2 Unit row). This fits the C3 prefix cases (default `a/`/`b/`, `mnemonicprefix` `i/`/`w/`, `noprefix`) and per-mutant kill tests.
- Per-child environment through `Command::env`, never process-global (per §11 Integration). This is the shape for C3's "git config held hostile" test, for example a per-child `GIT_CONFIG_GLOBAL` / `-c diff.mnemonicprefix=true` on the test's git calls.
- Every harness command prints one JSON document plus a typed exit, with codes, counts and repo-relative names only, never a clone or home path (per §3 `pre-push` output; §11 Universal "NEVER let a harness command print a human-only message"). This applies to the re-shaped `pre-push` document.

## Anti-patterns to avoid
- NEVER widen the coverage `--ignore-filename-regex` / `COVERAGE_IGNORE` (which excludes `crates[/\\]viola-e2e`) or lower a §10 floor to absorb the new viola-e2e or cfg(unix) tests (per §11 CI; §11 Quality).
- NEVER use `std::env::set_var` (edition 2024 `unsafe`, races) to make the git config hostile, and never `.env_clear()` without re-adding `LLVM_PROFILE_FILE` (per §11 Integration). The native `env -i` pre-push stage is outside nextest, but any harness test of it obeys this.
- NEVER add a retry or `#[ignore]` to green the 13 host-red `run --mutants` unit tests or a flaky boundary case. A red stays open until its cause is known (per §10 Zero-flakiness budget; §11 Quality).

## Contract bindings
- tests ↔ security: the `pre-push` `env -i` HOME+PATH boundary (§3 `pre-push`) is the same boundary as security-plan §Dependencies and CI (the WSL2 `pre-push` distro, the `wsl-provision.sh --install-deps` root-install rule, `wsl-exec.sh` operator-only). Retiring or keeping the WSL tooling decides the CARRY 4 root-install rule on both sides, and PATH widening is a founder call on both.
- tests ↔ CI (§9): the `pre-push` `tools` pins are read from ci.yml's `test`-job `tool:` line and `NODE_PIN_VERSION` (§3 `pre-push`). No CI job runs or gates `mutants` (§9 Mutation row; §3 `gate`). The ConPTY TUI cases stay witnessed by the `windows-2025` runner.
- tests ↔ obs: `secret-scan` excludes exactly `target/agent-run/chunk.diff` (§3 `secret-scan`), and `run --mutants` keeps no test home (`AGENT_RUN_KEEP_HOMES=0`, §3 `run` step 4). This is unchanged by the chunk but binds any new mutation output path.
- tests ↔ code-audit: the M1-form disposition of survivors and the not-measurable record of the 13th mutant feed the epoch-boundary audit that §10 Mutation gate names as the mutation verdict's owner.

## Acceptance criteria contributions
- C3: a harness unit test runs `diff_paths` / the classification over a `git diff` produced under a per-child hostile config (`diff.mnemonicprefix=true`, via `Command::env`, never `set_var`) and classifies the `.rs` paths correctly. The `run --mutants` unit tests then read 38 passed / 0 failed on the host with the user's own git config in place (per §3 `run` step 4 Classification; §11 Integration).
- M3: a viola-e2e mutation run passes its baseline (no `mutants-exit-4`), and its own `outcomes.json` shows `missed == 0 && timeout == 0 && unviable <= caught`, judged by counts and not by exit code. Every survivor is either killed by a new or strengthened viola-e2e test or recorded equivalent with its argument (per §10 Mutation gate; §3 `run` step 4 Verdict / Test scope; §11 Quality).
- cfg(unix): the 12 mutants are listed by `cargo mutants --list` on the host and scored in-repo with the same verdict rule, with `mutants.out/` at the repository root off Windows. The 13th (`sideload_outcome`, `cfg(all(windows, not(target_arch = "x86_64")))`) is recorded not measurable with its reason, never counted as caught (per §3 `run` step 4 Command; §10 Mutation gate; §11 Test Strategy, Linux-only-run rule).
- Gates: the re-shaped `pre-push` runs on the Linux host, refuses no stage for being off Windows, carries only `env -i` HOME+PATH with constant components, and ends green on `run --coverage` → `run --browser` → `gate --require coverage,doctest,playwright` with one JSON document and a typed exit. `cargo nextest run -p viola-e2e` (and the in-repo `tui_` set) passes with `retries = 0` (per §3 `pre-push`; §3 `gate`; §10 Zero-flakiness budget).
