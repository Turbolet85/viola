## Relevant amendment history
- **2026-09-28-mutation-testing-to-the-epoch-boundary** — §10 now says the CLI output-discipline invariants P4 and P6, where they live in crate tests, are covered by the epoch-boundary mutation audit (`run --mutants`, test-plan §10). It previously said "under the tests' mutation gate", and the change followed the founder's 2026-09-28 ruling that removed the per-chunk and CI mutation gates. This is the binding that makes items 1–2 a11y-relevant. Any surviving viola-e2e or cfg(unix) mutant (viola-pty `HostTerminal::enter` ×4 and `host_size` in particular) that sits under a P4/P6 assertion must be killed or recorded as equivalent at this boundary tier. No other mutation gate exists to catch it later.
- **2026-09-25-pty-wrapper-on-windows** — §3 Keyboard test harness → Tooling and §6 CLI equivalent split the zero-viola-bytes oracle. Byte-for-byte against an unwrapped run ("no SGR or cursor control the child did not emit") holds on Linux/macOS only. Windows ConPTY injects its own sequences, so the windows-2025 check is viola's literals absent. For item 3 this means the Linux-host TUI boundary set must use the byte-for-byte unwrapped comparison for clause (1), not literal absence. The amendment also left "ConPTY swallows focus reports" as a labelled HYPOTHESIS, not plan fact. That bears on clause (3) (focus/mouse/resize) and on how the host-vs-CI witness split is recorded.
- **2026-09-29-sideloaded-conpty** — §3 Tooling and §6 now name both ConPTY hosts. The inbox preamble and the sideloaded `OpenConsole.exe` bytes (`ESC[1t ESC[c ESC[?1004h ESC[?9001h` at spawn, `ESC[?1004l ESC[?9001l` at exit) are recorded, and the DA1 query is answered by the terminal or piped driver, never by viola. The literal-absence check runs on both backends: the default on the sideload, and `conpty_sideload`'s tampered case on the inbox fallback. These ConPTY variants are the cases item 3 leaves witnessed on `windows-2025` only. A Linux-host 5/0 (openpty) must not be credited for either backend.
- **2026-09-27-browser-verdict-reachability** — §3, §9, §11 and §12 (D-A11Y-12) changed together:
  - `run --browser` runs the locked Playwright CLI (`node node_modules/@playwright/test/cli.js test` after `npm ci`) on all three CI legs.
  - The a11y verdict is judged on the ubuntu leg only.
  - `browser-missing` covers a failed `npm ci` as well as a missing Chromium.
  - The test-job gate is `coverage,doctest,playwright`.
  - §11 bans judging the a11y verdict on Windows/macOS.

  This is what item 4's re-judgement rests on. Retiring the pre-push `windows-tests` `run --browser` mirror removes no verdict leg. A native Linux pre-push stage that carries `run --browser` inherits the locked-CLI form and the `browser-missing`-is-failure rule. It also needs the pinned Node plus the locked Playwright's Chromium on its `env -i` PATH, which is the founder's widening call.
- **2026-09-24-quality-gates** — §1 cli surface, §9 Unit/integration row and §10 changed where the CLI output-discipline tests report. They still run on all three OS legs. Locally they report under `nextest-integration` / `nextest-e2e`; in CI they report inside the per-OS `coverage` suite, gated by `gate --require coverage,doctest` (now `coverage,doctest,playwright`). Failures surface only as nextest failures in `suites[].failures[]`. Item 4 must keep this mapping when it migrates pre-push stages to the native Linux host: the suites the native stage runs must still report the P4/P6 and TUI boundary cases under these suite names.

  - D-A11Y-12 as amended 2026-09-27: the a11y verdict is ubuntu-judged.

  Item 3's outer-PTY boundary cases and any new mutant-killing viola-pty tests run on that portable-pty pin and must not re-pin it. Item 4's browser re-judgement rests on the ubuntu-judged reason.
