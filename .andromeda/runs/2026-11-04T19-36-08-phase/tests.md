@extract_section name=constraints
- test-plan §1 Test Scope Summary (multi-os-compat trigger) requires the full workspace and fake-agent E2E on all three runners, with OS-branch tests covering ConPTY vs openpty, named pipe vs Unix socket, Windows DACL / strict-modes vs Unix modes, and macOS euid + dir-only server verification. Which `cfg(windows)` cases under `tests/` read a Windows-only behaviour and which are a parity gap is research's question.
- test-plan §9 CI Integration (Matrix builds) requires `windows-2025`, `macos-latest` and `ubuntu-latest` with `fail-fast: false`, and its Build failure conditions fail the build on any unit / integration / E2E / contract / property failure on any of the 3 OSes. Whether the last green run already reads every job green on both Unix OSes is research's question.
- test-plan §10 Quality Gates requires coverage to be gated per OS job (`--fail-under-lines 85 --fail-under-functions 95 --fail-under-regions 80`), because `#[cfg(windows)]` / `#[cfg(unix)]` code compiles only on its own runner. Tests newly enabled on Unix have to hold that bar on `ubuntu-latest` and `macos-latest`.
- test-plan §3 `run` (5-command implementation) requires that tests compiled out by `#[cfg(windows)]` / `#[cfg(unix)]` are never counted as skipped, so only a real `#[ignore]` skip trips `gate`'s `suite-skipped`. test-plan §10 Zero-flakiness budget bans `#[ignore]` as a parking place. A Windows-only case therefore stays `cfg`-gated with its reason, and is never parked with `#[ignore]`.
- test-plan §3 `Log format` requires one schema for process-log lines (the required fields, a closed kebab-case `event` enum where a new value needs a Decisions Log entry, and a null `corr` / `instance` written as an absent key). This backs the scope's "one diagnostics schema, no OS-only word".
- test-plan §6 E2E Test Strategy (Chaos suite) requires the no-EOF held-output half on Windows + Linux only. On macOS, exit on the handle is shown by the handle wait alone, because the output ends at the leader's exit. test-plan §6 Exit-cause matrix compiles the server-identity negatives out on macOS (no peer pid, the named carve-out). Both are existing per-OS carve-outs with stated reasons, and no test reads the macOS case as a comparison.
- test-plan §6 E2E Test Strategy (drivers per surface) requires TTY rendering (dim `stale`) to be asserted only on SGR sequences in verb output under the portable-pty outer PTY. The `v1-40` outer-PTY dim-stale witness is named there as a CARRY on "Linux and macOS parity".
@extract_section name=patterns
- Test homes are fresh per test, at a not-yet-existing path under `target/e2e-home`. A test-made home or socket directory is made through `viola_state::fs::create_private_dir`, never a bare `tempfile::tempdir()` (per test-plan §5 Integration Test Strategy, Setup / teardown lifecycle). The test-owned socket root is `SOCKET_ROOT_VAR` in `tests/support/home.rs` (`TMPDIR` on macOS, else `XDG_RUNTIME_DIR`) (per test-plan §2 Test Strategy).
- The `wait_ready` readiness stall report in `tests/support/home.rs` appends per-OS process state at the deadline: `/usr/bin/sample` on macOS, `/proc/<pid>/wchan` + `stat` on Linux. It is the witness for the macOS readiness stall inside `run.start` (route WATCH) (per test-plan §5 Integration Test Strategy, Readiness stall report).
- The tui driver is a portable-pty outer PTY over the `viola-pty` seam. Exit comes only via `child.wait()`, and the master reader is drained on its own thread (per test-plan §6 E2E Test Strategy, Drivers per surface).
- On Unix, the fake agent runs each spawned command in its own process group (`process_group(0)`), and its exit ignores SIGHUP from its first step (per test-plan §7 Test Data & Fixtures, Fake agent).
- Shared helpers live once in `tests/support/`. Integration binaries keep the `<surface>_<topic>.rs` prefixes so the layer filtersets select them on every OS (per test-plan §2 Test Strategy, Test directory + naming conventions).
@extract_section name=anti_patterns
- Never treat a Linux-only local run as proof for Windows or macOS: OS-branch code is verified only on its own runner. Never treat a green fake-agent run as proof of real-CLI behaviour (per test-plan §11 Test Anti-Patterns, Test Strategy).
- Never use `sleep(N)` for synchronisation, never parse the rendered child screen, and never detect child exit by master EOF (per test-plan §11 Test Anti-Patterns, E2E).
- Never add a retry, never park a test with `#[ignore]`, never lower a coverage threshold, and never widen the coverage `--ignore-filename-regex` to turn a Unix job green (per test-plan §11 Test Anti-Patterns, Quality and CI).

Obs owns `schemas/diag-line.v1.json` / `schemas/diag-detail.v1.json`, and tests own the conformance check (per test-plan §6 E2E Test Strategy, Schema conformance). - tests ↔ security: the macOS server-check carve-out (no peer pid, so no pid / start-time comparison) and the Linux/macOS socket-directory negatives in `tests/security_negatives_socket_dir.rs` (per test-plan §6 E2E Test Strategy, Exit-cause matrix and Security control negatives).
- tests ↔ CI: the per-OS `test` (`agent-run run --coverage` + `viola-harness gate --require <suites>`), `perf` and `lint` jobs in `ci.yml` (per test-plan §9 CI Integration).
