@extract_section name=constraints
- The Unix wrapper runs its child through the same `pty` seam as Windows (spawn · read · write · resize · wait · kill), with portable-pty pinned `=0.8.1` and child exit detected on the process handle, never on EOF. `viola_pty::pty_backend()` reports `openpty` off Windows. No pin moves to make a Unix case pass (per architecture §Established Decisions → [PTY]; §Stack and Technologies → PTY layer). Whether the Unix spawn/resize/kill legs already behave as the Windows ones do under the fake agent is research's question.
- Every OS-specific branch compiles and is tested on its own CI runner. Children are spawned directly, with no shell-out through `sh`/`bash`/`cmd` (the one exception is `hook statusline` running the user's command). So a `cfg(windows)`/`cfg(unix)`/`cfg(target_os)` test gate needs an OS-specific behaviour behind it, never a parity gap (per architecture §Cross-cutting Patterns → Cross-platform discipline).
- `ci.yml` remains the only push/PR pipeline, with matrix `os: [windows-2025, macos-latest, ubuntu-latest]` on native runners. The `test` job (coverage floors 85/95/80 per OS, G2, G4 `schema-check`, secret-scan, `gate --require coverage,doctest`), `perf` (`gate --require perf`) and `lint` (G1/G3) run per OS. "Green on both" Unix runners means those per-OS jobs. The real `claude` never runs in CI, and `viola verify` runs there only against the fake agent, with all twenty-four relied ledger rows on the Unix runners (per architecture §Infrastructure Patterns → CI/CD approach).
- The diagnostics schema is one schema across OSes. Process-log lines are fixed by the obs-owned `schemas/diag-line.v1.json` and detail lines by `schemas/diag-detail.v1.json`. `events.ndjson` lines follow the event-line shape and snapshots follow the `{v, written_at, writer, data}` envelope. An absent optional field is omitted on write, and readers treat a missing field and `null` as the same thing (per architecture §Standard Contracts; §Conventions → Data model conventions; §Occupied Resources → Filesystem). Whether any writer or schema differs per OS today is research's question.
- The typed exit set stays `0, 1, 2, 10–14, 20, 21`, and `viola hook` always exits 0 with no stderr. No new code is added (per architecture §Conventions → CLI exit codes; §Occupied Resources → Binary, subcommands and exit codes).
- The macOS peer-pid gap is the recorded carve-out: `server_verdict` returns `Matches` with no comparison, and `server-verify-failed` on macOS means an euid mismatch alone. A parity test must not read it as a pid/start-time comparison (per architecture §Established Decisions → [Message Broker / IPC]; §Standard Contracts → Instance snapshot).
- No new env var outside the ratified sets. Test seams are read only under `cfg(feature = "fake-agent")`, and env vars are not a configuration channel. Each test runs in its own `--home`, so parallel Unix tests never share an endpoint, log or `budget.json` (per architecture §Occupied Resources → Environment variables; §Cross-cutting Patterns → Config management; §Established Decisions → [CI/CD]).
@extract_section name=patterns
- Unix endpoint: socket `<socket dir>/viola-<h12>.sock` in a per-user 0700 directory (`$XDG_RUNTIME_DIR/viola/` on Linux, `$TMPDIR/viola/` on macOS), chmod 0600 after the bind, with an euid peer check on both sides and never an abstract-namespace name. Socket-dir tests take their own socket root through `SOCKET_ROOT_VAR` (`TMPDIR` on macOS, `XDG_RUNTIME_DIR` elsewhere) (per architecture §Occupied Resources → IPC endpoints).
- Test homes live under `target/e2e-home/viola-test-*/home` and are kept in CI for the obs gates. The single exception is `viola-chaos-*`, which sits outside G2/G4. Test-only endpoints are `viola-test-chan-<pid>-<label>` sockets, outside the `viola-<h12>` namespace (per architecture §Occupied Resources → Filesystem and → IPC endpoints).
- The test support's `Wrapper::kill` / `Watch` (bound `WITHIN` = 7 s, report under `<temp dir>/viola-root-watch/`) and viola-pty's real-PTY report files under `<temp dir>/viola-pty-watch/` keep evidence of a killed test. These are the existing rigs for Unix kill/resize legs (per architecture §Occupied Resources → Filesystem).
- The fake agent is substituted by naming its executable after `--` (`viola run <name> -- <fake agent> <args>`). viola resolves the child to an absolute path itself (per architecture §Established Decisions → [CI/CD]).
@extract_section name=anti_patterns
- Do not move or weaken any Windows behaviour, ConPTY sideload, strict-modes rule or `cfg(windows)` pin to make a Unix case pass. Windows stays the first target (per architecture §Design Philosophy; §Established Decisions → [PTY]).
- No env, flag or feature seam may force an OS-specific decision outside `cfg(feature = "fake-agent")`. Do not add a `concurrency:` block or a mutation job to `ci.yml` (per architecture §Occupied Resources → Environment variables; §Infrastructure Patterns → CI/CD approach).
- Do not add an OS-only field or closed word to any viola format. An extra field is additive under the same `v`, and a field one OS cannot fill reads its documented null or word (per architecture §Conventions → Interfaces and versioning).
@extract_section name=bindings
- arch ↔ obs: G1–G4 and the `diag-line.v1.json` / `diag-detail.v1.json` schemas are obs-owned. Arch fixes only where they live (`diagnostics/`, codes-only role files) and that CI runs them per OS (§Cross-cutting Patterns → Diagnostic output channels; §Infrastructure Patterns → CI/CD approach).
- arch ↔ tests: the fake-agent suite, harness `run --coverage`, per-OS coverage floors and test-home layout bind to the test plan (§Infrastructure Patterns → CI/CD approach; §Occupied Resources → Filesystem).
- arch ↔ security: the Unix socket dir, the euid peer check and the macOS peer-pid carve-out are security-enforced. Arch fixes only the resource names and the recorded gap (§Occupied Resources → IPC endpoints; §Cross-cutting Patterns → Local endpoint trust boundary).
@extract_section name=acceptance
- The `test`, `perf` and `lint` jobs of `ci.yml` read green on `ubuntu-latest` and `macos-latest` beside `windows-2025` on the chunk's pushed sha, with no new workflow, `concurrency:` block or mutation job (per architecture §Infrastructure Patterns → CI/CD approach).
- Each remaining `cfg(windows)`/`cfg(unix)`/`cfg(target_os)` gate under `tests/` names the OS-specific behaviour it reads, and every shared behaviour runs on all three runners (per architecture §Cross-cutting Patterns → Cross-platform discipline).
- `git diff` of the chunk adds no exit code, no `VIOLA_*`/test-seam env var outside the ratified sets, and no OS-only key or closed word in `schemas/diag-line.v1.json`, `schemas/diag-detail.v1.json` or the event/snapshot writers (per architecture §Conventions → CLI exit codes; §Occupied Resources → Environment variables).
- No Windows ConPTY, endpoint or strict-modes source or pin changes in the diff (per architecture §Established Decisions → [PTY]).
