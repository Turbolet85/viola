- layout-templates §Component — Primary content block 1: `viola list` strip rows requires a `stale` row to be SGR dim from end to end, with the word `stale` in LIVE, NAME bold, and only the `DIALOG` word amber and not dim. - layout-templates §Output structure — `viola list` (piped / `NO_COLOR` / `TERM=dumb`) requires the width to come from `viola_pty::host_size()` and never from `COLUMNS`, a piped stdout to read no width and get no truncation, and colour to be off under `--json`, a piped stdout, `NO_COLOR`, `TERM=dumb` or a failed Windows VT enable. Colour depth (truecolor / 256 / 16) comes from `COLORTERM` / `TERM`. Whether `host_size()` already reports a width under the openpty backend is research's question.
- layout-templates §Output structure — `viola verify` requires `MM` in `[NN/MM]` to be `LedgerRow::relied()`'s length: 24 on Unix and 21 on Windows, because Windows skips the three statusline rows. Step lines must appear in ledger order and end with the `stamped <ver>  <n> pass  <m> fail` summary.
- layout-templates §Component — Primary content block 2: refusal lines and the `unable` column requires the server-check refusal on Linux, Windows and macOS to have the same line, hint and `server-verify-failed` `--json` detail. On macOS the check is an euid mismatch alone, with no pid or start-time comparison (the named carve-out). The Unix socket-directory refusal must have its own hint and the `socket-dir-refused` detail.
- layout-templates §Output structure — `viola --help` requires the usage line to be the override literal on every OS, pinned by the `HELP` literal in `tests/cli_output_plain.rs`. Only the per-verb clap usage may name the executable differently (`viola.exe` on Windows).
- layout-templates §Output structure — `viola plugin install` requires `<dir>` to be quoted per host. On Unix it is single-quoted unless every character is an ASCII letter, a digit or one of `_ - . / :`. On Windows it is double-quoted when it holds a space.
- layout-templates §IA notes requires the human columns and words to stay stable as a contract, with new fields going into `--json` first. The chunk's "one diagnostics schema" must not add an OS-only human word or column.
@extract_section name=patterns
- layout-templates §Output structure — `viola run` and §Output structure — `viola revive`: a passthrough start prints nothing while the child holds the terminal. The openpty wrapper must keep this behaviour.
- layout-templates §Component — Primary content block 2: refusal lines and the `unable` column (Streams): results go to stdout, while `waiting:`, the issue line, refusals, hints and errors go to stderr, and the two never mix. Under `--json` each outcome is one stdout document with an empty stderr.
- layout-templates §Component — Footer / terminator: on a refusal the `hint:` line is the last stderr line, and there is no terminator word.
- layout-templates §Surface: cli (Expression level): level 0.0 applies under `--json`, non-TTY, `NO_COLOR`, `TERM=dumb` and the `viola run` / `viola revive` passthrough. It means no colour, no non-ASCII glyph and no cursor control.
