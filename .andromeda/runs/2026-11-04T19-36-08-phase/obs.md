@extract_section name=constraints
- obs-plan §1 Obs Scope Summary (trigger multi-platform-exporter-compat) requires the same file sink and line schema on every OS, with identical fields and no OS-specific exporter. That is the obs side of the scope's "one diagnostics schema". Whether any writer or schema differs per OS today is research's question.
- obs-plan §8 PII Scrubbing (default-deny posture) requires home-level lines to validate against `schemas/diag-line.v1.json` and detail lines against `schemas/diag-detail.v1.json`, both closed by a top-level `unevaluatedProperties: false`. An OS-only field or `event` word is a conformance failure unless a Decisions Log entry adds it (also obs-plan §11 Logs: no `event` value added without a Decisions Log entry). obs-plan §3 Log format JSON schema (Null encoding) makes null a key absence (`corr`, `instance`). The scope says "never a missing key", so P3 must reconcile the scope's wording with that encoding for process-log lines.
- obs-plan §6 Log Coverage (Boundary-call wrappers, PTY seam) requires the openpty backend to log the same lines as ConPTY. Spawn emits `process-start{subject:"claude-child"}`. The child's exit comes from the handle-wait thread and never from reader EOF. A kill-fallback is logged as `exit_source:"kill-fallback"`. A paste logs `text_bytes` only. Whether the Unix path already does this is research's question.
- obs-plan §4 Span / Trace Coverage (Scenario: `wait` / `last` event-driven readback) requires the same closed words on Unix. A refused server or euid exits 21 with `detail:"server-verify-failed"`. A refused socket directory gives `detail:"socket-dir-refused"`. A refused tree gives `strict-modes-failed`. macOS compares euid only, which is its named carve-out. obs-plan §6 Log Coverage (Boundary-call wrappers, IPC invocation) requires that an euid-refused peer on Unix writes no line.
- obs-plan §3 Log file location requires every `diagnostics/` file to be 0600 inside a 0700 directory on Unix, with the home DACL on Windows. The secret-scan test enforces both. The Linux dev host's `target/e2e-home` is a link to an owner-only tmpfs directory, and no CI runner has that link.
- obs-plan §9 CI Integration requires G1–G4 each as its own `run:` step with `shell: bash` on all three OSes. G2, G4 and the secret scan must run `if: always()` in both the `test` and `perf` jobs, with `AGENT_RUN_KEEP_HOMES=1`. The uploads must be gated on `steps.secret-scan.outcome == 'success'`.
- obs-plan §10 SLO Invariants & Telemetry Budgets requires zero unlogged panics, zero schema-conformance failures and zero secret-scan hits on every OS. Any nonzero count makes the chunk red until it is fixed inside the chunk. The hook perf `max` budgets, measured by `gate --require perf`, hold per OS.
@extract_section name=patterns
- G2 runs as `scripts/g2-zero-panics.sh` (fail-closed, `--probe` first). Its `find target/e2e-home/` start point ends in a slash, so the walk goes into the Linux dev host's linked home root. The one exemption is the `fake-agent` seam's panic at `src/cmd/hook/seam.rs:<digits>` (per obs-plan §9 CI Integration).
- Every integration-test viola home lives under `target/e2e-home/`, so G2, G4, the secret scan and `diag-<os>` cover it. The one carve-out is the `tests/chaos_feed_panic.rs` `TestHome::outside_scan()` home, and that test asserts its own lines (per obs-plan §9 CI Integration).
- Artifacts are named per OS: `diag-${{ matrix.os }}`, `harness-<os>`, `junit-<os>`, `perf-<os>`, `diag-perf-<os>` and `secret-scan-<os>`, each kept 7 days (per obs-plan §9 CI Integration).
- Code that only one OS builds is written as `#[cfg(unix)]` twins. On the Windows mutation leg the harness leaves them out as host-excluded, for example `src/panic_frames.rs` (per obs-plan §9 CI Integration, Mutation row).
- The panic hook writes one line through a single `write_all` on a pre-opened file, and every Cargo profile keeps `panic = "unwind"` (G3). The `run` PTY pump and handle-wait threads each run inside `catch_unwind` on every OS (per obs-plan §7 Error Capture & Reporting).
@extract_section name=anti_patterns
- No test, gate or telemetry assertion may get a retry-once policy to make a Unix leg pass (per obs-plan §11 SLO; `retries = 0`).
- A failing job's `diagnostics/` must not be lost, and nothing may be uploaded before the secret scan passes. A re-run is not a substitute (per obs-plan §11 CI).
- Telemetry must not go to stdout on any role, and `print!` / `eprintln!` / `dbg!` must not appear in the `hook`, `run` or `mcp` paths. This holds for Unix-only code too (per obs-plan §11 Logs).
@extract_section name=bindings
- obs ↔ tests §3 Log format: obs owns `schemas/diag-line.v1.json` and `schemas/diag-detail.v1.json`, and tests own the G4 validator and the `target/e2e-home/` home layout that the newly ungated Unix tests must follow (per obs-plan §9 CI Integration).
- obs ↔ security Vector 7: Unix 0600/0700 permissions, `strict-modes-failed` and `socket-dir-refused` refusal telemetry (per obs-plan §1 Obs Scope Summary, triggers).
- obs ↔ arch CI/CD: the `windows-2025` / `macos-latest` / `ubuntu-latest` matrix that the obs gates run on (per obs-plan §9 CI Integration).
- obs ↔ tests §3 harness: `agent-run logs` / `status` give the same merged ndjson on every OS (per obs-plan §3 Snapshot / paste-to-AI integration).
@extract_section name=acceptance
- In the `test` and `perf` jobs on `ubuntu-latest` and `macos-latest`, as on `windows-2025`, G1 and G3 exit with rg exit 1, G2 (with `--probe`) and G4 pass, and the secret scan's outcome is `success` (per obs-plan §9 CI Integration).
- On all three OSes there are 0 `event:"panic"` lines (apart from the seam exemption), 0 schema-conformance failures and 0 secret-scan hits, measured by the in-job gate exit codes (per obs-plan §10 SLO Invariants & Telemetry Budgets).
- Each test moved off `cfg(windows)` boots its home under `target/e2e-home/`, so its Unix diagnostics are counted by G2, G4 and the secret scan (per obs-plan §9 CI Integration).
- On Linux and macOS, every `diagnostics/` file is 0600 inside a 0700 directory (per obs-plan §3 Log file location).
