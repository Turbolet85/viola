# a11y extract

## Relevance
partial — the cli surface only (the `viola list` human board and `list --json`, and `viola revive`'s new refusal pair); the ledger row, its probe, the parser's property / fuzz target and the fake-agent stub carry no a11y clause of their own.

## Constraints
- a11y-plan §1 (Surface: cli → ARIA roles inventory) names the `-- UNWRAPPED - READ-ONLY --` separator as the board's heading-equivalent, after the BAY context line and the uppercase caption line, and records it and its unwrapped rows as owed to "Unwrapped sessions on the board"; the separator stands in for a landmark and is printed as plain text. Whether the separator and the `no wrapped sessions …` empty line both print when there are no wrapped rows but some unwrapped ones is for the design and layout sources to settle. a11y-plan §1 does not decide it.
- a11y-plan §4 (landmark table, cli row) requires the structural order BAY line → caption line → wrapped rows → separator → unwrapped rows. Under that row, the as-built board stops at the wrapped rows.
- a11y-plan §4 (P6, C0/C1 escaped) requires every control character injected through a `claude agents --json` row to appear only in escaped form, including ESC / CSI, C1, `\n` and `\t`. `\n` and `\t` are escaped inside `list` table rows (`\x0A`, `\x09`), so each row stays one fixed-width line. Under non-TTY, `list` stdout holds no raw C0 / C1 byte inside a row. The plan also says the fixture-row setup waits on this chunk. Whether `escape_row` already covers each field the agents call contributes is research's question.
- a11y-plan §1 (Surface: cli → Notes) requires output that is static and linear, with no spinner or redraw. The `claude agents --json` read that `list` and `revive` now make must not add progress output, a `\r` redraw or cursor movement while it waits. The `waiting:` stderr line belongs to `wait` / `last` only.
- a11y-plan §6 requires each state to be carried by its printed word alone while `viola list` emits no SGR: the new STATUS values (`idle` / `busy` / `unknown`) and the read-only nature of an unwrapped row are text, never colour. The colour layer is owed to "CLI output discipline", not to this chunk.
- a11y-plan §8 (Consistency and predictability) requires the caption order `NAME · LIVE · STATUS · WHEEL · DIALOG · CLI`, pinned by the `CAPTION` literal, to stay unchanged. Unwrapped rows fill the same columns under that caption, with no second caption set.
- a11y-plan §8 (Error recovery) requires `viola revive`'s new exit-1 `session-live` refusal to take the fixed-message form of the other revive refusals: one `unable: <text>` line, then one `hint:` line last on stderr. a11y-plan §1 (CLI verbs entity) adds that the pair carries no ESC byte and no colour. a11y-plan §1 (tui entity) and §11 (Keyboard) require that a revive whose preflight passes, including through a fail-open agents read, enters the same passthrough with no line of its own and no blocked or delayed keystroke.

## Patterns to follow
- Board literals, not trycmd, pin `viola list`'s fixed strings (a11y-plan §8, Plain language): the root case `list_human_board_is_the_literal_rows` (`tests/cli_list.rs`) and the `src/human/board.rs` units `bay_line_*` / `board_row_*`. The separator and an unwrapped row extend these literals.
- The row escape is held by the unit cases `escape_row_shows_every_control_character_as_hex_text` and `board_row_cli_cell`, plus the no-ESC / no-non-ASCII stream assertions in `list_human_board_is_the_literal_rows` and `list_of_a_stopped_wrapper_is_an_empty_board` (a11y-plan §4, P6). The fixture-row setup this chunk owes runs `viola list` against an agents fixture row through the same assertions.
- Revive refusal pairs are pinned by root cases in `tests/cli_revive.rs` (a11y-plan §8, Error recovery). `session-live` joins them.
- The cases are ordinary nextest cases inside the existing suites, with no new driver (a11y-plan §3 CI integration).

## Anti-patterns to avoid
- Claiming WCAG conformance for the board. The literal and assert_cmd cases are output-discipline stand-ins for SC 1.3.2 / 1.4.1 / 3.3.1 only (a11y-plan §11, Strategy).
- Adding a spinner or redraw while the agents call runs, or while it waits out its time bound (a11y-plan §11, Motion).
- Adding an `a11y` suite value or a separate a11y driver for the new cases (a11y-plan §11, CI).

## Contract bindings
- a11y-plan §3 CI integration ↔ the tests harness: the new board and revive cases run under `scripts/agent-run.sh run` plus `gate --require coverage,doctest`, inside CI's per-OS `coverage` suite on all three OS legs.
- a11y-plan §3 Structured violation JSON schema ↔ the tests harness: cli has no a11y rows. An output-discipline failure surfaces only in `suites[].failures[]`.
- a11y-plan §4 (P6, C0/C1 escaped) ↔ the security plan's C0/C1 escaping and the tests' fake agent (`FAKE_CLAUDE_AGENTS_MODE=recorded`): the fixture row that carries the injected controls is the one this chunk records and stubs.
- a11y-plan §4 (landmark table) ↔ design-system / layout-templates cli: they set the separator's text and the unwrapped rack's columns. a11y-plan fixes only the separator's place in the order.

## Acceptance criteria contributions
- `viola list` run against a `claude agents --json` fixture row whose fields carry ESC / CSI, C1, DEL, `\n` and `\t` prints each control only as `\xHH`. Every unwrapped row is one line, and stdout holds no raw C0 / C1 byte inside a row (per a11y-plan §4 P6).
- With at least one wrapped and one unwrapped session, the human board prints, in order, the BAY line, the unchanged `CAPTION` literal, the wrapped rows, the `-- UNWRAPPED - READ-ONLY --` separator and then the unwrapped rows. A wrapped row's STATUS is the word `idle`, `busy` or `unknown`, with no SGR (per a11y-plan §4 landmark table; §8 Consistency and predictability; §6).
- `viola revive` refused `session-live` exits 1, writes exactly one `unable:` line and then one `hint:` line last on stderr, and leaves no ESC byte on either stream (per a11y-plan §8 Error recovery).
- An oversize, malformed or failed agents read leaves `viola list`'s output static, with no `\r`, cursor-movement or erase sequence and an unchanged exit (per a11y-plan §1 Surface: cli → Notes).
