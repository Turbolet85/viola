## Relevance
relevant — the chunk adds the `claude agents --json` child spawn and parser that obs-plan instruments as a boundary-only entity (subject `agents-probe`, parser `claude-agents-json`), adds a new revive exit-1 refusal, and widens `viola list`'s `cli` log.

## Constraints
- The `claude agents --json` read is a boundary-only entity: obs-plan §1 Obs Scope Summary (Instrumentation scope, the `claude agents --json` and `--version` probe entity) requires instrumenting its spawn/exit and its parse outcome. A parse failure must become `"unknown"` plus a counter, and the rows are untrusted. Whether any call site already spawns or logs it is research's question (the scope reads none today).
- obs-plan §1 Obs Scope Summary (Telemetry triggers, security Vector 8 child spawn) requires a `process-start` / `process-exit` pair for each `claude agents --json` probe. obs-plan §6 Log Coverage (Boundary-call wrappers, Child / shell spawns) fixes its `subject` as `agents-probe`, which is already a member of the closed `$defs.subject.enum` in `schemas/diag-line.v1.json`. The `process-exit` carries `child_exit_status` and `duration_ms` from the §6 additive field catalog. No row text, session id, `cwd` or path appears in either line.
- obs-plan §6 Log Coverage (Boundary-call wrappers) requires a parse failure to give `parse-rejected{parser:"claude-agents-json", detail, count}`, at `warn` (§6 Log levels mapping) and with `corr` null. The §6 `detail` code catalog gives this parser only `malformed`: `oversize` is catalogued for `channel-frame`, `hook-stdin` and `vt100-feed` only, and `diag-line.v1.json` constrains `parse-rejected.detail` to that list (D-31). An over-`MAX_FRAME` agents read therefore either logs `malformed` or needs a catalog and schema amendment. That choice is for P2/P3.
- The new revive refusal for an id that is live elsewhere (the scope's `session-live`) is an exit-1 cause. obs-plan §6 Log Coverage (`detail` code catalog) closes `process-exit` `detail` at 12 values in `schemas/diag-line.v1.json`, so a 13th value is a catalog and schema amendment. The refusal must be a distinct kebab-case code with no pid or path. It is written as one `process-exit{subject:"self", exit_code:1, detail}` in `run-<name>.ndjson`, with no child started. The preflight takes no later reading once one refusal fires, and the new reading's place in the holder → session → directory order must be stated.
- obs-plan §1 Obs Scope Summary (Telemetry triggers, creator-explicit Founder Direction 4) requires a distinct `detail` code, with no path or pid, for each cause behind exit 1, revive's preflight refusals included.
- obs-plan §4 Span / Trace Coverage (Instrumentation per surface, the cli short-lived-verbs row) requires `viola list` to keep its `cli.list` dispatch span. It opens `cli-<name>.ndjson` only after its strict-modes scan passes and only when `VIOLA_NAME` parses. A refused scan writes no line. Any agents-probe or parse line from `list` follows the same gate. Without a name, no log is open and the lines go nowhere.
- obs-plan §8 PII Scrubbing & Compliance (Data classification rules, the `claude agents --json` rows / unwrapped session ids row) classes the rows as Low and untrusted. They are never logged verbatim, only as `parse-rejected` counts, and C0/C1 controls are escaped in human terminal output. A row's `cwd` is an absolute path and follows the Medium rule in the same table: never in a home-level line.

## Patterns to follow
- obs-plan §6 Log Coverage (`detail` code catalog, Filesystem refusals): `viola_state::board::read` writes one `parse-rejected{parser, detail, count}` per nonzero count after its loop. It names no entry and writes into `cli-<name>.ndjson` under a `VIOLA_NAME` only, while `board::scan` itself logs nothing. An agents-row count line follows the same shape.
- obs-plan §6 Log Coverage (Boundary-call wrappers): `viola verify` logs each child spawn pair at its call site, and `run_bounded` itself stays unlogged. Do the same for the agents-probe spawn, whether it is called from `list`, from revive's preflight or from a verify probe.
- obs-plan §4 Span / Trace Coverage (Scenario: `viola run` start sequence, `run.version_gate`): the `version-probe` pair `process-start` / `process-exit{subject, child_exit_status, duration_ms}` is the existing model for a bounded `claude` sub-command read.
- obs-plan §4 Span / Trace Coverage (Edge flows, E5): a line written while `list` scans other instances carries the caller's own `instance`, never the scanned one. An unwrapped row's `name` never becomes `instance`.
- obs-plan §8 PII Scrubbing & Compliance (Integration points, item 1): emit through `obs_event!` with explicit typed fields only, under `#[instrument(skip_all, name = "<area>.<operation>", fields(..))]` with a static snake_case name (§4 Span naming convention).

## Anti-patterns to avoid
- obs-plan §11 Obs Anti-Patterns (PII Scrubbing): never log a field that is not in the §6 catalog (default-deny), and never put a pid or path in a `detail` code. The study's wording "naming the pid" for the live-elsewhere refusal is barred.
- obs-plan §11 Obs Anti-Patterns (Spans / Traces): no bare `#[instrument]` and no `err` / `ret` on the agents parser or spawn. Their errors can carry a serde source or row content.
- obs-plan §11 Obs Anti-Patterns (Metrics): never group derived counts by `pid`, `child_pid`, `instance` or a session id. `viola.parse.rejected` and `viola.child.exit` group by `parser` / `subject` / `detail` only (§5 Metric label cardinality discipline).

## Contract bindings
- obs ↔ tests: obs owns `schemas/diag-line.v1.json`, and G4 (tests-owned check body) validates every home-level line against it (obs-plan §9 CI Integration, G4). A new `process-exit` `detail` value, or any `parse-rejected.detail` widening, lands in the schema and in the §6 catalog together. The parser's proptest and fuzz target and the fake agent's `FAKE_CLAUDE_AGENTS_MODE` stub are tests-owned. obs adds no fixture content (obs-plan §8 PII Scrubbing & Compliance, the Recorded fixtures row).
- obs ↔ security: security Vector 8 child-spawn rules (direct spawn, R8 strip, bounded stdout). On the obs side the R8 strip logs names or counts only, never values (obs-plan §1 Obs Scope Summary, Telemetry triggers Vector 6). Rows rendered on the human board are C0/C1-escaped (obs-plan §1 Obs Scope Summary, Telemetry triggers Vector 8).
- obs ↔ arch / verify: a ledger-row probe that adds a `viola verify` spawn changes the count of seven spawn pairs that obs-plan §4 Span / Trace Coverage (Edge flows, `verify` / `plugin install`) states. The new pair would take a `subject` from the closed enum (`agents-probe` for an agents read), and that §4 text and §6's count move with it.
