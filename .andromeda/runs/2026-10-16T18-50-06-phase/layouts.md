# layouts extract

## Relevance
relevant: the chunk changes the cli surface's `viola list` board (STATUS words, the unwrapped rack, `list --json` items) and adds a `viola revive` refusal pair.

## Constraints
- The unwrapped rows sit after every wrapped row, under one `-- UNWRAPPED - READ-ONLY --` separator on its own line. The wrapped rack has no separator: it always comes first, headed by the caption row (per layout-templates §Component — Primary content block 1: `viola list` strip rows).
- The six columns NAME · LIVE · STATUS · WHEEL · DIALOG · CLI are fixed for both racks. The wireframe's unwrapped row fills WHEEL, DIALOG and CLI with `n/a` and STATUS with a word such as `idle`. No link column exists, and a pid column, which would be a seventh column, is not on the board (per layout-templates §Output structure — `viola list` (human TTY); per layout-templates §IA notes: "Adding a human column is a design change, not an implementation choice").
- STATUS on a wrapped row takes `idle`, `busy` or `unknown`. Rows are ordered by name, and nothing is re-sorted by state (per layout-templates §Output structure — `viola list` (human TTY)). The as-built padding is NAME to the longer of 4 and the longest name, LIVE to 5, STATUS to 7, WHEEL to 23, DIALOG to 17, and CLI last and unpadded. No line ends in a space (per layout-templates §Output structure — `viola list` (piped / `NO_COLOR` / `TERM=dumb`), its as-built paragraph). The plan does not say whether unwrapped NAMEs count toward the NAME width. That is research's question.
- Every field that comes from `claude agents --json` has its C0/C1 controls escaped as hex text, `\n` and `\t` included, so a row never splits and the columns keep their fixed width (per layout-templates §Component — Primary content block 1: `viola list` strip rows, Escaping).
- Truncation applies only to unwrapped NAMEs, marked with `...`, and only where the terminal width is known. Nothing is truncated when the width is unknown, and no line ever wraps (per layout-templates §Component — Primary content block 1: `viola list` strip rows, Truncation; per layout-templates §Output structure — `viola list` (piped / `NO_COLOR` / `TERM=dumb`)). The as-built paragraph prints the uncoloured form on every stream, and the styled human-TTY form is owed to "CLI output discipline". Whether this chunk adds width-known truncation, or leaves it with that owed form, is research's question.
- `<target>` is always a `ViolaName`, and unwrapped names are never valid targets (per layout-templates §Component — Primary navigation (verb structure)).
- Every `viola revive` refusal is exit 1, with an empty stdout and on stderr one `unable:` line followed by one `hint:` line, the hint last. It names no path, no pid and no logged id. Each refusal has its own distinct hint, and no hint names `viola release` (per layout-templates §Output structure — `viola revive`; per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column, Hint line).

## Patterns to follow
- The as-built board is one stdout write: the BAY line, the caption row, then the rows in name order. Column padding comes from the bin's hand-written fixed-width module, with the two-space gutter and no box drawing (per layout-templates §Surface: cli, Tooling context; per layout-templates §Output structure — `viola list` (piped / `NO_COLOR` / `TERM=dumb`), its as-built paragraph).
- The existing `escape_row` covers every control character, DEL and C1 included. As built, its one upstream-derived cell is the recorded CLI version. It is the escape to extend over the agents call's fields (per layout-templates §Component — Primary content block 1: `viola list` strip rows, As built).
- The revive refusal pairs follow the listed form `unable: <name> …` / `hint: …`, for example the `already-live` pair `unable: <name> is already live` / `hint: viola list`. A new `session-live` pair joins that list in the same form (per layout-templates §Output structure — `viola revive`).
- `list --json` is one JSON document on stdout, with no header line, no colour and no glyph. Its item shape is the `list` payload contract, and new fields go into `--json` first (per layout-templates §Output structure — `viola list --json`; per layout-templates §IA notes, Output as a contract).

## Anti-patterns to avoid
- A pid on the board or in a refusal or hint line: a hint never names a path or a pid, and the revive refusals name none (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column, Hint line; per layout-templates §Output structure — `viola revive`).
- Styling or colour on the new rows or the separator. On the cli, colour is reserved for `DIALOG` and `stale`, and the separator is plain. The styled form is "CLI output discipline"'s (per layout-templates §Component — Primary content block 1: `viola list` strip rows, Styling; per layout-templates §Output structure — `viola list` (piped / `NO_COLOR` / `TERM=dumb`), its as-built paragraph).
- Any spinner, redraw or cursor control while `claude agents --json` is read (per layout-templates §Surface: cli, token table, Motion tokens: "Nothing redraws in place").

## Acceptance criteria contributions
- (layouts) Given at least one agents row that joins no wrapped instance, `viola list` prints `-- UNWRAPPED - READ-ONLY --` on its own line after the last wrapped row, and each unwrapped row under it fills all six columns, with `n/a` in WHEEL, DIALOG and CLI. Given no unwrapped row, it prints no separator (per layout-templates §Component — Primary content block 1: `viola list` strip rows; per layout-templates §Output structure — `viola list` (human TTY)).
- (layouts) An agents field holding `\n`, `\t` or another C0/C1 control prints as hex text inside one line. Every printed line keeps the fixed column widths, and none ends in a space (per layout-templates §Component — Primary content block 1: `viola list` strip rows, Escaping; per layout-templates §Output structure — `viola list` (piped / `NO_COLOR` / `TERM=dumb`)).
- (layouts) A wrapped row's STATUS reads `idle` or `busy` when it joins an agents row, and `unknown` otherwise. Row order stays by name (per layout-templates §Output structure — `viola list` (human TTY)).
- (layouts) `viola revive` on an id that is live elsewhere exits 1, with an empty stdout and one `unable:` line and one distinct `hint:` line, the hint last, on stderr. Neither line holds a pid, a path or the session id, and the hint does not name `viola release` (per layout-templates §Output structure — `viola revive`).
