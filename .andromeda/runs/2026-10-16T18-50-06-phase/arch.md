# arch extract

## Relevance
relevant: the chunk adds the `claude agents --json` read, the parser and join for the existing `list` payload, a capability-ledger row with its `viola verify` probe, a fake-agent mode, a fuzz target and a new `viola revive` preflight refusal. Each of these is set by architecture.md's contracts, crate boundaries and occupied resources.

## Constraints
- architecture.md §Established Decisions [Agent Coverage] requires that the `claude agents --json` row shape, its `status` → `idle`/`busy` mapping and the join-field reading live only in `viola-agent-claude`, which stays pure (no I/O). The bounded spawn belongs to the root bin, like the version gate's `--version` read. §Infrastructure Patterns → Crate dependency direction names `viola-agent-claude` as "the only crate that knows Claude payload shapes, including `claude agents --json`". It also orders `viola-agent-claude` → `viola-state`, so `viola-state`'s `board` module cannot take an agent-crate type. P3 research must answer two questions: where the join between the parsed rows and `board::read`'s items sits (in the root bin `src/cmd/list.rs`, or over normalised `viola-core` data), and whether the agent crate's manifest already holds a `viola-state` edge.
- architecture.md §Standard Contracts (Session liveness) requires the following:
  - The reader resolves `claude` from its own PATH with the same npm-shim → `claude.exe` resolution that `run` uses, and spawns it directly.
  - If the read is not found, fails or cannot be parsed, every row's `status` is `unknown`, no unwrapped row is listed, and the outcome is never an error.
  - A row that matches a wrapped instance's `child_pid` or `agent_session_id` in its snapshot is merged into that instance's row and never listed separately.
- architecture.md §Established Decisions [Session Liveness] requires that `claude agents --json` only *enriches* liveness. Liveness is still decided by the heartbeat plus pid and start time, so the read must not change a wrapped item's `liveness` or bring back a `gone` instance. The same section fixes `viola revive`'s preflight as readings taken in a fixed order that stop at the first refusal (the name's holder, the logged session, the recorded directory), with the strict-modes check ahead of the preflight and before the wrapper log opens. A `session-live` reading joins that ordered chain; where it falls in the order is P4's.
- architecture.md §Standard Contracts (`list` payload) fixes the unwrapped item: `wrapped: false`, `name` set to the session identifier that `claude agents --json` reports (not a `ViolaName`, never a valid `target`), `liveness` `live`, `dialog_pending` `false`, and `wheel`, `budget_paused`, `cli_version` and `cli_verified` absent. `status` is one of `idle` · `busy` · `unknown`. The payload stays `{items, budget, skipped}` with no pagination.
- architecture.md §Cross-cutting Patterns (Capability ledger as the single gate for CLI-specific behaviour) requires the join field to be a ledger row in `viola-agent-claude` with a `viola verify` probe that has a post-condition check. One ruled limit applies: a shape no `send` relies on needs no probe. Whether the row joins `LedgerRow::relied()` (which gates `cli_verified` and turns every earlier stamp unverified) or is only a ledger record is the P4 question the scope already names.
- architecture.md §Conventions (CLI exit codes) requires a revive preflight refusal to be exit 1, with exactly one `unable:` / `hint:` pair on stderr that holds no recorded directory, pid or logged id, and one `process-exit{subject:"self", exit_code:1, detail}` line in `run-<name>.ndjson`. §Conventions (CLI) and §Established Decisions [CLI Conventions] add that `revive` takes no `--json`, so the new refusal has no machine form in this chunk.
- architecture.md §Conventions (Channel methods) and §Established Decisions [API Style] require that `list` stays a caller-side read of the disk and `claude agents --json`. It is not a channel method and needs no live wrapper, so no channel method or frame is added for the read.

## Patterns to follow
- The version gate's bounded child read (architecture.md §Established Decisions [CLI Version Compatibility], its `--version` paragraph): one run of the resolved executable, stdout and stderr drained through `MAX_FRAME`, killed at a fixed bound, and output it cannot parse read as a fixed fallback. This is the shape for a bounded `agents --json` read that cannot hang `list`.
- The capability-ledger row pattern (architecture.md §Established Decisions [CLI Version Compatibility]): add the row to the closed `LedgerRow::ALL` in order, give it a `check(row, &Probes)` post-condition over captured probe output and a `relied_on` per-OS decision, have `viola verify --record` write a scrubbed `<Event>.<stem>-<n>.json`-style variant through `scrub` / `unclean`, and have the fake agent replay it.
- The recorded-fixture discipline (architecture.md §Occupied Resources → Repository): sets live under `fixtures/claude/<cli-version>/`, are scrubbed (home → `~`, user word → `<user>`) and refused whole with a closed code, are hygiene-walked by `tests/contract_fixture_hygiene.rs`, and each committed set's file count is stated with its counting rule.
- The fuzz workspace (architecture.md §Occupied Resources → Repository; §Established Decisions [Module Boundaries]): a new `fuzz/fuzz_targets/<target>.rs` with a committed `fuzz/corpus/<target>/` sits in the separate `fuzz/` workspace, which depends on `viola-agent-claude` by path and is never a root member.
- The tolerant external-payload regime (architecture.md §Established Decisions [Validation]): no `deny_unknown_fields`, `#[serde(default)]` / `Option<T>`, the raw `serde_json::Value` kept for the fixture recorder, and serde_path_to_error for drift reports.

## Anti-patterns to avoid
- No new environment variable read by any `viola` build. architecture.md §Occupied Resources → Binary, subcommands and exit codes lists the fake agent as "twelve argv options (the count's rule is this list), no env". §Occupied Resources → Environment variables and §Cross-cutting Patterns → Config management allow only the two test seams `FAKE_AGENT_PUMP_DELAY_MS` and `FAKE_AGENT_HOOK_PANIC`. The scope's `FAKE_CLAUDE_AGENTS_MODE=recorded|oversize|malformed` therefore conflicts with the plan as written. It needs either an argv mode word or option, which would amend the twelve-option list, or a ratified new seam. P4 decides which.
- No shell and no shim spawn: architecture.md §Cross-cutting Patterns → Cross-platform discipline (children spawned directly, never through `sh` / `bash` / `cmd`; `hook statusline` is the only shell-out) and §Established Decisions [CI/CD] (a `.cmd` / `.bat` child is refused or resolved to the real `claude.exe`).
- No Tokio or async on the `list` and `revive` paths: architecture.md §Cross-cutting Patterns → Tokio containment and §Established Decisions [Concurrency / Backend Framework]. The read is a blocking std spawn.

## Contract bindings
- arch ↔ security: the direct spawn, the R8 strip, the `take(MAX_FRAME)` bound and the time bound on the new `claude agents --json` child. Also verify's child set (architecture.md §Established Decisions [Plugin Scope] lists verify's transient unwrapped children). A probe that adds a start amends that list, and it needs a widening ruling.
- arch ↔ tests: the fake agent's argv option list and its count rule (architecture.md §Occupied Resources → Binary, subcommands and exit codes); the committed fixture sets and per-set counts under `fixtures/claude/` (§Occupied Resources → Repository); the `fuzz/fuzz_targets/` list and its corpus counts (§Occupied Resources → Repository).
- arch ↔ obs: `list`'s enumerated `cli-<name>.ndjson` lines (architecture.md §Occupied Resources → Filesystem, `diagnostics/`). A spawn pair or `parse-rejected` line for the agents read amends that list. `revive`'s new closed `process-exit` detail also ties into obs-plan's vocabulary.
- arch ↔ design/layout: the unwrapped rows' columns and the `-- UNWRAPPED - READ-ONLY --` separator on the human board. The item shape is arch's (§Standard Contracts, `list` payload); the rendering is theirs.

## Acceptance criteria contributions
- The `claude agents --json` row type, its `status` mapping and the join-field reading are defined in `viola-agent-claude`, and `viola-state` gains no Claude-specific shape. No manifest edge is added against the stated direction (per architecture.md §Infrastructure Patterns → Crate dependency direction).
- With `claude` absent, exiting non-zero, timing out, or giving over-`MAX_FRAME` or malformed output, `viola list` (human and `--json`) exits as it does today. Every wrapped item reads `status: "unknown"`, no `wrapped: false` item appears, and no wrapped item's `liveness` changes (per architecture.md §Standard Contracts, Session liveness).
- Every `wrapped: false` item in `list --json` carries exactly `name`, `wrapped`, `liveness: "live"`, `status` and `dialog_pending: false`, with `wheel`, `budget_paused`, `cli_version` and `cli_verified` absent. No agents row that joins a wrapped instance's `child_pid` / `agent_session_id` is listed twice (per architecture.md §Standard Contracts, `list` payload).
- The join-field row is a member of `LedgerRow::ALL` with a `viola verify` post-condition check, and its `relied()` membership is stated per OS. `viola verify`'s `[NN/MM]` step count and the `contract_ledger_probes` row ids follow it (per architecture.md §Established Decisions [CLI Version Compatibility]).
