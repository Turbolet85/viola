## Constraints
- a11y-plan §1 A11y Scope Summary (CLI and terminal entities → `viola run` TUI passthrough) requires that human keystrokes are never blocked, refused or delayed past the current atomic paste, and that focus, mouse and resize sequences and terminal replies (F-W2's closed list) do not count as human editing while every other byte does — a behaviour-preserving restatement in `Classifier::step` / `is_reply` / `Classifier::abort` / `Recorder::record` must leave both halves unchanged.
- a11y-plan §1 A11y Scope Summary (Critical paths → 4, Human takes the wheel) requires SC 2.1.1 on the tui path (the human keyboard path through the wrapper is never blocked); a survivor disposal in `src/run/wheel.rs` may not narrow it.
- a11y-plan §3 Keyboard test harness requires the reply shapes and their negative controls to be proven by the classifier's unit table: each listed reply by exact grammar (fields compared as bytes, no intermediate byte, exact field count), and the nearest human keys (`n`, `t`, `m`, their Alt forms, their kitty key events) plus any sequence one field or one prefix away from a listed shape staying typing. New wheel tests belong in that unit table; whether the table already holds a row that kills each of the 9 `wheel.rs` mutants (e.g. the `:434:50` / `:467:35` `<`→`<=` bound mutants, the `:427:17` deleted ESC arm, the `:458:24` `osc` guard) is research's question.
- a11y-plan §3 Keyboard test harness requires the tui keystroke proof to be sequenced on the wrapper's `channel-request` line and the `wheel` record, never a timer — any new wheel-adjacent test (including one in the `src/run/send/*.rs` split) waits on records, not sleeps.
- a11y-plan §5 Keyboard Navigation (Focus order per layout → tui) requires that the terminal stays the child's and human keystrokes are never delayed past the atomic paste; a test-only seam added to reach a survivor stays behind `cfg(test)` or the existing test features and adds no path on the keystroke route of a release build.
- a11y-plan §10 SLO Invariants & A11y Budgets (Standard+ invariants) names the epoch-boundary mutation audit (`run --mutants`, test-plan §10) as the coverage reader of the CLI output-discipline invariants that live in crate tests — a survivor disposal on such an invariant is worded for the Epoch 5 boundary audit as its reader.

## Patterns to follow
- The classifier's unit table as the home of reply and negative-control rows (per a11y-plan §3 Keyboard test harness): one row per exact grammar plus a one-field / one-prefix-away negative control that stays typing.
- Step-wise wheel probing on records, never timers: the wheel read after each step by the `wheel` record or an `answer` to no pending dialog (exit 13 = driver, 10 = human) (per a11y-plan §3 Keyboard test harness).
- Output-discipline assertions as nextest cases inside `nextest-integration` / `nextest-e2e` locally and the per-OS `coverage` suite on CI, with no a11y rows and no conformance claim (per a11y-plan §9 CI Integration, Unit / integration row).

## Anti-patterns to avoid
- Never block, refuse or delay a human keystroke past the current atomic paste, and never count focus / mouse / resize sequences or terminal replies as editing (per a11y-plan §11 A11y Anti-Patterns § Keyboard) — a restatement that changes any classification is a production behaviour change and out of this chunk.
- Never claim WCAG conformance for the cli or the `viola run` TUI from these tests: assert_cmd / portable-pty / unit results are output-discipline stand-ins, not a11y-tool evidence (per a11y-plan §11 A11y Anti-Patterns § Strategy).
- Never parse the rendered `claude` TUI screen for content as evidence (per a11y-plan §11 A11y Anti-Patterns § Universal) — the fake-PTY tests for `src/cmd/verify/typed.rs` assert framing and the driver's own state, not rendered vendor content.
