# tests extract

## Relevance
relevant — the chunk is test-suite strength work: it disposes 47 mutation survivors under the forms test-plan §10 Mutation gate and §3 `run` step 4 define, by new owning-package unit tests, restatements and by-coordinate records.

## Constraints
- A kill must come from the owning package's own tests: §3 `run` step 4 (Test scope) keeps cargo-mutants' default (no `--test-workspace`), so a mutant in `crates/viola-<area>` is killed only by that crate's tests and `viola-e2e` scenarios never count against another package's mutants (per test-plan §3 `run` step 4). So the `viola-state`, `viola-agent-claude` and `viola-pty` survivors each need a test inside that crate, and the root-package survivors need root-package tests (`src/` inline or root `tests/`). Whether the three Linux-compiled resize tests the scope names for `viola-pty` `resize` `:202:9` live in `viola-pty` itself or in another package is research's question; if they live elsewhere, that is a candidate cause of the miss.
- A site this host cannot compile or reach (a `cfg(windows)` item, or behind a const such as `cfg!(windows)`) is recorded "not measured here; owed to {route entry}" by coordinate, never "equivalent" and never counted as caught. A const-gated mutant compiles on both hosts, the harness never leaves it out, and it stays a by-coordinate record (per test-plan §10 Mutation gate). This applies to the six `fs.rs` `replace_private_with` survivors unless a restatement lets the caller supply the decision. It also applies to the two `viola-e2e` `scratch.rs` `prepare` survivors, which §10 already records as not measured here and read caught on `windows-2025` (run 38036448183).
- §10 Mutation gate requires `missed == 0` after the harness's host-excluded records, `timeout == 0` and `unviable <= caught`. Only a mutant whose whole span sits under a `cfg` predicate proved false for the host is host-excluded (per test-plan §3 `run` step 4, Verdict). So a restatement must not add an unviable-prone or timeout-prone site, and a `cfg`-gated restatement is read by the harness's predicate reader, never by argument.
- No mutation run inside the chunk (`inputs#I1`) overrides the §3 `run` step 4 inner fix loop `run --mutants --file <path>` (per test-plan §3 `run` step 4). Each new test is proved by a hand-applied, then reverted, mutant in the working tree, and the counted verdict is the Epoch 5 boundary audit's (per test-plan §10 Mutation gate: "judged at the epoch boundary by `/andromeda-code-audit`").
- No real time in test-side code: no test-owned timer, sleep or elapsed-time verdict, so deadline-dependent sites (`dialog.rs` `millis`, `verify/typed.rs` `max_gap` / `Feed::take` / `Run::finish`, if timing-based) are driven through the injected `viola_core::Clock` or an instant passed as an argument (per test-plan §11 Universal). Under §8 Mocking & Stubbing Discipline, mock_instant is in no manifest yet; the seam is the `Clock` trait or a pure function's argument (per test-plan §8).
- Zero flakiness: nextest `retries = 0`, and `#[ignore]` is never a parking place for a test that cannot run here (per test-plan §10 Zero-flakiness budget). A test that cannot reach its site on Linux is compiled out by `cfg`, never ignored, the way the macOS-only exclusion of the real-cargo-mutants tests is done (per test-plan §10 Mutation gate).
- Unit tests sit inline in `#[cfg(test)] mod tests` in the mutated file, named `<subject>_<condition>_<expected>`. Table cases use rstest `#[case::label]`, except in `viola-e2e`, which has no `[dev-dependencies]` and uses a labelled case table in one `#[test]` (per test-plan §4 Conventions). New tests for the moved `close` go in the `src/run/send/*.rs` split files.

## Patterns to follow
- Doubles only for traits the product already defines at its seams (`Pty`, liveness probe, `Clock`) via `#[cfg_attr(test, mockall::automock)]`. The `verify/typed.rs` `<impl Pty for SharedPty>` survivors (`resize`, `close`, `child_pid`) and the Run B driver are exercised through a `Pty` double or fake reader, never a live `claude` (per test-plan §8 Mocking & Stubbing Discipline; §4 viola-pty). Whether `verify/typed.rs` already has such a seam is research's question.
- Prefer dependency injection to runtime patching: a const decision such as `HOST_IS_WINDOWS = cfg!(windows)` becomes a parameter the caller supplies (the restatement form), so the retry path runs on Linux with a real tempfile home (per test-plan §8 anti-monkey-patching; §8 Filesystem: not mocked).
- Pure-function unit cases with the instant or input as an argument, like `decide(reading, thresholds, override_until, now)` and `classify(beat_age, same_process)` with exact-boundary cases (5.0 s live, 5.1 s stale). The relational mutants (`>`→`>=`, `<`→`<=`) are killed by a case at the exact boundary value (per test-plan §4 What unit tests cover, root bin and viola-state).
- State-reader cases plant a malformed file only by altering the writer's own bytes, and `board.rs` `NotFound` guards use a real tempfile home with the file absent or present but unreadable (per test-plan §11 Test Data; §11 Integration).

## Anti-patterns to avoid
- NEVER dispose a survivor as "equivalent" or by argument, and NEVER count a not-measured-here site as caught (per test-plan §10 Mutation gate). NEVER treat a Linux-only run as proof for a Windows-gated site (per test-plan §11 Test Strategy).
- NEVER trust the cargo-mutants exit code or summary line alone (per test-plan §11 Quality). A hand-applied mutant's evidence is a named nextest test failing on an assertion under the mutant and passing on the original, not a compile failure or a panic outside the assertion.
- NEVER use `std::env::set_var` in tests, a test-owned `sleep`, or a live `claude` / `viola verify` start (per test-plan §11 Integration; §11 Universal; §11 Test Strategy).

## Contract bindings
- tests ↔ the epoch-boundary audit (`/andromeda-code-audit`): every disposal record is worded for the Epoch 5 boundary audit's mutation run, the only reader that confirms a kill (per test-plan §10 Mutation gate; §3 `run` step 4, Verdict).
- tests ↔ CI §9 Mutation row: a not-measured-here record names the route entry that measures it, and its Windows reading is the `windows-mutants.yml` dispatch (nine `mutants (<label>)` jobs, the root package split by file). If a restatement moves a Windows-gated site or file, it binds that matrix's `--file` list (per test-plan §9 Mutation row).
- tests ↔ security: `fs.rs` `replace_private_with` is the security plan's one replace helper. A restatement there keeps its mode-before-write behaviour, and that is the security domain's to state; tests only require that behaviour is preserved (per test-plan §8 Filesystem: not mocked).

## Acceptance criteria contributions
- Each of the 47 survivors maps to exactly one of three forms: an owning-package nextest test, a behaviour-preserving restatement removing the site, or a "not measured here; owed to {route entry}" record by audit coordinate. None is marked equivalent (per test-plan §10 Mutation gate; §3 `run` step 4, Test scope).
- Each new test is shown failing on an assertion under its hand-applied mutant and passing on the original. The mutant is reverted, and no `run --mutants` or workflow dispatch is made (per test-plan §3 `run` step 4; §10 Mutation gate).
- `scripts/agent-run.sh run --unit` (nextest `kind(lib) | kind(bin)`, `--features viola/fake-agent --profile ci`) and `cargo test --workspace --doc` pass with `retries = 0` and no new `#[ignore]` (per test-plan §3 `run` step 1; §10 Zero-flakiness budget).
- Per-OS coverage gates still hold after any restatement: lines ≥ 85, functions ≥ 95, regions ≥ 80 (per test-plan §10 Coverage thresholds).
