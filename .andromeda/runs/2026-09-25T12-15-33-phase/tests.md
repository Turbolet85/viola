## Constraints
- The SQOS pass criterion is the shape set in test-plan §6 Security control negatives → "Windows client SQOS". A test-owned, same-user pipe server calls `ImpersonateNamedPipeClient` and reads `TokenImpersonationLevel`. The only pass is `SecurityIdentification`. `SecurityImpersonation` or higher is a fail. Per test-plan §6, `#[cfg(windows)]`.
- A `#[cfg(windows)]` body only counts as verified on its own runner (`windows-2025`). A Linux or dev-host run is not proof (per test-plan §11 Test Strategy "NEVER treat a Linux-only local run as proof for Windows"; §9 Matrix builds; §10 Stack adjustments on per-OS gating).
- Mutation gate: `missed == 0`, `timeout == 0`, `unviable <= caught`. Any `.rs` in the diff makes it `counted`, test files included. In CI the verdict is the union of the ubuntu and windows-2025 legs. A `#[cfg(windows)]` body is killed only on the windows leg (per test-plan §10 Mutation gate; §3 `run` step 4). A Rust-free diff passes only as `no-rust-delta` (per test-plan §10). That can apply to the licence and README files alone.
- Supply chain must stay green on every leg: `cargo deny --format json check` on the root graph (bans / licences / sources / advisories), `cargo deny --manifest-path fuzz/Cargo.toml … check advisories sources`, the sole-root `deny-sync.toml` tokio ban for each crate in `scripts/sync-crates.txt`, and `scripts/deny-probes.sh` ending `deny-probes: 13/13 banned, control clean` (per test-plan §9 Pipeline structure → Supply-chain row; §9 Build failure conditions).
- Lint: `cargo clippy --workspace --all-targets --features fake-agent -- -D warnings`, and `cargo check` of the sync crates in `scripts/sync-crates.txt` without tokio. This applies to any new dependency or test target (per test-plan §9 Lint row).
- Coverage is gated per OS at lines ≥ 85, functions ≥ 95, regions ≥ 80 over the workspace. The ignore regex must not be widened to hold new spike code (per test-plan §10 Coverage thresholds; §11 CI).
- Determinism: nextest `retries = 0`. No `sleep` for synchronisation between the pipe server and client threads. Wait on an explicit signal instead (per test-plan §2 Agent-runnable invariants; §10 Zero-flakiness budget).

## Patterns to follow
- Placement and naming. Crate-level integration tests go in `crates/<crate>/tests/<topic>.rs`. Root sync suites use a `<surface>_<topic>.rs` prefix such as `channel_`, so nextest layer filtersets can select them. Security negatives go in `security_negatives_*.rs`. Functions are named `<subject>_<condition>_<expected>` (per test-plan §2 Test directory + naming conventions; §6 Security control negatives). The chunk scope leaves open whether a durable spike witness lives under the not-yet-existing `viola-channel` or somewhere else. Research answers that.
- The SHA-256 known-answer cases (the published vector, plus the 16-hex truncation for `bin/<version>-<hash>/`) are unit-level rstest `#[case::<readable_label>]` tables. The expected digests are written as literals, never computed by the product code under test (per test-plan §4 Fixture pattern; §11 Unit "NEVER import the product's own … as the test oracle").
- Windows API calls in tests go through windows-sys 0.61.2, and pipe-side test fixtures use the interprocess 2.4.4 server API (per test-plan §5 Driver(s) / Module ↔ IPC row; §8 Fake servers row).
- Run through the harness: `scripts/agent-run.sh run --unit` / `--integration` (`.ps1` on Windows) and `run --mutants`. Read the one JSON document on stdout and the exit code (per test-plan §3 5-command implementation `run`; §9 Unit/Integration rows).
- Remove-the-guard witness. Remove the guard and the new guard test must go red, so a spike or known-answer test cannot pass vacuously. This matches test-plan §3's "never a vacuous pass" grammar rule and the probe pattern in §9 (`deny-probes`, `orphans-check --probe`).

## Anti-patterns to avoid
- NEVER use interprocess `try_overwrite`, and NEVER reuse an endpoint name across tests. The test-owned SQOS pipe server needs a unique name for each test (per test-plan §11 Integration).
- NEVER use `std::env::set_var` in tests. Use `Command::env` for each child. NEVER call `.env_clear()` without re-adding `LLVM_PROFILE_FILE` (per test-plan §11 Integration).
- NEVER trust the cargo-mutants exit code alone. Count `missed` / `timeout` / `unviable` / `caught` from `outcomes.json` (per test-plan §11 Quality).
