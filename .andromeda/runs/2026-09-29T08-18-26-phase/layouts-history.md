## Relevant amendment history
- **2026-09-28-capability-ledger-and-viola-verify** — rewrote the `viola verify` output structure to the six measured ledger rows (`[01/06] … [06/06]`, last stdout line `stamped 2.1.283  6 pass  0 fail`, `MM` grows only as owning chunks land ledger rows), and added to the fixed-message exit-1 exceptions verify's four `unable:`/`hint:` pairs, `viola run`'s pinned-copy refusal, and a failed verify's exact `error: internal error`. Why it matters here: it is the source of two rules the extract leans on. First, `[NN/MM]` rows are ledger rows only, so a sideload/signature check routed through `verify` must not show up as a step line or bump `MM` without a ledger row, and the sideload is not a claude-CLI capability. Second, the pinned-copy refusal is the existing `viola run` start refusal that any new sideload or pin-failure refusal would sit beside. A new cause adds to that same exception list in fixed `unable:` + cause-specific last-line `hint:` form, with no path, hash or version. The preferred design is still a silent degrade that adds no list entry.
