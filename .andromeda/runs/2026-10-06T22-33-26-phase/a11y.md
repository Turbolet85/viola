# a11y extract

## Relevance
partial — cli output discipline only (the `send` client's human, plain and `--json` renderings of the new outcomes, plus the tui boundary of the wrapper's send slot); no web-spa surface is built here, and no WCAG conformance claim rests on anything this chunk adds (a11y-plan §1 A11y tier; §2 Agent-runnable invariants).

## Constraints
- a11y-plan §1 CLI and terminal entities lists `send` among the verbs asserted in three modes (human TTY, plain, `--json`); the new `unconfirmable` outcome and the confirmed `/clear` outcome are new renderings of that verb, so each mode's rendering falls under the output-discipline assertions. Whether the existing `send` tests already cover all three modes is research's question.
- a11y-plan §1 Surface: cli → Notes requires colour to be a second cue only, no SGR, glyph or cursor control under `--json` / non-TTY / `NO_COLOR` / `TERM=dumb`, and static linear output with no spinner or redraw. The `[  ] unconfirmable` line must carry its state in the printed word, and waiting out the `/clear` post-condition window must add no progress redraw.
- a11y-plan §6 State color tokens → CLI equivalent closes the CLI's SGR set to three spans (the `DIALOG` word, stale rows, NAME column values). The plan grants no SGR to a readback mirror line, so the `unconfirmable` line carries none of its own on a TTY either. Whether `src/human.rs` styles the existing mirror writers is research's question.
- a11y-plan §8 Error recovery → CLI defines the stderr `unable <reason> <detail>` + final `hint:` layout for refusals only, and `--json` as one document with no hint. `unconfirmable` is an `ok` outcome (scope W1: stdout, exit 0), so the plan requires no `unable` word and states no hint for it; the a11y plan mints neither. The changed `/clear` case (formerly exit 13 `no-prompt-submitted`) leaves the refusal layout only where the spec says it is no longer a refusal.
- a11y-plan §8 Plain language → Verification requires every fixed CLI string to be pinned by a test, so a copy change fails CI until the pin is moved on purpose. The mirror word `unconfirmable` is a new fixed string. Whether the mirror lines are pinned by trycmd or by assert_cmd today is research's question.
- a11y-plan §1 Surface: tui and §4 P4 (tui) require zero viola-originated bytes on the wrapper's terminal and human keystrokes never blocked or delayed past the current atomic paste. W1's send-slot and hook-tap changes, and any option on the W2 card that alters what `send` does while the paste hint stands, must leave both clauses intact; the mirror line belongs to the `send` client process, never to `viola run`'s terminal.
- a11y-plan §10 Standard+ invariants requires the CLI output-discipline invariants to pass on all three OS legs inside the nextest suites (CI: `coverage`), with the epoch-boundary mutation audit covering those that live in crate tests.

## Patterns to follow
- Tooling for cli checks is assert_cmd + predicates + trycmd in `nextest-integration` / `nextest-e2e`, with the portable-pty outer PTY for TTY-only behaviour (a11y-plan §3 A11y testing tool pick → Primary tool per surface; §4 P6).
- State is asserted as a printed word beside any visual cue; the plan's readback vocabulary already names `unconfirmable` as a state word (a11y-plan §1 A11y triggers → visual-discrimination; §4 Per-component pattern catalog, Transfer marker row; §6 State color tokens).
- The cli half of the send path is the readback mirror plus the refusal layout, pinned per case (a11y-plan §4 P2 → cli; §1 Critical paths 2).
- Output-discipline failures surface as nextest failures in `suites[].failures[]`; the cli emits no a11y violation row (a11y-plan §3 Structured violation JSON schema → cli / tui).
- Manual screen-reader passes on the cli are supplemental and founder-owned, never gating (a11y-plan §7 Per-surface SR test pattern, cli row; §2 Agent-runnable invariants); this chunk owes no pass record under the plan.

## Anti-patterns to avoid
- Never colour `unable` / `fail`, and never emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run` (a11y-plan §11 Visual).
- Never convey a state by colour alone, and never claim WCAG conformance for the cli or the `viola run` TUI on the strength of assert_cmd / trycmd / portable-pty results (a11y-plan §11 Visual; §11 Strategy).
- Never block, refuse or delay a human keystroke in `viola run` past the current atomic paste (a11y-plan §11 Keyboard) — the bound on every option the W2 card prices.

## Contract bindings
- a11y ↔ design / layouts: the mirror's word and box come from design-system's readback vocabulary and layout-templates' readback mirror (scope: Surfaces and contracts). a11y-plan §8 Consistent identification binds the CLI `[RB]` to the web `data-rb="read"`; the plan states no equivalent CLI ↔ web sentence for `unconfirmable`, but its web checks assert that exact word (§4 P2 → Tests), so the CLI word must not drift from the vocabulary.
- a11y ↔ tests: a11y-plan §6 State color tokens → Verification drives each web state through the fake agent. The fake agent's `--local-command-mode` path that yields `unconfirmable` is the driver the later web state will need; the web checks themselves (the readback-`unconfirmable` axe verdict and word-cell accessible name, a11y-plan §4 P2 and §10 Always-required SLO invariant) are outside this chunk by the scope's Boundaries (Epoch 8).
- a11y ↔ obs: a11y-plan §1 Structured violation JSON schema (the obs block it reproduces) fixes `send-confirmed`'s `corr` as the send `cursor`; §1 Critical paths 2 names that join as the source of the web readback state. `send-confirmed{confirmed:false}` must keep the `corr` binding (obs-plan §6 owns the event).
- a11y ↔ tests (CI): cli checks run inside the per-OS `test` job's suites with no new `suite` value (a11y-plan §9 Per-pipeline-stage a11y artifacts, Unit / integration row; §11 CI).

## Acceptance criteria contributions
- (a11y) In human mode, a ledger-listed local command with no measured post-condition ends with a line containing the literal word `unconfirmable`; under non-TTY, `NO_COLOR` and `TERM=dumb` the `send` output for that case and for a confirmed `/clear` contains no SGR, cursor-movement, erase or `\r` redraw sequence, on all three OS legs (per a11y-plan §1 Surface: cli → Notes; §4 P6).
- (a11y) Under `--json` both new outcomes are exactly one JSON document on stdout with no SGR, no glyph line and no hint text (per a11y-plan §1 Surface: cli → Notes; §8 Error recovery → CLI).
- (a11y) On a TTY (outer PTY) the `unconfirmable` line carries no SGR span of its own, the plan's SGR set being closed to `DIALOG`, stale rows and NAME values (per a11y-plan §6 State color tokens → CLI equivalent; §4 P6).
- (a11y) The three P4 outer-PTY boundary cases stay green after the send-slot change: no viola-originated byte on the wrapper's terminal stream from either new outcome, and human keystrokes delivered unblocked during a local-command `send` (per a11y-plan §4 P4 → tui; §1 Surface: tui).
