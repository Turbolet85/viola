# design extract

## Relevance
partial — W1's human rendering of `send` (the `[  ] unconfirmable` mirror line and the `/clear` send's read-back line) is the `cli` surface's readback mirror; W2, W3 and W4 (the readiness gate, the fake-agent screen variant, two comments) have no design coverage, and the web readback state is outside this chunk by its own Boundaries.

## Constraints
- design-system §Surface: cli → Component Patterns 2 (`viola send`: the readback mirror) requires the `unconfirmable` outcome to print as its own mirror line: the open mirror `[  ]`, the word `unconfirmable`, the instance name, then the fixed phrase of that sample's last line — on stdout, exit 0. The sample is the authority for the words, the two-space field separation and the stream; whether `src/human.rs` already has a writer of that shape is research's question.
- design-system §Brand Identity (Signature element, the "fourth printed word" sentence) and §Color Palette → Semantic Colors / Domain status colors (row `Readback::unconfirmable`) require `unconfirmable` to reuse the open drawing and never be filled: on the CLI that is `[  ]`, never `[RB]` and never `[/ ]`. It is the "degraded but not refused" state, carried by the word alone.
- design-system §Color Palette → Domain status colors (rows `Readback::read` and `SessionStartCause::clear`) requires a `/clear` send whose ledger post-condition is met to take the read-back state: the `[RB] read back` line of §Surface: cli → Component Patterns 2, in that sample's form (name, time, cursor; stdout, exit 0). No separate word or line exists in the plan for a post-condition-confirmed send.
- design-system §Surface: cli → Tokens (the Colour decision order paragraph) requires the mirror words `[RB]` / `[  ]` / `[/ ]` to print in every human output — piped, `NO_COLOR` and `TERM=dumb` included; only `--json` replaces them with its one JSON document. The same section's token table requires the mirror line to carry no SGR at all (colour is spent only on `DIALOG` and `stale` rows), so the new line is plain at every depth.
- design-system §Surface: cli → Tokens (Streams, Width) requires results on stdout and context/refusals on stderr, ASCII-only human output, no wrapping, and the readback word padded to one readback-word column as in the `viola send` sample. In that sample `unconfirmable` is the longest word of the column; whether the existing writers' pad width already holds it without shifting the `open` / `read back` / `unable` lines is research's question.
- design-system §Surface: cli → Component Patterns 2 (the hint list) keys every `hint:` line by a refusal reason (or reason · detail) and prints hints in human mode only. `unconfirmable` is an `ok` outcome, not a refusal: the plan lists no hint for it, and none may be invented. Under `--json` no hint text and no mirror word is printed (§Surface: cli → Exit-code phraseology, row 0: the `ok` document on stdout).
- Gap to carry, not coverage: the plan names no mirror line for a ledger-listed command whose measured post-condition does not arrive inside the window. Its only existing vocabulary for an unconfirmed send is the closed refusal set of §Color Palette → Domain status colors (`RefusalDetail::*`) and the `not-delivered · no-prompt-submitted` hint of §Surface: cli → Component Patterns 2, whose wording speaks of a prompt. Likewise the plan carries one fixed phrase for the `unconfirmable` line and no second wording for "not yet measured on this CLI version". What `send` prints in those two cases is P2's reading of the spec and P3's closure; a new word, phrase or hint would be a design-system amendment, not an implementation choice.

## Patterns to follow
- The existing mirror writers for `[  ] open` (stderr, TTY only), `[RB] read back` (stdout, exit 0) and `[/ ] unable` (stderr, exit 13, then one `hint:` line) are the pattern the fourth line joins: same prefix column, same word column, same two-space field separation (per design-system §Surface: cli → Component Patterns 2).
- State is said by a fixed phraseology word, never by a hue or a symbol (per design-system §Brand Identity, the "Standard phraseology" anchor and Design direction: nothing announces success before it is confirmed).
- One depth-and-colour decision per process, with `--json` first in the order (per design-system §Surface: cli → Tokens, Colour decision order): the new outcome goes through the same decision as every other `send` line, not a branch of its own.
- `open` and `unconfirmable` are meant to look identical but for the word (per design-system §Self-Validation Protocol → 2. Squint Test); the CLI column is the third required place of the signature (per §Self-Validation Protocol → 3. Signature Test).
- `viola verify`'s step-counter output stays at its seventeen rows and its summary line (per design-system §Surface: cli → Component Patterns 5): W3's control touches `framing_turns` only to neutralise and restore it, so no `verify` line may change.

## Anti-patterns to avoid
- Presuming delivery: an `unconfirmable` send must never print `[RB]`, `read back`, "sent", "done" or "success" (per design-system §Anti-Patterns → Rejected Defaults, the optimistic-send entry, and → Per-Surface Bans → cli, the "done"/"success" and the `✓`/`✗` bans).
- Colouring or decorating the new line, or emitting any mirror word, colour or cursor control under `--json`, non-TTY-coloured modes or `viola run` (per design-system §Anti-Patterns → Per-Surface Bans → cli, the colour and the `--json` bans).
- Echoing the sent text (the command itself) or any upstream text, path or pid in the mirror line or a hint, and mixing data with messages across the two streams (per design-system §Anti-Patterns → Per-Surface Bans → cli, the upstream-text and the data/messages bans; §Surface: cli → Component Patterns 2, "A hint never quotes the sent text").

## Contract bindings
- design ↔ layouts: the mirror line's column positions and its place in the `send` screen are layout-templates' (the scope cites its lines 351 and 419); design-system supplies only the vocabulary, the `[  ]` drawing and the colour/stream rules. If the two samples differ in a field (the design sample's `unconfirmable` line shows no time or cursor), layouts is the per-screen authority and the difference is a wrap reconcile item.
- design ↔ architecture: the `ok {confirmed:false, detail:"unconfirmable", cursor}` wire shape and the `--json` document are architecture's Standard Contracts; design-system §Surface: cli → Exit-code phraseology (row 0) only binds the human first word and the stream to exit 0.
- design ↔ architecture / obs (events): design-system §Surface: web-spa → Component Patterns 2 (`<viola-readback>`, Sources and Data dependency) states that the web `unconfirmable` state and the `/clear` fill need records carried by the CL-1 events (an outcome record for `ok` / `confirmed:false`; `session-start` cause `clear` with a new session id). The web state is outside this chunk (scope Boundaries, Epoch 8); whether this chunk's wrapper change owes that outcome record now, or leaves it to the CL-1 owner, is architecture's and obs's question for P2/P3.
- design ↔ security: the mirror line and hints carry fixed words only — binds to security-plan §Error Handling and the NEVER-log floor (no upstream text, no path, no pid in human output).
- design ↔ a11y: none on the CLI surface for this chunk beyond "the word carries the state" (colour never stands alone, per design-system §Color Palette → Semantic Colors), which the uncoloured mirror line satisfies by construction; the web readback's accessible name is owed with the Epoch 8 entries.

## Acceptance criteria contributions
- (design) A send of a ledger-listed local command with no measured post-condition prints exactly one result line on stdout — `[  ]`, `unconfirmable`, the instance name, the sample's fixed phrase — with exit 0, nothing on stderr but the TTY-only issue line, and no `hint:` line (per design-system §Surface: cli → Component Patterns 2)
- (design) That line never contains `[RB]`, `read back` or `[/ ]`, and contains no SGR byte in any mode; under `--json` stdout holds only the JSON document, with no mirror word and no hint (per design-system §Surface: cli → Tokens, Colour decision order; §Anti-Patterns → Per-Surface Bans → cli)
- (design) A `/clear` send confirmed by its post-condition prints the `[RB] read back` line in the sample's form on stdout with exit 0, and the readback word column stays aligned across the `open`, `read back`, `unable` and `unconfirmable` lines (per design-system §Color Palette → Domain status colors, rows `Readback::read` and `SessionStartCause::clear`; §Surface: cli → Tokens, Streams)
- (design) Every word the changed `send` paths print in human mode is one already in the plan's readback and refusal vocabulary; any new word, phrase or hint is backed by a design-system amendment recorded at the wrap (per design-system §Brand Identity, "Standard phraseology"; §Surface: cli → Component Patterns 2)
