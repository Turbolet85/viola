## Patterns to follow
- **Path 2's boot shape:** three instances, `builder`, `mute:--suppress-prompt-submit`, `local:--local-command-mode`; record the `events.ndjson` byte length before the send, assert `ok.cursor` against it, then the records after that offset and the fake-agent receipt. The local-command input may be taken from the compiled ledger rows (step 4). Per test-plan §6 Path 2.
- **Human mirror pinned by trycmd-redacted assert_cmd:** the `viola-send` mirror lines `[RB]` / `[  ]` / `[/ ]` are covered by trycmd `tests/cmd/*.toml` with snapbox `[..]` redactions for cursors and timestamps, stdout for the result line and stderr for refusals with a last-line `hint:`; the `[  ] unconfirmable` line joins that coverage. Whether a `viola-send` case already holds a `[  ]` line is research's question. Per test-plan §5 CLI / §6 Path 2 (Human mode).
- **Verified versus unverified homes come from the product:** stamps only from `viola verify` against the fake agent (rstest `stamped_home`), an unverified child through an unstamped home or `--report-version <unlisted>`, never a written `stamps.json`. Per test-plan §7 Seed strategies / §6 Path 7 step 1 / §7 Fake agent (`--report-version`).
- **A control proves its guard red before green:** the plan's standing form is a planted input that turns the check red, then the restored state green (the fixture-hygiene classes, the drift comparator's planted swap, the SQOS control). `tests/cli_verify.rs` already holds "Run B pasting nothing more once its turn screen shows a modal"; W3's control for the guard before the local-command paste is not named in the plan and joins that file's verify cases. Per test-plan §5 CLI (`tests/cli_verify.rs`) / §7 Fixture hygiene / §6 Contract suite.
- **Deterministic ordering without sleeps:** waits key on `events.ndjson` byte offsets or `viola wait --after`; scripted fake-agent steps are released through the `--control` file by byte offset. Per test-plan §2 Agent-runnable invariants / §7 Fake agent (`--script`, `--control`).

## Anti-patterns to avoid
- NEVER import the product's ledger rows or refusal ordering as the test oracle: the expected command names, verdicts, `detail` strings and exit codes are literals in the test, compared as serde kebab-case values and integer exit codes, never `Debug` strings (the Path 2 input may come from the compiled rows; the expectation may not). Per test-plan §11 Unit.
- NEVER parse the rendered child screen for content, and never treat the green fake-agent run as proof of real-CLI behaviour: the W3 verdict comes from verify's step lines, exit status and the receipt (no further `prompt` entry), and with no live session in this chunk the `/clear` confirmation is proven only against the recorded `clear-1` variants replayed byte for byte. Per test-plan §11 E2E / §11 Test Strategy.
- NEVER park or retry a red: no `#[ignore]`, no nextest retry, no raised bound to absorb the shared-host stall. Per test-plan §11 Quality / §11 CI / §10 Zero-flakiness budget.
