## Constraints
- **Layer ownership for scope §6.** test-plan §1 sets tier `Comprehensive (2)`, and test-plan §2 (Test pyramid) with §11 Test Strategy requires each case at the lowest layer that can hold it: parser, refusal-order and clock cases in §4 unit tables, contract shapes in §5, cross-process behaviour only in §6. The strip rule and the newline-only refusal are therefore owed unit cases first; an end-to-end case is added only for what crosses a process.
- **The plan's stated target for the typed text differs from the founder's ruling.** test-plan §4 (What unit tests cover → viola-agent-claude, the sent-text rule `typed_text`) requires "every trailing LF goes and nothing else (not a CR, …)" in nine labelled cases whose table name carries `trailing_newline`; test-plan §4 (root bin, the send-confirmation matcher) defines the typed text as the sent text "without its trailing LF characters" in seven `trailing_newline` tests; test-plan §6 Path 2 (Verification signal, the text-ending-in-newlines bullet) records the trailing-CR and newline-only outcomes as measured live with "no test at any tier pins the trailing-CR outcome". The ruling (scope §6) supersedes all three passages. The plan is not edited during a phase run (test-plan header), so the plan must name these three passages as amendments the wrap owes, and the chunk's tests replace the "not a CR" cases rather than stand beside them. Whether the code's cases today match the plan's count and names is research's question.
- **Live readings are not a test layer.** test-plan §1 (Untestable zones) and test-plan §6 (Skipped as "untestable") require a route entry's live readings of a real session to be that chunk's own local measurement, kept in its `evidence/` with its own launcher and readers, never harness surface and never a CI step. The CRLF and several-CR readings (scope §6, the 5-start cap) fall under this; only their measured shapes reach the suites, as literals.
- **Mutation verdict and who must kill.** test-plan §10 (Mutation gate) requires `missed == 0`, `timeout == 0` and `unviable <= caught`, read from `mutants.out/outcomes.json`, judged at the epoch boundary and on demand, with no chunk, pre-push or CI mutation gate. test-plan §3 `run` step 4 (Test scope) requires each mutant to be killed by the tests of the package that owns the mutated file, and test-plan §10 (Mutation gate) counts a mutant caught only by a doctest as missed. test-plan §10 names one recorded non-kill form only, "not measured here; owed to {route entry}" for a mutant the host cannot compile or reach, never "equivalent". It names no form for a reachable survivor "disposed with a recorded argument" (scope §5): such a mutant still reads `missed` in `outcomes.json`, so the disposition's form and how the boundary audit reads it are a P4 decision, and whether a cargo-mutants exclusion file exists in the tree is research's question.
- **The `mutants` profile's kill lines are a plan contract.** test-plan §3 Bootstrap phases (`test-runner-install`, `[profile.mutants]`) requires three overrides in this order: `package(viola-e2e)` and `test(/send_window_/)` at a 30 s kill, then `test(/verify_window_/)` at a 45 s kill; it states that a caught mutant "ends at most at the kill line (10 s; viola-e2e 30 s)" and is never graded Timeout, that the viola-e2e override keeps 30 s "because the harness's own tests wait out its 20 s boot deadline by design", and that cargo-mutants' auto timeout is about `max(20 s, 5 × baseline)`. A kill above the 34.5 s test of scope §4 moves that stated line under either fork form, so the keyed file is owed an amendment at the wrap, and the new bound must be shown to keep a hang graded caught (below the unit's auto timeout). The plan states the four-waits-of-8.5 s shape only for the root `verify_window_` no-screen case; that the viola-e2e test has the same shape is not stated by the plan and stays research's question.
- **One scaffolding contract for root tests.** test-plan §3 `run` step 2 requires the rstest chain `home → fake_agent_path → stamped_home → booted_wrapper`, `Wrapper::boot/send/stop` in `tests/support/home.rs`, and every wait on a child bounded at `WITHIN` = 7 s in `tests/support/watch.rs`, exit-aware, with its poll report, strictly below the `mutants` profile's 10 s kill. test-plan §2 (Test directory + naming conventions) requires `tests/support/ndjson.rs` to be the one complete-lines reader for every live-appended file. test-plan §5 (Setup / teardown lifecycle) requires every wrapper a test starts to sit in a `Drop` guard (`Child::kill()` then `wait()`) and, on Windows x64, every piped or outer-PTY `viola run` start to seed the ConPTY companions first. A helper lifted in scope §1 must land inside these, with no bound of its own; whether the per-file copies already go through them is research's question.
- **Gates that still bind a refactor.** test-plan §10 (Coverage thresholds, Stack adjustments) requires lines 85 / functions 95 / regions 80 per OS with `tests/support`, `viola-fake-agent`, `crates/viola-e2e` and `fuzz/` outside the number, so the splits of scope §2 in `src/cmd/verify.rs` and `crates/viola-agent-claude/src/ledger.rs` are measured while `submit` and the lifted helpers are not. test-plan §10 (Zero-flakiness budget) requires `retries = 0` and no `#[ignore]` parking. test-plan §9 (Pipeline structure, Lint row) requires `cargo clippy --workspace --all-targets --features fake-agent -- -D warnings`, which reads a shared helper in every test binary that includes the support module; how unused helpers are kept warning-free there is research's question.

## Patterns to follow
- **Labelled case tables with literal oracles.** test-plan §4 (Conventions; Fixture pattern at unit level) requires rstest `#[case]` tables with readable case labels (`#[case::esc_refused]`) and names `<subject>_<condition>_<expected>`; the existing trailing-newline tables carry `trailing_newline` in their names (test-plan §4, viola-agent-claude and root bin). `viola-e2e` carries no dev-dependencies, so a table there is a labelled array in one `#[test]` (test-plan §4, Conventions).
- **Measured live shapes become literal unit oracles.** test-plan §4 (viola-agent-claude, `prompt-submitted` normalisation) names `prompt_text_live_shape_normalises_as_measured` and `prompt_origin_live_shape_files_as_harness` as the form: each shape read on `claude` 2.1.287 is written into a case as a literal, with the measuring chunk named. The CRLF and several-CR readings follow it before any test pins them.
- **A refusal is asserted on both sides of the channel, by records.** test-plan §5 (Cross-module patterns → Wrapper channel, wrapper-side paste validation) requires a raw client that skips the client check to get the refusal from the wrapper, with no `send-issued` record and no new receipt prompt, and the client half in `tests/cli_*.rs` to exit before any frame is sent. test-plan §6 Path 2 (Verification signal) adds that under the echoing fake agent the exit code and records are a floor: the receipt entry, the `prompt-submitted` `text` and the role file's `text_bytes` are what prove what was typed. Whether the newline-only refusal is a shared validator (and so owes the wrapper half) is research's and P4's question.
- **Mutation run forms.** test-plan §3 `run` step 4 (Command) defines `run --mutants --file <path>` as `--in-diff` plus the file, verdict `scoped`; test-plan §3 `run` step 4 (Package) defines `run --mutants --package <member> [--file <path>]…` as reading no base and writing no diff, verdict `package`, with `NEXTEST_PROFILE=mutants`. The second is the harness form that regenerates a survivor on a line the chunk does not touch. test-plan §10 (Mutation gate) requires every Linux dev-host mutation run to take `TMPDIR=<repo parent>/viola-mutants-scratch`.
- **A route entry is cited by title.** test-plan §5 (Setup / teardown lifecycle) already names `the Epoch 6 entry "Home and code-bearing file integrity"` by title; test-plan §6 (Security control negatives, Windows `--home` outside `%USERPROFILE%`) still holds the bare `:127` twice for the same entry (scope §8's third site).

## Anti-patterns to avoid
- A green fake-agent run is never proof of real-CLI behaviour, and the real CLI never runs in CI (test-plan §11 Test Strategy); the fake agent gains no shape "invented before a recorded fixture" (test-plan §7, Fake agent, Modes), so a CR-dropping behaviour is not added to it on the strength of a live reading alone.
- No `sleep`, test-owned timer or elapsed-time verdict: "refused at once" is proven by the product's exit code and the absent `send-issued` record, with any deadline clock-driven in a unit case (test-plan §11 E2E; test-plan §11 Universal). No retry, and no raised bound to reach green (test-plan §11 Quality).
- Expected refusal details, ordering and exit codes are literals in the test, never imported from the product and never compared by `Debug` (test-plan §11 Unit); the cargo-mutants exit code alone is never the verdict, the `outcomes.json` counts are (test-plan §11 Quality); the coverage `--ignore-filename-regex` is never widened to carry a refactor (test-plan §11 CI).

## Contract bindings
- **tests ↔ security:** the typed-text sentence of security-plan §Input Validation and the three test-plan passages above state one rule; the ruling changes all of them together (test-plan §4 viola-agent-claude; test-plan §4 root bin; test-plan §6 Path 2).
- **tests ↔ architecture:** a new refusal `detail` joins the closed list the unit exit-code mapping reads (test-plan §4, root bin, exit-code mapping and Refusal ordering, where `control-character` precedes every other refusal), needs its own human `unable` line and a `hint:` that never contains `release` (test-plan §6 Exit-cause matrix), and must read the same on MCP and CLI (test-plan §6 Cross-surface parity). Its place in the refusal order is not stated by the plan.
- **tests ↔ obs:** test-plan §6 (Error sanitization and secret scan, Canary) requires every send text the tests feed to embed the content canary. A text of only newlines cannot carry it, and a text ending CR or CRLF carries it before the ending; how the newline-only case stands against that rule is a P4 question. The role file's `text_bytes` (test-plan §6 Path 2) is the obs-side field the strip is read from.
- **tests ↔ parsers:** if the newline-only refusal lands inside `validate_paste_text`, its proptest property (test-plan §6 Property suite) and the `paste_text` fuzz target's independent per-char oracle with its byte-exact corpus (test-plan §6 Property suite, cargo-fuzz paragraph) change with it; where the refusal is decided is research's question.
- **tests ↔ CI:** `.config/nextest.toml` is shared by the `ci` and `mutants` profiles; a rename into `verify_window_` also puts the viola-e2e test under the `ci` profile's 60 s override (test-plan §3 Bootstrap phases, `test-runner-install`, `[profile.ci]`). The Windows mutation leg stays dispatch-only and report-only (test-plan §9, Pipeline structure, Mutation row); this chunk adds no CI step.
- **tests ↔ harness:** scoring `viola-e2e` is `scripts/agent-run.sh run --mutants --package viola-e2e`, verdict `package` (test-plan §3 `run`, Test selection); a failing baseline reads `reason:"mutants-exit-4"`, never a zero-count pass (test-plan §3 `run` step 4, Verdict).
- **tests ↔ rules (scope §7):** test-plan §2 (Test directory + naming conventions) requires unit tests inline as `#[cfg(test)] mod tests` in every crate's source and in root `src/`, which is the fact behind the testing rule's reach into `src/`.

## Acceptance criteria contributions
- `typed_text` unit cases, labelled, pin the strip for LF, CR and CRLF endings and their repeats as measured, with a newline inside the text kept; the send-confirmation matcher cases confirm a text ending CR and CRLF; a `tests/cli_send.rs` case ends exit 0 with `send-issued` → `prompt-submitted{origin:"driver"}` → `send-confirmed`, no `wheel` record, a receipt prompt without the ending and `text_bytes` equal to the typed text's length (per test-plan §4 viola-agent-claude; per test-plan §4 root bin; per test-plan §6 Path 2).
- A text of only newlines is refused with the ruled detail and its literal exit code in a unit case, and end to end with no `send-issued` record, no new receipt prompt and no confirmation window waited; the raw-client wrapper half is present if the refusal is a shared validator (per test-plan §5 Cross-module patterns → Wrapper channel; per test-plan §11 Universal).
- For each of the eighteen survivors, a mutation run on its file in its owning package reads it caught in `outcomes.json`, or it carries the disposition form P4 rules; the run shows `timeout == 0` and `unviable <= caught`, counted from the file and not the exit code (per test-plan §10 Mutation gate; per test-plan §11 Quality).
- `viola-e2e`'s unmutated baseline passes under `NEXTEST_PROFILE=mutants` on the dev host, so `run --mutants --package viola-e2e` no longer ends `mutants-exit-4`, with the moved kill's planted-hang reading in `evidence/`; and the operator pass's `pre-push` reads `ok:true` at stage `linux-tests` (`run --coverage`, `run --browser`, `gate --require coverage,doctest,playwright`) with the per-OS floors held (per test-plan §3 `run` step 4; per test-plan §3 `pre-push`; per test-plan §10 Coverage thresholds).
