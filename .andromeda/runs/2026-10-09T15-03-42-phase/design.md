# design extract

## Relevance
partial — only scope §6 touches the design domain (a new refusal detail joins the printed phraseology of the cli surface and the web tape; the CR / CRLF strip changes which `viola send` outcome line a text ends on), with one thin tie through scope §2 (`sgr_attributes` in `tests/cli_output_plain.rs`); scope §1, §3, §4, §5, §7 and §8 render nothing and take no token.

## Constraints
- design-system §Color Palette → Domain status colors requires one row per variant of every enum that gets a visual, and it lists the `RefusalDetail::*` variants one by one. The new refusal detail of scope §6 therefore owes a row there (surface, border, ink and the printed `<reason> · <detail>` phrase, in ink / rule / strike and a word, no hue). Phase amends no master: the row is an amendment the plan names for this chunk's wrap, worded with the name P4 shows.
- design-system §Brand Identity (anchor "Standard phraseology and unable plus a reason") requires every refusal word to be a short fixed word of the existing vocabulary. The new detail's name follows the form of the listed details (lower-case, hyphenated, no filler), and it is one string on every surface that prints it.
- design-system §Surface: cli → Component Patterns 2 (`viola send`) requires a refusal to print the `[/ ]` mirror, `unable`, then reason and detail as two-space-separated fields, followed by exactly one `hint:` line keyed by the reason or by reason · detail where listed. The newline-only refusal needs its own listed hint (a fixed sentence); that list is closed in the plan, so the hint text is part of the contract change shown at P4.
- design-system §Surface: cli → Streams requires refusals and their `hint:` lines on stderr, results on stdout, and under `--json` one JSON document on stdout with the typed exit code and no hint line. The refusal "at once" of scope §6 takes the same streams whether the client or the wrapper decides it; where it is decided is research's question.
- design-system §Surface: cli → Exit-code phraseology enumerates the details each typed exit prints. Whichever reason the new detail rides, that exit's row owes the new word (the same wrap amendment as the status row); the code it rides is not the design plan's to choose.
- design-system §Surface: web-spa → Tokens (the `--tape-cols` derivation) sizes the tape's word / reason track on the longest typed refusal phrase. A new `unable · <reason> · <detail>` phrase longer than that track changes the stated premise: either the name fits the track, or the plan records the derivation as owed an amendment (the ellipsis-plus-expanded-body rule of that same block is the fallback, not a licence to ignore the budget).
- design-system §Surface: cli → Tokens (Colour decision order) requires the ASCII readback mirror to print in every human output and no SGR on a refusal line at any depth. The new refusal line and a CR / CRLF-ended send's outcome line are plain words; no colour is added for either.

## Patterns to follow
- The existing `not-delivered · <detail>` family is the model: a status row (design-system §Color Palette → Domain status colors), a hint keyed by reason · detail (design-system §Surface: cli → Component Patterns 2), a word in the exit row (design-system §Surface: cli → Exit-code phraseology). The new detail is added in all three places with the same shape, not as a special case. Whether the code prints refusals from one table that all three read is research's question.
- A send that is confirmed prints the read-back line and one that is not prints `unable` plus the typed reason (design-system §Brand Identity, anchor "Readback"; design-system §Surface: cli → Component Patterns 2). After the strip of scope §6, a text ending in CR or CRLF is expected to end on the read-back line; the plan pins that outcome by the measured match, never by a presumed one. Whether the code already reads the stripped text at the match site is research's question.
- A refused send on the web is folded into its send line as strike plus reason, never a line of its own (design-system §Color Palette → Domain status colors, the `EventKind::send-refused` and `Readback::refused` rows; design-system §Surface: web-spa → Component Patterns 2). Whether a refusal decided before any frame is written emits a `send-refused` record at all is research's question; the design plan draws only what the tape carries.
- `sgr_attributes` (`tests/cli_output_plain.rs`, scope §2) sits on the cli surface's styling contract (design-system §Surface: cli → Tokens). If P4 splits it, the split keeps every assertion on the SGR spans and on the no-colour modes as it stands. What that function asserts today is research's question.

## Anti-patterns to avoid
- A hint or refusal line that quotes the sent text, or any upstream text, a path or a pid (design-system §Surface: cli → Component Patterns 2; design-system §Anti-Patterns → Per-Surface Bans, cli). A newline-only text is still content: the hint names the cause in fixed words and prints no escaped rendering of what was sent.
- Colour, a glyph, or a `✓` / `✗`-style prefix on the new refusal or on the read-back of a stripped send (design-system §Anti-Patterns → Per-Surface Bans, cli). The mirror and the words are the only prefixes; amber and dim stay on `DIALOG` and `stale`.
- A hint that names `viola release` or guesses at an opaque detail (design-system §Surface: cli → Component Patterns 2). The new hint tells the driver what the text was refused for and nothing about the wheel.

## Contract bindings
- design ↔ architecture / security: the refusal detail is a member of the closed list the wire and the validators own (architecture.md §Conventions; security-plan §Input Validation). The design plan prints that name verbatim (design-system §Color Palette → Domain status colors), so the name ratified at P4 is the name in the status row, the hint key and the exit row; a design amendment worded before the name is ruled would drift.
- design ↔ a11y: readback refusals are among the few things the page's polite status region announces, spoken as reason and detail (design-system §Surface: web-spa → Navigation Pattern, "Attention outside the tab"; a11y-plan D-A11Y-06). A new detail word enters that announcement set, and a refusal stays carried by word plus strike, not colour (SC 1.4.1 through design-system §Color Palette → Semantic Colors).
- design ↔ tests: the cli tier's human-output tests pin the refusal line, its hint and its streams (design-system §Surface: cli → Streams), and `tests/cli_output_plain.rs` pins the no-colour modes (design-system §Surface: cli → Tokens). The tier that owns the new refusal's printed form is the test plan's to name.
- design ↔ obs: the machine view carries a refusal's cause as a code, never as hint prose (design-system §Surface: cli → Component Patterns 2). The new detail's code in events and logs is the obs plan's catalog entry, the same string as the printed word.

## Acceptance criteria contributions
- A newline-only `viola send` in human mode prints, on stderr only, the `[/ ]` mirror with `unable`, the reason and the new detail as two-space-separated fields, then exactly one `hint:` line; stdout is empty; under `--json` the refusal is one JSON document on stdout and no hint is printed (per design-system §Surface: cli → Component Patterns 2; design-system §Surface: cli → Streams).
- The new refusal line and its hint are ASCII, carry no SGR sequence in any colour mode, and contain no byte of the sent text, no path and no pid (per design-system §Surface: cli → Tokens; design-system §Anti-Patterns → Per-Surface Bans, cli).
- The new detail's name is a short fixed lower-case hyphenated word, and its `unable · <reason> · <detail>` phrase is checked against the tape's word / reason track; a phrase over the track is recorded as an owed `--tape-cols` amendment, not shipped silently (per design-system §Brand Identity; design-system §Surface: web-spa → Tokens).
- The chunk's wrap record names the design-system amendment the new detail owes: its `RefusalDetail` status row, its hint in the `viola send` list and its word in the exit row, all three with the P4-ratified name (per design-system §Color Palette → Domain status colors; design-system §Surface: cli → Exit-code phraseology).
