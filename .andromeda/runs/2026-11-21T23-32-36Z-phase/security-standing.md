# security · standing conventions

- S1 · each new test runs under its own test-created home, never the user's · secret-management
  decision/test-homes-gitignored · Test homes kept out of git — Local --home test directories are git-ignored so recorded state never lands in git.
- S2 · each new fake-agent behaviour or delay seam lives only under the fake-agent feature and is compiled out of release · security-anti-patterns
  decision/fake-agent-hook-panic-seam · Hook panic test seam — FAKE_AGENT_HOOK_PANIC exists only in test-feature builds and forces a fixed-payload hook panic only when exactly 1; the hook still fails open; it configures nothing, disables no control and widens no redaction. · why: Ratified.
- S3 · each new live-rig arm keeps closed words and counts only, no CLI output, screen text or transcript byte · data-protection
  decision/live-rig-context-arm-keeps-no-transcript · Live rig's context arm keeps no transcript byte — The live rig's CX arm reads the session transcript through MAX_FRAME, counting only tags past the kept length and keeping no byte of it, and sends only through viola send under the rig's private config.
  decision/live-rig-mb-arm-keeps-no-output · Live rig's MB arm keeps only closed words of the client — The live rig's MB arm runs a print-mode claude -p as the MCP client of viola mcp over the fake agent, in its scratch home and private config, one tool allowed (wait), no key, no dialog; it reads the client's output in memory and keeps only two booleans, one number and one closed word. · why: The shape the operator ratified; a long call counts only with timed-out true beside call-error false, so a result with no is_error key cannot turn a cut call green. · except: The rig reads the credentials file once per start, and the prompt and the tool result go to the model provider; nothing reaches a fixture, stamp or log, or the real ~/.claude* or ~/.viola. · provisional
  decision/live-rig-mcp-arm-keeps-no-output · Live rig's MCP arm keeps no CLI output — The live rig's MCP recording arm keeps no CLI output, stdout drained and dropped and stderr kept only as a byte count and a SHA, and its MCP config is a private 0600 file inside the scratch, removed with it.
  decision/live-rig-prompt-capture-closed · Live rig's prompt capture keeps closed words only — The rig's hook capture reads a payload under MAX_FRAME, default JSON depth, and writes one owner-only line: key names matching [a-z_]{1,40}, others counted; a UserPromptSubmit source word or a StopFailure error word of the CLI's 13 else other, two text lengths, never a text; a bad payload: unread · why: A ratified boundary widening.
- S4 · each new recorded fixture is scrubbed, kept to signature rows, and reviewed before commit · data-protection
  decision/env-fixture-names-only · Recorded env fixture holds names only — The recorded env fixture holds only its version and the CLAUDE names the CLI adds to a hook, never a value; it passes the record scrub and the env-name check, an env name carrying the user word refusing the recording as username with nothing recorded, and the hygiene walk checks it as its own class. · guard: env_fixtures_pass_hygiene; record_refuses_an_env_name_carrying_the_user_word
  decision/fixture-hygiene · Recorded fixture hygiene — Recorded claude fixtures are never committed from sessions with real prompts, nor before being checked for home paths and usernames.
  decision/fixture-recording-scrubbed · Fixture recordings scrubbed — verify --record scrubs the home prefix and user word before any write and refuses the whole recording when a home, drive-letter or user-folder path, the user word or an email-shaped token survives, naming file and closed code, never content.
  decision/fixture-scrub-and-refusal · Recorded fixtures scrubbed or refused whole — Before any write, verify --record scrubs the home prefix to ~ and the user word to <user>, and refuses the whole recording with exit 1 and nothing written when a home, drive-letter or user-folder path, the user word or an email-shaped token survives.
  decision/fixtures-reviewed-before-commit · Fixtures reviewed before commit — Recorded fixture payloads are reviewed for home paths, usernames and tool input before committing.
  decision/mcp-fixtures-via-test-only-tap · MCP fixtures recorded through a test-only tap — MCP exchange fixtures are recorded by a test-only tap, started live by the standing rig under its private CLI config, that spawns viola mcp directly with no shell, caps each line, keeps its raw capture 0600 in a private directory never committed, and applies the same scrub and closed refusal codes. · guard: schemas/claude-mcp-fixture.v1.json
  decision/screen-fixture-signature-rows-only · Screen fixtures keep only signature rows — A screen fixture keeps only signature rows (a row holding a compiled footer or modal literal whole, a box rule row as its rule chars alone, a prompt row as the prompt char alone), the rest blanked; another box row, a kept row the scrub would rewrite or a username split across a row seam is refused. · except: On a failed recording verify, a hidden rig-only option writes one first-screen file of whole scrubbed rows per run short of the input box, kept local and git-ignored; an unclean set is refused whole.
  decision/viola-format-fixtures-hygiene · viola-format fixtures under the hygiene walk — Committed viola-format fixtures, the old state shapes and retired words, are held to the same fixture hygiene walk as recorded fixtures: no path, user or email. · guard: viola_format_fixtures_pass_hygiene
- S5 · each new seam or environment read gets its log entry · security-anti-patterns-never-do-these
