@task_prose part=chunk
Adds the CLI verb `viola open`. It takes a closed allowlist of flags. It starts a `foot` terminal directly, with no shell, and the terminal runs the pinned viola `run <name>`. It places the new window on the parent's workspace through the Hyprland seam's one closed move dispatch, waits a bounded time for the instance to be live and for the window to appear, and answers with a closed set of exits and one --json document.
Adds the window record. The wrapper finds its own window by its terminal ancestor's pid through the seam and logs a new log-only event kind `window`, codes-only. The snapshot gains `window?`, replayed with the last line winning, and `list --json` gains `window?` and `origin?`. Open hands the origin (cli or agent) to run through one hidden checked flag.
Adds tests for the hypr tap recorder's three untested record-move failure codes over planted stubs, a stand-in `foot` and a compositor `clients` reply in the fake agent, and the seam's 5 s read deadline as a time-bound row of its own.
Re-measures at HEAD the seam counts the earlier split cited, and re-reads that split's reached rows. The one live reading (R2: one open beside a live parent) is a stop that this build does not run.

@task_item n=1 part=needs
The open argument allowlist. The flags are <name>, --parent, --role overseer|builder|worker (a closed enum), --cwd, --workspace N, --model/--effort, --json and --home. After -- only the word claude is allowed, with no claude flag. Any flag or word outside the list is refused before anything starts: exit 2 with clap's usage error, plus one fixed line for a word after -- other than claude, beside PAIR_AFTER_DASHES.
@task_item n=2 part=needs
The terminal spawn. foot is found on PATH and spawned directly with a fixed argv: app-id viola.<name>, title, working directory, then the pinned viola --home <home> run <name>. No shell line is built from the arguments, whatever characters they hold. This is a CLI and env vector negative case for argument bytes such as shell metacharacters, control characters and a leading slash.
@task_item n=3 part=needs
The open exit causes and their order. Exit 1 terminal-not-found. Exit 1 not-live, with the window left standing. already-live and stale-heartbeat are read from the heartbeat before any spawn. Exit 1 strict-modes-failed comes before any log is opened or read. Open has no exit 11.
@task_item n=4 part=needs
The open --json document: one document per run, {"v":1,"ok":{"name","parent","window","placement"}} on success and {"v":1,"error":"<code>","detail":null} on failure. The human lines and the --help grouped verb table's setup line `setup:  open, run, revive, verify, plugin install` are pinned by literals, with no SGR without a terminal.
@task_item n=5 part=needs
Window placement. Open reads clients until a window's pid is the terminal's pid, then issues the one closed move dispatch to the parent's workspace (or --workspace N), with no focus change. No parent window means no move, recorded as unplaced. Off Hyprland (the seam's unsupported or unreachable, with no environment read) the terminal still starts, placement is skipped and the record says why. On a locked desktop the open proceeds.
@task_item n=6 part=needs
Open's time bounds, each a row of its own beside the full time-bound lists. Liveness waits at most 30 s on the live endpoint, else exit not-live. Window appearance gets 5 s, polling clients every 100 ms, then unplaced. HYPRCTL_DEADLINE is the 5 s compositor read bound. Tests drive these bounds through injected clocks and bounded readers, never through real sleeps or test-owned real time.
@task_item n=7 part=needs
Open's liveness reading uses instance liveness (live, stale, gone) and the heartbeat staleness classification to decide when the started instance counts as live.
@task_item n=8 part=needs
The parent defaults to the caller's VIOLA_NAME when an agent calls open from its own shell. Test-started viola drops inherited env, so a test sets VIOLA_NAME on the child it spawns and never mutates the process-wide env.
@task_item n=9 part=needs
The window record is written by the wrapper alone, never by open: single writers of snapshot and start lines. The wrapper finds its window by its terminal ancestor's pid through the seam. Its origin (cli or agent) arrives on the run argv through one hidden checked flag, refused when malformed.
@task_item n=10 part=needs
The new log-only event kind window {address?, workspace?, placement, origin}, logged codes-only. It needs event-line keys and data keys, a round-trip through the event line, and forward-compatible reading: a reader without the kind counts and skips it.
@task_item n=11 part=needs
Snapshot window? is recovered by the replay with the last window line winning. This changes the snapshot replay's fixed field set, and every product snapshot reader goes through read-or-replay.
@task_item n=12 part=needs
list --json gains window? and origin? on its items. The six-column human board stays unchanged and is held to the read rule.
@task_item n=13 part=needs
