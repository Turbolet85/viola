# arch extract

## Relevance
partial — no new product surface (no subcommand, channel verb, route, contract or crate); arch governs where the cleanup's tests, lint and fixes live, the test-only resources they touch (`target/e2e-home`, `target/conpty-seed`, mutation scratch, temp-dir reports), the env-var floor, and the process-lifetime decisions P5 measures against.

## Constraints
- Workspace placement: each M1 killing test lives in the crate that owns the survivor (`viola-pty` for `sideload::search_restricted`, `PortablePty::resize`, `HostTerminal` Drop; `viola-state` for `fs::restrict` and the `pin_exe`/`pin_companions` NotFound guards; the root bin for `run::refuse_stale`), per architecture.md §Established Decisions [Module Boundaries] and §Occupied Resources (Workspace crates); a test-support need goes behind a test-only feature enabled only from a `[dev-dependencies]` entry, as `viola-channel` `test-support` does (§Occupied Resources, Workspace crates), never into a product build (release-check, §Infrastructure Patterns → CI/CD approach, target job 6).
- Env-var floor: any M2 fix (e.g. isolating inherited `CLAUDE*`/`VIOLA_*`/`ANTHROPIC*` from test children) and the P2 lint add no env var that `viola` reads; the only non-`VIOLA_*` reads are the two `fake-agent` test seams, and harness-only vars are the four listed (`AGENT_RUN_CHUNK_BASE`, `AGENT_RUN_KEEP_HOMES`, `AGENT_RUN_KEEP_FAILED`, `CI`), per architecture.md §Cross-cutting Patterns (Config management) and §Occupied Resources (Environment variables). A new seam or harness var is an Occupied Resources amendment at wrap (and a Decisions Log entry if `viola` reads it). Home resolution order (`--home`, then grandparent of `VIOLA_DIR`, then default) is fixed by §Cross-cutting Patterns (Config management); whether the in-repo red hinges on it is research's question.
- Test-home lifecycle: `target/e2e-home/viola-test-*` dirs are removed only when their `owner.json` owner process is gone — never by age or name, never a dir without a record — and kept under `AGENT_RUN_KEEP_*`; `target/conpty-seed/<key>/` is the one per-run seed, regenerated on demand; both per architecture.md §Occupied Resources (Repository). The tempdir-leak fix (§3) and any M2 cleanup keep this rule; the operator's hold on `target/baseline-target`, `target/e2e-home`, `target/conpty-seed` until M2's diff is recorded comes first (scope §1).
- Mutation runs go through `run --mutants`: on Windows the copies and `mutants.out/` live in `<repo parent>/viola-mutants-scratch/` (guarded, wiped before every counted or scoped run, path never printed), `CARGO_TARGET_DIR=target/mutants` with `--copy-target=true`, and `AGENT_RUN_KEEP_HOMES=0`/`AGENT_RUN_KEEP_FAILED=0`, per architecture.md §Occupied Resources (Repository: `target/mutants/`, host mutation scratch) and §Infrastructure Patterns → CI/CD approach. Where the 545 `.tmp*` dirs land relative to this scratch (whose `TMP`/`TEMP` it sets) is research's question.
- Test-only temp-dir artifacts are registered resources: `<temp dir>/viola-pty-watch/…` and `<temp dir>/viola-root-watch/…` are kept on panic/kill and removed on pass (architecture.md §Occupied Resources, Filesystem); a leak fix keeps that keep-on-failure contract, and any new test-only path the chunk lands is recorded there at wrap.
- P5 measures against architecture.md §Established Decisions [PTY] (child exit on the process handle; `TerminateProcess` kill fallback; the pump keeps the ConPTY input writer until child exit, since dropping it sends `CTRL_CLOSE`; sideloaded `OpenConsole.exe` host on Windows x64) and [Session Liveness] (pid + start time decide `gone`; `claude agents --json` only enriches). Whether a killed wrapper's child survives is research's (P5's) measurement, not a plan fact; a job-object fix would be a new windows-sys feature behind the `pty` seam and is routed at wrap, not built here (scope §7).
- Coverage re-take uses the project command `run --coverage` (cargo-llvm-cov 0.9.1 nextest, per-OS floors 85/95/80) per architecture.md §Stack and Technologies (Code quality) and §Infrastructure Patterns → CI/CD approach; CI on the pushed sha stays the verdict of record, the local run a filter.

## Patterns to follow
- Contract tests at the root (`tests/contract_lints.rs`, `tests/contract_diag_schema.rs`, `tests/contract_fixture_hygiene.rs`) assert workspace-wide invariants — a fitting home for the P2 deadline-below-kill-line check (architecture.md §Infrastructure Patterns → Build system; §Occupied Resources, Repository).
- A gate proves it fires: `scripts/lint-probes.sh` / `deny-probes.sh` / `orphans-check.sh --probe` each pair the gate with a planted violation and a clean control, so the P2 lint cannot pass vacuously (architecture.md §Infrastructure Patterns → Build system).
- Locate crates and targets through `cargo metadata` (`orphans-check.sh` enumerates lib/bin targets from `cargo metadata --no-deps`), the shape evolve L4's rule line records (architecture.md §Infrastructure Patterns → Build system, Boundary review).
- Bounded root waits use `tests/support/watch.rs` `Watch` (`WITHIN` = 7 s, evidence file per wait) — the deadline constant P2's lint must see (architecture.md §Occupied Resources, Filesystem).
- Spawners outside `viola run` (harness `supervise::spawn_in_pty`, `tests/support/outer_pty.rs`, viola-pty's own tests) stay on the inbox ConPTY; seeded starts go through `seed_conpty` (architecture.md §Established Decisions [PTY]; §Occupied Resources, Repository `target/conpty-seed`).

## Anti-patterns to avoid
- A new env var, test seam or `RUST_LOG`-style knob to make the in-repo suite pass, or any env read that configures or disables a control (architecture.md §Cross-cutting Patterns, Config management).
- Cleaning test homes or temp dirs by age, name or glob instead of the recorded-owner rule, or sending mutation copies to `%TEMP%`/the repo instead of the guarded scratch (architecture.md §Occupied Resources, Repository).
- Tokio in a sync crate's normal graph via a new test helper, or a product dependency on `viola-e2e` (architecture.md §Established Decisions [Concurrency / Backend Framework], [Module Boundaries]).

## Acceptance criteria contributions
- Each M1 killing test sits in the survivor's own crate and adds no product dependency, feature or `[workspace.dependencies]` pin reachable from a release build (per architecture.md §Established Decisions [Module Boundaries]; §Infrastructure Patterns → CI/CD approach, target job 6).
- `rg` over the diff shows no new `std::env::var` read in product source and no new name beyond §Occupied Resources' Environment variables list; any new test-only path or harness var is added to §Occupied Resources at wrap (per architecture.md §Occupied Resources, Environment variables / Filesystem).
- After one suite run, no `.tmp*` dir and no ownerless `target/e2e-home/viola-test-*` dir remains, and failing-test evidence (`viola-*-watch` reports, `AGENT_RUN_KEEP_FAILED=1` homes) is still kept (per architecture.md §Occupied Resources, Repository / Filesystem).
- The P2 check fails on a planted deadline at or above the nextest kill line and passes a control (per architecture.md §Infrastructure Patterns → Build system, probe pattern).
