The tempdir-leak, M2-diagnosis, P5 and WSL-CARRY items each touch a plan boundary. P6 and L4 are out of domain. `refuse_stale` and a kill-on-close job object have no anchor in security-plan.md.

## Constraints
- **sideload `search_restricted` (×2).** Security-plan §Input Validation ("DLL search order + sideloaded ConPTY companions" row) and §Security Anti-Patterns → Universal require two things. First, `restrict_dll_search()` runs as the second statement of `main` in every role. Second, a sideload failure degrades silently: no refusal, no exit change, no terminal byte. A killing test may observe the restricted state or the closed `run.conpty_sideload{outcome,search_restricted}` / `process-start.sideload_fallback` codes. It must not move the call, add a fallback path, or put a path or hash into any record. Whether `search_restricted` has any caller whose behaviour depends on its value (equivalence) is research's question.
- **viola-state `fs.rs` `restrict` → `Ok(())`.** §Authentication & Authorization (`~/.viola/` access control row) and §Data Protection (At rest, Files) require explicit 0700 dirs and 0600 files, with the mode set before any byte is written. If the mode cannot be set, the write is discarded. §Security Anti-Patterns → Data Protection bans the umask default. An equivalent-mutant exemption cannot rest on "no test observes the mode", because the mode is the mandated effect. What `restrict` does on Windows (a no-op, a DACL, or `cfg`-split) decides whether the mutant is observable on this host, and that is research's question.
- **pin NotFound match guards (`pin_exe`, `pin_companions`).**
  - §Data Protection (At rest, code-bearing artefacts) requires a SHA-256 re-hash of `bin/<version>-<hash>/viola(.exe)` before reuse, with exit 1 on a mismatch.
  - The same section requires companions to be written write-if-absent and never overwritten or deleted on a failed re-hash. They are left as found, and the child runs on the inbox ConPTY.
  - §Security Anti-Patterns → Data Protection restates both.
  - A killing test must keep these semantics. Whether a guard flipped to `true` turns a non-NotFound error into a write-over (that is, whether the mutant is security-observable) is research's question.
- **Test seams.** §Security Anti-Patterns → Universal (last bullet) allows exactly two non-`VIOLA_*` env reads, `FAKE_AGENT_PUMP_DELAY_MS` and `FAKE_AGENT_HOOK_PANIC`, both under `cfg(feature = "fake-agent")`. Any new seam a killing test or the M2 fix needs requires its own Decisions Log entry, and no `config.json` key, `VIOLA_*` var or CLI flag may switch off a control.
- **Release build and G2.** §Dependency Security (CI integration) keeps the release build free of test-only features (`test-support`, `fake-agent`) under `scripts/release-check.sh`. G2's single exemption (`src/cmd/hook/seam.rs:<digits>`) admits no addition without a Decisions Log entry.
- **M2 env probe and evidence.** §Secret Management (Storage, R8) and §Bootstrap phases (`logging-redaction-wire`) require inherited `CLAUDE*` values to be handled by name only. They never reach a log, diagnostic, snapshot or fixture. The same floor bars the GUI token, `?t=` and `Cookie`. Committed evidence under `chunks/2026-10-02-epoch-2b-cleanup/evidence/` is held to the same floor. §Bootstrap phases (`logging-redaction-wire`, operational metadata) bars absolute paths from external error output.
- **P5 fix routing.** A child that survives its wrapper is a "human always wins" breach (§Security Anti-Patterns → Universal: never let a refusal or automation path block the human). §Data Protection (In transit, Handle inheritance) requires portable-pty's `bInheritHandles = 0` and non-inheritable channel handles. Any fix the wrap routes, such as a kill-on-close job object, must keep both properties. The plan has no job-object row, so adding one is an amendment, not a fold-in.

## Patterns to follow
- **Mode-before-write helper.** `viola_state::fs::replace_private` sets the temp file's mode explicitly, then calls `sync_all` and `persist` (§Authentication & Authorization, `~/.viola/` access control). A `restrict` test reads the resulting mode or DACL back rather than trusting the call.
- **Closed outcome codes.** The sideload path records only closed codes, never a path or hash (§Input Validation, DLL search row). Tests assert on those codes.
- **Probe pattern.** Every gate script carries a `--probe` that proves it fires on minted bad inputs and passes a clean control: `release-check.sh --probe` 5/5, G2 `--probe`, `deny-probes.sh` (§Dependency Security, CI integration). The P2 deadline-below-kill-line lint should carry the same probe so it cannot pass vacuously.
- **Own `--home` per test.** Each test uses its own `--home` and its own GUI token (§Secret Management, Development). A leaked tempdir may therefore hold content-bearing `events.ndjson`, `diagnostics/` and `ui/<port>.url` files, which is why the fix is cleanup on every exit path, as with the drop-guarded `ledger/probes/<pid>/` in §Data Protection (Probe captures).

## Anti-patterns to avoid
- Never let `run --mutants`, or any cleanup the tempdir fix adds, wipe a directory other than `<repo parent>/viola-mutants-scratch`. Never fall back to `%TEMP%` or the repository, and never print the path (§Security Anti-Patterns → Code Patterns).
- Never commit local `--home` test directories, `.env*` files or evidence holding a credential value (§Security Anti-Patterns → Secrets).
- Never widen the WSL `env -i` boundary: every WSL call carries exactly `HOME` and `PATH`. Never run `wsl-provision.sh --install-deps` from a gate or harness. Re-provisioning first requires the root-runs-only-`apt-get` hardening (§Secret Management, Development). This chunk leaves `wsl-provision.sh` and ci.yml's `test`-job tool line byte-unchanged.
