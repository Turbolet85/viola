## Relevant amendment history
- **2026-09-24-quality-gates** — Changed where the CLI output-discipline tests report. They still run on all three OS legs. Locally they report under `nextest-integration` / `nextest-e2e`. In CI they report inside the per-OS `test` job's single instrumented `coverage` suite, and the `suites[]` enum gained `coverage`. Failures surface only as nextest failures in `suites[].failures[]`. Why it matters: this is the binding behind the extract's "No new suite" constraint. M2's red binaries and the re-taken coverage both feed this same `coverage` suite entry. So M2's green read is also the output-discipline stand-in's read. P2's lint, if it is a test, rides an existing suite rather than adding an enum value.
- **2026-09-25-pty-wrapper-on-windows** — Made the Windows zero-viola-bytes oracle literal absence of viola's own bytes. Byte-for-byte comparison against an unwrapped run holds on Linux and macOS only, because ConPTY emits its own preamble (`ESC[?9001h ESC[?1004h ESC[?25l ESC[2J ESC[m ESC[H`, an OSC 0 title, `ESC[?25h`) and re-renders nested output. It also carried "ConPTY swallows focus reports" as an unmeasured HYPOTHESIS. Why it matters: when M2 diffs the in-repo run against the copied tree (`target/conpty-seed` is a suspect), it must classify host-emitted bytes against this oracle, not treat them as viola output. Any M1 resize or drop-time-restore killing test that observes the outer byte stream is graded by literal absence on Windows, not byte equality. The focus-report claim is still a hypothesis, not a fact a test may rest on.
- **2026-09-29-sideloaded-conpty** — Extended the Windows zero-viola-bytes check to both ConPTY hosts. It now names the sideloaded `OpenConsole.exe` preamble (`ESC[1t ESC[c ESC[?1004h ESC[?9001h` at spawn, `ESC[?1004l ESC[?9001l` at exit), measured in that chunk's `evidence/da1-stall.md`. Its DA1 query is answered by the terminal (the piped driver in tests), never by viola. The check runs on both backends: the default case on the sideload, and `conpty_sideload`'s tampered case on the inbox fallback. Why it matters: this is the source of the extract's "zero-bytes case covers both sideload and inbox backends" acceptance criterion. M1's `sideload::search_restricted` survivors (→ `true` / `false`) sit on the seam that picks the backend, so a killing test or exemption must leave both backend cases passing. The DA1 answer path is a readiness dependency M2 should check against its "wrapped program never started" and readiness-timeout panics.
- **2026-09-28-mutation-testing-to-the-epoch-boundary** — Re-pointed §10's P4/P6 output-discipline invariants. Where they live in crate tests, they are now covered by the epoch-boundary mutation audit (`run --mutants`, test-plan §10), not by a per-chunk or CI mutation gate (founder ruling 2026-09-28). Why it matters: M1's eight survivors come from that boundary audit. The chunk's scoped mutation run over the touched units is the evidence path for any boundary or output-discipline assertion there (`missed == 0`). This amendment is why an M1 exemption or killing test bears on the a11y stand-in, in particular the clause-3 "resize does not move the wheel" case under `PortablePty::resize`.
- **2026-09-27-browser-verdict-reachability** — Made the `test` job's gate `gate --require coverage,doctest,playwright` (was `coverage,doctest` / `playwright`). It also put `run --browser` on all three CI legs with the a11y verdict judged on ubuntu only, and banned judging that verdict on Windows or macOS. Why it matters: the extract's acceptance criterion says the gate stays exactly `coverage,doctest,playwright`, and this amendment set that value. No M2 fix or P2 lint may alter the gate's `--require` set or add a suite. A Windows-host green read of the tui boundary cases is stand-in evidence, not an a11y verdict.
- **2026-09-29-t15-07-57-wrap** — Moved the a11y Decisions Log to the archive (registry migration U35) and lifted its in-force items into §3 key files. One lift: the portable-pty `=0.8.1` pin is an inherited risk (0.9.0 is the maintained line) that a11y never re-pins (D-A11Y-13). Why it matters: M1's `PortablePty::resize` and `HostTerminal::drop` survivors live in `viola-pty` over that pin. A killing test or a fix routed from P5 (for example a kill-on-close job object) works within portable-pty `=0.8.1` and must not move the pin as a side effect.
