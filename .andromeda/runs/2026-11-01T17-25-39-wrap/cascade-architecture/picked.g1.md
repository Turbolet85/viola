Each dialog event carries a wrapper-assigned `dialog_id` (an integer, monotonic per instance, with the counter restored from `events.ndjson` on start so an id never repeats across wrapper restarts), and `answer` names its target by that id. At most one dialog is pending per instance. A `hook.dialog` that arrives while another is pending is answered `null` at once, so that dialog renders for the human. Every `send` `ok` payload and every `wait` event result carries `cursor`, the offset to pass as the next `after`. Without `after`, `wait` returns the next such event appended after the call. With no `timeout_ms` it blocks until an event arrives, and if the endpoint vanishes first the caller gets `instance-unreachable`, its `detail` `endpoint-lost`. Accepted risk: interprocess has one main maintainer, which the seam contains.
