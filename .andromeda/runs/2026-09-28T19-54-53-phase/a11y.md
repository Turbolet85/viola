Research should check whether any of these steps carries a `needs:`, ordering or `if:` edge that points at the `mutants` / `mutants-verdict` jobs.

Retiring the `mutants` requirement and `--mutants-legs` from `harness/gate.rs` must not change how the `--require` list is parsed or how the `playwright` suite verdict is judged. Per a11y-plan §9 CI Integration (Unit/integration and E2E rows) and §3 CI integration (Command: `gate --require …playwright`, skips never allowed). Whether the union judge shares code paths with the `playwright` judgement is research's question.
- The browser suite runs on all three `test` legs, and the a11y verdict is judged on the ubuntu leg only. The workflow edit must not move, drop or re-scope that leg split or the `browser-missing`-is-failure rule. Per a11y-plan §9 CI Integration (Pipeline integration) and §3 CI integration.
- a11y stays inside the 5-command harness. Reworking `harness/gate.rs` or the pre-push stages must not add a `suite` value, a `webServer` or a separate a11y driver. Per a11y-plan §9 CI Integration (Pipeline integration: "no new `suite` enum value") and §11 A11y Anti-Patterns → CI.

- NEVER judge the a11y verdict on the Windows or macOS legs, and never treat `browser-missing` as a skip. Per a11y-plan §11 A11y Anti-Patterns → CI.
