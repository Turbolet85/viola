# a11y extract

## Relevance
partial: the chunk is input bounding at machine boundaries (hook and MCP stdin, channel frames, home files, child output), which per a11y-plan §1 A11y Scope Summary are mostly not-assertable surfaces. It reaches a11y at three points only: the terminal-parser panic degrade (the tui passthrough boundary), the human-mode CLI refusals that the paste rule and any new cap or closed-type check print (`not-delivered` / `control-character` / `empty-text`), and the C0/C1 escaping of bounded external content that the CLI prints.

## Constraints
- a11y-plan §1 A11y Scope Summary (tui entity, `.andromeda/a11y-plan-detail/a11y-scope-summary.md` scope-entities) requires that under `viola run` and a passed `viola revive`, viola writes zero bytes to the terminal except the child's output, and that human keystrokes are never blocked, refused or delayed past the current atomic paste. A vt100 screen-model panic caught by `catch_unwind` must degrade only the readiness verdict (to `input-not-ready`) and must not stop, delay or add to the passthrough. Whether the existing `catch_unwind` sites in `src/run/gate.rs` and `crates/viola-agent-claude/src/screen.rs` already keep the pump and the human-input path running after a panic is research's question.
- a11y-plan §1 A11y Scope Summary (tui surface Notes, scope-surfaces) requires that viola's diagnostics for `run` go to `diagnostics/`, never to the terminal. Any record of a caught parser panic, a cap hit or a rejected oversize read during `run` therefore lands only in the diagnostics or obs lines, never on the outer PTY.
- a11y-plan §8 Cognitive Accessibility › Error recovery requires every human-mode CLI refusal to print `unable  <reason>  <detail>` on stderr, then `hint:` as the last stderr line, with a typed exit code. Under `--json` it requires one document with no hint. This covers the paste-rule refusals of CLI `send` (`not-delivered` / `control-character`, `not-delivered` / `empty-text`, exit 13), whether the client or the wrapper raises them, and any new refusal a size cap or closed-type check adds to a CLI verb. Faults carry no hint.
- a11y-plan §8 Cognitive Accessibility › Plain language requires every fixed CLI string to be pinned by trycmd or by literal, and requires a kebab-case code never to appear without the plain word `unable`. A refusal text this chunk adds or touches must be pinned.
- a11y-plan §1 A11y Scope Summary (cli surface Notes, scope-surfaces) requires C0/C1 control characters in printed external content to be escaped, except `\n` and `\t` in `wait` / `last` text; `list` rows escape those too. Content read through a newly bounded reader (`claude agents --json` rows, event text) must still reach the CLI only through the existing escape (`escape_row` / `escape_message`). Bounding the read must not bypass that escape.
- a11y-plan §8 Cognitive Accessibility › Timeout extensions requires every bound viola holds, the 5 s `claude agents --json` read and the status-line deadline included, to fall on the driver, the user's own command or viola's own child, never on the human. An oversize, malformed or timed-out bounded read fails open (`list`'s board as read, `revive`'s preflight passed) and blocks, refuses or delays no key.
- a11y-plan §1 A11y Scope Summary (plugin entities, scope-entities) holds `viola hook` and `viola mcp` not-assertable because they write no human-facing byte. A stdin cap on `hook` that rejects input must keep that property: exit 0, empty stdout and stderr, no body.

## Patterns to follow
- The tui boundary cases per a11y-plan §3 Keyboard test harness (`.andromeda/registries/contracts/a11y-plan/keyboard-test-harness.md`): portable-pty outer-PTY nextest cases with `viola-fake-agent` as the child. They assert zero viola-originated bytes (byte for byte against an unwrapped run on Linux/macOS; on Windows, viola's own literals absent), and that a human key reaches the child unblocked, sequenced on log records and never on a timer. `passthrough_with_a_statusline_source_adds_no_viola_bytes` in `tests/tui_passthrough.rs` is the shape for a per-condition reading. A forced vt100 panic (via a test seam, which is security's question) can take the same shape.
- The refusal-layout pinning per a11y-plan §8 Cognitive Accessibility › Error recovery (Verification): trycmd / literal cases pin `unable … ` + final `hint:`, and assert_cmd checks the typed exit code and a hint-free `--json`, on all three OS legs.
- The C0/C1 escape witnesses per a11y-plan §4 ARIA Patterns & Roles (P6, `.andromeda/a11y-plan-detail/aria-patterns-roles.md` path-p6-board): `escape_row_shows_every_control_character_as_hex_text`, the `board_row_*` units and `tests/cross_list_rows.rs` in piped, `NO_COLOR` / `TERM=dumb` and outer-PTY modes.

## Anti-patterns to avoid
- a11y-plan §11 A11y Anti-Patterns › Keyboard: NEVER block, refuse or delay a human keystroke in `viola run` or a passed `viola revive` start past the current atomic paste. A cap, a closed-type rejection or a caught parser panic on the PTY path must not gate the human-input path.
- a11y-plan §11 A11y Anti-Patterns › Cognitive: NEVER render a stack trace as the only error text in the CLI, and never show a human-mode refusal without its `hint:` (except `unknown`). A caught panic or a rejected input must not surface its panic message or backtrace on stderr or the terminal.
- a11y-plan §11 A11y Anti-Patterns › Universal: NEVER parse the rendered `claude` TUI screen for content as evidence (R7). The panic-degrade witness reads the fake agent's stream and viola's log records, never `claude` content.

## Contract bindings
- a11y ↔ tests: per a11y-plan §3 CI integration, any outer-PTY or CLI output-discipline witness this chunk adds is an ordinary nextest case inside the existing suites (CI: the per-OS `test` job's `coverage` suite, `gate --require coverage,doctest`), with no new `suite` value (also a11y-plan §9 CI Integration).
- a11y ↔ obs: per a11y-plan §1 A11y Scope Summary (tui surface Notes), a caught parser panic or a rejected input during `run` is reported through obs and diagnostics lines only, never the terminal. The record's shape belongs to obs-plan.
- a11y ↔ design: per a11y-plan §8 Cognitive Accessibility › Plain language, the copy of any refusal this chunk adds comes from design-system §Surface: cli. a11y pins its layout only.

## Acceptance criteria contributions
- (a11y) Under the outer PTY with `viola-fake-agent` as the child, a forced vt100 screen-model panic leaves the outer-PTY stream free of viola-originated bytes (byte for byte against the unwrapped run on Linux/macOS, viola's literals absent on Windows), and a human key written after it still reaches the child, on all three OS legs (per a11y-plan §3 Keyboard test harness).
- (a11y) A human-mode CLI `send` of a text carrying a refused control character, and of an empty typed text, prints `unable` + `not-delivered` + `control-character` / `empty-text` with `hint:` as the last stderr line and exits 13. Under `--json` it prints one document with no hint and empty stderr. Both outputs are pinned by trycmd or literal (per a11y-plan §8 Cognitive Accessibility › Error recovery).
- (a11y) A `viola hook` invocation whose stdin exceeds `MAX_FRAME` exits 0 with empty stdout and stderr (per a11y-plan §1 A11y Scope Summary, plugin entities).
- (a11y) An oversize `claude agents --json` read under `viola list` leaves the board as `board::read` gave it, and any row printed still has every C0/C1 byte as `\xHH` text (per a11y-plan §4 ARIA Patterns & Roles, P6).
