## Relevance
relevant — two new capability-ledger rows move every literal row-set oracle, add `viola verify` probe arms and recorded fixtures, and change `send`'s local-command claim; all of it is test-plan surface (multi-version-compat, contract-test-against-sandbox).

## Constraints
- Every relied ledger row needs a `viola verify` probe with a post-condition, proven by a local run's exit code and its `stamped … pass … fail` line (per test-plan §1 Test Scope Summary, trigger multi-version-compat); test-plan §1 Test Scope Summary also routes Run B's framing variants and the status line variants through live `viola verify` alone, so a new `resume` / `compact` variant is recorded the same way, never hand-made.
- `contract_ledger_probes.rs` must list each relied literal row id exactly once with its post-condition result and end `stamped <ver>  <n> pass  0 fail`, `<n>` the relied count per OS, the row ids and the stamped / drift-only fixture-set lists written as test literals (per test-plan §5 Integration Test Strategy, CLI); test-plan §5 Integration Test Strategy, CLI also pins `tests/cli_verify.rs`'s `[NN/MM]` step lines, `STEPS_PASS` / `ROW_IDS` (`[&str; 21]` today) and the per-OS `cfg(unix)` / `cfg(windows)` literals plus the partial-replay counts (`17 pass  4 fail` / `17 pass  1 fail`, `19 pass  2 fail` / `16 pass  2 fail`) — each moves when a row is added, and where each new row is relied (every OS or Unix only) decides which literal moves.
- The harness's `--local-live` reading keys on the relied literal `LEDGER_ROWS` (`[&str; 21]` under `cfg(unix)`, 18 under `cfg(not(unix))`) and `boot` step 4 stamps every relied row; both literals are unit-proven per OS in `harness::run::tests` (per test-plan §3 `run`, and §3 `boot`).
- The fake agent builds exactly one payload not read from a recorded fixture: under `--resume <id>` the launch SessionStart is `SessionStart.default` rewritten (`source` → `resume`, `session_id` → the id; `--fork-session` → the compiled fork id), and its recorded replacement is owed to this route entry by name; without `--resume` every payload is recorded bytes (per test-plan §7 Test Data & Fixtures, Fake agent). Whether a recorded `resume` variant retires the rewrite, and how `--fork-session` is then served, is research's question.
- The local-command decision is unit-tier: an exact match of the typed text against the compiled list; a listed command with no measured post-condition or on an unverified CLI gives `unconfirmable`; `/clear` on a verified CLI is confirmed only by a `session-start` of cause `clear` with a NEW id, never by a `prompt-submitted` or another `session-start` (per test-plan §4 Unit Test Strategy, root bin); test-plan §6 Path 2 holds the cross-process `local` leg (`send_window_local_command_is_not_presumed_delivered`, `send_clear_on_a_verified_cli_is_confirmed_by_its_new_session` on the recorded `clear-1` variants). A `/compact` post-condition (cause `compact`, the SAME id) needs its own cases in both layers; whether the code's claim arm already admits a same-id session-start is research's question.
- The version gate is pinned by an older-stamp oracle ("a stamp holding exactly the fourteen older row ids, all `pass`, reads unverified") (per test-plan §4 Unit Test Strategy, viola-agent-claude); test-plan §4 Unit Test Strategy, viola-agent-claude also names the relied-set cases (`relied_rows_drop_the_three_statusline_rows_…`, `verified_reads_a_failed_statusline_row_by_the_relied_set`: 21 Unix / 18 Windows). Every such row-set reader moves with the new rows; which further shape-readers (`merge_stamp`'s envelope oracle, the dialog-less summary, the framing-variant list) the code holds is research's question, listed by the function the row set decides.
- Stamps come only from `viola verify` run against the fake agent (no test or harness code writes `ledger/stamps.json`), and recorded fixtures are synthetic probe text only, scrubbed and `unclean`-checked, a dirty payload refusing the whole recording (per test-plan §7 Test Data & Fixtures).

## Patterns to follow
- Three unit cases per ledger arm, each reading its Run B capture: a pass on the recorded shape, a fail on each broken post-condition, a fail with no matching capture — as the four framing arms (`check_framing_rows_pass_on_the_recorded_shape` …, `check_paste_newline_*`) and the nine `check_statusline_*` cases do (per test-plan §4 Unit Test Strategy, viola-agent-claude).
- A probed local command replayed by the fake agent under `--framing` from its recorded variants: the probed `/clear` fires the recorded `clear-1` SessionEnd then SessionStart and no UserPromptSubmit (per test-plan §7 Test Data & Fixtures, Fake agent) — the model for a `compact-<n>` replay; `contract_fake_agent_drift` then compares every framing variant byte for byte through the receipt's `stdin_hex` (per test-plan §2 Test Strategy, Contract row).
- New recorded variants join the run-time hygiene walk (`tests/contract_fixture_hygiene.rs`, its named per-set variant list) against `schemas/claude-fixture.v1.json`, with a planted case proving each violation class red (per test-plan §7 Test Data & Fixtures, Fixture hygiene).
- Per-OS literal oracles split by `cfg` (`cfg(unix)` / `cfg(windows)` in `tests/cli_verify.rs`, `cfg(not(unix))` in the harness so it stays outside the Windows mutation scope) (per test-plan §3 `run`).
- Revive's resume path is exercised under the fake agent's `--resume <id>` in `tests/cli_revive.rs` (per test-plan §6 E2E Test Strategy, exit-cause matrix) — a recorded `resume` payload feeds the same suite.

## Anti-patterns to avoid
- NEVER import the product's own ledger rows (`LedgerRow::ALL` / `relied()`) as the test oracle; row ids and counts are literals in the test (per test-plan §11 Test Anti-Patterns, Unit).
- NEVER run the real `claude` or `viola verify` against it in CI, and never treat a green fake-agent run — or a Linux-only local run — as proof of real-CLI or Windows behaviour; the live stamp is `agent-run run --local-live` on the operator's host, and a Windows relied count waits on its own runner (per test-plan §11 Test Anti-Patterns, Test Strategy).
- NEVER synchronise on sleep or a test-owned timer (a compaction measured at 18.8 s is waited on through `events.ndjson` offsets; the send window's expiry is the product's own exit code and is clock-driven in a §4 case) (per test-plan §11 Test Anti-Patterns, E2E and Universal).

## Contract bindings
- tests ↔ arch: the relied set `LedgerRow::relied()` per OS feeds the harness literal `LEDGER_ROWS`, `boot` step 4's stamp and verify's `[NN/MM]` counter (test-plan §3 `run`, §3 `boot`); a new row's OS reach is an arch decision the test literals follow.
- tests ↔ security: a new verify child (the `--resume` probe's session) or a `/compact` paste in Run B widens the security-plan's verify child set and Run B's compiled paste list; the test cases follow that founder ruling and never precede it (test-plan §5 Integration Test Strategy, CLI; scope §Gates).
- tests ↔ obs: `--local-live`'s suite record `{"suite":"local-live","passed","failed"}` and its failure codes (`row-missing` …) in the 5-command output (test-plan §3 `run`, Closed enums).

## Acceptance criteria contributions
- `scripts/agent-run.sh run` (default `--all`) is green on all three CI OSes, with `contract_ledger_probes.rs` and `tests/cli_verify.rs` naming each new relied row id exactly once and ending `stamped <ver>  <n> pass  0 fail`, `<n>` the new literal relied count per OS (per test-plan §5 Integration Test Strategy, CLI).
- Each new ledger arm (`--resume` reopen, `/compact`) has its pass / broken-post-condition / no-capture unit cases, and the `/compact` local-command claim has `send_local_command_` unit cases (cause `compact`, the same id; never a `prompt-submitted`) plus a verified-CLI cross-process case on its recorded variants (per test-plan §4 Unit Test Strategy, viola-agent-claude and root bin).
- Every newly recorded `resume` / `compact` variant passes the hygiene walk and schema, is replayed byte for byte by `contract_fake_agent_drift`, and the fake agent's rewritten `--resume` SessionStart is no longer the only source of that payload (per test-plan §7 Test Data & Fixtures).
- Under the founder's ruling and live-start cap only: `scripts/agent-run.sh run --local-live` on the operator's host reads `"suite":"local-live","passed":1,"failed":0` with each relied `LEDGER_ROWS` id one `  pass` step line; coverage holds `--fail-under-lines 85 --fail-under-functions 95 --fail-under-regions 80` per OS (per test-plan §3 `run`; §10 Quality Gates & Coverage Targets).
