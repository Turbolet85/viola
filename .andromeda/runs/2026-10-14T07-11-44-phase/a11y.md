# a11y extract

## Relevance
partial — no web-spa or ARIA surface; the chunk touches only the cli output-discipline surface (`viola verify` step lines and count, `send`'s confirm or refusal of `/compact`, the `unverified-cli` state a new row brings back on every earlier-stamped home) and the tui boundary a passed `viola revive` enters.

## Constraints
- The cli and the tui make no WCAG conformance claim: assert_cmd / trycmd / portable-pty results stand in as output discipline for SC 1.3.2 / 1.4.1 / 3.3.1 only, so no row, probe or step line this chunk adds may be described as a11y-tool evidence (per a11y-plan §1 A11y Scope Summary, Surface: cli; per a11y-plan §11 A11y Anti-Patterns, Strategy).
- `viola verify`'s output stays linear and static: step lines of the form `[NN/MM] … pass|fail`, with no `\r` redraw, cursor-movement or erase sequence (no spinner), and `fail` never coloured; when the relied set grows (21 → 23 on Unix, 18 → 20 on Windows, as scope infers), the `[NN/MM]` count moves with it (per a11y-plan §4 ARIA Patterns & Roles, P6; per a11y-plan §1 A11y Scope Summary, path 6 "CLI board, wait/last, verify and launch-line output").
- No SGR, glyph or cursor control under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run` / a passed `viola revive`, and `unable` / `fail` carry no SGR; any new verify line or send refusal this chunk adds is held to it (per a11y-plan §6 Visual Design Verification, State color tokens (not-color-alone); per a11y-plan §11 A11y Anti-Patterns, Visual).
- Every human-mode CLI refusal is `unable  <reason>  <detail>` on stderr with `hint:` as the last stderr line and a typed exit code (except `unknown`, exit 14); if the `/compact` claim change leaves or adds any refusal arm (today `not-delivered` / `no-prompt-submitted`, exit 13), it keeps that shape, and `--json` carries no hint (per a11y-plan §8 Cognitive Accessibility, Error recovery).
- A copy change to any fixed CLI string is pinned on purpose: trycmd pins every fixed CLI string, so a moved verify count or step-line literal fails CI until its pin is updated in the same change (per a11y-plan §8 Cognitive Accessibility, Plain language).
- A passed `viola revive` enters the same tui passthrough boundary as `viola run`: it writes no line of its own while the child holds the terminal, and no human keystroke is blocked, refused or delayed past the current atomic paste; a resume probe or claim change must not alter that (per a11y-plan §1 A11y Scope Summary, tui entity; per a11y-plan §11 A11y Anti-Patterns, Keyboard).
- A home left `cli_verified:false` by the new rows shows that state by its word `unverified-cli` (never by colour alone) on the CLI and web CLI column (per a11y-plan §6 Visual Design Verification, State color tokens (not-color-alone)).

## Patterns to follow
- `viola verify`'s interrupted pair (`unable: verify was stopped before it finished` / `hint: run viola verify again to stamp this CLI`, plain ASCII, exit 1) pinned by the stop table in `tests/cli_verify.rs`: the model for any new fixed verify line (per a11y-plan §8 Cognitive Accessibility, Error recovery).
- `viola revive`'s exit-1 refusals in the fixed-message form (one `unable: <text>` line, one `hint:` line last, no ESC byte), pinned by root cases in `tests/cli_revive.rs` (per a11y-plan §1 A11y Scope Summary, CLI verbs entity; per a11y-plan §8 Cognitive Accessibility, Error recovery).
- The budget-pause clause shape: a bound that falls on the driver only, with a case reading that a key written meanwhile reaches the child and the outer PTY carries none of viola's own literals (`tests/cli_budget.rs`) — the pattern if the `/compact` claim adds a wait to `send` (per a11y-plan §8 Cognitive Accessibility, Timeout extensions).
- CLI output-discipline checks run inside the per-OS `coverage` suite on all three OS legs, not as a separate a11y gate (per a11y-plan §9 CI Integration).

## Anti-patterns to avoid
- NEVER colour CLI `unable` / `fail`, and never emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run` / a passed `viola revive` (per a11y-plan §11 A11y Anti-Patterns, Visual).
- NEVER show an error without a recovery suggestion: every human-mode CLI refusal except `unknown` ends with a `hint:` line (per a11y-plan §11 A11y Anti-Patterns, Cognitive).
- NEVER block, refuse or delay a human keystroke in `viola run` or in a start a passed `viola revive` made (per a11y-plan §11 A11y Anti-Patterns, Keyboard).

## Contract bindings
- cli output discipline ↔ tests harness: the assert_cmd / trycmd / portable-pty checks report through the harness `run` JSON suites (CI: `coverage`), gated by the per-OS `test` job, with no a11y rows (per a11y-plan §9 CI Integration).
- `unverified-cli` state word ↔ design State color tokens: the warning word carries the state, colour only a second cue (per a11y-plan §6 Visual Design Verification, State color tokens (not-color-alone)).

## Acceptance criteria contributions
- `viola verify`'s step lines read `[NN/MM] … pass|fail` with MM equal to the per-OS relied-set size after this chunk, stderr/stdout carry no `\r` redraw or cursor sequence, and `fail` carries no SGR (per a11y-plan §4 ARIA Patterns & Roles, P6).
- Every fixed CLI string this chunk adds or moves (verify count, any new or changed `send` refusal for `/compact`) is pinned by a trycmd case or literal, each refusal ending with `hint:` last on stderr and a typed exit code, `--json` carrying no hint (per a11y-plan §8 Cognitive Accessibility, Error recovery).
- Under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json`, no new output line emits an ESC byte (per a11y-plan §6 Visual Design Verification, State color tokens (not-color-alone)).
- A passed `viola revive` writes no line of its own while the child holds the terminal; whether the existing `tests/chaos_revive.rs` case still holds after any revive-path change is research's question (per a11y-plan §1 A11y Scope Summary, tui entity).
