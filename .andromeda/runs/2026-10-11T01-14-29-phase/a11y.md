# a11y extract

## Relevance
partial — the chunk adds one verb to the cli surface (`viola list`, human and `--json`), which a11y-plan covers by output-discipline assertions only, with no WCAG conformance claim; no web-spa or tui surface is touched.

## Constraints
- Tier and reach: a11y-plan §1 A11y Scope Summary sets tier Standard, and scopes that label to web-spa; the cli entity "CLI verbs" (which names `list`) is assertable for output discipline on text and streams only, in human, plain and `--json` modes. No check of this chunk may be reported as WCAG evidence (per a11y-plan §1 A11y Scope Summary, Surface: cli).
- Caption parity: a11y-plan §8 Consistency and predictability requires the `viola list` caption set and order to equal the web `columnheader`s (NAME · LIVE · STATUS · WHEEL · DIALOG · CLI), pinned by a trycmd case for `viola list`; a11y-plan §3 WCAG criteria mapping (row 3.2.4) rests its web-side SC 3.2.4 evidence on that CLI order. The chunk lands the CLI half of that pair.
- State by word: a11y-plan §6 State color tokens (not-color-alone), CLI equivalent, requires every state to stand as a printed word, with colour only ever a second cue beside it. The slice prints no colour at all, so each state the board shows (stale liveness, a pending dialog and its kind, the human wheel, the budget pause, an unverified CLI) must be readable from the row's and the BAY line's words alone. The exact words are layout-templates' and design-system's; a11y-plan fixes only that a word is there.
- No terminal control in the output: a11y-plan §1 A11y Scope Summary (Surface: cli, Notes) requires no SGR, glyph or cursor control under `--json`, non-TTY, `NO_COLOR` and `TERM=dumb`, and output that is static and linear with no spinner or redraw. The slice's "uncoloured on every stream" form is narrower than the plan's target state and satisfies the clause; the plan's TTY-side colour rules have no subject until the colour layer lands.
- Row escaping: a11y-plan §4 ARIA Patterns & Roles (P6) requires C0 and C1 controls to appear only in escaped form, and in `list` table rows `\n` and `\t` escaped as well, so every row stays one fixed-width line. The slice's row-mode escaper is the mechanism this clause reads.
- Structure and order: a11y-plan §4 ARIA Patterns & Roles (Per-surface landmark roles inventory, cli row) names the terminal's structural equivalents: the BAY context line, then the uppercase caption line, then the rows (the unwrapped separator is not in this slice). The human form must keep that order on every run, the empty board included.
- No interaction: a11y-plan §5 Keyboard Navigation (Focus order per layout, cli) requires that the cli has no interactive prompt, no pager and no redraw. `viola list` reads no key and waits on nothing.
- Faults and refusals as text: a11y-plan §8 Cognitive Accessibility (Error recovery, CLI) requires a human-mode refusal to be a plain `unable` line with a `hint:` line last on stderr and a typed exit code, a fault to carry no hint, and `--json` to give one document with no hint text. What `list` prints for a home or an instance that fails the instance check is not worded in a11y-plan; whichever form research finds in the other masters, this clause binds its shape.

## Patterns to follow
- The cli tool set is assert_cmd + predicates + trycmd, run in the nextest suites locally and inside the per-OS `coverage` suite in CI, on all three OS legs (per a11y-plan §3 A11y testing tool pick, cli). Whether the tree already holds a trycmd case, or the root cases in `tests/cli_*.rs` pin fixed strings by another means, is research's question.
- The caption-order pin is one trycmd case for `viola list` (per a11y-plan §4 ARIA Patterns & Roles, P1 cli mirror). Any fixed CLI string the slice adds (the empty-board line, the BAY line's fixed words) is pinned the same way, so a copy change fails until the pin is moved on purpose (per a11y-plan §8 Cognitive Accessibility, Plain language, Verification).
- The control-byte check is an assert_cmd case over a row whose field carries C0 and C1 bytes (ESC and CSI among them) plus `\n` and `\t` (per a11y-plan §4 ARIA Patterns & Roles, P6). The plan words its `list` setup against a `claude agents --json` fixture row, which this slice does not build; the slice's only escaped field is the snapshot's recorded CLI version text. Whether a test can plant that value in a snapshot, and whether the fixture-row form stays owed with the unwrapped rows, is research's and the plan's question.
- ESC-free static rows already have a worded precedent in the plan: `viola revive <name> --list` (per a11y-plan §1 A11y Scope Summary, CLI verbs entity). Whether its root cases hold a reusable no-ESC predicate is research's question.
- The manual screen-reader pass on the cli (P6 step: linear output, no escape noise) is founder-owned and supplemental, recorded under `a11y/sr-pass/` (per a11y-plan §7 Screen Reader Support, Per-surface SR test pattern). It is no gate of this chunk and no step of the slice.

## Anti-patterns to avoid
- NEVER claim WCAG conformance for the cli: the assert_cmd / trycmd results are stand-ins for SC 1.3.2, 1.4.1 and 3.3.1, not a11y-tool evidence (per a11y-plan §11 A11y Anti-Patterns, Strategy).
- NEVER let the caption set or order drift between `viola list` and the web `columnheader`s (per a11y-plan §11 A11y Anti-Patterns, Cognitive).
- NEVER emit SGR under non-TTY, `NO_COLOR`, `TERM=dumb` or `--json`, and never carry a state by colour alone (per a11y-plan §11 A11y Anti-Patterns, Visual).

## Contract bindings
- a11y ↔ tests: cli output-discipline failures surface only as nextest failures in the harness `run` document's `suites[].failures[]`; no a11y row is written for the cli and no `a11y` suite value exists (per a11y-plan §3 Structured violation JSON schema, cli / tui; a11y-plan §9 CI Integration, Unit / integration row). The epoch-boundary mutation audit covers these cases where they live in crate tests (per a11y-plan §10 SLO Invariants & A11y Budgets, Standard+ invariants).
- a11y ↔ layouts: the BAY line, the caption row and the row words are layout-templates' (Output structure, `viola list`); a11y-plan binds only the caption order parity and the line order (per a11y-plan §1 A11y Scope Summary, Critical path 1).
- a11y ↔ design: the SGR rules for the board (amber on the `DIALOG` word, dim on stale rows, bold on NAME values, each beside its word) are design-system cli's and travel with the held colour layer; the outer-PTY assertion on them is owed with that layer, not with this slice (per a11y-plan §6 Visual Design Verification, State color tokens, CLI equivalent).
- a11y ↔ security: the C0/C1 escaping of a row field is security-plan's input rule read as an output-discipline check here (per a11y-plan §4 ARIA Patterns & Roles, P6).
- a11y ↔ web-spa (later chunk): the web `columnheader` order is compared with the CLI captions under `identification-mismatch` (per a11y-plan §3 Structured violation JSON schema, Additive fields); this chunk fixes the CLI side that comparison reads.
