# design extract

## Relevance
partial — the cli surface only (the board's words, field order, separators, streams and the no-colour form); every web-spa section, Typography's web faces, Depth, Radius and Motion are out of this slice, and the plan's TTY colour tokens are a standing mandate this slice's scope leaves unbuilt.

## Constraints
- The human board is a static surface: fixed-column rows under one static context header, nothing redrawn in place, no spinner; the `--json` form carries no colour, glyph or cursor control at all (per design-system §Brand Identity → Expression level, the per-surface table, rows "cli, human TTY" and "cli, `--json` / non-TTY").
- The six fields are fixed and in the order NAME, LIVE, STATUS, WHEEL, DIALOG, CLI, and a field with no reading prints the word `unknown`, never a blank or a placeholder (per design-system §Brand Identity → Domain anchors, "Flight-progress strip").
- Every state the slice shows is a printed word taken from the fifth column of the domain status rows: `Liveness`, `SessionStatus`, `WheelHolder`, `DialogPending`, `PendingDialogKind`, `CliVerified`, `CliVersion::(absent)`, `InstanceBudgetPaused`, `BudgetEnvelope` (reading and unknown), `BudgetEnvelope.paused`, `BudgetWindow`, `Window` (unknown and expired) and `Skipped` (zero and nonzero). The slice builds wrapped rows only, so none of the `(absent, unwrapped)` rows applies (per design-system §Color Palette → Semantic Colors, "Domain status colors").
  - Not worded there for the cli, for research or the layouts extract to close: the WHEEL cell of a row whose holder is `human` while `budget_paused` is true (the rows give the `driver` pairing only), and the cli form of a nonzero `skipped` (the row gives the web wording and a box; the cli sample shows the zero form only).
- Human output is ASCII only; inside one field or label the web's middle dot becomes space-hyphen-space, and two spaces separate columns (per design-system §Iconography, "Separator"). The column gutter is the terminal grid's, two spaces, with no other spacing token on this surface (per design-system §Spacing, the closing cli line).
- A session keeps its slot: rows are ordered by name and never re-ranked by state, and a `stale` row stays on the board in its slot, never dropped (per design-system §Brand Identity → Domain anchors, "Strip bay and racks" and "Coasting track"; the ordering by name is restated per design-system §Surface: cli → Component Patterns, 1 "`viola list`").
- The BAY line is the web ATIS header less its product word, its address, its `resets` times and its TAPE cell; a budget window whose reset has passed still prints its figure followed by the old-information word, and every reading carries its age (per design-system §Surface: cli → Component Patterns, 1 "`viola list`"; the age rule per design-system §Brand Identity → Domain anchors, "ATIS information with its age").
- The form with no colour is: no SGR, no non-ASCII glyph, no cursor control, while the ASCII words still print in full; `--json` is the first match of that order and replaces the words with its document (per design-system §Surface: cli → Tokens, "Colour decision order"). The same plan requires, on a terminal where no match of that order holds, bold NAME values, an amber `DIALOG` word and a dim whole `stale` row, each beside its word (per design-system §Surface: cli → Tokens, the token table). The slice's scope prints the no-colour form on every stream, so that requirement stands unmet after this chunk: it is a deferral to carry on the review card, not a form the plan gives for a colour-capable terminal.
- Lines are never wrapped, and where the width is not detected nothing is truncated; the only cell the plan ever lets a table clip is the NAME of an unwrapped row, which this slice does not print (per design-system §Surface: cli → Tokens, "Width").

## Patterns to follow
- The board is the one cli component "the k9s strip table": the same columns and the same words as the web strip, the caption row under the BAY line, the empty-board line as one fixed phrase that names the start command (per design-system §Surface: cli → Component Patterns, 1 "`viola list`"). Column widths and the row grammar are the layouts extract's.
- The escaper has two modes over one text form, a backslash, `x` and two uppercase hex digits per control character, nothing stripped: the message mode `wait` and `last` share keeps LF and TAB (per design-system §Surface: cli → Component Patterns, 3 "`viola wait` / `viola last`"), and the row mode escapes those two as well so a row stays one line (per design-system §Surface: cli → Component Patterns, 1 "`viola list`"). Whether a message-mode escaper already stands in the code for the row mode to sit beside is research's question.
  - The plan names the row mode for fields of `claude agents --json` origin. The scope's first consumer is the CLI version text, which the plan does not name; and component 1 lists C0 and C1 where component 3 lists C0, DEL and C1. Whether the row mode escapes DEL is research's to close against the security plan.
- Streams: the table is a result, so it goes to stdout; faults go to stderr; under `--json` the whole answer, a fault included, is one JSON document on stdout with the typed exit code and no `hint:` line (per design-system §Surface: cli → Tokens, "Streams").
- Exit phraseology: exit 0 prints no stderr word and its `--json` form is the `ok` envelope; a fault is the one fixed internal-error line with no chain, path or hint (per design-system §Surface: cli → Component Patterns, "Exit-code phraseology", rows 0 and 1).
- `list` is a flat one-word verb, grouped in `viola --help` under the board group beside `ui`; there is no interactive prompt, TUI mode or pager (per design-system §Surface: cli → Navigation Pattern). Whether the help text already carries that grouping is research's question.

## Anti-patterns to avoid
- No status prefix, tick, cross, emoji, dot or icon stands for a state; no spinner, progress bar or live-redrawing table (per design-system §Anti-Patterns → Per-Surface Bans, cli; the dot ban also per design-system §Anti-Patterns → Rejected Defaults, "Traffic-light status dots").
- No colour, glyph or cursor control under `--json` or on a stream that is not a terminal, and never a colour without its word; nothing is coloured but the `DIALOG` word and a `stale` row (per design-system §Anti-Patterns → Per-Surface Bans, cli).
- No hard-coded wrap point, no data mixed with messages on one stream, and no upstream text, path or pid in an error line (per design-system §Anti-Patterns → Per-Surface Bans, cli).

## Contract bindings
- design ↔ layouts: the words, separators and tokens are this plan's; column widths, the row and BAY-line grammar and the empty form are layout-templates' "Output structure — `viola list`". The two open wordings named under Constraints land there or at research.
- design ↔ a11y: the plan's rule that colour is a second cue beside a printed word is the not-colour-alone criterion's cli half; in this slice the word is the only cue, so nothing of contrast is in play (the terminal background is the user's, per design-system §Surface: cli → Tokens, the "backgrounds" row).
- design ↔ security: the row-mode escaper is stricter than the security plan's control-escaping floor, which keeps LF and TAB (per design-system §Surface: cli → Component Patterns, 1 "`viola list`"); the cli bans on paths, pids and upstream text in errors restate the NEVER-log floor.
- design ↔ architecture: the `--json` envelope and the exit codes are architecture's; the plan's colour decision order reads two terminal variables and one colour variable, which the scope holds as a boundary matter for the founder, so the TTY colour mandate cannot be met without that ruling.
- design ↔ tests: byte-level checks on the human form (no ESC byte, ASCII only, one line per row) are the natural pins for the constraints above; which test file owns them is the test-plan extract's.

## Acceptance criteria contributions
- (design) The human `viola list` output of this slice holds no ESC byte and no byte outside ASCII, on a terminal and on a pipe alike, and no line is wrapped or truncated (per design-system §Surface: cli → Tokens, "Colour decision order" and "Width").
- (design) Each row prints its six fields in the fixed order, each state as its domain-status word with two spaces between columns and space-hyphen-space inside a field; a field with no reading prints `unknown`; rows are in name order and a `stale` row is present (per design-system §Color Palette → Semantic Colors, "Domain status colors"; per design-system §Iconography, "Separator").
- (design) `viola list --json` writes exactly one JSON document to stdout and no human word, caption, `hint:` line or SGR on either stream (per design-system §Surface: cli → Tokens, "Streams").
- (design) A control character in an escaped row field, LF and TAB included, prints as backslash-`x` plus two uppercase hex digits with nothing stripped, and the row stays one line (per design-system §Surface: cli → Component Patterns, 1 "`viola list`").
