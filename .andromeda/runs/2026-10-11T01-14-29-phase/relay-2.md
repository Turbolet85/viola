Question put at P4 (AskUserQuestion, header "Failed check"):

What does `viola list` do when the strict-modes check fails? No master words it for a verb that reads many instances (security-plan, layout-templates and obs-plan each say so; test-plan gives exit 21 for a home that fails under 'every other verb'). No option reads a value from a file that failed, so none is a boundary widening. Whichever lands is the operator's answer, and it extends the 'a refused check opens no log and writes no line' shape the founder has not ruled on.

Options offered:

1. Refuse whole, exit 21 (Recommended) — Any failing path (the home, instances/, one instance's directory or files) refuses the whole board: nothing read, no log opened, the home's mode left as found. Exit 21 as test-plan words it; `--json` prints the one worded exit-21 document; the human form prints an already-worded pair (the home: run's 'the viola home is not private to you'; an instance: revive's '<name>'s state files can be written by another user'). Loud, no new wording, no new log line. Cost: one bad instance blocks the board until fixed.
2. Skip the failing instance — A failing home or instances/ refuses as above. A failing instance gives no row, the rest print, exit 0. The board stays usable, but an instance is left out with nothing saying so: no master words a line for it, and the obs catalogue has no line for a refused instance in a scan (adding one is a three-place amendment).
3. Refuse whole, exit 1 — The same refusal and the same two worded pairs, with the pairs' own exit 1 as run and revive use it. `--json` then prints nothing on stdout, since no master gives exit 1 a document. Departs from test-plan's 'CLI 21 for every other verb'.

Answer selected: "Refuse whole, exit 21 (Recommended)"

Notes given with the answer: The operator answer, not a ruling of the founder: list it on the review card among the shapes he has not ruled on.
