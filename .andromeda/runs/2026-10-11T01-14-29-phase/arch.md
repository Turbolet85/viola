# arch extract

## Relevance

relevant — the slice lands a subcommand architecture already names, on a payload contract architecture already fixes; it adds no crate, port, endpoint, channel method or environment variable.

## Constraints

- `list` is a caller-side read of the disk, never a channel request: the calling process reads `instances/*/` itself, owns no endpoint, writes no frame and needs no live wrapper (per architecture §Standard Contracts, Channel methods, the `list` line; §Established Decisions [API Style]; §Design Philosophy, "No daemon; the disk is the shared truth").
  - The same `list` line also requires a read of `claude agents --json`. The slice holds that read back, so the landed verb departs from the target there and the departure needs an "as landed" record at wrap. With no such read, §Standard Contracts (Session liveness) gives `unknown` as the `status` of every row for the cases "not found, fails or cannot be parsed"; whether "not read at all" takes the same value is research's question (the masters word no fourth case).
- The machine form is the CLI `--json` success envelope around the caller-side payload `{items, budget, skipped}`, with the item, `budget` and `skipped` shapes of `/api/sessions` (per architecture §Standard Contracts, CLI `--json` output; §Standard Contracts, GUI list envelope). The item rules of that envelope bind each row: gone instances are omitted; `liveness` is one of two words; `status` one of three; `wheel` one of the two holders; `budget_paused` is the instance's own gate from its snapshot. JSON keys are snake_case, enum words kebab-case, and an absent optional field is omitted on write (per architecture §Conventions, Naming patterns; §Conventions, Data model conventions, Optional fields).
- Liveness follows the one rule: the snapshot's pid and start time decide `gone` whatever the beat's age, and only then does the beat's age split `live` from `stale` (per architecture §Standard Contracts, Session liveness; §Established Decisions [Session Liveness]). For an unreadable or newer snapshot the state is rebuilt from the log and only log-derived fields exist: liveness rests on the heartbeat alone and is never `stale`, `dialog_pending` reads false, the CLI version and its verdict are absent, and a field no line gave is absent, never a default (per architecture §Standard Contracts, Snapshot envelope; §Standard Contracts, Instance snapshot, the `pending_dialog` bullet).
- The top-level `budget` comes from `budget.json`, in the per-window shape with its `"unknown"` forms, and its `paused` says only that the newest reading crosses a threshold; it is a different fact from an item's `budget_paused` (per architecture §Standard Contracts, GUI list envelope; §Occupied Resources, Filesystem, the `budget.json` row). The board shows what the snapshot holds, a stale pause included, because the gate never polls (per architecture §Established Decisions [Budget Governor]).
  - Architecture words no `list`-side source for the thresholds `budget.paused` is measured against: `config.json` is read by the wrapper at its start (§Occupied Resources, Filesystem, the `config.json` row) and the crossed rule is the gate's ([Budget Governor]). Which thresholds and which crossed rule `list` applies is research's question.
- `skipped` is the events reader's three counts, surfaced for the first time: the reader counts per read and logs nothing, and showing the counts is owed to this route entry (per architecture §Established Decisions [Database / State Store]; §Cross-cutting Patterns, Mixed-version tolerance). Architecture does not say which reads feed `list`'s total (the plan describes `list` as reading heartbeat and snapshot, and the log only through the replay fallback); what the total is over several instances is research's question, as the scope already holds.
- The code is root-bin code: the subcommand module under `src/cmd/`, its human text in `src/human.rs`, sync std only, anyhow only at that edge, and no Claude-specific shape in it (per architecture §Infrastructure Patterns → Project directory structure; §Infrastructure Patterns → Crate dependency direction; §Established Decisions [Concurrency / Backend Framework]; §Inherited Defaults, Agent isolation).
- No new environment variable, `config.json` key or flag beyond `--json` and the global `--home`; no direct or dependency-borne read of a colour or terminal variable (per architecture §Cross-cutting Patterns, Config management; §Conventions, Naming patterns, the CLI and Environment variables bullets). The home resolves as the other CLI verbs' does; the `VIOLA_DIR` step for CLI verbs is owed to another route entry, "CLI machine contract", and is not this chunk's (per architecture §Cross-cutting Patterns, Config management, the Viola home bullet).

## Patterns to follow

- The CLI verb shape: human text by default, `--json` for agents, a typed exit code; a dispatch error or caught panic prints the one internal-error line from the `main` catch site and no dispatch arm prints it (per architecture §Established Decisions [CLI Conventions]; §Conventions, Error handling schema, CLI exit codes). That exit-code text files every first word but three named ones and a leading flag under the `cli` role, so by the plan's wording `list` is already a `cli` word; whether `role_of` needs any edit is research's question.
- The instance check ahead of everything else: the two existing readers run `viola_state::strict::check_instance` before a log is opened, because opening a log narrows an existing home's mode and a later check then passes a widened home (per architecture §Occupied Resources, Filesystem, the `instances/<ViolaName>/` row). That row counts the check's product call sites by a stated rule; a `list` call site changes the count and is amended at wrap. What `list` does on a refused home or instance is not worded by architecture.
- Reuse `viola-state`'s existing readers instead of a second parser: the classified snapshot read with its replay fallback, the checked budget read, the one events reader, the pid-and-start-time liveness check (per architecture §Standard Contracts, Snapshot envelope; §Occupied Resources, Filesystem, the `budget.json` row; §Infrastructure Patterns → Crate dependency direction, the `viola-state` line). Architecture records each with a named caller set ("one product reader", "the file's one reader", the events reader's caller list); each is amended at wrap when `list` joins it. Whether the replay's result still carries the three fields and the pass's skip counts is research's question.
- Place anything a later surface must share below the root bin: the same payload is promised to MCP `list` and `/api/sessions`, and `viola-mcp` and `viola-ui` reach `viola-state` and `viola-agent-claude` but never the root package (per architecture §Infrastructure Patterns → Crate dependency direction; §Conventions, Error handling schema, the MCP bullet). Architecture names no crate for the assembled item; the placement is planning's call.
- Versioned-tolerant reading of viola's own files: `v` carried, unknown keys skipped, no deny-unknown parsing, and an unparseable external value rendered as the word `"unknown"`, never an error (per architecture §Established Decisions [Validation]; §Conventions, Data model conventions, Unparseable external values).

## Anti-patterns to avoid

- Contacting a wrapper to build the board: no channel method, frame, endpoint connect or MCP tool for `list`, and no new listener or route (per architecture §Conventions, Interfaces and versioning, Channel methods; §Established Decisions [API Style]).
- Writing while reading: the snapshot has one writer (its wrapper), `budget.json` one (the statusline arm), the replay writes no file, the budget read creates nothing for an absent file, and readers count a torn line and never rewrite or truncate the log (per architecture §Standard Contracts, Instance snapshot; §Occupied Resources, Filesystem, the `budget.json` row; §Established Decisions [Database / State Store]).
- Any Claude-specific read or spawn in this slice's code path, or a dependence on `claude agents --json` output without its ledger row: that shape lives only in `viola-agent-claude` behind the open join-field row, and nothing shells out (per architecture §Cross-cutting Patterns, Capability ledger as the single gate; §Cross-cutting Patterns, Cross-platform discipline; §Inherited Defaults, Agent isolation).

## Contract bindings

- security: the instance check at `list`'s entry and the `ViolaName` parse of a directory name before any path join (architecture §Conventions, Data model conventions, the instance key; the enforcement and the refused-instance behaviour are security-plan's). `list` becomes a second reader of `budget.json`, a file architecture records as outside the trusted-file list with an unratified widening on the wrapper's side (§Occupied Resources, Filesystem, the `budget.json` row); whether a display-only read touches that hold is security's to say.
- obs: architecture's process-log row names the `cli` role file by the target instance (§Occupied Resources, Filesystem, the `diagnostics/` row); `list` has no target, and no role file is named for it. The replay fallback logs one `state-recovered` line per recovered snapshot (§Standard Contracts, Snapshot envelope); under a `list` caller, where that line lands is obs's contract. Human output on stdout and stderr for a short-lived CLI verb is permitted (§Cross-cutting Patterns, Diagnostic output channels).
- tests: the `--json` envelope and item shapes are what the owed E5, Chaos and Path 6 readings assert; every OS-specific branch compiles and is tested on its CI runner under the fake agent (§Cross-cutting Patterns, Cross-platform discipline; §Established Decisions [CI/CD]).
- design / layout: the human rows and the row-mode escaper are layout-templates' text; architecture fixes only their home, `src/human.rs`, where the message-mode escaper already sits (§Infrastructure Patterns → Project directory structure).
- mcp / ui (later epochs): the payload shape is shared verbatim with MCP `list` and `/api/sessions` (§Conventions, Error handling schema, the MCP bullet; §Standard Contracts, GUI list envelope), so a shape chosen here binds both.
- capability ledger: the `claude agents --json` join field is an open ledger row (§Established Decisions [CLI Version Compatibility]; §Standard Contracts, Session liveness); the slice claims nothing of it.

## Acceptance criteria contributions

- In a home with no live wrapper, `viola list --json` prints exactly one document on stdout, the success envelope holding `items`, `budget` and `skipped`, and exits 0; no endpoint is connected and no frame written (per architecture §Standard Contracts, CLI `--json` output; §Standard Contracts, Channel methods, the `list` line).
- A gone instance is absent from `items`; an instance whose snapshot is unreadable or newer and whose heartbeat is fresh is present with `dialog_pending` false, no CLI version or verdict field, its `wheel` and `budget_paused` from the log, and a liveness that is never `stale` (per architecture §Standard Contracts, GUI list envelope; §Standard Contracts, Snapshot envelope).
- After a `list`, every instance's `snapshot.json` and `events.ndjson` and the home's `budget.json` are byte-identical, and a home without `budget.json` holds neither it nor its lock sibling (per architecture §Occupied Resources, Filesystem, the `budget.json` row; §Established Decisions [Database / State Store]).
- The verb's code sits in the root package's `src/cmd/` and `src/human.rs` with no new workspace edge, no Tokio in any sync crate (the sole-root ban still passes) and no new environment variable read by the binary or a dependency (per architecture §Infrastructure Patterns → Crate dependency direction; §Established Decisions [Concurrency / Backend Framework]; §Cross-cutting Patterns, Config management).
