# security extract

## Relevance
relevant — `viola list` is a new entry point that reads `snapshot.json`, `events.ndjson`, `heartbeat` and `budget.json` of every instance in a home, and a new stdout surface (human rows and `--json`); it adds no channel method, listener, child spawn, dependency or secret.

## Constraints
- **Strict-modes before any snapshot or log value.** security-plan §Authentication & Authorization, row "`~/.viola/` access control" (Strict-modes check and its Unix Read rule) requires the check in every process that reads `snapshot.json`, on the home, `instances/`, the instance directory and the trusted file itself. `list` is a new reader and is none of the seven dated interim gaps that row lists; it may borrow none of them. That row words the failure outcome for `run` / `ui` / `mcp`, for `hook`, and for CLI client verbs that resolve an `endpoint` (exit 21); it words no outcome for a verb that reads many instances and resolves no endpoint. What `list` does with one failing instance, or a failing home, is research's question; no option may use a value taken from files that failed the check.
- **The check comes before anything narrows the home.** security-plan §Authentication & Authorization, row "`~/.viola/` access control" records, for `revive` and for `hook statusline`, that opening a log sets an existing home to 0700 and a check made after it passes a home at 0770. The same order is required of `list`: the check before the process log opens. Whether the `cli` role's obs init opens a file under the home before `list`'s first read is research's question. That a refused check writes no line is, per that row, the operator's answer and not the founder's ruling; this chunk must not word it as ruled.
- **Home path.** security-plan §Input Validation, row "CLI arguments / stdin" (Home path) requires `--home` / `VIOLA_DIR` canonicalised and then passed through the strict-modes check before any snapshot read.
- **Names before joins.** security-plan §Security Anti-Patterns → Input requires that no `instances/<name>` join takes a string that did not come out of `ViolaName::try_new`; a directory entry read from `instances/` is such a string.
- **Bounded, non-writing reads; the replay only after the instance check.** security-plan §Input Validation, row "Own state files on read" requires every ndjson line and the snapshot read through the `MAX_FRAME` bounds, a reader that never writes, and `read_snapshot_or_replay` taken only after `check_instance` has passed. The three `Skipped` counts are numbers only and are not logged per that row.
- **`budget.json` only through the checked read.** security-plan §Input Validation, row "Own state files on read" requires the read through `viola_state::budget::read_budget` in its stated order, every failure being no reading with no line, no write of `budget.json` and no lock sibling created under an absent file. security-plan §Authentication & Authorization, row "`~/.viola/` access control" records that `budget.json` is not on the trusted-file list and that the wrapper refusing a `send` on it is NOT ratified; `list` shows the value and decides nothing on it, and no artifact of this chunk may word that widening as ratified.
- **What reaches stdout and stderr.** security-plan §Bootstrap phases, `logging-redaction-wire` requires that user content (prompts, assistant text, plan and question text, tool `input`), the `statusline_command` string and absolute paths stay out of every surface that is not one of its named content payloads; `list` and `list --json` are not among them. security-plan §Threat Model Summary (Data classification, operational metadata) requires the snapshot's `cwd` on no log line, error body or stdout. security-plan §Error Handling (External responses) requires `--json` error output with fixed codes and messages, no absolute path, no anyhow chain holding a serde source. So an item holds closed words, numbers, a parsed name and the escaped CLI version text only, and `pending_dialog` leaves the process as a boolean.

## Patterns to follow
- `viola revive`'s preflight: `viola_state::strict::check_instance` first, then `replay::read_snapshot_or_replay`, with no value of either file used before the check passes (security-plan §Input Validation, row "Own state files on read"; §Authentication & Authorization, row "`~/.viola/` access control").
- The `read_budget` order — `check_path` on the home, `check_path` on the file, shared lock, capped read, tolerant parse, `v` = 1 — with "no reading" as the one failure shape (security-plan §Input Validation, row "Own state files on read"). The scope's `"unknown"` maps onto that one shape; no second reader of the file is written beside it.
- The enumeration rule the plan gives the tail: only names that pass `ViolaName::try_new`, under the canonical home, symlinks ignored through `symlink_metadata`, failing names ignored (security-plan §Input Validation, row "Tailed paths (notify)"). That row is worded for the notify tail; whether it is taken for `list`'s directory walk is the plan's to state, and the symlink half is not otherwise required of `list` by any row read here.
- Human-mode escaping of C0/C1 before a terminal write (security-plan §Bootstrap phases, `logging-redaction-wire`, the `wait` / `last` / `list` bullet). The CLI version text is child output by origin, which security-plan §Input Validation, row "Child process output" classes as untrusted.
- Error mapping to a fixed message before it joins a chain (security-plan §Bootstrap phases, `error-sanitization-wire`).

## Anti-patterns to avoid
- NEVER join `instances/<name>` with an unparsed string, and NEVER take reference values from a `snapshot.json` that has not passed strict-modes in the same process (security-plan §Security Anti-Patterns → Input; → Authentication).
- NEVER print a `list` row to a terminal with a raw C0/C1 control in it, and NEVER put an absolute path in an external error (security-plan §Security Anti-Patterns → Logging).
- NEVER let a flag, a `VIOLA_*` variable or `config.json` switch off the strict-modes check, NEVER add a channel method without a Decisions Log entry, and NEVER let a process other than the instance's wrapper write `snapshot.json` (security-plan §Security Anti-Patterns → Universal). `list` stays a disk reader: no frame, no spawn, no write of another process's state file.

## Contract bindings
- **security ↔ architecture (stale "one caller" sentences, a wrap amendment, not an edit of this chunk).** security-plan §Threat Model Summary (Attack surface, "Filesystem state under `~/.viola/`") says the replay has one product reader, `viola revive`'s preflight; security-plan §Input Validation, row "Own state files on read" says `read_snapshot_or_replay` has one product caller and `budget.json` has one reader, the wrapper's gate, and lists the `events.ndjson` reader's callers. `list` adds a caller to each. The drift detectors should expect these at the wrap.
- **security ↔ design (the row-mode escaper).** security-plan §Bootstrap phases, `logging-redaction-wire` words the human-mode escape as keeping `\n` and `\t`, and scopes the `list` mandate to fields taken from `claude agents --json`; the scope's row-mode escaper writes `\n` and `\t` as hex text too and has no `claude agents --json` field in this slice. The stricter row form is not banned by the plan, but the two wordings differ; research reads design-system / layout-templates for the row mode and the plan states which master the escaper follows.
- **security ↔ obs.** The NEVER-log floor (security-plan §Bootstrap phases, `logging-redaction-wire`) binds every `obs_event!` line `list` emits: no absolute path, no snapshot `cwd`, no content. The artifact canary scan over test homes (security-plan §Bootstrap phases, `secret-scanning-ci-gate`) reads the new cases' homes.
- **security ↔ tests.** Strict-modes refusals are proven by `cfg(unix)` cases; security-plan §Authentication & Authorization, row "`~/.viola/` access control" records that no Windows case widening an instance tree's DACL exists yet and owes it to the route entry "Home and code-bearing file integrity". The plan's fuzz / property scope (security-plan §Input Validation, "Parser surfaces") names the `claude agents --json` parser, which is outside this slice, and does not name the escaper.
- **Out of slice, so not extracted as a mandate:** the `claude agents --json` spawn, its PATH resolution and its `name` rule (security-plan §Input Validation, row "Child executable resolution") bind the chunk that lands unwrapped rows. This slice spawns no child.

## Acceptance criteria contributions
- With the home, an instance directory or its `snapshot.json` group- or other-writable, or the home or instance directory granting any group or other permission, `viola list` and `viola list --json` build nothing from that tree's snapshot or log values, and a home found at 0770 is refused, not narrowed and then passed (per security-plan §Authentication & Authorization, row "`~/.viola/` access control").
- An `instances/` entry whose name fails `ViolaName::try_new` produces no path join and no item (per security-plan §Security Anti-Patterns → Input).
- A recorded CLI version text holding ESC, another C0 control, DEL or a C1 control reaches the human rows with no raw control byte (per security-plan §Security Anti-Patterns → Logging; §Bootstrap phases, `logging-redaction-wire`).
- `list --json`, the human rows and every error line hold no absolute path, no snapshot `cwd`, no `statusline_command` and no prompt, assistant or dialog text; and a `list` run leaves `snapshot.json`, `events.ndjson`, `budget.json` and its lock sibling unwritten, an absent `budget.json` staying absent (per security-plan §Error Handling, External responses; §Input Validation, row "Own state files on read").
