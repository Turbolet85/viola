- New gap: §3 `run` step 3 names "Path 6's statusline command" as a reason sessions need different boot flags, but `boot` has no flag that configures a statusline command. Path 6 step 1 also depends on the unresolved §12 open question about the `statusline_command` source and never points to it. Patch 2 and Patch 3.
- New gap: §7 gives the fake agent a `--script` turn script, and Paths 3 and 4 and their Playwright tests depend on it. No file location or path resolution is given, yet nextest (cwd `crates/viola-e2e`) and Playwright (cwd `e2e-web`) run from different directories. Patch 4.

Playwright's default 30 s test timeout would therefore kill boots in some runs and not others, which breaks zero-flakiness. `playwright.config.ts` sets no timeout. Patch 5.

**2. Tool Anchoring**
- The catalog lists cargo-mutants exit codes 1, 4, 5, 6 and 70. The §3 verdict checks only `missed == 0 && timeout == 0`. A failing baseline (exit 4), a diff that does not match the tree (5) or an invalid diff (6) tests zero mutants, so the run passes silently. This is the same kind of false pass that iteration 8 closed for `base-missing`. The plan also never states the test scope. By cargo-mutants' default (this comes from my knowledge of the tool, not from the catalog), each mutant is tested only by the package that owns it. In that case `--features fake-agent` hits crates that do not declare the feature. Patch 1.
- §8 says stub executables are "resolved through `CARGO_BIN_EXE_viola-fake-agent`". This contradicts §3 boot step 5 and §12: `viola-e2e` tests and the harness cannot see `CARGO_BIN_EXE_*`. Patch 6 (small).
- Install and version checks across §3 Bootstrap `ci-tool-install`, §9 and the catalog are consistent. jq is dropped and jaq 3.1.1 is pinned. No patch.

**3. Test Scope Faithfulness**

## Patches

### Patch 1: Make the mutation verdict reject exit codes that test no mutants, and state the mutation test scope
**Reason:** Dimension 2, Tool Anchoring (the catalog lists exit codes 4/5/6/70), and Dimension 4, Tier Calibration. The verdict counts only `missed`/`timeout`, so a failing baseline or a bad diff tests zero mutants and still passes. The test scope and the handling of the root-only `fake-agent` feature are unstated.
**Old:**
```
- Verdict: parse `mutants.out/outcomes.json` and require `missed == 0 && timeout == 0`. The exit code alone is not trusted, because exit 3 masks exit 2.
```
**New:**
```
- Verdict: parse `mutants.out/outcomes.json` and require `missed == 0 && timeout == 0`. The exit code alone is not trusted, because exit 3 masks exit 2. It is still checked: only exit 0, 2 or 3 can pass, and then the counts decide. Exit 1, 4 (baseline failing), 5 (diff does not match the tree), 6 (invalid diff) or 70 fails `run --mutants` with `reason:"mutants-exit-<code>"`. Those runs test no mutants, so their zero counts would otherwise read as a pass.
- Test scope: cargo-mutants' default is kept (`--test-workspace` is not set), so each mutant is tested only by the tests of the package that owns the mutated file. A mutant in a `crates/viola-<area>` crate must be killed by that crate's own tests (§11 Test Strategy layer rule), and the `viola-e2e` scenarios never run under mutation. `fake-agent` is declared only by the root package, so setup-project must show the baseline passing for a diff that touches only a non-root crate. A feature error there surfaces as exit 4 and fails the run.
```

### Patch 2: Give `boot` a way to configure Path 6's statusline command, tied to the §12 open question
**Reason:** Dimension 1, Downstream Readiness. §3 `run` step 3 says Path 6 needs its own boot flags for "Path 6's statusline command", but `boot` has no such flag, so neither `harness_session` nor the `path6` spec can set up the scenario. The settings source is an unresolved §12 open question, and no section may use it as if it were resolved.
**Old:**
```
[--agents-mode recorded|oversize|malformed]`. The default is instances `overseer` and `builder` plus `--ui`, with `--agents-mode recorded`.
```
**New:**
```
[--agents-mode recorded|oversize|malformed] [--statusline-echo]`. The default is instances `overseer` and `builder` plus `--ui`, with `--agents-mode recorded`. `--statusline-echo` runs before boot step 5. It configures the user statusline command as `<bin dir>/viola-fake-agent[.exe] statusline-echo`, appending to `<home>/fake/statusline.marker`, in the settings source that `run` reads, redirected into the session home. It is used by Path 6 and its `path6` spec. That source is still a §12 open question. Until arch names it, `--statusline-echo` exits 2 with `reason:"statusline-source-unresolved"`, and Path 6's pass-through bullets are blocked. They are never written against a guessed source.
```

### Patch 3: Point Path 6 step 1 at the boot flag and the open question
**Reason:** Dimension 1, Downstream Readiness (§12 open question cross-reference). Step 1 treats "the settings source `run` reads" as known, and it names no boot mechanism.
**Old:**
```
  1. Boot `builder` with a user statusline command configured as `viola-fake-agent statusline-echo`, through the settings source `run` reads, pointed at a per-test dir. It prints a fixed marker and appends to a marker file.
```
**New:**
```
  1. `agent-run boot --session p6 --statusline-echo`, which boots the default `overseer` and `builder` (§3 `boot`). The user statusline command becomes `viola-fake-agent statusline-echo`, which prints a fixed marker and appends to a marker file. The settings source it is written to is a §12 open question. Until that is resolved, only the pass-through bullets (marker stdout in step 2, the unchanged marker file in step 6) are blocked. The budget, refusal and override bullets run on a boot without the flag.
```

### Patch 4: Give fake-agent turn scripts a shared location and absolute-path resolution
**Reason:** Dimension 1, Downstream Readiness. Paths 3 and 4 (and their Playwright tests under the §3 cross-runner rule) depend on `--script`, but no file location or path resolution is given. nextest and Playwright run with different cwds, and boot step 5 resolves only `--fixtures` to an absolute path.
**Old:**
```
- It follows a JSON turn script (`--script`) for PreToolUse, PermissionRequest, PostToolUse and Stop steps.
```
**New:**
```
- It follows a JSON turn script (`--script`) for PreToolUse, PermissionRequest, PostToolUse and Stop steps. Scenario scripts are checked in as `fixtures/fake-scripts/<scenario>.json` (for example `path3.json`, `path4.json`), contain synthetic text only, and are passed as `--instance <name>:--script fixtures/fake-scripts/<scenario>.json`. Boot step 5 and both `booted_wrapper` copies resolve a relative `--script` against `<workspace root>`, the same way as `--fixtures`. A Rust scenario and its Playwright test load the same file.
```

### Patch 5: Stop Playwright's default test timeout from killing slow session boots
**Reason:** Dimension 1, Downstream Readiness, and Dimension 4, Tier Calibration (zero-flakiness). The test-scoped fixture runs `boot`, whose deadlines are 20 s per instance plus 10 s for the UI, plus `viola verify`. Path 2 boots three instances. The config sets no timeout, so Playwright's default 30 s would kill some boots and not others.
**Old:**
```
- `retries: 0` and `forbidOnly: true` (a stray `test.only` would silently skip the rest)
```
**New:**
```
- `retries: 0` and `forbidOnly: true` (a stray `test.only` would silently skip the rest)
      - the test-scoped session fixture (§3 `run` step 3) declares its own fixture `timeout`. It is computed from boot's deadlines (20 s per `--instance` plus 10 s with `--ui`), plus a fixed margin for boot steps 1 and 4 and for teardown `cleanup` (10 s supervisor deadline). Boot time therefore never counts against the test body's timeout. A fixture timeout is a failure, never retried.
```

### Patch 6: Fix §8's claim about `CARGO_BIN_EXE_*`, which contradicts §3 and §12
**Reason:** Dimension 2, Tool Anchoring (cross-section consistency). §3 boot step 5 says Cargo sets `CARGO_BIN_EXE_*` only for the root package's own integration tests, and §12 says `viola-e2e` uses the assert_cmd target-dir lookup. §8 generalises `CARGO_BIN_EXE_viola-fake-agent` to all tests.
**Old:**
```
external processes are real stub executables resolved through `CARGO_BIN_EXE_viola-fake-agent`
```
**New:**
```
external processes are real stub executables, resolved through `CARGO_BIN_EXE_viola-fake-agent` in root `tests/` only. `viola-e2e` tests and the harness use the assert_cmd target-dir lookup (§3 boot step 5)
```

### Patch 7: Assert the GUI token's 32-byte length and per-launch rotation
**Reason:** Dimension 3, Test Scope Faithfulness (entity attributes). §1 GUI token entity: "32 getrandom bytes", per-launch. grep for `getrandom|32 bytes|per-launch|different token` hits only line 83. No suite asserts either attribute.
**Old:**
```
after graceful shutdown it is absent (cleanup step 5)
```
**New:**
```
after graceful shutdown it is absent (cleanup step 5)
  - the token read from `ui/<port>.url` decodes to exactly 32 bytes in the product's token encoding. After that `viola ui` shuts down gracefully, a second launch on the same home writes a different token, and replaying the first token against it gives 401 with no `Set-Cookie` (§1 GUI per-launch token entity)
```
