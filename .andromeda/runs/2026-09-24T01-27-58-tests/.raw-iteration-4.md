## Patches

### Patch 1: Give the fake-agent control file a concrete path in boot
**Reason:** Downstream Readiness. §7 gates scripted steps on a control file, but boot never passes its path. Tests and specs can't release Path 3's gated steps.
**Old:**
```
--receipt <home>/fake/<name>.receipt.ndjson <fake-agent-args>`. It drains every master on its own thread.
```
**New:**
```
--receipt <home>/fake/<name>.receipt.ndjson --control <home>/fake/<name>.control <fake-agent-args>`. It drains every master on its own thread. The control file is created empty before spawn. Both rstest `booted_wrapper` copies pass the same `--control` path.
```

### Patch 2: Fake-agent contract: control path semantics and a report-only version mode
**Reason:** Downstream Readiness. §7 names no control path, and no fake-agent mode lets a stamped home run an unlisted `--version` (needed by Path 7).
**Old:**
```
- It follows a JSON turn script (`--script`) for PreToolUse, PermissionRequest, PostToolUse and Stop steps. Steps are gated by a control file the test writes, which gives deterministic ordering without sleeps.
- It writes receipt lines to `--receipt <path>`, covering received prompts (text, raw hex, `bare_esc`), keystrokes, env names, Unix fds, and hook invocations (exit code, stderr length, stdout bytes).
- Modes: `--suppress-prompt-submit`, `--local-command-mode`, `--inject-harness-turn`, `--exit-no-eof`, `--vt100-panic-bytes`, `statusline-echo`, `agents --json`.
```
**New:**
```
- It follows a JSON turn script (`--script`) for PreToolUse, PermissionRequest, PostToolUse and Stop steps. Each gated step waits for the next line the test appends to `--control <path>` (always `<home>/fake/<name>.control`; the fake agent reads it by byte offset). This gives deterministic ordering without sleeps. A Rust test and a Playwright spec (§3 `run` step 3) release steps the same way.
- It writes receipt lines to `--receipt <path>`, covering received prompts (text, raw hex, `bare_esc`), keystrokes, env names, Unix fds, and hook invocations (exit code, stderr length, stdout bytes).
- Modes: `--suppress-prompt-submit`, `--local-command-mode`, `--inject-harness-turn`, `--exit-no-eof`, `--vt100-panic-bytes`, `--report-version <ver>`, `statusline-echo`, `agents --json`. `--report-version` changes only the `--version` answer. Fixture replay still follows `--cli-version` / `--fixtures`, so a home stamped for a fixture version can run an unlisted reported version (Path 7).
```

### Patch 3: Reconcile §6 `--session` labels and Path 2's literal `agent-run cleanup` with the nextest boot model
**Reason:** Downstream Readiness. §3 says session ids are `<test name>-<pid>` and no test shells out to `agent-run`. Path 2/7 use fixed ids, and Path 2's Cleanup is a shell-out.
**Old:**
```
- In §6, a step written `agent-run boot --session <id> <flags>` means `harness_session` with those flags.
```
**New:**
```
- In §6, a step written `agent-run boot --session <id> <flags>` means `harness_session` with those flags. A Cleanup written `agent-run cleanup --session <id>` means harness `cleanup` as defined below. The `<id>` there (`p2`, `p7`) is only a readable label. The real session id always follows the `<test name>-<pid>` rule below, so parallel tests never share a session.
```

### Patch 4: Make Path 7's stamped-but-unlisted boot expressible
**Reason:** Downstream Readiness. As written, boot step 4 would run verify against a version with no fixtures and fail with `verify-failed`, so the scenario can't run.
**Old:**
```
`agent-run boot --session p7 --unstamped --instance builder --ui`. Separately, boot a stamped home whose fake agent reports `--cli-version 0.0.0-unlisted`.
```
**New:**
```
`agent-run boot --session p7 --unstamped --instance builder --ui` (no stamps at all). Separately, `agent-run boot --session p7-stamped --instance builder:--report-version 0.0.0-unlisted --ui`. Boot step 4 stamps the default fixture version, because the `claude` copy on PATH runs without instance args. `builder` answers `--version` with `0.0.0-unlisted` but replays the stamped version's fixtures (§7 `--report-version`). Steps 2–4 run against both sessions, with the same verdicts.
```

### Patch 6: Give the web-spa state-strip copy and width signals an owning suite
**Reason:** Test Scope Faithfulness. The Sec 2 web-spa signals "fixed state-strip copy" and "`scrollWidth <= clientWidth` at 1024 and 760–1023" appear only in §1, and no §6 spec plans them.

**New:**

### Patch 7: Replace §11 CI bans that contradict §9/§12, and add the browser-skip and exclusion-regex bans
**Reason:** Anti-Pattern Relevance. "Skip caching" contradicts §12 Browser caching and the §9 E2E row. "Run sequentially" contradicts the `fixed-port` group and the single-job mutation/fuzz stages. The browser-skip and coverage-exclusion back doors are unbanned.
**Old:**
```
- NEVER run sequentially when you can parallelize (unit + integration are
  parallel-safe with proper isolation)
- NEVER skip caching of dependencies (slows agent feedback loop)
```
**New:**
```
- NEVER serialise tests outside the nextest `fixed-port` group. Isolation comes from the per-test home. The mutation and fuzz stages are single jobs by design (§9), which does not license `max-threads = 1` anywhere else.
- NEVER add a cache beyond Swatinem/rust-cache in `ci.yml`. npm and Playwright browsers are deliberately not cached (§12 Browser caching).
- NEVER let `run --all`, `run --browser` or `viola-harness gate` pass on ubuntu with the `playwright` suite missing or skipped (§3 `run` step 3, §3 `gate`).
- NEVER widen the coverage `--ignore-filename-regex` (`viola-fake-agent|crates/viola-e2e|tests/support|fuzz/`) to pass a gate. It is a back door to lowering the §10 thresholds and needs a Decisions Log entry first.
```
