## Patches

### Patch 1: Require a full-history base for the mutation diff; fail on a missing base instead of passing on an empty diff
**Reason:** Downstream Readiness. The default shallow CI checkout has no PR base commit, so the three-dot diff fails or comes out empty. cargo-mutants then tests 0 mutants, which §10 accepts as `"mutants":{"tested":0}`. The Founder Direction 1 gate silently goes green.
**Old:**
```
     - Base: `AGENT_RUN_CHUNK_BASE`, or else `git merge-base HEAD origin/main`.
```
**New:**
```
     - Base: `AGENT_RUN_CHUNK_BASE`, or else `git merge-base HEAD origin/main`. In CI the mutation job sets `AGENT_RUN_CHUNK_BASE=${{ github.event.pull_request.base.sha }}` and checks out with `actions/checkout` `fetch-depth: 0`, because the default shallow clone has no base commit for the three-dot diff. If the base commit is not reachable (`git cat-file -e <base>^{commit}` fails), `run --mutants` exits 1 with `reason:"base-missing"`. It never writes an empty `chunk.diff`, which cargo-mutants would report as zero mutants, i.e. a false `"mutants":{"tested":0}` pass.
```

### Patch 2: Define what `suites[].skipped` counts, and the doctest parse source
**Reason:** Downstream Readiness / Tier Calibration. `gate` breaches on `skipped > 0`, but `skipped` is undefined. If filterset-excluded or cfg-compiled-out tests counted, every layered nextest run would breach. If nothing counted, `#[ignore]` parking would pass. The `doctest` suite has no JUnit to build from.
**Old:**
```
  - Built from `target/nextest/ci/junit.xml`, `e2e-web/pw.json`, `mutants.out/outcomes.json` (`survived` = missed + timeout), `cargo llvm-cov report --json --summary-only`, and the hyperfine `--export-json` files.
```
**New:**
```
  - Built from `target/nextest/ci/junit.xml`, `e2e-web/pw.json`, `mutants.out/outcomes.json` (`survived` = missed + timeout), `cargo llvm-cov report --json --summary-only`, and the hyperfine `--export-json` files.
  - `skipped` counts only tests that were selected and then not run: JUnit `<skipped/>` entries (`#[ignore]`, Playwright `test.skip` / `test.fixme`). Tests excluded by the layer filterset (for example `kind(test)` binaries during `nextest-unit`) and tests compiled out by `#[cfg(windows)]` / `#[cfg(unix)]` are never counted, so the `gate` `suite-skipped` breach fires only on a real skip. The `doctest` suite has no JUnit. It is counted from the `test result: … N passed; M failed; K ignored` lines of `cargo test --workspace --doc`, with `ignored` as `skipped`, so doc examples that must not run use `no_run` or a `text` fence, never `ignore`.
```

### Patch 3a: Keep doctests under `--coverage` and name the suite it reports
**Reason:** Downstream Readiness. "Replaces step 1+2" drops `cargo test --workspace --doc`, which contradicts §10 "Doctests are run". The coverage run's suite name and JUnit copy are not tied together here.
**Old:**
```
- `--coverage` replaces step 1+2 with `cargo llvm-cov nextest --workspace --features fake-agent --profile ci --lcov --output-path target/lcov.info --ignore-filename-regex '(viola-fake-agent|crates/viola-e2e|tests/support|fuzz/)' --fail-under-lines 85 --fail-under-functions 95 --fail-under-regions 80`.
```
**New:**
```
- `--coverage` replaces the nextest invocations of steps 1+2 with `cargo llvm-cov nextest --workspace --features fake-agent --profile ci --lcov --output-path target/lcov.info --ignore-filename-regex '(viola-fake-agent|crates/viola-e2e|tests/support|fuzz/)' --fail-under-lines 85 --fail-under-functions 95 --fail-under-regions 80`. That run reports as the single suite `coverage` (JUnit copied as `junit-coverage.xml`, see `gate`). The `cargo test --workspace --doc` run from step 1 still follows it, as suite `doctest`.
```

### Patch 3b: Give each CI job its composition and `gate --require` list
**Reason:** Downstream Readiness. §9 lists separate Unit, Integration and E2E stages and also says Coverage replaces them "in the same job". `gate --require` lists are left to `ci.yml`, which setup-project writes from this plan, so a missing or wrong list means `gate` either breaches with `suite-missing` or doesn't check a suite that actually ran.
**Old:**
```
| Coverage report | `agent-run run --coverage` (cargo-llvm-cov 0.9.1 under nextest; replaces the plain Unit+Integration+E2E runs in the same job) | per OS | rust-cache |
```
**New:**
```
| Coverage report | `agent-run run --coverage` (cargo-llvm-cov 0.9.1 under nextest). In CI this is the per-OS test job. Its one instrumented nextest run replaces the Unit, Integration and `run --e2e` rows, which are the local `agent-run` equivalents, and the doctest run follows it. Each job's last step is `viola-harness gate --require <suites>`: the per-OS test job uses `coverage,doctest`, the ubuntu E2E job (`run --browser`) uses `playwright`, and the Perf, Mutation, Fuzz replay and MSRV jobs use `perf`, `mutants`, `fuzz-replay` and `nextest-unit` respectively | per OS | rust-cache |
```

### Patch 4: Assert the CLI `[RB]` for the same send that flips the tape and marker readbacks
**Reason:** Cross-Surface Coordination. The trigger requires one `send` to show `[RB]` on the CLI and `data-rb="read"` on both the tape line and the outbound transfer marker. E3 checks only the two DOM readbacks, and Path 2 has no transfer marker, so no single send is checked across all three places.
**Old:**
```
  - After the send, the tape line `viola-readback` and the marker `viola-readback` both have `data-rb="read"`, asserted in one `page.waitForFunction` evaluation (the "flips same frame" rule).
```
**New:**
```
  - After the send, the tape line `viola-readback` and the marker `viola-readback` both have `data-rb="read"`, asserted in one `page.waitForFunction` evaluation (the "flips same frame" rule). The `e3` spec runs step 2's send in human mode through `child_process` and, for that same send, asserts stdout `[RB] read back … cursor <n>` before the DOM check. This is the cross-surface-coordination trigger's single-send CLI + tape + marker case.
```
