## Analysis

**1. Downstream Readiness**
- `gate` and `supervise` now have bodies, inputs, output JSON and exit codes. The JUnit copy rule and the closed enums are present. The Status prose says `list`/`ui`, which matches the JSON block. Ownership of the log and status contracts is consistent across §3 Log format, Bootstrap and the closing paragraph. Nothing to patch there.
- **Contradiction found:** §3 `run` step 2 says "there is never a nested `cargo run` inside nextest". But `harness_session` "calls the same library code as the `boot` / `cleanup` commands", and boot step 1 is `cargo build --workspace --features fake-agent`. Nothing tells it to skip that build or where to find the binaries. Under `--coverage`, a nested build writes non-instrumented binaries to `target/debug`, so Paths 2/3/4/6/7/E3/E4 would spawn those and silently drop out of coverage. §10 Perf already has a "binary dir, skip step 1" parameter, but `harness_session` does not use it. Patch 1.
- **Gap:** boot step 7 requires a 303 plus the `HttpOnly; SameSite=Strict` cookie, but the closed `reason` enum has no value for that failure. Patch 2.
- **Gap:** Path 6 step 7 says "boot a second wrapper `overseer` in the same home" inside a `harness_session` scenario. `harness_session` has no add-instance call, so the step cannot be run as written. Patch 8.

**2. Tool Anchoring**
- Installs are pinned in §3 `ci-tool-install` and §9, and they match the catalog versions. cargo-deny and zizmor are chosen as CLIs, not actions.
- Path 6 uses fixed stdin, and override expiry was moved to §4. §11 bans using mock_instant across processes.
- **Gap:** the hook fail-open trigger needs "a forced panic" (test-scope and the research assert_cmd entry). The plan never says how the product is made to panic, so no test seam exists. This is fixed inside Patch 4, which scopes the trigger to the `fake-agent` feature so the release build never contains it.

**3. Test Scope Faithfulness**
- The V6 slash-argument, controls-not-disableable and ledger-probe items now have §5 files. The Windows non-inheritance case is in §4. The `ui/<port>.url` 0600 check is in the sweep.
- **Gap:** V3 "good `?t=` → 303 + HttpOnly / SameSite=Strict cookie" exists only as a harness boot step, not as a test with a verification signal.
- **Gap:** the Security sweep names no file and mixes Rust tools (reqwest/curl) with browser-only checks (axe, the `<img onerror>` DOM check) without saying which runner owns which. It also gives no file for the hook fail-open matrix or the MCP schema-violating calls.
- Both gaps are fixed by Patch 4.

**4. Tier Calibration**
- A browser skip is now a failure, and `gate` treats `skipped > 0` as a breach. The integration filterset excludes `contract_`, so nothing is double-counted. Widening the exclusion regex is banned. No patch beyond the coverage-binary issue in Patch 1.

**5. Performance Budget Coverage**
- Columns are renamed, warm-up and the no-rerun verdict are stated, perf runs on a non-instrumented release build, the real-time SSE smoke is gone, the exclusions are justified, and the spine deadline will be read from the product constant. No patch.

**6. Cross-Surface Coordination**
- **Gap:** the cross-runner rule gives a web bullet to "the spec that the scenario names", but only Path 2 names one. Paths 3, 4, 5, 6, E1 and E3 name no spec, so their Playwright bullets have no owner. Iteration 4's changelog says a default spec was added, but that text is not in the draft. Patch 3.
- **Gap:** Path 3 lists MCP `wait` as a surface, but the only rmcp `wait` call is on a dead instance, so no live MCP wake is ever checked. Patch 7.

**7. Anti-Pattern Relevance**
- The CI caching and parallelism bans now agree with §9/§12.
- "NEVER violate test pyramid" is still generic, and there is no ban on checking a multi-surface path on one surface only. Patch 6 fixes both and is small. The other missing bans (-32603 text, row `name` used as a target) are already enforced by tests, so they are left for a later iteration.

**8. E2E Selector Strategy**
- **Anchor still present:** `role="cell"` is anchored upstream but missing from the plan's role list, and no rule says how a cell is addressed. Path 3 (STATUS), Path 4 (DIALOG) and Path 5 (WHEEL) all check cell text. `data-live` is not used for waiting on tape lines.
- **Scope:** "axe run over every GUI route" includes JSON routes. Patch 4 limits axe to the page states.
- Patch 5.

## Patches

### Patch 1: Stop `harness_session` from running a nested cargo build and pin where it finds binaries
**Reason:** Downstream Readiness / Tier Calibration. "never a nested `cargo run` inside nextest" contradicts `harness_session` reusing boot step 1 (`cargo build`). Nothing says where the binaries come from, so under `--coverage` the scenarios would spawn non-instrumented `target/debug` binaries.
**Old:**
```
and runs the supervisor as a fixture-owned thread instead of a detached `supervise` process.
```
**New:**
```
and runs the supervisor as a fixture-owned thread instead of a detached `supervise` process. `harness_session` always skips boot step 1, so no `cargo build` runs inside nextest. It passes `viola_e2e::harness::boot` the binary dir found from the test executable's own target dir (the assert_cmd `cargo_bin` lookup), never a literal `target/<profile>`, and boot step 3 copies the fake agent from that same dir. This is the same binary-dir parameter `--perf` uses (§10). As a result, the scenarios spawn the instrumented `viola` / `viola-fake-agent` under `--coverage`, and the plain debug binaries otherwise.
```

### Patch 2: Add a boot reason for a failed token exchange
**Reason:** Downstream Readiness. Boot step 7 requires a 303 plus the `HttpOnly; SameSite=Strict` cookie, but the closed `reason` enum has no value for that failure, so setup-project cannot emit a valid JSON reason when it happens.
**Old:**
```
"ui-port-taken"|"stale-embedded-assets", "instance":<name|null>, "exit_code":<int|null>, "missing":[<unmet readiness checks>]}`. When the reason is `run-exited`, `exit_code` is the wrapper's exit code verbatim (for example 1 for a live endpoint or `stale` heartbeat).
```
**New:**
```
"ui-port-taken"|"stale-embedded-assets"|"token-exchange-failed", "instance":<name|null>, "exit_code":<int|null>, "missing":[<unmet readiness checks>]}`. When the reason is `run-exited`, `exit_code` is the wrapper's exit code verbatim (for example 1 for a live endpoint or `stale` heartbeat). `token-exchange-failed` means boot step 7 got a status other than 303, or a `Set-Cookie` without `HttpOnly` or `SameSite=Strict`. `missing` then names the failed attribute, and the cookie value is never printed.
```

### Patch 3: Give every scenario that names no spec a default Playwright spec
**Reason:** Cross-Surface Coordination / Test Scope Faithfulness. The cross-runner rule gives each web bullet to "the spec that the scenario names", but only Path 2 names one. The Playwright bullets in Paths 3, 4, 5, 6, E1 and E3 have no owning spec (Iteration 4's default-spec text is not in the draft).
**Old:**
```
is owned by a test in the spec that the scenario names, and the test title contains the scenario id (for example `path2`) so `--grep path2` selects it.
```
**New:**
```
is owned by a test in the spec that the scenario names, and the test title contains the scenario id (for example `path2`) so `--grep path2` selects it. A scenario that names no spec defaults to `bay-steady-state.spec.ts`: Paths 3, 4, 5 and 6, E1 and E3. E1's test boots with `--agents-mode recorded`. A spec releases the fake agent's gated script steps by appending to `<session home>/fake/<name>.control` (§7), the same way the Rust test does.
```

### Patch 4: Split the Security sweep by runner, name its files, add the good-token case, scope axe, and give the forced panic a seam
**Reason:** Test Scope Faithfulness (V3 "good `?t=` → 303" has no test; the V4 fail-open matrix and V5 schema calls have no file). Tool Anchoring (no seam exists to force a hook panic). E2E Selector Strategy (axe "over every GUI route" includes JSON routes). Cross-Surface Coordination (browser checks have no runner).
**Old:**
```
- **Security sweep:** reqwest, curl and axe run over every GUI route:
  - wrong-case, trailing-dot, wrong-port and missing Host give 403 with `urn:viola:problem:host-not-allowed`
  - POST, PUT and DELETE give 405
  - no cookie gives 401
  - a bad `?t=` gives 401 with no `Set-Cookie` and with `Cache-Control: no-store`
```
**New:**
```
- **Security sweep:** split by runner, because no nextest test drives Chromium (§3 `run` step 3).
  - The Rust half is `http_security_sweep.rs` in `viola-e2e` (`harness_session`). It runs reqwest and curl over every GUI route, JSON routes included.
  - The browser half is the `security` test in `bay-steady-state.spec.ts`, which owns the `<img onerror>` bullet below. axe runs only on the `/` page states listed in Selector strategy, never on JSON routes.
  - The MCP schema-violating calls live in `mcp_schema_violations.rs`, and the hook fail-open matrix in root `hook_fail_open.rs` (assert_cmd). Its forced-panic case uses a hook panic trigger compiled only with feature `fake-agent`, so `cargo build --release --bin viola` never contains it. The trigger's name is a row in the `cli_controls_not_disableable.rs` table.
  - wrong-case, trailing-dot, wrong-port and missing Host give 403 with `urn:viola:problem:host-not-allowed`
  - POST, PUT and DELETE give 405
  - no cookie gives 401
  - a bad `?t=` gives 401 with no `Set-Cookie` and with `Cache-Control: no-store`
  - a good `?t=` gives 303 with `Set-Cookie: viola_<p>=…; HttpOnly; SameSite=Strict`, asserted by this test and not only inside `boot` step 7
```

### Patch 5: Say how a cell is addressed and how tape arrivals are awaited
**Reason:** E2E Selector Strategy (anchor still present). `role="cell"` is anchored upstream but missing from the role list, and there is no rule for addressing a cell. The STATUS, DIALOG and WHEEL cell checks in Paths 3–5 would fall back to position or CSS classes. `data-live` is unused.
**Old:**
```
- **Role-based queries** follow the design Brand Identity Anchors: `getByRole('table')` for racks, `'row'` for strips, `'columnheader'` for the six captions, `'log'` for the tape and `'status'` for the live region.
```
**New:**
```
- **Role-based queries** follow the design Brand Identity Anchors: `getByRole('table')` for racks, `'row'` for strips, `'cell'` for strip cells, `'columnheader'` for the six captions, `'log'` for the tape and `'status'` for the live region.
- **Cell addressing:** a cell is the `cell` in the `row` filtered by the exact NAME text, taken at the index of the `columnheader` whose accessible name is the caption (for example `WHEEL`). That index is resolved at runtime from the header row, never written as a literal `nth()`. If design reorders or adds a column, the lookup still finds the right cell. If a caption is renamed, the lookup fails in one place.
- **Tape synchronisation:** new tape lines and markers are awaited with auto-waiting locators on `[data-live]` elements filtered by the unique text the test sent, never by a timeout.
```

### Patch 6: Replace the generic pyramid ban with viola-scoped layer and one-surface bans
**Reason:** Anti-Pattern Relevance. "NEVER violate test pyramid" is template text with no link to viola's layers. §11 has no ban on checking a multi-surface critical path on one surface only, which is the gap Patches 3 and 7 close.
**Old:**
```
- NEVER violate test pyramid: heavy E2E with sparse unit tests is
  slow + brittle
```
**New:**
```
- NEVER assert at E2E a case that a lower layer can hold. Parser, refusal-order, threshold and clock cases belong in §4, contract shapes in §5, and §6 asserts only cross-process behaviour (§2 pyramid).
- NEVER assert a multi-surface critical path on one surface only. Every surface a §6 scenario lists needs its own driver step and transition signal, with web bullets owned per the §3 `run` step 3 cross-runner rule.
```

### Patch 7: Check a live MCP `wait` wake in Path 3
**Reason:** Cross-Surface Coordination. Path 3 lists MCP `wait` as a surface, but the only rmcp `wait` (step 7) runs against a dead instance. No live MCP `wait` wake on `turn-ended` is checked.
**Old:**
```
  - `last` gives `{last_assistant_message:"done: …", ts}`, and the MCP `structured_content` is equal.
```
**New:**
```
  - `last` gives `{last_assistant_message:"done: …", ts}`, and the MCP `structured_content` is equal.
  - Live MCP `wait` wake: an rmcp `call_tool("wait", {target:"builder", after:C})` is issued after the step 3 `activity` record is logged and before step 4. It resolves with `is_error:false` and the same `turn-ended` event and `cursor` as the CLI `wait`, never with the `activity` record.
```

### Patch 8: Make Path 6 step 7 use an instance booted at session start
**Reason:** Downstream Readiness. Path 6 cleans up with harness `cleanup`, so it runs under `harness_session`, which has no add-instance call. "Boot a second wrapper `overseer` in the same home" cannot be run as written.
**Old:**
```

```
**New:**
```
Per-instance override: use the session's `overseer` instance. Step 1's `harness_session` boots it alongside `builder`; `harness_session` has no add-instance call, so no wrapper starts mid-session. Re-feed `five_hour` 91 through `viola hook statusline` so the budget is over threshold again.
```
