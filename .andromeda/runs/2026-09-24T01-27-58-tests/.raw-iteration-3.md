## Analysis

**1. Downstream Readiness**
- Iterations 1–2 fixed the big items: `gate` and `supervise` are specified, the closed enums exist, the log and status ownership now reads the same in §3 Log format, the Bootstrap phases and the closing paragraph, and `ci-tool-install` exists. Status prose now says `list`/`ui`.
- **Boot model gap:** §3 `run` step 2 says every `crates/viola-e2e` scenario uses `harness_session`. But Paths 1 and 5 and E1, E2 and E5 use the rstest `stamped_home` chain or a test-owned outer PTY with TempDir drop. That chain lives in root `tests/support/`, which another package cannot import, and the root package must not dev-depend on the tokio-based `viola-e2e`. Setup-project can't build Paths 1/5 (which need the rmcp client, so they must live in `viola-e2e`). → Patch 1.
- **JUnit naming mismatch:** §9 uploads `junit-${{ matrix.os }}.xml`, which nothing produces. §3 `gate` writes `junit-<suite>.xml` under `target/agent-run/artifacts/`. → Patch 2.
- **Path 5 web bullet can't run as written:** under the cross-runner rule, the Playwright spec drives CLI steps through `child_process`. It has no handle on the outer PTY that the supervisor owns, so it can't make the keystroke wheel flip. → Patch 3.
- **E1 web bullet can't run as written:** the unwrapped row needs `FAKE_CLAUDE_AGENTS_MODE` on the `viola ui` that the supervisor spawns, and `boot` has no flag for it. → Patch 4.

**2. Tool Anchoring**
- Installs and versions now match in §9, §3 `ci-tool-install` and the catalog. hyperfine `--input` is anchored in the catalog.
- **Time-seam contradiction:** §11 Universal still bans all "real time without injection". But E2E waits on deadlines inside the product that no test can inject: the confirmation window behind Path 2's mute `no-prompt-submitted`, Path 3's `wait --timeout-ms`, and the chaos SIGSTOP >5 s staleness. No §11 ban covers using mock_instant across processes. → Patch 5.

**3. Test Scope Faithfulness**
- **multi-os-compat "macOS euid + dir-only server verification" is uncovered, and some claims are false on macOS.** The upstream Vector 1 text says "macOS checks euid and the dir only". Yet the §6 exit-cause matrix and the §5 channel bullet assert that a pid/start-time impostor gives exit 21 on every OS, which would be red on macos-latest. → Patch 6, plus a qualifier inside Patch 7.
- **Orphaned trigger items:** grep found no suite for four of them:
  - V2 "at both the client and the wrapper" (wrapper-side rejection with the client bypassed)
  - V2 free-text answers
  - V6 "oversize `answer` JSON"
  - V6 "out-of-range `Percent` in `config.json`"

  → Patch 7.
- Minor and deferred: the error-sanitization check leaves out "tool `input`" and "serde values", and unknown event *kinds* are not asserted explicitly.

**4. Tier Calibration**
- Skip semantics, the contract double-count and the coverage flags are consistent now. §11 still has no ban on widening `--ignore-filename-regex`; deferred because the patch budget ran out.

**5. Performance Budget Coverage**
- Columns, warm-up, the release build, the verdict and the exclusions are all fixed.
- **Gap:** `--perf` needs a live wrapper (and an unstamped one for the `pre-tool-use` row) built from `target/perf`, but nothing says how it boots one. → Patch 8.

**6. Cross-Surface Coordination**
- The cross-runner rule exists. The only impossible cases were Paths 5 and E1 (Patches 3–4). Deferred: Path 3 has no live MCP `wait` wake, and Path 7 leaves web-spa out.

**7. Anti-Pattern Relevance**
- These §11 CI bans still contradict §12: "NEVER skip caching" (browser caching decision) and "NEVER run sequentially" (`fixed-port`). They are lower priority, so they are deferred to the next iteration. The mock_instant cross-process ban is added in Patch 5.

**8. E2E Selector Strategy**
- There is still no `role="cell"` or row × columnheader addressing rule. It is small but lower priority, so it is deferred.

## Patches

### Patch 1: Give the non-harness viola-e2e scenarios a fixture source they can import
**Reason:** Downstream Readiness. §3 step 2 routes every `viola-e2e` scenario through `harness_session`, but Paths 1 and 5 and E1, E2 and E5 use `stamped_home` or a test-owned PTY. That chain exists only in root `tests/support/`, which `viola-e2e` cannot import.
**Old:**
```
- `crates/viola-e2e` scenarios use the rstest `harness_session` fixture. It calls the same library code as the `boot` / `cleanup` commands (`viola_e2e::harness::{boot, cleanup}`), and runs the supervisor as a fixture-owned thread instead of a detached `supervise` process.
```
**New:**
```
- `crates/viola-e2e` scenarios use one of two fixtures, chosen by the scenario's §6 Cleanup line:
       - Cleanup "harness `cleanup`" (Paths 2, 3, 4, 6, 7, E3, E4): the rstest `harness_session` fixture. It calls the same library code as the `boot` / `cleanup` commands (`viola_e2e::harness::{boot, cleanup}`), and runs the supervisor as a fixture-owned thread instead of a detached `supervise` process.
       - Cleanup "TempDir drop" or a test-owned outer PTY (Paths 1, 5, E1, E2, E5): the chain `home → fake_agent_path → stamped_home → booted_wrapper` from `viola_e2e::fixtures`. Root `tests/support/` cannot be imported by another package, and the root package must not dev-depend on the tokio-based `viola-e2e`, so the chain exists twice (the sync root copy and the `viola-e2e` copy) against one contract. In both copies `stamped_home` runs `viola verify` against the fake agent.
```

### Patch 3: Path 5 web bullet driven only by CLI steps the spec can actually run

**Old:**

```
**New:**

After `viola pause builder --json` (step 6) the WHEEL cell reads `human`, and after `viola release builder --json` it reads `driver`. Each state is tied to that command's exit 0. The keystroke-driven flip (steps 2–4) is asserted only by the Rust test, through `events.ndjson`.
```

### Patch 4: Add a `boot` flag so specs can set the fake `claude agents --json` mode
**Reason:** Downstream Readiness. E1's Playwright bullet needs an unwrapped row, which comes from `FAKE_CLAUDE_AGENTS_MODE` on the `viola ui` that the supervisor spawns. `boot` has no way to set it.
**Old:**
```
`scripts/agent-run.sh boot [--session <id>] [--instance <name>[:<fake-agent-args>]]... [--ui] [--unstamped] [--cli-version <ver>]`. The default is instances `overseer` and `builder` plus `--ui`.
```
**New:**
```
`scripts/agent-run.sh boot [--session <id>] [--instance <name>[:<fake-agent-args>]]... [--ui] [--unstamped] [--cli-version <ver>] [--agents-mode recorded|oversize|malformed]`. The default is instances `overseer` and `builder` plus `--ui`, with `--agents-mode recorded`. `--agents-mode` sets `FAKE_CLAUDE_AGENTS_MODE` (§7) via `Command::env` on every child the supervisor spawns and on the `viola list` that `status` runs. It is recorded in `session.json` and `supervise.json`, so a spec can reproduce the E1 unwrapped row.
```

### Patch 5: Limit the real-time ban to test-side code and ban mock_instant across processes
**Reason:** Tool Anchoring (time seams) and Anti-Pattern Relevance. E2E necessarily blocks on deadlines inside the product (Path 2 mute window, Path 3 `--timeout-ms`, chaos SIGSTOP staleness), which the blanket ban forbids. And nothing forbids using `MockClock` across processes, which was the Path 6 defect.
**Old:**
```
- NEVER use real time without injection (use deterministic clocks)
```
**New:**
```
- NEVER use real time without injection (use deterministic clocks) in test-side code: no test-owned timer, sleep or elapsed-time verdict. E2E may block on a deadline inside the product that it cannot inject: the send confirmation window behind Path 2's `no-prompt-submitted`, `wait --timeout-ms` in Path 3, and heartbeat staleness in the chaos SIGSTOP case. Two conditions apply: the verdict is the product's own exit code or status field, and the same deadline is clock-driven in a §4 unit case.
- NEVER use mock_instant `MockClock` (or any in-process clock) to control another process's time. Global mode reaches only threads of the test process, never a spawned `viola run` / `viola ui`. Cross-process expiry is asserted in the §4 unit case, as Path 6 step 7 does.
```

### Patch 6: macOS server verification is euid + dir only; split the exit-cause case per OS
**Reason:** Test Scope Faithfulness. The multi-os-compat item "macOS euid + dir-only server verification" is uncovered, and the pid/start-time impostor case is false on macOS (upstream Vector 1: "macOS checks euid and the dir only").
**Old:**
```
    - server verification fails: `snapshot.json` pid or start time does not match the listening process (a same-user impostor listener on the recorded endpoint)
```
**New:**
```
    - server verification fails. On Linux and Windows: `snapshot.json` pid or start time does not match the listening process (a same-user impostor listener on the recorded endpoint), as a `#[cfg(not(target_os = "macos"))]` case. On macOS the client checks only euid and the socket dir (security excerpt, Vector 1), so the `#[cfg(target_os = "macos")]` case loosens the verified per-user socket dir to 0755 and asserts exit 21. A same-user impostor inside a valid 0700 dir on macOS is an accepted upstream limitation, not asserted as a refusal.
```

### Patch 7: Wrapper-side paste validation, oversize `answer`, out-of-range `Percent` and the macOS qualifier in §5
**Reason:** Test Scope Faithfulness. Grep found no §4–§6 suite for four trigger items:
- V2 "at both the client and the wrapper"
- V2 free-text answers
- V6 "oversize `answer` JSON"
- V6 "out-of-range `Percent` in `config.json`"

Separately, the pid-mismatch bullet is not true on macOS.
**Old:**
```
  - higher `params.v` gives -32602
  - a frame over `MAX_FRAME` gives -32600 and the socket closes (the next read returns 0 bytes)
  - a server pid / start-time mismatch versus `snapshot.json` gives CLI exit 21, and the hook exits 0 with no body
```
**New:**
```
  - higher `params.v` gives -32602
  - a frame over `MAX_FRAME` gives -32600 and the socket closes (the next read returns 0 bytes)
  - a server pid / start-time mismatch versus `snapshot.json` gives CLI exit 21, and the hook exits 0 with no body (Linux and Windows; macOS verifies euid + dir only, see the §6 exit-cause matrix)
  - wrapper-side paste validation (Vector 2, "at both the client and the wrapper", `channel_paste_validation.rs`): the raw client skips `validate_paste_text`. It sends `send` with ESC, DEL or U+0085 in `text`, and `answer` with ESC in a free-text answer and in a revise `message`. The wheel is `human` and the budget is paused, so control-character must win over every other refusal. Each gets `{"refusal":"not-delivered","detail":"control-character"}` from the wrapper, no `send-issued` record is written, and the receipt gains no prompt. The client half lives in `tests/cli_*.rs`: the same inputs through `viola send` / `viola answer` exit 13 before any frame is sent.
  - oversize `answer` (Vector 6): `viola answer` stdin over `MAX_FRAME` exits non-zero with one `--json` error document before connecting. Through the raw client it gets -32600 and the connection closes. In both cases the dialog stays pending (`dialog_pending:true`) and the hook stdout stays empty.
  - out-of-range `Percent` in `config.json` (Vector 6, a case in `tests/cli_controls_not_disableable.rs`): `five_hour` / `seven_day` thresholds of `101`, `-1` and `"90"`. The product may fall back to the default or refuse to start (exit 1). The case fails only if a `send` is accepted after `five_hour` 91 is fed through `viola hook statusline`.
```

### Patch 8: State how `--perf` boots the live wrapper from the non-instrumented build
**Reason:** Performance Budget Coverage. The §10 rows time hooks against a "live wrapper", and the `pre-tool-use` row needs an unstamped CLI. Nothing says how `--perf` boots them from `target/perf`, since `boot` step 1 always builds debug.
**Old:**
```
- **Binary under test:** `--perf` first runs its own non-instrumented `cargo build --release --workspace --features fake-agent --target-dir target/perf`. It never reuses the debug `boot` build or a `cargo llvm-cov` build, and never runs with `LLVM_PROFILE_FILE` set.
```
**New:**
```
- **Binary under test:** `--perf` first runs its own non-instrumented `cargo build --release --workspace --features fake-agent --target-dir target/perf`. It never reuses the debug `boot` build or a `cargo llvm-cov` build, and never runs with `LLVM_PROFILE_FILE` set.
- **Perf session:** `--perf` then calls `viola_e2e::harness::boot` with its binary dir set to `target/perf/release`, skipping boot step 1. It boots session `perf-<pid>` with a stamped `builder` for the spine and SessionEnd rows, plus an `--unstamped` `builder` in a second home for the `pre-tool-use` row. hyperfine gets that home's `VIOLA_NAME` / `VIOLA_DIR` and the fixture payload via `--input`. After the last hyperfine call, `cleanup` must report `ok:true`. A failed boot exits 1 with the boot `reason`, never a missing or skipped perf row.
```
