## Patches

### Patch 1: Resolve the supervisor's fake-agent and fixture paths without CARGO_BIN_EXE or cwd-relative paths
**Reason:** Downstream Readiness. `viola-harness` (a `viola-e2e` bin) cannot read `CARGO_BIN_EXE_viola-fake-agent`, and the relative `fixtures/claude/<ver>` breaks under the nextest per-crate cwd.
**Old:**
```
-- <CARGO_BIN_EXE_viola-fake-agent> --cli-version <ver> --fixtures fixtures/claude/<ver> --receipt <home>/fake/<name>.receipt.ndjson --control <home>/fake/<name>.control <fake-agent-args>`. It drains every master on its own thread.
```
**New:**
```
-- <bin dir>/viola-fake-agent[.exe] --cli-version <ver> --fixtures <workspace root>/fixtures/claude/<ver> --receipt <home>/fake/<name>.receipt.ndjson --control <home>/fake/<name>.control <fake-agent-args>`, where `viola` is also taken from `<bin dir>`. It drains every master on its own thread. `<bin dir>` is the directory boot step 3 copies from: `target/<profile>` for the CLI, the test executable's own target dir for `harness_session`, and `target/perf/release` for `--perf`. The harness never reads `CARGO_BIN_EXE_*`, because Cargo sets that only for the root package's own integration tests. `<workspace root>` is resolved from `cargo metadata` or `CARGO_MANIFEST_DIR/../..` and passed as an absolute path, because nextest runs `viola-e2e` tests with `crates/viola-e2e` as the cwd.
```

### Patch 2: Name the coverage run's JUnit source for `gate`
**Reason:** Downstream Readiness. `cargo llvm-cov nextest` writes JUnit under its own target dir, so the stated copy source is wrong for the `coverage` suite.
**Old:**
```
    - `junit-<suite>.xml`. `run` copies `target/nextest/ci/junit.xml` here right after each nextest invocation (unit, integration, e2e, coverage), because nextest overwrites that path on every invocation.
```
**New:**
```
    - `junit-<suite>.xml`. `run` copies the invocation's `nextest/ci/junit.xml` here right after each nextest invocation, because nextest overwrites that path on every invocation. For unit, integration and e2e the source is `target/nextest/ci/junit.xml`. For coverage it is `target/llvm-cov-target/nextest/ci/junit.xml`, because `cargo llvm-cov nextest` builds and runs in its own target dir. `run` deletes the source before each invocation. If the file is missing afterwards, that is an `artifact-missing` breach, never a copy of an earlier run's file.
```

### Patch 3: State `status` exit semantics
**Reason:** Downstream Readiness. `status` has no exit-code definition, so setup-project cannot tell whether `degraded` / `down` is exit 0 or 1, or what happens when there is no session.
**Old:**
```
  - derived: `api_sessions_equal_list`, which is `/api/sessions.items` deep-equal to `list --json.items`
```
**New:**
```
  - derived: `api_sessions_equal_list`, which is `/api/sessions.items` deep-equal to `list --json.items`
- Exit code:
  - 0 when `ok:true` (`state:"ready"`).
  - 1 for `degraded` or `down`. The full Status endpoint shape document is still printed, so an agent waiting for a `stale` or 503 transition reads exit 1 as a state, not a harness fault.
  - 2 on a usage error, or when no `session.json` exists for the id: `{"v":1,"cmd":"status","ok":false,"reason":"unknown-session"}`.
```

### Patch 5: Remove the cross-process `wait` `timeout_ms` claim from §8
**Reason:** Tool Anchoring (time seams). §8 says `start_paused` in the async crates drives `wait` `timeout_ms`, but §4 root bin says that timer lives in the wrapper process. A paused tokio clock in a test never reaches a spawned wrapper.
**Old:**
```
Async crates (`viola-mcp`, `viola-ui`) use `#[tokio::test(start_paused = true)]` from tokio 1.53.1 `test-util` for the SSE keep-alive and `wait` `timeout_ms`.
```
**New:**
```
Async crates (`viola-mcp`, `viola-ui`) use `#[tokio::test(start_paused = true)]` from tokio 1.53.1 `test-util` for the SSE keep-alive and for any timer the MCP adapter itself owns. The `wait` `timeout_ms` deadline runs in the wrapper process, and only the injected `viola_core::Clock` in the §4 root-bin case drives it. A paused tokio clock in a test never reaches a spawned wrapper (§11 Universal).
```

**New:**

### Patch 8: State the axe boundary without gating a11y conformance
**Reason:** E2E Selector Strategy (axe scope). `analyze()` with `violations == []` runs axe's full default rule set, so the claim that the a11y plan owns the rule set was not true as written.
**Old:**
```
It guards the role-query contract; the rule set is owned by the a11y plan.
```
**New:**
```
The test plan owns only where axe runs and the verdict: an empty `violations` array passes, anything else fails the test. Rule tags, disabled rules and the conformance target come from the a11y plan's configuration, and specs must not add their own `withTags` / `disableRules`. Until the a11y plan names a configuration, axe's default rule set applies unchanged.
```
