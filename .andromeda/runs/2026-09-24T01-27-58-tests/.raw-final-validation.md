Inside the plan, readers will take them as plan §2 (Test Strategy) and §4 (Unit).
  Section: §1 Test Scope Summary (tier justification)
  Severity: medium

  Section: §3 `run` Output format; §3 Closed enums
  Severity: low

- **[DANGLING_REF]** The Trigger → layer map sends "error sanitization / secret logging" to "§6 Security sweep". That coverage actually lives in the separate §6 suite "Error sanitization and secret scan". The Security sweep does not contain it.
  Section: §2 Trigger → layer map; §6 Non-path suites
  Severity: low

- **[CONTRADICTION]** The §3 cross-runner rule says a scenario that names no spec defaults to `bay-steady-state.spec.ts`, and lists E3 and Path 6 there.   Section: §6 Non-path suites header; §3 `run` steps 1–2
  Severity: low

- **[DUPLICATION]** In the §6 Security sweep, the closing paragraph ("The same sweep covers MCP schema-violating calls, the hook fail-open matrix … and the `--home` strict-modes refusals") repeats the earlier bullet that already places MCP schema violations and the hook fail-open matrix. Only the list of fail-open cases and the strict-modes item are new.
  Section: §6 Security sweep
  Severity: low
