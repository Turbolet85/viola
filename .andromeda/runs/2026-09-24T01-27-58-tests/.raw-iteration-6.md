## Analysis

**1. Downstream Readiness**
- `gate` and `supervise` now have bodies, inputs, output JSON and exit codes. The JUnit copy rule, the closed enums and the `list`/`ui` prose are consistent. The obs ownership conflict is resolved. OK.
- The boot model is consistent across all scenarios: harness `cleanup` for Paths 2/3/4/6/7, E3 and E4; TempDir for the rest. OK.
- **Defect: session ids collide.** The session id rule `<test name>-<pid>` gives the same id to two sessions in one test. Path 7 step 1 boots `p7` and `p7-stamped` in one test, so both write the same `target/agent-run/<session>/session.json` and `bin/`. §10 `--perf` has the same problem: it puts a stamped and an unstamped builder "in a second home" under one session `perf-<pid>`, but `session.json` holds one `home`. Patches 1, 2 and 3.
- **Defect: Playwright sessions are worker-scoped, but tests need their own.** §3 `run` step 3 makes sessions worker-scoped ("that spec's flags"). The cross-runner rule then says each scenario test "boots its own session with the scenario's instance flags". Those tests need different instances in the same `bay-steady-state.spec.ts` (Path 2 needs `mute`/`local`; Path 6 needs a statusline config). They also leave destructive state behind (paused budget, human wheel). `bay-degraded` already says "test-scoped", and the session record line says "one per Playwright spec". Patches 4 and 8.
- **Gap: no Playwright config in Bootstrap.** Nothing tells setup-project to create `playwright.config.ts`. That leaves out `retries: 0` (a §10 claim), the `pw.json`/`pw-junit.xml` reporters that `run`/`gate` parse, `headless` and no `webServer` (catalog config). Patch 5.
- **Gap: `status` exit code is unclear.** It is not tied to `ok`, even though `degraded` is an expected state in some scenarios. Patch 7.

**2. Tool Anchoring**
- §9 and §3 `ci-tool-install` versions match the catalog, and cargo-deny and zizmor each have exactly one version source. OK.
- **Defect: time seam for `wait --timeout-ms`.** §11 Universal allows Path 3's real-time `wait --timeout-ms` only if "the same deadline is clock-driven in a §4 unit case". §4 root bin has no `wait` timeout case. §8 assigns it to viola-mcp `start_paused`, but IPC `wait {after?, timeout_ms?}` is enforced in the separate wrapper process. That is the same cross-process fault §11 bans for mock_instant. Patch 6.

**3. Test Scope Faithfulness**
- The Vector 6 slash-arg and controls tables, ledger probes, Windows non-inheritance, wrapper-side paste validation, oversize `answer` and `Percent` are all covered now.
- **Orphan trigger item:** multi-version-compat "unknown event kinds / fields counted in `skipped` rather than failing". `skipped.unknown_kinds` appears only in shape and status listings, and no suite produces or asserts it. The §4 viola-agent-claude "unknown fields counted" bullet is about hook payloads, not event-log readers. Patch in Chaos suite (Patch 6 block, second part), which fits the §7 "corrupt files the product already wrote" exception.

**4. Tier Calibration**
- The skip semantics are closed: Linux browser-missing is a failure, and `gate` treats `skipped>0` as a breach. The integration filterset now excludes `contract_`. The coverage flags match 85/80/95. No patch.

**5. Performance Budget Coverage**
- The columns are honest, and warm-up, the release build, the no-rerun verdict, exclusions and the spine-constant rule are all stated. Only the two-homes-in-one-session defect remains (Patch 3).

**6. Cross-Surface Coordination**
- The cross-runner rule gives every web bullet an owner, and Path 3 now has a live MCP `wait`. The remaining gap is the session scoping above (Patch 4). Path 7 correctly omits web-spa.

**7. Anti-Pattern Relevance**
- The contradictory generic bans are gone, and the viola-specific bans (browser skip, exclusion regex, cross-process mock_instant, one-surface) are present. No patch.

**8. E2E Selector Strategy**
- `cell`, row × columnheader addressing, `[data-live]` waits and axe scope are all stated. No patch.

**Adversarial checks**
- Path 7 run in parallel with itself cannot collide under `<test name>-<pid>`, but within one test its two sessions do.
- A Playwright `path6` test that pauses the budget in a worker session would turn the next `path2` test's `send` into exit 11. Test-scoped sessions close that.

## Patches

### Patch 1: Make the session-id rule reference unique within one test
**Reason:** Downstream Readiness. Path 7 opens two sessions in one test, and `<test name>-<pid>` gives both the same id.
**Old:**
```
The real session id always follows the `<test name>-<pid>` rule below, so parallel tests never share a session.
```
**New:**
```
The real session id always follows the `<test name>-<label>-<pid>` rule below, so neither parallel tests nor two sessions opened by one test (Path 7) share a session.
```

### Patch 2: Define the session-id rule with a label
**Reason:** Downstream Readiness. Same defect, at the rule's definition site.
**Old:**
```
The session id is `<test name>-<pid>`, and each session gets its own temp home.
```
**New:**
```
The session id is `<test name>-<label>-<pid>`, where `<label>` is the §6 `--session` label (`p2`, `p7`, `p7-stamped`) or `main` when the step gives none. Each session gets its own temp home and its own `target/agent-run/<session>/` dir, because a session record holds exactly one `home`.
```

### Patch 3: `--perf` boots two sessions instead of two homes in one session
**Reason:** Performance Budget Coverage / Downstream Readiness. `session.json` has a single `home`, so "a second home" inside session `perf-<pid>` cannot be recorded or cleaned up.
**Old:**
```
It boots session `perf-<pid>` with a stamped `builder` for the spine and SessionEnd rows, plus an `--unstamped` `builder` in a second home for the `pre-tool-use` row. hyperfine gets that home's `VIOLA_NAME` / `VIOLA_DIR` and the fixture payload via `--input`. After the last hyperfine call, `cleanup` must report `ok:true`.
```
**New:**
```
It boots two sessions, each with its own home: `perf-stamped-<pid>` (a stamped `builder`, for the spine and SessionEnd rows) and `perf-unstamped-<pid>` (an `--unstamped` `builder`, for the `pre-tool-use` row). hyperfine gets the matching session home's `VIOLA_NAME` / `VIOLA_DIR` and the fixture payload via `--input`. After the last hyperfine call, `cleanup` must report `ok:true` for both sessions.
```

### Patch 4: Playwright sessions are test-scoped, not worker-scoped
**Reason:** Downstream Readiness + Cross-Surface Coordination. A worker-scoped session with "that spec's flags" contradicts the cross-runner rule, where each scenario test boots its own session with its own instance flags. It would also leak destructive state (paused budget, human wheel, 0770 home) between tests in `bay-steady-state.spec.ts`.
**Old:**
```
Sessions are worker-scoped. A worker-scoped fixture runs `scripts/agent-run.sh boot --session pw-<spec>-<workerIndex> <that spec's --instance / --ui flags>`, and on teardown `scripts/agent-run.sh cleanup --session pw-<spec>-<workerIndex>`. Both must return `ok:true`.
```
**New:**
```
Sessions are test-scoped. A test-scoped fixture runs `scripts/agent-run.sh boot --session pw-<spec>-<test id>-<workerIndex> <that test's --instance / --ui / --agents-mode flags>`, where `<test id>` is the scenario id in the test title (`path2`, `e1`) or the layout-state slug. On teardown it runs `scripts/agent-run.sh cleanup` with the same id. Both must return `ok:true`. No session is shared across tests, because scenario tests in one spec need different instances (Path 2 `mute` / `local`, Path 6's statusline command) and leave destructive state (paused budget, human wheel, 0770 home) behind.
```

### Patch 5: Add the Playwright config to Bootstrap test-runner-install
**Reason:** Downstream Readiness / Tool Anchoring. §10 claims Playwright `retries: 0`, and `run`/`gate` parse `e2e-web/pw.json` and `pw-junit.xml`. No bootstrap slot creates the config that produces them. The catalog gives the reporter, `headless` and no-`webServer` settings.
**Old:**
```
Node side: `e2e-web/package.json` pinning `@playwright/test@1.63.0` and `@axe-core/playwright@4.13.0`.
```
**New:**
```
Node side: `e2e-web/package.json` pinning `@playwright/test@1.63.0` and `@axe-core/playwright@4.13.0`, plus `e2e-web/playwright.config.ts` (catalog configuration):
    - `use: { headless: true }` and a single `chromium` project
    - `retries: 0` and `forbidOnly: true` (a stray `test.only` would silently skip the rest)
    - no `webServer`, and `globalSetup` limited to boot step 1 (§3 `run` step 3)
    - `reporter: [['json',{outputFile:'pw.json'}],['junit',{outputFile:'pw-junit.xml'}]]`, the two files `run` and `gate` read
```

### Patch 6: Add a §4 unit case for the `wait` timeout
**Reason:** Tool Anchoring (time seam) + Test Scope Faithfulness. §11 Universal allows Path 3's real-time `wait --timeout-ms` only if a §4 unit case drives the same deadline by clock, and none exists. §8's viola-mcp `start_paused` cannot control a timeout the wrapper process enforces (IPC `wait {after?, timeout_ms?}`).
**Old:**
```
  - The send-confirmation matcher: normalised `prompt-submitted.text` equals the sent text, and the window expiry gives `no-prompt-submitted`.
```
**New:**
```
  - The send-confirmation matcher: normalised `prompt-submitted.text` equals the sent text, and the window expiry gives `no-prompt-submitted`.
  - The channel `wait` handler with the injected `viola_core::Clock`:
    - it wakes only on `turn-ended` / `question` / `permission` / `plan` / `session-end`
    - it returns at once when a matching record is at or after `after`
    - it returns `{timed_out:true}` only once the clock passes `timeout_ms`, never before
    - this is the §4 case that §11 Universal requires for Path 3's `wait --timeout-ms`
    - the timeout runs in the wrapper process, so viola-mcp `start_paused` tests (§8) cover only a timer the MCP adapter itself owns
```

### Patch 7: Cover the orphaned forward-compat `skipped` counters
**Reason:** Test Scope Faithfulness. The multi-version-compat trigger requires "unknown event kinds / fields counted in `skipped` rather than failing". `skipped.unknown_kinds` / `unknown_fields` are polled but never produced or asserted by any suite.
**Old:**
```
  - forced vt100 panic mode: `send` exits 13 with `input-not-ready`, and human passthrough still reaches the receipt
```
**New:**
```
  - forced vt100 panic mode: `send` exits 13 with `input-not-ready`, and human passthrough still reaches the receipt
  - forward-compat lines (`chaos_forward_compat.rs`, multi-version-compat trigger). Append two lines to a product-written `events.ndjson`, under the §7 exception for files the product already wrote: one with an unknown `kind`, and one known-kind line with an extra unknown field. Then:
    - `list --json` exits 0 and `/api/sessions` returns 200
    - `skipped.unknown_kinds` and `skipped.unknown_fields` each rise by exactly 1 on both surfaces
    - the known-kind line still counts toward item state
    - `wait --after <offset before the append>` does not wake on the unknown-kind line
```

### Patch 8: Align the session record line with test-scoped Playwright sessions
**Reason:** Downstream Readiness. Keeps the §3 session record line consistent with Patch 4.
**Old:**
```
allows parallel sessions (one per Playwright spec)
```
**New:**
```
allows parallel sessions (one per Playwright test, per §3 `run` step 3)
```
