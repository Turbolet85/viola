## Relevance
partial: the plan has no section on an interrupted `viola verify`. The chunk's stop path and its two literal moves fall under the plan's general CLI-integration, unit, mocking, coverage and per-OS rules, which bind them here.

## Constraints
- The stop path is cross-process: a `viola verify` child the test spawns, stopped by a signal, then its dirs read back. Per test-plan §2 Test Strategy (pyramid row "Integration": process boundaries, real tempfile home, assert_cmd against `CARGO_BIN_EXE_viola`), the observable leg belongs at integration. Per test-plan §11 Test Strategy ("NEVER assert at E2E a case that a lower layer can hold"), the stop ordering (child ended and reaped before any guard removes a dir) and any pure ending decision belong in §4 inline unit cases.
- Per test-plan §11 Test Strategy, a Linux-only run never proves Windows. The `cfg(windows)` console-control arm is verified only on the `windows-2025` leg, and its lines count only there. Test-plan §10 Coverage thresholds (Stack adjustments) gates each OS job on its own `cfg` code (Comprehensive: `--fail-under-lines 85 --fail-under-functions 95 --fail-under-regions 80`). So a Windows arm with no Windows-run case lowers that leg's number. Which console events a test can raise on the runner is research's question.
- Per test-plan §10 Coverage thresholds (Stack adjustments, the short-profile mechanism), an instrumented child that is killed during its exit-time profile write leaves a short `.profraw`, and that profile fails the coverage merge. So a test that signals `viola verify` must let it exit by itself and read that exit through `child.wait()`. It never follows the signal with `kill()` in the normal path. Whether a signal that lands before the handler is installed can cut an exit short is research's question.
- Per test-plan §10 Zero-flakiness budget, nextest `retries = 0` applies. A signal-timing race that flakes once keeps the chunk red until its root cause is fixed inside the chunk. No `#[ignore]` parking.
- Per test-plan §8 Mocking & Stubbing Discipline ("Filesystem: not mocked"), the removal is checked on a real tempfile filesystem. The real `claude` is replaced only by `viola-fake-agent`. Process doubles are allowed only for traits the product already defines at its seams (`Pty`, liveness, `Clock`).
- Per test-plan §7 Test Data & Fixtures (test data lifecycle, "Per-test"), each test owns its own home. The env is set per child with `Command::env`, never `std::env::set_var`. A test therefore gives the verify child a cwd it owns (where `.viola-verify-<pid>` and its siblings land) and, if it observes Run A's OS-temp dir, an OS temp root it owns, rather than reading the shared temp root. Whether verify's Run A dir follows the child's temp-dir env var is research's question.
- Per test-plan §5 Integration Test Strategy (Cross-module patterns, CLI: the `tests/cli_verify.rs` bullet), verify's human lines, the seventeen step lines, the `stamped <ver>  <n> pass  <m> fail` last line and "no run dir left behind" are pinned against the fake agent. A run that is not interrupted must keep every one of them unchanged.

## Patterns to follow
- `tests/cli_verify.rs` drives verify's four interactive runs against the fake agent and already asserts "no run dir left behind". The interrupted arm extends that file's assertion to the stop paths (test-plan §5 Integration Test Strategy, CLI). A mid-run stop needs a child the test can signal. Use the one started-child guard and runner in `tests/support/cli.rs` (`Running` / `spawn`; test-plan §2 Test Strategy, directory conventions), not a blocking assert_cmd `.assert()` (test-plan §11 E2E).
- Unit cases go inline in `#[cfg(test)] mod tests` of `src/cmd/verify.rs` / `src/cmd/verify/typed.rs`. Names follow `<subject>_<condition>_<expected>`, and tables use rstest `#[case::<label>]` (test-plan §4 Unit Test Strategy, Conventions). The ending order runs through the existing `Pty` seam. `SharedPty` is generic over its `Pty` and is reached through a test-only recording double (test-plan §10 Mutation gate, the chunk 2026-10-13-epoch-4-survivors-ii disposition). The existing `ctrl_c_ending` / `ended_by` cases must stay green.
- Homes are fresh per test, created by viola inside a `tempdir_in("<workspace root>/target/e2e-home")` parent (the `home` / `stamped_home` fixtures). That keeps any line the run writes inside G2, G4 and the secret scan (test-plan §5 Integration Test Strategy, Setup / teardown lifecycle; test-plan §3 Test data bootstrap, Mechanism).
- Fault injection uses plain `std` / OS process operations on the child's own pid (test-plan §2 Test Strategy, "Chaos / Fault" row). The test sends SIGINT and SIGTERM only, never SIGKILL: what a kill leaves is out of scope.

## Anti-patterns to avoid
- Never import the product's own constants as the oracle. A test that pins verify's argv writes `claude` and `--settings` as literals, never `viola_agent_claude::PROGRAM` / `statusline::SETTINGS_FLAG` (test-plan §11 Unit).
- Never use `sleep(N)` to wait for the run to reach a probe before the signal. Wait for an explicit signal from the product or the fake agent (a stdout step line, a receipt entry). Never detect the child's end by reading master EOF: use `child.wait()` on the handle (test-plan §11 E2E; test-plan §11 Universal, no test-owned timer).
- Never run `viola verify` against the real CLI in CI. The stop is proven against the fake agent alone (test-plan §11 Test Strategy).

## Contract bindings
- tests ↔ obs: any `obs_event!` line the interrupted run writes lands in the test home's role files. The §9 test job scans those files with G2 (zero `panic` lines), G4 (schema conformance) and the secret scan. A handler panic, or a line outside the diag-line schema, reds the leg (test-plan §5 Integration Test Strategy, Setup / teardown lifecycle; test-plan §9 CI Integration, Test report format). Which line, if any, is obs-plan's event catalog's call.
- tests ↔ security: the security rule that Run A's OS-temp dir and `<cwd>/.viola-verify-<pid>/`, `-dialogs/` and `-plan/` are removed on every exit path, with no key typed into any dialog, is the clause the stop-path cases hold. The no-key half is read from the fake-agent receipt, never from the child's screen (test-plan §11 E2E, no screen parsing).
- tests ↔ architecture §Conventions: the interrupted exit status is asserted as the integer exit code, never by `Debug` string (test-plan §11 Unit). Its value is architecture's.
