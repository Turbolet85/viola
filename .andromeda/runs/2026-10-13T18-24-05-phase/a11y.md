# a11y extract

## Relevance
partial: the chunk's only user-facing surface is what `viola verify` writes to the terminal when Ctrl-C or TERM stops it. That is CLI output discipline with no conformance claim. The stop handler, the guards and the two literal moves (`claude`, `--settings`) are out of a11y's reach.

## Constraints
- Per a11y-plan §1 (must-be-accessible path 6, "CLI board, wait/last, verify and launch-line output"), verify's output stays linear and static. Its step lines take the form `[NN/NN] … pass|fail`, and the plan names no other verify line. If the interrupted run prints anything (a step line, a `fail`, a closing line), it is held to the same linear form. Whether an interrupted run prints any line at all, and which one, is for research and design to settle. a11y fixes only its shape.
- Per a11y-plan §1 (Surface: cli → Notes), the plan forbids any SGR, glyph or cursor control under `--json`, non-TTY, `NO_COLOR` or `TERM=dumb`. It also forbids a spinner or a redraw. An interrupt must not leave a partly redrawn line, an erase sequence or a `\r` overwrite on either stream.
- Per a11y-plan §4 P6, `fail` (and `unable`) carry no SGR even under a TTY. Any SGR viola emits sits beside its word. Output under the outer PTY holds no `\r` redraw, cursor-movement or erase sequence.
- Per a11y-plan §8 (Error recovery), a human-mode CLI refusal takes the form `unable  <reason>  <detail>` on stderr, with `hint:` as the last stderr line and a typed exit code. Faults (`error: …`) are not refusals and carry no hint, and `--json` gives one document with no hint. If the interrupted verify reports through either form, that form's rules bind. Which form an interrupt takes, if any, is research's question, read from architecture §Conventions. a11y does not invent one.
- Per a11y-plan §5 (Keyboard Navigation, cli), the cli has no interactive prompt, pager or redraw. The stop path adds no prompt (for example "really stop?") and no wait on a key.
- Per a11y-plan §10 (Standard+ invariants), the CLI output-discipline invariants (P4, P6) pass on all three OS legs inside `nextest-integration` / `nextest-e2e` (in CI, the `coverage` suite). Any new verify output case lands there, not in a separate a11y suite.

## Patterns to follow
- Per a11y-plan §4 P6, the plan's way to check P6 output discipline on all three OS legs is `assert_cmd` + `predicates` for the non-TTY streams and the portable-pty outer PTY for TTY-only behaviour. An interrupted-verify case checks its streams with the same drivers.
- Per a11y-plan §1 (Surface: cli → Automated tool reach), the plan names no a11y tool for terminal output. The stand-in is output-discipline assertions whose pass/fail results reach the harness `run` JSON.
- Per a11y-plan §8 (Plain language), a fixed CLI string is pinned by trycmd or by literal, so a copy change fails CI until the pin is updated on purpose. Any fixed line the stop path prints is pinned the same way.

## Anti-patterns to avoid
- Per a11y-plan §11 (Visual), never colour CLI `unable` / `fail`, and never emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json`.
- Per a11y-plan §11 (Strategy), never claim WCAG conformance for the cli. An interrupted-verify output check is an output-discipline stand-in for SC 1.3.2 / 1.4.1 / 3.3.1, not a11y-tool evidence.
- Per a11y-plan §11 (Cognitive), never show a human-mode CLI refusal without its final `hint:` line (the one exception is `unknown`, exit 14). Never show a stack trace or a bare status number as the only error text.

## Contract bindings
- a11y-plan §9 (CI Integration, the "Unit / integration (all three OS legs)" row) binds a11y to the tests harness. CLI output-discipline cases report through the harness `run` JSON `suites[…]` (`nextest-integration` / `nextest-e2e`, and the `coverage` suite in CI) under the per-OS `test` job's gate. They add no a11y rows and no conformance claim.

## Acceptance criteria contributions
- (a11y) Stop `viola verify` with SIGINT and with SIGTERM under non-TTY. Whatever it writes to stdout and stderr contains no ESC byte, no `\r` redraw and no erase or cursor sequence (per a11y-plan §1 Surface: cli → Notes).
- (a11y) If the interrupted run prints a step line, the line keeps the `[NN/NN] … pass|fail` form and its `fail` carries no SGR (per a11y-plan §4 P6).
- (a11y) If the interrupt surfaces as a human-mode refusal, stderr ends with a `hint:` line and the exit code is the typed one. A `--json` run carries no hint text (per a11y-plan §8 Error recovery).
