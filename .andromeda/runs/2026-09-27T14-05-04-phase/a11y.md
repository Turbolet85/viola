# a11y extract

## Relevance
Partial. The chunk adds no web-spa surface, so the axe, focus, contrast and ARIA work does not apply. It does touch the `viola run` TUI boundary (the `viola-pty` split and the tests for the Windows `HostTerminal::enter` / `host_size` survivors), `viola run` diagnostics routing (the tracing-capture dedupe in `src/cmd/run.rs`), and the harness `run` JSON that the a11y gate reports through.

## Constraints
- a11y-plan §1 (tui surface) sets three boundary clauses for `viola run`. The `viola-pty` `lib.rs` split and any new `HostTerminal` killing tests must keep all three:
  - viola writes zero bytes to the terminal apart from the child's output;
  - human keystrokes are never blocked or delayed past the current atomic paste;
  - focus, mouse and resize sequences pass through and do not count as human editing.
- a11y-plan §4 P4 and §3 Keyboard test harness require each of those clauses to be its own portable-pty outer-PTY nextest case on all three OS legs. Research must answer three questions: whether these cases exist at HEAD, which files hold them, and whether the split moves them with their production code.
- a11y-plan §1 (tui Notes) requires viola's diagnostics for `run` to go to `diagnostics/`, never to the terminal. The shared tracing-capture helper that replaces the `test_capture` / `src/cmd/run.rs` clone must not open a path from `run` tracing output to stdout, stderr or the terminal.
- a11y-plan §9 (Unit / integration row) and §10 (Standard+ invariants) keep the CLI/TUI output-discipline checks inside `nextest-integration` / `nextest-e2e` locally and the single CI `coverage` suite, on all three OS legs, under the tests' mutation gate. New killing tests must land in those same suites.
- a11y-plan §3 CI integration and §9 Pipeline integration say a11y results reach the harness `run` JSON only through `suites[{suite,passed,failed,skipped,artifact}]` and `suites[].failures[]`. The item 4–5 aids may add fields or files but must not rename or remove these, and must not add a `suite` enum value.
- a11y-plan §10 failure conditions and §3 Structured violation JSON schema (Scrubbing) fail the build on any unscrubbed token, `Cookie`, `?t=`, absolute path or `CLAUDE*` value in an a11y artifact. The P7 archive of `outcomes.json` and junit must copy the artifacts as they are and must not produce a less-scrubbed copy. Research must check whether the archived set includes Playwright JSON or JUnit carrying a11y attachments.
- a11y-plan §11 Strategy bans claiming WCAG conformance for the CLI or the `viola run` TUI. New pty or CLI tests are output-discipline evidence only.

## Patterns to follow
- a11y-plan §3 Keyboard test harness (Tooling) sets the per-leg boundary oracle:
  - Linux and macOS: compare byte for byte against an unwrapped `viola-fake-agent` run under the same outer PTY.
  - Windows ConPTY: check only that viola's own literals are absent, because ConPTY emits its own `ESC[?9001h …` preamble on every spawn.
  - Windows `HostTerminal` killing tests should follow the Windows form.
- a11y-plan §12 D-A11Y-13: portable-pty stays at the inherited `=0.8.1` pin, and a11y does not re-pin it. The split changes no dependency pin.
- a11y-plan §3 CI integration: new checks go into existing suites and gates (`gate --require coverage,doctest` for nextest-hosted boundary checks). Do not create a new driver or suite.

## Anti-patterns to avoid
- a11y-plan §11 Universal bans parsing the rendered `claude` TUI screen for content or using screenshots as evidence (R7). Killing tests for `HostTerminal::enter` / `host_size` assert on viola's own boundary behaviour, never on child screen content.
- a11y-plan §11 Keyboard bans blocking, refusing or delaying a human keystroke in `viola run` past the current atomic paste. The same section bans counting focus, mouse or resize sequences as editing. The `viola-pty` split and the item 7 test-only hold must not change either behaviour.
- a11y-plan §11 CI bans adding a `suite` value such as `a11y`, and §11 SLO bans parking a check with `#[ignore]`, quarantine or retry. This applies to the new killing tests and to the two recurrence-watch tests.

## Contract bindings
- a11y ↔ tests harness contract (tests §3, 5 commands with one JSON document each): a11y reads its verdict from the `run` JSON `suites[]` and `gate`. Any field the aids add must be additive (per a11y-plan §3 CI integration and §9).
- a11y ↔ obs log format: `viola run` tracing lines go to `<home>/diagnostics/run-<name>.ndjson`, never to the terminal. This matters for the tracing-capture dedupe (per a11y-plan §1 tui Notes and §3 Structured violation JSON schema).
- a11y ↔ tests portable-pty driver: the three boundary clauses sit on the tests' outer-PTY driver. The `viola-pty` split must keep every symbol those cases import reachable at its current path (per a11y-plan §3 Keyboard test harness and §12 D-A11Y-13).

## Acceptance criteria contributions
- The three `viola run` boundary nextest cases pass on the windows, macos and ubuntu legs after the `viola-pty` `lib.rs` split, unchanged and inside the `coverage` suite: zero viola-originated bytes, keystrokes unblocked past the atomic paste, and focus/mouse/resize not moving the wheel. If research finds any case missing at HEAD, it is reported, not silently assumed (per a11y-plan §4 P4).
- After the tracing-capture dedupe, the `viola run` outer-PTY stream carries no viola diagnostic or refusal literal, and `run` tracing lines land only in `diagnostics/` (per a11y-plan §1 tui Notes).
- The harness `run` JSON keeps `suites[{suite,passed,failed,skipped,artifact}]` and `suites[].failures[]` field for field, and no new `suite` value appears. Any added field or file is named in the plan as additive (per a11y-plan §3 CI integration).
- The new `HostTerminal` / channel / state killing tests contain no rendered-child-screen assertions, no `#[ignore]` and no retry wrapper (per a11y-plan §11 Universal and §11 SLO).
