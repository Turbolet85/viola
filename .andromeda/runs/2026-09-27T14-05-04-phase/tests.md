# tests extract

## Relevance
Relevant. The chunk works on the test harness itself (pre-push, `run --mutants`, loop aids), adds tests to kill surviving mutants, removes duplicated test fixtures and capture layers, and moves inline tests during the file splits. It adds no product surface, so no E2E path is in play.

## Constraints
- test-plan §3 (opening contract and "Closed enums") requires every harness command, `pre-push` included, to keep printing exactly one JSON document and a typed 0/1/2 exit. A new `reason`/`detail`/`stage` value or field needs a Decisions Log entry (§3 Closed enums: "A new value needs a Decisions Log entry"). This applies to any field items 4–5 add (scratch bytes for the Windows leg, archived `outcomes.json`/junit paths, a scoped mutants mode). Whether `pre-push` already reports a Windows scratch field is for research to answer. §3 `pre-push` names `cache{…scratch_bytes,…scratch_bytes_after}` only for the Linux-side `~/viola-pre-push-scratch`.
- test-plan §3 `pre-push` and §10 Mutation gate require the local verdict to stay the union of both legs (`ubuntu-latest` in WSL, `windows-2025` on the host), with the same `base` on each leg, then `gate --require mutants --mutants-legs ubuntu-latest,windows-2025`. A scoped `run --mutants` inner loop (item 5, P3) may only be a local aid. It must never replace the whole-chunk base from §3 `run` step 4 or become the verdict. CI's `mutants-verdict` job stays the verdict of record (§10).
- test-plan §3 `run` step 4 Command requires mutation runs to use `AGENT_RUN_KEEP_HOMES=0` and `AGENT_RUN_KEEP_FAILED=0`. The "keep a failed test's home" aid (item 5, P3) must fit the existing `AGENT_RUN_KEEP_FAILED=1` → `TempDir::keep()` rule and owner-record reaping in §3 Test data bootstrap. It must not leak kept homes into mutation runs. Whether the harness already honours `AGENT_RUN_KEEP_FAILED` end to end is for research to answer.
- test-plan §9 Test report format and §3 `secret-scan` bar `mutants.out/` from ever leaving the machine, because `outcomes.json` holds absolute argv paths. Archiving `outcomes.json` and junit into a run's record (item 5, P7) must stay local, stay outside the upload paths, and not break the scan scope. That scope covers everything under `target/agent-run/` except `chunk.diff`, so an archive placed there gets scanned.
- test-plan §10 Mutation gate and §3 `gate` (union) require the Windows-only survivors (item 3) to be killed on the leg that compiles their `#[cfg]` body, or proven unviable there. A survivor counts only if no judged leg catches it. Per §3 `run` step 4 Test scope, each killing test must sit in the mutated crate's own tests (`viola-channel`, `viola-state`, `viola-pty`), never in `viola-e2e` scenarios.
- test-plan §4 Conventions requires inline `#[cfg(test)] mod tests` in the same source file. §9 Lint requires the cargo-modules orphans gate (`scripts/orphans-check.sh` ending `N/N targets clean`). Each split (item 1) must therefore move a module's inline tests with its production code. It must not create an out-of-line test module that the orphans gate reports.
- test-plan §10 requires coverage of ≥85% lines, ≥95% functions and ≥80% regions per OS, plus the zero-flakiness budget (`retries = 0`; the chunk stays red until the root cause is fixed). The splits and dedupes must not lower any floor. Both recurrence watches (item 7) are handled as quarantine-and-fix, never with retries or `#[ignore]`.

## Patterns to follow
- A forced-window reproduction before a fix (item 7): per test-plan §12 (2026-09-2x entries at lines ~1895–1899), a test-only hold widens the race window, the red signature is measured against a green control, and the change is then re-run green, all through a `fake-agent`-only seam that release builds do not contain.
- test-plan §3 `run` step 1: copy JUnit to `artifacts/junit-<suite>.xml` right after each nextest invocation, because nextest overwrites the file. An `outcomes.json`/junit archive (P7) should use the same copy-before-overwrite approach, and a missing source is a failure, never a stale copy.
- test-plan §3 `pre-push` Sync: the Linux scratch dir sits outside the copied tree, is wiped and recreated at the `cache` stage, and is counted in `cache{scratch_bytes,scratch_bytes_after}`. This is the model for the Windows D: scratch (item 4).
- test-plan §3 `pre-push`: every WSL call is `wsl.exe -d Ubuntu --exec /usr/bin/env -i …`, never the `--` form and with no inherited environment. The `scripts/wsl-exec.sh` wrapper (item 5, P11) must keep this.
- test-plan §7 and §11 Integration: shared fixtures come from rstest `#[fixture]` chains, and env is set per child with `Command::env`, never `set_var`. The deduped endpoint fixtures and tracing-capture helper (item 2) should follow this.

## Anti-patterns to avoid
- Retries of any kind, `#[ignore]`/skip parking, or `sleep`-based synchronisation for the two recurrence-watch tests (per test-plan §11 CI / Quality / E2E, §10 Zero-flakiness budget).
- Trusting the cargo-mutants exit code alone, or treating a scoped or one-leg inner-loop result as the verdict (per test-plan §11 Quality, §11 Test Strategy "NEVER treat a Linux-only local run as proof for Windows").
- Widening `COVERAGE_IGNORE` or moving test helpers into ignored trees to keep the split files under a coverage floor (per test-plan §11 CI).

## Contract bindings
- tests ↔ security: `pre-push` scratch dirs and archived `outcomes.json`/junit fall under security's secret-scanning and no-upload rules for `mutants.out/` (test-plan §9 Test report format, §3 `secret-scan`; §12 2026-09-25 decision citing security-plan §Bootstrap `secret-scanning-ci-gate`). The Linux `TMPDIR` constant is security-owned (scope item 4).
- tests ↔ obs: the harness JSON documents and kept homes under `target/e2e-home/` feed obs-plan §9 gates G2, G4, the secret scan and uploads (test-plan §3 `logs`, `cleanup` step 6). The keep-failed-home aid must leave homes where those gates read them.
- tests ↔ CI config: the `ci.yml` mutation legs and `mutants-verdict` job stay unchanged. The `pre-push` changes are local only (test-plan §9 Mutation row).

## Acceptance criteria contributions
- `viola-harness pre-push` goes green end to end, with both legs printing the same `base` and `gate --require mutants --mutants-legs ubuntu-latest,windows-2025` returning `breaches: []`. The union reports 0 survivors for the audit's `viola-channel` (4), `viola-state` (2) and `viola-pty` (5) mutants, each caught or unviable on its compiling leg (per test-plan §10 Mutation gate, §3 `gate`).
- On every OS, `agent-run run --coverage` then `gate --require coverage,doctest` passes at ≥85% lines, ≥95% functions and ≥80% regions. `scripts/orphans-check.sh` ends `N/N targets clean` after the splits (per test-plan §10, §9 Lint).
- Every harness document changed by items 4–5 (`pre-push` cache report, `run --mutants`) still prints one JSON document with a 0/1/2 exit. Each new field or enum value appears in a test-plan §12 Decisions Log entry (per test-plan §3 Closed enums).
- No archived `outcomes.json`, junit or kept home is uploaded or appears outside the secret-scan scope. `mutants.out/` stays un-uploaded (per test-plan §9 Test report format).
