# security extract

## Relevance
partial. The chunk adds no product surface. It does move security-bearing code (channel listener, PTY spawn), touches the pre-push WSL boundary and the test seam in `src/cmd/run.rs`, and makes harness artefacts outlive a run (archived `outcomes.json`/junit, kept failed-test homes).

## Constraints
- The `crates/viola-channel/src/server.rs` split must keep every IPC listener control in place and reachable at the same call sites. On Windows: the protected user+SYSTEM `security_descriptor`, `accept_remote(false)`, first-pipe-instance exclusive bind, `inheritable(false)`. On Unix: the 0700 per-user directory, chmod 0600 after bind, the `peer_creds` euid drop, `try_overwrite` off. (per security-plan §Authentication & Authorization, IPC access control (Windows)/(Unix) and the IPC server-side peer check rows; §Security Anti-Patterns → Authentication, → Code Patterns.) Research must answer which of these the code already implements and where they sit in `server.rs` today.
- The `crates/viola-pty/src/lib.rs` split must keep two properties. First, the spawn never inherits handles (`bInheritHandles = 0`). Second, a `.cmd`/`.bat` child is refused and an absolute resolved path is handed to portable-pty. `PtyError`'s hand-written `Display` must keep fixed messages that never include paths or upstream text. (per security-plan §Data Protection → In transit, Handle inheritance; §Input Validation, Child executable resolution row; §Error Handling → External responses.)
- The tracing-capture dedupe in `src/cmd/run.rs` must leave `hold_pump_start` / `FAKE_AGENT_PUMP_DELAY_MS` exactly as it is: behind `#[cfg(feature = "fake-agent")]`, capped at 5 000 ms, absent from release builds. Item 7's "test-only hold" (forced-window reproduction) must not add a new environment seam unless it gets its own Decisions Log entry. (per security-plan §Input Validation, Test seam row; §Security Anti-Patterns → Universal, the env-var carve-out; Decisions Log `2026-09-27`.)
- The move of the Windows mutation scratch to D: must not widen the WSL boundary. Every pre-push WSL call stays under `env -i HOME=… PATH=…`. The only other assignment allowed is the Linux leg's distro-derived constant `TMPDIR`. The D: scratch path is host-side only, and any host-valued assignment that crosses into WSL counts as a boundary widening that needs a Decisions Log entry. (per security-plan §Secret Management → Storage, Development.)
- `scripts/wsl-exec.sh`: the proposal's form (`wsl.exe -d <distro> --exec "$@"`) has no `env -i`. If pre-push or any harness path routes through the wrapper, it must keep the `env -i` isolation. Research must answer whether the wrapper is only a manual aid or will sit on a gate path. (per security-plan §Secret Management → Storage, Development; Decisions Log `2026-09-27`.)
- Archived `outcomes.json`/junit (P7), the kept failed-test home (P3) and a relocated cargo-mutants `--output` (P10) all hold data that must not be committed or uploaded outside the secret-scan gate. `outcomes.json` holds absolute argv paths, and those paths carry the OS username. A test home holds `diagnostics/` and `ui/*.url` tokens. (per security-plan §Bootstrap phases → secret-scanning-ci-gate, which says why the `mutants.out/` upload was removed and which uploads are admissible unscanned; §Security Anti-Patterns → Secrets, never commit local `--home` test directories.) `.andromeda/runs/` is tracked in git. Research must answer where "the run's own record" lives and whether it is tracked.
- The machete annotation adds only `[package.metadata.cargo-machete]` metadata. Any dependency a shared helper introduces goes through `[workspace.dependencies]` exact pins and `cargo deny check`. (per security-plan §Dependency Security → Pinning, CI integration.)

## Patterns to follow
- The Windows client open in endpoint-fixture helpers shared between `server.rs` and `tests/channel_endpoint.rs` should reuse the SQOS recipe that `tests/channel_sqos_open.rs` pins. Interprocess's default connect is banned as a fallback or test double. (per security-plan §Authentication & Authorization, IPC client-side server verification row; Decisions Log `2026-09-25`.)
- Harness-owned output goes under `target/agent-run/`, which the obs-owned `viola-harness secret-scan` covers. It never prints matched bytes, and scan-gated uploads wait for it. The one unscanned verdict file (`mutants-verdict-<os>.json`) holds repo-relative locations and outcomes only. (per security-plan §Bootstrap phases → secret-scanning-ci-gate; §Secret Management → Secret scanning in CI.)
- Harness-only environment overrides use the `AGENT_RUN_` prefix ("never read by `viola`"), never `VIOLA_`. (per security-plan Decisions Log `2026-09-27`; §Security Anti-Patterns → Universal.)
- Release-build hygiene: `scripts/release-check.sh` keeps confirming that the release build is `viola` only, built without `fake-agent`. (per security-plan Decisions Log `2026-09-27` → Conditions.)

## Anti-patterns to avoid
- Don't let a mechanical split drop or duplicate-and-diverge a listener or spawn control. That covers: an interprocess Windows listener without `security_descriptor`, `ListenerOptionsExt::mode`, `try_overwrite`, inheritable channel handles, and a `.cmd`/`.bat` PTY child. (per security-plan §Security Anti-Patterns → Authentication, → Data Protection, → Code Patterns.)
- Don't add a new environment seam, or let the fake-agent seam reach a release build, without its own Decisions Log entry. (per security-plan §Security Anti-Patterns → Universal.)
- Don't commit, or upload unscanned, anything holding absolute paths, test output or a test home: archived `outcomes.json`/junit, kept failed-test homes, the `mutants.out/` equivalents. (per security-plan §Security Anti-Patterns → Secrets; §Bootstrap phases → secret-scanning-ci-gate.)

## Contract bindings
- security ↔ obs ↔ tests: the artifact canary scan (`viola-harness secret-scan`, obs-plan §9) must also cover any new artefact location P7/P10 add under `target/agent-run/`, or that location must stay out of every CI upload. The CI gate sits in the tests §CI Integration workflow.
- security ↔ tests harness contract: the pre-push `env -i` WSL boundary and the `CLAUDE_CODE_MESSAGING_TOKEN` canary (which reads 0) are part of the gate that items 4–5 change (test-plan §3 harness contract).
- security ↔ arch: `FAKE_AGENT_PUMP_DELAY_MS` is a joint arch + security-plan amendment. Any item-7 hold that needs a new seam amends both.

## Acceptance criteria contributions
- `cargo deny check` (root) and the `fuzz/Cargo.lock` advisories/sources audit pass. The machete change adds no dependency. (per security-plan §Dependency Security.)
- After the splits, a grep of `viola-channel` finds exactly one Windows listener construction path, and it carries `security_descriptor`. There are zero `try_overwrite`/`ListenerOptionsExt::mode` uses. The existing security tests (`tests/channel_sqos_open.rs`, `security_negatives_*`) and `scripts/release-check.sh` pass unchanged. (per security-plan §Authentication & Authorization; §Security Anti-Patterns → Authentication, → Code Patterns.)
- Local `pre-push` stays green. Its `CLAUDE_CODE_MESSAGING_TOKEN` canary reads 0 inside `wsl --exec`, and no new host-valued assignment crosses into WSL. (per security-plan §Secret Management → Storage, Development.)
- CI `secret-scan` passes. `git ls-files` shows no archived `outcomes.json`/junit, kept test home or cargo-mutants output tracked. No new CI upload bypasses the scan gate. (per security-plan §Bootstrap phases → secret-scanning-ci-gate.)

## Relevant amendment history
- **2026-09-27-wrapper-channel — listener hardening as landed: SDDL through windows-sys, chmod 0600 after the bind**: This set the listener controls the `server.rs` split has to carry over unchanged. On Windows, the protected DACL `D:P(A;;GA;;;<user-SID>)(A;;GA;;;SY)` is converted by windows-sys (`Win32_Security_Authorization`) into `ListenerOptionsExt::security_descriptor`, not `SecurityDescriptor::deserialize`. It reads back canonical as `D:P(A;;FA;;;<sid>)(A;;FA;;;SY)`, and the SID may come back as an alias (`LA`). On Unix, the socket is chmod 0600 right after the bind, and `ListenerOptionsExt::mode` is banned because it fails the bind on macOS. The grep acceptance criterion rests on this: one Windows listener path that carries `security_descriptor`, and zero `mode`/`try_overwrite` uses. The `peer_creds` decision and the directory verification are still with their route entries. So research has to confirm what is actually in `server.rs` today and not assume the full control list.
- **2026-09-25-security-prerequisites — SQOS spike passed, SHA-256 crate picked, 0BSD per-crate exceptions**: This decided how the client verifies the server. The SQOS open needs `FILE_FLAG_OVERLAPPED` and reads `SecurityIdentification`. The default interprocess connect reads `SecurityImpersonation` and stays banned. The shared endpoint-fixture helpers between `server.rs` and `tests/channel_endpoint.rs` must reuse the recipe that `tests/channel_sqos_open.rs` pins. The entry also added two per-crate 0BSD licence exceptions (`doctest-file`, `recvmsg`) and ruled that any further exception needs its own entry. That matters if a shared helper adds a dependency.
