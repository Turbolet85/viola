# obs extract

## Relevance
Partial. The chunk adds no new telemetry. Its splits, dedupe and harness aids do move obs call sites, and they touch the obs gates, the upload rules and the path-free rules for harness documents.

## Constraints
- The splits of `viola-channel/src/server.rs` and `viola-pty/src/lib.rs` must keep every boundary event exactly as it is. This includes `channel-request`/`channel-response` with `conn`/`srv_conn` and `corr`, which is required per obs-plan §3 Trace context propagation (D-10). It also includes the PTY seam's `process-start{subject:"claude-child"}`, the handle-wait `process-exit`, and `exit_source:"kill-fallback"`, all required per obs-plan §6 Boundary-call wrappers. The `channel.dispatch` `Drop` guard that logs `-32603` on a worker panic must survive the move, per obs-plan §7 Panic hooks (run worker threads).
- Moving code into submodules changes the tracing `target` field. `target` is a required field holding the Rust module path; obs-plan §6 Required fields gives `viola_channel::server` as its example. Research must check whether any test, schema or harness assertion pins a `target` value. The in-code `filter::Targets` gate works on crate prefixes (obs-plan §6 Per-module log levels), so submodule targets still pass that filter.
- New and moved `*.rs` files must follow the logging bans:
  - only `obs_event!`, with no raw `tracing::{info,warn,error,debug,trace}!` and no raw `event!`, per obs-plan §3 logger-stack-install and §11 Logs;
  - no bare `#[instrument]`: `skip_all` must be the first argument, per obs-plan §9 G1.

  This applies to the shared tracing capture helper that replaces the `viola-channel` `test_capture` / `src/cmd/run.rs` clone pair.
- viola-e2e is exempt from the print lints because it carries its own `[lints.clippy]` table and has no `[lints] workspace = true`, per obs-plan §3 obs-ci-gate-wire (B5). The machete metadata edit to `crates/viola-e2e/Cargo.toml` must keep that arrangement. A CI assertion checks that only `viola-e2e` lacks `workspace = true`.
- The local `viola-harness pre-push` document, and the ubuntu verdict it copies back, carry no absolute path (Windows repo/home path, Linux clone/home path), per obs-plan §8 item 6. This constrains how item 4's D: scratch directory is named in the cache report.
- Mutation-output rules, per obs-plan §8 item 6 and §9 Telemetry artifact handling:
  - `mutants.out/` is never uploaded, because its `outcomes.json` held absolute argv paths and its `log/` held test output;
  - `target/agent-run/chunk.diff` is the only path skipped by the scan, and it is excluded from the `harness-<os>` upload;
  - everything else under `target/agent-run/` is secret-scanned before upload.

  The P7 archive of `outcomes.json` and junit, and any P10 `--output` redirect, must not bring these files into an unscanned or uploaded path.
- A surviving cargo-mutants mutant in obs code is a build failure, per obs-plan §10 Build / deploy failure conditions. It is judged by the per-leg union rule, per obs-plan §9 Pipeline integration (Mutation row). Research must check whether any of the `viola-channel`/`viola-state`/`viola-pty` survivors sit on obs code (`obs_event!` call sites, guards).

## Patterns to follow
- One `obs_event!` per boundary event. `corr`/`conn`/`instance` are passed as explicit typed values and are never recovered from span context across threads (obs-plan §3 Logging stack; §3 Trace context propagation, Internal async boundaries).
- Unit tests capture emitted lines with an in-memory `Vec<u8>` writer and validate them against `schemas/diag-line.v1.json` (obs-plan §9 Pipeline integration, Unit tests row). The deduped capture helper should keep serving this pattern.
- Log only gate and boundary outcomes on the PTY pump. Emit no per-chunk events (obs-plan §11 Telemetry Strategy).

## Anti-patterns to avoid
- No `print!`/`println!`/`eprintln!`/`dbg!` in the product crates' `hook`/`run`/`mcp` paths. The exceptions are the `viola-e2e` harness and the fake agent (obs-plan §11 Logs).
- Never upload `diagnostics/` or harness captures before the secret-scan passes, and never upload `mutants.out/` (obs-plan §11 CI; §8 item 6).
- No new `event` value and no renamed field. A behaviour-preserving split adds neither (obs-plan §11 Logs).

## Contract bindings
- obs ↔ tests §3 harness contract. The `logs`/`status` output shapes, and the JSON document plus typed exit of each harness command, stay identical, except for fields or files that items 4–5 add. The plan must name any such addition (obs-plan §3 Snapshot / paste-to-AI integration).
- obs ↔ tests §10 mutation gate. The per-leg union verdict computed by `pre-push` is a filter before the push, never the verdict of record (obs-plan §9 Mutation row).
- obs ↔ security. The path-free pre-push document and the secret-scan coverage of `target/agent-run/*` enforce the NEVER-log floor and the absolute-path scrub (obs-plan §8 item 6).

## Acceptance criteria contributions
- G1 (bare `#[instrument]`) and the fail-closed raw-`event!` grep in `scripts/lint-probes.sh` both pass over the tree after the splits. Each exits exactly as specified: rg exit 1 for G1, and a clean grep (per obs-plan §9 Gate commands; §3 logger-stack-install).
- The set of `obs_event!` call sites in `viola-channel` and `viola-pty` (event values plus field names) is identical before and after the split. G4 schema conformance passes on real process output (per obs-plan §9 G4; §6 Additive field catalog).
- The `pre-push` document and its cache report, including the new D: scratch-directory entry, contain no absolute path. The existing `pre_push_` unit test and path-grep entry are extended to cover the new field (per obs-plan §8 item 6).
- No archived `outcomes.json`, junit copy or cargo-mutants `--output` directory falls under an upload path that is not scanned first, and `mutants.out/` stays un-uploaded (per obs-plan §8 item 6; §9 Telemetry artifact handling).
