# arch extract

## Relevance
partial. The chunk adds no product surface, but it moves code across crate and module boundaries, adds shared helpers, and lands new harness resources: a D: scratch dir, `scripts/wsl-exec.sh`, archived run artifacts and a cargo-mutants `--output` location. Architecture's workspace, dependency-direction and occupied-resource rules govern all of these.

## Constraints
- **Dependency direction must hold after the splits and the dedupe.** Per architecture §Infrastructure Patterns → Crate dependency direction:
  - `viola-pty` depends on no viola crate. Its normal deps are exactly portable-pty, tracing, windows-sys and libc, with no thiserror.
  - `viola-channel` → `viola-core` plus its listed third-party set.
  - The root bin → all members.
  - So a helper shared between `viola-channel`'s `test_capture` and `src/cmd/run.rs` must live where both may reach it without reversing an edge.
  - Per architecture §Established Decisions [Module Boundaries], no product crate may depend on the test-only `viola-e2e`.
- **No new workspace member.** The member set is locked (architecture §Occupied Resources → Workspace crates; §Established Decisions [Module Boundaries]). A new shared-test-support crate would be an arch amendment, not an implementation detail.
- **tracing-subscriber stays root-bin only.** Its features are `fmt,json,registry,std`, per architecture §Stack and Technologies (Logging row). A deduped capture layer must not add tracing-subscriber to a product crate's normal dependencies. Whether `viola-channel`'s `test_capture` currently uses tracing-subscriber as a dev-dep or a hand-written `Layer` is research's question.
- **Tokio containment for sync crates.** `viola-pty`, `viola-channel` (without its feature), `viola-state` and the other listed sync crates must stay tokio-free in their normal graph. This is checked by the sole-root `deny-sync.toml` ban and target job 3 (architecture §Established Decisions [Concurrency / Backend Framework] KEYSTONE; §Cross-cutting Patterns → Tokio containment).
- **Split files must stay reachable.** Every file a split creates must be reached through a `mod` path, because `cargo modules orphans --deny` is a CI gate per lib/bin target via `scripts/orphans-check.sh` (architecture §Infrastructure Patterns → Build system → Boundary review).
- **Lint inheritance applies to new submodules.** Per architecture §Infrastructure Patterns → Build system (Lint):
  - Product crates inherit `[workspace.lints.clippy]` (the print bans and `dbg_macro`).
  - `viola-e2e` denies only `dbg_macro`.
  - `clippy.toml` `disallowed-macros` bans the tracing level macros, so `obs_event!` stays the only emitter.
  - `viola-pty`'s `PtyError` keeps its hand-written `Display`/`Error` (architecture §Established Decisions [Error Handling]).
- **Pre-push and mutation-gate rules the aids must respect** (architecture §Infrastructure Patterns → CI/CD approach):
  - `pre-push` is Windows-host only.
  - The Linux leg's `TMPDIR=<distro home>/viola-pre-push-scratch` is wiped and recreated at the cache stage.
  - `run --mutants` sets `AGENT_RUN_KEEP_HOMES=0` and `AGENT_RUN_KEEP_FAILED=0` (a mutation run keeps no test home).
  - The full `gate --require mutants --mutants-legs ubuntu-latest,windows-2025` union stays the verdict, with CI on the pushed sha as the verdict of record. A scoped inner loop is a filter only.
  - Stopping rust-analyzer is currently an operator-pass step before `pre-push`. Moving it into `run --mutants` changes the documented pass order.

## Patterns to follow
- **Windows scratch dir:** mirror the Linux leg's scratch pattern, i.e. a dedicated scratch dir outside the copied tree, wiped at the cache stage and reported in the cache report (architecture §Infrastructure Patterns → CI/CD approach).
- **Harness artifacts:** harness outputs live under gitignored `target/` subpaths, one named path per purpose. Examples are `target/agent-run/<session>/`, `target/agent-run/artifacts/` (JUnit, `run-summary.json`, `mutants-verdict-<leg>.json`) and `target/pre-push/` (architecture §Occupied Resources → Repository). Put archived `outcomes.json`/junit in a named per-run path of the same kind.
- **Scripts:** `scripts/*.sh` are fail-closed bash tools, several with a `--probe` self-proof mode (e.g. `wsl-provision.sh`, `orphans-check.sh`, `deny-probes.sh`). `scripts/wsl-exec.sh` joins this set (architecture §Infrastructure Patterns → Project directory structure).
- **Test endpoint names:** keep test endpoints in the `viola-test-chan-<pid>-<label>` namespace, outside `viola-<h12>`, when the endpoint fixtures are deduped (architecture §Occupied Resources → IPC endpoints, Test-only).
- **Harness dependencies:** `viola-e2e` takes syn and proc-macro2 (`span-locations`) for `harness::cfg_legs`. The machete `ignored` entry records that fact and keeps the dep (architecture §Infrastructure Patterns → Crate dependency direction; §Stack and Technologies, Code quality row).

## Anti-patterns to avoid
- Moving a shared helper into `viola-e2e` or into a new crate that a product crate then depends on (architecture §Established Decisions [Module Boundaries]).
- Adding any environment variable for the new aids that lacks the `AGENT_RUN_` prefix, or that the `viola` binary reads (architecture §Conventions → Naming patterns, Environment variables).
- Treating the scoped `run --mutants` inner loop, or the pre-push result, as the verdict in place of the two-leg union and CI (architecture §Infrastructure Patterns → CI/CD approach).

## Contract bindings
- **arch ↔ tests:** the test-plan §3 harness contract (5 commands, one JSON document plus a typed exit per command) is referenced from architecture §Occupied Resources → Binary. Any field or file an aid adds must be named in the plan. The mutation-union semantics (`harness::cfg_legs`, per-leg `base`) are shared with the tests plan.
- **arch ↔ security:** the Linux leg's scratch path is a security-owned, distro-derived constant and is out of scope here. `secret-scan` covers `target/agent-run/` and skips only `chunk.diff`. Archived run records and a relocated cargo-mutants `--output` must not create unscanned copies of repository source text, and `mutants.out/` is never uploaded (architecture §Occupied Resources → Repository; §Infrastructure Patterns → CI/CD approach).
- **arch ↔ obs:** the tracing capture dedupe touches the `obs_event!`-only emitter rule and the obs-owned log format (architecture §Infrastructure Patterns → Build system, Lint; §Cross-cutting Patterns → Diagnostic output channels).

## Acceptance criteria contributions
- No new workspace member. No product crate gains a dependency on `viola-e2e`. `viola-pty`'s normal deps remain exactly portable-pty, tracing, windows-sys and libc. tracing-subscriber appears in no product crate's normal dependencies (per architecture §Infrastructure Patterns → Crate dependency direction).
- `scripts/orphans-check.sh --probe && scripts/orphans-check.sh` passes on every lib/bin target after the four splits (per architecture §Infrastructure Patterns → Build system → Boundary review).
- The sole-root `deny-sync.toml` tokio ban passes for every crate in `scripts/sync-crates.txt`, and target job 3 passes on all three OSes (per architecture §Established Decisions [Concurrency / Backend Framework]).
- Each resource the chunk lands is recorded in architecture §Occupied Resources at wrap: the D: Windows mutation scratch dir, `scripts/wsl-exec.sh`, the archived per-run `outcomes.json`/junit path and any cargo-mutants `--output` dir. Any new env var carries the `AGENT_RUN_` prefix (per architecture §Occupied Resources → Repository / Environment variables).
