## Surface: web-spa

**Tooling context:** Framework Lit 3.3.3 (vendored ESM, embedded via `include_bytes!`, no JS build step). CSS is hand-written modern CSS with no tool: native nesting, `@layer tokens, base, components, states, motion`, and custom properties in the single stylesheet `/assets/app.css`. Components: none. The page is built from plain light-DOM `viola-*` Lit elements (`createRenderRoot(){ return this; }`) over semantic HTML: `<viola-atis>`, `<viola-session-row>`, `<viola-transfer>`, `<viola-readback>`, `<viola-event-feed>`, plus the native `<details>` / `<summary>` for tape lines. State lives only in `data-*` attributes (`data-rb`, `data-dialog`, `data-liveness`, `data-wrapped`, `data-live`). There is no `style="…"`, no `styleMap` and no `unsafeHTML`.

**Token names used in this document.** The same names are used in the cli section. Each points to a design-system role and to its CSS alias in `/assets/app.css`:

| Layout token name | Design-system role | web-spa CSS alias |
|---|---|---|
| `color-surface-base` | Surface Base (console anthracite) | `--surface-bay` |
| `color-surface-raised-1` | Surface Raised-1 (holder boot) | `--surface-strip` |
| `color-surface-raised-2` / `-3` | Reserved (no v1 use) | none |
| `color-surface-inset` | Surface Inset | `--surface-inset` |
| `color-primary` / `color-text-primary` | Primary (strip buff) | `--ink`, `--rb-fill` |
| `color-text-secondary` / `-tertiary` / `-muted` | Secondary / Tertiary / Muted (lamp-off buff) | `--ink-dim` (and the `stale` `--ink` swap) |
| `color-text-on-paper` | On-paper (graphite) | `--ink-on-paper`, `--rb-ink` |
| `color-accent` | Accent (arrival-holder amber, `dialog_pending` only) | `--attention` |
| `color-role-handoff` | Role (departure-holder blue, transfer markers only) | `--handoff` |
| `color-border-subtle` | Border Subtle (rack rail) | `--rule-deco` |
| `color-border-standard` | Border Standard (printed field grid) | `--rule-field` |
| `color-border-emphasis` | Border Emphasis (a border that is a state) | `--rule-info`, `--rb-rule`, `--rb-strike` |
| `color-border-focus` | Border Focus | `--focus-ring` |
| `color-border-handoff` | Border Handoff (the blue left tick) | `--handoff` at `--rule-strong` |

Spacing uses `space-micro` · `space-xs` · `space-sm` · `space-md` · `space-lg` · `space-xl`. Geometry uses `--strip-h`, `--line-h`, `--band-w`, `--rb-size`, `--cock-offset`, `--rule`, `--rule-strong`, `--focus-w` and `--focus-offset`. Radius uses `radius-sm` · `radius-md` · `radius-lg`, all resolving through `--radius`. `radius-full` is never used. Tracks come from `--strip-cols`, `--strip-cols-wrapped` and `--tape-cols`. Motion uses `--cock-dur` / `--cock-ease` and `--fade-dur` / `--fade-ease`.

**Expression level (this surface):** 0.3. It allows exactly two motions, each played once on a state change: the cock (`translateX(--cock-offset)` over `--cock-dur`) and the new-line / new-marker opacity fade (`--fade-dur`). The readback fill, the strike, `stale` dimming, a strip's return into line, scroll jumps and text swaps are all instant. The Motion section overrides the 0.3–0.4 calibration row.

**Signature placement:** The readback box (`<viola-readback>`, a `--rb-size` square) appears in two components:
1. At the far right of every `send` line `<summary>` in `<viola-event-feed>`, spanning the last two `--tape-cols` tracks.
2. At the far right of every outbound `<viola-transfer>` marker in the WRAPPED rack gap, once a send on that link has been seen since page open.

It opens (`data-rb="open"`) when a CL-1 `send-issued` line arrives over SSE. That new tape line fades in, and the box itself is drawn without motion.

It fills to `RB` (`data-rb="read"`) instantly when the matching `prompt-submitted` with origin `driver` lands on the driven instance's tape. For a `/clear` send, the trigger is `session-start` with cause `clear`. The tape box and the marker box flip in the same frame.

It takes the `/` strike (`data-rb="refused"`) instantly when a CL-1 `send-refused` arrives, and the reason goes in the word cell. That same moment feeds the polite announcement and the out-of-view refusal copy.

The supporting attention element, the cocked strip, fires on `<viola-session-row>` when its `dialog_pending` reading turns true.

### Primary screens

There is one route (`/`), so the "screens" are the states the single bay passes through. None of them is a separate route.

- **Bay, steady state (≥1024)** is the working view. The ATIS header, the WRAPPED rack with transfer markers, the UNWRAPPED · READ-ONLY rack and the TAPE are all live over SSE.
- **Bay, narrow (760–1023)** is the same bay with each strip wrapped onto two lines, for a half-width window next to two terminals.
- **Bay, first reading / empty** is the first paint before `/api/sessions` answers, and the case where no `viola run` instance exists yet.
- **Bay, degraded** covers a closed tape (`TAPE stopped`) and an unreadable viola home (`unable · state-unreadable`). The strips keep their last values.
- **Tape line, expanded** is an in-place `<details>` disclosure of one event's full text. It is not a route and not a panel.

### Component — Header (`<viola-atis>`)

- **Layout:** a sticky block at the top of the document on `color-surface-base`, with a bottom `--rule` in `color-border-subtle` and `radius-lg`. Inside the page's `space-md` inline margin, it is an inline wrapping row of cells. Neighbouring cells are exactly `space-sm` apart, and the cells have no inline padding. There is no row gap: each line is as tall as its tallest cell (`--lh-display` on the `VIOLA` line, `--line-h` otherwise). A cell wraps only at a cell boundary. It never truncates and never scrolls sideways, and the header grows downward. The `space-xl` top margin of the WRAPPED rack sits under the header's last line.
- **Cell order (fixed), with the typography role and colour of each:**
  1. `VIOLA`: Display, `color-text-primary`. There is no logo mark, no icon and no link.
  2. `BAY`: Label, `color-text-secondary`, followed by `127.0.0.1:47319` in Data, `color-text-primary`.
  3. `5H` / `7D`: Label. The figure (`62 %`) is Data in `color-text-primary`. The word `resets` is Body in `color-text-secondary`, followed by the time in Data. `expired` is Body, boxed with a `--rule` in `color-border-standard`, `space-micro` inline padding and `radius-sm`. The figure keeps its primary ink: old information is shown as old.
  4. `read 4m ago`: always printed. The words are Body and the age is Data, both `color-text-secondary`. The text swaps each minute with no motion.
  5. `gate open`: Body, `color-text-secondary`. When the gate is closed this cell becomes `budget-paused` in Body `color-text-primary`, boxed with `color-border-emphasis`. There is no amber and no red.
  6. `TAPE`: Label, followed by `live since 19:40:02Z` (primary ink, with the time in Data), or `connecting` (`color-text-secondary`), or `stopped · viola ui not answering`, boxed in `color-border-emphasis`.
  7. `skipped 0 · 0 · 0`: Body with Data counts, `color-text-muted` while zero. When a count is nonzero it prints in `color-text-primary`, boxed in `color-border-emphasis`, and it is never cleared automatically.
- **Density:** about 112ch of Body/Data. It takes two lines at 1024 and three or more at 760–1023. When `expired`, `TAPE stopped` or a nonzero `skipped` box appears, the header gains a line and the content below moves down by one `--line-h`, instantly. This is the logged UX-guideline-5 deviation: order is kept, pixel position is not.
- **Never here:** `viola_home`, the token, a version string, a settings gear or a user menu. `/api/info`'s `version` has no slot on the page. The CLI owns version display.

### Component — Primary navigation (rack separators and keyboard order)

- **IA model:** one page, one bay, no nav chrome, no tabs, no sidebar and no breadcrumbs. The four regions stand in a fixed vertical order: (1) `<viola-atis>`, (2) the WRAPPED rack, (3) the UNWRAPPED · READ-ONLY rack, (4) the TAPE. The rack separator labels (`WRAPPED`, `UNWRAPPED · READ-ONLY`, `TAPE`) are the only wayfinding. Each is Heading (uppercase, `--track-rack`) in `color-text-primary` on `color-surface-base`, followed by a `--rule` in `color-border-subtle` that runs to the rack's end edge. The label sits `space-md` above the rack's caption row. Racks are `space-lg` apart, and the tape is `space-lg` below the last rack.
- **Skip link:** `skip to tape` is the first tab stop. It is hidden until focused, then drawn over the header's inline start in Label type on `color-surface-base` with the focus ring. Its target is the tape region.
- **Tab order after the skip link:** every tape `<summary>` from oldest to newest, then the `N new lines below` anchor. Strips, captions and transfer markers are not focusable, because v1 has no controls.
- **Focus:** a `--focus-w` outline in `color-border-focus`, offset `--focus-offset`, `radius-sm`, appearing instantly. The only hover feedback is the underline on the link-styled `N new lines below` anchor and the skip link. There is no hover colour anywhere.
- **Responsive:** at ≥1024 every strip is one line. At 760–1023 strips switch to `--strip-cols-wrapped` / `--strip-rows-wrapped` / `--strip-areas-wrapped`, and the caption row follows the same two-line template. The region order never changes, and a narrow viewport never collapses a rack into a menu.
- **No search, no filter, no command palette.** The tape is capped at 2000 DOM lines. The full record is `events.ndjson`, and the trim notice says so.

### Component — Hero / signature section (no hero; the readback box, with the cocked strip as supporting element)

- **No hero banner.** The eye goes first to the WRAPPED rack under the ATIS header: the bay itself is the product's first view. There is no welcome copy, no illustration and no onboarding.
- **The readback box, anatomy (identical in every place):** a `--rb-size` square `.rb` with a `--rule` outline in `color-border-emphasis` and `radius-sm`, followed at `space-micro` by a word cell in Body `color-text-primary` on `color-surface-base`. It is laid out as an inline grid (`--rb-size` then auto).
  - `open`: interior `color-surface-inset`, word `open`.
  - `read`: fill `color-primary`, with `RB` inside in Data at the Label size, strong weight, `color-text-on-paper`. Word `read back`.
  - `refused`: the outline plus a `--rule`-wide `/` strike in `color-border-emphasis` (the one stylesheet gradient). Word `unable · <reason> · <detail>`, and no dangling `·` when the detail is null.
  - `unconfirmable`: the open drawing, never filled. Word `unconfirmable`.
- **Placement 1, tape send line (in `<viola-event-feed>`):** the box and word are one grid item spanning the last two `--tape-cols` tracks (`--rb-size`, then word / reason), so send-line words line up with each other down the tape. Issue on the left (`send  → builder  <text>`), readback on the right, read as one unit.
- **Placement 2, outbound transfer marker (`<viola-transfer>`):** the same element at the far right of the marker line. It shows the state of the last send on that link. Before any send on the link has been seen since page open, it prints only the word `unknown` with no box. That is deliberate, not a missing signature.
- **Trigger events (all instant, never animated):**
  - SSE `send-issued` (CL-1): a new send line with an `open` box, which gets the ambient `--fade-dur` line fade. The marker's box on that link flips to `open` in place.
  - The matching driver-origin `prompt-submitted` on the driven instance (or `session-start` cause `clear` for `/clear`): the box in both places becomes `read`, in the same frame. The matching `prompt-submitted` does not get its own tape line, because it is folded into the send.
  - SSE `send-refused` (CL-1): strike and reason in both places. The polite announcement reads the refusal ("send to builder unable, not-delivered, input-not-ready").
  - `turn-ended` never touches the box.
  - Until CL-1 lands, only `read` boxes render, and markers print `unknown`.
- **Supporting element, the cocked strip (the High-impact moment):** when a strip's `dialog_pending` turns true, `<viola-session-row data-dialog="pending">` moves by `translateX(--cock-offset)` over `--cock-dur` with `--cock-ease`, once. In the same frame the `--band-w` band slot turns `color-accent`, the DIALOG cell drops to `color-surface-inset`, `DIALOG` prints in `color-accent` at the strong weight, and the kind word stays `color-text-primary` (or `color-text-muted` when the strip is also `stale`). `document.title` becomes `DIALOG overseer · viola` (the first cocked strip by slot, plus `+N`). When the dialog clears, the return into line is instant.
- **Reduced motion:** `--cock-dur` and `--fade-dur` become `0ms`. The offset position and the amber band stay, because they are state.

### Component — Primary content block 1: racks of `<viola-session-row>` strips

- **Rack layout:** a block in document flow made of the separator label, then the caption row, then one strip per session in a single column. Strips are `space-xs` apart, with the same `space-xs` rhythm around transfer markers: strip, gap, marker, gap, strip. The rack reserves end padding equal to `--cock-offset`, so a cocked strip never causes horizontal scroll. Racks use `radius-lg`, with no fill and no border beyond the separator rule.
- **Ordering (the stable-slot rule):** the WRAPPED rack is ordered by `ViolaName` ascending, and the UNWRAPPED · READ-ONLY rack by reported name ascending, both matching `viola list`. State never reorders anything. Only a session starting or ending changes slots. This is not a card grid: every row has the same fixed fields in the same tracks.
- **Caption row:** on `color-surface-base`, never inside a strip, because lamp-off text on the holder fails contrast. Label type, uppercase, `color-text-secondary`. It uses the same grid as the strips below it (`--strip-cols`, empty band track), and each caption carries the cells' `space-xs` inline padding, so it starts exactly where its value starts. The six captions are always drawn, even for an empty rack.
- **Strip anatomy:** a grid on `--strip-cols` with `--strip-h` block size, on `color-surface-raised-1`, with a `--rule` outer edge in `color-border-subtle`, cell dividers in `color-border-standard` and `radius-md`.
  - The band track (`--band-w`) is `color-border-subtle`, or `color-accent` when cocked.
  - NAME is Callsign role in `color-text-primary`, printed exactly as typed. It is never text-transformed and never clipped when wrapped.
  - LIVE, STATUS, WHEEL, DIALOG and CLI are Body in `color-text-primary` with `space-xs` inline padding. `human` in WHEEL is at the strong weight. `budget-paused` is appended in WHEEL as `driver · budget-paused`.
  - A missing reading prints `unknown`. A field that is absent by contract on an unwrapped strip prints `n/a`. A cell is never blank.
- **Per-state instances in the steady-state wireframe:**
  - `builder`: live, lit.
  - `overseer`: cocked, and also holding a readback marker.
  - `scratch`: `stale`, a coasting track. The fill is `color-surface-base`, all ink is `color-text-muted`, the field grid is `color-border-subtle` and the band slot stays rail. The change is instant.
  - `c1f9e2a4-7b…`: an unwrapped bare strip. It has `color-surface-base`, a dashed `--rule` outline in `color-border-subtle`, no band track, and a name that ends in an ellipsis. It is text only, never a link or a target.
- **Narrow (760–1023):** two rows. Row 1 at `--strip-h` holds the band, NAME, LIVE, STATUS and DIALOG. Row 2 at `--line-h` holds WHEEL under NAME + LIVE and CLI under STATUS + DIALOG. A `color-border-standard` rule runs between the rows, and the band spans both. The cock moves the whole two-row block.

### Component — Primary content block 2: transfer markers (`<viola-transfer>`)

- **Placement:** in the rack gap on `color-surface-base`, never on the holder, because blue on holder fails contrast. Each marker is its own `--line-h` item in the rack flow, with `space-xs` above and below.
  - The outbound marker sits directly under the driver's strip.
  - The inbound twin sits directly under the driven strip.
  - A driver with several links gets one outbound marker per link, ordered by driven name.
- **Anatomy (outbound):** indented by `--band-w` plus `space-xs`. A `--rule-strong` left tick in `color-border-handoff`. Then `→ builder`, arrow and name in `color-role-handoff`, Body. Then `since 19:43:58Z` in Data, `color-text-secondary`. The rest of the line is empty up to the `<viola-readback>` at the far right (signature placement 2).
- **Anatomy (inbound twin):** the same indent and tick, then `← overseer` (arrow and name in `color-role-handoff`), with no box and no `since`.
- **Motion:** a marker created by an SSE `link` event is marked `data-live` and fades in over `--fade-dur`. An `unlink` removes it instantly. Strips below shift by the marker line and its gap, with no animation and no change of order. There is no node graph, no curve and no connector drawn between strips.

### Component — Primary content block 3: the tower tape (`<viola-event-feed>`)

- **Region:** the last region of the bay, on `color-surface-base` with `radius-lg`. It is headed by the `TAPE` separator (Heading), with `UTC` beside it in Label `color-text-secondary`.
- **Scrolling:** the tape is the page's only bounded scroll region. It fills the viewport below the racks, with a floor of ten `--line-h` lines, so the racks, and with them any cocked strip, stay in view while the founder reads history. The page itself scrolls only when the racks plus that floor exceed the viewport.
- **Line anatomy:** each line is a `<details class="tape-line">`. Its `<summary>` is a grid on `--tape-cols` with `space-xs` column gap and `--line-h` block size. The native disclosure marker is hidden and nothing replaces it.
  - TIME `HH:MM:SS.mmm`: Data, `color-text-tertiary`.
  - INSTANCE: Body, `color-text-primary`, ellipsis at the track maximum. On send lines it prints the sending instance, because the arrow names the receiver.
  - KIND: the kind word in Body.
  - TEXT: the first line as plain text with an ellipsis.
  - On send lines only, the `<viola-readback>` spans the last two tracks. On every other line TEXT spans to the end.
- **Per-kind colour (from the domain rows):**
  - Everything is `color-text-primary` except the lines below.
  - `activity` and `prompt · harness` lines are entirely `color-text-tertiary`.
  - `link` / `unlink` names are `color-role-handoff`.
  - `session-end` has a `--rule` in `color-border-subtle` under it.
  - `skipped  1 unknown kind` is printed in place, in `color-text-muted`.
  - Dialog kinds (`question`, `permission`, `plan`) are never amber in the tape.
- **Rhythm:** oldest at the top, newest appended at the bottom. A `--rule` in `color-border-subtle` marks each minute boundary.
- **Motion:** only lines arriving over SSE after first paint (`data-live`) fade in over `--fade-dur`. The initial paint and scroll jumps are instant.
- **Follow rule:** the tape follows the bottom only while the reader is already at the bottom. See the footer block for what happens otherwise.
- **Line cap:** past 2000 lines, the first line of the region is the static notice `older lines trimmed from view: N — the full tape is events.ndjson` in Body `color-text-secondary`.

### Component — State strips (first reading, empty, degraded)

- **Anatomy:** a full-width strip in the rack (or tape) position, on `color-surface-base` with `radius-md`. Body type, one phraseology first word and one plain line. A buff-bordered strip means a declared state or error: `--rule` in `color-border-emphasis`. A neutral notice uses a `--rule` in `color-border-subtle`.
- **Instances:**
  - `sessions: no reading yet` (first paint, `color-text-secondary`, rail rule). It is replaced in place by strips, with no fade.
  - `no wrapped sessions — start one with  viola run <name> -- claude` (the command in Code role).
  - `no unwrapped sessions`.
  - `TAPE live since 19:40:02Z — no events yet`.
  - `unable · state-unreadable  viola home could not be read` (503, emphasis rule).
  - `TAPE stopped · viola ui not answering` at the top of the tape (emphasis rule, paired with the boxed ATIS cell).
  - The 401 access strip occupies the same position, but its content is deferred to implementation.
- **Never:** "Loading…", a spinner, a skeleton, a toast or an auto-dismissing notice.

### Component — Footer (tape end zone; no page footer)

- **No page footer chrome.** There is no version string, no legal text, no links and no status bar. The ATIS header already carries every piece of status, and the CLI owns version and help.
- **What sits at the bottom of the bay is the tape's end edge:**
  - `#tape-end`: a zero-height anchor after the newest line. It is the target of the follow rule and of the skip-link / new-lines jump. Jumps are instant.
  - `N new lines below`: a static, link-styled anchor to `#tape-end`, pinned as the last line inside the tape region. It uses Body `color-text-primary`, a `--rule` top edge in `color-border-subtle`, `space-xs` inline padding, and underline on hover or focus. It overlays the region's bottom line rather than pushing content, so its appearance moves nothing. It is present only while the reader is scrolled up, and the count updates as a text swap.
- **Page end spacing:** `space-lg` below the tape region.

### IA notes

- **Global model:** one route `/`. The page loads `/api/sessions` and `/api/links` for current state, then tails SSE `/api/events`. There are no client-side routes, no query-string state and no history entries.
- **Deep links:** only the in-page fragment `#tape-end` (and the skip-link target). Individual strips and tape lines have no permalinks in v1. The stable reference for an event is its `cursor` in `events.ndjson`, which is a CLI concept.
- **Breadcrumbs:** none. The IA is one level deep.
- **Search:** none (UX guideline set; #81's command palette is rejected).
- **Out-of-view attention:** `document.title` (`DIALOG overseer · viola`, `+N` when more strips are cocked) plus polite announcements limited to a strip turning cocked, a readback refusal and `TAPE stopped`. a11y owns the mechanics. The whole tape is never announced.
- **Library shortlist top-10 UX guidelines, as layout decisions:**
  1. Colour only (#37): amber always sits beside `DIALOG`, dimming beside the printed `stale`, and blue beside a name and an arrow.
  2. Contrast (#36): lamp-off, amber and blue text live only on `color-surface-base`. That is why captions sit in the rack header, markers sit in the rack gap and the DIALOG cell is inset.
  3. Reduced motion (#9): both durations become zero, and the offset and band stay.
  4. Excessive motion (#7): exactly two motions, each placed as described above.
  5. Content jumping (#19): stable slots, `unknown` printed in place, the cock done with `transform`, and a sticky overlay for `N new lines below`. The header and marker shifts are the logged deviation (order kept).
  6. Error feedback (#33): the refusal prints in the cell next to the struck box, and the 503 strip sits in the rack it affects.
  7. Errors announced (#44): the announcement scope listed above.
  8. Loading indicators (#78): overridden. Waiting is shown as words (`open`, `unknown`, `read 4m ago`, `sessions: no reading yet`, `TAPE connecting`).
  9. Horizontal scroll (#69): fixed `ch` tracks sized for the widest fallback face, `--cock-offset` end padding, and ellipsis only in the tape TEXT, the INSTANCE and word/reason tracks, and unwrapped names.
  10. Focus states (#28): the `color-border-focus` ring on the skip link, the summaries and the new-lines anchor.
- **Multi-surface coordination:**
  - The strip's six fields and words are exactly `viola list`'s columns and words, in the same order and slot order.
  - Every action (send, pause, release, link, answer) is a CLI verb. The page shows its outcome as a tape line and a field word, and never offers the action itself.
  - The only command the page ever prints is the empty-rack `viola run <name> -- claude`, in Code role.
  - The later phone view reuses this page below 760. That layout is not specified here.

## Surface: cli

**Tooling context:** Rust stable with clap 4.6.7 (derive). TTY detection uses std `IsTerminal`. Windows VT output is enabled with windows-sys 0.61.2 `SetConsoleMode`, and colour is off if that fails. Styling is a small hand-written SGR module in the `viola` bin, with no colour or table crate. Columns are padded to fixed widths by that same module.

**Token names on this surface (same names as web-spa):**

| Token name | cli rendering |
|---|---|
| `color-accent` | The design system's attention SGR token (truecolor / 256 / 16-colour fallback row). Only on the `DIALOG` word, always followed by the uncoloured kind word |
| `color-text-muted` | The `stale` token: SGR dim across a whole `stale` row, and never without the word `stale` in LIVE |
| Callsign role | The callsign token: SGR bold on NAME values only |
| `color-text-primary` / `color-text-secondary` | The terminal's default foreground. The terminal owns ink |
| `color-role-handoff` | Not used. Link output is plain |
| `color-surface-*` | Never set. The terminal background belongs to the user |
| Label role | Uppercase column captions (`NAME LIVE STATUS WHEEL DIALOG CLI`) and group labels, plain |
| Data role | Tabular figures and timestamps, right where the web prints them |
| `space-xs` equivalent | The column gutter: two spaces on the terminal grid. Inside one field, ` - ` replaces the web's `·` |
| `radius-*` | No terminal analogue. Square brackets `[ ]` keep the ruled-rectangle reading |
| Motion tokens | None. Nothing redraws in place |

**Expression level (this surface):** 0.2 on a human TTY: static fixed-column rows, one static context header, and colour only as a second cue. 0.0 for `--json`, non-TTY, `NO_COLOR`, `TERM=dumb` and `viola run` passthrough: no colour, no non-ASCII glyph and no cursor control.

**Signature placement:** the readback mirror `[RB]` / `[  ]` / `[/ ]` is the first column of `viola send` output, in two components:
1. The issue line `[  ] open …`, on stderr and only on a TTY. It is printed when the request goes to the wrapper.
2. The outcome line: `[RB] read back …` on stdout with exit 0 when the matching `prompt-submitted` confirms the send; `[/ ] unable …` on stderr with exit 13 (or 10/11/12/14) when the wrapper returns a refusal; `[  ] unconfirmable …` on stdout with exit 0 for an unmeasured local command.

The word half of the box (`unable` plus `reason  detail`) is also the first-word column of every other verb's refusal line (`viola answer`, `viola pause`, `viola release`). So the struck-box vocabulary is shared, while the glyph itself belongs to `send`. Under `--json` the mirror is replaced by the typed `ok` / `refusal` document. The supporting attention element, the amber `DIALOG` word, appears only in `viola list`.

### Primary screens (commands)

- `viola list` is the board: every session as one strip row, with the BAY context header.
- `viola send <target>` is the readback mirror. It types at a turn boundary and reports read back, unable or unconfirmable.
- `viola wait <target>` / `viola last <target>` return one turn-boundary result or the last assistant message, with no spinner.
- `viola pause` / `release` / `link` / `unlink` / `answer` are the wheel, handoff and dialog verbs. Their output is spoken phraseology.
- `viola verify` stamps a CLI version with a step counter, the project's only progress pattern.
- `viola run <name> -- claude` is passthrough and prints nothing while the child runs.
- `viola --help` is the grouped verb table.
- `viola ui` prints one unstyled launch line to stderr. Its credential-bearing content is deferred to implementation with the security plan.

### Output structure — `viola list` (human TTY)

```
$ viola list
BAY  5H 62 %  7D 41 %  read 4m ago  gate open  skipped 0 - 0 - 0                <- context header (Label BAY/5H/7D, Data figures), one static line
NAME          LIVE   STATUS   WHEEL                    DIALOG             CLI    <- captions, Label, plain
builder       live   idle     driver                   none               2.1.280 verified
overseer      live   busy     human                    DIALOG permission  2.1.280 verified     <- DIALOG in color-accent, `permission` plain
scratch       stale  unknown  driver - budget-paused   none               2.1.281 unverified-cli <- whole row color-text-muted (SGR dim)
-- UNWRAPPED - READ-ONLY --                                                      <- rack separator, Heading-equivalent, plain
c1f9e2a4...   live   idle     n/a                      n/a                n/a    <- NAME truncated with `...` only when the width is known
```

- NAME values are bold (Callsign). Rows are ordered by name, the same slots as the web racks. Nothing is re-sorted by state.
- A closed budget gate prints `budget-paused` in place of `gate open`. A passed window prints `5H 62 % expired`.
- On a cocked + `stale` row, `DIALOG` stays amber and not dim, and the kind word and the rest of the row stay dim.
- Empty board: `no wrapped sessions  start one: viola run <name> -- claude`.

### Output structure — `viola list` (piped / `NO_COLOR` / `TERM=dumb`)

```
NAME          LIVE   STATUS   WHEEL                    DIALOG             CLI
overseer      live   busy     human                    DIALOG permission  2.1.280 verified
...
```

These are the same characters with no SGR. The words carry every state, so nothing is lost. Nothing is truncated when the width is unknown.

One JSON document on stdout, with no header line, no colour and no glyph. The item, `budget` and `skipped` shapes are identical to `/api/sessions`.

### Output structure — `viola send`

```
$ viola send builder < step4.txt
[  ] open           builder  issued 19:45:05.300Z                 <- stderr, TTY only (issue: box open)
[RB] read back      builder  19:45:05.912Z  cursor 48213          <- stdout, exit 0 (SIGNATURE: filled)

$ viola send builder < clear.txt

[/ ] unable         builder  not-delivered  input-not-ready       <- stderr, exit 13 (SIGNATURE: struck)

[  ] open           builder  issued 19:46:12.001Z
[  ] unconfirmable  builder  local command, no measured post-condition   <- stdout, exit 0 (never filled)

{"v":1,"ok":{"submitted_at":"2026-09-23T19:45:05.912Z","cursor":48213}}   <- stdout; no glyph, no issue line
```

The word column is padded so `open`, `read back`, `unable` and `unconfirmable` line up, and the name always starts in the same column. Lines are appended, never redrawn: the issue line stays and the outcome is printed under it. When stdout is piped, the TTY-only issue line is dropped and the outcome line alone carries the mirror.

### Component — Header / banner (the BAY context line)

- **The only header on any verb** is the one static BAY line at the top of `viola list`. It is the web ATIS without `VIOLA`, without the address, without `resets` times and without the TAPE cell.
- **Cell order:** `BAY`, `5H <n> %`, `7D <n> %` (each followed by `expired` when the window has passed), `read <age> ago`, `gate open` or `budget-paused`, `skipped a - b - c`. Cells are separated by the two-space gutter.
- **Typography:** Label words and Data figures, all in the default foreground. There is no bold, no colour, no box drawing and no rule line under it.
- **No banner anywhere:** no ASCII-art logo, no tagline and no version line on normal output. The version appears only in `--version` / `--help`. `viola run` prints nothing, and `viola hook` / `viola mcp` have no human surface.

### Component — Primary navigation (verb structure)

- **Flat verbs:** one lower-case word each (`plugin install` is the one two-word verb). There is no nested noun hierarchy, no interactive prompt, no TUI mode and no pager.
- **Argument order mirrors the channel `params`:** `viola <verb> <target>` for one strip, `viola link|unlink <driver> <driven>` for a handoff, `viola answer <target> <dialog_id>`. `<target>` is always a `ViolaName`. Unwrapped names are never valid targets, just as they are text-only on the web.
- **Board vs. strip:** `viola list` (and `viola ui`) show the whole bay. Every other verb acts on one strip.
- **Global flag `--home`:** the same on every verb. `--json` is the machine view of every data verb.
- **Discoverability:** `--help` groups verbs as board / traffic / wheel / handoff / setup. `hint:` lines point to the next verb by name (`viola wait builder`, `viola list`, `viola release builder --budget`). They are the CLI's breadcrumbs.

### Component — Hero / signature output line (the `viola send` readback mirror)

- **Layout:** a fixed first column holding the four-character box (`[RB]`, `[  ]`, `[/ ]`). Then one space, then the padded state word (`open` / `read back` / `unable` / `unconfirmable`). Then the two-space gutter, then NAME, then the outcome fields: time, `cursor`, `reason  detail`, or the unconfirmable note.
- **Issue left, readback right, spread over time:** the TTY issue line on stderr is the open box. The outcome line under it is the closed box. The two lines line up column for column, so the eye reads them as one strip entry, like the web's send line with its box at the far right.
- **Colour:** none, on purpose. The mirror is words and brackets only. `read back` is never green and `unable` is never red, because colour on the CLI is reserved for `DIALOG` and `stale`.
- **What never happens:** no `Sending…` spinner, no `✓`, no `done`. `turn-ended` is never reported as a send outcome. That is `viola wait`'s result.
- **Machine view:** `--json` prints only the typed document (`ok` with `submitted_at` + `cursor`, `ok` with `confirmed:false` + `unconfirmable`, or `refusal` + `detail`), with the typed exit code and no glyph and no hint.

### Component — Primary content block 1: `viola list` strip rows

- **Columns:** NAME · LIVE · STATUS · WHEEL · DIALOG · CLI, identical to the web strip's fields and words. Each column is padded to its widest word (`stale`, `unknown`, `driver - budget-paused`, `DIALOG permission`, `2.1.281 unverified-cli`), with the two-space gutter between columns. There are no box-drawing borders.
- **Styling:**
  - NAME is bold (Callsign).
  - The `DIALOG` word takes `color-accent` and the kind word after it stays default. This is the CLI cocked strip.
  - A `stale` row is `color-text-muted` (dim) from end to end, and the word `stale` is always in LIVE.
  - Nothing else is styled.
- **Rack separator:** `-- UNWRAPPED - READ-ONLY --` on its own line before the unwrapped rows. The WRAPPED rack has no separator, because it is always first and the caption row heads it.
- **Truncation:** only unwrapped NAMEs, with `...`, and only where the terminal width is known. Wrapped names are never clipped. No line ever wraps.
- **Escaping:** every field that comes from `claude agents --json` has C0/C1 controls escaped as hex text.
- **No link column:** the six shared columns stay fixed. Links are visible only as `link` / `unlink` verb output (`overseer -> builder`).

### Component — Primary content block 2: refusal lines and the `unable` column

- **Line form (stderr):** `unable  <name>  <reason>  <detail>`, fields separated by two spaces. `viola send` pads `unable` into the mirror's word column after `[/ ]`. The one fixed-message exception is the exit-1 start refusal `unable: <name> is already live`.
- **Hint line:** directly under each refusal, `hint: <one plain instruction>`, keyed by reason (or by reason · detail). There is no hint for the opaque `unknown` refusal, for `wrapper fault` or for `internal error`. A hint never quotes the sent text or any upstream text.
- **Exit codes as the typed tail:** 10 `human-typing`, 11 `budget-paused`, 12 `unverified-cli`, 13 `not-delivered`, 14 `unknown`, 20 wrapper fault (`error: wrapper fault  <code>`), 21 `unable  instance-unreachable`. Under `--json` the same outcome is one document on stdout, with no stderr line and no hint.
- **Streams:** results go to stdout. `waiting:`, the issue line, refusals, hints, errors and the `viola ui` launch line go to stderr. The two are never mixed.

### Component — Footer / terminator

- **No terminator word.** No `done.`, no `success`, no summary banner. The exit code is the terminator, and the last printed line always says what happened, to whom and where: `[RB] read back      builder  19:45:05.912Z  cursor 48213`, `answered  builder  dialog 7`, `link    overseer -> builder  since 19:43:58Z`.
- **On a refusal**, the `hint:` line is the last line on stderr.
- **On `verify`**, the summary `stamped <version>  <n> pass  <n> fail` closes the run.
- **No persistent footer.** Terminal scrollback is the history. The tape lives in `events.ndjson` and on the web page.

### IA notes

- **Command model:** flat verbs plus a target. The board is `viola list` and the strip-level verbs act on one `ViolaName`. There are no subcommand trees beyond `plugin install`.
- **Deep links:** none, and the CLI has no URL coupling. The shared references are `ViolaName` (the same string the web prints in the Callsign cell, never case-transformed) and `cursor` (the byte offset `send` prints and `wait --after` consumes).
- **Output as a contract:** the human columns and words are stable, because LLM drivers may read them. New fields go into `--json` first. Adding a human column would break the six-column parity with the web strip, so it is a design change, not an implementation choice.
- **Multi-surface coordination:**
  - The same six captions, words and slot order as the web racks.
  - The same readback vocabulary (`open`, `read back`, `unable`, `unconfirmable`). The web draws the box and the CLI brackets it.
  - `·` on the web becomes ` - ` inside a CLI field. `→` becomes `->`. There is no CLI inbound `<-` form.
  - Amber means `DIALOG` on both surfaces and nothing else. `stale` is lamp-off ink on the web and SGR dim in the terminal.
  - Handoff blue exists only on the web.
  - The web page never offers an action. The CLI is where every action lives, and the page's empty state prints the CLI command that fills it.

## Decisions Log

`2026-09-24`: Initial layout templates generated by `/andromeda-design` Phase 8.

**Surfaces covered:** web-spa (`viola ui`), cli (`viola` verbs).

**Key layout choices:**
- **web-spa:** one route and one bay, in four fixed regions (ATIS header, WRAPPED rack, UNWRAPPED · READ-ONLY rack, TAPE). There is no nav chrome, no hero and no page footer. Strips are fixed-field grid rows on `--strip-cols`, in stable name order, never a card grid.
- **web-spa:** the tape is the only bounded scroll region, filling the viewport below the racks with a ten-line floor. This keeps the racks, and any cocked strip, in view while history is read. The page scrolls only when the racks plus that floor exceed the viewport.
- **web-spa:** transfer markers are `--line-h` lines in the rack gap on `color-surface-base`, under the driver (outbound, with the box) and under the driven strip (inbound twin, no box). There is no graph.
- **web-spa:** state strips (first reading, empty, 503, tape stopped) occupy the rack or tape position they describe. They are words only, with no loaders.
- **cli:** `viola list` is the single board, with one static BAY header and six padded columns identical to the web strip. Every other verb prints one or two phraseology lines, and the exit code is the terminator.
- **cli:** `viola send` is the only verb carrying the bracketed readback mirror. Other verbs share only its `unable` word column.

**Cross-surface IA decisions:**
- One token vocabulary (`color-*`, `space-*`, `radius-*`, typography roles) is used on both surfaces. The web resolves it to the CSS aliases in `/assets/app.css`, and the cli to the SGR tokens, the terminal default foreground or "not used". Differences are platform mechanics only: ANSI depth, the two-space gutter, ASCII `->` / ` - `, and brackets for the ruled box.
- The same six fields, words and slot order apply on both surfaces. `ViolaName` and `cursor` are the only shared references. There is no URL coupling.
- The web shows state and history. The CLI is the only place actions happen. The web's only printed command is the empty-rack `viola run <name> -- claude`.

**Signature placement strategy:**
- **web-spa:** `<viola-readback>` at the far right of every tape `send` line (spanning the last two `--tape-cols` tracks) and of every outbound `<viola-transfer>` marker once a send on that link is seen (`unknown` before that). It is one element and one drawing in both places, and both flip in the same frame.
- **cli:** the `[  ]` issue line (stderr, TTY) plus the `[RB]` / `[/ ]` / `[  ] unconfirmable` outcome line of `viola send`, with the `unable` word column carried into every verb's refusal line.
- **Supporting element:** the cocked strip on `<viola-session-row>`, mirrored by the amber `DIALOG` word in `viola list` and by `document.title`.

**Motion trigger placement:**
- **The cock** (the only High-impact moment): `<viola-session-row>` in the WRAPPED rack, when its `dialog_pending` turns true. It plays `translateX(--cock-offset)` over `--cock-dur` once. The band turns `color-accent` and the DIALOG cell insets in the same frame. The return into line is instant. It never fires in the tape, on unwrapped strips or on the CLI.
- **Ambient fade:** tape lines and `<viola-transfer>` markers that arrive over SSE after first paint (`data-live`) fade in over `--fade-dur`. The first paint is instant.
- **Deliberately instant:** the readback fill and strike (tape and marker), `stale` dimming, `unlink` removal, the header gaining a line, the `N new lines below` count and the `read Nm ago` age.
- **Reduced motion:** both durations are zero, and the cock position and band persist.
- **cli:** no motion. Nothing redraws in place, and nothing uses a spinner or progress bar. `verify` appends step-counter lines.

**Responsive breakpoints (web only):**
- ≥1024: primary, with one-line strips on `--strip-cols`.
- 760–1023: two-line strips on `--strip-cols-wrapped` / `--strip-rows-wrapped` / `--strip-areas-wrapped`, a caption row on the same template, the ATIS header on three or more lines, and tape word/reason ending in an ellipsis with the full text in the expanded body.
- <760: reserved for the later phone view and not laid out in v1.
- Never horizontal scroll at any supported width. Racks keep `--cock-offset` end padding.

**Notable surface-specific deferrals:**
- The 401 access strip content and recovery copy, the `viola ui` launch line's credential content, and the v1.x brake controls (`I HAVE CONTROL`, `UNLINK`, Raised-3 confirmation). Their placement and copy are deferred to implementation with the security plan. No control slot is reserved in the v1 bay.
