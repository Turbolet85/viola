## Reference Products

### Product 1: vStrips (vNAS) — web-based flight-progress strip bay for VATSIM controllers

- **What's exceptional:** It is a web app that recreates the physical strip bay with a strict spatial vocabulary. A **bay** is one position's workspace. A **rack** is a vertical rail that strips sit on. A **separator** is a labelled divider that can be locked. A **half-strip** holds free-text coordination notes. When a strip needs attention it is **offset**: it "slides the strip out of the rack to serve as a visual reminder". It is not re-coloured or re-sorted. Strips move between bays by drag-and-drop or by **push**, and a pushed strip is only received if another controller has that bay open. So a handoff needs a receiver on the other end.
- **Domain match:** viola's `web-spa` is a small set of fixed-field session rows plus a `driver → driven` link set. That is a single bay holding a few strips and their transfers. Because vStrips runs in the browser, it shows that the metaphor works as HTML/CSS rows without any canvas or custom font.
- **Personality match:** It is the chosen metaphor, built literally. A strip that needs attention changes position (cocked out of line) and stays in its place in the order. A handoff only counts when the other side has the bay open, which is the same idea as readback and confirmed-after-the-fact sends.
- **What to learn:** (1) Show `dialog_pending` as a horizontal offset of the whole `<viola-session-row>` (a CSS `translate` or margin shift of the strip, with a text label as well), not as re-sorting. Rows keep a stable order so the eye can find "builder" in the same slot every time. (2) Use locked, labelled separators to split the rack into groups (e.g. "wrapped" / "read-only unwrapped"). Render each link as a transfer marker between two strips, not as a node graph.

### Product 2: Frequentis smartStrips / Saab EFS — professional electronic flight strip systems (NATS, LVNL, Airways NZ, FAA TFDM)

- **What's exceptional:** The FAA TFDM requirement is that the electronic strip should "look just like its paper counterpart". smartStrips follows paper-strip use patterns on purpose, including bays organised by controller responsibility (TWR vs RWY). Each strip is a row of fixed boxes, one field per box, always in the same column position (callsign, type, code, time, level, then annotation boxes). A controller reads a strip by where a box is, not by a label beside it.
- **Domain match:** viola's session row has the same kind of fixed field set: name, liveness `live`/`stale`, status `idle`/`busy`/`unknown`, wheel `human`/`driver`, `budget_paused`, `dialog_pending`, CLI version + verified. A boxed strip layout (CSS grid with fixed `grid-template-columns` and a 1px ruled cell for each field) matches this directly and needs no component library.
- **Personality match:** These systems are safety-rated (ED-109A AL4/SWAL3). They add nothing decorative to the strip, and an empty box stays empty rather than being filled with a guess. That is viola's "Measured, never assumed" rule and the creator's anti-"Overclaiming" anchor: `unknown` is printed in its box, and the box is never hidden.
- **What to learn:** (1) Use a ruled box grid for each strip, with a callsign-weight first cell (session name in heavier system-font weight, uppercase-tracked). The other fields sit in fixed-width tabular cells (`font-variant-numeric: tabular-nums`) so values line up down the rack. (2) Use a coloured left-edge band or strip-holder colour for one categorical fact only, here the wheel holder (`human` vs `driver`), the way paper-strip holders are coloured by flight type. Keep text on a neutral background.

### Product 3: Temporal Web UI — Event History (Compact / Timeline / live feed)

- **What's exceptional:** The event history shows each unit of work as paired events (Scheduled → Started → Completed/Failed), grouped into one "Event Group" bar. The Compact view drops clock time and shows "simply what happened, in what order". Recent releases add a live-streaming event history. You can see at a glance which requests were issued but never acknowledged, because the group is left open.
- **Domain match:** viola's live SSE feed (session-start, prompt-submitted, turn-ended, question, permission, plan, session-end, activity, link, unlink, wheel, budget-gate) is an ndjson event history for durable agent processes. The overseer→builder send followed by confirmation (or a `not-delivered` refusal) is the same issue-then-acknowledge pair.
- **Personality match:** Temporal presents a send and its readback as two distinct recorded events. Nothing counts as done until the completion event is on disk. That is "read back before it counts" and "every send is confirmed after the fact, never presumed".
- **What to learn:** (1) In `<viola-event-feed>`, pair `prompt-submitted` with its confirming `turn-ended` (or typed refusal) as one feed line with an open/closed state. An unconfirmed send shows visibly unclosed, never as done. (2) Offer a compact, order-only reading of the feed (sequence numbers, no relative timestamps) next to the timestamped one. Show `skipped` counts inline where they happened, the way Temporal keeps gaps visible.

### Product 4: Claude Code Agent View — multi-session CLI dashboard (Anthropic, research preview, May 2026)

- **What's exceptional:** It has one row per session and a fixed state vocabulary (Working / Needs input / Idle / Completed …). "Needs input" is the single yellow state. Pressing Space opens a peek panel with the blocking question inline, without leaving the table.
- **Domain match:** It sits in the same domain and serves the same user as viola: a Claude Code subscriber watching several sessions. It is also the fresh 2026 comparison users will make, so viola's vocabulary must be clearly different while staying just as readable.
- **Personality match:** Partial match, and a useful contrast. Its fixed state words and single attention colour fit standard phraseology. But it automatically moves "needs you" sessions to the top of the list, which a strip bay does not do (a cocked strip stays in its rack slot). It also shows last-response content, which viola's text-only, anti-overclaiming rule treats with care.
- **What to learn:** (1) Keep exactly one attention colour, reserved for `dialog_pending`, alongside the offset and a text label. (2) Deliberately do not auto-reorder rows. Stable strip order is viola's point of difference and matches the ATC metaphor. The peek-panel idea maps to an expand-in-place strip detail for v1.x.

### Product 5: k9s — Kubernetes terminal UI (for viola's `cli` surface)

- **What's exceptional:** k9s renders every resource as a fixed-column row. The whole row is coloured by status (errored rows stand out, completed rows are dimmed). A compact header shows the context (cluster, user, version), and a hint area lists the available keys. Its dense table stays readable because columns never move and status is shown by both colour and the STATUS text column.
- **Domain match:** `viola list` / `viola last` print human text by default and `--json` for agents. k9s is a reference for how a live-process listing should look in a terminal on Windows, macOS and Linux.
- **Personality match:** k9s uses fixed column headings, lowercase status words taken straight from the API, and no prose. The terminal output reads like standard phraseology and parallels the strip rack in the web page.
- **What to learn:** (1) Make `viola list` a fixed-column table whose column order and words match the web strip exactly (NAME · LIVE · STATUS · WHEEL · DIALOG · CLI), so the two surfaces read identically. (2) Put a one-line context header above the table (budget `five_hour`/`seven_day` %, reading age). Dim `stale` rows and never colour-code without the status word next to it.

## Recommended

**Top references:** vStrips (vNAS) and Temporal Web UI Event History

**Reasoning:** vStrips is the "Strip-bay handoff, read back" metaphor already built as a working web page. Its bay/rack/separator/offset/push vocabulary gives viola's view-only `web-spa` a concrete layout grammar for session rows, `driver → driven` links and `dialog_pending`, all doable with hand-written CSS grid, system fonts and no component library under the CSP. Temporal's event history covers the other half of the metaphor, readback. It shows issued-then-acknowledged pairs as one unit with open and closed states. That is how the founder should see "every send is confirmed after the fact, never presumed" in the live feed, with nothing overclaimed. Frequentis/Saab EFS should shape the box-grid strip anatomy within that frame. Claude Code Agent View is the comparison to set viola against: same states, but stable rack order instead of automatic re-sorting.
