### axe-core 4.13.0 (engine; runs through `@axe-core/playwright` only)

- **Version:** 4.13.0
- **Last release:** 2026-08-05. Earlier releases: 4.12.1 on 2026-06-09, 4.12.0 on 2026-06-01, 4.11.4 on 2026-04-28.
- **Status:** actively maintained. The dequelabs/axe-core repo is not archived; its last push was 2026-09-23.
- **Agent-runnable:** yes. It produces axe-core JSON: `violations[]`, `incomplete[]`, `passes[]` and `inapplicable[]`, plus `testEngine`, `url` and `timestamp`. Each node carries `target`, `html`, `impact` and `failureSummary`. The built-in reporters are `v1`, `v2`, `raw`, `no-passes` and `na`. Configuration: never call it directly; see `@axe-core/playwright` below. Recommended tag set: `['wcag2a','wcag2aa','wcag21a','wcag21aa','wcag22aa']`.
- **WCAG SCs covered:** I enumerated these from axe 4.13.0's `axe.getRules()` for that tag set. It covers 24 SCs with 70 rules:
  - SC 1.1.1 · 1.2.1 · 1.2.2 · 1.3.1 (`aria-required-children`, `aria-required-parent`, `list`, `listitem`, `td-headers-attr`, `th-has-data-cells`, `td-has-header`, `p-as-heading`) · 1.3.4 · 1.3.5
  - SC 1.4.1 (`link-in-text-block`) · 1.4.2 · 1.4.3 (`color-contrast`) · 1.4.4 (`meta-viewport`) · 1.4.12 (`avoid-inline-spacing`)
  - SC 2.1.1 and 2.1.3 (`scrollable-region-focusable`) · 2.2.1 · 2.2.2 (`blink`, `marquee`) · 2.4.1 (`bypass`) · 2.4.2 (`document-title`) · 2.4.4 (`link-name`) · 2.5.3 · 2.5.8 (`target-size`)
  - SC 3.1.1 (`html-has-lang`, `html-lang-valid`) · 3.1.2 (`valid-lang`) · 3.3.2
  - SC 4.1.2 (`aria-hidden-focus`, `nested-interactive`, `summary-name`, `aria-allowed-attr`, `aria-prohibited-attr`, `aria-valid-attr-value` and 20 more)
  - **Not covered by any axe rule**, and needed by a11y-scope Section 4: SC 1.3.2, 1.4.10, 1.4.11, 1.4.13, 2.1.2, 2.3.1, 2.4.3, 2.4.6, 2.4.7, 2.4.11, 3.3.1, 3.3.3 and 4.1.3. SC 2.2.2 is covered only for `blink`/`marquee`. The keyboard, focus, contrast and screen-reader blocks below have to cover these gaps.
- **Fits because:** a11y-scope Section 2 (web-spa) and Section 3 name axe-core as the web-spa engine. The tests plan's binary `violations: []` verdict runs per state strip (empty, 503, cocked), and a11y extends it to the 401 strip, `TAPE stopped` and steady state. It serves Section 4 Paths 1, 2, 3 and 5, and the visual-discrimination trigger in Section 5 (`color-contrast`).
- **Key detail:** I checked the source and ran it.
  - (a) `target-size` (SC 2.5.8) is `enabled:false` in a default run. I confirmed in jsdom that a default `axe.run` skips it, while `runOnly` on the `wcag22aa` tag runs it. The design-bound SC 2.5.8 addition therefore needs `wcag22aa` in the tag set.
  - (b) The 4.13.0 `axe.js` has one `innerHTML` setter. It sits inside `_pollyfillElementsFromPoint`, which is never reached in Chromium because native `elementsFromPoint` exists. `new Function` is used only by doT when `axe.configure({locale})` merges template-string locales. The default English messages are plain `${}` strings.
  - (c) So under viola's `require-trusted-types-for 'script'` / `script-src 'self'` CSP: never pass a `locale`, and the run needs no `bypassCSP`.
  - (d) `best-practice` rules (`region`, `landmark-one-main`, `page-has-heading-one`, `heading-order`, `landmark-banner-is-top-level`) are the only axe rules that reach the scope's landmark and heading gaps. They carry no SC tag, and adding them makes them gating under the binary verdict. Phase 3 decides.
- **Source:** https://github.com/dequelabs/axe-core/blob/develop/CHANGELOG.md · https://dequeuniversity.com/rules/axe/4.11 · https://www.npmjs.com/package/axe-core

## Keyboard Test Harness Pattern

### Playwright Test 1.63.0 keyboard API (`page.keyboard.press`, `expect(locator).toBeFocused()`)

- **Version:** 1.63.0
- **Last release:** 2026-09-04
- **Status:** actively maintained
- **Agent-runnable:** yes, as Playwright JSON reporter results. Configuration: one spec walks the full sequence and runs the key contracts.
  - Start from a known state (`page.locator('body').focus()`), then `Tab`: skip link, then each tape `<summary>` from oldest to newest, then the `N new lines below` anchor (only while scrolled up). Assert `toBeFocused()` after each press. Reverse with `Shift+Tab`.
  - Assert strips, captions and transfer markers are never focused.
  - Key contracts: `Enter` on the skip link lands at `#tape-end`; `Enter` on the anchor jumps instantly; `Enter` and `Space` toggle `<details>` `open`.
  - Focus-ring check: `getComputedStyle(el).outlineColor/outlineWidth/outlineOffset` equal the resolved `--focus-ring`/`--focus-w`/`--focus-offset`.
  - SC 2.4.11 check: after each Tab, the focused `<summary>`'s `getBoundingClientRect()` is not fully covered by the sticky `<viola-atis>` rect. AA tolerates partial overlap; prefer zero intersection via `scroll-padding-top` on the tape scroller.
  - Waits use auto-waiting locators only, with `retries: 0`.
- **WCAG SCs covered:** SC 2.1.1 Keyboard, SC 2.1.2 No Keyboard Trap (the full Tab and Shift+Tab cycle returns to browser chrome), SC 2.4.1 Bypass Blocks (skip link), SC 2.4.3 Focus Order, SC 2.4.7 Focus Visible, SC 2.4.11 Focus Not Obscured (Minimum), and SC 3.2.1 On Focus (no state change or focus theft on SSE arrivals, cocking, refusal, 503, 401 and `TAPE stopped`).
- **Fits because:** the Section 5 keyboard-only trigger, a11y-scope Section 3 "Keyboard test harness" and "Focus management test harness" (they reuse the tests' Playwright driver), and Section 4 Paths 1, 2, 3 and 5. It covers four axe-uncovered SCs: 2.1.2, 2.4.3, 2.4.7 and 2.4.11.
- **Key detail:** axe has no rule for SC 2.4.3, 2.4.7 or 2.4.11. `focus-order-semantics` is `experimental` and disabled. These three SCs therefore rest entirely on this scripted walk.
- **Source:** https://playwright.dev/docs/api/class-keyboard · https://playwright.dev/docs/test-assertions · https://accessibility.build/wcag/2-4-11
