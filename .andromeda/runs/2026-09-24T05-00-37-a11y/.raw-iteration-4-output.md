## Analysis

**Dimension 1: Downstream Readiness**
- The `scrub-leak`, `axe-rule-not-run` and `csp-console` ids are now separate, all at `serious`, with no `wcag_criterion`. Fixed in earlier iterations.
- State-strip positions, lint paths, the `tbody` content model and Aggregation `if: always()` are all defined. Fixed in earlier iterations.
- **Defect: the CSP / Trusted Types check only covers one spec.** Section 10 fails the build on "A CSP / Trusted Types console violation during any a11y spec". The only listener the plan defines is "the first VSR spec also asserts…" (§3 Screen reader test pattern → CSP guard). Nothing produces `csp-console` rows for the axe, token, keyboard or other specs, and the row's `check_source` and `selector` are undefined. As written, CI stays green if an axe injection hits a Trusted Types sink in any non-VSR spec. Patch 1.
- **Defect: §10 and §9 define "applicable" differently.** §10 says "every applicable SC … (WCAG 2.1 AA + SC 2.4.11 + SC 2.5.8 …)". Read literally, that drops the `3.2.6, 3.3.7, 3.3.8 (2.2)` row. §9 Aggregation says `sc-coverage.json` lists every map row. `setup-project` cannot tell which row set the gate covers. Patch 6.

**Dimension 2: A11y Scope Faithfulness**
- The three tui boundary clauses each have a nextest case (§3 Keyboard, P4). The P6 TTY-only CLI behaviours are pinned. Both fixed earlier.
- **Defect: the 404/405 strips are announced but never driven by a spec.** §7 message (5) and D-A11Y-06 add "503 / 404 / 405 rack error strips that appear after first render" to the announcer. But the P5 per-state list covers only 503, `TAPE stopped`, stale and 401, and the §10 axe list has no 404/405 state. So no spec produces status text, a VSR phrase or an axe verdict for the 404/405 strips. Patches 2 and 3.
- **Defect: P5 contradicts §7 for the stale state.** P5 asserts "status text" and "VSR phrase" for every state, including stale. §7 says stale liveness is "Not announced". Folded into Patch 2.
- The v1.x brakes text in §7 ("when built") is not in the §3 map, so `sc-coverage.json` does not pick it up. No patch.

**Dimension 3: Tool Anchoring**
- **Defect: D-A11Y-01 still credits SC 2.4.6 to axe.** It says the five best-practice rules "close the SC 1.3.1 / 2.4.6 landmark and heading gaps". §3 (following research) now says SC 2.4.6 is never credited to axe. Patch 4.
- **Defect: "axe 4.1.2 rules" reads like a version.** In the §2 Robust row it sits beside "html-validate 11.16.0", so it can be taken as an axe version rather than SC 4.1.2. Patch 5. The §3 per-SC map row 4.1.2 has the same wording, but the row context makes it clear; left alone because of the patch budget.
- Versions agree across Section 1, the body and the Decisions Log. `jq` is labelled "catalog-less JSON transport". The option-ordering claim is now labelled an assumption and backed by the `axe-rule-not-run` check. No patch.

**Dimension 4: Tier Calibration**
- **Defect: the §10 state list and the path scenarios disagree.** §10 assigns P1 the states tape-line-expanded, scrolled-up, skip link focused, after skip-link activation and tape trimmed. P2 is assigned readback-refused. But P1's Tests list asks for an axe verdict only in steady, bay-narrow and first-reading/empty, and P2's Tests list has no axe verdict at all. A spec built from §4 would leave most of the SLO states unchecked. Patches 7 and 8.
- P4's WHEEL `human` state has the same gap. Not patched because of the 8-patch budget; carry it to the next iteration.
- Budgets are tied to `duration_ms` / `stats.duration` and evaluated by Aggregation. No patch.

**Dimension 5: WCAG Mapping Discipline**
- SC 2.4.11 triggers match between §3 and §5, including combined growth and `#tape-end`. The SC 2.5.8 spacing exception is defined. No patch.
- The per-SC map still has no A/AA level column. Adding one means rewriting the whole table, which is a structural change, so no patch.
- The exception wording in §10 is folded into Patch 6.

**Dimension 6: Design-Token Binding**
- No raw values in Sections 3, 5, 6 or 10. The two derived pairs trace to D-A11Y-18.
- Upstream gives no token pairing for the skip link or anchor text. Rendered contrast is now covered because §10 has axe states for skip link focused and scrolled-up. Inventing a pair would break the binding contract. No patch.
- `--strip-h` is consistent: upstream calls it a "fixed strip row height", so it is clip-checked, and it is not a v1 target. No patch.

**Dimension 7: Anti-Pattern Relevance**
- § CI is fixed.
- § Universal still says "(axe-core JSON / pa11y JSON / Lighthouse JSON / equivalent)". The § Strategy / § ARIA template bans are still generic.
- These are lowest priority, and the 8-patch budget is used up by dimensions 1–4. Deferred.

## Patches

### Patch 1: §3 Screen reader test pattern → CSP guard scoped to every a11y spec, with a defined `csp-console` row
**Reason:** Dimension 1. Section 10 fails the build on a CSP / Trusted Types console violation "during any a11y spec", but the only listener defined is in the first VSR spec, and the `csp-console` row's `check_source` / `selector` are undefined.
**Old:**
```
  - **CSP guard:** the first VSR spec also asserts that no `securitypolicyviolation` or Trusted Types console error occurred.
```
**New:**
```
  - **CSP guard:** the shared fixture in `e2e-web/fixtures/a11y.ts` records `securitypolicyviolation` events and Trusted Types console errors in every `@a11y` test, not only the VSR specs. It fails the test at teardown with one row per event: `violation_type:"csp-console"`, `severity:"serious"`, the `check_source` of the check running when the event fired, and a `selector` naming the violated directive, never the blocked URI (it can carry `?t=`). This is the runtime evidence for the Section 1 `[resolved: …]` claim that axe injection reaches no Trusted Types sink, and it feeds the Section 10 CSP / Trusted Types failure condition. The first VSR spec's clean-console assertion remains the D-A11Y-11 check on the VSR import.
```

### Patch 2: §4 P5 → drive the 404/405 strips and exempt stale from announcement checks
**Reason:** Dimension 2. D-A11Y-06 and the §7 message (5) announce 404/405 strips that appear after first render, but no path spec drives them. P5 also asserts status text and a VSR phrase for stale, which §7 says is "Not announced".
**Old:**
```
  - **Tests:** `a11y-path5` asserts, per state (503, `TAPE stopped`, stale, 401 after a `viola ui` restart under the same harness session):
    - axe verdict;
    - status text;
    - VSR phrase;
```
**New:**
```
  - **Tests:** `a11y-path5` asserts, per state (503, and the defensive 404 and 405 rack strips appearing after first render, `TAPE stopped`, stale, 401 after a `viola ui` restart under the same harness session):
    - axe verdict;
    - status text (for stale: the `role="status"` text is unchanged, because stale is never announced, per Section 7);
    - VSR phrase (for stale: zero new phrases);
```
