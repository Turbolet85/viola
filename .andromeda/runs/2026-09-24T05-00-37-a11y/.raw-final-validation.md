- **[INCOMPLETE]** Section 10 never uses the phrase "Zero WCAG AA violations". Iteration 8 changed it to "Zero violations against the web-spa label". The meaning is the same, because the label is WCAG 2.1 AA + SC 2.4.11 + SC 2.5.8. But the Phase 7 contract asks for an explicit "Zero WCAG AA violations" statement on must-be-accessible paths, and that literal text is now missing. There is no contradiction with the § SLO "NEVER use retry-once policy" ban: Section 10 also says `retries: 0` and no retry-once.
  Section: 10
  Severity: low

- **[INCOMPLETE]** The scrubber rule in Section 3 would fail the plan's own output. It fails the test on any string that matches "an absolute path". But the same bullet list reduces axe `url` to its path `/`, which is an absolute path. `remediation` also carries the axe `helpUrl`, whose path starts with `/rules/axe/…`. The Error-sanitization trigger means absolute filesystem paths, and the plan never says so.
  Section: 3 (Structured violation JSON schema → Scrubbing)
  Severity: medium

Only a11y-research's CI Integration Pattern prescribes it. No bootstrap phase wires it, so setup-project would have nothing to materialize.
  Section: 3 (Bootstrap phases → a11y-ci-gate-wire), 9 (Artifact retention)
  Severity: medium

  Section: 3 (Bootstrap phases), 12
  Severity: medium
