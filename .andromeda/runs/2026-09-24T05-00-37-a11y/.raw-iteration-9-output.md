## Analysis

**1. Downstream readiness**
- The closed vocabularies are mostly consistent. `scrub-leak`, `csp-console` and `axe-rule-not-run` each have one meaning, are `serious`, and have no `wcag_criterion`. Aggregation runs `if: always()` and reports `violation_type_counts`.
- **Defect:** two gating checks have no closed-list id. `a11y-path1` re-asserts the tests' reflow check (`scrollWidth <= clientWidth`, SC 1.4.4 / 1.4.10) and route check (only `/` serves HTML, SC 2.4.5 / 3.2.3), but none of the Section 3 `violation_type` ids covers either failure. §6 Typography lists the Reflow bullet under the "(`text-spacing-clip`)" label, which suggests reusing that id, and that would give one id two meanings. Patches 1–3.
- **Defect:** the html-validate `elements` declaration lists `viola-readback` as "flow content". Upstream places `<viola-readback>` on the tape send lines ("the line reads 'send to builder, read back'"), and the plan names the `<summary>` from that line text minus the `aria-hidden` box. So the host sits inside `<summary>`, which accepts phrasing content only. A flow-only declaration makes html-validate's content-model rules fail on the rendered DOM, so the SC 4.1.1 gate goes red from setup. Patch 4.
- State-strip placement, lint source paths, config paths and the definition of "applicable SC" are all concrete now. No patch.

**2. Scope faithfulness**
- All three tui boundary clauses have their own nextest case in §3 Keyboard harness, P4 and the §9 Unit/integration row. The CLI C0/C1 escaping, static-output and SGR-beside-word checks are pinned in P6. The v1.x brake SC 3.3.2 / 4.1.2 text is excluded from v1 coverage.
- Every `[resolved: …]` pointer lands on a real subsection.
- **Defect (pointers):** several "see the Decisions Log" references do not name the D-A11Y ID that exists for them: D-A11Y-13, 04, 18 and 19. Patches 5–8. D-A11Y-11 (§3 SR fallback), D-A11Y-12 (§3 guidepup) and D-A11Y-04 (§11 Strategy) are also unnamed; they were left over because the 8-patch budget ran out.
