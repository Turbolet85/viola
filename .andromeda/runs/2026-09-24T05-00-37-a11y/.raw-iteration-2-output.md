## Analysis

**Before starting:** Iteration 1 already fixed all 7 anchor examples except the Dimension 7 one. `iteration-2.md` in the run directory is byte-identical in size to the draft, so it is the snapshot taken after iteration 1. The analysis below covers what is still wrong.

**1. Downstream Readiness**
- `violation_type` / `severity` are consistent now. `scrub-leak` and `axe-rule-not-run` exist and emit `serious`, and Section 10's separate failure conditions can be told apart through `violation_type_counts`. No patch.
- The state-strip positions are valid HTML now (a `<p>` sibling after `<table>`, or the first child of the log `<div>`). No patch.
- **Defect:** the Section 9 Lint row still says "over the Lit `html` templates" and "the embedded `assets/index.html`". It has no `-c e2e-web/eslint.config.js`, no `crates/viola-ui/` and no `.htmlvalidate.json`, while Section 3 → a11y-ci-gate-wire names all of them. `setup-project` reads the stage table, so the two disagree. → Patch 1.
- **Defect:** the coverage gate gives SC credit to the wrong spec. Aggregation says the `no custom pointer/motion/drag` row is "met by the `surface-absence` spec". But the Section 3 map gives 2.5.1/2.5.2/2.5.4/2.5.7 a tabbable-oracle path, and `surface-absence` only walks for elements (`video … button`). The four SCs would go green while nothing verifies them. → Patch 2.

**2. Scope Faithfulness**
- The three tui boundary clauses each have a nextest case (Section 3 Keyboard test harness). The cli C0/C1, static-output and SGR-word checks are pinned in P6 and Section 6. No patch.
- **Defect:** the word for the `cli_verified:false` entity has two spellings. The Section 4 session-strip row prints "CLI `unverified`", while P3, Section 6 State color tokens and the upstream design warning word use `unverified-cli`. The SC 1.4.1 map row, which is the state-word list `setup-project` materializes, has neither, and it also leaves out the boxed `budget-paused` word. → Patches 3 and 4.
- The v1.x brake SC text in Section 7 says "when built", and the SC map marks 3.3.2 as absence. That is acceptable. No patch.

**3. Tool Anchoring**
- The `options()`/`withTags()` ordering is now labelled an assumption and backed by `axe-rule-not-run`. `jq` is labelled catalog-less. The `target-size` default claim matches research (a). No patch.
- **Defect:** Section 3 Configuration says the five best-practice rules "close the SC 1.3.1 / 2.4.6 landmark and heading gaps". Research (d) says they "carry no SC tag", and research line 15 lists 2.4.6 as "Not covered by any axe rule". → Patch 5.
- The Robust row's "axe 4.1.2 rules" is ambiguous, but it is wording only. Deferred as cosmetic.

**4. Tier Calibration**
- The SLO state list now covers the P1–P5 and Section 5 states. No patch.
- **Defect:** no named stage or command evaluates the "a11y CI duration > 50 % over the budgets" failure, and `duration_ms` is recorded but never read. That makes it a soft SLO in practice. → Patch 6.

**5. WCAG Mapping**
- **Defect:** the SC 2.4.11 triggers still disagree. The Section 3 row says "singly and combined (Section 5 Sticky header)" and includes skip-link activation, but Section 5 Sticky header has neither. Both leave out `budget-paused`, even though it is a boxed `--rule-info` ATIS state and upstream says ATIS "cells wrap at cell boundaries". → Patches 7 and 8.
- Deferred for budget: how the SC 2.5.8 spacing exception is computed, and the missing level column.

**6. Design-Token Binding**
- No raw values found.
- Deferred for budget: the Typography list ("every element sized by `--line-h`, `--strip-h` …") does not say how a test identifies those elements, and `--strip-h`'s two upstream meanings are not separated.
- The skip-link and anchor contrast is now machine-checked through the "skip link focused" and "scrolled-up" axe states added to the SLO list. No patch.

**7. Anti-Patterns**
- § CI "runtime axe-core / pa11y / Lighthouse" and § Universal "pa11y JSON / Lighthouse JSON" still name the dropped tools, and § Visual and § Motion share a duplicate ban. These can wait under the patch-budget order, so they are deferred to the next iteration.

**Adversarial checks**
- A scrub leak now shows up as `scrub-leak` in `violation_type_counts`, and Aggregation runs under `if: always()`. Resolved.
- A pointer-gesture regression would pass the SC 2.5.x gate through an unrelated spec. Patch 2 closes this.

### Patch 2: §9 Aggregation — take SC 2.5.1/2.5.2/2.5.4/2.5.7 credit away from `surface-absence`
**Reason:** Dimension 1, coverage gate derivable. The Section 3 map verifies these SCs with the tabbable-oracle actuator test, but Aggregation credits the element-absence spec, which cannot prove there are no path, motion or drag gestures. CI would be green with the SCs unverified.
**Old:**
```
`no submissions`, `no custom pointer/motion/drag`, `no surface`) are met by the `surface-absence` spec carrying one `@sc-<id>` per absent SC.
```
**New:**
```
`no submissions`, `no surface`) are met by the `surface-absence` spec carrying one `@sc-<id>` per absent SC. The `no custom pointer/motion/drag` row (SC 2.5.1 / 2.5.2 / 2.5.4 / 2.5.7) is met only by the tabbable-oracle actuator test named in that map row (the only actuators are native `<a>` / `<summary>`), tagged `@sc-2.5.1 @sc-2.5.2 @sc-2.5.4 @sc-2.5.7`. `surface-absence` never carries these four tags, because an element-absence walk cannot prove the absence of path, motion or drag gestures.
```

### Patch 6: §10 failure conditions — name the stage and fields that evaluate the +50 % budget breach
**Reason:** Dimension 4, budgets measurable. `duration_ms` is recorded but no stage reads it, and the Playwright JSON total is never compared. As written, the "> 50 %" failure condition is a soft SLO with no evaluator.
**Old:**
```

```
**New:**
```

```

### Patch 7: §3 SC 2.4.11 map row — add `budget-paused` to the header-growth triggers
**Reason:** Dimension 5, same SC verified the same way everywhere. `budget-paused` is a boxed `--rule-info` ATIS state (Section 6 pair row), and upstream says ATIS "cells wrap at cell boundaries", so it can grow the sticky header. The `@sc-2.4.11` coverage built from this row would miss it.
