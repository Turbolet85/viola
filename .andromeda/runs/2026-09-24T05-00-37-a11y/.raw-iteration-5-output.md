## Patches

### Patch 1: §4 P4 web — add the axe verdict for the WHEEL `human` state that §10 assigns to `a11y-path4`
**Reason:** Dimension 4 (Tier Calibration) plus Dimension 1. The §10 SLO list assigns "`a11y-path4` (WHEEL `human`)" as the owning `analyze()`, but P4 never asserts an axe verdict. The SLO state would have no spec running it.
**Old:**
```
  - **web:** the WHEEL `cell` word `human` (`--fw-strong`), with no focus change (`a11y-path4`).
```
**New:**
```
  - **web:** `a11y-path4` asserts the WHEEL `cell` word `human` (`--fw-strong`), no focus change, and the axe verdict in the WHEEL `human` state (the Section 10 state `a11y-path4` owns).
```

### Patch 2: §4 State strips row — position the empty-tape line and stop implying that empty/first-reading lines are announced
**Reason:** Dimension 1 (structural placement can be materialized). The empty-tape line has no valid position inside the `role="log"` → `<ol>` → `<li>` structure, so html-validate content-model rules could fail on a guessed position. "no role, announced through the status announcer" also contradicts the §7 closed message list, which never announces first-reading or empty lines.
**Old:**
```
empty/first-reading rack lines are a `<tr>` with one `<td colspan="6">`; no role, announced through the status announcer (Section 7)
```
**New:**
```
empty/first-reading rack lines are a `<tr>` with one `<td colspan="6">` in the rack's `<tbody>`; the empty-tape line (`TAPE live since <time> — no events yet`) is a native `<p>` inside the `role="log"` `<div>`, after any `TAPE stopped` `<p>` and before the `<ol>` (never an `<ol>` child). Strips carry no role; only the strips in the Section 7 message list are announced (through the status announcer), and first-reading / empty lines are never announced
```

### Patch 3: §3 Per-SC verification map — state the WCAG level for every row
**Reason:** Dimension 5 (levels are auditable). The map has no A/AA marker, so the "WCAG 2.1 AA + SC 2.4.11 + SC 2.5.8" label cannot be checked row by row, and `sc-coverage.json` has no level to report.

```
`video, audio, iframe, object, embed, img, input, select, textarea, form, dialog, button` in the rendered DOM in every state.
```
**New:**

- **Levels** (for auditing the label row by row; `sc-coverage.json` carries the level per row): Level A — 1.1.1, 1.2.1–1.2.3, 1.3.1–1.3.3, 1.4.1, 1.4.2, 2.1.1, 2.1.2, 2.1.4, 2.2.1, 2.2.2, 2.3.1, 2.4.1–2.4.4, 2.5.1–2.5.4, 3.1.1, 3.2.1, 3.2.2, 3.3.1, 3.3.2, 4.1.1, 4.1.2, 3.2.6 (2.2), 3.3.7 (2.2). **New:**

### Patch 6: §6 Typography — say how the text-spacing check finds token-sized elements
**Reason:** Dimension 6 (token-named checks can be implemented by name). Computed style returns resolved values, not token references, so "every element sized by `--line-h` …" cannot be materialized. The draft also leaves unclear whether `--strip-h` is asserted in v1. Upstream: `--line-h` is the "tape line / transfer marker row height"; `--strip-h` is the "fixed strip row height token (callsign line)".
**Old:**
```
  - Then assert that every element sized by `--line-h`, `--strip-h`, `--lh-display` or `--lh-label` has `scrollHeight <= clientHeight`.
```
**New:**
```
  - Then assert that every element sized by `--line-h`, `--strip-h`, `--lh-display` or `--lh-label` has `scrollHeight <= clientHeight`. Computed style returns resolved values, not token references, so the spec finds these elements through one shared selector list derived from the design token contexts: `--line-h` → tape `<summary>` and `<viola-transfer>` rows; `--strip-h` → the strip callsign line (clip check only; its v1.x brake target-size role is not asserted in v1); `--lh-display` → the Display-role `<h1>`; `--lh-label` → Label-role text (column captions, ATIS labels). A selector that matches zero elements, in a state where design renders that element, fails as `text-spacing-clip`.
```
