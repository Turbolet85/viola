## Patches

### Patch 1: §3 Structured violation JSON schema — `wcag_criterion` for the three ids with no SC
**Reason:** Dimension 1. `csp-console`, `scrub-leak` and `axe-rule-not-run` have no SC, so the row writer has no defined `wcag_criterion` value. It would invent an SC or write a literal `null` (banned), and either would corrupt the SC aggregation.
**Old:**
```
  - `wcag_criterion` is the bare SC ID. For axe it comes from the `wcagNNN` tag. The five best-practice rules map to `"1.3.1"`.
```
**New:**
```
  - `wcag_criterion` is the bare SC ID. For axe it comes from the `wcagNNN` tag. The five best-practice rules map to `"1.3.1"`. The three check-integrity ids `csp-console`, `scrub-leak` and `axe-rule-not-run` have no SC: their rows omit `wcag_criterion` (absent = null, never a literal `null`). The Section 9 SC coverage ignores rows without it, and they are counted only in `violation_type_counts`.
```

### Patch 2: §4 P4 — tui boundary names all three Section 1 clauses
**Reason:** Dimension 2. The tui entity has three boundary clauses, but P4 names only two. The zero-viola-bytes clause, which Section 3 now specifies, is missing from the path scenario.
**Old:**
```
  - **tui:** the portable-pty boundary asserts that human keystrokes are never blocked and that focus/mouse/resize sequences do not move the wheel.
```
**New:**
```
  - **tui:** three portable-pty outer-PTY nextest cases on all three OS legs, one per Section 1 boundary clause (Section 3 → Keyboard test harness → Tooling): (1) zero viola-originated bytes on the outer-PTY stream (byte for byte against an unwrapped fake-agent run on Linux/macOS; viola's own literals absent on Windows ConPTY); (2) human keystrokes delivered unblocked past the current atomic paste; (3) `\x1b[I`/`\x1b[O`, mouse and resize sequences do not move the wheel.
```

### Patch 3: §4 P6 — TTY-only CLI behaviours need the portable-pty outer PTY
**Reason:** Dimension 2. trycmd / assert_cmd run without a TTY, so they cannot check the TTY-only behaviours: `waiting:` printed once, no spinner or redraw, and a word beside every SGR. P6 credits them anyway, so those required cli behaviours have no real check.
**Old:**
```
- **P6 — CLI board, wait/last, verify, launch line** (cli). No ARIA. trycmd / assert_cmd assert, on all three OS legs:
  - linear static output (`waiting: <name>` once on stderr, TTY only);
  - `[NN/NN] … pass|fail`;
  - one `viola ui` launch line on stderr;
  - no SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json`;
```
**New:**
```
- **P6 — CLI board, wait/last, verify, launch line** (cli). No ARIA. trycmd / assert_cmd assert the non-TTY modes, and the portable-pty outer PTY asserts the TTY-only behaviours, on all three OS legs:
  - linear static output: under the outer PTY, `waiting: <name>` appears exactly once on stderr and the stream contains no `\r` redraw, cursor-movement or erase sequence (no spinner); under non-TTY the `waiting:` line is absent;
  - `[NN/NN] … pass|fail`;
  - one `viola ui` launch line on stderr;
  - no SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json`;
  - under the outer PTY, every SGR span sits beside its word (amber only on `DIALOG`, dim only on stale rows), and `unable` / `fail` carry no SGR;
```

### Patch 4: §3 Focus management harness — trimming keeps the focused line; trim notice verified
**Reason:** Dimension 2. The trim notice (a Section 1 entity item) has no verification path. The existing assertion ("focus is not on `<body>`") is also weaker than the Section 5 rule that trimming never removes the focused line (`focus-lost`).
**Old:**
```
  - **Focus survives trimming:** push beyond the 2000-line DOM cap while the oldest `<summary>` is focused, then assert focus is not on `<body>`.
```
**New:**
```
  - **Focus survives trimming:** push beyond the 2000-line DOM cap while the oldest `<summary>` is focused, then assert the same `<summary>` is still focused (`focus-lost` otherwise; Section 5 → Focus restoration). In this trimmed state also assert: the design trim-notice text (`older lines trimmed from view: N — the full tape is events.ndjson`) is a `<p>` inside the `role="log"` `<div>` before the `<ol>` (after the `TAPE stopped` `<p>` when present); it is not a tab stop; and the axe verdict holds (Section 10 state list).
```

### Patch 5: §10 Always-required SLO — each axe state gets an owning spec; add the trimmed state
**Reason:** Dimension 4. Several listed states have no owning spec, so `setup-project` cannot tell which spec runs `analyze()` there. None of the P1–P5 test lists covers readback-refused, WHEEL `human`, tape-line-expanded, scrolled-up, skip link focused or after skip-link activation. The trimmed state is also missing.

**New:**

### Patch 6: §3 per-SC map row 2.2.2 — auto-follow contract matches Section 5 / D-A11Y-17
**Reason:** Dimension 5. The Section 3 row says auto-follow "stops when … focus is in the tape". Section 5 and D-A11Y-17 say it may keep following but must never scroll the focused `<summary>` out of the viewport. A spec written from the SC map would therefore test a different contract from Section 5.
**Old:**
```
auto-follow stops when the reader scrolls up or focus is in the tape (Section 5) |
```
**New:**
```
auto-follow runs only while the reader is at the bottom, and while focus is inside the tape it never scrolls the focused `<summary>` out of the tape viewport (bounding-rect check after N injected events; Section 5 → Focus restoration → Auto-follow; D-A11Y-17) |
```

### Patch 7: §3 per-SC map row 2.5.8 — define how the spacing exception is computed
**Reason:** Dimension 5. "meets the spacing exception" gives no rule to compute, so `setup-project` cannot build `target-size-bbox`, and an undersized target could pass on an undefined condition.
**Old:**
```
`boundingBox()` of each summary, skip link (when focused) and anchor ≥ 24×24 CSS px or meets the spacing exception |
```
**New:**
```
`boundingBox()` of each summary, skip link (when focused) and anchor ≥ 24×24 CSS px. An undersized target passes only under the SC 2.5.8 spacing exception as the SC defines it: a 24 CSS px diameter circle centred on its bounding box intersects no other target and no other undersized target's circle. This is computed from the `boundingBox()` of every tabbable-oracle target in the same state (`target-size-bbox`) |
```

### Patch 8: §11 § CI — the lint-only ban no longer endorses dropped tools
**Reason:** Dimension 7. The ban offers pa11y and Lighthouse as the acceptable runtime half, which contradicts D-A11Y-05, § Strategy and Overseer Direction 1. It is a one-line fix, and it has been flagged since iteration 1 without being fixed.
**Old:**
```
- NEVER ship lint-only a11y without runtime axe-core / pa11y /
  Lighthouse (lint catches subset; runtime catches rest)
```
**New:**
```
- NEVER ship lint-only a11y without the runtime `@axe-core/playwright` 4.13.0 checks inside `scripts/agent-run.* run --browser` (lint catches a subset; runtime catches the rest). pa11y and Lighthouse are dropped (D-A11Y-05) and never serve as the runtime half.
```
