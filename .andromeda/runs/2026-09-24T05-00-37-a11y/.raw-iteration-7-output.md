## Analysis

**Dimension 1: Downstream readiness**
- The closed `violation_type` list, the `scrub-leak`, `csp-console` and `axe-rule-not-run` ids, and the `serious` severity rule all agree with each other. The state-strip positions are valid HTML. The lint paths and configs are named. Aggregation runs with `if: always()`.
- **Defect (blocks CI):** the coverage gate can't be satisfied as written. Section 9 and Section 10 need at least one passing `@sc-*`-tagged test for every map row. But the SC 1.4.4, 1.4.10 and 2.4.5 rows, which SC 3.2.3 also depends on, are credited only to *the tests'* reflow and route checks. Those live in tests-owned specs, which have no `@a11y`/`@sc-*` tags: upstream-context line 308 has the tests plan's `scrollWidth <= clientWidth` checks, and nothing tags them. The Section 2 tag rule also covers only `a11y-path1…5` titles and says nothing about `a11y-tokens` or `surface-absence`. So `setup-project` would either build a gate that always fails on SC 1.4.10 and 2.4.5, or retag another specialist's specs. **Patch needed.**

**Dimension 2: Scope faithfulness**
- Each of the three tui boundary clauses has its own nextest case (Section 3 Keyboard harness, P4). The P6 CLI behaviours are pinned. The v1.x brake text is excluded from `sc-coverage.json`.
- **Gap:** `unconfirmable` is one of the Section 1 readback states, but it only gets a state-word check. No path spec runs axe in it, even though it renders text in the word cell. **Patch needed (together with Dimension 4).**

**Dimension 3: Tool anchoring**
- The `options()`/`withTags()` ordering is labelled as an assumption and backed by the rule-execution check. Versions match across Section 1, the body and the Decisions Log. `jq` is labelled as catalog-less transport. SC 2.4.6 gets no axe credit. No patch needed.

**Dimension 4: Tier calibration**
- The SLO list covers every state that P1–P5 and the Section 5 layouts give an axe verdict to, and each state has an owning spec. Budgets are tied to `duration_ms` and `stats.duration`.
- **Gap:** the boxed ATIS states (`budget-paused`, `expired`, nonzero `skipped`) and the readback `unconfirmable` state show text, and some of them are in the P1 source (Critical Path 6, `budget-paused`). None of them ever gets an axe run, so `color-contrast` never sees their words. This is the same "a rendered state is missing from the list" pattern as the anchor. **Patch needed.**

**Dimension 5: WCAG mapping**
- SC 2.4.11 triggers match between Sections 3 and 5, combined growth and `#tape-end` included. The SC 2.5.8 spacing exception is defined. SC 2.2.2 reads the same in Sections 3, 5 and 6. Levels are listed. No new defect beyond the tagging issue under Dimension 1, which the map-row patches below fix.

**Dimension 6: Design tokens**
- The pairs match upstream-context Section 3, and the two derived pairs trace to D-A11Y-18. `--focus-ring`/`--surface-strip` is marked as a token-ratio check only. The text-spacing selectors are defined. The only raw numbers are SC thresholds and test viewports. No patch needed.

**Dimension 7: Anti-patterns**
- The § CI and § Universal bans now name the `@axe-core/playwright` pick. The duplicate and template bans were removed in earlier iterations. No patch needed.

**Adversarial check:** if the reflow check lives only in tests-owned specs, which artifact carries `@sc-1.4.10`? None does. Aggregation would report zero passing tests for SC 1.4.10 and fail every run. The alternative is that an implementer retags tests-owned specs, which crosses the specialist boundary. Patches 1, 2, 5, 6 and 7 fix this.

## Patches

### Patch 1: §2 Test tags: `@sc-*` tags only in a11y-owned specs, and a11y specs re-assert the tests-owned checks the map relies on
**Reason:** Dimension 1, coverage gate derivability. The SC 1.4.4, 1.4.10, 2.4.5 and 3.2.3 map rows rely on tests-owned checks that carry no `@sc-*` tags, so the Section 9/10 gate can't be met.
**Old:**
```
- **Test tags:** every a11y Playwright test has the tag `@a11y`, one
  `@sc-<id>` tag per SC it verifies (for example `@sc-2.4.11`), and
  its path id in the title (`a11y-path1` … `a11y-path5`). This follows
  the tests plan's "title contains scenario id" rule.
```
**New:**
```
- **Test tags:** every a11y Playwright test has the tag `@a11y`, one
  `@sc-<id>` tag per SC it verifies (for example `@sc-2.4.11`), and
  its path id in the title (`a11y-path1` … `a11y-path5`). This follows
  the tests plan's "title contains scenario id" rule. The two non-path
  specs (`a11y-tokens`, `surface-absence`) use their spec name as the
  title id. `@sc-*` tags live only in a11y-owned specs, and the tests
  plan's specs are never retagged. Where the Section 3 per-SC map cites
  a tests-owned check, `a11y-path1` re-asserts it under its own tags:
  the reflow check `scrollWidth <= clientWidth` at 1024 and 760–1023
  (`@sc-1.4.4 @sc-1.4.10`), and the route check that only `/` serves
  HTML (`@sc-2.4.5 @sc-3.2.3`, beside the region-order test). Without
  this, those rows have zero tagged tests and the Section 9 Aggregation
  gate fails.
```
