# a11y extract

## Relevance
partial — no web-spa, ARIA, focus or contrast surface is touched. The chunk reaches a11y in three places: the `src/run/wheel.rs` `Classifier` / `is_reply` / `Recorder::record` survivors, which sit on the tui keystroke boundary (the F-W2 closed non-editing list); the `src/human.rs` split, which carries the cli board's pinned caption and row-escape cases; and the `src/run/send.rs` split, which carries the `human-typing` refusal text. The Windows baseline (§2 of the scope) and the cross-target clippy gate (§4) are outside this domain.

## Constraints
- The tui boundary has three clauses: viola writes zero terminal bytes of its own; human keystrokes are never blocked, refused or delayed past the current atomic paste; and focus, mouse and resize sequences and terminal replies (F-W2's closed list) do not count as human editing, while every other byte does. A test or restatement that disposes of a `Classifier::step`, `Classifier::abort`, `is_reply` or `Recorder::record` survivor must leave all three clauses as they are (per a11y-plan §1 A11y Scope Summary → CLI and terminal entities, `viola run` TUI passthrough).
- The non-editing list is closed and exact. It holds focus reports, mouse reports (X10, SGR, urxvt) and terminal replies (DA1, DA2, CPR, DECRPM, kitty flags, OSC and DCS replies, and the seven post-`CSI` reply shapes). Each shape is matched by exact grammar: field count exact, no intermediate byte. The keys `n`, `t` and `m`, their Alt forms, their kitty key events, and any sequence one field or one prefix away from a listed shape all stay typing. A survivor fix must not widen or narrow this list. Whether the classifier's existing unit table already covers the sites behind the ESC-arm, `params.len() < BOUND`, `osc` and `is_reply` mutants is research's question (per a11y-plan §3 Keyboard test harness → Tooling).
- On `windows-2025` the platform fact stands (F-W3): the ConPTY host swallows focus reports, and an injected mouse report under win32-input-mode arrives as key-down records and takes the wheel. Any survivor test that runs on all three OS legs must keep that per-OS split ("the error only ever favours the human") (per a11y-plan §3 Keyboard test harness → Tooling).
- Critical path 4 requires a `send` refused `human-typing` to go to stderr as `unable … hint:` with a typed exit code (10). The `src/run/send.rs` phase split is a pure move and must leave that text, its stream and its exit code byte-identical (per a11y-plan §1 A11y Scope Summary → Critical paths, 4. Human takes the wheel).
- On the cli, colour is only ever a second cue. There is no SGR, glyph or cursor control under `--json`, non-TTY, `NO_COLOR` or `TERM=dumb`. Output is static and linear. In `list` rows, C0/C1 characters are escaped, `\n` / `\t` included. The `src/human.rs` split must move this behaviour without changing it. The colour layer belongs to "CLI output discipline", not to this chunk (per a11y-plan §1 A11y Scope Summary → A11y surfaces & assistive tech reach, cli Notes).
- P6 pins the board's caption order and row escape to named cases. Two are unit cases the plan places in `src/human.rs`: `board_row_caption_and_default_row_are_the_literals` and `escape_row_shows_every_control_character_as_hex_text` / `board_row_cli_cell`. The root cases are `list_human_board_is_the_literal_rows` and `list_of_a_stopped_wrapper_is_an_empty_board`. A split that moves the unit cases into a sibling module keeps their names. Whether the plan's `src/human.rs` location citation then needs a wrap-time amendment is for the wrap to read (per a11y-plan §4 ARIA Patterns & Roles → Must-be-accessible path scenarios, P6 and the cli mirror under it).
- The CLI output-discipline invariants (P4, P6) that live in crate tests are covered by the epoch-boundary mutation audit. A survivor in those paths is therefore an a11y-invariant gap that the next audit reads (per a11y-plan §10 SLO Invariants & A11y Budgets → Standard+ invariants).

## Patterns to follow
- The classifier's replies and their negative controls (one field away, one prefix away, `n` / `t` / `m` and their Alt and kitty forms) are proven in the classifier's unit table. Add the new survivor cases as rows of that table rather than as outer-PTY cases (per a11y-plan §3 Keyboard test harness → Tooling).
- Outer-PTY boundary cases are sequenced step-wise on the wrapper's own records: the `channel-request` line, the `wheel` record, a size receipt, a mouse report as read barrier, and an `answer` to no pending dialog as the wheel probe (exit 13 = driver, 10 = human). Never sequence on a timer (per a11y-plan §3 Keyboard test harness → Tooling).
- Caption order is pinned as a literal (`CAPTION`) in one unit case and one root case, not as a trycmd case. A moved writer keeps that one literal (per a11y-plan §4 ARIA Patterns & Roles → Must-be-accessible path scenarios, cli mirror).
- Each tui boundary clause is its own nextest case on all three OS legs: `tests/tui_passthrough.rs`, `tests/cli_budget.rs` and `tests/chaos_revive.rs`. They must stay green, untouched, through the `send.rs` / `human.rs` splits (per a11y-plan §3 Keyboard test harness → Tooling).

## Anti-patterns to avoid
- NEVER block, refuse or delay a human keystroke past the current atomic paste. NEVER count focus, mouse or resize sequences or terminal replies as editing. A `Classifier` restatement that admits one more shape as non-editing breaks this. Note that a mouse report the Windows ConPTY has already turned into key-down records is typing (per a11y-plan §11 A11y Anti-Patterns → Keyboard).
- NEVER colour CLI `unable` / `fail`, and NEVER emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run` / a passed `viola revive`. The `human.rs` split introduces no SGR (per a11y-plan §11 A11y Anti-Patterns → Visual).
- NEVER claim WCAG conformance for the cli or the TUI. A new assert_cmd or portable-pty survivor test is an output-discipline stand-in, not a11y-tool evidence (per a11y-plan §11 A11y Anti-Patterns → Strategy).

## Acceptance criteria contributions
- (a11y) Each new test that disposes of a `src/run/wheel.rs` classifier or `is_reply` survivor asserts against the F-W2 closed list. A listed shape leaves the wheel unmoved. Its one-field and one-prefix neighbours, and the keys `n` / `t` / `m`, take the wheel. Each test fails under its hand-applied mutant (per a11y-plan §3 Keyboard test harness → Tooling).
- (a11y) After the `src/human.rs` split, `board_row_caption_and_default_row_are_the_literals`, `escape_row_shows_every_control_character_as_hex_text`, `board_row_cli_cell`, `list_human_board_is_the_literal_rows` and `list_of_a_stopped_wrapper_is_an_empty_board` exist under the same names and pass with their literals unchanged (per a11y-plan §4 ARIA Patterns & Roles → Must-be-accessible path scenarios, P6).
- (a11y) After the `src/run/send.rs` split, a `send` refused `human-typing` still exits 10 with the `unable` line and one `hint:` line on stderr. The tui boundary cases in `tests/tui_passthrough.rs`, `tests/cli_budget.rs` and `tests/chaos_revive.rs` pass unchanged (per a11y-plan §4 ARIA Patterns & Roles → Must-be-accessible path scenarios, P4).
