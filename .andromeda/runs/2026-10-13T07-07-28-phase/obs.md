## Patterns to follow
- Disposal by a test that fails on an assertion under the mutant, or a behaviour-preserving restatement removing the site (scope §1, the Epoch 3 cleanup II precedent), judged later against obs-plan §10's `survived` definition.
- Pure-move split: each moved function keeps its `#[instrument(skip_all, name = "...", fields(...))]` attribute verbatim and its `obs_event!` calls verbatim (obs-plan §4 Span naming convention; §11 Spans / Traces).
- Unit-level obs assertions parse in-memory `Vec<u8>` writer lines with serde_json against `schemas/diag-line.v1.json` (obs-plan §9 Pipeline integration, Unit tests row) — the form for any new survivor test that asserts on an emitted line.
- Test homes for any new integration case live under `target/e2e-home/` so G2, G4 and the secret scan cover them (obs-plan §9 Pipeline integration, Integration tests row).

## Anti-patterns to avoid
- NEVER a bare `#[instrument]` or `#[instrument(err)]` / `#[instrument(ret)]` on a moved or new function (obs-plan §11 Spans / Traces; gate G1 per obs-plan §9).
- NEVER add a local `#[allow(clippy::print_stderr)]` or a print macro to the split `human.rs` siblings to make a move compile (obs-plan §11 Logs), nor a crate-level `#![allow(clippy::disallowed_macros)]` to quiet the Windows-target clippy (obs-plan §3 Bootstrap phases, logger-stack-install).
- NEVER add a log line, `event` value or field to "explain" a Windows baseline refusal on the statusline path (obs-plan §11 Logs: no new `event` values without a Decisions Log entry; obs-plan §4 Scenario: Budget governor no-line shape).
