## Constraints
- The §3 split stays inside the root `viola` bin: `src/run/send.rs` is the wrapper's `send` method (the one-in-flight slot, the local-command decision over `LOCAL_COMMANDS`, the driver relabel, the `session-start` post-condition claim) and `src/human.rs` is the one home of human-facing text and the board writers. Both are tree entries of their own, so a split into siblings or a directory module changes those entries, to be read back at wrap (per architecture §Infrastructure Patterns → Project directory structure).
- The root bin carries no print allow, and its only human writer is `src/human.rs`. The `refuse` / `internal_error` / `result` wrappers lock the stream, call the writer and drop the result, so a closed pipe is swallowed and never panics. `write_refusal` writes the `unable:` / `hint:` pair as ONE `write_all`. A split of `human.rs` must keep every human writer under the `human` module, keep these write shapes byte-identical and add no print allow. `[lints] workspace = true` is asserted by `tests/contract_lints.rs` (per architecture §Infrastructure Patterns → Build system).
- `cargo modules orphans --deny` is a CI gate, run per lib/bin target by `scripts/orphans-check.sh`. Every file the split creates must be reached by a `mod` declaration on every OS's target (per architecture §Infrastructure Patterns → Build system).
- `windows-mutants.yml` is `workflow_dispatch` only. It is dispatched only during the epoch-boundary audit and is never a gate, a required check or a dependency of `ci.yml`. The root package is four of its nine matrix items, split by file over `cfg(windows)` sources. `tests/contract_windows_mutation_scope.rs` keeps each item's file list equal to the gated sources. If a split sibling of `send.rs` or `human.rs` carries `cfg(windows)` code, it joins that test's subject. Whether either file holds Windows-gated code today is research's question (per architecture §Infrastructure Patterns → CI/CD approach).
- On a Windows host, `run --mutants` points `TMP` / `TEMP` at `<repo parent>/viola-mutants-scratch/`, so a test's tempdir lands outside the user's profile. Its guard refuses unless the final component is exactly `viola-mutants-scratch`. It never falls back to `%TEMP%` or the repository, and the path is never printed (documents carry only `scratch_bytes`). Any §2 remedy on the harness side must keep the guard, the no-fallback rule and the no-path rule (per architecture §Occupied Resources).
- The strict-modes check reads Windows owner + DACL through windows-sys. A home created outside the user's profile is given a protected user + SYSTEM DACL, and a DACL that cannot be set fails the creation. This is the mechanism §2's hypothesis turns on. Whether the test's tempdir in the scratch gets that DACL or an inherited one is research's question, closed against run 38215104120's own log (per architecture §Stack and Technologies, State-file primitives row).
- The CI lint target is `cargo clippy --workspace --all-targets --features fake-agent -- -D warnings` per OS. No C-building crate (`cc`, `libsqlite3-sys`, `openssl-sys`) may enter the graph, and bans are evaluated for the Windows, macOS and Linux triples. §4's check-only `--target x86_64-pc-windows-msvc` lint must mirror that command and need no C toolchain or Windows SDK. Pinned files currently read: `rust-toolchain.toml` is `components = ["rustfmt", "clippy"]` with no `targets` key, and the `pre-push` stages are `tools → linux-tests`. A change to either is an architecture change to be read at wrap (per architecture §Infrastructure Patterns → Build system).

## Patterns to follow
- One concern per file under `src/run/`: `gate.rs`, `wait.rs`, `dialog.rs`, `wheel.rs`, `snapshot.rs`, `budget.rs` and `links.rs`, each with a one-line role in the tree. The send/human split takes the same shape: phase files, each with a stated role (per architecture §Infrastructure Patterns → Project directory structure).
- Each gate script proves it fires before it judges: `--probe` modes on `lint-probes.sh`, `deny-probes.sh`, `orphans-check.sh`, `release-check.sh` and `g2-zero-panics.sh`, each with a planted failure and a clean control. A new cross-target lint gate follows the same proof-then-check shape (per architecture §Infrastructure Patterns → Build system).
- The Windows mutation matrix splits the root package by file so that each job ends inside the 120-minute ceiling, and the scope contract test keeps the lists honest. A survivor disposal or split that moves a gated file updates the matrix and the contract test together (per architecture §Infrastructure Patterns → CI/CD approach).
- The `hook statusline` arm's order is fixed: canonicalise, then `check_instance`, then open the log, then read stdin, then write `budget.json`, then read the snapshot, then run the command. The check comes before the log. A §2 fix must not reorder it (per architecture §Standard Contracts, Hook contract).

## Anti-patterns to avoid
- Dispatching `windows-mutants.yml`, or adding a mutation job to `ci.yml` or `pre-push`, inside the chunk. Mutation runs only at the epoch-boundary audit, and its Windows leg is dispatch-only (per architecture §Infrastructure Patterns → CI/CD approach).
- Adding a print allow on the root bin or a human writer outside the `human` module, or breaking a single-write pair into two writes during the split (per architecture §Infrastructure Patterns → Build system).
- Pointing the mutation scratch at `%TEMP%` or the repository, or printing its path, to dodge the DACL read (per architecture §Occupied Resources).
