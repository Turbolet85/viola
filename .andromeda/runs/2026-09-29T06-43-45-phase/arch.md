## Constraints
- Stamps have ONE writer: per architecture §Occupied Resources (Filesystem, `ledger/stamps.json`) and §Standard Contracts (Ledger stamps envelope), `viola_state::stamps::update_stamps` is called only by `viola verify`, `writer` is the literal `"verify"`, and a version counts as verified only when every row reads `pass`. So a stamped test home or harness `boot` gets its stamp only from running the verb. Whether any test or harness path writes the file some other way today is research's question.
- Test isolation is per home: per architecture §Cross-cutting Patterns (Config management) and §Established Decisions [CI/CD], each test runs in its own `--home`. That home's `ledger/stamps.json` is where the fake agent's reported version gets stamped. The endpoint hash, logs, plugin and pinned copy all follow the home. Test homes live at `target/e2e-home/viola-test-*/home` with `owner.json`, and harness homes at `viola-session-*/home` (per architecture §Occupied Resources, Repository).
- Real CLI only locally: per architecture §Infrastructure Patterns (CI/CD approach) and §Established Decisions [CLI Version Compatibility], the real `claude` never runs in CI. `viola verify` runs in CI only against the fake agent's `-p/--print` mode, and the real probe and `--record` run only locally. This is what `run --local-live`'s `live-in-ci` refusal enforces.
- One error enum per crate: per architecture §Established Decisions [Error Handling] and §Conventions (Error handling schema, Rust error types), `viola-agent-claude` holds `AgentError` only. `StampError` is named there as an interim divergence that this route entry is meant to fold. Per architecture §Established Decisions [Agent Coverage], the crate stays pure (no I/O, no `viola-state` dependency). The stamps file I/O stays in `viola_state::stamps` and the root bin's `run::version_gate`.
- The endpoint name is per home: per architecture §Conventions (Data model conventions, Endpoint name), it is `viola-<h12>`, the first 12 hex of an FNV-1a 64 hash over `ViolaName` + `\0` + the absolute viola home path, and `DefaultHasher` is forbidden. Per architecture §Occupied Resources (IPC endpoints; Environment variables `VIOLA_DIR`), the Windows pipe is `\\.\pipe\viola-<h12>` and `hook` reaches the endpoint recorded in the snapshot. Two same-named wrappers in different homes should therefore never share a pipe. Whether the code at HEAD hashes the home, and so whether item 8's hypothesis can hold, is research's question.
- Spawn logging in the version gate: per architecture §Established Decisions [Session Liveness] (as-landed start order), `run`'s bounded `--version` read is logged as a `version-probe` `process-start`/`process-exit` pair. Per architecture §Established Decisions [CLI Version Compatibility], the read is bounded (5 s, `MAX_FRAME`) and the probe has a 120 s deadline. Per architecture §Occupied Resources (Filesystem, `diagnostics/`), verify's `cli-<name>.ndjson` today carries only the `subject:"self"` pair, written only under a valid `VIOLA_NAME`. Per architecture §Occupied Resources (Repository), the line schema `schemas/diag-line.v1.json` is obs-owned and pinned by `tests/contract_diag_schema.rs`.
- The env var namespace is closed: per architecture §Conventions (Naming patterns, Environment variables) and §Cross-cutting Patterns (Config management), harness-only variables take the `AGENT_RUN_` prefix and are never read by `viola`. The only non-`VIOLA_*` variables any build reads are the two ratified `fake-agent` seams. Any CI detection behind `live-in-ci` sits in the harness, never in the product binary.

## Patterns to follow
- Recorded fixtures: per architecture §Occupied Resources (Repository), the layout is `fixtures/claude/<cli-version>/<Event>.default.json`, recorded by `viola verify --record` only when 0 rows fail, scrubbed, and walked by `tests/contract_fixture_hygiene.rs`. The first set is `2.1.283`. Per architecture §Occupied Resources (Binary), the fake agent's print mode fires the four spine `default` fixtures. Per architecture §Infrastructure Patterns (CI/CD target job 5), the suite replays `fixtures/claude/*`.
- Root contract tests: per architecture §Infrastructure Patterns (Project directory structure: `tests/`, sync root integration tests) and §Occupied Resources (Repository), existing tests follow the `tests/contract_*.rs` pattern (`contract_fixture_hygiene`, `contract_diag_schema`, `contract_content_hash`). The new `tests/contract_ledger_probes.rs` joins them over the six compiled ledger rows in `viola_agent_claude::ledger`, a closed set (per architecture §Established Decisions [CLI Version Compatibility]).
- The version line contract: per architecture §Established Decisions [CLI Version Compatibility], the first line must read exactly `X.Y.Z (Claude Code)`, and the fake agent answers `--version` the same way. Moving its default to `2.1.283` keeps that shape.
- Test-only endpoint namespaces: per architecture §Occupied Resources (IPC endpoints), `viola-test-chan-<pid>-<label>` and `viola-test-sqos-…` sit outside `viola-<h12>` and are unique per test. This is the precedent if item 8's witness or fix needs a test-side name.
- Human output and refusals: per architecture §Infrastructure Patterns (Build system, lint) and §Conventions (CLI exit codes), `src/human.rs` is the only human writer. Verify's refusals and step lines are fixed `unable:`/`hint:` pairs with no path, and a failing row still writes its stamp and exits 1. The harness's `verify-failed` outcome reads that verdict and never re-derives it.

## Anti-patterns to avoid
- Never hand-write `ledger/stamps.json` or `snapshot.json` from a test or the harness. Per architecture §Occupied Resources (Filesystem) and §Standard Contracts (Ledger stamps envelope; Instance snapshot), each has exactly one sanctioned writer.
- Never run the real `claude` in CI, and never let the `live-in-ci` guard be bypassed by a flag or environment variable (per architecture §Infrastructure Patterns, CI/CD approach; §Cross-cutting Patterns, Config management).
- Never keep a second thiserror enum in `viola-agent-claude`, and never give it I/O or a `viola-state` dependency to host the fold (per architecture §Established Decisions [Error Handling] / [Agent Coverage]). Never drop the home from the endpoint hash or switch to `DefaultHasher` (per architecture §Conventions, Endpoint name).
