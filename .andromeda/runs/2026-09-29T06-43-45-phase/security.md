## Relevance
partial — mostly test/harness plumbing, but it touches the stamp writer rule, the recorded fixtures, the real-CLI boundary, error-enum sanitisation, spawn logging, and (item 8) possibly the IPC endpoint's local trust boundary.

## Constraints
- **Stamps come only from `viola verify`.** security-plan §Security Anti-Patterns → Universal ("NEVER let any process other than `viola verify` write `ledger/stamps.json`") and §Data Protection (Code-bearing artefacts: written only by verify, under its `.lock`, 0600) apply to every stamped test home and to harness `boot` step 4. The same Universal section bans any writer of `instances/<name>/snapshot.json` other than the instance's own wrapper. That includes test support code and the harness. Whether any test or harness path hand-writes either file today is research's question.
- **Item 8 must stay inside the dated `hook.event` exception.** Per §Authentication & Authorization (IPC client-side server verification, Interim gap) and Decisions Log `2026-09-28` (`hook.event` served), `viola hook` sends `hook.event` without server verification or strict-modes until Epoch 6. No other frame, verb or process may take that exception, and the rationale rules out "a hook must not grow a partial verifier first". Any fix therefore lands elsewhere: in endpoint naming, in test isolation, or as a bound. It does not add a verifier to the hook. Per §Threat Model Summary (Attack surface: Local IPC, trust boundary), the endpoint name is meant to be FNV-1a over `ViolaName` + home path. Whether the Windows pipe name at HEAD actually carries the home, and so whether same-named wrappers in different homes can collide, is research's question. §Authentication & Authorization (IPC access control, Windows) keeps `FILE_FLAG_FIRST_PIPE_INSTANCE` and `accept_remote(false)` either way.
- **The hook fails open on every path.** Per §Error Handling (Internal logging) and §Security Anti-Patterns → Logging, `viola hook` exits 0 with empty stdout and stderr, including after security-check failures. The item 8 witness and the restamped consumers must keep `hook_fail_open`'s cases asserting this.
- **Folding `StampError` into `AgentError` keeps fixed messages.** Per §Error Handling (External responses: `AgentError` `Display` uses fixed messages, and variant fields holding paths or payloads stay out of `Display`) and §Bootstrap phases `error-sanitization-wire`, the folded `Malformed` variant must not interpolate a path, the stamps bytes, or a serde_json source whose `Display` quotes input.
- **The new spawn log lines respect the NEVER-log floor.** Per §Bootstrap phases `logging-redaction-wire`, the `version-probe` and probe-child `process-start`/`process-exit` pairs carry codes only. No absolute paths, no child stdout/stderr content, no `CLAUDE*` values (R8: names only, per §Secret Management → Storage). Per §Input Validation (Constants), child output stays drained through `MAX_FRAME` and is killed at 5 s. Per the Decisions Log `2026-09-28` capture arm entry, captures stay in the 0700 `ledger/probes/<pid>/` dir that verify removes on every exit path.
- **The real CLI runs only locally.** Per §Threat Model Summary (Infrastructure → CI/CD: "`viola verify` runs in CI only against the fake agent, and its real-CLI probe and `--record` only locally"), `run --local-live` must be refused under CI (`live-in-ci`). Every other harness path stamps against the fake agent.
- **No new flag or env var switches off a control.** Per §Security Anti-Patterns → Universal, `--unstamped`, `--cli-version`, `--local-live` and any new test-home option must not disable the IPC DACL, verification, strict-modes, `validate_paste_text` or redaction. Only the two ratified `fake-agent` seams exist, and a third needs a Decisions Log entry. Per §Dependency Security (release build) and security.md, `release-check.sh` keeps refusing `fake-agent`-feature artifacts.

## Patterns to follow
- `viola_state::fs::replace_private` for every file a test home or verify writes (mode set before the first byte). Per §Authentication & Authorization (`~/.viola/` access control).
- The ratified stamps read: `viola_state::stamps::read_stamps` with `take(MAX_FRAME + 1)`, where an over-cap file is an error and a malformed one produces one codes-only `parse-rejected{parser:"ledger-stamps"}` and `cli_verified:false`. Per §Input Validation (Own state files on read) and Decisions Log `2026-09-28` (stamps read).
- The fixture scrub and refuse rule when verify handles recorded sets: home prefix → `~`, user word → `<user>`, and the whole recording refused if a path or username survives. Per §Data Protection (Repository fixtures).
- A remove-the-guard witness, as with the `FAKE_AGENT_HOOK_PANIC` seam (Decisions Log `2026-09-28`, seam witness): the check reads red with the fix removed. This is the shape item 8's non-vacuous witness needs.
- Test homes as their own `--home`, with local `--home` dirs kept out of git by `.gitignore`. Per §Secret Management (Development) and §Bootstrap phases `secret-scanning-ci-gate`.

## Anti-patterns to avoid
- Hand-writing `ledger/stamps.json` or `snapshot.json` in test support, the harness or a fixture to reach a "stamped" state. Per §Security Anti-Patterns → Universal.
- Borrowing or widening the `hook.event` exception, or growing a partial server verifier in `viola hook`, to close item 8. Per §Security Anti-Patterns → Authentication (the one dated exception) and Decisions Log `2026-09-28` (`hook.event` served).
- Committing `fixtures/claude/*` recorded with non-synthetic prompts or unscrubbed, or registering the hidden `hook --capture` arm from any caller other than verify's probe plugin. Per §Security Anti-Patterns → Data Protection and Decisions Log `2026-09-28` (capture arm).

## Acceptance criteria contributions
- No test support file, harness script or fixture writes `ledger/stamps.json` or `instances/*/snapshot.json`. A grep over `tests/` and `scripts/agent-run.*` finds no such writer, and every stamped home's stamp comes from a `viola verify` invocation (per security-plan §Security Anti-Patterns → Universal).
- `agent-run run --local-live` under CI (`CI` / `GITHUB_ACTIONS` set) exits with the typed `live-in-ci` refusal and spawns no real `claude` (per security-plan §Threat Model Summary, Infrastructure → CI/CD).
- The folded `AgentError` variant's `Display` is a fixed string with no path or payload interpolation, and the new spawn-log lines carry codes only. The CI `secret-scan` step stays green over the test homes and the harness capture (per security-plan §Error Handling and §Bootstrap phases `logging-redaction-wire`).
- Item 8's fix leaves `viola hook` fail-open (exit 0, empty streams) on every `hook_fail_open` case, and adds no server verification to the hook client. Its witness forces the colliding condition and reads red with the fix removed (per security-plan §Error Handling, Internal logging, and Decisions Log `2026-09-28`, `hook.event` served).
