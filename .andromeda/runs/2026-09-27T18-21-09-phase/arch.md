# arch extract

## Relevance
partial — no product crate or wire contract is touched; the chunk lands the planned `e2e-web/` package, the ts code-graph plane, a harness/CI/pre-push extension and test-only resources, all of which architecture.md places and bounds.

## Constraints
- `e2e-web/` is test-side Node only and is the ts code-graph plane from its first chunk. It is typed by a tracked `e2e-web/tsconfig.json` (noEmit, strict, `e2e-web/**` only). No tsconfig, package manifest or bundler config may ever cover `crates/viola-ui/`, because the page has no JS build step. The plan names a CI-runnable guard that lists any such file; whether that guard exists yet is research's question (per architecture §Infrastructure Patterns → Code-graph planes; §Infrastructure Patterns → Project directory structure `e2e-web/` and `crates/viola-ui/assets/` rows).
- The browser pipe's Rust side lives only in the test-only `viola-e2e` crate (`viola-harness`, `publish = false`, no product crate depends on it). The chunk adds no workspace member. `e2e-web/` is not a Cargo member. `viola-ui` is not created early: each product crate is created by the first chunk that consumes it (per architecture §Established Decisions [Module Boundaries]; §Occupied Resources → Workspace crates).
- The stub page lives on the test side. It must not pre-empt `viola ui`'s occupied shape. `127.0.0.1:47319` and the GET routes (`/`, `/assets/*`, `/health`, `/api/*`) belong to `viola ui`, and the plan lists "no other listening TCP port". A `file://` page or a Playwright `route` fulfilment occupies nothing. A fixture server would be a new test-only resource: it would bind loopback only, and the wrap would record it. The P4 choice is bounded by this (per architecture §Occupied Resources → Network / HTTP routes; §Established Decisions [GUI Control Scope]).
- One set of pins serves the three CI OSes and the WSL pre-push leg. `scripts/wsl-provision.sh` installs only CI's own pins, so the Node, npm, Playwright and Chromium versions come from CI's lines and never from host values. The pre-push runs the ubuntu `test` job's suites in WSL2, and `wsl-exec.sh` is never a gate or harness path (per architecture §Stack and Technologies CI/CD row; §Infrastructure Patterns → CI/CD approach, the pre-push paragraph; §Infrastructure Patterns → Project directory structure `wsl-exec.sh` and `wsl-provision.sh` rows).
- CI stays least-privilege. Any new action a Node or Playwright setup needs (for example a setup-node) is pinned by full commit SHA with a version comment. Workflow `permissions: {}` and job `contents: read` stay in force. Event values reach a step only through `env:`. Gate steps are fail-closed `shell: bash`. The `test` job's order and its secret-scan-gated uploads keep their shape when a `playwright` suite and `--require playwright` join the `Gate verdict` step (per architecture §Infrastructure Patterns → CI/CD approach, the least-privilege, setup-steps and jobs-wired-today bullets).
- Any new variable the harness or tests read uses the `AGENT_RUN_` prefix, and the `viola` binary never reads it. No new `VIOLA_*` or unprefixed variable is added (per architecture §Conventions, Environment variables; §Occupied Resources → Environment variables; §Cross-cutting Patterns → Config management).
- The 10 s-bound recorder fold follows the existing viola-pty recorder pattern: a test-only file outside the viola home that `viola` never reads or writes, kept on panic or kill and removed on pass. A new `<temp dir>/viola-root-watch/` dir is a new test-only resource and gets its own §Occupied Resources line at wrap (per architecture §Occupied Resources → Filesystem, the `<temp dir>/viola-pty-watch/` entry).

## Patterns to follow
- Per-suite artifacts go under `target/agent-run/artifacts/` (per-suite JUnit plus `run-summary.json`). This is where `junit-playwright.xml` lands, inside the tree that `secret-scan` scans before any upload (per architecture §Occupied Resources → Repository, the `target/agent-run/` entry; §Infrastructure Patterns → CI/CD approach, the `test` job).
- Playwright outputs are gitignored and never tracked. The plan already reserves `e2e-web/test-results/`. `e2e-web/pw.json`, `e2e-web/pw-junit.xml` and `e2e-web/node_modules/` are further outputs the chunk ignores and records (per architecture §Occupied Resources → Repository, the `e2e-web/test-results/` entry).
- The harness runs its cargo work in its own target dir (`target/harness/`), because a running harness exe cannot be relinked on Windows. The browser step keeps that separation (per architecture §Occupied Resources → Repository, the `target/harness/` entry).
- Pinned tool installs follow the CI pattern: an exact version on the install line, reproduced verbatim by provisioning, as with cargo-modules, zizmor and ripgrep (per architecture §Infrastructure Patterns → CI/CD approach, setup steps).
- The tree's `e2e-web/package.json` comment names `@axe-core/playwright` as a target-state pin. Deferring it to Epoch 8 is consistent with the plan's staged landing ("they land with the Web UI chunks"), not a deviation (per architecture §Infrastructure Patterns → Project directory structure; §Occupied Resources → Repository, `e2e-web/test-results/`).

## Anti-patterns to avoid
- No tsconfig, `package.json` or bundler config under `crates/`, and no stub page placed in `crates/viola-ui/assets/` (per architecture §Infrastructure Patterns → Code-graph planes).
- No host value crosses into WSL provisioning, and no gate or harness step runs through `scripts/wsl-exec.sh` (per architecture §Infrastructure Patterns → Project directory structure, the `wsl-exec.sh` row; §Stack and Technologies CI/CD row).
- No product-crate or `viola`-bin code for a test-only pipe. The release build must still carry `viola` only (per architecture §Infrastructure Patterns → CI/CD approach, target job 6; §Occupied Resources → Binary).

## Contract bindings
- arch ↔ tests: the harness command contract (`run --browser`, the `browser-linux-only` refusal, `gate --require playwright`, `run-summary.json` suites) is owned by test-plan §3. Arch only places its artifacts under `target/agent-run/artifacts/` and its binary in `viola-e2e` (§Occupied Resources → Binary: "its command contract is test-plan §3"). The three-OS reversal is a test-plan amendment. Arch's CI/CD job list needs a matching amendment at wrap, and so does its pre-push stage list if WSL gains a browser stage.
- arch ↔ security: new CI actions are SHA-pinned, and WSL provisioning takes CI pins only. Whether the committed npm lockfile gets a supply-chain gate is a security-plan question. Arch's `supply-chain` job list changes only if such a gate lands.
- arch ↔ obs: `secret-scan` covers `target/agent-run/` before the `junit-<os>` and `harness-<os>` uploads. A Playwright artifact that is uploaded must sit behind the same scan gating (§Infrastructure Patterns → CI/CD approach, the `test` job).
- arch ↔ code-graph tooling: the tracked tsconfig activates the ts plane (§Infrastructure Patterns → Code-graph planes). Whether the refresh and health checks then expect scip-typescript is research's question.

## Acceptance criteria contributions
- `e2e-web/tsconfig.json` is tracked with `noEmit` and `strict`, and its `include` covers only `e2e-web/**`. `git ls-files` lists no `tsconfig*.json`, `package.json` or bundler config under `crates/` (per architecture §Infrastructure Patterns → Code-graph planes).
- The chunk adds no Cargo workspace member and no product-crate dependency. The browser pipe code sits only in `crates/viola-e2e/`, and `scripts/release-check.sh` still passes with `viola` as the only artifact (per architecture §Established Decisions [Module Boundaries]; §Infrastructure Patterns → CI/CD approach, target job 6).
- The stub needs no listening port other than a recorded, loopback-only test fixture, and `127.0.0.1:47319` is never bound by the stub (per architecture §Occupied Resources → Network).
- Every new output (`e2e-web/node_modules/`, `pw.json`, `pw-junit.xml`, and the root-watch report dir if chosen) is gitignored or outside the repo and gets a §Occupied Resources line at wrap. Any new variable is `AGENT_RUN_`-prefixed and unread by `viola` (per architecture §Occupied Resources → Repository / Filesystem; §Conventions, Environment variables).
