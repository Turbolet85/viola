# obs extract

## Relevance
partial — the chunk adds no product instrumentation (stub page, no `viola ui`, no new product code path). Obs applies through the CI telemetry-artifact rules and gate order the new browser step and CI jobs must fit into, the "every verdict sets an exit code" rule the `playwright` suite verdict carries, the zero-retry parallel, and keeping the test-side recorder reports (the overseer's 10 s wait fold) outside the product diagnostics scope.

## Constraints
- Obs tier is Standard with Minimal-tier exporter carve-outs (per obs-plan §1 Obs Scope Summary). The chunk adds no OTel SDK, no browser telemetry SDK and no new listener. The stub page carries no web-vitals or `@opentelemetry/sdk-trace-web` (per obs-plan §4 frontend row and §12 D-17). On the browser side the only admissible observables are DOM attributes and `performance` entries read by Playwright (per obs-plan §4 Frontend observable boundary). Real DOM-state reads are Epoch 8 work.
- The browser verdict must be a machine assertion that sets an exit code: `gate --require playwright` over the `run-summary.json` `playwright` suite, built from `pw.json` / `pw-junit.xml`. It is never human review of a Playwright HTML report (per obs-plan §11 CI "NEVER use human-review-gated log analysis" and §11 Universal).
- Playwright runs with `retries: 0`, the tests-side parallel of obs's zero-unlogged-panics invariant (per obs-plan §10 Cross-input parallel, §11 SLO "NEVER add retry-once policies … for flaky telemetry assertions").
- Where the browser step lands in a CI job on each OS, it keeps the §9 step order: G2 and G4 `if: always()` after the last test step, then the `if: failure()` harness capture into `target/agent-run/`, then `secret-scan` `if: always()`, then the scan-gated uploads (per obs-plan §9 Step order and conditions). A failing browser step must not skip G2, G4 or the scan (per obs-plan §11 CI "NEVER lose the failing job's `diagnostics/`").
- Artifact names are unique per workflow run, and v4+ artifacts are immutable. So a new Playwright artifact (e.g. `pw.json` / `junit-playwright.xml`) gets its own OS-suffixed name. It must never reuse `diag-<os>` / `harness-<os>` / `junit-<os>` or use `overwrite: true`, and it uses SHA-pinned `actions/upload-artifact` v7.0.1 with `retention-days: 7` (per obs-plan §9 Telemetry artifact handling, Artifact retention, and §11 CI "NEVER use unpinned Actions"). Whether a Playwright report can carry captured output that the scan must cover (as it covers nextest `junit.xml`) is research's question. If it can, the upload is gated on `steps.secret-scan.outcome == 'success'` like the others (per obs-plan §9 Step order item 3–4).
- If the browser step runs in a job that has no viola home (no fake-agent or E2E run before it), G2's non-empty check `test -n "$(find target/e2e-home …)"` fails closed there (per obs-plan §9 Gate commands G2). So on the new CI OSes the browser step either joins the existing per-OS E2E job, or the job runs no G2 at all and says why. Which one is P3/P4's read of `ci.yml`. The same single-job argument §10 makes for the perf gates applies (per obs-plan §9 Step order item 1).
- The 10 s-wait recorder reports (overseer direction) are test-side artifacts under `<temp dir>/…`. They are never written into `target/e2e-home/**/diagnostics/`: a non-schema line there fails G4, and screen content in a home-level file breaks the codes-only rule (per obs-plan §3 Log file location "codes-only by construction", §9 G4). A report dumped in a test's panic message lands in nextest `junit.xml`, which the secret scan already covers (per obs-plan §9 Step order item 3).

## Patterns to follow
- Every CI verdict is a gate exit code, and each gate is its own `run:` step with `shell: bash` on all three OSes (per obs-plan §9 Gate commands). The `gate --require playwright` step follows the same shape.
- Failure-path evidence goes through the harness capture (`agent-run logs` / `status` into `target/agent-run/`, `if: failure()`, before the scan). It is not a new ad hoc sink (per obs-plan §3 Snapshot / paste-to-AI integration, §9 Telemetry artifact handling row 2).
- Recorder pattern: evidence goes to a known file that survives a runner kill, is kept on failure and removed on pass, and the bound sits below the kill line. This mirrors the viola-pty recorder the chunk cites, and it matches the obs stance that a failing run's evidence must never be lost (per obs-plan §11 CI "NEVER lose the failing job's `diagnostics/`", by analogy for test-side evidence).
- `viola-harness` (`crates/viola-e2e`) is exempt from the `print_stdout` / `print_stderr` bans and prints one JSON document per command. Extending `run --browser` keeps that contract and does not add `[lints] workspace = true` to `viola-e2e` (per obs-plan §3 Bootstrap phases, obs-ci-gate-wire).

## Anti-patterns to avoid
- NEVER upload any artifact that can hold captured test output before the secret scan passes, and never gate an upload on a bare `always()` / `failure()` (per obs-plan §11 CI and §9 Telemetry artifact handling).
- NEVER inject CI env metadata (`ci.run.id`, commit sha, OS) into product log lines. CI identity lives in artifact names (per obs-plan §9 CI-specific resource attributes, §11 CI).
- NEVER add a browser telemetry SDK, a `/metrics` or other telemetry endpoint, or a Playwright `webServer` that stands up a viola listener for the stub (per obs-plan §11 Metrics "NEVER add a `/metrics` or other telemetry endpoint", §4 frontend row).

## Contract bindings
- obs ↔ tests §3 harness: the `playwright` suite in `run-summary.json` and `junit-playwright.xml` are tests-owned shapes. Obs requires only that they reach the `gate` verb as an exit code and fit the §9 artifact and scan rules.
- obs ↔ security (CI rows / WSL provisioning): Node and Playwright pins enter `scripts/wsl-provision.sh` as CI's pins only. Obs adds no env-var read and requires that no CI env value is carried into product logs (§9 CI-specific resource attributes).
- obs ↔ a11y (boundary, out of scope): the `a11y-violation` harness row and `e2e-web/test-results/a11y/*.ndjson` with `e2e-web/schemas/a11y-row.v1.json` are Epoch 8 (per obs-plan §3 Log format JSON schema, harness-side a11y rows). This chunk must not create that directory or schema, and must not add `a11y-violation` to `schemas/diag-line.v1.json`.

## Acceptance criteria contributions
- (obs) A deliberately failing stub run makes `gate --require playwright` exit non-zero. The browser verdict is an exit code, with no manual report reading (per obs-plan §11 CI).
- (obs) Playwright config has `retries: 0` (per obs-plan §10 Cross-input parallel).
- (obs) In every CI job that runs the browser step, G2, G4 and `secret-scan` still run `if: always()` after it, and every new Playwright artifact upload is SHA-pinned, OS-suffixed, `retention-days: 7`, and gated on `steps.secret-scan.outcome == 'success'` wherever it can carry captured output (per obs-plan §9 Step order and conditions).
- (obs) No recorder report path resolves under `target/e2e-home/**/diagnostics/`, and G4 stays green over the E2E homes after the recorder lands (per obs-plan §9 G4, §3 Log file location).
