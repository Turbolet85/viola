### established-decisions#7.1 · values · dec-message-broker-ipc · ## Established Decisions · lines 60–61 · add-to
- **[Message Broker / IPC] interprocess 2.4.4 `local_socket`, one endpoint per `viola run`, behind viola's own `channel` seam.** `hook` blocks on the channel for a dialog answer. `wait` blocks until the next driver-relevant event (`turn-ended`, `question`, `permission`, `plan`, `session-end` or `dialog-expired`) and returns that event, so nothing polls and a driver parked in `wait` learns that a dialog is pending. If a dialog is already pending when `wait` is called without `after`, or with an `after` at or before that dialog's event line, it returns that dialog at once (as landed by 2026-10-04-dialog-answers-by-dialog-id: `hook.dialog` is served, the dialog line is appended and signalled through `WaitFeed::appending_dialog` and cleared through `WaitFeed::dialog_settled`). With an `after` past that line the driver has already seen the dialog, so `wait` blocks for the next driver-relevant event, and a driver that leaves a dialog to the human never spins. Each dialog event carries a wrapper-assigned `dialog_id` (an integer, monotonic per instance, with the counter restored from `events.ndjson` on start so an id never repeats across wrapper restarts), and `answer` names its target by that id. At most one dialog is pending per instance. A `hook.dialog` that arrives while another is pending is answered `null` at once, so that dialog renders for the human. Its event is still logged with its own `dialog_id`, and a later `answer` for it is refused `not-delivered` with detail `unknown-dialog`. Whether Claude Code can hold two dialog hooks open at once (for example on parallel tool calls) is a capability-ledger row. `wait` takes an optional `after` cursor and an optional `timeout_ms`. `after` is a byte offset into the instance's `events.ndjson`.
 `wait` returns the first driver-relevant event whose line starts at or after it, at once if that event is already logged, so a turn that ends before the driver calls `wait` is never missed. Every `send` `ok` payload and every `wait` event result carries `cursor`, the offset to pass as the next `after`. Without `after`, `wait` returns the next such event appended after the call. With no `timeout_ms` it blocks until an event arrives, and if the endpoint vanishes first the caller gets `instance-unreachable`. On timeout it returns `ok` with `{"timed_out":true}`. `last` returns the `last_assistant_message` of the newest `turn-ended` event. The wrapper holds it in memory and rebuilds it from `events.ndjson` on start. Endpoint names are a short hash of the instance, never the raw `VIOLA_NAME` + path. On Windows the client connects only through the SQOS Identification open (windows-sys `CreateFileW` with `SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION | FILE_FLAG_OVERLAPPED`, adopted by `Stream::try_from`), never interprocess's default connect, so a squatted or rogue server cannot impersonate the client; a non-overlapped handle adopted this way hangs (as measured at chunk 2026-09-25-security-prerequisites). Rationale: one API over named pipes and Unix sockets, sync and Tokio flavours, and no daemon. macOS caps socket paths at about 104 bytes. Accepted risk: interprocess has one main maintainer, which the seam contains.
### established-decisions#15.1 · values · dec-budget-governor · ## Established Decisions · lines 131–133 · stale
- **[Budget Governor] Soft stop at the turn boundary.** Once a configured threshold is crossed (defaults `five_hour` ≥ 90 %, `seven_day` ≥ 85 %), automated `send` is refused with `budget-paused` through the same refusal path as `human-typing`. Human keys are never blocked, and a running turn finishes. The pause lifts when `resets_at` passes or on `viola release --budget`. `release --budget` leaves the wheel where it is, and a plain `release` returns the wheel to `driver` without lifting a budget pause. `release --budget` is sent to one instance's wrapper and lifts the pause for that instance only, until the crossed window's `resets_at` passes, so the next over-threshold reading does not re-pause it. The wrapper evaluates its gate from `budget.json`, read under `budget.json.lock`, at three points: at start, when a `send` arrives, and at each `turn-ended`. It never polls. A crossed threshold, a passed `resets_at` or an expired override takes effect at the next of these points, and only then is `budget-gate` appended. So a snapshot can still read `budget_paused: true` after the reset, until a `send` arrives or a turn ends, and every surface that shows the snapshot inherits that. The wrapper mirrors its budget-pause state, including any override, to the instance snapshot, where `list` reads it. As landed (chunk 2026-10-10-budget-governor; `src/run/budget.rs`, one `BudgetGate` per wrapper, no thread and no timer): a window is crossed only when its `used_percentage` is known and at or above its threshold and its `resets_at` is known, parses as RFC 3339 and is later than now, so a window whose `resets_at` is `"unknown"`, unparseable or passed never pauses. With both windows crossed the refusal names `five-hour`.
 The `send` point sits after the text refusals and the first `human-typing` read and before the running-turn read, so the order is `control-character` → `empty-text` → `human-typing` → `budget-paused` → `turn-running` → the readiness gate's wait; the gate is read once per `send`, never again after that wait. `answer`, `wait`, `last`, `pause` and `hook.dialog` do not read the gate (read in the diff: its five product call sites; since chunk 2026-10-10-session-links the root case `path6_a_closed_gate_leaves_answer_wait_last_and_pause_alone`, `tests/cli_budget.rs`, drives `answer`, `wait`, `last` and `pause` under one closed gate, each giving the exit code and the document it gives under an open one; no case drives `hook.dialog` under a closed gate). An override covers both windows until its end and is dropped at the next point after that end. It does not outlive its wrapper: every start, a revived one included, evaluates from `budget.json` alone and restores none. `release --budget` with no pause standing records nothing. `budget-gate` is appended, and the snapshot's `budget_paused` and `budget_override_until` are rewritten, only when the triple (paused, window, override end) changes, both before the evaluation returns; a record that cannot land is an error and the recorded state stays as it was. The thresholds are read once, at the wrapper's start, and no value of either switches the gate off. The gate is fail-open: no reading, an `"unknown"` figure, a passed or unparseable `resets_at`, an unreadable or refused `budget.json` and a bad threshold each leave it open or at its default. The decision takes the wall-clock instant as an argument (no clock seam). With figures missing, viola uses the newest reading from any wrapped session and shows its age. With no reading at all it records `unknown` and does not block.
 The statusline is wrapped only for sessions started by `viola run`, through a per-session settings override that then runs the user's own statusline command unchanged. As landed (chunk 2026-10-10-statusline-pass-through) the wrap is Unix only: on Windows no override is written and no command is run, and that half is owed to the working-route entry "Windows-only live measurements" (the founder's word on the cut, live, 2026-10-10, relayed verbatim by the operator). A reading is recorded only when the payload holds `rate_limits`. Rationale: the per-model weekly window is hidden (claude-code#91920), so thresholds are set low. The user's global statusline config is never touched, and a visible, conservative governor supports the "ordinary individual usage" posture.
