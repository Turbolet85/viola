# layouts extract

## Relevance
relevant: the chunk builds the cli surface's owed styled board, grouped `--help` and static-output forms, which layout-templates §Surface: cli specifies wireframe by wireframe.

## Constraints
- layout-templates §Output structure — `viola --help` requires `viola --help` to print the `Usage: viola [--home <dir>] <verb> [args]` line, a blank line, then the group rows `board:` · `traffic:` · `wheel:` · `handoff:` · `setup:` with their verbs. `viola <verb> --help` stays clap's per-verb usage, and `send`'s help says that prompt text comes from stdin or `--file`, never from a leading-slash argument. The wireframe's `handoff:  link, unlink` row names verbs that the project overview says are not served. Whether the row is kept, dropped or amended is a planning fork, and the code's current verb set is for research to read.
- layout-templates §Component — Primary navigation (verb structure) requires `--help` to group verbs as board / traffic / wheel / handoff / setup. `release` is a human verb that `--help` reaches, and no `hint:` line names it. The verbs stay flat, with no pager, no interactive prompt and no TUI mode.
- layout-templates §Output structure — `viola list` (human TTY) requires the styled board to show NAME values bold (Callsign), only the `DIALOG` word in `color-accent` with the kind word after it in the default style, and a `stale` row dim from end to end. On a cocked + `stale` row, `DIALOG` stays amber and not dim. Rows stay in name order and are never re-sorted by state. The "As built" paragraph under §Output structure — `viola list` (piped / `NO_COLOR` / `TERM=dumb`) records this styled form as not built and owed to this entry.
- layout-templates §Component — Primary content block 1: `viola list` strip rows requires that only unwrapped NAMEs are truncated, with `...`, and only where the terminal width is known. Wrapped names are never clipped, no line ever wraps, and nothing else is styled. Its As-built bullet records that truncation is not built.
- layout-templates §Surface: cli (Expression level) requires expression 0.0 (no colour, no non-ASCII glyph, no cursor control) for `--json`, non-TTY, `NO_COLOR`, `TERM=dumb` and the `viola run` / `viola revive` passthrough. §Output structure — `viola list` (piped / `NO_COLOR` / `TERM=dumb`) requires those forms to keep the same characters with no SGR and to truncate nothing when the width is unknown.
- layout-templates §Output structure — `viola wait` / `viola last` requires `waiting: <name>` to print once on stderr, only when stderr is a terminal and `--json` is not set, with no spinner and no elapsed-time counter. `last`'s message goes to stdout with C0/C1 escaped (`no message` on stderr for null). Per §Component — Primary content block 1 (Escaping), `\n` / `\t` stay unescaped in `wait` / `last` text, unlike the board's row escape. Whether `wait` / `last` already do this is research's question.
- layout-templates §Surface: cli (token table, Motion tokens row) requires that nothing redraws in place. §Output structure — `viola verify` requires each `[NN/MM] <row id> <row words>  pass|fail` step line to be appended once, with no progress bar and no redraw. §Output structure — `viola send` requires the issue line to stay and the outcome to be printed under it. §Output structure — `viola run` requires `run` to print nothing while the child holds the terminal.

## Patterns to follow
- layout-templates §Surface: cli (Tooling context) specifies styling as a small hand-written SGR module in the `viola` bin with no colour or table crate, TTY detection through std `IsTerminal`, and Windows VT output through windows-sys `SetConsoleMode`, with colour off if that fails.
- The "As built" paragraph under layout-templates §Output structure — `viola list` (piped / `NO_COLOR` / `TERM=dumb`) fixes the board's column widths: NAME padded to the longer of 4 and the longest name (counted in characters), LIVE 5, STATUS 7, WHEEL 23, DIALOG 17, CLI last and unpadded, and no line ending in a space. The styled form adds SGR around these words without changing the characters (per §Output structure — `viola list` (piped / `NO_COLOR` / `TERM=dumb`): "the same characters with no SGR").
- layout-templates §Component — Primary content block 2 (Streams) requires results on stdout, and `waiting:`, the issue line, refusals, hints and errors on stderr, never mixed.
- layout-templates §Component — Footer / terminator requires that no terminator word is printed. The exit code is the terminator, the last printed line says what happened, and on a refusal the `hint:` line is the last stderr line.

## Anti-patterns to avoid
- Colouring anything other than `DIALOG`, `stale` rows and NAME values. Per layout-templates §Component — Hero / signature output line, `read back` is never green and `unable` is never red, and the mirror is words and brackets only. Per §Output structure — `viola verify`, `fail` is never coloured. Per §IA notes, amber means `DIALOG` and nothing else.
- A spinner, `Sending…`, `✓`, `done`, a progress bar or an in-place redraw on any verb (per layout-templates §Component — Hero / signature output line and §Output structure — `viola verify`).
- A banner, ASCII-art logo, tagline or version line on normal output; the version appears only in `--version` / `--help` (per layout-templates §Component — Header / banner (the BAY context line)).

## Contract bindings
- layouts ↔ design-system §Tokens (platform-specific): layout-templates §Surface: cli (token table) names `color-accent` (attention SGR at truecolor / 256 / 16 depths), the `stale` dim token and the Callsign bold token. Their SGR values and the stale × cock composition are design's to supply, not layouts'.
- layouts ↔ a11y-plan P6 / P4: the expression-0.0 passthrough (layout-templates §Surface: cli, Expression level) and `viola run` printing nothing (§Output structure — `viola run`) are the layout side of a11y's linear static output and zero wrapper bytes.
- layouts ↔ architecture Config management / security-plan Secret Management: the 0.0 conditions `NO_COLOR` and `TERM=dumb` (layout-templates §Surface: cli, Expression level) presuppose reading those env vars. Layouts names the conditions but does not ratify the read, which is CARRY 2's boundary widening.
- layouts ↔ the human-output contract: layout-templates §IA notes says the human columns and words are stable for LLM drivers and that adding a human column is a design change. Styling and truncation must leave the column words and their order unchanged.

## Acceptance criteria contributions
- `viola --help` prints the Usage line and the group rows in the order board · traffic · wheel · handoff · setup, with no SGR. `viola send --help` names stdin / `--file` as the prompt source. (per layout-templates §Output structure — `viola --help`)
- On a TTY with colour enabled, `viola list` bolds only NAME values, makes amber only the `DIALOG` word (kind word plain), and dims a `stale` row end to end, keeping `DIALOG` amber on a cocked + stale row. Piped, `NO_COLOR`, `TERM=dumb` or `--json`, the same rows carry zero SGR bytes and no truncation. (per layout-templates §Output structure — `viola list` (human TTY))
- `viola wait <name>` with stderr on a TTY writes `waiting: <name>` exactly once on stderr. With stderr not a TTY, or under `--json`, it writes no `waiting:` line. No `\r` or cursor sequence appears on either stream. (per layout-templates §Output structure — `viola wait` / `viola last`)
- Under `viola run <name> -- <child>`, the outer terminal receives no byte of viola's own while the child runs. (per layout-templates §Output structure — `viola run`)
