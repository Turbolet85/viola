# a11y extract

## Relevance
relevant — this chunk is the cli surface's output discipline and the tui boundary clauses (Paths P4 and P6) that a11y-plan holds owed to "CLI output discipline"; the `ui` clause is out (frontend deferred to 0.2.0, per a11y-plan §1 A11y Scope Summary).

## Constraints
- a11y-plan §1 A11y Scope Summary (cli surface, Notes) requires colour only as a second cue (amber `DIALOG`, dim `stale`, always beside the word), no SGR, glyph or cursor control under `--json`, non-TTY, `NO_COLOR`, `TERM=dumb`, `viola run` or a passed `viola revive`, and static linear output with no spinner or redraw, on `[windows-2025, macos-latest, ubuntu-latest]`.
- a11y-plan §1 A11y Scope Summary (tui entity) requires the wrapper boundary: viola writes zero bytes to the terminal except the child's output, and human keystrokes are never blocked, refused or delayed past the current atomic paste; focus / mouse / resize sequences and terminal replies stay non-editing (the F-W2 closed list), with the Windows platform fact F-W3 as the stated exception.
- a11y-plan §4 ARIA Patterns & Roles (P6) requires, under the outer PTY, `waiting: <name>` exactly once on stderr and no `\r` redraw, cursor-movement or erase sequence; under non-TTY the `waiting:` line is absent; `verify` prints `[NN/NN] … pass|fail` step lines. Whether `wait` and `verify` already hold these shapes is research's question.
- a11y-plan §4 ARIA Patterns & Roles (P6) requires the SGR spans exactly: amber only on `DIALOG`, dim only on stale rows, bold only on NAME column values, each beside its word; `unable` / `fail` carry none. a11y-plan §6 Visual Design Verification restates the same and adds that `viola run` emits zero SGR of its own (stdout is the child's screen there).
- a11y-plan §4 ARIA Patterns & Roles (P6) requires C0/C1 controls shown only escaped: in `wait` / `last` text every C0 / C1 byte except `\n` / `\t`; in `list` rows `\n` / `\t` too (`\x0A`, `\x09`). Whether `wait` / `last` already escape is research's question.
- a11y-plan §4 ARIA Patterns & Roles (cli landmark row) names the `--help` group labels board / traffic / wheel / handoff / setup as the terminal's structural equivalent, not built (the built help is clap's ordered list). a11y-plan §1 A11y Scope Summary lists `link` / `unlink` among the CLI verbs; whether the grouped table may name verbs the binary does not serve is research's / P4's question, not settled by the plan.
- a11y-plan §8 Cognitive Accessibility (Plain language) requires every fixed CLI string to be pinned (trycmd, or literals for `viola list`), so new fixed copy (group labels, `waiting:` line, step lines) fails CI on any unplanned change.

## Patterns to follow
- The outer-PTY boundary driver (portable-pty `=0.8.1`, inherited, never re-pinned) for TTY-only behaviours, and assert_cmd 2.2.2 + predicates 3.1.4 + trycmd 1.2.1 for the non-TTY modes (per a11y-plan §3 A11y testing tool pick).
- Each P4 boundary clause as its own nextest case on all three OS legs: zero viola bytes compared byte for byte against an unwrapped `viola-fake-agent` run on Linux / macOS and as viola's literals absent on windows-2025 (on both ConPTY backends); the readiness-gate case `send_under_the_paste_hint_a_human_key_during_the_gate_wait_wins` sequenced on the `channel-request` line and the `wheel` record, never a timer (per a11y-plan §3 Keyboard test harness). Which of these cases already exist (`tests/tui_wheel.rs`, `tests/tui_passthrough.rs`) is research's question.
- The three-mode row check already named for `viola list` — piped, `NO_COLOR` / `TERM=dumb`, outer PTY; the no-ESC assertion Unix-only, and on windows-2025 the escaped text read under a 200-column terminal because ConPTY re-renders escapes (per a11y-plan §4 ARIA Patterns & Roles, P6), extended to the styled board's three spans.
- The `escape_row` hex form `\xHH` for row escaping, held by unit cases (per a11y-plan §4 ARIA Patterns & Roles, P6).

## Anti-patterns to avoid
- Never add a spinner, never colour `unable` / `fail`, never emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run` / a passed `viola revive`, never convey a state by colour alone (per a11y-plan §11 A11y Anti-Patterns, Motion and Visual).
- Never block, refuse or delay a human keystroke past the current atomic paste, and never count focus / mouse / resize sequences or terminal replies as editing (per a11y-plan §11 A11y Anti-Patterns, Keyboard).
- Never claim WCAG conformance from these cases, never parse the rendered `claude` TUI for content (R7), and never add an `a11y` suite value or a separate driver outside `scripts/agent-run.* run` (per a11y-plan §11 A11y Anti-Patterns, Strategy, Universal and CI).

## Contract bindings
- a11y ↔ tests harness: the cases run as ordinary nextest cases inside the CI `test` job's `coverage` suite under `gate --require coverage,doctest` on every leg, no skip, no new suite (per a11y-plan §3 CI integration; a11y-plan §9 CI Integration).
- a11y ↔ obs: no a11y violation rows for cli / tui; a failure surfaces only in the harness `run` JSON `suites[].failures[]` (per a11y-plan §3 Structured violation JSON schema).
- a11y ↔ design-system §Tokens (platform-specific) and cli: the SGR tokens, depths and the stale × cock composition the spans use (per a11y-plan §6 Visual Design Verification).
- a11y ↔ layout-templates `--help` / the board's styled form: the group labels and the styled board are the cli structural equivalents (per a11y-plan §4 ARIA Patterns & Roles).
- a11y ↔ architecture Config management / security-plan Secret Management: the "no SGR under `NO_COLOR` / `TERM=dumb`" requirement presupposes reading those env vars, which the scope's CARRY 2 names a boundary widening owed a founder ratification (per a11y-plan §1 A11y Scope Summary, A11y triggers → visual-discrimination).

## Acceptance criteria contributions
- (a11y) Three outer-PTY nextest cases pass on all three OS legs: zero viola-originated bytes (byte-for-byte vs an unwrapped fake-agent run on Linux / macOS; viola's literals absent on windows-2025), human keys delivered unblocked past the atomic paste including the readiness-gate case (send exits 10 `human-typing`, nothing typed, the key reaches the child), and focus / mouse / resize not moving the wheel (per a11y-plan §4 ARIA Patterns & Roles, P4; a11y-plan §3 Keyboard test harness).
- (a11y) Under the outer PTY `viola wait` writes `waiting: <name>` exactly once on stderr and no stream of any verb holds `\r` redraw, cursor-movement or erase bytes; under non-TTY the `waiting:` line is absent; `viola verify` step lines read `[NN/NN] … pass|fail` (per a11y-plan §4 ARIA Patterns & Roles, P6).
- (a11y) Under the outer PTY every SGR span sits beside its word (amber only `DIALOG`, dim only stale rows, bold only NAME values), `unable` / `fail` carry none, and no SGR appears under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run` (per a11y-plan §4 ARIA Patterns & Roles, P6; a11y-plan §6 Visual Design Verification).
- (a11y) Human-mode `wait` / `last` against a fake-agent event carrying C0 / C1 bytes (ESC / CSI included) show each injected control only escaped, `\n` / `\t` raw, checked with assert_cmd on all three legs (per a11y-plan §4 ARIA Patterns & Roles, P6).
