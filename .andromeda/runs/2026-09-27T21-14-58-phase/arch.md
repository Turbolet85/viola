# arch extract

## Relevance
relevant: the chunk lands a new CLI verb (`hook`), fills an embedded plugin contract, adds the first `hook.event` producer on the wrapper channel and the first `source:"hook"` event lines, and touches the one shared replace helper. All of these are architecture-owned surfaces.

## Constraints
- **Crate placement.** Hook JSON parsing, the hook-to-kind map, the `<pasted_content>` unwrap and the tag-escape reversal must live only in `viola-agent-claude`. The normalised kinds come from `viola-core`, and new kinds are added only there, never under Claude-specific names. The `hook` verb's clap arm and dispatch sit in the root bin (`src/cmd/`), which is the only crate allowed `anyhow` (per architecture §Established Decisions [Agent Coverage], [Error Handling]; §Conventions Normalised event kinds, Rust error types).
- **Tokio containment on the hot path.** The `hook` path must use std threads and blocking I/O over `viola-channel`'s sync client, with no runtime startup. `viola-agent-claude` is a listed sync crate, so it must keep passing target job 3 (`cargo check` without the `tokio` feature) and the sole-root `deny-sync.toml` ban (per architecture §Established Decisions [Concurrency / Backend Framework] KEYSTONE; §Cross-cutting Patterns Tokio containment; §Infrastructure Patterns CI target job 3).
- **Hook transport and tiers.** Each registered hook is exec-form: `"command": "<pinned viola copy>"`, `"args": ["hook", "<event>"]`, with the event argument taken from the kebab list in §Occupied Resources. The tiers are:
  - the spine: SessionStart, UserPromptSubmit and Stop, sync with no body, each within one built-in spine deadline that sits below the `hooks.json` `timeout`;
  - SessionEnd: about 1 s, with the direct `try_lock` append as its fallback;
  - async and silent: Notification, PostToolUse and PostToolUseFailure;
  - the dialog tier.

  The spine deadline's value is still an open item in arch, and the scope's `max < 1.0 s` stays provisional until arch names the value. Which tiers this chunk registers versus the dialog entry :62 is P3's call (per architecture §Established Decisions [Hook Transport]; §Occupied Resources Binary, subcommands and exit codes; Claude Code integration names).
- **Fail open and the unwrapped no-op.** `viola hook` must exit 0 on every path, including clap parse errors, channel failures and panics caught at the edge. It must write nothing to stderr and never exit 2. It must exit 0 at once when `VIOLA_NAME` is absent. Arch fixes the resolution key as the `VIOLA_NAME` / `VIOLA_DIR` pair that `viola run` sets in the child, never the working directory. The hook derives the home as the grandparent of `VIOLA_DIR` and connects to the `endpoint` recorded in `snapshot.json`, rebuilding the endpoint by rule only when the snapshot is missing or unreadable. Whether the code already reads it this way is research's question (per architecture §Established Decisions [Hook Contract]; §Conventions `viola hook` exit codes; §Occupied Resources Environment variables, IPC endpoints; §Cross-cutting Patterns Identity by instance, Fail open toward the human).
- **`prompt-submitted` normalisation order.** The `<pasted_content id=…>` wrapper is removed first, then tag escaping (`<\` → `<`) is reversed, so the wrapper-side matcher never sees a Claude shape. `data` is `{text, origin}` with `origin` ∈ `driver` · `human` · `harness`. Harness classification uses the ledger's harness prefixes (`<agent-message from=`, `<task-notification>`). Where the driver/human split is decided is research's question: arch ties it to the wrapper's send window and byte-source claim, not to the hook payload (per architecture §Established Decisions [Delivery Confirmation], [Human Takeover / Wheel]; §Standard Contracts Event `data` per kind).
- **Tolerant external parsing.** Hook stdin is parsed without `deny_unknown_fields`, using `#[serde(default)]` / `Option<T>`. The raw `serde_json::Value` is kept for the fixture recorder, and `serde_path_to_error` feeds the drift reports. Every read is under `Read::take(MAX_FRAME)`. Unparseable external values become `"unknown"`, never an error (per architecture §Established Decisions [Validation]; §Conventions Data model conventions).
- **The one replace helper.** Any fix to the `snapshot.json` replace, including a bounded Windows retry, belongs inside `viola_state::fs::replace_private`, and no call site may carry its own temp-plus-rename or retry code. On final failure the target must be left as it was. The plugin files keep going through `replace_private_shared` (per architecture §Established Decisions [Snapshot writer]; §Stack and Technologies State-file primitives).

## Patterns to follow
- **Plugin write-out.** `viola run` rewrites the embedded `include_str!` `hooks.json` into `<viola home>/plugin/<version>-<hash>/` on every start. It substitutes the pinned copy's absolute path, with forward slashes, into every exec-form `command`, and the result is passed with `--plugin-dir`. Hooks never search PATH. The `{"hooks": {}}` placeholder rule was tied to the `hook` verb not existing yet, and this chunk retires it (per architecture §Established Decisions [Deployment / Distribution] KEYSTONE; §Cross-cutting Patterns Cross-platform discipline).
- **Channel notification shape.** `hook.event` is the only id-less frame. Its `params` are `{v, sender, ts, event:{kind, …}}` on one line of at most `MAX_FRAME` bytes. A client may add `conn`, which the server strips and never treats as identity (per architecture §Conventions Channel methods; §Standard Contracts Wrapper channel frames).
- **Event line.** The wrapper appends `{v, ts, instance, kind, source:"hook", data}` with one `write` per line and never truncates. `data` holds only normalised fields and never a raw Claude payload. `session-start` data is `{cause ∈ startup·clear·resume·compact·unknown, agent_session_id}`. The `activity` kind is log-only and never wakes `wait` (per architecture §Standard Contracts ndjson event line, Event `data` per kind; §Conventions Hook → kind map, ndjson line discipline).
- **Diagnostic channels.** `hook` writes its codes-only process log to the home-level `diagnostics/hook-<name>.ndjson`. Content-bearing detail, including drift reports, goes only to `instances/<name>/diagnostics/detail-hook.ndjson`. A failure to write either file is ignored. The line formats are owned by obs (per architecture §Cross-cutting Patterns Diagnostic output channels; §Established Decisions [Hook Contract]; §Occupied Resources Filesystem `diagnostics/`).
- **The capability ledger.** Every undocumented CLI behaviour the chunk leans on must be named as a ledger row for :51 to probe: the pasted-content wrapper, tag escaping, the harness prompt prefixes and the hook tier map. None of them may be hard-coded as an unconditional assumption (per architecture §Established Decisions [CLI Version Compatibility]; §Cross-cutting Patterns Capability ledger as the single gate).

## Anti-patterns to avoid
- A PATH lookup, a relative path or backslashes in a plugin `command`, or a hook launched through `sh`, `bash` or `cmd` (per architecture §Established Decisions [Deployment / Distribution]; §Cross-cutting Patterns Cross-platform discipline).
- Claude-specific shapes leaking out of `viola-agent-claude`: a raw hook payload in event `data`, or a Claude-named event kind (per architecture §Established Decisions [Agent Coverage]; §Standard Contracts ndjson event line).
- A Tokio or async dependency on the `hook` path, or `deny_unknown_fields` on the hook payload or on viola's own formats (per architecture §Cross-cutting Patterns Tokio containment; §Established Decisions [Validation]).

## Contract bindings
- **arch ↔ security:** before the first `hook.event` frame, the hook must verify the server's pid and start time against a `snapshot.json` that passed strict-modes in the same process. On Windows the connect must be the SQOS Identification open (per architecture §Established Decisions [Message Broker / IPC]; §Cross-cutting Patterns Local endpoint trust boundary; the mechanism is the security plan's).
- **arch ↔ obs:** the hook role files `hook-<name>.ndjson` and `detail-hook.ndjson`, `drift_report` in `diag-detail.v1.json`, and the catch-site role classification that keeps `hook` at exit 0 (per architecture §Cross-cutting Patterns Diagnostic output channels; the format is obs's).
- **arch ↔ tests:**
  - the `target/perf/` build dir and the `run --perf` exports;
  - the `fixtures/claude/<cli-version>/` replay by the fake agent;
  - any new `fuzz/fuzz_targets/<target>.rs` with its `fuzz/corpus/<target>/`, which is a new resource the wrap records in §Occupied Resources Repository;
  - the `events.ndjson` line 3 `session-start` after `wheel` and `budget-gate`, which matches the start order in [Session Liveness].

  (Per architecture §Occupied Resources Repository; §Established Decisions [Session Liveness].)
- **arch ↔ :51 ledger:** every normalisation rule above rests on a ledger row that `viola verify` must probe (per architecture §Established Decisions [CLI Version Compatibility]).

## Acceptance criteria contributions
- Every entry in the written `plugin/<version>-<hash>/hooks/hooks.json` is exec-form. Its `command` is the pinned copy's absolute forward-slash path, its `args` are `["hook", "<kebab event>"]` from the §Occupied Resources list, and no entry relies on PATH (per architecture §Established Decisions [Hook Transport], [Deployment / Distribution]).
- Hook-payload parsing and `prompt-submitted` normalisation compile only in `viola-agent-claude`. The unwrap-then-unescape order holds on a round trip, and `viola-agent-claude` still passes CI target job 3 and the `deny-sync.toml` tokio ban (per architecture §Established Decisions [Agent Coverage], [Delivery Confirmation]; §Infrastructure Patterns CI target job 3).
- `viola hook <event>` exits 0 with empty stdout and empty stderr in each case: `VIOLA_NAME` absent (no event appended), malformed stdin, an unreachable endpoint, and a caught panic (per architecture §Conventions `viola hook` exit codes; §Established Decisions [Hook Contract]).
- A spine hook produces one id-less `hook.event` frame carrying `v`, `sender` and `ts`, and the wrapper appends exactly one `events.ndjson` line with `source:"hook"` whose `data` holds only the normalised fields for its kind (per architecture §Standard Contracts Wrapper channel frames, ndjson event line, Event `data` per kind).
