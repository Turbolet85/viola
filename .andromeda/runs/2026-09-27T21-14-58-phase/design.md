# design extract

## Relevance
partial — the chunk adds no rendered surface (no tokens, type, spacing, motion or iconography apply), but it produces the event vocabulary the web tape and readback box consume, and it adds the `hook` verb, which the cli surface fixes as having no human design surface.

## Constraints
- design-system §Surface: cli → Platform-Specific Notes requires `viola hook` to write nothing to stderr and always exit 0. It has no human design surface: no hint line, no `error:` line, no `unable` phraseology, no readback mirror.
- design-system §Surface: cli → Tokens (Colour decision order, rule 3) puts `viola hook` ahead of every depth test. The hook role never emits SGR, glyphs or cursor control, whatever the TTY, `NO_COLOR`, `TERM` or VT state. Whether the chunk's dispatch path runs the colour/depth selection or the Windows `SetConsoleMode` VT enable for `hook` at all is research's question. The lean is that it should not, because the rule yields "no colour" before any probe.
- design-system §Surface: cli → Exit-code phraseology (row 2) requires that clap usage text (exit 2) is "never produced by `viola hook`". A malformed argv to the hook verb must not reach clap's usage/exit-2 path.
- design-system §Color Palette → Semantic Colors (EventKind / SessionStartCause / PromptOrigin / EventSource rows) fixes the word set the tape prints for what this chunk emits. It covers the kind words `session-start` and `prompt-submitted` (printed as `prompt · <origin>`), the cause words `startup` / `clear` / `resume` / `compact` / `unknown`, the origins `driver` / `human` / `harness`, and `source hook`. The emitted wire values must be exactly these words. The canonical spelling lives in architecture §Standard Contracts, and design depends on it.
- design-system §Surface: web-spa → Component Patterns 2 (`<viola-readback>` Sources) and the Design Decisions Log 2026-09-24 (Data dependency) pair a readback `read` with the next `prompt-submitted` whose origin is `driver` on that instance, or with `session-start` cause `clear` and a new session id for `/clear`. The origin this chunk assigns therefore decides whether a send ever reads back. A driver prompt mislabelled `human`/`harness` leaves the box `open`. A human prompt mislabelled `driver` fills a box falsely, which breaks the "no presumption" stance in §Anti-Patterns → Rejected Defaults (optimistic "Sent ✓").
- design-system §Color Palette → Semantic Colors (PromptOrigin::harness) renders harness-origin lines whole in lamp-off as "neither party's traffic". This is separate from `PromptOrigin::human` (weight 600, "the human took the wheel"). Classifying a harness-injected prompt (`<agent-message from=`, `<task-notification>`) as `human` would render as a human wheel-take on the tape.

## Patterns to follow
- Words carry every state and colour is only a second cue (design-system §Anti-Patterns → Per-Surface Bans (cli), and §Surface: cli → Platform-Specific Notes on conhost without VT). The chunk's contribution is to emit the typed word values the renderers already key on. It adds no new visual state.
- Unknown values degrade to a printed word, never a guess. The tape prints `SessionStartCause::unknown` as `unknown`, and a kind unknown to the page as `skipped  1 unknown kind` (design-system §Color Palette → Semantic Colors). A hook source the map cannot classify should map to the contract's `unknown` value (for example `session-start` cause `unknown`) rather than to a plausible-looking guess. The architecture contract decides whether such a value exists for each field.
- The expanded tape line shows prompt text as plain text in Code type (design-system §Surface: web-spa → Component Patterns 4, Expanded body). The normalised `prompt-submitted.text` (the long-paste wrapper removed, tag escaping reversed) is the exact string a human later reads there. The normalisation must not add or leave behind any wrapper markup.

## Anti-patterns to avoid
- Printing anything human-facing from the hook role (a hint, an `error: internal error` line, colour or a glyph): design-system §Surface: cli → Platform-Specific Notes and §Anti-Patterns → Per-Surface Bans (cli, "NEVER emit colour, glyphs or cursor control under … `viola run`", and by colour-decision rule 3, `hook`).
- Inventing event-kind, origin or cause words outside the tape's table (for example a `pasted` origin or a `hook-start` kind). The page counts an unknown kind as `skipped` and never renders it (design-system §Color Palette → Semantic Colors, `EventKind::(unknown to this page)`).

## Contract bindings
- design ↔ architecture §Standard Contracts (event line): the design-system's EventKind / PromptOrigin / SessionStartCause / EventSource word sets must equal the architecture's wire enums. This chunk is the first producer of `session-start{source:"hook"}` and `prompt-submitted{text, origin}`.
- design ↔ tests (test-plan §6 Path 1, event line 3 `session-start`): the readback pairing source (design-system §Surface: web-spa → Component Patterns 2) rests on the same `origin:"driver"` and `session-start` cause `clear` values that the test-plan paths assert.
- design ↔ security (NEVER-log floor, R8 strip): the plain-text-only rendering of prompt text (design-system §Anti-Patterns → Per-Surface Bans (web-spa), no `innerHTML`/Markdown) assumes `text` stays untrusted content. Normalisation reverses only the CLI's tag escaping and never interprets the text.
- design ↔ a11y: none new. The chunk adds no rendered element, token, contrast pair or motion.

## Acceptance criteria contributions
- (design) Every `kind`, `origin` and `session-start` cause value this chunk writes to `events.ndjson` is one of the words in the Semantic Colors table (`session-start`, `prompt-submitted`; `driver`/`human`/`harness`; `startup`/`clear`/`resume`/`compact`/`unknown`; source `hook`). A test enumerates the emitted values against that set (per design-system §Color Palette → Semantic Colors).
- (design) A harness-injected prompt (`<agent-message from=` / `<task-notification>` prefix) is emitted with `origin:"harness"`, never `human`, so the tape draws it lamp-off rather than as a human wheel-take (per design-system §Color Palette → Semantic Colors, PromptOrigin rows).
- (design) `viola hook` under a TTY with colour available (no `NO_COLOR`, `COLORTERM=truecolor`) and a malformed argv or stdin produces zero stderr bytes, no SGR/escape bytes on stdout, and exit 0, never clap's exit-2 usage text (per design-system §Surface: cli → Tokens, Colour decision order rule 3, and §Surface: cli → Exit-code phraseology row 2).
