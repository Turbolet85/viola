# tests extract

## Relevance
relevant — the chunk is a real-PTY test probe over `viola-pty` (the recorder, its seam tests, a possible CI probe job), and it decides the fate of a flaking test under the zero-flake budget.

## Constraints
- **Zero-flakiness budget governs the outcome.** Per test-plan §10 Zero-flakiness budget (and §11 CI / §11 Quality), nextest `retries = 0`, and a flake that has been seen once is quarantined: the chunk stays red until the root cause is fixed. `#[ignore]` and `test.skip` are banned as parking places, and so is a `#[cfg]` compile-out done only to hide the red. This binds both exits of step 3. The "document" arm must still leave `spawn_runs_a_raw_child_that_sees_its_size_a_resize_and_its_own_exit_code` (and any new probe test) as a witness that cannot flake, with no retry, ignore or skip. How that witness is reshaped once a loss is documented as below viola is a P4 fork, not a licence to relax the test.
- **Module ↔ PTY stays real.** test-plan §5 (Boundary types, Module ↔ PTY) requires a real ConPTY / openpty spawn through the `viola-pty` seam, with a resize propagated even when it lands between the spawn sizing and the pump's first look. The pump's resize baseline is the spawn size, never a second host read (§12 Decisions Log `2026-09-27`, local-linux-pre-push-gate). Any fix in `PortablePty::resize`, the writer or the pump's resize-then-write path must keep `pump_forwards_a_resize_that_lands_before_its_first_look` and `tui_host_resize_in_the_pump_start_window_reaches_the_child` green.
- **Deterministic, event-keyed waits.** test-plan §2 (Agent-runnable invariants) and §11 Universal ban sleep-based synchronisation and any test-owned timer or elapsed-time verdict. Waits key on observed signals, and a bound is only a failure deadline. test-plan §3 (`run` step 2) caps root child waits at 7 s, below the nextest `mutants` profile's 10 s kill, and makes them exit-aware. The test-side sequence the recorder adds (resize returned · key written · key flushed) is an ordering record. It must not become an elapsed-time pass/fail verdict.
- **Three-OS verification, OS by OS.** test-plan §1 (multi-os-compat trigger) and §9 (Matrix builds: `windows-2025` ConPTY, `macos-latest` / `ubuntu-latest` openpty, `fail-fast: false`) require the cross-platform recorder change to be green on all three runners. test-plan §11 Test Strategy bans treating one OS's run as proof for another. Host greens (60/60, 20/20, 30/30) are not evidence about the windows-2025 runner. Neither is the WSL `pre-push` Linux leg.
- **Coverage floors per OS, regex untouched.** test-plan §10 (Coverage thresholds, Stack adjustments) enforces `--fail-under-lines 85 --fail-under-functions 95 --fail-under-regions 80` per OS job. `#[cfg(windows)]` recorder or fix code counts only on the Windows leg. `viola-pty` is not in `COVERAGE_IGNORE`, and §11 CI bans widening that regex to pass.
- **CI probe job, if P4 picks one.** test-plan §9 (Pipeline structure, Test report format, tool-install paragraph) requires SHA-pinned `uses:`, `permissions: {}` with job `contents: read`, and rust-cache only (§11 CI: no other cache). Every uploaded artifact goes out only behind the secret scan, and every tool comes from its pinned install source. test-plan §10 (Verdict) and §11 Quality forbid reruns or retrying away: a looped probe is a measurement with a count fixed beforehand, never a job that passes on any green iteration.
- **Seams go through existing traits and fake-agent-only seams.** test-plan §8 (Mocking libraries: mockall on the `viola-pty` `Pty` trait only; Anti-monkey-patching) and §11 Mocking require fault seams to be mockall doubles of existing traits, or process and file faults. The forced-window precedent reaches its window through the `fake-agent`-only `FAKE_AGENT_PUMP_DELAY_MS` seam (§12 `2026-09-27`). A mock cannot reproduce a ConPTY loss, so the localisation and fix witnesses stay real-PTY.

## Patterns to follow
- **Kill-proof codes-only recorder** (per test-plan §3 `run` step 2, `tests/support/watch.rs`; §12 `2026-09-27` browser-verdict-reachability). The watch writes one line per change to `<temp dir>/viola-root-watch/<test>.<label>.report`. The file is kept on a failure or a runner kill and removed on a pass. The report carries codes, counts and booleans, never content. This is the model for step 1's localisation report, so that a runner kill still says which of resize and key was lost. Whether the viola-pty seam test's report (`start pid=… raw=… size=…`, `byte … size=…`) already travels through a side channel or through the PTY master stream is research's question.
- **Independent size oracle** (per test-plan §7, fake agent receipt kinds). The `size` {`cols`, `rows`} receipt is written at start and again whenever the terminal size changed, apart from any key. It is the shape to mirror for the child recorder's size-change line. The file uses one write per line, and each line carries `v` plus a kebab `kind`.
- **Measured-cause method** (per test-plan §12 Decisions Log `2026-09-27`, local-linux-pre-push-gate Rationale). First force the window open (a hold). Then show N/N red with the exact signature, a control at N/N green, and N/N green after the fix. Only then is the cause called measured, "not inferred from a green". This is the template for step 2's fixed-count reproduction and step 3's non-vacuous witness.
- **Test commands** (per test-plan §3 `run` / Test selection, §9 Coverage row, §3 `pre-push`):
  - the seam's lib tests: `scripts/agent-run.sh run --unit --filter 'test(/spawn_runs_a_raw_child/)'`
  - the default `scripts/agent-run.sh run` (unit + integration)
  - `run --e2e` whenever a `tui_` test or the `run` pump changes
  - CI's per-OS `run --coverage`, then `viola-harness gate --require coverage,doctest,playwright`
  - locally, `pre-push` (the `linux-tests` stage, then the host `windows-tests` stage)
- **Naming** (per test-plan §2 Test function naming): new tests follow `<subject>_<condition>_<expected>`. Table-driven cases use a readable rstest `#[case::label]`, except in `viola-e2e`, which uses a labelled case table (§4 Test grouping).

## Anti-patterns to avoid
- Retrying, `#[ignore]`-ing, skipping or retry-budgeting the H2 test, or closing its red on a green re-run (per test-plan §10 Zero-flakiness budget; §11 CI "NEVER ignore flaky tests", "NEVER set nextest `retries` above 0"; §11 Quality).
- Using `sleep(N)` for synchronisation, or an elapsed-time verdict owned by the test (per test-plan §11 E2E and §11 Universal). A hold or delay that forces the window open is fault injection through an allowed seam. It is never the sync mechanism.
- Parsing the rendered child screen or PTY master output for content in a tui / E2E verdict (per test-plan §11 E2E, R7). Verdicts come from the fake-agent receipt (`size`, `key`), `events.ndjson` and exit status.

## Contract bindings
- **tests ↔ obs (secret scan / uploads):** any report or probe artifact under `target/agent-run/` or `target/e2e-home/` leaves CI only behind obs-plan §9's secret scan, with codes-only content (test-plan §9 Test report format; §6 Error sanitization and secret scan, Canary).
- **tests ↔ security (seams + CI):** a new env-var test seam, like the `fake-agent`-only `FAKE_AGENT_PUMP_DELAY_MS` precedent, needs a Decisions Log entry and must stay out of release builds (test-plan §12 `2026-09-27`; security rules). A ci.yml probe job carries §9's pinning and permissions rules.
- **tests ↔ WSL provisioning:** `scripts/wsl-provision.sh` installs the pins it parses from ci.yml's `test`-job `tool:` line (test-plan §9 tool-install paragraph). If the chunk edits that line, the scope's Folded freight 3 CARRY (`--install-deps` hardening) binds.
- **tests ↔ arch:** the §5 Module ↔ PTY resize-baseline contract. A "document" outcome that amends the seam's contract flows through the wrap, not this extract.

## Acceptance criteria contributions
- The default `scripts/agent-run.sh run` and CI's per-OS `run --coverage` + `gate --require coverage,doctest,playwright` are green on windows-2025, macos-latest and ubuntu-latest. Retries stay at 0, and no H2-related test is `#[ignore]`d, skipped or compiled out (per test-plan §10 Zero-flakiness budget; §9 Matrix builds).
- A failing resize seam test leaves a kept, codes-only report that names which event was lost: the resize, the key, or a key that arrived before the size changed. The child's size-change line is recorded independently of any key, and the report is removed on a pass (per test-plan §3 `run` step 2 recorder; §7 `size` receipt).
- The step 2 count is fixed in the plan before the run, and every counted reproduction is an observed, localised loss. A fix is proven non-vacuous: forced-window red N/N with the exact signature, a control green N/N, and green N/N after the fix, with a witness that observes both the resize and the key (per test-plan §12 Decisions Log `2026-09-27`; §5 Module ↔ PTY).
- Coverage stays ≥ 85% lines / 95% functions / 80% regions on every OS, with `COVERAGE_IGNORE` unchanged (per test-plan §10 Coverage thresholds; §11 CI).
