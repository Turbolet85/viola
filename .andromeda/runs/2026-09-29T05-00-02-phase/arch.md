# arch extract

## Relevance
relevant — the chunk lives in `crates/viola-pty` (the PTY seam), may touch the `run` pump's resize/write path and optionally `ci.yml`, all of which architecture governs.

## Constraints
- Architecture §Established Decisions [PTY] requires portable-pty `=0.8.1`, pinned behind viola's own seam (spawn · read · write · resize · wait · kill). 0.9.0 is excluded (wezterm#6783). The swap triggers are narrow: portable-pty-psmux 0.9.7 only for the O1 artifact, and an own ConPTY on windows-sys + nix only "after a measured defect the seam cannot absorb". A Fix that needs either one goes to P4 as a fork and to the wrap as an amendment to this decision. It is not a silent change.
- Architecture §Established Decisions [PTY] (as built) requires the pump to keep the ConPTY input writer until the child exits, because dropping it makes conhost send `CTRL_CLOSE` (exit `0xC000013A`). It also requires child exit to be detected on the process handle, never on EOF. Any writer-side fix must keep both. Whether `PortablePty::resize` and the writer are ordered or synchronised today is research's question.
- Architecture §Infrastructure Patterns → Crate dependency direction requires `viola-pty` to depend on no viola crate and to know no agent. Its third-party dependencies, as landed, are exactly portable-pty, tracing, windows-sys (Windows only) and libc (Unix only). It takes no thiserror, serde, serde_json or chrono (§Established Decisions [Error Handling]: `PtyError` has a hand-written `Display` with fixed messages). A child-side size observation must fit inside that set. Whether the windows-sys features it needs (e.g. `Win32_System_Console`) are already enabled is research's question.
- Architecture §Established Decisions [Concurrency] and §Cross-cutting Patterns → Tokio containment require `viola-pty` to stay a sync crate on std threads and blocking I/O. It is listed in `scripts/sync-crates.txt` and checked by CI job 3 plus the sole-root `deny-sync.toml` tokio ban.
- Architecture §Established Decisions [Human Takeover / Wheel] rules that resize sequences never count as human editing keys, and that human bytes held during a bridge write are passed on straight after it. A `run`-pump reordering to protect a resize must never delay, drop or reorder a human keystroke.
- Architecture §Cross-cutting Patterns → Cross-platform discipline and §Established Decisions [Scale / Product] require every OS-specific branch to compile and be tested on its CI runner (windows-2025, macos-latest, ubuntu-latest). A recorder change that is `cfg(windows)`-only on the child side still needs a Unix counterpart, or an explicit cfg split that keeps the three-OS real-PTY tests green.
- Architecture §Cross-cutting Patterns → Config management and §Conventions → Environment variables rule that environment variables are not a configuration channel. No `viola` build reads a new variable: the only seams are `FAKE_AGENT_PUMP_DELAY_MS` and `FAKE_AGENT_HOOK_PANIC`, and a third needs a Decisions Log entry. A test-harness-only knob (such as an iteration count) takes the `AGENT_RUN_` prefix, and the `viola` binary never reads it.

## Patterns to follow
- Kill-proof test evidence (architecture §Occupied Resources → Filesystem, test-only): `<temp dir>/viola-pty-watch/<test name>.report`. The real-PTY child streams one line per step, and the file is kept on panic or kill and removed on pass. The root `tests/support/watch.rs` `Watch` (bound `WITHIN` = 7 s) is similar: a line only when the polled state changes, codes and counts only. The new resize line and the test-side sequence (resize returned · key written · key flushed) extend this report shape.
- Forced-window resize seam (architecture §Occupied Resources → Environment variables): `FAKE_AGENT_PUMP_DELAY_MS`, read by `hold_pump_start` in `src/cmd/run.rs`, is compiled only under `cfg(feature = "fake-agent")` and capped at 5 000 ms. It exists so that `tui_host_resize_in_the_pump_start_window_reaches_the_child` can land a resize inside a window. A pump-side probe reuses this seam rather than adding a new one.
- Measured "as built" facts appended to a decision (architecture §Established Decisions [PTY] records research facts 1-5 inline, with their chunk). The Document branch has a natural home in the [PTY] decision as a measured platform limit, with the reproduction count and localisation. Where it lands is P4's choice, and any arch amendment goes through the wrap.
- CI job shape (architecture §Infrastructure Patterns → CI/CD approach): `permissions: {}` at workflow level and `contents: read` per job, every `uses:` pinned by full SHA, fail-closed `shell: bash`, uploads gated on `secret-scan`, a closing `Gate verdict` step, and no `concurrency:` block. Any Windows probe job or loop follows this shape.

## Anti-patterns to avoid
- Bumping portable-pty (0.9.0 is explicitly excluded), vendoring an own ConPTY, or adding a viola-crate, tokio, thiserror or serde dependency to `viola-pty` to make the probe or the fix easier (architecture §Established Decisions [PTY], §Infrastructure Patterns → Crate dependency direction).
- Dropping or recreating the ConPTY input writer while the child runs, or detecting the child's end by EOF (architecture §Established Decisions [PTY]).
- Adding a product-read environment variable or `config.json` key as a probe knob (architecture §Cross-cutting Patterns → Config management).

## Contract bindings
- arch §Occupied Resources (`viola-pty-watch` report) ↔ tests: the report is the real-PTY tests' evidence channel, and step 1's localisation verdict is read from it. Its lines stay codes, counts and sizes only (↔ obs and security NEVER-log floor: no user content).
- arch §Infrastructure Patterns → CI/CD approach ("7 jobs / 15 check-runs") ↔ test-plan §10 quality gates and obs-plan §9 gate order: a new Windows probe job or loop changes the recorded job and check-run count and has to carry the G2, secret-scan and upload gating. If one is added, the wrap amends the arch count.
- arch §Established Decisions [Human Takeover / Wheel] ↔ security (the invariant that the human always wins): a Fix in the `run` pump's resize-then-write ordering is bound by both.
- arch §Established Decisions [PTY] ↔ drift at wrap: a Document outcome recorded as a measured platform limit, or a Fix that triggers a swap clause, is an amendment to this decision.

## Acceptance criteria contributions
- `viola-pty`'s normal dependencies remain exactly portable-pty `=0.8.1`, tracing, windows-sys (Windows only) and libc (Unix only), with no viola crate, tokio, thiserror or serde, and it stays in `scripts/sync-crates.txt` (per architecture §Infrastructure Patterns → Crate dependency direction).
- The recorder's resize observation and the test-side sequence land in the `<temp dir>/viola-pty-watch/<test name>.report` contract (kept on panic or kill, removed on pass, never read by `viola`). Any new test-only path is added to §Occupied Resources at the wrap (per architecture §Occupied Resources → Filesystem).
- No new environment variable is read by any `viola` build. Any probe knob is test-harness-only under `AGENT_RUN_` (per architecture §Cross-cutting Patterns → Config management).
- If a CI probe job or loop is added, it has `permissions: {}` / `contents: read`, SHA-pinned `uses:`, fail-closed bash and secret-scan-gated uploads, and the §Infrastructure Patterns job and check-run count is amended at the wrap (per architecture §Infrastructure Patterns → CI/CD approach).
