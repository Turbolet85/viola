## Patterns to follow
- CLI fixed strings and the readback mirror are pinned by trycmd; typed exit codes and the `--json` no-hint rule by assert_cmd, on all three OS legs (per a11y-plan §4 → P2 cli line; §8 → Error recovery → Verification).
- TTY-only behaviour (SGR beside its word, `waiting:` once, no redraw) is asserted under the portable-pty outer PTY; non-TTY modes by trycmd / assert_cmd (per a11y-plan §4 → P6; §3 A11y testing tool pick → Primary tool per surface → cli).
- State words are driven through the fake agent, never a live `claude`, and asserted as text (per a11y-plan §6 → State color tokens → Verification).
- The tui boundary is three portable-pty nextest cases, one per boundary clause, with the Windows leg asserting the platform fact rather than byte equality (per a11y-plan §3 Keyboard test harness → Tooling; §4 → P4 tui).
- CLI output-discipline checks live inside the existing nextest suites (CI: the `coverage` suite); no a11y suite value and no a11y violation rows for the cli (per a11y-plan §9 CI Integration → Per-pipeline-stage a11y artifacts, Unit / integration row; §10 → Standard+ invariants).

## Anti-patterns to avoid
- NEVER colour CLI `unable` / `fail` or emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run`; the new mirror line and the new `verify` step lines add no SGR of their own (per a11y-plan §11 A11y Anti-Patterns → Visual).
- NEVER parse the rendered `claude` TUI screen for content: a probe for a local command's post-condition, the long-paste wrapper or tag-escaping reads hook payloads and events, not the screen's text (per a11y-plan §11 → Universal; §1 → `viola run` TUI passthrough entity).
- NEVER let the readback word differ between surfaces, and never announce `unconfirmable` through the status region (per a11y-plan §11 → Cognitive; §11 → Screen Reader, the Section 7 message-list ban).
