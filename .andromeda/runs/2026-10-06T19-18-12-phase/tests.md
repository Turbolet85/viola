Only the cli / ipc-internal / tui surfaces are this chunk's; the MCP, SSE and Playwright halves stay owed to `:110` / `:139` / `:147` (per §6 Scenario Path 2, Surfaces involved).
- The real `claude` never runs in CI; the typed probes are local-only and `--local-live` refuses under `CI` (per test-plan §11 Test Strategy, §6 "Skipped as untestable", §3 `run` `--local-live`). ## Patterns to follow
- Verify-driven pinning: literal assert_cmd asserts on the `[NN/<count>] <row id> <row words>  pass|fail` step lines and the last `stamped` line, the dialog-less run failing only the rows its replay lacks (per test-plan §5 Cross-module patterns → CLI, `tests/cli_verify.rs`); the per-set contract check in `contract_ledger_probes.rs` (same anchor).
- Fake-agent replay by argv mode, never env: `--local-command-mode` and the receipt's `prompt.submit` value `local-command` already exist as the local-command stand-in, and the paste-wrap form is emitted past the fixture's threshold (per test-plan §7 Fake agent, Modes and receipt kinds; §6 Scenario Path 2 step 3). A new replay mode follows the "argv options (no env)" shape of the four interactive runs.
- Human-mode mirror lines are pinned by trycmd-redacted assert_cmd, the `viola-send` mirror set `[RB]` / `[  ]` / `[/ ]` (per test-plan §5 Cross-module patterns → CLI; §6 Scenario Path 2, Human mode bullet) — the `[  ] unconfirmable` writer joins there.
- Normalisation cases live at unit level with a proptest round-trip beside them: the four prefixes on the raw start with no trim, the M3/M4 pasted-content forms (per test-plan §4 What unit tests cover → viola-agent-claude; §6 Property suite). Any change to the prefix set or the unwrap / un-escape in `hook.rs` lands as new labelled `#[case]` rows plus a committed `proptest-regressions/` update.
- Recorded payloads go through the recorder's scrub and the one run-time hygiene walk with jsonschema (per test-plan §7 Fixture hygiene; §2 File naming `<Event>.<variant>.json`); fake scripts are committed under `fixtures/fake-scripts/` and schema-checked by the same walk (per test-plan §7 Fake agent).

## Anti-patterns to avoid
- NEVER import the product's ledger rows or `IDENTITY_FLOOR` as the test oracle — row ids, the row count and the 11 floor names are literals in the test (per test-plan §11 Unit; §4 viola-agent-claude R8 strip). Path 2 step 4 takes its local-command *input* from the compiled rows; the expected verdict stays a literal.
- NEVER hand-write `ledger/stamps.json`, and never run the real CLI or a real-CLI `viola verify` in CI (per test-plan §11 Test Data; §11 Test Strategy).
- NEVER read a verdict off the rendered child screen beyond the compiled signature literals, and never add a test-owned sleep or elapsed-time verdict: a local-command post-condition is judged from hook events / `events.ndjson` / the receipt, and the confirmation-window deadline behind `unconfirmable` may be blocked on in E2E only if the verdict is the product's own exit code and the same deadline is clock-driven in a §4 unit case (per test-plan §11 E2E; §4 viola-agent-claude screen signatures; §11 Universal).
