## 3. Design System Excerpt

### Surfaces
- **web-spa: `viola ui`** (desktop-browser SPA, loopback only at `http://127.0.0.1:47319`). A single page with no routes. It is built from Lit 3.3.3 light-DOM `viola-*` custom elements, vendored as ESM and embedded in the Rust binary via `include_bytes!`, with no JS build step. It runs on Windows 10/11 (Edge/Chrome) first, plus macOS and Linux (Chromium, Firefox, Safari 17.5+), and is verified in a headless browser; CI runs on ubuntu. It shows session strips, transfer markers and an SSE-fed event tape. Frontend telemetry hint: browser OTel SDK + web-vitals is the candidate. Any telemetry JS must be vendored and same-origin, because the CSP is `default-src 'none'; script-src 'self'; style-src 'self'; font-src 'none'; require-trusted-types-for 'script'`, with no CDN assets, no inline script and no `innerHTML`. The `/ready` checks (`ok` / `unavailable` / `error`) and `/health` status are probe routes for tests and obs, and they are not shown on the page.
- **cli: `viola` binary** (cli; Rust stable, clap 4.6.7). It runs on Windows Terminal/conhost, macOS and Linux terminals. Callers are a human on a TTY and LLM driver sessions via `--json` / MCP. Results go to stdout. Context lines, refusals, `hint:` lines, errors and the `viola ui` launch line go to stderr. `--json` prints one JSON document on stdout with a typed exit code. `viola run` prints nothing while the child `claude` TUI runs. `viola hook` never writes stderr and always exits 0. `viola mcp` writes only MCP frames to stdout. Stack traces never print, and full error detail goes only to `instances/<name>/diagnostics/`. Frontend telemetry hint: stdout/stderr only, no frontend.

### Loading / Error / Empty State Patterns
- **Initial read (before `/api/sessions` answers, typically under 100ms locally)**: page-replace text. Each rack prints the ruled line `sessions: no reading yet` and the ATIS fields print `unknown`. There is no skeleton and no spinner; both are banned. Telemetry hook: a span from page load to the first `/api/sessions` response, which is the time-to-first-reading / TTI proxy.
- **Failed or missing reading (`unknown`)**: inline word in the field cell. For example, STATUS shows `unknown` when `claude agents --json` is missing, fails or has not joined. A missing CLI version or budget envelope also shows `unknown`, and budget prints `5H unknown  7D unknown  read unknown`. Absent-by-contract fields on unwrapped rows print `n/a`, which does not mean a failure. Telemetry hook: a counter for `unknown` occurrences per field and source.
- **Empty rack**: inline text `no wrapped sessions — start one with  viola run <name> -- claude`. The CLI equivalent is `no wrapped sessions  start one: viola run <name> -- claude`. Telemetry hook: a counter for empty-state occurrences.
- **Empty tape**: inline text `TAPE live since 19:40:02Z — no events yet`. The SSE stream starts at each file's current end. Telemetry hook: a span from SSE open to the first event.
- **Tape connection state (SSE `EventSource`)**: an inline ATIS cell with three values: `TAPE connecting` (lamp-off), `TAPE live since <time>`, and `TAPE stopped · viola ui not answering` (boxed). Telemetry hook: a span around connecting → open, plus a counter for transitions to `closed` with a disconnect-cause attribute.
- **Readback state (send lifecycle)**: an inline 16px box plus a word at the far right of tape send lines and transfer markers. Changes are instant, with no transition. There are four states:
  - `open`, from CL-1 `send-issued`.
  - `read back`, when the matching `prompt-submitted` with origin `driver` arrives, or `session-start` cause `clear` for `/clear`.
  - `unable · <reason> · <detail>`, from CL-1 `send-refused`.
  - `unconfirmable`, from an `ok` send with `confirmed:false`.

  The CLI mirrors these as `[  ]` / `[RB]` / `[/ ]`. Until CL-1 lands, the page shows only `read` boxes and prints `unknown` in the marker's last-send cell. Telemetry hook: a span from `send-issued` to read back or refusal (send-to-readback latency), a counter per terminal state, and the refusal reason and detail as error attributes.
- **Stale liveness (coasting track)**: an inline, instant lamp-off dimming of the whole strip. The strip keeps its slot. In the CLI the row is SGR-dimmed and the word `stale` appears in LIVE. Telemetry hook: a counter for live → stale transitions.
- **Budget expired / budget-paused**: inline ATIS words. `5H 62 % expired` appears once `resets_at` has passed. `budget-paused` is boxed, otherwise the cell shows `gate open`. The age `read 4m ago` is always shown. Telemetry hook: a counter for pause-gate transitions and a gauge for reading age.
- **Skipped counts (unknown kinds / unknown fields / torn lines)**: inline ATIS text `skipped 0 · 0 · 0`, boxed when nonzero and never auto-cleared. In the tape, `skipped  1 unknown kind` is printed at the point where it occurred. Telemetry hook: counters for unknown event kinds, unknown fields and torn ndjson lines.
- **Tape line cap (2000 DOM lines)**: an inline notice at the top of the tape: `older lines trimmed from view: N — the full tape is events.ndjson`. Telemetry hook: a counter for trim events.
- **Tape follow rule**: an inline static line `N new lines below`, shown when the reader is not at the bottom. Telemetry hook: none specified.
- **CLI `viola wait`**: one static `waiting: <name>` line on stderr (TTY only), then one result line: `turn-ended …`, `question … dialog N …` or `timed out  <name>  30000 ms`. There is no spinner or elapsed counter. Telemetry hook: a span around the wait, with the outcome (turn-ended / dialog / timed out) as an attribute.
- **CLI `viola verify`**: a step counter with static appended lines, `[03/14] S3 … pass` / `fail`, followed by a summary `stamped 2.1.280  14 pass  0 fail`. Telemetry hook: a span per step, and pass/fail counters.

### User-Facing Error Surfaces
- **401 `unauthorized` access strip** (in-page, a full-width strip in the rack position). Appears for: a missing or invalid GUI session. Line 1: `UNAUTHORIZED  this page has no session for 127.0.0.1:47319`. Line 2: `open the launch line printed by "viola ui" at start, or restart viola ui`. Recovery affordance: the user reopens the launch line or restarts; there is no retry control and no input field. The strip never shows or echoes the token, the launch URL, the `?t=` query, the `ui/<port>.url` path or any cookie value, and it never reads `location.search`. Feedback widget candidate: no. v1 has no page controls or credential fields.
- **503 `state-unreadable` rack strip** (in-page). Appears for: viola home could not be read. Prints `unable · state-unreadable  viola home could not be read`. Recovery affordance: none on the page. Feedback widget candidate: no. v1 is view-only.
- **404 `not-found` / 405 `method-not-allowed` rack strips** (in-page, defensive only). Appear for: route or method problems the page should never trigger, since it makes GET requests to its own routes only. Print `unable · not-found` / `unable · method-not-allowed`. Recovery affordance: none. Feedback widget candidate: no.
- **403 `host-not-allowed`** (dedicated error page: the browser shows the raw Problem JSON, with no in-page visual). Appears for: a Host header check failure, so the page cannot load. Recovery affordance: none. Feedback widget candidate: no, because the page never loads.
- **`Problem::cross-origin-forbidden` (403)**: reserved for the v1.x brake controls and not used in v1.
- **Tape stopped** (in-page: a boxed ATIS `TAPE stopped · viola ui not answering` cell plus a strip at the top of the tape). Appears for: the SSE connection closing or the server not answering. Strips keep their last values and the ATIS age keeps counting. Recovery affordance: none on the page. It is announced through the polite `aria-live` status region. Feedback widget candidate: no.
- **Readback refusal** (in-page, inline on the tape send line and in the transfer marker's box). Appears for: typed send refusals shown as `unable · <reason> · <detail>`. The reasons are `human-typing`, `budget-paused`, `unverified-cli`, `not-delivered` and `unknown`. The details are `manual-pause`, `five-hour`, `seven-day`, `input-not-ready`, `no-prompt-submitted`, `turn-running`, `unknown-dialog` and `control-character`. An `unknown` reason prints its detail as opaque plain text. Recovery affordance: none on the page; it is announced via `aria-live`. Feedback widget candidate: no.
- **CLI refusals** (stderr text line). Appear for: typed refusals in the form `unable  <name>  <reason>  <detail>`, followed by one `hint:` line keyed by the reason. Exit codes: 10 `human-typing`, 11 `budget-paused`, 12 `unverified-cli`, 13 `not-delivered`, 14 `unknown` (no hint), 21 `instance-unreachable`, and 1 for `unable: <name> is already live` + `hint: viola list`. Under `--json` the refusal is a `{"v":1,"refusal":…,"detail":…}` object on stdout with no hint. Hints never quote sent text or upstream text. Recovery affordance: the hint names the next command, e.g. `viola release`, `viola wait` or `viola verify`. Feedback widget candidate: no.
- **CLI faults** (stderr text line). Appear for: exit 1 `error: internal error` (fixed message, no chain, no paths, no hint) and exit 20 `error: wrapper fault  <code>`. Under `--json` a fault is `{"v":1,"error":"wrapper-fault","detail":{…}}`. Stack traces never print, and full detail goes only to `instances/<name>/diagnostics/`. Errors and hints never contain upstream text, paths, pids or anyhow chains with serde sources. Recovery affordance: none. Feedback widget candidate: no.
- **CLI Git Bash path warning** (stderr text line). Appears for: an argument that looks like a Git Bash rewritten path. Prints `warning: argument looks like a Git Bash rewritten path`. Recovery affordance: none. Feedback widget candidate: no.
- **Redaction constraints that apply to all error surfaces**: the GUI token, the launch URL, the `?t=` query, the `.url` path and cookie values must never be displayed or logged. The one exception is the single unstyled `viola ui` stderr launch line. `viola_home` from `/api/info` contains the OS username, which is the only PII in scope, and it is never rendered.
