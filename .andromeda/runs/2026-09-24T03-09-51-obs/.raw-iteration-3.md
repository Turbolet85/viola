### Patch 4: Extend the append rule to every multi-writer file and state its real basis
**Reason:** Log Format Alignment. The atomicity claim covered `hook` only, cited the pipe-only `PIPE_BUF` rule, and ignored `mcp.ndjson` and `cli-<name>.ndjson`, which also have concurrent writers. No multi-OS check was named.
**Old:**
```
The line is codes-only and stays well under 4 KiB, so concurrent `hook` appends stay atomic (POSIX `O_APPEND`; Windows append-only handle).
```
**New:**
```
The line is codes-only and stays well under 4 KiB. Three files have concurrent writers in separate processes, and the same rule covers all three:
  - `hook-<name>.ndjson`, shared by hook processes;
  - `mcp.ndjson`, shared by one `viola mcp` per Claude session;
  - `cli-<name>.ndjson`, shared by concurrent short-lived verbs.

  Each line is one `write_all` of one complete line on an append-mode handle. POSIX `O_APPEND` fixes the offset per write; on Windows, `append(true)` opens with `FILE_APPEND_DATA` only. Non-interleaving at this size is an assumption, not a POSIX guarantee, because the 4 KiB `PIPE_BUF` rule applies to pipes. Two things back it:
  - readers tolerate a torn line: the harness emits `{"torn":true}`, and G2 skips it through `fromjson?`;
  - a tests-owned concurrent-append check on windows-2025, macos-latest and ubuntu-latest asserts that every line of each shared file parses. This is a multi-platform-exporter-compat item. A torn line fails that check.
```

### Patch 5: Make the panic line's null encoding identical to `obs_event!`
**Reason:** Log Format Alignment. The two emitters used different null shapes for `corr` (literal `null` vs key absence), and `instance` for `ui` was unspecified, so the schema would have to accept both shapes and would hide drift.
**Old:**
```
The panic hook's hand-written line writes a literal `"corr":null`.
```
**New:**
```
The panic hook's hand-written line follows the same rule. It never writes `corr`, and it omits `instance` when none resolved (always for `ui`). Both emitters are therefore schema-identical: `schemas/diag-line.v1.json` declares `corr` (number | string) and `instance` (string) as optional keys and rejects a literal `null` for either, which catches an emitter that drifts (D-26).
```
