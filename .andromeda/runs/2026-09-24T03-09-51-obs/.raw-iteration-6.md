1. **Downstream Readiness**
   - The `obs-ci-gate-wire` bootstrap list is what setup-project materializes, and it is stale against §9/§11:
     - it leaves out G3 (`panic = "abort"`), the PCRE2 ripgrep install step, the G4 id and the step order;
     - it leaves out the clippy `print_stdout` / `print_stderr` / `dbg_macro` ban;
     - the §11 ban relies on `[workspace.lints.clippy]`, which Cargo applies only to members that declare `[lints] workspace = true`. As written, that ban can be silently inert. **Patch 1.**
   - G2 passes vacuously when `target/e2e-home` exists but holds no home-level role files, for example when homes are misplaced or the sink is broken. Nothing asserts the scope is non-empty. **Patch 2.**
2. **Obs Scope Faithfulness**
   - Vector 7 requires telemetry for "ignored symlinks". §6 declares a `symlink-ignored` detail code, but no event carries it: it is not a `process-exit` or `hook-decision` cause, and no catalog row lists it. Under default-deny plus G4, the signal cannot be emitted. **Patches 3 and 4.**
   - All other instrumentable entities are covered: ledger (`state.ledger_read` / `ledger-stamps`), `verify` / `plugin install`, and `state.tail_notify`.
3. **Tool Anchoring:** versions agree across the three sites. The config-line divergences (max level, `chrono` feature, writer) are recorded in D-25 and D-26. No patch.
4. **Performance Budget & SLO Discipline**
   - The §10 error budget says it is measured by "`jq` counts over the `diag-<os>` artifact". That artifact is never uploaded when the secret scan fails, and it contains `detail-*.ndjson` panic duplicates. So the stated measurement surface cannot count scan hits and would double-count panics. **Patch 5.**
   - The §10 build-failure list leaves out G3 and the print / `dbg!` lints, and doesn't say that an rg exit 2 or 127 is itself a failure. **Patch 6.**
5. **Log Format Alignment to Tests:** §7's detail panic line is `{"event":"panic", ..., "panic_payload", "backtrace"}`. The `...` implies `panic_location` / `thread`, but `diag-detail.v1.json` (`additionalProperties:false`) allows only the required fields plus the four content fields. So G4 would fail every correctly written detail panic line. **Patch 7.**
6. **PII Scrubbing & Compliance Coverage**
   - The nextest JUnit XML is uploaded from every test job, outside the secret-scan scope and without the scan gate. By default nextest keeps each failing test's captured stdout/stderr in the XML, and a failing assertion can quote a diagnostics line, the canary or the per-launch GUI token.
   - This is a new egress path that bypasses §11 CI "scan before upload". **Patch 8.**
7. **Tier Calibration:** p99 is stated as not computed. The liveness path without `ui` is cross-referenced. The spine deadline names tests as the owner. No patch.
8. **Anti-Pattern Relevance:** the abort, print and `LogTracer` bans are present. The duplicate Universal ban is gone. The remaining inline duplicates are low priority and are skipped because the patch budget is spent.
