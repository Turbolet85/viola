## Patches

### Patch 1: Make `conn` survive PID reuse
**Reason:** Obs Scope Faithfulness. The cross-surface join key collides when a PID is recycled.
**Old:**
```
The client generates `conn = "<process>-<pid>-<n>"`, with `n` a per-process connection counter,
```
**New:**
```
The client generates `conn = "<process>-<pid>-<t0>-<n>"`, with `t0` the process's start instant in Unix epoch milliseconds (captured once at init; Low sensitivity like `pid`) and `n` a per-process connection counter (D-32),
```

### Patch 2: Correct the uniqueness claim
**Reason:** Obs Scope Faithfulness. "Globally unique" is false for `<process>-<pid>-<n>`.
**Old:**
```
`conn` is already globally unique (`<process>-<pid>-<n>`, D-10).
```
**New:**
```
`conn` is unique across the session home (`<process>-<pid>-<t0>-<n>`, D-10, D-32). `<pid>` alone is not unique: PIDs are recycled, quickly on Windows. Every `hook` process opens exactly one connection (`n` = 1) and sends the same first JSON-RPC `id`, so without `t0` two hook calls from a reused PID would share `(conn, corr)`.
```

### Patch 5: Give the JUnit and perf uploads explicit status conditions
**Reason:** Downstream Readiness. A bare `steps.secret-scan.outcome == 'success'` gets an implicit `success()` and skips the upload on failing runs. The perf sample is lost when its `jq -e` assertion fails.
**Old:**
```
every test job | uploaded as `junit-${{ matrix.os }}` | failing test ID joined to `diag` lines by time and `instance` |
| hyperfine `--export-json perf/*.json` | every perf-gate job | uploaded as `perf-${{ matrix.os }}` |
```
**New:**
```
every test job, `if: always() && steps.secret-scan.outcome == 'success'`. An `if:` without a status function gets an implicit `success()`, so the bare `steps.secret-scan.outcome == 'success'` would skip this upload on exactly the failing runs | uploaded as `junit-${{ matrix.os }}` (upload-artifact v7.0.1 SHA-pinned, `retention-days: 7`) | failing test ID joined to `diag` lines by time and `instance` |
| hyperfine `--export-json perf/*.json` | every perf-gate run, `if: always()`, so a failing `jq -e` budget assertion still leaves its sample (timings and benchmarked command lines only, no log content) | uploaded as `perf-${{ matrix.os }}` |
```

### Patch 6: Place the perf gates in the step order
**Reason:** Downstream Readiness. §10's "perf job" hook home is otherwise unscanned and not uploaded, or it collides with the `diag-<os>` artifact name.
**Old:**
```
1. Integration and E2E tests (every viola home under `target/e2e-home/`), then G2 and G4, **both** `if: always()`.
```
**New:**
```
1. Integration and E2E tests and the hyperfine perf gates (every viola home under `target/e2e-home/`, including the §10 perf-gate hook home), then G2 and G4, **both** `if: always()`. The perf gates run in this same per-OS job ("the perf job" in §10), so G2, the scan and the `diag-<os>` upload cover their home. A separate perf job would either upload no diagnostics or collide on `diag-<os>`, because artifact names are unique per workflow run.
```

### Patch 7: Add the failed-open exemption and tighten the failure condition
**Reason:** Perf/SLO Discipline. The panic hook writes only to the step-4 handle, so the `sink` writer and the `mcp` stderr fallback produce no panic line, which contradicts "exactly one … after init step 4".
**Old:**
```
    3. `hook` without `VIOLA_NAME` (D-16).

    The failure condition "a panic evidenced by an exit code without its line" applies only to processes that wrote `process-start`.
```
**New:**
```
    3. `hook` without `VIOLA_NAME` (D-16);
    4. a failed step-4 role-file open (§3 init step 4). The writer becomes `std::io::sink`, or stderr JSON for `mcp` (D-09), and the panic hook's `OnceLock` stays empty, so it writes nothing, not even to `mcp`'s stderr (D-32).

    The failure condition "a panic evidenced by an exit code without its line" applies only to processes whose `process-start` is in a home-level role file.
```
