### tracing-subscriber 0.3.23 (features `fmt`, `json`, `chrono`, `registry`; default `ansi` off for files)

- **Version:** 0.3.23 (MSRV 1.65). Satisfies the security floor `>=0.3.20` (RUSTSEC-2025-0055). 0.3.21 was yanked.
- **Last release:** 2026-03-13
- **Status:** Actively maintained. No 2026 RUSTSEC advisory against tracing-subscriber was found. The `json` feature enables `serde`, `serde_json` and `tracing-serde`. The `chrono` feature enables `chrono ^0.4.26` (already in the tree at 0.4.45).
- **Agent-readable:** Yes. It produces JSON-per-line structured logs, `jq -c 'select(.event=="dialog-raised")'`-parseable. Configuration:
  `fmt().json().flatten_event(true).with_current_span(false).with_span_list(false).with_ansi(false).log_internal_errors(false).with_timer(MillisUtc).with_writer(<append File MakeWriter>).with_max_level(<from config.json/flag>).init()`
- **Fits because:** It is the tests-bound logger verbatim (Sec 3 Logging stack; Founder Direction 1). It serves every Sec 2 surface through one init in `main`. This research found four configuration points that the tests line alone does not settle:
  1. **Timestamp precision.** The default `SystemTime` timer writes `{:06}` fractional digits plus `Z` (microseconds). `ChronoUtc::rfc_3339()` calls `to_rfc3339()`, which gives auto nanoseconds and a `+00:00` offset. **Neither matches** the arch/tests `timestamp` (RFC 3339 UTC, ms, `Z`). Use a ~5-line custom `FormatTime` that writes `chrono::Utc::now().to_rfc3339_opts(SecondsFormat::Millis, true)`, the same call arch mandates for `ts`, or use `ChronoUtc::new("%Y-%m-%dT%H:%M:%S%.3fZ".into())`.
  2. **`log_internal_errors` defaults to `true`.** Doc: "If writing to the writer fails, the error message is printed to stderr as a fallback". That breaks the Hook contract ("hook never writes to stderr") and the `run` terminal rule. Set `.log_internal_errors(false)` on every role.
  3. **`with_span_list` defaults to `true`.** The tests line disables only `current_span`, so a `spans:[…]` array with span fields would still be appended. Set `.with_span_list(false)`. This does not rename or remove any required field. It closes a leak path for span fields.
  4. **The default writer is stdout** (`W = fn() -> Stdout`). `with_writer` must always be explicit (mcp stdout = MCP frames; hook stdout = decision body).
- **Key detail:** `on_event` formats into a thread-local `String`, then does **one `io::Write::write_all` per event**. With a `MakeWriter` that returns a `std::fs::File` opened with `OpenOptions::new().append(true).create(true)` (+ `OpenOptionsExt::mode(0o600)` on Unix, dir `0o700`), each line becomes one append write. That satisfies arch "one `write` per line" and concurrent `hook` writers (POSIX `O_APPEND`, Windows append-only handle).
  - `with_ansi_sanitization` defaults to `true` in 0.3.23 (terminal-injection protection). Keep it.
  - `process` and `instance` must appear on every line, but with `flatten_event(true)` + `with_span_list(false)` only event fields are emitted. Wrap `tracing::event!` in a crate-local macro that always attaches `event` (Display of a closed kebab-case enum in viola-core), `corr`, `process` and `instance`. This compile-time enforces the tests' closed enum.
  - Unit-test emitted lines by pointing `with_writer` at an in-memory `Vec<u8>` and parsing with serde_json. No extra dependency is needed, and it keeps obs code under the cargo-mutants gate.
- **Source:** https://docs.rs/crate/tracing-subscriber/latest ; https://docs.rs/tracing-subscriber/0.3.23/tracing_subscriber/fmt/struct.Layer.html ; https://docs.rs/tracing-subscriber/0.3.23/tracing_subscriber/fmt/format/struct.Json.html ; https://docs.rs/tracing-subscriber/latest/src/tracing_subscriber/fmt/time/datetime.rs.html ; https://docs.rs/tracing-subscriber/latest/src/tracing_subscriber/fmt/time/chrono_crate.rs.html ; https://docs.rs/tracing-subscriber/0.3.23/src/tracing_subscriber/fmt/fmt_layer.rs.html ; https://rustsec.org/advisories/RUSTSEC-2025-0055.html
