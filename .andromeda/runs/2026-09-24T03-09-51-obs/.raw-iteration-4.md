### Patch 2: State the CI step order and conditions exactly
**Reason:** Dimension 1. "Runs before upload" cannot be copied into `ci.yml`. The scan needs `if: always()` or a failed E2E step skips it and both uploads are lost, and the hit-report upload has no step.
**Old:**
```
**Artifact retention:** `retention-days: 7`, below the 90-day default (obs-research CI pattern). The secret-scan step runs **before** upload, so a failing scan blocks the upload.
```
**New:**
```
**Artifact retention:** `retention-days: 7`, below the 90-day default (obs-research CI pattern).

**Step order and conditions** (copied into `ci.yml`):
1. E2E tests, then G2.
2. Harness capture, `if: failure()`, into `target/agent-run/`.
3. Secret scan, `id: secret-scan`, `if: always()`, over `target/e2e-home/**/diagnostics/*.ndjson` and `target/agent-run/*`. Without `always()`, a failed E2E step skips the scan (outcome `skipped`), and both gated uploads are then skipped too, which loses the failing job's diagnostics (§11 CI).
```

### Patch 3: The harness artifact is content-bearing too

**New:**

### Patch 4: The send join must include the target instance
**Reason:** Dimension 2. The cross-surface-trace-propagation trigger is at stake. A byte-offset cursor is unique per target only, so `corr==412` alone mixes sends from different wrappers.
**Old:**
```
  - To follow one send across every side: `agent-run logs | jq -c 'select((.record.event|IN("send-issued","send-confirmed","send-refused")) and .record.corr==412)'`.
    - There is no `--instance` filter, because each side logs its own instance (see Trace context propagation).
```
**New:**
```
  - To follow one send across every side: `agent-run logs | jq -c 'select(.record.instance=="B" and (.record.event|IN("send-issued","send-confirmed","send-refused")) and .record.corr==412)'`, where `B` is the send's target.
    - A send `cursor` is a byte offset into the target's own `events.ndjson`, so it is unique per target instance only. Two wrappers with identical start sequences (common in E2E) can both hold a send at 412, so `corr` alone mixes sends.
    - `send-*` lines with a cursor `corr` are emitted only by the target wrapper (`side:"wrapper"`, D-27), so the jq `instance` predicate is the target's. The caller-side `send-refused{side:"client"}` has `corr` null and is read from the caller's `channel-response{conn}` and `process-exit` instead.
    - The harness `--instance` filter is still not used. It would also drop the caller's `channel-*` lines, which carry the caller's instance (see Trace context propagation).
```

### Patch 5: Define `mcp` / `ui` exits after a main-thread panic
**Reason:** Dimension 4. The main-thread catch site maps an `Err` "to the role's exit below", but no exit is defined for `mcp` / `ui`, so the §10 "exit code without its line" condition cannot be evaluated for them.
**Old:**
```
  - `mcp` / `ui`: a task panic is logged, and the process continues or exits per its own error policy.
```
**New:**
```
  - `mcp` / `ui`:
    - A panic inside a spawned Tokio task is logged by the hook. The runtime contains it at the task boundary, and the process continues.
    - A main-thread panic reaches the main-thread catch site. The process writes `process-exit{subject:"self", exit_code:1, detail:"internal-error"}` and then exits 1. `mcp` writes nothing to stdout on this path.
```


**New:**

