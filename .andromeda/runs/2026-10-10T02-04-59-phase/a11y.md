## Patterns to follow
- A boundary case is sequenced on the wrapper's own records, never on a timer (per a11y-plan §3 Keyboard test harness, Tooling) — the form a Windows-side case near the input path takes.
- On `windows-2025` an assertion states the platform fact as measured, on both backends, where Linux and macOS carry the full assertion (per a11y-plan §4 P4, tui).
- The tui reach is the portable-pty outer-PTY boundary driver and the cli reach is assert_cmd / trycmd on all three OS legs (per a11y-plan §4 Per-surface a11y testing tool reach); a new test stays inside those drivers.
- Crate-test invariants are covered by the mutation audit rather than by a second a11y gate (per a11y-plan §10 Standard+ invariants).

## Anti-patterns to avoid
- NEVER block, refuse or delay a human keystroke in `viola run`, and NEVER count focus / mouse / resize sequences as editing — a test-only helper on the console path adds no seam that could (per a11y-plan §11 Keyboard).
- NEVER read a mutation grade or a cli / tui crate test as WCAG conformance evidence: cli and `viola run` carry no conformance claim (per a11y-plan §11 Strategy).
- NEVER add a `suite` value or judge the a11y verdict on the Windows or macOS legs (per a11y-plan §11 CI).
