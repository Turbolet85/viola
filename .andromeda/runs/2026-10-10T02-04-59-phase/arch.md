## Patterns to follow
- The strict-modes refusal has one specified observable at `run`'s entry point: architecture §Standard Contracts (Ledger stamps envelope) and §Occupied Resources (Filesystem, `ledger/stamps.json`) require a `read_stamps_strict` refusal to read as `cli_verified:false` with one `parse-rejected` line whose detail is `strict-modes-failed`. A Windows-side refusal test above the `strict` module asserts that outcome and nothing wider.
- The mechanism the Windows checks are specified against is in architecture §Stack and Technologies (State-file primitives): owner + DACL through windows-sys, and a protected user + SYSTEM DACL on a home created outside the user's profile, where a DACL that cannot be set fails the creation. A refusal test builds its bad state against that description.
- `console::is_console` selects the branch architecture §Established Decisions [PTY] specifies for `viola_pty::host_stdin()`: viola's own `ReadConsoleW` reader on a Windows console stdin, `std::io::stdin()` for a redirected Windows stdin. A kill test pins one side of that sentence. Whether a `windows-2025` job gives a test process a console stdin is research's question.
- Test isolation follows architecture §Established Decisions [CI/CD] and §Cross-cutting Patterns (Config management): each test runs in its own viola home. A test-only path a new test writes outside a home is a new entry under architecture §Occupied Resources (Filesystem), recorded at wrap.
- The harness's host-keyed arms are compile-time consts with the other arm inert (`HOST_SCRATCH = cfg!(windows)`, architecture §Occupied Resources (Repository), the `viola-mutants-scratch` entry). The exclusion of scope §3 follows that shape so both arms compile on every host. If it runs `rustc --print cfg`, the child is spawned directly, per architecture §Cross-cutting Patterns (Cross-platform discipline).

## Anti-patterns to avoid
- A mutation job in `ci.yml`, or `inputs:`, a cache, an upload, a `concurrency:` block or a `needs:` in `windows-mutants.yml`, to make the grade easier to read: banned by architecture §Infrastructure Patterns → CI/CD approach.
- A new environment variable, a new test-only Cargo feature or a new seam to steer the exclusion or a test: architecture §Conventions (Naming patterns, Environment variables) and §Cross-cutting Patterns (Config management) allow only the `VIOLA_*` plumbing, the `AGENT_RUN_*` harness variables and the two ratified `fake-agent` seams, and architecture §Occupied Resources (Workspace crates) lists the only test-only features.
- A path in a harness document or an uploaded `outcomes.json`: architecture §Occupied Resources (Repository) requires the scratch path never to be printed (documents carry `scratch_bytes` only) and `target/run-archive/<n>/` never to be uploaded, because `outcomes.json` holds absolute argv paths. The exclusion's document fields carry counts and repo-relative names only.
