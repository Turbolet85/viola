## Relevance
partial — no web rendering lands (scope Boundaries: the GUI brake route and any web wheel rendering are out of scope), but the chunk adds two human CLI verbs (`pause`, `release`), new refusal output (`human-typing` / `manual-pause` on `send` and `answer`), and changes the WHEEL value `viola list` prints, all governed by design-system §Surface: cli.

## Constraints
- `viola pause <name>` and `viola release <name>` print fixed phraseology result lines on stdout (exit 0): `<name>  wheel human  manual-pause  I have control` and `<name>  wheel driver  you have control` — two-space separated, ASCII only, per design-system §Surface: cli → Component Patterns 4 (Wheel, link and gate verbs) and §Brand Identity ("Pilot-in-command, 'I have control'"). The `release --budget` line (`budget gate lifted until …`) belongs to the budget governor (`:91`) and is out of scope here; the plan specifies no line for `pause` on an already-`human` wheel, so that case is P4's to decide and must not invent new vocabulary.
- The wheel refusal prints on stderr as `unable  <name>  human-typing`, with `manual-pause` as the detail field when the cause is `viola pause`, then exactly one `hint:` line: `the human has the wheel; send again after the human hands it back` — per §Surface: cli → Streams, Component Patterns 2 (hint list) and the Exit-code phraseology row 10. `viola send` prefixes the `[/ ]` mirror and pads `unable` to the readback-word column (Component Patterns 2 sample); `viola answer` uses the plain `unable  <name>  <reason>  <detail>` form (Component Patterns 4).
- No hint, help text or refusal output names `viola release` (T3): the `human-typing` hint reaches drivers, and `release` stays a human verb documented only under the wheel verbs — per §Surface: cli → Component Patterns 2 ("So no hint ever names `viola release`").
- Under `--json` the result is one JSON document on stdout with the typed exit: `{"v":1,"ok":{…}}` for pause/release, `{"v":1,"refusal":"human-typing","detail":…}` (detail `"manual-pause"` or null) for exit 10, and no `hint:` line — per §Surface: cli → Streams and Exit-code phraseology. `release-from-driver` is a channel `-32602` refusal surfacing as exit 20 (Component Patterns 2, T3 bullet); its human line follows the exit-20 row (`error: wrapper fault  <code>`) — whether the CLI can ever produce it (CLI `release` carries no `from`) is research's question.
- `viola run` prints nothing while the child runs: a wheel move (human key, pause, release, the `null` dialog answer) writes no byte, colour or cursor control to the wrapper's terminal — the child's screen owns it — per §Surface: cli → Colour decision order item 2 and Per-Surface Bans (cli) "NEVER emit colour, glyphs or cursor control under … `viola run`".
- The WHEEL column of `viola list` prints the bare word `driver` / `human` (with ` - budget-paused` appended only when budget-paused — out of scope here); `human` takes no colour and no bold in the CLI (bold is NAME only, colour is `DIALOG` amber and `stale` dim only) — per §Surface: cli → Tokens and Component Patterns 1; the weight-600 `human` is web-only (§Typography Body row, §Color Palette → Semantic Colors `WheelHolder::human`).
- Verb placement: `pause` and `release` are flat lower-case verbs, grouped `wheel: pause, release` in `viola --help` — per §Surface: cli → Navigation Pattern. Whether the help grouping already exists at HEAD is research's question.

## Patterns to follow
- The fixed-word phraseology vocabulary: wheel causes print as `driver · start` / `human · human-input` / `human · manual-pause` / `driver · release` (ASCII ` - ` inside one CLI field), and the refusal reason/detail pairs as `human-typing` / `human-typing · manual-pause` — per §Color Palette → Semantic Colors (`WheelCause::*`, `RefusalReason::human-typing`, `RefusalDetail::manual-pause`) and §Iconography → Separator.
- The existing refusal + one-hint-per-reason stderr shape that `send` / `answer` already follow for `not-delivered` details (§Surface: cli → Component Patterns 2): the wheel refusal is one more row in the same keyed hint table, not a new output form.
- Stream discipline: results on stdout, refusals/hints/errors on stderr (§Surface: cli → Streams; Per-Surface Bans cli "NEVER mix data and messages").
- The colour decision order applies to any new human output: `--json`, `NO_COLOR`, `TERM=dumb`, non-TTY each yield no SGR (§Surface: cli → Colour decision order) — the pause/release lines carry no styled span at any depth.

## Anti-patterns to avoid
- No robot/person icons, emoji, `✓` / `✗` or "done"/"success" wording for a wheel move; the result line says who holds the wheel and why (§Anti-Patterns → Rejected Defaults "Robot and person icons or emoji for the wheel", Per-Surface Bans cli "NEVER use green `✓` / red `✗`" and "NEVER print 'done' or 'success' without context").
- No colour on the wheel words or the `human-typing` refusal, and no colour without its word (§Anti-Patterns → Per-Surface Bans cli "NEVER colour anything except `DIALOG` (amber) and `stale` rows (dim)").
- No upstream text, path or pid in a wheel refusal, hint or `release-from-driver` error (§Anti-Patterns → Per-Surface Bans cli "NEVER print upstream text, paths, pids …").

## Contract bindings
- design ↔ architecture: the exit-code phraseology rows 10 / 20 / 21 and the `{"v":1,"ok"|"refusal"|"error"…}` JSON shapes mirror architecture's typed exit codes and the channel `pause` / `release` result shapes (`{wheel}` / `{wheel, budget_paused}`) — the human line's `wheel <holder>` word is the channel result's `wheel` field (§Surface: cli → Exit-code phraseology).
- design ↔ obs: the cause words `start` / `human-input` / `manual-pause` / `release` in the `wheel` event and the `wheel` field on `send-refused` (obs-plan §4 CL-1) are the same closed vocabulary the design tables print (§Color Palette → Semantic Colors `WheelCause::*`, `EventKind::wheel`).
- design ↔ a11y: State is carried by the word, never colour (`human` / `driver`, `unable  human-typing`) — binds to a11y §Use of Color SC 1.4.1; the CLI adds no colour here, so no new contrast pair arises.
- design ↔ CLAUDE.md Session Learnings: "`viola release` is a human verb" is the same rule as the T3 hint ban (§Surface: cli → Component Patterns 2).

## Acceptance criteria contributions
- (design) Human-mode `viola pause <name>` prints exactly `<name>  wheel human  manual-pause  I have control` on stdout and `viola release <name>` prints exactly `<name>  wheel driver  you have control`, exit 0, no SGR when stdout is not a TTY (per design-system §Surface: cli → Component Patterns 4 / Colour decision order).
- (design) A `send` refused for the wheel prints on stderr `[/ ] unable  <name>  human-typing` (plus `  manual-pause` after `viola pause`) followed by the single line `hint: the human has the wheel; send again after the human hands it back`, exit 10; `answer` prints `unable  <name>  human-typing[  manual-pause]` with the same hint; under `--json` the stdout document is `{"v":1,"refusal":"human-typing","detail":"manual-pause"|null}` and no `hint:` is printed (per design-system §Surface: cli → Component Patterns 2 / Exit-code phraseology row 10).
- (design) No hint, `--help` text, refusal or doc string reachable by a driver contains the string `viola release` (per design-system §Surface: cli → Component Patterns 2, T3).
- (design) A wheel move inside `viola run` writes no byte of viola's own to the wrapper's terminal (per design-system §Surface: cli → Colour decision order item 2 / Per-Surface Bans cli).
