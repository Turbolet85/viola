- obs: `logging-redaction-wire` is the single NEVER-log floor. No patch.
- design: the 401 on a wrong `?t=`, the ungated `/`, the no-recovery-shortcut rule and the `detail` limits are all stated in the Token row and Error Handling. No patch.
- route / setup-project: all 8 amendments are ordered against chunks, and the SHA-256 re-hash, the Windows `--home` DACL and the owner + DACL check each have a bootstrap item. No patch.
- tests: the parser surfaces are listed in one place. No patch.

**2. Threat → Control / TMS fidelity**
- All nine vectors map to controls or accepted risks: PATH `claude`, cross-port cookie, local availability and disk growth are all accepted risks. `heartbeat` is in the own-state row. The §1 classes are covered, including `settings.json` and `budget.json`. The TMS justification is already verbatim (iteration 2). No patch.

**3. Tool anchoring**
- The SHA-256 open question is linked from Data Protection, Bootstrap and the Decisions Log, with pick constraints. rmcp is `>=3.4.1, <3.5` everywhere, and the CLIs use floors. atomic-write-file comes from arch's Stack, and research lists tempfile only as an alternative with no advisory, so no justification gap. No patch.

**4. GUI credential lifecycle**
- These are all stated: cross-port exposure (accepted risk plus Decisions Log), the 401 on `?t=` mismatch, headers on the failure response, the constant-time exchange, the stale `.url` after a crash, and no recovery shortcut. No patch.

**5. Tier / elevation coverage (Windows)**: two defects in the "integrity of `~/.viola/`" elevation on the primary OS:
- **Generic bits missed.** The Windows write rule says only "write", and the read rule lists only `FILE_READ_DATA` / `GENERIC_READ`. Inherit-only ACEs keep generic bits unmapped (`icacls (OI)(CI)(IO)(F)` stores `GENERIC_ALL`). So a check written literally from the plan passes `Users:(OI)(CI)(IO)(GA)` on `instances/<name>/`, `ui/` or `bin/`. Every file viola creates there then inherits read and write access for other users (`events.ndjson`, `.url` token, `snapshot.json`, pinned exe).
- **Empty DACLs pass.** A NULL DACL, or a `--home` on a volume without persistent ACLs (FAT32/exFAT), grants everyone full access but has no ACE for the `GetAce` loop to reject, so the check passes silently.
- Adversarial: a `--home` on an exFAT drive, or a home that inherits a `GA` ACE, gets past the Windows check before `hook statusline` shells out.
- Patches 1–4 fix this, with the Decisions Log companion and the § Data Protection ban.
- Secret Management "Access auditing" says the token file's 0600 mode is the access control. That is Unix-only and wrong for Windows, the primary host; Patch 5 fixes it.
- Over-engineering: each above-Minimal control traces to a named elevation. The v1.x items sit in Decisions Log deferrals or forward-looking notes. No patch.

**6. Anti-pattern relevance (medium)**
- The output-encoding bans are in § API, and the client-address ban has been reframed. The v1.x Code Patterns bans duplicate the Decisions Log but are harmless, so they are deferred.

**7. API hardening (medium)**
- The connection and SSE bounds are an accepted risk, compression is limited to `/assets/*` only, and the Host edge cases are stated. No patch.

## Patches

### Patch 1: Windows write rule: unreadable descriptor, NULL DACL, non-ACL volume, generic write bits
**Reason:** Dimension 5 (integrity of `~/.viola/` elevation is under-served on Windows). Without these rules, a NULL DACL, a FAT32/exFAT `--home`, or an inherit-only `GENERIC_WRITE`/`GENERIC_ALL` grant passes an ACE loop that checks only specific rights.
**Old:**
```
Refuse when the owner is not the user SID or Administrators, or when any allow ACE grants write, delete, `WRITE_DAC` or `WRITE_OWNER` to a SID other than the user, SYSTEM or Administrators
```
**New:**
```
Refuse when the security descriptor cannot be read, when the DACL is NULL (a NULL DACL grants everyone full access yet holds no ACE for `GetAce` to reject), when the volume lacks persistent ACLs (`GetVolumeInformationW` without `FILE_PERSISTENT_ACLS`, for example a `--home` on FAT32/exFAT), when the owner is not the user SID or Administrators, or when any allow ACE grants write (`FILE_WRITE_DATA`/`FILE_ADD_FILE`, `FILE_APPEND_DATA`/`FILE_ADD_SUBDIRECTORY`, `FILE_DELETE_CHILD`, `GENERIC_WRITE` or `GENERIC_ALL`), delete, `WRITE_DAC` or `WRITE_OWNER` to a SID other than the user, SYSTEM or Administrators
```

### Patch 2: Windows read rule: include GENERIC_ALL and the unmapped generic bits
**Reason:** Dimension 5. Inherit-only ACEs store unmapped generic bits. `Users:(OI)(CI)(IO)(GA)` passes a `FILE_READ_DATA` / `GENERIC_READ` test, but it exposes `events.ndjson` and the `.url` token in every file viola later creates.
**Old:**
```
grants read (`FILE_READ_DATA` / `GENERIC_READ`) to such a SID.
```
**New:**
```
grants read (`FILE_READ_DATA`, `GENERIC_READ` or `GENERIC_ALL`; inherit-only ACEs usually keep unmapped generic bits, as `icacls (OI)(CI)(IO)(F)` stores `GENERIC_ALL`, so test the generic bits as well as the specific ones) to such a SID.
```

### Patch 3: Decisions Log companion for Patches 1–2
**Reason:** Output Protocol rule 5. Patches 1–2 refine a boundary mechanism, so the key-decision Windows bullet needs a matching entry.
**Old:**
```
`.url` token). On both OSes
```
**New:**
```
`.url` token). It refuses an unreadable descriptor, a NULL DACL or a volume without persistent ACLs, and it tests the generic bits (`GENERIC_READ`, `GENERIC_WRITE`, `GENERIC_ALL`) that inherit-only ACEs keep unmapped. On both OSes
```

### Patch 4: § Data Protection ban against passing a NULL DACL or generic-bit grants
**Reason:** Dimension 5 / 6. The Anti-Patterns section is the single source of truth for bans. A distiller that reads only bans would otherwise let an ACE loop that checks only specific rights stand in for the check.
**Old:**
```
must not return `Ok(())` unchecked).
```
**New:**
```
must not return `Ok(())` unchecked), and NEVER pass a NULL DACL, a volume without persistent ACLs, or an inherit-only `GENERIC_*` grant just because no specific-rights ACE matched.
```

### Patch 5: Secret Management access auditing: state the Windows control
**Reason:** Cross-section consistency (the same control appears in several sections), Dimension 5. "0600 mode" describes Unix only. On Windows, the primary host, the `.url` file is protected by the checked home DACL, as the Storage bullet and the Token row already say.
**Old:**
```
The token file's 0600 mode is the access control.
```
**New:**
```
The token file's access control is its 0600 mode on Unix and, on Windows, the home DACL enforced by the owner + DACL startup check (Authentication & Authorization, `~/.viola/` access control).
```
