## Analysis

**Dimension 1: Downstream readiness (high)**
- `logging-redaction-wire` is the single consolidated NEVER-log floor. Data Protection § Logs, Error Handling, § Secrets and § Logging all point back to it. The full union is present: GUI token, launch URL, `.url`, `Cookie`, `CLAUDE_CODE_MESSAGING_TOKEN`/`_SOCKET`, other R8 `CLAUDE*` values, user content, tool `input`, `statusline_command`, drift reports and operational metadata.
- Adversarial question ("obs implements exactly these bullets"): one leak remains. The token also travels in the request target of `GET /?t=<token>` before the 303 redirect. The floor bans "the GUI token" and the `Cookie` header, but never says that request URIs carry it. A generic HTTP request/span logger records the path with its query by default, so obs would log the token without breaking any listed rule. `query|URI|access log` finds no floor or ban about this (only the Host row's "URI authority"). **Patch 1 fixes the floor; Patch 2 is the matching § Secrets ban.**
- The design boundaries (401 `detail` never holds the token or `.url`, `/` without `?t=` serves the ungated page, no reprint route) are stated. The 8 amendments are ordered against their chunks. The phases cover the SHA-256 re-hash, the Windows DACL and strict-modes checks, the `deny.toml` blocks, `schedule:` and `permissions`. Parser surfaces are listed in one place. No patch.

**Dimension 2: Threat to control traceability (high)**
- All 9 TMS vectors map to a control or an accepted risk. PATH `claude`, cross-port cookie and local availability/disk are all in Accepted risks.
- `heartbeat`, `settings.json`, `budget.json` and `/api/sessions` are covered.
- The TMS tier justification already matches the source verbatim. No patch.

**Dimension 3: Tool anchoring (high)**
- The SHA-256 open question is cross-referenced from Data Protection and Bootstrap, with its constraints and deadline.
- rmcp uses `>=3.4.1, <3.5`. External CLIs use `>=` floors in the body, Bootstrap and the Decisions Log.
- The atomic-write-file choice over tempfile is not justified, but that is cosmetic and was skipped.

**Dimension 4: GUI credential lifecycle (high)**
- Cross-port exposure is accepted and logged. The 401 on a failed exchange has no cookie and carries the security headers. The comparison is constant-time. No recovery shortcut exists. The stale `.url` after a crash is handled. No patch.

**Dimension 5: Tier calibration and elevations (high)**
- The Windows owner + DACL strict-modes check is now concrete.
- One gap remains in "integrity of `~/.viola/`" on Unix. The Auth & Authz row says "Check that atomic-write-file's temp file is 0600 before rename." That is a to-do, not a control. Without an explicit mode, a temp file gets its mode from the umask (for example 0644) or from the file being replaced. That contradicts "every file is created 0600" (Data Protection, § Data Protection ban), and nothing tells /implement what to do if the mode is wrong. security-research.md contains the same "check" wording, so turning it into an explicit set-mode step uses only std and adds no new tool. **Patch 3.**
- Over-engineering: each control above Minimal traces to a named elevation. No patch.

**Dimension 6: Anti-pattern centralisation (medium)**
- The output-encoding bans are in § API, and the `X-Forwarded-For` ban has been reframed.
- The v1.x release bans in § Code Patterns duplicate the Decisions Log, but they do no harm, so this was deferred.

**Dimension 7: API hardening (medium)**
- Host edge cases, the `/assets/*`-only compression and the availability accepted risk are all present. No patch.

## Patches

### Patch 1: Say that the token in the `/?t=` request URI is on the NEVER-log floor
**Reason:** Dimension 1, downstream readiness. The consolidated floor given to obs does not cover the request URI that carries the token before the redirect, and HTTP request or span logging records path plus query by default.
**Old:**
```
or any other R8-stripped `CLAUDE*` value to any log, diagnostic, snapshot, `events.ndjson` or fixture. The only exception
```
**New:**
```
or any other R8-stripped `CLAUDE*` value to any log, diagnostic, snapshot, `events.ndjson` or fixture. This includes the token inside a request URI: `GET /?t=<token>` carries it until the 303 redirect, so any HTTP request or span logging in `viola-ui` records the path without its query string. The only exception
```

### Patch 2: Matching § Secrets ban on logging the GUI request query string
**Reason:** Dimension 1 plus cross-section consistency. § Secrets restates the floor and "must not diverge from it", and Patch 1 widens the floor.
**Old:**
```
- NEVER print or log the GUI token outside the one-time launch line and the 0600 `.url` file. NEVER log the `Cookie` request header.
```
**New:**
```
- NEVER print or log the GUI token outside the one-time launch line and the 0600 `.url` file. NEVER log the `Cookie` request header, or the query string of a GUI request URI (`/?t=<token>` carries the token).
```

### Patch 3: Turn the atomic-write-file mode "check" into an explicit control
**Reason:** Dimension 5, the "integrity of `~/.viola/`" elevation, plus same control in several sections. "Check that … is 0600" is a to-do /implement cannot turn into code. Without an explicit mode the temp file takes the umask (for example 0644) or a mode carried over from the replaced file. That contradicts the 0600 file rule in Data Protection and § Data Protection.
**Old:**
```
Check that atomic-write-file's temp file is 0600 before rename.
```
**New:**
```
Set the mode of atomic-write-file's temp file explicitly (std `set_permissions`: 0600, or 0700 for the pinned `viola`) before `commit()` renames it into place. Never rely on the umask or on a mode carried over from the file being replaced. If the mode cannot be set, discard the write.
```
