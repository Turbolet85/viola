## Analysis

**Dim 1: Downstream Readiness**
- `logging-redaction-wire` is now the single NEVER-log floor. It covers the token, URL/`.url`, `Cookie`, `MESSAGING_TOKEN`/`SOCKET`, other R8 `CLAUDE*` values, and diagnostics-only user content / tool `input` / drift reports. § Secrets and Error Handling point back to it. No patch.
- Design boundary: 401 `detail`, no reprint route and headers on the failure response are all stated. No patch.
- Route ordering: amendments 2, 1 and 8 are placed. Parser surfaces are named. No patch.
- Gap: the `viola-channel` client bootstrap item depends on the open SQOS spike and does not say so. Patched together with Dim 2.

**Dim 2: Traceability / cross-references**
- All nine vectors now map to controls (PATH `claude`, `heartbeat` and disk exhaustion are in Accepted risks or Input Validation). TMS fidelity was restored in iteration 2.
- Defect: the open-question link is broken. The Windows client-verification row requires `Stream::try_from(OwnedHandle)` over a SQOS `FILE_FLAG_OVERLAPPED` handle, which is the unresolved spike. The row has no pointer to the spike and no rule for what happens if the spike fails. An implementer who hits a failed spike would most likely fall back to interprocess's default connect, which has no SQOS. The § Authentication ban forbids that, but nothing in the row or bootstrap says so. Patches 4–6.
- Defect: the strict-modes check is described inconsistently across sections.
  - Auth & Authz says it runs at "`run`, `ui`, `mcp` and `hook statusline`" only.
  - Input Validation (CLI row) says it runs "before any snapshot, `statusline_command` or ledger read", which covers `hook <event>` and `send`/`answer`.
  - The difference matters on Windows. Client verification there compares `server_process_id()` and start time only against the snapshot's `pid`/`started_at`, with no server-SID check. So a client that reads an unchecked (tampered) snapshot verifies against values an attacker chose, and `hook.dialog` payloads and decisions go to the attacker's pipe. Patches 1, 3, 7.

**Dim 3: Tool anchoring**
- rmcp range, `>=` floors and SHA-256 open-question linkage are all fixed.
- The atomic-write-file vs tempfile justification is cosmetic (no advisory against either). Skipped.
- No new tools are introduced. Every patch uses only the catalogued windows-sys and interprocess.

**Dim 4: GUI credential lifecycle**
- Cross-port exposure is accepted and logged. Exchange failure, the stale `.url` file and the no-recovery-shortcut rule are all stated. No patch.

**Dim 5: Elevations on every OS**
- Defect: the Windows "integrity of `~/.viola/`" and "GUI cross-user readability" controls are incomplete.
  - The Windows owner + DACL check refuses only write-type ACEs.
  - On Unix, confidentiality comes from creating every file 0600. On Windows, files inherit the home's DACL.
  - So a pre-existing `--home` with `Users:(R)` (or an object-inherit read ACE) passes the check. Every new `events.ndjson`, `diagnostics/` file and `ui/<port>.url` (the GUI token) then becomes readable by other local users, and the token gives them the full SSE feed.
  - Secret Management already claims the home DACL "admits only the user, SYSTEM and Administrators and is checked at startup", which is currently false for reads.
  - "Ignore inherit-only ACEs" is wrong for a read rule, because inherit-only object-inherit ACEs are exactly what new files receive.
  - Patch 2, with Decisions Log companion Patch 3.

**Dim 6: Anti-patterns**
- Output-encoding bans are in § API, and X-Forwarded-For has been reframed.
- The v1.x release bans duplicated in § Code Patterns are harmless. Skipped (medium priority, not blocking).
- The snapshot-reference ban is added in § Authentication (Patch 7).

**Dim 7: API hardening**
- Connection and stream exhaustion is an accepted risk, and the Compression control is now implementable.
- Host edge cases (missing Host, `LOCALHOST`, trailing dot) all fail closed under "compare exactly … anything else gets 403". No patch.

## Patches

### Patch 1: Run the strict-modes check in every process that reads snapshot/ledger state, and define the outcome for each entry point
**Reason:** Dim 2, same control in several sections (Auth & Authz lists four entry points; the Input Validation CLI row says "before any snapshot … read"). Dim 5 (IPC impersonation on Windows depends on snapshot integrity).
**Old:**
```
**Strict-modes check:** at the start of `run`, `ui`, `mcp` and `hook statusline`, refuse when the home, `instances/<name>/`, `bin/`, `plugin/` or `ledger/` is group- or world-writable or not owned by euid (ssh StrictModes style). `run`/`ui` then exit 1; `hook statusline` prints nothing and exits 0.
```
**New:**
```
**Strict-modes check:** in every process that reads `snapshot.json`, `ledger/stamps.json` or `statusline_command` (that is, at the start of `run`, `ui`, `mcp`, every `hook <event>` including `hook statusline`, and every CLI client verb that resolves an instance's `endpoint`), refuse when the home, `instances/<name>/`, `bin/`, `plugin/` or `ledger/` is group- or world-writable or not owned by euid (ssh StrictModes style). The snapshot's `endpoint`, `pid` and `started_at` are the reference values for client server verification, so a client that skips this check verifies the server against values an attacker could have written. On failure `run`, `ui` and `mcp` exit 1; every `hook` event prints nothing and exits 0; CLI client verbs report `instance-unreachable` (exit 21).
```

### Patch 2: The Windows owner + DACL check also refuses read grants to other SIDs, counts inheritable ACEs for reads, and covers `ui/`
**Reason:** Dim 5. The "GUI cross-user readability" and "integrity of `~/.viola/`" elevations are under-served on Windows. Files inherit the home's DACL, so a read-granting ACE exposes `events.ndjson` and the `.url` token. This also makes Secret Management's "admits only the user, SYSTEM and Administrators" claim true (Dim 2 consistency).
**Old:**
```
**Windows strict-modes check:** at the same four entry points (`run`, `ui`, `mcp`, `hook statusline`), read the owner and DACL of the home, `instances/<name>/`, `bin/`, `plugin/` and `ledger/` (each checked separately, because Windows bypass-traverse makes a subdirectory reachable regardless of the home's ACL) (windows-sys `GetNamedSecurityInfoW` + `GetAce`). Ignore inherit-only ACEs. Refuse when the owner is not the user SID or Administrators, or when any allow ACE grants write, delete, `WRITE_DAC` or `WRITE_OWNER` to a SID other than the user, SYSTEM or Administrators (for example `Users`, `Authenticated Users`, `Everyone`). The outcomes match Unix.
```
**New:**
```
**Windows strict-modes check:** at the same entry points as Unix, read the owner and DACL of the home, `instances/<name>/`, `bin/`, `plugin/`, `ledger/` and `ui/` (each checked separately, because Windows bypass-traverse makes a subdirectory reachable regardless of the home's ACL) (windows-sys `GetNamedSecurityInfoW` + `GetAce`). Refuse when the owner is not the user SID or Administrators, or when any allow ACE grants write, delete, `WRITE_DAC` or `WRITE_OWNER` to a SID other than the user, SYSTEM or Administrators (for example `Users`, `Authenticated Users`, `Everyone`); inherit-only ACEs may be ignored for this write rule only. **Read rule:** on the home, `instances/<name>/` and `ui/`, also refuse any allow ACE, including an inherit-only ACE with object-inherit, that grants read (`FILE_READ_DATA` / `GENERIC_READ`) to such a SID. Files viola creates inherit these DACLs, so a readable directory exposes `events.ndjson`, `diagnostics/` and `ui/<port>.url` (the GUI token). This is the Windows counterpart of Unix's 0600 file creation. The outcomes match Unix.
```

### Patch 3: Decisions Log companion for Patches 1 and 2
**Reason:** Output Protocol rule 5 (a boundary mechanism changed). Dim 5.
**Old:**
```
For `~/.viola/`, an owner + DACL startup check (the Windows strict-modes equivalent) that tolerates only the user, SYSTEM and Administrators as writers.
```

**New:**
```

```
