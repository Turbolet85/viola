## Analysis

**Dimension 1: Downstream Readiness**
- NEVER-log floor: iteration 1 consolidated it in `logging-redaction-wire`, and § Secrets and Error Handling point to it. Two defects remain.
  - **Contradiction with the launch line.** The floor bans the GUI token and launch URL from every log, and Error Handling says "stderr never carries ... any other value on the NEVER-log floor". But the Token row requires the launch URL to be "printed once to stderr at launch". An obs or `/implement` reader gets two rules that cannot both hold. Patch needed.
  - **Over-broad second bullet.** It says user content, tool `input` and `statusline_command` "never go to ... CLI `--json`, MCP results", and outside `events.ndjson` only to `diagnostics/`. Read literally, that forbids the product's own data plane: MCP and CLI `wait`/`last` return `last_assistant_message`, `hook.dialog` carries `input`, and `snapshot.json` and `settings.json` store `statusline_command` (TMS §1). The floor needs a scope limited to log, diagnostic and error output. Patch needed.
- Route ordering: only amendments 1, 2 and 8 are placed against chunks. Amendments 3–7 are not, so route cannot order them from the text. Patch needed.
- Bootstrap: the `viola-ui` item names only the token and cookie middleware. The outermost Host allowlist, which the cookie check runs after ("Host allowlist first ... then the cookie"), is in no phase. Neither are the security-header layer and the `/assets/*`-only compression scoping. Patch needed.
- Design boundary (no token or `.url` in the page or `detail`, ungated `/`, 401 on a mismatched `?t=`) is stated. The tests parser-surface list exists. No patch.

**Dimension 2: Threat → Control Traceability and TMS Fidelity**
- All nine vectors trace to controls or accepted risks. PATH `claude`, cross-port cookie exposure and availability are now in Accepted risks. `heartbeat` is in the own-state-file row, and the `settings.json` class is covered. The TMS was restored in iteration 2. No patch.

**Dimension 3: Tool Anchoring**
- The SHA-256 open question is cross-referenced, phased and constrained. The external CLI floors use `>=` in the body, Bootstrap and the Decisions Log.
- Update policy still calls the rmcp pin "`~3.4`". That range admits 3.4.0 and contradicts the Pinning bullet's `>=3.4.1, <3.5`, so a reader could write `~3.4` into `Cargo.toml`. Patch needed.
- atomic-write-file is the arch/Stack choice, and research lists tempfile only as an alternative with no advisory. No justification gap. No patch.

**Dimension 4: GUI Credential Lifecycle**
- Constant-time `?t=` check, 401 with headers on failure, no recovery shortcut, stale `.url` after a crash, and cross-port leakage (accepted, with a Decisions Log entry) are all present. No patch.

**Dimension 5: Tier Calibration and Elevation Coverage**
- The Windows owner + DACL strict-modes check (write and read rules) is now defined at the same entry points as Unix. SKIP markers are correct.
- The v1.x signing entries in "What counts as secret" and the Code Patterns release bans are harmless forward notes. They do not break implementation, so I did not spend a patch on them.

**Dimension 6: Anti-Pattern Relevance**
- The output-encoding bans are in § API, and the `X-Forwarded-For` ban has been reframed. The Universal bans are acceptable. No patch.

**Dimension 7: API Hardening**
- Connection and stream exhaustion is an accepted risk. Compression is now an implementable control. Exact Host comparison rejects a missing Host, `LOCALHOST` and a trailing dot by construction. No patch.

## Patches

### Patch 1: Scope the NEVER-log floor and state the launch-line exception
**Reason:** Dimension 1 (downstream readiness / same control in several sections). The floor bans the launch URL from all output, but the Token row requires a stderr launch line. The second bullet, read literally, bans content from the MCP and CLI `wait`/`last` results, from `hook.dialog` and from the snapshot's `statusline_command`, all of which carry it by contract.
**Old:**
```
  - Never write the GUI token, the launch URL or `.url` contents, the `Cookie` header, `CLAUDE_CODE_MESSAGING_TOKEN`, `CLAUDE_CODE_MESSAGING_SOCKET` or any other R8-stripped `CLAUDE*` value to any log, diagnostic, snapshot, `events.ndjson` or fixture.
  - Outside `events.ndjson` (the event store itself), user content (prompts, `last_assistant_message`, plan and question text), tool `input`, the `statusline_command` string, and serde_path_to_error drift reports (paths and values) go only to `instances/<name>/diagnostics/`. They never go to stderr, CLI `--json`, MCP results, Problem Details or channel `error.data`.
```
**New:**
```
  - Never write the GUI token, the launch URL or `.url` contents, the `Cookie` header, `CLAUDE_CODE_MESSAGING_TOKEN`, `CLAUDE_CODE_MESSAGING_SOCKET` or any other R8-stripped `CLAUDE*` value to any log, diagnostic, snapshot, `events.ndjson` or fixture. The only exception is the launch URL that `viola ui` prints once to stderr at start and writes to the 0600 `.url` file (Authentication & Authorization, Token / session storage). No other stderr line carries it.
  - Scope: this floor governs log lines, diagnostics and error output. It does not restrict the contract payloads that carry content by design: `events.ndjson`, SSE `/api/events`, `wait`/`last` results (CLI and MCP), `hook.dialog`, and `statusline_command` in `snapshot.json` and `instances/<name>/settings.json`. Outside those payloads, user content (prompts, `last_assistant_message`, plan and question text), tool `input`, the `statusline_command` string, and serde_path_to_error drift reports (paths and values) go only to `instances/<name>/diagnostics/`. They never go to stderr log or error lines, CLI `--json` error output, MCP `isError` results, Problem Details or channel `error.data`.
```

### Patch 2: Align the Error Handling stderr rule with the floor's launch-line exception
**Reason:** Dimension 1 (same control, several sections). Error Handling says stderr never carries a floor value, which contradicts the required stderr launch line.
**Old:**
```
stderr never carries upstream text, tool `input`, drift-report values or any other value on the NEVER-log floor (Bootstrap phases, `logging-redaction-wire`).
```
**New:**
```
stderr never carries upstream text, tool `input`, drift-report values or any other value on the NEVER-log floor (Bootstrap phases, `logging-redaction-wire`). The one-time `viola ui` launch line is that floor's only exception.
```

### Patch 3: Order all eight arch amendments against chunks
**Reason:** Dimension 1 (route readiness). Only amendments 1, 2 and 8 are ordered. Route cannot place 3 (`control-character`, URNs), 4 (`release-from-driver`), 5 (`.url` file), 6 (`MAX_FRAME`) or 7 (ledger row) from the text.
**Old:**
```
- **auth-scaffolding-baseline:** Narrowed to the local boundary; no auth library. Arch amendment 2 (Unix endpoint move) must be folded in before the `viola-channel` chunk, amendment 1 (v1 GUI cookie) before the `viola-ui` chunk, and amendment 8 (SHA-256 `<hash>`) before the chunk that writes `bin/`.
```
**New:**
```
- **auth-scaffolding-baseline:** Narrowed to the local boundary; no auth library. Each arch amendment (Decisions Log) must be folded in before the first chunk that implements it:
  - Amendments 3 (`control-character` detail and the two Problem Details URNs) and 6 (`MAX_FRAME`): before the `viola-core` chunk.
  - Amendment 2 (Unix endpoint move): before the `viola-channel` chunk.
  - Amendment 4 (`release-from-driver`): before the `viola` bin channel dispatch.
  - Amendments 1 (v1 GUI cookie) and 5 (`ui/<port>.url`): before the `viola-ui` chunk.
  - Amendment 7 (largest-hook-payload ledger row): before the `viola verify` chunk.
  - Amendment 8 (SHA-256 `<hash>`): before the chunk that writes `bin/`.
```

### Patch 4: Put the Host allowlist and the header and compression layers in the `viola-ui` bootstrap item
**Reason:** Dimension 1 (MUST controls missing from every phase). The cookie middleware is phased, but the Host allowlist it must run behind is not. Neither are the CSP/security-header layer and the `/assets/*`-only compression scoping.
**Old:**
```
  - `viola-ui`: getrandom token, `.url` file, `?t=` exchange and `viola_<port>` cookie middleware with constant_time_eq.
```
**New:**
```
  - `viola-ui`: the outermost Host allowlist middleware (before routing, on every route), the `SetResponseHeaderLayer` CSP and security headers, and `CompressionLayer` on `/assets/*` only (API Security). Then the getrandom token, `.url` file, `?t=` exchange and `viola_<port>` cookie middleware with constant_time_eq on the `/api` sub-router.
```

### Patch 5: Make the Update policy rmcp range match Pinning
**Reason:** Dimension 3 (tool anchoring). "`~3.4`" admits 3.4.0, below the catalogued 3.4.1, and contradicts the Pinning bullet's `>=3.4.1, <3.5`.
**Old:**
```
The rmcp minor pin (`~3.4`) makes the scheduled run the main signal for that crate.
```
**New:**
```
The rmcp minor range (`>=3.4.1, <3.5`) makes the scheduled run the main signal for that crate.
```
