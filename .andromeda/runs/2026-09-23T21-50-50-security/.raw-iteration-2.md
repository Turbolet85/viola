## Patches

### Patch 1: Universal PATH ban covers the settings.json statusline command
**Reason:** Dimension 2. The TMS §1 config class `instances/<ViolaName>/settings.json` has no control. `viola run` writes a statusline command into it (`viola hook statusline`, per architecture.md Occupied Resources), and Claude Code runs that command. Only `hooks.json` and `.mcp.json` are protected against PATH resolution.
**Old:**
```
or in `viola plugin install`'s `.mcp.json`, resolve `viola` through PATH.
```
**New:**
```
or in `viola plugin install`'s `.mcp.json`, or the statusline command `viola run` writes into `instances/<name>/settings.json` (it wraps the statusline with `viola hook statusline`), resolve `viola` through PATH.
```

### Patch 2: Data Protection lists settings.json as a code-bearing artefact
**Reason:** Dimension 2. The `settings.json` data class needs a stated at-rest control. The same class of file under `plugin/` is always rewritten rather than trusted, and `settings.json` gets no such rule.
**Old:**
```
    - `viola run` always rewrites `plugin/<version>-<hash>/` files with atomic-write-file rather than trusting an existing copy.
```
**New:**
```
    - `viola run` always rewrites `plugin/<version>-<hash>/` files with atomic-write-file rather than trusting an existing copy.
    - `instances/<name>/settings.json` (the per-session override whose statusline command Claude Code executes) is rewritten by `viola run` at every start with atomic-write-file (0600) and never reused from an existing copy. Its command uses the absolute pinned `bin/<version>-<hash>/viola(.exe)` path (§ Universal).
```

### Patch 3: Unix strict-modes list includes `ledger/`
**Reason:** Dimension 5 (integrity of `~/.viola/`). The ledger stamps are named in the elevation and switch on dialog answering, but the strict-modes directory list leaves out `ledger/`. This keeps the Unix list the same as the Windows list in Patch 4.
**Old:**
```
refuse when the home, `instances/<name>/`, `bin/` or `plugin/` is group- or world-writable
```
**New:**
```
refuse when the home, `instances/<name>/`, `bin/`, `plugin/` or `ledger/` is group- or world-writable
```

### Patch 4: Windows strict-modes check reads `ledger/`
**Reason:** Dimension 5. On Windows, bypass traverse checking lets a subdirectory with a permissive explicit ACE be written even when the home's DACL is correct. `ledger/stamps.json` decides PermissionRequest `allow`, and the Windows check does not read `ledger/`.
**Old:**
```
read the owner and DACL of the home, `instances/<name>/`, `bin/` and `plugin/` (windows-sys
```
**New:**
```
read the owner and DACL of the home, `instances/<name>/`, `bin/`, `plugin/` and `ledger/` (each checked separately, because Windows bypass-traverse makes a subdirectory reachable regardless of the home's ACL) (windows-sys
```

### Patch 5: § Data Protection Windows DACL ban matches Auth & Authz
**Reason:** Dimension 5 and cross-section consistency. The ban says "user-only DACL", while Auth & Authz, Data Protection and Bootstrap say protected user + SYSTEM. The ban also leaves out the Windows startup check, so a distiller that pulls only Anti-Patterns loses it.
**Old:**
```
On Windows, NEVER accept a `--home` outside `%USERPROFILE%` without an explicit user-only DACL.
```
**New:**
```
On Windows, NEVER accept a `--home` outside `%USERPROFILE%` without an explicit protected user + SYSTEM DACL, and NEVER skip the Windows owner + DACL strict-modes check at startup (`#[cfg(windows)]` must not return `Ok(())` unchecked).
```

### Patch 6: Compression row becomes a control that can be coded
**Reason:** Dimension 7. "Re-test the exclusion" is a to-do that /implement cannot turn into code, yet the § API ban "NEVER compress `text/event-stream`" depends on it. Limiting the catalogued `CompressionLayer` to the assets router removes the dependence on tower-http 0.7's 406 behaviour for SSE.
**Old:**
```
| Compression | `CompressionLayer` excludes `text/event-stream`. Re-test the exclusion under tower-http 0.7's 406 semantics for `identity;q=0` and `*`. |
```
**New:**
```
| Compression | Apply `CompressionLayer` only to the `/assets/*` sub-router. `/api/*` and SSE `/api/events` sit outside it, so SSE is never compressed and never receives tower-http 0.7's 406 for `Accept-Encoding: identity;q=0` or `*` (a 406 on `/assets/*` is harmless). Do not rely on a content-type predicate alone for the SSE exclusion. |
```

### Patch 7: § Secrets CLAUDE_* ban matches the NEVER-log floor
**Reason:** Dimension 1. The consolidated floor in `logging-redaction-wire` bans these values from "any log". The § Secrets ban leaves out logs and stderr, so the two diverge even though Bootstrap says restatements must not.
**Old:**
```
or any R8-stripped `CLAUDE*` value into `events.ndjson`, snapshots, `diagnostics/` or fixtures.
```
**New:**
```
or any R8-stripped `CLAUDE*` value into any log or stderr, `events.ndjson`, snapshots, `diagnostics/` or fixtures (consolidated floor: Bootstrap phases, `logging-redaction-wire`).
```
