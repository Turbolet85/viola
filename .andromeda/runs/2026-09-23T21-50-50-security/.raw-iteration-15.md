## Patches

### Patch 1: Extend the Windows read rule to `diagnostics/` and existing `events.ndjson`
**Reason:** Dimensions 2 and 5. On Windows, the TMS §1 user-content class (`events.ndjson`, drift reports in `diagnostics/`) is left under-protected. The read rule covers directories only, while the same row says bypass-traverse and explicit file ACEs defeat directory-only checks. `events.ndjson` is appended to and never replaced, so an explicit read ACE on it persists.
**Old:**
```
**Read rule:** on the home, `instances/<name>/` and `ui/`, also refuse any allow ACE
```
**New:**
```
**Read rule:** on the home, `instances/<name>/`, `instances/<name>/diagnostics/` and `ui/`, and on each existing `events.ndjson` before the process opens it (the file is appended to across sessions and never replaced, so an explicit ACE on it survives, and bypass-traverse makes it readable by its predictable path whatever the directory ACLs say), also refuse any allow ACE
```

### Patch 2: Decisions Log companion for the Windows read-rule scope
**Reason:** Output Protocol rule 5. Patch 1 changes a boundary mechanism, so the key-decision entry has to match.
**Old:**
```
and as readers of the home, `instances/<name>/` and `ui/` (files inherit those DACLs; this protects `events.ndjson` and the `.url` token).
```
**New:**
```
and as readers of the home, `instances/<name>/`, `instances/<name>/diagnostics/`, `ui/` and each existing `events.ndjson` before it is opened (files inherit the directory DACLs, but `events.ndjson` is appended to rather than replaced, so its own ACE is checked too; this protects `events.ndjson`, `diagnostics/` and the `.url` token).
```
