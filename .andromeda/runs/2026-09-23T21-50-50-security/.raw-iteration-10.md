## Analysis

**Dim 1, Downstream Readiness (high).** No patch needed.
- `logging-redaction-wire` is now the single NEVER-log floor. It covers the GUI token, the launch URL and `.url` contents, `Cookie`, `CLAUDE_CODE_MESSAGING_TOKEN`/`_SOCKET`, other R8 `CLAUDE*` values, the diagnostics-only rule for user content, tool `input` and drift reports, and operational metadata. § Secrets, Error Handling and Data Protection § Logs point back to it.
- Design gets the recovery boundary: 401 with no cookie on a bad `?t=`, security headers on the failure response, and no token-reprint route.
- All 8 amendments are ordered against their first chunk, and the SHA-256 and Windows `--home` DACL items each have a Bootstrap phase.
- The parser surfaces tests needs are named in one place.

**Dim 2, Threat → Control / TMS fidelity (high).**
- All nine vectors map to a control. The PATH `claude` lookup, local availability and cross-port cookie exposure are in Accepted risks, and `heartbeat` is in the own-state-file row.
- New defect, "integrity of `~/.viola/`" elevation plus cross-section consistency:
  - Every Unix file is created 0600, including the pinned `bin/<version>-<hash>/viola` that Claude Code runs on every hook event and for MCP. A 0600 binary cannot be executed, so the rule as written breaks the product, or /implement will quietly pick its own mode (possibly 0755/0777). Three places say the same thing (Auth row, Data Protection, § Data Protection ban), and none gives an exception.
- The TMS is already verbatim (restored in iteration 2).

**Dim 3, Tool anchoring (high).**
- The SHA-256 re-hash is linked to its open question, has its pick constraints and has a Bootstrap owner.
- rmcp uses a floored range, and the external CLIs use `>=` floors in body, Bootstrap and Decisions Log.
- The atomic-write-file vs tempfile rationale is still missing, but it is low impact and I did not patch it.

**Dim 4, GUI credential lifecycle (high).** No patch needed. Constant-time `?t=`, the 401 path, headers on the failure response, no recovery shortcut, the stale `.url` after a crash, and cross-port exposure (accepted, with a Decisions Log entry) are all present.

**Dim 5, Tier / elevation coverage (high).** Windows owner + DACL strict-modes exists. It is now Unix that falls short:
- The Unix strict-modes check looks only at the listed top-level directories.
- It never checks the version folders Claude Code executes from (`bin/<version>-<hash>/`, `plugin/<version>-<hash>/`) or the trusted files themselves (`snapshot.json`, `ledger/stamps.json`, the pinned exe). A 0755 `bin/` with a 0777 version folder passes, which leaves time to swap the file between the re-hash and the hook run. A 0666 `stamps.json` inside non-writable directories also passes, and that enables dialog answering.
- It has no read rule. The Windows row covers "pre-existing and later-modified homes" with a read rule, but Unix only sets 0600 at creation time, so a pre-existing 0755/0644 home exposes `events.ndjson` and `ui/<port>.url`.
- Windows has the matching gap for explicit (non-inherited) ACEs on the version folders.
- Nothing over-engineered needed a patch.

**Dim 6, Anti-patterns (medium).** Output-encoding bans are in § API, and the client-address ban is reframed. The v1.x release bans duplicated in Code Patterns are deferrable, so no patch.

**Dim 7, API hardening (medium).** Host edge cases, the compression predicate and the availability accepted risk are all present. No patch.

## Patches

### Patch 1: Pinned exe needs an executable mode exception (Auth & Authz)
**Reason:** Dim 2/5, integrity of `~/.viola/`. Every file at 0600 includes the pinned `viola`, which Claude Code must execute. The mode is unstated, so it is either broken or left to /implement.
**Old:**
```
**Unix:** home (and any `--home`) is created 0700, and every file is created with `OpenOptionsExt::mode(0o600)`. Check that atomic-write-file's temp file is 0600 before rename.
```
**New:**
```
**Unix:** home (and any `--home`) is created 0700, and every file is created with `OpenOptionsExt::mode(0o600)`, except the pinned `bin/<version>-<hash>/viola`, which must be executable and is created 0700 (never group- or world-writable; at 0600 every hook and MCP exec would fail). Check that atomic-write-file's temp file is 0600 before rename.
```

### Patch 2: Unix strict-modes covers version folders and trusted files, plus a read rule
**Reason:** Dim 5, integrity of `~/.viola/`, which must hold on every OS. The Unix check skips the executed version folders and the trusted files, and has no counterpart to the Windows read rule for pre-existing homes.
**Old:**
```
refuse when the home, `instances/<name>/`, `bin/`, `plugin/`, `ledger/` or `ui/` is group- or world-writable or not owned by euid (ssh StrictModes style).
```
**New:**
```
refuse when the home, `instances/<name>/`, `bin/`, `plugin/`, `ledger/` or `ui/`, the `bin/<version>-<hash>/` and `plugin/<version>-<hash>/` folders the process uses or writes, or a trusted file itself (`snapshot.json`, `ledger/stamps.json`, the pinned `viola`) is group- or world-writable or not owned by euid (ssh StrictModes style). **Read rule:** also refuse when the home, `instances/<name>/` or `ui/` grants any group or other permission (`mode & 0o077 != 0`). This is the Unix counterpart of the Windows read rule, so a pre-existing home cannot expose `events.ndjson`, `diagnostics/` or `ui/<port>.url`.
```

### Patch 3: Windows strict-modes covers version folders in use
**Reason:** Dim 5. An explicit (non-inherited) ACE on `bin/<version>-<hash>/` or `plugin/<version>-<hash>/` escapes the parent-directory check. Claude Code executes from those folders after the re-hash.
**Old:**
```
read the owner and DACL of the home, `instances/<name>/`, `bin/`, `plugin/`, `ledger/` and `ui/` (each checked separately
```
**New:**
```
read the owner and DACL of the home, `instances/<name>/`, `bin/`, `plugin/`, `ledger/`, `ui/` and the `bin/<version>-<hash>/` and `plugin/<version>-<hash>/` folders the process uses or writes (each checked separately
```

### Patch 4: Data Protection file-mode line matches the exe exception
**Reason:** Cross-section consistency with Patch 1.
**Old:**
```
  - Unix: 0700 directories and 0600 files.
```
**New:**
```
  - Unix: 0700 directories and 0600 files, except the pinned `bin/<version>-<hash>/viola`, which is 0700.
```

### Patch 5: § Data Protection ban matches the exe exception
**Reason:** Cross-section consistency with Patch 1. The ban list is the single source of truth, and as written it forbids an executable pinned binary.
**Old:**
```
Directories are 0700 and files 0600 (`OpenOptionsExt::mode`).
```
**New:**
```
Directories are 0700 and files 0600 (`OpenOptionsExt::mode`); the only exception is the pinned `bin/<version>-<hash>/viola` at 0700, and NEVER make it group- or world-writable.
```

### Patch 6: Decisions Log companion for the Unix home-integrity mechanism
**Reason:** Output Protocol rule 5. Patches 1–3 change a boundary mechanism.
**Old:**
```
  - Unix: a 0700 per-user socket directory as the primary control, `mode(0o600)` as secondary, and a `peer_creds` euid check on both sides.
```
**New:**
```
  - Unix: a 0700 per-user socket directory as the primary control, `mode(0o600)` as secondary, and a `peer_creds` euid check on both sides. For `~/.viola/`, the strict-modes check covers the listed directories, the `bin/`/`plugin/` version folders in use and the trusted files (`snapshot.json`, `ledger/stamps.json`, the pinned exe, which is the only file created 0700 rather than 0600). It also refuses group/other permissions on the home, `instances/<name>/` and `ui/`, matching the Windows read rule, so pre-existing homes are covered on both OSes. On Windows the check also covers the version folders in use.
```
