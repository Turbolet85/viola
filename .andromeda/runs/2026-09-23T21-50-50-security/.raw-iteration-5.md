## Patches

### Patch 1: Run server verification before any channel frame, including `hook.event`
**Reason:** Dimension 2 / the IPC server impersonation elevation. `hook.event` notifications from UserPromptSubmit, Stop and PostToolUse carry prompt text, `last_assistant_message` and tool data. The Timing rule does not cover them, so a squatted endpoint gets the conversation without any server check.
**Old:**
```
**Timing:** all of this runs before the first `send`, `answer` or `hook.dialog` frame.
```
**New:**
```
**Timing:** all of this runs before the first frame of any method is written on the connection, including `hook.event` notifications (UserPromptSubmit, Stop and PostToolUse carry prompt text, `last_assistant_message` and tool data) and `wait`/`last` requests, not only `send`, `answer` and `hook.dialog`.
```

### Patch 2: Widen the § Authentication verification ban to every frame
**Reason:** Dimension 2 / Dimension 6 cross-section consistency. The ban must match Patch 1, or a distiller that pulls only Anti-Patterns will let `hook.event` go out unverified.
**Old:**
```
- NEVER send a `send`, `answer` or `hook.dialog` frame before verifying the server's pid
```
**New:**
```
- NEVER write any channel frame (`send`, `answer`, `hook.dialog`, `wait`/`last`, and `hook.event` notifications, which carry prompt and reply text) before verifying the server's pid
```
