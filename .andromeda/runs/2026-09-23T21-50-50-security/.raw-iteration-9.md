## Analysis

**Dimension 1: Downstream readiness (obs, design, route, setup-project, tests)**
- obs: `logging-redaction-wire` is now the single consolidated NEVER-log floor. It covers the GUI token, the launch URL and `.url` file, the `Cookie` header, `CLAUDE_CODE_MESSAGING_TOKEN` and `_SOCKET`, the other R8 `CLAUDE*` values, the diagnostics-only rule for user content, tool `input` and drift reports, and operational metadata. § Secrets, § Logging, Error Handling and Data Protection § Logs all point back to it. No divergence apart from the gap below.
- **Gap:** the C0/C1 escape floor covers only human-mode `wait`/`last`. Human-mode `list` prints rows parsed from `claude agents --json` (unwrapped session names). That output is untrusted: it comes from a PATH-resolved child, which is an accepted risk, so a planted `claude` can supply it. Nothing requires escaping it before it reaches the terminal. This is the same terminal-escape-injection class that the `wait`/`last` rule (RUSTSEC-2025-0055) exists to stop. **Patch needed** (Patches 1–4).
- design: the exchange failure (401, no cookie, security headers), `/` without `?t=`, and the no-token-in-`detail` rule are all stated. Design can derive the rest. No patch.
- route / setup-project: all 8 amendments are ordered against chunks. The SHA-256 re-hash, the Windows `--home` DACL and startup check, the code-bearing artefact rewrite, the `deny.toml` blocks and the `ci.yml` schedule each have an owning phase. No patch.
- tests: the parser surfaces are listed in one place in Input Validation. No patch.

**Dimension 2: Threat → control traceability and TMS fidelity**
- All 9 vectors map to a control:
  - IPC → Auth & Authz rows.
  - `send` PTY → paste rule.
  - Loopback HTTP → API Security.
  - Hook stdin → Input Validation row.
  - MCP → MCP inputs row.

- The PATH-`claude` accepted risk says injected rows are "rendered as text only". That holds for the GUI but not for terminal output. Patch 4 fixes this.
- The TMS matches the source verbatim (restored in iteration 2). No patch.

**Dimension 3: Tool anchoring**
- The SHA-256 re-hash is linked to its open question, has pick constraints and belongs to a Bootstrap phase.
- rmcp uses the range `>=3.4.1, <3.5` consistently.
- External CLI tools use `>=` floors in Dependency Security, the Bootstrap phases and the v1.x prerequisites.
- The atomic-write-file vs tempfile justification is a cosmetic matter only.
- No patch.

**Dimension 4: GUI credential lifecycle and recovery**
- Constant-time `?t=` comparison, the 401 with no cookie, headers on the failure response, no recovery shortcut, the stale `.url` after a crash, and the cross-port exposure (accepted risk) are all stated.
- **Sibling gap:** the Windows strict-modes check covers `ui/`, but the Unix check does not. On Unix, a group- or world-writable `ui/` lets another user replace `<port>.url` (directory write allows rename/unlink even of a 0600 file). A replacement file could send the user to a foreign `127.0.0.1` port, turning the accepted cross-port cookie exposure into something an attacker can trigger. It is also a cross-OS inconsistency inside the same row. **Patch needed** (Patch 5, one line).

- The file-level mode check (as opposed to directory-level) is left alone. It needs same-user action, and the plan puts same-user tampering outside the v1 boundary.

## Patches

### Patch 1: Extend the consolidated terminal-escape floor to `list` rows from `claude agents --json`
**Reason:** Dimension 1 (obs/consolidated floor). Human-mode `list` prints untrusted child-process output to a terminal with no escaping rule.
**Old:**
```
  - Human-mode CLI output of `wait`/`last` escapes C0/C1 controls (keeping `\n` and `\t`).
```
**New:**
```
  - Human-mode CLI output of `wait`/`last`, and of `list` rows (every field taken from `claude agents --json`, including unwrapped session names), escapes C0/C1 controls (keeping `\n` and `\t`).
```

### Patch 2: Align the § Logging terminal-escape ban with the floor
**Reason:** Dimension 1 and cross-section consistency. The ban has to match the consolidated floor, and it must cover the PATH-resolved child output that is accepted as untrusted.
**Old:**
```
- NEVER print `wait`/`last` human-mode output to a terminal without escaping C0/C1 controls (the same class as RUSTSEC-2025-0055).
```
**New:**
```
- NEVER print `wait`/`last` human-mode output, or `list` rows taken from `claude agents --json`, to a terminal without escaping C0/C1 controls (the same class as RUSTSEC-2025-0055).
```

### Patch 3: State the terminal-escape requirement in the child-process Input Validation row
**Reason:** Dimension 2. The row covering the "Child process spawning / PATH resolution" vector names only the GUI as a text-only renderer. The CLI `list` terminal sink has no stated control in the row the `viola-agent-claude` / CLI chunk distiller reads.
**Old:**
```
The GUI renders it as text only.
```
**New:**
```
The GUI renders it as text only, and human-mode CLI `list` escapes C0/C1 controls in it before printing (§ Logging).
```

### Patch 4: Correct the PATH-`claude` accepted-risk bound
**Reason:** Dimension 2. The accepted risk claims a planted `claude` can at most inject display rows "rendered as text only". Without escaping, those rows can carry terminal control sequences into the user's terminal through `viola list`, which goes beyond display rows. This patch is itself the Decisions Log entry for the change.
**Old:**
```
Those rows are never a `ViolaName` or `target` and are rendered as text only.
```
**New:**
```
Those rows are never a `ViolaName` or `target`, are rendered as text only in the GUI, and are printed by human-mode `list` only with C0/C1 controls escaped.
```

### Patch 5: Add `ui/` to the Unix strict-modes directory list
**Reason:** Dimension 4/5 and cross-section consistency. The Windows check covers `ui/`, but the Unix check does not. A group- or world-writable `ui/` lets another user replace `<port>.url`, the plan's stated recovery path, with a URL to a foreign loopback port, which makes the accepted cross-port cookie exposure attacker-triggerable.
**Old:**
```
`plugin/` or `ledger/` is group- or world-writable or not owned by euid (ssh StrictModes style)
```
**New:**
```
`plugin/`, `ledger/` or `ui/` is group- or world-writable or not owned by euid (ssh StrictModes style)
```
