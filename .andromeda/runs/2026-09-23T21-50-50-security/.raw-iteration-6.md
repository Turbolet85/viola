**Dimension 5: Elevation coverage per OS**
- The Windows owner + DACL strict-modes check with its read rule is concrete and consistent across Auth & Authz, Data Protection, Secret Management, § Data Protection and the Decisions Log.
- **Defect (cross-section, macOS):** Auth & Authz explicitly records that macOS gets euid plus the 0700 directory with no pid or start-time check (a known gap). The § Authentication ban still says "euid/pid (Unix `peer_creds()`) plus sysinfo start time" with no macOS exception.
  - An implementer who follows the ban cannot meet it on macOS: `peer_creds()` gives no pid there, so there is nothing to check a start time against. They will either break every macOS CI connect or quietly weaken the check on all platforms.
  - The ban is the text that distillers pull. → Patch 1.
- **Defect (cross-section, hook fail-open):** the Unix IPC row's directory check says "clients report `instance-unreachable` (exit 21)". `hook` is a channel client, and the Hook Contract, Error Handling, § Logging and the server-verification row all require `hook` to exit 0 with no body on any security-check failure.
  - The `viola-channel` client chunk reads this row, so a `hook` that exits 21 would break "never let a security refusal block the human". → Patch 2.

**Dimension 6: Anti-pattern centralisation**
- The output-encoding bans are in § API, and the client-address ban has been reframed.
- The v1.x release bans in Code Patterns duplicate the Decisions Log prerequisites but do no harm. That is medium priority and can wait. No patch.

**Dimension 7: API hardening**
- Connection and stream exhaustion is an accepted risk. Compression is now a real control (assets sub-router only). A Host header that is missing or in a different letter case falls under "anything else → 403". No patch.

## Patches

### Patch 1: Match the § Authentication server-verification ban to the macOS known gap
**Reason:** Dimension 5 and same-control consistency. The ban requires a pid and start-time check that cannot be done on macOS, which contradicts the Auth & Authz identity check and the Decisions Log known gap.
**Old:**
```
before verifying the server's pid (Windows `server_process_id()`) or euid/pid (Unix `peer_creds()`) plus sysinfo start time against `snapshot.json`
```
**New:**
```
before verifying the server's pid (Windows `server_process_id()`) or euid + pid (Linux/FreeBSD `peer_creds()`) plus sysinfo start time against `snapshot.json` (on macOS, where `peer_creds()` gives no pid: euid + the verified 0700 socket directory only, per the recorded known gap; the euid check is never skipped)
```

### Patch 2: Make `hook` fail open when the Unix IPC directory check fails
**Reason:** Dimension 5 and same-control consistency. The Unix directory-check outcome sends every client to exit 21, which contradicts the rule that `hook` fails open (Hook Contract, Error Handling, § Logging, and the server-verification "On mismatch" rule).
**Old:**
```
On failure `run` refuses to start (exit 1) and clients report `instance-unreachable` (exit 21).
```
**New:**
```
On failure `run` refuses to start (exit 1), CLI/MCP clients report `instance-unreachable` (exit 21), and `hook` fails open (exit 0, no body, a note in `diagnostics/`) without writing any frame.
```
