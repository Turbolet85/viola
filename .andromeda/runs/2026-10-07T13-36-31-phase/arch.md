## Constraints
- **Confirmation contract.** architecture §Established Decisions → [Delivery Confirmation] requires every `send` that is not a listed local command to be confirmed by a matching `prompt-submitted` inside the compiled window, and requires the wrapper to claim the in-flight send's prompt, append it relabelled, and only then settle the send with that line's `ts`. The same entry requires the match to be exact, with no trim, after `viola-agent-claude`'s normalisation. A remedy that widens the match changes that sentence: the P4 card names the exact widening (one last newline, as measured), and the entry is the wrap's to amend. Whether the code today compares exactly as the entry says is research's question (scope item 1).
- **Wheel contract.** architecture §Established Decisions → [Human Takeover / Wheel] requires that the relabelled in-flight `driver` prompt never moves the wheel and that an unsent prompt the hook filed `human` moves it before its line is appended. The widened claim therefore covers the in-flight send's own prompt only; every other `human` prompt still moves the wheel. The same entry requires the running turn to be marked by the line's kind alone, the claimed driver prompt included, so the confirmed newline send still marks its turn.
- **Agent isolation.** architecture §Established Decisions → [Agent Coverage] requires Claude-specific shapes to live only in `viola-agent-claude`, and architecture §Infrastructure Patterns → Crate dependency direction requires the root bin's pump, wheel and send path to consume only normalised events. "The CLI drops a pasted text's last newline" is a Claude behaviour: a remedy sited in `src/run/send.rs` must take that knowledge from `viola-agent-claude`, not state it in the root bin or in `viola-core`. Scope item 11 (no fix inside `hook.rs`) does not lift this: the hook cannot see the sent text, but the rule can still be defined in that crate and consumed by the wrapper. Placement is the P4 card's.
- **Ledger rule.** architecture §Cross-cutting Patterns → Capability ledger as the single gate requires any new dependence on an undocumented `claude` behaviour to be a ledger row with a `viola verify` probe and never an unconditional assumption. It holds one ruled limit only: a shape no `send` relies on needs no probe. The plan defines no "tolerates, does not rely on" class, so a remedy that claims to need no row for the drop is not derivable from the plan: it is a ruling for the P4 card (the founder's, answered provisionally by the operator per inputs#I1), not a reading.
- **Cost of a new row.** architecture §Established Decisions → [CLI Version Compatibility] fixes the ledger as a closed seventeen-row set gating `cli_verified`, and states that a further row needs its probe and a re-stamp of every stamped version, a verify being five `claude` starts. A remedy that needs an eighteenth row cannot land inside this chunk's zero live starts; P4 says so rather than landing an unprobed row.
- **Refusal and text surface.** architecture §Conventions → Error handling schema fixes `not-delivered`'s `detail` values as a closed set extended only in `viola-core`, fixes the `send` refusal order, and lets LF through `validate_paste_text`. A remedy that refuses a newline-ending text needs a `detail` from that set (a new one is a `viola-core` change plus a place in the order); a remedy that removes the newline before the paste changes what architecture §Standard Contracts → Event `data` per kind calls `text`, "the submitted prompt as it was sent". Both are contract changes the P4 card must show, not implementation details.
- **CI shape for the folded red.** architecture §Infrastructure Patterns → CI/CD approach fixes the `test` job as one harness `run --coverage` through the OS's shim followed by an `if: always()` `Gate verdict` requiring `coverage,doctest,playwright`, and names CI's run on the pushed sha as the verdict of record. architecture §Stack and Technologies (Code quality row) pins cargo-llvm-cov 0.9.1 with `llvm-tools-preview`. The plan holds no rule on a corrupt profile or on the profile merge: the cause and its witness are outside arch's coverage (tests and obs own the coverage suite and the gate). `target/llvm-cov-target/` is not a registered path in architecture §Occupied Resources → Repository; if the fix or its evidence depends on that directory, it is an entry for the wrap to record.

## Patterns to follow
- **Claude knowledge compiled in the agent crate, consumed by `send`.** The local-command list is the precedent: a compiled item in `viola_agent_claude::ledger`, read by `src/run/send.rs` by exact equality, with the verified bit handed to `SendSlot::new` and no stamps read on the send path (architecture §Established Decisions → [Delivery Confirmation]). A newline rule the wrapper applies follows the same shape.
- **Claim, append, then settle.** The prompt line is appended with `origin:"driver"` before the send settles, so `prompt-submitted` precedes `send-confirmed` in `events.ndjson`, and the `ok` payload is `{submitted_at, cursor}` (architecture §Standard Contracts → Channel methods, `send` and `hook.event`).
- **Nothing wider than the measurement.** The long-paste unwrap removes exactly the measured frame and keeps everything else byte for byte (architecture §Established Decisions → [CLI Version Compatibility], the long-paste wrapper row). The newline remedy covers the one measured shape; more than one trailing newline and a text of only newlines stay stated as unmeasured, with what the build does for each said plainly (scope item 13).
- **Module placement.** The slot, the driver relabel and the post-condition claim sit in `src/run/send.rs`; hook normalisation sits in `viola-agent-claude`'s `hook` module (architecture §Infrastructure Patterns → Project directory structure).
- **Tests against the fake agent, one home each.** The fake agent is named after `--`, each test has its own `--home` (architecture §Established Decisions → [CI/CD]). `fixtures/claude/<cli-version>/` is written only by `viola verify --record`; committed synthetic turn scripts live in `fixtures/fake-scripts/` under `schemas/fake-script.v1.json` (architecture §Occupied Resources → Repository). Whether the fake agent can reproduce the drop from what is committed is research's question (scope items 5 and 9).

## Anti-patterns to avoid
- A general trim, a whitespace-insensitive compare or a prefix match in the claim: architecture §Established Decisions → [Delivery Confirmation] requires exact matching, and a loose match would relabel a human's prompt as the driver's against architecture §Established Decisions → [Human Takeover / Wheel].
- Hard-coding the newline drop in the root bin or `viola-core` as an unconditional assumption about the CLI (architecture §Cross-cutting Patterns → Capability ledger as the single gate; architecture §Inherited Defaults, Agent isolation).
- A blind re-send or a second paste to reach confirmation: architecture §Cross-cutting Patterns → Fail open toward the human requires an unconfirmed delivery to be reported, never retried blindly. For the red, likewise no new variable, flag or config key to steer the coverage run (architecture §Cross-cutting Patterns → Config management).
