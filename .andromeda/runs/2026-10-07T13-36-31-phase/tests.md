## Constraints
- Tier is Comprehensive (per test-plan §1 Test Scope Summary): the remedy needs a unit case, a cross-process case and a negative control, not one of the three.
- The matcher case is a root-bin unit case: test-plan §4 What unit tests cover → root bin (the send-confirmation matcher bullet) requires the matcher and its window expiry to be held at unit tier, and test-plan §11 Test Strategy bans asserting at E2E a case a lower layer can hold. That bullet states the match as text equality; a remedy that sits in the wrapper changes what the bullet must say, which is the wrap's amendment, not phase's. Whether today's unit cases already pin a text ending in a newline as unclaimed is research's question.
- The cross-process outcome follows test-plan §6 Scenario: Path 2 — verdicts are the CLI exit and `--json` document, the `events.ndjson` records after the pre-send offset and the fake-agent receipt; the wheel half (no `wheel` record, a following `send` not refused `human-typing`) reads the same record kinds test-plan §6 Scenario: Path 5 asserts. Per test-plan §6 Scenario: Path 2 "As landed", the home of these cases is `tests/cli_send.rs`, on all three CI OSes.
- The fake agent may not invent the drop: test-plan §7 Fake agent (the paste bullet and the Modes bullet) requires a pasted text to fire UserPromptSubmit with that text, lets only `--framing` replay a recorded `paste-<n>` variant with its bytes unchanged, takes test-only switches as argv options and never env, and states that no shape is invented before a recorded fixture. test-plan §7 Seed strategies (Recorded hook payloads row) requires such payloads to come from a live `viola verify` recording. With zero live starts no variant can be recorded, so whether a committed `2.1.287` framing variant already carries a prompt one newline short of its compiled paste text, and whether a new fake-agent switch for the drop is an invented shape under that rule, are research's questions and P4's card.
- A green fake-agent case is a floor, not the live proof: test-plan §11 Test Strategy requires a behaviour change against the real CLI to be backed by a local `viola verify` fixture refresh plus the contract suite, and bans the real CLI in CI. The plan must therefore name what stays unmeasured and carry it to `working-route.md:102`, as test-plan §6 Scenario: Path 2 already does for `/clear`.
- Time: test-plan §11 Universal lets an E2E case block on the product's send confirmation window only when the verdict is the product's own exit code and the same deadline is clock-driven in a §4 unit case; a remove-the-remedy control that reads exit 13 falls under it. No test-owned sleep or elapsed-time verdict (test-plan §11 E2E).
- The folded red is governed by test-plan §10 Zero-flakiness budget (a red is fixed at its root cause inside the chunk; no retry, no `#[ignore]` parking) and test-plan §10 Coverage thresholds → Stack adjustments (child `viola` processes write profiles because `LLVM_PROFILE_FILE` propagates; an earlier corrupt-header merge failure on the ubuntu leg is "recorded, not established"). test-plan §7 Fake agent (the exit bullet) requires the fake agent to wait for a running hook before it exits, the one measured cause of a truncated hook profile. Whether this red is that path, another kill path (test-plan §5 Setup / teardown lifecycle requires wrappers to be killed then waited by a `Drop` guard) or a writer outside the repository is research's question, closed against the run's own artifacts.

## Patterns to follow
- Root E2E boot chain `home → fake_agent_path → stamped_home → booted_wrapper`, a fresh home per test under `target/e2e-home`, the wrapper in a kill-then-wait `Drop` guard (per test-plan §3 `run` step 2; test-plan §5 Setup / teardown lifecycle).
- Naming and tables: `<subject>_<condition>_<expected>` function names and rstest `#[case::label]` tables with readable labels for the matcher cases (per test-plan §4 Conventions; test-plan §2 Test function naming).
- Literal oracles: the expected prompt text, origin, exit code and refusal strings are written as literals in the test, as the two live-shape newline cases in `viola-agent-claude` already are (per test-plan §4 What unit tests cover → viola-agent-claude, the `prompt-submitted` normalisation bullet; test-plan §11 Unit). Those two cases stay as they are if the remedy sits in the wrapper.
- A guard's proof is its unit cases plus a remove-the-guard control, with the end-to-end case stated as a floor where it cannot isolate the guard (per test-plan §6 Scenario: Path 2, the `local` verification bullet's closing sentences). The chunk's "control that fails when the remedy is removed" takes this shape.
- Every send text a test feeds embeds the tests-owned content canary, and the after-test sanitization and secret scan run over the home (per test-plan §6 Non-path suites → Error sanitization and secret scan).

## Anti-patterns to avoid
- NEVER treat the green fake-agent case as proof the real CLI's newline drop is handled, and never hand-build a hook payload or fixture to stand in for a recording (per test-plan §11 Test Strategy; test-plan §11 Test Data).
- NEVER close the coverage red by a retry, a re-run, a skipped gate, a merge that tolerates the corrupt profile or a widened `--ignore-filename-regex` (per test-plan §11 Quality; test-plan §11 CI; test-plan §10 Zero-flakiness budget).
- NEVER synchronise with `sleep`, parse the child's rendered screen for the verdict, or call `.env_clear()` on a child without re-adding `LLVM_PROFILE_FILE` (per test-plan §11 E2E; test-plan §11 Integration) — the last one bears on the folded red as well as on new tests.
