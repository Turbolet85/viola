## Relevance
relevant — the remedy sits on `send`'s paste-text boundary and on delivery confirmation, the one post-hoc check the plan names for sent text; two of the three remedy shapes meet a written rule of the plan; the folded red touches the CI gate and upload chain.

## Constraints
- **A trailing newline is allowed input.** security-plan §Input Validation (Paste text row) requires LF, CR and TAB to pass, and §Security Anti-Patterns → Input bans refusing them. Remedy shape 3 (refuse a text ending in a newline) refuses a text for an allowed character: it is not a choice the card can take silently. It needs the plan's row amended first, which is the founder's and is held, not answered (scope §Authority).
- **Reject, never strip; validation first and authoritative.** security-plan §Input Validation (Paste text row) requires `validate_paste_text` to run client-side before any frame and again in the wrapper's `send`, first in its refusal order, before anything is typed, and gives the exact match of delivery confirmation as the reason nothing is stripped. Shape 2 (drop the last newline before the paste) changes the bytes typed, and shape 1 (accept the prompt less its last newline) changes the comparison that row leans on. Either way the validator must still see the text as received, and the row's "exact match" sentence becomes the wrap's to amend. Whether the code today validates before any other handling of the text is research's question.
- **The comparison is the only post-hoc check on sent text.** security-plan §Threat Model Summary (Attack surface, CLI input vector) names delivery confirmation as the one check after the paste. The plan states no rule for a non-exact match, so a relaxation the remedy adds must be the single covered case (the last newline) and nothing wider: no trim, no prefix match, no normalisation. The unmeasured shapes of scope item 13 get a stated behaviour, not a silent pass through the relaxed arm.
- **`origin` and the wheel stay closed, and `driver` is the wrapper's own label.** security-plan §Input Validation (Channel frames row, `hook.event` re-validation) requires a `prompt-submitted` frame's `origin` to be `harness` or `human` only, an invalid event not appended. §Security Anti-Patterns → Authentication bans treating `from` as identity, and §Security Anti-Patterns → Input bans a free-string wheel holder. The `driver` relabel must come only from the wrapper's in-flight claim, never from a field of the frame. Whether the wrapper refuses a wire `origin:"driver"` today is research's question.
- **The human is never blocked.** security-plan §Security Anti-Patterns → Universal requires refusals to reach automation only. A wider claim files as the driver's a prompt that would otherwise have moved the wheel to the human. The plan requires that this never delays, refuses or swallows a human keystroke; whether a human's own prompt can fall inside the relaxed claim during the in-flight window is P4's question on the card.
- **No new seam, flag, key or stamp.** security-plan §Security Anti-Patterns → Universal bans any `config.json` key, `VIOLA_*` variable or CLI flag that switches off `validate_paste_text`, bans a third test seam without its own Decisions Log entry, and lets only `viola verify` write `ledger/stamps.json`. A fake-agent reproduction of the newline drop (scope item 5) must ride committed scripts and the `fake-agent` feature already there. A remedy that needs an eighteenth gating row cannot be stamped by hand or by a test helper, and the plan's seventeen-row count would then be the wrap's to amend.
- **The folded red closes inside the existing CI controls.** security-plan §Bootstrap phases (`secret-scanning-ci-gate`) requires every scan-gated upload to wait for `secret-scan`, which reads `target/agent-run/` only, and lists exactly one unscanned upload. security-plan §Dependency Security (CI integration) requires SHA-pinned actions, `permissions: {}` with job `contents: read`, event values only through `env:`, and a Decisions Log entry for any further G2 exemption. A fix that uploads `target/llvm-cov-target/` profiles, adds a step input or exempts a panic line is a widening and is held. security-plan §Error Handling (Internal logging) requires `viola hook` to exit 0 with an empty stderr on every path, so a fix in a hook's exit or kill path keeps that.

## Patterns to follow
- One shared validator in `viola-core`, called by the CLI and re-run by the wrapper; a client check is advisory (security-plan §Input Validation, Boundary paragraph). A new rule about the last newline that both sides apply belongs in that one place.
- A `send` outcome is a closed `refusal` / `detail` pair in `result.refusal`; protocol faults are fixed JSON-RPC errors with `data: null` (security-plan §Error Handling, Error format). The confirmed outcome and any new refusal detail carry codes only.
- Prompt classification reads the prompt's raw start with no trim, against compiled literals (security-plan §Security Anti-Patterns → Code Patterns). The remedy touches the end of the text only and leaves the start matching as it is.
- Prompt text outside the contract payloads goes only to `instances/<name>/diagnostics/` (security-plan §Bootstrap phases, `logging-redaction-wire`). A new line that records the relaxed claim carries a code or a length, never the text.
- Fixtures under `fixtures/claude/<cli-version>/` come from `viola verify --record`, synthetic and scrubbed (security-plan §Data Protection, Repository fixtures). With zero live starts none is recorded; test texts for the newline cases are synthetic literals.

## Anti-patterns to avoid
- Stripping a character from `send.text` silently, or refusing LF, CR or TAB (security-plan §Security Anti-Patterns → Input).
- Adding an environment seam, flag or config key for the fake agent's newline drop or for the coverage fix, or writing `ledger/stamps.json` from anything but `viola verify` (security-plan §Security Anti-Patterns → Universal).
- Committing a fixture or test text copied from the earlier chunk's live evidence where it holds real prompt content, a home path or a username (security-plan §Security Anti-Patterns → Data Protection).
