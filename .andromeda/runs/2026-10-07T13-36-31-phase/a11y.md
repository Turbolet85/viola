## Relevance
partial — no web-spa markup, role, focus, contrast or motion work; the chunk moves the outcome of CLI `viola send` (path P2's cli mirror) and the wheel record behind path P4, both carried by a11y-plan as output-discipline and boundary assertions with no conformance claim.

## Constraints
- a11y-plan §1 A11y Scope Summary (A11y tier) sets tier Standard for web-spa only; cli and tui get output-discipline and boundary assertions and no WCAG conformance claim. Nothing this chunk builds may be reported as WCAG evidence.
- a11y-plan §4 ARIA Patterns & Roles (P2, cli line) requires the CLI `send` outcome to be the readback mirror on a confirmed send and the refusal layout on a refused one, pinned by trycmd. A delivered send whose text ends in a newline falls under the confirmed arm once the remedy lands; whether the code already prints the mirror for an `ok` result on that path is research's question.
- a11y-plan §8 Cognitive Accessibility (Error recovery, CLI) requires every human-mode refusal to be the plain word, reason and detail on stderr, a `hint:` as the last stderr line, a typed exit code, and one `--json` document with no hint. It binds the P4 card: the remedy shape that refuses a newline-ending text mints a refusal that must take this layout; the two shapes that confirm the send add no refusal text.
- a11y-plan §8 Cognitive Accessibility (Plain language) requires every kebab-case reason/detail code to sit beside the plain word and every fixed CLI string to be pinned by trycmd, so a copy change fails CI until the pin is changed on purpose. A new detail code or hint line is therefore a pinned-copy change, never a side effect. The `input-not-ready` hint wording stays outside this chunk (scope Boundaries).
- a11y-plan §4 ARIA Patterns & Roles (P4) requires the wheel to move for the human and automation to be refused `human-typing` on stderr with a typed exit code. The chunk removes a wheel move no human made; it must not remove one a human did make. Whether a relaxed claim could file a prompt a human typed as the driver's is research's and the P4 card's question.
- a11y-plan §3 Keyboard test harness (Tooling) requires every stdin byte outside the closed non-editing list to take the wheel, human keystrokes during a driver `send` to be delivered unblocked, and zero viola-originated bytes on the outer PTY across a driver send and a refused one. No remedy shape may touch the stdin classifier or print a literal to the terminal under `viola run`.
- a11y-plan §10 SLO Invariants & A11y Budgets (Standard+ invariants) requires the CLI output-discipline invariants (P4, P6) to pass on all three OS legs inside the CI `coverage` suite. The folded red sits in that suite on the ubuntu leg, so on that attempt those invariants carry no verdict; its closure by cause is what restores one.

## Patterns to follow
- Refusal layout by trycmd, typed exit codes and the hint-free `--json` document by assert_cmd, on all three OS legs (per a11y-plan §8 Cognitive Accessibility, Error recovery → Verification).
- The wheel read through an `answer` to no pending dialog, its exit code telling driver from human, with the absence of a `wheel` record asserted beside it (per a11y-plan §3 Keyboard test harness, Tooling). It fits scope item 2's "the wheel still `driver`" reading.
- Sequencing on the wrapper's logged lines and the `wheel` record, never a timer (per a11y-plan §3 Keyboard test harness, Tooling; a11y-plan §10 SLO Invariants & A11y Budgets, Performance budget).
- Where the new cases land: `nextest-integration` / `nextest-e2e` locally, the per-OS `coverage` suite in CI, with no new `suite` value (per a11y-plan §9 CI Integration, Unit / integration row).

## Anti-patterns to avoid
- Never block, refuse or delay a human keystroke in `viola run` past the current atomic paste, and never count the closed non-editing sequences as editing (per a11y-plan §11 A11y Anti-Patterns, Keyboard).
- Never show a refusal without its recovery line, and never a kebab-case code without the plain word beside it (per a11y-plan §11 A11y Anti-Patterns, Cognitive). It applies only if the P4 card picks the refusing shape.
- Never overclaim: the page and its announcements show only what hooks and the wrapper observed (per a11y-plan §11 A11y Anti-Patterns, Universal). A driver's prompt filed `human` puts the word `human` in the WHEEL cell and a refusal in the readback for a send that was delivered; the chunk's event sequence is what the web surface later reads.

## Contract bindings
- **a11y ↔ obs:** the readback state on both surfaces is derived from `send-issued` / `send-confirmed` / `send-refused` joined on `corr` = the send cursor, and `event` is a closed enum (per a11y-plan §1 A11y Scope Summary, Structured violation JSON schema and Critical path 2 → Source). The remedy must leave the confirmed send with that join intact and add no event value without a Decisions Log entry.
- **a11y ↔ tests:** a11y's P2 and P4 rest on the tests plan's Critical Paths 2 and 5 (per a11y-plan §1 A11y Scope Summary, Critical paths 2 and 4 → Source); the CLI assertions ride the tests' drivers and the harness `run` JSON, not an a11y tool (per a11y-plan §4 ARIA Patterns & Roles, Per-surface a11y testing tool reach).
- **a11y ↔ tests (the folded red):** a `gate --require playwright` breach of kind `suite-missing` or `artifact-missing` is a build failure condition for a11y (per a11y-plan §10 SLO Invariants & A11y Budgets, Build / deploy failure conditions). Attempt 1's gate listed both for `playwright`; why that suite was absent is research's question, and the a11y verdict of that attempt does not exist.
- **a11y ↔ design:** CLI refusal copy and the hint line are design's (per a11y-plan §1 A11y Scope Summary, Critical path 6 → Source). A refusing remedy needs its copy from there before trycmd pins it.
- **a11y ↔ web-spa (cross-surface):** the CLI readback mirror corresponds to the web `data-rb="read"` state, and the readback word is one word across tape line and transfer marker (per a11y-plan §8 Cognitive Accessibility, Consistency and predictability). The chunk adds no web state and no axe state to the §10 list.
