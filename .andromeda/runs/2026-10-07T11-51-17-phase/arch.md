## Relevance
relevant — the chunk builds a ruling architecture.md already records as "decided, not built" (§Established Decisions [CLI Version Compatibility]); its two code sites, its ledger row, its refusal vocabulary and its test-only flag are all arch-owned.

## Constraints
- **Crate placement.** architecture.md §Established Decisions [Screen Model] requires the readiness verdict to be the pure `viola_agent_claude::screen::Screen` (no I/O, no clock read, every instant a parameter) and requires `QUIET_PERIOD` and `GATE_MAX_WAIT` to be compiled built-ins of `viola-agent-claude`; §Infrastructure Patterns → Crate dependency direction places the `screen` module's verdict, `Signatures` and "the compiled gate constants" in that crate and the feed/`Gate` in the root bin. The new "keep waiting" arm and the moved bound belong in `screen`; `src/run/gate.rs` stays the consumer. Whether the waiting can be expressed inside the pure verdict (an instant parameter) with no change to `Gate::wait_ready`'s shape is research's question.
- **Verified-only, and the partial gate untouched.** architecture.md §Established Decisions [Screen Model] requires `run` to hand `Some(&SIGNATURES)` to the gate exactly when its version gate read `cli_verified`, and requires `Screen::verdict(None, …)` to keep its three outcomes (poisoned refuses, not quiet within the maximum wait refuses, quiet is ready with no row read); §Design Philosophy ("Measured, never assumed") states the same split. The ruling the chunk builds is scoped to the verified branch by §Established Decisions [CLI Version Compatibility] ("on a verified CLI the gate waits for the input box on a quiet screen with no literal, and the bound rises to 8.5 s").
- **What still refuses at once.** architecture.md §Established Decisions [Screen Model] requires a poisoned model to read `input-not-ready` and requires readiness to mean an input-box literal on some row and no modal literal on any row; on any failed check the wrapper types nothing. The chunk's waiting arm covers only the quiet screen with NO compiled literal; a modal literal and a poisoned model are not waited on.
- **Closed refusal vocabulary and order.** architecture.md §Conventions → Error handling schema fixes `not-delivered`'s detail set (extended only in `viola-core`), the `send` refusal order (control-character, `human-typing`, `budget-paused`, `turn-running`, then the gate's `input-not-ready`, then confirmation) and CLI exit `13` for `not-delivered`. The bound-expiry outcome reuses `not-delivered` / `input-not-ready`; the chunk adds no reason, no detail, no exit code and no normalised event kind (§Conventions → Naming patterns: new kinds only in `viola-core`).
- **The human always wins.** architecture.md §Design Philosophy ("The human always wins the wheel") requires that no human keystroke is delayed past the current atomic paste; §Established Decisions [Screen Model] requires the passthrough never to wait on the model (the tee offers a copy with `try_send`); §Established Decisions [Human Takeover / Wheel] requires any editing key to move the wheel and holds human bytes only during the one bracketed-paste write. A gate wait lengthened to 8.5 s must stay entirely on the automation side of those three.
- **`send`'s blocking bound is derived, not a second constant.** architecture.md §Established Decisions [Delivery Confirmation] requires `send` to block at most the gate's maximum wait plus the atomic paste plus the confirmation window (`CONFIRM_WINDOW_FALLBACK` = 10 s, compiled, never in `config.json`) and to return no later than the window's close; it also requires the MCP-surface total to stay below the client's tool-call timeout, which §Established Decisions [MCP] leaves an open item. The plan names no client read deadline on the `send` frame; whether any code bound was sized against the old 15 s total is research's question.
- **The ledger stays seventeen rows, and the stamp has one writer.** architecture.md §Established Decisions [CLI Version Compatibility] makes the ledger a closed seventeen-row set and makes the `quiet-period` row the per-version validation of the two gate constants (ready and turn screens settle within `GATE_MAX_WAIT`); §Cross-cutting Patterns ("Capability ledger as the single gate for CLI-specific behaviour") requires any NEW dependence on an undocumented CLI behaviour to be a row with a probe; §Standard Contracts → Ledger stamps envelope and §Occupied Resources (`ledger/stamps.json`) require the file to be written only by `viola verify` through `viola_state::stamps::update_stamps`, with `run` reading no `measured` field. The chunk moves a constant an existing row is checked against and reads no new CLI shape (the hint's text is not read), so it lands no row and re-stamps through `verify` only.

## Patterns to follow
- **Instants as parameters, polled by the `Gate`.** architecture.md §Established Decisions [Screen Model]: the `Screen` sits behind one mutex shared by the feed thread and the `Gate` handle, `Gate::wait_ready` re-reads it every 20 ms, and the model reads no clock. The 8.5 s bound is counted by the caller that already owns the wait, not by a new timer thread.
- **The precedent for "a quiet literal-less screen keeps waiting".** architecture.md §Established Decisions [CLI Version Compatibility] describes `viola verify`'s `Run::box_wait`: it ends only on a `QUIET_PERIOD`-quiet screen holding a compiled literal, on a poisoned screen, or at its deadline. That is the same three-way exit the chunk gives the verified run gate, with `GATE_MAX_WAIT` in the deadline's place. Whether the two can share one verdict path is research's question.
- **`verify`'s ordinary settle reads the same constant.** architecture.md §Established Decisions [CLI Version Compatibility] requires each probe screen to settle at the first quiet instant holding a compiled literal, "else at the first quiet instant past `GATE_MAX_WAIT`", every wait bounded by `PROBE_DEADLINE`. Moving the constant moves that fallback settle in Runs A to D and in CI's fake-agent `verify` runs; the stamp's `measured.typed_probe` settle times (§Standard Contracts → Ledger stamps envelope) are what the `quiet-period` row then compares against the new bound.
- **Holding the window open in tests.** architecture.md §Occupied Resources → Binary, subcommands and exit codes defines the fake agent's test-only hold `--paste-hint-ms` (capped at 8 000 ms; with `--framing`, `Screen.turn` is drawn only after the hold) among eight argv options and no env. A hold that outlasts the bound is an argv change to that option or a further argv option, recorded in that row at the wrap.
- **A verified CLI under test.** architecture.md §Cross-cutting Patterns → Config management (Viola home) makes the per-test `--home` the isolation point whose `ledger/stamps.json` can stamp the fake agent's reported version; that is how a test reaches the verified branch.

## Anti-patterns to avoid
- **No knob.** A gate bound, a per-instance override or a "wait out the hint" switch in `config.json`, a `VIOLA_*` variable or a CLI flag is banned: architecture.md §Established Decisions [Screen Model] makes the two values compiled built-ins, and §Cross-cutting Patterns → Config management states environment variables are not a configuration channel (a new test seam read from the environment needs a Decisions Log entry per §Conventions → Naming patterns, Environment variables).
- **No reading the hint.** Matching `paste again to expand`, or any other new screen literal, as an unconditional assumption is banned by architecture.md §Cross-cutting Patterns ("Capability ledger as the single gate for CLI-specific behaviour"): a new compiled literal is an eighteenth row, a probe and a re-stamp of every stamped version (§Established Decisions [CLI Version Compatibility]).
- **No queueing and no runtime.** A send that outlives its gate wait is refused, never parked: architecture.md §Established Decisions [Human Takeover / Wheel] forbids queueing a `send`; §Cross-cutting Patterns ("Tokio containment") requires new code on the `run` / `send` paths to use std threads and blocking I/O.

## Contract bindings
- **arch ↔ tests.** The fake agent's `--paste-hint-ms` cap and its `--framing` replay are an arch-registered resource (§Occupied Resources → Binary, subcommands and exit codes) that test-plan's cases consume; CI runs `verify` against the fake agent's interactive modes (§Established Decisions [CLI Version Compatibility]), so the moved constant reaches CI through `verify`'s settle as well as through `send`. The committed `2.1.287` fixture set is stamped at seventeen rows by `contract_ledger_probes` (§Occupied Resources → Repository); whether its recorded settle readings sit inside the row's check under the new bound is research's question.
- **arch ↔ security.** The one live re-verify runs inside the ratified typed-input probe (§Established Decisions [CLI Version Compatibility]: four interactive runs, compiled pastes only, no byte into a dialog); `stamps.json` keeps its single writer and its strict-modes reader (§Occupied Resources, `ledger/stamps.json`).
- **arch ↔ a11y / design.** The keystroke guarantee (§Design Philosophy) is the arch side of a11y-plan's keystroke clause. §Established Decisions [CLI Version Compatibility] records that the `input-not-ready` hint line's advice "does not lead out of" the hint window; the line's wording is design-system / layout-templates content, not arch.
- **arch ↔ MCP surface.** §Established Decisions [Delivery Confirmation] ties `send`'s total to the MCP client's tool-call timeout; the total grows by 3.5 s while §Established Decisions [MCP] still holds that timeout open. The chunk does not settle it; the wrap carries the new total.
- **A residual that widens.** §Established Decisions [Human Takeover / Wheel] records an accepted residual: a turn that starts during the gate's wait "up to `GATE_MAX_WAIT`, 5 s" is not refused `turn-running`. The moved bound widens that window to 8.5 s; whether that needs a word from the overseer is P4's.
- **Plan sites the wrap must amend** (the plan still states the pre-chunk values; scope.md names only the first two): §Established Decisions [Screen Model] (`GATE_MAX_WAIT` = 5 s; "ready when" wording; the not-quiet refusal sentence) · §Established Decisions [CLI Version Compatibility] ("It is not built: the gate, `GATE_MAX_WAIT`, the hint line and the fake agent's 8 000 ms hold cap stay as they are"; "The readiness gate of `viola run` is unchanged by this"; the `send`-under-the-hint outcome) · §Established Decisions [Human Takeover / Wheel] ("`GATE_MAX_WAIT`, 5 s") · §Design Philosophy ("Measured, never assumed", the verified build's gate clause) · §Occupied Resources → Binary, subcommands and exit codes (the `--paste-hint-ms` cap, if raised).
