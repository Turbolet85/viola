# layouts extract

## Relevance
partial — the chunk renders in the `cli` surface only (`viola send`'s readback mirror, its `input-not-ready` refusal and hint line, and `viola verify`'s step output for the one re-verify round); it creates no region, column, state word or focusable element, and the `web-spa` surface is read here, not changed.

## Constraints
- A confirmed send has one outcome shape whatever the gate waited: layout-templates §Surface: cli (Signature placement) requires the filled-box outcome line on stdout with exit 0 for a confirmed send, so a send delivered after the paste hint clears takes that line and no other. The scope's item 3 adds no "waited" variant, and the plan defines none.
- The refusal at the bound keeps the struck mirror: layout-templates §Output structure — `viola send` requires the struck-box `unable` line on stderr with `not-delivered` then `input-not-ready` as its two outcome fields, exit 13, with `unable` padded into the mirror's word column (scope items 1 and 4: modal, poisoned, never-quiet and bound-run-out all end on this one line).
- The hint line is keyed, single and last: layout-templates §Component — Primary content block 2: refusal lines and the `unable` column requires `hint: <one plain instruction>` directly under the refusal, keyed by reason (or reason and detail). One key therefore serves every cause that still prints `input-not-ready` after this build, so any changed wording (scope item 7) has to read true for a modal, a screen that never goes quiet, a poisoned screen and a hint that outlasts the bound alike.
- A hint points to a verb and to nothing upstream: layout-templates §Component — Primary navigation (verb structure) requires hint lines to name the next verb and forbids any hint naming `viola release`; layout-templates §Component — Primary content block 2: refusal lines and the `unable` column requires that a hint never quotes the sent text or any upstream text and never names a path or a pid. The CLI's own paste-hint wording is upstream screen text under that clause.
- The longer block is silent: layout-templates §Output structure — `viola send` requires lines to be appended and never redrawn, with the TTY-only issue line printed when the request goes to the wrapper and the outcome printed under it; layout-templates §Surface: cli (Expression level) allows no cursor control. Up to 18.5 s (scope item 9) therefore passes with the issue line standing and nothing else printed. Whether the code prints the issue line before the gate's wait starts is research's question.
- The machine view is unchanged in shape: layout-templates §Component — Hero / signature output line (Machine view) requires `--json` to print only the typed document with the typed exit code, no glyph and no hint; layout-templates §Component — Primary content block 2: refusal lines and the `unable` column (Exit codes) requires no stderr line under `--json`. A reworded hint never reaches the `--json` path.
- The re-verify prints the standing step format: layout-templates §Output structure — `viola verify` requires one appended stdout step line per ledger row in ledger order, a count of 17 today, the `stamped <ver>  <n> pass  <m> fail` summary as the last stdout line, exit 0 only when every row passes, plain ASCII and no redraw. The scope adds no row, so the denominator stays 17 and `quiet-period` keeps its place in the order.

## Patterns to follow
- The two-line mirror read as one strip entry: issue line open, outcome line closed, column for column (per layout-templates §Component — Hero / signature output line, Layout and Issue left / readback right).
- The refusal pair: `unable` line, then its `hint:` line as the last line on stderr (per layout-templates §Component — Footer / terminator).
- Stream split: results on stdout; the issue line, refusals and hints on stderr, never mixed (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column, Streams).
- The printed example for this refusal is the layout's reference text for the `input-not-ready` pair (per layout-templates §Output structure — `viola send`, its second example). Whether the product's string equals it today, and which tests pin it, is research's question; the master's text itself is amended only by the wrap.
- Output as a contract: human words and columns are stable because drivers read them, and a new field goes into `--json` first (per layout-templates §IA notes under Surface: cli). A changed hint string is a change to text a driver reads as its last stderr line.

## Anti-patterns to avoid
- No progress cue for the gate's wait: no spinner, no elapsed counter, no `Sending…`, no tick or `done` word (per layout-templates §Component — Hero / signature output line, What never happens). The `waiting:` line belongs to `viola wait` alone (per layout-templates §Output structure — `viola wait` / `viola last`), so `send` does not borrow it.
- No new state word, box state, column or human field to say a send waited out the hint (per layout-templates §IA notes under Surface: cli, Output as a contract; the four mirror words are closed per layout-templates §Component — Hero / signature output line, Layout).
- No hint that quotes the CLI's screen text, names a path or pid, or names `viola release` (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column, Hint line; layout-templates §Component — Primary navigation (verb structure), Discoverability).

The `input-not-ready` line stands in both masters (scope item 7 names both sites), so a changed product string lands in both at the wrap or in neither.

The chunk keeps `not-delivered` / `input-not-ready` and needs no new detail code.
- layouts ↔ security: the no-upstream-text, no-path, no-pid rule on hints (layout-templates §Component — Primary content block 2: refusal lines and the `unable` column) is the layout face of the security plan's error-sanitisation floor.
- layouts ↔ tests: the end-to-end cases the scope turns (`hint` from refused to delivered, plus the outlasting case) observe exactly the lines and streams fixed by layout-templates §Output structure — `viola send`; the fake agent's hold and the harness timeouts are the test plan's.

The chunk changes no box state and no announcement text; an `open` box may stand for the longer wait, drawn as today. Whether `send-issued` is emitted before the gate's wait is research's question.

## Acceptance criteria contributions
- (layouts) On a verified CLI a `send` issued while the paste hint stands ends with exactly one filled-box `read back` outcome line on stdout (name, time, `cursor <n>`), exit 0, and no `unable` or `hint:` line on stderr (per layout-templates §Output structure — `viola send`).
- (layouts) A screen that stays quiet and literal-less past the bound ends with the struck-box `unable  <name>  not-delivered  input-not-ready` line on stderr, exit 13, and its `hint:` line as the last stderr line; under `--json` the same outcome is one document on stdout and nothing on stderr (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column).
- (layouts) Between the issue line and the outcome line `send` writes nothing to either stream: no spinner, no elapsed counter, no redraw, no cursor control, for the whole of the gate's wait (per layout-templates §Component — Hero / signature output line).
- (layouts) If the `input-not-ready` hint string changes, the new line is one `hint:` line that names a verb by name, never names `viola release`, and quotes no upstream text, path or pid (per layout-templates §Component — Primary navigation (verb structure)).
