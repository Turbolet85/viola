## Constraints
- Layer placement: test-plan §11 Test Anti-Patterns → Test Strategy requires parser, refusal-order, threshold and clock cases at the unit layer and only cross-process behaviour at §6. The verdict arm (quiet, literal-less screen keeps waiting on a verified CLI; modal and poisoned refuse at once; unverified unchanged) and the bound's boundary belong to `Screen::verdict` and `gate.rs` unit cases; the `cli_send` pair is the one cross-process witness (per test-plan §4 Unit Test Strategy → viola-agent-claude, the Screen signatures bullet).
- Verdict surface: test-plan §4 Unit Test Strategy → viola-agent-claude requires the readiness-gate verdict to be evaluated over fed vt100 bytes against the compiled `SIGNATURES` literals only, the full gate only on a verified CLI, and content beyond the compiled literals never asserted. The paste hint's own text is therefore no oracle in any case of this chunk; a hint window is expressed as "no compiled literal on a quiet screen".
- Real time: test-plan §11 Test Anti-Patterns → Universal bans a test-owned timer, sleep or elapsed-time verdict, and lets E2E block on a product deadline it cannot inject only when the verdict is the product's own exit code or status field AND the same deadline is clock-driven in a §4 unit case. "Within 8.5 s" and "refused at the bound" are therefore never a test-side stopwatch reading. The clause names three deadlines (the send confirmation window, `wait --timeout-ms`, heartbeat staleness); the gate bound is not among them, so an E2E case that blocks to `GATE_MAX_WAIT` (scope item 4) either stays at unit level or needs that list amended at the wrap — a P4 fork. Whether `gate.rs`'s cases already drive the gate's wait through the injected `viola_core::Clock` is research's question.
- Kill lines: test-plan §3 `run` (step 2, the `booted_wrapper` wait) requires every root wait on a child bounded at 7 s (`WITHIN`), strictly below the nextest `mutants` profile's 10 s kill and below cargo-mutants' 20 s auto-timeout floor, so a stuck wait fails the test itself and a mutant grades caught, not Timeout. A case that blocks through an 8.5 s gate, or through `send`'s 18.5 s longest block, sits against that 10 s line. Whether the `mutants` profile (or `[profile.ci]`) carries a per-test override for the existing hold cases, and what the new cases need, is research's question; no bound in the plan is stated as raisable.
- Mutation and flake budget: test-plan §10 Quality Gates & Coverage Targets → Mutation gate requires `missed == 0`, `timeout == 0` and `unviable <= caught` at the epoch boundary (no per-chunk gate), with `[profile.ci]`'s 120 s kill and `retries = 0` unchanged; test-plan §10 → Zero-flakiness budget allows no retry, `#[ignore]` or skip as a parking place. The new waiting arm and the moved constant must be killed by `viola-agent-claude`'s and the root bin's own unit cases (per test-plan §3 `run` step 4 Test scope), and a long-blocking case must not become a boundary-audit Timeout.
- Fake agent contract: test-plan §7 Test Data & Fixtures → Fake agent (Modes) states `--paste-hint-ms <ms>` as capped at 8 000 ms, an argv option (no env), active with `--framing`, drawing `Screen.turn` only after the hold. A raised cap or another hold mechanism for scope item 4 changes that binding contract text (the wrap's amendment); any new hold stays an argv option, test-only, with unknown arguments ignored as that section requires.
- Stamps and the live round: test-plan §7 Test Data & Fixtures → Seed strategies requires `ledger/stamps.json` to come only from `viola verify` (against the fake agent in tests), never hand-written; test-plan §11 Test Anti-Patterns → Test Strategy requires the real `claude` to be local-only, never in CI, and a green fake-agent run never to stand as proof of real-CLI behaviour. test-plan §3 `run` (`--local-live`) defines the harness's live form as the program default `claude` with no `--`, home `target/e2e-home/viola-live-<pid>/home`, refusing when `CI` is set. The scope's round names `claude` by path: whether it runs through `--local-live` or as a direct `viola verify -- <path>`, and which home it stamps, is research's question; the plan gives no by-path harness form.

## Anti-patterns to avoid
- NEVER parse the rendered child screen (the vt100 grid, PTY master output) for content in an E2E case; the gate is tested through its refusal outputs, the receipt and `events.ndjson` (per test-plan §11 Test Anti-Patterns → E2E; test-plan §1 Test Scope Summary → Surface: tui).
- NEVER synchronise with `sleep(N)`, a test-owned timer or an elapsed-time verdict, and NEVER use `MockClock` to move a spawned `viola run`'s time; the hold is the fake agent's argv option and the wait is on an explicit signal (per test-plan §11 Test Anti-Patterns → E2E and → Universal).
- NEVER re-run a red for green, add a retry, or read a green fake-agent run as the real CLI's behaviour; a red live round stops and is reported (per test-plan §11 Test Anti-Patterns → Test Strategy and → Quality; test-plan §10 Quality Gates & Coverage Targets → Zero-flakiness budget).
