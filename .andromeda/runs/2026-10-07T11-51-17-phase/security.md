## Constraints
- The longer gate wait (up to 8.5 s) and its refusal are automation-side only: security-plan §Security Anti-Patterns → Universal requires that no refusal ever blocks the human and that refusals go only to `send` / `answer`. Scope item 8's case is the evidence; whether the gate's wait path can hold anything a human keystroke passes through is research's question.
- The wrapper's `send` runs `validate_paste_text` first in its refusal order, before anything is typed, and the paste stays one bracketed write: security-plan §Input Validation (Paste text row) requires it. The gate's longer wait must sit after that check, so a `control-character` refusal never waits on the gate; a refusal at the bound (scope item 4) types nothing. Whether the code already orders it so is research's question.
- The screen model the gate reads is fed only under `catch_unwind`, a poisoned model reads `input-not-ready`, and the tee never blocks the human's passthrough (a full feed queue drops the copy and poisons): security-plan §Input Validation (PTY output bytes row) requires all three, and names one mutex shared by the feed thread and the gate. A gate that now waits for seconds must take that lock per read, never across the wait; whether the code already does is research's question.
- `ledger/stamps.json` is written only by `viola verify`, under its `.lock`, at 0600: security-plan §Data Protection (At rest, code-bearing artefacts) requires it. A stamp holds the seventeen rows and a non-`null` dialog decision flows only when every row passes: security-plan §Security Anti-Patterns → Universal requires it. The moved bound changes what the `quiet-period` row's pass means, so the only path to a fresh stamp is the built binary's own `viola verify`; no test, script or hand edit writes the file, and the row count stays seventeen.
- The one by-path re-verify runs inside the standing interactive-run boundary as written: direct spawns under the R8 strip, fixed size, output through `MAX_FRAME`, compiled pastes only into a settled input box, no byte into any dialog, a modal start killed with no key (security-plan §Threat Model Summary → Attack surface, Child process spawning). Verify's settles read the moved constant (scope items 10, 11); what that does to when a paste is typed is research's question, and those guards hold whatever it finds. A change to them is a new widening, which inputs#I1 holds.
- The round's dirs are 0700 and removed on every exit path, viola writes nothing under `~/.claude`, and the CLI's own Run B / C / D transcripts are the already-accepted residual: security-plan §Data Protection (Interactive probe dirs; Accepted risk, verify's trusted runs). The round starts from a folder trusted in Claude Code with the external-import answer already given, and verify never answers that dialog: security-plan §Data Protection (Dev-host prerequisite).
- The bound is a compiled constant: security-plan §Security Anti-Patterns → Universal bans a `config.json` key, a `VIOLA_*` variable or a CLI flag of `viola` that switches off or widens a control, and bans a further env seam without its own Decisions Log entry. Security-plan §Input Validation (Test seam `FAKE_AGENT_PUMP_DELAY_MS` row) fixes that seam's cap at 5 000 ms, so scope item 5's hold mechanism neither moves that cap nor adds an env var read by `viola`.

## Patterns to follow
- A refusal reaches the caller as a channel `result.refusal` with a closed detail (`not-delivered` / `input-not-ready`), never as free text: security-plan §Error Handling (Error format, Channel).
- Any changed product string for the `input-not-ready` hint line (scope item 7) is a fixed message: no screen row text, no path, no upstream text; full detail only to `instances/<name>/diagnostics/`: security-plan §Error Handling (External responses; Internal logging).
- A poisoning or feed fault is recorded as one codes-only line with no screen text: security-plan §Input Validation (PTY output bytes row). A line added for the gate's wait follows the same shape under the floor of security-plan §Bootstrap phases (`logging-redaction-wire`).
- Verify's existing wait shape (a quiet screen holding a compiled literal, a poisoned screen or the deadline each ends it with no key) is the model for a gate that keeps waiting: security-plan §Threat Model Summary → Attack surface (Child process spawning).
- Test-only behaviour lives behind `cfg(feature = "fake-agent")` and the release build carries `viola` only, judged by `scripts/release-check.sh`: security-plan §Dependency Security (CI integration).

## Anti-patterns to avoid
- NEVER build a screen signature from runtime or upstream text, the hint's own text included; signatures come only from compiled ledger rows: security-plan §Security Anti-Patterns → Code Patterns. The gate waits on the absence of a compiled literal, it does not read the hint.
- NEVER let a moved client read deadline on the `send` frame (scope item 9) change `viola send`'s pre-check or borrow another dated gap; its liveness-only gap stands exactly as dated and no other frame may borrow it: security-plan §Security Anti-Patterns → Authentication.
- NEVER commit a local `--home` test directory, and so nothing of the home the re-verify stamps or of the scratch homes under `target/e2e-home.disk/`: security-plan §Security Anti-Patterns → Secrets.
