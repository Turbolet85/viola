## Carried
- (.andromeda/architecture.md:420) The verification is how this boundary's per-connection proof is built: every client that writes a frame must refuse to treat an endpoint as its instance's wrapper unless that endpoint is held by the same-user process the snapshot records, and how it is enforced per OS stays the security plan's.
  > - **Local endpoint trust boundary.** Any process that can open an instance's endpoint can `send` prompts and `answer` dialogs, including PermissionRequest. v1 trusts every process of the same OS user and no other. Each endpoint, whether a named pipe or a Unix socket file, must not be connectable by another OS user. The security specialist owns how this is enforced per OS and any per-connection proof beyond it.
- (.andromeda/architecture.md:404) Every verified client must find the instance, and so the snapshot whose `pid` / `started_at` it checks, by name and never by the working directory.
  > - **Identity by instance, never by location.** Every hook, MCP call and CLI verb finds its instance through `VIOLA_NAME` (or an explicit `ViolaName` argument), never through the working directory. Two sessions in one folder never share records.
- (.andromeda/architecture.md:405) A failed or mismatched verification in `viola hook` (`hook.event` and `hook.dialog` alike) must end in exit 0 with no body, so the dialog renders for the human.
  > **Fail open toward the human.** Any internal failure in `hook` produces exit 0 with no body, so the dialog renders for the human.
- (.andromeda/architecture.md:406) The snapshot the verification reads is a viola format written by possibly another binary version: its reader must skip unknown fields, and the check must not fail on a newer writer's additive field.
  > **Mixed-version tolerance.** Every channel `params`, event, snapshot and config carries `v`, and channel `params` also carry the sender's `CARGO_PKG_VERSION`. Readers skip unknown kinds and fields and surface the counts.
- (.andromeda/architecture.md:410) The verification added to `hook`, `send` and the other CLI clients must be std-thread, blocking code; only the MCP tools' path, through `viola-mcp`'s runtime, may run it async.
  > - **Tokio containment.** New code on the `run`, `hook`, `send` or channel-server paths uses std threads and blocking I/O. Only `viola-mcp` may build a runtime. CLI `wait` is a blocking read on `viola-channel`'s sync client.
- (.andromeda/architecture.md:412) A mismatch or an unmakeable check must leave `hook`'s stdout and stderr empty and `mcp`'s stdout MCP frames only.
  > `hook` writes only its decision body to stdout and nothing to stderr;
- (.andromeda/architecture.md:412) Any line the verification logs (a mismatch, a check not made) goes to the role's codes-only process log, and anything content-bearing only to the instance's detail file.
  > Every role's codes-only process log goes to its home-level role file under `diagnostics/`: `run-<name>`, `hook-<name>`, `mcp` or `cli-<name>` `.ndjson`. Content-bearing detail belongs only in the instance's `diagnostics/detail-<role>.ndjson`. `mcp` writes only MCP frames to stdout, and its log goes to `diagnostics/mcp.ndjson`; it writes JSON to stderr only when that file cannot be opened. Short-lived CLI verbs may use stderr for their human output.
- (.andromeda/architecture.md:418) The per-OS server-identity reads (Unix socket peer, Windows pipe server process, the macOS euid + dir gap) must each compile and be tested on its own CI runner.
  >   - Every OS-specific branch compiles and is tested on its CI runner.
- (.andromeda/architecture-detail/cross-cutting-patterns.md:9) The snapshot every verifying client reads must be the one under the home `resolve_home` / `canonical_home` resolved, the resolution creating nothing.
  > `resolve_home(flag, name, dir, user_home)` in `src/cmd/mod.rs` resolves `--home` as given, else the `instance_of` home when both `VIOLA_NAME` and `VIOLA_DIR` pass the one shape check (a valid `ViolaName`, an absolute dir ending `instances/<name>`), else `<user home>/.viola`, a failing pair falling through; `resolved_home` reads the two variables and `std::env::home_dir()` once, at every verb arm of `dispatch`; `canonical_home` canonicalises a home that exists (`std::fs::canonicalize`, a Windows `\\?\C:\…` written back as `C:\…`, every other verbatim form kept) and keeps `std::path::absolute`'s spelling for one that does not, creating nothing;
- (.andromeda/architecture-detail/cross-cutting-patterns.md:9) The verification's tests must run each wrapper in its own home, so a test's endpoint and snapshot are never another test's.
  > This is the isolation point for tests: each test runs in its own home, and that home's `ledger/stamps.json` can stamp the fake agent's reported version.
- (.andromeda/architecture-detail/cross-cutting-patterns.md:12) No environment variable may switch the verification off or alter it, and a new dependency or feature brought in for the start-time or peer read (sysinfo, an interprocess feature) must read no environment variable.
  > There are no secrets in v1, and environment variables are not a configuration channel. The `VIOLA_*` variables are wrapper-to-child plumbing set by `viola run` only.
- (.andromeda/architecture-detail/cross-cutting-patterns.md:12) The rule binds a dependency's own environment reads as it binds a direct one.
  > a dependency or feature that reads an environment variable breaks this rule like a direct read does.
