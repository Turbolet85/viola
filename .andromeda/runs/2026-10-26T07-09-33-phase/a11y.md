# a11y extract

## Relevance
partial — only the CLI verbs' refusal output (`send` · `wait` · `last` · `answer` · `pause` · `release` on a verification mismatch) touches an a11y surface; the `viola hook` client and the `viola mcp` tools are not-assertable ipc-internal (per a11y-plan §1 A11y Scope Summary, "Not-assertable"), and the check itself adds no UI.

## Constraints
- a11y-plan §8 Cognitive Accessibility › Error recovery requires every human-mode CLI refusal, the new server-verification mismatch and the "check could not be made" case included, to be `unable  <reason>  <detail>` on stderr with `hint:` as the last stderr line and a typed exit code (the scope infers exit 21); whether the mismatch path reuses the liveness pre-check's existing exit-21 pair or needs a new one is research's question.
- a11y-plan §8 Cognitive Accessibility › Error recovery requires that under `--json` the refusal is one document with no hint text and nothing else (the established exit-21 shape is `{"v":1,"error":"instance-unreachable","detail":null}` with stderr empty, per the same section's verification detail); whether each of the six verbs already gives that document for a mismatch is research's question.
- a11y-plan §8 Cognitive Accessibility › Plain language requires any kebab-case reason/detail code the mismatch prints to sit beside the plain word `unable`, never a bare code, bare status number or stack trace as the only error text.
- a11y-plan §6 Visual Design Verification requires `unable` never to be coloured and no SGR of viola's own under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json`, so a new refusal path writes plain text only.
- a11y-plan §1 A11y Scope Summary (tui surface) requires viola to write zero terminal bytes of its own while the child holds the terminal; the hook client's fail-open on a mismatch (exit 0, nothing on stdout or stderr) must therefore put no byte on the `viola run` terminal.
- a11y-plan §8 Cognitive Accessibility › Timeout extensions requires any time bound the verification adds (a `sysinfo` start-time read, an endpoint pid query) to fall on the client process only, never blocking, refusing or delaying a human key.

## Patterns to follow
- The exit-21 state pairs pinned by literal for `viola list` (`list_refuses_*`, `instance_and_home_state_pairs_are_the_fixed_texts`) and `viola plugin install` (`plugin_install_refuses_a_widened_home`): the model for pinning a new or reused unreachable pair, human and `--json` forms both (per a11y-plan §8 Cognitive Accessibility › Error recovery, its verification detail).
- Every fixed CLI string pinned by trycmd or literal, so a copy change fails CI until updated on purpose (per a11y-plan §8 Cognitive Accessibility › Plain language).
- CLI output-discipline cases are ordinary nextest cases inside the existing suites (CI: the per-OS `test` job's `coverage` suite) on all three OS legs (per a11y-plan §3 CI integration).

## Anti-patterns to avoid
- NEVER show a human-mode CLI refusal without a final `hint:` line (only `unknown`, exit 14, is exempt) (per a11y-plan §11 A11y Anti-Patterns › Cognitive).
- NEVER block, refuse or delay a human keystroke in `viola run` — a security refusal goes to automation only (per a11y-plan §11 A11y Anti-Patterns › Keyboard).
- NEVER add a new `suite` value (such as `a11y`) or a separate driver for these cases (per a11y-plan §11 A11y Anti-Patterns › CI).

## Contract bindings
- a11y CLI refusal layout ↔ design-system cli refusal pattern (the `unable` / `hint:` pair and its fixed copy) (per a11y-plan §8 Cognitive Accessibility › Error recovery).
- a11y output-discipline cases ↔ tests harness: they ride `scripts/agent-run.sh run` and `gate --require coverage,doctest`, results in `suites[].failures[]` (per a11y-plan §3 CI integration).

## Acceptance criteria contributions
- For each of `send`, `wait`, `last`, `answer`, `pause`, `release`, a server-identity mismatch in human mode gives exit 21, stdout empty, stderr an `unable` line with the plain reason/detail and `hint:` last, no SGR; pinned by literal or trycmd (per a11y-plan §8 Cognitive Accessibility › Error recovery).
- The same mismatch under `--json` gives exactly one `{"v":1,"error":"instance-unreachable","detail":null}` document on stdout, stderr empty, no hint text (per a11y-plan §8 Cognitive Accessibility › Error recovery).
- A `viola hook` mismatch under a running `viola run` writes no byte to the outer PTY (exit 0, empty stdout and stderr) (per a11y-plan §1 A11y Scope Summary, tui surface).
- The cases run green on all three OS legs inside the `coverage` suite, no new suite value (per a11y-plan §3 CI integration).
