# a11y extract

## Relevance
partial — the chunk is mostly ledger rows and probes with no web-spa surface; it touches a11y only through the cli output of `viola verify` (more `[NN/NN] … pass|fail` step lines and the summary), the `unverified-cli` state word that every re-gated home shows until it is re-stamped, the statusline bound, and the refusal text a `/compact` send may get.

## Constraints
- a11y-plan §1 A11y Scope Summary (justification) scopes the cli to output discipline plus manual screen-reader passes with no WCAG conformance claim. A row or probe added here makes no a11y conformance claim, and the Standard tier applies to web-spa only.
- a11y-plan §4 Critical Paths P6 requires `viola verify` output to stay linear and static: `[NN/NN] … pass|fail` step lines, no `\r` redraw, cursor-movement or erase sequence, and no SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json`. A larger row count changes both `NN` values, but it must not change this shape. Whether each new row's step line and the summary are pinned today by trycmd / assert_cmd or by a literal is research's question.
- a11y-plan §6 Visual Design Verification › State color tokens (not-color-alone) requires `unable` / `fail` never to be coloured, and every cli state to be carried by its printed word (`unverified-cli` among them). A new row that reads `fail`, or a home pushed back to `cli_verified:false` by the larger `LedgerRow::ALL`, must still show its word with no SGR.
- a11y-plan §4 ARIA Patterns & Roles, P3 (the `unverified-cli` state word in the CLI column, and `viola answer`'s `unverified-cli` refusal text on the CLI) requires that word on both surfaces. This chunk re-gates every stamped home, so that state becomes the common case until the next `viola verify`.
- a11y-plan §8 Cognitive Accessibility › Timeout extensions requires `STATUSLINE_DEADLINE` (5 s, PROVISIONAL) to bound only the user's own command, never a keystroke or the human, with exit 0 and empty stderr in every case. A statusline / `/bin/sh` / `rate_limits` probe or the `budget-paused` gate it underpins must not move that bound onto the human. The same section requires every bound to stay a bound on the driver: a resume child or a compaction turn inside `viola verify` must not either.
- a11y-plan §8 Cognitive Accessibility › Error recovery requires every human-mode cli refusal except `unknown` (exit 14) to be `unable  <reason>  <detail>` on stderr, then `hint:` as the last stderr line, with a typed exit code. The rule also covers `viola verify`'s interrupted pair (`unable: verify was stopped before it finished` / `hint: run viola verify again to stamp this CLI`). If `/compact` is listed as a local command, its delivered or refused outcome must keep this layout. Any new verify refusal must too.
- a11y-plan §8 Cognitive Accessibility › Plain language requires every fixed cli string to be pinned (trycmd, or literals where the plan names them), so any copy change fails CI until the pinned string is updated on purpose. A new row's name in a step line counts as such a string.

## Patterns to follow
- a11y-plan §4 Critical Paths P6: trycmd / assert_cmd for the non-TTY modes and the portable-pty outer PTY for the TTY-only behaviours, on all three OS legs.
- a11y-plan §1 A11y Scope Summary (CLI verbs entity): `verify` stopped by Ctrl-C or TERM prints no step line and no summary, only the plain-ASCII `unable:` / `hint:` pair (pinned by the stop table in `tests/cli_verify.rs` per §8 Error recovery). Keep that stop path's shape as new runs or children are added.
- a11y-plan §6 Visual Design Verification › State color tokens (not-color-alone): each state is carried by its printed word alone (`unverified-cli`, `budget-paused`), and viola emits zero SGR of its own under `viola run` / a passed `viola revive`.
- a11y-plan §8 Cognitive Accessibility › Timeout extensions: `tests/cli_budget.rs` holds the cases `path6_a_reading_over_the_threshold_refuses_the_send` and `path6_a_closed_gate_leaves_answer_wait_last_and_pause_alone`. They show that a gate built on the `rate_limits` shape blocks no key. A recorded `rate_limits` fixture that feeds the gate keeps both cases green.

## Anti-patterns to avoid
- NEVER claim WCAG conformance for the cli or the `viola run` TUI, including one started by a passed `viola revive` (per a11y-plan §11 A11y Anti-Patterns › Strategy). assert_cmd / trycmd / portable-pty results are output-discipline stand-ins only.
- NEVER colour CLI `unable` / `fail`, and never emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run` / a passed `viola revive` (per a11y-plan §11 A11y Anti-Patterns › Visual).
- NEVER show an error without a recovery suggestion (per a11y-plan §11 A11y Anti-Patterns › Cognitive). Every human-mode cli refusal except `unknown` ends with a `hint:` line, and a kebab-case code (`not-delivered`, `unverified-cli`) never appears without the plain word `unable`.

## Acceptance criteria contributions
- `viola verify` under non-TTY prints one `[NN/NN] … pass|fail` step line per row in `LedgerRow::ALL` (the new total), with no ESC byte, no `\r` and no SGR on any line, and no SGR on `fail` under the outer PTY (per a11y-plan §4 Critical Paths P6).
- A home stamped before this chunk shows the printed word `unverified-cli` in the CLI column (and in `viola answer`'s refusal text) with no colour as its only cue, until it is re-stamped (per a11y-plan §6 Visual Design Verification › State color tokens (not-color-alone)).
- Any new or changed human-mode refusal (a `/compact` send, a new verify refusal) prints `unable  <reason>  <detail>` then `hint:` last on stderr with its typed exit code, pinned by trycmd or a literal, and `--json` carries no hint text (per a11y-plan §8 Cognitive Accessibility › Error recovery).
- `viola hook statusline` still exits 0 with empty stderr in every case, and no key is blocked or delayed under `STATUSLINE_DEADLINE` or a closed budget gate. The `tests/cli_budget.rs` path6 cases stay green on all three legs (per a11y-plan §8 Cognitive Accessibility › Timeout extensions).
