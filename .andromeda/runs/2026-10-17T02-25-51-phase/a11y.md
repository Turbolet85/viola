# a11y extract

## Relevance
partial — scope items 1–3 (`--json` per verb, typed exits, cause-named hints, `revive` / `verify` outcomes) sit on the cli surface's output-discipline and error-recovery contract; items 4–6 (`--home` resolution, `config.json`, the `state-recovered` field) have no a11y surface.

## Constraints
- Every human-mode refusal a verb prints is `unable  <reason>  <detail>` on stderr followed by `hint:` as the last stderr line, with a typed exit; the one refusal with no hint is `unknown` (exit 14), faults (`error: wrapper fault`, `error: internal error`) are not refusals and carry no hint, and `--json` gives one document with no hint (per a11y-plan §8 Error recovery). Whether every verb's every refusal already prints this pair is research's question.
- A fixed-message refusal (the `viola revive` exit-1 set, `verify`'s interrupted pair) uses design-system cli pattern 2: one `unable: <text>` line, then one `hint:` line last; a clap usage error exits 2 (per a11y-plan §8 Error recovery).
- The CLI verbs entity states `revive` takes no `--json`, its `--list` rows are static ASCII (`<ts>  <cause>  <id>`, no header, no colour, no ESC byte), and each exit-1 refusal is one `unable:` + one `hint:` line last on stderr (per a11y-plan §1 A11y Scope Summary, CLI verbs entity). A `--json` the chunk adds to `revive` (scope item 1, CARRY 2) changes that clause, and its human mode must keep the rows and pairs as stated.
- No SGR, glyph or cursor control under `--json`, non-TTY, `NO_COLOR` or `TERM=dumb`; output static and linear, with no spinner or redraw (per a11y-plan §1 A11y Scope Summary, cli surface Notes).
- `unable` / `fail` are never coloured, and the revive refusal pairs and `--list` rows carry no ESC byte (per a11y-plan §6 Visual Design Verification).
- Every kebab-case reason/detail code (`not-delivered`, `human-typing`, `unverified-cli`) sits beside the plain word `unable`; the CLI never shows a stack trace or a bare status number as the only error text; and every fixed CLI string is pinned by trycmd or a literal, so a copy change fails CI until the pin is updated on purpose (per a11y-plan §8 Plain language).
- CLI output-discipline cases are ordinary nextest cases inside the existing suites (`nextest-integration` / `nextest-e2e` locally, the per-OS `test` job's `coverage` suite in CI) on all three OS legs; no new `suite` value and no separate driver (per a11y-plan §3 CI integration).

## Patterns to follow
- `viola list`'s exit-21 state pairs pinned by literal (hint last, stdout empty; under `--json` exactly `{"v":1,"error":"instance-unreachable","detail":null}` with stderr empty) in the `cfg(unix)` root cases `list_refuses_*` and the unit `instance_and_home_state_pairs_are_the_fixed_texts` (per a11y-plan §8 Error recovery).
- The revive refusal pairs pinned by the root cases in `tests/cli_revive.rs`, and `verify`'s interrupted pair pinned by the stop table in `tests/cli_verify.rs` (per a11y-plan §8 Error recovery).
- One case reading each verb's exit code and document side by side: `path6_a_closed_gate_leaves_answer_wait_last_and_pause_alone` (`tests/cli_budget.rs`) reads `send`, `wait`, `last`, `answer` and `pause` exits and documents in one flow (per a11y-plan §8 Timeout extensions).
- The cli drivers are assert_cmd 2.2.2 + predicates 3.1.4 + trycmd 1.2.1, with no a11y tool (per a11y-plan §3 A11y testing tool pick); P4's cli leg is `send` refused `human-typing` on stderr with a typed exit, read by assert_cmd (per a11y-plan §4 ARIA Patterns & Roles, P4).

## Anti-patterns to avoid
- NEVER show an error without a recovery suggestion (every human-mode refusal except `unknown` ends with `hint:`), never print a kebab code without `unable`, never render a stack trace as the only error text (per a11y-plan §11 A11y Anti-Patterns, Cognitive).
- NEVER colour CLI `unable` / `fail`, and never emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` (per a11y-plan §11 A11y Anti-Patterns, Visual).
- NEVER claim WCAG conformance for the cli, and never add an `a11y` suite value or a separate a11y driver outside `scripts/agent-run.* run` (per a11y-plan §11 A11y Anti-Patterns, Strategy and CI).

## Contract bindings
- a11y ↔ architecture: the `unable` / `hint:` pair per refusal and the `--json` document-without-hint (a11y-plan §8 Error recovery) bind to architecture §Conventions (CLI exit codes, the refusal → exit map, the per-verb pairs) and §Standard Contracts (CLI `--json` output).
- a11y ↔ design: the fixed-message refusal form binds to design-system cli pattern 2 (a11y-plan §8 Error recovery).
- a11y ↔ tests: output-discipline failures surface only as nextest failures in the harness `run` JSON `suites[].failures[]`, gated by `gate --require coverage,doctest` (a11y-plan §3 Structured violation JSON schema; §3 CI integration).
- a11y plan amendment cascade: a `--json` on `viola revive` (scope item 1, CARRY 2) contradicts the "`revive` takes no `--json`" clause in a11y-plan §1 A11y Scope Summary (CLI verbs entity); if the chunk lands it, that clause is a drift item for the wrap.

## Acceptance criteria contributions
- For each refusal the chunk adds or documents, human mode prints one `unable` line and a final `hint:` line on stderr (none for `unknown` exit 14 or a fault), and the `--json` form is one document carrying no hint text and no ESC byte, its exit one of 0/1/2/10–14/20/21, asserted with assert_cmd on all three OS legs (per a11y-plan §8 Error recovery).
- Every new fixed CLI string (refusal pair, hint, row) is pinned by a trycmd case or a literal (per a11y-plan §8 Plain language).
- `viola revive --list` rows and its exit-1 refusal pairs in human mode remain static ASCII with no header, no colour and no ESC byte, the hint last, whatever machine document the chunk adds (per a11y-plan §1 A11y Scope Summary, CLI verbs entity).
- The new cases run inside the existing nextest suites, adding no `suite` value (per a11y-plan §3 CI integration).
