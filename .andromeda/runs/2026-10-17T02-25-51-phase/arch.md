# arch extract

## Relevance
relevant — the chunk is the CLI surface the architecture plan fixes in §Standard Contracts (CLI `--json` output), §Conventions (CLI exit codes, CLI flags) and §Cross-cutting Patterns (Config management), and it lands in the root `viola` bin (`src/cmd/`, `src/main.rs`), the one crate allowed anyhow per §Established Decisions [Error Handling] and [Module Boundaries].

## Constraints
- Every `--json` document is one of four shapes, each carrying `v` = 1: the channel `ok`, the channel `refusal` + `detail`, `error:"instance-unreachable"` (exit 21) and `error:"wrapper-fault"` with the `{code, message, data}` detail (exit 20). A refusal's exit follows the `RefusalReason` → exit map (10–14). Per architecture §Standard Contracts (CLI `--json` output) and §Conventions (CLI exit codes). The same error documents are MCP's `structuredContent` per §Conventions (MCP), so the shapes cannot fork per surface.
- The exit set is closed: `0, 1, 2, 10–14, 20, 21`, per architecture §Occupied Resources (Binary, subcommands and exit codes). §Conventions (CLI exit codes) assigns every outcome that is not a refusal: `revive` exit 1 for its strict-modes check and its four preflight readings, in a fixed order (`already-live` · `no-session` · `session-live` · `cwd-missing`; `--list` has two, strict-modes and `no-session`); `verify` exit 1 for a failing row, a Ctrl-C/TERM stop and its four refusal pairs; `list` exit 21 for a refused scan; `wait`/`last` exit 1 versus 21 by channel-error class; exit 2 for clap usage errors and the `send` text bound. A new document must keep each of these exits.
- §Established Decisions [CLI Conventions] says `viola revive` takes no `--json` today and that its `--json` is owed to the working-route entry "CLI machine contract". The scope's CARRY 2 quotes an earlier operator answer that revive takes no `--json`. Which of the two governs is the scope's question to settle, and it goes to P4. Any revive document must hold no recorded directory, pid or logged id, as §Conventions (CLI exit codes) requires of the revive refusal pairs.
- The home is resolved in this order: `--home`, then the grandparent of `VIOLA_DIR` when it is set, then `<user home>/.viola/`. Per architecture §Cross-cutting Patterns (Config management), the `VIOLA_DIR` step for the CLI verbs is owed to this entry. Today only `hook` takes it. §Occupied Resources (Environment variables) names every CLI verb run inside a session as a `VIOLA_DIR` reader in the target state. The statusline source rule's `cmd::default_home` is shared with `resolve_home`, so changing the order must keep "only the default home falls back to `~/.claude/settings.json`", per §Cross-cutting Patterns (Config management).
- `config.json` must carry `v` = 1. It is read through a `MAX_FRAME` cap and parsed tolerantly: unknown keys are skipped and counted. `five_hour` / `seven_day` are whole-number `Percent` values 0–100 with defaults 90 / 85. A bad key takes its own default and logs one `parse-rejected{parser:"config-json"}` line, and no value switches the gate off. `diagnostics_level` is `info` | `debug`. `claude_env_keep` holds at most 32 names matching `^CLAUDE[A-Z0-9_]*$`; a bad value is rejected whole, and a name on the identity floor has no effect. Per architecture §Occupied Resources (Filesystem, `config.json`) and §Cross-cutting Patterns (Config management). Precedence is CLI flag over `config.json` over built-in default, per §Cross-cutting Patterns (Config management).
- Process roles: `src/main.rs` `role_of` puts every first word except `run`, `revive`, `hook` and a leading flag under `cli`. `revive`'s start arm logs as process `run`. `viola revive --list` opens no process log. Per architecture §Conventions (CLI exit codes, the `cli` role clause) and §Occupied Resources (Filesystem, `diagnostics/`). Having `--list` open the `cli` role log is a `role_of` change for a word that is not `cli` today. On revive (§Occupied Resources, Filesystem `instances/` clause) and on list (the same clause), the strict-modes check must still run before any log opens.
- stdout is reserved for the `--json` result, and short-lived verbs put human text on stderr, per architecture §Cross-cutting Patterns (Diagnostic output channels). A dispatch `Err` or a caught panic in a `cli`-role verb prints exactly `error: internal error` once, from the `main` catch site, per §Conventions (CLI exit codes).

## Patterns to follow
- `viola list --json` is the template for a refused scan: exit 21 with `{"v":1,"error":"instance-unreachable","detail":null}` on stdout, empty stderr, no log opened and the home's mode left as found (architecture §Occupied Resources, Filesystem `instances/` clause; §Conventions, exit 21).
- Use one shared reader per file: thresholds only through `run::budget::read_thresholds`, which the wrapper and `list` share (architecture §Occupied Resources, Filesystem `config.json`). Home derivation goes through `resolve_home` / `cmd::default_home`, and `hook` already takes the `VIOLA_DIR` grandparent step (§Cross-cutting Patterns, Config management).
- `serde_json` `preserve_order` keeps a printed document's declared key order (architecture §Stack and Technologies, Serialization). The `RefusalReason` / `detail` strings are kebab-case from closed sets, extended only in `viola-core`, and an unknown `detail` reads as opaque text (§Conventions, Error handling schema).
- A refusal is one `unable:` / `hint:` pair per cause, in fixed text with no path, pid or id. The revive and verify pairs in architecture §Conventions (CLI exit codes) are the worded precedents. `send`'s `input-not-ready` hint wording is the founder's (§Established Decisions [CLI Version Compatibility], `send_hint`).
- Verb arguments mirror the channel `params`. Flags are kebab-case long options, with the global `--home`. `revive` and `list` send no channel frame (architecture §Conventions, Naming patterns, CLI; §Established Decisions [API Style]).

## Anti-patterns to avoid
- Environment variables are not a configuration channel. The chunk adds no `config.json` key, `VIOLA_*` variable or flag that switches off a control, and no `VIOLA_*` name beyond `VIOLA_NAME`, `VIOLA_DIR` and `VIOLA_BIN`. Reading `VIOLA_DIR` in the CLI verbs is existing wrapper-to-child plumbing (architecture §Cross-cutting Patterns, Config management; §Conventions, Naming patterns, Environment variables).
- No `deny_unknown_fields` on `config.json` or any viola format, because mixed binary versions are real (architecture §Established Decisions [Validation]; §Cross-cutting Patterns, Mixed-version tolerance).
- No anyhow chain, path or upstream text in a `--json` document or on stderr. anyhow stays at the root bin's edge, and its chain goes only to the instance detail file (architecture §Established Decisions [Error Handling]).

- arch §Conventions (CLI exit codes) ↔ test-plan's integration layer for the CLI verbs: the witness that reads every verb's exit against the documented set.

## Acceptance criteria contributions
- Every driver-facing verb's `--json` output, for each outcome, is exactly one of the four documented shapes with `"v":1`, and its exit matches the shape: the refusal reason's 10–14 code, 21 for `instance-unreachable`, 20 for `wrapper-fault`, 0 for `ok` (per architecture §Standard Contracts, CLI `--json` output; §Conventions, CLI exit codes).
- A CLI verb resolves its home in this order: `--home` first; otherwise, with `VIOLA_DIR` set, the grandparent of `VIOLA_DIR`; otherwise `<user home>/.viola/`. A session started with `--home` keeps its nested CLI calls in that home (per architecture §Cross-cutting Patterns, Config management).
- If `config.json` has `v` ≠ 1, an unknown key, or a bad threshold, the reader falls back to the default for each affected key and logs one `parse-rejected{parser:"config-json"}` per bad key. Unknown keys are skipped and counted, and no value of either threshold leaves the budget gate unable to close (per architecture §Occupied Resources, Filesystem `config.json`; §Cross-cutting Patterns, Config management).
- Any machine document added for `viola revive` reports exit 1 with exactly one of its five refusal codes (`strict-modes-failed` · `already-live` · `no-session` · `session-live` · `cwd-missing`; on `--list` only strict-modes and `no-session`). It holds no recorded directory, pid or logged id, and on a refused strict-modes check no log opens before it (per architecture §Conventions, CLI exit codes; §Occupied Resources, Filesystem `instances/` clause).
