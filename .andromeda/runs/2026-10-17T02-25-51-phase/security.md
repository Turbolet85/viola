# security extract

## Relevance
relevant — the chunk reshapes the CLI's external error surface (`--json` documents, exits, `hint:` lines), the `--home` / `VIOLA_DIR` resolution ahead of every strict-modes check, the `config.json` reader and one log field, each a boundary the security plan governs.

## Constraints
- Home resolution: security-plan §Input Validation (CLI arguments / stdin row) requires `--home` and `VIOLA_DIR` to be canonicalised (`std::fs::canonicalize`) and then to pass the home strict-modes check before any snapshot, `statusline_command` or ledger read; the same row's `list` clause names that canonicalisation as owed to this route entry ("CLI machine contract"). CARRY 1 records the landed form as "without `std::fs::canonicalize`", so whether the code canonicalises today, and how the planned resolution order reconciles with the row, is research's question; a departure from the row is a master amendment, not a silent choice.
- `VIOLA_DIR` is not trusted input: security-plan §Security Anti-Patterns (Universal) records that `VIOLA_DIR` is set by a child any same-session agent can influence, and that no `VIOLA_*` variable, `config.json` key or CLI flag may switch off the IPC directory check, server verification, the home strict-modes check or `validate_paste_text`. Adding the `VIOLA_DIR`-grandparent step to the CLI verbs must leave every one of those controls running on the resolved home.
- `config.json`: security-plan §Input Validation (Configuration values row) requires a tolerant parse with unknown keys counted, `v` checked, the read capped at `MAX_FRAME`, the thresholds as whole numbers into `Percent` (a bad key takes its default, one `parse-rejected` line per key), `diagnostics_level` the closed set `info` | `debug`, and `claude_env_keep` at most 32 names matching `^CLAUDE[A-Z0-9_]*$`, rejected whole on a bad value, an identity-floor name having no effect. The row also states "`port` goes into `u16`"; the scope drops `port` from 0.1.0, so that clause's fate is an amendment question for P4, not a requirement to build.
- External documents are sanitised: security-plan §Error Handling (External responses) requires every CLI `--json` document to carry no anyhow context chain, no absolute path, no upstream text, no serde_path_to_error path or value and no internal type name; security-plan §Bootstrap phases (`logging-redaction-wire`, Operational metadata) bars absolute paths (the OS username) and internal type names from CLI `--json` error output. Every new refusal / error document this chunk adds (revive, verify, run start) holds codes and fixed text only.
- Human stderr: security-plan §Bootstrap phases (`error-sanitization-wire`) requires that an anyhow chain printed to human-mode stderr never includes a serde_json or serde_path_to_error source; security-plan §Error Handling (Internal logging) requires that stderr never carries upstream text, tool `input` or any NEVER-log value. Each cause-named `hint:` is a fixed sentence, never an interpolated path or payload.
- Strict-modes before any log: security-plan §Authentication & Authorization (`~/.viola/` access control) requires `revive`'s `check_instance` on both arms before any snapshot or log value is used and before any log opens (opening a log sets an existing home to 0700, so a later check passes a 0770 home), with a refusal writing no line and leaving the home's mode as found; the same row fixes a CLI client verb's strict-modes refusal at exit 21 `instance-unreachable` and `list`'s whole-board refusal at exactly `{"v":1,"error":"instance-unreachable","detail":null}` with stderr empty. `revive --list` opening the `cli` role log (CARRY 2) must keep the check ahead of that open.
- The dated interim gaps stay as ratified: security-plan §Authentication & Authorization (IPC client-side server verification row) lists the liveness-only pre-check for `send`, `wait`, `last`, `answer`, `pause` and `release` until the Epoch 6 entries; security-plan §Security Anti-Patterns (Authentication) forbids any other frame or process borrowing them. A verb or path this chunk gives a `--json` form gains no channel frame under those gaps.

## Patterns to follow
- Name arguments through `#[arg(value_parser = parse_viola_name)]` (`ViolaName::try_new`) before any `instances/<name>` join — per security-plan §Input Validation (CLI arguments / stdin row) and §Security Anti-Patterns (Input).
- `viola list`'s order — `check_path` on the home and `instances/`, `check_instance` per instance, before any file under the home is opened or its log starts; the fixed exit-21 `--json` refusal with empty stderr — per security-plan §Authentication & Authorization (`~/.viola/` access control); the model for `revive --list`'s new log and any new `--json` refusal.
- `config.json` reads through `run::budget::read_thresholds` and `obs::log_config_rejection` (one `parse-rejected` per bad key, under a `VIOLA_NAME` only, no `config.json` read on a refused `list`) — per security-plan §Input Validation (Configuration values row).
- `hook`'s existing `VIOLA_DIR` shape check (absolute, ending `<home>/instances/<name>`, `VIOLA_NAME` through `ViolaName::try_new`) is the landed shape check on that variable — per security-plan §Input Validation (CLI arguments / stdin row); whether the CLI verbs reuse it is research's question.
- Human rows built from `claude agents --json` go through `escape_row`; `wait` / `last` human output escapes C0/C1 — per security-plan §Bootstrap phases (`logging-redaction-wire`).

## Anti-patterns to avoid
- Letting a `config.json` key, a `VIOLA_*` variable (`VIOLA_DIR` included) or a CLI flag switch off a control — per security-plan §Security Anti-Patterns (Universal).
- Exposing an absolute path in any external error, or printing an anyhow chain that still holds a serde source — per security-plan §Security Anti-Patterns (Logging).
- Writing a channel frame from a new path before server verification, or borrowing a dated gap for it — per security-plan §Security Anti-Patterns (Authentication).

## Acceptance criteria contributions
- Every `--json` refusal / error document a verb prints, the new revive / verify / run-start ones included, holds no absolute path and no test-home prefix: a test greps each captured stdout and stderr for the test home's absolute path and reads zero matches (per security-plan §Error Handling).
- A `config.json` holding unknown keys, a wrong `v`, an out-of-range threshold, a bad `diagnostics_level` and a bad `claude_env_keep` leaves the budget gate on (defaults), `claude_env_keep` rejected whole and every identity-floor name still stripped; no value disables a control (per security-plan §Input Validation, Configuration values row).
- `viola revive --list` against an instance whose home or instance directory is mode 0770 refuses with no log opened, no line written and the mode still 0770 afterwards (per security-plan §Authentication & Authorization, `~/.viola/` access control).
- A CLI verb run with `--home` (and, where the planned order reads it, `VIOLA_DIR`) naming a group-writable home is refused by the strict-modes check on the resolved home before any snapshot read, never passed because the variable chose the path (per security-plan §Security Anti-Patterns, Universal).
