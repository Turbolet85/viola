# tests extract

## Relevance
relevant — tier Comprehensive (2) with mutation testing a founder mandate judged at the epoch boundary (per test-plan §1 Test Scope Summary); scope §1, §4 and §5 are test-domain work and §2 is bound by the suites and floors. The plan records nothing on the duplication or cognitive-complexity scalars (the instruments of scope §1–§3 are the audit's), so nothing is cited for them.

## Constraints
- **Mutation run form.** test-plan §3 `run` (step 4 Package) requires the whole-member form `run --mutants --package <member>` [`--file <path>`…] for a boundary-tier score, and admits only `viola` or a `crates/<member>` whose manifest declares a `fake-agent` feature (else `package-refused`, exit 2). test-plan §3 `run` (step 4 Command) passes a bare `--file` beside `--in-diff`, so it reaches only changed lines: an unchanged survivor line is reached only through the package form. Whether `viola-state` and `viola-agent-claude` declare that feature today is research's question. If the plan settles on a direct cargo-mutants run, test-plan §3 `run` (step 4 Command) names what it must mirror (root prebuild with `fake-agent` into the mutation target dir, the relative target dir, the `mutants` nextest profile, `--test-tool=nextest`, `--copy-target=true`, no kept homes): without it root integration tests drive the unmutated binary and the outcome is no evidence.
- **Dev-host scratch.** test-plan §10 Mutation gate requires every mutation run on the Linux dev host to take `TMPDIR=<repo parent>/viola-mutants-scratch` (the operator's NOCOW dir); a run on the default temp dir is the measured overflow / lost-exec-bit case and not a valid score.
- **Verdict and disposition.** test-plan §10 Mutation gate reads a run as `missed == 0`, `timeout == 0`, `unviable <= caught`, from the counts in the run's own `outcomes.json`, and says no chunk, pre-push or CI mutation gate exists (consistent with `inputs#I1`). It names exactly one non-kill disposition: a mutant this host cannot compile or reach is recorded "not measured here; owed to {route entry}" by coordinate, never "equivalent" and never counted caught. It records no form for a reachable survivor that is argued rather than killed: such a mutant stays `missed`, and the next boundary `run --mutants --package <member>` reads red on it. Scope §5's "disposed with a recorded argument" therefore has no plan-side standing; P4 settles kill-only, or names the argued ones as still red and owed a ruling.
- **Owning-package kills.** test-plan §3 `run` (step 4 Test scope) requires each mutant to be killed by the tests of the package that owns the mutated file: the six viola-state survivors by viola-state's tests, the six viola-agent-claude ones by its own, the six root ones (four in the fake-agent bin) by the root package's. test-plan §10 Mutation gate adds that a mutant caught only by a doctest counts as missed under nextest.
- **Bounded waits.** test-plan §3 `run` (step 2) requires every root wait on a child to go through the shared watch helper and its one bound, held below the `mutants` profile's kill and below cargo-mutants' auto-timeout floor, exit-aware, so a mutant that stalls a wrapper grades caught and not timeout. Scaffolding lifted in scope §1 and any new kill test must keep that bound; test-plan §2 Agent-runnable invariants bans a sleep as synchronisation.
- **Home of the shared scaffolding.** test-plan §2 Test directory + naming conventions puts the root sync suites' helpers in `tests/support/` (it names an `events.rs` there, and `ndjson.rs` as the one complete-lines reader) and gives every root `tests/<surface>_<topic>.rs` a filterset prefix, so a lifted helper is a `tests/support` module, never a new test binary. test-plan §3 `run` (step 2) fixes one boot model (the `home → fake_agent_path → stamped_home → booted_wrapper` chain) and states that root `tests/support/` cannot be imported by `viola-e2e`, so the lift stops at the root package. test-plan §5 Setup / teardown lifecycle requires a started wrapper to sit in a `Drop` guard (kill, then wait) and every home to come from the `TestHome` base. Whether `tests/support/events.rs` exists at HEAD (scope §1 lists none) is research's question.
- **Floors on every OS.** test-plan §10 Coverage thresholds gates lines 85 / regions 80 / functions 95 per OS job; the helpers scope §2 splits out of `ledger.rs` and `src/cmd/verify.rs` are new functions under the function floor on each OS, while the fake-agent bin and `tests/support` sit outside the number (test-plan §10 Stack adjustments). test-plan §9 Matrix builds runs every new or moved test on all three OSes; a kill that needs a Unix-only fault is compiled out by `cfg`, never parked, per test-plan §10 Zero-flakiness budget.

## Patterns to follow
- Force an error path on the real filesystem: test-plan §8 What to mock keeps the filesystem unmocked (a real tempfile home), and test-plan §3 `schema-check` records the standing practice of a directory planted at a file's path to force an I/O error — the shape the four `NotFound`-guard survivors call for. test-plan §7 Seed strategies allows corrupting only a file the product already wrote.
- Table cases: test-plan §4 Conventions requires rstest `#[case::label]` tables with readable labels and `<subject>_<condition>_<expected>` names, inline `#[cfg(test)] mod tests`; `viola-e2e` carries no dev-dependency and uses a labelled case table in one `#[test]` (applies if P4 has the chunk kill a viola-e2e mutant).
- Literal oracles survive the lift: test-plan §5 Cross-module patterns covered (CLI) pins `tests/cli_verify.rs` by literal asserts and `tests/cli_output_plain.rs` by a parser self-check against literals; a per-file helper (scope §1) or a split of `sgr_attributes` (scope §2) keeps both.
- Selection and reading: test-plan §3 `run` (Test selection) gives `run --integration --filter 'binary(<stem>)'` for one root test file and `run --mutants --package viola-e2e` for the member score; test-plan §3 `run` (Output format) gives the record to copy — the one JSON document with its `mutants` object (`tested`, verdict `package`, `package`) and the repo-relative outcome lines.

## Anti-patterns to avoid
- NEVER read a mutation run from its exit code: count `missed`, `timeout`, `unviable`, `caught` (per test-plan §11 Test Anti-Patterns → Quality).
- NEVER take the Linux run as the Windows grade: `strict.rs:34:23` and viola-e2e's Windows-gated mutants stay owed to "Windows mutation grade" (per test-plan §11 Test Anti-Patterns → Test Strategy).
- NEVER use the product's own ledger rows as a kill test's oracle, or aim a test at a split-out private helper instead of observable behaviour (per test-plan §11 Test Anti-Patterns → Unit); never hand-write `ledger/stamps.json` or `snapshot.json` to reach an error path (per test-plan §11 Test Anti-Patterns → Test Data).

## Contract bindings
- tests ↔ obs: homes made through `TestHome` stay under `target/e2e-home`, inside obs-plan's G2, G4 and secret-scan reads (test-plan §5 Setup / teardown lifecycle); a new kill test must write no G2-counted `panic` line. The content canary is one constant in `tests/support`, and `crates/viola-e2e/tests/scan_patterns.rs` requires every canary literal in root `tests/` and `src/` to be in the scan's table (test-plan §6 Error sanitization and secret scan; test-plan §3 `secret-scan`) — scope §1's moves keep it single-sourced.
- tests ↔ security: test-plan §9 Test report format keeps `mutants.out/` out of every upload because `outcomes.json` holds absolute argv paths and its `log/` holds test output; the `evidence/` copies of scope §4 and §5 are committed, so they carry the harness document, counts and repo-relative mutant names, not the raw directory.
- tests ↔ CI: test-plan §9 Pipeline structure (Mutation row) has no push or pull-request mutation job and the chunk adds none; `windows-mutants.yml`'s per-package `--file` lists are untouched as long as scope §2 renames no file.
- tests ↔ the boundary audit: the duplication and complexity re-takes are read on the audit record's own commands, outside this plan.

## Acceptance criteria contributions
- `scripts/agent-run.sh run` (the default `--all`: unit, integration, doctest, fake-agent E2E) exits 0 with `failed` 0 and `skipped` 0 on every suite after scope §1, §2 and §5 land, and no assertion text changed in a file that only lost scaffolding (per test-plan §3 `run`).
- The viola-e2e score is one `run --mutants --package viola-e2e` under the dev-host scratch `TMPDIR`; `evidence/` holds its document (verdict `package`, `tested`) and the four counts, names every `missed` or `timeout` mutant, and words a host-unreachable one "not measured here; owed to Windows mutation grade" (per test-plan §10 Mutation gate).
- Each of the eighteen survivors reads `caught` in a package-scoped run over its file, killed by a test in its owning package (the three inside split functions matched by mutation text), that run reading `timeout == 0` and `unviable <= caught`; any one left `missed` is listed as still red with its argument, never as caught or "equivalent" (per test-plan §10 Mutation gate).
- `scripts/agent-run.sh run --coverage` holds lines ≥ 85, regions ≥ 80 and functions ≥ 95 with the coverage ignore regex unchanged (per test-plan §10 Coverage thresholds).
