## Patterns to follow
- A kill test for a `NotFound` match guard in `viola-state` (scope §5) can read the existing codes-only outcome instead of content: an unreadable, unparsable or strict-modes-refused ledger is `parse-rejected{parser:"ledger-stamps", detail:"unreadable"|"malformed"|"strict-modes-failed", count}` and is treated as unverified, with no path or stamp content in the line (per obs-plan §4 Span / Trace Coverage → Edge flows → Capability ledger). Whether each of the four guards' non-`NotFound` branch ends in such a line is research's question.
- `verify` logs its six child spawns at the call site, each a `process-start{subject}` / `process-exit{subject, child_exit_status, duration_ms}` pair, and `run_bounded` itself stays unlogged; a helper split out of `record` in `src/cmd/verify.rs` leaves every pair where it stands and in its order (per obs-plan §6 Log Coverage → Boundary-call wrappers, Child / shell spawns). Whether `record` holds one of the pairs is research's question.
- The fake agent prints under one crate-level `#![allow(clippy::print_stdout, clippy::print_stderr)]` in `src/bin/viola-fake-agent.rs`; helpers split out of `submit` stay in that file (scope §Boundaries) and so under that one allow, with no second one added (per obs-plan §3 Bootstrap phases → obs-ci-gate-wire).
- A test that asserts an emitted line at unit level parses it from an in-memory `Vec<u8>` writer with serde_json against `schemas/diag-line.v1.json`; a null `corr` or `instance` is key absence, read the same as `null` (per obs-plan §9 CI Integration → Pipeline integration, Unit tests row).

## Anti-patterns to avoid
- No `print!` / `println!` / `eprint!` / `eprintln!` / `dbg!` in a product crate's `hook`, `run` or `mcp` path, and no new local `#[allow]` for one: a helper split out of `dialog_variants` (`viola-agent-claude`) or `record` (`src/cmd/verify.rs`) adds neither (per obs-plan §11 Obs Anti-Patterns → Logs).
- No retry-once for a panic or a flaky telemetry assertion, and no log-based wait that rests on a sleep: the shared `wait_events` (scope §1) stays event-keyed on its bounded watch (per obs-plan §11 Obs Anti-Patterns → SLO).
- No bare `#[instrument]`, and no `err` / `ret` on a function whose error or return can carry a serde source or user content — the ledger's dialog parsing is such a function (per obs-plan §11 Obs Anti-Patterns → Spans / Traces).
