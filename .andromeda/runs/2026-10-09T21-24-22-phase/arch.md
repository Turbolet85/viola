## Patterns to follow
- The package-and-file mutation arm: architecture §Infrastructure Patterns → CI/CD approach describes `run --mutants --package <member> --file …` (the form `windows-mutants.yml` dispatches), and architecture §Occupied Resources (Environment variables) says that arm reads no diff base, so `AGENT_RUN_CHUNK_BASE` is not set for it. Per the same CI/CD approach contract, `run --mutants` itself sets `AGENT_RUN_KEEP_HOMES=0` and `AGENT_RUN_KEEP_FAILED=0` on the `cargo mutants` command (a mutation run keeps no test home).
- Package-scoped feature resolution: architecture §Occupied Resources (Workspace crates) requires each sync crate and `viola-e2e` to declare a code-free `fake-agent = []` feature so a package-scoped `--features fake-agent` build (cargo-mutants) resolves. The survivor runs in `viola-state` and `viola-agent-claude` rely on it; the chunk adds no feature and removes none.
- One test home per test: architecture §Established Decisions [CI/CD] requires each test to run in its own viola home (`--home`), and architecture §Occupied Resources (Repository) names `tests/support/home.rs` as the owner of the `viola-test-*` homes, their `owner.json` and the `prepare_home_base` keeper. A lifted wrapper-boot helper takes its home from that chain and adds no second home-making path.
- The root wait instrument: architecture §Occupied Resources (Filesystem) names `tests/support/watch.rs` `Watch` (bound `WITHIN`) as the root test chain's wait on a child, with its `.report` file. A lifted `wait_events` or child-run-and-wait helper keeps waiting through `Watch`; whether every per-file copy already does is research's question (the scope's sibling read says so at `59e791e`).
- State-store behaviours as the survivor tests' subject: architecture §Established Decisions [Database / State Store] (the events reader skips an unterminated last line, neither returned nor rewritten, and skips and counts an over-long or non-object line) and architecture §Established Decisions [Snapshot writer] (`replace_private_shared`: a failed replace counts as done only when the target already holds exactly those bytes) are the stated behaviours a kill test for `events.rs:209:24` and `fs.rs:290:19` pins. The tests assert them; they do not change them.

## Anti-patterns to avoid
- A bare `cargo mutants` over a root-package file (`src/bin/viola-fake-agent.rs`, `src/cmd/mod.rs`, `src/cmd/hook.rs`) with the default target dir: architecture §Occupied Resources (Repository) (`target/mutants/`) records that a copied default `target/` keeps the original tree's `CARGO_BIN_EXE_*` paths, so root integration tests drive the unmutated binary and a mutant reads missed for a reason that is not the test's.
- Reaching a kill by widening a test-only surface: a new env seam, a new fake-agent option or a new `test-support`-style feature. Architecture §Occupied Resources (Workspace crates) limits the test-only feature to `viola-channel`'s `test-support`, enabled only by the root package's dev-dependency entry, and architecture §Infrastructure Patterns → CI/CD approach (target job 6) requires the release build to carry `viola` only, with no artifact built under a test-only feature.
- Healing, rewriting or newly reporting a torn line while adding the `events.rs` tests: architecture §Established Decisions [Database / State Store] owes healing and `state-recovered` to the working-route entry "Self-healing state", not to this chunk.
