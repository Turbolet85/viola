## Relevance
partial — the cli surface only (`viola verify` output, the verify catch-site line, `viola run` staying silent through the version gate). The web-spa surface and the `viola list` CLI column that reads `cli_verified` are out of this chunk (Epochs 5/8 per scope Boundaries).

## Constraints
- `viola verify` output is a step counter, one appended line per ledger row, shaped `[NN/TT] <row id> <description>  <verdict>`. The counter is zero-padded to the total's width, and the verdict word is `pass` or `fail`. There is no progress bar, no redraw and no cursor control, and it is the project's only progress pattern (per layout-templates §Surface: cli → Output structure — `viola verify`, §Primary screens (commands), §Decisions Log "Motion trigger placement" cli). The example's `14` is illustrative. `TT` is the chunk's actual row count (about 17 per scope).
- The run closes with exactly one summary line, `stamped <version>  <n> pass  <n> fail`, with fields separated by the two-space gutter. No `done.`, `success` or banner follows it, and the exit code is the terminator (per layout-templates §Component — Footer / terminator, §Output structure — `viola verify`). The plan doesn't say what a run with `fail > 0` prints or how it exits, and whether it still writes a stamp. P3/P4 have to settle that against the test-plan result line (:290, :518).
- No colour anywhere in verify output: `fail` is never coloured, and CLI colour is reserved for `DIALOG` and `stale`. The expression level is 0.0 under non-TTY, `NO_COLOR` and `TERM=dumb` (per layout-templates §Output structure — `viola verify`, §Component — Hero / signature output line "Colour", §Surface: cli "Expression level").
- No header, banner, logo or version line on `verify` output. The CLI version shows up only as the `<version>` field of the summary. The only header on any verb is `viola list`'s BAY line (per layout-templates §Component — Header / banner).
- `viola run` prints nothing on success while the child runs. The new `--version` pre-spawn gate and the transport-only degrade must not write a notice, warning or banner to the terminal (per layout-templates §Output structure — `viola run`, §Component — Header / banner "`viola run` prints nothing"). Its only human lines stay the exit-1 start refusals, `unable: <name> …` followed by `hint:` (per §Component — Primary content block 2).
- Streams are never mixed: results go to stdout, and errors, refusals and hints go to stderr (per layout-templates §Component — Primary content block 2 "Streams"). The plan doesn't name the stream for the verify step lines and summary. By that rule they are results, so stdout. P4 should state which stream it uses.
- The verify catch-site line is an `internal error` line on stderr with no `hint:` under it. The plan gives no hint for `internal error` (per layout-templates §Component — Primary content block 2 "Hint line"). The exact text `error: internal error` is owned by design-system §Surface: cli → Exit-code phraseology and obs-plan §7 (see Contract bindings).

## Patterns to follow
- The fixed-column phraseology that other verbs use. The two-space gutter separates fields, and within one field ` - ` replaces `·` and `->` replaces `→`. There are no box-drawing borders and no Unicode glyphs (per layout-templates §Surface: cli token table "`space-xs` equivalent", §IA notes "Multi-surface coordination").
- A line is appended, never redrawn. Each step line prints once when its probe finishes, the same way `send`'s outcome line prints under its issue line (per layout-templates §Output structure — `viola send`, §Output structure — `viola verify`).
- Output is a contract. LLM drivers and tests may read the human words and columns, so the step-line shape and the `stamped …` summary stay stable. Any new field goes into `--json` first (per layout-templates §IA notes "Output as a contract"). Whether `verify` takes `--json` at all is not in the plan. `--json` is "the machine view of every data verb" (§Component — Primary navigation), and `verify` is a setup verb, so this is an open P4 question.
- Human output goes through the one-writer human-output seam (`src/human.rs`, per scope CARRY 3). It stays ASCII-only and SGR-free, consistent with the 0.0 expression level (per layout-templates §Surface: cli "Expression level").
- `viola --help` already groups `verify` under `setup: run, verify, plugin install` (per layout-templates §Output structure — `viola --help`). Whether the current help output already lists `verify` there is research's question.

## Anti-patterns to avoid
- No spinner, progress bar, elapsed-time counter, `✓`, `done` or `success` word, and no in-place redraw on `verify` (per layout-templates §Output structure — `viola verify`, §Component — Hero / signature output line "What never happens", §Component — Footer / terminator).
- No upstream text in human verify output. Step lines carry the compiled-in row id, its fixed description and the verdict word, never a measured payload, a path or a username (per layout-templates §Output structure — `viola verify`; hints never quote upstream text or name a path, per §Component — Primary content block 2).
- No hint that names `viola release`, and no hint line under `internal error` (per layout-templates §Component — Primary navigation "Discoverability", §Component — Primary content block 2).

## Acceptance criteria contributions
- (layouts) `viola verify` against the fake agent prints one `[NN/TT] <row id> …  pass|fail` line per ledger row, appended in order. `TT` equals the row count and `NN` counts up to it, and the last line is `stamped <version>  <n> pass  <n> fail`, with no line after it (per layout-templates §Output structure — `viola verify`, §Component — Footer / terminator).
- (layouts) `viola verify` output contains no ESC/SGR byte, no non-ASCII glyph and no carriage-return redraw, on a TTY and when piped (per layout-templates §Output structure — `viola verify`, §Surface: cli "Expression level", §Decisions Log "Motion trigger placement").
- (layouts) A forced internal failure in `viola verify` leaves `error: internal error` as the last stderr line, with no `hint:` line after it and nothing on stdout from that line (per layout-templates §Component — Primary content block 2 "Hint line" / "Streams").
- (layouts) `viola run` with an unlisted or unverified child `--version` writes no viola-originated byte to the terminal before or during the child's session. Transport-only degrade is silent on the human surface (per layout-templates §Output structure — `viola run`, §Component — Header / banner).
