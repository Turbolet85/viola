# obs extract

## Relevance
relevant — the chunk adds a new `cli` verb (`verify`), the ledger read inside `run`'s version gate, a new child spawn (the `--version` probe), a ledger writer, and the catch-site stderr line, each with named spans / events in obs-plan §4 and §6; fixture recording is scrub-owned by security/tests (obs adds no fixture content).

## Constraints
- `verify` requires the dispatch span `cli.verify`, one `cli.verify_step` per step, and `state.ledger_write` for the stamp write; with an instance resolved (`VIOLA_NAME` set) it logs `process-start` / `process-exit{exit_code, detail}` to `cli-<name>.ndjson`, and with none it writes no process-log file (D-06), leaving the exit code plus the `stamped <ver>  N pass  N fail` stderr summary as its outcome (per obs-plan §4 Edge flows → `verify` / `plugin install`; §3 Logging stack, D-06).
- `run`'s version gate requires the span `run.version_gate` (fields `cli_version`, `cli_verified`) inside `run.start`, before `channel.bind` and `pty.spawn`, with the probe logged as `process-start` / `process-exit{subject:"version-probe", child_exit_status, duration_ms}`; `process-start{subject:"claude-child"}` carries the resulting `cli_version` and `cli_verified` (per obs-plan §4 Scenario: `viola run` start sequence to child spawn; §6 Boundary-call wrappers → Child / shell spawns). Whether any of these spans / events exist today (the scope says `cli_verified` is hard-coded `false`) is research's question.
- The ledger read requires the child span `state.ledger_read` under `run.version_gate`; a missing stamp yields `cli_verified:false`, and an unreadable or unparsable `ledger/stamps.json` yields `parse-rejected{parser:"ledger-stamps", detail:"unreadable"|"malformed", count}` at `warn` in `run-<name>.ndjson` and is treated as unverified; the path and the stamp contents never appear (per obs-plan §4 Edge flows → Capability ledger; §6 `detail` code catalog and Log levels mapping).
- The short-lived `cli` catch site requires the fixed stderr `error: internal error` and exit 1, with the anyhow chain going only as a one-line `chain:[...]` to `instances/<name>/diagnostics/detail-cli.ndjson` when an instance resolves, through the root-bin reporter `viola::obs::report_internal_error`; a serde-sourced chain is replaced by the fixed message before any external surface (per obs-plan §7 Panic hooks → Per-role behaviour; §7 `before_send` scrubbing pattern, layers 2–3).
- Every new line is default-deny: only events and fields named in the §6 catalog (`process` value `cli`, `subject` `version-probe`, `parser` `ledger-stamps`, `cli_version`, `cli_verified`) may be emitted, and `detail` codes are closed kebab-case with no path or pid; `cli_version` is Low-confidentiality and loggable, stamp contents are not (per obs-plan §6 Additive field catalog; §8 Data classification rules; §8 Default-deny posture).
- In CI, `viola verify` runs only against the fake agent (harness `boot` step 4 and the rstest `stamped_home` fixture) as the only writer of `ledger/stamps.json`; the real-`claude` verify never runs in CI; no obs gate depends on verify's own lines, but its home-level lines under `target/e2e-home/` fall under G2, G4 and the secret scan (per obs-plan §4 Edge flows → `verify`; §9 Pipeline integration → Integration tests).
- The NEVER-log floor for `CLAUDE_CODE_MESSAGING_TOKEN`, `_SOCKET` and every R8-stripped `CLAUDE*` value holds across all sinks and fixtures; recorded fixtures are scrub-required (security/tests-owned) and are not a telemetry source (per obs-plan §1 Obs Scope Summary, Vector 6 row; §8 Data classification rules → Recorded fixtures).

## Patterns to follow
- Spans declared `#[instrument(skip_all, name = "<area>.<operation>", fields(...))]` with static snake_case names (`cli.verify`, `cli.verify_step`, `state.ledger_read`, `state.ledger_write`, `run.version_gate`) and an explicit field allow-list (per obs-plan §4 Span naming convention; §2 span naming).
- Events only through `obs_event!` with typed fields; `corr` set explicitly (null by key absence) (per obs-plan §11 Logs; §6 Required fields).
- Child spawns bracketed by `process-start` / `process-exit` with a closed `subject` (here `version-probe`) and `child_exit_status` / `duration_ms` (per obs-plan §6 Boundary-call wrappers).
- Human stderr for `run` / `cli` goes through the output module `src/human.rs` (one `write_all` on locked stderr, no print macro, no `#[allow]`) — the catch-site line reuses it (per obs-plan §11 Logs, print-macro ban clause).
- Parse failures of a persisted store surface as `parse-rejected{parser, detail, count}` and degrade (here to unverified) rather than failing the process (per obs-plan §6 `detail` code catalog → `parse-rejected`).

## Anti-patterns to avoid
- No bare `#[instrument]`, no `#[instrument(err)]` / `(ret)` on functions whose error can carry a serde source (the stamps parse), and no raw `tracing::*!` outside `viola_core::obs` (per obs-plan §11 Spans / Traces; §11 Logs).
- No print / eprint / dbg macros in product paths, and no telemetry to stdout — `verify`'s `--json` result and stdout are reserved (per obs-plan §11 Logs).
- No path, stamp content, probe output or pid in any `detail` code or home-level field; no fixture content added by obs (per obs-plan §11 PII Scrubbing; §8 Data classification rules).

## Acceptance criteria contributions
- (obs) A `viola run` against an unstamped fake-agent CLI version writes `process-start{subject:"claude-child", cli_verified:false}` plus a `version-probe` `process-start` / `process-exit` pair in `run-<name>.ndjson`, and against a `verify`-stamped home writes `cli_verified:true`; a corrupted `ledger/stamps.json` yields exactly one `parse-rejected{parser:"ledger-stamps"}` and `cli_verified:false`, with no path or stamp content in any home-level line (per obs-plan §4 Scenario: `viola run` start sequence; §4 Edge flows → Capability ledger).
- (obs) `viola verify` with `VIOLA_NAME` set writes `process-start` / `process-exit{exit_code}` to `cli-<name>.ndjson` and every line passes G4 against `schemas/diag-line.v1.json`; without an instance it writes no process-log file (per obs-plan §4 Edge flows → `verify`; §9 G4; D-06).
- (obs) A forced internal error in `viola verify` prints exactly `error: internal error` on stderr (uncoloured, no chain), exits 1, and puts the chain only in `detail-cli.ndjson` when an instance resolves (per obs-plan §7 Panic hooks → Per-role behaviour; §7 scrubbing layers 2–3).
- (obs) G2 (zero panics) and the secret scan stay green over every home the fake-agent verify and version-gate tests create under `target/e2e-home/`, including the R8 canary names (per obs-plan §10 Error budget; §8 Integration points item 6).
