# security · standing conventions

- S1 · every new test, fixture or harness uses its own viola home, kept out of git, and removes only directories it created · secret-management · security-anti-patterns
  decision/live-session-screens-kept-local · Live session screens kept local — A live session's screen frames are kept only under a gitignored local path, never in a work dir, a run dir or a commit; what lands is a closed-word summary per frame. · why: A real session's screen holds the user's own status-line output and the repository is public.
  decision/mcp-fixtures-via-test-only-tap · MCP fixtures recorded through a test-only tap — MCP exchange fixtures are recorded by a test-only tap that spawns viola mcp directly with no shell, caps each line, keeps its raw capture 0600 in a private directory never committed, and applies the same scrub and closed refusal codes. · guard: schemas/claude-mcp-fixture.v1.json
  decision/probe-artifacts-cleanup · Probe artifacts owner-only and removed — Probe captures and dirs are owner-only and removed when verify passes, fails or is stopped, each run removing only what it created, never by pattern or listing. · except: a kill or a crash leaves them to be removed by hand
  decision/verify-probe-dirs-cleanup · Verify probe directories removed by drop guards — Every probe directory of viola verify is 0700 and removed when verify passes, fails or is stopped by SIGINT or SIGTERM; a guard removes only what its own run created, never by a pattern or a listing, and no remover of an earlier run's directories exists. · except: SIGKILL, a crash or a failed handler install leave the directories to be removed by hand.
- S2 · every new test-only seam or binary stays under the fake-agent test feature, compiled out of the release build, and any new environment read or seam gets its log entry · input-validation · security-anti-patterns
- S3 · every new or changed CI job pins its actions by commit SHA, runs with least workflow permissions and checkout without persisted credentials, and passes the workflow audit gate · dependency-security
  decision/actions-pinned-by-sha · GitHub Actions pinned by full commit SHA — Every GitHub Action is referenced by a full commit SHA with a version comment, never by @stable, @v2 or any mutable ref, and actions/checkout runs with persist-credentials: false.
  decision/actions-sha-pinned · Third-party actions SHA-pinned — Third-party GitHub Actions are SHA-pinned.
  decision/checkout-no-persisted-credentials · Checkout without persisted credentials — The CI checkout action runs with persist-credentials false.
  decision/cli-tool-exact-pins · Exact pins for external CLI tools — External CLI and audit tools are installed at exact pinned versions, in CI and by the ripgrep install script, and CI actions are pinned by commit SHA; no tool is expressed as a minimum version floor. · why: CI installs each tool at its pin itself, and no drift check compares a locally installed build against a pin.
  decision/least-workflow-permissions · Least workflow permissions — Workflows set empty permissions at workflow level and contents read at job level.
  decision/zizmor-workflow-audit · zizmor for workflows — zizmor 1.30.1 or newer audits the GitHub Actions workflows.
  decision/zizmor-workflow-gate · zizmor workflow audit gate — zizmor audits the workflows in CI and fails on unpinned actions, excessive permissions, template injection and cache poisoning.
- S4 · every new log line or test output honours the never-log floor: no paths, pids, ids or upstream text in external error output · error-handling · bootstrap-phases-derive-for-route-setup-project
  contract/fixture-refusal-line/form · verify's unclean-fixture refusal · line form — The refusal reads `unable: a recorded fixture is not clean: <file> <code>`, or `<file> row <n>[ seam] <code>` for a screen, naming the file and a closed code, never the content.
  contract/mcp-stdin/oversize-line · viola mcp stdin · oversize line — After the session ends one WARN parse-rejected parser mcp-stdin detail oversize count 1, no byte of the line; exit 0 for an initialized session, exit 1 with both streams empty when cut before initialize completes.
  contract/mcp-stdin/parse-rejected · MCP stdin refusal log · parse-rejected — An over-long MCP stdin line is recorded as one parse-rejected line holding no byte of it.
  contract/revive-json/output-fields · revive --json output · output fields — revive --json prints codes, closed words and session-shaped ids only, never a path or pid.
  contract/revive-list-json/document · viola revive --list --json · sessions document — Prints {"v":1,"ok":{"sessions":[{"ts","cause","id"}]}} in log order: codes, closed words and session-shaped ids only, never a path or pid.
  contract/revive-refusal/no-session · revive refusal words · no-session — An --id the log does not hold is refused no-session before any spawn, and no refusal line or hint holds the recorded directory, a pid or a logged id.
  contract/verify-refusal-codes/unclean-fixture · verify's refusal codes · unclean-fixture — One of the closed codes verify writes on its process-exit when refused; the fixture's file name enters no code.
  decision/agents-probe-log-content-free · Agents probe log holds no content — An agents-probe spawn pair is logged only under an open log and holds no row text, id, cwd or path.
  decision/agents-probe-log-redaction · Agents-probe logging redacted — Each agents-probe spawn pair is logged with no row text, id, cwd or path.
  decision/api-error-turn-end-text-dropped · API-error turn end carries no error text — StopFailure's error text, error_details and last_assistant_message are dropped at the parse; an API-error end's turn-ended data holds only null last_assistant_message, background_tasks and scheduled_wakes and one nine-word cause set word, crossing into events.ndjson, wait --json and MCP wait. · why: A boundary widening held to a closed set of nine words, so the upstream error text crosses into nothing. · guard: hook_stop_failure_error_text_reaches_no_event_line_or_snapshot
  decision/claude-credentials-stripped-from-child · Inherited CLAUDE credentials stripped from the child — The inherited CLAUDE* credentials stay only in the viola run wrapper's environment, are removed from the child by an exact-name strip that always strips the identity floor, and are never serialised into events, snapshots, diagnostics or the ledger.
  decision/cwd-only-in-snapshot · Recorded cwd kept to the snapshot — The snapshot's recorded cwd, which can carry the OS username, stands only in the 0600 snapshot and never on a log line, error body or stdout.
  decision/error-display-no-upstream-text · Error messages carry no upstream text — The Display output of the product error enums never interpolates upstream text or absolute paths.
  decision/hyprland-reply-text-dropped · Hyprland reply text dropped at the parse — Hyprland reply types hold no text field: window titles, classes and every other reply string are dropped at the parse and reach no log line and no error. · guard: contract_hyprland_canary_reaches_no_line_and_no_error
  decision/inherited-credentials-never-serialised · Inherited credentials never serialised — Inherited CLAUDE* credentials stay only in the wrapper's environment and are never serialised into events, snapshots, diagnostics or the ledger.
  decision/link-names-kept-out-of-process-log · Link names kept out of the process log — The wrapper's link and unlink methods write no process-log line of their own and their request and response lines carry no name; viola link and unlink print only their own parsed arguments, never a name read back from a reply or log.
  decision/never-log-claude-values · CLAUDE values never logged — CLAUDE_CODE_MESSAGING_TOKEN, CLAUDE_CODE_MESSAGING_SOCKET and every other stripped CLAUDE* value are never written to any log, diagnostic, snapshot, events.ndjson or fixture.
  decision/no-absolute-paths-in-external-errors · No absolute paths in external errors — No external error ever exposes an absolute path.
  decision/no-identity-values-in-refusals · No identity values in verification output — No line or output of a server-verification refusal holds a pid, start time, path or endpoint.
  decision/no-parser-error-chains-outward · No parser error chains in external output — serde_path_to_error drift reports and anyhow chains never reach MCP structuredContent or channel error.data, and no anyhow chain still holding a serde_json or serde_path_to_error source is printed to stderr. · why: their Display quotes input values such as tool input
  decision/no-paths-in-error-output · No paths or type names in error output — Absolute paths, which carry the OS username, and internal type names never go to CLI --json error output, MCP isError results or channel error.data. · why: the OS username is the only PII in scope
  decision/refusals-hold-no-paths-pids-ids · Refusals hold no paths, pids or ids — No refusal line or hint holds the recorded directory, a pid or a logged id; revive --list prints only session-shaped ids.
  decision/serde-errors-mapped-to-fixed-message · Upstream-quoting errors mapped to fixed messages — An error chain printed on the viola binary's human-mode stderr never includes a source whose Display can quote upstream text; such a source is mapped to a fixed message and the full error goes only to the instance diagnostics. · why: serde errors quote the offending value
  decision/socket-dir-refusal-names-only-name · Socket-directory refusal discloses no path — The socket-directory refusal names only the parsed ViolaName, and its lines hold no path, pid or uid.
  decision/spawn-cwd-snapshot-only · Spawn directory kept in the snapshot only — The start's spawn directory lives only in the 0600 snapshot, on no log line, error body or stdout, and is omitted when absent. · why: an absolute host path can carry the OS username
  decision/stderr-never-log-floor · stderr honours the never-log floor — stderr never carries upstream text, tool input, drift-report values or any other value on the NEVER-log floor.
  decision/transcript-path-redacted · Transcript path redacted — The Claude transcript path is a redacted value, carried only as the optional transcript param beside hook.event, and appears in no event data, events log, log line, span, reply or verify record. · guard: session_start_transcript_path_stays_out_of_data
  decision/user-content-only-to-diagnostics · User content only in diagnostics — Outside the content-carrying contract payloads, user content, tool input and drift reports go only to the instance diagnostics, never to stderr, CLI --json errors, MCP isError results or channel error.data. · except: events.ndjson, wait and last results and hook.dialog carry content by design
