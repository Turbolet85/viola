- a11y-plan §8 Cognitive Accessibility › Error recovery requires every human-mode CLI refusal to be a printed word with plain detail and `hint:` as the last stderr line, with a typed exit code, and `--json` to carry no hint; the squatted-name start refusal (`squatted-name`, exit 1, scope: unchanged) keeps that layout if `src/cmd/run.rs`'s start refusal is touched — whether its current stderr already has that shape is research's question.

## Patterns to follow
- The tui boundary witness per a11y-plan §4 ARIA Patterns & Roles (P4): outer-PTY nextest cases on all three OS legs reading zero viola-originated bytes and keystrokes delivered unblocked — the existing form any start-path assertion of this chunk reuses (portable-pty `=0.8.1`, per a11y-plan §3 A11y testing tool pick, never re-pinned).

## Anti-patterns to avoid
- NEVER block, refuse or delay a human keystroke in `viola run` past the current atomic paste (a11y-plan §11 A11y Anti-Patterns › Keyboard): pipe admission narrows automation's path only, never the human's.
- NEVER use a retry-once policy (a11y-plan §11 A11y Anti-Patterns › SLO): the CARRY's "three green runs under plain `cargo test`" reads a cause, never retries a red to green.
- NEVER add a `suite` value or a separate driver outside `scripts/agent-run.* run` (a11y-plan §11 A11y Anti-Patterns › CI) for the Windows pipe cases.
