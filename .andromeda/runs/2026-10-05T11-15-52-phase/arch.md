## Patterns to follow
- The ledger is a closed set (`LedgerRow::ALL`), each row judged by the pure `check(row, &Probes)` over `Probes { print, typed }`, with one stdout step line per row and a `stamped` summary (§Established Decisions [CLI Version Compatibility]; §Infrastructure Patterns → Crate dependency direction lists the pure `ledger` module's surface).
- Dialog decision bodies come from the pure `dialog` module (`classify`, `Response`, `decision_body`) and are pinned by insta snapshots (§Infrastructure Patterns → Crate dependency direction). The channel `answer` shapes per kind are in §Standard Contracts "Channel methods" (`answer`, `hook.dialog`, including the PermissionRequest continuation match).
- Verify's own call-site wrapper logs each spawn as a `process-start{subject}` / `process-exit{subject, child_exit_status, duration_ms}` pair (`verify-pty-probe` per interactive run), carrying no row text, prompt or path (§Occupied Resources → Filesystem `diagnostics/`).
- External hook payloads are parsed tolerantly: no `deny_unknown_fields`, `Option`/`#[serde(default)]`, with the raw `serde_json::Value` kept for the recorder (§Established Decisions [Validation]).
- Disk writes go through `viola_state::fs::replace_private`, and probe dirs are removed by drop guards (§Established Decisions [Snapshot writer]; §Occupied Resources → Filesystem `ledger/probes/<pid>/`).

## Anti-patterns to avoid
- Hard-coding a dialog-body or concurrency behaviour, or keying the gate on the ten-row stamp alone once the rows land, with no row or probe behind it (§Cross-cutting Patterns "Capability ledger as the single gate…"). A probe that fails to raise its dialog must not read as a pass.
- Policy inside the probe or the wrapper: the probe measures and stamps and never decides a driver's answer. Recorded plan text and tool `input` are content, never commands (§Design Philosophy "Mechanism, not policy"; §Cross-cutting Patterns "Untrusted upstream text").
- Tokio, a shell-out or a new environment variable on the `verify` / `hook` paths. The fake-agent test seams stay the two named ones (§Cross-cutting Patterns "Tokio containment", "Cross-platform discipline", "Config management").

## Contract bindings
- arch ↔ security: the M7 options (an answering probe hook, or keying a rendered tool dialog) cross the ratified [Hook Contract] `--capture` boundary and the "never a byte into a CLI dialog" ruling. The NEVER-log floor applies to recorded dialog payloads, whose `tool_input` can carry plan text and paths. Fixture scrubbing follows §Occupied Resources → Repository.
- arch ↔ tests: §Infrastructure Patterns → CI/CD approach requires CI to stamp every row only against the fake agent: print mode plus the interactive `--screens --turn-stop --trusted-root` modes, `tests/cli_verify.rs`, and harness `boot` step 4. The fake agent therefore has to replay dialog hooks for the new rows to pass in CI. The real CLI and `--record` stay local only. `schemas/claude-fixture.v1.json`'s event enum is the fake agent's nine `REGISTERED_EVENTS`.
- arch ↔ obs: any new interactive re-probe spawn adds `process-start` / `process-exit` pairs to verify's `cli-<name>.ndjson` (§Occupied Resources → Filesystem `diagnostics/`, which today names four spawn pairs). The count and subjects there need a wrap amendment if they change.

## Acceptance criteria contributions
- `LedgerRow::ALL` holds S3, S7, S8 and dialog-concurrency rows, each judged by `check` against a re-probe post-condition. A re-probe that raises no dialog makes its row `fail`, and the CI fake-agent `viola verify` stamps every row `pass` (per architecture §Established Decisions [CLI Version Compatibility]; §Infrastructure Patterns → CI/CD approach).
- When the child version's stamp lacks a `pass` on the dialog row(s) the gate keys on, `hook.dialog` is answered `null` and the driver's `answer` is refused `unverified-cli`. That covers a ten-row-only stamp (per architecture §Standard Contracts "Channel methods" `hook.dialog`; §Established Decisions [CLI Version Compatibility]).
- `ledger/stamps.json` stays the `v:1` envelope and its only writer stays `update_stamps` via `viola verify`. `viola-agent-claude` gains no `viola-state` or I/O dependency, and no Tokio enters the `verify` / `hook` paths (per architecture §Standard Contracts "Ledger stamps envelope"; §Infrastructure Patterns → Crate dependency direction; §Cross-cutting Patterns "Tokio containment").
- `--record` of the re-probe writes the dialog fixtures only when 0 rows fail and passes the scrub. An unclean recording is refused whole, naming the file and code only (per architecture §Occupied Resources → Repository).
