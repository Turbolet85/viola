@extract_section name=constraints
- The workspace member set and the sync/Tokio split stay as they are: the removal deletes files and cfg arms inside the existing crates (`viola`, `viola-core`, `viola-pty`, `viola-channel`, `viola-state`, `viola-agent-claude`, `viola-mcp`, test-only `viola-e2e`), adds or drops no member, and among the product crates only `viola-mcp` still enables `tokio` (per architecture §Established Decisions [Module Boundaries]).
- Crate dependency direction requires the Windows-only edges to leave with their code: windows-sys in `viola-pty`, `viola-channel` (the SQOS open and the listener DACL), `viola-state` (the `strict` DACL check, `create_private_dir`'s protected DACL) and the root bin (`src/run/env.rs`, `src/panic_frames.rs`, `src/cmd/verify/stop.rs`, `src/human/style.rs`), plus the root's `[target.'cfg(windows)'.dev-dependencies]` windows-sys; the Unix-only libc edges become unconditional, and no new edge is added (per architecture §Infrastructure Patterns → Crate dependency direction).
- Build system requires `deny.toml` (and `deny-sync.toml`) to keep every licence, source, C-build, telemetry and feature ban; both are evaluated today for the Windows, macOS and Linux triples, so whether those triples narrow to Linux is P4's decision against the amendment, and whether the Windows deny entries named in the scope exist is research's question (per architecture §Infrastructure Patterns → Build system).
- CI/CD approach requires the Linux jobs of `ci.yml` (`test`, `perf`, `msrv`, `fuzz-replay`, `lint`, `release`, `supply-chain`) to keep their steps, gate order and least-privilege rules (`permissions: {}`, SHA-pinned `uses:`, values through `env:`), while the matrix legs `windows-2025` and `macos-latest`, the Windows-only `ConPTY vendor verification` step and `windows-mutants.yml` leave; the plan records `nightly.yml` as two ubuntu jobs, so whether it holds any Windows or macOS job is research's question (per architecture §Infrastructure Patterns → CI/CD approach).
- The OS-gated test census `tests/contract_os_gated_tests.rs` fails both ways, so each removed gate's `GATES` row must leave in the same change; whether the census is re-pointed at the remaining `unix` gates or retired with them is P4's decision (per architecture §Cross-cutting Patterns → OS-gated tests).
- Occupied Resources lists Windows-only resources that lose their code: the named pipe `\\.\pipe\viola-<h12>` and the test pipe `viola-test-sqos-*`, `bin/<version>-<hash>/conpty/` companions, `vendor/conpty/`, `target/conpty-seed/`, `<repo parent>/viola-mutants-scratch/`; the Linux socket row (`<socket dir>/viola-<h12>.sock`, 0700 dir, 0600 socket, same-euid peers, no abstract namespace) stays unchanged (per architecture §Occupied Resources).
- Linux contracts do not move: the exit codes `0, 1, 2, 10-14, 20, 21`, the `RefusalReason` set and the closed code words (the `batch-script-child` exit-1 code included) stay as they are, and any wording change about a removed OS is P4's decision against the amendment (per architecture §Conventions).
@extract_section name=patterns
- Contract binaries pair a table with a census and a planted self-check (`tests/contract_os_gated_tests.rs`, `tests/contract_windows_mutation_scope.rs`); the second keeps `windows-mutants.yml`'s file lists equal to the `cfg(windows)`-gated sources, so it leaves with that workflow (per architecture §Infrastructure Patterns → CI/CD approach).

The orphans probe writes a `cfg(windows)`/`cfg(unix)` file-pair control into `target/orphans-probes/`, so whether that probe text counts against "no `cfg(windows)` left in the tree" is research's question (per architecture §Occupied Resources).
- The pre-push gate already runs on Linux only (`pre-push-linux-only` elsewhere) and replays the ubuntu `test` job's `run --coverage` and `gate --require coverage,doctest`, so it is the template for "every gate green on Linux" (per architecture §Infrastructure Patterns → CI/CD approach).
- The relied ledger set is per OS through `relied_on(WRAPPED_HERE)` (24 rows on Unix, 21 on Windows); removing the Windows arm must leave the Unix set of 24 unchanged (per architecture §Cross-cutting Patterns → Capability ledger).
@extract_section name=anti_patterns
- No Linux-only shortcut while the cfg arms are collapsed: nothing shells out through `sh`/`bash` except `hook statusline`, child processes stay direct spawns, and no Linux abstract-namespace socket name is used (per architecture §Cross-cutting Patterns → Cross-platform discipline; §Occupied Resources).
- No `tokio` reaches the sync crates' normal graph; the sole-root `deny-sync.toml` loop and `scripts/channel-tokio-free.sh` stay, even though the per-OS `cargo check` of the sync crates shrinks to Linux (per architecture §Established Decisions [Concurrency / Backend Framework]).
- The chunk does not edit the masters itself: the architecture amendments (D3 "every OS a target", the Windows-first live truth in §Design Philosophy, Cross-platform discipline, §Inherited Defaults CI, the per-OS rows, and the facts that name "Windows-only live measurements" as their owner) are the wrap's to write. The plan only names them as expected amendments (per architecture §Design Philosophy).
