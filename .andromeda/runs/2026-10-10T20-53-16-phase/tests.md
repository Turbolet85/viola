Every statusline payload a test feeds embeds the fixed content canary from `tests/support` (per test-plan §6 Non-path suites → Error sanitization and secret scan, Canary); whether the existing statusline helpers already embed it is research's question.

A gate evaluated at start therefore appends exactly one `budget-gate` as record two, whatever its `paused` value; a second start-time append breaks every booted session.

That key reads the flag AND a `reason:"statusline-source-unresolved"` refusal as owed to this entry while stating the refusal's premise is gone; the scope adds no refusal, and a new `boot` reason value needs a Decisions Log entry (per test-plan §3 Closed enums) — the tension is P3's to close. Whether a default boot can imply `--ui` before the UI surface is built is research's question.

## Patterns to follow
- Path 6 in its harness-session form is a `crates/viola-e2e` scenario on the rstest `harness_session` fixture (its Cleanup line is "harness `cleanup`"): the test calls `session.cleanup()` and asserts no field `false`, the session id is `<test name>-<label>-<pid>`, and no test shells out to `agent-run` (per test-plan §3 `run`, step 2). Whether `harness_session` exists at HEAD or the library `boot` still spawns `supervise` is research's question. The file is `tests/path_<topic>.rs`, the function `path6_<slug>`; `viola-e2e` carries no `[dev-dependencies]`, so its table-driven cases are a labelled case table in one `#[test]` (per test-plan §4 Unit Test Strategy, Conventions).
- Root cases follow the chain `home → fake_agent_path → stamped_home → booted_wrapper` and the shared helpers in `tests/support/` (`events`, `wait_events`, `Running`, `Ran`, the complete-lines ndjson reader); no root test file outside `tests/support/` defines its own copy of the reader, the wait, the guard or the result struct (per test-plan §2 Test Strategy, Test directory + naming conventions).
- Time goes through the product's own seam: mock_instant global mode or the injected `viola_core::Clock` for `budget_override_until`, and `chrono::Utc::now()` read only through the clock seam, so the gate's comparison of now against `resets_at` and against the override's end is unit-drivable (per test-plan §8 Mocking & Stubbing Discipline, What to mock → Time).
- Waits key on an `events.ndjson` byte offset or a status field, never a timer: a test that feeds a reading waits for the `budget-gate` record the next evaluation point appends (per test-plan §2 Test Strategy, Agent-runnable invariants → Deterministic). Path 6's fed values are fixed literals; randomised `rate_limits` / `resets_at` inputs stay in the Property suite (per test-plan §6 Scenario: Path 6 — budget governor, step 2).
- The `revive` refusal is asserted in the shape root `tests/cli_revive.rs` uses: exit 1, one `process-exit` line (`subject` `self`, `exit_code` 1) with the closed detail in `run-<name>.ndjson`, one `unable:` line and one `hint:` line last, hints distinct, none naming `viola release`, no `--json` document (per test-plan §6 Non-path suites → Exit-cause matrix, Exit 1 `revive` refuses to start). The plan requires that `process-exit` line on the start arm (also per test-plan §5 Integration Test Strategy, Cross-module patterns → On-disk, strict-modes refusals); with the check moved ahead of the log's opening, whether that line can still be written, or the plan's signal must be restated, is research's question.

## Anti-patterns to avoid
- NEVER assert a threshold, clock or refusal-order case at E2E that §4 can hold, and NEVER use `MockClock` or any in-process clock to move a spawned `viola run`'s time; cross-process expiry is the §4 unit case (per test-plan §11 Test Anti-Patterns → Test Strategy; → Universal).
- NEVER hand-write `budget.json` or `snapshot.json`, and NEVER import the product's refusal ordering, thresholds or exit codes as the oracle: 90, 85, exit 11, `five-hour` / `seven-day` and the order are literals in the test, compared as the serde kebab-case value and the integer exit code, never a `Debug` string (per test-plan §11 Test Anti-Patterns → Test Data; → Unit).
- NEVER treat a green fake-agent run as proof of real-CLI behaviour, and NEVER run the real `claude` in CI: the fake agent's rehearsal of `rate_limits` proves the gate's logic, not the payload shape on a live CLI (per test-plan §11 Test Anti-Patterns → Test Strategy). The plan itself classes real Anthropic-side usage values as untestable (per test-plan §1 Test Scope Summary, Entity: budget data source).
