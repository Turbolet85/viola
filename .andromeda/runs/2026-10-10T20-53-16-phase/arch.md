## Constraints
- Placement: the governor (the gate's state, its three evaluation points, the `release --budget` handling) belongs to the root bin's `src/run/` and consumes only normalised events and `viola-core` types; the `budget.json` reader belongs to `viola-state` beside the landed writer; a new refusal detail, event kind or event data key is added only in `viola-core`; no Claude payload shape is read outside `viola-agent-claude`, which stays pure (per architecture §Infrastructure Patterns → Crate dependency direction, and → Project directory structure). Where the pure decision function sits (root bin or `viola-core`, beside the `Clock` seam that key lists) is research's question; either way it adds no viola-crate edge to `viola-core`.
- Gate semantics: architecture §Established Decisions [Budget Governor] requires the gate to be evaluated from `budget.json` under its lock sibling at exactly three points (start, a `send`'s arrival, each `turn-ended`), never by a poll; a crossed threshold, a passed `resets_at` or an expired override takes effect, and `budget-gate` is appended, only at the next of those points; the override is per instance and lasts to the crossed window's `resets_at`; a plain `release` lifts no pause; no reading at all never blocks. The same decision is silent on two cases the scope raises (a `release --budget` with no pause standing; a pause whose crossed window's `resets_at` is `unknown`): nothing is extracted for them, they are research's read of the other masters, else a P4 question.
- Refusal: architecture §Conventions (Error handling schema) fixes `budget-paused` with the closed details `five-hour` · `seven-day` as a channel refusal result, never a protocol fault, and fixes its place in `send`'s order (after `human-typing`, before `turn-running`); the second read after the readiness gate's wait names `human-typing` and `turn-running` only, so that section requires no second budget read there. Architecture §Conventions (CLI exit codes) binds it to exit 11. Architecture §Established Decisions [Human Takeover / Wheel] requires that it gates `send` only, never `hook.dialog` or `answer`, and that `release --budget` leaves the wheel and the running-turn state as they are.
- Wire shapes: architecture §Standard Contracts requires `release`'s params and `ok` payload as its Channel methods list gives them (a non-bool `budget` and any string `from` stay `-32602`), the `budget-gate` data keys and its two `window` words as the event list gives them, the wrapper's append of `budget-gate` once at start and on every change as log-only and never waking `wait`, and the instance snapshot's `budget_paused` / `budget_override_until` written only by the wrapper and recoverable by the replay from the last `budget-gate` line. The scope's inferred override end in `release --budget`'s machine result is a field that payload does not name today: per architecture §Conventions (Interfaces and versioning) an added field is additive with no `v` bump, and the contract line is the wrap's to amend if the plan takes it.
- Thresholds: architecture §Cross-cutting Patterns (Config management) requires them as `Percent` in `config.json` with the stated defaults, parsed tolerantly, with no environment variable or flag as a configuration channel; architecture §Occupied Resources (viola home, `config.json`) requires the `MAX_FRAME` cap, `v` = 1, and an unusable file or value falling back to the default with one `parse-rejected{parser:"config-json"}` line, which is the plan's answer to what an out-of-range threshold becomes. Architecture §Conventions (Data model conventions, Percentages) requires the reading's `used_percentage` to stay a `Reading<f64>`, not `Percent`, so the comparison crosses two types and an `unknown` reading never compares.
- `viola revive` order: architecture §Occupied Resources (viola home, the instance files) names this entry as the owner of the start arm's log-before-check order and states the mechanism as read in source, not measured on `revive`; architecture §Conventions (CLI exit codes) requires the preflight's four readings in a fixed order with `strict-modes-failed` first, each refusal one `unable:` / `hint:` pair plus one `process-exit{subject:"self", exit_code:1, detail}` line in `run-<name>.ndjson`. Whether the code can still write that line once the check precedes the log's opening, and whether the present order really passes a widened home, are research's questions.
- Capability ledger: architecture §Cross-cutting Patterns (Capability ledger as the single gate) requires a ledger row with a `viola verify` probe for the `rate_limits` shape and names this entry as where it is owed; architecture §Established Decisions [CLI Version Compatibility] lists it as unrowed today. The row and its probe may live only in `viola-agent-claude`. The scope holds both behind the founder's word: the plan's requirement and that hold meet on the review card, and this extract settles neither.

## Patterns to follow
- The wheel's shape for a gate held in the wrapper: the decision in memory under one lock, each change's event, snapshot update and span on a worker, every snapshot write through the one in-process holder, and `pause` / `release` answered only after the change's record has landed (per architecture §Established Decisions [Human Takeover / Wheel]; architecture §Standard Contracts, Channel methods). Whether `release --budget` must likewise wait for its `budget-gate` record is not stated there: research's question.
- The landed `budget.json` discipline for its new reader: the same lock sibling, the `MAX_FRAME` bound, the versioned-tolerant read of a viola format with `v` (unknown fields skipped and counted, never `deny_unknown_fields`), and `"unknown"` for a window or field that does not parse (per architecture §Occupied Resources, viola home, `budget.json`; architecture §Established Decisions [Validation]; architecture §Conventions, Data model conventions).
- The statusline arm's landed order (canonicalise, instance check, then the log) as the model for `revive`'s fix (per architecture §Standard Contracts, Hook contract). That passage states what a refused check leaves undone but not whether the arm still opens its log afterwards: the one-invocation hypothesis is research's measurement, and the passage is the wrap's to amend from what it shows.
- Test isolation by home: each case in its own `--home`, the statusline source planted as `<home>/statusline-source.json`, the fake agent's `statusline-echo` mode as the command (per architecture §Established Decisions [CI/CD]; architecture §Occupied Resources, viola home and the test-only binaries).
- Human lines for `release` in the root bin's one human-text module, `--json` as the machine form, a typed exit per refusal (per architecture §Infrastructure Patterns → Project directory structure; architecture §Established Decisions [CLI Conventions]).

## Anti-patterns to avoid
- No poll, timer thread or runtime for the gate: std threads and blocking I/O on the `run` and `send` paths, evaluation at the three points only (per architecture §Established Decisions [Budget Governor]; architecture §Cross-cutting Patterns, Tokio containment).
- No effect on the human or on a running turn: no human key blocked, refused or delayed, no dialog or `answer` gated, and nothing decided for the driver beyond the typed refusal (per architecture §Design Philosophy; architecture §Established Decisions [Human Takeover / Wheel]).
- No new channel method, subcommand, flag or environment variable, and no `config.json` key beyond the two thresholds: the channel method list and the CLI flag list are closed as written, and `--budget` already exists (per architecture §Conventions, Interfaces and versioning and Naming patterns; architecture §Cross-cutting Patterns, Config management).

## Acceptance criteria contributions
- The gate, its evaluation points and the `release --budget` handling live in the root bin's `src/run/`, the `budget.json` reader in `viola-state`, any new closed-set word in `viola-core`; no new viola-crate edge, no Tokio in a sync crate, no Claude shape outside `viola-agent-claude` (per architecture §Infrastructure Patterns → Crate dependency direction).
- An automated `send` over a threshold is answered as the channel refusal result `budget-paused` with detail `five-hour` or `seven-day`, client exit 11, ordered after `human-typing` and before `turn-running`; `answer` and `hook.dialog` are not gated (per architecture §Conventions, Error handling schema and CLI exit codes).
- `budget-gate` is appended by the wrapper once at start and then only on a change taken at a `send`'s arrival or a `turn-ended`, with only the keys its event contract names, never waking `wait`; the snapshot's `budget_paused` / `budget_override_until` match the last such line, and a replay recovers both (per architecture §Standard Contracts, the event data list, Instance snapshot and the replay paragraph).
- A `viola revive` over a group-writable home is refused `strict-modes-failed`, exit 1, with no child started and its one `unable:` / `hint:` pair (per architecture §Occupied Resources, viola home, the instance files; architecture §Conventions, CLI exit codes).
