## Relevance
partial — the chunk builds no web-spa surface (the ATIS `budget-paused` cell and the board cell are other entries'); it touches the cli surface (the `send` refusal `budget-paused`, the `release --budget` human line, the `viola revive` refusal pair) and the tui boundary (the gate must leave the human's keys and the terminal stream alone), where a11y-plan holds output-discipline and boundary assertions with no WCAG conformance claim.

## Constraints
- a11y-plan §1 A11y Scope Summary (A11y tier; Surface: cli) requires that cli and tui carry output-discipline and boundary assertions only: no WCAG conformance claim rests on any test this chunk adds, and no a11y tool is introduced for a terminal surface.
- a11y-plan §8 Cognitive Accessibility → Error recovery requires every human-mode CLI refusal to be `unable  <reason>  <detail>` on stderr, then `hint:` as the last stderr line, with a typed exit code, and `--json` to give one document with no hint text. The `budget-paused` refusal (detail `five-hour` or `seven-day`, exit 11, inside the plan's `10`–`14` range) takes that form. Whether the code already prints a hint line for `budget-paused` is research's question: the reason word has no producer today (scope item 3).
- a11y-plan §8 Cognitive Accessibility → Plain language requires that a kebab-case reason or detail code never appears without the plain word `unable`, that no stack trace or bare number is the only error text, and that trycmd pins every fixed CLI string. That binds `budget-paused` / `five-hour` / `seven-day` on the refusal and the fixed words of the `release --budget` human line.
- a11y-plan §1 A11y Scope Summary (Surface: cli, Notes) requires CLI output to be static and linear, with colour only a second cue and no SGR, glyph or cursor control under `--json`, non-TTY, `NO_COLOR` or `TERM=dumb`. That binds the `release --budget` human line and the `budget-paused` refusal lines.
- a11y-plan §6 Visual Design Verification → State color tokens (not-color-alone), CLI equivalent, requires that `unable` is never coloured and that viola's SGR is limited to the three named words (`DIALOG`, stale rows, NAME values): the budget state on the CLI is carried by its printed words, never by a new SGR.
- a11y-plan §1 A11y Scope Summary (Critical paths 4; Entity: `viola run` TUI passthrough) requires that human keystrokes are never blocked, refused or delayed past the current atomic paste and that viola writes zero bytes to the terminal except the child's output. The gate's three evaluation points (start, a `send` arriving, `turn-ended`) and its refusal fall on automation only and write nothing to the terminal; the same boundary binds a start a passed `viola revive` made.
- a11y-plan §1 A11y Scope Summary (Entity: CLI verbs) requires each exit-1 refusal of `viola revive` to be one `unable:` line and one `hint:` line last on stderr, with no ESC byte. Moving the instance check ahead of the log's opening (scope item 7) must keep that pair for `strict-modes-failed`. Whether the refusal as printed today survives the reorder unchanged is research's question.

## Patterns to follow
- The refusal layout pinned per refusal by trycmd, the typed exit codes checked by assert_cmd, both on all three OS legs (a11y-plan §8 Cognitive Accessibility → Error recovery, Verification, cli). The `budget-paused` case joins that set beside `human-typing`.
- The `viola revive` refusal form pinned by the root cases in `tests/cli_revive.rs` (a11y-plan §8 Cognitive Accessibility → Error recovery, CLI): the home-mode witness of scope item 7 is a case of that file's shape and asserts the same two-line pair.
- The three portable-pty outer-PTY boundary cases, one per clause (zero viola-originated bytes across start, a driver `send`, a refused automation send and exit; human keys delivered unblocked; focus / mouse / resize not moving the wheel), sequenced on logged records and never on a timer (a11y-plan §3 Keyboard test harness → Tooling; a11y-plan §4 ARIA Patterns & Roles → P4, tui). The plan names `human-typing` as the refused send in the zero-bytes case and names no budget-specific case: whether a `budget-paused` refusal is already covered by the existing cases, or needs a leg of its own, is research's question.
- CLI output-discipline checks run inside the per-OS `test` job's instrumented `coverage` suite and report through the harness `run` JSON as nextest results (a11y-plan §9 CI Integration, Unit / integration stage). No new suite, step or artifact.

## Anti-patterns to avoid
- NEVER block, refuse or delay a human keystroke in `viola run`, or in a start a passed `viola revive` made, past the current atomic paste (a11y-plan §11 A11y Anti-Patterns → Keyboard). A paused gate that held a human key would break it.
- NEVER show an error without a recovery suggestion: every human-mode CLI refusal except `unknown` (exit 14) ends with a `hint:` line (a11y-plan §11 A11y Anti-Patterns → Cognitive). A `budget-paused` refusal with no hint is banned; a Problem URN, stack trace or bare status as the only error text is banned in the same subsection.
- NEVER colour CLI `unable` / `fail`, and never emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run` / a passed `viola revive` (a11y-plan §11 A11y Anti-Patterns → Visual). NEVER claim WCAG conformance for the cli or the wrapper-hosted TUI from these cases (a11y-plan §11 A11y Anti-Patterns → Strategy).
