## Constraints
- The live proof (send a pipeline skill, wait, read the final text, answer a review, `/clear` between skills, a terminal key taking the wheel) is that chunk's own local measurement, kept in its `evidence/` with its own launcher, driver and readers: not a test layer, not harness surface, never in CI (per test-plan §6 E2E Test Strategy, "Skipped as untestable": the real `claude` CLI). It may not be turned into a suite case, a harness command or a CI step (per test-plan §11 Test Strategy, the real-CLI ban).
- A green fake-agent run is no proof of real-CLI behaviour, and a Linux-only run is no proof for Windows or macOS: the switch's readings on claude 2.1.296 (or 2.1.287) on the Linux dev host stand for that version and that host alone (per test-plan §11 Test Strategy).
- A product defect the switch exposes is fixed with a regression case at the lowest layer that can hold it — parser, refusal-order, threshold and clock cases in §4 unit, contract shapes in §5, cross-process behaviour only in §6 E2E (per test-plan §11 Test Strategy, the pyramid ban; test-plan §2 Test Strategy, pyramid table). A behaviour change to the fake agent needs a local `viola verify` fixture refresh plus the contract suite, so the fake agent does not drift from the real CLI (per test-plan §11 Test Strategy).
- If `viola verify` is run against the builder's CLI version (2.1.296 has no stamp; whether the plan stamps it or keeps the builder on 2.1.287 is the founder's fork), it runs local-only — through `agent-run run --local-live`, which refuses under `CI` (exit 2 `live-in-ci`), or as the chunk's own live step (per test-plan §3 `run` (`--local-live`)). Fixtures it records under `fixtures/claude/<version>/` must be scrubbed and pass the hygiene walk and its schemas, and a dirty payload refuses the whole recording (per test-plan §7 Test Data & Fixtures, Fixture hygiene).
- Zero flakiness: the WATCH case (`send_budget_paused_is_refused_with_the_window_word_and_no_cursor` case_4) gets no retry, no `#[ignore]`, no nextest `retries` above 0. If it reads red during this chunk, the chunk stays red until its root cause is fixed inside the chunk (per test-plan §10 Quality Gates & Coverage Targets, Zero-flakiness budget).
- Stamps, snapshots and `budget.json` in any test this chunk adds come only from their writers (`viola verify` against the fake agent, the wrapper, `viola hook statusline`), never hand-written; every test makes its own tempfile `--home` (per test-plan §11 Test Data; test-plan §7 Test Data & Fixtures, Seed strategies).
- Coverage stays at the Comprehensive thresholds per OS — lines ≥ 85%, functions ≥ 95%, regions ≥ 80% — with the `--ignore-filename-regex` unwidened (per test-plan §10 Quality Gates & Coverage Targets, Coverage thresholds).

## Patterns to follow
- The earlier live-reading chunks' form: a local live measurement recorded in `evidence/` (e.g. `live-readings.ndjson`, `live-run.md`), quoted into the plan as "as measured … (a local live measurement, no suite)" beside the suite case that holds the same signal under the fake agent (per test-plan §6 E2E Test Strategy, Path 2 and Path 5 verification signals).
- The live signals v1-33 reads each have a fake-agent suite form already named in the plan: Path 2's `/clear` on a verified CLI confirmed by `session-start` with cause `clear` and a new session id (`send_clear_on_a_verified_cli_is_confirmed_by_its_new_session`); Path 3's `wait` / `last`; Path 4's `answer` by dialog id (permission / plan); Path 5's `wheel{holder:"human",cause:"human-input"}` and `release` (per test-plan §6 E2E Test Strategy, Paths 2–5). Whether the code already satisfies each on the switched builder is research's question.
- A defect fix's single case is run through the harness filter form: `scripts/agent-run.sh run --integration --filter 'test(/…/)'`, a root file through `binary(<stem>)`, an E2E-prefixed binary through `run --e2e --filter 'binary(…)'` (per test-plan §3 `run`).
- Test naming `<subject>_<condition>_<expected>`; root suites in `tests/{cli,hook,tui,channel,chaos,contract}_<topic>.rs` sharing `tests/support/` helpers, never a local copy of the events reader, wait or child guard (per test-plan §2 Test Strategy, Test directory + naming conventions).

## Anti-patterns to avoid
- No manual smoke step and no "human verifies" step in any test; the human-keyed takeover and the live answers stay in the chunk's evidence, never a suite step (per test-plan §11 Universal (agent-driven specific)).
- No `sleep(N)` for synchronisation and no screen parsing in any test this chunk adds: waits key on `events.ndjson` offsets or `viola wait --after`, verdicts come from events, channel payloads and receipts (per test-plan §11 E2E).
- No test that auto-approves a dialog or passes when a decision body is emitted without a verify stamp and wheel `driver` — this binds any fix around "answers a review" on an unstamped 2.1.296 (per test-plan §11 Universal (agent-driven specific)).
