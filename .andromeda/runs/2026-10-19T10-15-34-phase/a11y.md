# a11y extract

## Relevance
partial — the chunk adds no UI surface, but its live proof of v1-33 runs through a11y Path 4 (the human takes the wheel with a key typed into the session terminal; the next automated send is refused; `release` hands the wheel back) and through Paths 2, 3 and 6, the cli verbs the overseer drives. Every rule below binds that live reading and any defect fix the switch forces in `src/run/` or the cli verbs.

## Constraints
- a11y-plan §11 Keyboard requires that no human keystroke in `viola run`, or in a start made by a passed `viola revive`, is blocked, refused or delayed past the current atomic paste. This holds for the switched builder whichever verb restarts it. Focus, mouse and resize sequences and terminal replies never count as editing (per a11y-plan §11 Keyboard).
- a11y-plan §1 (Entity: `viola run` TUI passthrough) requires that viola writes zero bytes of its own to the terminal while the child holds it. Under a revive, the clause read by a case of its own is that a passed revive writes no line of its own. The switched builder's terminal therefore carries no `unable` / `hint:` / diagnostic text from viola, and diagnostics go to `diagnostics/` (per a11y-plan §1 Entity: `viola run` TUI passthrough).
- a11y-plan §4 P4 requires the takeover to be read on the cli side as `send` refused `human-typing` on stderr with a typed exit code (10). The refusal is written as `unable <reason> <detail>`, with `hint:` as the last stderr line, and `--json` carries no hint text (per a11y-plan §8 Error recovery).
- a11y-plan §8 Timeout extensions requires that the dialog hold (`dialog_hold_s`, 60–3600, PROVISIONAL bounds) bounds the driver only, never the human. Any human key hands a held dialog back at once, whatever the hold. At expiry the dialog renders for the human in the `claude` TUI, one `dialog-expired` line is appended, and a later `answer` is refused `not-delivered` / `unknown-dialog` (exit 13). That governs the CARRY's near-3600 s reading under the overseer's home (per a11y-plan §8 Timeout extensions).
- a11y-plan §8 Timeout extensions also requires that a verified `send` waiting in the readiness gate (`GATE_MAX_WAIT` 8.5 s), or in its confirm window (10 s; `/compact` 40 s PROVISIONAL), takes no key and delays none. A key pressed during the gate wait goes to the child and takes the wheel, and the waiting send is refused `human-typing` (per a11y-plan §8 Timeout extensions).
- a11y-plan §1 (Critical paths 3) and §4 P3 require that `viola answer` on an unverified CLI is refused `unverified-cli` in text on the cli. This is the visible form of the scope's fact that a builder on claude 2.1.296 with no stamp cannot have a review answered (per a11y-plan §4 P3).
- a11y-plan §11 Strategy forbids any WCAG conformance claim for the cli or the wrapper-hosted TUI. The live reading is an output-discipline and boundary stand-in, never conformance evidence (per a11y-plan §11 Strategy).

## Patterns to follow
- The live takeover reading of chunk 2026-10-08-first-live-test-and-self-drive (`evidence/live-run.ndjson`, its `takeover` line). A key is typed with `wtype` into the live session's own terminal window and writes `wheel{holder:"human",cause:"human-input"}`. The window's focus writes no `wheel` record. The next driver `send` exits 10 `human-typing` with one `hint:` line that does not name `release`, and no `send-issued`. This reading is supplemental and never gating (per a11y-plan §3 Keyboard test harness).
- Each step is sequenced on log records, never on a timer: the wrapper's `channel-request` line and the `wheel` record. The wheel can be probed by an `answer` to no pending dialog (exit 13 = driver, 10 = human) (per a11y-plan §3 Keyboard test harness).
- The overseer reads machine state through `--json` or the `viola mcp` tools. Those carry no SGR, glyph or hint text. Human-mode `wait` / `last` text has its C0/C1 controls escaped, with `\n` / `\t` kept raw (per a11y-plan §1 Surface: cli Notes; a11y-plan §4 P6).
- Human-mode refusals keep the `unable … hint:` layout, pinned by literal or trycmd. Any copy that a defect fix changes is updated on purpose with its pinned string (per a11y-plan §8 Plain language).

## Anti-patterns to avoid
- NEVER parse the rendered `claude` TUI screen for content, or take screenshots as evidence. The prototype's `scr.sh` / `out.raw` screen read (gap-list group 3) is not rebuilt in the product to serve the switch (per a11y-plan §11 Universal).
- NEVER count a window focus, mouse report, resize or terminal reply as editing, and never let a fix made for the switch block or delay a human key past the atomic paste (per a11y-plan §11 Keyboard).
- NEVER make a manual or live keyboard reading the only method: the live takeover supplements the automated P4 outer-PTY cases and does not replace them (per a11y-plan §11 Universal).

## Contract bindings
- a11y ↔ tests: the P4 boundary cases (zero viola bytes, keystrokes unblocked past the paste, focus/mouse/resize not moving the wheel, and the gate-wait case `send_under_the_paste_hint_a_human_key_during_the_gate_wait_wins`) run inside the per-OS `test` job's `coverage` suite under `gate --require coverage,doctest`. The live v1-33 record adds no `suite` value and no second driver (per a11y-plan §9 CI Integration; a11y-plan §11 CI).
- a11y ↔ obs: the takeover and the hold are read from log records, not from the screen: `wheel{holder,cause}`, `session-start{cause:"clear"}`, `dialog-expired` (`source: wrapper`, `{dialog_id, dialog_kind}`), and the absence of `send-issued` on a refused send (per a11y-plan §3 Keyboard test harness; a11y-plan §8 Timeout extensions).
- a11y ↔ design: the refusal copy (`unable` + kebab code + `hint:` last; none for `unknown`, exit 14) is design-system cli pattern 2 (per a11y-plan §8 Error recovery).
