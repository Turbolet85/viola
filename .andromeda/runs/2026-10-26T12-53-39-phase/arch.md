# arch extract

## Relevance
relevant — the chunk adds the explicit `viola link` / `viola unlink` verbs and their two channel methods. Those are a CLI surface, a channel-contract surface and a log/snapshot writer, and the plan names them all. The plan also still records them as held, so whatever lands means amending the plan at wrap.

## Constraints
- architecture §Established Decisions [Links] (detail `dec-links`) requires the following: the driven wrapper appends a `link` line only when the `driver → driven` pair is not already in its link set. An explicit `viola link` of an existing pair adds no line. `since` is the time of the first link after any `unlink`. `unlink` appends an `unlink` event. The snapshot's link set is derived by replaying the log, so the log stays the single source of truth. The same section records the explicit verbs as held: they are unbuilt until the founder's own word on the widening (the wrapper serving two more methods, the frame after the liveness-only pre-check, the snapshot read without strict-modes). So none of steps 12 to 15 is planned or built ahead of the P4 answer that names a form.
- architecture §Standard Contracts → Wrapper channel frames / Channel methods (detail `contract-channel-methods`) requires `link` and `unlink` to take `{driver, driven}`, be sent to the driven instance's wrapper, and carry `v` and `sender` in every `params`. The plan's result is `{}`, while the scope's owed result is `{since, already_linked}` for `link`. Whether the plan's `{}` is amended to the scope's shape (additive, no `v` bump per §Conventions → Protocol versioning) is a P3/P4 question. Bad params are `-32602` `invalid params` with `data: null`, never `-32600`.
- architecture §Standard Contracts → Instance snapshot (detail: the `links` item) requires the following: `links` is `{driver, driven, since}`, `since` being the `link` line's `ts`. The set follows the log: a failed append leaves it as it was, and a line that landed is in the set even if the snapshot write then fails. The `links` rewrite goes through `Snapshots::update` after the line has landed. A link that cannot be recorded answers `-32603`.
- architecture §Standard Contracts → Event `data` per kind requires `link` / `unlink` lines to carry `{driver, driven}` with `source: wrapper`. They are log-only and never wake `wait` (`EventKind::WAIT_WAKE` excludes them). The same section says no product path appends `unlink` until the `unlink` method is served (`LinkSet::remove`'s first caller).
- architecture §Standard Contracts → Session liveness (detail `contract-session-liveness`) requires every frame-writing client to take the liveness-only pre-check (`viola_state::liveness::live_endpoint`) and then, on Linux and Windows, the server check (`verify_server` / `ServerVerdict`) before its first frame. A mismatch or an unverifiable check writes no frame, and macOS is the recorded gap. The detail's client list (`send` … `hook.dialog`) does not yet name `link` / `unlink`. Whether the verbs' snapshot read also takes `viola_state::strict::check_instance` is the founder's P4 form, and how it is built is research's question.
- architecture §Conventions → CLI requires the verbs to be `viola link <driver> <driven>` and `viola unlink <driver> <driven>`: arguments mirror the channel `params`, flags are kebab-case long options (`--json`, global `--home`), and the CLI adds `from` from its own `VIOLA_NAME` when set. architecture §Conventions → CLI exit codes (detail `conv-exit-codes`) gives `20` for a wrapper protocol fault (the `-32602` / `-32603` replies) and `21` for an unreachable instance or failed server check. The detail names the server-verify exit-21 case for `send` … `release` only, so the verbs join it by amendment.
- architecture §Established Decisions [MCP] requires `link` and `unlink` to stay CLI-only, as human controls over the link topology. The MCP tools stay `send · wait · last · answer · list`.

## Patterns to follow
- The wrapper's `LinkSet` (`src/run/links.rs`: `restore`, `current`, `record`, `remove`) and the shared rule `viola_state::replay::apply_link_line`, both applied by the restore pass at start. The explicit methods reuse these rather than a second set or rule (per architecture §Infrastructure Patterns → Project directory structure, `src/run/links.rs` and `viola-state` rows).
- One module per subcommand under `src/cmd/`, with `link` and `unlink` already named in the tree, and trycmd human-mode cases under `tests/cmd/*.toml` (per architecture §Infrastructure Patterns → Project directory structure).
- The existing frame-verb client path: the liveness-only pre-check, then `client::connect`'s server check, with `--json` mirroring the channel `result` as `{"v":1,"ok":{…}}`. `instance-unreachable` / `wrapper-fault` go out through the shared document writers. The pattern is `send`, `pause` and `release` (per architecture §Standard Contracts → CLI `--json` output).
- The implicit link's recording discipline: a link that cannot be recorded answers `-32603` and changes nothing else, and the set is restored from the log at every start, a revived wrapper included (per architecture §Established Decisions [Links]).

## Anti-patterns to avoid
- No `link` / `unlink` MCP tool and no `release`-like driver affordance on the MCP surface (per architecture §Established Decisions [MCP]).
- No Tokio on the CLI or wrapper path: the verbs use `viola-channel`'s sync client (per architecture §Cross-cutting Patterns → Tokio containment). No `deny_unknown_fields` on the new `params` (per architecture §Established Decisions [Validation]).
- No Claude-specific shape, ledger row or `viola-agent-claude` change. A link is recorded from viola's own parameters, and new event kinds come only from `viola-core`, which already has `link` / `unlink` (per architecture §Conventions → Normalised event kinds).

## Acceptance criteria contributions
- On the driven wrapper: an explicit `link` of a pair already in the set appends no line, and a new pair appends exactly one `link` line `{driver, driven}`, `source: wrapper`. An `unlink` of a present pair appends one `unlink` line, and an `unlink` of an absent pair appends nothing. After a restart, the restored `links` equals the replay of those lines, with `since` the first `link` after the last `unlink` (per architecture §Established Decisions [Links]).
- A `link` / `unlink` frame whose `driven` is not the serving wrapper's name, or whose `driver` equals `driven`, or with params that fail `ViolaName` is answered `-32602` with `data: null`, appends no line and leaves the snapshot's `links` unchanged. The CLI maps it to exit 20 (per architecture §Conventions → Error handling schema).
- On Linux and Windows, `viola link` / `viola unlink` aimed at a server that is not the recorded wrapper write no frame and exit 21, printing `{"v":1,"error":"instance-unreachable","detail":null}` under `--json` (per architecture §Standard Contracts → Session liveness).
- The MCP server's `tools/list` still names exactly `send · wait · last · answer · list` after the chunk (per architecture §Established Decisions [MCP]).
