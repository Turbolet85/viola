# security extract

## Relevance
relevant — the chunk serves two new channel methods (`link` / `unlink`) on the local IPC boundary and adds two CLI frame verbs that read `snapshot.json` and write a frame; this is crossing (a) plus the strict-modes half (c) of the held widening.

## Constraints
- Serving a new channel method requires a Security Decisions Log entry that maps it to this plan's IPC controls (DACL / per-user socket dir, server peer check, frame cap, closed params). Answering `link` / `unlink` with something other than `-32601` is that kind of addition, so it waits for the founder's recorded word naming the verbs and one form (per security-plan §Security Anti-Patterns › Universal).
- Before the first frame of any method, a client must check the serving process: on Linux and Windows, the connected peer's pid and that process's start time against the snapshot's `pid` / `started_at`. A mismatch, or a check that cannot be made, writes no frame. The CLI frame verbs then exit 21 `instance-unreachable` (`--json` exactly `{"v":1,"error":"instance-unreachable","detail":null}`, stderr empty), with the `server-verify` hint in human mode. macOS stays the recorded gap. The plan's list of CLI frame verbs (`send`, `wait`, `last`, `answer`, `pause`, `release`) does not name `link` / `unlink` yet, so they would be added to it. Whether the verbs reach this check through the shared `client::connect` path is research's question (per security-plan §Authentication & Authorization, IPC client-side server verification).
- The server check must compare against a `snapshot.json` that passed strict-modes in the same process. The eight dated gaps that skip strict-modes cover only the frames they name, and "no other frame or process may borrow them". For the two verbs this leaves two options. Option one: they run the strict-modes check before the snapshot read (option 2 in the scope). Option two: they get a ninth dated gap of their own, the founder's word recorded and owed to "Home and code-bearing file integrity" (option 1 in the scope). They must never quietly ride `send`'s or `pause`/`release`'s gap (per security-plan §Security Anti-Patterns › Authentication).
- The plan names the strict-modes form that comes ahead of a snapshot read: `viola_state::strict::check_instance` on the home, `instances/`, the instance dir, `snapshot.json` and `events.ndjson`. It runs before any value of those files is used and before any log opens, because opening a log narrows an existing home and a later check would pass a home at 0770. A refusal opens no log, writes no line and leaves the home's mode as found. Whether this check can be taken for `link` / `unlink` alone, apart from the other eight clients, is research's question (per security-plan §Authentication & Authorization, `~/.viola/` access control).
- Channel frames: `link` / `unlink` run under the `MAX_FRAME` read cap, serde_json's default depth and the `v` check. The wrapper takes `driver` / `driven` through `ViolaName::try_new` before acting, and refuses bad params with `-32602`. CLI argument names go through `ViolaName::try_new` before any frame. No string from outside `ViolaName::try_new` is ever joined into `instances/<name>` (per security-plan §Input Validation, channel frames and CLI arguments rows; §Security Anti-Patterns › Input).
- `from` and the link record are self-reported and authenticate nothing. No refusal, permission or wheel decision may rest on the link set. Leaving `link` / `unlink` off the MCP tool list is an affordance, not an enforcement (per security-plan §Threat Model Summary, Local IPC vector and MCP vector; §Security Anti-Patterns › Authentication).
- External errors and results carry codes and closed words only. That covers CLI `--json` errors, the `-32602` `data` (`null` or a closed reason) and the three human result lines. None of them holds an absolute path, pid, start time, endpoint or anyhow / serde chain, and channel `-32603` stays `"internal error"` with `data: null` (per security-plan §Error Handling; §Bootstrap phases, `logging-redaction-wire`).

## Patterns to follow
- The CLI frame-verb client path the plan records for `send` / `pause` / `release`: a liveness pre-check through `live_endpoint`, then connect, then `verify_server`'s closed `ServerVerdict` before the frame. A refusal maps to the existing 21 / `instance-unreachable` shape and one `process-exit{… detail:"server-verify-failed", during:"connect"}` WARN line (per security-plan §Authentication & Authorization, IPC client-side server verification and its CLI refusal row).
- The instance check as `viola revive` and `hook statusline` take it: `check_instance` first, then the snapshot read, then the log. A `--json` refusal is a fixed `{"v":1,"error":"<code>","detail":null}` document (per security-plan §Authentication & Authorization, `~/.viola/` access control).
- Wrapper param checks shaped like `pause` / `release`: a wrong-typed or invalid param is `-32602` `"invalid params"` with `data: null`. The frame envelope types no method param, so a bad name reaches the method's `-32602` and never an envelope `-32600` (per security-plan §Input Validation, channel frames row).
- A logged link name read back from `events.ndjson` for a result line comes back as data under the reader's bounds (`MAX_FRAME + 1` per line, torn or unknown lines counted, the reader never writes). The scope's CARRY requires parsing it again through `ViolaName::try_new` before it is shown (per security-plan §Input Validation, own state files on read).

## Anti-patterns to avoid
- NEVER serve `link` / `unlink`, or say in a master that they are served, without the Security Decisions Log entry and the founder's own word on the widening (per security-plan §Security Anti-Patterns › Universal).
- NEVER write a `link` / `unlink` frame against a snapshot that skipped strict-modes by borrowing another frame's dated gap. Each gap is named per frame, and no other frame may borrow one (per security-plan §Security Anti-Patterns › Authentication).
- NEVER put an absolute path, pid, start time or endpoint in a `link` / `unlink` refusal, `--json` document or result line (per security-plan §Security Anti-Patterns › Logging).

## Acceptance criteria contributions
- `viola link` / `viola unlink` against an instance whose endpoint is served by a process other than the snapshot's `pid` + `started_at` write no frame and exit 21. Under `--json` the output is exactly `{"v":1,"error":"instance-unreachable","detail":null}` on stdout with stderr empty, on Linux and Windows (per security-plan §Authentication & Authorization, IPC client-side server verification).
- A raw-channel `link` / `unlink` gets `-32602` and appends no line in each of these cases: `driver` or `driven` fails `ViolaName::try_new`; `driven` is not the serving wrapper's name; `driver` equals `driven` (per security-plan §Input Validation, channel frames row).
- Under the instance-check form: with a group-writable instance dir or `snapshot.json`, the verb is refused before any snapshot value is used and before any log opens, and the home's mode is left as found. Under the dated-gap form: the plan's gap list and its §Security Anti-Patterns › Authentication bullet name the `link` / `unlink` frames as their own gap, with the founder's word recorded (per security-plan §Authentication & Authorization, `~/.viola/` access control).
- A Security Decisions Log entry mapping `link` / `unlink` to the IPC controls exists before the wrapper stops answering them `-32601` (per security-plan §Security Anti-Patterns › Universal).
