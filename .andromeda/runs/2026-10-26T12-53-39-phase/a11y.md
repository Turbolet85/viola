# a11y extract

## Relevance
partial. The cli surface binds only the human, plain and `--json` output of `viola link` / `viola unlink` and the `--help` `handoff:` row. The channel methods, `LinkSet` and the log lines are ipc-internal, which per a11y-plan §1 A11y Scope Summary is not-assertable. If the founder's P4 answer serves no verbs, nothing below applies.

## Constraints
- a11y-plan §1 A11y Scope Summary (scope-entities) names `link` and `unlink` among the CLI verbs that must be assertable in human TTY, plain (non-TTY / `NO_COLOR` / `TERM=dumb`) and `--json` modes. The assertions cover output discipline on text and streams only, and no WCAG conformance claim may rest on them.
- a11y-plan §1 A11y Scope Summary (scope-surfaces, cli) requires static, linear output with no spinner or redraw. It bans SGR, glyphs and cursor control under `--json`, non-TTY, `NO_COLOR` and `TERM=dumb`. It requires C0/C1 control characters to be escaped (`\n` / `\t` excepted). The three result lines (`link … since …Z`, `link … already linked`, `unlink …`) show logged link names, so they fall under this clause. Research has to answer two questions: does the `ViolaName::try_new` re-parse (the scope's second CARRY) already exclude every control character, and does an escape step still apply?
- a11y-plan §8 Cognitive Accessibility › Error recovery requires the following for every human-mode refusal of the new verbs:
  - stderr carries `unable  <reason>  <detail>` with `hint:` as its last line, and the exit code is typed;
  - under `--json` the output is one document, with no hint and stderr empty;
  - faults (`error: wrapper fault` / `error: internal error`) carry no hint.

  For the frame verbs' exit-21 server-verify refusal, the hint is fixed as `hint: the process on <name>'s endpoint is not its recorded wrapper; it was not contacted`. Under `--json` it is the `{"v":1,"error":"instance-unreachable","detail":null}` document. Research has to read whether the verbs' `-32602` answers (a `driven` other than the serving wrapper, `driver` = `driven`) already map to a CLI refusal with a hint.
- a11y-plan §8 Cognitive Accessibility › Plain language requires every fixed CLI string to be pinned by trycmd or by a literal, so that a copy change fails CI. It also requires every kebab-case reason/detail code to sit beside the plain word `unable`. The three result lines and every link/unlink refusal pair are new fixed copy under this rule.
- a11y-plan §4 ARIA Patterns & Roles (aria-landmarks) names the `--help` group labels as the cli's structural equivalents: board / traffic / wheel / handoff / setup. It assigns the `handoff:` row to "Explicit session links", and the `HELP` literal pins that row's output. a11y-plan §1 A11y Scope Summary (path-p6-board) repeats that the `handoff:` row joins with this entry.
- a11y-plan §6 Visual Design Verification bans viola's own SGR under non-TTY, `NO_COLOR`, `TERM=dumb` and `--json`, and requires any SGR to sit beside its word. It also requires that `unable` / `fail` are never coloured. Any styling of the link result lines on a terminal falls under this rule.

## Patterns to follow
- The `HELP` literal in `help_is_the_grouped_verb_table` and the served-set check `help_lists_only_served_verbs` (`tests/cli_output_plain.rs`) hold `viola --help` as plain ASCII over the served verbs only. Both are named in a11y-plan §4 ARIA Patterns & Roles (aria-landmarks) and §8 Cognitive Accessibility › Plain language.
- The server-verify refusal table in `tests/security_negatives_server_identity.rs` follows the a11y-plan §8 Cognitive Accessibility › Error recovery procedure. It is gated `not(target_os = "macos")`, uses the `HINT` literal and checks the six frame verbs in both modes:
  - human mode: the hint is the last stderr line, there is no ESC byte, and stdout is empty;
  - `--json`: the exact document, with stderr empty;
  - neither mode prints a pid, path or endpoint.

  Research has to read whether `link` / `unlink` should join its verb list.
- The `--json` refusal shape `{"v":1,"error":"<code>","detail":null}` (stdout only, stderr empty, no hint) and the `ok` document follow the `revive_json_*` cases and `plugin_install_refuses_a_widened_home`. These are cited in a11y-plan §8 Cognitive Accessibility › Error recovery.
- The no-ESC / no-lone-CR check in `tests/support/sgr.rs` (`redraws`) is applied to `viola wait` and `viola --help` per a11y-plan §4 ARIA Patterns & Roles (path-p6-board).

## Anti-patterns to avoid
- a11y-plan §11 A11y Anti-Patterns › Cognitive bans the following:
  - a human-mode refusal without a final `hint:` line (only `unknown`, exit 14, is exempt);
  - a kebab-case code without the plain word `unable`;
  - a stack trace as the only error text.
- a11y-plan §11 A11y Anti-Patterns › Visual bans colouring `unable`, and bans SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json`.
- a11y-plan §11 A11y Anti-Patterns › CI bans a new `suite` value (such as `a11y`) and any a11y driver outside `scripts/agent-run.* run`. The link/unlink output-discipline cases are ordinary nextest cases.

## Contract bindings
- a11y ↔ tests harness: the link/unlink cli cases run inside the existing suites, which in CI is the per-OS `test` job's `coverage` suite under `gate --require coverage,doctest`. They add no a11y artifact, and a failure surfaces only in `suites[].failures[]` (per a11y-plan §3 CI integration, and §3 Structured violation JSON schema: no a11y rows).
- a11y ↔ layouts: the `handoff:  link, unlink` row goes between `wheel:` and `setup:` (layout-templates §Output structure — `viola --help`). Its wording and order come from layouts. a11y binds the group-label structure and the pinned literal (per a11y-plan §4 ARIA Patterns & Roles).
- a11y ↔ design / security: the result-line copy is design cli's. The displayed link names are re-parsed through `ViolaName::try_new` under security's input validation. a11y binds only the C0/C1-escaped, SGR-free rendering (per a11y-plan §1 A11y Scope Summary).

## Acceptance criteria contributions
- (a11y) When the verbs are served, `viola --help` prints the `handoff:` row between `wheel:` and `setup:`. The `HELP` literal and `help_lists_only_served_verbs` move with it. The output stays plain ASCII with no ESC byte, and no row names an unserved verb (per a11y-plan §4 ARIA Patterns & Roles).
- (a11y) Each link/unlink result line and each human refusal pair is pinned by literal or trycmd. Each refusal reads `unable  <reason>  <detail>` with `hint:` as the last stderr line and a typed exit code. Under `--json` each is one document with no hint text and stderr empty (per a11y-plan §8 Cognitive Accessibility › Error recovery).
- (a11y) `viola link` / `viola unlink` output, results and refusals alike, carries no ESC/SGR byte when piped, under `NO_COLOR`, under `TERM=dumb` or under `--json`. A link name never reaches either stream as a raw C0/C1 byte. Checked on all three OS legs (per a11y-plan §1 A11y Scope Summary).
- (a11y) Off macOS, a link/unlink against an endpoint whose serving process is not the recorded wrapper exits 21. In human mode it prints the server-verify `hint:` last with stdout empty. Under `--json` it prints the exact `instance-unreachable` document with stderr empty. No output holds a pid, path or endpoint (per a11y-plan §8 Cognitive Accessibility › Error recovery).
