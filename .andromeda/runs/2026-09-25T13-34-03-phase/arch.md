# arch extract

## Relevance
relevant. The chunk lands the `viola-pty` seam, the first `viola-agent-claude` duties (R8 strip, shim resolution) and changes to the workspace, CI and build policy.

## Constraints
- architecture §Established Decisions [PTY] requires portable-pty `=0.8.1` behind viola's own seam (spawn · read · write · resize · wait · kill). Child exit must be read on the process handle, never on EOF. The `kill()` fallback is `TerminateProcess` on `child.process_id()` via windows-sys. 0.9.0 is excluded (wezterm#6783). An own ConPTY is allowed only after a measured defect the seam cannot absorb. The Stack "PTY layer" row pins windows-sys 0.61.2 for that fallback.
- architecture §Infrastructure Patterns → Crate dependency direction requires `viola-pty` to depend on no viola crate and know no agent. Its only third-party deps are portable-pty and windows-sys (Windows only). The same section has `viola-agent-claude` → `viola-core`, `viola-state`, serde_path_to_error, vt100. Research must answer whether creating `viola-agent-claude` now forces `viola-state` to exist, or whether a narrower first cut is allowed under §Established Decisions [Module Boundaries] ("each product crate is created by the first chunk that consumes it").
- architecture §Established Decisions [Agent Coverage] and §Inherited Defaults (Agent isolation) require the R8 `CLAUDE*` strip and npm-shim → `claude.exe` resolution to live only in `viola-agent-claude`, never in `viola-pty` or the root bin. §Established Decisions [CLI Version Compatibility] makes both of them capability-ledger rows. §Cross-cutting Patterns (Capability ledger as the single gate) forbids hard-coding either as an unconditional assumption.
- architecture §Established Decisions [Concurrency] and §Cross-cutting Patterns (Tokio containment) require the `run` path to use std threads and blocking I/O. `viola-pty` and `viola-agent-claude` are in the sync-crate target set. Per §Infrastructure Patterns → Build system (Dependency policy) and CI target job 3, each crate joins `scripts/sync-crates.txt` when it is created and is checked as sole root under `deny-sync.toml`.
- architecture §Cross-cutting Patterns (Diagnostic output channels) requires that while the child runs, `run` writes nothing to the terminal except the child's own output. Codes-only lines go to the home-level `diagnostics/run-<name>.ndjson`. Content-bearing detail goes only to `instances/<name>/diagnostics/detail-run.ndjson`. This is the architectural basis for "zero own bytes".
- architecture §Cross-cutting Patterns (Cross-platform discipline) requires that child processes are spawned directly, nothing shells out through `sh`/`bash`/`cmd`, and every OS-specific branch compiles and is tested on its CI runner. §Established Decisions [CI/CD] requires the program after `--` to be spawned as given, with shim resolution applied only when it resolves to the `claude` npm shim. The fake agent must never be rewritten.
- architecture §Infrastructure Patterns → Build system requires every third-party version to be pinned once in `[workspace.dependencies]` (portable-pty as `=0.8.1`). New members use `license.workspace = true`, `publish = false` and `[lints] workspace = true` (asserted by `tests/contract_lints.rs`). `cargo deny` must pass on all three target triples under the licence `allow` list. Per §Conventions (Rust error types), the new crates carry one thiserror enum each (`PtyError`, `AgentError`), and anyhow is not allowed outside the root bin.

## Patterns to follow
- The seam pattern: `viola-channel` wraps interprocess behind viola's own API, and `viola-pty` should wrap portable-pty the same way. The windows-sys dep goes under a Windows-only target table, as `viola-channel` already does for its SQOS open (§Crate dependency direction).
- Probe-proven gates: `scripts/deny-probes.sh`, `scripts/lint-probes.sh` and `orphans-check.sh --probe` each prove their gate fires on a planted fault and passes a clean control (§Infrastructure Patterns → Build system). The ripgrep-resilience witness in the scope should take the same form: the resilience path fires, and a sha256 mismatch still fails.
- `scripts/install-ripgrep.sh` fetches the official release asset, checks it against its published sha256 and exports it on `PATH` (§Infrastructure Patterns → CI/CD approach, Setup steps). Any retry or revocation-tolerance change must keep that verification.
- The orphans gate runs per lib/bin target from `cargo metadata --no-deps` on every `lint` leg (§Infrastructure Patterns → Build system, Boundary review). A cfg-gated kill-fallback module must pass it on all three legs.
- `ci.yml` has a `windows-2025` mutants leg because cargo-mutants reports another OS's `#[cfg]` bodies as missed (§CI/CD approach). Windows-only guards are judged by the union of the legs.

## Anti-patterns to avoid
- Putting agent knowledge (`CLAUDE*` names, shim shapes, `claude.exe`) in `viola-pty`, or putting a `tokio` dependency (even a transitive one) in `viola-pty` or `viola-agent-claude` (§Crate dependency direction; §Established Decisions [Concurrency]).
- Inferring child exit from PTY EOF, moving to portable-pty 0.9.x, or spawning through `cmd`/a shell (§Established Decisions [PTY]; §Cross-cutting Patterns, Cross-platform discipline).
- Writing any wrapper diagnostic to stdout or stderr while the child runs. The workspace `print_stdout`/`print_stderr` bans enforce this (§Cross-cutting Patterns, Diagnostic output channels; §Build system, Lint).

## Contract bindings
- arch ↔ security: the R8 strip list is a ledger row (§Established Decisions [CLI Version Compatibility]; §Occupied Resources → Environment variables). The stripped values must never reach a log, event, fixture or error body, which is the security never-log floor. The `.cmd`/`.bat` refusal is the security rule and matches §Cross-cutting Patterns (Cross-platform discipline, no `cmd` shell-out). A `deny.toml` advisory ignore brought in by portable-pty is a security-owned dependency-policy entry under §Build system (Dependency policy).
- arch ↔ obs: the `run` process-log destination and codes-only content (§Cross-cutting Patterns, Diagnostic output channels; the Stack "Logging" row). The line format and `log_child_exit`/`exit_source` vocabulary are owned by obs.
- arch ↔ tests: `supervise`, `tests/support/home.rs` `Wrapper` and the `run_cli` tests move to the PTY form. The fake agent is substituted after `--` without shim resolution (§Established Decisions [CI/CD]). Each test gets its own `--home` (§Cross-cutting Patterns, Config management).
- arch ↔ run start order: §Established Decisions [Session Liveness] fixes the order: collision check → pinned copy/plugin → version gate → endpoint bind → snapshot/heartbeat → start events → child spawn. §Occupied Resources → Environment variables says `VIOLA_NAME`/`VIOLA_DIR`/`VIOLA_BIN`/`PATH` are set by `run` in the child. §Established Decisions [Hook Contract] makes hooks exit 0 when `VIOLA_NAME` is absent. P3/P4 must decide whether setting `VIOLA_NAME` before any endpoint exists is admissible, given the scope's boundary of "no wrapper channel, no snapshot".

## Acceptance criteria contributions
- `crates/viola-pty/Cargo.toml` lists no viola crate and no third-party dep except portable-pty (from `[workspace.dependencies]`, `=0.8.1`) and windows-sys under a `cfg(windows)` target table. R8 and shim code sits only in `viola-agent-claude` (per architecture §Infrastructure Patterns → Crate dependency direction; §Established Decisions [Agent Coverage]).
- Every new product crate is listed in `scripts/sync-crates.txt`. It passes the sole-root `cargo deny --config deny-sync.toml --manifest-path crates/<crate>/Cargo.toml check bans` and the job-3 `cargo check` on all three OSes (per architecture §Established Decisions [Concurrency]; §Infrastructure Patterns → CI/CD target job 3).
- The wrapper's exit status comes from the child's process-handle `wait`, not from PTY EOF. Across a full run, the bytes on the wrapper's stdout equal the child's output and the bytes the child receives equal the human's input, with nothing added either way (per architecture §Established Decisions [PTY]; §Cross-cutting Patterns, Diagnostic output channels).
- The ripgrep install still refuses a sha256 mismatch after the resilience change, and `orphans-check.sh` passes on every `lint` leg with any cfg-gated `viola-pty` module (per architecture §Infrastructure Patterns → CI/CD approach, Setup steps; §Build system, Boundary review).
