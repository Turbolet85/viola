# a11y extract

## Relevance
Partial. This chunk builds no UI, ARIA, focus, contrast or motion surface, and it creates no a11y tests. It does build `viola-fake-agent`, which the a11y plan names as the driver for the TUI boundary cases, the CLI C0/C1 output-discipline cases and the web-spa state transitions. The a11y contribution is limited to making sure the fake agent's modes, receipts and fixtures can serve those later cases.

## Constraints
- a11y-plan §3 Keyboard test harness → Tooling and §4 P4 (tui) require a zero-viola-bytes case: with `viola-fake-agent` as the child, the outer-PTY stream across start, a driver `send`, a refused `human-typing` send and exit is compared byte for byte (Linux/macOS) against an unwrapped fake-agent run under the same outer PTY. So the fake agent's terminal output for a given script must be deterministic and independent of timing, and it must run both wrapped and unwrapped. Research should check whether any fake-agent diagnostics or receipt data reach stdout/stderr instead of the `--receipt` file.
- a11y-plan §4 P4 (tui clauses 2 and 3) requires proof that human keystrokes arrive unblocked past the current atomic paste, and that `\x1b[I`/`\x1b[O`, mouse and resize sequences do not count as editing. This chunk's receipt lines for keystrokes and bracketed-paste prompts (text, raw hex, `bare_esc`) are the observation channel for those future cases. They need to record byte-exact input per keystroke, including paste boundaries.
- a11y-plan §4 P6 (C0/C1 escaping; Decisions Log fix pass 3, Z3) requires two setups. `viola wait` / `viola last` must run against a fake-agent event whose text carries C0 and C1 bytes (including ESC / CSI). `viola list` must run against a `claude agents --json` fixture row carrying the same bytes plus `\n` / `\t`. The scripted turns and the `agents --json` modes (`FAKE_CLAUDE_AGENTS_MODE=recorded|oversize|malformed`) must be able to carry arbitrary control bytes without sanitising them.
- a11y-plan §3 Focus management test harness ("No focus theft") and §6 State color tokens require every web-spa transition (SSE arrival, cock/revert, readback refusal, `liveness-changed` stale, E4/E5 and so on) to be triggerable through the harness or fake agent, with waits on a DOM signal. The control-file gating (byte offset, no sleeps) is what lets a later spec trigger one transition at a time.
- a11y-plan §1 (tui entity is boundary-only) and §11 Universal ban parsing the rendered `claude` TUI screen for content (R7). Fake-agent observations belong in receipts, never in screen-scraped assertions.
- a11y-plan §3 Structured violation JSON schema (scrubbing) fails a11y artifacts that contain absolute filesystem paths or `CLAUDE*` strings. This chunk's fixture scrub walk (absolute paths, non-placeholder usernames) is test-plan-owned. It should agree with, and not contradict, a11y's path-leak notion for fixtures that later feed a11y specs.

## Patterns to follow
- a11y-plan §3 Keyboard test harness → Tooling: the fake agent is the reference child for outer-PTY comparisons. Keep its output a pure function of script plus input, so wrapped and unwrapped runs stay comparable.
- a11y-plan §11 SLO (no sleeps or `waitForTimeout`): gate on events and offsets. The chunk's byte-offset control file follows the same rule, so no timing-based waits should creep into the fake agent or fixtures.
- a11y-plan §4 P6: control-byte payloads are test data that must pass through the fake agent unchanged. Escaping is viola's job, not the child's.
- a11y-plan §3 Structured violation JSON schema: harness-only rows are ndjson with a version field, readers skip unknown fields, and there are no literal `null`s. This matches the chunk's inferred receipt `v` rule.

## Anti-patterns to avoid
- a11y-plan §11 Universal: never parse the rendered `claude` TUI screen for content and never use screenshots as evidence. Receipts are the channel.
- a11y-plan §11 Keyboard: never block, refuse or delay a human keystroke past the current atomic paste, and never count focus / mouse / resize sequences as editing. The fake agent's paste and keystroke handling must not add delays or merging that would hide such a regression.
- a11y-plan §11 SLO: no sleeps, retries or quarantine to make driven transitions pass.

## Contract bindings
- a11y ↔ tests: the fake agent (test-plan §7 binding contract) is the driver for a11y-plan §4 P4 (three portable-pty tui nextest cases on all three OS legs), §4 P6 (C0/C1 escaping with assert_cmd) and the web-spa `a11y-p*` transitions (§3 Focus management, §6 State color, §7 Live regions). a11y cases consume fake-agent modes and receipts; they do not redefine them.
- a11y ↔ tests: fixture scrub walk vs. the a11y scrubber (§3 Scrubbing). Both reject absolute filesystem paths, so their pattern sets should not diverge for shared fixtures.
- a11y ↔ obs: none in this chunk. a11y violation rows are emitted only from `e2e-web/fixtures/a11y.ts`, never by the fake agent or the viola binary (§3 Emission location, D-A11Y-09).

## Acceptance criteria contributions
- (a11y) A fake-agent script plus control sequence, run twice under the same outer PTY, produces byte-identical stdout, and receipt data never appears on stdout or stderr. This keeps the future zero-viola-bytes comparison valid (per a11y-plan §3 Keyboard test harness → Tooling; §4 P4).
- (a11y) A scripted turn and an `agents --json` recorded-mode row can each carry C0 and C1 bytes (ESC, CSI, plus `\n` / `\t` for the agents row) and emit them unchanged. A test checks the raw bytes (per a11y-plan §4 P6).
- (a11y) Receipts record each keystroke and each bracketed-paste prompt byte-exact (raw hex), including focus-in/out (`\x1b[I`/`\x1b[O`) sequences sent as input, so later P4 cases can assert delivery (per a11y-plan §4 P4).
