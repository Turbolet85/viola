## Constraints
- Moving the panic-line asserts (`main.rs:218` and `obs.rs:521`) into a shared helper must keep the assertion target unchanged. Per obs-plan §7 Panic hooks, the target is exactly one line with the key set `timestamp`, `level:"ERROR"`, `target:"viola::panic"`, `message:"panic"`, `event:"panic"`, `process`, `instance`, `panic_location`, `thread`. `corr` is never written, and `instance` is absent when unresolved (§3 Null encoding, D-26). The helper must not loosen this into a subset check.
- Moving the diag-detail validator loading (`main.rs:293` and `obs.rs:662`) into a shared helper must keep validating against `schemas/diag-detail.v1.json`, per obs-plan §8 Default-deny posture → Detail-file scope. That schema is self-contained with a top-level `unevaluatedProperties: false`, and the content fields allowed on detail lines stay exactly `panic_payload`, `backtrace`, `chain` and `drift_report`. The kept `LOG_FORMAT_EVENTS` clone is outside this, by operator decision (scope item 4).
- Per obs-plan §6 `detail` code catalog (`parse-rejected` → `oversize` for `channel-frame` beyond `MAX_FRAME`, D-31), the 16 MiB cap is an obs-visible boundary. A boundary witness at `src/obs.rs:195` (`file.take(MAX_FRAME)`) must not change what is logged when the cap is hit. What that read feeds, and whether it emits any `parse-rejected` line, is research's question.
- The fake agent's print exemption is a crate-level `#![allow(clippy::print_stdout, clippy::print_stderr)]` in `src/bin/viola-fake-agent.rs`, per obs-plan §3 Bootstrap phases → obs-ci-gate-wire and §11 Logs. When `main` is decomposed, that attribute must stay crate-level: a function-level allow on extracted helpers would be a different mechanism. `viola-e2e` keeps its own `[lints.clippy]` table without the print bans, and the CI member-list assertion must still name only `viola-e2e`.
- The `run.rs` split must leave the harness `logs`/`status` output byte-identical, per obs-plan §3 Snapshot / paste-to-AI integration. That covers the `{"src":"events",...}`, `{"src":"diag","file",...}` and detail `{"src":"diag","file","instance",...}` record wrappers, `{"torn":true,"offset":n}`, the `--instance/--kind/--process/--after` filters, and the detail-file glob `instances/*/diagnostics/detail-*.ndjson`.
- Any new or extracted helper in `tests/` or `viola-e2e` that starts a viola home must still put it under `target/e2e-home/`, per obs-plan §9 Pipeline integration (Integration tests row). Otherwise G2, G4, the secret scan and the `diag-<os>` upload stop covering it. Whether the extracted `cli_fake_agent.rs` helpers keep this is research's question.
- Obs code is under cargo-mutants like product code. Per obs-plan §9 Pipeline integration (Mutation row) and §10 Build / deploy failure conditions, a surviving mutant in obs code is a build failure. That applies to in-diff mutants in `src/obs.rs`, including any added by the `MAX_FRAME` boundary witness.

## Patterns to follow
- Tests emit through `obs_event!` only. Per obs-plan §3 Logging stack and §11 Logs, raw `tracing::{info,warn,error,debug,trace}!` is banned by clippy `disallowed-macros`, and raw `event!` outside `crates/viola-core/src/obs.rs` is caught by the fail-closed grep in `scripts/lint-probes.sh`. That grep covers every `*.rs`, test helpers included.
- `#[instrument]` is always written `#[instrument(skip_all, fields(...))]` with `skip_all` as the first argument. Per obs-plan §9 Gate commands, G1 scans the whole workspace (root, `crates/*`, `tests/`, `fuzz/`), so new helpers are covered.
- Unit-level log assertions use an in-memory `Vec<u8>` writer, parsed with serde_json and checked against the schemas, per obs-plan §9 Pipeline integration (Unit tests row). Shared helpers should keep that shape.
- Panic accounting counts home-level role files only and excludes `detail-*.ndjson`, per obs-plan §10 Zero unlogged panics → Counting rule. Any shared helper that counts panic lines must apply the same exclusion.

## Anti-patterns to avoid
- Never widen the print exemption to a product crate or code path while refactoring the fake agent or harness. Per obs-plan §11 Logs (print ban), the exemption belongs to `viola-harness` and the fake agent only.
- Never weaken a schema or key-set assertion to make a shared helper fit both call sites. Per obs-plan §11 PII Scrubbing (default-deny), any field outside the §6 catalog is a failure.
- Never use a bare `#[instrument]`, and never print/log with `?`/`%` formatting of `corr`, in extracted code. Per obs-plan §11 Spans / Traces and §11 Logs.

## Contract bindings
- obs ↔ tests §3 harness contract. The 5-command JSON documents and `logs`/`status` shapes that the `run.rs` split must preserve are the consumption path fixed in obs-plan §3 Snapshot / paste-to-AI integration. Tests owns the harness bodies; obs owns `schemas/diag-line.v1.json` and `schemas/diag-detail.v1.json` (§9 G4).
- obs ↔ tests (fake agent). The print exemption binds to the tests §3/§4 claim that the fake agent emulates the claude CLI on stdout/stderr, per obs-plan §3 obs-ci-gate-wire.
- obs ↔ security (`MAX_FRAME`). The 16 MiB `Read::take` invariant pinned by this chunk is security-owned. Obs's tie is the `parse-rejected{detail:"oversize"}` code in obs-plan §6 `detail` code catalog.
