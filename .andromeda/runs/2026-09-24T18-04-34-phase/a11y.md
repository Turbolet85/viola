# a11y extract

## Relevance
Partial. The chunk ships no UI, no new WCAG surface and no a11y tooling. It does refactor three things the a11y gates depend on: the harness `run` path (`run --browser` and the `suites[]` JSON), the `viola-fake-agent` driver behind the P4/P6 CLI/TUI output-discipline cases, and `tests/cli_fake_agent.rs`. This domain's only concern is that those gates stay unchanged.

## Constraints
- The a11y gate runs only through the tests' 5-command harness. `run --browser` invokes `npx --prefix e2e-web playwright test` and is followed by `gate --require playwright`. The run.rs split into `harness/` submodules must keep that command, its JSON document and its typed exits byte-identical (per a11y-plan §3 CI integration; §9 Pipeline integration).
- `run --browser` must still exit 2 with `reason:"browser-linux-only"` on the Windows and macOS legs. A missing Chromium must still fail as `browser-missing` and never count as a skip. Whichever extracted helper takes over this branch must keep both outcomes (per a11y-plan §3 CI integration; §9 Pipeline integration).
- The harness `run` JSON `suites[]` enum stays closed at `nextest-integration` | `nextest-e2e` | `coverage` | `playwright`. The split and helper extraction may not add a value (such as `a11y`) or rename one (per a11y-plan §9 Per-pipeline-stage table; §3 CI integration).
- The CLI output-discipline invariants (P4, P6) must keep passing on all three OS legs inside `nextest-integration` / `nextest-e2e` (CI: `coverage`), "under the tests' mutation gate where they live in crate tests" (per a11y-plan §10 Standard+ invariants). This ties into the chunk's 0-missed-mutants rule.
- The three P4 tui boundary cases run under the portable-pty outer PTY with `viola-fake-agent` as the child: zero viola-originated bytes, compared byte for byte against an unwrapped fake-agent run on Linux/macOS; keystrokes delivered unblocked; focus, mouse and resize sequences do not move the wheel. The P6 C0/C1 escaping case injects control bytes through a fake-agent event. So decomposing the fake agent's `main` must keep its output bytes and script semantics exactly the same. Any stray byte breaks the byte-for-byte comparison (per a11y-plan §4 P4, §4 P6; §3 Keyboard test harness → Tooling).
- Whether any P4/P6 output-discipline cases live in `tests/cli_fake_agent.rs`, or in the `#[cfg(test)]` modules of `src/main.rs` / `src/obs.rs` that are being de-cloned, is research's question. If they do, extracting shared helpers must keep each boundary clause as its own nextest case, not merge them into one assertion (per a11y-plan §3 Keyboard test harness → Tooling: "Each of the three boundary clauses is its own nextest case on all three OS legs").

## Patterns to follow
- a11y has one entry point, `scripts/agent-run.* run --browser`. There is no separate driver, no `webServer` and no `npm test:a11y` (per a11y-plan §3 CI integration). Keep that single path when splitting run.rs.
- The P6 non-TTY checks use assert_cmd / predicates / trycmd, and the TTY-only checks use the portable-pty outer PTY (per a11y-plan §4 P6; §9 Unit/integration row). Extracted test helpers should wrap these existing drivers, not add another.
- Timing keys on DOM signals and logged events, never on sleeps (per a11y-plan §10 Performance budget). Any shared wait helper pulled out of the fake-agent tests should follow the same rule.

## Anti-patterns to avoid
- NEVER add a `suite` value (such as `a11y`), a `webServer` or a separate driver outside `scripts/agent-run.* run --browser`. NEVER treat `browser-missing` as a skip, or run `--browser` on Windows or macOS legs (per a11y-plan §11 CI).
- NEVER emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run`, and never colour `unable` / `fail` (per a11y-plan §11 Visual). The fake-agent and harness refactors must not add output that the P6 streams would pick up.
- NEVER park a test with `#[ignore]` / `test.skip`, and never use retry-once (per a11y-plan §10 Cross-input parallel; §11 SLO). This applies to any fake-agent-driven test that goes flaky during the refactor.

## Contract bindings
- a11y ↔ tests §3 harness contract: the 5-command discipline and the `run` JSON `suites[]` shape carry the a11y verdict (`gate --require playwright`). The scope's "harness contract must hold unchanged" is the same obligation (per a11y-plan §3 CI integration; §9 Pipeline integration).
- a11y ↔ tests mutation gate: the P4/P6 invariants sit under the tests' mutation gate (per a11y-plan §10 Standard+ invariants). If run.rs's 154 viola-e2e mutants are pulled into `--in-diff` scope and some are on the `--browser` branch, killing them strengthens the a11y gate path.
- a11y ↔ tests `viola-fake-agent`: the P4 zero-viola-bytes baseline and the P6 C0/C1 injection both depend on the fake agent's exact output (per a11y-plan §4 P4, §4 P6).

## Acceptance criteria contributions
- After the run.rs split, `run --browser` on a Windows or macOS leg still exits 2 with `reason:"browser-linux-only"`, and a missing Chromium still yields `browser-missing` as a failure, not a skip. The `suites[]` enum is unchanged, with no new value (per a11y-plan §3 CI integration; §9 Pipeline integration).
- The P4 tui boundary cases (three separate nextest cases) and the P6 CLI output-discipline cases pass on windows, macos and ubuntu after the `viola-fake-agent` `main` decomposition. Whether these cases exist in code yet is research's question (per a11y-plan §4 P4, §4 P6; §10 Standard+ invariants).
- The fake agent's scripted output is byte-identical before and after the decomposition, so the Linux/macOS byte-for-byte outer-PTY comparison still holds (per a11y-plan §3 Keyboard test harness → Tooling).
