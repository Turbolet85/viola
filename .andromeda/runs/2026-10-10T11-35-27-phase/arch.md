# arch extract

## Relevance
relevant — a new CLI verb in the root bin that re-enters the `run` start order, adds a snapshot field, becomes the first reader of the log replay, and leans on CLI behaviours (`--resume`, `--fork-session`, `claude agents --json`) the plan gates behind the capability ledger. The plan names no `revive` subcommand, no `cwd` snapshot field, no revive refusal name and no fake-agent `--resume` option: each is a new resource this chunk lands and the plan records at wrap.

## Constraints
- **Start order and collision.** architecture §Established Decisions [Session Liveness] requires one fixed start order (program resolution → collision check → pinned copy and plugin → ConPTY sideload → strip plan → version gate → exclusive endpoint bind → first snapshot → heartbeat → start events → spawn), a start refusal for a name that is `live` or `stale`, and that a gone instance's directory is reused at once with its `events.ndjson` appended to, never truncated. Revive runs that order whole; `instance-live` is that refusal. `gone` is decided by the snapshot's pid + start time, never by the heartbeat alone (per architecture §Standard Contracts → Session liveness). Whether the landed `run` entry can be re-entered by a second verb without duplicating the order is research's question.
- **The snapshot field.** architecture §Standard Contracts → Instance snapshot lists the `data` keys and names the instance's wrapper as the only writer; `cwd` is not among them. architecture §Conventions → Protocol versioning makes an added field additive with no `v` bump, and architecture §Conventions → Data model conventions (Optional fields) requires `Option<T>` omitted on write with missing and `null` read alike. So `cwd` lands optional, `v` stays 1, and a snapshot from an older binary reads as having none. The same contract lists `agent_session_id?` in `data`, while the scope reads the landed struct as holding none: whether the code already carries that key is research's question, and it decides whether the snapshot arm can hand revive an id at all.
- **The replay.** architecture §Standard Contracts → Snapshot envelope requires that an unreadable or unsupported snapshot is replaced by a one-pass replay of `events.ndjson` with one `state-recovered` line, that an absent snapshot is neither replayed nor logged, that the replay writes no file, that it recovers only log-derived fields (`agent_session_id` from the last `session-start` carrying one) and that every field no event carries is absent, never a default. `cwd` is a field no event carries, so the replay arm yields none; on that arm liveness rests on the heartbeat alone and the endpoint is rebuilt by rule. The same section names this entry as the replay's first reader. It describes the last id only, not a chain: whether anything landed returns the `(ts, cause, id)` chain `--id` and `--list` need is research's question.
- **Log reads.** architecture §Established Decisions [Database / State Store] requires readers to count what they step over (`unknown_kinds`, `unknown_fields`, `torn_lines`), never return an unknown-kind line and never rewrite the log. A chain reader for `--list` / `--id` holds the same discipline, bounded by `MAX_FRAME` as the classified snapshot read is.
- **Exit codes are a closed set.** architecture §Conventions → Error handling schema (CLI exit codes) and architecture §Occupied Resources → Binary, subcommands and exit codes fix `0, 1, 2, 10–14, 20, 21`. `run`'s start refusals are exit 1 with a closed kebab `detail` and a fixed `unable:` / `hint:` stderr pair that names no path. The plan mints no number and no detail for `cwd-missing`, `session-live` or `no-session`; a new code is an amendment to both sections, so the plan must state which existing code each takes or which amendment it asks for. `RefusalReason` and its `detail` sets are channel outcomes extended only in `viola-core` (same §Conventions block); a preflight refusal that never reaches a wrapper is not one of them.
- **CLI behaviour is ledger-gated.** architecture §Cross-cutting Patterns → Capability ledger as the single gate requires every new dependence on an undocumented `claude` behaviour to be a ledger row in `viola-agent-claude` with a `viola verify` probe and a post-condition. `--resume <id>`, `--fork-session`, a SessionStart of source `resume` carrying the same id, and the `claude agents --json` `sessionId` join each fall under it. architecture §Established Decisions [CLI Version Compatibility] holds the ledger at seventeen rows that gate `cli_verified`, states that an added row needs its probe and a re-stamp of every stamped version (a verify is five `claude` starts), and places the `agents --json` join row with Epochs 4 and 5. A row added here changes what `cli_verified` means for every stamped home.
- **The child spawn.** architecture §Established Decisions [PTY] requires viola to resolve the child program to an absolute path itself and to set the child's cwd explicitly (as built: viola's current directory); architecture §Established Decisions [CI/CD] requires the `.cmd`/`.bat` refusal and the npm-shim resolution; architecture §Cross-cutting Patterns → Cross-platform discipline requires a direct spawn, never a shell. Revive's child cwd is the recorded `cwd`, a second source for the value [PTY] describes: how the spawn takes it (an explicit cwd on the spawn, not a process-wide change of directory the pinned-copy and home resolution would also see) is research's read of the seam.
- **What a start restores, and the wheel.** architecture §Established Decisions [Human Takeover / Wheel] requires the wheel to start with `driver` at every `viola run` start and keeps the running-turn state in memory only, so a restarted wrapper starts with no turn; architecture §Established Decisions [Message Broker / IPC] requires the `dialog_id` counter restored from `events.ndjson` so an id never repeats across restarts, and `last` rebuilt from the log at start. architecture §Standard Contracts → Event `data` per kind closes the `wheel` causes at `start` · `human-input` · `manual-pause` · `release`. A revive that starts at `human` departs from the first sentence and needs either an existing cause or an additive one in `viola-core`: that is the founder's open question, and the plan prices both against these two anchors without picking.

## Patterns to follow
- **One module per subcommand.** architecture §Infrastructure Patterns → Project directory structure puts each verb in `src/cmd/`, human-facing text in `src/human.rs`, and the wrapper's snapshot writes behind the one in-process holder `src/run/snapshot.rs`; architecture §Established Decisions [Snapshot writer] routes every replaced file through `viola_state::fs::replace_private`. The verb, its hint lines and the `cwd` write follow those three homes.
- **Claude shapes behind compiled names in one crate.** architecture §Infrastructure Patterns → Crate dependency direction keeps every Claude payload shape, `claude agents --json` included, in `viola-agent-claude` (pure, no I/O) with compiled constants such as `PLUGIN_DIR_FLAG`; architecture §Established Decisions [Agent Coverage] keeps the root bin on normalised events only. The `--resume` / `--fork-session` argv literals, the id-shape check and any `agents --json` parser follow it; the bounded spawn and file I/O stay in the root bin and `viola-state`.
- **The start-refusal shape.** architecture §Conventions → Error handling schema (CLI exit codes) gives the model: a `process-exit{subject:"self"}` with a closed `detail`, two fixed stderr lines, nothing written before the refusal where the order says so, and architecture §Established Decisions [CLI Conventions] adds human text by default with `--json` for agents (the `{"v":1,…}` document of architecture §Standard Contracts → CLI `--json` output). `--list`'s output and the four refusals take that shape; flags stay kebab-case long options and the verb a single lower-case word (architecture §Conventions → Naming patterns, CLI).
- **Fake agent by argv, one home per test.** architecture §Established Decisions [CI/CD] substitutes the fake agent after `--` and isolates each test in its own `--home`; architecture §Occupied Resources → Binary, subcommands and exit codes records the fake agent's options as argv only, no env. A `--resume <id>` mode is a new argv option of that test-only binary, recorded there at wrap.
- **Normalised assertion.** architecture §Conventions → Naming patterns (Hook → kind map) fixes SessionStart → `session-start` with `data.cause` in `startup · clear · resume · compact · unknown` and `data.agent_session_id`. The E2E reads the event line, never a raw payload.

## Anti-patterns to avoid
- **A CLI behaviour assumed without a row.** Hard-coding that `--resume` reopens the same id, or that `claude agents --json` exposes it, with no ledger row and no probe (architecture §Cross-cutting Patterns → Capability ledger as the single gate). Related: architecture §Established Decisions [Session Liveness] makes `claude agents --json` an enrichment whose absence, failure or parse error is never an error (architecture §Standard Contracts → Session liveness). A `session-live` refusal that rests on it turns an enriching read into a deciding one; the plan must say so and name what a failed read does.
- **Writing state from the preflight.** A snapshot write from anything but the instance's wrapper, a replay that writes a file, or any rewrite or truncation of `events.ndjson` (architecture §Standard Contracts → Instance snapshot; architecture §Standard Contracts → Snapshot envelope; architecture §Established Decisions [Database / State Store]).
- **A side channel or a location key.** A new env var, config key or async runtime on the verb's path, or finding the instance through the working directory: architecture §Cross-cutting Patterns → Config management (env vars are not a configuration channel; `--home` is the isolation point), architecture §Cross-cutting Patterns → Tokio containment, architecture §Cross-cutting Patterns → Identity by instance, never by location. The recorded `cwd` is a spawn argument only, never an identity or a join key.

## Contract bindings
- **arch ↔ security.** The preflight is a new entry point that reads `snapshot.json` and then spawns in a directory it names; the strict-modes rule and the standing dated exceptions are security-plan's. The id reaching argv is upstream-derived text (architecture §Cross-cutting Patterns → Untrusted upstream text), so its validation rule is security's; the no-path rule on every external surface bounds the `cwd-missing` and `session-live` lines (architecture §Conventions → CLI exit codes names no path, pid or pipe name on the endpoint refusal; whether a foreign session's pid may be printed is not ruled in the plan).
- **arch ↔ tests.** The fake agent's `--resume` mode, the recorded `SessionStart` variant it replays and the kill-then-revive E2E bind to test-plan's harness and fixture rules; a new ledger row binds to `contract_ledger_probes` and the stamped test homes (architecture §Established Decisions [CLI Version Compatibility]).
- **arch ↔ obs.** The replay arm's `state-recovered` line, the `process-exit` `detail` values of the new refusals and the role file the verb logs under (architecture §Cross-cutting Patterns → Diagnostic output channels: `run-<name>` for the wrapper, `cli-<name>` for the verbs) bind to obs-plan's event catalog. Revive starts as a CLI verb and ends as the wrapper; which role file its lines land in is not stated by the plan.
- **arch ↔ design.** The `unable:` / `hint:` wording and the `--list` rows bind to layout-templates' CLI surface.
- **Owed to the plan at wrap** (new resources, architecture §Occupied Resources): the subcommand list, the snapshot `data` key list and its "fields no event carries" list, the exit-code and `detail` lists, the fake agent's argv options, the Snapshot envelope's "no reader takes it yet" sentence, and the `src/cmd/` module list of §Infrastructure Patterns → Project directory structure.

## Acceptance criteria contributions
- The verb's code is a module under `src/cmd/` of the root bin; no `--resume` / `--fork-session` literal, session-id shape or `claude agents --json` shape appears outside `viola-agent-claude`; no sync crate gains a `tokio` edge (per architecture §Infrastructure Patterns → Project directory structure; architecture §Infrastructure Patterns → Crate dependency direction; architecture §Cross-cutting Patterns → Tokio containment).
- A snapshot written with `cwd` still carries `v` 1 and parses under a reader that does not know the key; a snapshot without `cwd` parses under the new reader as absent, and the replay arm yields no `cwd` and writes no file (per architecture §Conventions → Protocol versioning; architecture §Standard Contracts → Snapshot envelope).
- After a kill and a revive the instance's `events.ndjson` is longer, every byte before the revive is unchanged, no `dialog_id` repeats, and the new `session-start` line reads `cause:"resume"` with the prior `agent_session_id` (per architecture §Established Decisions [Session Liveness]; architecture §Established Decisions [Message Broker / IPC]; architecture §Conventions → Naming patterns, Hook → kind map).
- Each of the four preflight refusals exits with a code inside the plan's set (or one the wrap adds to both lists), prints a fixed `unable:` / `hint:` pair holding no path, and every CLI behaviour the verb relies on is either a ledger row with a probe or named as owed on a route entry (per architecture §Conventions → Error handling schema, CLI exit codes; architecture §Occupied Resources → Binary, subcommands and exit codes; architecture §Cross-cutting Patterns → Capability ledger as the single gate).
