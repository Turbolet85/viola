# design extract

## Relevance
partial — the chunk adds one human CLI verb (`viola revive`, its `--list` output, four preflight refusals with hints) on the cli surface; no web-spa token, layout or motion is built, and design-system.md names no `revive` verb, line or hint anywhere (a search for the word printed nothing), so the cli rules bind by pattern and the verb's own words are a plan gap.

## Constraints
- A refusal on the human stream is the word `unable` plus its fields, two-space separated, with exactly one `hint:` line directly after it, on stderr; design-system §Surface: cli → Tokens (platform-specific) → Streams requires this form for every refusal, and names the fixed-message form `unable: <name> is already live` for the exit-1 start refusal only. Which of the two forms each of the four revive refusals takes is not stated by the plan.
- `instance-live` is scoped as `run`'s existing collision refusal, unchanged: design-system §Surface: cli → Component Patterns (component 2, the exit-1 start refusals list, and component 5 `run`) fixes that refusal's message line and its hint. Whether revive's `instance-live` reuses those two lines byte for byte, and whether the code prints them today, is research's question.
- No start refusal and no hint shows a path or a pid: design-system §Surface: cli → Component Patterns (component 2: "None of them shows a path or a pid") and §Anti-Patterns → Per-Surface Bans (cli: never print upstream text, paths, pids). This binds `cwd-missing` (the recorded directory is never printed) and conflicts with the scope's inferred `session-live` wording "names the pid" — a departure the plan does not grant; it goes to P4 as a question.
- Hints are human-mode only; under `--json` the whole result is one JSON document on stdout with the typed exit code and no hint text: design-system §Surface: cli → Tokens (platform-specific) → Streams, and §Surface: cli → Component Patterns (component 2, "Hints are human-mode only"). The same component records that exit 1 has no `--json` document pending an architecture amendment; whether revive's refusals get a `--json` shape is architecture's, not this plan's.
- Colour on the cli is limited to the amber `DIALOG` word, dim `stale` rows and the bold NAME column; nothing else is styled: design-system §Surface: cli → Tokens (platform-specific) (token table) and §Typography (the `cli` paragraph). `revive --list` and the four refusals therefore print plain, with no SGR at any depth unless the plan is amended.
- No SGR, glyph or cursor control under `--json`, `NO_COLOR`, `TERM=dumb`, a non-terminal stdout, or `viola run`: design-system §Surface: cli → Tokens (platform-specific) → Colour decision order. Revive runs the ordinary `run` start order, and §Surface: cli → Component Patterns (component 5 `run`) requires that nothing is printed once the child starts; whether revive counts as `viola run` at item 2 of that order is not stated and is a plan gap.
- Human output is ASCII only, two spaces between columns, ` - ` inside one field, never wrapped, truncated only where the width is known: design-system §Surface: cli → Tokens (platform-specific) → Width, §Iconography (Separator), §Spacing (the CLI spacing line). This binds the `--list` chain rows `(ts, cause, id)`.

## Patterns to follow
- The `--list` chain is a static fixed-column table in the k9s strip-table manner, results on stdout: design-system §Surface: cli → Component Patterns (component 1, `viola list`) and §Brand Identity (Expression level, the `cli, human TTY` row: static rows, nothing redraws). The plan gives no sample for a session chain; its column words and order are a gap for P4.
- The cause column prints the plan's fixed cause words, never a paraphrase: design-system §Color Palette → Semantic Colors (the `SessionStartCause::startup` / `clear` / `resume` / `compact` / `unknown` rows give the printed word of each).
- Timestamps print in the plan's time form with the trailing `Z`, as in the send and wait result lines: design-system §Surface: cli → Component Patterns (components 2 and 3) and §Typography (the Data role). Which precision `--list` uses is not stated.
- Refusal vocabulary is short fixed lower-case words, hyphen-joined, with no filler: design-system §Brand Identity (Domain anchors, "Standard phraseology and unable plus a reason"). The four codes `instance-live` · `cwd-missing` · `session-live` · `no-session` fit that form; each hint follows the per-cause hint manner of §Surface: cli → Component Patterns (component 2, the T4 hints).
- Verbs are flat, one lower-case word, with no interactive prompt, TUI mode or pager, and `viola --help` groups them: design-system §Surface: cli → Navigation Pattern. The verb list and the help groups there do not hold `revive`; which group it joins is a plan gap (an amendment at the wrap, with the founder's or operator's word on the group).

## Anti-patterns to avoid
- No green or red mark, no emoji, no spinner, progress bar or redrawing line while revive runs its preflight or reads `claude agents --json`: design-system §Anti-Patterns → Per-Surface Bans (cli).
- No "done" or "success" word without context, and no data on stderr or message on stdout: design-system §Anti-Patterns → Per-Surface Bans (cli: never mix data and messages; never print "done" without context). A revive that starts prints nothing of its own, per §Surface: cli → Component Patterns (component 5 `run`).
- No hint that names `viola release`: design-system §Surface: cli → Component Patterns (component 2, the T3 note). No hint that quotes upstream text: the same component ("A hint never quotes the sent text or any upstream text"); a session id read from the log and a `claude agents --json` field are upstream values.

## Contract bindings
- design ↔ architecture: the exit codes and the `--json` shape of the four refusals are architecture §Conventions; design-system §Surface: cli → Component Patterns (Exit-code phraseology) mirrors that table and holds no row for revive. A new code or a new exit-1 line needs both documents amended together.
- design ↔ security: the path and pid ban in design-system §Anti-Patterns → Per-Surface Bans (cli) is the security plan's NEVER-log floor and error-sanitization rule; the recorded `cwd` is bound by both. Fields of `claude agents --json` origin need their C0/C1 controls escaped if any is ever printed, per §Surface: cli → Component Patterns (component 1).
- design ↔ layouts: the line-by-line shape of the `--list` table and of each refusal with its hint is layout-templates' (cli); this extract carries only the stream, colour, separator and vocabulary rules.
- design ↔ a11y: colour is never the only cue on the cli (design-system §Anti-Patterns → Per-Surface Bans, cli: never colour without the word); revive adds no colour, so the binding holds by absence.
- design ↔ the founder's open question (wheel at `human` after a revive): design-system §Color Palette → Semantic Colors holds four `WheelCause` rows (`start`, `human-input`, `manual-pause`, `release`), and the only one that prints `human` without a human action is none of them. An option that starts a revived instance at `human` under a new cause word needs a Semantic Colors row and a tape wording; an option that reuses `driver · start` needs no design change. This prices the options; it picks none.
- design ↔ web-spa (read-only effect): a revived session's `session-start` with cause `resume` prints on the tape as the existing `EventKind::session-start` line with the `resume` word, per design-system §Color Palette → Semantic Colors. Nothing on the page is built here; whether the page already renders that cause word is research's question.

## Acceptance criteria contributions
- Each of the four revive refusals prints `unable` with its fields then exactly one `hint:` line, both on stderr, nothing on stdout, and no hint line under `--json` (per design-system §Surface: cli → Tokens (platform-specific) → Streams)
- No revive refusal line, hint or `--list` row contains an absolute path, the recorded cwd, a pid or upstream text, in human and `--json` output alike (per design-system §Anti-Patterns → Per-Surface Bans, cli) — unless P4 returns a founder's word allowing the pid on `session-live`
- `revive --list` and every revive refusal carry no SGR byte and no non-ASCII character with stdout on a terminal, piped, and under `NO_COLOR` (per design-system §Surface: cli → Tokens (platform-specific) → Colour decision order, and §Typography, the `cli` paragraph)
- A revive that passes its preflight writes no line of its own to stdout or stderr once the child starts (per design-system §Surface: cli → Component Patterns, component 5 `run`)
