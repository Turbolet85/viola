# security extract

## Relevance
relevant — revive is a new entry point that reads `snapshot.json`, takes a directory and a session id from disk state into a child spawn, and adds four refusals; three plan sentences meet it head-on (strict-modes, the child's cwd, the "no caller yet" wording).

## Constraints
- **Strict-modes before the snapshot read.** security-plan §Authentication & Authorization (`~/.viola/` access control row) requires the strict-modes check in every process that reads `snapshot.json`, naming the start of `run` and every CLI verb that resolves an instance; the seven dated gaps in that row each name their own verbs, and security-plan §Security Anti-Patterns → Authentication says no other frame or process may borrow any of them. No gap names revive. The plan therefore requires the check before revive uses any snapshot value (the recorded `cwd` included); a read without it is an eighth dated gap, which is the founder's own to give (scope §Boundaries holds this as a P4 question, never a lean). Whether `run`'s landed start order already runs the check on the path revive reuses is research's question. The failure outcome the row gives a wrapper role is exit 1, a client verb exit 21; which class revive takes is not stated by the plan.
- **The child's cwd sentence.** security-plan §Input Validation (Child executable resolution row) requires that the child's cwd is set explicitly to the spawner's current directory. Scope item 2 spawns the child in the snapshot's recorded `cwd` instead. That is a departure from the row as written: an amendment owed at wrap, and a boundary matter for the review card, because a value in `snapshot.json` now decides the directory a `claude` child starts in (its project settings and hooks with it). security-plan §Threat Model Summary (data classification, config) already classes snapshot fields that decide what code runs as integrity-sensitive; the plan names no `cwd` field.
- **The session id is content until validated.** security-plan §Input Validation (Boundary paragraph) requires validation at every point where untrusted data enters, with shared validators in `viola-core`; security-plan §Security Anti-Patterns → Code Patterns forbids interpreting upstream text as a viola command or config. The logged session id originates in a hook payload, so it reaches argv only after a closed-shape check (scope item 1: a UUID, and for `--id` one this instance's own log holds), as its own argv element of a direct spawn. The plan carries no row for an id used as an argv value; the row is owed. What id shapes the hook parser and the fake agent produce today is research's question.
- **One start path, every start-time control.** Revive "runs the ordinary `run` start order" (scope item 1), so each control the plan attaches to a start applies unchanged: the program re-resolved by `run`'s own resolver to an absolute path, with `.cmd`/`.bat` refused, per security-plan §Input Validation (Child executable resolution row); the pinned-exe re-hash and the rewrite of `plugin/` and `instances/<name>/settings.json`, per security-plan §Data Protection (At rest, code-bearing artefacts); the R8 strip on the revived child, per security-plan §Secret Management (Storage); the collision check under the same verification as a client, per security-plan §Authentication & Authorization (IPC client-side server verification row, "Collision check"). Whether the landed `instance-live` refusal performs that verification is research's question.
- **The recorded cwd is written privately and shown nowhere external.** security-plan §Authentication & Authorization (`~/.viola/` access control row) requires every replaced file to go through `viola_state::fs::replace_private` at 0600, and security-plan §Security Anti-Patterns → Universal requires that only the instance's own wrapper writes `snapshot.json`. security-plan §Bootstrap phases (`logging-redaction-wire`, operational metadata) requires that absolute paths (they carry the OS username) never reach CLI `--json` error output, MCP `isError`, Problem Details or channel `error.data`, with `/api/info`'s `viola_home` the only intended path disclosure. Whether any surface serialises the snapshot struct whole (so that a new field would ride out with it) is research's question.
- **Bounded, non-writing reads of the id chain.** security-plan §Input Validation (Own state files on read row) requires each `events.ndjson` line to be read under the `MAX_FRAME` cap, a reader that never writes, the classified snapshot read and the log replay to read through the same bounds and write no file, and the read to follow the strict-modes check. The row's own wording says the replay has no caller yet; revive is its first.
- **`session-live`, if it calls the CLI.** security-plan §Input Validation (Child process output row) requires `claude agents --json` output to be read with `Read::take(MAX_FRAME)`, parsed tolerantly, a failure read as `unknown`, and a row's `name` never used as a `ViolaName`. security-plan §Input Validation (Child executable resolution row) records PATH resolution of `claude` for that call as an accepted risk for `list`, `mcp` and `ui` only; a fourth role making the call is not covered by that wording.

## Patterns to follow
- The four preflight refusals take the closed-refusal form the plan already holds for `batch-script-child`: a closed code, exit code and two fixed `unable:`/`hint:` stderr lines with no path or pid, per security-plan §Input Validation (Child executable resolution row) and security-plan §Error Handling (External responses). The study's `session-live` wording "names the pid" has no plan sentence behind it; whether a pid may stand in a hint line is a review-card question.
- `<name>` goes through the shared clap parser (`value_parser = parse_viola_name`, `ViolaName::try_new`) before any `instances/<name>` join, and `--id` is a typed value rather than a free string, per security-plan §Input Validation (CLI arguments / stdin row).
- The id check lives beside the other shared validators in `viola-core`, per security-plan §Input Validation (Boundary paragraph). A hand-written check adds no crate; a new crate would fall under security-plan §Dependency Security (Pinning; `deny.toml` additions): a `[workspace.dependencies]` pin, the four-licence allow list, crates.io only, no C build.
- A boundary gap is recorded in the plan's dated-exception form: the founder's own word, a Decisions Log entry, the verb named, the removing route entry named, and "borrows none of the earlier ones", per security-plan §Authentication & Authorization (IPC client-side server verification row).
- Human-mode output of log-held values follows the plan's terminal rule: C0/C1 controls escaped before printing, per security-plan §Bootstrap phases (`logging-redaction-wire`). `--list` prints `(ts, cause, id)`; an id that passed the closed-shape check and a closed `cause` hold no control character, and anything printed outside those needs the escape.

## Anti-patterns to avoid
- Never reach a revive start by borrowing one of the seven dated gaps, and never treat the snapshot's reference values as trusted when the snapshot did not pass strict-modes in the same process (security-plan §Security Anti-Patterns → Authentication).
- Never pass the id, the recorded cwd or the `--` arguments through a shell or build a command string from them; `statusline_command` stays the only shell-out and upstream text is never a command (security-plan §Security Anti-Patterns → Code Patterns). Never join the recorded cwd with anything, and never put it or any other absolute path into an external error (security-plan §Security Anti-Patterns → Logging).
- Never let `--fork`, `--id`, the `--` arguments, a `VIOLA_*` variable or a new test seam for the fake-agent E2E switch off a control of the plan (the strict-modes check and the server verification among them), and never add a listener or channel method for revive without a Decisions Log entry (security-plan §Security Anti-Patterns → Universal).

## Contract bindings
- **Architecture — snapshot envelope and exit codes.** The `cwd` field, whether it moves the snapshot's `v`, the four refusals' exit codes and the hint lines are architecture's (§Standard Contracts, §Conventions) and layout-templates'; security's floor on them is security-plan §Error Handling (fixed messages, no path).
- **Architecture — capability ledger.** A product call to `claude agents --json`, and the reliance on `--resume` / `--fork-session` behaviour, are ledger-row matters (CLAUDE.md, architecture); security-plan §Security Anti-Patterns → Universal ties a non-`null` dialog decision to the stamp, so a new row that gates `cli_verified` also moves what a stamped home may answer.
- **Obs — where the cwd and the id may be logged.** security-plan §Bootstrap phases (`logging-redaction-wire`) allows pids and `agent_session_id` in `diagnostics/` and keeps absolute paths out of every external error surface; which process-log line, if any, carries the recorded cwd, and where the replay arm's one `state-recovered` line is written against "write no file" in security-plan §Input Validation (Own state files on read row), are obs-plan's answers.
- **Tests — own processes, synthetic fixtures.** The E2E kills only the wrapper it started (scope `inputs#I2`); any new fixture or fake-agent stub is synthetic and free of home paths and usernames, per security-plan §Data Protection (Repository fixtures); the CI artifact canary scan in security-plan §Secret Management (Secret scanning in CI) reads the new test homes like every other.
- **Founder — live starts.** security-plan §Threat Model Summary (attack surface, child process spawning) admits four interactive `viola verify` children, each by the founder's live ruling, and security-plan §Data Protection (Accepted risk, verify's trusted runs) accepts the CLI's own transcripts for Runs B, C and D only. The P4 · P6 · P7 · P12 live starts are neither: their count and their transcript residual go on the review card and wait for his number.
- **Founder — the wheel at a revived start.** The plan sets no rule for it. Its nearest words are the affordance guard in security-plan §Authentication & Authorization (Driver-originated `release` row) and "refusals go only to automation" in security-plan §Security Anti-Patterns → Universal; neither settles the question.
- **Plan text this chunk makes stale (owed at wrap).** "No product reader takes it yet" in security-plan §Threat Model Summary (attack surface, filesystem state); "library code with no caller yet" in security-plan §Input Validation (Own state files on read row); the spawner's-current-directory sentence in security-plan §Input Validation (Child executable resolution row); and security-plan §Threat Model Summary (data classification, operational metadata) lists `agent_session_id` as a snapshot field, while scope item 2 read none in the snapshot at take-up.

## Acceptance criteria contributions
- (security) A revive against a home or instance directory that fails strict-modes spawns no child and uses no snapshot value, or the plan carries a founder-dated gap that names revive (per security-plan §Authentication & Authorization, `~/.viola/` access control row).
- (security) An `--id` that is not the closed id shape, or is not held by the instance's own log, is refused before any spawn; the accepted id reaches the child as one argv element of a direct spawn, with no shell in the path (per security-plan §Input Validation, Boundary paragraph, and security-plan §Security Anti-Patterns → Code Patterns).
- (security) Each of the four refusals, in human mode and under `--json`, prints a closed code and fixed text only; a test whose recorded cwd holds a canary directory name reads no occurrence of it in stdout, stderr or any error body (per security-plan §Error Handling, External responses, and security-plan §Bootstrap phases, `logging-redaction-wire`).
- (security) After a revive the instance's `snapshot.json` reads 0600 inside a 0700 directory on Unix, its writer is the revived wrapper through `replace_private`, and `events.ndjson` is no shorter than before the kill (per security-plan §Authentication & Authorization, `~/.viola/` access control row, and security-plan §Input Validation, Own state files on read row).
