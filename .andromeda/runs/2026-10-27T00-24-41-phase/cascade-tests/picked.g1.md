### unit-test-strategy#1.2 · procedure · unit · ## 4. Unit Test Strategy · lines 15–28
- **viola-state:**
  - The ndjson writer does one `write` per line.
  - The reader counts and never panics. `torn_lines`: an over-long line (> `MAX_FRAME`), a terminated line that is not one JSON object, and the unterminated last line of the read, which it neither returns nor rewrites. `unknown_kinds`: a line whose `kind` is absent, not a string or not a known kind; it is not returned. `unknown_fields`: once per line, a known-kind line with a top-level key outside the six or a `data` key outside its kind's list; it is returned (unit cases `three_counts`).
  - The heal is the appender's. An append to a log whose last byte is not LF writes one LF and its line in a single write; `append_event_at` hands its builder and returns the line's real start (L + 1 after a heal, L otherwise); `try_append_event` with the lock held writes and heals nothing; one `state-recovered` line is logged per heal and none without one (unit cases `torn_tail`, the lines read in memory through the crate's `#[cfg(test)]` capture).
  - Snapshot envelope: the classified read tells the snapshot, no file, an unreadable one and an unsupported `v` apart, reading `v` first; an unsupported `v` or a parse failure goes to replay through the read-or-replay function, which logs one `state-recovered` line for each and none for a present or an absent snapshot (unit cases `snapshot_cause`, `replay_recovers`). `viola revive` is the read-or-replay function's first product caller and `viola list`'s `board::read` its second (chunk 2026-10-11-the-board-viola-list, read in `tests/cli_list.rs` `e5_list_reads_a_live_wrapper_through_the_replay`) (revive's in its second preflight reading, the logged session, of four since chunk 2026-10-16-unwrapped-sessions-on-the-board added `session-live` (the strict-modes check ahead of the preflight since chunk 2026-10-10-budget-governor); the one `state-recovered` line on the replay arm is read in `tests/cli_revive.rs`).   - The liveness classifier (live / stale / gone) is the pure `classify(beat_age, same_process)`, fed ages directly (no clock): a pid that is dead or carries another start time is `gone` at any age; for the same process 4.9 s and 5.0 s are live, 5.1 s and an absent beat `stale`; `same_process` compares the snapshot's `started_at` with the pid's OS start time.
  - The server check: `ServerVerdict { Matches, Mismatch, Unverifiable }` from the pure `server_verdict(recorded_pid, started_at, observed_pid, observed_start, peer_pid_reported)`, pinned by the decision table `server_verdict_rows`; where no peer pid is reported (`peer_pid_reported` false, macOS) the verdict is `Matches` with no comparison, the recorded gap. `verify_server_reads_the_observed_start_time_from_the_os` covers the joined `verify_server`'s read of the observed start time from the OS (`process_start_time`, none for a zombie). `live_endpoint` returns `LiveEndpoint { endpoint, pid, started_at }`, all from its one `read_snapshot_or_replay` call: only a present snapshot proceeds, and a replayed or absent snapshot or a read error is `None`, since a replayed snapshot carries no `endpoint`, `pid` or `started_at`.
  - Strict-modes has two rules, the write rule and the read rule, which holds the content-bearing paths the instance check names below: `unix_read_verdict(mode, uid, euid)` is the write rule plus a refusal of `mode & 0o077` (`unix_read_verdict_needs_the_write_rule_and_no_foreign_bit`), and `windows_read_verdict` is the write rule plus a refusal of any allow ACE granting a right in `READ_RIGHTS` (`0x9000_0001`: `FILE_READ_DATA` | `GENERIC_READ` | `GENERIC_ALL`) to an untrusted SID, inherit-only ACEs included (`windows_read_verdict_refuses_any_read_right_to_another_sid`, `windows_read_verdict_takes_the_trusted_sids_and_keeps_the_write_rule`, and the `cfg(windows)` `read_rights_are_the_named_flags`).
  - Windows strict-modes feeds synthetic security descriptors built from SDDL strings (via windows-sys) to the descriptor-check function. This covers a foreign-owner SID, a NULL DACL, an inherit-only GENERIC_WRITE ACE, a read grant on `diagnostics/`, and `CREATOR OWNER` treated as the user.
