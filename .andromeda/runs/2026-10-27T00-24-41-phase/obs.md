## Relevance
partial — part A (the `pin_bytes` / `pin_exe` absent-copy race) touches the `viola run` start's must-trace span `run.pin_copy` and its closed outcome / `detail` vocabulary; part B (two clean release builds compared) is a build measurement with no product telemetry, and obs binds it only through service identity and the bans on new fields.

## Constraints
- obs-plan §4 Scenario: `viola run` start sequence to child spawn requires `run.pin_copy` to stay in the must-trace chain between `run.collision_check` and `run.conpty_sideload` / `run.version_gate`, with its attribute `outcome` closed to `ok|pinned-hash-mismatch`. Any new outcome the race fix introduces (a wait on a concurrent writer, a same-bytes acceptance, a lost race) is an extension of that closed set, not a free value. Whether the code already records `outcome` on that span is research's question.
- obs-plan §4 Scenario: `viola run` start sequence to child spawn bans the endpoint name, the `pinned_bin` path and env values in any span or line, and requires a failure's `process-exit{subject:"self", exit_code:1, detail}` to carry no path or pid. The pin's `bin/<key>/` path, its key/hash and any temp-file name used by the fixed write stay out of every home-level line.
- obs-plan §6 Log Coverage (log-details detail) requires `process-exit` exit-1 `detail` to come from the closed list (`pinned-hash-mismatch` among it), and `schemas/diag-line.v1.json` closes that enum at 13 values. A new exit-1 cause from the race fix (for example a pin write that times out) needs a new member, which means a Decisions Log entry and a schema change. It must not reuse `pinned-hash-mismatch` for a cause that is not a hash difference.
- obs-plan §8 PII Scrubbing & Compliance requires that `endpoint` / `pinned_bin` are never logged, that home-level lines stay path-free, and that low-class metadata is logged as typed fields, never inside `detail` codes. This applies equally to `viola verify`'s `pin_exe` call site under `cli.verify`.
- obs-plan §1 Obs Scope Summary (telemetry trigger, logging-sensitive, Vector 7) requires refusal telemetry for pinned-exe hash mismatches. The fix must leave the present-copy re-hash and its `pinned-hash-mismatch` refusal observable exactly as before, and it must not weaken it into a silent overwrite.
- obs-plan §2 Telemetry Strategy (Resource attributes) fixes `service.version` as `env!("CARGO_PKG_VERSION")`, emitted as `version` on `process-start`. Two builds of one tree that hash apart (part B) are therefore indistinguishable in process logs by `version`. Adding a build-hash or pin-key field would extend the catalog, so it is a fork, not a lean.
- obs-plan §10 SLO Invariants & Telemetry Budgets requires zero unlogged panics and every Cargo profile at `panic = "unwind"` (G3). Any profile key part B's measurement proposes, for a reproducible build, must keep `panic = "unwind"`.

## Patterns to follow
- obs-plan §4 Scenario: `viola run` start sequence to child spawn, the `run.conpty_sideload` precedent: the Windows `pin_companions` absent-then-replace arm waits out `ERROR_SHARING_VIOLATION`, and its degrade reaches the existing info-level lines as a closed `sideload_fallback`, never at `warn`, never as a refusal or an exit change, and never with a companion path or hash. A wait or retry on the exe's arm follows the same codes-only shape.
- obs-plan §11 Obs Anti-Patterns § Spans / Traces: any new or changed function on the pin path (`pin_bytes`, `pin_exe`, `replace_private_shared`) is declared `#[instrument(skip_all, fields(..))]`, with neither `err` nor `ret`, and logs only through `obs_event!` (§11 § Logs).
- obs-plan §3 Observability Harness Contract (Snapshot / paste-to-AI integration): the race's red and clean readings are machine verdicts read through `agent-run logs` / `status` and the harness `boot` readiness stage `start_records` (`events.ndjson` lines 1–3, `wheel{cause:"start"}` → `budget-gate` → `session-start{source:"hook"}`, missing code `<name>:events`, per §4 Scenario: `viola run` start sequence to child spawn). They are never a human reading of a log.
- obs-plan §9 CI Integration: every integration-test home, the two-instance race rig included, lives under `target/e2e-home/`, so G2, G4, the secret scan and the `diag-<os>` upload cover it.

## Anti-patterns to avoid
- obs-plan §11 Obs Anti-Patterns § Logs: never add an `event` value, or rename a tests field, without a Decisions Log entry. A "pin-raced" or "pin-waited" signal is either an existing event with a catalogued field or an enum extension through that entry, never an ad hoc line.
- obs-plan §11 Obs Anti-Patterns § PII Scrubbing: never put paths or pids inside `detail` codes, and never log a field the §6 catalog does not name. This covers a pin path, a pin key or hash, a temp-file name, the concurrent start's pid, and a kernel errno string (for example the hypothesised `ETXTBSY`) on a home-level line.
- obs-plan §11 Obs Anti-Patterns § SLO: never add retry-once policies for flaky telemetry assertions. A race witness that passes only on a re-run is red, and a retry in the product's pin write is a design choice for P3/P4, not a way to mask the test's flake.

## Contract bindings
- obs ↔ tests §3: the two-sided race witness reads the harness `boot` `start_records` stage and the `agent-run logs` merge (obs-plan §3 Snapshot / paste-to-AI integration; §4 Scenario: `viola run` start sequence to child spawn). The failure the CARRY measured, a hook spawn with `ran:false` and no `session-start`, is a missing `events.ndjson` record. No `hook-<name>.ndjson` line exists for it: a hook whose exec failed never runs its obs init (obs-plan §10 SLO Invariants & Telemetry Budgets, bounded exemptions).
- obs ↔ security §Local trust boundary (Home): `pinned-hash-mismatch` stays the observable side of the hash-before-reuse rule (obs-plan §1 Obs Scope Summary Vector 7 trigger; obs-plan §6 Log Coverage, Filesystem refusals).
- obs ↔ `schemas/diag-line.v1.json` (G4): any new `run.pin_copy` outcome surfaced in a line, any `process-exit` `detail` member or any new `process-start` field is a schema change, gated by G4 at zero conformance failures (obs-plan §8 PII Scrubbing & Compliance, Default-deny posture; obs-plan §10 SLO Invariants & Telemetry Budgets).

- (obs) A tampered present copy still ends a start in `process-exit{subject:"self", exit_code:1, detail:"pinned-hash-mismatch"}`, with the copy neither overwritten nor run, and the race fix leaves this unchanged (per obs-plan §6 Log Coverage).
- (obs) G2 reads zero `event:"panic"` lines across the race rig's role files, and G3 finds no `panic = "abort"` in any profile part B's measurement touches (per obs-plan §10 SLO Invariants & Telemetry Budgets).
