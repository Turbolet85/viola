## Bindings
- **`pinned_bin` in the snapshot ↔ Occupied Resources (Filesystem)**: the copy's directory is named by the first 16 hex of the exe's SHA-256, and each snapshot records the path it uses. This is the one Standard Contracts field a rebuilt tree that reads as another binary moves, (.andromeda/architecture.md:157) ↔ (.andromeda/architecture.md:319).
- **Atomic snapshot and stamps replace ↔ Established Decisions [Snapshot writer]**: `replace_private` is the one helper, and it sets the mode before the first byte, then writes, `sync_all`s and `persist`s, leaving the target as it was on a failure. Any Part A change to the helper or its `_shared` variant binds both envelopes, (.andromeda/architecture.md:152) · (.andromeda/architecture-detail/standard-contracts.md:31) ↔ (.andromeda/architecture.md:37).
- **Stamps keyed by CLI version ↔ Established Decisions [Deployment / Distribution]**: the content hash keys only `bin/<key>/` and `plugin/<key>/` ("the content hash keys the copy because the version alone collides across rebuilds"), never the stamps, (.andromeda/architecture-detail/standard-contracts.md:33) ↔ (.andromeda/architecture.md:69).
- **`pinned-hash-mismatch` start refusal ↔ Conventions (CLI exit codes)**: it exits 1 and prints no document, which the chunk leaves unchanged, (.andromeda/architecture.md:228) ↔ (.andromeda/architecture.md:100).
- **`hook.event` / `session-start` witness ↔ Established Decisions [Hook Transport]**: the hooks' exec-form `command` is the pinned copy, so a write of that path while a start is in flight is what the witness reads as a lost `session-start`, (.andromeda/architecture-detail/standard-contracts.md:87) ↔ (.andromeda/architecture.md:45).
