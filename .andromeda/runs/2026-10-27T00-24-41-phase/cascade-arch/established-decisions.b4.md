### established-decisions#29.1 · values · dec-plugin-scope · ## Established Decisions · lines 262–263
- **[Plugin Scope] The plugin loads only into wrapped sessions via `--plugin-dir`.** Both driver and driven run under `viola run`. `viola plugin install` (a local marketplace) is optional, for the MCP verbs in an unwrapped driver. The installed plugin carries only `.mcp.json` and no hooks, so a wrapped session that also has it installed never runs two hook processes for one event (two `hook.dialog` requests for one dialog). Its `command` is the absolute path of the exe that ran `plugin install`, never a PATH lookup: as built, `viola plugin install` writes only `<home>/marketplace/` and spawns no `claude`, and its `.mcp.json` registers `viola` as `{"command": <the canonical current_exe, forward slashes>, "args": ["--home", <the canonical home, forward slashes>, "mcp"]}`, each document built by `serde_json` (`viola_agent_claude::marketplace::marketplace_files`). A wrapped session that also has the installed plugin enabled starts one `viola` MCP server, the `--plugin-dir` plugin's, and that server answers its tools: the installed plugin's `viola mcp` never starts there, and the session runs one SessionStart hook process (as measured on claude 2.1.287 on the Linux dev host at `viola-0.1.0/chunks/2026-10-18-plugin-precedence-live-readings/evidence/live-round.md`: the wrapped home's `mcp.ndjson` one `process-start{subject:"self"}` and the `list` call's `agents-probe` pair, the installed home none, the CLI's MCP log one server). It is no capability-ledger row (no `send` relies on it, the ruled limit); its Windows leg is owed to "Windows-only live measurements". Rationale: unwrapped sessions carry no viola hooks at all, so there is no per-tool-call spawn cost outside viola. The exceptions are `viola verify`'s transient unwrapped children, all gone when verify ends.
 The first is the print-mode probe, an unwrapped `claude -p` that loads only the `viola-verify-probe` plugin (four exec-form `hook <event> --capture` hooks) from `ledger/probes/<pid>/plugin/`. The other five are the interactive runs: Run A, untrusted in an OS-temp `viola-verify-*` dir and killed at its screen; Run B, trusted in `<cwd>/.viola-verify-<pid>/`; Runs C and D, trusted in `<cwd>/.viola-verify-<pid>-dialogs/` and `<cwd>/.viola-verify-<pid>-plan/`, each loading the dialog-kind `viola-verify-probe` plugin; and Run E, trusted in `<cwd>/.viola-verify-<pid>-resume/`, loading the capture plugin from `ledger/probes/<pid>/resume/plugin/` and resuming Run B's first session with `--resume <id>`, no key typed. Runs B, C and D, as real interactive turns, also run the user's own global hooks, and Runs C and D, and Run B on Windows, the user's own status line (on Unix Run B's status line is the probe capture its one probe `--settings` names, [CLI Version Compatibility]), and each leaves the CLI's session transcripts under `~/.claude/projects/` (an accepted residual, security-plan Data Protection): Run B three per real-CLI verify, its session, the `<id>-backup-<n>.jsonl` the CLI writes at its pasted `/compact`'s compaction and the session its pasted `/clear` opens (the last inferred, not read), and C and D one each; Run E adds none (as measured on 2.1.287 at chunk 2026-10-18-compact-post-condition-ledger-row, `evidence/live-round.md`: the `viola-verify` transcript count 60 → 65). ### established-decisions#30.1 · values · dec-cli-conventions · ## Established Decisions · lines 269–269
- **[CLI Conventions] Human text by default, `--json` for agents, a typed exit code per refusal. Prompt text comes from stdin or `--file`, never from a leading-slash argument.** viola warns when an argument carries a Git Bash rewritten-path prefix. Rationale: Git Bash rewrites `/skill` arguments into Windows paths (brief §6), and agents need machine-parseable refusals. `viola revive` takes `--json` on both arms (chunk 2026-10-17-cli-machine-contract): a refused strict-modes check or a preflight refusal prints `{"v":1,"error":"<code>","detail":null}` (`strict-modes-failed` · `already-live` · `no-session` · `session-live` · `cwd-missing`) in place of its `unable:` / `hint:` pair, exit 1, and `<name> --list --json` prints `{"v":1,"ok":{"sessions":[…]}}` in log order; without `--json` the pairs and the `--list` rows are byte-identical. A refusal `run`'s start makes after a passed preflight (`batch-script-child`, `pinned-hash-mismatch`, `squatted-name`, a `claude` not on `PATH` as `internal-error`) prints no document as landed; its document is owed to the working-route entry "Exit-cause code catalogue".
