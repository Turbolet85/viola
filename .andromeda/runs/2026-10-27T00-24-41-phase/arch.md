# arch extract

## Relevance
relevant — both halves sit on the pinned copy's key and its write (`viola-state`'s `pin` / `fs`, reached from `src/cmd/run.rs` and `src/cmd/verify.rs`), on the start order and on the release build route.

## Constraints
- Every replaced file goes through the one shared helper `viola_state::fs::replace_private`, and no call site carries its own temp + rename code. `replace_private_shared` is the variant for files every concurrent start of one version writes identically: the pinned copy, the plugin files and the Windows x64 ConPTY companions. Under it, a failed replace counts as done when the target already holds exactly those bytes. A fix for the race changes this helper or `viola_state::pin`, never a call site. Whether that same-bytes acceptance already covers the exe's concurrent-first-start arm is research's question (per architecture §Established Decisions → [Snapshot writer]).
- On Windows, the `persist` retry of raw OS error 5 and the companions' held-open retry of Win32 error 32 are both bounded by `viola_state::fs::REPLACE_ATTEMPTS` = 100. That bound is an attempt count, never a time bound, and the retry decision is passed in by the caller (`replace_private_retrying` / `retry_replace`, `retry_open` / `open_held_waiting`). Any new wait the race fix adds takes the same form (per architecture §Established Decisions → [Snapshot writer]).
- `viola run` creates `bin/<version>-<hash>/viola(.exe)` only when it is absent (0700 on Unix). It re-hashes an existing copy on every start. A mismatch refuses the start (exit 1, `pinned-hash-mismatch`) and leaves the file as found. v1 never deletes pinned copies or plugin folders. The race fix changes none of this, only the absent-copy write's concurrency (per architecture §Occupied Resources → Filesystem).
- The key `<version>-<16 hex>` is named in one place, `viola_state::pin::pin_key`. `pin_bytes(home, bytes)` pins bytes already read and `pin_exe` delegates to it. `run`'s start pins the very exe bytes that `checked_exe` read and keyed for its home-tree check, and `viola verify` calls `pin_exe` (per architecture §Established Decisions → [Deployment / Distribution]).
- The hash is the SHA-256 of the exe bytes truncated to 8 bytes (16 hex), computed by sha2 `=0.11.0` (pure Rust, no `cc`). The key carries the content hash because `CARGO_PKG_VERSION` stays `0.1.0` across rebuilds, so a rebuild never changes what a running session calls. A rebuild of one tree that hashes differently is therefore a second key by design, which is why measurement B bears on the product (per architecture §Stack and Technologies → Content hash; §Established Decisions → [Deployment / Distribution]).
- The start runs in this order: program resolution → collision check → pinned copy and plugin → ConPTY sideload → version gate → exclusive endpoint bind (`squatted-name`). The bind serialises two starts of one name only. Two starts of different names on one fresh home both reach the pin step with nothing excluding them. The fix keeps this order, or changes it only as a recorded decision (per architecture §Established Decisions → [Session Liveness]).
- `viola-state` is a sync crate (`scripts/sync-crates.txt`, `deny-sync.toml`). New code on the `run` path uses std threads and blocking I/O, and no Tokio and no C-building crate enters with the fix (per architecture §Cross-cutting Patterns → Tokio containment; §Infrastructure Patterns → Build system).

## Patterns to follow
- `replace_private_shared`'s same-bytes acceptance and the companions' write-if-absent `pin_companions` with `open_held_waiting`. Both are existing answers to concurrent first starts of one version (per architecture §Established Decisions → [Snapshot writer]).
- A guarded file gets its own `.lock` sibling under std `File::lock`, opened for write, because Windows refuses an exclusive lock on an append-only handle. This is the existing serialisation primitive if research shows the pin needs exclusion (per architecture §Cross-cutting Patterns → Crash-safe disk writes; §Stack and Technologies → State-file primitives).
- A release build is judged by its own `compiler-artifact` records (`scripts/release-check.sh`: `cargo build --release --locked --bin viola`), never by listing `target/release/`, where a shared or cached dir keeps stale exes. Measurement B builds through that route, each build from an empty target dir (per architecture §Infrastructure Patterns → CI/CD approach).
- Every relied-on behaviour is measured and recorded with its reading. A cause no measurement shows is carried as unknown, never inferred (per architecture §Design Philosophy → Measured, never assumed).

## Anti-patterns to avoid
- A temp + rename, a delete or an overwrite of `bin/<key>/viola(.exe)` outside `replace_private_shared`, which includes clearing a mismatched copy so the start can proceed (per architecture §Established Decisions → [Snapshot writer]; §Occupied Resources → Filesystem).
- A wall-clock bound or an unbounded loop on a retry or wait, and a new dependency (a file-lock crate, a C build) where std `File::lock` and the existing helper serve (per architecture §Established Decisions → [Snapshot writer]; §Infrastructure Patterns → Build system).

## Contract bindings
- arch ↔ security: the pinned copy's hash-before-reuse rule, its 0700 mode and the home-tree strict-modes check (`check_home_tree` on `bin/<key>/`, the pinned copy and `plugin/<key>/`) all run before the pin step. The fix keeps that order (per architecture §Occupied Resources → Filesystem, Home tree).
- arch ↔ tests: each test runs in its own `--home`, and the root tests seed `bin/<key>/conpty/` from `target/conpty-seed/<key>/`. A two-instance boot on one fresh home is the reproduction rig, and Path 7's instance count is P4's decision (per architecture §Established Decisions → [CI/CD]; §Occupied Resources → Filesystem).
- arch ↔ standard contracts (readers of the key): the instance snapshot records `pinned_bin`, the plugin folder is `plugin/<version>-<hash>/`, and `ledger/stamps.json` is keyed by CLI version, not by binary hash. Which other readers key on the hash is research's question for B (per architecture §Standard Contracts → Instance snapshot; → Ledger stamps envelope).
- arch ↔ obs: the start's pin step is a named place in the start order beside `run.conpty_sideload`. Any new outcome the fix adds (for example a waited replace) is obs's to name (per architecture §Established Decisions → [Session Liveness]).

## Acceptance criteria contributions
- The absent-copy write of `bin/<key>/viola(.exe)` and the per-start `plugin/<key>/` rewrite stay in `viola_state` through `replace_private_shared`, and `src/cmd/run.rs` and `src/cmd/verify.rs` hold no temp + rename code of their own (per architecture §Established Decisions → [Snapshot writer]).
- Under concurrent first starts, a present pinned copy with differing bytes still refuses with exit 1 `pinned-hash-mismatch` and is left byte-identical. A present matching copy is reused and never rewritten (per architecture §Occupied Resources → Filesystem).
- Any wait or retry the fix adds is bounded by an attempt count in `viola-state`, and `cargo deny --config deny-sync.toml --manifest-path crates/viola-state/Cargo.toml check bans` stays clean (per architecture §Established Decisions → [Snapshot writer]; §Infrastructure Patterns → Build system).
- Measurement B builds twice through `cargo build --release --locked --bin viola`, each build from an empty target dir. It compares the two files by hash and by section and records any differing section or note without a cause it did not measure (per architecture §Infrastructure Patterns → CI/CD approach; §Design Philosophy → Measured, never assumed).
