## Constraints
- The four framing arms (`long-paste-wrapper` · `tag-escaping` · `local-command-clear` · `paste-newline`) each read their Run B capture, with named cases for passing on the recorded shape and for failing without a matching capture or on each broken post-condition. test-plan §4 Unit Test Strategy requires a corrected oracle for `tag-escaping`, `local-command-clear` or `paste-newline` to keep that pass/fail pairing. The `local-command-compact` row is bound the same way through its `SessionStart.compact-<n>` variant (per test-plan §4 Unit Test Strategy). Whether the current cases already hold the 2.1.302 shapes is research's question.
- `contract_ledger_probes.rs` runs `viola verify --home <tmp>` against the fake agent with `--dialogs --framing` for every stamped fixture set. Each run must list each relied literal row id exactly once (`ROW_IDS: [&str; 24]` on Unix, 21 on Windows) and end `stamped <ver>  <n> pass  0 fail`. The stamped and drift-only lists are test literals, and every fixture dir must sit on exactly one of them. So a recorded `fixtures/claude/2.1.302/` set must be placed on one list (per test-plan §5 Integration Test Strategy).
- `tests/cli_verify.rs` pins verify's human lines as literals: one `[NN/MM] <row id> … pass|fail` line per relied row and the last line `stamped <ver>  <n> pass  <m> fail`. It also pins which rows a run fails without the framing replay (`19 pass  5 fail` on Unix, `19 pass  2 fail` on Windows). A changed Run B paste sequence, oracle or fake-agent echo must keep these per-OS literals true or move them deliberately (per test-plan §5 Integration Test Strategy).
- `contract_fake_agent_drift` compares the fake agent's hook stdin byte for byte with every recorded set. That covers the spine, every dialog variant, every framing variant (`paste-<n>`, `compact-<n>`, `clear-<n>`), the statusline, resume and compact variants, and the agents key and type shape. A set with no framing variant runs without `--framing` and must exit 1. Any fake-agent change made to follow 2.1.302 must keep every committed set replaying (per test-plan §6 E2E Test Strategy, Contract suite).
- Fixtures come only from a live `viola verify --record` (Run B's framing pastes for the four rows), scrubbed and `unclean`-checked; a dirty payload refuses the whole recording. Each must pass the `claude_fixtures` hygiene walk (absolute path, username and email checks, plus jsonschema against `schemas/claude-fixture.v1.json` or its statusline, agents and screen siblings) (per test-plan §7 Test Data & Fixtures, Fixture hygiene).
- The real CLI is reached only through `scripts/agent-run.sh run --local-live`, which refuses under `CI` with `live-in-ci`, exit 2. Suite `local-live` passes when verify exits 0 and every `LEDGER_ROWS` id is present. Its failure codes are `build` · `verify-exit-<n>` · `verify-exit-none` · `row-missing` (per test-plan §3 5-command implementation, `run`).
- Zero flakiness: nextest `retries = 0`, and `#[ignore]` is no parking place. A flake keeps the chunk red until its root cause is fixed inside the chunk. This binds the folded macOS readiness flake (`wrapper builder not ready` in the two `cross_list_rows_*` tests). A green attempt 2 closes nothing (per test-plan §10 Quality Gates & Coverage Targets, Zero-flakiness budget).

## Patterns to follow
- Local-command confirm tests run on recorded variants, never synthetic ones. Examples are `send_compact_on_a_verified_cli_is_confirmed_by_its_same_session` on 2.1.287 `compact-1`, `send_clear_on_a_verified_cli_is_confirmed_by_its_new_session` on 2.1.287 `clear-1`, and the unverified-CLI `unconfirmable` pair (per test-plan §6 E2E Test Strategy, Path 2).
- A stamped home comes only from `viola verify --home <home>` run against the fake agent (rstest `stamped_home`). No test or harness code writes `ledger/stamps.json` (per test-plan §7 Test Data & Fixtures).
- rstest `#[case]` tables carry a row's shape variants. The drift comparator's planted order swap and planted one-byte difference show that a comparator cannot pass vacuously (per test-plan §4 Unit Test Strategy; test-plan §6 E2E Test Strategy, Contract suite).
- Test names follow `<subject>_<condition>_<expected>` and sit in the layer files `cli_` / `contract_` / `cross_` (per test-plan §2 Test Strategy).

## Anti-patterns to avoid
- NEVER import the product's ledger rows as the test oracle: expected row ids, counts and `stamped …` lines are literals in the test (per test-plan §11 Test Anti-Patterns, Unit).
- NEVER treat a green fake-agent run, or a Linux-only run, as proof of real-CLI or other-OS behaviour. A behaviour change needs a local `viola verify` fixture refresh plus the contract suite, and the rows' Windows legs stay owed (per test-plan §11 Test Anti-Patterns, Test Strategy).
- NEVER add a retry or retry budget, or `#[ignore]`, to settle the macOS readiness flake, and never hand-write `stamps.json` to reach a stamped home (per test-plan §11 Test Anti-Patterns, CI / Quality / Test Data).
