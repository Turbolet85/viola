### error-handling#1.1 · values · errors · ## Error Handling · lines 8–8
- `hook` never writes to stderr and never exits non-zero (Hook Contract). A security check failing in `hook` (server verification mismatch, oversized stdin, strict-modes failure) still ends in exit 0 with no body, so the dialog renders for the human. As landed, `viola hook <event>` runs the stdin cap, the `VIOLA_NAME` / `VIOLA_DIR` shape checks and the one-object parse and, on Linux and Windows, the server verification (macOS the recorded gap), and fails open with `hook-decision` detail `oversize-stdin` · `malformed-json` · `channel-unreachable` · `server-verify-failed`. Before it reads the diagnostics level or initialises obs, the event and dialog paths run the instance's strict-modes check (`canonical`, then `trusted`): a refused or absent instance, a `VIOLA_DIR` naming no existing directory included, exits 0 at once with no `config.json` read, no role file, no stdin read, no line, no frame and no SessionEnd append; the two `--capture` arms run ahead of that check. Its hidden `--capture <DIR>` arm runs the stdin cap, the absolute, existing `<DIR>` check and the exclusive `create_private_new` claim, and writes the capture raw; with `--answers <DIR>` it also runs the `take(64)` closed-`ProbeAnswer` read and `probe_body`'s payload shape check, and prints one `decision_body` body to stdout only for a mapped answer. Its statusline form `hook statusline --capture <DIR> [--shell <WORD>]` runs the same stdin cap and `<DIR>` check and claim, writes the payload raw and the closed shell verdict, and prints nothing on any path. On every failure it prints nothing, its stderr is always empty, and it exits 0 (Decisions Log `2026-09-28`, capture arm; the founder's live ruling of 2026-10-05 on `--answers`; the founder's own answer to P4 fork 3 of chunk 2026-10-13-owed-ledger-rows («Run B + --settings», relayed verbatim by the operator, that chunk's `inputs#I1`), on the statusline form).

### security-anti-patterns#5.1 · exception · bans · ## Security Anti-Patterns (NEVER do these) › ### Universal · lines 39–39
- NEVER let `config.json`, a `VIOLA_*` environment variable or a CLI flag switch off any control in this plan: the IPC DACL or socket-directory check, the peer or server verification, the home strict-modes check or `validate_paste_text`. Environment variables are not a configuration channel (architecture.md Cross-cutting Patterns: Config management), and `VIOLA_DIR` is set by a child any same-session agent can influence. The two carve-outs are the test seams `FAKE_AGENT_PUMP_DELAY_MS` (capped at 5 s; Decisions Log 2026-09-27) and `FAKE_AGENT_HOOK_PANIC` (fires only on the exact value `1`, a forced fail-open `hook` panic; Decisions Log 2026-09-28): each exists only under `cfg(feature = "fake-agent")`, is absent from every release build and switches off nothing (§Input Validation). The terminal colour facts `NO_COLOR`, `TERM` and `COLORTERM` are read in every build (the founder's own word, chunk 2026-10-17-cli-output-discipline), only by `viola list`'s human mode and only to choose whether and how deep SGR bytes are written: they switch off no control (no escaping, no `validate_paste_text`, no check), widen no redaction and are not a configuration channel (§Input Validation). NEVER add another such seam or environment read, let these reach a release build, or let a colour fact change a control or reach a log line, error or refusal, without its own Decisions Log entry.
