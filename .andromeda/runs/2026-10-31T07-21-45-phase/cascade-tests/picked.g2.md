### test-strategy#2.1 · values · naming · ## 2. Test Strategy · lines 39–50
- **Directory pattern:** the arch uses flat `crates/viola-<area>` plus the root bin, with no declared test crate. This plan adds one test-only crate; see Decisions Log.
  - **Unit tests:** inline `#[cfg(test)] mod tests` at the bottom of each source file.
  - **Crate-level integration tests:** `crates/viola-<area>/tests/<topic>.rs`.
  - **Sync (tokio-free) E2E suites:** root `tests/{cli,hook,tui,channel,chaos,contract,security_negatives}_<topic>.rs`, sharing helpers in `tests/support/{home.rs,outer_pty.rs,fake.rs,events.rs,cli.rs,ndjson.rs}`. `events.rs` holds the one `events.ndjson` reader and its wait (`events`, `wait_events`) and the `boot` that waits for the session-start record; `cli.rs` holds the one started-child guard and runner (`Running`, `Ran`, `spawn`, `viola`), with stdout and stderr as two captures beside the exit code, and `spawn_on` / `viola_on`, which put a planted bin dir on the child's `PATH`; a plain `spawn` of `list` runs with `PATH` set to an empty bin dir, so no test reads the host's `claude` sessions. `fake.rs` holds `empty_bin`, `claude_bin` and `claude_in`, the one place a test plants the fake agent as `claude` (chunk 2026-10-16-unwrapped-sessions-on-the-board). `home.rs` holds the home-widening helpers `widen` · `grant_read` · `unwiden` · `still_widened` (Unix modes; on Windows `icacls`, its exit asserted), through which a root test widens or read-grants a home path, restores it and reads whether it is still widened. No root test file outside `tests/support/` defines its own copy of the reader, the wait, the guard or the result struct. `ndjson.rs` is the one complete-lines reader: every reader of a live-appended file parses only newline-terminated lines, because a Linux reader can observe an append part-way.
  - **Tokio-client E2E suites and the harness binary `viola-harness`:** `crates/viola-e2e/` (publish = false). This covers the rmcp client, cross-surface parity and critical-path scenarios, as `tests/{path<N>,mcp,cross}_<topic>.rs` (a numbered Path binary `path<N>_<topic>.rs`, e.g. `path6_budget_harness.rs`). The root package carries numbered Path binaries too (`tests/path1_run_start.rs`, sync, `[[test]]` `required-features = ["fake-agent"]`); both homes report in the E2E layer, whose regex is `^(path[0-9]*|tui|mcp|cross|chaos|contract)_` (§3 5-command `run` step 2).
  - **Why a test-only crate:** `crates/viola-e2e` hosts `viola-harness` and the tokio-based test clients (rmcp client), so the root package and the sync crates carry no tokio dev-dependency.   - **Fake agent:** `src/bin/viola-fake-agent.rs`, a root-package `[[bin]]` with `required-features = ["fake-agent"]`.
  - **Fuzz targets:** `fuzz/fuzz_targets/<parser>.rs`.
  - **Recorded fixtures:** `fixtures/claude/<cli-version>/`.
  - **trycmd cases:** `tests/cmd/*.toml`.
  - **insta snapshots:** `tests/snapshots/` and `crates/*/src/snapshots/`.
  - **Harness shims:** `scripts/agent-run.{sh,ps1}`.
