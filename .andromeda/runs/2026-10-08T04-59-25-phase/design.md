## Constraints
- The `not-delivered · input-not-ready` hint is a listed line of the design plan: design-system §Surface: cli → Component Patterns → 2. `viola send`: the readback mirror fixes its text, keyed by reason · detail. Whether `src/human.rs` prints the listed text today is research's question (the scope reads it so at `:215-216`).
- A hint is exactly one `hint:` line, printed on stderr directly after its refusal line, in human mode only; under `--json` no hint text is printed and the typed `refusal` / `detail` fields are the whole answer (design-system §Surface: cli → Tokens (platform-specific) → Streams). Every candidate line shown to the founder is one line of that shape.
- No hint, in any wording, names `viola release`; the two refusals that reach a driver after the takeover (`human-typing`, `budget-paused`) keep hints that speak of the human handing the wheel back (design-system §Surface: cli → Component Patterns → 2. `viola send`: the readback mirror, the T3 note). This binds W1's takeover step and every W7 candidate.
- A hint never quotes the sent text or any upstream text (design-system §Surface: cli → Component Patterns → 2. `viola send`: the readback mirror). A W7 candidate may carry the `<name>` field and fixed words only.
- Human output is ASCII only: no `·`, no `→`, no glyph in a hint or a result line (design-system §Surface: cli → Tokens (platform-specific) → Width). The web's middle dot and arrow forms are not cli forms (design-system §Iconography, Separator and Transfer arrows).
- The vocabulary of every label, cli column and refusal is short fixed phraseology words, with no filler and no guessing (design-system §Brand Identity → Domain anchors, "Standard phraseology and unable plus a reason"). The plan's own ground for withholding a hint is that it would have to guess (design-system §Surface: cli → Component Patterns → 2. `viola send`: the readback mirror, the `unknown` exit-14 bullet); whether an advice to `viola wait` is such a guess after the live reading the scope cites is the founder's question at P4, not this extract's.
- `viola run` is expression 0.0 while the child runs: it prints nothing at all, no colour, no glyph, no cursor control, and the terminal belongs to the child's screen (design-system §Brand Identity → Per-surface values; design-system §Surface: cli → Component Patterns → 5. `viola verify` / `viola ui` / `viola run`). W1's typed key and W3's "never renders" reading are taken on a window that, by this mandate, carries the child's bytes only; whether the product build honours it on the live session is research's question.

## Patterns to follow
- The send result and refusal mirror: `[RB]` / `[  ]` / `[/ ]`, the readback word padded to its column, then name, reason and detail two-space separated; a `/clear` send reads back by its measured post-condition, and a local command with none prints `unconfirmable` (design-system §Surface: cli → Component Patterns → 2. `viola send`: the readback mirror; design-system §Brand Identity → Domain anchors, Readback). W5's four readings (trailing newlines, newlines only, trailing CR, `/clear` plus a newline) are recorded in these words.
- The colour decision order: `--json`, a non-terminal stdout, `NO_COLOR` and `TERM=dumb` each give no colour and no SGR, while the ASCII readback mirror still prints in every human output (design-system §Surface: cli → Tokens (platform-specific) → Colour decision order). A driver session that captures a verb's output reads the uncoloured form; evidence files hold that form.
- `wait` prints one result line per outcome (`<kind>  <name>  <time>  cursor <n>`, the dialog form with its `dialog <id>`, and the timed-out form), with no spinner and no elapsed counter; `last` prints the message text through the shared escaper (design-system §Surface: cli → Component Patterns → 3. `viola wait` / `viola last`). The live run's "waits for the turn, reads the final text" steps, and the W7 reading of a `wait` that woke on nothing, are evidenced by these lines.
- `answer`, `pause` and `release` print the fixed phraseology lines of design-system §Surface: cli → Component Patterns → 4. Wheel, link and gate verbs; the board's WHEEL, DIALOG and CLI columns print the same words as the web strip (design-system §Surface: cli → Component Patterns → 1. `viola list`: the k9s strip table). The takeover and the stamped-home reading are read off those columns, not off a colour.
- `verify` is a step counter of static appended stdout lines, one per ledger row, closed by one summary line (design-system §Surface: cli → Component Patterns → 5. `viola verify` / `viola ui` / `viola run`). W4's pass criterion is worded in that form.

## Anti-patterns to avoid
- NEVER print upstream text, paths, pids or anyhow chains in errors or hints (design-system §Anti-Patterns → Per-Surface Bans → cli). A reworded `input-not-ready` hint that explains itself with a screen reading, a path or the sent text breaks it.
- NEVER emit colour, glyphs or cursor control under `--json`, non-TTY, `NO_COLOR`, `TERM=dumb` or `viola run` (design-system §Anti-Patterns → Per-Surface Bans → cli). Nothing added for the live run may write into the wrapped session's terminal.
- NEVER mix data and messages, and NEVER use a spinner or a live-redrawing line for a wait (design-system §Anti-Patterns → Per-Surface Bans → cli). A W7 remedy that turns the hint into progress output, or moves it to stdout, breaks both.
