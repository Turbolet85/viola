# a11y extract

## Relevance
partial — no web-spa surface is touched (no axe, ARIA, contrast or focus-order mandate applies); the chunk lands on the tui boundary (the wheel takeover, W1) and on cli output discipline (the `human-typing` refusal in W1, the `input-not-ready` hint line in W7), where a11y-plan makes no WCAG conformance claim.

## Constraints
- The tui surface is boundary-only: a11y-plan §1 (A11y scope → `viola run` TUI passthrough) requires that viola write zero bytes of its own to the builder's terminal, so in the live run every refusal, `hint:` and diagnostic must land on the driver verb's own stderr or in `diagnostics/`, never in the session window the key is typed into.
- The typed key must never be blocked, refused or delayed past the current atomic paste, and it is the key that takes the wheel: a11y-plan §4 P4 (tui) requires this as the SC 2.1.1 boundary stand-in. The compositor key of W1 is a live reading of that clause, not a new contract.
- Focus, mouse and resize sequences and terminal replies must not move the wheel on Linux: a11y-plan §3 Keyboard test harness (Tooling, the closed non-editing list F-W2) requires it. W1 focuses the target window through `hyprctl` before the key, so a focus report may reach `viola run` first; the run's evidence must attribute the wheel move to the key and not to the focus change. Whether the child enables focus reporting in that terminal, and whether the code already ignores it at HEAD, is research's question.
- After the takeover a driver `send` must be refused `human-typing` on stderr with a typed exit code: a11y-plan §4 P4 (cli) requires it. The exit value the harness contract names for that refusal is in a11y-plan §3 Keyboard test harness (Tooling).
- Any re-wording of the `input-not-ready` hint (W7) must keep the human-mode refusal layout: a11y-plan §8 Error recovery (CLI) requires `unable <reason> <detail>` on stderr, then `hint:` as the last stderr line, a typed exit code, and no hint text under `--json`.
- A kebab-case reason or detail code never stands without the plain word `unable`: a11y-plan §8 Plain language (Pattern) requires it of every candidate line P4 shows the founder.
- The readiness-gate bound falls on the driver only: a11y-plan §8 Timeout extensions (CLI) requires that a key pressed during the gate's wait go to the child and take the wheel at once, the waiting `send` then being refused `human-typing`. The W5 reading of a `send` under the real paste hint must not turn that bound onto the human.

## Patterns to follow
- Read the takeover on the product's own records (the wrapper's `channel-request` line and the `wheel` record), never on a timer: a11y-plan §3 Keyboard test harness (Tooling) sequences its gate-wait case that way, and the live run's evidence follows the same ordering.
- Probe who holds the wheel the way the harness contract does, by a driver verb's typed exit rather than by reading the screen: a11y-plan §3 Keyboard test harness (Tooling, the step-wise case). Whether that probe is usable against a live stamped session without side effect is research's question.
- A fixed CLI string is changed on purpose, with its pin: a11y-plan §8 Plain language (Verification) requires that trycmd pin every fixed CLI string, so a W7 wording change carries its trycmd case in the same commit. Whether the current hint line is pinned by a trycmd case at HEAD is research's question.
- The live run is supplemental evidence beside the gating automated cases, never in their place: a11y-plan §2 Agent-runnable invariants requires machine-verifiable evidence as the gate. The gating cases for the tui boundary are the nextest cases a11y-plan §4 P4 (tui) names; whether all of them exist and are green at HEAD is research's question.

## Anti-patterns to avoid
- NEVER parse the rendered `claude` TUI screen for content: a11y-plan §11 Universal bans it (R7). W3 reads "never renders" from the builder's screen record, so what that reading inspects must stay inside the ban; how it does is research's question.
- NEVER claim WCAG conformance for the cli or the `viola run` TUI from this run: a11y-plan §11 Strategy bans it. The run is an output-discipline and boundary reading only.
- NEVER colour `unable`, and never let a refusal other than `unknown` end without its `hint:` line: a11y-plan §11 Visual and §11 Cognitive ban both, and both bind the W7 candidates.

## Contract bindings
- a11y ↔ tests: the tui boundary and cli output-discipline checks are nextest cases on all three OS legs, surfacing only as `suites[].failures[]` in the harness `run` JSON, with no a11y rows (a11y-plan §3 Structured violation JSON schema → cli / tui; a11y-plan §9 Per-pipeline-stage a11y artifacts, the Unit / integration row). A W7 product change is graded there.
- a11y ↔ design (cli): the refusal layout and the `hint:` line are design's cli copy; a11y pins the layout, not the wording (a11y-plan §8 Error recovery). The wording stays the founder's.
- a11y ↔ architecture: the gate bound `GATE_MAX_WAIT` and the `input-not-ready` refusal are architecture's [Screen Model]; a11y-plan §8 Timeout extensions binds only that the bound falls on the driver.
- a11y ↔ obs: no a11y row is written into `<home>/diagnostics/` and none is emitted by the viola binary (a11y-plan §11 Universal); the live run's evidence is the product's own records plus the chunk's evidence files.
- The manual screen-reader pass records (`a11y/sr-pass/`) are founder-owned real-AT rows (a11y-plan §7 Per-surface SR test pattern). The founder is not at the keyboard, so this run writes none.

## Acceptance criteria contributions
- (a11y) After the key typed in the session terminal, a driver `viola send` to that session is refused `human-typing` on stderr with its typed exit code, and nothing is typed into the child (per a11y-plan §4 P4).
- (a11y) The takeover's `wheel` record follows the typed key, and the window-focus change before it produced no `wheel` record; the key itself reached the child (per a11y-plan §3 Keyboard test harness).
- (a11y) If W7 changes the hint line: the human-mode `input-not-ready` refusal still prints `unable <reason> <detail>`, then `hint:` as the last stderr line, `--json` carries no hint text, `unable` carries no SGR, and the pinned string is updated with it, on all three OS legs (per a11y-plan §8 Error recovery).
- (a11y) After any product change in this chunk, the tui boundary cases (zero viola-originated bytes, keystrokes unblocked, non-editing sequences leave the wheel, the key during the gate wait) are green on all three OS legs (per a11y-plan §4 P4).
