# security extract

## Relevance
relevant — the chunk serves two more IPC channel methods that carry user content (`wait`, `last`), adds CLI client verbs that resolve an instance's endpoint, renders untrusted upstream text to a terminal in human mode, and touches the panic and error-output path in `src/main.rs`.

## Constraints
- **Server verification before the first frame covers `wait` and `last` by name.** security-plan §Authentication & Authorization (row "IPC client-side server verification", Timing) and §Security Anti-Patterns → Authentication require the server's pid and start time to be verified, against a snapshot that passed strict-modes, before the client writes a `wait` or `last` frame. Two dated exceptions exist: `hook.event`, and CLI `viola send` after its liveness-only pre-check. The plan says no other frame or process may borrow either one. So CLI `wait` / `last` may not reuse `send`'s pre-check without their own founder-ratified Decisions Log entry (precedent: security-plan-amendments.md `2026-10-04-confirmed-send-with-cl-1-records — the fourth dated gap`). The alternative is the full Epoch 6 verification, which this chunk does not build. Scope §2's fork is a boundary widening and has to be decided at P4 / escalated. It cannot be settled inside the implementation.
- **Strict-modes entry-point set.** security-plan §Authentication & Authorization (row "`~/.viola/` access control") requires the strict-modes check in every CLI client verb that resolves an instance's `endpoint`. `wait` and `last` are such verbs. The fourth interim gap names `viola send` only. Its `snapshot.json` read is listed separately under §Input Validation (rows "CLI arguments / stdin" and "Own state files on read"). Any reuse by `wait` / `last` belongs to the same Decisions Log entry as above.
- **Serving a channel method needs its own Decisions Log entry.** security-plan §Security Anti-Patterns → Universal requires an entry for each new channel method that maps it to the IPC controls. Precedents: `hook.event` (amendments `2026-09-27-hooks-to-normalised-events`) and `send` (amendments `2026-10-04-confirmed-send…`, "`send` is served by the wrapper"). `wait` and `last` already appear in §Threat Model Summary (Attack surface, Local IPC). Whether that listing satisfies the ban, or each method needs a served-as entry like `send` got, is P4's call.
- **Channel frame bounds and closed params.** security-plan §Input Validation (row "Channel frames") requires the `MAX_FRAME` reader cap (`-32600` and close when exceeded), serde_json's default depth, the `v` check, and closed param types, with `from` absent, `null` or passing `ViolaName::try_new`. Following the landed `send` param rule, `wait` `{after?, timeout_ms?}` and `last` `{}` must be rejected with `-32602` `"invalid params"`, `data: null`, when their shape is wrong. CLAUDE.md's "bound every input" applies to `timeout_ms`. Its maximum is open in scope §2 and must be pinned, not left unbounded.
- **Own-log reads stay capped.** security-plan §Input Validation (rows "Own state files on read" and "Tailed paths (notify)") requires that replaying or tailing `events.ndjson` reads each line under a `MAX_FRAME` cap and counts an over-long line as `torn_lines`. Tailing is limited to `instances/<name>/events.ndjson` with `<name>` from `ViolaName::try_new`, ignoring symlinks. This applies to `last`'s rebuild on start, to `wait`'s lookup of already-logged events, and to whatever wake mechanism research picks.
- **Human-mode terminal escaping.** security-plan §Bootstrap phases (`logging-redaction-wire`, the human-mode CLI output bullet) and §Security Anti-Patterns → Logging (the RUSTSEC-2025-0055 class) require human-mode `wait` / `last` output to escape C0 and C1 controls, keeping `\n` and `\t`. Per §Input Validation (row "Paste text", rationale), the check runs over decoded `char`s, never raw bytes. It escapes and never strips, and it never touches `--json` output.
- **Error output is sanitised, and content stays in its contract payloads.** security-plan §Error Handling and §Bootstrap phases (`error-sanitization-wire`, and the scope bullet of `logging-redaction-wire`) allow `last_assistant_message` and event lines in the `wait` / `last` result payloads by design. They never allow them in stderr, CLI `--json` errors or channel `error.data`. External errors carry fixed codes only: `-32603` with `"internal error"` and `data: null`, `instance-unreachable` with `detail: null`, and no absolute path. No anyhow chain may hold a serde source. Full detail goes only to `instances/<name>/diagnostics/detail-*.ndjson`.

## Patterns to follow
- `send`'s landed validation split (security-plan §Input Validation, rows "Paste text" and "Channel frames"): the client checks its arguments, and the wrapper re-runs every check authoritatively before acting. `wait` / `last` params get the same wrapper-side re-check, and per §Security Anti-Patterns → Input the client checks are advisory.
- `send`'s pre-connect outcome mapping (security-plan §Authentication & Authorization, row "IPC client-side server verification", "On mismatch"): a failed reachability or verification check is `instance-unreachable` with exit 21, never a wrapper fault. This also covers a peer that vanishes while a caller is parked, which is scope §2's open client-behaviour question for research.
- The `list`-row escaping obligation shares the human-mode escaper rule (security-plan §Input Validation, row "Child executable resolution", and §Bootstrap phases `logging-redaction-wire`). One `char`-based escaper should serve every human-mode content printer. Whether any escaper already exists in code is research's question. Scope §3 records that `src/human.rs` holds none.
- If the §4 witness needs a forced panic in a `cli` verb, copy the `FAKE_AGENT_HOOK_PANIC` seam shape (security-plan §Input Validation, row "Test seam `FAKE_AGENT_HOOK_PANIC`"). That means: `cfg(feature = "fake-agent")` only, an exact closed trigger value, a fixed ASCII payload with no upstream text or path, product source naming it only in its own file, and a G2 exemption at that exact path only.

## Anti-patterns to avoid
- Writing a `wait` / `last` frame from the CLI before server verification while relying on `send`'s or `hook.event`'s dated exception without a ratified entry of its own (security-plan §Security Anti-Patterns → Authentication).
- Printing `last_assistant_message` or a `wait` event's upstream text to a terminal unescaped, or stripping controls instead of escaping them (security-plan §Security Anti-Patterns → Logging; §Bootstrap phases `logging-redaction-wire`).
- Adding a second panic seam, or any env-var-driven test switch, without its own Decisions Log entry, or letting one reach a release build (security-plan §Security Anti-Patterns → Universal, the closing seam bullet).

## Contract bindings
- **security ↔ obs:** the `cli`-role panic line (scope §4) must print exactly the fixed `error: internal error` and the codes-only `process-exit{detail:"internal-error"}` (obs-plan §7). It must carry no panic payload, path or upstream text (security-plan §Error Handling). The obs artifact canary scan's content canary must not find `wait` / `last` content in home-level role files (security-plan §Secret Management, "Secret scanning in CI").
- **security ↔ design:** design-system Component Patterns 3 (the message-mode escaper) is the rendering for the security-plan §Bootstrap phases `logging-redaction-wire` escaping floor. Design owns the `\xHH` format; security owns the set of controls covered and the no-strip rule.
- **security ↔ arch:** the `instance-unreachable` `--json` shape and exit 21, plus any new reading of an out-of-range or mid-line `after`, are §Conventions contracts. Security's only constraint on them is that the refusal or clamp carries a fixed code and no path or upstream text (security-plan §Error Handling).
- **security ↔ tests:** a new panic seam's absence from release builds is witnessed by `scripts/release-check.sh` (security-plan §Dependencies and CI, release-build rule in `.claude/rules/security.md`). The once-only stderr line is a tests-owned witness that must not pass vacuously.

## Acceptance criteria contributions
- Human-mode `viola last` / `viola wait` over a turn whose `last_assistant_message` contains ESC, BEL, CR, DEL and U+009B prints each one as escaped text, keeps `\n` and `\t` as-is, and writes no raw C0/C1 byte to stdout. `--json` output of the same turn stays serde-escaped JSON (per security-plan §Bootstrap phases `logging-redaction-wire`; §Security Anti-Patterns → Logging).
- The wrapper answers `wait` with a non-integer or negative `after`, an out-of-type or over-bound `timeout_ms`, or a `from` that fails `ViolaName::try_new`, and answers `last` with unexpected param shapes, using `-32602` `"invalid params"` and `data: null`. A frame over `MAX_FRAME` gets `-32600` and the connection closed (per security-plan §Input Validation, row "Channel frames").
- Before the chunk's code is accepted, security-plan-amendments.md holds a dated entry for each boundary the chunk crosses: (a) `wait` / `last` served by the wrapper under the IPC controls; (b) if CLI `wait` / `last` write frames after a liveness-only pre-check, a founder-ratified fifth interim gap naming them with the same Epoch 6 owners `:109` / `:111`; (c) any new `fake-agent` panic seam and its G2 exact-path exemption. A grep of the amendments file for each item is the witness (per security-plan §Security Anti-Patterns → Universal and → Authentication; §Authentication & Authorization, row "IPC client-side server verification").
- Every failing `wait` / `last` path produces sanitised output only. That covers unreachable before connect, a peer vanishing mid-park, a wrapper fault, and a panic. The `--json` body is a fixed code with `detail` either `null` or a fixed object, stderr holds no absolute path, upstream text or serde-quoted value, and the CI `secret-scan` step passes (per security-plan §Error Handling; §Bootstrap phases `error-sanitization-wire` / `logging-redaction-wire`).
