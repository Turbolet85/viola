## Constraints
- `wait` / `last` output follows the drawn shapes per layout-templates §Surface: cli / §Output structure — `viola wait` / `viola last`. `wait`: a `waiting: <name>` line on stderr, TTY only, printed once; each result is one stdout line: `<kind>  <name>  <fields>  cursor <n>` for an event, `timed out  <name>  <ms> ms` for a timeout. `last`: a `last  <name>  turn-ended <ts>` context line on stderr, TTY only; the message on stdout; `no message` on stderr when the value is null. The plan draws only `turn-ended` and `question` lines. How `permission` / `plan` / `session-end` render (presumably the same `<kind>  <name>  …  cursor <n>` form) is P4's to pin. A new human shape is a design change, not an implementation choice (per layout-templates §Surface: cli / §IA notes, "Output as a contract").
- No spinner, no elapsed-time counter, no redraw and no cursor control: every line is appended once (per layout-templates §Output structure — `viola wait` / `viola last`; §Surface: cli expression level, motion tokens "None").
- Expression level 0.0 for `--json`, non-TTY, `NO_COLOR` and `TERM=dumb`: no colour, no non-ASCII glyph. On a TTY, colour is reserved for `DIALOG` and `stale` on `viola list`. So a `question` / `permission` / `plan` result line from `wait` is NOT coloured, because it is a result, not the board (per layout-templates §Surface: cli expression level and token table; §Output structure — `viola wait` / `viola last` annotation).
- Streams never mix. Results (`wait` event / timeout lines, the `last` message) go to stdout. `waiting:`, the `last` context line, `no message`, refusals, hints and errors go to stderr. Under `--json` the outcome is ONE document on stdout, with no stderr line, no hint and no glyph (per layout-templates §Component — Primary content block 2 "Streams" and "Exit codes as the typed tail"; §Output structure — `viola list --json` for the one-document form).
- Escaping differs between `list` and these verbs. The `last` message, and any upstream text in a `wait` line, is escaped C0/C1-to-hex in human mode with `\n` and `\t` KEPT. `viola list` is stricter and escapes `\n` / `\t` too. This chunk must not copy the list escaper (per layout-templates §Output structure — `viola wait` / `viola last` "C0/C1 escaped"; §Component — Primary content block 1 "Escaping", which names the `wait` / `last` floor).
- Refusal form: `unable  <name>  <reason>  <detail>` on stderr, fields separated by two spaces, then its `hint:` line as the last stderr line. Exit 21 is `unable  instance-unreachable`, and every exit-21 cause gets its own hint. A hint names no path, pid, upstream text or `viola release`. `internal error` and `wrapper fault` take no hint (per layout-templates §Component — Primary content block 2; §Component — Primary navigation "Discoverability").
- `internal error` line: exactly `error: internal error` with no hint. The plan states it for a failed or panicked `verify` only. Extending it to `send` / `wait` / `last` (scope §4) keeps that exact text and no-hint rule (per layout-templates §Component — Primary content block 2 "Line form").

## Patterns to follow
- Argument order mirrors the channel `params`: `viola wait <target> [--after <cursor>]`, `viola last <target>`. `<target>` is always a `ViolaName`, and an unwrapped name is never a valid target (per layout-templates §Component — Primary navigation (verb structure)).
- `cursor` is the shared cross-verb reference: the byte offset `send` prints in its `[RB]` line and `wait --after` consumes. A `wait` event line prints `cursor <n>` as its last field, in the same form as the send readback line (per layout-templates §IA notes "Deep links"; §Output structure — `viola send`).
- Two-space gutter between fields, and ` - ` in place of `·` inside a field. Timestamps are printed as Data role, time-of-day with milliseconds and `Z` (`19:44:10.221Z`), as in the send mirror (per layout-templates §Surface: cli token table, `space-xs` equivalent and Data role; §Output structure — `viola wait` / `viola last`).
- No terminator word. The last printed line says what happened, to whom and where: the event line, `timed out  <name>  <ms> ms`, or the message. The exit code is the terminator (per layout-templates §Component — Footer / terminator).
- `hint:` lines point to the next verb by name (send's `input-not-ready` hint already points to `viola wait builder`). Any new exit-21 hint for `wait` / `last` follows that breadcrumb form. Whether `send`'s existing exit-21 hint text can be reused is research's question (per layout-templates §Component — Primary navigation "Discoverability"; §Output structure — `viola send`).

## Anti-patterns to avoid
- No `Waiting…` spinner, no progress or elapsed counter, no `✓` / `done` / `success`, and no summary banner (per layout-templates §Output structure — `viola wait` / `viola last`; §Component — Footer / terminator; §Component — Header / banner "No banner anywhere").
- Never report `turn-ended` as a `send` outcome. It is `wait`'s result alone (per layout-templates §Component — Hero / signature output line "What never happens").
- No colour on `wait` / `last` lines, including `DIALOG` amber on a dialog-kind result. Never strip a control character from the message: escape it as hex text (per layout-templates §Surface: cli token table `color-accent` "Only on the `DIALOG` word" in `viola list`; §Component — Primary content block 1 "Escaping").

## Acceptance criteria contributions
- `viola wait <t> --after <cursor>` on a logged `turn-ended` prints exactly one stdout line `turn-ended  <t>  <HH:MM:SS.mmmZ>  cursor <n>`. With `--timeout-ms` and no wake, it prints `timed out  <t>  <ms> ms` on stdout. `waiting: <t>` reaches stderr only on a TTY, once. No line is ever rewritten (no `\r`, no cursor-control bytes) (per layout-templates §Output structure — `viola wait` / `viola last`).
- `viola last <t>` prints the message on stdout with C0/C1 controls (CR and DEL included) escaped as hex text and `\n` / `\t` kept verbatim. A null value prints `no message` on stderr and nothing on stdout. Under `--json`, each verb prints exactly one document on stdout and nothing on stderr (per layout-templates §Output structure — `viola wait` / `viola last`; §Component — Primary content block 2 "Streams").
- A vanished wrapper on `wait` / `last` gives exit 21, with the human form `unable  <t>  instance-unreachable` followed by a `hint:` line as the last stderr line, naming no path, pid or `viola release`. Under `--json` it gives `{"v":1,"error":"instance-unreachable","detail":null}` on stdout with an empty stderr (per layout-templates §Component — Primary content block 2).
- A panic or failure in `send` / `wait` / `last` prints exactly one `error: internal error` line on stderr, with no `hint:` line, and exits 1 (per layout-templates §Component — Primary content block 2 "Line form" and "Hint line").
