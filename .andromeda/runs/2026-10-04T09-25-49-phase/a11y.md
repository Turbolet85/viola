# a11y extract

## Relevance
partial. The chunk adds the human-mode, non-TTY and `--json` output of two cli verbs (`wait`, `last`) plus the `cli`-role panic line. The a11y plan covers this as cli output discipline under Section 4 Path 6, with no WCAG conformance claim. It adds no web-spa, ARIA, focus, keyboard, contrast or motion surface.

## Constraints
- The cli surface is assertable through output discipline only. assert_cmd 2.2.2 + predicates 3.1.4 + trycmd 1.2.1, with portable-pty outer-PTY checks for TTY-only behaviour, stand in for SC 1.3.2 / 1.4.1 / 3.3.1. No result may be presented as a11y-tool evidence or as a conformance claim (per a11y-plan §1 A11y Scope Summary, "CLI and terminal entities" and Surface: cli; §3 A11y testing tool pick).
- C0/C1 escaping in `wait` / `last` human-mode text: every injected control (ESC / CSI included) must appear only in escaped form. In `wait` / `last`, `\n` and `\t` stay raw, unlike `list` table rows, where they are escaped. Under non-TTY, stdout must carry no raw C0 / C1 byte other than `\n` / `\t` (per a11y-plan §1 Surface: cli Notes, resolved bullet; §4 P6 "C0/C1 escaped"). The escaper itself is CARRY 1. How it renders CR and DEL is the security and design extracts' to pin. a11y requires only the escaped-only pass condition.
- Linear, static output: when stderr is a TTY, `wait` prints `waiting: <name>` exactly once on stderr. There is no `\r` redraw, cursor movement, erase sequence or spinner, and the line is absent under non-TTY (per a11y-plan §4 P6 "linear static output"; §4 Path 6 "Required focus order").
- No SGR, glyph or cursor control under `--json`, non-TTY, `NO_COLOR` or `TERM=dumb`. Colour is only ever a second cue beside a word, and `unable` is never coloured (per a11y-plan §1 Surface: cli Notes; §4 P6; §11 A11y Anti-Patterns → Visual).
- Refusals and faults, which covers `instance-unreachable` (exit 21) on a vanished wrapper and the `cli`-role panic line:
  - A human-mode refusal is `unable  <reason>  <detail>` on stderr, then a final `hint:` line, with a typed exit code.
  - `--json` carries one document and no hint text.
  - Faults (`error: wrapper fault`, `error: internal error`) are not refusals and carry no `hint:` line (per a11y-plan §8 Cognitive Accessibility → Error recovery, CLI bullet).
- `wait`'s timeout is caller-supplied only. `{timed_out:true}` answers a caller-passed `timeout_ms`, and viola imposes no time limit on a human (per a11y-plan §8 → Timeout extensions, CLI bullet). This is consistent with the scope's "with no `timeout_ms` it blocks".
- The cli invariants must hold on all three OS legs (`windows-2025`, `macos-latest`, `ubuntu-latest`), inside `nextest-integration` / `nextest-e2e` locally and the CI `coverage` suite (per a11y-plan §1 Surface: cli Notes; §3 CI integration; §10 SLO Invariants & A11y Budgets).

## Patterns to follow
- Results go to stdout. `waiting:`, refusals with their `hint:` and `error:` lines go to stderr, and the two are never mixed. The exact `wait` result-line shape is the design extract's (per a11y-plan §4 Path 6; design-system `:784`, `:879`).
- Fixed CLI strings are pinned by trycmd, so a copy change fails CI until the pin is updated on purpose (per a11y-plan §8 → Plain language, Verification). This applies to the new `wait` / `last` refusal layouts and to the `waiting:` line.
- Every kebab-case reason code (`instance-unreachable`, …) sits beside the plain word `unable`. No stack trace or bare number is ever the only error text, and that includes the panic path: exactly `error: internal error`, never a panic message (per a11y-plan §8 → Plain language; §11 → Cognitive).
- A11y output-discipline failures surface only as nextest failures in the harness `run` JSON `suites[].failures[]`. cli emits no a11y-violation rows (per a11y-plan §3 Structured violation JSON schema, "cli / tui").

## Anti-patterns to avoid
- NEVER claim WCAG conformance for the cli, and never present assert_cmd / trycmd / portable-pty results as a11y-tool evidence (per a11y-plan §11 A11y Anti-Patterns → Strategy).
- NEVER add a spinner, progress redraw or live-redrawing output to a parked `wait`, which prints one static `waiting:` line (per a11y-plan §11 → Motion; §4 P6).
- NEVER strip control characters: escape them. Never colour `unable`, and never emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` (per a11y-plan §11 → Visual; §1 Surface: cli Notes).

## Contract bindings
- a11y ↔ security: the C0/C1 escaper pass condition (a11y-plan §4 P6) binds to security-plan §Input Validation `:425` ("Human-mode CLI output of `wait`/`last` … escapes C0/C1 controls (keeping `\n` and `\t`)"). The escaping rule is security's, and its assertion setup is a11y's.
- a11y ↔ design: the `waiting:` line, the stream split and the "word beside every SGR" rule bind to design-system cli (`:723`, `:784`, `:878-879`) and the message-mode Component Pattern named in CARRY 1. a11y asserts them, and design owns the strings.
- a11y ↔ tests: the P6 checks run on the tests' cli drivers (assert_cmd / trycmd / portable-pty outer PTY) inside the nextest suites on all three OS legs (a11y-plan §3 CI integration). They report no a11y rows (§3 Structured violation JSON schema, "cli / tui"). Research must answer whether the harness already has an outer-PTY driver for a cli verb's stderr, which the TTY-only `waiting:` assertion needs, and whether fixtures can carry a `viola-fake-agent` turn whose `last_assistant_message` includes C0/C1 bytes.
- a11y ↔ obs: the `cli`-role panic line (`error: internal error`, exactly once, no `hint:`) binds to obs-plan §7 Per-role behaviour. a11y adds only the fault-has-no-hint rule from §8 Error recovery.

## Acceptance criteria contributions
- (a11y) In human mode, `viola wait` and `viola last` against a `viola-fake-agent` turn whose `last_assistant_message` carries C0 and C1 bytes (ESC / CSI included, plus `\n` / `\t`) show every control only in escaped form, with `\n` / `\t` raw. Under non-TTY, stdout holds no raw C0/C1 byte other than `\n` / `\t`. This is asserted with assert_cmd on all three OS legs (per a11y-plan §4 P6 "C0/C1 escaped").
- (a11y) `viola wait` under the portable-pty outer PTY prints `waiting: <name>` exactly once on stderr, with no `\r`, cursor-movement or erase sequence. Under non-TTY the `waiting:` line is absent (per a11y-plan §4 P6 "linear static output"). Whether an outer-PTY cli driver already exists is research's question. If none can land in this chunk, P4 must say so explicitly rather than drop the check silently.
- (a11y) `wait` / `last` emit no SGR under non-TTY, `NO_COLOR`, `TERM=dumb` or `--json` (per a11y-plan §4 P6; §11 → Visual).
- (a11y) In human mode, `instance-unreachable` from `wait` / `last` prints `unable  instance-unreachable  <detail>` and then a final `hint:` line on stderr, with exit 21. The `--json` document carries no hint text. The `cli`-role panic path prints exactly `error: internal error` with no `hint:` line. All three are pinned by trycmd / assert_cmd (per a11y-plan §8 → Error recovery, CLI and Verification bullets).
