## Constraints
- The message-mode pattern numbered 3 is the **cli** one: design-system §Surface: cli §Component Patterns item 3, "`viola wait` / `viola last`" (`:783`). The web-spa §Component Patterns item 3 (`:530` block) is `<viola-transfer>` and does not apply. This answers scope §3's open question.
- `wait` human mode requires: one static `waiting: <name>` context line on stderr (TTY only), then exactly one result line on stdout in one of three shapes: `turn-ended  <name>  <HH:MM:SS.mmmZ>  cursor <n>`, `<dialog-kind>  <name>  dialog <id>  cursor <n>`, `timed out  <name>  <ms> ms`. Fields are two-space separated, with no spinner and no elapsed counter (per design-system §Surface: cli §Component Patterns 3; §Anti-Patterns §Per-Surface Bans cli "spinner").
- `last` human mode requires a context line `last  <name>  turn-ended <HH:MM:SS.mmmZ>` on stderr (TTY only), then the message text on stdout with C0/C1 escaped. A `null` message prints `no message` on **stderr** and nothing on stdout (per design-system §Surface: cli §Component Patterns 3).
- Escaping strength: `wait` / `last` message text keeps `\n` and `\t`. Only `list` rows also escape those two (T5), so `list`'s stricter rule must not leak into the `last` escaper (per design-system §Surface: cli §Component Patterns 1, `:746`; §Anti-Patterns §Per-Surface Bans cli "NEVER print upstream text …").
- No colour, glyph or SGR on these verbs. A `DIALOG`-kind wait result is not amber ("a result, not the board"). The colour decision order still makes `--json`, non-TTY, `NO_COLOR` and `TERM=dumb` plain. Viola's own words are ASCII only (per design-system §Surface: cli §Component Patterns 3; §Surface: cli §Tokens "Colour decision order"; §Anti-Patterns §Per-Surface Bans cli).
- Streams: results go to stdout and context lines to stderr. Under `--json`, the whole result, refusal or error is one JSON document on stdout. It carries no `hint:` line and no TTY context line (per design-system §Surface: cli §Tokens "Streams"; §Anti-Patterns §Per-Surface Bans cli "NEVER mix data and messages").
- Exit phraseology for these verbs: exit 21 prints `unable  instance-unreachable`, then the cause's hint. Exit 20 prints `error: wrapper fault  <code>` with no hint. Exit 1 prints exactly `error: internal error`: fixed, with no hint, no chain and no stack trace (per design-system §Surface: cli §Exit-code phraseology table; §Component Patterns 2 hint list, `instance-unreachable` causes; §Platform-Specific Notes "Stack traces").

## Patterns to follow
- `viola send`'s mirror and hint lines in `src/human.rs`: two-space separated fixed fields, a TTY-gated stderr context line, and the result on stdout. `wait` / `last` follow the same stream split and field spacing (per design-system §Surface: cli §Component Patterns 2).
- The per-cause `instance-unreachable` hints (not running / unwrapped / strict-modes / server verification) are shared across verbs because the code is shared (T4). `wait` / `last` reuse those exact hint strings and must not add new prose (per design-system §Surface: cli §Component Patterns 2).
- Data fields: timestamps in `HH:MM:SS.mmmZ`, and cursors and dialog ids as plain integers after their keyword (`cursor 49102`, `dialog 7`) (per design-system §Typography, Data row; §Surface: cli §Component Patterns 3).
- Context only, never bare success. A result says what happened, to whom and at which cursor (per design-system §Anti-Patterns §Per-Surface Bans cli "NEVER print \"done\" or \"success\" without context").

## Anti-patterns to avoid
- No spinner, progress bar, elapsed-time counter or in-place redraw while `wait` is parked. Only the one static `waiting:` line is allowed (per design-system §Anti-Patterns §Per-Surface Bans cli; §Rejected Defaults "Optimistic \"Sending…\" spinner").
- Never strip control characters from upstream text and never put upstream text in a hint or error line. Escape it as `\xHH` text in the message body only (per design-system §Anti-Patterns §Per-Surface Bans cli "NEVER print upstream text …"; §Surface: cli §Component Patterns 1).
- No green `✓`, red `✗`, emoji, or colour on `timed out` / `turn-ended` (per design-system §Anti-Patterns §Per-Surface Bans cli; §Universal Bans "NEVER use color purely for decoration").

## Acceptance criteria contributions
- (design) `viola wait <name>` on a TTY prints exactly one `waiting: <name>` line on stderr and one result line on stdout matching `turn-ended  <name>  <HH:MM:SS.mmmZ>  cursor <n>`. With `--timeout-ms` expiring it prints `timed out  <name>  <ms> ms`. With stdout piped, no `waiting:` line, no SGR byte and no non-ASCII viola glyph appears (per design-system §Surface: cli §Component Patterns 3; §Tokens "Colour decision order").
- (design) `viola last <name>` prints the message on stdout with every `Cc` except `\n` / `\t` rendered as `\xHH` text (for example ESC as `\x1B`, CR as `\x0D`, DEL as `\x7F`) and no character dropped. A `null` message prints `no message` on stderr and an empty stdout (per design-system §Surface: cli §Component Patterns 3; §Component Patterns 1 `:746`).
- (design) Under `--json`, neither verb prints a `hint:` line, a `waiting:` / `last` context line or any SGR. Stdout holds exactly one JSON document (per design-system §Surface: cli §Tokens "Streams").
- (design) A vanished wrapper exits 21. In human mode stderr shows `unable  instance-unreachable` followed by exactly one cause hint from the shared T4 list. A panic or fault shows exactly one `error: internal error` line with no hint (per design-system §Surface: cli §Exit-code phraseology; §Component Patterns 2).
