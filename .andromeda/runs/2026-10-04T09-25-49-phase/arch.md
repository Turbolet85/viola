# arch extract

## Relevance
relevant — the chunk adds two channel methods and two CLI verbs whose wire shapes, wake set, cursor semantics, exit codes and blocking model are all fixed by architecture.md.

## Constraints
- **Wire shapes are locked.** architecture §Standard Contracts → Channel methods requires `wait` `{after?, timeout_ms?}` → `{event:<ndjson event line>, cursor}` (cursor = end offset of that event's line) or `{timed_out:true}`, and `last` `{}` → `{last_assistant_message:<string|null>, ts:<string|null>}`. Every `params` carries `v` + `sender`, plus `from` when `VIOLA_NAME` is set; success travels as `result.ok`, faults as `error` with the closed `-32600…-32603` codes (§Conventions → Error handling schema). The CLI verbs mirror those params: `viola wait <target> [--after <cursor>] [--timeout-ms <n>]` and `viola last <target>` (§Conventions → CLI).
- **Wake set and cursor reading.** §Established Decisions [Message Broker / IPC] requires `wait` to wake only on `turn-ended` · `question` · `permission` · `plan` · `session-end`. With `after`, it returns the first such event whose line STARTS at or after that byte offset into `events.ndjson`, at once if it is already logged. Without `after`, it returns the next one appended after the call. `send`'s `ok` cursor (§Standard Contracts: the end offset when the send was accepted, before the paste) must be a valid `after`. `activity` never wakes it (§Conventions → Hook → kind map), and neither do `wheel` / `budget-gate` / `send-issued` / `send-confirmed` / `send-refused` (§Standard Contracts → Event `data` per kind, the log-only paragraph). The plan defines no reading for an `after` past EOF or one that falls mid-line: P4 pins one, and a new detail is a §Conventions / §Standard Contracts amendment at wrap. Closest precedent: the SSE `id:` rule, "an offset beyond the file's length means the file was replaced… replayed from 0" (§Standard Contracts → SSE feed).
- **Pending-dialog rule.** [Message Broker / IPC] requires a dialog that is pending when `wait` is called without `after`, or with an `after` at or before that dialog's line, to be returned at once. With an `after` past that line, `wait` blocks for the next event. The plan gives the pending source as the wrapper's in-memory state, mirrored to the snapshot's `pending_dialog` (§Standard Contracts → Instance snapshot). No code produces that state before `:78`. Whether the without-`after` branch lands here or with `:78` is P4's call.
- **Timeout and unreachable.** [Message Broker / IPC] requires a `timeout_ms` expiry to answer `ok` `{"timed_out":true}`, never a refusal. With no `timeout_ms`, `wait` blocks until an event arrives. A vanished endpoint gives the caller `instance-unreachable`: exit `21`, CLI `--json` `{"v":1,"error":"instance-unreachable","detail":null}` (§Conventions → CLI exit codes; §Standard Contracts → CLI `--json` output). A wrapper protocol fault is exit `20` with the `wrapper-fault` `detail` object. Whether the sync client today tells a mid-call peer close apart from a fault is research's question. The MCP default `timeout_ms` is an open item that must stay below the MCP client's tool-call timeout ([MCP]). The MCP tools are outside this chunk.
- **`last` source.** [Message Broker / IPC] and §Standard Contracts → Event `data` per kind (`turn-ended`: "the source `last` rebuilds from") require the value to be the newest `turn-ended`'s `last_assistant_message`. The wrapper holds it in memory and rebuilds it from `events.ndjson` on start. Both fields are `null` before any turn has ended. The rebuild must follow the versioned-tolerant reading: heal a torn last line, skip and count unknown kinds and fields, no `deny_unknown_fields` (§Established Decisions [Validation]; §Cross-cutting Patterns → Mixed-version tolerance, Crash-safe disk writes).
- **Tokio containment and crate placement.** §Cross-cutting Patterns → Tokio containment requires CLI `wait` to be a blocking read on `viola-channel`'s sync client, and the server side on the `run` path to use std threads and blocking I/O only. Per §Infrastructure Patterns → Crate dependency direction: the wake and in-memory `last` live in the root bin's `run` (`src/run/`, `src/cmd/run.rs` `Methods::dispatch`). Event-log reading and tailing belong to `viola-state`, the only crate listed with notify "with tailing". `viola-channel` stays sync and tokio-free. No sync crate may gain `tokio` (deny-sync ban, [Concurrency / Backend Framework]).
- **Exit `1` and the `cli`-role panic line.** §Conventions → CLI exit codes says the `cli` role's internal error prints exactly `error: internal error` on stderr, with no hint. That same entry records the present `send` gap: a panic in `viola send` exits 1 with no line, because `src/main.rs` files only `verify` under `cli`. The panic hook stays the first statement of `main`, and anyhow stays only in the root bin, with the catch-site reporter `viola::obs::report_internal_error` ([Error Handling]). If `send` / `wait` / `last` are re-filed and the line moves to the one catch site, the gap text in that exit-`1` entry becomes a §Conventions amendment at wrap.

## Patterns to follow
- `send`'s landed path is the template: CLI verb → sync channel client → `run`'s `Methods::dispatch` arm, `ok` / `refusal` / `error` mapped to the typed exits and the CLI `--json` mirror (§Standard Contracts → CLI `--json` output, Wrapper channel frames). `wait` and `last` refuse nothing on the wheel or the budget: those gates cover only `send` / `answer` ([Human Takeover / Wheel]; [Budget Governor]: "`budget-paused` gates only `send`").
- Replay-on-start: the snapshot is rebuilt from the log, and `last` and the `dialog_id` counter are restored from `events.ndjson` the same way ([Database / State Store]; [Message Broker / IPC]). Readers tolerate a torn last line and never truncate the log (§Standard Contracts → Snapshot envelope).
- Output channels: short-lived CLI verbs may write their human output to stderr, and stdout carries the `--json` result (§Cross-cutting Patterns → Diagnostic output channels). Codes-only lines go to `diagnostics/cli-<name>.ndjson`. Content (`last_assistant_message`, event `data`) goes only to the instance's `diagnostics/detail-<role>.ndjson`.
- Upstream text is content: `last_assistant_message` and event lines are forwarded as escaped strings and never interpreted (§Cross-cutting Patterns → Untrusted upstream text). `--json` carries them serde-escaped. The human-mode escaper is security / design's to specify.

## Anti-patterns to avoid
- Polling: "nothing polls" ([Message Broker / IPC]; §Standard Contracts → Communication protocols: "no polling endpoints in v1"). A parked `wait` wakes on the append, never on a timed re-read of the file. The wake mechanism (an append-path signal vs `viola-state` tailing) is research's to ground.
- A Tokio runtime, an async client, or a `tokio` dependency anywhere on the CLI `wait` / `last` or `run` server paths (§Cross-cutting Patterns → Tokio containment).
- New wire vocabulary outside `viola-core`: a new refusal reason or `detail`, or a `-32602` cause, for an out-of-range `after` or `timeout_ms` would extend a closed set. §Conventions → Error handling schema allows that only in `viola-core`, and the change needs its amendment.

## Acceptance criteria contributions
- `wait` returns `{event, cursor}`, with `cursor` the end offset of the returned line, for each of the five wake kinds only. An `after` equal to a prior `send` `ok` cursor returns an already-logged `turn-ended` at once. A log holding only `activity` / `wheel` / `budget-gate` / `send-*` / `prompt-submitted` / `session-start` lines after `after` does not wake it (per architecture §Established Decisions [Message Broker / IPC]; §Standard Contracts → Channel methods).
- `wait --timeout-ms <n>` with no wake event exits 0 with `{"v":1,"ok":{"timed_out":true}}`. A wrapper killed while `wait` is parked exits `21` with `{"v":1,"error":"instance-unreachable","detail":null}`, not `20` (per architecture §Conventions → CLI exit codes; §Standard Contracts → CLI `--json` output).
- `last` returns `{last_assistant_message:null, ts:null}` before any turn, and the newest `turn-ended`'s message + `ts` after one. A restarted wrapper on the same instance returns the same value, rebuilt from `events.ndjson`, torn last line tolerated (per architecture §Established Decisions [Message Broker / IPC]; [Database / State Store]).
- Workspace discipline holds: the new code lives in the root bin (`src/cmd/`, `src/run/`), plus `viola-channel` / `viola-state` for client and log reading. No sync crate gains `tokio`: the `deny-sync.toml` per-crate run and the tokio-less `cargo check` stay green. Channel `METHODS` dispatch no longer answers `wait` / `last` `-32601` (per architecture §Infrastructure Patterns → Crate dependency direction; §Cross-cutting Patterns → Tokio containment).
