## Relevance
relevant — this chunk lands the CLI + channel halves of critical Path 3 (`wait` / `last` readback), a §4 root-bin clock-driven unit case, a chaos case, the human-mode C0/C1 escaping case and a `cli`-role exit/panic-line table change.

## Constraints
- Tier is Comprehensive: per-OS coverage gates `--fail-under-lines 85 --fail-under-functions 95 --fail-under-regions 80` apply to the new `wait` / `last` / escaper / main.rs code on all three OS jobs, and a Linux-only local green is not proof for the Windows/macOS legs (per test-plan §10 Coverage thresholds; §11 Test Strategy "Linux-only local run").
- The `wait` `timeout_ms` deadline runs in the wrapper and is driven in tests only by the injected `viola_core::Clock` in the §4 root-bin `wait` handler case. It wakes only on `turn-ended` / `question` / `permission` / `plan` / `session-end`, returns at once for a match at or after `after`, and returns `{timed_out:true}` only once the clock passes `timeout_ms`, never before. No mock_instant or paused tokio clock may be used to steer a spawned wrapper (per test-plan §4 root bin; §8 Time; §11 Universal "MockClock … another process's time").
- E2E may block on `wait --timeout-ms` only if the verdict is the product's own exit code or `timed_out` field AND the same deadline has the §4 clock-driven unit case. No test-owned sleep, timer or elapsed-time verdict is allowed, and sync waits key on `events.ndjson` byte offsets or `viola wait --after` (per test-plan §11 Universal "real time without injection"; §11 E2E "sleep(N)"; §2 Agent-runnable invariants).
- Path 3 is multi-surface (cli, ipc-internal channel + MCP, api-service, web-spa). If this chunk lands only the cli + channel halves, then like Path 2's landed form each unbuilt surface step (MCP `wait`/`last`, `/api/sessions` busy→idle, Playwright STATUS cell) needs a named owning route entry. Never assert the path on one surface and call it covered (per test-plan §6 Path 3; §6 Path 2 "As landed"; §11 Test Strategy "multi-surface critical path on one surface only").
- Oracles are literals: the wake-set kinds, the exit codes (0 / 1 / 21), the `{"v":1,"error":"instance-unreachable","detail":null}` document and the exact `error: internal error` line are written into the tests, never imported from product constants. Exit codes are compared as integers and refusals/errors as serde kebab values, never as `Debug` strings (per test-plan §11 Unit).
- On-disk state comes only from real `viola run` / hooks / verbs against `viola-fake-agent` in a fresh `target/e2e-home` home, with env passed per child via `Command::env`. The only exception is chaos and forward-compat edits to files the product already wrote, so an `events.ndjson` turn-ended or dialog line is never hand-written into a fresh home. A hand-appended dialog line for the scope §1 pending-dialog reading counts as a §7 exception only on a product-written file, and that has to be argued (per test-plan §7 Seed strategies, Test data lifecycle; §11 Test Data).
- Zero flakiness: nextest `retries = 0`, no `#[ignore]` parking, and a red stays in-chunk until its root cause is fixed. This covers the parked-`wait` and killed-wrapper races (per test-plan §10 Zero-flakiness budget; §11 CI / Quality).

## Patterns to follow
- Test layout: root `tests/cli_*.rs` (integration layer) for the `--json` document per exit code; root `tests/channel_*.rs` for the channel `wait` / `last` frames with jsonschema-validated result shapes; `chaos_*.rs` (E2E layer, filterset `binary(/^(…|chaos|contract)_/)`) for the endpoint-vanishes case; inline `#[cfg(test)] mod tests` with rstest `#[case::label]` for unit tables. Critical-path tests are named `path3_<slug>`, everything else `<subject>_<condition>_<expected>` (per test-plan §2 Test directory + naming conventions; §5 Cross-module patterns Wrapper channel; §3 5-command implementation `run` step 1–2).
- Root boot model: the rstest chain `home → fake_agent_path → stamped_home → booted_wrapper` (`tests/support/home.rs`, `Wrapper::boot/send/stop`, bounded `WITHIN` waits in `tests/support/watch.rs`). A spawned `viola wait` is a `std::process` child checked with `try_wait()`, never assert_cmd `.assert()` on a long-lived process, and readers of the live `events.ndjson` use the complete-lines reader `tests/support/ndjson.rs` (per test-plan §3 5-command implementation `run` step 2; §2 `ndjson.rs`; §11 E2E assert_cmd rule).
- Deterministic event order through a checked-in fake script `fixtures/fake-scripts/<scenario>.json` (Path 3 names `path3.json`: gated PostToolUse activity, then gated Stop), released by control lines appended to `<home>/fake/<name>.control`. The script is validated by `schemas/fake-script.v1.json` and joins the `contract_fixture_hygiene.rs` walk. One caveat: §7 says the fake agent sends a hook only the recorded fixture bytes (`<Event>.<variant>.json`) and invents no shape, so Path 3's `last_assistant_message:"done: <prompt>"` signal depends on what the recorded `Stop` fixture carries. Whether `fixtures/claude/2.1.283/Stop.default.json` has a `last_assistant_message`, and whether a per-prompt value needs a new fixture variant or fake-agent change, is research's question (per test-plan §7 Fake agent, Fixture hygiene; §6 Path 3 step 1).
- The `cli`-role exit/panic table: extend the existing rstest tables (`exit_code_maps_role_and_outcome`, `role_of_…`) to `send` / `wait` / `last` with literal expectations, beside the `cli_verify.rs` pin of `error: internal error` (per test-plan §6 Security sweep, hook in-process panic unit tests; §5 CLI `tests/cli_verify.rs`).

## Anti-patterns to avoid
- NEVER add a new forced-panic env seam, or widen G2's exemption, to witness the `cli`-role panic line on the real binary without a Decisions Log entry. `FAKE_AGENT_HOOK_PANIC` is the only seam, G2 exempts only `src/cmd/hook/seam.rs:<digits>`, any new seam name becomes a `cli_controls_not_disableable.rs` row, and a real-binary panic in a `target/e2e-home` home trips G2 unless it runs in an out-of-scan home like `chaos_feed_panic.rs`. Which witness to use is P4's fork (per test-plan §6 Security sweep seam paragraph; §5 second carve-out; §11 Mocking "monkey-patch" / failpoint rule).
- NEVER parse the child screen or use `sleep` to order `activity` before `turn-ended`. Use the gated fake-script steps and the logged `activity` record's offset (per test-plan §11 E2E).
- NEVER let a parked `wait` test or the chaos kill reuse an endpoint name, or use `try_overwrite`. Take the endpoint only from `snapshot.json` (per test-plan §11 Integration).

## Contract bindings
- tests ↔ obs: the `cli` role panic/err path must emit `process-exit{detail:"internal-error"}` when an instance resolves (obs-plan §7 Per-role behaviour), and G2 (zero `event:"panic"` lines) plus G4 (schema conformance) run over every `target/e2e-home` home these tests create. The tests own the check bodies (per test-plan §6 Schema conformance; §7 Test data lifecycle CI).
- tests ↔ security/obs NEVER-log floor: `last_assistant_message` is user content. The canary scan asserts the fed canary never appears in home-level `<home>/diagnostics/*.ndjson` (for example `cli-<name>.ndjson` from `viola last` / `viola wait`), only in `events.ndjson` and `instances/<name>/diagnostics/detail-*.ndjson`. Error-sanitization checks apply to every `--json` document (per test-plan §6 Error sanitization and secret scan, Canary).
- tests ↔ security Vector 8: human-mode `wait` / `last` escape C0/C1 (keeping `\n`, `\t`) is a required test (per test-plan §1 security-vector-coverage (child spawn); §4 root bin "Human-mode C0/C1 escaping").
- tests ↔ arch Wrapper channel: `wait` / `last` result and error shapes are schema-validated with jsonschema from the product's schemars schemas, and `cursor` is the end offset of the returned line (per test-plan §5 Cross-module patterns Wrapper channel).
- The harness 5-command surface (`boot` / `status` / `logs` shapes) is unchanged by this chunk. Whether `boot --script` already serves Path 3's script is research's question (per test-plan §3 5-command implementation).

Coverage stays at or above 85 / 95 / 80 per OS (per test-plan §6 Security sweep unit tests; §4 root bin; §10 Coverage thresholds; §11 Unit literals).
