## Relevant amendment history
- **2026-09-28-cli-output-tokens** — built clap 4.6.7 without its `color` feature, so `--help` and usage are plain in every mode, no dependency reads a colour or terminal variable, and every styled byte of human output comes from viola's own SGR module (research F1: `CLICOLOR_FORCE` could force SGR into a pipe; `cli_output_plain` witnessed on 3 OSes). This chunk's design acceptance requires "no SGR byte" on `wait` / `last` with stdout piped or under `--json`. The new subcommands and their flags (`--after`, `--timeout-ms`) must not bring that back, and `cli_output_plain` is the precedent witness to extend. The same chunk's P4 ruling ("no code without a live consumer") deferred the message-mode escaper to this entry (CARRY 1). That deferral is a route carry, not a design amendment.
- **2026-09-28-capability-ledger-and-viola-verify** — fixed `verify`'s static step-counter lines and the exit-1 row of the §Exit-code phraseology table. Exit 1 carries verify's own `unable: …` refusals, each with a hint, beside `error: internal error`, and a failing row prints no stderr word. `verify` is the only verb `role_of` files as `Role::Cli` today. This chunk's CARRY 2 fixes the panic line for `send` / `wait` / `last` by moving `error: internal error` to the one catch site. That move must not double the line or change verify's exit-1 phraseology this amendment fixed. The static per-line output, with no in-place redraw, is also the precedent for `wait`'s single static `waiting:` line.
- **2026-09-29-t15-07-57-wrap** — registry migration (U35). It moved the design-system Decisions Log verbatim to `design-system-amendments-archive.md` and lifted its in-force items into the body. The cli rules the extract relies on (§Surface: cli Component Patterns 1–3, the hint list, the exit-code table) therefore stand in the body. Their reasons live only in the archived 2026-09-24 entries below, so read those entries when P4 weighs a contestable reading.
- **2026-09-24 overseer fix pass, T4 (archived)** — gave cli pattern 2 one fixed hint per cause for exit 21: not running, unwrapped name, strict-modes, server verification. `error: internal error` keeps no hint. Under `--json` no hint prints, and the exit-21 payload stays `{"v":1,"error":"instance-unreachable","detail":null}`, "pending an arch amendment" for per-cause detail codes (obs-plan D-20; stale-heartbeat and unwrapped-name have no code yet). This is the source of the extract's rule that `wait` / `last` reuse the shared exit-21 hints with no new prose and keep `detail: null`. A per-cause `detail`, or a new cause such as a mid-call close while parked, is an arch amendment, not a design one.
- **2026-09-24 overseer fix pass, T5 (ratified, archived)** — made `list` rows also escape `\n` and `\t`, so each row stays one fixed-width line. It states that the security plan's "keeping `\n` and `\t`" is a floor and that `wait` / `last` text keeps them. This is the direct source of the extract's warning that `list`'s stricter escaping must not leak into the `last` escaper built here (CARRY 1).
- **2026-09-24 overseer fix pass, T3 (archived)** — banned `viola release` from every driver-facing hint, with tests asserting that no driver-facing hint contains `release`. The exit-21 and fault lines of `wait` / `last` reach drivers, so whatever hint strings this chunk wires fall under the same assertion.
- **2026-09-24 overseer decisions, exit-1 start refusal hint (archived)** — every refusal carries a fixed `hint:` line with no paths or pids. `error: internal error`, the other exit-1 outcome, keeps no hint. This is the rule behind CARRY 2's acceptance: exactly one `error: internal error`, with no hint, on a panic or dispatch `Err` in `send` / `wait` / `last`.
- **2026-09-24 Phase 6 iteration 1, Loading Indicators override (archived)** — overrode UX guideline 8 (#78, "spinner or skeleton"). Waiting is shown as words, `waiting:` among them. This is the origin of the ban on spinners and elapsed counters, and of the single static `waiting: <name>` stderr line on TTY that `wait` human mode must print.
