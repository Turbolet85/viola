## Relevant amendment history
- **2026-10-04-dialog-answers-by-dialog-id** — §8 Timeout extensions (CLI): was "viola imposes no limit on a human"; now a raised dialog takes `viola answer` only within `DIALOG_DEADLINE` (60 s PROVISIONAL, under the `hooks.json` `timeout` of 75 s). On expiry the hook exits 0 with no body, the dialog renders for the human in the `claude` TUI, and a later `answer` is refused `not-delivered` / `unknown-dialog` (exit 13). This is the human fallback that W3d-b's "the `null` to the human stays" outcome and the extract's acceptance item depend on. The `permission` case's late-answer or expiry assertions must use this exact refusal and exit code. The amendment also keeps "the terminal carries no conformance claim", which matches the extract's ban on WCAG claims.
- **2026-10-04-the-wheel** — §4 P4 case (3) as landed probes the wheel with an `answer` to no pending dialog: exit 13 for the driver, 10 for the human. This is the precedent that the same `answer` refusal carries a different typed exit code by caller role. The `permission` case's human-mode refusal assertions (extract: `unable <reason> <detail>` + `hint:`, typed exit `10`–`14`) must pin the role-correct code. It also fixes the Windows platform fact for the wheel (the inbox ConPTY swallows focus reports, and an injected mouse report takes the wheel as key-down records). Any `permission` case that drives through the outer PTY on `windows-2025` must not assume Linux/macOS wheel behaviour.
- **2026-09-24-quality-gates** — §1 CLI output-discipline bullet · §1 cli tool reach · §9 Unit / integration row · §10 Standard+ invariants: the cli output-discipline tests run on all three OS legs. Locally they report under `nextest-integration` / `nextest-e2e`. In CI they report inside the per-OS `test` job's single instrumented `coverage` suite, and the `suites[]` enum gained `coverage`. This is the placement the extract requires for the `permission` case: no new `suite` value, no skip, and failures surfacing only as nextest failures in `suites[].failures[]`.
- **2026-09-27-browser-verdict-reachability** — the `test` job's gate became `coverage,doctest,playwright` (was `coverage,doctest`), and the browser pipe now runs on all three legs with the a11y verdict ubuntu-judged. This is the gate the extract's a11y ↔ tests binding cites for the cli case. The web-spa half of Path 3 (`a11y-p3`) stays a Playwright concern outside this chunk.
- **2026-09-28-mutation-testing-to-the-epoch-boundary** — §10: the CLI output-discipline invariants P4/P6, where they live in crate tests, are covered by the epoch-boundary mutation audit (`run --mutants`), no longer by a per-chunk or CI mutation gate. Any P6 no-SGR / control-escaping check this chunk adds or relies on for `wait` / `answer` output gets no per-chunk mutation run. Its mutation coverage falls to the Epoch 3 boundary audit.
- **2026-09-25-pty-wrapper-on-windows** — §3 Keyboard test harness · §6 CLI equivalent: on Windows the zero-viola-bytes oracle is literal absence of viola's own literals, not byte-for-byte "no SGR the child did not emit". ConPTY emits its own SGR and cursor bytes on every spawn. This is a trap if the `permission` case asserts TTY-only P6 behaviour (the once-only stderr `waiting: <name>` line, no SGR) through the portable-pty outer PTY on `windows-2025`: a raw no-SGR check there would fail on ConPTY's own bytes.
- **2026-09-29-sideloaded-conpty** — §3 · §6: the Windows literal-absence check names both ConPTY hosts. The inbox host emits its spawn preamble. The sideloaded `OpenConsole.exe` emits `ESC[1t ESC[c ESC[?1004h ESC[?9001h` at spawn and `ESC[?1004l ESC[?9001l` at exit, and its DA1 query is answered by the piped driver in tests, never by viola. This extends the previous trap: any outer-PTY output assertion this chunk writes on Windows must tolerate both hosts' bytes and credit them, not viola.
