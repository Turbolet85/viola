## Constraints
- `viola answer` success prints one stdout line, `answered  <name>  dialog <id>`, with two-space gutters. This is the last printed line, and there is no terminator word (`done`, `success`) (per layout-templates §Output structure — wheel, handoff and dialog verbs; §Component — Footer / terminator).
- The argument order mirrors the channel `params`: `viola answer <target> <dialog_id>`, with `<target>` always a `ViolaName`. The plan's example takes the response on stdin (`viola answer builder 7 < response.json`). This bears on the scope's open `[inferred]` about how `response` is supplied, and it agrees with the stdin/`--file` Session Learning. Whether `--file` is also offered is not pinned by this plan (per layout-templates §Component — Primary navigation (verb structure); §Output structure — wheel, handoff and dialog verbs).
- `answer` refusals use the shared `unable` column on stderr: `unable  <name>  <reason>  <detail>`, then a `hint:` line as the last stderr line, keyed by reason (or reason · detail). The `unknown-dialog` case is pinned: `unable  builder  not-delivered  unknown-dialog`, exit 13, then `hint: that dialog is not pending; viola list shows the current DIALOG`. The `unverified-cli` refusal (exit 12) needs its own hint. The plan does not pin that hint's wording. Hints that point to the next verb by name (e.g. `viola verify`) are the pattern (per layout-templates §Component — Primary content block 2: refusal lines and the `unable` column; §Component — Primary navigation (verb structure)).
- The exit codes are the typed tail: 10 `human-typing`, 12 `unverified-cli`, 13 `not-delivered`, 14 `unknown`, 20 wrapper fault (`error: wrapper fault  <code>`), 21 `unable  <name>  instance-unreachable`. There is no hint for `unknown`, wrapper fault or `internal error` (per layout-templates §Component — Primary content block 2).
- `--json` is the machine view of every data verb. Under it `answer` prints exactly one typed document on stdout (`{"v":1,"ok":…}` or the refusal document), with no stderr line and no hint (per layout-templates §Component — Primary navigation (verb structure); §Component — Primary content block 2).
- The `viola wait` dialog result line is `<kind>  <name>  dialog <id>  cursor <n>` on stdout, where `<kind>` is `question` / `permission` / `plan`. The kind is never coloured, because this is a result and not the board. An event with no `dialog_id` reads `dialog unknown`. `waiting:` goes to stderr, only on a TTY without `--json`. There is no spinner and no elapsed counter (per layout-templates §Output structure — `viola wait` / `viola last`).
- Streams never mix: results go to stdout, and refusals, hints and errors go to stderr. Colour on the CLI is reserved for `DIALOG` (in `viola list` only) and `stale`, so `answered` / `unable` take no SGR. Non-TTY, `NO_COLOR` and `TERM=dumb` output is plain ASCII (per layout-templates §Surface: cli (Expression level); §Component — Hero / signature output line; §Component — Primary content block 2).

## Patterns to follow
- The landed `wait` / `last` human writers and their one catch site, which prints `error: internal error` once with exit 1 and no hint. The plan's catch-site list names `send`, `wait`, `last` and `verify` only. Whether `answer` joins that one printer is research's and P4's question (per layout-templates §Component — Primary content block 2; §Output structure — `viola wait` / `viola last`).
- The shared `unable` and `hint:` vocabulary: `send` pads it after `[/ ]`. Every other verb, `answer` included, prints the bare `unable` first word, so `answer` takes the `[/ ]` glyph nowhere (per layout-templates §Surface: cli (Signature placement)).
- The `viola list` DIALOG column (`DIALOG <kind>`, with `DIALOG` in `color-accent`, or `none`) is the board's reading of a pending dialog. The `unknown-dialog` hint points the driver there. Whether `list` already renders DIALOG from the snapshot's `pending_dialog` is research's question (per layout-templates §Component — Primary content block 1: `viola list` strip rows; §Output structure — `viola list` (human TTY)).
- `--help` groups `answer` under `traffic:` with `send, wait, last`. Whether the landed help table already lists it is research's question (per layout-templates §Output structure — `viola --help`).

## Anti-patterns to avoid
- Printing upstream text (the question text, plan text, tool `input` or the free-text answer) in any human line or hint. A hint never quotes sent or upstream text, and never names a path or a pid (per layout-templates §Component — Primary content block 2).
- Naming `viola release` in any `answer` hint, including on a `human-typing` refusal, because hints reach drivers (per layout-templates §Component — Primary navigation (verb structure)).
- Adding a human column or a new human field to the `wait` dialog line or `answer` output. Human columns and words are a stable contract, and new fields go into `--json` first (per layout-templates §IA notes (Output as a contract)).
