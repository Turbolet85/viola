## Patterns to follow
- `obs_event!` only, with explicit typed fields, under `#[instrument(skip_all, name = "...", fields(...))]` (§4 naming convention; §8 Integration points 1); `corr`, `conn`, `instance` passed as explicit values into the channel worker / await thread, never recovered from span context (§3 Trace context propagation, `.andromeda/registries/contracts/obs-plan/trace-context-propagation.md` → Internal async boundaries).
- `channel-response` emitted from the `channel.dispatch` `Drop` guard, so a blocking `hook.dialog` await that errors or panics still logs once (§4 Scenario 2 Cleanup; §7 Panic hooks, `run` worker threads); `hook` keeps its `catch_unwind` → exit 0, empty stdout (§7 Per-role behaviour).
- Join keys: hook ↔ wrapper via `instance` + `dialog_id` (`corr`); channel lines via `(conn, corr)` (§3 Trace context propagation → IPC boundaries, Claude Code → hook stdin); `from` always logged with `from_trust:"self-reported"`.
- `wait` wake telemetry: §4 Scenario "`wait` / `last`" requires `run.wait_dispatch.woken_kind` and `channel-response{method:"wait"}.outcome` ∈ `question|permission|plan` derived once in `viola-channel` from the shared wake set — the dialog-kind wakes this chunk's v1-30 witness exercises end to end (§5 `viola.wait.outcome`).
- CLI verb surface: `answer` logs `process-start` / `process-exit{subject:"self", exit_code, detail}` into `cli-<name>.ndjson` when an instance resolves, the anyhow chain to `detail-cli.ndjson` only (§4 Instrumentation per surface, cli row; §7 short-lived `cli`).

## Anti-patterns to avoid
- Bare `#[instrument]`, or `err` / `ret`, on any `hook.dialog` / `answer` path — it leaks the dialog payload and tool `input` (§11 Spans / Traces; G1 §9).
- Logging the question, plan text, answer `response` or tool `input` in any home-level line, or a path / pid inside a `detail` code (§11 PII Scrubbing).
- Adding an `event` value or field (e.g. a pending-conflict `detail`) without a Decisions Log entry and its `diag-line.v1.json` row, or raw `tracing::*!` / `print!` in the `hook` / `run` paths (§11 Logs).
