# a11y extract

## Relevance
partial — the new verb `viola plugin install` is a cli-surface entity (human, plain and `--json` modes, plus the `--help` `setup:` row it joins), held to output discipline only; the installed MCP-only plugin, the `viola mcp` server and the precedence / exit-1 ledger measurements are not-assertable machine-to-machine surfaces (per a11y-plan §1 A11y Scope Summary, Not-assertable).

## Constraints
- The `viola plugin install` human output must use colour only as a second cue and must write no SGR, glyph or cursor control under `--json`, non-TTY, `NO_COLOR` (an empty value included) or `TERM=dumb`; its output must be static and linear, with no spinner or redraw (per a11y-plan §1 A11y Scope Summary, surface cli Notes). Whether the verb writes any SGR at all is the implementer's choice; plain ASCII meets the rule (per a11y-plan §6 Visual Design Verification).
- Without `--json`, each refusal of `plugin install` must be the word `unable` with its reason and detail in text, then `hint:` as the last stderr line, with a typed exit code; under `--json` it must be one document carrying no hint text (per a11y-plan §8 Error recovery). Faults are not refusals and carry no hint (per a11y-plan §8 Error recovery).
- Each kebab-case reason/detail code `plugin install` introduces must sit beside the plain word `unable`, and no stack trace or bare status number may be the only error text (per a11y-plan §8 Plain language).
- Every fixed CLI string the verb prints must be pinned (trycmd or a literal case), so that a copy change fails CI until the pinned string is updated on purpose; `viola --help`'s copy is pinned by the `HELP` literal in `help_is_the_grouped_verb_table` with the served set held by `help_lists_only_served_verbs` (`tests/cli_output_plain.rs`) (per a11y-plan §8 Plain language).
- `plugin install` in the `--help` `setup:` row is owned by the route entry "Optional plugin install", and the `--help` output stays plain ASCII under the grouped rows `board:` · `traffic:` · `wheel:` · `setup:` over the served verbs only (per a11y-plan §4 ARIA Patterns & Roles, cli landmarks row). This makes the `setup:` group label (the cli heading equivalent) part of this chunk.
- The installed plugin and its `viola mcp` server are ipc-internal with no UI surface, so they get no a11y assertion (per a11y-plan §1 A11y Scope Summary, Not-assertable). The wrapped `viola run` TUI boundary (zero viola bytes on the terminal, human keystrokes never blocked) must stay intact wherever the precedence measurement touches the wrapped path (per a11y-plan §1 A11y Scope Summary, tui entity).
- The verb's output-discipline cases must be ordinary nextest cases inside the existing suites on all three OS legs (`[windows-2025, macos-latest, ubuntu-latest]`), with no new `suite` value and no separate driver (per a11y-plan §9 CI Integration).

## Patterns to follow
- The grouped `--help` table pinned by the `HELP` literal in `help_is_the_grouped_verb_table` and the served-set case `help_lists_only_served_verbs` (`tests/cli_output_plain.rs`): add the row in the literal and the served set together (per a11y-plan §8 Plain language; a11y-plan §4 ARIA Patterns & Roles).
- The refusal shape of design-system cli pattern 2 used by `viola revive` and `viola verify`'s interrupted pair: one `unable: <text>` line, then one `hint:` line last on stderr, and under `--json` one `{"v":1,"error":"<code>","detail":null}` document with empty stderr, pinned by root cases (per a11y-plan §8 Error recovery).
- No-ESC / no-lone-CR checks through `tests/support/sgr.rs` `redraws`, as used for `viola wait` and `viola --help` on Unix (per a11y-plan §4 ARIA Patterns & Roles, P6 scenario).

## Anti-patterns to avoid
- NEVER colour `unable` / `fail`, and never emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` (per a11y-plan §11 Visual).
- NEVER show an error without a recovery suggestion (a human-mode refusal ends with `hint:`), never use a kebab-case code without the plain word `unable`, and never render a stack trace as the only error text (per a11y-plan §11 Cognitive).
- NEVER add a spinner or progress redraw while the verb writes the marketplace or runs any step (per a11y-plan §11 Motion). NEVER add an `a11y` suite value or a separate a11y driver for the new cases (per a11y-plan §11 CI).

## Contract bindings
- a11y ↔ tests harness: the verb's output-discipline failures surface only as nextest failures in the harness `run` JSON `suites[].failures[]`, gated by `gate --require coverage,doctest` (per a11y-plan §3 CI integration; a11y-plan §3 Structured violation JSON schema).
- a11y ↔ design-system cli: the refusal layout (cli pattern 2) and the colour-as-second-cue rule bind the verb's human mode (per a11y-plan §8 Error recovery; a11y-plan §6 Visual Design Verification).
- a11y ↔ layout-templates: the `--help` `setup:` heading-equivalent row and the flat-verb table bind to layout-templates' cli Heading Hierarchy Anchors (per a11y-plan §1 A11y Scope Summary, surface cli ARIA roles inventory).

## Acceptance criteria contributions
- `viola --help` (and `viola help`) lists `plugin install` in the `setup:` row once the verb is served, and the `HELP` literal of `help_is_the_grouped_verb_table` and the served set of `help_lists_only_served_verbs` are updated with it; the output stays plain ASCII with no ESC byte (per a11y-plan §4 ARIA Patterns & Roles; a11y-plan §8 Plain language).
- `viola plugin install` writes no ESC byte on either stream under a pipe, `NO_COLOR`, `TERM=dumb` and `--json`, checked by assert_cmd on all three OS legs (per a11y-plan §6 Visual Design Verification).
- Each human-mode refusal of `viola plugin install` is pinned by literal as `unable …` with its last stderr line `hint: …` and a typed exit code; under `--json` the same refusal is one document with no hint text and empty stderr (per a11y-plan §8 Error recovery).
- Every fixed success line `viola plugin install` prints (for example, any printed `claude plugin …` steps, if the verb prints them) is pinned by a trycmd case or a literal (per a11y-plan §8 Plain language).
