- **2026-10-04-the-wheel** — fixed the tui wheel boundary that this chunk's running-turn state sits beside. The non-editing set is now a closed list: focus reports, mouse reports (X10, SGR, urxvt) and terminal replies (DA1, DA2, CPR, DECRPM, kitty flags, OSC, DCS); every other byte is editing and takes the wheel. P4 (tui) case (3) landed step-wise, with the wheel probed by an `answer` to no pending dialog (exit 13 driver, 10 human). It gets the full assertion on Linux and macOS and the platform fact on `windows-2025`: the inbox ConPTY swallows focus reports, and an injected mouse report under win32-input-mode arrives as key-down records and takes the wheel. The §11 Keyboard ban now treats a ConPTY-converted mouse report as typing. This matters here in three ways. The new human-keystrokes-unblocked-during-a-running-turn case (acceptance 2) extends this same §3 Tooling / P4 tui harness and must keep its per-OS split. A human interrupt moving the wheel, followed by `release` clearing the turn state, rests on this editing classification. The amendment's "measured live at route `:82`" is pre-insert numbering, now `:84`, the same renumber whose two test comments this chunk corrects.
- **2026-10-04-dialog-answers-by-dialog-id** — §8 Timeout extensions (CLI): a dialog takes a `viola answer` only within `DIALOG_DEADLINE` (60 s PROVISIONAL). On expiry, the hook fails open, the dialog goes to the human in the `claude` TUI, and a later `answer` is refused `not-delivered` / `unknown-dialog` (exit 13). It is the nearest precedent for a driver-only `not-delivered` refusal whose limit falls on automation and never on the human. It also backs the scope's boundary that `answer` (a dialog held during a running turn) is not gated by the running-turn state.
- **2026-09-25-pty-wrapper-on-windows** — the zero-viola-bytes clause (§3 Keyboard test harness → Tooling; §6 CLI equivalent) now means viola's own literals are absent on every leg. This is exactly the split acceptance 3 (the `turn-running` refusal leaves no viola bytes on the outer PTY) has to follow. On `windows-2025` the oracle is literal absence, not byte-for-byte.
