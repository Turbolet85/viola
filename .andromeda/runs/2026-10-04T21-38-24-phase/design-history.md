## Relevant amendment history
- **2026-10-04-wait-and-last** — amended §Surface: cli → Component Patterns 3 (`viola wait` / `viola last`). `session-end` gained a result line: every non-dialog kind takes the `turn-ended` form. Message mode is spelled out: control characters print as `\xHH`, never stripped, and `--json` stays serde-escaped. This matters because the `turn-running` hint sends the driver to `viola wait <name>` first. This chunk ends a running turn on `turn-ended`, `session-start` or `session-end`, so the turn ends the wrapper recognises should match what `wait` already reports as a turn end (`session-end` in the `turn-ended` form). It is also the latest precedent for amending a cli Component Pattern at the wrap where a result-line form changes. This chunk adds no new form, so the wrap should owe none.
- **2026-09-28-cli-output-tokens** — clap is built without its `color` feature. No dependency reads a colour or terminal variable, and every styled byte of human output comes from viola's own SGR module. This underpins the extract's anti-pattern (no colour on the refusal line; cli colour only for `DIALOG` / `stale`) and the acceptance clause "no SGR bytes" under `--json`. The `turn-running` refusal and hint must go through the same plain path, and `CLICOLOR_FORCE` must not be able to put SGR into them.
- **2026-09-28-capability-ledger-and-viola-verify** — amended §Exit-code phraseology (the exit 1 row) and the cli `verify` pattern. Each refusal there has its own fixed `unable: …` wording and its own hint, and a failing row prints no stderr word. This is the precedent for the refusal-plus-one-keyed-hint shape the extract binds (`not-delivered  turn-running` then `hint: a turn is running; viola wait <name> first`, exit 13). It also shows that the exit-code phraseology table is amended only when a refusal word or hint actually changes; this chunk reuses an existing row. The ledger row count "grows as owning chunks land rows", and this chunk adds no ledger row, so the six-row counter is untouched.
- **2026-09-29-t15-07-57-wrap** — registry migration (U35). The design-system Decisions Log moved verbatim to `design-system-amendments-archive.md`, and its in-force items were lifted into the body: §Brand Identity, §Color Palette, and web-spa Component Patterns 1, among others. The extract's binding sections (§Brand Identity phraseology, §Semantic Colors, and web-spa Component Patterns 1, the session strip) now hold their current truth in the body, not in a log. Any wrap amendment from this chunk goes to this amendments file, not to a body Decisions Log.
- **2026-10-01-t12-19-55-wrap** — the web-spa toolkit moved from Lit to React + TypeScript, and the session strip renders a native `<tr>` / `<td>`. The rendered-DOM requirements and every ban were kept. It is relevant only because the extract leans on web-spa Component Patterns 1 (the STATUS word comes from `claude agents --json`) and 2 (`<viola-readback>` sources: at most one send in flight, `turn-ended` never fills a readback box). This amendment left those semantics unchanged. Exposing the running-turn state on the strip or readback would still be a design amendment, and the frontend toolchain is still OPEN, so this chunk has no web rendering path to touch.
