## Relevance
relevant: the chunk changes the `send` refusal order and wheel `release` behaviour, which test-plan §4 (root-bin refusal ordering, wheel state machine), §6 Path 5 and §11 cover directly.

## Constraints
- Layer placement: the turn-state transitions belong at unit level, per test-plan §2 (pyramid, Unit row) and §11 Test Strategy ("NEVER assert at E2E a case that a lower layer can hold"). These are: `prompt-submitted` of each `origin` (driver / human / harness) starts a turn; `turn-ended` / `session-start` / `session-end` ends it; `release` clears it; `release` leaves the in-flight `send` slot alone. They go in rstest `#[case::<label>]` tables in the root bin's inline `mod tests`, beside the existing `turn-running` cases in `src/run/send.rs`. The E2E layer asserts only the cross-process cases: a harness turn, and a turn left running after a wheel move.
- The refusal order must be written as a literal oracle. test-plan §4 root bin ("Refusal ordering") fixes the `send` order human-typing → budget-paused → turn-running → input-not-ready → no-prompt-submitted, with `control-character` ahead of all of them. §11 Unit bans importing the product's own refusal ordering as the oracle. `budget-paused` is not built in this chunk (scope Boundaries), so a case that pairs a running turn with a paused budget is research's question.
- Refusals are asserted on wire values, never `Debug` strings, per test-plan §11 Unit. That means the serde kebab value `{"refusal":"not-delivered","detail":"turn-running"}` and the integer CLI exit. §6 Path 2 maps the `not-delivered` family to exit 13 (`mute`), and §4 root bin owns the exit-code mapping.
- Synchronisation must be deterministic, per test-plan §2 (agent-runnable invariants: no sleeps, `retries = 0`) and §11 E2E (no `sleep(N)`). The E2E witness orders "turn running" before `send` by waiting on an `events.ndjson` byte offset (the `prompt-submitted` line). It drives turn end through a gated fake-script step released on `<home>/fake/<name>.control` (§7 Fake agent), never through a timer.
- Verdicts never come from the child screen, per test-plan §11 E2E (R7) and §6 Path 2 verification. "Nothing typed" is proven by the fake-agent receipt gaining no new `prompt` / `key` entry for the refused text, together with the `events.ndjson` records after the pre-send offset. A screen read is not evidence.
- The chunk is not done until it is green on all three CI OSes, per test-plan §11 Test Strategy (a Linux-only run is no proof for Windows / macOS) and §9 (Matrix builds). Coverage stays at or above line 85 / function 95 / region 80 per OS (§10 Coverage thresholds). There is no retry and no `#[ignore]` parking (§10 Zero-flakiness budget).
- Mutation scope applies to the new running-turn branches in root `src/run/`. Per §3 `run` step 4 (Test scope; `.andromeda/registries/contracts/test-plan/5-command-implementation.md`), a mutant there must be killed by root-package tests. The verdict comes at the epoch boundary or from an on-demand `run --mutants` with `missed == 0`, `timeout == 0` and `unviable <= caught`. No per-chunk mutation gate applies (§10 Mutation gate).

## Patterns to follow
- §6 Path 5's harness-turn case (step 8, `tests/tui_wheel.rs`): the fake agent's `--inject-harness-turn` mode fires a gated `<task-notification>` prompt with `origin:"harness"` (§7 Fake agent, Modes). This is the ready driver for the measured hypothesis: the harness turn is running, then `viola send` gets `turn-running` and the receipt shows nothing typed.
- §6 Path 5 steps 2–5 (outer-PTY human keys, then `viola release`, then `send`) are the shape for the "release clears a turn with no `turn-ended`" witness. Keep the Stop step gated and unreleased, so no `turn-ended` arrives (it stands in for the user interrupt). The `send` after `release` then exits 0.
- §6 Path 3 / §4 root bin (`wait` wakes only on `turn-ended` / `question` / `permission` / `plan` / `session-end`) is the driver contract the refusal relies on ("the driver calls `wait` first"). The witness can show `wait --after <cursor>` returning `turn-ended`, followed by an accepted `send`.
- Fixtures: any new turn script is `fixtures/fake-scripts/<scenario>.json` with synthetic text only, valid against `schemas/fake-script.v1.json`, and covered by the `tests/contract_fixture_hygiene.rs` walk (§7 Fake agent, Fixture hygiene). Each test has its own fresh home (the rstest `home → fake_agent_path → stamped_home → booted_wrapper` chain, §3 `run` step 2). Every send text embeds the tests-owned canary (§6 Error sanitization and secret scan).
- Naming and layer: test names follow `<subject>_<condition>_<expected>` (§2 Test function naming). The nextest layer comes from the file prefix (§2 File naming, §3 `run` step 1–2 filtersets). A `cli_*.rs` file runs under `run --integration`. A `tui_*` / `chaos_*` / `path_*` file runs under the E2E filterset.

## Anti-patterns to avoid
- Do not wait in real time for a "turn is running" state, and do not use a test-owned timer (§11 E2E `sleep(N)`, §11 Universal real-time ban). The one product deadline E2E may block on is the confirmation window behind `no-prompt-submitted` (§11 Universal), and that window is not the `turn-running` verdict.
- Do not copy the refusal-order list or the product's state enum into the test as its oracle (§11 Unit).
- Do not hand-write `snapshot.json` to seed a running turn (§11 Test Data, §7 Seed strategies). State comes only from real `viola run` against the fake agent.
