## Constraints
- `mutants.out/` is never uploaded. Its `outcomes.json` held absolute argv paths and its `log/` held test output. On a Windows host it sits in the host mutation scratch `<repo parent>/viola-mutants-scratch/`, whose path is never printed: documents carry only `scratch_bytes`. The scope's "[inferred] result readable by the auditor" item has to fit inside this rule. Two forms fit: the harness run document (codes and counts only) printed in the job log, or uploaded as an artifact under a fresh admissibility argument. Shipping `mutants.out` as-is does not fit. (per obs-plan §8 PII Scrubbing item 6, "Unscanned uploads, admissible by content")
- Any artifact the new workflow uploads follows the §9 artifact rules: `actions/upload-artifact` v7.0.1 SHA-pinned, `retention-days: 7`, and a member that could carry a host path or log content is either scanned before upload or dropped. An unscanned upload is a new crossing and needs its own admissibility basis; the ratified basis for the `supply-chain` artifact was 0 absolute paths, measured. (per obs-plan §9 Telemetry artifact handling / Artifact retention; §8 item 6, the supply-chain guard)
- Mutation stays out of CI's blocking path. The obs-plan Mutation row has had no CI job since 2026-09-28: `run --mutants` runs at the epoch boundary through `/andromeda-code-audit`, and on demand. A missed or timed-out obs-code mutant, or unviable outnumbering caught, is red at that run. The `workflow_dispatch`-only workflow is the boundary-run form, not a CI gate. (per obs-plan §9 Pipeline integration, Mutation row; §10 Build / deploy failure conditions, last bullet)
- `src/panic_frames.rs` is obs code: the raw frames the panic hook writes to `detail-<process>.ndjson`. Its 9 owed mutants (`:37:5` ×3, `:50:5` ×5, `:55:79`) are graded under the obs-code rule: a survivor there is red at the boundary run, never counted as caught until measured on the windows runner. Any killing test must keep the panic-path contract: one line, one `write_all`, no stderr, not gated by `RUST_BACKTRACE`. (per obs-plan §7 Panic hooks; §10 Build / deploy failure conditions)
- G3 scans `*.yml` / `*.yaml` workflows for an abort panic strategy (`panic = "abort"`, `-C panic=abort`, `CARGO_PROFILE_*_PANIC`). The new workflow, and any env or rustflags it sets for cargo-mutants, must not introduce one. (per obs-plan §9 Gate commands, G3)
- No CI env metadata reaches product log lines, and env is never a configuration channel. Workflow `env:` may steer the harness/tooling (for example a short `TMP`), but never a `viola` build's behaviour. (per obs-plan §9 CI-specific resource attributes; §11 CI)
- The leak fix must not shorten home lifetime under `AGENT_RUN_KEEP_HOMES=1`. CI keeps homes under `target/e2e-home/` until G2, G4, the secret scan and the scan-gated uploads have read them. A fix that makes a test home's drop or teardown delete unconditionally would empty G2's scope and fail its non-empty check. (per obs-plan §9 Step order and conditions, item 1, overseer fix pass 2 B1)

## Patterns to follow
- Every CI verdict is an exit-code-setting machine assertion (`jq` over a JSON document), never human-reviewed log reading. The workflow's outcome counts and missed / timeout lists should come out as the harness's JSON run document, readable with `gh run view` / `gh run download` → `jq`. (per obs-plan §11 CI; §11 Universal)
- The harness run document carries codes, counts and repo-relative names only (the `archived`, `scratch_bytes` pattern). `target/run-archive/<n>/` and `mutants.out/` stay gitignored and outside every upload path. (per obs-plan §8 item 6)
- Upload steps keep the explicit status-function discipline: `if: always() && …` / `failure() && …`, never a bare condition that gets an implicit `success()`. This matters only if the workflow uploads anything. (per obs-plan §9 Telemetry artifact handling, the junit row's note)
- CI identity lives in artifact names and GitHub run metadata (`gh run view --json`), not in log lines. (per obs-plan §9 CI-specific resource attributes)

## Anti-patterns to avoid
- NEVER use an unpinned Action. Every `uses:` is pinned by full commit SHA and checked by zizmor. (per obs-plan §11 CI)
- NEVER upload `mutants.out/`, cargo-mutants `log/` output or any member holding an absolute host path or test output. NEVER print the host scratch path in a document or job log. (per obs-plan §8 item 6)
- NEVER add a retry-once policy to mask a flaky mutant outcome or telemetry assertion. A timeout is graded, not re-run away. (per obs-plan §11 SLO; §10 Cross-input parallel)
