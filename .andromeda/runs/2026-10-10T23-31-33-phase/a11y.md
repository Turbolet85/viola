# a11y extract

## Relevance
partial — the chunk adds two verbs to the cli surface (`viola link`, `viola unlink`), which a11y-plan covers by output discipline only, with no WCAG conformance claim; the web-spa link surfaces (transfer marker rows, `/api/links`) are outside the chunk's Boundaries and nothing is extracted for them.

## Constraints
- a11y-plan §1 A11y Scope Summary (CLI and terminal entities) names `link` and `unlink` in the CLI verbs entity and requires each in three modes: human TTY, plain (non-TTY / `NO_COLOR` / `TERM=dumb`) and `--json`. The entity is assertable by output discipline on text and streams only; the tier label Standard applies to web-spa, never to these verbs.
- a11y-plan §1 A11y Scope Summary (Surface: cli → Notes) requires no SGR, glyph or cursor control under `--json`, non-TTY, `NO_COLOR` or `TERM=dumb`, and static linear output with no spinner or redraw; a11y-plan §5 Keyboard Navigation (Focus order per layout → cli) requires no interactive prompt, pager or redraw, so neither verb may ask for a confirmation (an `unlink` included).
- a11y-plan §6 Visual Design Verification (State color tokens (not-color-alone) → CLI equivalent) requires colour to be a second cue only, always beside its word, and lists three SGR placements, none of them a `link` / `unlink` line; `unable` and `fail` are never coloured. Whether design-system gives the link line any SGR on a TTY is the design extract's; if it does, the word carries the state and the SGR sits beside it.
- a11y-plan §8 Cognitive Accessibility (Error recovery → CLI) requires every human-mode refusal as the `unable` reason-and-detail line on stderr, then `hint:` as the last stderr line, with a typed exit code; `--json` gives one document with no hint text; the one hintless refusal is `unknown`, and faults are not refusals and carry no hint. Whether the two new verbs already reach a shared refusal renderer that prints this pair is research's question.
- a11y-plan §8 Cognitive Accessibility (Plain language) requires every fixed CLI string to be pinned by a test, so a copy change fails until the pin is updated on purpose, and requires a kebab-case reason or detail code never to appear without the plain word `unable`. The new human lines (the `since` line, the existing-pair words, the `unlink` line) are fixed copy under this rule; their wording is design-system's, not this plan's.
- a11y-plan §1 A11y Scope Summary (CLI and terminal entities → `viola run` TUI passthrough) requires the wrapper to write zero bytes of its own to the terminal and never to block, refuse or delay a human keystroke past the current atomic paste. The wrapper serving `link` / `unlink` and appending the implicit `link` line on a `send` or an `answer` is bound by it: the append and the snapshot rewrite reach the log and the disk, never the child's screen. Whether the implicit-link write sits on the path a human key takes is research's question.
- a11y-plan §8 Cognitive Accessibility (Timeout extensions → CLI) requires a budget pause to bind the driver only, through the automated `send`, and states that `answer`, `wait`, `last` and `pause` do not read the gate, a clause it records as read in the diff with no case driving it. The folded case is that missing case; the sentence is the wrap's to amend when the case lands.

## Patterns to follow
- The mode split of a11y-plan §4 ARIA Patterns & Roles (Must-be-accessible path scenarios → P6): assert_cmd / trycmd cases assert the non-TTY modes, the portable-pty outer PTY asserts the TTY-only behaviours, on all three OS legs. Whether the repository's existing CLI cases pin lines through trycmd or through root assert_cmd cases is research's question.
- The refusal pattern of a11y-plan §4 ARIA Patterns & Roles (Must-be-accessible path scenarios → P2 cli and P4 cli): the refusal text on stderr with its `hint:` line, and the typed exit code read by assert_cmd.
- The new-verb precedent of a11y-plan §8 Cognitive Accessibility (Error recovery → CLI): `viola revive`'s refusal lines are pinned by root cases in `tests/cli_revive.rs`; the two new verbs' lines get root cases of their own in the same way.
- The closed-gate precedent of a11y-plan §3 A11y Assertion Harness Contract (Keyboard test harness → Tooling): `path6_a_reading_over_the_threshold_refuses_the_send` in `tests/cli_budget.rs` reads a closed gate with a refused automated `send` beside it; the folded case sits in the same file and keeps that refused `send` as its control.
- Failure reporting per a11y-plan §3 A11y Assertion Harness Contract (Structured violation JSON schema → cli / tui): the cli writes no a11y row; an output-discipline failure surfaces only as a nextest failure in `suites[].failures[]`.

## Anti-patterns to avoid
- Never colour CLI `unable` / `fail`, and never emit SGR under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` (per a11y-plan §11 A11y Anti-Patterns → Visual).
- Never show a human-mode refusal without its `hint:` line (the `unknown` refusal excepted), never print a kebab-case code without the plain word `unable`, and never print a Problem URN, a stack trace or a bare status number as the only error text (per a11y-plan §11 A11y Anti-Patterns → Cognitive).
- Never claim WCAG conformance for the cli on the strength of assert_cmd / trycmd / portable-pty results, and never write an a11y violation row for a cli check or into the home's `diagnostics/` (per a11y-plan §11 A11y Anti-Patterns → Strategy and → Universal (agent-driven specific)).

## Contract bindings
- a11y ↔ design: the human lines of `link` / `unlink` (the ASCII arrow, the word `since`, the existing-pair words) are design-system's cli patterns; a11y-plan §8 Cognitive Accessibility (Plain language) binds only that they are pinned, and a11y-plan §6 Visual Design Verification (State color tokens (not-color-alone) → CLI equivalent) binds only where an SGR may sit.
- a11y ↔ tests: the cli discipline cases run inside `nextest-integration` / `nextest-e2e` locally and inside the per-OS `test` job's `coverage` suite in CI, on all three OS legs, with no new `suite` value (a11y-plan §3 A11y Assertion Harness Contract → A11y testing tool pick; a11y-plan §9 CI Integration → Per-pipeline-stage a11y artifacts, the Unit / integration row). The epoch-boundary mutation audit covers discipline cases that live in crate tests (a11y-plan §10 SLO Invariants & A11y Budgets → Standard+ invariants); this chunk plans no mutation run and the plan asks none of a single chunk.
- a11y ↔ obs: none added. The cli emits no a11y row and no product `event` value is added for a11y (a11y-plan §3 A11y Assertion Harness Contract → Structured violation JSON schema).
- a11y ↔ the wrap: one sentence of a11y-plan §8 Cognitive Accessibility (Timeout extensions → CLI) goes stale when the folded case lands (the four verbs under a closed gate); it is an amendment for this chunk's wrap, not an edit for implement.
- a11y ↔ later entries: the `link` / `unlink` kinds and their `{driver, driven}` data are what the web transfer-marker rows will read (a11y-plan §1 A11y Scope Summary → Web-spa entities, the Transfer marker entity). No web assertion is owed by this chunk; the supplemental manual screen-reader pass on cli steps stays founder-owned and never gates (a11y-plan §7 Screen Reader Support → Per-surface SR test pattern).

## Acceptance criteria contributions
- (a11y) `viola link` and `viola unlink`, each for a new pair, an existing pair and a refusal, write no ESC byte, SGR or cursor control to stdout or stderr under non-TTY, `NO_COLOR`, `TERM=dumb` and `--json`, on all three OS legs (per a11y-plan §4 ARIA Patterns & Roles → Must-be-accessible path scenarios → P6)
- (a11y) every human-mode refusal of the two verbs prints the `unable` reason-and-detail line on stderr with `hint:` as the last stderr line and exits with its typed code, and the same refusal under `--json` is one document holding no hint text (per a11y-plan §8 Cognitive Accessibility → Error recovery)
- (a11y) the human lines of the two verbs are pinned by a test as fixed copy (the time after `since` matched by shape, not by value), each is one static line with no carriage-return redraw, and the existing-pair outcome is told by its words alone (per a11y-plan §8 Cognitive Accessibility → Plain language)
- (a11y) under a closed budget gate `answer`, `wait`, `last` and `pause` are not refused `budget-paused`, while an automated `send` in the same gate is, so the case cannot pass on a gate that never closed (per a11y-plan §8 Cognitive Accessibility → Timeout extensions)
