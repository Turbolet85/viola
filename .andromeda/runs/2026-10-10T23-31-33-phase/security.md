# security extract

## Relevance
relevant — the chunk first serves two channel methods (`link`, `unlink`), adds two CLI client verbs that resolve an instance's `endpoint`, records an unauthenticated `from` as a link, and holds one boundary widening the plan does not cover.

## Constraints
- **Server verification before the first frame.** security-plan §Authentication & Authorization (row "IPC client-side server verification (anti-impersonation)", Timing) requires the server's identity to be verified before the first frame of any method is written. That row's dated interim gaps name `hook.event`, `send`, `wait` / `last`, `answer` / `hook.dialog` and `pause` / `release`, and none names `link` or `unlink`. A `link` / `unlink` frame written after the liveness-only pre-check is therefore outside every ratified gap: it needs the founder's own ruling as an eighth dated gap, or the full verification. Whether the code holds a verification path that a client verb could use today is research's question.
- **The widening has a second half: the snapshot read.** security-plan §Authentication & Authorization (row "`~/.viola/` access control", Strict-modes check) requires the strict-modes check in every CLI client verb that resolves an instance's `endpoint`, and its seven dated gaps name their verbs one by one; `link` and `unlink` are in none. security-plan §Input Validation (row "CLI arguments / stdin", and row "Own state files on read", Integrity) repeat the same verb lists. A `viola link` / `viola unlink` that reads `snapshot.json`'s `endpoint`, `pid`, `started_at` and the heartbeat without that check is a second uncovered crossing, and the review card's one held item must name both halves.
- **A Decisions Log entry for a newly served method.** security-plan §Security Anti-Patterns → Universal requires a Security Decisions Log entry, mapping the method to the plan's IPC controls, before a channel method is added. The plan lists `link` and `unlink` among the channel's methods (security-plan §Threat Model Summary, Attack surface, Local IPC) but records no chunk as serving them. A pattern search of both log files at this extract (`unlink`, and `link` as a method or verb, in `security-plan-amendments.md` and its archive) matched no line that names them; research re-reads the log for a ratification that covers them, and the entry is otherwise owed at this chunk's wrap.
- **Both names are validated by the wrapper, not only by the client.** security-plan §Input Validation (row "Channel frames (IPC ndjson)", Closed types) requires `link` / `unlink` `driver` and `driven` to go through `ViolaName::try_new`, under that row's frame cap, depth limit and `v` check; security-plan §Security Anti-Patterns → Input requires the wrapper to re-run the check whatever the client did. security-plan §Input Validation (row "CLI arguments / stdin", Names) requires every `ViolaName` argument of the two new verbs to use the shared clap name parser. The plan words no error code for a bad `driver` / `driven`; the code is architecture's channel contract to state.
- **`from` is a self-reported label, and a link is a record.** security-plan §Threat Model Summary (Attack surface, Local IPC, Trust boundary) states that `from` is self-reported, so link records and driver identity are not authenticated. security-plan §Authentication & Authorization (row "Driver-originated `release`") allows `link` and `unlink` from drivers and keeps the `from` refusal for `release` alone. No refusal, no lifting and no access decision in this chunk may rest on a link or on `from`. The `from` the implicit link reads on `send` and `answer` must first pass the one shared check (absent, `null`, or a string that passes `ViolaName::try_new`) of security-plan §Input Validation (row "Channel frames (IPC ndjson)", `send` params and `answer` params). That row words `answer`'s `from` as following the `send` rule; whether the code's `answer` frame already carries it is research's question.
- **Only the serving wrapper writes the link state.** security-plan §Security Anti-Patterns → Universal requires that no process but the instance's own wrapper writes `instances/<name>/snapshot.json`, so the two CLI verbs write neither the snapshot nor the log. security-plan §Authentication & Authorization (row "`~/.viola/` access control") requires every replaced file to go through `viola_state::fs::replace_private`, which covers the snapshot's rewrite on a change of `links`. security-plan §Data Protection (At rest, Logs) requires `events.ndjson` at 0600 inside 0700 directories, which covers the appended `link` / `unlink` lines.
- **Sanitised results and refusals.** security-plan §Error Handling (External responses; Error format, Channel) requires channel errors, CLI `--json` output and refusals to carry codes and fixed messages only: no absolute path, no upstream text, no internal type name, `-32603` as its one fixed form. The link result payload and both verbs' failure output fall under it; the planned payload (two validated names, a time, a flag) holds nothing the section bans.

## Patterns to follow
- The landed form of a client verb's gap, should the founder rule the eighth one: each earlier verb is recorded with its own liveness-only pre-check, its own exit on a dead instance, its own named residual, and a sentence that it borrows no earlier gap (per security-plan §Authentication & Authorization, row "IPC client-side server verification (anti-impersonation)"). The residual for `link` / `unlink` is this chunk's to word for him: a process squatting the endpoint could swallow an `unlink` or answer a `link`.
- Shared validators live in `viola-core` and are called by the CLI and the wrapper alike (per security-plan §Input Validation, Boundary); the bootstrap list already names the channel `link` / `unlink` params as a `ViolaName::try_new` site (per security-plan §Bootstrap phases, `input-validation-library-install`).
- Read the log through the one bounded reader and append through the one locked append: each line through its `MAX_FRAME` cap with the skip counts, a reader that never writes, an append that heals a torn last line (per security-plan §Input Validation, row "Own state files on read", Line cap). That row also states the log replay has one product caller, `viola revive`'s preflight, taken after `check_instance`. Whether this chunk adds a second caller (a wrapper seeding its link set from the log at start) is research's question; if it does, the read comes after the home strict-modes check (same row, Integrity) and the sentence is the wrap's to amend.
- Tests use their own `--home` and synthetic names (per security-plan §Secret Management, Storage, Development); nothing recorded from a real session is committed (per security-plan §Data Protection, Repository fixtures).

## Anti-patterns to avoid
- Writing a `link` or `unlink` frame under one of the seven dated gaps: each names its own frames, and no other frame or process may borrow any of them (per security-plan §Security Anti-Patterns → Authentication).
- Treating the channel `from`, or a link derived from it, as an authenticated identity (per security-plan §Security Anti-Patterns → Authentication).
- Joining `instances/<name>` with a `driver` or `driven` string that did not come out of `ViolaName::try_new`; the ban names the `link` / `unlink` params (per security-plan §Security Anti-Patterns → Input).

## Contract bindings
- **architecture §Standard Contracts (channel methods, snapshot, event `data` per kind).** The result keys of `link`, the error code for a bad `driver` / `driven`, and the three unsettled shapes (a `driven` that is not the serving wrapper's name, an `unlink` of a pair not in the set, a `driver` equal to `driven`) have no security-plan sentence. They are architecture's to word; the security floor on whatever is chosen is the validation and the sanitised error form above.
- **obs-plan (event catalog, process-log lines).** The NEVER-log floor does not restrict `events.ndjson` as a contract payload, and a process-log line for a link holds names only (per security-plan §Bootstrap phases, `logging-redaction-wire`). The landed `release-from-driver` line labels its `from` as self-reported (per security-plan §Authentication & Authorization, row "Driver-originated `release`"); whether a link line carries the same label is obs's to rule.
- **test-plan §6 (Scenario E3, Scenario E5, Path 6).** The folded budget case rests on a gate that is fail-open on every failed read, fed by a hook arm that writes no `budget.json` and no line when its instance check refuses (per security-plan §Authentication & Authorization, row "`~/.viola/` access control"; security-plan §Input Validation, row "Own state files on read"). A case that only shows `answer`, `wait`, `last` and `pause` passing proves nothing about a closed gate, so the in-gate `send` refusal is the control the security reading needs. The CI artifact canary scan runs over this chunk's test homes as over any other (per security-plan §Secret Management, Secret scanning in CI).
- **MCP and GUI, both out of this chunk.** Keeping `link` / `unlink` off the MCP tool list is an affordance, not an enforcement (per security-plan §Threat Model Summary, Attack surface, MCP over stdio); `/api/links` and the reserved v1.x `/unlink` route carry their own cookie and origin checks when they land (per security-plan §Authentication & Authorization, rows "GUI principal check").
- **Wrap freight for security-plan, if the verbs land.** The "served by the wrapper as of chunk" sentence and, on the founder's ruling, the eighth gap in the four places the seven stand (security-plan §Authentication & Authorization, both rows cited above; §Input Validation, rows "CLI arguments / stdin" and "Own state files on read"; §Security Anti-Patterns → Authentication), then the leaf `.claude/rules/security.md`.

## Acceptance criteria contributions
- A wrapper `link` and a wrapper `unlink` whose `driver` or `driven` fails `ViolaName::try_new` (an upper-case name, a name with a path separator, a non-string) each return a protocol error with a fixed message, append no line to `events.ndjson` and leave `snapshot.json` as it was; `viola link` / `viola unlink` with such an argument is a usage error before any frame (per security-plan §Input Validation, rows "Channel frames (IPC ndjson)" and "CLI arguments / stdin").
- The step that writes a `link` / `unlink` frame after the liveness-only pre-check, and reads the snapshot without strict-modes, is built only behind the founder's recorded word naming those two verbs; without it the plan holds that one item and the rest of the chunk stands (per security-plan §Authentication & Authorization, rows "IPC client-side server verification (anti-impersonation)" and "`~/.viola/` access control"; security-plan §Security Anti-Patterns → Authentication).
- A `link`, an `unlink`, a `send` and an `answer` carrying a string `from` are not refused for it, and a `release` carrying a string `from` is still refused `release-from-driver`; no code path added by the chunk branches a refusal or a permission on the link set (per security-plan §Authentication & Authorization, row "Driver-originated `release`"; security-plan §Security Anti-Patterns → Authentication).
- `viola link --json` and `viola unlink --json`, on success, on an unreachable instance and on a refused frame, print no absolute path, no pid and no internal type name (per security-plan §Error Handling, External responses); and the folded budget case fails when its in-gate `send` is not refused `budget-paused` (per security-plan §Input Validation, row "Own state files on read").
