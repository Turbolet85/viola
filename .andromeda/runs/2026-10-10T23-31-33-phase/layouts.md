## Relevance

## Constraints
- Surface and region: the chunk's output is the handoff pair of the "wheel, handoff and dialog verbs" screen of the cli surface; the plan requires each verb to print one static result line of spoken phraseology on stdout and nothing else (per layout-templates §Surface: cli → Primary screens (commands); §Surface: cli → Output structure — wheel, handoff and dialog verbs).
- Line anatomy: the plan requires the result line to open with the verb word, padded so the pair starts in the same column on both verbs, then the pair as `<driver> -> <driven>` in ASCII, then for `link` only the `since` word and a UTC clock time; `unlink` carries no time field (per layout-templates §Surface: cli → Output structure — wheel, handoff and dialog verbs). Fields are separated by the two-space gutter, and `->` is the terminal form of the web arrow with no inbound `<-` form (per layout-templates §Surface: cli → token table, row `space-xs` equivalent; §Surface: cli → IA notes, Multi-surface coordination).
- Existing pair: the plan words the existing-pair case only as a comment on the `link` line (`already linked`); whether those words replace the `since` field or stand beside it is not worded as a full line (per layout-templates §Surface: cli → Output structure — wheel, handoff and dialog verbs). This is a fork for the plan, not an implementation choice (per layout-templates §Surface: cli → IA notes, Output as a contract).
- No styling on link output: the handoff role colour is not used on this surface and link output is plain; colour on the cli is reserved for `DIALOG` and `stale`, so the TTY form and the piped / `NO_COLOR` / `TERM=dumb` form of both lines are the same characters (per layout-templates §Surface: cli → token table, row `color-role-handoff`; §Surface: cli → Expression level).
- Argument order: `viola link|unlink <driver> <driven>` mirrors the channel `params`; both verbs are flat one-word verbs with no prompt, no pager and no nested noun, and an unwrapped name is never a valid target (per layout-templates §Surface: cli → Component — Primary navigation (verb structure)).
- Machine view: `--json` is the machine view of every data verb but `viola revive`, one document on stdout with no stderr line and no hint text; new facts go into `--json` first, and the human line stays stable because drivers may read it (per layout-templates §Surface: cli → Component — Primary navigation (verb structure); §Surface: cli → Component — Primary content block 2: refusal lines and the `unable` column; §Surface: cli → IA notes, Output as a contract). The plan words no key of the `link` / `unlink` document.
- Streams and the last line: results go to stdout, refusals, hints and errors to stderr, never mixed; there is no terminator word, the exit code terminates, and the plan names the `link` result line as one of its three examples of a last printed line that says what happened, to whom and where (per layout-templates §Surface: cli → Component — Primary content block 2: refusal lines and the `unable` column, Streams; §Surface: cli → Component — Footer / terminator).

## Patterns to follow
- The sibling lines of the same screen (`pause`, `release`, `release --budget`, `answer`) are the model for a one-line stdout result with exit 0 and for the stderr refusal with its hint line last (per layout-templates §Surface: cli → Output structure — wheel, handoff and dialog verbs). Whether the bin already has one shared printer for these lines is research's question.
- Refusal form for the two verbs: `unable  <name>  <reason>  <detail>` on stderr with the `hint:` line directly under it and last, exit 21 taking the `instance-unreachable` line and its own hint, exit 20 the wrapper-fault line (per layout-templates §Surface: cli → Component — Primary content block 2: refusal lines and the `unable` column, Line form / Hint line / Exit codes). Which of the two names fills `<name>` for a pair is not worded by the plan; research reads whether a master settles it, else it is a fork.
- Fixed-width padding comes from the bin's one hand-written SGR / column module, with no table or colour crate (per layout-templates §Surface: cli → Tooling context). Whether that module already pads a verb-word column is research's question.
- Help grouping: `link` and `unlink` sit in the `handoff:` group of `viola --help`, and `viola <verb> --help` is clap's per-verb usage (per layout-templates §Surface: cli → Output structure — `viola --help`). Whether the group line is already printed with these two names before the verbs exist is research's question.
- The folded budget case reads lines this plan places: the `pause` and `answer` result lines, the `wait` / `last` result lines, and the control's `send` refusal as the struck mirror with exit 11 (per layout-templates §Surface: cli → Output structure — wheel, handoff and dialog verbs; §Surface: cli → Output structure — `viola wait` / `viola last`; §Surface: cli → Component — Primary content block 2: refusal lines and the `unable` column, Exit codes).
