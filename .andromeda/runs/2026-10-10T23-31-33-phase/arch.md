# arch extract

## Relevance
relevant — the chunk lands a decision the plan already words (architecture §Established Decisions, [Links]), two channel methods, two CLI verbs, two event kinds and the replay's link half; one item (the `link` result payload) departs from a contract the plan fixes today.

## Constraints
- **Crate placement, no new edge.** The two kinds are added only in `viola-core`, with no Claude-specific name (per architecture §Conventions, Naming patterns → Normalised event kinds). The log-derived link set belongs to `viola-state` (per architecture §Standard Contracts, Snapshot envelope: replay recovers `links`), and the wrapper methods and the CLI verbs to the root bin, which is the only crate with anyhow (per architecture §Established Decisions, [Module Boundaries] and [Error Handling]). `viola-core` depends on no viola crate, `viola-state` and `viola-channel` only on `viola-core`, and the root bin on all members (per architecture §Infrastructure Patterns → Crate dependency direction): the chunk needs no new edge, and a shared link item type must sit where that direction allows.
- **What records a link.** Architecture §Established Decisions ([Links]) requires: the driven instance's wrapper appends the `link` line to its own `events.ndjson`, only when the pair is not in its link set; a repeated `send` or `answer` adds no line; an explicit link of an existing pair adds none; `unlink` appends an `unlink` line; `since` is the time of the first link after any `unlink`. The same decision names `send` and `answer` only, so `wait`, `last` and `pause`, which also carry `from` (per architecture §Standard Contracts, Channel methods), record none. A consequence of the same wording: after an `unlink`, the next `send` or `answer` carrying that `from` links the pair again with a new `since`. Not worded there, for research and the fork round: whether a `send` or `answer` that is refused still counts as "issued" (a `budget-paused` or `human-typing` send with a `from` included), and what a `from` equal to the wrapper's own name does.
- **The log is the one source; the snapshot is derived.** Architecture §Standard Contracts (Instance snapshot) requires `links` as the set derived by replaying `link` / `unlink` lines, each item `{driver, driven, since}`, in a file only that instance's wrapper writes and rewrites on every change to a listed field. Architecture §Standard Contracts (Snapshot envelope) requires the replay fallback to recover `links` from the log, in one pass, writing no file. A wrapper that starts over an existing log (a revive included) must therefore hold the set its log gives, not an empty one; whether the wrapper's start already rebuilds any set from the log is research's question.
- **Wire shapes are fixed, and the payload departs from one.** `link` and `unlink` are id-bearing requests (per architecture §Established Decisions, [API Style]) whose `params` are `{driver, driven}` plus `v` and `sender`, sent to the driven instance's wrapper, and whose event `data` is `{driver, driven}` (per architecture §Standard Contracts, Channel methods and Event `data` per kind). Architecture §Standard Contracts (Channel methods) fixes both results as the empty object, and architecture §Established Decisions ([Links]) says the same of an explicit link of an existing pair. Scope item 6 (a first-linked time and an already-existed fact in the `link` result) is therefore a change to those two sentences: additive under architecture §Conventions (Interfaces and versioning → Protocol versioning: a new field or kind needs no `v` bump), but its keys are worded by no plan sentence, so it is a fork for the plan and an amendment at the wrap, not a reading of the plan.
- **Shapes the plan leaves open.** Architecture §Standard Contracts (Channel methods) lists the methods that read `from` as `send`, `wait`, `last`, `answer` and `pause`, and types `from` for those only; `link` and `unlink` are not in that list, while architecture §Conventions (Naming patterns → CLI) has the CLI add `from` from its own `VIOLA_NAME` when set. What a `link` / `unlink` frame carrying `from` does is unworded. Architecture §Standard Contracts (ndjson event line) closes `source` to `hook` · `wrapper` · `cli`, and the paragraph after Event `data` per kind lists the wrapper-appended kinds without `link` / `unlink`: the `source` of a link line is unworded. For a `driven` that is not the serving wrapper, an `unlink` of an absent pair and a `driver` equal to `driven`, architecture §Conventions (Error handling schema → `RefusalReason`) holds no reason or detail; a new detail may be added only in `viola-core`'s closed set, and the worded alternative for a bad parameter is `-32602` with `data: null` (per architecture §Standard Contracts, Channel methods).
- **Offsets and wakes stay as they are.** `events.ndjson` is never rotated or truncated, because `wait`'s `after`, `send`'s `cursor` and the SSE ids are byte offsets into it (per architecture §Occupied Resources, Filesystem). A `send`'s cursor is the log's end offset when the send was accepted, and `send-issued`'s `cursor` is the offset its own line starts at (per architecture §Standard Contracts, Channel methods → `send`, and Event `data` per kind → `send-issued`): where the implicit `link` line lands relative to `send-issued` must keep both true. `link` and `unlink` are not among the kinds that wake `wait`, and only hook lines signal a parked call (per architecture §Standard Contracts, Channel methods → `wait`).
- **The budget gate has three read points.** Architecture §Established Decisions ([Budget Governor]) requires the gate to be read at start, at a `send` and at each `turn-ended`, and states that `answer`, `wait`, `last`, `pause` and `hook.dialog` do not read it; the same decision records that no case drives one of them under a closed gate, which is the folded test's subject. `link` and `unlink` add no fourth read point. For the control: architecture §Conventions (Error handling schema → `RefusalReason`, the `send` order) puts `human-typing` ahead of `budget-paused`, so the control `send` reads `budget-paused` only while the wheel is not `human`, which bounds where the `pause` step may sit in the case. Whether the `budget.json` feed through `viola hook statusline` runs on every CI OS is research's question (architecture §Standard Contracts, Hook contract, words the shell-out as Unix only and the write as part of the arm's order).

## Patterns to follow
- **A set rebuilt from the log at start.** The `dialog_id` counter is restored from `events.ndjson` on start, and `last` is rebuilt from the whole log before the server serves (per architecture §Established Decisions, [Message Broker / IPC], and §Standard Contracts, Channel methods → `last`). The link set follows the same shape.
- **Answer only after the record has landed.** `pause` and `release` are answered only after their record is in the log, with `-32603` when it is not, and the budget gate appends its line and rewrites its snapshot fields only on a change of state, both before it returns (per architecture §Standard Contracts, Channel methods → `pause` / `release`, and §Established Decisions, [Budget Governor]). A link change follows it: the line, the snapshot's `links`, then the answer.
- **Module layout.** One module per subcommand under `src/cmd/` (`link` and `unlink` are named there), the shared channel client in `client.rs`, human lines in `src/human.rs`, the wrapper's state under `src/run/` with `snapshot.rs` as the one in-process snapshot holder, and the replay in `viola-state`'s `replay.rs` with its crate-level suite (per architecture §Infrastructure Patterns → Project directory structure).
- **Names through the newtype.** A method that reads a name takes it absent, `null` or a valid `ViolaName`, and answers anything else `-32602` with `data: null` (per architecture §Standard Contracts, Channel methods); the instance key is `ViolaName` (per architecture §Conventions, Data model conventions). `driver` and `driven` follow it on both the client and the wrapper side.
- **Tolerant own formats.** A known-kind line with a `data` key outside its kind's list is returned and counted once, and an older binary counts a kind it does not know (per architecture §Established Decisions, [Database / State Store], and §Cross-cutting Patterns, Mixed-version tolerance). A link line carries exactly its listed keys; `since` is RFC 3339 UTC with milliseconds and `Z` (per architecture §Conventions, Data model conventions → Timestamps).

## Anti-patterns to avoid
- No MCP tool and no GUI write route for `link` or `unlink`: they are CLI-only human controls over the link topology, and the page is view-only in v1 (per architecture §Established Decisions, [MCP] and [GUI Control Scope]).
- No writer but the wrapper, and no second store: the CLI verb sends a frame and writes neither `events.ndjson` nor `snapshot.json`, and no links file is added beside the log (per architecture §Established Decisions, [Links]; §Standard Contracts, Instance snapshot; §Design Philosophy, "No daemon; the disk is the shared truth"). With no live endpoint the verb ends as instance unreachable, exit 21 (per architecture §Conventions, Error handling schema → CLI exit codes).
- No Tokio on the channel-server or CLI path, no `deny_unknown_fields` on the new lines, and no reading of `from` as identity: it is self-reported (per architecture §Cross-cutting Patterns, Tokio containment; §Established Decisions, [Validation] and [MCP]).
