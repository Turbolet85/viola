## Constraints
- design-system §Surface: cli → Component Patterns, component 4 "Wheel, link and gate verbs" requires the exact human line of each verb: the `link` line with its `since` time, the `link` line of an existing pair ending in the words `already linked` (no time on that line), and the `unlink` line. The scope's `design-system.md:804` / `:805` citations resolve to this component; cite it by this title, not by line number.
- design-system §Surface: cli → Component Patterns, component 4 shows the verb word padded so the `<driver> -> <driven>` field starts at one column for both verbs (the sample holds four spaces after `link`, two after `unlink`). The plan words no padding rule beside the sample; the sample is the authority, and the two-space gutter between the remaining fields is the one design-system §Iconography (Separator) requires.
- design-system §Surface: cli → Tokens (platform-specific), the handoff-blue row, requires link output to be plain at every colour depth: no SGR byte of any kind on a `link` / `unlink` line, TTY or not. The human and plain modes of these two verbs are therefore required to be byte-identical; whether the SGR module is already bypassed for a verb that styles nothing is research's question.
- design-system §Iconography (Transfer arrows) requires the CLI arrow to be ASCII `->`, with no inbound form, and design-system §Surface: cli → Tokens (Width) requires human output to be ASCII only and never wrapped; the names are not truncated on a verb line (truncation there is for NAME of unwrapped table rows only).
- design-system §Surface: cli → Tokens (Streams) requires the result line on stdout and every refusal, its `hint:` line and every error on stderr; under `--json` the whole result, refusals and errors included, is one JSON document on stdout with the typed exit code and no `hint:` line.
- design-system §Surface: cli → Tokens (Colour decision order) requires `--json` to replace the human words with its JSON document alone, and design-system §Surface: cli → Component Patterns (Exit-code phraseology, the exit 0 row) fixes the success envelope's outer shape; the keys inside it for `link` are not design's (see Contract bindings).
- design-system §Surface: cli → Navigation Pattern requires `link` and `unlink` as flat one-word lower-case verbs listed in `viola --help` under the `handoff:` group. Whether the verbs and that help group already exist in clap's dispatch is research's question.

## Patterns to follow
- The other verb lines of design-system §Surface: cli → Component Patterns, component 4 (`pause`, `release`, `answer`) are the model: one static unstyled stdout line, two-space gutters, fixed phraseology words, no trailing prose. `link` / `unlink` follow the same shape.
- Refusals of the two verbs take the forms design-system §Surface: cli → Tokens (Streams) and component 2's hint list already fix for the shared codes: the `unable  <name>  <reason>  <detail>` line, then the one `hint:` line keyed by reason; exit 21 `instance-unreachable` takes its per-cause hint from design-system §Surface: cli → Component Patterns, component 2. The plan words no link-specific refusal line and does not say which of the two names fills `<name>` on a `link` / `unlink` refusal: a gap for the fork round, not a form to invent.
- A clock time on a verb line follows the UTC `HH:MM:SS` + `Z` form of the component 4 sample, whole seconds (the millisecond form belongs to the `send` / `wait` result lines of components 2 and 3).
- The brand stance of design-system §Brand Identity (Standard phraseology; "nothing announces success before it is confirmed") governs wording: the line states the pair and the fact (`since <time>` or `already linked`), never a bare "done".

## Anti-patterns to avoid
- design-system §Anti-Patterns → Per-Surface Bans (cli): never colour anything but `DIALOG` and `stale` rows — no blue, bold or dim on a link line, and no reserved blue index (design-system §Surface: cli → Tokens, the handoff-blue row).
- design-system §Anti-Patterns → Per-Surface Bans (cli): never emit colour, glyphs or cursor control under `--json`, non-TTY, `NO_COLOR` or `TERM=dumb`; never mix data and messages across stdout and stderr; never print "done" or "success" without context.
- design-system §Anti-Patterns → Per-Surface Bans (cli): never print upstream text, paths, pids or error chains in an error or hint; and per design-system §Surface: cli → Component Patterns, component 2, no hint ever names `viola release` (relevant to the folded case, whose control is a `budget-paused` refusal).

## Contract bindings
- **design ↔ architecture (the link result payload, scope item 6).** design-system §Surface: cli → Component Patterns, component 4 prints two facts on the human `link` line — a first-linked time, or that the pair already existed — and §Surface: cli → Tokens (Streams) requires `--json` to be the whole answer. The machine payload therefore needs to carry both facts for the human line to be rendered from the reply; its key names are architecture's channel contract to word, not design's. The human line of an existing pair prints no time even if the payload holds one.
- **design ↔ architecture (unsettled shapes).** The plan words no human line for an `unlink` of a pair not in the set, for a `driven` that is not the serving wrapper's name, or for a `driver` equal to `driven`; component 4 holds exactly one `unlink` line and two `link` lines. Whatever the fork round rules, a new human line or hint is a design-system amendment owed at the wrap, and until then no such wording is written into the plan as the master's.
- **design ↔ architecture (a `since` on another UTC date).** Component 4's `link` sample gives a time-only form. The date-bearing form on the `release --budget` line of the same component is marked there as a planning form the founder has not worded, so it is not a precedent to borrow for `since` silently; the choice is a fork, and its wording a wrap amendment.
- **design ↔ tests (Scenario E3's CLI half, the folded budget case).** Any assertion on human output binds to the exact lines of design-system §Surface: cli → Component Patterns: component 4 for `link`, `unlink`, `pause` and `answer`; component 3 for `wait` and `last`; component 2 and the exit 11 row of the Exit-code phraseology table for the control's `budget-paused` refusal and its hint.
- **design ↔ a11y (colour never alone).** design-system §Color Palette (Domain status colors: "Colour never stands alone") is met on this surface by the absence of colour: every fact on a link line is a word. The `EventKind::link` / `EventKind::unlink` rows of that table (handoff-blue names in tape lines) are requirements on the page's tape, which this chunk does not build; the event kinds landed here are the ones those rows will later render.
- **design ↔ security.** Names on the human line are `ViolaName` values, so no C0/C1 escaping pass is defined for them in component 4; that rests on both arguments passing the security plan's name validation before anything is printed. Whether the client validates before printing is research's question.

## Acceptance criteria contributions
- (design) `viola link <driver> <driven>` on a new pair prints exactly one stdout line of the component 4 form (padded verb, `<driver> -> <driven>`, `since` and a UTC `HH:MM:SSZ` time), and on an existing pair the `already linked` form; `viola unlink` prints the component 4 `unlink` line; nothing goes to stderr on exit 0 (per design-system §Surface: cli → Component Patterns, component 4 "Wheel, link and gate verbs").
- (design) The bytes of a `link` / `unlink` human line hold no ESC (0x1B) and no non-ASCII byte in any mode, a forced-colour TTY included (per design-system §Surface: cli → Tokens (platform-specific), the handoff-blue row, and §Iconography, Transfer arrows).
- (design) Under `--json` each verb writes one JSON document on stdout and no human word, no `hint:` line and no stderr text, refusals included (per design-system §Surface: cli → Tokens, Streams and Colour decision order).
- (design) A refusal of either verb prints its `unable` line and its `hint:` line on stderr only, with stdout empty in human mode, and the hint names no path, pid, upstream text or `viola release` (per design-system §Anti-Patterns → Per-Surface Bans, cli, and §Surface: cli → Component Patterns, component 2).
