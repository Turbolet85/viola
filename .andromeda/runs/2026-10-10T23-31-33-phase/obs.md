# obs extract

## Relevance
partial — tier Standard (1) with Minimal exporter carve-outs (per obs-plan §1 Obs Scope Summary). The chunk's two channel methods, two short-lived CLI verbs, the implicit link and the replay's link half all ride lines and spans obs-plan already words; obs-plan names no new `event` value, no new log field and no span of its own for a link. The folded budget case reads obs lines that exist.

## Constraints
1. **The process-log trace of a link is the channel pair, nothing else.** obs-plan §4 Edge flows (E3) requires `channel-request` / `channel-response` with `method` `link` or `unlink` on the driven wrapper, and places the product `link` / `unlink` records in `events.ndjson`. It words no process-log line for the link itself. The implicit link on a `send` or an `answer` therefore adds no process-log line beyond the lines that call already writes; its record is the product line (per obs-plan §2 Telemetry signal pyramid, the Audit Logs row: event payloads are never copied into process logs). obs-plan names no join key between an implicit `link` record and the call that caused it; whether the plan wants one is a fork, and a new key is a field outside the catalog (constraint 3).
2. **No new `event` value.** obs-plan §3 Log format JSON schema requires a Decisions Log entry for every new value of the closed `event` enum, and the binding text is the tests' (obs aligns to tests). The chunk as scoped needs none; a `link`-named process event would be an amendment plus a `schemas/diag-line.v1.json` change, not a plan step.
3. **`driver`, `driven`, `since` and the link result reach no home-level line.** obs-plan §8 Default-deny posture admits only fields the §6 catalog names, and obs-plan §6 Additive field catalog gives `channel-request` and `channel-response` no such field. obs-plan §6 Boundary-call wrappers (IPC invocation) requires that `params` and result bodies are never recorded, not even hashed. So the item-6 result payload (first-linked time, already-linked) is a wire and stdout fact only. The one name the channel line may carry is `from`, with `from_trust` (per obs-plan §6 Additive field catalog).
4. **Correlation on both sides.** obs-plan §3 Trace context propagation (IPC boundaries) requires `corr` = the JSON-RPC `id` and the client-made `conn` on the `channel-*` lines of both sides, `conn` stripped from `params` before dispatch, and `from` logged only with `from_trust:"self-reported"`, never as identity. obs-plan §10 Standard+ invariants (Correlation propagation) requires it of every channel call, so of `link` and `unlink` too. Whether the shared client and dispatch paths already write both lines for any method name, with no per-method work, is research's question.
5. **CLI verbs: a dispatch span and the process pair.** obs-plan §4 Instrumentation per surface (the short-lived verbs row) requires a dispatch span per verb and `process-start` / `process-exit{exit_code, detail}` in `cli-<name>.ndjson` when an instance resolves, the full chain in `detail-cli.ndjson` only. obs-plan §2 Naming conventions closes the span `<area>` list, which holds no `link`, and names `cli.<verb>` for a verb with no dedicated client span: `cli.link` and `cli.unlink` fit without an amendment; `link.client` would need one. obs-plan §3 Trace context propagation (`cli` instance precedence) puts the caller's `VIOLA_NAME` first and "the explicit target" second; with two positional names the plan does not say which one names the file when `VIOLA_NAME` is unset. That is a fork for the plan (the driven instance is the frame's target) and an amendment for the wrap.
6. **Levels follow the reply class the plan picks.** obs-plan §6 Log levels mapping requires `info` for a refusal, `warn` for a `channel-response` with `-32600` / `-32602` and for a `process-exit` with exit 21, `error` for `-32603` and for exit 1 or 20. The three unsettled shapes (a `driven` that is not the serving wrapper, an `unlink` of an absent pair, `driver` equal to `driven`) and a name `ViolaName::try_new` refuses take their level from that choice. A `-32602` answer adds one more cause to the over-count obs-plan §5 Per-surface / per-path metrics records on `viola.compat.v_rejected`; the wrap amends that row if one lands.
7. **The replay's link half adds no line.** obs-plan §4 Edge flows (E5) requires the spans `state.replay` and `state.snapshot_recover` to stay `skip_all` with neither `err` nor `ret`, and one `state-recovered` line per recovering call. obs-plan §4 Edge flows (Torn append) states the reader's per-read counts have no process-log carrier. So a `link` line moving out of `unknown_kinds` leaves no process-log trace, and the derived `links` are read from the snapshot or the replay's return, not from a log line.

## Patterns to follow
- **A no-span, no-line operation whose trace is its neighbours.** obs-plan §4 Scenario: Budget governor records two operations that carry no span and no line of their own, traced by the `channel-*` pair, the product record and the snapshot fields. The link-set change has the same three carriers (the `channel-*` pair, the `link` / `unlink` record, the snapshot's `links`). If the plan gives it a span instead, the name is static, in the `run` or `state` area (per obs-plan §2 Naming conventions). Either choice is written into obs-plan §4 at the wrap.
- **Span declaration form.** `#[instrument(skip_all, name = "<area>.<operation>", fields(...))]` with an explicit field allow-list, `skip_all` the first argument (per obs-plan §4 Span naming convention). A `ViolaName` may be a span field (obs-plan §4 Scenario: `viola run` start sequence does so on `run.start`), never part of a span name.
- **`channel-response` from the dispatch guard.** obs-plan §4 Scenario: Confirmed `send` (Cleanup) requires the response line from a `Drop` guard in `channel.dispatch`, so an early return or an error still logs it; obs-plan §7 Panic hooks requires a panicking connection worker to end in `channel-response{result_class:"error", error_code:-32603}` with `run` continuing. The `link` / `unlink` arms sit inside that guard, not beside it.
- **Explicit values, typed fields.** `corr`, `conn` and `instance` are passed as explicit values and set on each `obs_event!`, never recovered from span context (per obs-plan §3 Trace context propagation, Internal async boundaries); every line goes through `obs_event!` with typed fields (per obs-plan §8 Integration points).
- **The healing append.** obs-plan §4 Edge flows (Torn append) puts `state-recovered{detail:"torn-line-healed"}` on the process whose append healed. The wrapper's `link` / `unlink` append goes through the same append as its other product lines so a heal is logged once; whether one append helper already carries that is research's question.

## Anti-patterns to avoid
- NEVER add an `event` value or rename a tests field without a Decisions Log entry, and NEVER log a field the §6 catalog does not name — no `driver`, `driven`, `since` or already-linked field on any home-level line (per obs-plan §11 Logs; obs-plan §11 PII Scrubbing).
- NEVER a bare `#[instrument]`, `err` or `ret`, and no instance name in a span name (per obs-plan §11 Spans / Traces).
- NEVER write telemetry to stdout or use a print macro outside the output modules that own `--json` and the human CLI lines: the two verbs' human, plain and `--json` output goes through those modules, and nothing else of the chunk prints (per obs-plan §11 Logs).

## Contract bindings
- **obs ↔ tests §3 Log format.** The required fields, the `event` enum and each value's `corr` rule are the tests' text reproduced (per obs-plan §3 Log format JSON schema). E3's "exactly one `link` record" and E5's `link` step read `events.ndjson`, which the harness reaches through `agent-run logs --kind` (obs-plan §4 Scenario: `viola run` start sequence names that read for product order). Whether the harness's `--kind` filter admits `link` and `unlink` is research's question, tests-owned.
- **obs ↔ tests, the gates.** New cases keep their viola homes under `target/e2e-home/` so G2, G4 and the secret scan read them (per obs-plan §9 Pipeline integration, the Integration tests row). `schemas/diag-line.v1.json` is obs-owned and G4's check body tests-owned (per obs-plan §9 Gate commands, G4). Whether that schema closes `method` to a list without `link` / `unlink` is research's question; if it does, the schema edit belongs to this chunk and the Decisions Log entry to its wrap.
- **obs ↔ tests, the folded budget case.** The gate is fed through `viola hook statusline`, whose obs witness is `hook-decision{hook_event:"statusline", budget_written}`; the control's witness is the wrapper's `send-refused{refusal:"budget-paused"}` with client exit 11; `run.budget_eval` is opened only at start, at a `send` and after `turn-ended`, so `answer`, `wait`, `last` and `pause` open none (per obs-plan §4 Scenario: Budget governor).
- **obs ↔ security.** obs-plan §4 Scenario: `wait` / `last` records that `strict-modes-failed` and `server-verify-failed` cannot occur on the liveness-only verbs until the Epoch 6 entries; `link` / `unlink` are not named there. Their exit-21 `detail` set (`instance-dead` with `during`, per obs-plan §6 `detail` code catalog) follows the founder's word on the held widening, and the wrap amends that sentence either way.
- **obs ↔ architecture.** The `link` / `unlink` event line and the snapshot's `links` are architecture's contracts; obs requires only that their content stays out of process logs (per obs-plan §1 Obs Scope Summary, the Persistent stores entity).
- **obs ↔ the dialog path.** obs-plan §4 Scenario: Dialog → `answer` requires `dialog-answered` to carry `from` and `from_trust`, which bears on the scope's question whether `answer` carries `from` on the wire; what the code sends is research's question.
- **Wrap amendments this chunk would owe obs-plan:** §4 Edge flows (E3) as landed; §4 Span kinds and §2 Naming conventions if a span name is added; the instance-precedence sentence of §3 Trace context propagation for a two-name verb.

## Acceptance criteria contributions
- (obs) An explicit `viola link` and an explicit `viola unlink` each leave, in the driven wrapper's `run-<name>.ndjson`, one `channel-request` and one `channel-response` with that `method` sharing `(conn, corr)`, and neither line holds `driver`, `driven`, `since` or a result field (per obs-plan §4 Edge flows).
- (obs) With an instance resolved, each verb writes `process-start` and `process-exit{subject:"self", exit_code}` to `cli-<name>.ndjson`, and a dead target ends `process-exit{exit_code:21, detail:"instance-dead", during}` at WARN (per obs-plan §4 Instrumentation per surface).
- (obs) In the folded budget case the automated `send` under the closed gate writes the wrapper's `send-refused{refusal:"budget-paused"}` and exits 11, and no `channel-response` of method `answer`, `wait`, `last` or `pause` in the same home carries `refusal:"budget-paused"` (per obs-plan §4 Scenario: Budget governor).
- (obs) Every home-level line the chunk's cases produce passes `schemas/diag-line.v1.json` under G4 with zero panic lines under G2, and every new span declaration passes G1 (per obs-plan §9 Gate commands).
