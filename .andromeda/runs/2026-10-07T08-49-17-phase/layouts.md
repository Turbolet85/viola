# layouts extract

## Relevance
partial — the chunk renders nothing on web-spa and adds no surface; it touches the cli surface only where its measurements run through `viola verify`, `viola send` and `viola wait`, and where a landed ledger row (W1, W2, W6) or a chosen remedy (W4, W5) would move a human output line.

## Constraints
- Surface and region: every human line this chunk can move sits on the cli surface, in three output structures — the `viola verify` step list and its summary, the `viola send` readback mirror with its refusal and hint, and the `viola wait` result line; no web-spa wireframe, component, focus order or breakpoint is in scope (per layout-templates §Surface: cli › Primary screens (commands)).
- If W1 or W2 lands a ledger row, layout-templates requires one stdout step line per ledger row in ledger order, the `MM` denominator equal to the row count, and the `stamped` summary as the last stdout line; the section names `MM` as 17 today and its ordered id list holds seventeen ids, so a landed row makes that text stale and its amendment is the wrap's (per layout-templates §Surface: cli › Output structure — `viola verify`).
- The chunk's live rounds name the 2.1.287 binary after `--`; layout-templates requires the usage shape `viola verify [--record <DIR>] [-- <program> [args…]]` and nothing else, so a W5 remedy that gives `verify` a new flag or a new human line (a leftover-removal report, a census line) is a change to this output structure, not an implementation choice (per layout-templates §Surface: cli › Output structure — `viola verify`).
- W4's in-hint `send`: when the outcome is a refusal, layout-templates requires the struck mirror line on stderr with exit 13 and the `hint:` line as the last stderr line, the hint keyed by reason and detail; the hint text for `input-not-ready` is a fixed line of the plan, so a remedy that rewords it (for instance because `viola wait` proves to have nothing to wake on) is a layout amendment carried with the founder's card (per layout-templates §Surface: cli › Output structure — `viola send`).
- Any hint a W4 remedy introduces points to the next verb by name and never names `viola release`; hints never quote sent or upstream text, a path or a pid (per layout-templates §Surface: cli › Component — Primary navigation (verb structure)).
- W4's `viola wait` in the live window: the result is one of the section's stdout result forms (the timed-out form included), `waiting:` on stderr and TTY only, no spinner and no elapsed counter; under `--json` exactly one stdout document and nothing on stderr (per layout-templates §Surface: cli › Output structure — `viola wait` / `viola last`).
- Human columns and words are a stable contract because LLM drivers read them; a new field goes into `--json` first, and the card's four options are to be priced against that (an option that adds a human state word or column is a design change) (per layout-templates §Surface: cli › IA notes).

## Patterns to follow
- A new ledger row's step line takes the existing three-part form (counter, row id, row words, then the verdict word) and is appended once, plain ASCII, no redraw (per layout-templates §Surface: cli › Output structure — `viola verify`).
- A `verify` refusal a new probe path can raise is an `unable:` line with its own `hint:` line, fixed text, naming no name, path or pid; the recorded-fixture refusal names the fixture file and a closed code, never the content — the form W3's fixture variants and W2's names-only record must fit if they pass through `--record` (per layout-templates §Surface: cli › Component — Primary content block 2: refusal lines and the `unable` column).
- The send outcome vocabulary is closed at four state words padded into one column; a remedy's outcome is expressed in those words and in the typed exit tail, with the cause carried as a reason and detail pair (per layout-templates §Surface: cli › Component — Hero / signature output line (the `viola send` readback mirror)).
- Streams stay split: results on stdout; the issue line, `waiting:`, refusals, hints and errors on stderr (per layout-templates §Surface: cli › Component — Primary content block 2: refusal lines and the `unable` column).
- The run closes on the `stamped` summary for `verify` and on the `hint:` line for a refusal; the exit code is the terminator (per layout-templates §Surface: cli › Component — Footer / terminator).

## Anti-patterns to avoid
- No progress bar, spinner, redraw or colour on `verify` output, and no extra human line from `--record`; a longer hint-window wait (one of the card's options) may not be shown as a spinner or an elapsed counter on `send` or `wait` (per layout-templates §Surface: cli › Output structure — `viola verify`; §Surface: cli › Output structure — `viola wait` / `viola last`).
- `turn-ended` is never reported as a send outcome, and no `Sending…`, tick or `done` line appears; a remedy that waits out the hint still ends in one of the four mirror words (per layout-templates §Surface: cli › Component — Hero / signature output line (the `viola send` readback mirror)).
- No terminator word, summary banner or version line added to any verb for the sake of the live record; the measurement record lives in the chunk's evidence, not in product output (per layout-templates §Surface: cli › Component — Footer / terminator).
