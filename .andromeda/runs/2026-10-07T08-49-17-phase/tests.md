## Constraints
- The real `claude` CLI is local-only and never a CI input: test-plan §1 Test Scope Summary puts the real CLI and Anthropic backend out of CI scope ("local only, through `viola verify`"), and test-plan §11 Test Strategy bans running the real CLI or a real-CLI `viola verify` in CI. Nothing this chunk commits (test, harness arm, workflow step) may start the real CLI outside the operator's host.
- `run --local-live` is not this chunk's live channel: test-plan §3 `run` (the `--local-live` bullet) requires one `viola verify` with the program default `claude` and no `--`, under a `viola-live-<pid>` home, refused with `live-in-ci` when `CI` is set; its live firing at the full row count is owed to "First live test and self-drive". The chunk's by-path 2.1.287 rounds therefore sit outside that suite; test-plan §3 `run` names no harness arm for a by-path live round, and whether one is needed is P4's question, not a plan mandate.
- If a ledger row lands, every row-count oracle is a test literal and moves with it: test-plan §3 `run` (the `--local-live` bullet) requires each literal id of `LEDGER_ROWS` to name exactly one step line ending `  pass` and the literals to be unit-proven in `harness::run::tests`; test-plan §3 `boot` step 4 requires the fake-agent verify to stamp every row with the `stamped <ver>  <n> pass  0 fail` last line; test-plan §5 Integration Test Strategy (CLI, `tests/cli_verify.rs`) pins the `[NN/<count>] <row id> …  pass|fail` step lines; test-plan §5 Integration Test Strategy (CLI, `contract_ledger_probes.rs`) requires each literal row id exactly once per stamped set and `<n>` equal to the literal count. How many sites carry the count today is research's question.
- A new row needs a probe the fake agent can replay in CI: test-plan §1 Test Scope Summary (contract-test-against-sandbox trigger) requires every ledger row to have a `viola verify` probe with a post-condition, and test-plan §2 Test Strategy (Contract row) requires the fake agent to replay each recorded variant byte for byte. A row whose probe path exists only against the real CLI (either widening of the probe-path card) has no CI-side proof under the plan; that gap is part of what each card option must price.
- Recorded fixtures come only from the recorder: test-plan §7 Test Data & Fixtures (Seed strategies, Recorded hook payloads) requires payloads under `fixtures/claude/<cli-version>/` to be recorded by live `viola verify`, scrubbed and `unclean`-checked, a dirty payload refusing the whole recording; test-plan §7 Test Data & Fixtures (Fixture hygiene) requires the run-time walk plus the jsonschema check over every committed fixture and synthetic probe text only. A paste-shape or prefix reading taken by a scratch probe is not a fixture under these rules; whether it becomes one (W3's "recorded") depends on it becoming a probed row.
- Test oracles are literals, never product imports: test-plan §11 Unit bans importing `IDENTITY_FLOOR` or the ledger rows as the oracle, and test-plan §4 Unit Test Strategy (viola-agent-claude) requires the R8 strip tested against a literal copy of the 11 identity-floor names and `prompt-submitted` normalisation tested over the four harness prefixes on the raw start with no trim. If W1 or W2 measures something the compiled set does not hold on 2.1.287, the literal test copies move with the product; whether the existing cases already cover the measured readings is research's question.
- No timer, sleep or screen-content verdict in any test this chunk adds: test-plan §2 Test Strategy (Agent-runnable invariants) requires waits keyed on event offsets or `viola wait --after`, and test-plan §11 Universal bans a test-owned timer or elapsed-time verdict, allowing a block on an un-injectable product deadline only when the verdict is the product's own exit code or status field and the same deadline is clock-driven in a §4 unit case. A hint-window test (W4) falls under both.

## Patterns to follow
- The paste-hint window is forced open on the fake agent, not timed: test-plan §7 Test Data & Fixtures (Fake agent, Modes) defines `--paste-hint-ms` (capped) with `--framing`, and test-plan §5 Integration Test Strategy (CLI, `tests/cli_verify.rs`) names the `verify_window_` case built on it. A corrected real-CLI reading for a `send` or a `viola wait` inside the window lands as a fake-agent case of this kind; the plan adds that no fake-agent shape is invented before a recorded fixture (test-plan §7 Test Data & Fixtures, Fake agent, Modes).
- Paste-shape readings land as unit cases at the parser layer: test-plan §4 Unit Test Strategy (viola-agent-claude) names the eight labelled cases of `prompt_text_drops_the_cli_framing_around_a_pair` and the wrapped-paste property. Whether those cases already hold W3's three shapes (a paste beside typed text, two pastes in one prompt, a paste ending in a newline) is research's question; test-plan §11 Test Strategy keeps such cases out of E2E.
- A fixture set is on exactly one list: test-plan §5 Integration Test Strategy (CLI, `contract_ledger_probes.rs`) requires the stamped and drift-only lists to be test literals with every fixture dir on exactly one; `2.1.287` stays the one stamped set, and no `2.1.289` dir is created (scope boundary R-L3).
- Verify leaves no run dir on its exit paths: test-plan §5 Integration Test Strategy (CLI, `tests/cli_verify.rs`) requires "no run dir left behind". The plan is silent on a killed verify; if `viola verify` gains a removal of what a kill left (W5), its test belongs at this assert_cmd layer against the fake agent.
- Homes and env per child: test-plan §5 Integration Test Strategy (Setup / teardown lifecycle) requires a fresh not-yet-existing home under `target/e2e-home` per test, and test-plan §7 Test Data & Fixtures (Test data lifecycle) requires env set by `Command::env` only. The receipt's `env` kind is names only (test-plan §7 Test Data & Fixtures, Fake agent, receipt kinds), the shape W2's names-only recording matches.

## Anti-patterns to avoid
- Treating a green fake-agent run as proof of a real-CLI behaviour, in either direction: test-plan §11 Test Strategy requires a local `viola verify` fixture refresh plus the contract suite for a behaviour change. The fake-agent reading of a `send` inside the hint window is not the real CLI's until W4 measures it.
- Hand-writing a stamp, a fixture payload or a home to make a row or a shape pass: test-plan §11 Test Data bans hand-written `ledger/stamps.json` and committed `--home` dirs, and requires fixtures to come only from `viola verify` probe text, scrubbed.
- Parsing the rendered child screen for content, or re-running a red for green: test-plan §11 E2E takes verdicts from hook events, `events.ndjson`, channel payloads and the receipt only; test-plan §10 Quality Gates & Coverage Targets (Zero-flakiness budget) allows no retry, `#[ignore]` or skip as a parking place.

## Contract bindings
- tests ↔ architecture: the row ids in `LEDGER_ROWS` (test-plan §3 `run`, the `--local-live` bullet) mirror `viola_agent_claude::ledger`; a row landing changes both, plus architecture's [CLI Version Compatibility] record of the harness prefixes and the identity floor.
- tests ↔ obs: every home a test or harness arm creates sits under `target/e2e-home/**`, the root obs-plan §9's G2, G4, secret scan and uploads read (test-plan §3 `boot` step 2); a live round's home that sits elsewhere is outside those gates.
- tests ↔ security: the `claude-stripped` canary table (test-plan §3 `secret-scan`) and the names-only receipt bind to security-plan's NEVER-log floor for `CLAUDE*` values; the recorder's refusal codes (test-plan §7 Test Data & Fixtures, Fixture hygiene) bind to security-plan's `--record` ruling; both probe-path widenings are security-plan rulings, not test-plan ones.
- tests ↔ wrap: test-plan §3 `run` (the `--local-live` bullet) names fourteen ids under its seventeen-row count; the spec text is the wrap's to amend (scope W6), and test-plan §3 Closed enums requires a Decisions Log entry for any new `run` suite, reason or `local-live` failure code.
