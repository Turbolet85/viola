## Constraints
- A dependence on an undocumented `claude` behaviour is required to be a capability-ledger row in `viola-agent-claude` with a `viola verify` probe that carries a post-condition check, never an unconditional assumption (per architecture §Cross-cutting Patterns → Capability ledger as the single gate for CLI-specific behaviour). The harness prefixes and the R8 identity floor are listed as ledger rows not yet landed and owed to this entry (per architecture §Established Decisions → [CLI Version Compatibility]). The plan gives neither row a probe path: W1's cross-session half and W2's environment-name reading have no described mechanism, so each is new surface, not a reading of an existing one.
- The ledger is required to be a closed set (seventeen rows today), and a CLI version is verified only when its stamp holds every landed row `pass`; a stamp holding fewer ids reads unverified. A new row therefore needs its own `viola verify` probe and a re-stamp of every stamped version, and the plan prices one verify at five `claude` starts (per architecture §Established Decisions → [CLI Version Compatibility]; the stamp shape per architecture §Standard Contracts → Ledger stamps envelope). W6's count literals and the live cap of 10 are bound by this. Whether the code's row count and count literals match is research's question.
- `viola verify`'s shape is fixed: one print-mode probe, then four interactive runs, each a direct spawn under the R8 strip at 80×24 with output capped at `MAX_FRAME`; Run B's pastes are compiled texts, each added only into rows holding the input-box literal and no modal literal; no run writes a byte into a CLI dialog and a start showing a modal is killed with no key (per architecture §Established Decisions → [CLI Version Compatibility]). The hidden `hook <event> --capture <DIR> [--answers <DIR>]` arm is required to read no `VIOLA_*`, do no obs init, open no channel and write only the raw stdin it was handed (per architecture §Established Decisions → [Hook Contract]; per architecture §Occupied Resources → Binary, subcommands and exit codes). Both of that arm's earlier extensions are recorded there as founder-ratified boundary widenings, so a probe that records environment names, or a verify child a second session can address, is outside the described shape until ratified the same way.
- The readiness gate is required to stay as it is: `QUIET_PERIOD` (300 ms) and `GATE_MAX_WAIT` (5 s) are compiled built-ins in `viola-agent-claude`, validated per CLI version by the stamped `quiet-period` row (per architecture §Established Decisions → [Screen Model]). What `send` does while the paste hint stands is recorded as the founder's open decision, made on this entry's numbers, with the gate unchanged until then; the plan states no `send` was run in the real CLI's hint window and that the hint is timed a second time here (per architecture §Established Decisions → [CLI Version Compatibility]). Any priced card option that lengthens a bound also moves `send`'s total blocking time, which is required to stay below the MCP client's tool-call timeout (per architecture §Established Decisions → [Delivery Confirmation]).
- Delivery matching is required to compare the sent text with `prompt-submitted`'s `text` exactly (no trim) after `viola-agent-claude` normalises it in a fixed order: `harness` classification on the raw prefix first, then removal of the long-paste wrapper with its frame, then the un-escape (per architecture §Established Decisions → [Delivery Confirmation]; per architecture §Standard Contracts → Event `data` per kind). `hook::unwrap_pastes` is required to unwrap only the exact same-id pair and its measured frame, nothing wider; the three shapes W3 measures are listed there as unmeasured, and the trailing-newline behaviour as read statically, not measured (per architecture §Established Decisions → [CLI Version Compatibility]). Whether the compiled unwrap already returns the pasted text for each of the three shapes is research's and the live reading's question.
- The R8 strip is names-only: the strip, the registry reader and the logs are required never to read a value, and the identity floor (`IDENTITY_FLOOR` in `viola-agent-claude`, 11 names, recorded as measured on the Windows host) is removed whatever the persistent environment says (per architecture §Occupied Resources → Environment variables). Environment variables are not a configuration channel, and no `viola` build reads a variable beyond `VIOLA_*` and the two `fake-agent` test seams (per architecture §Cross-cutting Patterns → Config management). W2's reading on 2.1.287 on this host is put against those 11 names; a new environment reader in a `viola` build falls under this rule.
- verify's interactive probe dirs (`<cwd>/.viola-verify-<pid>/`, `-dialogs/`, `-plan/`, and Run A's OS-temp dir) are required to be 0700, each a drop guard, removed on every exit path, with the repo's ignore entry for a leftover (per architecture §Occupied Resources → Filesystem). The plan names no kill path; whether a killed verify leaves them (W5) is research's question, and a remover would change this resource entry.

## Patterns to follow
- The landed-row pattern of the three framing rows: compiled probe texts in the pure `ledger` module, `check(row, &Probes)` over Run B's captures in claim order, a stamp written through the one writer, `--record` variants named by `ledger::framing_variants` and written only when 0 rows fail, and the fake agent replaying them in CI under `--framing` (per architecture §Established Decisions → [CLI Version Compatibility]; per architecture §Occupied Resources → Repository).
- The binary under test is named after `--` on `viola verify [--record <DIR>] [-- <program> [args…]]`, and the version is learned from that program's own `--version` first line; that is the described way to reach 2.1.287 by path while PATH `claude` stays unstamped (per architecture §Established Decisions → [CLI Version Compatibility]).
- Workspace placement: Claude-specific shapes (harness prefixes, the identity floor, the unwrap, ledger rows, compiled probe texts) live only in `viola-agent-claude`, which stays pure (no file I/O for stamps); the probe runs live in the root bin (`src/cmd/verify/typed.rs`); stamps I/O stays in `viola-state` and the root bin (per architecture §Infrastructure Patterns → Crate dependency direction; per architecture §Inherited Defaults).
- Provenance wording: each behaviour is recorded with its version, its chunk and its evidence file, and with one of the plan's standing labels ("as measured", "read statically, not measured", "relayed, not yet measured here", "unmeasured"); this chunk's readings are what move those labels at wrap (per architecture §Design Philosophy; per architecture §Established Decisions → [CLI Version Compatibility]).
- The test-side stand-in for the hint window is the fake agent's `--paste-hint-ms` hold (capped at 8 000 ms, with `--framing`); a live reading that corrects the fake-agent result is replayed through that hold, not through a new seam (per architecture §Occupied Resources → Binary, subcommands and exit codes).

## Anti-patterns to avoid
- Compiling a relayed or statically read CLI behaviour in as fact, or recording it as measured: the cross-session prefixes and the start-of-prompt `<task-notification>` reading stay labelled until this repository's own measurement exists (per architecture §Design Philosophy; per architecture §Cross-cutting Patterns → Capability ledger as the single gate for CLI-specific behaviour).
- Widening the unwrap or loosening the match to make a paste shape pass: no trim, no leading-slash test, no Claude-specific shape in the wrapper-side matcher (per architecture §Established Decisions → [Delivery Confirmation]).
- Running the real `claude` in CI, recording a fixture set for an unstamped version, or adding a config key, `VIOLA_*` variable or flag as a probe switch (per architecture §Infrastructure Patterns → CI/CD approach; per architecture §Cross-cutting Patterns → Config management).
