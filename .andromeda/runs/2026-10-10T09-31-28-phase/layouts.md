# layouts extract

## Relevance
partial — the chunk builds no surface and places no component; it produces the counts and refusals that two existing layout slots print (the `skipped` triple and the CLI refusal / fault lines), and it touches `viola verify`, whose stdout shape is fixed.

## Constraints
- The skip count has one shape on every surface: layout-templates §Surface: cli › Output structure — `viola list --json` requires a `skipped` object of three counts (unknown kinds, unknown fields, torn lines) and requires the item, `budget` and `skipped` shapes to be identical to `/api/sessions`. Scope item 3 ("counted and surfaced") and item 1 (the torn-line count) feed that triple; the scope reads today's reader count as `Skipped { oversize, malformed }`, so whether the code's count already maps onto the three named counts is research's question.
- The human order of the triple is fixed: layout-templates §Surface: cli › Component — Header / banner (the BAY context line) requires `skipped a - b - c` as the last cell of the one BAY line, in that cell order, with no bold, colour or box. The board is a later entry (scope §Boundaries); a count this chunk exposes must not foreclose that order.
- A nonzero count is sticky on the page: layout-templates §Surface: web-spa › Component — Header (`<viola-atis>`) requires the `skipped` cell to print muted while zero, boxed in primary ink when nonzero, and never cleared automatically. That is a requirement on the count's lifetime as well as on its drawing (the page is Epoch 8's; whether today's count can only grow within one reader's life is research's question).
- An unknown kind is kept where it happened: layout-templates §Surface: web-spa › Component — Primary content block 3: the tower tape (`<viola-event-feed>`) requires a `skipped  1 unknown kind` line printed in place in the tape. A reader that only totals unknown kinds loses the position that line needs; whether this chunk's count carries a position (an offset or cursor) is architecture's contract and research's question.
- An unreadable home is a declared state, not a blank: layout-templates §Surface: web-spa › Wireframe — Bay, degraded and §Surface: web-spa › Component — State strips require the `unable · state-unreadable` strip in the rack position with the strips keeping their last values. Scope item 2 (replay when `snapshot.json` is unreadable or newer) decides which unreadable cases still reach that strip; the layout names no strip for a replayed or newer-`v` snapshot.
- Refusal and fault lines are closed forms: layout-templates §Surface: cli › Component — Primary content block 2: refusal lines and the `unable` column requires `unable  <name>  <reason>  <detail>` on stderr with its `hint:` as the last stderr line, the typed exit tail (20 wrapper fault as `error: wrapper fault  <code>`, 21 `instance-unreachable`), no hint for `wrapper fault` or `internal error`, no path or pid in any line, and under `--json` one document on stdout with no stderr line. Scope item 4's newer-peer refusal reaches a human only through one of these forms; which exit and code it takes is architecture's to name.
- `viola verify`'s stdout is enumerated: layout-templates §Surface: cli › Output structure — `viola verify` requires one appended step line per ledger row in ledger order, then the `stamped` summary as the last stdout line, plain ASCII, no redraw, and says `--record` adds no human line. It gives no line for an owner record or a leftover removal (scope item 6).

## Patterns to follow
- Words carry state, never a blank cell: layout-templates §Surface: web-spa › Component — Primary content block 1: racks of `<viola-session-row>` strips requires a missing reading to print `unknown` and a contract-absent field to print `n/a`. A snapshot field the replay cannot recover (scope item 2, "log-derived fields only") follows that rule on every surface that later prints it.
- New fields go into `--json` first: layout-templates §Surface: cli › IA notes (Output as a contract) requires the human columns and words to stay stable and treats a new human column as a design change. A count or version this chunk surfaces today lands in a `--json` document, not in a new human column or line.
- Streams are never mixed: layout-templates §Surface: cli › Component — Primary content block 2: refusal lines and the `unable` column requires results on stdout and refusals, hints and errors on stderr.
- The last printed line says what happened: layout-templates §Surface: cli › Component — Footer / terminator requires no terminator word, the exit code as the terminator, the `hint:` line last on a refusal and the `stamped` summary closing `verify`.
- One failure line for a failed verb: layout-templates §Surface: cli › Output structure — `viola wait` / `viola last` requires a failure, an unparseable reply or any other channel error to print `error: internal error` once, exit 1, no hint. A healed or replayed read is not that failure (scope items 1 and 2 make it a success path).

## Anti-patterns to avoid
- A recovery notice on a human stream: layout-templates §Surface: cli › Output structure — `viola wait` / `viola last` and §Surface: cli › Output structure — `viola verify` enumerate each verb's lines and hold no "recovered", "healed" or "removed" line; adding one is a design change, not an implementation choice (per §Surface: cli › IA notes).
- A hint or refusal that names a path, a pid or upstream text: banned by layout-templates §Surface: cli › Component — Primary content block 2: refusal lines and the `unable` column. Scope item 6's owner record holds a pid and a start time, and neither may reach a `verify` line.
- Building the page's or the board's `skipped` drawing here: layout-templates §Surface: web-spa › Component — Header (`<viola-atis>`) and §Surface: cli › Component — Header / banner (the BAY context line) place it on surfaces the scope's Boundaries leave to later entries.
