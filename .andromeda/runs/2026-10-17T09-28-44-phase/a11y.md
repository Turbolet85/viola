# a11y extract

## Relevance
partial — the stdio MCP server itself is a not-assertable surface (no UI; machine-to-machine), so the chunk's a11y reach is only where it touches the cli surface (a new `viola mcp` verb vs. the `--help` table), the human-wins wheel boundary its `send` / `answer` frames meet, and the driver-only time bounds its tools carry.

## Constraints
- The plugin's stdio MCP server is classed not-assertable (ipc-internal, no UI surface), so its tool results and `isError` bodies take no a11y assertion and no a11y tier rigor of their own; the chunk adds no a11y case for the MCP frames themselves (per a11y-plan §1 A11y Scope Summary → Not-assertable).
- The human always wins over every MCP-originated frame: a driver `send` / `answer` arriving through the MCP server must never block, refuse or delay a human keystroke past the current atomic paste, and a human key during a gate wait takes the wheel with the driver refused `human-typing` (per a11y-plan §11 A11y Anti-Patterns → Keyboard). Whether the MCP path reaches the same wrapper `send` path the existing boundary cases hold is research's question.
- Every bound the MCP tools carry (the in-server `wait` bound below the tool-call timeout, `DIALOG_DEADLINE` on `answer`, `GATE_MAX_WAIT` on `send`, the budget pause) must fall on the driver only, never on a keystroke or the human (per a11y-plan §8 Cognitive Accessibility → Timeout extensions).
- The MCP `budget-paused` refusal maps a gate that bounds the driver only: while the gate is closed a human key still reaches the child and the outer-PTY stream carries none of viola's own literals (per a11y-plan §8 Cognitive Accessibility → Timeout extensions).
- If `viola mcp` becomes a clap verb, the `viola --help` grouped table is served-verbs-only and pinned by the `HELP` literal; whether `mcp` is listed (and under which group label: board / traffic / wheel / setup) is a deliberate copy change that must update the pinned literal on purpose, never drift (per a11y-plan §8 Cognitive Accessibility → Plain language).
- The `--help` group labels are the cli surface's structural (heading-equivalent) landmarks; a new verb must not add or reorder a group outside the labelled set without the owning entry (per a11y-plan §4 ARIA Patterns & Roles → Per-surface landmark roles inventory).
- No WCAG conformance claim may be made for the MCP server, the cli or the wrapped TUI on the strength of this chunk's tests (per a11y-plan §11 A11y Anti-Patterns → Strategy).

## Patterns to follow
- The P4 wheel boundary is read step-wise on the wrapper's `channel-request` line and the `wheel` record, never a timer (`send_under_the_paste_hint_a_human_key_during_the_gate_wait_wins`) — an MCP-driven reading of the same clause, if one is added, follows that sequencing (per a11y-plan §3 Keyboard test harness).
- The driver-side budget reading beside the keyboard one (`path6_a_reading_over_the_threshold_refuses_the_send` / `path6_a_closed_gate_leaves_answer_wait_last_and_pause_alone`, `tests/cli_budget.rs`) is the shape for proving the MCP `budget-paused` form leaves the human path untouched (per a11y-plan §3 Keyboard test harness).
- The served-verbs `--help` check (`help_is_the_grouped_verb_table` + `help_lists_only_served_verbs`, `tests/cli_output_plain.rs`) is the place a new `mcp` verb is pinned or excluded (per a11y-plan §8 Cognitive Accessibility → Plain language).
- Any new case lands as an ordinary nextest case inside the existing suites (CI: the per-OS `coverage` suite), on all three OS legs (per a11y-plan §3 CI integration).

## Anti-patterns to avoid
- NEVER let an automation path (here the MCP server's frames) block, refuse or delay a human keystroke, or count focus / mouse / resize sequences or terminal replies as editing (per a11y-plan §11 A11y Anti-Patterns → Keyboard).
- NEVER add a `suite` value (such as `a11y` or `mcp-a11y`) or a separate a11y driver outside `scripts/agent-run.* run` (per a11y-plan §11 A11y Anti-Patterns → CI).
- NEVER write SGR into a machine channel: the MCP stdout frames sit with `--json` under the no-SGR rule (per a11y-plan §11 A11y Anti-Patterns → Visual).

## Contract bindings
- a11y ↔ tests: the P4 keyboard boundary (human key wins over a driver `send`) is held by tests' portable-pty outer-PTY cases; an MCP-originated `send` reaching the wrapper binds to the same harness and the `gate --require coverage,doctest` verdict (per a11y-plan §3 Keyboard test harness, §3 CI integration).
- a11y ↔ design: the `--help` group labels and fixed copy (design cli) are pinned by literal; a `viola mcp` verb's placement binds to design's served-verbs table (per a11y-plan §4 ARIA Patterns & Roles).
- a11y ↔ security: the `budget-paused` hint never naming `release` and `release` being a human verb is a security/conventions rule; a11y's stake is only that the driver bound never reaches the human (per a11y-plan §8 Cognitive Accessibility → Timeout extensions).

## Acceptance criteria contributions
- (a11y) A human key written while an MCP-issued `send` waits in the readiness gate (or while the budget gate is closed) reaches the child, the wheel moves to `human`, the MCP `send` result is the `human-typing` (or `budget-paused`) refusal with nothing typed, and the outer-PTY stream holds none of viola's own literals — or research shows the MCP path is the same wrapper `send` path the existing cases already hold (per a11y-plan §11 A11y Anti-Patterns → Keyboard).
- (a11y) `help_lists_only_served_verbs` and the `HELP` literal in `tests/cli_output_plain.rs` pass with `viola mcp` either listed under a labelled group by a deliberate literal update or held out of the table by a stated rule (per a11y-plan §8 Cognitive Accessibility → Plain language).
- (a11y) Every MCP tool call, `wait` included, returns within its in-server bound and that bound is the driver's only: no case shows a key blocked or delayed by it (per a11y-plan §8 Cognitive Accessibility → Timeout extensions).
- (a11y) No new `suite` enum value appears in the harness `run` JSON; any new case is a nextest failure surface inside `coverage` on all three OS legs (per a11y-plan §9 CI Integration).
