# a11y extract

## Relevance
partial. The chunk has no UI and builds no a11y surface: Playwright, the a11y lint stage and the browser job are all deferred to Epoch 8 by the scope's Boundaries. Three things still touch a11y: the new `gate` verb parses `playwright` artifacts, the CLI output-discipline assertions run inside the nextest runs this chunk restructures, and the zero-retry rule is a shared invariant.

## Constraints
- For the `playwright` suite, the `gate` verb must fail on four breaches: `suite-failed`, `suite-skipped`, `suite-missing` and `artifact-missing`. Skips are never allowed (per a11y-plan §10 Build / deploy failure conditions; §3 CI integration → Command; §1 A11y assertion harness specification → CI integration "Gate"). This chunk builds `gate` to parse playwright artifacts per test-plan §10 even though no job requires `playwright` yet. Those semantics must hold when Epoch 8 wires it.
- The harness `suite` enum stays closed. Adding a value such as `a11y` needs a Decisions Log entry (per a11y-plan §1 CI integration "No new suite"; §9 Pipeline integration; D-A11Y-14 "adds no harness `suite`"). If this chunk adds suite names such as `coverage`, `doctest` or `fuzz-replay`, none of them may be an a11y suite. Whether a11y results stay inside `playwright` is Epoch 8's concern, but `gate` must not assume a separate a11y suite.
- The a11y plan requires the CLI output-discipline invariants (P4, P6) to pass on all three OS legs inside `nextest-integration` / `nextest-e2e` (per a11y-plan §10 Standard+ invariants; §9 Per-pipeline-stage table, Unit / integration row, consumer `gate`). Scope item 3 replaces the separate unit / integration / e2e nextest runs with one instrumented `--coverage` run. The CLI a11y assertions (assert_cmd / trycmd / portable-pty SGR and TUI-boundary checks) must still run on windows, macos and ubuntu under that run. Research must answer two questions: whether the single `coverage` suite still reports them, and whether any a11y-bound artifact or suite name (`nextest-integration` / `nextest-e2e`) changes meaning.
- The coverage ignore regex excludes `crates/viola-e2e` and `tests/support` from the coverage number only. The a11y plan puts CLI a11y output-discipline evidence in crate and integration tests (per a11y-plan §1 cli surface → Automated tool reach; §10 Standard+ "under the tests' mutation gate where they live in crate tests"). Excluding files from the coverage number must not stop those tests from running.
- Zero retries and no parking. The a11y zero-violation invariant is declared parallel to the tests' `retries: 0` and its ban on `test.skip` / `#[ignore]` (per a11y-plan §10 Cross-input parallel; §10 Always-required invariant, Playwright `retries: 0`). Scope item 5's retry check is the Rust-side half. The Playwright `retries: 0` half has no subject until Epoch 8, and it must not be implemented or relaxed here.
- `nightly.yml` carries no a11y step, and the E2E/a11y leg stays in the push/PR `ci.yml` (per a11y-plan §9 Platform, as amended). The nightly fuzz time-box (scope item 4) must not add an a11y step to `nightly.yml`.
- New CI steps follow the same discipline the a11y plan relies on: SHA-pinned `uses:` per zizmor, and `actions/upload-artifact` v7.0.1 SHA-pinned (per a11y-plan §9 Artifact retention; §3 CI integration → Artifact). A `concurrency:` decision (scope item 7) must not cancel the future ubuntu `if: always()` aggregation or upload steps that a11y needs (per a11y-plan §9 Aggregation row).

## Patterns to follow
- Gate as the last step of each job, with exactly that job's suites. This matches the a11y plan's shape: `run --browser` followed by `gate --require playwright` (per a11y-plan §3 CI integration → Command; §9 E2E row).
- Post-gate steps run with `if: always()`, so they still report after `gate` has failed the job (per a11y-plan §9 Aggregation row; §3 Bootstrap phases → a11y-ci-gate-wire). Use the same pattern for any upload or report step this chunk adds after `gate`.
- The verdict is binary, with no fingerprint baseline and no soft SLO (per a11y-plan §10 Standard+ "Zero new violations per PR"; §11 SLO). This matches the scope's rule that no gate is weakened: no floor lowered, no regex widened.
- `gate` reads artifacts from the run JSON `suites[{suite,passed,failed,skipped,artifact}]`, with failures in `suites[].failures[]` (per a11y-plan §1 CI integration "Where results land"; §9 E2E row). The `gate` parser should read this same shape.

## Anti-patterns to avoid
- NEVER use a retry-once policy or soft SLO, and never park a test with `test.skip` / `test.fixme` / `#[ignore]` / a quarantine tag (per a11y-plan §11 SLO).
- NEVER add a `suite` value such as `a11y`, a `webServer`, or a separate `npm test:a11y` driver outside `scripts/agent-run.* run --browser` (per a11y-plan §11 CI).
- NEVER treat `browser-missing` as a skip (per a11y-plan §11 CI). If `gate` parses playwright artifacts now, a missing or skipped playwright suite must surface as a breach, never as a pass.

## Contract bindings
- a11y ↔ tests §9 / §10 (harness `gate`): `gate --require playwright` breach semantics (`suite-failed` / `suite-skipped` / `suite-missing` / `artifact-missing`) are an a11y build-failure condition (a11y-plan §10). This chunk defines `gate`'s parsing of playwright artifacts, and Epoch 8 consumes it unchanged ("`gate --require playwright` is unchanged", a11y-plan §3 Bootstrap phases → a11y-ci-gate-wire).
- a11y ↔ tests nextest suites: the CLI output-discipline evidence lives in `nextest-integration` / `nextest-e2e` on all three OS legs (a11y-plan §9 Unit / integration row; §10 Standard+). The chunk's switch to one instrumented `coverage` run changes where that evidence is reported.
- a11y ↔ obs: none new in this chunk. The `a11y-violation` rows remain harness-only, validated by the tests-owned `e2e-web/schemas/a11y-row.v1.json` (a11y-plan §3 Structured violation JSON schema; D-A11Y-09). `gate` has no reason to validate them against `diag-line.v1.json`.

## Acceptance criteria contributions
- `viola-harness gate --require playwright`, given a run JSON whose `playwright` entry has `skipped > 0`, whose entry is absent, or whose artifact file is missing, exits non-zero with the matching breach. A test fixture covers each case even though no CI job requires `playwright` yet (per a11y-plan §10 Build / deploy failure conditions).
- After the per-OS `test` job switches to the single instrumented `--coverage` nextest run, the CLI output-discipline tests (SGR / `NO_COLOR` / `TERM=dumb` / `--json`, TUI boundary) are still executed and counted on windows-2025, macos-latest and ubuntu-latest (per a11y-plan §10 Standard+ invariants; §9 Unit / integration row).
- No suite value named `a11y` (or any a11y-specific suite) appears in `gate`'s accepted `--require` set or in the run JSON enum (per a11y-plan §11 CI; §9 Pipeline integration).
- `nightly.yml` has no a11y, Playwright or `run --browser` step after this chunk (per a11y-plan §9 Platform, amended).
