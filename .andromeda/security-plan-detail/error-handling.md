## Error Handling

<!-- detail: values · errors -->

- `hook` never writes to stderr and never exits non-zero (Hook Contract). A security check failing in `hook` (server verification mismatch, oversized stdin, strict-modes failure) still ends in exit 0 with no body, so the dialog renders for the human. As landed, `viola hook <event>` runs the stdin cap, the `VIOLA_NAME` / `VIOLA_DIR` shape checks and the one-object parse and, on Linux and Windows, the server verification (macOS the recorded gap), and fails open with `hook-decision` detail `oversize-stdin` · `malformed-json` · `channel-unreachable` · `server-verify-failed`; strict-modes is owed to "Home and code-bearing file integrity" (Decisions Log `2026-09-28`). Its hidden `--capture <DIR>` arm runs the stdin cap, the absolute, existing `<DIR>` check and the exclusive `create_private_new` claim, and writes the capture raw; with `--answers <DIR>` it also runs the `take(64)` closed-`ProbeAnswer` read and `probe_body`'s payload shape check, and prints one `decision_body` body to stdout only for a mapped answer. Its statusline form `hook statusline --capture <DIR> [--shell <WORD>]` runs the same stdin cap and `<DIR>` check and claim, writes the payload raw and the closed shell verdict, and prints nothing on any path. On every failure it prints nothing, its stderr is always empty, and it exits 0 (Decisions Log `2026-09-28`, capture arm; the founder's live ruling of 2026-10-05 on `--answers`; the founder's own answer to P4 fork 3 of chunk 2026-10-13-owed-ledger-rows («Run B + --settings», relayed verbatim by the operator, that chunk's `inputs#I1`), on the statusline form).
- A `viola hook` event or dialog whose server check fails writes no frame and exits 0 with empty streams; its `hook-decision` line carries `server-verify-failed` (on the dialog path after `hook-invoked{corr:null}`, with `decision_emitted:false`), and a SessionEnd whose check fails is appended through the direct `append_session_end`.
- A `viola mcp` frame tool (`send` · `wait` · `last` · `answer`) whose server check fails (the connected peer is not the recorded wrapper, or the check cannot be made) sends no frame and returns the result of an unreachable instance: `isError` `instance-unreachable` with `detail: null`, text `refused: instance-unreachable`; it adds no error word and writes no log line.
