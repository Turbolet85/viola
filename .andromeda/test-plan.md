# Test Plan — viola

_Generated by `/andromeda-tests`. This file is the single source of truth
for all test strategy + harness contracts + quality gates. Read by
downstream skills (obs / a11y / route / setup-project per D26 cross-
cutting) and the phase loop per chunk (`/andromeda-phase` distillers + `/andromeda-implement`)._

_Do not edit during phase loop runs (`/andromeda-phase` / `/andromeda-implement`).
Manual edits between runs are fine._

_**Agent-driven invariant:** every test layer described in this plan must
be runnable end-to-end by an agent reading exit codes and structured
output. No human-in-the-loop checkpoints, no manual verification, no
visual regression with human review. If a surface cannot be agent-driven,
it is flagged "untestable" in test-scope.md Section 1 and handled via
boundary tests / mocks._

**Surfaces under test:**

- **Surface:** cli (`viola` verbs) — driven as a subprocess by `assert_cmd` with a per-test `--home` and `--json`; its signal is the exit code plus one JSON document on stdout, human mode checked by line match with no SGR under non-TTY / `NO_COLOR` / `TERM=dumb`; the TTY rendering goes through the outer-PTY driver, never by inspecting the child agent's screen.

- **Surface:** cli (the `viola hook <event>` and `viola hook statusline` exec-form entry points, invoked by Claude Code or the fake agent)
  - **Driver:** subprocess + `assert_cmd` feeding recorded hook payloads from `fixtures/claude/<cli-version>/` on stdin, with and without `VIOLA_NAME` / `VIOLA_DIR`
  - **Signal:** exit code is always 0. stderr is always empty. stdout is either empty (no decision / async hooks) or exactly the PreToolUse / PermissionRequest decision body. Side effects are checked as a matching `events.ndjson` line, a hook trace under `diagnostics/`, and `budget.json` contents for statusline.
  - **Boundary:** cross-surface (hook → IPC `hook.dialog` / `hook.event` → wrapper → disk)
  - **Notes:** traced to arch excerpt, Hooks and security excerpt, Vector 4. Deadline checks apply: spine hooks within the spine deadline, SessionEnd ~1 s.

- **Surface:** tui (`viola run` terminal passthrough, the human's side of the PTY) — driven by an outer-PTY driver that writes keystrokes and bracketed pastes and resizes; its signal is `events.ndjson`, the fake agent's receipt and exit detection on the process handle; assertions never parse the rendered child screen for content, and the readiness gate is tested through its refusal outputs.

- **Surface:** ipc-internal (the wrapper channel, JSON-RPC 2.0 over ndjson) — driven by a language-native IPC client with JSON schema assertion; its signal is the success, refusal or protocol-error payload, cross-checked against the `events.ndjson` cursor; cross-user peer rejection is flagged in section 1.

- **Surface:** ipc-internal (MCP stdio server `viola mcp`) — driven by a language-native MCP stdio client with JSON schema assertion; its signal is the tool result (`isError` with the `ok` payload, a refusal or a coded error); `tools/list` is exactly the five tools, never `release` / `pause` / `link` / `unlink`, and negative inputs must violate the advertised schema, which is advisory.

- **Surface:** library-only (workspace crates `viola-core`, `viola-pty`, `viola-channel`, `viola-state`, `viola-agent-claude`, `viola-mcp` at the unit level)
  - **Driver:** language-native test runner only (`cargo test` per crate / workspace)
  - **Signal:** process exit code plus libtest per-test result lines
  - **Boundary:** single-surface
  - **Notes:** traced to arch excerpt, Workspace / Modules and Test-Relevant Conventions. The arch registers exactly one test-only member, `crates/viola-e2e` (`publish = false`), and lists every test artifact in its §Project directory structure. These tests run on all three CI OSes.

**Test harness requirements:**

Inherited pattern: arch excerpt, Test Harness Commitment ("Development Style: agent-driven") with harness design deferred to tests. Binding founder direction: creator excerpt, Founder Directions 2 and 3: "the fake agent + `viola verify` fixtures are the contract"; "Structured JSON logs from every process (run/hook/mcp/ui) … a `logs` command in the harness, hook trace in diagnostics/".

- **5-command requirements:** `boot` builds `viola` and starts the wrappers in a fresh home to readiness; `run` runs the unit and integration tests, the fake-agent E2E and, only under `run --mutants`, mutation testing, exiting 0 only if every suite passes and no mutant survives; `status` queries `viola list --json`; `cleanup` stops every wrapper and deletes the home, idempotently; `logs` prints the per-process logs as JSON lines. `viola verify` against the real CLI is local-only, never in CI.

- **Status endpoint shape:**
  - `viola list --json`: `{"v":1,"ok":{items:[{name, wrapped, liveness:"live"|"stale", status:"idle"|"busy"|"unknown", wheel?:"human"|"driver", budget_paused?, dialog_pending, cli_version?, cli_verified?}], budget:{five_hour:{used_percentage,resets_at}, seven_day:{…}, read_at, paused}|"unknown", skipped:{unknown_kinds, unknown_fields, torn_lines}}}`. Its items are read at `.ok.items` (arch: `list` `ok` payload; CLI `--json` mirrors the channel `result`).
  - Source: arch excerpt, CLI.
- **Log format:**
  - Events: JSON-per-line ndjson `{"v":1,"ts","instance","kind","source":"hook|wrapper|cli","data"}` (arch excerpt, Event line).
  - Process logs: structured JSON lines per Founder Direction 3, parseable with `jq`.
  - Logs must never contain the `Cookie` header or stripped `CLAUDE*` values (security excerpt, Error-sanitization).
- **PID file location:**
  - There is no standalone pid file. The wrapper `pid`, `started_at` and `child_pid` live in `<home>/instances/<name>/snapshot.json`, with liveness in `<home>/instances/<name>/heartbeat` (touched every 1 s): when pid + start time no longer name a running process the instance is `gone` whatever the beat's age; otherwise a beat at most 5 s old is `live`, and an older or absent one `stale`.
  - Source: arch excerpt, Instance snapshot / Other files.

- **Test data strategy:** self-bootstrapping per test in a fresh `--home`: the fake agent is the child and replays recorded fixtures, `budget.json` is seeded through `viola hook statusline`, stamps come from running `viola verify` against the fake agent, and property / fuzz generators cover the parser surfaces; fixtures never come from real prompts and are checked for absolute paths and usernames, and no state is developer-seeded.

**Critical paths:**

- **Path:** `run` start sequence — the collision check, pinned copy and plugin folder, the fail-open ConPTY sideload, version gate, exclusive endpoint bind, first snapshot and heartbeat, and the start `wheel` and `budget-gate` events all precede the child spawn; a second `run` of the same name, a squatted endpoint or a tampered pinned exe exits 1.

- **Path:** confirmed `send` with CL-1 events — a driver `send` logs `send-issued`, writes one bracketed paste + Enter of the typed text (CR LF and CR as LF, trailing CR and LF dropped) and is confirmed by the matching `prompt-submitted{origin:"driver"}`, else refused `not-delivered`/`no-prompt-submitted`; an empty typed text is refused `empty-text`; a ledger-listed local command is matched by exact equality and confirmed only by its post-condition or `unconfirmable`, never presumed delivered.

- **Path:** `wait` / `last` event-driven readback, including the §6 live flow (overseer sends to builder, waits for `Stop`). `wait` wakes only on `turn-ended` / `question` / `permission` / `plan` / `session-end` / `dialog-expired` (the six of `EventKind::WAIT_WAKE`), returns at once if the event is already logged at or after `after`, and times out with `{timed_out:true}`.
  - **Surfaces involved:** cli + ipc-internal (channel + MCP `wait` / `last`)
  - **Verification signal:**
    - `wait --after <cursor> --json` returns the `turn-ended` event with its `cursor` after the fake agent fires Stop.
    - `activity` / `wheel` lines do not wake it.
    - `last` returns `{last_assistant_message, ts}` from the newest `turn-ended`.
    - Killing the wrapper mid-wait gives exit 21 / MCP `instance-unreachable`.
  - **Source:** arch excerpt, Critical paths hint 3; creator excerpt, S5 and §6 first live test
- **Path:** dialog → `answer` (question / permission / plan). The hook raises `hook.dialog`, exactly one dialog is pending per instance, and the driver answers by `dialog_id`. The hook emits the correct decision body: PreToolUse `allow` + `updatedInput.answers` (incl. `annotations`); PermissionRequest `allow` / `deny`; plan approve via PreToolUse only, revise via PermissionRequest `deny` + `message`.
  - **Surfaces involved:** cli (`hook` + `answer`) + ipc-internal (channel `hook.dialog` / `answer`, MCP `answer`)
  - **Verification signal:**
    - The `question` / `permission` / `plan` event is logged exactly once with a `dialog_id`.
    - `wait` returns it at once.
    - Hook stdout equals the exact decision JSON, exit 0, stderr empty.
    - A second concurrent dialog gets a `null` response.
    - An unknown `dialog_id` yields exit 13 `unknown-dialog`.
  - **Source:** arch excerpt, Critical paths hint 4 and Hooks; creator excerpt, S3/S7/S8

- **Path:** human takes the wheel, automation is refused, `release` returns it — a human editing key since the last turn boundary moves the wheel to the human, a driver `send` is refused `human-typing`, `pause` forces it manually, and the wheel returns only via CLI `viola release`, never through a `release` carrying `from`; a harness-injected turn does not flip the wheel, and the human is never blocked.

- **Path:** budget governor — `viola hook statusline` writes `rate_limits` to `budget.json` (only when the payload holds a `rate_limits` object) and passes the user's statusline through unchanged on Unix; crossing `five_hour` ≥ 90 % or `seven_day` ≥ 85 % refuses automated `send` with `budget-paused`, and `release --budget` overrides it.

- **Path:** unverified CLI version gate. On a version not in the ledger stamps, viola still types, runs the wheel and emits events, but withholds dialog answers, and drivers get `unverified-cli`.
  - **Surfaces involved:** tui (fake agent reporting an unlisted `--version`) + cli (`hook`, `answer`) + ipc-internal
  - **Verification signal:**
    - `send` still confirms (exit 0).
    - `hook.dialog` returns `null` at once, so hook stdout is empty.
    - `answer` exits 12. MCP `answer` gives `isError:true` `"refused: unverified-cli"`.
    - `viola verify` against a stamped fixture version ends `stamped <ver>  <n> pass  0 fail`.
  - **Source:** arch excerpt, Critical paths hint 7; security excerpt, Vector 4 ("A non-null dialog decision needs a `viola verify` stamp")

Covered by E2E suite expansion in Phase 3 if needed (beyond the 7):
- R5: unwrapped session hooks are a silent no-op.
- R8: the `CLAUDE*` env strip.
- `link` / `unlink`.
- Snapshot corruption → replay recovery.

## 3. Test Harness Contract

Architecture committed to the harness pattern (verbatim from
upstream-context arch Test Harness Commitment): "- Development Style: agent-driven." This section specifies
the concrete contract.

**Harness implementation:** `scripts/agent-run.sh` (POSIX) and `scripts/agent-run.ps1` (PowerShell) are identical thin shims. They run `cargo run -q -p viola-e2e --bin viola-harness -- <command> [flags]` and forward its exit code and stdout unchanged. All logic lives once, in Rust, so both shells have byte-identical semantics on all 3 OSes.

- **Session record:** each harness session writes `target/agent-run/<session>/session.json` with `{v, session, home, instances:[{name, wrapper_pid, started_at, fake_args}], supervisor_pid, supervisor_started_at, agents_mode}`; `agents_mode` (`recorded` · `oversize` · `malformed`, serde default `recorded`, by chunk 2026-10-17-end-to-end-path-binary-and-harness-legs) is written by `boot` and stands in `supervise.json` too. `viola-e2e` holds no `deny_unknown_fields`, so an older record carrying `ui` and `cookie_file`, or lacking `agents_mode`, still parses. The default session is `default`, and `--session <id>` allows parallel sessions.

Each prints exactly one JSON document on stdout, starting `{"v":1,"cmd":"<command>","ok":<bool>,…}` (key order held by serde_json `preserve_order`). A usage error carries `reason:"usage"` and a `detail` from `invalid-session-id`, `session-exists`, `invalid-instance`, `arguments`, `no-supervise-spec` and `unknown-suite` (a `gate --require` value outside the eight suites of `gate::SUITES`: `nextest-unit · nextest-integration · doctest · nextest-e2e · mutants · coverage · perf · fuzz-replay`). The grammar grows per chunk: a flag or selector whose surface is not built yet is a usage error until its chunk lands, never a vacuous pass (`run --e2e`, the example this clause named, is built since chunk 2026-10-17-end-to-end-path-binary-and-harness-legs).

## 4. Unit Test Strategy

Detail: .andromeda/test-plan-detail/unit-test-strategy.md — read whole.

**Framework:** cargo test (libtest, current Rust stable pinned in `rust-toolchain.toml`, ≥ 1.96; MSRV 1.96, edition 2024), executed through cargo-nextest 0.9.146 (process-per-test, JUnit). Doctests run through `cargo test --workspace --doc`, because nextest cannot run them.
**Coverage tool:** cargo-llvm-cov 0.9.1 (`cargo llvm-cov nextest`, LCOV + JSON summary).
**Coverage target:** see Section 10 Quality Gates for tier-specific
threshold.

**Conventions** (from upstream-context Test-Relevant Conventions and the Rust stack defaults):
- Test file location: inline `#[cfg(test)] mod tests` in the same source file, in every `crates/viola-<area>` and in root `src/`.
- Test function naming: `<subject>_<condition>_<expected>` in snake_case.
- Test grouping: flat modules per source file. Table-driven cases use rstest `#[case]`, and each case name must be a readable label (for example `#[case::esc_refused]`). The one exception is `viola-e2e`, which carries no `[dev-dependencies]`: its table-driven cases are a labelled case table (an array of `(label, …)` rows in one `#[test]`, each assertion naming its label), so no manifest edge is added for rstest alone. `viola-core` carries no rstest dev-dependency either, and its table-driven cases are literal tables in one `#[test]` (for example `dialog_hold_takes_whole_seconds_from_sixty_to_thirty_six_hundred`).

**Fixture pattern at unit level:**
- rstest 0.27.0 `#[fixture]` for shared constructors, for example a `TempHome` or a `Clock`.
- `#[rstest] #[case(...)]` tables for the refusal-order and exit-code matrices.
- `#[files("fixtures/claude/*/*.json")]` generates one test per recorded hook payload.
- proptest 1.11.0 `proptest!` blocks at `cases: 512` for parser invariants.
- insta 1.48.0 `assert_json_snapshot!` with redactions (`.dialog_id`, `.ts`) for decision bodies.

**What unit tests cover:**
- **viola-core:**
  - `RefusalReason` serde round-trip in kebab-case, including the `#[serde(other)] unknown` fallback.
  - `ViolaName` accepts `[a-z0-9-]` and rejects `../x`, uppercase, `/` and empty.
  - `Percent` accepts 0–100 and rejects 101 and negatives.
  - `DialogHold` accepts whole seconds 60–3600 and rejects 0, 59, 3601 and `u16::MAX`, its `Default` the 60 s `DIALOG_HOLD_DEFAULT` (`dialog_hold_takes_whole_seconds_from_sixty_to_thirty_six_hundred`, `dialog_hold_bounds_are_sixty_and_thirty_six_hundred_seconds`); `EventKind::ALL` holds 16 kinds and `WAIT_WAKE` 6 (chunk 2026-10-19-dialog-hold-for-the-driver).
  - `v` constants.
  - `validate_paste_text`: LF/CR/TAB and multi-byte UTF-8 accepted; ESC, other C0, DEL and U+0080–U+009F refused with `control-character`. The check runs on decoded `char`s, and a proptest property shows UTF-8 continuation bytes never trip it.
- **viola-pty:** exit is reported from `wait()` on the handle, never from reader EOF. Consumers are tested with a `mockall` double of the six-method seam whose reader never returns EOF while `wait()` returns an exit status. The `TerminateProcess` fallback path is `#[cfg(windows)]`.

- **viola-channel:** the ndjson frame codec at the `MAX_FRAME` boundary, the JSON-RPC error mapping, the FNV-1a endpoint golden vectors, the peer-credential decision with injected euids, the connected stream's server pid on each OS, and Windows handle non-inheritance.

- **viola-state:** the one-`write`-per-line writer, the reader's three skip counts (it counts and never panics), the appender's heal, the snapshot envelope's classified read and the replay, the pure liveness classifier fed ages directly (no clock), the pure server verdict's decision table, Unix strict-modes and Windows strict-modes over synthetic SDDL descriptors, and the instance check.

- **viola-agent-claude:** hook payload parsing per recorded fixture set (unknown fields counted, not fatal), the insta-pinned dialog mapping, the R8 strip against a literal copy of the identity floor (never imported), npm-shim resolution, the version gate, the statusline and `claude agents --json` parsers, `prompt-submitted` normalisation, the `typed_text` rule, the ledger rows' arms and the screen signatures; content beyond the compiled literals is never asserted.

- **viola-mcp:** handler re-validation:
  - a non-`ViolaName` `target`, a non-`u64` `dialog_id`, an open-string `behavior` and control chars in `text` all give `isError:true` with code-only payloads
  - `tools/list` is exactly `send, wait, last, answer, list`

- **root bin:** the exit-code mapping (an unknown refusal maps to exit 14, never a panic and never 20), the wheel state machine, the budget governor's pure decision and override expiry, the send-confirmation matcher and the local-command decision, the clock-driven `wait` handler, the `send` and `answer` refusal ordering, the server check refused inside each frame verb's and the hook's span with each closed unreachable cause logged, human-mode C0/C1 escaping, and the clock-driven dialog hold.

- Pure functions
- Module logic with mocked dependencies (mockall doubles only for traits the product already defines at its seams: `Pty`, liveness probe, `Clock`)
- Edge cases + invariant assertions (proptest properties listed in §6 Property suite)

**What unit tests do NOT cover** (handled at higher levels):
- Integration boundaries (Section 5)
- E2E flows (Section 6)
- External services, mocked at unit level. For viola these are the real `claude` CLI and Anthropic usage values. They are untestable in CI (test-scope Sec 1) and covered by local `viola verify` only.

## 5. Integration Test Strategy

Detail: .andromeda/test-plan-detail/integration-test-strategy.md — read whole.

**Driver(s):**

- **Disk:** a real tempfile 3.27.0 filesystem.
- **Windows DACL read-back:** windows-sys 0.61.2.

**Boundary types covered:**

- **Module ↔ module:** direct calls across crate APIs with shared rstest fixtures.

- **Module ↔ DB:** there is no database; module ↔ on-disk state is tested instead over real ndjson, snapshots and `.lock` siblings in a tempfile home, with a concurrent-append check that every line of every shared diagnostics file parses as one JSON object.

- **Module ↔ external API:** no outbound HTTP exists; the only external boundary is child processes, served by `viola-fake-agent` as `claude` on a test-scoped `PATH` and by a fixture npm shim.

- **Module ↔ IPC:** a real endpoint bound in a temp home with frames validated by jsonschema, the squatter created first through the server API (never `try_overwrite`), and the Unix socket modes and the Windows pipe DACL read back — the DACL compared in its canonical form, never the literal it set.

- **Hook exec ↔ channel ↔ disk:** `viola hook <event>` fed fixture stdin against a live test wrapper, its event line, hook trace and `budget.json` asserted.

**Setup / teardown lifecycle:** a fresh tempfile home per test, at a not-yet-existing path under `target/e2e-home` that viola creates, so obs-plan's CI gates, the secret scan and the upload cover integration runs; started wrappers sit in a `Drop` guard that kills and waits, and nothing is shared between tests. Two carve-outs: Windows x64 starts seed the ConPTY companions before viola runs, and `tests/chaos_feed_panic.rs` alone boots outside the scans.

**Readiness stall report:** at its deadline `wait_ready` appends the stalled wrapper's state to the watch report before the panic; it signals nothing and adds nothing to a passing boot.

**DA1 answer:** under the sideloaded ConPTY the piped test driver answers a DA1 query as a terminal would; viola sends no DA1 answer of its own.

**Cross-module patterns covered (per arch Standard Contract):**

- **Wrapper channel:** every method through the crate and root channel suites, with schema-validated result, refusal and error shapes, the `cursor` equal to the log length at acceptance, `-32602` on a higher `v`, `-32600` and a close on an oversize frame, server verification, and wrapper-side paste validation in which `control-character` wins over every other refusal.

- **On-disk:** every event kind round-trips the event line, `ts` is RFC 3339 UTC with ms, tailing ignores symlinks and invalid names, and strict-modes refusals give exit 1 for `run` / `mcp` / `viola revive`, hook 0 with no output, and CLI 21 for every other verb.

- **Hooks:** root `tests/hook_*.rs` checks every event name in the arch Hooks list:
  - exit 0 and empty stderr
  - decision body or empty stdout
  - async hooks print nothing
  - no `VIOLA_NAME` means an immediate exit 0

- **CLI:** root `tests/cli_*.rs` cover the `--json` document per exit code, the human layouts by trycmd or literal with no `\x1b[` under non-TTY / `NO_COLOR` / `TERM=dumb`, `viola verify`'s step lines and its stop cleanup, `plugin install`, leading-slash argv never delivered as a prompt, no setting that disables a control, and the home resolution order and machine contract; `contract_ledger_probes.rs` holds the ledger-probe contract per stamped fixture set.

- **MCP:** adapter-level handler tests in `crates/viola-mcp/tests/handlers.rs` drive the transport-free `viola_mcp::Tools` handle (the same `Server::call` `serve` answers with) against a `viola_channel::Server` test wrapper (`TestWrapper`, its snapshot written through `viola_state::snapshot::write_snapshot`); the handlers under test use the Tokio client (`viola_channel::tokio_client::TokioClient`, `viola-channel`'s `tokio` feature), never the sync client (chunk 2026-10-17-mcp-server-for-drivers). ## 6. E2E Test Strategy

Detail: .andromeda/test-plan-detail/e2e-test-strategy.md — read whole.

**Drivers per surface** (from research Per-Surface Driver category):

- **cli (verbs + `--json`):** assert_cmd with predicates, and trycmd or literals for human layouts; TTY rendering is asserted only on the SGR sequences in verb output under the outer PTY, never on the child agent's screen.

- **cli (`viola hook` / `hook statusline`):** assert_cmd with an `Instant` deadline over recorded fixture stdin; `.env_clear()` must re-add `LLVM_PROFILE_FILE`.

- **tui (`viola run` passthrough):** a portable-pty outer PTY over the `viola-pty` seam; exit only via `child.wait()`, the master reader drained on its own thread, verdicts from `events.ndjson`, the receipt and the exit status.

- **ipc-internal (MCP stdio):** an rmcp client over a `viola mcp` child the test spawns and owns, closing its stdin and awaiting its exit, never rmcp's `TokioChildProcess`; beside it, a replay of the recorded MCP exchange.

- Cross-OS-user peers. Covered by the peer-credential boundary unit test (§4) and same-user SDDL read-back (§5).

- **As landed: in part.** The replay's product readers (`viola revive`, `viola list`), its budget and link legs and its `list --json` leg are covered; steps 1–3 stay unbuilt while `run`'s collision check calls `read_snapshot`: every snapshot reader stays on `read_snapshot` (option 1), and their move onto `read_snapshot_or_replay` stays a CARRY owed to the route entry "Home and code-bearing file integrity".

- Two of the signals above are set against what landed, for the entry that builds it to restate: every start appends `wheel{holder:"driver", cause:"start"}`, so `wheel:"human"` does not hold after step 3, and the replay writes no file, so no snapshot is rebuilt from it.

- **Cleanup:** TempDir drop.

**Non-path suites (trigger coverage; run in the E2E layer, except root `hook_*` files such as `hook_fail_open.rs`, which the §3 layer filtersets run in the integration layer):**

- **Security sweep:** nextest runs the MCP schema-violation cases (each `invalid-params` with its field, no frame written) and the hook fail-open matrix — oversize stdin, malformed JSON, clap error, channel failure, a forced panic, a missing `VIOLA_NAME` and, on Linux and Windows, a server that is not the recorded wrapper, each exit 0 with no body — plus the `--home` strict-modes refusals; the panic seam fires only under the `fake-agent` feature and never reaches the release build.

- **Error sanitization and secret scan:** after every E2E test, no absolute path, serde path or `Caused by` in any error payload, every `-32603` exactly `"internal error"` / `null`, no `Cookie` header or stripped-variable value in any log, `diagnostics/` files 0600 on Unix, and the fixed canary in no home-level diagnostics line; a hit is reported by place and class, never the matched bytes.

- **Schema conformance** (the check body behind obs-plan gate G4; obs owns the schemas, tests own the check): after the test steps, every home-level `diagnostics/*.ndjson` line under `target/e2e-home/**` is validated with jsonschema 0.57.0 against obs-plan's `schemas/diag-line.v1.json`, and every `instances/*/diagnostics/detail-*.ndjson` line against `schemas/diag-detail.v1.json`. A line that is not JSON is skipped and counted (chaos cases tear lines by design). Any failing line fails the step, which prints file, line number and the failing schema keyword, never the line's content.

- **Exit-cause matrix** (`cross_exit_causes.rs`, not built): one negative test per cause of exit 21 and of exit 1, each asserting the exit code, the `--json` document and a last `hint:` line that names its cause — a hint shared across causes fails the table; the server-verification cause is a case of `tests/security_negatives_server_identity.rs` on Linux and Windows (its macOS case owed to the route entry "Unix endpoint and home hardening"), and `revive`'s refusals are cases of `tests/cli_revive.rs`; driver-facing hints never contain `release`.

- **Security control negatives** (`security_negatives_*.rs`): one negative test per security-plan control that had none — the Unix socket directory refusal, Windows client SQOS at the identification level, the Windows listener rejecting remote clients and denying an anonymous open (each beside its controls), raw-channel `link` / `unlink` name validation, a Windows `--home` outside the profile given a protected DACL (its test home never under `%TEMP%`), umask-independent modes, single writers of `stamps.json` and `snapshot.json`, and, on Linux and Windows, a CLI frame verb writing no frame to a server that is not the recorded wrapper (`tests/security_negatives_server_identity.rs`, beside its control reaching the recorded wrapper).

- **`list` row integrity** (`cross_list_rows.rs`): unwrapped session names holding `\n`, `\t` or a C1 character print escaped in every mode — no row splits, every row's columns start at the caption row's offsets, the raw bytes never reach a NAME cell, and `list --json` keeps the original name.

- **Cross-surface parity:**
  - for the same refusal, the MCP `structured_content` `{refusal, detail}` equals the CLI `--json` `{refusal, detail}`

- **Chaos suite** (`chaos_*.rs`): a torn append counted and healed on a fresh line, a no-EOF child's exit detected on the handle, an endpoint vanishing during `wait` (exit 21), a SIGSTOPped wrapper read `stale` and its name refused to a new `run`, a forced vt100 panic refusing `send` `input-not-ready` while passthrough continues, forward-compat lines counted in `skipped`, and a `.cmd` child refused exit 1.

- **Property suite** (proptest, `cases: 512`): `validate_paste_text`, ndjson framing at `MAX_FRAME` ± 1, the hook stdin and statusline parsers, the `claude agents --json` parser, the vt100 feed under `catch_unwind` and `prompt-submitted` normalisation; cargo-fuzz targets in the separate `fuzz/` workspace join as their parsers land.

- **Contract suite** (`contract_*.rs`): for each recorded fixture set, walked at run time (an empty walk fails), the fake agent's hook sequence and payloads equal the recorded order and bytes, never an insta snapshot; the forwarded `annotations` are asserted; every fixture is checked against the tolerant parser schema; and the pinned-exe content hash is pinned to its library by literal vectors.

## 7. Test Data & Fixtures

Detail: .andromeda/test-plan-detail/test-data-fixtures.md — read whole.

**Fixture library:** rstest 0.27.0 (`#[fixture]`, `#[case]`, `#[files]`) + tempfile 3.27.0, plus proptest 1.11.0 strategies (proptest-derive 0.8.0) and insta 1.48.0 snapshots. Recorded `viola verify` spine fixtures, dialog variants and framing variants (`paste-<n>`, `compact-<n>`, `clear-<n>`), the MCP exchanges (`Mcp.<variant>.json`) recorded by the test-only `viola-mcp-tap`, and `2.1.287`'s superseded relayed dialog captures (`RELAYED.md`), live in `fixtures/claude/<cli-version>/`.

**Seed strategies:**

- **On-disk product state:** produced only by real `viola` runs against the fake agent in a fresh home, never hand-written — except the chaos tests' corruption of files the product already wrote, the Windows x64 `seed_conpty` companions and the server-identity impostors' test-built `snapshot.json`; a case that needs a home viola created starts from `stamped_home`.

- **`ledger/stamps.json`:** produced by `viola verify` against the fake agent; no test or harness code writes the file.

- **`budget.json`:** generated statusline stdin piped into `viola hook statusline` in every booted-wrapper test; the reader's own unit cases alter only bytes the writer wrote.

- **The statusline source:** written by the test, never by viola, which only reads it.

- **`claude agents --json` output:** `viola-fake-agent` placed as `claude` in a test-scoped bin dir, answering from files beside its exe with no env var; every test-started `list` / `revive` runs under a test-scoped `PATH`.

- **Recorded hook payloads:** checked-in `fixtures/claude/<cli-version>/<Event>.<variant>.json`, recorded locally by live `viola verify`, scrubbed and `unclean`-checked (a dirty payload refuses the whole recording), and replayed in CI.

- **Recorded MCP exchange:** checked-in `Mcp.<variant>.json`, recorded by the test-only `viola-mcp-tap` through the same scrub and refusal, schema-validated and replayed.

- **Human-mode expected output:** trycmd cases with snapbox redactions; `viola --help` and the `viola list` board are literals in their test files.

- **Decision bodies:** insta snapshots, regenerated only by the local fixture refresh.

- **Fake-agent hook transcripts:** no snapshot of their own; compared byte for byte against the recorded hook payloads.

- **Randomized data:** proptest strategies, their seeds persisted in committed `proptest-regressions/`.

- **Time-sensitive data:** injected per test behind `viola_core::Clock`; the budget gate's override expiry takes its instant as an argument, and `viola-mcp` owns no timer.

**Fake agent (`viola-fake-agent`, binding contract behaviour):**
- It answers `--version` in the real CLI's format for `--cli-version <ver>`.

- It reads the hook commands from the plugin dir `run` passes and runs every command entry for the event: an absolute `command` is spawned directly, never through a shell or a PATH lookup, and a non-absolute one is never run; the payload on stdin is the recorded fixture's bytes, save the fields a prompt, a resume or a compact replay sets; a status line command runs only when it is absolute.

- After `start_receipts` it fires SessionStart (variant `default`) once, silent without a registered hook or a fixture like every `fire`; this gives Path 1 its third record.
- It accepts bracketed pastes + Enter as one prompt and fires UserPromptSubmit (variant `default`) with that text; under `--framing` a compiled paste text of verify's Run B fires its recorded `paste-1` / `paste-2` / `paste-3` variant instead, its bytes unchanged, the probed `/clear` fires the recorded `clear-1` SessionEnd then SessionStart and no UserPromptSubmit, and the probed `/compact` fires the set's recorded `SessionStart.compact-1` with `session_id` set to the last SessionStart the agent fired (the launch one, or a replayed clear's; only a SessionStart whose fixture exists moves it) and no UserPromptSubmit; a set without the variant fires nothing for it (unit `fake_compact_replay_carries_the_last_fired_session_id`). Every byte typed outside a paste is a keystroke, and a CR submits what was typed.
- It follows a JSON turn script (`--script`) for PreToolUse, PermissionRequest, PostToolUse and Stop steps. Scenario scripts are checked in as `fixtures/fake-scripts/<scenario>.json` (for example `path3.json`, `path4.json`), contain synthetic text only, and are passed as `--instance <name>:--script fixtures/fake-scripts/<scenario>.json`. Boot step 5 and both `booted_wrapper` copies resolve a relative `--script` against `<workspace root>`, the same way as `--fixtures`. Each gated step waits for the next line the test appends to `--control <path>` (always `<home>/fake/<name>.control`; the fake agent reads it by byte offset). This gives deterministic ordering without sleeps.

- It writes ndjson receipt lines to `--receipt <path>`, one `write_all` per line, each `"v":1` with a kebab `kind` (`start`, `size`, `cwd`, `hold`, `env`, `fds`, `key`, `prompt`, `hook`, `statusline`, `step`); an `env` receipt holds names only, never a value.

- Scripts are `{"v":1,"steps":[{"event","variant","gate"}]}` over the nine registered hook events, validated by `schemas/fake-script.v1.json`. An unreadable script exits 2. A gated step waits for one more `\n`-terminated control line past the byte offset.

- Modes: `--suppress-prompt-submit`, `--local-command-mode`, `--inject-harness-turn`, `--exit-no-eof`, `--report-version <ver>` and print mode, plus argv options (no env) for the statusline tests, verify's interactive runs, the test-only holds and screen switches and `viola revive`'s `--resume` / `--fork-session`, two mode words (`statusline-echo`, `agents`), and unknown arguments ignored.

- It exits on `\x03` or at stdin EOF. Before it exits it waits for a hook still running and starts no other, and on Unix every command it spawns (each hook, and the status line command) runs in a process group of its own (`process_group(0)`, as the `--exit-no-eof` holder does): its PTY's foreground group is what a hangup of that terminal reaches, at the agent's exit as its session leader or when a killed wrapper closes the PTY, and a `viola hook` reached in its exit-time coverage write leaves a cut-short profile (as measured at `viola-0.1.0/chunks/2026-10-20-epoch-5-cleanup/evidence/profraw-cause.md`). The agent itself, its PTY's session leader, cannot leave that group (`setpgid` refuses a leader), so on Unix its exit ignores SIGHUP from its first step (`\x03` or stdin's end): a hangup that lands while it exits (a killed wrapper, or portable-pty's SIGHUP-first kill) no longer cuts its own exit-time coverage write, and one that lands before the exit begins still ends it (as measured on the Linux dev host at `viola-0.1.0/chunks/2026-10-26-server-verification-before-any-frame/evidence/fake-agent-exit-hangup.md`).

**Fixture hygiene:**
- One run-time directory walk (`claude_fixtures` in `tests/contract_fixture_hygiene.rs`, with its own walker test; it leaves the `Mcp.` exchanges out, which `mcp_fixtures` walks) does two checks per fixture — not an rstest `#[files(…)]` case, because rstest 0.27 refuses a glob that matches no file at compile time (`rstest_macros-0.27.0/src/parse/rstest/files.rs:635` "No file found", as measured at chunk 2026-09-28-capability-ledger-and-viola-verify):
  - it fails on absolute paths (`^[A-Za-z]:[\\/]`, `/home/`, `/Users/`, `\\Users\\`), on non-placeholder usernames (a `workspace.repo` naming this repository's own remote is kept in a fixture (the founder's own word, chunk 2026-10-13-owed-ledger-rows `inputs#I3`, relayed verbatim by the operator; worded by `inputs#I4`)), on an email-shaped token, and on a username split across a screen row seam
  - it validates the file with jsonschema
- The checker (`tests/support/hygiene.rs`) reports a violation class only (`absolute-path`, `username`, `schema`), never the offending content. Planted inputs prove each class red.

- Today the walk covers the committed fake scripts, every recorded `fixtures/claude/*/*.json` hook payload, status line, agents and MCP fixture, and the screen fixtures, each against its own schema with the same path, username and email walk; planted files prove each class red.

- The `viola verify` recorder must rewrite home paths to `~` and usernames to `<user>` in hook payloads and the status line variants before writing, and writes them only at 0 failing rows. A screen fixture keeps only the rows that hold a compiled signature literal (the rest `""`), and is checked scrub-as-detector: a kept row the scrub would rewrite refuses the recording whole, never written rewritten, as `unable: a recorded fixture is not clean: <file> row <n>[ seam] <code>` (codes `home-path` · `absolute-path` · `username` · `email`). The test-only `viola-mcp-tap fixture` applies the same scrub (the home → `~`, the user word → `<user>`) and refuses a dirty exchange whole with the same four codes, naming the file only.
- Fixture prompts are synthetic probe text only, never real prompts.
- A `workspace.repo` naming this repository's own remote is kept in a fixture (the founder's own word, chunk 2026-10-13-owed-ledger-rows `inputs#I3`, relayed verbatim by the operator; worded by `inputs#I4`): the `StatusLine` variants' `workspace.repo.owner`, the remote owner's handle, is neither rewritten by the scrub's whole-word OS-user rule nor refused by the hygiene walk. Nothing else in this rule widens.

**Self-bootstrapping requirement:**
- Tests MUST seed their own data; no developer pre-populates a home.
- The `boot` command creates the home, stamps it via `viola verify`, and starts the wrappers automatically.

**Test data lifecycle:**
- **Per-test:** isolated state. Each test has its own home, so there is no shared endpoint, log or `budget.json`. Env is set per child with `Command::env`, never `std::env::set_var`, which is `unsafe` in edition 2024.
- **Per-session:** `cleanup` removes the harness home, `session.json` and the supervisor.
- **CI:** an ephemeral runner per job. Homes live under the workspace's `target/e2e-home/` (all but the `viola-chaos-*` home of `tests/chaos_feed_panic.rs`, §5) and are kept (`AGENT_RUN_KEEP_HOMES=1`) until obs-plan's gate steps have run (G2, G4, the secret scan and the scan-gated uploads). The runner discards them with the job.

## 8. Mocking & Stubbing Discipline

Detail: .andromeda/test-plan-detail/mocking-stubbing-discipline.md — read whole.

**What to mock:**
- External HTTP APIs: none exist. viola makes no outbound HTTP calls, so no HTTP mock library is used.
- External services not under test: the real `claude` CLI is replaced by the native `viola-fake-agent` binary, both as the PTY child and as `claude` on a test-scoped PATH. Anthropic usage values are replaced by generated statusline stdin. These are fakes, never the real services.

- Time: sync crates use the injected `viola_core::Clock` (or mock_instant) for the heartbeat and the send confirmation window, `viola-mcp` uses tokio's paused clock for a timer it owns, and the budget gate's override expiry is a pure-function case; `chrono::Utc::now()` is read only through the clock seam, except at the budget gate's three evaluation points, and a paused clock in a test never reaches a spawned wrapper.

- Filesystem: not mocked. A real tempfile home is used everywhere, because modes, `File::lock`, torn lines and symlink handling are the behaviour under test. Only the Windows foreign-SID / non-persistent-ACL descriptors are stubbed, as synthetic SDDL descriptors fed to the check function.
- Random sources: proptest seeds are persisted.

**What NOT to mock:**
- Pure functions in modules under test (`validate_paste_text`, parsers, refusal ordering), which are tested directly.
- On-disk state at integration level (the arch has no DB). Use real files in a tempfile home.
- The wrapper channel, PTY, vt100 or serde in E2E. Code paths the agent must verify end-to-end go in E2E (§6).
- `viola hook` invocations inside E2E. The fake agent calls the real pinned binary.

**Mocking libraries (specific, from research):**

- **HTTP mocking:** none — viola makes no outbound HTTP calls.

- **Time mocking:** inject the `Clock` through constructors and advance it, or hand a pure decision its instant as an argument.

- **Process mocking:** mockall `automock` on seam traits only; external processes are real stub executables (`viola-fake-agent`).

- **Fake servers:** the interprocess server API binds the squatter before `run`, and `viola-fake-agent` is the fake CLI; no HTTP fake servers.

**Anti-monkey-patching:** prefer dependency injection over runtime patching of production code. Doubles exist only for traits viola already defines at its seams (research, mockall key detail).

(See `## 11. Test Anti-Patterns` § Mocking for mocking bans.)

## 9. CI Integration

Detail: .andromeda/test-plan-detail/ci-integration.md — read whole.

**Platform:** GitHub Actions (one `ci.yml` on push and PR, a scheduled `nightly.yml` for fuzz and weekly advisories, and the dispatch-only `windows-mutants.yml` for the boundary audit's Windows mutation leg). There is no deploy stage in v1.
**Caches:** rust-cache is the only cache, in `ci.yml` only; no caching action beyond rust-cache was researched.

**Pipeline structure:**

- **Lint:** fmt, clippy `-D warnings`, the tokio-free `cargo check` of each listed sync crate, the cargo-modules orphans gate with its probe, and the rmcp release-graph assertion, per OS; the `--acyclic` review and the dev-host Windows- and macOS-target check-only clippy runs are not gates.

- **Supply-chain:** one fail-closed ubuntu job runs cargo deny over the root and fuzz lockfiles, the sole-root tokio ban per sync crate with the channel's tree form, the deny probes and zizmor, uploading their JSON; a weekly nightly job re-runs the advisories.

- **Unit / Integration / E2E:** `agent-run run --unit`, `--integration` and `--e2e`, the local equivalents of CI's one instrumented coverage run.

- **Coverage report:** `agent-run run --coverage` is the per-OS test job, on `windows-2025` after the ConPTY vendor verification; its one instrumented nextest run replaces the unit, integration and E2E rows, and each job ends in `viola-harness gate --require <suites>`.

- **Mutation:** no push or pull-request job and no gate — mutation runs at the epoch boundary through `/andromeda-code-audit` and on demand through `run --mutants`; the audit's Windows leg, `windows-mutants.yml`, is dispatch-only and report-only.

- **Perf:** `agent-run run --perf` in its own per-OS job, its verdict from `viola-harness gate`, never from a `jq` binary.

- **MSRV:** an ubuntu job checks the workspace and runs the unit suite on Rust 1.96, the security toolchain floor.

- **Fuzz replay:** a corpus replay on push and PR, and a nightly time-boxed `cargo fuzz run` per target.

- **Release build:** `scripts/release-check.sh`, with its probe, judges a `--release` build of `viola` alone and fails on a test-only feature or binary; no upload and no gate step.

- **Quality gates:** `viola-harness gate` reads the JUnit, run-summary, coverage and hyperfine outputs and exits non-zero on any §10 breach.

Every workflow has `permissions: {}` at the top and `contents: read` per job, and every `uses:` is SHA-pinned, zizmor `unpinned-uses` the assertion; each tool has exactly one version source, ci.yml's pins, and the local pre-push gate checks the host's tools against them and installs nothing.

No workflow has a `concurrency:` block: a concurrency group cancels pending runs, which would drop a push's `always()` gate and upload chain; zizmor's `concurrency-limits` finding is declined and stays visible.

**Matrix builds** (from the multi-os-compat trigger):

- OS: `windows-2025` (ConPTY, named pipe, DACL / SDDL read-back, `.cmd` refusal), `macos-latest` (macOS 26 arm64: openpty, Unix socket, euid + dir-only server verification; pin `macos-26` if the label moves), `ubuntu-latest` (openpty, Unix socket, modes; also the deny, zizmor, fuzz and MSRV jobs). `fail-fast: false`.
- Language version: Rust 1.98.1 (current stable at 2026-09-24, ≥ the 1.96 floor), pinned exactly in `rust-toolchain.toml` and installed by `rustup toolchain install` on every OS, host included. Plus MSRV 1.96 (ubuntu check + unit).

**Test report format:** machine-parseable. Artifacts are uploaded with actions/upload-artifact v7.0.1:
- In the per-OS `test` job, every test artifact leaves CI only behind obs-plan §9's secret scan (`id: secret-scan`):
  - `target/agent-run/` minus `target/agent-run/chunk.diff` (`run --mutants`' diff, which the scan skips and the upload excludes), including `artifacts/` with the per-suite `junit-<suite>.xml`, `run-summary.json`, `llvm-cov-summary.json` (§3 `gate`) and the failure-only `logs.ndjson` / `status.json` capture: `harness-${{ matrix.os }}`, on failure with a passed scan (the `test` job does not run `--perf`, so no perf export lands here);
  - `target/e2e-home/**/diagnostics/*.ndjson`: `diag-${{ matrix.os }}`;
  - `target/nextest/ci/junit.xml`, the report of the job's single instrumented `run --coverage` nextest invocation: `junit-${{ matrix.os }}` (one path);
  - the hit report `target/secret-scan/`: `secret-scan-${{ matrix.os }}`, only when the scan failed.

  All use `retention-days: 7`. The per-suite JUnit copies stay in `artifacts/` because each nextest invocation overwrites the raw file.
- `mutants.out/` is never uploaded (no push or pull-request job runs mutation since 2026-09-28, and the dispatch-only `windows-mutants.yml` uploads nothing): its `outcomes.json` holds absolute argv paths and its `log/` holds test output.
- `target/lcov.info` and the llvm-cov JSON summary
- the `perf` job's uploads, all behind that job's own secret scan: `perf-${{ matrix.os }}` (`target/agent-run/artifacts/perf-*.json`, the hyperfine exports) and `diag-perf-${{ matrix.os }}` (`target/e2e-home/**/diagnostics/*.ndjson`) only when `always() && steps.secret-scan.outcome == 'success'`, and `secret-scan-perf-${{ matrix.os }}` only when the scan failed
- cargo-deny and zizmor JSON
- on failure, the secret-scanned homes' `diagnostics/` and `events.ndjson`

The agent reads job conclusions with `gh run view --json jobs` and fetches artifacts with `gh run download`. Locally the same files come from `agent-run run` and `agent-run logs`.

**Build failure conditions:**
- Any unit / integration / E2E / contract / property test fails (on any of the 3 OSes)
- Coverage falls below threshold (Section 10) on any OS
- A hyperfine budget breach, or a fuzz corpus replay crash
- Lint errors: fmt, clippy `-D warnings`, a sync crate listed in `scripts/sync-crates.txt` failing to build without tokio (or an empty list), a cargo-modules orphan in any lib/bin target (`scripts/orphans-check.sh` not ending `N/N targets clean`, or its probe not ending `2/2 fired, control clean`), `scripts/rmcp-features.sh` not ending `rmcp-features: server transport-io` (rmcp absent from `viola`'s release graph, or a feature beyond `server` + `transport-io` requested)

- Quality gate check fails

## 10. Quality Gates & Coverage Targets

Detail: .andromeda/test-plan-detail/quality-gates-coverage-targets.md — read whole.

**Coverage thresholds (per tier):**

| Tier | Line coverage | Branch coverage | Function coverage |
|------|---------------|-----------------|-------------------|
| Minimal | ≥ 60% | ≥ 50% | ≥ 70% |
| Standard | ≥ 75% | ≥ 70% | ≥ 85% |
| **Comprehensive (viola)** | **≥ 85%** | **≥ 80%** (enforced as region coverage `--fail-under-regions 80`) | **≥ 95%** |

Stack adjustments:
- Gates are enforced per OS job with `cargo llvm-cov nextest … --fail-under-lines 85 --fail-under-functions 95 --fail-under-regions 80`. Per-OS gating is deliberate: `#[cfg(windows)]` / `#[cfg(unix)]` code compiles only on its own runner.
- Coverage rolls up across all workspace crates.
- Excluded via the separator-agnostic `--ignore-filename-regex` `(viola-fake-agent|crates[/\\]viola-e2e|tests[/\\]support|fuzz[/\\])`, the harness const `COVERAGE_IGNORE`. llvm-cov reports Windows paths with `\`, so the forward-slash form never matched there (as measured at chunk 2026-09-24-quality-gates, research.md M5).

- Child `viola` processes spawned by E2E tests are included, because `LLVM_PROFILE_FILE` propagates; tests that call `env_clear()` must re-add it, the one deliberate exception being the harness self-tests' nested cargo over a throwaway crate, whose binaries write no profile into the outer run.

- Doctests are run but are not part of the coverage number.

**Mutation gate:** judged at the epoch boundary by `/andromeda-code-audit` and on demand by `run --mutants`, with no chunk, pre-push or CI mutation gate; the run's `outcomes.json` must show `missed == 0` (after the host-excluded records), `timeout == 0` and `unviable <= caught`, because a run whose mutant builds mostly failed is no evidence of test strength; a mutant this host cannot compile or reach is recorded as owed, never equivalent or caught.

**Performance budgets** (Comprehensive + performance-budget trigger):

The gate is on the `max` sample, because Claude Code hook deadlines are hard cutoffs. Mean, median and stddev from the hyperfine JSON are reported for trend only. No percentile is computed or gated.

Perf run rules (all inside `agent-run run --perf`):
- **Binary under test:** `--perf` first runs its own non-instrumented `cargo build --release --workspace --features viola/fake-agent --target-dir target/perf` (the spelling `boot`'s workspace build uses). It never reuses the debug `boot` build or a `cargo llvm-cov` build, and never runs with `LLVM_PROFILE_FILE` set.

- **Perf session:** `--perf` boots one unstamped session with a `builder` instance and times each hook through the real logging and channel path on synthetic payloads; before `cleanup` it asserts no `panic` line in the home's role files, because a hook panic exits 0 and hyperfine cannot see it; a failed build, boot, row, panic check or cleanup turns suite `perf` red, never a missing or skipped row.

- **Invocation:** every hyperfine call is `-N --warmup 3 --runs 30 --export-json target/agent-run/artifacts/perf-<hook>.json`. Warm-up runs absorb first-execution costs, for example Windows Defender scanning a freshly built exe, and are not part of `max`.
- **Verdict:** `viola-harness gate` evaluates the exported JSON once; the `jq -e` expressions below are equivalent. There is no rerun, no outlier trimming and no second attempt. A breach is fixed in the product or escalated through a Decisions Log entry, never retried away.
- **Spine deadline:** the gate reads the product constant `viola_core::SPINE_DEADLINE` (1.0 s), imported by `viola-harness` (`gate.rs` `perf()`), never an edited literal in `ci.yml` or this table. The hook's own connect deadline is the crate-private, provisional `CONNECT_DEADLINE` = 750 ms in the root bin's `src/cmd/hook.rs`, below the gate and asserted below it by `connect_deadline_is_below_the_spine_deadline`.
- **Status:** built. `run --perf` times the `session-start`, `user-prompt-submit`, `stop`, `session-end` and `pre-tool-use` rows (`pre-tool-use` since chunk 2026-10-04-dialog-answers-by-dialog-id); CI runs it in its own per-OS `perf` job (`test` and the pre-push carry no perf step), ending in `gate --require perf`. No async-tier row is timed. The fail-open matrix's `Instant` bound (`hook_fails_open_silently_within_the_spine_bound`, each case `< 1.0 s`) still asserts the spine bound at unit speed as well. Host reading at chunk 2026-09-28-hook-perf-gate (Windows dev host, release build): each row's `max` 72.8–73.7 ms.

| Path / operation | Trend (hyperfine JSON) | Gate |
|------------------|------------------------|------|
| `viola hook session-end` (synthetic payload via `--input`, live wrapper), per OS | mean, median, stddev | `max < 1.0 s` (`jq -e '.results[0].max < 1.0'`) |
| Spine hooks `session-start`, `user-prompt-submit`, `stop` (same method, `VIOLA_NAME`/`VIOLA_DIR` exported to hyperfine) | mean, median, stddev | `max <` `viola_core::SPINE_DEADLINE` (1.0 s) |
| `viola hook pre-tool-use` on an unverified CLI (`hook.dialog` → `null` at once), timed by `run --perf` and required by `perf::ROWS` | mean, median, stddev | `max <` `viola_core::SPINE_DEADLINE` (1.0 s) |
| Heartbeat staleness flip (`viola-state` `classify`, injected age) | n/a | same process: 5.0 s → live, 5.1 s → stale; pid or start-time mismatch → gone at any age (exact boundary test) |

Deliberately not in this table:
- `send` → `prompt-submitted` confirmation latency and `wait` wake latency. Both are bounded by product constants that are still open (arch request 1), so they are asserted as behaviour in Paths 2 and 3, not timed.
- `boot`'s 20 s deadline. This is a harness readiness timeout, not a product budget.

The same deadlines are also asserted at unit speed inside the assert_cmd hook tests, with a `std::time::Instant` bound. criterion 0.8.2 is not a gate (see Decisions Log).
criterion 0.8.2 is not a gate because it does not exit non-zero on a regression; hyperfine 1.20.0 (the `max` gate above) is the perf gate.

**Zero-flakiness budget:** flaky tests are NOT tolerated. The nextest `retries = 0`. If a test flakes once, it gets quarantined immediately and fixed at the root cause, never with a retry-once budget. For viola, quarantine means the chunk stays red until the root cause is fixed within that chunk. `#[ignore]` is not allowed as a parking place. Agent-driven dev cannot distinguish a flake from a real bug; retry policies mask actual failures.

**Build failure conditions:**
- Test failure (any level, any OS)
- Coverage below threshold for tier (per OS)
- Performance budget regression (hyperfine `max` gate)
- At a `run --mutants` (the epoch-boundary audit, or on demand): any missed mutant the harness does not leave out as host-excluded (§3 `run` step 4, Verdict), any timed-out mutant, or unviable mutants outnumbering caught ones (`unviable-exceeds-caught`)
- Lint / clippy / cargo-deny / zizmor / cargo-modules orphans failure, or a release build carrying a test-only binary

(See `## 11. Test Anti-Patterns` § Quality for quality-gate bans.)

## 11. Test Anti-Patterns (NEVER do these)

### Test Strategy

- NEVER assert at E2E a case that a lower layer can hold. Parser, refusal-order, threshold and clock cases belong in §4, contract shapes in §5, and §6 asserts only cross-process behaviour (§2 pyramid).
- NEVER assert a multi-surface critical path on one surface only. Every surface a §6 scenario lists needs its own driver step and transition signal.
- NEVER over-mock at integration level (you stop testing the integration)
- NEVER run the real `claude` CLI or `viola verify` against the real CLI in CI. The suites reach the real CLI only through `agent-run run --local-live`, which refuses when `CI` is set; a route entry's own live measurement of a real session is local too and never a CI step.
- NEVER treat a green fake-agent run as proof of real-CLI behaviour. Behaviour changes require a local `viola verify` fixture refresh plus the contract suite, because the fake agent must not drift from the real CLI (S8, §4.2).
- NEVER treat a Linux-only local run as proof for Windows or macOS. OS-branch code is verified only on its own runner.

### Unit

- NEVER test implementation details (private methods / internal state):
  test public API + observable behavior
- NEVER write brittle assertions against fixture-internal values; assert
  on contract
- NEVER import the product's own `IDENTITY_FLOOR`, ledger rows or refusal ordering as the test oracle. The expected values (the 11 identity-floor names, the refusal order, exit codes) are written as literals in the test.
- NEVER compare `RefusalReason` or exit codes by `Debug` string. Assert on the serde kebab-case value and the integer exit code.

### Integration

- NEVER mock the on-disk state (the arch has no DB; this is the DB-equivalent rule). Use a real tempfile home.
- NEVER skip cleanup between integration tests: order-dependent tests
  hide bugs
- NEVER use interprocess `try_overwrite`, or reuse an endpoint name across tests. Take the endpoint only from `snapshot.json`.
- NEVER use `std::env::set_var` in tests. It is `unsafe` in edition 2024 and races across threads; use `Command::env` per child.
- NEVER call `.env_clear()` without re-adding `LLVM_PROFILE_FILE`, because that run silently drops out of coverage.

### E2E

- NEVER use `sleep(N)` for synchronization. Wait for an explicit signal: an `events.ndjson` offset, `viola wait --after` or a status field.
- NEVER parse the rendered child screen (the vt100 grid, PTY master output) for content. Verdicts come from hook events, `events.ndjson`, channel payloads and the fake-agent receipt (R7).
- NEVER detect child exit by reading master EOF; use `child.wait()` on the handle (ConPTY).
- NEVER use `assert_cmd` `.assert()` on the long-lived `viola run` wrapper. It blocks until exit; use std::process + a `Drop` guard.

### Test Data

- NEVER use production data in tests. Fixtures come only from `viola verify` probe text and are scrubbed of paths and usernames; a `workspace.repo` naming this repository's own remote is kept (§7 Fixture hygiene).
- NEVER share mutable state across parallel tests
- NEVER use non-deterministic generators without seed control. Commit `proptest-regressions/`.
- NEVER hand-write `ledger/stamps.json`, `snapshot.json` or `budget.json`. Stamps come from `viola verify`, snapshots from the wrapper and budget from `viola hook statusline`. The ban binds every booted-wrapper test. A reader's own unit cases may plant a malformed state file only by altering the writer's own bytes: write through the writer, then pad, replace or re-version (the operator's answer at the chunk 2026-10-10-budget-governor wrap, where `budget_read_*` landed in that form).
- NEVER commit `--home` test dirs, `.env` files or tokens.

### Mocking

- NEVER mock what you don't own (libraries / language runtime) without
  abstraction layer
- NEVER over-stub (you stop testing real behavior)
- NEVER monkey-patch production code at runtime (use dependency injection)
- NEVER introduce a failpoint crate that pulls tokio into the sync crates (for example fail-parallel). Fault seams go through mockall doubles of existing traits plus process and file faults.
- NEVER stub `viola hook` in E2E. The fake agent must invoke the real pinned binary through the plugin files `run` wrote.

### CI

- NEVER serialise tests (`max-threads = 1`): isolation comes from the per-test home. The fuzz stages are single jobs, by design (§9).
- NEVER add a cache beyond Swatinem/rust-cache in `ci.yml`.
- NEVER widen the coverage `--ignore-filename-regex` (`viola-fake-agent|crates[/\\]viola-e2e|tests[/\\]support|fuzz[/\\]`) to pass a gate. The separator class that makes it match Windows paths is not a widening, because the four trees are unchanged. It is a back door to lowering the §10 thresholds and needs a Decisions Log entry first.
- NEVER ignore flaky tests; quarantine and fix immediately
- NEVER reference an Action by mutable tag (`@v2`, `@main`); SHA-pin everything, with `permissions: {}`.
- NEVER use rust-cache in a release workflow; it is ci.yml only.
- NEVER set nextest `retries` above 0.

### Quality

- NEVER add retry-once policies for flaky tests (masks real failures)
- NEVER lower coverage threshold to pass build (raise quality, not bar)
- NEVER skip quality gates "just this once"
- NEVER trust the cargo-mutants exit code or its summary line alone. Exit 3 masks exit 2, and the summary counts a host-excluded mutant as missed. The harness counts `missed`, `timeout`, `unviable` and `caught` in `outcomes.json` and leaves the host-excluded missed records out (§3 `run` step 4, Verdict): any other missed mutant, any timed-out mutant, or more unviable than caught, is red.
- NEVER gate hook deadlines on the hyperfine `mean`; gate on `max`.

### Universal (agent-driven specific)

- NEVER use Percy / Chromatic / Applitools (visual regression with human
  review)
- NEVER include manual smoke step ("developer verifies before deploy")
- NEVER use Selenium IDE / Playwright codegen-recorder as test author
- NEVER include "human reviews screenshots" in any test step
- NEVER use real network calls in tests (use mocks / localhost stubs).
- NEVER use real time without injection (use deterministic clocks) in test-side code: no test-owned timer, sleep or elapsed-time verdict. E2E may block on a deadline inside the product that it cannot inject: the send confirmation window behind Path 2's `no-prompt-submitted`, `wait --timeout-ms` in Path 3, and heartbeat staleness in the chaos SIGSTOP case. Two conditions apply: the verdict is the product's own exit code or status field, and the same deadline is clock-driven in a §4 unit case.
- NEVER use mock_instant `MockClock` (or any in-process clock) to control another process's time. Global mode reaches only threads of the test process, never a spawned `viola run`. Cross-process expiry is asserted in the §4 unit case, as Path 6 step 7 does.
- NEVER accept interactive snapshot review (`cargo insta review`, trycmd overwrite) as a gate step. Snapshots change only through the local `viola verify` fixture refresh, and then get committed.
- NEVER write a test that auto-approves a dialog (blanket approval), or one that passes when a decision body is emitted without a verify stamp and wheel `driver`.
- NEVER let a harness command print a human-only message without the JSON document and exit code.
- NEVER add retry-once policies or any retry budget for flaky tests (§10 Zero-flakiness budget).
- NEVER run property or chaos tests without deterministic replay: proptest seeds persist in committed `proptest-regressions/`, and chaos faults come only from explicit process / file operations or existing mockall seams (§2 Property-based and Chaos rows).
