# Test Plan — viola

_Generated by `/andromeda-tests`. This file is the single source of truth
for all test strategy + harness contracts + quality gates. Read by
downstream skills (obs / a11y / route / setup-project per D26 cross-
cutting) and the phase loop per chunk (`/andromeda-phase` distillers + `/andromeda-implement`)._

_Do not edit during phase loop runs (`/andromeda-phase` / `/andromeda-implement`).
Manual edits between runs are fine._

_**Agent-driven invariant:** every test layer described in this plan must
be runnable end-to-end by an agent reading exit codes and structured
output. No human-in-the-loop checkpoints, no manual verification, no
visual regression with human review. If a surface cannot be agent-driven,
it is flagged "untestable" in test-scope.md Section 1 and handled via
boundary tests / mocks._

## 1. Test Scope Summary

**Test tier:** `Comprehensive (2)`
_Justification: The passed security tier is Minimal, but the security excerpt adds targeted elevations and 9 attack vectors, each needing negative tests. It also explicitly hands 7 parser surfaces to tests for property/fuzz coverage. **Surfaces under test:**

- **Surface:** cli (`viola` verbs: `send · wait · last · list · answer · pause · release · link · unlink · verify · plugin install · ui · run` launch semantics)
  - **Driver:** subprocess + `assert_cmd` / `Command::cargo_bin("viola")`, with `--home <per-test temp>` and `--json`
  - **Signal:** exit code (0, 1, 2, 10–14, 20, 21) plus one JSON document on stdout (`{"v":1,"ok":…}` / `{"v":1,"refusal":…,"detail":…}` / `{"v":1,"error":…}`). Human mode is checked by stdout/stderr line match: `[RB] read back … cursor <n>`, `unable  <name>  <reason>  <detail>` + last-line `hint:`, `stamped <ver>  <n> pass  <n> fail`. There must be no SGR under non-TTY / `NO_COLOR` / `TERM=dumb`.
  - **Boundary:** cross-surface (verbs talk to the `run` wrapper over the IPC channel, and read disk for `list`)
  - **Notes:** traced to arch excerpt, CLI and design excerpt, Surfaces (cli). The human TTY rendering (bold NAME, amber `DIALOG`, dim `stale`) needs a pseudo-TTY on stdout. It is driven through the same outer-PTY driver as the tui surface, not by screen inspection of the child agent.

- **Surface:** cli (the `viola hook <event>` and `viola hook statusline` exec-form entry points, invoked by Claude Code or the fake agent)
  - **Driver:** subprocess + `assert_cmd` feeding recorded hook payloads from `fixtures/claude/<cli-version>/` on stdin, with and without `VIOLA_NAME` / `VIOLA_DIR`
  - **Signal:** exit code is always 0. stderr is always empty. stdout is either empty (no decision / async hooks) or exactly the PreToolUse / PermissionRequest decision body. Side effects are checked as a matching `events.ndjson` line, a hook trace under `diagnostics/`, and `budget.json` contents for statusline.
  - **Boundary:** cross-surface (hook → IPC `hook.dialog` / `hook.event` → wrapper → disk)
  - **Notes:** traced to arch excerpt, Hooks and security excerpt, Vector 4. Deadline checks apply: spine hooks within the spine deadline, SessionEnd ~1 s.

- **Surface:** tui (`viola run <name> -- <fake agent>` terminal passthrough, i.e. the human's side of the PTY)
  - **Driver:** PEXPECT-class outer-PTY driver. The test spawns `viola run` inside a PTY it owns, writes human keystrokes and bracketed pastes, and resizes. The concrete crate is Phase 2's choice.
  - **Signal:** `events.ndjson` lines (`wheel {holder:"human", cause:"human-input"}`, `prompt-submitted {origin:"human"}`), the fake agent's own report of what it received (one prompt, newlines inside, no Esc), and process exit code / exit detection on the process handle
  - **Boundary:** cross-surface (TUI input → wrapper wheel → IPC refusals seen by cli / MCP)
  - **Notes:** traced to arch excerpt, Stack (portable-pty, vt100) and creator excerpt, Must-Work (R2, R3/S1, Windows ConPTY). Assertions must never parse the rendered child screen for content (creator excerpt, Test Anti-Patterns: "Nobody parses the rendered screen for content"). The vt100 readiness gate is tested through its refusal outputs (`input-not-ready`), not by scraping the screen.

- **Surface:** ipc-internal (wrapper channel: JSON-RPC 2.0 over ndjson on a named pipe / Unix socket; methods `send`, `wait`, `last`, `answer`, `pause`, `release`, `link`, `unlink`, `hook.dialog`, `hook.event`)
  - **Driver:** language-native IPC test client (the `viola-channel` sync client, or a raw `interprocess` `local_socket` client for malformed frames) + JSON schema assertion
  - **Signal:** IPC response payload check. Success is `{"result":{"ok":…}}`. Refusal is `{"result":{"refusal":…,"detail":…}}` with the first-applicable ordering. Protocol faults are `{"error":{code,message,data}}` with codes -32700 / -32600 / -32601 / -32602 (`data:{supported, wrapper}`) / -32603 (`"internal error"`, `data:null`). This is cross-checked against the `events.ndjson` byte-offset `cursor`.
  - **Boundary:** single-surface for protocol tests; cross-surface when fed by the fake agent
  - **Notes:** traced to arch excerpt, Wrapper channel and security excerpt, Vector 1. Cross-user peer rejection is flagged in section 1.

- **Surface:** ipc-internal (MCP stdio server `viola mcp`, tools `send · wait · last · answer · list`)
  - **Driver:** language-native MCP stdio test client. It spawns `viola mcp --home <tmp>` and speaks JSON-RPC over stdin/stdout, with JSON schema assertion.
  - **Signal:** MCP tool result. `isError:false` + `structuredContent` equal to the `ok` payload. `isError:true` + `{refusal, detail}` and text `"refused: <reason>"`. `isError:true` + `{"error":"instance-unreachable"|"wrapper-fault"}`.   - **Notes:** traced to arch excerpt, MCP and security excerpt, Vector 5. Schemas are advisory, so negative inputs must be sent that violate the advertised schema.

**Test harness requirements:**

Inherited pattern: arch excerpt, Test Harness Commitment ("Development Style: agent-driven") with harness design deferred to tests. Binding founder direction: creator excerpt, Founder Directions 2 and 3: "the fake agent + `viola verify` fixtures are the contract"; "Structured JSON logs from every process (run/hook/mcp/ui) … a `logs` command in the harness, hook trace in diagnostics/".

- **5-command requirements:**
  - `boot`:
    - Builds `viola` and creates a fresh temp home, passed as `--home` (arch excerpt, Per-test isolation).
    - Starts one or more `viola run <name> -- <fake agent> <args>` wrappers and optionally `viola ui --home <tmp> --port <free port>`.
    - Readiness, per instance: `instances/<name>/snapshot.json` exists with `pid`, `started_at`, `child_pid` and `endpoint`. The `heartbeat` mtime is under 5 s old. The log has a start `wheel` and a `budget-gate` event, followed by `session-start` once "Verify-stamped test homes and harness" (the `boot` step-4 owner) joins it to harness readiness.
    - Readiness, UI: `GET /health` returns 200 `"status":"ok"` and `GET /ready` returns 200 `"status":"ready"` (arch GUI readiness).
    - On readiness failure it exits non-zero with a JSON reason on stdout. A `run` refusal to start (exit 1: a `live` or `stale` name, a tampered pinned copy, or a `.cmd`/`.bat` child) is surfaced verbatim.
  - `run`:
    - Invokes, in order:
      1. the workspace unit and integration tests (`cargo test`)
      2. fake-agent E2E against `fixtures/claude/*`
      3. the headless-browser suite against the booted UI (selected only by `run --browser`, never by the default)
      4. mutation testing scoped to the chunk diff (Founder Direction 1: "surviving mutants are red") — only under `run --mutants`, never in the default or `--all`; its cadence is the epoch-boundary code audit
    - Exit 0 only if every suite passes and no mutant survives. Non-zero otherwise, with a JSON summary on stdout (suite, passed, failed, survived).
    - Local-only mode adds `viola verify` against the real CLI. It must never run in CI (arch excerpt, CI/CD).
  - `status`:
    - Queries `viola list --json --home <tmp>` (no cookie needed) and, if the UI is booted, `GET /ready` and cookie-authenticated `GET /api/sessions`.
    - The agent polls per item: `name`, `wrapped`, `liveness`, `status`, `wheel`, `budget_paused`, `dialog_pending`, `cli_verified`.
    - It also polls the envelope `skipped{unknown_kinds, unknown_fields, torn_lines}` and `budget`.
  - `cleanup`:
    - Stops every wrapper and the UI process started by `boot`. Exit is confirmed on the process handle, not EOF.
    - Deletes the temp home and verifies the endpoint is gone: a CLI verb against the name returns exit 21, and the Unix socket file or pipe no longer exists.
    - Verifies the UI port is free and `ui/<port>.url` was removed.
    - Must be idempotent: a second run exits 0 and reports nothing to clean.
  - `logs`:
    - Prints, as JSON lines, the structured per-process logs of `run` / `hook` / `mcp` / `ui` in the §3 log format (Founder Direction 3; the exact field set is not in the distilled excerpt, so Phase 3 pins it).
    - Also prints `instances/<name>/events.ndjson` and the hook trace under `diagnostics/`.
    - Filterable by instance and kind.
    - Retention is the lifetime of the temp home: events are never truncated (arch excerpt, Event line), and `cleanup` deletes the home.
- **Status endpoint shape:**
  - `GET /health`: `{"v":1,"status":"ok","name":"viola","version":"0.1.0","ts":<RFC3339 ms Z>}`.
  - `GET /ready`: `{"v":1,"status":"ready"|"not-ready", …, "checks":{"viola_home":"ok"|"unavailable"|"error","event_tail":…,"claude_agents":…}}` (503 when not-ready; `claude_agents` failing alone keeps 200). The check values are `ok` / `unavailable` / `error`; the top-level success word is `ready`, never `ok`.
  - `GET /api/sessions` (cookie-authenticated): `{v, generated_at, items:[{name, wrapped, liveness:"live"|"stale", status:"idle"|"busy"|"unknown", wheel?:"human"|"driver", budget_paused?, dialog_pending, cli_version?, cli_verified?}], skipped:{unknown_kinds, unknown_fields, torn_lines}, budget:{five_hour:{used_percentage,resets_at}, seven_day:{…}, read_at, paused}|"unknown"}`.
  - `viola list --json`: `{"v":1,"ok":{items, budget, skipped}}`, with the same item, `budget` and `skipped` shapes as `/api/sessions` and no `generated_at`. Its items are read at `.ok.items` (arch: `list` `ok` payload; CLI `--json` mirrors the channel `result`).
  - Source: arch excerpt, GUI HTTP.
- **Log format:**
  - Events: JSON-per-line ndjson `{"v":1,"ts","instance","kind","source":"hook|wrapper|cli","data"}` (arch excerpt, Event line).
  - Process logs: structured JSON lines per Founder Direction 3, parseable with `jq`.
  - Logs must never contain the token, the `Cookie` header, `?t=`, or stripped `CLAUDE*` values (security excerpt, Error-sanitization).
- **PID file location:**
  - There is no standalone pid file. The wrapper `pid`, `started_at` and `child_pid` live in `<home>/instances/<name>/snapshot.json`, with liveness in `<home>/instances/<name>/heartbeat` (touched every 1 s): when pid + start time no longer name a running process the instance is `gone` whatever the beat's age; otherwise a beat at most 5 s old is `live`, and an older or absent one `stale`.
  - The UI process is discovered through `<home>/ui/<port>.url` and `GET /api/info` (`pid`, `bind`).
  - Source: arch excerpt, Instance snapshot / Other files.
- **Test data strategy:**
  - Self-bootstrapping per test: a fresh `--home` temp dir.
  - The fake agent is the child (`viola run <name> -- <fake agent>`; it answers `--version` like the real CLI). It replays hook payloads from `fixtures/claude/<cli-version>/`, which `viola verify` records locally and CI replays.
  - `budget.json` is seeded by piping synthetic statusline stdin into `viola hook statusline`, and `claude agents --json` by a stub on PATH.
  - Property / fuzz generators cover the parser surfaces the security excerpt lists.
  - Constraints:
    - Fixtures must not come from real prompts and must be checked for absolute paths and usernames (security excerpt, Anti-Patterns: "Fixtures from real prompts, or unchecked for paths and usernames").
    - Open conflict for Phase 3: the arch excerpt (Per-test isolation) says the home's `ledger/stamps.json` "can stamp the fake agent's version". The security excerpt rejects "a non-`verify` process writing `stamps.json`". Stamps must therefore be produced by running `viola verify` against the fake agent, or the conflict must be resolved upstream. Resolved in §12 (initial entry, ratified by User review 1): the first option is used.
    - No developer-seeded state.

**Agent-runnable invariants (apply across all levels):**
- Every test layer produces machine-parseable output. Rust suites give an exit code plus nextest JUnit (`target/nextest/ci/junit.xml`). Playwright writes `pw.json` and `pw-junit.xml`. cargo-mutants writes `mutants.out/outcomes.json` (under the harness-set output dir: the host mutation scratch `<repo parent>/viola-mutants-scratch/` on a Windows host, the repository root elsewhere), hyperfine writes `--export-json`, cargo-llvm-cov writes `report --json --summary-only`, and harness commands print one JSON document on stdout.
- No human-in-loop verification, no Percy / Chromatic, no manual exploratory steps. Playwright runs only in headless test-runner mode. insta runs only in check mode (`INSTA_UPDATE=no`), and trycmd only in verify mode.
- Deterministic:
  - no nextest retries (`retries = 0`) and no `std::thread::sleep` / `tokio::time::sleep` used for synchronisation
  - waits key on `events.ndjson` byte offsets, `viola wait --after <cursor>`, SSE `id:` offsets or Playwright auto-waiting locators
  - the only network is 127.0.0.1 (`viola ui`), and CI never touches the real `claude`
- Self-bootstrapping fixtures, with no developer-seeded data:
  - every test creates its own `--home` via tempfile 3.27.0
  - stamps come only from `viola verify` run against the fake agent
  - `budget.json` comes only from `viola hook statusline` stdin

**Test directory + naming conventions:**
- **Directory pattern:** the arch uses flat `crates/viola-<area>` plus the root bin, with no declared test crate. This plan adds one test-only crate; see Decisions Log.
  - **Unit tests:** inline `#[cfg(test)] mod tests` at the bottom of each source file.
  - **Crate-level integration tests:** `crates/viola-<area>/tests/<topic>.rs`.
  - **Sync (tokio-free) E2E suites:** root `tests/{cli,hook,tui,channel,chaos,contract}_<topic>.rs`, sharing helpers in `tests/support/{home.rs,outer_pty.rs,fake.rs,events.rs,ndjson.rs}`. `ndjson.rs` is the one complete-lines reader: every reader of a live-appended file parses only newline-terminated lines, because a Linux reader can observe an append part-way.
  - **Tokio-client E2E suites and the harness binary `viola-harness`:** `crates/viola-e2e/` (publish = false). This covers the rmcp client, reqwest/eventsource-client, cross-surface parity and critical-path scenarios, as `tests/{path,mcp,http,sse,cross}_<topic>.rs`.
  - **Why a test-only crate:** `crates/viola-e2e` hosts `viola-harness` and the tokio-based test clients (rmcp client, reqwest, eventsource-client), so the root package and the sync crates carry no tokio dev-dependency. It is never a root of the tokio ban: the ban runs `deny-sync.toml` once per crate in `scripts/sync-crates.txt`, each as the sole root, so `viola-e2e`'s tokio graph lies outside it with no `wrappers` allowlist and no `--exclude` (an `--exclude` false-fails on a feature-unified optional tokio).

## 3. Test Harness Contract

Architecture committed to the harness pattern (verbatim from
upstream-context arch Test Harness Commitment): "- Development Style: agent-driven." This section specifies
the concrete contract.

**Harness implementation:** `scripts/agent-run.sh` (POSIX) and `scripts/agent-run.ps1` (PowerShell) are identical thin shims. They run `cargo run -q -p viola-e2e --bin viola-harness -- <command> [flags]` and forward its exit code and stdout unchanged. All logic lives once, in Rust, so both shells have byte-identical semantics on all 3 OSes.

- **Session record:** each harness session writes `target/agent-run/<session>/session.json` with `{home, instances:[{name, wrapper_pid, started_at, fake_args}], ui:{port, pid}|null, supervisor_pid, cookie_file}`. The default session is `default`, and `--session <id>` allows parallel sessions (one per Playwright test, per §3 `run` step 3).
- **Exit codes:** every harness command exits 0 on success, 1 on failure and 2 on usage error. Each prints exactly one JSON document on stdout, starting `{"v":1,"cmd":"<command>","ok":<bool>,…}` (key order held by serde_json `preserve_order`). A usage error carries `reason:"usage"` and a `detail` from `invalid-session-id`, `session-exists`, `invalid-instance`, `arguments`, `no-supervise-spec` and `unknown-suite` (a `gate --require` value outside the nine suites). The grammar grows per chunk: a flag or selector whose surface is not built yet (`boot --ui`, `run --e2e`, …) is a usage error until its chunk lands, never a vacuous pass.

Contracts: .andromeda/registries/test-plan-contracts.toml — ask registry.py contracts; read one contracts/test-plan/{key}.md; never whole.

## 4. Unit Test Strategy

**Framework:** cargo test (libtest, current Rust stable pinned in `rust-toolchain.toml`, ≥ 1.96; MSRV 1.96, edition 2024), executed through cargo-nextest 0.9.146 (process-per-test, JUnit). Doctests run through `cargo test --workspace --doc`, because nextest cannot run them.
**Coverage tool:** cargo-llvm-cov 0.9.1 (`cargo llvm-cov nextest`, LCOV + JSON summary).
**Coverage target:** see Section 10 Quality Gates for tier-specific
threshold.

**Conventions** (from upstream-context Test-Relevant Conventions and the Rust stack defaults):
- Test file location: inline `#[cfg(test)] mod tests` in the same source file, in every `crates/viola-<area>` and in root `src/`.
- Test function naming: `<subject>_<condition>_<expected>` in snake_case.
- Test grouping: flat modules per source file. Table-driven cases use rstest `#[case]`, and each case name must be a readable label (for example `#[case::esc_refused]`). **Fixture pattern at unit level:**
- rstest 0.27.0 `#[fixture]` for shared constructors, for example a `TempHome` or a `Clock`.
- `#[rstest] #[case(...)]` tables for the refusal-order and exit-code matrices.
- `#[files("fixtures/claude/*/*.json")]` generates one test per recorded hook payload.
- proptest 1.11.0 `proptest!` blocks at `cases: 512` for parser invariants.
- insta 1.48.0 `assert_json_snapshot!` with redactions (`.dialog_id`, `.ts`) for decision bodies.

**Selector strategy:**
- **Role-based queries** follow the design Brand Identity Anchors: `getByRole('table')` for racks, `'row'` for strips, `'cell'` for strip cells, `'columnheader'` for the six captions, `'log'` for the tape and `'status'` for the live region.
- **Cell addressing:** a cell is the `cell` in the `row` filtered by the exact NAME text, taken at the index of the `columnheader` whose accessible name is the caption (for example `WHEEL`). That index is resolved at runtime from the header row, never written as a literal `nth()`. If design reorders or adds a column, the lookup still finds the right cell. If a caption is renamed, the lookup fails in one place.
- **Tape synchronisation:** new tape lines and markers are awaited with auto-waiting locators on `[data-live]` elements filtered by the unique text the test sent, never by a timeout.
- **`data-*` state attributes** are asserted with `toHaveAttribute`: `viola-session-row[data-dialog="pending"]`, `[data-liveness="stale"]`, `[data-wrapped="false"]`, `viola-readback[data-rb="open|read|refused|unconfirmable"]`.
- **Component names** (`viola-atis`, `viola-transfer`, `viola-event-feed`) scope text matches. The selector form these and the `viola-*[data-*]` selectors above take (an element, a class or a data attribute) follows how each component maps onto React's output, which is OPEN, owned by the route's frontend-toolchain entry.
- **Session names** are matched by exact text of the `ViolaName`, never text-transformed.
- **Never used:** CSS classes (`.band`, `.rb`), inline `style`, or xpath.
- **axe:** `AxeBuilder({page}).analyze()` runs after each state strip renders (empty, 503, cocked), with `violations` required to be `[]`. The test plan owns only where axe runs and the verdict: an empty `violations` array passes, anything else fails the test. Rule tags, disabled rules and the conformance target come from the a11y plan's configuration, and specs must not add their own `withTags` / `disableRules`. Until the a11y plan names a configuration, axe's default rule set applies unchanged.

- One run-time directory walk (`claude_fixtures` in `tests/contract_fixture_hygiene.rs`, with its own walker test) does two checks per fixture — not an rstest `#[files(…)]` case, because rstest 0.27 refuses a glob that matches no file at compile time (`rstest_macros-0.27.0/src/parse/rstest/files.rs:635` "No file found", as measured at chunk 2026-09-28-capability-ledger-and-viola-verify):

  - it validates the file with jsonschema
- The checker (`tests/support/hygiene.rs`) reports a violation class only (`absolute-path`, `username`, `schema`), never the offending content. Planted inputs prove each class red.
- Today the walk (`tests/contract_fixture_hygiene.rs`) covers `fixtures/fake-scripts/*.json` against `schemas/fake-script.v1.json` (draft 2020-12, unknown fields allowed, `v` const 1, closed nine-event enum). The walk covers one or more committed scripts (`fixtures/fake-scripts/{gated-turn,path3,path4,path4-permission}.json` today). - Fixture prompts are synthetic probe text only, never real prompts.

**Self-bootstrapping requirement:**
- Tests MUST seed their own data; no developer pre-populates a home.
- The `boot` command creates the home, stamps it via `viola verify`, and starts the wrappers and UI automatically.

**Test data lifecycle:**
- **Per-test:** isolated state. Each test has its own home, so there is no shared endpoint, log or `budget.json`. Env is set per child with `Command::env`, never `std::env::set_var`, which is `unsafe` in edition 2024.

## 8. Mocking & Stubbing Discipline

**What to mock:**
- External HTTP APIs: none exist. viola makes no outbound HTTP calls, so no HTTP mock library is used.
- External services not under test: the real `claude` CLI is replaced by the native `viola-fake-agent` binary, both as the PTY child and as `claude` on a test-scoped PATH. Anthropic usage values are replaced by generated statusline stdin. These are fakes, never the real services.
- Time: sync crates use mock_instant 0.6.1 (global mode) or the injected `viola_core::Clock` for heartbeat 1 s / 5 s, the send confirmation window and `budget_override_until`. Async crates (`viola-mcp`, `viola-ui`) use `#[tokio::test(start_paused = true)]` from tokio 1.53.1 `test-util` for the SSE keep-alive and for any timer the MCP adapter itself owns. The `wait` `timeout_ms` deadline runs in the wrapper process, and only the injected `viola_core::Clock` in the §4 root-bin case drives it. A paused tokio clock in a test never reaches a spawned wrapper (§11 Universal). `chrono::Utc::now()` is read only through the clock seam.
- Filesystem: not mocked. A real tempfile home is used everywhere, because modes, `File::lock`, torn lines and symlink handling are the behaviour under test. Only the Windows foreign-SID / non-persistent-ACL descriptors are stubbed, as synthetic SDDL descriptors fed to the check function.
- Random sources: proptest seeds are persisted. The GUI token is never mocked; tests read the real token from `ui/<port>.url`.

**What NOT to mock:**
- Pure functions in modules under test (`validate_paste_text`, parsers, refusal ordering), which are tested directly.
- On-disk state at integration level (the arch has no DB). Use real files in a tempfile home.
- The wrapper channel, PTY, vt100, serde or the axum router in E2E. Code paths the agent must verify end-to-end go in E2E (§6).
- `viola hook` invocations inside E2E. The fake agent calls the real pinned binary.

**Mocking libraries (specific, from research):**

| Concern | Library | Pattern |
|---------|---------|---------|
| HTTP mocking | N/A (no outbound HTTP) | Inbound HTTP is tested against the real router via axum-test 21.1.0 or the real `viola ui` via reqwest 0.13.5 |
| Time mocking | mock_instant 0.6.1; tokio 1.53.1 `test-util` | Inject the `Clock` dependency through constructors and call `MockClock::advance(Duration::from_secs(6))`; use `start_paused` + `tokio::time::advance(15s)` for SSE |
| Process mocking | mockall 0.15.0 on the `viola-pty` `Pty` trait and the liveness / `Clock` traits; native stub binaries (`viola-fake-agent`) | `#[cfg_attr(test, mockall::automock)]` on seam traits only; external processes are real stub executables, resolved through `CARGO_BIN_EXE_viola-fake-agent` in root `tests/` only. `viola-e2e` tests and the harness use the assert_cmd target-dir lookup (§3 boot step 5) |
| Fake servers | interprocess 2.4.4 server API (squatter listener); `viola-fake-agent` as the fake CLI | The squatter binds the computed endpoint before `run`; no HTTP fake servers |

**Anti-monkey-patching:** prefer dependency injection over runtime patching of production code. Doubles exist only for traits viola already defines at its seams (research, mockall key detail).

## 10. Quality Gates & Coverage Targets

**Coverage thresholds (per tier):**

| Tier | Line coverage | Branch coverage | Function coverage |
|------|---------------|-----------------|-------------------|
| Minimal | ≥ 60% | ≥ 50% | ≥ 70% |
| Standard | ≥ 75% | ≥ 70% | ≥ 85% |
| **Comprehensive (viola)** | **≥ 85%** | **≥ 80%** (enforced as region coverage `--fail-under-regions 80`) | **≥ 95%** |

Stack adjustments:
- Gates are enforced per OS job with `cargo llvm-cov nextest … --fail-under-lines 85 --fail-under-functions 95 --fail-under-regions 80`. Per-OS gating is deliberate: `#[cfg(windows)]` / `#[cfg(unix)]` code compiles only on its own runner.
- Coverage rolls up across all workspace crates.
- Excluded via the separator-agnostic `--ignore-filename-regex` `(viola-fake-agent|crates[/\\]viola-e2e|tests[/\\]support|fuzz[/\\])`, the harness const `COVERAGE_IGNORE`. llvm-cov reports Windows paths with `\`, so the forward-slash form never matched there (as measured at chunk 2026-09-24-quality-gates, research.md M5).
- Child `viola` processes spawned by E2E tests are included, because `LLVM_PROFILE_FILE` propagates. Tests that call `env_clear()` must re-add it. The one deliberate exception is not the product: the harness self-tests' nested cargo over the throwaway `mini` crate (package `viola`) removes cargo-llvm-cov's four names (`CARGO_LLVM_COV`, `LLVM_PROFILE_FILE`, `RUSTC_WRAPPER`, `__CARGO_LLVM_COV_RUSTC_WRAPPER_RUSTFLAGS`) through `test_support::uninstrumented`, so the throwaway's binaries write no profile into the outer run — as measured at chunk 2026-09-29-h2-conpty-resize-probe on the dev host (new `.profraw` per run of one such self-test: 17 with the names inherited, 13 without, the throwaway's two binary signatures gone). **Zero-flakiness budget:** flaky tests are NOT tolerated. The nextest `retries = 0`, and Playwright `retries: 0`. If a test flakes once, it gets quarantined immediately and fixed at the root cause, never with a retry-once budget. For viola, quarantine means the chunk stays red until the root cause is fixed within that chunk. `#[ignore]` and `test.skip` are not allowed as a parking place. Agent-driven dev cannot distinguish a flake from a real bug; retry policies mask actual failures.

**Build failure conditions:**
- Test failure (any level, any OS)
- Coverage below threshold for tier (per OS)
- Performance budget regression (hyperfine `max` gate)
- At a `run --mutants` (the epoch-boundary audit, or on demand): any missed or timed-out mutant, or unviable mutants outnumbering caught ones (`unviable-exceeds-caught`)

## 11. Test Anti-Patterns (NEVER do these)

### Test Strategy

- NEVER assert at E2E a case that a lower layer can hold. Parser, refusal-order, threshold and clock cases belong in §4, contract shapes in §5, and §6 asserts only cross-process behaviour (§2 pyramid).
- NEVER assert a multi-surface critical path on one surface only. Every surface a §6 scenario lists needs its own driver step and transition signal, with web bullets owned per the §3 `run` step 3 cross-runner rule.
- NEVER over-mock at integration level (you stop testing the integration)
- NEVER run the real `claude` CLI or `viola verify` against the real CLI in CI. The real CLI is local-only through `agent-run run --local-live`, which refuses when `CI` is set.
- NEVER treat a green fake-agent run as proof of real-CLI behaviour. Behaviour changes require a local `viola verify` fixture refresh plus the contract suite, because the fake agent must not drift from the real CLI (S8, §4.2).
- NEVER treat a Linux-only local run as proof for Windows or macOS. OS-branch code is verified only on its own runner.

### Unit

- NEVER test implementation details (private methods / internal state):
  test public API + observable behavior
- NEVER write brittle assertions against fixture-internal values; assert
  on contract
- NEVER import the product's own `IDENTITY_FLOOR`, ledger rows or refusal ordering as the test oracle. The expected values (the 11 identity-floor names, the refusal order, exit codes) are written as literals in the test.
- NEVER compare `RefusalReason` or exit codes by `Debug` string. Assert on the serde kebab-case value and the integer exit code.

### Integration

- NEVER mock the on-disk state (the arch has no DB; this is the DB-equivalent rule). Use a real tempfile home.
- NEVER skip cleanup between integration tests: order-dependent tests
  hide bugs
- NEVER use interprocess `try_overwrite`, or reuse an endpoint name across tests. Take the endpoint only from `snapshot.json`.
- NEVER use `std::env::set_var` in tests. It is `unsafe` in edition 2024 and races across threads; use `Command::env` per child.
- NEVER call `.env_clear()` without re-adding `LLVM_PROFILE_FILE`, because that run silently drops out of coverage.

### E2E

- NEVER use xpath selectors; use role / data-* attributes / text
- NEVER use `sleep(N)` for synchronization. Wait for an explicit signal: an `events.ndjson` offset, `viola wait --after`, an SSE `id:`, a status field or an element role.
- NEVER use brittle selectors that drift across iterations, such as CSS class selectors (`.band`, `.rb`) or inline `style`
- NEVER parse the rendered child screen (the vt100 grid, PTY master output) for content. Verdicts come from hook events, `events.ndjson`, channel payloads, the fake-agent receipt and DOM attributes (R7).
- NEVER detect child exit by reading master EOF; use `child.wait()` on the handle (ConPTY).
- NEVER use `assert_cmd` `.assert()` on the long-lived `viola run` wrapper. It blocks until exit; use std::process + a `Drop` guard.
- NEVER set Playwright `bypassCSP`, use `toHaveScreenshot`, or let a test pass while a CSP or Trusted Types violation fired.
- NEVER enable eventsource-client auto-reconnect in resume tests. It hides the "no header → start at end" behaviour.

### Test Data

- NEVER use production data in tests. Fixtures come only from `viola verify` probe text and are scrubbed of paths and usernames.
- NEVER share mutable state across parallel tests
- NEVER use non-deterministic generators without seed control. Commit `proptest-regressions/`.
- NEVER hand-write `ledger/stamps.json`, `snapshot.json` or `budget.json`. Stamps come from `viola verify`, snapshots from the wrapper and budget from `viola hook statusline`.
- NEVER commit `--home` test dirs, `.env` files, tokens or cookies.

### Mocking

- NEVER mock what you don't own (libraries / language runtime) without
  abstraction layer
- NEVER over-stub (you stop testing real behavior)
- NEVER monkey-patch production code at runtime (use dependency injection)
- NEVER introduce a failpoint crate that pulls tokio into the sync crates (for example fail-parallel). Fault seams go through mockall doubles of existing traits plus process and file faults.
- NEVER stub `viola hook` in E2E. The fake agent must invoke the real pinned binary through the plugin files `run` wrote.

### CI

- NEVER serialise tests outside the nextest `fixed-port` group. Isolation comes from the per-test home. The fuzz stages are single jobs, by design (§9). That does not license `max-threads = 1` anywhere else.
- NEVER add a cache beyond Swatinem/rust-cache in `ci.yml`. npm and Playwright browsers are deliberately not cached (§12 Browser caching).
- NEVER let `run --browser` or `viola-harness gate --require …playwright` pass on any OS with the `playwright` suite missing or skipped (§3 `run` step 3, §3 `gate`).
- NEVER widen the coverage `--ignore-filename-regex` (`viola-fake-agent|crates[/\\]viola-e2e|tests[/\\]support|fuzz[/\\]`) to pass a gate. The separator class that makes it match Windows paths is not a widening, because the four trees are unchanged. It is a back door to lowering the §10 thresholds and needs a Decisions Log entry first.
- NEVER ignore flaky tests; quarantine and fix immediately
- NEVER reference an Action by mutable tag (`@v2`, `@main`); SHA-pin everything, with `permissions: {}`.
- NEVER use rust-cache in a release workflow; it is ci.yml only.
- NEVER set nextest `retries` above 0.

### Quality

- NEVER add retry-once policies for flaky tests (masks real failures)
- NEVER lower coverage threshold to pass build (raise quality, not bar)
- NEVER skip quality gates "just this once"
- NEVER trust the cargo-mutants exit code alone. Exit 3 masks exit 2, so count `missed`, `timeout`, `unviable` and `caught` in `outcomes.json`: any missed or timed-out mutant, or more unviable than caught, is red.
- NEVER gate hook deadlines on the hyperfine `mean`; gate on `max`.

### Universal (agent-driven specific)

- NEVER use Percy / Chromatic / Applitools (visual regression with human
  review)
- NEVER include manual smoke step ("developer verifies before deploy")
- NEVER use Selenium IDE / Playwright codegen-recorder as test author
  (use as headless runner only)
- NEVER include "human reviews screenshots" in any test step
- NEVER use real network calls in tests (use mocks / localhost stubs). The only socket allowed is 127.0.0.1 `viola ui`.
- NEVER use real time without injection (use deterministic clocks) in test-side code: no test-owned timer, sleep or elapsed-time verdict. E2E may block on a deadline inside the product that it cannot inject: the send confirmation window behind Path 2's `no-prompt-submitted`, `wait --timeout-ms` in Path 3, and heartbeat staleness in the chaos SIGSTOP case. Two conditions apply: the verdict is the product's own exit code or status field, and the same deadline is clock-driven in a §4 unit case.
- NEVER use mock_instant `MockClock` (or any in-process clock) to control another process's time. Global mode reaches only threads of the test process, never a spawned `viola run` / `viola ui`. Cross-process expiry is asserted in the §4 unit case, as Path 6 step 7 does.
- NEVER accept interactive snapshot review (`cargo insta review`, trycmd overwrite) as a gate step. Snapshots change only through the local `viola verify` fixture refresh, and then get committed.
- NEVER write a test that auto-approves a dialog (blanket approval), or one that passes when a decision body is emitted without a verify stamp and wheel `driver`.
- NEVER let a harness command print a human-only message without the JSON document and exit code.
- NEVER add retry-once policies or any retry budget for flaky tests (§10 Zero-flakiness budget).
- NEVER run property or chaos tests without deterministic replay: proptest seeds persist in committed `proptest-regressions/`, and chaos faults come only from explicit process / file operations or existing mockall seams (§2 Property-based and Chaos rows).
