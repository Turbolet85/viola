# Viola 0.1.0 — requirements

_Capabilities this version delivers. No prior `P-NNN` space exists outside `refs/`, so ids are version-scoped
(`v1-NN`), and `v1-NN` maps one-to-one onto intent finding `F-NN`. Derived from `viola-0.1.0/intent.md`; each line
carries that finding's EXPECT, and the matching OBSERVED clause travels into `verification-matrix.json` as
`observed_gap`. The groups keep the intent's order (a)–(g)._

## (a) Infrastructure first — before any feature code

- **v1-01** · Three-OS CI pipeline from the first commit — every push and PR runs build, format, fatal lint, the tokio-free check of the sync crates, the dependency policy, workflow linting and tests natively on Windows, macOS and Linux under SHA-pinned least-privilege actions, plus a weekly advisory run; perf gates run in their own job, gate tools are checked present first, test homes survive until every gate has read them, and nothing from a test home uploads unless the secret scan passed (per intent F-01; A:431-442; S:303-333; TP §9; OB §9).
- **v1-02** · The headless harness: five agent-run commands — an agent can `boot`, `run`, `status`, `cleanup` and `logs` a product session on all three OSes through identical shims, each printing one JSON document and a typed exit; `boot` reaches readiness or names the unmet check, `cleanup` is idempotent and proves endpoints, ports and token files gone, `status` shows the CLI board and GUI sessions agree (per intent F-02; TP §3).
- **v1-03** · The fake agent and recorded fixtures as the test contract — a fake agent behaves like the CLI at every boundary viola uses and replays per-CLI-version hook fixtures recorded by `viola verify`; a contract suite fails when it drifts from the fixtures (annotations included), and fixtures carry no real prompts, home paths or usernames (per intent F-03; TP §6-§7).
- **v1-04** · Structured JSON logs from every process, and a `logs` view — `run`, `hook`, `mcp`, `ui` and client-side `cli` write one-line JSON records with the grepped fields under the closed event vocabulary, a null correlation is a missing key, `hook` never writes stderr and a failed log write never changes its exit; `logs` merges events, process logs and detail files, filterable, emitting torn lines as marked records (per intent F-04; OB §3, §6, D-21; TP §3).
- **v1-05** · Observability gates: no unlogged panic, schema-true lines, no leaked secret — every panic after log init leaves one error line and `hook` still exits 0; every CI log line validates against the committed schemas; a canary never reaches home-level logs and no secret appears in any artifact; product crates cannot print or log outside the sanctioned macro while test-only binaries may; redaction cannot be switched off (per intent F-05; OB §7-§10, D-19).
- **v1-06** · Mutation gate per chunk from chunk 1 — every chunk's diff is mutation-tested in the harness `run` and in CI; a missed or timed-out mutant turns the run red, a missing diff base fails, each guard test is paired with its remove-the-guard mutation, and obs code is mutated like product code (per intent F-06; TP §10).
- **v1-07** · Quality gates: coverage, performance budgets, property/fuzz replay, zero flakes — per-OS coverage meets lines 85 / functions 95 / regions 80, hook deadlines hold on the worst sample, every security-named parser surface has seeded property tests and a corpus replay that fails on an empty corpus, no retries, a flaky test keeps its chunk red, and one `gate` verdict per job treats a missing artifact as a breach (per intent F-07; TP §10; OB §10).
- **v1-08** · Code-graph seeded at setup and built on the first real code — all five code-graph files land at setup with a green health check, the Rust plane reports ok with its database after the first chunk's wrap, and whether a TypeScript plane is active for `e2e-web/` is stated explicitly (per intent F-08; founder direction).

## (b) Architecture amendments the other masters depend on

- **v1-09** · Security's eight amendments folded into the architecture — the architecture carries the per-launch GUI cookie, the per-user 0700 Unix endpoint directory, `not-delivered`/`control-character` ordering with the two new problem URNs, `release-from-driver`, the `ui/<port>.url` file, `MAX_FRAME` 16 MiB, the largest-hook-payload ledger row and `<hash>` = truncated SHA-256, each landing no later than the chunk ordering security names (per intent F-09; S:572-580, S:358-364).
- **v1-10** · CL-1: send issue and outcome are events in the log — every wrapper-accepted send leaves an issue record in the instance's event log, every outcome is recoverable from that log alone, these records never wake `wait`, client-side refusals are visible in the `cli` process log, and page and tests read the same records (per intent F-10; XF X1, T2).
- **v1-11** · The live page sees a dialog clear and state refresh — without polling, the view learns when a pending dialog clears and when liveness, status or the budget reading change, through the same feed that carries events (per intent F-11; XF X2).
- **v1-12** · At most one send in flight per instance — two concurrent sends to one instance can never both be typed; the second is refused or ordered, and every read-back pairs with exactly the send that caused it (per intent F-12; XF X3).
- **v1-13** · Result payloads carry what the CLI prints — every human output line of `release --budget` and `link` is derivable from its machine result, and the `--json`/MCP result carries the same facts (per intent F-13; XF X4, X5, F3).
- **v1-14** · `viola verify` against the fake agent runs in CI — CI test homes are stamped only by `viola verify` run against the fake agent, the real `claude` never runs in CI, and a local-live mode refuses to start under CI (per intent F-14; XF T8).
- **v1-15** · Plan revise is answered as a plan, not a permission — a plan dialog raised by either hook is presented and answered as a `plan` (approve / revise with a message), approve never relies on the ignored PermissionRequest path, and the mapping is one ledger-backed rule (per intent F-15; XF T9).
- **v1-16** · Permission suggestions have a place in the answer — the architecture decides whether a driver can pick an offered permission suggestion; if yes the answer carries it and it takes effect, if no the omission is recorded as a deliberate v1 limit (per intent F-16; XF I1; B R7).
- **v1-17** · Diagnostics roots, sinks and initialisation order — the architecture names both diagnostics roots and every process's sink; the home is created and passes the strict-modes check before any diagnostics file is opened; existing diagnostics files get the same owner, mode and symlink checks; content-bearing detail exists only per instance (per intent F-17; XF O4, O6, B2, B10; OB D-08, D-09, D-22).
- **v1-18** · Every exit-21 and exit-1 cause has a machine-readable code — every cause of exit 21 and exit 1 reaches `--json`, MCP and the process log as a distinct code with no path or pid, matching the human hint for the same cause (per intent F-18; XF X7, T4, F4, B6).
- **v1-19** · Toolchain floor 1.96 — one declared floor is what the workspace states, what the MSRV job checks and what the pinned toolchain provides; the primary toolchain is one pinned current stable; external CLI tools are minimum floors (per intent F-19; XF T14, T15, O5, I2, I3).
- **v1-20** · Obs additions to the channel and config contracts — the channel contract names the optional connection discriminator, older peers still work and it is never identity; `config.json` names the diagnostics level, which changes volume only and never disables redaction (per intent F-20; XF O6).
- **v1-21** · Timing constants named and located — the send-confirmation window, spine-hook deadline, dialog deadline, readiness quiet period and maximum wait, and MCP `wait` default each have one named home, are driven in tests through an injected clock, feed the perf gate, and keep every MCP call below the client's tool-call timeout (per intent F-21; TP §12).
- **v1-22** · `viola ui` on an OS-assigned port — `viola ui` can start on an OS-assigned port and report the bound port through its launch file, so a headless boot never races for a port (per intent F-22; TP §12).
- **v1-23** · The architecture's tree includes the test and obs artifacts — the architecture's workspace, tree and dependency policy include every test, obs and a11y artifact, the tokio ban still holds for every sync crate, and the release build contains no test-only binary (per intent F-23; XF T16, B12, Z15).
- **v1-24** · The statusline source `run` records — the source of the user's statusline command is named, read-only to viola and redirectable per test home, and the wrapped statusline prints the user's output unchanged (per intent F-24; TP §6 Path 6).
- **v1-25** · The PTY dependency pin is decided on current evidence — the chunk that writes the PTY seam records which portable-pty line it uses and why (the Windows defect re-checked), keeping the seam's contract, exit-on-handle detection and non-inheritable handles either way (per intent F-25; XF Y6).
- **v1-26** · Cross-plan fix-pass items honoured by the implementing chunks — each chunk implementing a surface touched by the three fix passes (incl. X8, X10, X11, X13) follows the ratified side and carries the corresponding test, so no shipped behaviour contradicts a master (per intent F-26).

## (c) The thin Windows slice: run / send / wait / answer with delivery confirmation

- **v1-27** · `viola run` wraps the unmodified CLI on Windows — the child's screen and the human's keys pass exactly as without the wrapper with zero bytes of viola's own; the npm shim resolves to the real executable and a `.cmd`/`.bat` child is refused; the parent's identity is stripped; a pinned self-copy and a freshly written plugin are called by absolute path; start follows the documented order; a live or stale name is refused; child exit is detected on the process (per intent F-27; B §3.2.1, R5, R8).
- **v1-28** · Hooks report normalised events and fail open — every registered hook event becomes one normalised event line, harness prompts are classified, paste wrappers and tag escaping normalised away; a hook outside a wrapped session is a silent no-op; any hook failure exits 0 with no output; spine hooks never delay a turn past their deadline (per intent F-28; B R5, M2–M4, M7).
- **v1-29** · `send` types at a turn boundary and is confirmed after the fact — driver text (stdin or file, never a leading-slash argument) is typed as one paste plus Enter only when the input box is ready; it returns read back only on the matching prompt, `not-delivered` with a typed detail otherwise, `unconfirmable` only for a ledger-listed local command; `/clear` is confirmed by its post-condition; a disallowed control character is refused, never stripped (per intent F-29; B R3, M1, M3–M5).
- **v1-30** · `wait` and `last` wake on turn boundaries without polling — `wait` returns the first driver-relevant event at or after a cursor, at once if already logged, never woken by non-driver lines, times out typed, reports an unreachable instance when the wrapper vanishes; `last` returns the newest turn's final text; every send and wait result carries the next cursor (per intent F-30; B §4.1 S5).
- **v1-31** · Dialogs answered through hooks by `dialog_id` — one dialog is pending per instance and appears once with its id; a driver answers a question, permission or plan and the dialog never renders; a second concurrent dialog, a human wheel, an unverified CLI or an expired deadline leave it to the human; an unknown id is refused `unknown-dialog` (per intent F-31; B R7, S3/S7/S8).
- **v1-32** · The wheel: the human always wins, automation is refused with a reason — any human editing key since the last turn boundary moves the wheel to the human (focus, mouse, resize do not), human keys are never blocked beyond the current paste, a pending dialog is handed back at once, harness turns never flip it, `pause` takes it without a keystroke, only a human `release` returns it; drivers are refused `human-typing` (`manual-pause` after `pause`) and no driver hint suggests `release` (per intent F-32; B R2, M2).
- **v1-33** · The slice passes the first live test on Windows, then viola drives its own build — with the product binary an overseer sends a pipeline skill to a builder, waits, reads the final text, answers a review, clears between skills, and the founder's typing takes the wheel; then the overseer switches its own driving from the prototype to viola (per intent F-33; B §6).

## (d) Remaining v1 capabilities

- **v1-34** · Capability ledger, `viola verify`, and transport-only degrade — every relied-on CLI behaviour is a versioned ledger row with a live probe and post-condition; `viola verify` probes, stamps, records scrubbed fixtures and prints a step counter ending in a verdict; on an unstamped version viola types, holds the wheel and logs but withholds dialog answers and refuses drivers `unverified-cli` (per intent F-34; B §4).
- **v1-35** · Budget governor from the statusline — wrapped sessions record usage readings without touching the user's statusline config or output; crossing a threshold (five-hour 90 %, seven-day 85 %) refuses automated sends `budget-paused` while turns and human keys continue; the pause lifts at the window's reset or by a per-instance override; missing readings show `unknown` with their age and never block (per intent F-35; B §5 O8).
- **v1-36** · Links between sessions — a send or answer from inside a wrapped session records a `driver → driven` link once, `link`/`unlink` add or remove one, and the link set with its first-linked time is derived from the log and shown by the board and the page (per intent F-36; B D5).
- **v1-37** · The board: `viola list` and session liveness — `list` works with no live wrapper and shows liveness, status, wheel holder with any budget pause, pending dialog kind and CLI verdict, plus unwrapped sessions as read-only never-targetable rows; human output is the fixed six-column board with the BAY line and escaped single-line rows, and `--json` equals the GUI sessions envelope (per intent F-37; B R6).
- **v1-38** · The MCP server for drivers — a wrapped driver gets `send`, `wait`, `last`, `answer` and `list` as MCP tools with the CLI's results and refusals (codes only), no wheel or link controls, server-side re-validation, and every call below the client's tool-call timeout (per intent F-38; B §3.2.3).
- **v1-39** · CLI contract: machine output, typed exits, cause-named hints — every verb has a `--json` form mirroring the channel result and a typed exit (0, 1, 2, 10–14, 20, 21); human output follows the design phraseology; a global `--home` isolates all state; `config.json` sets thresholds, port and diagnostics level, and no setting switches off a security control (per intent F-39; DS/LT Surface: cli).
- **v1-40** · CLI and terminal output discipline — on all three OSes CLI output is linear and static, colourless under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json`, every colour span beside its word, injected controls shown only escaped, `verify` appends step lines, `ui` prints its launch line once; under `viola run` viola adds zero bytes, human keys pass unblocked during a send, and focus, mouse and resize never move the wheel (per intent F-40; AY P4, P6).
- **v1-41** · Crash-safe, self-healing, version-tolerant state — logs are append-only one-line records never truncated, snapshots are replaced atomically, a torn line or unreadable/newer snapshot heals by replay, unknown kinds and fields are counted and shown, and a newer peer's request is refused with the supported version (per intent F-41; B R4).
- **v1-42** · Optional plugin install for unwrapped drivers — an unwrapped driver can install viola's MCP tools without hooks, calling viola by absolute path; a session with both never runs two hook processes for one event, and which MCP server wins is measured (per intent F-42; A:97).

## (e) Security hardening after the slice

- **v1-43** · Chunk-blocking security prerequisites — the SQOS spike is resolved (or its replacement recorded) before the chunk that writes the channel client, the pure-Rust SHA-256 choice is recorded before the chunk that writes `bin/`, and a failed spike never falls back to an unprotected connect (per intent F-43; S:589-592).
- **v1-44** · The IPC endpoint admits only the same OS user and verifies its server — only the owning user (and SYSTEM on Windows) can connect, remote and other-user peers are rejected, every client verifies the recorded wrapper process before writing a frame (CLI/MCP report unreachable, hooks fail open), a squatted name blocks start, and macOS's missing pid check is recorded as a known gap (per intent F-44; S:202-205, S:472-478).
- **v1-45** · The viola home and its code-bearing files keep their integrity — the home is owner-only, every trusting process refuses a home or file open to others, the pinned binary is re-hashed before reuse, plugin and settings files are rewritten at every start, only `viola verify` writes stamps and only the owning wrapper a snapshot, and the statusline never runs from a failing home (per intent F-45; S:207, S:262-266).
- **v1-46** · Bounded, validated inputs at every boundary — every external reader is size-capped, depth-limited and closed-typed; names are validated before any path join; a bad `Last-Event-ID` pair drops the whole header; the paste rule holds client-side and authoritatively in the wrapper; a terminal-parser panic degrades to `input-not-ready` without harming passthrough (per intent F-46; S:219-240).
- **v1-47** · Sanitised errors and the never-log floor — every error surface carries only codes and fixed messages; no log, diagnostic, fixture, event or a11y artifact holds the GUI token, cookie, launch URL or stripped `CLAUDE*` values; content goes only to owner-readable per-instance detail files; a secret scan after every E2E test proves it (per intent F-47; S:378-389).

## (f) Web UI per design, layouts and a11y

- **v1-48** · `viola ui` serves a loopback, view-only, authenticated feed — loopback bind, own-Host only, GETs only (others 405), health/readiness/info, the sessions and links envelopes and a resumable SSE feed of verbatim event lines, all content behind a per-launch token exchanged once for a strict same-site cookie, security headers and CSP on every response, uncompressed feed, embedded assets only, query-free request logs, one launch line (per intent F-48; B §3.2.4).
- **v1-49** · The strip-bay page — one page shows the ATIS header, the WRAPPED and UNWRAPPED · READ-ONLY racks as native tables in stable order, a cocked strip for a pending dialog, transfer markers for links, and a silent tape with a readback box that changes only on the logged outcome; upstream text renders as text; no horizontal scroll at supported widths; no spinner; out-of-view attention via title and polite announcements; focus never moves or is lost on updates; CLI board and page agree cell for cell (per intent F-49; DS/LT Surface: web-spa; AY D-A11Y-02/03).
- **v1-50** · Automated accessibility verdict on every page state — every web-spa state passes the a11y configuration with zero violations and zero contrast-incomplete items; the keyboard sequence equals the oracle with no trap and focus never obscured; only defined messages are announced, once each; every applicable success criterion has a passing tagged test; template lint errors fail the build; violation rows stay scrubbed in test artifacts with no CSP or Trusted Types violation (per intent F-50; AY §3, §9-§10).
- **v1-51** · Token-pair contrast, forced colours and reduced motion hold — every text token pair meets 4.5:1 and every non-text state pair 3:1 on the rendered Linux fallback, no failing ink sits on the holder surface, forced colours keep every state distinguishable, and reduced motion drops both motions to zero while position and band remain (per intent F-51; AY §6).
- **v1-52** · The 401 access strip after a UI restart — a page whose cookie no longer matches the running `viola ui` shows the access strip in place of the stopped tape, announces it once, states the recovery in plain words, and never shows or echoes the token, URL, `?t=` or file path (per intent F-52; XF X9; AY P5).

## (g) Cross-OS completion

- **v1-53** · Linux and macOS reach parity with Windows — on Linux and macOS the same end-to-end suite passes against the fake agent (openpty, per-user socket directory, file modes, peer and server checks, macOS gap recorded), Windows remains the live-supported target, and one live `viola run` on Linux confirms the fake agent's Unix behaviour before the Unix-specific chunk lands (per intent F-53; B D3, §5 O5).
