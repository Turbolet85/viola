  No other call form reaches a compositor, but `lock-read` below.

  the desktop signature taken from the session's own environment. At the first reading an IPC error from the shell
  is recorded as `no-answer` (it may be relaunching). At the second the shell's answer is polled for up to 30 s.
  `false` from either, at either reading, or no shell answer at the second: S6. This is the only call that names

  path; `--font=monospace:size=<n>`, no padding. It refuses when the own instance already holds a window.
- `guard <class>`: the own compositor is alive (pid and start time), the own instance is not locked, it holds
  exactly one window, of that class, and its active window's address is that window's.
- `key <class> <text>`: `guard`, then `wtype <text>` on the own socket; nothing is typed when the guard fails (S3).
- `close <class>`: ends that window's own foot process by pid and reads it gone.
- `end`: reads the own compositor's runtime dir from its environment, ends it by pid, reads it gone.
