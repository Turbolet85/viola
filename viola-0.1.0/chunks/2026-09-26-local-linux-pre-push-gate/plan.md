## Goal
The goal is to catch Unix reds before the push (founder ruling, overseer direction 1). This is a new internal
`viola-harness` subcommand, `pre-push`, run from this Windows host, and it does four things:
- It syncs a history-carrying clone in WSL2 `Ubuntu`'s Linux filesystem from the Windows working tree,
  uncommitted and untracked files included.
- It runs the ubuntu test job's own suites there (`run --coverage` + `gate --require coverage,doctest`).
- It runs the `ubuntu-latest` mutation leg there, and the `windows-2025` leg on the host.
- It judges both legs with CI's own union (`gate --require mutants --mutants-legs ubuntu-latest,windows-2025`).

The result is one JSON document with a typed exit, and a red stops the push. A provisioning script installs the
toolchain inside Ubuntu at CI's pins. The harness verifies those pins on every run, and they never float.

One base-rule fix makes the local legs print CI's `base`. Before the pre-CI commit, HEAD is the last wrap flip, so
the derived base stepped back to HEAD^ (scope item 4, `premise-corrected`). The rule now skips that step while a
promoted chunk is uncommitted, and the fix also corrects /implement's local Windows leg.

The work is test-side only: `viola-e2e`, `scripts/`, chunk evidence (per architecture §Established Decisions
[Module Boundaries]; test-plan §3 Internal harness subcommands / `run` step 4; security-plan §Dependency Security;
obs-plan §9, §11). Operator rulings at P4 (2026-09-26), all four recommendations:
- fix the base rule;
- the union of both legs;
- CI test-job suites;
- project-side wiring, with the Andromeda `plan-template.md` change recorded as a proposal in evidence for the
  overseer to relay. A project chunk never edits Andromeda.

          `git write-tree` (the tree id) → `git diff --cached --binary --no-color --no-ext-diff HEAD` into
          `target/pre-push/tree.patch`. Run git with `-c core.safecrlf=false` and no stderr on stdout. The real index
          is never touched.
        - Clone `<home>/viola-pre-push`: `git clone --no-hardlinks <src>` when absent, where `<src>` is

     8. `union`. Both documents' `mutants.base` must be equal, else `reason:"base-mismatch"`. Then
        `gate(&ws.artifacts(), &ws.root, &["mutants"], Some(&["ubuntu-latest", "windows-2025"]))`, whose document is
        the stage's verdict.

## Constraints & rejected approaches
- rsync from `/mnt/d`: rejected. It is slower (9.85 s / 2.74 s against 4.47 s / ≈0.9 s) and carries every git-ignored
  file (local homes, `.url` token files) unless excluded by hand (research M8; security extract).
- A checkout on `/mnt/d` (drvfs): rejected. Unix modes and the per-user 0700 checks need a real Linux filesystem
  (security extract; scope item 2).
- The `wsl -d Ubuntu -- …` form: rejected. It re-parses argv through the distro shell (research M2). Every call is
  `--exec`.
- Inheriting the WSL environment: rejected. It carries the Windows PATH, and a future `WSLENV` could carry `CLAUDE*`
  (research M4/M5).
- Setting `AGENT_RUN_CHUNK_BASE` from the gate, or deriving the base outside `resolve_base`: rejected. It would split
  the local legs from CI (arch extract).
- Judging the Linux leg alone: rejected (operator ruling). A `--leg` run defers survivors (run.rs:122), and a single
  named leg judges `#[cfg(windows)]` bodies (gate.rs:144-149).
- A sync over a listener (git daemon, rsync daemon, sshd): rejected (security extract, listener ban in spirit).
- Any retry of a red stage or leg: rejected (obs-plan §11 SLO; test-plan §11).
- Editing Andromeda's `plan-template.md` or any pipeline file: rejected (operator ruling). It is a proposal in evidence.
- Running `pre-push` in CI, a macOS leg, a `ci.yml` change, and any product-crate change beyond the pump baseline of
  steps 11–12: out of scope. CI stays the verdict of record; the local gate is a filter (scope §Boundaries;
  test-plan §11 "never treat a Linux-only local run as proof").
- Applying the pump fix without the instrument's confirmation, or reading "it went green" as the cause: rejected
  (operator ruling at implement). A timing-based window test (a sleep, a race to win): rejected; the window is
  forced by the size closure.
- Shipping the instrument: rejected. A product file written outside the declared sinks breaks the obs contract
  (observability.md §Sinks); it is removed whole at step 11.
- `#[cfg(unix)]` / `#[cfg(windows)]` bodies in `pre_push.rs`: rejected. One body per OS keeps both legs judging every
  line (verification-harness.md 2026-09-25; the carried 0.8 learning — the host gate is a const).

## Implementation notes
- **Leg name.** The Linux leg is exactly `ubuntu-latest`, the unix+linux family (cfg_legs.rs:24). A bare `ubuntu`
  would fall to "unknown family keeps the leg".
- **Empty patch.** `git apply` refuses empty input ("No valid patches in input"), so skip the apply when the Windows
  diff has 0 files. The tree-id check still runs.
- **CRLF warnings.** `git add -A` under the temp index warns per `w/crlf` checkout-artifact file (research M8: those
  files normalise to their HEAD blobs). Run with `-c core.safecrlf=false` and keep stderr off the document.

  anything else as `linux-document-unreadable`, never a pass.
