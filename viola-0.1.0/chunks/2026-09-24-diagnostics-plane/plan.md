## Goal
Turn the walking skeleton's hand-rolled role logging into the diagnostics plane obs-plan §3 describes. That means a closed
`ObsEvent` / `ObsProcess` vocabulary and the one sanctioned `obs_event!` macro in `viola-core`, a root-bin `viola::obs`
that owns the per-role JSON sink, and a `config.json` `diagnostics_level` read (the only level knob, never
`RUST_LOG`). It also means owner-only per-instance detail files that finally receive the panic payload and backtrace,
plus two committed line schemas (`diag-line.v1.json`, `diag-detail.v1.json`). The harness `logs` merge gains the
detail source (per obs-plan §3 Logging stack / Log format / Snapshot integration, §6, §7, §8; test-plan §3 Log format
and `logs`; security-plan §Bootstrap `logging-redaction-wire`; architecture §Cross-cutting Patterns → Config management).

Research found most of the builder chain already in place. `src/run/mod.rs:65-80` already sets every mandatory
builder setting, and `viola_core::{SERVICE_NAME, VERSION}` exist at `crates/viola-core/src/lib.rs:3-4`. What is missing is
the vocabulary, the macro, the detail sink and the level read. The chunk is therefore mostly a move plus a migration:
the six raw `tracing::info!/error!` sites in `src/run/mod.rs:83-148` become `obs_event!` calls whose `process` /
`instance` come from a process-global context, and `process-exit{subject:"self"}` gains `duration_ms` (CARRY).

The chunk also closes two pieces of carried work. First, the Rust gate deferral from
2026-09-24-supply-chain-and-workflow-gates is closed by running the unit suite on a real `.rs` delta (PREREQ).
Second, the operator-relayed repair of the `.claude/settings.json` PreToolUse write guard is folded in. P3 measured
that the guard blocks nothing under Git Bash and verified the fix. A repo-local regression probe proves the fix,
chosen by the operator at P4.

   `crates/viola-core/src/lib.rs`.
   - `ObsEvent`: a closed enum with exactly the 19 values of obs-plan §3 Log format (`obs-plan.md:650-656`): `channel-request`,
     `channel-response`, `dialog-raised`, `dialog-answered`, `hook-invoked`, `hook-decision`, `send-issued`,
     `send-confirmed`, `send-refused`, `release-from-driver`, `process-start`, `process-exit`, `http-request`,

     `as_str()` are kebab-case. There is no `a11y-violation` variant.
   - `ObsProcess`: `run|hook|mcp|ui|cli` with a kebab `Display`/`as_str()`.
   - `ProcessCtx { process: ObsProcess, instance: Option<ViolaName> }`, held in a private `OnceLock` with a setter
     (`set_ctx`, first call wins, returns whether it took) and a getter (`ctx() -> Option<&ProcessCtx>`).
   - No new dependency in `crates/viola-core/Cargo.toml`.
2. **`obs_event!`** — a `#[macro_export] macro_rules!` in the same module.
   - It takes a level, an `ObsEvent` path, an optional `corr` and additive `key = value` fields. It expands to a block
     whose inner `::tracing::event!` statement carries `#[allow(clippy::disallowed_macros)]`.
   - It attaches `event = <ObsEvent>.as_str()`, `process` and `instance` from `ctx()`, and `corr` as a typed value,
     never `?`/`%`. An absent `instance`/`corr` is an `Option::None` field, so the key is absent.
   - The message is the event's static literal.
   - The `::tracing` path resolves in the calling crate; `viola-core` does not name tracing in its manifest.
3. **`MAX_FRAME`** — add `pub const MAX_FRAME: u64 = 16 * 1024 * 1024;` to `crates/viola-core/src/lib.rs` (the 16 MiB
   cap, per security-plan §Input Validation, CLAUDE.md module map). Its first consumer is step 5's config read.

   - Absent file → INFO, no rejection.

## Acceptance Criteria
- (obs/tests) Every line `viola run` writes to `<home>/diagnostics/run-<name>.ndjson` has the following properties,
  witnessed by `binary(contract_diag_schema)`:
  - It validates against `schemas/diag-line.v1.json`, and `message` equals `event`.
  - `corr`/`instance` are never a literal `null`.
  - `process-start{subject:"self"}` carries `service_name:"viola"`, `version`, `os`, `pid`.
  - (per obs-plan §3 Log format JSON schema; §8 Default-deny posture; test-plan §3 Log format)
- (obs) `process-exit{subject:"self"}` carries `duration_ms` on the success and the internal-error path, witnessed by
  `run_self_exit_carries_duration_ms` (per obs-plan §6 Additive field catalog).
- (tests/a11y) The schema's `event` enum and `ObsEvent`'s `Display` values each equal the literal 19-value list of

## Constraints & rejected approaches
- **A product-side panic trigger** (an env var, a hidden flag or a feature-gated verb that panics the real binary) is
  rejected. Env vars and flags are not a configuration channel and may not alter controls (architecture
  §Cross-cutting Patterns → Config management; CLAUDE.md Critical Warnings). The panic routing is proven in-process
  (`src/main.rs:172-197` pattern).
- **A `v` key on diag lines** is rejected. The obs-plan §6 catalog does not name it and §8 makes an uncatalogued key a
  G4 failure. The schema filename carries the version (`diag-line.v1.json`).
- **tracing-appender, `EnvFilter`, `env-filter`, `RUST_LOG`, a stdout default writer** are all banned (obs-plan §11
  Logs; `deny.toml` feature bans).
- **Pre-clap argv role classification** is deferred to the hook chunk. With `run` as the only verb, every caught panic
  exits 1. Classification decides the hook's exit-0 path, which has no producer yet (obs-plan §7 Main-thread catch
  site).
- **The three-OS concurrent-append check (obs D-28)** is deferred to the first shared-writer producer (hook). No
  product path has two writers on one file today: there is no `already-live` collision yet, and `detail-run` has one
  writer (research.md §Open questions).
- **Strict-modes check of the home before the diagnostics open** belongs to *Home and code-bearing file integrity*,
  not here. This chunk keeps the skeleton's create-then-narrow behaviour.
- **Role-file naming for hook/mcp/ui/cli is exercised by unit tests only.** No producer is added for those roles.
- **No oracle import:** tests pin the 19 event values as literals and never iterate `ObsEvent` to build the expected
  list (test-plan §11 Unit).
