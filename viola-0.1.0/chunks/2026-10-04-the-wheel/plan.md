## Goal
The wheel becomes real. Today `viola run` writes `wheel{holder:driver,cause:start}` once and nothing can move it (`src/cmd/run.rs:392`, `:401-410`). This chunk lets the human take it by typing. Every human editing key read from `viola run`'s stdin moves it to `human`, while focus reports, mouse reports, terminal replies and host resizes never do. `viola pause` takes it without a keystroke, and only `viola release` returns it. Under a human wheel, automated `send` and `answer` are refused `human-typing` (detail `manual-pause` after a pause), `hook.dialog` is answered `null` at once, and a dialog already pending is handed back to the human at once (architecture §Established Decisions [Human Takeover / Wheel]; security-plan §Authentication & Authorization, "Driver-originated `release`"; obs-plan §4 Scenario "Human takes the wheel…"; test-plan §6 Path 5).

viola stays mechanism. The wheel is byte provenance plus an explicit CLI verb, and it never decides an answer. The classifier is agent-neutral and lives in the root bin. The human's bytes are never held, refused or delayed: classification is a side observation on the stdin stream, and the existing `PasteHandle` lock (`crates/viola-pty/src/pump.rs:58-108`) remains the only hold.

The chunk also does three more things:
- It lands the two CARRYs from the 2026-09-25 Windows wrapper:
  - The `^Z` CARRY is source-read at the pinned 1.98.1, where it is wider than carried: any console read ending in `0x1A` loses that byte, and a read of `^Z` alone ends the human→child copy. It is fixed in viola-pty's Windows stdin and witnessed on `windows-2025`.
  - The ConPTY focus-report hypothesis is measured by the same outer-PTY case.
- It adds the human-wheel row to the "no setting disables a control" table.
- It folds the founder-ruled U40 `andromeda:walks-tree` mark into the three `fixtures/claude/*` walkers.

5. **The wheel and its stdin observer** (new `src/run/wheel.rs`; `src/run/mod.rs`).

      - A move to `human` also hands the pending dialog back (step 7).
   2. **Transitions.**
      - human editing key → `human` / `human-input` (no change while already `human`, whatever the cause);
      - an unsent `prompt-submitted` with `origin:"human"`, while `driver` → `human` / `human-input` ("an unsent `prompt-submitted` confirms and logs the take"). An `origin:"harness"` prompt, and the in-flight send's own prompt relabelled `driver` (`src/run/send.rs:132-150`), never move it;
      - `pause` → `human` / `manual-pause`;
      - `release` → `driver` / `release`;
      - `release` with `budget:true` → no change.
   3. **The byte classifier** (F-W2). A bounded state machine over the stdin byte stream that carries an unfinished sequence across reads.
      - Ground bytes are editing.
      - `ESC` starts a sequence. A sequence that completes as one of F-W2's non-editing forms is not editing; any other completed sequence is editing.
      - A sequence past its bound (64 bytes of parameters or payload) is editing and resets the machine.
      - A read that ends on a lone `ESC` counts it at once as the Esc key, an editing key, since the human's Esc must take the wheel without waiting for a next read. A sequence already past `ESC [` / `ESC ]` / `ESC P` / `CSI M` carries over.
   4. **The observer.** A `Read` wrapper around the host stdin, mirroring the output `Tee` (`src/run/gate.rs:130-140`).
      - Each `read` returns the inner bytes unchanged and in full. Before returning, if the chunk held an editing key and the holder is `driver`, the wrapper flips the holder in memory (so a `send` that checks after this read is refused).
      - The disk work (event, snapshot, dialog hand-back) runs on a wheel worker thread fed by a channel, so no human byte waits on disk I/O.
      - No per-byte span or line (observability.md "No per-byte or per-line logging in hot loops"), and the keystroke bytes reach no log, span, event or detail line (obs-plan §8).
   5. **Wiring.** `pump_child` (`src/cmd/run.rs:447-491`) passes the observer, wrapping step 9's host stdin, as `pump_with_paste`'s `input` (`:470-472`). No viola-pty pump change.

## Constraints & rejected approaches
- A classifier inside viola-pty's pump — rejected. `pump_with_paste` already takes any `Read` (research.md), and viola-pty must not learn the wheel.
- Holding or buffering human bytes until a sequence is classified — rejected. The human is never delayed past the current paste (CLAUDE.md invariant 1). Classification only observes, and a trailing lone `ESC` counts at once.
- Writing the `wheel` event and snapshot on the stdin thread — rejected. Disk I/O would delay the human's next byte, so the in-memory flip is synchronous and the disk work is the worker's.
- Appending `wheel` through the wait feed — rejected. It is log-only and must not wake `wait` (architecture §Standard Contracts).
- A fake-agent mode emitting `<agent-message from=` — rejected. The wheel reads `origin`, and the prefix set is unit-proven at the hook layer.
- An MCP `pause` / `release` tool, a `--budget` CLI flag, `--help` grouping, a GUI brake route — out of scope (architecture [MCP]; `:91`; `:100`; v1.x).
- A new fake-agent or wrapper test seam (for example, to stall a paste) — not added. A third seam is a boundary widening needing a Decisions Log ruling (security.md); the existing receipts and the outer PTY suffice.
- `release` emptying the in-flight send slot — rejected. That slot belongs to a live `send` (research.md §Mechanisms).
- `#[ignore]`-parking the Windows focus or `^Z` cases — forbidden (test-plan §10). A Windows red folds into this chunk.
