Host: Linux, btrfs `/home`, 32 threads, 62 GB. `-j`: cargo-mutants' default (one mutant at a time). The arm passes no

## Where the copy goes (overseer direction, founder-delegated)
- **Run 1 died on the `/tmp` quota.** cargo-mutants copies the tree, `target/` included, into `std::env::temp_dir()`.
  Here that is `/tmp`, a 32 GB tmpfs with `usrquota`. The copy plus build growth hit `Disk quota exceeded (os error 122)`
  after 460 of 709 mutants. **25 of that run's 77 unviable carry the quota error in their logs**, plus one caught. The
  overseer ruled: every mutation run from now on uses `TMPDIR` on btrfs, the died unit is re-run in full, and partial
  outcomes are never merged. Run 1 is discarded whole: its 5 missed are disposed of below, but none of its counts are
  used.
- **Run 2 broke its baseline on btrfs.** `mutants-exit-4`: 32 failed, each `EACCES` spawning the copied tree's
  `target/mutants/debug/viola-fake-agent`. The cause, read in the pinned versions' source:
  - cargo-mutants 27.1.0 `copy_tree.rs` `copy_file` tries `reflink::reflink` first and falls back to `fs::copy` only
    after a reflink fails.
  - `reflink 0.1.3` `sys/unix.rs` creates the clone with `OpenOptions::create_new` and copies no mode.
  - So on btrfs, where the clone succeeds, every copied file is 0644. A prebuilt root binary that cargo never rebuilds
    in a viola-e2e-scoped run (`viola-fake-agent`) loses its exec bit.
  - On tmpfs the clone is unsupported, so the fallback copy keeps the mode. That is why P3's 245/245 baseline passed
    there.
- **The fix is environmental, with no code change.** The scratch dir is marked NOCOW (`chattr +C`; new files and dirs
  inherit it). btrfs refuses to clone a COW file into a NOCOW one (EINVAL), so the first reflink fails and
  cargo-mutants copies with `fs::copy` for the rest of the run. Two-sided probe, same day:

  | probe | target | result |
  |---|---|---|
  | raw `FICLONE` into a `create_new` file (what `reflink 0.1.3` does) | an ordinary btrfs dir (`target/`) | clone succeeds, new mode **0644** (source 0755) |
  | `cp --reflink=always` | the NOCOW scratch | `failed to clone … Invalid argument`, nothing left behind |

  Runs 3 and 4 used the NOCOW scratch. Their logs carry no quota or EACCES line, and run 3's copy reached 12 GB in its
  first 26 s by the plain copy.
