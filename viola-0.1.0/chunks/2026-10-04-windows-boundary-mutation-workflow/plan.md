## Goal
Give the project's `cfg(windows)` code a mutation score at every epoch boundary, now that the dev host is Linux and only
the `windows-2025` runner compiles that code. The founder's ruling C2 (2026-10-04, relayed by the overseer) fixes the
form: a `workflow_dispatch`-only, non-blocking workflow on the windows runner, run during the boundary audit, keeping the
2026-09-28 ruling (no mutation entry in a chunk gate, no pre-push leg, no blocking CI job). The workflow drives the
harness's own boundary verb, `run --mutants --package <member> --file …` (test-plan §3 `run` step 4), one matrix job per
package, over the source files that carry a Windows gate. A root contract test keeps that file list complete as Windows
code grows ("and later ones").

Its first dispatch, in this chunk's operator pass, grades the 34 mutants the previous chunk could not measure on Linux
(2 viola-e2e `prepare`, 10 viola-pty, 13 viola-channel, 9 `src/panic_frames.rs`): each one caught, unviable with its
reason, or missed and then killed by a Windows test. None is counted caught before that run.

It also fixes the mutation run's temp-dir leak at its mechanism. The nextest `mutants` profile's
`terminate = "immediate"` kills running tests before their `TempDir` drops. P3's two-sided witness measured
170 leftovers under the committed profile against 0 under `--max-fail=1:wait`, same file and same 10/10 caught.
`terminate = "wait"` is the fix, and the slow-timeout kill (5 s × 2; viola-e2e 15 s × 2) still bounds the
post-failure tail below cargo-mutants' 20 s floor. Provenance: architecture §Infrastructure Patterns → CI/CD
approach · security-plan §Dependency Security (CI integration) · test-plan §3 `run` step 4, §9 Mutation row,
§10 Mutation gate · obs-plan §8 item 6, §9 Mutation row.
