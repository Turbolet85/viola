## Constraints & rejected approaches
- A `viola_e2e::fixtures` copy of the root chain for Path 1 — rejected at fork 1 (`inputs#I1`): about a thousand
  lines mirrored by hand for steps the root chain already holds.
- A fixture-owned supervisor thread — rejected at fork 2 (`inputs#I1`): its pid is the test process, so `cleanup`'s
  `processes_gone` could not read true.
- An rstest `harness_session` — `viola-e2e` has no `[dev-dependencies]` (testing.md §Naming).
- A `ci.yml` edit for the E2E suite — CI's `run --coverage` already runs every binary, and `gate::SUITES` already
  holds `nextest-e2e`.
- Moving Path 1's root cases into the flow — the cases stay as they are; the flow is additive.
- Writing `budget.json`, `snapshot.json` or `stamps.json` by hand anywhere (testing.md §Test data), or feeding
  through `hook statusline --capture` (security-plan, the capture arm is verify's alone).
- `sleep` for synchronisation, or a retry for the WATCH red — never (test-plan §10 Zero-flakiness budget).
- Editing a product crate to make a leg pass — a leg red that needs product code is a red folded into this chunk,
  raised at implement, not silently patched.
