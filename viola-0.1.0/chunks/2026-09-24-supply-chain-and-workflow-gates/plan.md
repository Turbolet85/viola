## Goal
Give viola its dependency policy and workflow gates. A root `deny.toml` covers all four cargo-deny families
(advisories · licenses · sources · bans), including the C-crate, telemetry-crate and feature bans. The feature bans are
the redaction toggle `veil/toggle`, `rmcp` `auth`/`transport-streamable-http-server`, `axum/http2` and
`tracing-subscriber/env-filter`. Sources: security-plan §Dependency Security (deny.toml additions), obs-plan §3
otel-sdk-install and §8 PII Scrubbing (D-19), and §9/§11 Logs (D-15). Tokio containment is the KEYSTONE
(architecture §Established Decisions [Concurrency]). It is enforced two ways. First, a dedicated tokio-ban config
is run once per sync crate as the sole root of its graph, for the three runner triples. Second, a per-OS `cargo
check` of the sync crates runs without viola-channel's feature (architecture §Infrastructure Patterns → Build
system, CI jobs 3-4).

Every ban is proven live in CI by a permanent negative-probe script, alongside the green gate. A ban on a crate absent
from the graph prints nothing, so a green gate alone cannot tell a working ban from a missing one (operator decision
at P4: "a ban that cannot be seen failing is a vacuous gate"). `ci.yml` gains the per-OS tokio-free check and an ubuntu
supply-chain job: deny + probes + zizmor, with JSON artifacts. A new `nightly.yml` runs the weekly `cargo deny check
advisories` (operator decision at P4: test-plan §9 Platform owns CI layout). Every workflow keeps the least-privilege
shape `ci.yml` already has (security-plan §Dependency Security, CI integration; test-plan §9).

   §Measured facts). Record both `--version` lines in the chunk evidence.
2. **Write `deny.toml` at the repo root** (architecture §Infrastructure Patterns tree):
   - `[graph] targets` = `x86_64-pc-windows-msvc`, `aarch64-apple-darwin`, `x86_64-unknown-linux-gnu`.
   - `[advisories]`: `unmaintained = "all"`, `unsound = "all"`, `yanked = "deny"`, and exactly one
     `ignore = [{ id = "RUSTSEC-2017-0008", reason = … }]`. The reason names `serial` via portable-pty `=0.8.1` and says
     serial ports are never opened.
   - `[licenses]`: an explicit `allow` list that is exactly what today's graph needs, plus
     `private = { ignore = true }` (every member is `publish = false`).
   - `[sources]`: `unknown-registry = "deny"`, `unknown-git = "deny"`.
   - `[bans] deny` entries, each with a `reason` citing its cause: `cc`, `libsqlite3-sys`, `openssl-sys` (no C in the
     build); `opentelemetry-otlp`, `opentelemetry-stdout`, `sentry` (no reporter / egress); `tracing-appender`
     (`non_blocking` drops lines).
   - `[[bans.features]]`: `veil` → `toggle`; `rmcp` → `transport-streamable-http-server`, `auth`; `axum` → `http2`;
     `tracing-subscriber` → `env-filter`.
   - No `tokio` entry, no `wrappers`, no `skip`/`allow` exception.
3. **Write `deny-sync.toml` at the repo root.** It holds only the tokio ban: `[bans] deny = [{ crate = "tokio", reason = … }]`,
   the same three `[graph] targets`, and `exclude-dev = true`. It is a separate file because the workspace
   `deny.toml` cannot ban tokio, which `viola-mcp`/`viola-ui` will legitimately use.
4. **Write `scripts/sync-crates.txt`.** It is the single list of sync crates, one package name per line, and holds
   `viola-core` today. Each later sync crate joins by one line. Its readers treat an empty list as a failure.
5. **Write `scripts/deny-probes.sh`** (bash, fail-closed, `set -euo pipefail`). It is the permanent proof that every
   ban fires.
   - Preflight: `cargo deny --version` must succeed, else print `tool-missing: cargo-deny` and exit 1.
   - Scratch root: create a fresh, uniquely named scratch dir under `target/deny-probes/` for each invocation.
   - Probe shape: for each probe, write a throwaway Cargo project whose manifest carries its own empty `[workspace]`
     table, so it is not captured by the viola workspace. It depends on exactly the banned crate or feature. Generate
     its lockfile and run `cargo deny --config <repo config> --manifest-path <probe>/Cargo.toml check bans`
     (cargo-deny 0.20 takes `--config` as a global option before `check`; `check -c` is gone).
   - A probe passes only when the exit is non-zero AND the output carries the expected diagnostic:
     `error[banned]` for a crate ban, `error[feature-banned]` for a feature ban. A config or tool error is therefore
     a FAILED probe, never a pass.
   - The 13 probes:
     - tokio under `deny-sync.toml`;
     - under `deny.toml`: `cc`, `libsqlite3-sys`, `openssl-sys`, `opentelemetry-otlp`, `opentelemetry-stdout`,
       `sentry`, `tracing-appender`, `veil/toggle`, `rmcp/transport-streamable-http-server`, `rmcp/auth`,
       `axum/http2`, `tracing-subscriber/env-filter`.
   - Control: a clean project must pass `check bans` under both configs (exit 0).
   - Output: one line per probe. The last line is exactly `deny-probes: 13/13 banned, control clean` on success. Any
     failure exits 1 and names the probe.
6. **Edit `.github/workflows/ci.yml`: add job `lint`.** A per-OS matrix `[windows-2025, macos-latest, ubuntu-latest]`,
   `permissions: contents: read`. Steps: checkout (`persist-credentials: false`), `rustup toolchain install`,
   rust-cache, then a `shell: bash` step that:
   - reads `scripts/sync-crates.txt`;
   - fails if the list is empty;
   - runs `cargo check` with one `-p <crate>` per listed crate and no `--features`.

   This is CI job 3 (architecture §CI/CD approach; test-plan §9 Lint row). A listed but absent package makes cargo
   exit non-zero, so the job never passes vacuously.
7. **Edit `.github/workflows/ci.yml`: add job `supply-chain`.** `runs-on: ubuntu-latest`, `permissions: contents: read`.
   - Setup: checkout (`persist-credentials: false`), `rustup toolchain install`, rust-cache. `cargo-deny@0.20.2` goes
     into the SHA-pinned `taiki-e/install-action` `tool:` list, and `cargo install --locked zizmor@1.30.1` is its own
     step (test-plan §9 tool paragraph). Version self-checks `cargo deny --version` / `zizmor --version` run before the
     gates (obs-plan §9 G1 shape).
   - Separate fail-closed `shell: bash` steps, in this order:
     1. `cargo deny --format json check`, all four families, with its JSON saved under `target/supply-chain/` (CI job 4);
     2. the sole-root tokio ban for every crate in `scripts/sync-crates.txt`: `cargo deny --config deny-sync.toml
        --manifest-path crates/<crate>/Cargo.toml check bans`, with the empty-list guard;
     3. `bash scripts/deny-probes.sh`;
     4. `zizmor --format=json .github/workflows/`, with its JSON saved under `target/supply-chain/`.
   - Last: an `if: always()` SHA-pinned `actions/upload-artifact` of `target/supply-chain/`, `retention-days: 7`
     (test-plan §9 Test report format).
   - The job adds no new action: only the four already pinned (security-plan §Dependency Security pinned set).
8. **Write `.github/workflows/nightly.yml`.**
   - Triggers: `on: schedule` (one weekly cron) + `workflow_dispatch`. Workflow `permissions: {}`.
   - One ubuntu job `advisories`, `permissions: contents: read`. Steps: checkout (`persist-credentials: false`),
     `rustup toolchain install`, taiki-e `cargo-deny@0.20.2`, `cargo deny --version`, then `cargo deny check
     advisories`.
   - No cache of any kind (test-plan §9 Cache column / §11 CI), and no event-payload value in any `run:`.
   - The repo's default branch is `build/viola-0.1.0`, so both triggers are live on push (research.md §Platform issues).
9. **Run zizmor over every workflow and fix every finding at its cause**, keeping the least-privilege shape. Findings on
   HEAD's `ci.yml` are unmeasured (research.md Open questions). A finding is never silenced with a zizmor config,
   ignore comment or persona change. If a finding cannot be fixed within this chunk's boundaries, surface it to the
   operator.
10. **Run the local gates below.** Then hand the tree to the operator for the commit + push and the `nightly.yml`
    dispatch that the CI-witness entries read.

## Constraints & rejected approaches
- `cargo deny --exclude viola-mcp …` or `[graph] exclude` for the tokio ban: rejected. Measured false-fail: workspace
  feature unification keeps a shared crate's optional tokio feature on after the enabler is excluded (research.md).
- A cargo-deny `wrappers` allowlist for tokio (test-plan L1617 "added to the cargo-deny tokio wrappers list"):
  rejected. It is a direct-parent allowlist, which architecture §Build system rejects. Under sole roots `viola-e2e` is
  simply not a root.
- A tokio entry in the workspace `deny.toml`: rejected. `viola-mcp`/`viola-ui` will legitimately use tokio.
- A one-time local ban proof: rejected by the operator. A ban no gate sees failing is vacuous.
- A `schedule:` trigger on `ci.yml`: rejected by the operator. Every job would need a schedule guard.
- A cache in `nightly.yml`, a toolchain action, a new third-party action (`cargo-deny-action`, `zizmor-action`), a
  mutable `uses:` ref: forbidden (test-plan §9/§11 CI; security-plan §Security Anti-Patterns).
- Silencing a zizmor finding, or adding any `[bans] skip`/`allow` exception or a second advisory ignore to reach
  green: forbidden (test-plan §11 Quality; obs-plan §11 "a skip counts as admitting it").

## Implementation notes
- The probe projects live under the gitignored `target/`, but cargo walks up to the viola root `Cargo.toml`. Each probe
  manifest therefore carries its own empty `[workspace]` table (research.md scratch probes used a separate root).
- The probe projects resolve real crates from crates.io, so the script needs the network. An offline host fails the
  probes loudly, which is correct; it never skips them.
- The licence allow-list at HEAD, from the draft run (research.md, cargo-deny 0.19.4): `MIT`, `Apache-2.0`, `Zlib`,
  `Unicode-3.0`. `MIT-0` was unmatched (`warning[license-not-encountered]`). Re-derive it under 0.20.2 and keep the
  list minimal.
- `warning[advisory-not-detected]` for RUSTSEC-2017-0008 and `warning[duplicate]` for `syn` are warnings at HEAD
  (draft exit 0). Neither may be promoted to `deny` in a way that turns the gate red today.
- The deny JSON goes to stderr in cargo-deny's JSON mode. The redirect must keep the step's exit code as the verdict:
  no `|| true`, and no pipe without `pipefail`.
- Channel-root limit (research.md): once `viola-channel` exists and `viola-mcp` enables its `tokio` feature,
  `viola-channel` as its own sole root false-fails, because `cargo metadata` unifies its features. It is then covered
  as a dependency of the other sync roots. Wrap carries this to the channel chunk.
