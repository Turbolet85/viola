## Goal
Land viola's first driving verb. `viola send <name>` reads a driver's text from stdin or `--file` and refuses a disallowed control character before any frame. It finds the live wrapper and asks it to type the text as ONE bracketed paste + Enter. The wrapper re-validates the text and lets one send in flight at a time. The readiness gate (landed 2026-10-04) runs as a partial gate: a poisoned model, a full feed queue and a screen not quiet within `GATE_MAX_WAIT` refuse; the signature read is skipped while no signature row is compiled. Then the wrapper logs `send-issued` at the pre-paste cursor, types, and confirms after the fact: the matching `prompt-submitted`, relabelled `origin:"driver"`, inside the confirmation window. Otherwise the send is `not-delivered` with a typed detail. Every outcome is a CL-1 record in `events.ndjson` (v1-10's issue/outcome shape) and a codes-only `send-*` line. The human sees the `[RB]` readback mirror with per-reason hints; `--json` returns the channel result.

Sources: architecture [Delivery Confirmation], [Screen Model], §Conventions `RefusalReason`, §Standard Contracts "Channel methods"; security-plan §Input Validation (paste text, PTY output row); obs-plan §4 Scenario "Confirmed `send` (CL-1)", §6, §7; test-plan §6 Path 2 and Chaos, §5; layout-templates §Output structure — `viola send`; design-system cli pattern 2.
