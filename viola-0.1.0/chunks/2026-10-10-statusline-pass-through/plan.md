## Goal
A wrapped session records the usage reading its status line carries, and still shows the user's own status
line. `viola run` (and a passed `viola revive`, which starts through the same start) reads the user's statusline
command from one named source, records it in the instance snapshot, writes a per-session settings override that
puts `viola hook statusline` in the status line's place, and passes that override to the child. `viola hook
statusline` writes the `rate_limits` reading to `budget.json`, runs the user's command with the same stdin and
prints its output unchanged (per architecture §Standard Contracts → Hook contract; security-plan §Data
Protection; obs-plan §4 Scenario: Budget governor; test-plan §6 Path 6).

Nothing statusline-shaped exists at HEAD `4d77eac` (research.md finding 1), so the chunk also gives the fake
agent what it needs to rehearse it: the override read, a statusline run fed by a file the test owns, and the
`statusline-echo` mode. The property the fourth CARRY owes lands with the reader.

The chunk is built and proven under the fake agent only. Four things in it are the founder's and are not
settled by this plan (`inputs#I1`, `inputs#I2`, `inputs#I3`): three boundary widenings (W1 the override file
written at every start and passed to the CLI, W2 the user's command run through a shell, W3 the source files
that decide that command) and how the three CLI behaviours it relies on stand without a ledger row (R). Stop
rule S1 holds the whole chunk until his word on them is recorded. The Windows half is cut, provisionally

### Step 1 — the normalised reading (`crates/viola-core/src/lib.rs`)

  word `"unknown"` or `{used_percentage, resets_at}`; `used_percentage` is a JSON number or `"unknown"`;
  `resets_at` is an RFC 3339 UTC string or `"unknown"` (architecture §Standard Contracts, the `/api/sessions`

- It holds no timestamp of its own and no Claude name. Its serde form is the one the file and later readers

### Step 2 — Claude's statusline shapes (`crates/viola-agent-claude/src/statusline.rs`, `lib.rs`, `Cargo.toml`)
- A new pure module, the one home of every Claude-specific statusline shape. Nothing in it reads a file, a
  clock or the environment. The crate takes the workspace's `chrono` (research.md, the crate fact).
- **The payload reader.** Input: the statusline stdin bytes. A payload that is not one JSON object is the
  crate's `AgentError::Malformed`. An object with no `rate_limits` object yields no reading. An object with one
  yields a reading: per window, an absent or non-object window is `"unknown"`; `used_percentage` is kept when
  it is a finite number from 0 to 100, else `"unknown"`; `resets_at` is taken as a whole number of Unix epoch
  seconds, or as an RFC 3339 string, and written as RFC 3339 UTC with milliseconds, else `"unknown"`
  (research.md finding 4; security-plan §Input Validation, Hook stdin row). Every other key, the documented
  `spend_limit` window included, is ignored. No `deny_unknown_fields` (architecture §Established Decisions
  [Validation]).
- **The settings reader.** Input: a settings file's bytes. It returns the user's command when the document is
  an object whose `statusLine.type` is the string `command` and whose `statusLine.command` is a non-empty
  string holding no NUL; anything else is no command, never an error.
- **The override document.** Input: the pinned binary's forward-slash absolute path. On Unix it returns the
  JSON document whose `statusLine` is `type` `command` and `command` the path, one space, `hook statusline`,
  but only when every character of the path is an ASCII letter, a digit or one of `_ - . / :`; for any other
  path it returns nothing (research.md finding 6). On Windows it returns nothing for every path (S3).
- **The flag and the shell.** The literal `--settings` is defined here and nowhere else in product code. The
  shell a user's command runs through is defined here: on Unix the absolute `/bin/sh` with `-c` and the
  command as ONE argument; on Windows none (S3). No `SHELL`, `COMSPEC` or `PATH` is read (architecture
  §Cross-cutting Patterns, Config management).
- Tests, in this crate: rstest tables named `statusline_reading_…`, `statusline_user_command_…` and
  `statusline_override_…` with one case per sentence above; and the property
  `statusline_prop_resets_at_never_fails`, `cases: 512`: for an arbitrary JSON value in `resets_at` and in
  `used_percentage` the reader returns without panicking, and each field is `"unknown"` or a value that
  round-trips (a number from 0 to 100; a string chrono parses as RFC 3339 in UTC). Build strings outside the
  format macro inside the `proptest!` body. Run the property red once on a stub that returns a wrong value, so
  proptest writes `proptest-regressions/statusline.txt`, and commit that file (test-plan §6 Property suite).

## Constraints & rejected approaches
- A `config.json` key naming the source — every existing test that boots a wrapper would read the developer's
  settings, and a home that does not exist before viola creates it cannot hold the key (`inputs#I3`; research.md
  finding 3).
- A third `fake-agent` environment seam for the source — security-plan allows no seam beyond the two without
  its own entry, and the release build would read another source than the tested one.
- Reading project, local or managed settings for the command — "named" is one file; the limit is stated on
  the card.
- An exec-form override (`command` plus `args`) — the fetched documentation names no `args` key for
  `statusLine`; unmeasured.
- Quoting the pinned path in the override — the right quoting differs by shell and the shell is unmeasured;
  an unsafe path gets no override instead.
- A Windows shell chosen from the documentation, or PowerShell alone — research.md finding 7; S3.
- A recorded or invented statusline payload in the fake agent — test-plan §7's "no shape before a recorded
  fixture"; the agent relays a test's file.
- `statusline` as a tenth `HookEvent` — it is not a Claude Code hook event; the perf rows and the dialog
  parser key on that set.
- A new `hook-decision` detail code, a new span name outside the three obs-plan names, or a `process-start`
  field naming the source — each is a schema or catalog amendment the chunk does not need.
- An end-to-end case that waits out `STATUSLINE_DEADLINE` — a test-owned wait on a product bound (test-plan
  §11 Universal); the bound is a unit case with a short value.
- Do not run the user's command, write `budget.json` or read the snapshot before the instance check passes.
- Do not write the override with `replace_private_shared`: the file is one instance's.
- Do not pass the command to the shell as anything but one argument, and never build a shell line from it.
- Do not add a hint, a refusal line or any terminal byte for an absent or unreadable source.
