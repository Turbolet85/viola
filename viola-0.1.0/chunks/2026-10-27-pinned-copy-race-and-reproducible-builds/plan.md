## Goal
Close the `pin_exe` first-start race on a fresh home: the absent copy of `bin/<key>/viola(.exe)` is placed once, already
closed, and never replaced under a concurrent first start, so no agent's hook spawn of the pinned path can fail while
another start's write of it is in flight. Research re-derived the folded hypothesis on both halves: viola's
`replace_private_retrying` renames through `NamedTempFile::persist` while it still holds the temp file's write handle
(`crates/viola-state/src/fs.rs:288–303`), and an exec racing that window fails `ETXTBSY` on the Linux dev host
(scratch control: 4059 of 16283 open-handle execs failed, 0 of 13066 with the handle closed first; research.md,
Mechanism re-derivation). The fix lands in `viola_state` (a sibling placement helper in `fs.rs`, used by `pin_bytes`'s
absent-copy arm), never at a call site, keeps hash-before-reuse whole and the start order unchanged (per architecture
§Established Decisions [Snapshot writer] + security-plan §Data Protection, code-bearing artefacts).

Measure whether a rebuild of one tree can read as another binary: two clean release builds of one tree, through
`scripts/release-check.sh`'s build, compared by file and by every section, with two controls; a difference is recorded
as not explained unless its cause is measured, and acting on it is the founder's (the CARRY; verification-harness.md
2026-10-09).
