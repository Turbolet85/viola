## Patterns detected
- **The rename while the write handle is open** (`crates/viola-state/src/fs.rs:296`, `tempfile-3.27.0/src/file/mod.rs:767`): `NamedTempFile::persist` renames the temp file over `path` and returns the handle, which `replace_private_retrying` drops only after the rename; for that moment the inode at `path` is open for write in the replacing process.
- **Write-if-absent, then re-hash** (`crates/viola-state/src/pin.rs:90–97`): an absent copy is written, a present one re-hashed and refused on any difference; two first starts both read `NotFound` and both write.
- **The caller-supplied decision** (`crates/viola-state/src/fs.rs:271–282`, `replace_private_with` / `replace_private_retrying`): the retry decision is passed in so a bound is testable on every host — the shape a placement helper's test hook takes.

## Conventions to follow
- **One helper for every replaced file** (architecture §Established Decisions [Snapshot writer]): the placement lives in `viola_state::fs`, never as a call site's own temp + rename (`crates/viola-state/src/fs.rs:262` doc).
- **Mode before any byte** (`crates/viola-state/src/fs.rs:288`, `restrict`): the pinned copy 0700, set on the temp file before the write.
- **An attempt-count bound, never a time bound** (`REPLACE_ATTEMPTS`, `crates/viola-state/src/fs.rs:248`).
- **A forced window, never a sampled race** (`.claude/rules/testing.md` 2026-09-27) and **remove-the-guard** (2026-09-25).

## Mechanism re-derivation
- **The hypothesis (folded freight):** "the kernel error is not read — hypothesis: `ETXTBSY`". Re-derived, both halves:
  - **viola's half, verified at HEAD by reading:** `replace_private_retrying` holds the temp file's write handle across `persist`'s rename (`crates/viola-state/src/fs.rs:288–303`; `tempfile-3.27.0/src/file/mod.rs:767–779`), so after a second start's rename `bin/<key>/viola` names an inode that process still holds open for write.
  - **The kernel's half, verified by a scratch control on the Linux dev host** (`$TMPDIR/{scratchpad}/etxtbsy_probe.py`, tmpfs `/tmp`, 5 s an arm, run at this P3 on 2026-10-27, `df -h /tmp` 22G free): a writer replacing an executable the way `replace_private` does (temp written, synced, renamed over the target with its handle open, then closed) while another process execs the target: `arm open: 16283 execs, failed 4059: {'ETXTBSY': 4059}`; the control arm, the handle closed before the rename: `arm closed: 13066 execs, failed 0: none`.
  - **Not measured:** which errno the CARRY's 6 failed product boots read. The fake agent receipts `ran:false` only (`src/bin/viola-fake-agent.rs:648`). The equality the fix needs — the exec of `bin/<key>/viola` fails only while a placing process holds its inode open for write — holds for the scratch control; the product run's own errno is the plan's first reading.
- **The fix's equality, at the criterion's grain:** `persist_noclobber` on a CLOSED temp path (`into_temp_path`, then `TempPath::persist_noclobber`) makes `bin/<key>/viola` appear once, already closed, and never replaces it: a second start's placement reads `AlreadyExists` (Linux and macOS `renameat2`/`renamex` `NOREPLACE`, else `hard_link`'s `EEXIST`; Windows `MoveFileExW` without replace, `ERROR_ALREADY_EXISTS`) and re-hashes the copy that stands. The scratch control's closed arm is that equality's kernel half (0 of 13066).
- **The Windows exe arm, read:** a rename over an image another process runs is refused there (raw OS error 5, retried under `REPLACE_ATTEMPTS`, then accepted as same bytes by `replace_private_shared`), but the placing start still holds its write handle on the inode it placed; a no-clobber placement of a closed temp file removes that window on every OS. The companions (`pin_companions`) are opened held with `FILE_SHARE_READ` only before any launch and are not changed. Read on the `windows-2025` runner only.
- **The plugin rewrite, read:** `hooks.json`, `.mcp.json` and `plugin.json` are read, never executed; a rename gives a reader either whole file; no failure mode stands there.
