5. **The screen model** (new `crates/viola-agent-claude/src/screen.rs`, exported from `lib.rs`). Pure, no I/O, no
   clock read — every instant is a parameter:
   - `Screen`: owns an optional `vt100::Parser` (scrollback 0), the current size and the instant of the last fed byte.
     `new(rows, cols, now)`; `feed(bytes, now)` processes bytes and records `now` (a no-op while poisoned);
     `resize(rows, cols, now)` builds a FRESH parser at the new size (clearing poison) and records `now`; `poison()`
     drops the parser; `is_poisoned()`.
   - Constants (one home each, doc line: provisional built-ins, not measured; per-version ledger values land with the
     held rows): `QUIET_PERIOD` = 300 ms, `GATE_MAX_WAIT` = 5 s, `CONFIRM_WINDOW_FALLBACK` = 10 s (architecture
     [Delivery Confirmation]: "a built-in fallback window compiled into `viola-agent-claude`").
   - `Signatures`: two `&'static [&'static str]` lists — `input_box` (a screen row must contain at least one) and
     `modals` (no screen row may contain any). Compiled data only, never built from screen or upstream text
     (security-plan §Security Anti-Patterns → Code Patterns). No per-version table is added (rows held).
   - `Readiness` closed enum `Ready | InputNotReady` with kebab `as_str` (`ready`, `input-not-ready` — the obs
     `run.readiness_gate.outcome` values and the design word, design-system §Color Palette → Semantic Colors), and a
     `GateStep` `Wait | Done(Readiness)`.
   - `verdict(&self, sigs, waiting_since, now) -> GateStep`, in this order: poisoned → `Done(InputNotReady)`; not quiet
     (`now - last_fed < QUIET_PERIOD`) and `now - waiting_since >= GATE_MAX_WAIT` → `Done(InputNotReady)`; not quiet →
     `Wait`; quiet → `Done(Ready)` only when some row contains an `input_box` literal and no row contains a `modals`
     literal, else `Done(InputNotReady)`. Rows are read as plain text (`Screen::rows`) inside this function only; no row
     text is returned, stored or logged (obs-plan §11 "NEVER derive telemetry from screen content").
6. **The tee and the feed thread** (new `src/run/gate.rs`, `mod gate` in `src/run/mod.rs`):
   - A `Tee` implementing `Write` over the real output and a `Sender` of feed messages: `write` writes to the output
     first and only then sends a copy of exactly the bytes written; a send failure is ignored; `flush` flushes the
     output. The human's bytes are never delayed by the model and never altered (architecture §Design Philosophy "The
     human always wins the wheel").
   - Feed messages: bytes, or a host size. `start(clock, size)` spawns the feed thread owning a `Screen` and returns the
     sender. Bytes → `feed` under `std::panic::catch_unwind(AssertUnwindSafe(..))`; an `Err` → `poison()` and ONE
     `obs_event!(WARN, ObsEvent::ParseRejected, parser = "vt100-feed", detail = "panicked", count = 1)` (the
     `log_config_rejection` shape, `src/obs.rs:208-216`; no `corr` key). While poisoned, bytes are dropped unread (no
     second panic, no second line, no per-chunk work — obs-plan §11 no hot-path telemetry). A size different from the
     current one → `resize` under the same catch (an `Err` poisons and logs the same way). The thread ends when every
     sender is dropped.

     the gate with `Launched.size` and a `SystemClock`, hand `pump` a `Tee` over `io::stdout()` instead of the bare
     stdout, and a `host_size` closure that reads `viola_pty::host_size()` and also sends each reading to the feed.
     `viola_pty::pump`'s signature and viola-pty are unchanged.

     which is `:74`'s.
