## Goal
Close the driver's loop over the CLI. `send` types a prompt and returns a `cursor`. `viola wait <name>` now parks on the wrapper's channel until the next driver-relevant event (`turn-ended` · `question` · `permission` · `plan` · `session-end`) whose line starts at or after `--after`, and returns it at once when it is already logged. It answers a typed `{timed_out:true}` when `--timeout-ms` expires, and exit 21 `instance-unreachable` when the wrapper vanishes mid-park. `viola last <name>` returns the newest `turn-ended`'s `last_assistant_message` and `ts`, held in the wrapper's memory and rebuilt from `events.ndjson` at start (per architecture §Established Decisions [Message Broker / IPC], §Standard Contracts Channel methods; obs-plan §4 Scenario `wait` / `last`; test-plan §6 Path 3).

Nothing polls. The wake is a signal on the wrapper's own append path, on the landed `SendSlot` Condvar + injected-`Clock` precedent (research E2, `src/run/send.rs:44-124`). The human forms follow design-system cli Component Patterns 3. That includes the message-mode escaper CARRY 1 left here, whose live consumer is `last` (security-plan §Input Validation `:425`).

CARRY 2 is its own acceptance item. `role_of` files `send`, `wait` and `last` as the `cli` role, and the one `error: internal error` line moves to the catch site. A panic or a dispatch error then prints it exactly once (obs-plan §7 Per-role behaviour). CLI `wait` / `last` write their frame after `send`'s liveness-only pre-check under a **fifth dated interim gap**, ratified live by the founder at this P4 (F1 below), owned by Epoch 6 `:109` / `:111`.

## Implementation Steps
1. **`viola-core` dialog kinds** (`crates/viola-core/src/lib.rs`). `EventKind` gains `Question`, `Permission`, `Plan` (`as_str` `question` / `permission` / `plan`), and the `event_kind_as_str_is_kebab_case` table gains their rows. No producer is added: dialog events are `working-route.md:78`'s (research E3, E9).
2. **A capped event-log reader** (`crates/viola-state/src/events.rs`). One function reads the complete lines of `events.ndjson` whose start offset is ≥ a given byte offset. Each line comes back with its start offset, its end offset (the byte after its `\n`) and its parsed JSON value.
   - Each line is read through `Read::take(MAX_FRAME + 1)`. An over-long line is skipped and counted.
   - A line that is not a JSON object is skipped and counted.
   - A last line with no `\n` is not returned and is not rewritten. Healing it is `:85`'s (research E8).
   - An offset inside a line skips that line, which is the contract's "line STARTS at or after".
   - An absent log reads as no lines.
   - Unit tests in the same file cover every case above.
3. **The wrapper's `wait` / `last`** (new `src/run/wait.rs`, declared in `src/run/mod.rs`). One shared struct is built with an injected `Clock`. It holds a generation counter and the newest turn (`last_assistant_message`, `ts`) under one `Mutex`, plus a `Condvar`.
   - **Signal.** A method records an appended event line. It bumps the generation and stores the line's `data.last_assistant_message` and `ts` when the line is `turn-ended`, then `notify_all`.
   - **Rebuild.** A function reads the whole log once through step 2's reader and keeps the newest `turn-ended`.
   - **`wait`.** `params` = `{after?, timeout_ms?, from?}`, plus `v` / `sender`. `after` and `timeout_ms` must be non-negative integers that fit `u64`, and `from` must be absent, `null` or a valid `ViolaName`. Anything else is `ProtocolError::InvalidParams`. Unknown fields are ignored (additive tolerance; `tests/channel_endpoint.rs:113` "an extra params field is no fault").
     - The start offset is `after`, or `events::end_offset` read at the call when `after` is absent.
     - The deadline is `clock.now() + timeout_ms`, through `checked_add`: an overflow means no deadline.
     - The loop: read the generation; scan from the start for the first line whose `kind` is one of the five wake kinds, named through `EventKind` (step 1). Found → `{"ok":{"event":<the line's JSON object>,"cursor":<its end offset>}}`. Else, past the deadline → `{"ok":{"timed_out":true}}`. Else `wait_timeout(STEP)` until the generation moves, re-reading the clock.
     - A timed re-scan without a generation change never happens: the step wake only re-reads the clock.
     - The handler runs under `#[instrument(skip_all, name = "run.wait_dispatch", fields(woken_kind, timed_out))]`.
   - **`last`.** `params` = `{from?}` (same `from` rule) → `{"ok":{"last_assistant_message":<string|null>,"ts":<string|null>}}`.
   - Unit tests use a `JumpClock` like `src/run/send.rs:363-371`:
     - each wake kind wakes;
     - `activity`, `wheel`, `budget-gate`, `send-issued`, `send-confirmed`, `send-refused`, `session-start`, `prompt-submitted` and an unknown kind never wake;
     - a match already logged at or after `after` returns at once with `cursor` = its line's end;
     - a mid-line `after` skips that line;
     - `timed_out` comes only once the clock passes `timeout_ms`, never before;
     - a line appended and signalled during the park wakes it;
     - `last` before any turn is `null` / `null`, and after a rebuild is the newest turn's message.

## Implementation notes
- **Leaned decisions** (each a decisive material lean, stated for the P5 review):
  - leaned literal `after` past EOF per architecture `:52` ("returns the first driver-relevant event whose line starts at or after it"): no refusal, no clamp. It parks until such a line exists.
  - leaned `timeout_ms` bounded by its `u64` type with a `checked_add` deadline (an overflow = no deadline), per architecture `:52` (no cap stated). A huge timeout behaves as none.
  - leaned `role_of` "every other verb is `cli`" per obs-plan §7 Main-thread catch site.
  - leaned `outcome` derived in `viola-channel` per obs-plan §4 Scenario `wait` / `last` (`channel-response{… outcome}`).
  - leaned the exit-21 human form `unable  <name>  instance-unreachable` per layout-templates §Component — Primary content block 2 (`unable  <name>  <reason>  <detail>`) over the design line that omits the name.
  - leaned exit 21 at WARN for all three verbs per obs-plan §6 Log levels mapping (`.andromeda/obs-plan.md:844`).
  - leaned unknown params fields ignored per `tests/channel_endpoint.rs:113`.
- **Order sensitivity**: rebuild before `server.serve` (step 4). Signal after the append succeeds, never before (a scan then sees the line). Read the generation BEFORE each scan, so a line appended during the scan is never missed.
- **A parked handler holds its connection's worker thread** (`crates/viola-channel/src/server.rs:67-74`) until the next wake, its deadline, or the wrapper's exit. An abandoned no-timeout `wait` is released by the next wake event, whose reply write then fails.
