asserted on the `windows-2025` CI leg, for what chunk 2026-09-27-wrapper-channel left unasserted. The protected DACL's

Two controls get their first witness, each with a control that proves the witness can fire:
- **remote pipe clients rejected:** the bound listener's pipe type read back through `NtQueryInformationFile`
  (`FilePipeLocalInformation`), its `FILE_PIPE_REJECT_REMOTE_CLIENTS` bit set; a test-owned pipe created accepting
  remote clients reads it clear (the founder's answer to fork (a), `inputs#I5`);
- **the DACL's effect:** an open of the bound listener under the anonymous token is denied, while the same anonymous
  open of a test-owned pipe carrying the default descriptor succeeds (fork (c), `inputs#I5`), which amends test-plan §1's
  untestable zone at the wrap.

No product file changes: viola's listener already takes interprocess 2.4.4's defaults whole (research.md, Patterns).
The listener tests are Windows-only and are verified only on CI's `test (windows-2025)` leg (test-plan §11: a Linux run
proves no Windows branch).

The folded CARRY (the budget send case_4) is closed at its root cause (fork 3, `inputs#I5`). tracing-core 0.1.36 caches
a callsite's interest as `never` when the callsite is first registered, while at most one dispatcher is registered, on
a thread with no subscriber; the one scoped capture then loses its own thread's line (research.md, P4 additions). The
fix is one shared root-bin test helper that keeps a second, always-interested dispatcher registered for the process,
routed through every scoped capture of the root bin, and a witness case that reproduces the loss without it. The three
other plain `cargo test --bin viola` reds are recorded with their known cause and get no owner: plain `cargo test` is not
a supported runner, nextest is the gate (fork 4, `inputs#I5`).
