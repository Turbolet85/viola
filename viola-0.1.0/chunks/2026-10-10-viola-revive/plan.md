## Goal
`viola revive <name>` restarts a dead instance in the terminal it is typed in. It reads the instance's last
snapshot and its event log, picks the newest logged session id (or the one `--id` names), and runs the ordinary
`run` start order with the child `claude --resume <id>` spawned in the directory the dead wrapper recorded. It
replays no launch spec: the program is resolved again by name, the environment is the current terminal's, and
any other flag is typed after `--`. `--list` prints the logged session chain. Three preflight refusals are
built (`already-live`, `no-session`, `cwd-missing`), behind a strict-modes check on the files revive reads
(scope.md items 1 to 4; architecture §Established Decisions [Session Liveness]; security-plan §Authentication &
Authorization).

To carry this the chunk adds one optional snapshot field (`cwd`), a session-chain reader beside the landed log
replay (revive is the replay's first product reader), two argv options on the fake agent, and a test that kills
a wrapper it started and revives it (scope.md items 2, 3 and 5).

The plan covers the cut scope.md names. The `session-live` refusal is not built: everything it reads is pinned
on the route entry "The board: viola list" (research.md finding 6). Three live readings are one held step that
waits for the founder's number (step 12). Three P4 forks are closed by `inputs#I3`: no ledger row now, the fake
agent sets two payload fields under `--resume`, and the recorded cwd is ratified as the child's spawn directory.
