## Goal
Give viola its first build: a Cargo workspace on one pinned toolchain, the headless five-command harness
(`boot · run · status · cleanup · logs`) driving a real product process pair on Windows, macOS and Linux, a
per-chunk mutation gate that runs locally and in CI, and a 3-OS GitHub Actions workflow with SHA-pinned,
least-privilege actions (per test-plan §3 Test Harness Contract, §9 CI Integration, §10 Mutation gate;
security-plan §Dependency Security; architecture §Infrastructure Patterns).

The skeleton is a **walking skeleton** (operator decision, P4 fork 1). Its product side is the **first slice of the
real `viola run`**, in the root bin and on the spawn seam that Epoch 2 extends, not a throwaway stub. No abstraction
is built over code that does not exist yet. It resolves the home, writes the role's JSON lines
(`process-start` / `process-exit` / `panic`) to `<home>/diagnostics/run-<name>.ndjson` (per test-plan §3 Log format,
obs-plan §3, §7), spawns the named child directly, and detects the child's exit on the process handle. The harness
drives that process pair with a detached supervisor and a minimal fake agent. It proves the lifecycle end to end:
readiness, liveness, graceful stop and verified teardown.

Codebase reality (research.md): cold start. No `Cargo.toml`, `src/` or `crates/` exists yet. The setup-seeded
`scripts/agent-run.{sh,ps1}` shims already match the contract and are consumed unchanged. The host runs rustc
1.95.0, below the floor. No `main` branch exists on the remote, so the mutation base comes from
`AGENT_RUN_CHUNK_BASE` or the push's `before` sha (operator decision, P4 fork 2).

4. **Root bin `viola`, the process shell (`src/main.rs`).**
   - The first statement of `main` installs `viola_panic_hook` with `std::panic::set_hook`.
   - Everything after it runs inside one `std::panic::catch_unwind`, and the exit code is decided at that catch site:
     1 for a caught panic.
   - The hook never calls the default hook and never writes stderr. It writes one JSON line with one `write_all` to a
     pre-opened `OnceLock<Arc<File>>` role file. The key set is `timestamp`, `level:"ERROR"`, `target:"viola::panic"`,
     `message:"panic"`, `event:"panic"`, `process` and `instance`. It never includes the panic payload or `corr`, and
     `panic_location` is workspace-relative. Before the role file is open, the hook writes nothing. (per obs-plan §7
     Panic hooks, §3 Init order; design-system §Surface: cli Platform-Specific Notes)
   - Dispatch uses clap 4.6.7. The global option is `--home <dir>`. Home resolution is `--home`, else
     `<user home>/.viola/`. The `VIOLA_DIR` step arrives with `hook`. (per architecture §Cross-cutting Patterns
     "Config management")
   - anyhow is allowed here only (per architecture §Established Decisions [Error Handling]).
   - Clap usage errors exit 2, per architecture §Conventions CLI exit codes.

5. **`viola run <name> -- <program> [args…]`, first slice (`src/cmd/run.rs` + `src/run/`).** Steps, in order:
   1. Parse `<name>` through `ViolaName::try_new` before any path join. An invalid name is a usage error (exit 2).
   2. Create the home and `diagnostics/`. On Unix, directories are created 0700 via `DirBuilderExt::mode` and files
      0600 via `OpenOptionsExt::mode`, never through the umask. On Windows, the protected DACL is the home-integrity
      chunk's (see Constraints).
   3. Open `diagnostics/run-<name>.ndjson` in append mode. Initialize tracing-subscriber 0.3.23 with the obs-mandated
      builder:
      - `default-features = false`, features `fmt,json,registry,std`;
      - an explicit writer;
      - `.log_internal_errors(false)`, `.with_ansi(false)`, `.with_span_list(false)`, `.with_current_span(false)`,
        `.flatten_event(true)`;
      - a `MillisUtc` timer on chrono 0.4.45;
      - a `filter::Targets` level filter only (no env-filter, no `RUST_LOG`).

      Every event is one line and one `write`. If the file cannot be opened, the writer falls back to `io::sink`.
   4. Emit `process-start` with `process:"run"`, `instance:<name>`, `service_name`, `version`, `os` and `pid`
      (message == event; `corr` absent).
   5. Spawn `<program>` directly with std `Command`: no shell, stdio inherited, `VIOLA_DIR` set per child through
      `Command::env`. Emit `process-start` for the child with its pid.
   6. Wait on the child's process handle. Emit `process-exit` with the child's exit code, using fields from the
      obs-plan §6 additive catalog only.
   7. Exit 0. A spawn failure emits `process-exit` with a detail code and exits 1.

   The spawn lives in one function in `src/run/`. The PTY chunk replaces its body with the `viola-pty` seam: no trait,
   no alternative backend (operator note). Upstream text, env values and argv never reach a line (per security-plan
   §Bootstrap phases `logging-redaction-wire`).

6. **Minimal fake agent (`src/bin/viola-fake-agent.rs`, feature `fake-agent`).**
   - `--version` prints the real CLI's version line for `--cli-version <ver>` (default a fixed fixture version) and
     exits 0 (per test-plan §7).
   - Any other invocation reads stdin until a `\x03` byte or EOF, then exits 0.
   - It prints no ANSI and only ASCII text (per design-system §Anti-Patterns cli).
   - Scripted modes, the control file, receipts and fixture replay are left out (next chunk).
   - It carries its own `[lints.clippy]` without the print bans (per obs-plan §3 obs-ci-gate-wire, B5).

7. **`crates/viola-e2e` harness: the library.**

     anyhow in this chunk: no HTTP or MCP client exists yet, and anyhow is root-only (leaned per architecture

   - It has its own `[lints.clippy]` without print bans, one `HarnessError` enum, and modules `harness::{boot, run,
     status, cleanup, logs, supervise}`.
   - `boot` takes a binary-dir parameter. The CLI passes `target/debug`, and tests pass the test executable's own
     target dir (per test-plan §3 `run` step 2). Children are spawned directly and get env through `Command::env`,
     never `set_var`.
   - Readiness and teardown probes are bounded 100 ms file-state or pid probes against deadlines, never
     sleep-as-synchronization. Kill and liveness targets are checked by pid + start time via sysinfo (per test-plan §3
     PID file).

8. **`boot` (`viola-harness boot [--session <id>] [--instance <name>[:<fake-args>]]… [--cli-version <ver>]`).**
   - With no `--instance`, the instances are `overseer` and `builder`. `--ui`, `--unstamped`, `--agents-mode` and
     `--statusline-echo` are not in this chunk's grammar (Constraints).
   - The steps, per test-plan §3 `boot`:
     1. `cargo build --workspace --features fake-agent`. On failure, `reason:"build-failed"`.
     2. A fresh `tempfile::Builder::new().prefix("viola-session-").tempdir_in("<root>/target/e2e-home")?.keep()`
        parent, passing `<parent>/home`, which does not exist yet, so `viola run` creates it.
     3. Copy the fake agent to `target/agent-run/<session>/bin/claude[.exe]`, with that dir first on a per-child
        `PATH`.
     4. (Step 4, `viola verify`, is absent this chunk.)
     5. Write `supervise.json` and spawn the detached `viola-harness supervise --session <id>`. It uses
        `process_group(0)` on Unix and `CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS` on Windows (std `CommandExt`).
        The supervisor spawns, per instance, `<bin>/viola run <name> --home <home> -- <bin>/claude[.exe]
        --cli-version <ver> <fake-args>` with stdin piped and stdout/stderr drained.
   - **Interim readiness**, polled per instance within 20 s:
     - `diagnostics/run-<name>.ndjson` holds a parseable `process-start` line for `process:"run"`, `instance:<name>`;
     - the wrapper pid is alive with a matching start time;
     - the child `process-start` line is present.
   - `session.json` = `{home, instances:[{name, wrapper_pid, started_at, fake_args}], ui:null, supervisor_pid,
     cookie_file:null}`, written once readiness passes.
   - Output: `{"v":1,"cmd":"boot","ok":true,"session":…,"instances":[…]}`.
   - On failure: `ok:false` with `reason` from the closed §3 list (`build-failed | run-exited | readiness-timeout`),
     `instance`, `exit_code` and `missing` naming the unmet checks.

9. **`supervise` (internal).**
   - Owns the wrapper processes and polls for `stop.request` every 100 ms.
   - On stop, it writes `\x03` to each wrapper's stdin and closes it. That is the pipe analogue of test-plan §3
     cleanup step 1; the outer PTY arrives with `viola-pty`.
   - It waits up to 10 s per handle, then calls `kill()` on survivors.
   - It writes `supervisor-exit.json` = `{"v":1,"cmd":"supervise","ok":…,"exits":[{name, exit_code, killed}]}`.
   - Exit 0 when nothing was killed, 1 otherwise.

10. **`status` (`viola-harness status [--session <id>]`).**
    - No `session.json` → exit 2, `{"v":1,"cmd":"status","ok":false,"reason":"unknown-session"}`.
    - Otherwise it prints the §3 Status endpoint shape. `list`, `ui`, `pid` and `uptime_ms` are `null` (no
      `viola list` / `viola ui` yet), `api_sessions_equal_list` is `null`, and an added `instances:[{name,
      wrapper_pid, alive}]` member holds pid+start-time liveness.
    - `state` is `ready` when every wrapper is alive and `degraded` when any is not. `ok` is true only for `ready`.
      Exit 0 for ready, 1 otherwise.

11. **`cleanup` (`viola-harness cleanup [--session <id>|--all]`).**
    - It creates `stop.request`, waits for the supervisor pid (+ start time) to be gone, reads
      `supervisor-exit.json`, and verifies every wrapper and child pid is gone.
    - It then removes the `viola-session-*` parent, the session dir's `session.json` and `supervise.json`. Under
      `AGENT_RUN_KEEP_HOMES=1` it keeps the home and reports `home_removed:"kept"`.
    - Report: `{"cleaned":[…],"processes_gone":true,"endpoint_gone":null,"port_free":null,"url_file_removed":null,
      "home_removed":true|"kept","killed":[…]}`. `null` means that no endpoint or UI exists this chunk. Any `false`
      field means exit 1. A force-kill is reported and does not by itself fail cleanup.
    - With no `session.json` it prints `{"v":1,"cmd":"cleanup","ok":true,"cleaned":[]}` and exits 0 (idempotent).

12. **`logs` (`viola-harness logs [--session <id>] [--instance <name>] [--process <role>]`).**
    - It streams ndjson on stdout. Each `<home>/diagnostics/*.ndjson` line becomes
      `{"src":"diag","file":<basename>,"record":<line>}`.
    - A torn or unparseable line becomes `{"src":"diag","file":…,"torn":true,"offset":n}` and is never dropped.
    - `--instance` and `--process` filter on `record.instance` / `record.process`. An absent key equals null.
    - The `events` and `detail-*` sources and the `--kind` / `--after` filters arrive with their producers
      (Constraints).
    - Unknown session → exit 2 with one JSON document.

    - integration: `-E 'kind(test) & !binary(/^(path|tui|mcp|http|sse|cross|chaos|contract)_/)'`.

## Constraints & rejected approaches
- A trait or alternate "backend" around the child spawn — rejected: no abstraction over emptiness. The PTY chunk
  swaps the one function's body for the `viola-pty` seam.
- Pre-creating the home in the harness — rejected: test-plan §3 boot step 2 says a pre-created home inherits the
  workspace ACL. `viola run` creates it.
- The Windows protected DACL on a `--home` outside `%USERPROFILE%` — deferred to the home-integrity chunk (F-45).
  This chunk sets the Unix modes only. No strict-modes check exists to trip yet.
- `--ui`, `--unstamped`, `--agents-mode`, `--statusline-echo` (boot), `--e2e`, `--browser`, `--coverage`, `--perf`,
  `--fuzz-replay`, `--local-live` (run), and `--kind` / `--after` / events / detail sources (logs) — not in the grammar
  until their producers land. They are usage errors now, never a vacuous pass.
- test-plan §3's literal `git diff <base>...HEAD` — replaced by the working-tree + untracked diff from
  `merge-base(base, HEAD)`. /implement never commits, so the committed-only form would mutate nothing and report a
  vacuous `tested:0`. On a committed tree with an ancestor base both forms are equal.
- `dtolnay/rust-toolchain` and `--test-workspace` — rejected: the toolchain file is the one version source, and each
  package's own tests must kill its mutants.
- fmt/clippy as fatal CI steps, cargo-deny, zizmor, the weekly run, the MSRV job, coverage, the release build and the
  `gate` verdict — the later Epoch 1 chunks own these. Locally, fmt and clippy are gates of this plan.

## Implementation notes
- **Mutation runtime is the chunk's main cost risk.** cargo-mutants rebuilds per mutant, and the whole new tree is in
  the diff. Keep product code small and each branch tested. The local gate has `timeout = 14400` and runs in the
  background. If the CI mutants job threatens the 6 h job limit, use `--jobs` on the ubuntu runner and record it;
  never add an `exclude_re` to dodge a mutant.
- The detached supervisor must outlive `boot`: `process_group(0)` on Unix and `DETACHED_PROCESS |
  CREATE_NEW_PROCESS_GROUP` on Windows, both std `CommandExt`, so no new dependency. Stdin is a pipe, so no console is
  needed.
- Windows exit detection is on the process handle (`Child::wait`), never on pipe EOF (per obs-plan §3 line 177).
- The lifecycle test and the gate use the host's `-gnu` default triple, while CI windows uses `-msvc`. Only pure-Rust
  deps are allowed, so both link. Do not add a C-building crate (security-plan §Dependency Security).
- `jq` is on the host (research) and is used only by the local logs gate. CI's lifecycle leg asserts with the shim's
  exit codes plus a `python -X utf8` one-liner, never an unpinned jq.
