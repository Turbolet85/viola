## Goal
The wrapper learns that a turn is running. Any `prompt-submitted` marks it, whether the driver's own confirmed
prompt, a human's or a harness turn's. `turn-ended`, `session-start` or `session-end` ends it. A `viola release` that
returns the wheel clears it, because a user interrupt ends a turn with no `turn-ended`. While a turn runs, an automated
`send` is refused `not-delivered` / `turn-running` at the existing rung. It is never queued, and nothing is typed for it
(per architecture §Established Decisions [Human Takeover / Wheel]; §Conventions Error handling schema, the `send` order).

As built, `turn-running` covers only a second `send` in flight (`src/run/send.rs:239-243`). The folded CARRY's
hypothesis is measured true at HEAD: `path5_harness_turns_never_take_the_wheel` (`tests/tui_wheel.rs:240-258`) shows a
driver `send` accepted, so pasted, into an unended harness turn (research.md §Mechanism claims). This chunk closes that
gap. It adds no event kind, refusal detail, snapshot field, channel method, param or test seam: the state lives in memory
only, and the refusal reuses the one existing emitter (per architecture §Standard Contracts; obs-plan §6, §8 Default-deny;
security-plan §Security Anti-Patterns → Universal).

It also folds the wheel wrap's renumber CARRY: `tests/tui_wheel.rs:267` and `tests/cli_answer.rs:9` cite First live
test as `:84`. The `.profraw` WATCH rides as an observation only (scope.md).

## Rulings and leans this plan rests on
- **Leaned: only a wheel-returning `release` clears the turn.** Per `architecture.md:70`: "the `viola release` that
  returns the wheel is to clear the running-turn state", and "a `release` on a wheel the driver already holds changes
  nothing and appends nothing". `release {budget:true}` (leaves the wheel), a `release` on a driver-held wheel and a
  rejected `release-from-driver` therefore clear nothing. A turn stuck under a driver-held wheel is recovered without a
  keystroke by `viola pause` then `viola release` (step 7 witnesses it). The alternative, any non-budget `release`
  clears, contradicts that sentence and would need an architecture reversal.
- **Leaned: the rung decides at the send's arrival.** Per `architecture.md:70`: "A `send` while a turn is running (after
  `prompt-submitted`, before `turn-ended`) is not queued. It is refused". The turn is read once, at the existing
  `turn-running` rung. A turn that starts during the readiness gate's wait (≤ `GATE_MAX_WAIT`) is not refused by this
  chunk. That window is recorded as a residual (Expected amendments), not closed. A second check after the gate has no
  observable effect a test could force without a new seam, so it would be an unkillable mutant
  (`.claude/rules/testing.md:52`).
- **Leaned: the state is marked and cleared before the hook line is appended.** Per the precedent at
  `src/run/send.rs:152-156` (an unsent human prompt moves the wheel "before the line can be read"). A driver that read
  `turn-ended` through `wait` is never refused by that turn, and one that read a `prompt-submitted` is.
- **Leaned: the state sits in `WheelSlot`'s `Held`, beside holder and cause.** `release` lives on `WheelSlot`, and `send`
  already holds an `Arc<WheelSlot>` (`src/run/send.rs:52`). A wheel-returning move and its clear are therefore one lock
  hold, with no instant at which the wheel is the driver's while a stale turn still refuses. No signature changes.
- **Not a widening:** no playbook `verdict: escalate` pattern applies (`.andromeda/playbook.md:37`, `:49`, the
  "Boundary widening" class). The chunk narrows what automation may do and adds no crossing, input class or method.

## Implementation Steps
1. **The running-turn state** (`src/run/wheel.rs`). Add a closed two-state type, idle or running, never a bool parsed
   from text and never a `String` (security-plan §Security Anti-Patterns → Input, the closed-types rule). It goes in
   `Held` (`:73-76` region), starting idle. `WheelSlot` gains three crate-private methods: one marks the turn running,
   one marks it idle, and one reads whether it is running. None of them records anything: no event, no snapshot, no
   span, no obs line (obs-plan §11 Logs, "never log at `info` inside hot loops"; §6, no new field).
2. **`release` clears it** (`src/run/wheel.rs`, `apply` `:123-143`). When the `Input::Release` move is made (the
   `next()` arm at `:44`, a human-held wheel), the same `held` hold sets the turn idle. Every path where `next()` returns
   `None` for `Release` (`:45`), the `budget:true` path (`release` `:177-179`) and the `release-from-driver` / invalid
   params returns (`:170-176`, before `apply`) leave the turn as it was. `pause` and `Input::Human` never touch it.
3. **Turn start and end at the one hook entry** (`src/run/send.rs`, `append_hook_event` `:139-161`). Before
   `feed.appending`, beside the existing human-wheel move:
   - a `prompt-submitted` of any origin marks the turn running, the claimed driver prompt included;
   - a `turn-ended`, `session-start` or `session-end` marks it idle;
   - `activity` changes nothing.

   It keys on `line.kind` only, never on prompt text (security-plan §Input Validation, `hook.event` re-validation). The
   existing claim, relabel and settle order is unchanged.
4. **The rung** (`src/run/send.rs`, `send` `:236-243`). Under the flight lock hold, the rung returns
   `ctx.not_delivered(None, NotDelivered::TurnRunning)` when another send is in flight or a turn is running. The flight
   is not reserved, nothing is pasted, and `send-issued` is not written. Lock order is flight, then held. Nothing in
   `WheelSlot` takes the flight lock (`WheelSlot` holds no `SendSlot`), so no inversion exists. The rung keeps its place:
   after `control-character` and `human-typing`, before the readiness gate and confirmation.
5. **Unit cases** (`src/run/send.rs` `mod tests`; `src/run/wheel.rs` `mod tests`). They are rstest `#[case::…]` tables
   with literal wire values as the oracle (test-plan §4 root bin "Refusal ordering"; §11 Unit):

     then `human-typing` / `manual-pause`, then `turn-running`, never `input-not-ready`;

   - `wheel.rs`: a wheel-returning `release` clears the turn. A `release` on a driver-held wheel, `budget:true` and a

## Implementation notes
- **Order sensitivity.**
  - The mark and clear in `append_hook_event` happen before `feed.appending`. A `wait` that returns `turn-ended` (it
    re-scans only after the append, `src/run/wait.rs:71-84`) is therefore never followed by a `turn-running` refusal
    from that turn.
  - The claimed driver prompt marks the turn too. Its own `send` is already past the rung, so it confirms as before.
- **The boot `session-start`** (start records line 3) finds the turn idle and changes nothing. The wrapper starts idle,
  so a restarted wrapper never inherits a turn.
- **SessionEnd fallback** (`src/cmd/hook.rs:174-175`): a SessionEnd the channel missed is appended directly, and the
  wrapper's turn stays running. Its child is ending, so no driver send depends on it. Recorded as a residual.
- **Fake-agent turns:** an interactive submit fires no Stop (`src/bin/viola-fake-agent.rs:288-307`), so every test that
  sends twice ends the first turn with a scripted gated `Stop`. Research's sweep found exactly two existing sites that
  needed it (`tests/cli_send.rs:216`, `tests/tui_wheel.rs:254`; research.md §Companion sweep).
- **`--inject-harness-turn` with `--script`:** the harness step comes first, then the script's steps, each gated in
  control-line order (`src/bin/viola-fake-agent.rs:466-485`). With `path3.json` the releases are: 1 the harness prompt,
  2 `PostToolUse`, 3 `Stop`.
