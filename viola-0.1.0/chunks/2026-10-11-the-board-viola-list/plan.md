## Goal
Build `viola list` for wrapped sessions: a read model over the home's `instances/`, the machine form
`viola list --json` (`items`, `budget`, `skipped`) and the uncoloured human board (the BAY line, the six
captions, one row per session). The verb reads the disk itself and contacts no wrapper (architecture §Standard
Contracts, Channel methods; GUI list envelope). It is the first surface that shows the reader's three skip
counts, and the second product reader of the snapshot's replay fallback.

This is a cut of the route entry, by the operator's direction (`inputs#I1`): the smallest slice that needs no
word of the founder. It reads no `claude agents --json`, so every row's STATUS is `unknown` and no unwrapped
row is printed; it prints no colour, so the masters' styled terminal form stays unmet; it shows no link. Every
part left out is on the review card with a price and a proposed owner.

A failed strict-modes check refuses the whole board with exit 21 (the operator's answer to the P4 fork,
`inputs#I2`, not a ruling of the founder).

   second public form that returns the reading together with the stored `read_at` as a
   `viola_core::Reading<String>` (`"unknown"` when the key is absent or no string). `read_budget` keeps its
   signature and its one product caller (`BudgetGate::decide_at` @ `src/run/budget.rs:268`) and becomes a call
   of the new form. The order of the read does not change: `check_path` on the home, on the file, the shared
   lock, the capped read, the tolerant parse, `v` = 1; every failure is no reading and no line. Unit cases

   `"unknown"`; an absent file is nothing and creates nothing.

2. **The read model** — new `crates/viola-state/src/board.rs`, declared in `crates/viola-state/src/lib.rs`.
   Sync, std only, no Claude shape, no anyhow. Two entry points, so the caller can open its log between them:
   - **the scan and the checks.** Given the absolute home: `check_path` on the home and on `instances/`, each
     that exists; then the entries of `instances/` read with `symlink_metadata`. A directory whose name passes
     `ViolaName::try_new` is an instance; a link is counted as ignored; any other entry is counted as
     malformed. No path is joined from a name that did not parse. Then `check_instance` for every instance, in
     name order. The result is the name-ordered instance list with the two counts, or a refusal that says
     which failed first: the home (the home or `instances/`) or one named instance. Nothing under the home is
     opened for reading or writing by this step.
   - **the read.** Given the scan's result and `now` (a `SystemTime` argument, never read inside): for each
     instance, `read_snapshot_or_replay`, then:
     - a snapshot that reads: `classify(beat_age(dir, now), same_process(&snapshot))`. `Gone` gives no item.
       Otherwise the item holds the name, `wrapped: true`, the liveness word, `status: "unknown"`, the
       snapshot's `wheel`, `budget_paused`, `dialog_pending` (whether `pending_dialog` is set), `cli_version`
       when recorded and `cli_verified`. The pending dialog's kind is kept beside the item for the human row
       and is not a document field.
     - a replay: a beat at most `STALE_AFTER` old gives an item with liveness `live`, `wheel` and
       `budget_paused` only where the log gave one, `dialog_pending: false` and no CLI field. An older or
       absent beat gives no item. It is never `stale`.
     - an absent snapshot gives no item.
     - the skip counts: for a replay, the replay's own `skipped`; otherwise one drained `read_from(dir, 0)`
       pass and its `skipped()`. The board's `skipped` is the field-wise sum over every scanned instance,
       items or not.
     - after the loop, one `parse-rejected` line per nonzero scan count through `obs_event!`: parser
       `state-entry`, detail `symlink-ignored` or `malformed`, with `count` (obs-plan §6, `detail` code
       catalog, Filesystem refusals). No entry name is logged.
   - The item and the counts derive `Serialize` with the contract's snake_case keys in the contract's order;
     an absent optional field is omitted. `endpoint`, `pinned_bin`, `cwd`, `statusline_command`, `pid`,
     `started_at` and `links` are on no type of this module.
   - Unit cases `board_scan_*` and `board_read_*`, each through the writers (`write_snapshot`,
     `touch_heartbeat`, `append_event`), a malformed file made only by altering the writer's bytes: an absent
     home passes with no instance; a widened home and a widened instance directory are refused, the instance
     by name, the first in name order (`cfg(unix)`); a link, a plain file and a name that is no `ViolaName`
     give no instance and the right count; this process's own pid and start time with a fresh beat is `live`;
     the same with `now` six seconds past the beat is `stale`; a wrong start time is omitted; a snapshot cut
     mid-object with a fresh beat is `live` with the logged `wheel` and `budget_paused`, and with an old beat
     is omitted; a `v` above this build's reads the same way; a pending dialog reads `dialog_pending: true`
     with its kind; `skipped` sums two instances' torn tails, one of them gone; the serialised item equals a
     literal, once with every optional field and once with none.

## Constraints & rejected approaches
- No read, spawn or parse of `claude agents --json`, no fake-agent option, no ledger row, no `viola verify`
  child, no re-stamp, no live `claude` start — the founder's matters (`inputs#I1` item 2).
- No read of `NO_COLOR`, `TERM` or `COLORTERM`, no `IsTerminal` branch, no SGR byte, no clap feature or crate
  that reads a terminal variable — the colour layer is a boundary widening that waits for the founder.
- No link on any row or in the document. The first surface that shows a logged link name parses it through
  `ViolaName::try_new` again (`inputs#I1` item 3); this chunk builds no such surface.
- No value of a file that failed its check is used, and no log is opened before the checks — opening the role
  file narrows the home and a later check would pass a widened one.
- No second reader of `budget.json` beside the one checked read, and no write of any state file by `list`.
- No new environment variable, `config.json` key or test seam; the read model takes `now` as an argument.
- No hand-written `snapshot.json`, `budget.json` or `ledger/stamps.json` in a booted-wrapper case; a snapshot
  is made unreadable only by altering bytes the wrapper wrote.
- No harness change: `status`'s `list` member, `run --e2e`, the `path_` binary and `boot --statusline-echo`
  are not this chunk's.
- No mutation run, witness run or workflow dispatch (`inputs#I1` item 4).
- Skipping a failing instance and showing the rest — rejected at the P4 fork: it leaves an instance out with
  nothing saying so (`inputs#I2`).
- A `stale` root case that stops a wrapper and waits five seconds — rejected: the read model takes `now`, so
  the flip is a unit case with no real time.

## Implementation notes
