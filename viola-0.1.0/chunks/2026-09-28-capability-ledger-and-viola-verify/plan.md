## Goal
This chunk lands the capability ledger as the single gate for CLI-specific behaviour, and the verb that measures it
(architecture §Established Decisions → [CLI Version Compatibility]; §Cross-cutting Patterns → "Capability ledger as
the single gate").
- `viola-agent-claude` gains a closed, compiled-in table of six ledger rows: the behaviours a print-mode run of the CLI
  can measure today, including security-plan Amendment 7's largest-hook-payload row.
- `viola verify` resolves the local `claude` and reads its `--version`. It then runs one print-mode probe through a
  capture plugin, checks each row's post-condition, and prints the design-system step counter and its `stamped` summary.
  It is the ONLY writer of `ledger/stamps.json` (security-plan §Data Protection; arch §Occupied Resources → Filesystem).
  With `--record` it also writes scrubbed hook-payload fixtures.
- `viola run` gains its version gate between the pinned copy and the endpoint bind. It sets `cli_version`/`cli_verified`
  in the first snapshot and on the `claude-child` start line, with the obs spans and events obs-plan §4 names. On an
  unstamped, unlisted or unparseable version it degrades silently.

The `cli` role's catch site gains its one stderr line, `error: internal error` (obs-plan §7; design-system §Surface: cli
→ Exit-code phraseology). That line is folded CARRY 3.

In the operator pass the overseer records the first real fixture set against the installed CLI (2.1.283, Haiku). The
claude-fixture schema and the `fixtures/claude/*/*.json` hygiene walk land with it (the head half of folded CARRY 1).
The rows needing typed input, the dialog decision it will gate, and every test-home or harness stamping are out of
scope; each is named with its owner in §Implementation notes.

## Implementation Steps
1. **Ledger module** — create `crates/viola-agent-claude/src/ledger.rs` and declare/re-export it in `lib.rs`. It holds
   only pure code, with no I/O and no `#[cfg]` outside its tests:
   - `LedgerRow`, a closed kebab-case enum in this order, each with fixed ASCII row words:
     1. `shim-resolution` "claude resolves to a real executable"
     2. `spine-hooks` "spine hooks fire through the plugin dir"
     3. `session-start-fields` "SessionStart carries session_id and source"
     4. `prompt-verbatim` "UserPromptSubmit carries the prompt as sent"
     5. `stop-message` "Stop carries last_assistant_message"
     6. `largest-hook-payload` "every hook payload fits the frame cap"
   - `PROBE_PROMPT`, the fixed synthetic ASCII text `viola verify probe: reply with the single word ok`, with no tag
     characters.
   - `parse_version(stdout: &[u8]) -> Option<String>`. The first line must be exactly `X.Y.Z (Claude Code)`, with three
     dot-separated decimal fields and optional trailing whitespace; anything else is `None`.
   - `capture_plugin_files(pinned_bin_fwd, capture_dir_fwd)` renders `.claude-plugin/plugin.json` (name
     `viola-verify-probe`) and `hooks/hooks.json`. The hooks file registers SessionStart, UserPromptSubmit, Stop and
     SessionEnd, each as one exec-form `command` hook: the absolute pinned path with `args` `["hook", "<kebab event>",
     "--capture", "<capture dir>"]`, in the same shape `PLUGIN_FILES` renders.
   - `Capture { event: HookEvent, bytes: usize, payload: Option<Value> }`.
   - `check(row, &ProbeRun) -> bool`, one post-condition per row:
     - `shim-resolution`: the resolved program is not a script and answered `--version`.
     - `spine-hooks`: the captures are exactly SessionStart, UserPromptSubmit, Stop, SessionEnd, one each, in that order,
       and each payload is an object whose `hook_event_name` names its event.
     - `session-start-fields`: `session_id` is a non-empty string and `source` is `"startup"`.
     - `prompt-verbatim`: `prompt` equals `PROBE_PROMPT` byte for byte.
     - `stop-message`: `last_assistant_message` is a string.
     - `largest-hook-payload`: every capture's `bytes <= MAX_FRAME`.
   - The stamp shape: an envelope `{"v":1,"written_at","writer":"verify","data":{"versions":{"<ver>":{"verified_at",
     "rows":{"<row id>":"pass"|"fail"},"measured":{"largest_hook_payload":{"<Event>":<bytes>}}}}}}`. It is parsed
     tolerantly (no `deny_unknown_fields`; unknown versions, rows and fields are kept on merge). Two functions go with
     it:
     - `merge_stamp(existing: Option<&[u8]>, version, results, measured, written_at) -> Vec<u8>` replaces only this
       version's entry. An existing file that does not parse is replaced whole.
     - `verified(stamps: &[u8], version) -> Result<bool, StampError>` is `true` only when every `LedgerRow` id is
       `"pass"` in that version's entry. `StampError` has `Malformed` and is a thiserror variant of `AgentError` with a
       fixed message.
   - `scrub(value, home, user, case_insensitive) -> Value` rewrites, in every string, the home prefix (both separator
     spellings) to `~` and the user name as a whole word to `<user>`. `is_clean(value, user) -> bool` rejects any
     remaining `^[A-Za-z]:[\\/]`, `/home/`, `/Users/`, `\Users\` or user word. `case_insensitive` is a parameter
     (`CASE_INSENSITIVE` at the call site), never a `#[cfg]` body.
2. **Stamps file I/O** — create `crates/viola-state/src/stamps.rs` and declare it in `lib.rs`. This module knows no
   Claude shape, only bytes.
   - `update_stamps(home, update: impl FnOnce(Option<&[u8]>) -> Vec<u8>) -> Result<(), StateError>`:
     1. `create_private_dir(<home>/ledger)`.
     2. `open_private_lock(ledger/stamps.json.lock)` and `.lock()` for the whole read-modify-write, as `write_snapshot`
        does (`crates/viola-state/src/snapshot.rs:75-76`).
     3. Read the current bytes (`take(MAX_FRAME + 1)`; more than `MAX_FRAME` counts as absent).
     4. `replace_private(ledger/stamps.json, bytes, FILE_MODE)`.
   - `read_stamps(home) -> Result<Option<Vec<u8>>, StateError>`: `NotFound` is `Ok(None)`. The read is capped at
     `take(MAX_FRAME + 1)`, over is an error, and the read takes no lock.
   - `update_stamps` is the only function in the workspace that writes `stamps.json`.
3. **Capture arm of the hook verb** — in `src/cmd/hook.rs`, `HookArgs` gains a hidden `--capture <dir>`. When it is
   given, `hook` does exactly this and nothing else: no `VIOLA_*` read, no obs init, no channel.
   1. Require `<dir>` to be absolute and an existing directory.
   2. Read stdin through `take(MAX_FRAME + 1)`.
   3. Write the bytes to the first free `<dir>/<PascalEvent>.<k>.json` (`k` from 1) through
      `viola_state::fs::replace_private(…, FILE_MODE)`.
   4. Return exit 0.

   Every failure (a bad dir, a read error, a write error) returns exit 0 with nothing written, and there is never a byte
   on stdout or stderr. The role stays `Hook` because argv[1] is `hook` (`src/main.rs:77-91`).
4. **`viola verify` verb** — create `src/cmd/verify.rs`. `src/cmd/mod.rs` gains
   `Verify(verify::VerifyArgs) = verify [--record <dir>] [-- <program> [args…]]` (program default `claude`), dispatched
   with a `DetailSink { process: Cli, instance }` when `VIOLA_NAME` is a valid `ViolaName`. The verb is
   `#[instrument(skip_all, name = "cli.verify")]` and runs:
   1. With an instance, `viola_obs_init(home, ObsProcess::Cli, Some(name), level)` and the same
      `process-start{subject:"self"}` line `run` writes (`src/run/mod.rs:17-28`). Without one, no process-log file is
      written (obs D-06).
   2. Resolve the program with `run::resolve_program` (`src/run/mod.rs:117`). A `.cmd`/`.bat` gets the batch-script
      refusal text `run` uses. A missing program gets `unable: the claude CLI was not found` /
      `hint: install Claude Code or put it on PATH`, exit 1, nothing written.
   3. Pin this exe (`viola_state::pin::pin_exe`). A hash mismatch gets `run`'s tampered-pin refusal, exit 1.
   4. Compute the R8 strip plan the way `run` does (`viola_agent_claude::plan_strip` + `run::persistent_names`), so the
      probes measure the CLI as a wrapped child sees it.
   5. Spawn `<program> <args> --version` directly (no shell, stdin null, stdout piped through `take(MAX_FRAME)`, stderr
      null, the strip applied), bounded by `VERSION_DEADLINE` = 5 s with `try_wait` and a kill at expiry.
      `parse_version` returning `None` → `unable: the CLI version could not be read` /
      `hint: run claude --version to check the install`, exit 1, no stamp.
   6. Create the probe dir `<home>/ledger/probes/<pid>/` (0700), holding `plugin/` (the capture plugin files) and
      `captures/`. A drop guard removes the whole probe dir on every exit path.
   7. Spawn the print-mode probe: `<program> <args> -p <PROBE_PROMPT> --model haiku --plugin-dir <probe>/plugin
      --no-session-persistence`, with cwd = the probe dir, stdin null, stdout and stderr drained through
      `take(MAX_FRAME)` and discarded (upstream text is content, never printed), and the strip applied. It is bounded
      by `PROBE_DEADLINE` = 120 s, with a kill at expiry. Then read `captures/` in `k` order into `Capture`s.
   8. For each row in order, under `#[instrument(skip_all, name = "cli.verify_step", fields(row = id))]`, append one
      static stdout line `[NN/06] <row id> <row words>  pass|fail`: NN zero-padded to the total's width, a two-space
      gutter before the verdict, printed as that row is checked.
   9. Under `state.ledger_write`, call `update_stamps` with `merge_stamp` (`written_at`/`verified_at` via
      `obs::timestamp`).
   10. Print the summary line `stamped <ver>  <n> pass  <m> fail` on stdout, the last line.
   11. `--record <dir>`, only when `m = 0`: for the first capture of each event, `scrub` its payload (home from
       `std::env::home_dir()`, user = that home's last component, `CASE_INSENSITIVE`). Every scrubbed payload must pass
       `is_clean` before any file is written. It is then written as compact JSON + `\n` to
       `<dir>/<ver>/<PascalEvent>.default.json` (dirs created). If a payload is not clean, nothing is written and the
       result is `unable: a recorded payload still holds a path or a username` /
       `hint: record with a viola home under your user home`, exit 1. The stamp is already written.
   12. Exit 0 when `m = 0`, else 1. With an instance, the matching `process-exit{subject:"self", exit_code}` line.
5. **Version gate in `run`** — create `src/run/version_gate.rs` (declared in `src/run/mod.rs`) with
   `version_gate(home, program, cwd, strip) -> Gate { cli_version: Option<String>, cli_verified: bool }` under
   `#[instrument(skip_all, name = "run.version_gate", fields(cli_version = Empty, cli_verified = Empty))]`:
   1. Spawn `<program> --version` bare (no user arguments; arch [CLI Version Compatibility] "running the resolved child
      executable once with `--version`") with the same spawn discipline and `VERSION_DEADLINE` as step 4.5.
   2. Log it as `process-start` / `process-exit{subject:"version-probe", child_exit_status, duration_ms}`.
   3. `parse_version`. `None` → `Gate { None, false }`.
   4. Otherwise, under `state.ledger_read`, run `read_stamps`, then the pure
      `stamps_verdict(read_result, version) -> (bool, Option<&'static str>)`:
      - `Ok(None)` → false.
      - Read error → false, `"unreadable"`.
      - `verified` returning `Malformed` → false, `"malformed"`.
      - Otherwise `verified`'s bool.
   5. A detail code logs `parse-rejected{parser:"ledger-stamps", detail, count:1}` at WARN. No path and no stamp
      content appear.

   In `src/cmd/run.rs` `start`, compute the strip plan before the gate, then call the gate after `pin_and_plugin`
   (`:167`) and before `bind_endpoint` (`:171`). Pass `Gate` into `start_state`, which sets `cli_version`/`cli_verified`
   instead of the hard-coded `false`/`None` (`:278-279`). `run::log_child_start` gains the `cli_version` and
   `cli_verified` fields. Update the `start` doc comment (`:143-145`) to name the gate's step. `run` still writes nothing
   to the terminal on every gate outcome.
6. **`cli` catch-site line** — in `src/main.rs`, `Role` gains `Cli` for argv's verb `verify` (`role_of`). `exit_code`
   maps `Cli` like `Other`. After the catch site, a `Cli` outcome of `Failed` or `Panicked` calls
   `human::internal_error()`. `src/human.rs` gains:

   - `internal_error()`: stderr, a write error swallowed.
   - `write_result(out, line)` / `result(line)`: one stdout line per `write_all`, used by step 4 for the step lines and

   `src/obs.rs::internal_error_exit_line` also writes its `process-exit{detail:"internal-error"}` line when the context

## Acceptance Criteria
- (design/layouts/a11y) Against the fake agent with a complete test-written 2.1.0 set, `viola --home H verify -- <fake>
  --cli-version 2.1.0 --fixtures <set>` exits 0. Its stdout is exactly six lines `[01/06] shim-resolution claude
  resolves to a real executable  pass` … `[06/06] largest-hook-payload every hook payload fits the frame cap  pass`,
  then `stamped 2.1.0  6 pass  0 fail` as the last line. Stderr is empty, and the output holds no ESC byte, no `\r` and
  no non-ASCII byte (per design-system §Surface: cli → Component Patterns 5; layout-templates §Output structure —
  `viola verify`; a11y-plan §4 → P6).
- (security/arch) After that run `H/ledger/stamps.json` exists (0600 on Unix, its `.lock` sibling present), with
  `"v":1`, `"writer":"verify"`, all six rows `"pass"` under `2.1.0`, and `measured.largest_hook_payload` naming the four
  spine events. The step-2 probe finds `stamps.json` in exactly one source file (per security-plan §Data Protection, At
  rest → Code-bearing artefacts; architecture §Occupied Resources → Filesystem).
- (tests) With a set missing `Stop.default.json`, verify exits 1. `spine-hooks` and `stop-message` read `fail` and the
  last line is `stamped 2.1.0  4 pass  2 fail`. A later `viola run` with that home records `cli_verified:false` (per
  test-plan §5 CLI; architecture §Established Decisions → [CLI Version Compatibility]).
- (tests/security) A child answering `--version` with something other than `X.Y.Z (Claude Code)` (`--report-version
  garbage`) makes verify print `unable: the CLI version could not be read` + the `hint:` line on stderr and exit 1.
  `H/ledger/stamps.json` is never created (per security-plan §Input Validation, Child process output).
- (arch/obs) `viola run` with a home verify-stamped for 2.1.0 and the fake agent as child writes the first snapshot with
  `cli_version:"2.1.0"`, `cli_verified:true`. `run-<name>.ndjson` holds a `version-probe` `process-start`/`process-exit`
  pair before the `claude-child` `process-start`, which carries the same two fields. With an unstamped home it records
  `cli_verified:false`, and with a home stamped only for 3.0.0 also false. With the `viola` binary itself as the child
  (its `--version` prints `viola 0.1.0`), `cli_version` is absent and `cli_verified:false`. In every case `run` writes no
  byte of its own to stdout or stderr before the child's (per architecture §Established Decisions → [Session Liveness],
  [CLI Version Compatibility]; obs-plan §4 Scenario: `viola run` start sequence; design-system §Surface: cli →
  Component Patterns 5 `run`).
- (obs) `stamps_verdict` over malformed bytes returns `(false, Some("malformed"))` and over a read error
  `(false, Some("unreadable"))`, and the gate emits exactly one `parse-rejected{parser:"ledger-stamps"}` with no path or
  stamp content. `schema-check` passes over every kept home (per obs-plan §4 Edge flows → Capability ledger; §9 G4).
- (obs/design) `viola --home <a path under a regular file> verify -- <fake>` fails its home creation: stderr is exactly
  `error: internal error\n` with no hint and no path, stdout is empty, and the exit is 1. With `VIOLA_NAME` set and a
  valid home, a forced dispatch error puts the chain only in `instances/<name>/diagnostics/detail-cli.ndjson` (per
  obs-plan §7 Panic hooks → Per-role behaviour; design-system §Surface: cli → Exit-code phraseology).
- (security/tests) `verify --record <tmp>/rec` against a set whose payloads embed the test user's home path and user
  name writes exactly `<tmp>/rec/2.1.0/{SessionStart,UserPromptSubmit,Stop,SessionEnd}.default.json`. Each has the

  pure and tokio-free (architecture §Infrastructure Patterns → Crate dependency direction).
