## Goal
Land the per-instance wrapper channel: a new sync crate `viola-channel` carrying JSON-RPC 2.0 over ndjson on an
interprocess local socket (per architecture §Established Decisions [API Style] and [Message Broker / IPC];
§Standard Contracts "Wrapper channel frames"), bound by `viola run` in its documented start order so the child's
first hook finds a listening endpoint, recorded as `endpoint` in the first snapshot. Every frame is bounded at
`MAX_FRAME` before parsing, every `params` carries `v` + `sender` (+ the client's additive `conn`), a newer `v` is
refused with `-32602`, and every method this chunk does not implement answers `-32601` (security-plan §Input
Validation; obs-plan §3 Trace context propagation, D-10/D-32).

The endpoint is admitted as the security-plan requires from its first bind: on Windows the listener takes the
protected SDDL `D:P(A;;GA;;;<user-SID>)(A;;GA;;;SY)` — interprocess 2.4.4 already defaults `accept_remote:false`,
`inheritable:false` and `FIRST_PIPE_INSTANCE` (research.md §Measured facts) — and the client opens with SQOS
Identification; on Unix the socket lives in the per-user 0700 directory of security-plan Decisions Log
amendment 2. The exclusive bind is the arbiter of two concurrent starts of one name (Windows:
`FIRST_PIPE_INSTANCE`; Unix: a held `.lock` sibling), and the loser exits 1 with the squatted-endpoint refusal
(design-system §Surface: cli → Component Patterns 2).

The chunk also lands the first redaction and span subjects (veil `#[derive(Redact)]`, `#[instrument(skip_all, …)]`,
the fixed-`Display` `ChannelError`), the Scenario 1 start-sequence spans in the crates that own each step
(obs-plan §3 Backend instrumentation hooks, §4 Scenario 1), makes `corr` required on the lines whose `corr`
obs-plan always defines, adds the channel-frame fuzz target and property, the Unix E2 fds witness, the harness's
endpoint readiness and `endpoint_gone`, and a Windows coverage `test` stage in `pre-push`. It carries two
recurrence watches without new mechanism (scope fold items 9 and 11).

   workspace) with normal deps `viola-core` (path), `serde`, `serde_json`, `thiserror`, `tracing`, `veil`,
   `interprocess`, and `windows-sys` under `[target.'cfg(windows)'.dependencies]`; dev-deps `rstest`, `proptest`,
   `tempfile`, `tracing-subscriber` (test-only span capture). No `tokio` feature (research.md §Conventions). Add
   `viola-channel` to root `[dependencies]` and a line to `scripts/sync-crates.txt`.

2. **`ChannelError` + the protocol-error map** (`crates/viola-channel/src/lib.rs`). A `thiserror` enum, one variant
   per failure class (bind taken, bind other, connect, frame oversize, frame parse, io, peer closed), each with a
   fixed `#[error("…")]` literal — no field is interpolated into `Display`. A closed `ProtocolError` type maps to
   the five JSON-RPC codes: `-32700` "parse error", `-32600` "invalid request", `-32601` "method not found",
   `-32602` "unsupported protocol version" with `data:{"supported":1,"wrapper":VERSION}`, `-32603` exactly
   "internal error" with `data:null`. No other `data` is ever built (security-plan §Error Handling).

3. **Frames** (`src/frame.rs`). One frame = one line INCLUDING its terminating `\n`, at most `MAX_FRAME` bytes.
   `read_frame` wraps the reader in `Read::take(MAX_FRAME)` before `read_until(b'\n')`: a line that ends in `\n`
   within the bound is a frame; hitting the bound without `\n` is `Oversize`; EOF before any byte is `Closed`; EOF
   mid-line is `Closed` (a torn frame is never parsed). `write_frame` serializes one JSON object and writes it plus
   `\n` in ONE `write_all`. Envelope types: `Request { jsonrpc, id: Option<u64>, method, params: Value }`, the
   common params view `{ v: u32, sender: String, conn: Option<String>, from: Option<String> }` read tolerantly
   (`#[serde(default)]`, no `deny_unknown_fields`, serde_json default depth), `Response { id: Option<u64>,
   result | error }`. `Request` derives veil `Redact` with `params` redacted, so its `Debug` never prints content
   (obs-plan §8 Scrubbing libraries).

4. **Endpoint naming** (`src/endpoint.rs`). `endpoint_name(name: &ViolaName, home: &Path) -> String` =
   `viola-` + the first 12 lowercase hex chars of the FNV-1a 64-bit hash (offset `0xcbf29ce484222325`, prime
   `0x100000001b3`) over the name's bytes + `0x00` + the absolute home path's UTF-8 bytes (architecture
   §Conventions Data model conventions → Endpoint name; std `DefaultHasher` forbidden). A non-UTF-8 home is a
   `ChannelError`, never a lossy hash. `socket_dir(xdg: Option<&OsStr>, tmpdir: Option<&OsStr>, uid: u32, macos:
   bool) -> PathBuf` is a PURE decision function compiled on every OS: Linux `$XDG_RUNTIME_DIR/viola/`, macOS
   `$TMPDIR/viola/`, fallback `/tmp/viola-<uid>/` (security-plan Decisions Log amendment 2); a thin
   `#[cfg(unix)]` reader supplies its inputs (testing.md 2026-09-24: decision logic in a plain fn). `endpoint_path`
   yields `\\.\pipe\viola-<h12>` on Windows and `<socket_dir>/viola-<h12>.sock` on Unix.

5. **Server + arbiter** (`src/server.rs`). `Server::bind(path, …) -> Result<Server, ChannelError>` with a distinct
   `BindTaken` outcome.
   - Windows: the current user's SID string from `GetTokenInformation(TokenUser)` + `ConvertSidToStringSidW` (no
     logon SID), the SDDL `D:P(A;;GA;;;<sid>)(A;;GA;;;SY)` through `SecurityDescriptor::deserialize` and
     `ListenerOptionsExt::security_descriptor`. A second bind of a live name fails at `FIRST_PIPE_INSTANCE` →
     `BindTaken` (the error kind is measured by the step-8 test, not assumed).
   - Unix: `File::try_lock` on `<socket_dir>/viola-<h12>.lock` (0600), held in the `Server` for the process life;
     `WouldBlock` → `BindTaken`; with the lock held, a leftover `.sock` is unlinked, then bind with
     `try_overwrite(false)`. The lock is what makes the takeover race-free (research.md §Measured facts: unlink-then-
     bind alone lets two starts both win).
   - `Server::serve(self, dispatch)` spawns one accept thread and one worker thread per connection. Each worker, in a
     cloned `channel.dispatch` SERVER span entered with `in_scope`: `read_frame`; `Oversize` → reply `-32600`, log
     `parse-rejected{parser:"channel-frame", detail:"oversize"}` at warn, close; parse failure → `-32700`
     (`id: null`); a request whose `params.v > 1` → `-32602`; otherwise `dispatch(method, params)`; a notification
     (no `id`) gets no reply. `channel-request` is logged per parsed frame with `corr` = the id when present and
     `conn` from params or `srv_conn = "srv-<accept counter>"`; `channel-response` is emitted from a `Drop` guard
     (`result_class`, `error_code`, `duration_ms`) so early returns still log it (obs-plan §4 Scenario: Confirmed
     `send`, Cleanup). A worker panic is caught (`catch_unwind`): `-32603` "internal error", the connection closes,
     the server keeps accepting (obs-plan §7 Panic hooks → `run` worker threads). Nothing is written to
     stdout/stderr. Every line goes through `obs_event!`; `params` and result bodies are never logged.
   - `Dispatch` is a trait the root implements; this chunk's root implementation answers every method `-32601`.

6. **Client** (`src/client.rs`). `Client::connect(endpoint: &str, process: &'static str)`: on Windows the SQOS open
   moved from `tests/channel_sqos_open.rs:119-134` — `CreateFileW(GENERIC_READ|GENERIC_WRITE, OPEN_EXISTING,
   SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION | FILE_FLAG_OVERLAPPED)` → `OwnedHandle` →
   `local_socket::Stream::try_from` (leaned: the windows-sys route the architecture Wrapper IPC row and security-plan
   Decisions Log 2026-09-25 name; the std `OpenOptions` route would amend both); on Unix interprocess connect by
   path. `conn = "<process>-<pid>-<t0>-<n>"` with `t0` the process start instant in Unix-epoch ms captured once
   and `n` a per-process connection counter (obs-plan §12 D-10, D-32). `request(method, params)` stamps `v:1`,
   `sender:VERSION`, `conn`, integer ids monotonic per connection, reads the reply through `read_frame`, and logs
   `channel-request` / `channel-response` in a `channel.request` CLIENT span.

7. **Crate tests** (`crates/viola-channel/src/*` inline + `crates/viola-channel/tests/channel_frames.rs`):
   rstest tables with literal oracles for framing at `MAX_FRAME` − 1, `MAX_FRAME`, `MAX_FRAME` + 1 (line length
   counts the `\n`); the five-code error map (`-32603` body compared as a literal JSON string); `ChannelError`
   `Display` for every variant (no path-like or payload text); FNV-1a golden vectors (literal expected names for
   two name/home pairs, hash constants never imported); `socket_dir` cases for the three Unix forms; the `conn`
   shape `^[a-z]+-\d+-\d+-\d+$`; on Windows `GetHandleInformation` reports `HANDLE_FLAG_INHERIT` clear on the
   server and client pipe handles; a proptest property (`cases: 512`) that any byte string round-trips or is
   refused `Oversize` exactly when its line length exceeds `MAX_FRAME`; commit `proptest-regressions/` if it
   shrinks. A span-capture test (a `tracing-subscriber` layer recording span names and fields) asserts
   `channel.dispatch` and `channel.request` exist with their fields and no `params` field.

8. **Real-endpoint tests** (`tests/channel_endpoint.rs`, root, sync). In a fresh home under
   `target/e2e-home`: a server bound on a test-scoped name (`viola-test-chan-<pid>-<label>` — outside the
   `viola-<h12>` namespace like `tests/channel_sqos_open.rs:138`'s, never bound by `viola`) serves a raw
   interprocess client and the viola client;
   assert `-32601` for an unknown method, `-32602` + `data:{supported:1,wrapper}` for `v:2`, an extra unknown
   params field accepted, a `MAX_FRAME` + 1 line answered `-32600` and the next read returns 0 bytes, and the
   `-32700` reply for a non-JSON line; a second `bind` of the same path returns `BindTaken` while the first

  §Infrastructure Patterns → Build system).
- (arch/security) A request with `params.v` 2 gets exactly `{"code":-32602,"message":"unsupported protocol
  version","data":{"supported":1,"wrapper":"0.1.0"}}`; an unknown method gets `-32601`; an extra unknown params
  field is accepted; `-32603` is exactly `"internal error"` with `data:null` (per architecture §Standard Contracts
  "Wrapper channel frames"; security-plan §Error Handling) — `binary(channel_endpoint)` in the filtered
  integration entry and `package(viola-channel)` in the unit entry.
- (security/tests) A line of `MAX_FRAME` bytes (its `\n` included) is a frame; `MAX_FRAME` + 1 is answered `-32600`
  and the connection closes (the next read returns 0); every channel reader goes through `read_frame`'s
  `take(MAX_FRAME)` (per security-plan §Input Validation; test-plan §4 viola-channel).

  the viola client's open reads `SecurityIdentification` at a same-user impersonating server (per security-plan

  in this chunk.
