## What this chunk builds

- **`viola run` over a real PTY on Windows (ConPTY).** The wrapper spawns its child inside a pseudo-terminal and pumps it both ways: the child's screen bytes reach the wrapper's stdout, and the human's keystrokes reach the child. Passthrough carries **zero own bytes**: viola adds nothing to the child's output stream and nothing to its input stream that the human did not type.
- **The `viola-pty` crate** (the PTY seam: spawn · read · write · resize · wait · kill over portable-pty `=0.8.1`; it knows no agent). `src/run/mod.rs::spawn_child` is the one spawn function, and its body becomes this seam (CARRY, three-os-ci chunk).
- **npm-shim → `claude.exe` resolution.** A `claude` found on PATH as an npm shim (`claude.cmd` / `claude.ps1` / an extensionless sh shim) resolves to the real `.exe` it launches, which is then spawned directly.
- **`.cmd` / `.bat` refusal.** A child that resolves to a `.cmd` or `.bat` is refused, never spawned (portable-pty bypasses BatBadBut escaping; security rule "never spawn a `.cmd`/`.bat` PTY child").
- **R8 `CLAUDE*` strip.** Per the founder ruling of 2026-09-25 (P4; intent-incomplete, amended at P5 validation-1), every `CLAUDE*` name is removed from the child's environment except names defined in the persistent environment. On Windows that is the HKCU/HKLM `Environment` keys; on Unix it is an explicit pass-list in `config.json`. Each stripped and kept name is named in the start line.
  - The plan adds a compile-time identity floor that is always stripped, which keeps the "no config key disables a control" invariant: the 11 identity names measured on this host (research fact 7).
  - The tests check that a session-identity name is stripped, a persistent-config name survives, and an unknown new `CLAUDE*` name is stripped.
  - The S6 "14 names" are enumerated nowhere (research fact 7). Today `spawn_child` passes the full inherited environment, so the strip is this entry's (CARRY). The stripped values are secrets that must never reach a log, event, snapshot, fixture or error body.
- **Process-handle exit.** The child's exit is read from its process handle (`wait`), never inferred from EOF on the PTY. The logged `process-exit{claude-child}` carries it (`exit_source = "handle-wait"`, or `"kill-fallback"`). The wrapper's own exit-code contract stays as it is at HEAD: 0 once the child ran, 1 on refusal or internal error (`src/cmd/run.rs:36-47`).
- **The portable-pty line recorded** (requirement v1-25 / intent F-25): the chunk that writes the PTY seam records which portable-pty line it uses and why, with the Windows defect re-checked, keeping the seam's contract, exit-on-handle detection and non-inheritable handles. Research re-checked it: wezterm#6783 is still open against 0.9.0, 0.9.0 is still crates.io's newest, and 0.8.1 passes `bInheritHandles = 0`. The record lives beside the pin (the `[workspace.dependencies]` comment) and in the `viola-pty` crate doc. The `TerminateProcess` kill fallback via windows-sys is part of the seam (arch §Established Decisions [PTY]).
- **Host terminal in raw mode.** [premise-corrected: research facts 1-3 — through ConPTY a cooked console line-buffers keystrokes until Enter, echoes them and swallows `\x03`, both in the child and in the wrapper's own console] "Passthrough with zero own bytes" requires two things. First, the wrapper puts its own console/tty stdin into raw VT input (and stdout into VT processing) when they are terminals, and restores the modes on exit. Second, the fake agent sets its own terminal raw, as the real CLI does. Without both, a human keystroke is delayed and Ctrl-C never arrives. The child's cwd is set to the wrapper's cwd (portable-pty otherwise defaults to `%USERPROFILE%`, research fact 5). Host-size changes are forwarded to the child PTY (resize).
- **Zero own bytes, Windows oracle.** [premise-corrected: research fact 4 — ConPTY itself emits `ESC[?9001h ESC[?1004h ESC[?25l ESC[2J ESC[m ESC[H`, an OSC 0 title with the command line, and a re-render when nested] On Windows the witness is the absence of viola-authored bytes (its literals, refusal/hint/error text, diagnostic lines), not byte identity and not "no cursor control the child did not emit". A byte comparison applies on the Unix legs.
