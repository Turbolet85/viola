## Goal
`viola run <name> -- <program>` hosts its child in a real pseudo-terminal: ConPTY on Windows (the live target) and openpty on Unix. It does this through a new `viola-pty` seam over portable-pty `=0.8.1` (per architecture §Established Decisions [PTY], §Infrastructure Patterns → Crate dependency direction).

The human's keystrokes reach the child byte-exact and at once, Ctrl-C included, and the child's screen reaches the terminal. viola adds no byte of its own, and child exit is read on the process handle, never on EOF (per layout-templates §Surface: cli / Output structure — `viola run`; design-system §Brand Identity 0.0 row; obs-plan §3 Sink; a11y-plan §1 tui). Research measured what that takes on Windows (research.md §Measured facts 1-4):
- the wrapper switches its own console into raw VT input and VT output while it runs, and restores it afterwards;
- the fake agent does the same, as the real CLI does;
- the child's cwd is set explicitly;
- the program is resolved by viola, never by portable-pty's own search.

A new `viola-agent-claude` crate holds the two Claude-specific decisions (per architecture §Established Decisions [Agent Coverage]; security-plan §Input Validation row "Child executable resolution"):
- **npm-shim resolution:** a `claude.cmd` resolves to its sibling `claude.exe`, and any other `.cmd`/`.bat` child is refused with exit 1 and design's fixed line + hint.
- **The R8 strip, per the operator's ruling:** every `CLAUDE*` name leaves the child's environment except names defined in the persistent environment. A compile-time identity floor is stripped whatever the persistent environment says.

The run logs `process-start{claude-child, pty_backend, env_stripped_count, env_stripped_known, env_kept}` and `process-exit{exit_source}` codes-only (per obs-plan §4 Scenario 1, §6 PTY seam, D-14 as amended).

The harness `supervise`, the root `Wrapper` and the `run_cli` tests leave the stdin-pipe interim for outer PTYs on all three OSes (per test-plan §3 `boot` step 5, `cleanup` 1-2).

Folded in here are:
- the cfg-aware orphans gate (the CARRY's verified hypothesis);
- the ripgrep install's resilience to the Schannel revocation-offline transient, with the sha256 check intact (CI run 36141312209);
- the portable-pty line record (verification-matrix.json#v1-25).

1. **Workspace pins** (`Cargo.toml` `[workspace.dependencies]`).
   - Add `portable-pty = "=0.8.1"` with a rationale comment. The comment is the v1-25 record: 0.9.0 is excluded for wezterm#6783 (Windows `pty.read` garbage, open as of 2026-09-25, 0.9.0 still crates.io's newest); 0.8.1 spawns with `bInheritHandles = 0`; exit is read on the handle.

   - Extend `windows-sys` features with `Win32_System_Console` and `Win32_System_Registry`.
   - Append `viola-pty` and `viola-agent-claude` to `scripts/sync-crates.txt`.
2. **`crates/viola-pty`** (new; sync; deps portable-pty, `cfg(windows)` windows-sys, `cfg(unix)` libc; `[lints] workspace = true`).
   - **The seam:** a `Pty` trait with spawn · read · write · resize · wait · kill, behind `#[cfg_attr(test, mockall::automock)]`.
   - **Spawn input:** a `SpawnSpec` with an absolute program path, args, cwd, the names to remove and the size.
   - **Spawn behaviour:** spawning always sets `cwd` (research fact 5: portable-pty's default is `%USERPROFILE%`) and applies `env_remove` per name.
   - **Child handle:** a child handle with `wait`/`try_wait`/`kill`. `kill` falls back to `TerminateProcess` on the pid via windows-sys when portable-pty's kill errs, inside an **inline** `#[cfg(windows)]` block (research fact 8). `ExitSource::{HandleWait, KillFallback}` carries which path produced the exit.
   - **`HostTerminal`:** an RAII guard that switches a terminal stdin to raw input and a terminal stdout to VT output, and restores the saved modes on `Drop`. On Windows it clears `ECHO|LINE|PROCESSED` and sets `ENABLE_VIRTUAL_TERMINAL_INPUT`, and sets `ENABLE_VIRTUAL_TERMINAL_PROCESSING|DISABLE_NEWLINE_AUTO_RETURN` on stdout (research fact 2 measured `0x1f7 → 0x3f0`). On Unix it applies `cfmakeraw` via `tcgetattr`/`tcsetattr`. It is a no-op returning `None` when the handle is not a terminal (a pipe).
   - **`host_size()`:** reads the terminal's cols/rows (`GetConsoleScreenBufferInfo` / `TIOCGWINSZ`), `None` off a terminal.
   - **`PTY_BACKEND`:** a `const` `"conpty"`/`"openpty"` chosen by an inline cfg block. It is a const, not a `cfg!()`-valued fn, per the deferred learning in the handoff.
   - **`PtyError`:** thiserror with fixed-message `Display`. The portable-pty `anyhow` error is kept only as a boxed `#[source]` for the detail file, never in `Display` (research fact 5: its message embeds the command line and cwd).
   - **Crate doc:** records the portable-pty line, why, exit-on-handle and non-inheritance (v1-25).
3. **`crates/viola-agent-claude`** (new; sync; deps `viola-core`, thiserror; `[lints] workspace = true`).
   - (a) **`plan_strip(inherited names, persistent names) -> StripPlan { remove, kept, count }`.**
     - A name is stripped when it starts with `CLAUDE` (ASCII case-insensitive on Windows, where env names are case-insensitive; exact on Unix) unless it is in the persistent set **and** not on `IDENTITY_FLOOR`.
     - `IDENTITY_FLOOR` holds the 11 names measured in research fact 7: `CLAUDECODE, CLAUDE_CODE_BRIDGE_SESSION_ID, CLAUDE_CODE_CHILD_SESSION, CLAUDE_CODE_ENTRYPOINT, CLAUDE_CODE_EXECPATH, CLAUDE_CODE_MESSAGING_SOCKET, CLAUDE_CODE_MESSAGING_TOKEN, CLAUDE_CODE_SESSION_ATTENDED, CLAUDE_CODE_SESSION_ID, CLAUDE_EFFORT, CLAUDE_PID`.
     - Values are never touched: the function sees names only.
   - (b) **`resolve_program(program, PATH, PATHEXT, is_file) -> Result<PathBuf, Refusal>`.**
     - A program containing a path separator is taken as given.
     - Otherwise the PATH is searched: on Windows over the PATHEXT extensions only, never the bare name (fact 5: the extensionless sh shim); on Unix the bare name.
     - A hit or given path whose file name is `claude.cmd`/`claude.bat` (case-insensitive) resolves to `<dir>/node_modules/@anthropic-ai/claude-code/bin/claude.exe` when `is_file` says it exists (fact 6). The shim is never read or parsed.
     - Every other `.cmd`/`.bat`, a `claude.cmd` without that sibling included, is `Refusal::BatchScriptChild` (arch §Established Decisions [CI/CD]: resolution applies only to the `claude` npm shim).
     - A `.exe`/`.com` or Unix hit is used as is.
   - `AgentError`/`Refusal` are thiserror enums with fixed messages.
4. **Persistent-environment names** (root, `src/run/env.rs`, a minimal OS reader; its decision lives in step 3a).
   - On Windows, enumerate value **names** (never data) under `HKCU\Environment` and `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment` via windows-sys Registry. The root gains `windows-sys` as a `cfg(windows)` normal dependency.
   - On Unix, read `config.json` `claude_env_keep`, an array of names each matching `^CLAUDE[A-Z0-9_]*$`, at most 32. Read it with `Read::take(MAX_FRAME)` like `read_diagnostics_level` (`src/obs.rs:190-200`), and add `claude_env_keep` to `CONFIG_KEYS` (`src/obs.rs:33`) so the key is not an `unknown-keys` rejection.
   - A bad value is rejected whole through the existing `ConfigRejection`/`log_config_rejection` path. A floor name in the list is simply ineffective (step 3a), never an error.
5. **The run path** (`src/run/mod.rs`, `src/cmd/run.rs::run()`, the only caller of `spawn_child` @ `src/cmd/run.rs:36`, research §Graph impact).
   - The order is: obs init → `resolve_program` → strip plan → PTY spawn (cwd = `std::env::current_dir()`, size = `host_size()` or 80×24) → `log_child_start` → `HostTerminal` guard → pump.
   - **Pump:** three threads, each body in `std::panic::catch_unwind` with an `Err` routed to `run()`'s exit path:
     - stdin → PTY writer;
     - PTY reader → stdout, flushed per read;
     - a resize poller that compares `host_size()` every 250 ms and calls `resize` on change.
   - **Exit:** `run()` blocks on the child's `wait()`, logs `process-exit{claude-child, child_exit_status, exit_source}`, drops the guard (modes restored), drains the reader for a bounded time after closing the PTY, and logs `process-exit{self}`.
   - **Exit code:** it keeps today's contract: 0 when the child ran (its status is logged), 1 on refusal or internal error.
   - **`log_child_start` fields:** `pty_backend = PTY_BACKEND`, `env_stripped_count`, `env_stripped_known` (the stripped names, comma-joined) and `env_kept` (the kept names, comma-joined). `schemas/diag-line.v1.json` `process-start` gains `env_kept` (string).
   - **`.cmd`/`.bat` refusal:** exit 1 with no child spawned and no `process-start{claude-child}`. It writes `process-exit{self, exit_code:1, detail:"batch-script-child"}` and exactly two stderr lines, `unable: <name>'s command is a .cmd or .bat script` then `hint: pass the real executable, not a .cmd or .bat shim` (design-system.md:772). This is the root bin's first human output site, in one small fn with a local `#[allow(clippy::print_stderr)]` (Cargo.toml lints comment).
   - **Other spawn/resolution failures:** unchanged (`internal-error`, chain to the detail file only).
6. **Fake agent** (`src/bin/viola-fake-agent.rs`).
   - At start, before reading stdin, it takes a `viola_pty::HostTerminal` guard on its own stdin/stdout, as the real CLI does (research facts 1-2). A pipe stays a pipe.
   - It adds a `size {cols, rows}` receipt written at start and again before handling any input byte whenever `host_size()` changed. This is the resize oracle.
   - `env` receipt, `\x03` exit and `--exit-no-eof` are unchanged.

## Constraints & rejected approaches
- Handing portable-pty a bare `claude` is rejected: its Windows search matches the extensionless sh shim first, which `CreateProcessW` cannot run (research fact 5).
- Parsing `claude.cmd` to find its target is rejected: upstream text is content, never a command (Critical Warnings). Resolution is the fixed sibling path only.
- Byte identity or "no cursor control the child did not emit" as the Windows oracle is rejected: ConPTY emits its own preamble, an OSC 0 title and a nested re-render (research fact 4).
- A `cfg(windows)`/`cfg(unix)` `mod x;` **file** is rejected: OS branches live in inline blocks/modules (research fact 8). The gate change in step 10 is for robustness, not a licence to add such files.
- `--target <own triple>` per leg is rejected as the orphans fix: it changes nothing (research fact 8).
- `--ssl-no-revoke` is rejected: it disables revocation outright. `--ssl-revoke-best-effort` fails only when the revocation server is unreachable, and the sha256 pin stays the integrity gate.
- Setting `VIOLA_NAME`/`VIOLA_DIR`/`VIOLA_BIN` here is rejected (ruling 3): they point at an instance dir and a pinned copy the next entry creates.
- Building the `viola_e2e::fixtures` copy here is rejected: E2 lands only its strip half, in a sync root suite on the root chain (test-plan §2 root `tests/tui_*`). A copy with no consumer is an unobservable body (testing.md 2026-09-24).
- Reading any env **value** in the strip, the registry reader or a log is rejected: names only (security-plan NEVER-log floor).
- A `sleep` in a test is rejected. Tests wait on receipt/role-file lines, bounded below 20 s and exit-aware (testing.md). The product's 250 ms resize poll is product timing, not test sync.

## Implementation notes
- **Mutants and cfg:** the Windows-only bodies are the console modes, the registry reader, `TerminateProcess` and the `.cmd` refusal test. They are killed only on the windows leg, and the Unix termios / `claude_env_keep` bodies only on ubuntu (testing.md 2026-09-24). Keep each OS body a minimal reader and the decisions in the plain fns of step 3.
- **Supervisor leak hazard:** a mutated `stop`/`cleanup` that leaks a PTY-owning supervisor locks `viola-harness.exe` and swamps the leg with unviable mutants (verification-harness.md). Every booted-session test keeps its `Drop` guard.
- **ConPTY close ordering:** after `wait()` returns, closing the PTY may be needed before the reader sees EOF, and a grandchild (`--exit-no-eof`) may hold the console. `run()` must exit within its bound regardless. Measure the drain on this host and record the reading in `evidence/`.
- **Windows env names are case-insensitive:** `plan_strip` compares ASCII-uppercased names on Windows only, via an inline cfg in one shared fn.
- **`env_stripped_known` and `env_kept`** are comma-joined strings: the schema types `env_stripped_known` as a string (`schemas/diag-line.v1.json` allOf[25]).
