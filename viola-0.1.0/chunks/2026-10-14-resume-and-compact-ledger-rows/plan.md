`resume` with that id, and no ledger row covers it (scope §1). This chunk lands it as the twenty-second ledger row,
`resume-session`, probed by a new sixth interactive run, Run E. After Run D, Run E resumes Run B's FIRST session id
(read from Run B's own first SessionStart capture, the session that holds the probe turn and the pastes; research.md
§Measured facts 5). It is stamped live on 2.1.287 under the founder's cap of twelve starts. The row is relied on every

stamped before it reads `cli_verified:false` until re-stamped (per architecture §Established Decisions [CLI Version
Compatibility]; security-plan §Security Anti-Patterns).

`/compact` joins the local-command list with no post-condition, so a driver's `send` of it reads `ok`
`unconfirmable` at once instead of a false exit 13 `no-prompt-submitted` while the command runs (per architecture
§Established Decisions [Delivery Confirmation]). That needs no ledger row (the founder's ruled limit: a shape no
`send` relies on needs no probe, architecture §Cross-cutting Patterns → Capability ledger). No live compaction is run
and no bound is added. A `/compact` post-condition row stays owed: its confirm would need a window of its own,
