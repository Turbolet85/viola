## Goal
Bring every human-mode CLI output to the terminal discipline the masters bind:
- linear, static output with no redraw or cursor movement on any stream;
- colour only as a second cue beside its word: bold NAME, an amber `DIALOG` word, a dim stale row; only on a terminal
  that can take it, and never under `--json`, a pipe, `NO_COLOR` or `TERM=dumb`;
- `viola --help` as the grouped verb table;
- an unwrapped session's long NAME clipped with `...` on a terminal too narrow for it, never wrapped;
- under `viola run`, nothing of viola's own on the terminal, and a human key that always passes.

The sources are a11y-plan §4 P4 / P6, design-system §Surface: cli (Tokens (platform-specific), Width, Navigation
Pattern, Per-Surface Bans), layout-templates §Output structure — `viola --help` / `viola list`, architecture
§Cross-cutting Patterns → Diagnostic output channels and obs-plan §3 (intro).

Research shows half the discipline is already built and witnessed, so this chunk re-runs it rather than rebuilding it:
- zero wrapper bytes (`tests/tui_passthrough.rs`);
- the human key during a send's readiness wait (`tests/cli_send.rs`);
- the human bytes held whole past a paste (`crates/viola-pty/src/pump.rs`);

- `waiting:` once (`tests/cli_wait_last.rs`);

### Part B — width-known truncation of unwrapped NAMEs (`inputs#I1` Q2)
5. **Units first** in `src/human/board.rs` (`mod tests`, prefix `board_row_width_`). Each expected row is a literal:
   - (a) With no width, nothing is truncated: today's rows are unchanged.
   - (b) With a width, an unwrapped NAME longer than the room left is cut to end in `...`, and its row is exactly the
     width or shorter.
   - (c) A wrapped NAME is never cut, whatever the width. The wrapped row may stay longer than the width.
   - (d) A cut never falls inside a `\xHH` escape. It moves back to before the escape's backslash.
   - (e) A width too small for the `...` form keeps NAME at no less than the caption's 4 columns. An unwrapped NAME is
     then its first character and `...`.
   - (f) An unwrapped NAME that already fits is never cut.

   Read them red against stubs that hold the new parameter and no behaviour (testing.md 2026-09-25, extended
   2026-10-10).
6. In `src/human/board.rs`, `board_rows` and `write_board` take the terminal width as an `Option<usize>` of columns.

   With `Some(w)`, NAME's column width is the largest of:
   - the caption's 4;
   - the longest wrapped escaped NAME;
   - the longest unwrapped escaped NAME, capped at `w` minus the rest of an unwrapped row.

   The rest of an unwrapped row is 65 columns: LIVE 5, STATUS 7, WHEEL 23, DIALOG 17, five 2-space gutters and the
   `n/a` CLI cell. The basis is `src/human/board.rs:98`–`101` and `:136`–`141` at `6d8b662`.

   Every unwrapped NAME longer than that column is cut to the column width minus 3, at a character boundary that is
   not inside an escape, and `...` is appended. The cut acts on the ESCAPED text: `escape_row` runs first, as now at
   `src/human/board.rs:151`.

   With `None`, the rows are byte-identical to today's. The board stays ONE `write_all`.
7. In `src/cmd/list.rs`, in human mode only, pass `viola_pty::host_size().map(|size| usize::from(size.cols))` to
   `write_board`.
   - That reader is a stdout `TIOCGWINSZ` ioctl on Unix and the console buffer on Windows
     (`crates/viola-pty/src/lib.rs:466`). It reads no env var.
   - The `--json` path is untouched.
   - A piped stdout reads no size, so a piped board truncates nothing, as layout-templates' piped form requires.

     line, an error or a refusal, and never change escaping, redaction, `validate_paste_text` or any check
     (security-plan §Security Anti-Patterns, Universal; obs-plan §11 Logs).
10. **Board units** in `src/human/board.rs` (prefix `board_row_style_`). Each expected row is a literal byte string:
    - (a) A live wrapped row at each depth: `\x1b[1m` + NAME + `\x1b[0m`, then the padding plain. A pending dialog's
      cell is the attention token + `DIALOG` + `\x1b[0m`, then ` <kind>` plain.
    - (b) A stale row is dim from its first byte to its last. Every span inside it re-opens dim after its reset. NAME
      on it is dim and bold. On a stale row with a pending dialog, only the `DIALOG` word is amber and not dim: the
      kind word and the rest of the row stay dim.
    - (c) An unwrapped row's NAME is bold, and nothing else in the row is styled.
    - (d) The BAY line, the caption row, the empty-board line and the separator carry no SGR.
    - (e) Padding and widths are counted on the plain text, so a styled board shows the same columns as the plain
      one.
    - (f) Under no depth (`None`), every row is byte-identical to today's.
    - (g) An escaped control (`\x1B`, `\x0A`) reads the same at every depth: no raw control byte, and no SGR inside
      an escape.
