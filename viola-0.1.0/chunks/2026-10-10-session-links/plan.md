## Goal
viola records which session drives which. A `link` is one line `driver → driven` in the driven instance's own
`events.ndjson`, written by that instance's wrapper, and the link set is whatever replaying those lines gives
(architecture §Established Decisions, [Links]). This chunk adds the two event kinds, the one rule that turns
`link` / `unlink` lines into a set of `{driver, driven, since}` items, the replay's link half, the wrapper's own
copy of the set (restored from the log at every start, mirrored to `snapshot.json`), and the implicit link a
`send` or an `answer` from another instance makes. It also lands the test the budget chunk left owed: under a
closed budget gate `answer`, `wait`, `last` and `pause` behave as under an open one, with a refused `send` in the
same gate as the control (test-plan §6 Path 6; `inputs#I1`, note 3).

The explicit half is `viola link <driver> <driven>` and `viola unlink <driver> <driven>`, served by two channel
methods, with a `link` result that carries what its human line prints (requirement `v1-13`, the `link` half).
That half widens the local trust boundary in three places no ratified gap covers, so it is **held behind step
11**: the founder's own word. Steps 1 to 10 and the operator pass do not wait for it (`inputs#I1`, note 4).

The chunk needs no ledger row, no `viola verify` child, no re-stamp and no live `claude` start, and it plans no
mutation run, witness run or workflow dispatch (`inputs#I1`, notes 1 and 2). Everything runs under the fake agent.

Three shapes no master words were answered by the operator in the fork round (`inputs#I2`): a refused `send` or
`answer` records no link; the `link` result is `{since, already_linked}` and `unlink`'s stays the empty object;
an `unlink` of a pair that is not linked appends nothing and answers as any `unlink`.

2. **The link rule and the replay's link half** (`crates/viola-state/src/replay.rs`). Add one public function
   that applies one logged line to a link set (a `Vec<Value>` of `{driver, driven, since}` items) and says
   whether the set changed. It carries no span and writes nothing. Its rule, whole:
   - a `link` line whose `data.driver` and `data.driven` are strings adds the item with `since` = that line's
     `ts`, unless the pair is already in the set, and then it changes nothing (`since` stays the first one);
   - an `unlink` line removes the pair; for a pair that is not in the set it changes nothing;
   - a `link` or `unlink` line whose `driver` or `driven` is not a string changes nothing; every other kind
     changes nothing.
   `replay` calls it for every line of its one pass, so `Replayed.links` holds the set. Nothing else of `replay`
   changes: its span, its three other fields, its skip counts, and the rule that it writes no file. Add inline
   unit cases named `link_rule_*`: one link; a repeated link keeps the first `since`; a link after an unlink
   takes the later `ts`; an unlink of an absent pair; two drivers of one driven; a line with a non-string name.
   A new test helper must not be named `link` (one exists at `replay.rs:455`).

13. **The three result lines** (`src/human.rs`). One writer each, stdout, plain in every mode, the forms of
    design-system §Surface: cli → Component Patterns, component 4:
    - `link` then four spaces, `<driver> -> <driven>`, two spaces, `since`, one space, the UTC clock time of

    - `unlink` then two spaces, `<driver> -> <driven>`.
