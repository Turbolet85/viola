## Goal
A `viola verify` stopped by Ctrl-C or TERM now ends its run cleanly. It ends the child it is running with no key,
removes only the dirs that run created, prints one `unable:` / `hint:` pair, logs
`process-exit{subject:"self", exit_code:1, detail:"interrupted"}` and exits 1. It writes no stamp, no step line and
no `stamped` line. Older, foreign and kill-or-crash leftovers stay by hand. No owner record and no remover of an
earlier run's dirs is built. This is the founder's narrow entry (scope.md §1, CARRY), and the operator answered its
three open forms at P4 (`inputs#I2`).

Ctrl-C and TERM mean Unix `SIGINT` and `SIGTERM`, and Windows `CTRL_C_EVENT` and `CTRL_BREAK_EVENT`. A closed console
window, logoff, shutdown, SIGKILL and a crash keep their default and are the stated exception (`inputs#I2`;
research.md §Measured facts 3). Every wait verify makes already polls a predicate on a short `POLL`. A stop flag read
in the same loops ends a wait within one `POLL`, and the run's existing kill and drop guards then do the rest
(research.md §Measured facts 2, 4). The handler sits on `libc` (Unix) and `windows-sys` (Windows), both already the
root package's. No manifest line and no `Cargo.lock` package changes (research.md §Measured facts 6).

The chunk also moves two CARRY'd literals onto their one homes, both behaviour-preserving (research.md §Measured
facts 7). Verify's default program becomes `viola_agent_claude::PROGRAM`, and Runs C and D's `--settings` becomes
`viola_agent_claude::statusline::SETTINGS_FLAG`. Per architecture §Occupied Resources, security-plan §Data Protection
and §Threat Model Summary, obs-plan §4 / §6, test-plan §5 / §11, design-system and layout-templates §Surface: cli.

## Implementation Steps
1. **The stop, `src/cmd/verify/stop.rs` (new).** One stop flag for the verify process, with:
   - `install`, called once by verify;
   - a read;
   - a set that tests use with no signal.

   The handler only sets the flag (an async-signal-safe store). On Unix it is installed for `SIGINT` and `SIGTERM`
   through `libc`'s `sigaction`.

   On Windows a console control routine is registered through `windows-sys`'s `SetConsoleCtrlHandler`. The routine sets
   the flag and returns TRUE for `CTRL_C_EVENT` and `CTRL_BREAK_EVENT`. For every other event it returns FALSE without
   setting it, so the OS default stands.

   Which events stop is a plain function of the event number, tested on every OS. The `cfg(windows)` routine only
   forwards to it (testing.md 2026-09-24, the `cfg` reader rule). A failed install, such as no console on Windows,
   is ignored: the run goes on as it does today, fail-open.

   Each FFI call sits in its own `unsafe` block, as `src/panic_frames.rs` does. The module carries its inline
   `#[cfg(test)] mod tests` (step 7).
2. **Install before the first child (`src/cmd/verify.rs` `measure`).** `measure` installs the stop as its first act,
   before program resolution, the pin and the version probe (`verify.rs:102`–`:156`). By then `main` has already run
   the panic hook and `restrict_dll_search()` (`src/main.rs:48`, `:52`). Verify is the only verb that installs it. No
   other verb's signal behaviour changes.
3. **The bounded children observe the stop (`src/run/version_gate.rs` `run_bounded`).** `run_bounded` takes one more
   input, the stop. When the stop reads set, it kills the child, reaps it and returns with the outcome "stopped", which
   is told apart from the deadline's kill. `version_gate` (`version_gate.rs:115`) passes an input that never stops, so
   `run`'s gate is byte-for-byte unchanged in behaviour. Verify's `run_logged` (`verify.rs:76`) passes the stop and
   still writes its spawn pair: the `process-exit` of a stopped child carries `duration_ms` and no
   `child_exit_status`.
   - When the version probe or the print probe is stopped, `measure` ends as step 5 says, before `ProbeDir` exists or
     with `ProbeDir` dropped on the return.
   - Impact: `run_bounded` @ `src/cmd/verify.rs:86`, `src/run/version_gate.rs:115`, and its two unit cases `:301`,
     `:321` (research.md §Graph impact).
4. **The interactive runs observe the stop (`src/cmd/verify/typed.rs`).**
   - **The waits.** Every wait a run makes returns as soon as the stop reads set. That covers `wait_for` (`:195`),
     `wait_capture` (`:328`), and the loops in `Run::settle` (`:639`) and `Run::box_wait` (`:655`). The polling those
     four loops share becomes one plain function of a clock, a deadline, the stop and a predicate, unit-tested with the
     stop set and unset.
   - **The Ctrl-C ending.** The stop also ends the two waits of `ctrl_c_ending` (`:543`) early, so a stop during Run
     B's Ctrl-C ending goes straight to its kill.
   - **The pump wait is the exception.** The wait for the pump to end after a kill, `ended_by` inside `Run::finish`
     (`:705`), does NOT observe the stop. A run's dir is never removed while its child may still be writing into it.
   - **Ending a stopped run.** After any wait returns, a run that finds the stop set ends its child with
     `Run::end_by_kill` (no key, `:684`) and drops its dir. `measure` (`:63`) then returns the outcome "stopped" and
     starts no later run.
   - **Normal runs are unchanged.** A run that is not stopped behaves exactly as today: Run B's Ctrl-C ending, every
     deadline, paste, guard and order.
   - **The literal.** The two `--settings` literals (`:132`, `:173`) read `SETTINGS_FLAG`.
   - Impact: `end_by_kill` from `measure` `:77`, `trusted_run` `:111`, `dialog_run` `:159`, `plan_run` `:188`;
     `settle` ×7, `wait_for` ×4, `wait_capture` ×2 (research.md §Graph impact).
5. **The interrupted outcome (`src/cmd/verify.rs`).**
   - **When the stop counts.** `measure` reads the stop:
     - when a bounded child or `typed::measure` reports "stopped";
     - once more after `typed::measure` returns and the probe dir is dropped, before `check_rows` (`:211`).

     Set at either point, `measure` prints no step line, calls neither `update_stamps` nor `record`, and prints the
     pair below through `human::refuse` (`src/human.rs:38`). Once `check_rows` has begun, the run completes as today.
     The stamp write is atomic through `replace_private` (research.md §Measured facts 4).
   - **The pair.** The stderr pair, verbatim (a planning form on the operator's word, the founder's wording owed;
     `inputs#I2`):
     ```
     unable: verify was stopped before it finished
     hint: run viola verify again to stamp this CLI
     ```
   - **Exit and log.** The exit is 1. Under a `VIOLA_NAME`, `verify` (`:67`–`:69`) writes
     `process-exit{subject:"self", exit_code:1, detail:"interrupted"}` through `run::log_self_exit`.
   - **Default program.** The default program (`:105`) reads `viola_agent_claude::PROGRAM`.
6. **The schema (`schemas/diag-line.v1.json`).** `process-exit.detail` gains the member `interrupted`, making it 12
   members (the rule: the enum's members as listed in research.md §Files inspected, plus this one). No other schema
   change.
7. **Unit cases (inline `#[cfg(test)] mod tests`, literal oracles).**

     - the existing `ctrl_c_ending` / `ended_by` cases stay green.
   - `version_gate.rs`:

   - **Holding the run.** Run B pastes its prompt and then waits for a Stop that never comes (research.md §Measured

   - **The planted dirs.** Before the start, the test plants three foreign dirs: `<cwd>/.viola-verify-0` and

   - **The signal.** The test waits for the receipt's third `cwd` line and first `prompt` line, an observed event and

- Decisive leans:
  - **Every stopped run ends by kill with no key.** The basis is security-plan §Threat Model Summary: no byte goes into
    any dialog, and a modal start is killed with no key. A stop can land while any screen is up, and only a kill types
    nothing. Run B's founder-ruled Ctrl-C ending is its normal end, and it stays unchanged. The stop path is a new end,
    not a change to that ruling.
  - **The handler lives in the root package, verify-local.** It is the only process that installs it. `viola-pty`
    stays agent-agnostic and gains no process-wide disposition. The edge is already the root's (research.md §Measured
    facts 6).
  - **The stop is read once more after the interactive runs, never after `check_rows` begins.** Past that point the
    measurement is complete and the stamp write is atomic.
  - **A second Ctrl-C during the cleanup changes nothing.** The flag is already set. The cleanup's waits are the
    existing kill and pump join, which end at once after a kill (research.md §Measured facts 4). The stop path adds no
    bound.
  - **Sized against one window** (`inputs#I1`): one verb's stop path, about ten wait and ending sites in one file, one
    `run_bounded` input, one schema member, two literal moves, two integration cases and about eight unit cases. No
    split is proposed.

## Constraints & rejected approaches
- **A crate such as `ctrlc` or `signal-hook`, or `tokio::signal`.** The existing `libc` / `windows-sys` edges carry the
  handler (research.md §Measured facts 6), and `tokio` is banned in sync crates (architecture §Cross-cutting
  Patterns, Tokio containment).
- **Removing anything by a pattern or a listing.** That rules out a glob of `viola-verify-*`, a `<pid>` scan, an older
  run's dir, another process's dir, an owner record or a SIGKILL / crash recovery (the founder's narrow entry, CARRY).
  The same-pid pre-clean in `ProbeDir::create` / `TrustedDir::create` predates the ruling and stands unchanged
  (research.md §Measured facts 8).
- **Typing Ctrl-C, or any byte, into a PTY child on the stop path** (security-plan §Threat Model Summary).
- **Making the pump wait after a kill (`ended_by` in `Run::finish`) observe the stop.** The dir would then be removed
  under a child that may still write into it.
- **Holding `CTRL_CLOSE_EVENT` (or logoff / shutdown) for cleanup.** The operator chose Ctrl-C and Ctrl-Break only
  (`inputs#I2`). The OS terminates the process about 5 s after a close handler starts.
- **A Windows integration case that delivers `CTRL_BREAK_EVENT` to a running verify.** It is not chosen (`inputs#I2`).
  Whether the runner's test process has a console is unmeasured.
- **A new exit code (130).** Exit 1 is inside architecture's set (`inputs#I2`).
- **A new fake-agent option or test seam to hold verify mid-run.** The existing flags without `--turn-stop` hold Run B
  in its turn wait (research.md §Measured facts 5). A new seam is a boundary widening (security-history
  `2026-09-28-hook-perf-gate`).
- **A `sleep` before the signal, a `kill()` after it, or a signal at a process the test did not start** (testing.md
  2026-10-10; test-plan §10 Coverage thresholds, the short-profile rule).
- **Changing verify's probes, texts, deadlines, order, stamps or ledger rows on an uninterrupted run, or any other
  verb's signal behaviour.**

## Implementation notes
- Mechanism, stated as the equality the cases need (research.md §Measured facts 4). With the stop set, a wait returns
  within one `POLL`: 5 ms in `typed.rs` (`:38`), 10 ms in `run_bounded` (`version_gate.rs:23`). The kill and the pump
  join then precede the guards' drop on the return. The frames that produce the asserted quantities are the polling
  loops, `Run::kill` (`typed.rs:675`) and the `Drop` impls (`verify.rs:304`, `typed.rs:363`, the `TempDir` at
  `typed.rs:68`).
- On Unix a terminal's Ctrl-C also reaches the `run_bounded` child, which shares verify's process group. The PTY
  children are their own session leaders and see no signal. Verify ends whichever child it is running
  (research.md §Measured facts 3).
- The case waits for the receipt's third `cwd` line and its first `prompt` line, and signals only then. At that point
  the UserPromptSubmit hook has already run and no hook is in flight, so the kill hangs up none (verification-harness.md,
  the fake agent's exit rule).
- A new `Instant::now() + WITHIN` wait in the stop case's receipt watch moves the registered count of root `WITHIN`
  sites, 28 in 20 files (the rule: the pattern `Instant::now() + WITHIN` under `tests/`, test-plan sidecar
  `2026-10-10-budget-governor`). Re-take it with that rule at the wrap; it is not counted here.
- A script that edits a `.rs` file runs `rustfmt` in the same call. Pipeline-tool output is redirected to a file and
  read whole (the handoff's standing rules). Every record time comes from `date -u` in the writing call (`inputs#I1`).
