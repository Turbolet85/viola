## Goal
Every process that reads or opens anything under the viola home first refuses a home, instance tree, code-bearing
folder or diagnostics file another user could write (or read, where content lives), and does it before the first open,
because opening a role file narrows an existing home to 0700 and a check made after it passes a 0770 home (CARRY 14,
re-derived at src/obs.rs:43–45, 76–78). The check lands at the six CLI frame verbs, `viola hook`'s nine events, `viola
mcp`'s frame tools, `viola verify`, `viola run` (and `revive`'s start) and the diagnostics opens, closing the eight dated
strict-modes gaps the founder ratified until this entry (per security-plan §Authentication & Authorization, `~/.viola/`
access control; the detail authentication-authorization.md:25–39). The master's read rule lands with it: Unix `mode &
0o077` on the home and `instances/<name>/`, and on Windows a read grant to another SID on the home, `instances/<name>/`,
its `diagnostics/` and `events.ndjson` (authentication-authorization.md:38, :40) — neither is in code today
(strict.rs:76–84 refuses `0o022`, `windows_verdict` write rights only).

By the founder's own answers (`inputs#I3`): the four snapshot readers (hook `connect`, hook statusline `serve`, `run`'s
`collision_check`, `viola_state::liveness::live_endpoint`) move onto `read_snapshot_or_replay`, each after the new check
(his ratification of that boundary widening; test-plan §6 E5 steps 1–3); a refused check at every new entry point writes
no line, as `link` / `unlink`; the six frame verbs print `link`'s instance pair; and CARRYs 11 and 16 (build
reproducibility, the `pin_exe` race) leave this chunk for a new entry «Pinned copy race and reproducible builds» right
after this one (the P5 card's Beyond-the-plan row). The Windows proofs (the widened instance tree, the seeded home's
DACL, the `RUNNER_TEMP` negative, the `conpty/` leg) run on CI's `test (windows-2025)` leg (per test-plan §9; §11 «NEVER
treat a Linux-only local run as proof for Windows»).
