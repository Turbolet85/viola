   `viola-e2e` dependency (test-plan.md:542).
2. **Fake agent: argument surface** (`src/bin/viola-fake-agent.rs`). Parse, in any order:
   - `--version`
   - `--cli-version <v>` (default `2.1.0`, existing `cli_version` @ `src/bin/viola-fake-agent.rs:19`)
   - `--report-version <v>`: overrides ONLY the `--version` answer, so replay still follows `--cli-version`
   - `--script <path>`, `--control <path>`, `--receipt <path>`, `--fixtures <dir>`, `--plugin-dir <dir>`
   - the mode flags `--suppress-prompt-submit`, `--local-command-mode`, `--inject-harness-turn`, `--exit-no-eof`

   Every other argument is ignored, as today (`run_cli.rs` passes `--argv-sentinel-q1`). Paths are used exactly as
   given: resolving a relative `--script`/`--fixtures` against the workspace root is the caller's job (the root chain,
   step 9), never the fake agent's.
3. **Fake agent: receipt.** With `--receipt <path>`, the agent creates the parent dir if it is missing and appends one
   compact JSON object + `\n` per single `write` (append mode). Every line carries `"v":1` and a kebab-case `kind`;
   fields are snake_case. Without `--receipt`, no receipt is written. Kinds and their fields (the harness-owned
   receipt contract):
   - `start` {`cli_version`}
   - `env` {`names`: sorted env var NAMES, never a value}
   - `fds` {`fds`: sorted open descriptors from `/dev/fd`}, Unix only; no line on Windows
   - `key` {`hex`}: one line per byte received outside a bracketed paste
   - `prompt` {`text`, `hex`, `bare_esc`, `origin`: `human`|`harness`, `submit`: `fired`|`suppressed`|`local-command`|`no-fixture`|`no-hooks`}
   - `hook` {`event`, `command_absolute`, `ran`, and when `ran`: `exit_code`, `stderr_len`, `stdout_hex`}
   - `step` {`index`, `event`}

   Receipt lines never carry an absolute path or an env value.
4. **Fake agent: input.** Read stdin byte by byte:
   - `\x03` ends the process with exit 0, as today.
   - `ESC[200~ … ESC[201~` collects paste content; the next CR submits it as ONE prompt (`origin:"human"`).
   - Bytes typed outside a paste each produce a `key` line; a CR after typed bytes submits those bytes as one prompt.
   - `bare_esc` is true when the prompt's bytes contain `0x1b`.
   - Text is decoded lossily; `hex` is always the exact bytes.
5. **Fake agent: hook invocation.** For event E:
   - Read `<plugin-dir>/hooks/hooks.json` (architecture.md:345/364) as the documented Claude Code hooks shape
     `{"hooks":{E:[{"hooks":[{"type":"command","command":…,"args":[…]}]}]}}`. Run every `type:"command"` entry
     registered for E; matchers are NOT evaluated this chunk (see Constraints).
   - The payload is the bytes of `<fixtures>/<cli-version>/<E>.<variant>.json`. For `UserPromptSubmit` only, the
     top-level `prompt` key is set to the prompt text (the documented input field). No other payload is built.
   - An absolute `command` is spawned directly with its `args`: never through a shell, never via PATH lookup. Its
     stdin is the payload; exit code, stderr length and stdout bytes are captured into a `hook` receipt.
   - A non-absolute `command` is not run: `hook` {`command_absolute:false`, `ran:false`}.
   - With no `--plugin-dir` or no `hooks.json`: `no-hooks`. With no fixture file: `no-fixture`. In both cases no
     process is spawned.
6. **Fake agent: prompt-submit modes.**
   - A submitted prompt fires `UserPromptSubmit` with variant `default`.
   - `--suppress-prompt-submit` never fires it (`submit:"suppressed"`).
   - `--local-command-mode` does not fire it for a prompt whose text starts with `/` (`submit:"local-command"`); any
     other prompt fires normally.
   - `--inject-harness-turn` adds one gated step before the script's first step. When released, it fires
     `UserPromptSubmit` whose `prompt` starts with the harness-turn prefix `<task-notification>` (architecture
     §Established Decisions [Human Takeover / Wheel]) and writes a `prompt` receipt with `origin:"harness"`.
7. **Fake agent: script + control.**
   - `--script <file>` is JSON `{"v":1,"steps":[{"event":E,"variant":V,"gate":bool},…]}`, where E is one of the nine
     registered hook events (architecture.md:344). The steps run in order on their own thread, and stdin keeps being
     read.
   - A `gate:true` step blocks until one more complete line (`\n`-terminated) exists in the `--control` file past the
     agent's last byte offset. A missing control file reads as empty. The agent polls; the TESTS never sleep.
   - Each executed step writes a `step` receipt, then fires E (step 5).
8. **Fake agent: `--exit-no-eof`.** At `\x03` the agent first spawns a copy of itself (its own exe, hidden internal
   argument) that inherits stdout and holds it for a bounded 10 s, then exits 0. The process exit can therefore be
   observed while stdout has not reached EOF. The grandchild never outlives 10 s.
9. **Root fixture chain** (`tests/support/mod.rs`, `tests/support/home.rs`, `tests/support/fake.rs`; sync, no tokio):
   - `home`: a `tempfile::Builder` dir with prefix `viola-test-` under `<CARGO_MANIFEST_DIR>/target/e2e-home/`, with
     the home at `<dir>/home`. The home is NOT created; viola creates it. On drop it keeps the dir
     (`TempDir::keep()`) when `AGENT_RUN_KEEP_HOMES=1`, or when `AGENT_RUN_KEEP_FAILED=1` and the thread is
     panicking; otherwise it removes the dir. The decision is a pure function with a unit test over all four inputs.
   - `fake_agent_path`: `env!("CARGO_BIN_EXE_viola-fake-agent")`.
   - `stamped_home`: the interim seam. It returns the home with a documented "not stamped until `viola verify`
     exists" marker and never writes `ledger/stamps.json` (test-plan §7, §12 Stamps conflict).
   - `booted_wrapper`: spawns `viola --home <home> run <name> -- <fake agent> --control <home>/fake/<name>.control
     --receipt <home>/fake/<name>.receipt.ndjson [--script <workspace-root-resolved path>] <args>` with piped stdin,
     and env set per child only (`Command::env`). It waits (bounded 20 s, file-state probe, no sleep-as-sync) for the
     interim readiness lines `process-start` self + `claude-child` in `diagnostics/run-<name>.ndjson`.
     It exposes: write stdin bytes, append a control line, read receipt lines, and `stop()` (`\x03`, then wait).
     `Drop` is only a best-effort fallback.

- Evaluating hook `matcher`s is deferred. Every `command` for the event runs, and matcher semantics land with the
  drift contract, where recorded `tool_name`s exist.
- Running cargo-mutants on a Rust-free diff and trusting its silent exit 0 is rejected. The harness classifies the
  diff itself, and a stale `mutants.out/` can never feed a verdict.
- A sleep in any test is rejected: order comes from control appends and receipt lines. The fake agent's own
  control-file poll and the `--exit-no-eof` grandchild's bounded hold are inside the double, not in tests.
- Reading `instances/<name>/settings.json` is deferred with `statusline-echo`: the settings-override mechanism is an
  unrecorded ledger row (architecture.md:346).
