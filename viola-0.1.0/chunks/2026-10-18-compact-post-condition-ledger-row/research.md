## Measured facts
1. **The equality the post-condition needs** — "a `send` of `/compact` on a verified CLI is claimed by the next `session-start` whose `cause` is `compact` and whose `agent_session_id` equals the id the slot remembered before that line". The normalised line carries both fields: `compact` is a closed cause (`hook.rs:106`) and `agent_session_id` the payload's `session_id`. The live line has them: on 2.1.287 the SessionStart after `/compact` had `source` `compact` and the first id (`live-revive.md:87`, `:101`, `:103`). The frame that decides it is `session_started` (`slot.rs:103`–`:119`); today it overwrites the remembered id first, so the same-id arm must read the prior value before the overwrite. With nothing remembered, no line can equal it: the send is not claimed and waits out its window (never presumed, architecture §Established Decisions [Delivery Confirmation]).
2. **The window** — the one measured compaction took 18.8 s from the send's issue to its SessionStart (14:49:11.194 → 14:49:29.973, `live-revive.md:99`–`:101`), on a session of two short turns (`:147`: "`/compact` on a long session" not measured). Nothing in the tree measures a longer session's compaction (sweep: no other compaction reading under `viola-0.1.0/chunks/*/evidence/`). The ceiling: `GATE_MAX_WAIT` 8.5 s + paste + window must stay under the MCP client's tool-call timeout, which on 2.1.287 is only known to exceed 50 s (a `wait` answered at 50 012 ms, `architecture.md:58`). A window of 40 s gives 48.5 s plus an 8-byte paste, under the 50.012 s reading; 41.5 s is the arithmetic edge.
3. **A compaction inside Run B leaves the other rows' checks true** — `clear_start` searches source `clear` only and `local_command_cleared` compares with Run B's first id, which the compaction keeps (`ledger.rs:807`–`:828`); `framing_variants` takes clear's SessionEnd at `at - 1`, still clear's own when the compact SessionStart precedes it, unless the CLI fires a SessionEnd for `/compact` (unmeasured: the revive reading lists only the `session-start`). Run E resumes Run B's first id, which would then be a compacted session; a resume after a compaction was measured once on 2.1.287 (`live-revive.md`, start 3 resumed the same id after start 2's `/compact`).
4. **The fake agent's replay needs the session id set** — a recorded `SessionStart.compact-1.json` carries the recorded Run B's id, while the fake agent's launch SessionStart carries the set's `default` id (or a resumed one, `viola-fake-agent.rs:438`), so a byte-unchanged replay cannot satisfy the same-id claim; the `--resume` precedent sets `session_id` on a recorded variant and the drift contract stays byte-equal when given the variant's own id (`contract_fake_agent_drift.rs:417`–`:428`).
5. **The no-screen verify case is not lengthened** — `verify_window_without_screens_fails_every_interactive_row` (42.98 s against the mutants profile's 45 s kill, handoff) never reaches `framing_turns`: without screens Run B's input box is never up (`typed.rs:144`), so an added paste adds no wait there. With screens the added paste adds one fake-agent settle (`box_wait`) to the framing cases.
6. **The live cost of the probe** — a `/compact` paste in Run B is one more model call inside a start verify already makes (no start, spawn pair or `subject` added: obs extract; `verify-pty-probe` stays one pair per run); whether it adds a transcript under `~/.claude/projects/` is unmeasured (security-plan §Data Protection, Accepted risk).
