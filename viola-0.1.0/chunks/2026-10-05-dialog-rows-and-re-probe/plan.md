## Goal
The capability ledger gains its dialog tier. It adds four rows, each with a `viola verify` post-condition measured
live on the installed `claude`:
- `question-answer` (S3);
- `plan-approve-revise` (S7);
- `question-notes` (S8);
- `dialog-concurrency`.

They are measured by two new interactive runs beside Run A and Run B: Run C for dialogs and Run D for plan mode. In
both, the probe's own hook answers each dialog with a body the product's `dialog::decision_body` builds. viola never
types a key into a dialog (the founder's ruling, inputs#I3). The decision taking effect is read at the hook layer:
- a PermissionRequest that never comes;
- a PostToolUse that does come;
- a re-plan after a revise.

The prototype measured exactly this on 2.1.287 (inputs#I2, research M7), and 2.1.288's binary carries the path
(research M6). This chunk measures it with viola's own bodies.

The grown ledger closes the founder's R2 dated gap without a new contract. architecture [CLI Version Compatibility]
already says a version is verified only when every landed row passes, and that an unverified version withholds
dialog answers. So a non-`null` decision now needs the dialog rows. Run C and Run D record the first real dialog
fixtures for 2.1.288 and 2.1.287, which supersede the relayed set as measured truth. A new fake-agent argv mode
replays them, so CI stamps all fourteen rows without a credential. The `permission` end-to-end case and the
`tests/cli_answer.rs:9` reword go to "Permission end to end" (founder, P4).

## Constraints & rejected approaches
- **Typing into a rendered dialog (path C)** — rejected by the founder (inputs#I3). It would also never run viola's
  bodies.
- **The product path through `viola run` (path D)** — rejected. It needs a gate bypass, which is a widening of the
  decision gate.
- **Capture only (path B)** — rejected. "Takes effect" would stay unmeasured and S7 would be shape-only.
- **A split verdict** (spine + screen gate typing, dialog rows gate decisions) — not built. Leaned on architecture
  [CLI Version Compatibility]: "A version is verified only when its stamp holds every landed row `pass`", and an
  unverified version withholds dialog answers. Consequence, accepted at P5 (the operator, the overseer having checked
  the plan): one verdict means a model that skips the dialog tool unverifies the whole version, its readiness gate
  included (research M4). So a red record run must name the failed row: the `[NN/14] <row-id> … fail` step line
  verify prints, quoted into `evidence/live-sessions.md` and the report, never only the summary count. The report
  records this consequence under its decisions.
- **Changing the wrapper's one-pending rule from the concurrency measurement** — not here. The row and the
  `measured.dialog_probe` field record the CLI fact. A wrapper change, if any, is a later decision.
- **A row for the permission body** — not added. architecture lists S3/S7/S8/concurrency only. Run C's `touch` exists
  to record the ordinary-tool PermissionRequest fixture "Permission end to end" consumes.
- Never a Ctrl-C or any key into Run C / Run D. Never an env seam for `--dialogs`. Never a third probe subject.
  Never `--home "$h/home"` for a record.
- Never retry a live entry without the operator's word. The spare 4 sessions are the operator's to spend.
