## Goal
Make every byte of human text the `viola` binary prints today obey the cli surface's colour ban, and give the one
live human-stderr consumer, `run`'s start refusals, a single refusal writer. The chunk ships only what has a real
consumer now (the P4 operator ruling below).

Two things change:
- **clap's own output goes plain.** clap's default `color` feature colours `viola --help` and usage errors with
  bold/underline headers. It also obeys `CLICOLOR_FORCE`, which put 25 ESC bytes into piped `--help` output (research
  F1, measured). Both break design-system §Surface: cli (colour only on `DIALOG` / `stale`, never under non-TTY) and
  a11y-plan §6's CLI equivalent. Turning the feature off removes clap's colour code and its silent reads of `CLICOLOR`,
  `CLICOLOR_FORCE`, `NO_COLOR`, `TERM`, `COLORTERM` and `CI` (anstyle-query-1.1.5 src/lib.rs:24-134). That makes
  architecture.md:586's "the only other variables any `viola` build reads are the two test seams" true again. The
  change is a lockfile removal and adds nothing.
- **The start refusals print through one writer.** `run`'s five start refusals keep their exact two-line text
  (design-system §Surface: cli → Component Patterns 2, exit-1 start refusals). They are written by a new
  `src/human.rs` refusal writer as one write of the `unable:` / `hint:` pair, with `hint:` last (design-system §Streams;
  a11y-plan §8 Error recovery). The writer is unit-tested over any `io::Write`, and a failed write is swallowed, never
  a panic (obs-plan §10 zero unlogged panics).

**Operator ruling at P4 (overseer, founder-delegated: "no abstraction over emptiness, no code without a real
consumer plus a test").** The SGR tokens, the colour decision and depth rule, the env/TTY/VT fact reader, the
env-var admission and the control escaper have no production consumer until `wait`/`last`, Confirmed send and
`viola list` land. They leave this chunk as route CARRYs, each named with its owner under Implementation notes, for
the wrap route-resolve to place. The two folded CARRYs (the catch-site `error: internal error`, the WSL root-install
restriction) do not bind here and move on to working-route.md:53 (scope.md §Folded freight, verified at P3).

## Implementation Steps
1. **clap without `color`** — in the root `Cargo.toml` `[workspace.dependencies]`, change the clap line (Cargo.toml:143)
   to `default-features = false` and list every other default feature explicitly: `std`, `derive`, `help`, `usage`,
   `error-context`, `suggestions`. Regenerate `Cargo.lock` with a plain `cargo build`, not `cargo update`, so that no
   other version moves. Afterwards `Cargo.lock` no longer names `anstream`, `anstyle-query`, `anstyle-wincon` or
   `colorchoice`, and gains no package. Record in the report which packages left, from the lockfile diff. `anstyle`
   itself stays: clap_builder depends on it without the feature.
2. **The refusal writer** — create `src/human.rs`, declared from `src/main.rs` beside the other root modules. It holds:
   - `write_refusal`, generic over `io::Write`: writes `unable: {unable}\nhint: {hint}\n` as ONE `write_all` and
     returns the `io::Result`.
   - `refuse(unable, hint)`: locks `io::stderr()`, calls `write_refusal` and discards the result. This is the as-built
     form at run.rs:360-364 moved here unchanged in behaviour, except that the pair is now one write instead of two
     `writeln!`.

   No `print!` family and no `#[allow]` (Cargo.toml `[workspace.lints.clippy]`). The module doc names design-system
   §Streams (refusals and hints on stderr, `hint:` last) and says that later consumers (send, wait/last, list) extend
   this module with their own writers when they land.
3. **Route `run` through it** — in `src/cmd/run.rs`, delete the local `refuse` fn (run.rs:360-364) and have its five
   callers call `crate::human::refuse`. The callers are `refuse_batch_script` @ run.rs:367, `refuse_live` @ run.rs:376,
   `refuse_stale` @ run.rs:381, `refuse_tampered_pin` @ run.rs:388 and `refuse_squatted` @ run.rs:397 (research.md
   §Graph impact, rust-plane `calls` query, 5 rows). Their text is unchanged. Drop any `use` that becomes unused.
4. **Unit tests in `src/human.rs`** — an inline `#[cfg(test)] mod tests` with rstest cases and literal oracles:
   - `write_refusal_writes_the_pair_in_one_write`: a recording writer counts `write`/`write_all` calls and captures
     the bytes. Expect exactly one call carrying exactly `unable: builder is already live\nhint: viola list\n`.
   - `write_refusal_puts_the_hint_last`: the captured bytes end with the `hint:` line, and the `hint:` line is the last
     one.
   - `write_refusal_returns_the_writer_error`: a writer whose `write` fails returns an `Err` of the same kind, and
     nothing panics.

   `refuse` itself gets no unit case, because stderr cannot be closed per test. Its body is one call with the result
   dropped, and the integration refusal constants (step 5's gate list) cover it.
5. **Process witnesses** — create `tests/cli_output_plain.rs`, with a `[[test]]` entry in the root `Cargo.toml`
   carrying `required-features = ["fake-agent"]` like its siblings, because it uses `tests/support`. The cases are:
   - `help_is_plain_when_colour_is_forced_into_a_pipe`: `viola --help` with `CLICOLOR_FORCE=1` and `CLICOLOR=1` set
     through `Command::env`, stdout piped. Expect exit 0, zero `0x1B` bytes in stdout and stderr, and stdout still
     contains `Usage:`.
   - `usage_error_is_plain_when_colour_is_forced_into_a_pipe`: `viola frobnicate` under the same env. Expect exit 2,
     zero `0x1B` bytes in stdout and stderr, and stderr contains `error:`.
   - `help_is_plain_on_a_terminal`: `viola --help` under `tests/support/outer_pty.rs`'s `OuterPty` with no colour
     variable set, waited to exit within `EXIT_WITHIN`. Expect exit 0, and no SGR in the drained stream whose
     parameter list contains `1` (bold) or `4` (underline). The test parses the stream's `ESC [ params m` sequences
     and checks their numeric parameters, and never searches the screen text. That is the literal-absence oracle for
     viola's own bytes on Windows, where ConPTY adds its own `ESC[m` / `ESC[?25l` / title bytes (a11y history
     `2026-09-25-pty-wrapper-on-windows`). On all three OSes clap's coloured help carries bold/underline headers
     (`\x1b[1m\x1b[4mUsage:` measured piped under `CLICOLOR_FORCE`, research F1), so the parse is red at HEAD by
     construction of what clap prints.

   Env is set per child only; never `std::env::set_var` (testing.md Determinism).
6. **Guard runs** (testing.md 2026-09-25) — with the tests in place, temporarily put `color` back into the clap
   feature list, run `bash scripts/agent-run.sh run --integration --filter 'binary(=cli_output_plain)'`, and record the
   red reading. Then restore and record the green one. Also temporarily revert step 2's single write to two

   restore. Re-Read each site before the neutralising edit, because the rustfmt PostToolUse hook reflows files.
   Record all four readings in the report.

## Constraints & rejected approaches
- A bin module with `#[cfg_attr(not(test), expect(dead_code))]` over the tokens, decision and escaper — rejected by the
  operator at P4: no code without a real consumer.
- Moving the pure pieces into `viola-core` as `pub` — rejected: it contradicts design-system §Surface: cli → Toolkit
  ("a small hand-written SGR module in the `viola` bin") and would not give them a consumer either.
- `ColorChoice::Never` / `Styles::plain()` on the clap `Command` instead of dropping the feature — rejected: it keeps
  anstream and its env reads in the binary, and keeps the dead colour code in the lockfile and the deny graph.
- Reusing `viola_pty::vt_output_mode` (`0x000c`) for viola's own lines, when the VT enable lands — do not: it adds
  DISABLE_NEWLINE_AUTO_RETURN, which is right for the child's screen and wrong for `\n`-terminated lines (research,
  Patterns). This is recorded for the `viola list` CARRY, not built here.
- Two `writeln!` calls for the refusal pair — replaced by one write so the pair cannot interleave with another
  writer's bytes on a shared stderr.
