## Goal
Every viola client that writes a frame to a wrapper's endpoint verifies, before its first frame, that the process
serving the endpoint is the wrapper `snapshot.json` records: the connected stream's server pid equals the snapshot's
`pid`, and that pid's OS start time equals its `started_at` (security-plan §Authentication & Authorization, IPC
client-side server verification row; §Security Anti-Patterns › Authentication). The clients are the six CLI frame verbs
(`send`, `wait`, `last`, `answer`, `pause`, `release`), `viola hook`'s two (`hook.event` on every event, `hook.dialog`
on `pre-tool-use` / `permission-request`) and `viola mcp`'s four frame tools (`send`, `wait`, `last`, `answer`) — every
product connect site (research.md Sweeps).

On a mismatch, or a check that cannot be made, no frame is written: a CLI verb exits 21 with the
`{"v":1,"error":"instance-unreachable","detail":null}` document or its `unable  instance-unreachable` line and the
server-verification hint; an MCP tool returns its `instance-unreachable` `isError` result; `viola hook` fails open —
exit 0, nothing on stdout or stderr (architecture §Conventions exit codes / MCP; §Established Decisions [Hook
Contract]). The process log names the cause: `process-exit{exit_code:21, detail:"server-verify-failed"}` and
`hook-decision{detail:"server-verify-failed"}`, both already members of `schemas/diag-line.v1.json`'s closed enums
(obs-plan §6 Log Coverage, Founder Direction 4).

This closes the server-identity half of the first and the fourth to eighth dated gaps on Linux and Windows. Their
strict-modes half stays with "Home and code-bearing file integrity", and macOS — whose peer credentials carry no pid —
stays on the recorded gap, its euid and socket-directory checks owned by "Unix endpoint and home hardening". Every
snapshot reader keeps `read_snapshot` (the fork's option 1, `inputs#I3`, PROVISIONAL until the founder's own word).

## Implementation Steps
1. **The server pid on the sync client** (`crates/viola-channel/src/client.rs`). `Client` gains one read of the
   connected stream's peer credentials, `peer_creds().pid()` (interprocess 2.4.4 `traits::StreamCommon`): on Linux the
   socket's `SO_PEERCRED` pid, on Windows `GetNamedPipeServerProcessId` on the SQOS-adopted client end, on macOS none.
   It writes nothing to the stream and logs nothing. The Windows open stays `open_handle`'s SQOS + overlapped
   `CreateFileW` adopted by `Stream::try_from`, never a default connect. Unit cases in the module's tests: a `Client`
   connected to a `Server` the test serves reads the test process's own pid, `#[cfg(not(target_os = "macos"))]`; on
   macOS it reads none, `#[cfg(target_os = "macos")]` (keeps arch S2, S3; tests S2).
2. **The same read on the Tokio client** (`crates/viola-channel/src/tokio_client.rs`): `TokioClient` gains the same
   read off its stream, behind the `tokio` feature as the whole file is; no new tokio feature and no new dependency.
   Unit cases mirror step 1's two.
3. **The verification decision and the pre-check's identity** (`crates/viola-state/src/liveness.rs`).
   - `live_endpoint` returns, beside the endpoint, the recorded `pid` and `started_at` it already read from the same
     snapshot in its one `read_snapshot` call (no second read, the file not held open past the read: architecture
     §Established Decisions [Snapshot writer], the Windows `persist` retry).
   - A pure decision takes the recorded `pid`, the recorded `started_at`, the observed server pid (`Option<u32>`), the
     observed pid's start time in whole seconds (`Option<u64>`) and whether the platform reports a peer pid at all, and
     returns a closed verdict: the server matches · it does not (another pid, or the same pid with another start time)
     · it cannot be checked (`started_at` not RFC 3339, no observed pid on a platform that reports one, the observed
     process gone). On a platform with no peer pid (macOS) it returns "matches" with no comparison — the recorded gap,
     never a refusal. The platform fact is the decision's argument, not a `cfg!` inside it, so every row runs on the
     Linux host.
   - One function joins them: the observed pid's start time read through `process_start_time` (sysinfo, a zombie
     none), the decision applied. Unit cases: an rstest `#[case::label]` table over the decision's rows (keeps tests
     S2, S7), plus one case over the joined function with the test process as the recorded and the observed server.
4. **The exit-21 outcome names its cause** (`src/cmd/client.rs`). `unreachable` takes a closed cause in place of the
