## Goal
Every input that crosses into a `viola` process from outside it is bounded where it enters, and the bound set is one
a reader can check. Most of it stands as landed: 24 of the product's reader sites already read through `take(…)`, every
name joined into `instances/<name>` is a `ViolaName`, `validate_paste_text` runs at all six send and answer sites on
both sides, and a vt100 panic poisons the screen model to `input-not-ready` while the human's bytes go first (research
§Sweeps, §Graph impact). This chunk closes what does not stand and makes the set provable:

1. **`viola mcp`'s stdin gets its bound.** rmcp 3.4.1 reads each stdin line with an unbounded `read_until`
   (research §Files inspected, `async_rw.rs`; `inputs#I2`). The server's stdin passes through a line-capped reader of
   viola's own: a line of at most `MAX_FRAME` bytes, its `\n` counted, passes whole; a longer one passes no byte and
   ends the session as stdin's close does, with one codes-only `parse-rejected{parser:"mcp-stdin", detail:"oversize"}`
   line — the wrapper channel's own rule for an over-long line (per architecture §Standard Contracts, Wrapper channel
   frames; security-plan §Input Validation, Constants).
2. **The last whole-file compare read under the home is bounded** (`replace_private_shared`), and **the depth limit
   gets a gate**: no manifest enables serde_json's `unbounded_depth` today, but nothing holds that absence, so a
   `deny.toml` feature ban with a firing probe does (per security-plan §Security Anti-Patterns › Input).
3. **The passthrough half of the terminal-parser degrade is witnessed**: the chaos test already proves the refusal and
   a key reaching the child; it now also proves the child's output still reaches the human's terminal and no byte of
   viola's own does (per security-plan §Input Validation, PTY output bytes; a11y-plan §1).
4. **The enumeration**: one contract test names every external reader with its cap form, depth and type rule and the
   existing witness that holds it, and a census over the product sources reads red on any reader call it does not
   name or that reads without a bound (per test-plan §11 Unit, oracles as literals).

## Implementation Steps
1. **The line-capped reader** — new `crates/viola-mcp/src/stdin.rs`, declared from `crates/viola-mcp/src/lib.rs`: a
   type that wraps an async byte source and yields its lines. It holds the current line's bytes until that line's `\n`
   arrives, then releases the whole line; a line whose length, its `\n` counted, would pass the cap releases none of
   its bytes, records that the stream was cut, and from then on the reader reads as end of stream. At the inner
   source's own end it releases a held unterminated line (at most the cap) and then reads as end of stream. The cap is
   a constructor argument; `serve` passes `viola_core::MAX_FRAME`. A line of exactly the cap bytes, its `\n` included,
   passes (the same rule as `viola_channel::frame::framed`). Keeps tests S2 (rstest `#[case::label]`), S7 (literal
   oracles). Inline unit cases over a small cap, each through the reader as rmcp drives it (an async read into a
   buffer, the source split across reads): a line of cap − 1 and of exactly cap bytes passes whole; a line of cap + 1
   passes no byte and the next read is end of stream; a fitting line followed by an over-long one yields the first and
   then end of stream; the count restarts after each `\n`; the over-long line split across several reads is still cut;
   an unterminated last line within the cap passes at the inner end; one case at `MAX_FRAME` itself with the literal
   `16 * 1024 * 1024` (the constant the server passes, pinned).
2. **`serve` reads stdin through it** — `crates/viola-mcp/src/lib.rs` `serve`: the transport is the capped stdin with
   stdout (rmcp's `(reader, writer)` transport, the `transport-async-rw` path `transport-io` already enables — no
   feature changes, `scripts/rmcp-features.sh` reads `server transport-io`). When the session ends and the reader
   recorded a cut, `serve` writes exactly one `parse-rejected{parser:"mcp-stdin", detail:"oversize", count:1}` at WARN
   through `obs_event!` (no byte of the line, no path), then returns `Ok(())`: the `mcp` verb writes its
   `process-exit` 0 and exits 0, as on a closed stdin (`src/cmd/mcp.rs:36` is `serve`'s one product caller, unchanged).
   Keeps obs S1 (`obs_event!`, no raw tracing), S3 (no content), S6 (stdout MCP frames only). The mechanism, at the
   criterion's grain: for a stdin whose first k lines fit and whose line k + 1 does not, rmcp's
   `AsyncRwTransport::receive` reads the k lines whole through its `read_until` and answers each, then reads end of
   stream (`Ok(0)` → `None`), and the session's quit reason is `Closed` (measured on rmcp 3.4.1's source,
   `src/transport/async_rw.rs` lines 125–140: `receive`'s `read_until` at 137, `Ok(0) => return None` at 140). A process-level inline case beside
   `serve_on_a_closed_stdin_is_the_initialize_error`, through the same `serve_child_entry` child: an `initialize`
   request, its `initialized` notification, then one line of `MAX_FRAME + 1` bytes with no newline read by the child's
   stdin → the child exits with the code naming `Ok(())` within its 5 s bound (the parent tolerating a broken-pipe
   write error once the child stops reading, as the channel's oversize case accepts each OS's write error).
3. **The schema value** — `schemas/diag-line.v1.json`: the `parse-rejected.parser` enum gains `mcp-stdin`; `detail`
   already holds `oversize`. Keeps obs S2 (the catalog and the schema's default-deny).

## Constraints & rejected approaches
- Truncating an over-long MCP line to its first `MAX_FRAME` bytes and handing them to rmcp — a padded valid request
  would then be dispatched; the bound refuses a line whole, never silently truncates it (security-plan §Input
  Validation, Hook stdin row's rule).
- Skipping the over-long line and serving on — the peer's request then never gets an answer, with no signal; the
  channel's rule (close) is the boundary's precedent.
- Patching or forking rmcp, or using its `JsonRpcMessageCodec::new_with_max_length` — the codec serves only rmcp's
  writer side in 3.4.1 (`FramedWrite`); the receive path is `read_until` on the reader the server is handed, so the
  bound belongs to that reader.
- A new fuzz target for the MCP stdin reader — the parse stays rmcp's and the reader is a byte counter whose cases
  are the unit table; the six fuzz targets and their corpus counts do not move.
- Capping the reads of the process's own executable (`checked_exe`, `pin_exe`) — no external input, and the exe is
  larger than `MAX_FRAME` in a debug build (38 MB, testing.md 2026-09-27); they are named exceptions, never bounded.
- A new error enum, a new `ServeError` variant or an exit code for the oversize end — `ServeError` stays the crate's
  one enum, and the exit cause is the later "Exit-cause code catalogue" entry's.
- A second `TestHome::outside_scan()` home, or a G2 exemption, for the panic passthrough — the one carve-out stands.
- Importing the product's own reader list into the enumeration's oracle — the tables are literals (test-plan §11).
