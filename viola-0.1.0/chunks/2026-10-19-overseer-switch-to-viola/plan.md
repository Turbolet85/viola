## Goal
The viola overseer stops driving its builder (`viola-builder`, this repository's session) through the prototype
and drives it through this repository's `viola`. The switch is the v1-33 proof on the Linux dev host. With the
product binary and claude 2.1.296 stamped in `~/.viola`, the overseer sends a pipeline skill, waits for the turn,
reads the final text, answers a review dialog and clears between skills. A key the founder types in the session
terminal then takes the wheel, and his own `viola release` returns it.

The founder answered the four P4 forks himself (`inputs#I14`):
- **Start cap:** the builder keeps claude 2.1.296, with a live-start cap of 8.
- **Switch:** mid-implement.
- **Takeover:** he types the key and runs the release himself, later. No agent-typed key, so no widening.
- **New gaps:** both are built, the background tasks as a count only.

So the chunk ships three things:
- A small additive event-data change: each question option's `description` and `preview`, and a Stop's background
  task count on `turn-ended`, for the two gaps research found beyond the 2026-10-08 gap list (scope §Gaps found at P3).
- One verify and the switch, made at a turn end in the middle of implement.
- The recorded proof.

The takeover waits for the founder at his keyboard. It is this chunk's gated criterion (§Acceptance Criteria), so
the chunk can wrap `gated` and finish it later.

The overseer's scripts live outside this repository. They change as the overseer's own steps O1–O7 (§Overseer
steps), never as files of this repository (`inputs#I1`). This repository gains no subcommand, channel method, MCP
tool, env var or config key (per architecture §Established Decisions → [Scope Boundary]).

## Constraints & rejected approaches
- Changing `options` from `[label]` to `[{label, description, preview}]` — rejected. It breaks every existing reader
  of the question data (`multi_select` sweep: 3 files, `research.md` §Sweeps); `option_details` is additive.
- Carrying the `background_tasks` array or any element of it — rejected. It is the founder's "count only"
  (`inputs#I14` Q4), and it keeps task descriptions (upstream text) off the event.
- An agent typing the takeover key, or the overseer running `viola release` — rejected (`inputs#I14` Q3; a
  driver-facing release is banned, architecture §Established Decisions → [MCP]).
- A fallback verify of 2.1.287 on a failed 2.1.296 row — rejected by `inputs#I14` Q1. A failed row halts for the
  founder's word.
- Starting the switched builder by `viola revive` — not possible for the first start: no product log holds the id.
  O6 uses `run … -- claude --resume <id>`.
- Editing any overseer script or doc from this session — forbidden (`inputs#I1`); O1–O7 are the overseer's.
- A contrived long hold to read the 3600 s ceiling — rejected. Only a hold that arises naturally (step 11) is read.
