## Goal
A log whose last line was cut short no longer costs the next record. Today every append goes straight after the
fragment, so the new line is glued to it and lost to every reader. After this chunk the next append starts on a
fresh line, the process that healed writes one `state-recovered` line, and every offset handed out before still
names the start of the same line (per architecture §Established Decisions [Database / State Store];
§Occupied Resources → Filesystem; test-plan §6 Chaos suite; obs-plan §6 Additive field catalog).

The reader counts what it steps over under the contract's three names, `unknown_kinds`, `unknown_fields` and
`torn_lines`, so the surfaces that later print them have them (per architecture §Standard Contracts → GUI list
envelope; test-plan §4 What unit tests cover → viola-state). `viola-state` gains a snapshot read that tells an
absent, an unreadable and a newer-`v` snapshot apart, and a replay of the log that recovers the log-derived fields
(per architecture §Standard Contracts → Snapshot envelope). Both are library code here: the next entry, "viola
revive", is the first reader.

The crate gets its own `tests/` suite, owed since the writers landed, in which every event kind round-trips
(per test-plan §5 Cross-module patterns → On-disk). The newer-peer refusal is already landed and tested; nothing
is built for it.

5. **The heal** (`write_line` @ `crates/viola-state/src/events.rs:257-261`, and `append_event_at` @ `:81-91`).
   Under the lock every append already holds, when the log exists, is not empty and its last byte is not LF, the
   append's one write starts with an LF, followed by the line. Nothing else in the file is touched. For a log of
   length L in that state the line starts at L + 1, and `append_event_at` hands L + 1 to its builder and returns
   it. For an absent, empty or LF-ended log everything is as today. A failure to read the last byte is the
   append's own error, with `StateError`'s fixed message, and nothing is written.

   The healing append then writes one line through `obs_event!`: event `state-recovered`, level WARN, `detail`
   `torn-line-healed`, `file` `events.ndjson`, `offset` L, and no `corr`. No append that did not heal writes it.

   Unit cases, names carrying `torn_tail`, each on a temp dir, with the capture of step 2:
   - after a fragment, the file is the prior bytes, one LF, the line, one LF; the prior bytes are unchanged;
   - exactly one `state-recovered` line with the five facts above and no `corr` key; a second append writes none;
   - an append to an absent, an empty and an LF-ended log writes no such line and no leading LF;
   - `append_event_at` returns L + 1 and its builder was given L + 1;
   - `try_append_event` heals the same way when the lock is free, and writes nothing when it is held;
   - a reader started at L before the heal (`read_from(dir, L)`) returns the healed append's line;
   - a torn tail reads `torn_lines` 1 before the heal and 1 after it.

6. **The classified snapshot read** (`crates/viola-state/src/snapshot.rs`, beside `read_snapshot` @ `:100-110`).
   A new read returns one of four: the snapshot; absent (no file); unreadable (any other I/O failure, or bytes
   that are not a snapshot envelope with `v` 1 and a readable `data`, a `v` of 0 included); unsupported, with the
   `v` it saw, when the envelope's `v` is above 1, whatever its `data` holds. It reads through the same
   `MAX_FRAME` bound. `read_snapshot` keeps its signature and its results and is defined through the new read, so
   the two cannot disagree; its four product callers are not edited. Unit cases, names carrying `snapshot_cause`:
   one per result, the `v` 99 case reading `v_seen` 99 with a `data` the v1 struct could not hold.

7. **The replay** (new `crates/viola-state/src/replay.rs`, exported from `lib.rs`). One pass over
   `read_from(dir, 0)` returns: `wheel`, the `holder` of the last `wheel` line when it is `human` or `driver`;
   `budget_paused`, the `paused` of the last `budget-gate` line when it is a bool; `budget_override_until`, that
   line's `override_until` when it is a string; `agent_session_id`, from the last `session-start` line whose
   value is a string; `links`, empty; and the pass's three counts. A field no line gave is absent, never a
   default. The result reads `dialog_pending` false. The replay writes no file.

   A second function reads the snapshot through step 6 and returns the snapshot, or absent, or the replay with its
   cause. On the replay arm it writes one `state-recovered` line at WARN with no `corr`: `detail`
   `snapshot-replayed` and `file` `snapshot.json` for an unreadable snapshot; `detail` `snapshot-unsupported-v`,
   `file` `snapshot.json` and `v_seen` for a newer one. An absent snapshot writes no line and replays nothing.
   The replay's span is `state.replay` and the read-or-replay function's is `state.snapshot_recover`, both
   `skip_all`, neither with `err` or `ret`. Unit cases, names carrying `replay_recovers`: each field from its last line; a later `session-start`
   with a null id leaves the earlier string id standing; an empty and an absent log give every field absent; the

## Constraints & rejected approaches
- Healing by shortening, replacing or rewriting `events.ndjson` — rejected: "never truncate, rotate or rewrite
  it" (`.claude/rules/events.md`, Cursors and retention); offsets are cursors.
- Healing from a reader — rejected: a reader holds no lock and writes nothing.
- Healing once at the wrapper's start only — rejected: the hook's direct SessionEnd append
  (`append_session_end` @ `src/cmd/hook.rs:494`) runs when the wrapper is gone, and its line would be glued to
  the fragment.
- Moving any of `read_snapshot`'s four product callers to the fallback — not in this chunk: the CLI pre-check and
  the hook's endpoint read stand under founder-dated exceptions, and a change there is a boundary matter (playbook,
  "Boundary widening", verdict escalate).
- Adding `link` or `unlink` to `EventKind` — not here: no writer exists; they land with "Session links".
- A line per read for the counts, a fourth `state-recovered` detail, or a new field on it — rejected: obs-plan's
  catalogue is default-deny and names no process-log carrier for a read's counts.
- An owner record, a remover or a signal handler for `viola verify` — not in this chunk (scope item 6).
- A new env seam to inject the fault — banned (security.md, the two test seams); torn state is made as files.
- Reading a healed log through `tests/support/events.rs` or `tests/support/ndjson.rs` — rejected: their reader
  fails a test on a complete line that is not JSON, which the healed fragment is. The second boot on the torn home
  is `Wrapper::boot`, never `events::boot`.
- A `sleep`, a test-owned timer, a retry, `#[ignore]`, or a bound other than `WITHIN` in the root case; a kill of
  any process the test did not start (the chaos case kills none).
- A mutation run, a workflow dispatch, a witness run or a live `claude` start (`inputs#I1`); reshaping code for
  mutants.
- Any edit under `.andromeda/` to a spec master, and any edit to `tests/support/`.

## Implementation notes
- The heal's write is one `write_all` of the LF and the line together. The LF ends the fragment; the line is still
  one complete object and its own LF.
- A log with no LF at all (the fragment is the whole file) heals the same way: L is the file's length.
- `try_append_event` with the lock held writes nothing and heals nothing, as today.
- The counts are per read: each `read_from` call starts from zero. A long-lived caller that re-reads a region
  recounts it. A surface that must show a count that never clears keeps its own total; that is the surface's.
- A line of an unknown kind is not returned, so `scan` does not move its cursor past one that is last in the log;
  the next scan steps over it again. It never wakes a `wait`.
- The reader keeps the position of every line it steps over (`LoggedLines` tracks the offset). A later entry that
  prints a skipped line in place can extend the result; nothing here forecloses it.
- No `cfg` branch is added, so `tests/contract_windows_mutation_scope.rs`'s file lists do not move.
- The hook's SessionEnd fallback is the one hook path through the changed write; it gains one one-byte read. No
  other hook path appends directly.
- The root case's home is a `TestHome` under `target/e2e-home`, inside G2, G4 and the secret scan. Its log holds
  one line that is not JSON after the heal; the harness's own `logs` verb prints such a line as a marked record.
