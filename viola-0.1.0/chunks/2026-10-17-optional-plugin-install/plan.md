## Goal
Serve `viola plugin install`, the one two-word verb (layout-templates §Component — Primary navigation). It writes an
MCP-only Claude Code plugin in a local marketplace under `<viola home>/marketplace/`, the directory only this verb
writes (architecture §Occupied Resources → Filesystem).
- The plugin carries `.claude-plugin/plugin.json` and `.mcp.json` and no hooks of any kind. A wrapped session that also
  has it installed therefore never runs two hook processes for one event (architecture §Established Decisions
  [Plugin Scope]).
- Its `.mcp.json` registers the server `viola` with the absolute path of the exe that ran the verb, never a PATH lookup
  (security-plan §Security Anti-Patterns → Universal, the exec-form clause).
- The verb prints the CLI's own two commands for the human to run. viola spawns no `claude` child and writes nothing
  under `~/.claude` (`inputs#I2` Q1).

It takes the CLI contract of every verb (architecture §Established Decisions [CLI Conventions], §Standard Contracts
CLI `--json` output):
- human text by default, `--json` for agents, codes only, no path in a document;
- a home strict-modes check before any write and before its log, as `viola list` does (security-plan §Authentication
  & Authorization; security history 2026-10-11-the-board-viola-list);
- the `cli.plugin_install` span and, under `VIOLA_NAME`, the `cli` self pair (obs-plan §4 `verify` / `plugin install`).

`viola --help`'s `setup:` row gains `plugin install`, and the `HELP` literal and the served-verbs case move with it
(the CARRY of chunk 2026-10-17-cli-output-discipline; layout-templates §Output structure — `viola --help`).

One live round on claude 2.1.287 measures what CI cannot (`inputs#I2` Q2–Q4, test-plan §11):
- which `viola` MCP server a wrapped session holding both the `--plugin-dir` plugin and the installed one starts and
  answers with;
- whether a registered `viola mcp` that exits 1 blocks the CLI's start (the CARRY of chunk
  2026-10-17-mcp-server-for-drivers).

Both readings are recorded as facts in `evidence/` and written into the masters by the wrap. No ledger row is added
(`inputs#I2` Q2).

## Constraints & rejected approaches
- A `claude plugin marketplace add` / `install` child spawned by the verb: rejected by the founder (`inputs#I2` Q1).
  viola writes nothing under `~/.claude`.
- A 24th `LedgerRow` (`plugin-precedence`) with a verify Run F: rejected by the founder (`inputs#I2` Q2). No verify,
  ledger, fake-agent, fixture or harness-literal file changes, and every stamped home keeps its `cli_verified`.
- Reusing the embedded `@@VIOLA_BIN@@` template for the installed `.mcp.json`: rejected, because a raw replace
  breaks on a `"` or `\` in an arbitrary exe or home path (`crates/viola-agent-claude/src/lib.rs:180-184`).
- `args` `["mcp"]` alone: rejected, because an unwrapped driver's server would resolve the default home or the
  unratified `VIOLA_DIR` step instead of the install's home (Decisive leans).
- Any path in the `--json` document: rejected (security-plan §Error Handling).
- `claude plugin validate` in the round: not run. It is not among the four commands the founder's Q3 answer named,
  and whether it writes under `~/.claude` is unmeasured (research.md §Patterns detected). The shape it passed at P3 is
  pinned by `marketplace_files_are_the_validated_shape`.
- Removing an unknown entry found in `marketplace/`: not done. The tree's integrity against a same-user writer
  belongs to the route entry "Home and code-bearing file integrity".
- An uninstall or list sub-verb: out of scope (layout-templates §IA notes: no further sub-verb).
- A third live start, or a re-fire of a red one: not made (`inputs#I2` Q4).
- Any `claude` command beyond the four `claude plugin` commands, the `--version` reads and start 2's one agents read:
  not made.
