# Observability Rules

Path-scoped rules for product code that logs, spans or handles errors. Authoritative source: `.andromeda/obs-plan.md` (tier Standard with Minimal exporter carve-outs); the log format itself is bound to `.andromeda/test-plan.md` §3.

## Pipeline
- **Library:** tracing 0.1.44 in every instrumentable crate; tracing-subscriber 0.3.23 (`default-features = false`, `fmt,json,registry,std`) as a product dependency in the root bin only (`viola-channel` and `viola-state` take it as a dev-dependency for their unit tests' line capture). No OTel SDK, no exporter, no reporter (sentry banned), no `tracing-appender`, no `metrics` instruments, no `/metrics` route.
- **Builder:** `fmt().json().flatten_event(true).with_current_span(false).with_span_list(false).with_ansi(false).log_internal_errors(false)`, `MillisUtc` timer (RFC 3339 UTC ms + `Z`), explicit writer — never the stdout default.
- **Levels:** `filter::Targets` from `config.json` `diagnostics_level` (`info` | `debug`); never `RUST_LOG` / `EnvFilter` / the `env-filter` feature. Third-party targets (`rmcp`, `portable_pty`, `sysinfo`, `interprocess`) are OFF; capture their failures from returned `Result`s at viola's seam.

## Sinks
- Codes-only role files: `<home>/diagnostics/{run-<name>,hook-<name>,mcp,cli-<name>}.ndjson`; `mcp` always writes `mcp.ndjson` (D-09), stderr JSON only when that file cannot be opened, never stdout (it carries MCP frames). Content-bearing records (anyhow chain, drift report, panic payload + backtrace) only in `<home>/instances/<name>/diagnostics/detail-<process>.ndjson`, written by the root-bin detail writer, never through the subscriber.
- 0600 files in 0700 dirs; `OpenOptions::append`; one `write_all` per complete line (concurrent hook processes share a file). A failed log write is swallowed — `hook` still exits 0.
- Init order: panic hook first → clap → home/instance/role → home strict-modes (create first if new) → diagnostics dir/file checks and open → `config.json` → subscriber → `process-start`. `viola hook statusline` runs its instance check BEFORE this init (the role-file open sets an existing home to 0700, so a check made after it passes a widened home) and a refused check writes no line and opens no role file (exit 0 at once); its stdout carries the user's status-line output, never telemetry. Both `viola revive` arms (the start arm and `--list`) run their instance check before the log init as well: a refused check is the stderr pair, or under `--json` the `{"v":1,"error":"strict-modes-failed","detail":null}` document, and exit 1 with no log opened.

## Lines
- Every line goes through `obs_event!` (defined in `viola_core::obs`): it attaches `event`, `process`, `instance` (from `ProcessCtx`); the caller passes `corr` as a typed field on the events that carry one; `message` is a static literal equal to the event name. Raw `tracing::{event,info,warn,error,debug,trace}!` is banned in two halves. Clippy `disallowed-macros` (`clippy.toml`) bans the level macros by path. Raw `event!` is caught by the fail-closed grep in `scripts/lint-probes.sh`, because on clippy 1.98.1 no allow inside `obs_event!` can exempt its inner `::tracing::event!` (obs-plan §3 logger-stack-install, D-33).
- `event` is a closed kebab-case enum (`ObsEvent`): a new value needs an obs Decisions Log entry and a `schemas/diag-line.v1.json` update.
- `corr` per event (JSON-RPC `id` · `dialog_id` · send `cursor`), copied as a number or string — never `?corr` / `%corr`, never renamed. A null `corr` / `instance` is key absence, never a literal `null`.
- Channel lines carry `conn = "<process>-<pid>-<t0>-<n>"`; wrapper `send-*` lines carry `conn` + `rpc_id`; `from` is logged with `from_trust:"self-reported"`, both absent on a line whose call carried no `from` (a `dialog-answered` for an answer that carried none, as on the hold's expiry line).
- Log only fields named in obs-plan §6 (default-deny, enforced by G4). `detail` codes are closed kebab-case lists — never a path or pid.

## Spans
- `#[instrument(skip_all, name = "<area>.<operation>", fields(..))]` only — never bare `#[instrument]` (gate G1), never `err` / `ret` on anything that can carry a serde source or user content. Span names are static; no instance names, ids or paths.
- Spans are not serialized: pass `corr`, `conn`, `instance` as explicit values into threads/tasks.

## Panics and errors
- `panic = "unwind"` in every profile (gate G3). The panic hook writes one line to the role file (no stderr, never the default hook); `catch_unwind` at the main-thread catch site, around `hook` dispatch, the `run` pump and handle-wait threads, and the vt100 feed.
- `hook` → exit 0, empty stdout; `cli` → `process-exit{detail:"internal-error"}` when an instance resolves, then exit 1 with exactly `error: internal error` (no hint); `run` → `process-exit{detail:"internal-error"}`; `mcp` main-thread → `process-exit{detail:"internal-error"}`, then exit 1.
- The detail-line `backtrace` is raw, never-symbolised frames (`src/panic_frames.rs`: `0x<ip> <module path> base=0x<base> +0x<offset>`, up to 62) — symbolising cost 351 of a 403 ms hook run on the Windows runner; never call `Backtrace::force_capture().to_string()` in a panic path.
- The hidden capture arms, `hook <event> --capture` and `hook statusline --capture` (the latter runs no instance check, no shell-out and no `budget.json` write, opens no role file and prints nothing), do no obs init and write no line (a bounded panic-line exemption, obs-plan §10). A `viola verify` stopped by Ctrl-C or TERM (Unix `SIGINT` / `SIGTERM`, Windows Ctrl-C / Ctrl-Break) starts no further spawn, kills and reaps the child it is running, closes every spawn pair it opened (a child of an interactive PTY run killed at the stop closes with `duration_ms` and a `child_exit_status`, the PTY pump's exit code; a print-mode or `--version` probe child killed at the stop is not measured) and ends `process-exit{subject:"self", exit_code:1, detail:"interrupted"}` (a twelfth `detail` value in `schemas/diag-line.v1.json`); `run`'s version gate observes no stop.
- `viola list` (span `cli.list`) runs its strict-modes scan before its log; a refused scan (exit 21) opens no log and writes no line (obs-plan §10 exemption 7; the founder's own answer, 2026-10-13, superseding the operator's). Under a `VIOLA_NAME` it writes the self pair, one `parse-rejected{parser:"state-entry"}` per nonzero scan count, one `state-recovered` per replayed snapshot (its `instance` the caller, its `scanned` the scanned instance dir's own last component when it parses as a `ViolaName`, absent otherwise — never a path or a literal `null`), the `config-json` threshold rejections and one `agents-probe` spawn pair around its `claude agents --json` read (plus one `parse-rejected{parser:"claude-agents-json"}` on an oversize or malformed answer) into `cli-<name>.ndjson`; with no name it opens no log. `viola mcp`'s `list` tool makes the same board read (through `list::board_document`) and writes its `agents-probe` pair, `state-recovered`, `parse-rejected{parser:"state-entry"}` and `config-json` threshold lines into `mcp.ndjson`. `viola plugin install` runs its strict-modes tree check before its log; once it passes, under a parsed `VIOLA_NAME` it writes the self pair (`process-exit` exit 0, no detail) into `cli-<name>.ndjson`, and its span `cli.plugin_install` is no dispatch span: it is on `write_tree`, opened after the `cli` log opens, so the tree check and its refusal run outside it; no path in any line.
- `viola revive`'s start arm logs as process `run` once its instance check has passed (`run-<name>.ndjson`, each preflight refusal — `already-live`, `no-session`, `session-live` (the thirteenth `process-exit` `detail` value), `cwd-missing` — one `process-exit{exit_code:1, detail}`; its `session-live` reading, skipped under `--fork` and passing on a failed read, writes one `process-start` / `process-exit{subject:"agents-probe"}` pair there, plus one `parse-rejected{parser:"claude-agents-json"}` on an oversize or malformed answer); `viola revive --list` is role `cli` (chunk 2026-10-17-cli-machine-contract; the sixth exemption retired): after its strict-modes check passes and only under a parsed `VIOLA_NAME` it writes `process-start` / `process-exit` (`exit_code` 0 with no detail; `exit_code` 1 `detail:"no-session"` on an empty chain) into the caller's `cli-<VIOLA_NAME>.ndjson`, with no name no log, and its dispatch `Err` or panic reaches the `cli` catch site. A refused instance check on either `viola revive` arm (start or `--list`) or on `viola hook statusline`, or `viola mcp`'s refused `viola_state::strict::check_path` of its home or `diagnostics/` (run before its `mcp` role file opens; exit 1 with nothing on stdout or stderr; its plan's lean, approved by the operator at P5), or `viola plugin install`'s refused `check_path` of its home or a `marketplace/` tree dir (run before its `cli` role file opens; exit 21, the stderr pair or under `--json` the `instance-unreachable` document), opens no role file and writes no line (the seventh exemption; on `viola hook statusline` the founder's own answer, 2026-10-13). A failed server check (Linux and Windows; macOS compares no peer pid, the recorded gap) sends no frame and opens no `channel.request`: the six CLI frame verbs (`send`, `wait`, `last`, `answer`, `pause`, `release`) end `process-exit{subject:"self", exit_code:21, detail:"server-verify-failed", during:"connect"}` at WARN inside their dispatch span with no `channel-request` line; `viola hook` writes `hook-decision{detail:"server-verify-failed"}` at WARN (on a dialog hook `hook-invoked{corr:null}` first, then `decision_emitted:false`); MCP's frame tools return `instance-unreachable` with no line, as the liveness pre-check's; no pid, start time, path or endpoint in any line.
- `run.budget_eval` (INTERNAL; `trigger` `start|send|turn-ended`, `paused`, `window` only when paused) is declared once and opened once per evaluation; at start it sits between `channel.bind` and `state.snapshot_write`. `read_budget` and `release --budget`'s lift carry no span and no line of their own; `budget-gate` is appended only when (paused, window, override end) changes. The implicit link record on a `send` or an `answer`, the link set's restore at start and the replay's link rule carry no span and no process-log line either; `driver`, `driven` and `since` reach no home-level line. A `budget-paused` refusal's `send-refused` line carries `window`, `used_percentage`, `resets_at` and `paused:true`. At a dialog hold's end (`run.dialog_await`'s `deadline_ms`, `config.json`'s `dialog_hold_s` in ms, 60 000–3 600 000, default 60 000) the wrapper appends one `dialog-expired{dialog_id, dialog_kind}` product line and writes one `dialog-answered{corr:<dialog_id>, dialog_kind, deadline_hit:true, duration_ms}` with no `from` / `from_trust`; a hand-back or an answer writes neither; the hook then writes `hook-decision{decision_emitted:false, deadline_hit:false}`, `deadline_hit:true` only when its own read times out at its backstop bound `DIALOG_HOLD_MAX + 5 s` (3605 s).
- No per-byte or per-line logging in hot loops (PTY pump); no line per heartbeat tick — transitions only.
