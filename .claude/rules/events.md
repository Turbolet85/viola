# Event Rules

Path-scoped rules for viola's event log and state: the normalised event kinds, the `events.ndjson` line, snapshots and the hook → kind mapping. Authoritative source: `.andromeda/architecture.md` §Standard Contracts + §Conventions (Naming patterns, Data model conventions). There is no broker: the log on disk is the single source of truth.

## Event line
- `{"v":1,"ts":"<RFC3339 ms Z>","instance":"<ViolaName>","kind":"<kind>","source":"hook|wrapper","data":{}}` — one complete object + `\n` per single `write` call; multi-line text travels as an escaped string.
- `data` is kind-specific and uses only viola's normalised fields; it never embeds a raw Claude payload.
- Normalised kinds live only in `viola-core`, never with Claude-specific names: `session-start`, `turn-ended` `{last_assistant_message, background_tasks, scheduled_wakes, cause?}` (`cause` present only on an API-error turn end, one word of the closed nine-word `TurnEndCause` set: `rate-limited`, `overloaded`, `auth-failed`, `billing`, `invalid-request`, `model-not-found`, `server-error`, `output-limit`, `api-error`; absent on a Stop end), `prompt-submitted`, `question`, `permission`, `plan`, `session-end`, `activity`, `link`, `unlink`, `wheel`, `send-issued` `{cursor, from?}`, `send-confirmed` `{cursor, confirmed?}` (`confirmed:false` only for an unconfirmable send), `send-refused` `{refusal, detail, cursor?}` (the CL-1 send records, `source: wrapper`; `cursor` absent for a refusal before `send-issued`), `dialog-expired` `{dialog_id, dialog_kind}` (`source: wrapper`, appended once when a held dialog's hold ends; it carries no question, plan or tool text), `lineage` `{parent, role}` (each a string or `null`, `source: wrapper`), `launch` `{model, effort}` (both strings, `source: wrapper`, appended once at every start, after `lineage`), `window` `{address, workspace, placement, origin}` (`source: wrapper`, placement and origin closed words, appended once after `launch` only when started under --origin).
- `wait` wakes only on `turn-ended`, `question`, `permission`, `plan`, `session-end`, `dialog-expired` (the one wrapper-appended kind that wakes it, appended through `WaitFeed::appending`); `activity`, `link`, `unlink`, `wheel`, `lineage`, `launch`, `window`, a harness-origin `prompt-submitted` and the send records are log-only. The wake is by event kind alone: every `turn-ended` wakes whatever its `background_tasks` or `scheduled_wakes`, and telling a finished turn from a paused one is the driver's.

## Hook → kind map (only in `viola-agent-claude`)
- SessionStart → `session-start` (`cause` startup|clear|resume|compact|unknown, `agent_session_id`; the hook may send an optional string `transcript` param beside `event`, never inside it, only when the transcript path passes the shape check against its own session id; the wrapper re-validates it for a session-start line only, drops any other, and it never enters event data); UserPromptSubmit → `prompt-submitted` (`text` normalised: long-paste wrapper removed, then tag escaping reversed; `origin` driver|human|harness — the hook files only human|harness; the wrapper relabels a CLI-fired scheduled wake `harness`, and `driver` comes only from the wrapper's relabel of the in-flight send's own prompt, matched on the send's typed text, the sent text with every CR LF pair and every other CR as one LF and without its trailing CR and LF characters, or on a non-empty text equal to that typed text less its trailing run of ASCII space, TAB, CR and LF, the text kept as submitted); PreToolUse AskUserQuestion → `question`; PreToolUse ExitPlanMode → `plan`; PermissionRequest → `permission`, `question` for an AskUserQuestion call with no matching armed dialog, or `plan` for such an ExitPlanMode call (unmeasured live) (a PermissionRequest repeating the armed `question` / `plan` dialog's tool with an equal `tool_input` is that dialog's continuation and raises no event; a question first raised by PermissionRequest with no matching armed dialog is held for the driver and its answer returns as PermissionRequest allow with `updatedInput`, the tool input plus answers and annotations, while a human key, an expired hold or an unverified CLI leave it to the human); Stop → `turn-ended` (`last_assistant_message` or `null`; `background_tasks`, the Stop payload's `background_tasks` array length, a count only, or `null` when the key is absent, `null` or not an array; `scheduled_wakes`, the Stop payload's `session_crons` array length, a count only, or `null` when the key is absent, `null` or not an array); StopFailure (`viola hook stop-failure`) → `turn-ended`, not a dialog (data exactly `last_assistant_message` null, `background_tasks` null, `scheduled_wakes` null and `cause` one of the nine `TurnEndCause` words, classified from the CLI's error word inside the Claude adapter); SessionEnd → `session-end`; Notification / PostToolUse / PostToolUseFailure → `activity`.
- Dialog hooks send only `hook.dialog`; the wrapper assigns `dialog_id` (monotonic, restored from the log on start) and appends the dialog event before it can wake `wait` or reply — even when it replies `null`. At most one dialog pending per instance.
- Harness turns (a prompt whose raw start is `<agent-message from=`, `<task-notification>`, `<\cross-session-message` or `<cross-session-message`) are `origin:"harness"` and never flip the wheel. So is a fired scheduled wake: on a verified CLI, an unsent human-filed prompt with no key typed since the last human-filed prompt and a scheduled wake counted at the last turn end is relabelled `harness`, the wheel kept. The escaped cross-session form is the one escaped tag that classifies, so a human typing it at a prompt's start is filed `harness` (founder-ratified, 2026-09-29). As measured on 2.1.287, a human who types `<task-notification>` at a prompt's start is filed `harness` too.

## Cursors and retention
- `wait after` and the `send` `cursor` are byte offsets into the instance's `events.ndjson`: never truncate, rotate or rewrite it; instance dirs are reused and appended to.
- The link set is derived by replaying `link`/`unlink`; a repeated pair adds no line. The driven wrapper appends `link` (`source: wrapper`, `{driver, driven}`) once per new pair, for an issued `send` (directly before its `send-issued`), a taken `answer` whose `from` is another instance's name, or a served `link` call; a refused call, a call with no `from` and one under the wrapper's own name link nothing. `since` is that line's `ts`, and the wrapper restores the set from the log at every start (`src/run/links.rs`). The wrapper serves `link` `{driver, driven}` → `{since, already_linked}` and `unlink` `{driver, driven}` → `{}` (the verbs `viola link` / `viola unlink <driver> <driven> [--json]`; neither method reads `from`): a `link` of a held pair appends nothing and answers its `since` with `already_linked: true`; `unlink` appends `unlink` (`source: wrapper`, `{driver, driven}`) once per held pair it removes (`LinkSet::remove`) and answers `{}` either way; a missing, non-string or invalid name, a `driven` that is not the wrapper's own name and a `driver` equal to `driven` are each `-32602` with no line; each answers only after its event line and the snapshot write.

## Snapshots and liveness
- Envelope `{"v":1,"written_at","writer","data"}`, replaced atomically (tempfile `persist` through the one shared helper `viola_state::fs::replace_private`); only the instance's wrapper writes `instances/<name>/snapshot.json`, and it rewrites the snapshot's `agent_session_id` on each `session-start`, so the `claude agents --json` session-id join survives a `/clear`; it writes `pending_dialog` `{dialog_id, kind}` before the dialog's event line is appended and back to none when that append fails, so a reader that sees the line already sees it.
- An unsupported `v` or a parse failure → ignore the snapshot and replay the log; replay recovers only `links`, `agent_session_id`, `wheel`, `lineage`, `launch`, `window` (`dialog_pending` reads false; `window` is the last `window` line after the last `launch` line, a later `launch` line clearing it; the last `lineage` line replaces the held value, as the last `launch` line does, a `launch` line with a non-string member reading none). The wrapper appends no budget-gate line and the snapshot holds no budget field. As landed the classified read and the replay are library code (`viola_state::snapshot::read_snapshot_classified`, `viola_state::replay`) with product readers, each after the instance's strict-modes check has passed: `viola revive`'s preflight (one read for both its collision check and its recorded directory), `viola list`'s `viola_state::board::read` (a replayed snapshot gives a `live` row only for a beat at most `STALE_AFTER` old, never `stale`), `viola_state::liveness::live_endpoint` (the CLI frame verbs, `viola link` / `viola unlink` and `viola mcp`'s frame tools; only a real snapshot gives an endpoint), `viola hook`'s `connect` (a replayed or absent snapshot is unreachable, so the hook fails open) and `run`'s collision check (a replayed snapshot judged by the heartbeat alone: `already-live` within `STALE_AFTER`, else free); no product code under `src/` calls `read_snapshot`. The replay writes no file but logs one `state-recovered` line (an absent snapshot is neither replayed nor logged), gives no `cwd` (a revive over a replayed snapshot is refused `cwd-missing`), and recovers `links` from the logged `link` / `unlink` lines in its one pass through `replay::apply_link_line` (a `link` line with no string `ts` reads `since: "unknown"`). `replay::session_chain` reads the logged session ids in one pass and logs nothing.
- Heartbeat touched every 1 s. A snapshot pid that is dead, or alive with another start time, is `gone` whatever the beat; otherwise a beat ≤ 5 s old is `live`, an older or absent one `stale`. Never a bare pid. The snapshot's `pid` and `started_at` are also the server identity: `viola_state::liveness::live_endpoint` returns them with the endpoint from one `replay::read_snapshot_or_replay` (`LiveEndpoint`, only on a real snapshot: a replayed or absent one, a failed read or a stale wrapper gives none; where it gives none, `viola_state::liveness::without_endpoint`, behind the strict-modes check at every caller, reads the cause through `symlink_metadata`, opening nothing and writing no line: a directory reads `InstanceDead`, so a frame verb against a stale instance reads `instance-dead`, and anything else `UnwrappedName`), and every frame-writing client (CLI `send` / `wait` / `last` / `answer` / `pause` / `release` / `link` / `unlink`, `hook.event` / `hook.dialog`, the MCP `send` / `wait` / `last` / `answer` tools) runs the instance's strict-modes check first (`client::refuse_untrusted` for the CLI verbs, the hook's `trusted` for `hook.event` / `hook.dialog`, `strict::check_instance` in the MCP frame tools; a refused check writes no frame and no line), then takes its snapshot read (the CLI frame verbs and the MCP tools the liveness-only pre-check through `live_endpoint`, `viola hook`'s event and dialog paths one shared `replay::read_snapshot_or_replay`, a replayed or absent snapshot read as unreachable), then checks the recorded endpoint's directory (`viola_state::strict::check_endpoint_dir`; a refusal reads `socket-dir-refused` and writes one `process-exit` at the CLI, one `hook-decision` at the hook and no line at MCP), then connects (the hook through `Client::connect_by`), then refuses a connected peer of another euid or one it cannot read (`viola_channel::peer_admitted` over `server_euid`; a refusal reads `server-verify-failed`), then compares the connected peer's pid and its OS start time with them before its first frame (`verify_server` → the closed `ServerVerdict` `Matches` · `Mismatch` · `Unverifiable`); a refused directory, a refused euid, a mismatch, or a check that cannot be made, writes no frame. `server_verdict` and `verify_server` always make that comparison: no verdict reads `Matches` without it.

## Parsing
- The next append heals a torn last line: under the log's lock it writes one LF ahead of its line in the same single write, and logs one `state-recovered` line. A reader never writes. The one reader `events::read_from` counts what it steps over, per read, as `skipped{unknown_kinds, unknown_fields, torn_lines}`, never fatal: an unterminated last line, an over-long line and a line that is not one object are torn; a line of an unknown kind is not returned; a known-kind line with a key outside its contract is returned and counted once. `viola list` is the first surface that shows them: `list --json`'s `skipped` `{unknown_kinds, unknown_fields, torn_lines}` and the BAY line's `skipped a - b - c`, each summed over every scanned instance, gone ones included. External payloads parse tolerantly (`#[serde(default)]`, `Option<T>`, no `deny_unknown_fields`), with serde_path_to_error drift reports for hook JSON only, going to the instance detail file only.
- Lock files are separate siblings (`<name>.lock`), save `ledger/verify.lock`, the automatic verify's attempt lock, which guards no file of its own name and stands apart from `stamps.json.lock`: a layout chosen while Windows (where append + exclusive lock fails) was a target, and kept.
- Timestamps via chrono `to_rfc3339_opts(SecondsFormat::Millis, true)`; malformed external values become `"unknown"`, never an error (except a hyprctl reply the Hyprland seam cannot parse, which is the seam's `malformed` error; a StopFailure error word outside the CLI's known words reads the turn-end cause `api-error`). JSON fields snake_case, enum values kebab-case.
