# Accessibility Rules

Path-scoped rules for the cli output discipline, the tui boundary and the a11y harness. **Authoritative source:** `.andromeda/a11y-plan.md` §3 (Harness Contract) and §4–§8. No WCAG label: viola has no web or graphical frontend; the CLI and TUI make no conformance claim.

## The frontend (none)
- viola has no web or graphical frontend: the terminal fleet console (matrix#v2-14) takes its a11y scope at the route entry «Fleet a11y verification».

## Keyboard and focus
- cli: no interactive prompt, pager or redraw, and input is stdin / `--file` only; tui: once the child starts the terminal belongs to the child, and viola writes zero bytes of its own to it (only a start's automatic verify lines L1 to L5 and verify's own output precede the child's bytes, and only a not-resumed `viola adopt`'s refusal pair or document follows them once the child ends) (under `viola revive --json` or `viola adopt --json` a `pump_child` error prints no document: viola writes nothing past it, and a peer the wrapper refuses is dropped in `accept_loop`, before its worker thread and any frame: it writes nothing to the outer terminal and moves no wheel), and once the wrapped child holds the terminal, human keystrokes are never blocked, refused or dropped: queued with the paste in arrival order, they wait behind at most its in-flight chunk and closing marker (the one exception is a start's automatic verify window, before the child starts: a key typed then waits in the terminal's own buffer), and focus / mouse / resize sequences and terminal replies (F-W2's closed list) are never counted as editing; every other byte is. viola has no web or graphical frontend; the terminal fleet console's keyboard reach is the route entry «Fleet a11y verification»'s.

## Visual
- On the CLI, state is always a printed word (`stale`, `DIALOG <kind>`, `expired`, `unverified-cli`, the STATUS words `idle` / `busy` on joined wrapped rows and the unwrapped rows' `n/a` cells; on a terminal too narrow only an unwrapped NAME is cut, to the column less 3 characters plus `...` and never inside a `\xHH` escape, a wrapped NAME never, and piped output and `--json` keep every name whole); colour is a second cue only (amber SGR only on `DIALOG`, dim on stale rows, bold only on NAME values, always beside the word), `unable` / `fail` are never coloured, and viola emits no SGR of its own under non-TTY / `NO_COLOR` (an empty value included) / `TERM=dumb` / `--json` / a passthrough role / `viola run` / a passed `viola revive` / a passed `viola adopt`, and `viola link` / `viola unlink` print one plain-ASCII result line in one write with no SGR in any mode, and `viola up` prints one line per instance, `<name>  <word>` or `<name>  live  <placement>`, plain ASCII, with no SGR, each line in one write, and `viola switch` prints one line, `<name>  switched  <model> <effort>`, on stdout in plain ASCII with no SGR. viola has no web or graphical frontend, so no page token pair or layout to verify.

## Harness
- The a11y harness is the tests' own `std::process::Command` / literal-pin / portable-pty cases (cli output discipline, tui boundary), run by `scripts/agent-run.* run` inside the `test` job's `coverage` suite (matrix `[ubuntu-latest]`) under `gate --require coverage,doctest` (skips never allowed); no browser a11y leg: viola renders no page.
- cli / tui write no a11y rows: output-discipline failures surface only as nextest failures in `suites[].failures[]`; there is no web row shape: viola has no web or graphical frontend.
- No new `suite` enum value (such as `a11y`) without a Decisions Log entry, and no separate a11y driver outside `scripts/agent-run.* run`.
