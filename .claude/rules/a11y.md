# Accessibility Rules

Path-scoped rules for the `viola ui` page and the a11y harness. **Authoritative source:** `.andromeda/a11y-plan.md` §3 (Harness Contract) and §4–§8. No WCAG label in 0.1.0: the frontend (the `viola ui` page) is deferred to 0.2.0 and its technology is not chosen; the CLI and TUI make no conformance claim.

## The frontend (deferred to 0.2.0)
- The frontend is deferred to 0.2.0 and its technology is not chosen: no page structure, ARIA, announcement, focus or visual-token rule binds in 0.1.0.

## Keyboard and focus
- cli: no interactive prompt, pager or redraw, and input is stdin / `--file` only; tui: the terminal belongs to the child, and human keystrokes are never blocked or delayed past the atomic paste. The page's tab order is deferred with the frontend to 0.2.0.

## Visual
- On the CLI, state is always a printed word (`stale`, `DIALOG <kind>`, `expired`, `budget-paused`, `unverified-cli`); colour is a second cue only (amber SGR only on `DIALOG`, dim on stale rows, bold only on NAME values, always beside the word), `unable` / `fail` are never coloured, and viola emits no SGR of its own under non-TTY / `NO_COLOR` / `TERM=dumb` / `--json` / `viola run` / a passed `viola revive`. The page's contrast pairs are deferred with the frontend to 0.2.0.

## Harness
- The a11y harness is the tests' own assert_cmd / predicates / trycmd / portable-pty cases (cli output discipline, tui boundary), run by `scripts/agent-run.* run` inside the per-OS `test` job's `coverage` suite under `gate --require coverage,doctest` (skips never allowed) on every leg; 0.1.0 runs no browser a11y leg.
- cli / tui write no a11y rows: output-discipline failures surface only as nextest failures in `suites[].failures[]`; the web row shape is deferred with the frontend to 0.2.0.
- No new `suite` enum value (such as `a11y`) without a Decisions Log entry, and no separate a11y driver outside `scripts/agent-run.* run`.
