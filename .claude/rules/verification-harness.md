# Verification Harness Rules

Path-scoped rules for the agent-driven harness driver: the `scripts/agent-run.*` shims, `viola-harness`, the rstest fixture chains and the fake agent.

**Authoritative sources (bound):**
- `.andromeda/test-plan.md` §3 — the 5-command contract, status shape, log format, session record, test data bootstrap
- `.andromeda/obs-plan.md` §3 — the log sinks, the `event` enum, `corr` / `conn`, null-as-absence

A change on one side keeps the other in sync; a log-format break is a harness break.

## Shims
- `scripts/agent-run.sh` and `scripts/agent-run.ps1` are identical thin shims: `cargo run -q -p viola-e2e --bin viola-harness -- <command> [flags]`, forwarding exit code and stdout unchanged. All logic lives once, in Rust.
- Agent surface: exactly `boot · run · status · cleanup · logs`. `supervise`, `ui-restart`, `gate`, the CI gate bodies `schema-check` (G4) and `secret-scan`, and the operator pass's local Linux gate `pre-push` are internal subcommands, forwarded unchanged by both shims (test-plan §3 Internal harness subcommands). A 6th agent command needs a test-plan amendment.
- `pre-push` (Linux host only; exit 2 `pre-push-linux-only` elsewhere) runs natively in the working tree (no clone), every child through `/usr/bin/env -i HOME=<home> PATH=<home>/.cargo/bin:<home>/.local/viola-node/bin:/usr/local/bin:/usr/bin:/bin <argv>` — never an inherited environment (no `CLAUDE*` value; the PATH's components are constants under the home or system dirs). `<home>` is the passwd entry's field 6, read by two probes carrying only `PATH=/usr/bin:/bin` (`id -u`, then `getent passwd <uid>`; a failure is `tool-missing` `passwd-home`); the harness's `$HOME` is never read. Its `tools` stage checks `node` against ci.yml's `NODE_PIN_VERSION` (detail `node`), and `linux-tests` runs `run --coverage`, `run --browser`, then `gate --require coverage,doctest,playwright` (the document's `linux{run,browser,gate}`). Its stages are `tools → linux-tests` (`ok:true` when `linux-tests` is green); no stage runs mutation. Its document carries codes, counts and repo-relative names only — never a home or repository path. The operator pass runs it on the uncommitted tree before the pre-CI commit; a red stops the pass.
- Every command prints exactly one JSON document on stdout starting `{"v":1,"cmd":"<command>","ok":<bool>,…}`; exit 0 ok · 1 failure · 2 usage. A human-only message without the JSON document is forbidden.

## boot
- Steps in order: `cargo build --workspace --features viola/fake-agent` with `CARGO_TARGET_DIR=target/harness` (the CLI's `<bin dir>` is `target/harness/debug`: a running `target/debug/viola-harness.exe` cannot be relinked on Windows) → a not-yet-existing home under `target/e2e-home/viola-session-*/home` (the base first prepared by `Workspace::ensure_e2e_home`: a plain directory is created; a link, as on the Linux dev host, must point at an absolute, real, owner-only directory, made again 0700 when it is gone, else `build-failed`) → copy the fake agent to `target/agent-run/<session>/bin/claude[.exe]` on a harness-scoped `PATH` (per child via `Command::env`) → `viola verify --home` against it with `--screens --turn-stop --trusted-root <workspace root> --dialogs --framing` (print probe + all four interactive runs, seventeen rows) unless `--unstamped` → `viola-harness supervise` as an ordinary child (outlives `boot`, stops only via `stop.request`; it hands the fake agent `--screens --trusted-root <cwd>`) owning one portable-pty outer PTY per instance via `viola-pty` (master writer kept until the child exits, one drain thread per master) → optional `viola ui` → token exchange (303 + `HttpOnly; SameSite=Strict`, cookie stored 0600, never printed).
- Readiness is a bounded 100 ms file-state probe, staged: first `diagnostics/run-<name>.ndjson` has `process-start` for `subject:"self"` and `subject:"claude-child"`, both pids alive by pid + start time; then the snapshot has `pid/started_at/child_pid/endpoint` and the heartbeat is < 5 s (missing `<name>:snapshot` / `<name>:endpoint` / `<name>:heartbeat`); then `events.ndjson` lines 1–3 = `wheel{cause:start}` → `budget-gate` → `session-start{source:hook}` (`start_records`, missing `<name>:events`; `supervise` passes `--fixtures <root>/fixtures/claude`). Still to join: UI `/health` ok and `/ready` `"ready"`. Failure reasons are the closed list in test-plan §3.
- After UI readiness, byte-compare every embedded `/assets/*` with the repo file (`stale-embedded-assets`).
- No nested `cargo run` inside nextest: tests use the `harness_session` fixture or the rstest chain `home → fake_agent_path → stamped_home → booted_wrapper`.

## status / cleanup / logs
- `status`: `viola list --json` + `/ready` + cookie-gated `/api/info` and `/api/sessions`; `api_sessions_equal_list` deep-equals `.ok.items`; exit 0 only for `state:"ready"`.
- `cleanup`: `stop.request` → Ctrl-C into each outer PTY, pressed again every 500 ms until the child exits (a Ctrl-C into a child not yet raw is swallowed) → `child.wait()` 10 s → `kill()`; `processes_gone` proves supervisor, wrappers and children gone (endpoint/port/url fields `null` until those surfaces exist); verify endpoint gone (CLI exit 21, socket path absent), port free, `ui/<port>.url` removed. Idempotent (no session → `ok:true, cleaned:[]`). Kill targets verified by pid + start time. `AGENT_RUN_KEEP_HOMES=1` (CI) keeps the home (`home_removed:"kept"`).
- `logs`: merge `events.ndjson` (`src:"events"`, byte `offset`), home `diagnostics/*.ndjson` and `instances/*/diagnostics/detail-*.ndjson` (with `instance`); torn lines emitted as `{"torn":true}`, never dropped; filters `--instance --kind --process --after`.

## Fake agent (`viola-fake-agent`, feature `fake-agent`)
- Answers `--version` like the real CLI. It reads hook commands from `<plugin-dir>/hooks/hooks.json` (the `--plugin-dir` `run` passes). Only an absolute exec-form `command` is spawned: no shell, no PATH; a group's `matcher` is evaluated against a tool-bearing payload's `tool_name` (`hook_commands(…, tool)`). A non-absolute command is receipted `command_absolute:false, ran:false` and never run. The payload is `<fixtures>/<cli-version>/<Event>.<variant>.json`, with only `prompt` set for UserPromptSubmit and the fixture's trailing newline kept, so the recorded prompt yields the recorded bytes.
- Scripted turns (`{"v":1,"steps":[…]}`, `schemas/fake-script.v1.json`) gated on the `--control` file by byte offset.
- Receipt ndjson `"v":1` + kebab `kind`: `start`, `env` (names only), `fds` (Unix), `key`, `prompt` (`text`, `hex`, `bare_esc`, `origin`, `submit`), `hook` (with `stdin_hex`, the exact bytes offered, when it ran), `size` (a watcher writes it at start and on every change, no key needed; interactive mode only), `step`.
- Modes built: `--suppress-prompt-submit`, `--local-command-mode`, `--inject-harness-turn`, `--exit-no-eof`, `--report-version`, `--framing` (verify's Run B: a compiled paste text fires its recorded `paste-<n>` variant unchanged, the probed local command its recorded `clear-<n>` SessionEnd then SessionStart), the capped test-only hold `--paste-hint-ms` (10 s at most: a cleared screen after the long paste's turn), the test-only screen switch `--tag-turn-screen <phase>` (with `--framing` and `--turn-stop`: `Screen.<phase>` of the set after the tag-like paste's turn alone, in place of `Screen.turn`), `--vt100-panic-bytes` (after its `start` receipt it writes `e4 b8 ad` once to its terminal; under a 24×1 PTY that panics vt100's feed). `statusline-echo` and `agents --json` land with their consumers. Exits on `\x03` or at stdin EOF, first waiting for a hook still running and starting no other: it is its PTY's session leader, so its exit would hang up an in-flight hook mid-exit (a truncated coverage profile, measured).
- Root fixture chain: `tests/support/` (`home` → `fake_agent_path` → `stamped_home`, stamped by `viola verify` against the fake agent at 2.1.287 over `fixtures/claude` → `booted_wrapper`; `StampedHome::unstamped` for the unverified path; `Wrapper::stop` waits for the endpoint to be unconnectable, not only the exit). Homes live under `target/e2e-home/viola-test-*` (the base prepared by `prepare_home_base` under the harness keeper's contract; on the Linux dev host it is a link to an owner-only tmpfs directory, so removals reach outside the working directory and a kept home does not survive a reboot), kept per `AGENT_RUN_KEEP_HOMES` / `AGENT_RUN_KEEP_FAILED` (viola-e2e's booted lifecycle tests: a `Booted` drop guard stops the session, then keeps the home only for a panicking test under `AGENT_RUN_KEEP_FAILED=1`); each records `owner.json` `{pid, started_at}`, and a new home (no keep flag set) first removes only dirs whose recorded owner process is gone — never by age or name, never a dir without a record (a runner-killed test never drops its home); the drop and that sweep both go through `remove_owned`, which deletes `owner.json` last, so a removal that stops part-way keeps the record. The `viola_e2e::fixtures` copy lands with its first E2E consumer.
- `run --mutants` diffs against `AGENT_RUN_CHUNK_BASE` when set, else a derived base (the last master flip before the pending chunk's oldest operator pre-CI commit; `HEAD^` on the wrap push, but the flip itself while a promoted chunk is still uncommitted on top of it; test-plan §3 `run` step 4), and names it in its document (`base`). The `cargo mutants` command runs with `AGENT_RUN_KEEP_HOMES=0` / `AGENT_RUN_KEEP_FAILED=0` (a mutation run keeps no test home). The root pre-build and `cargo mutants` both build in the run's own target dir `target/mutants` (`MUTANTS_TARGET`: `<repo>/target/mutants` for the pre-build, the relative `CARGO_TARGET_DIR=target/mutants` for cargo-mutants), because a copied default `target/` keeps the original tree's `CARGO_BIN_EXE_*` paths and root integration tests would drive the unmutated binary (test-plan §3 `run` step 4). It classifies `chunk.diff` first. A diff with no `.rs` path gives `verdict:"no-rust-delta"` and never runs cargo-mutants. A diff whose `.rs` paths are all test targets (`test_target`: `tests/`, `benches/`, `examples/` at the root or under `crates/<member>/`) gives `verdict:"test-only-rust-delta"` with `rust_files`, and never builds or runs cargo-mutants either. Any other Rust delta, a mixed one included, deletes a stale `outcomes.json`, then gives `verdict:"counted"` (`verdict:"scoped"` with `files` under `--file <path>`, repeatable: the inner loop). `--package <member>` (needs `--mutants`) mutates one whole member instead — no base, no `chunk.diff`, no classification, `verdict:"package"`; a member other than `viola` or a `crates/<member>` whose manifest declares `fake-agent` is exit 2 `package-refused` before any cargo. `chunk_diff` pins `--src-prefix=a/ --dst-prefix=b/` on both `git diff` calls (a host `diff.mnemonicprefix` or `diff.noprefix` would break the header parse). On a Windows host (`HOST_SCRATCH`) the run first resolves the host mutation scratch `<repo parent>/viola-mutants-scratch`, refuses unless its final component is exactly that name and the repo is neither it nor inside it (`scratch-refused`, no fallback), measures, removes and recreates it (`scratch-wipe-failed`), and runs `cargo mutants` with `TMP`/`TEMP` and `--output` set to it; the document gains `scratch_bytes`. Every `run` archives the JUnit it wrote and the `outcomes.json` it read in `target/run-archive/<n>` (newest 10; the document's `archived`). More unviable than caught mutants (`unviable-exceeds-caught`: the mutant builds failed) is red. cargo-mutants' outcome lines stream live to the harness's stderr, so a stalled run names its mutant. `run --mutants` runs only when named — never under no selector or `--all` — and no chunk gate, pre-push stage or push/PR CI job runs it: its cadence is the epoch-boundary `/andromeda-code-audit` (test-plan §10 Mutation gate), whose Windows leg is the dispatch-only, report-only `windows-mutants.yml` (`run --mutants --package <member> --file …` per package on `windows-2025`; `tests/contract_windows_mutation_scope.rs` keeps its file lists equal to the Windows-gated sources). The nextest `mutants` profile's `fail-fast = { max-fail = 1, terminate = "wait" }` lets running tests finish after the first failure; only a slow-timeout or mutant-made kill leaves a test's temp dir behind. Its two real-cargo-mutants self-tests are compiled out on macOS. A booted-session test must stop its session in a `Drop` guard: under a mutated `cleanup` a leaked supervisor locks its `.exe` on Windows, and every later mutant build fails.
- `run --coverage` (one instrumented `cargo llvm-cov nextest` run as suite `coverage`, then doctest), `run --fuzz-replay` (Linux only) and `run --browser` (every OS, only when named: `npm ci` — `npm.cmd` on Windows, fixed argv, no shell — then a `node -e` Chromium probe, then `node node_modules/@playwright/test/cli.js test`, suite `playwright` from `pw.json` `stats`, the stale reports deleted first; a failed `npm ci` or absent Chromium is `reason:"browser-missing"`) drive their tools through the `run_with` runner seam, so the harness's own tests use a stand-in runner and never nest `cargo llvm-cov`, `cargo fuzz` or Playwright inside nextest. `run --perf` (only when named; hyperfine probe → `target/perf` release build → one unstamped `perf-<pid>` session → five hyperfine rows, `pre-tool-use` included → zero-panic check → cleanup) takes its tools through the same runner and its boot/cleanup through the `PerfSession` seam, so its tests never boot a session or nest a build.
- It must not drift from the recorded `viola verify` fixtures, the spine, the dialog variants and the framing variants (`paste-<n>`, `clear-<n>`), which `contract_fake_agent_drift` replays byte for byte (contract suite).

## Exemptions
- `viola-harness` and the fake agent print by design. `viola-e2e` omits `[lints] workspace = true` and carries its own `[lints.clippy]` without `print_stdout` / `print_stderr`; the fake agent is a `[[bin]]` of the root package (lints are per package), so it takes a crate-level `#![allow(clippy::print_stdout, clippy::print_stderr)]`. `tests/contract_lints.rs` asserts that every product member inherits the workspace lints and only `viola-e2e` opts out.

- 2026-09-25: On the Windows host, a diff that carries `#[cfg(unix)]` bodies cannot pass plain `run --mutants` (those bodies are compiled out, so their mutants grade missed), and neither can a shared body whose only killing test is OS-gated (a SIGSTOP stale-wrapper test, a `.cmd` child): read such misses as host-excluded — the epoch-boundary code audit classifies them itself. [corrected 2026-09-28: `--leg` and the CI union are retired; mutation runs at the code audit]
- 2026-09-25: Never pipe `agent-run.sh boot` (`boot | cut`, `| head`): the supervisor it leaves running inherits boot's stdout, so the pipe never reaches EOF and the call hangs until its tool bound — write each harness step's output to a file.
- 2026-09-26: cargo-mutants grades an identical tree a little differently from run to run (caught and unviable shift by a few), so judge a mutation run by its verdict — 0 missed, 0 timeout, unviable ≤ caught — never by comparing its counts with another run's or another host's. [corrected 2026-09-28: "leg" → run; the legs are retired]
- 2026-09-27: A nextest `test(=name)` filter needs the test's full path — an inline unit test is `tests::name` — so the bare name selects nothing and `run --filter` reads `nextest-exit-4`; write `test(=tests::name)` or a regex form. Extended 2026-10-04: `test(/…/)` matches test NAMES only, never the file they live in — select a whole root test file with `binary(<file stem>)`.
- 2026-09-29: A plan gate that calls a harness selector not yet built (a clap usage exit 2) is a plan defect, not a red to fold: record it and pin it on the route entry that builds the selector, with that entry's chunk named as owner.
- 2026-09-29: On this host the local suite grades an identical tree differently run to run, so one subject/control pair never separates two trees: judge a local red against a same-day control as reverse-order standalone pairs of the same harness command, then run the binaries still unmatched alone for a few rounds on BOTH trees — and the red stays open under its owner until its cause is known. Extended 2026-10-06: when every process-spawning test stalls by one common amount while tests that spawn nothing pass in milliseconds, suspect a host stall before the tree — read the other sessions' build dirs on the same volume by modification time per run window, and read a red entry's log before a targeted re-run overwrites it. Extended 2026-10-07: on the Linux dev host the homes sit on tmpfs behind the `target/e2e-home` link, so a stalled-start red is first a finding about the backing — read `test -L target/e2e-home && findmnt -n -o FSTYPE -T target/e2e-home/`, then stop and report it; never re-run for a green.
- 2026-10-04: Keep a mutation run's `TMPDIR` path short (about 60 bytes at most): a harness test binds a Unix socket at `$TMPDIR/.tmpXXXXXX/viola-test-chan-<pid>-<label>.sock`, and past `sun_path`'s 107 bytes cargo-mutants' unmutated baseline fails before any mutant runs.
- 2026-10-07: The fake agent receipts the Enter that submits a prompt as a `key` line of its own (`0d`), ahead of that prompt's line, so after any send the receipt already holds one `key` per submitted prompt: wait for the awaited key by its hex, never for "a key line", and assert the whole ordered list.
