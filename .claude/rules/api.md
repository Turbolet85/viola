# API Rules

Path-scoped rules for viola's interfaces: the wrapper channel, the MCP tools and the CLI verbs. Authoritative sources: `.andromeda/architecture.md` §Conventions + §Standard Contracts; `.andromeda/security-plan.md` §API Security + §Error Handling.

## Four interfaces, one binary
- CLI verbs · MCP tools (stdio JSON-RPC 2.0) · the hook stdin/stdout contract (owned by Claude Code) · the wrapper channel (JSON-RPC 2.0 over ndjson on a local socket). No REST write surface, GraphQL, gRPC, tRPC or WebSocket.
- A new listener or channel method needs a Security Decisions Log entry first.

## Versioning
- Every channel `params`, event line and snapshot carries integer `v` (starts at 1); every `params` also carries `sender` (`CARGO_PKG_VERSION`). Adding a field/kind is additive; removing or re-meaning bumps `v`. A newer `params.v` → `-32602` with `data:{supported, wrapper}`.

## Wrapper channel
- Methods: `send`, `wait`, `last`, `answer`, `pause`, `release`, `link`, `unlink`, `hook.dialog` (requests, integer ids monotonic per connection); `hook.event` (notification). `link` and `unlink` are the contract's and not built: the wrapper answers both `-32601`. A `send` or an `answer` whose `from` is another instance's name records the implicit link (before `send-issued`; before the answer is taken), and a link that cannot be recorded answers `-32603` with nothing issued or the answer not taken. `list` is not a channel method — it reads the disk (and, by contract, `claude agents --json`) caller-side and needs no live wrapper; its `ok` payload is `{items, budget, skipped}` in the shapes of the `list` payload (Standard Contracts), returned whole, with `skipped{unknown_kinds,unknown_fields,torn_lines}`. As landed CLI `list` reads `<home>/instances/` and `budget.json`, then makes one `claude agents --json` read joined by `viola_state::board::join`: a row matching a wrapped item's `child_pid` or `agent_session_id` sets that item's `status` to `idle` or `busy`, and every unjoined row is an unwrapped item (`wrapped: false`, its name the row's `sessionId`, never a `ViolaName` or a valid `target`); a failed, oversize or malformed read leaves every `status` `unknown` and no unwrapped item. `mcp`'s `list` tool (chunk 2026-10-17-mcp-server-for-drivers) builds the same board through `list::board_document` (scan → read with the one `claude agents --json` read and join → document, run on a blocking thread, its `agents-probe` pair in `diagnostics/mcp.ndjson`) on each call and returns the document's `ok`, or `instance-unreachable` for the board's refusal.
- Success `{"result":{"ok":<payload>}}`; refusal `{"result":{"refusal":"<reason>","detail":<string|null>}}` (a normal outcome); protocol fault `{"error":{code,message,data}}` with `-32700/-32600/-32601/-32602/-32603` — `-32603` is exactly `"internal error"`, `data: null`.
- `RefusalReason` (kebab-case): `human-typing` · `budget-paused` · `unverified-cli` · `not-delivered` · `unknown` (`#[serde(other)]`). Details are closed per reason; `control-character` and then `empty-text` (an empty typed text on `send`) precede the documented order (`send`: human-typing → budget-paused → turn-running → input-not-ready → no-prompt-submitted, with human-typing and turn-running read a second time once the readiness gate's wait has returned ready, before anything is issued or typed; `answer`: human-typing → unverified-cli → unknown-dialog). `unconfirmable` only ever appears inside an `ok` payload.
- Frames: `Read::take(MAX_FRAME)` before `read_line` (over → `-32600` + close); `behavior`, `dialog_id` (u64), wheel holder and dialog kind are closed types; `link`/`unlink` names through `ViolaName::try_new`; optional additive `conn`. Method params are each method's: `wait`'s `after` / `timeout_ms` are absent or a `u64`, and `from` (read by `send`, `wait`, `last`, `answer` and `pause`) is absent, `null` or a valid `ViolaName`, anything else `-32602` with `data: null` (the envelope types none of them).
- `release` carrying a string `from` → `-32602` with `data:{"reason":"release-from-driver"}`; a `from` neither absent, `null` nor a string, or a `budget` that is not a bool (`null` included), → `-32602` with `data: null`.
- `release` `{budget?, from?}` → `{wheel, budget_paused, override_until?}`: `budget:true` leaves the wheel and lifts the instance's budget gate (`override_until` = the crossed window's `resets_at` when a pause was lifted; nothing recorded when none stood), answered only after its `budget-gate` line and the snapshot land (`-32603` otherwise); a plain `release` answers the gate's recorded `budget_paused`. `send` reads the gate once at arrival, after `human-typing` and before `turn-running`: a closed gate is `budget-paused` with detail `five-hour` | `seven-day` (exit 11), no cursor, nothing typed.

## CLI
- Human text by default (`viola list`'s human mode alone reads `NO_COLOR`, `TERM` and `COLORTERM` in every build, never set, only to decide whether and how deep its SGR bytes are written: none under `--json`, a non-terminal stdout, `NO_COLOR` present, `TERM` exactly `dumb` or a failed Windows VT enable; they configure nothing and reach no log line, error or refusal; `COLUMNS`, `CLICOLOR`, `CLICOLOR_FORCE` and `CI` are not read), `--json` for agents (`viola revive` takes it on both arms, chunk 2026-10-17-cli-machine-contract: a refused strict-modes check or a preflight refusal is the exit-1 `{"v":1,"error":"<code>","detail":null}` with stderr empty, `<code>` one of `strict-modes-failed` · `already-live` · `no-session` · `session-live` · `cwd-missing` through `client::refused_document`, and `--list --json` prints `{"v":1,"ok":{"sessions":[…]}}` in log order, or the `no-session` document with exit 1; a refusal `run`'s start makes after a passed preflight prints no document, owed to "Exit-cause code catalogue"; `viola plugin install --json` prints `{"v":1,"ok":{"marketplace":"viola","plugin":"viola@viola"}}` with no path, exit 0, and its refused strict-modes check the `instance-unreachable` document, exit 21, through `client::refused_document`): one JSON document on stdout mirroring the channel result (`{"v":1,"ok":…}` / `{"v":1,"refusal":…,"detail":…}` / `{"v":1,"error":"instance-unreachable"|"wrapper-fault",…}`).
- Exit codes: 0 ok · 1 internal / a `run` start refusal, a `revive` strict-modes or preflight refusal, a `verify` failing row, refusal or Ctrl-C / TERM stop (no stamp written, `unable: verify was stopped before it finished`), `list`'s `instances/` that cannot be listed or failed log start, the hidden `viola mcp`'s home or `diagnostics/` (each that exists) failing `viola_state::strict::check_path` (nothing on stdout or stderr, no role file) · 2 usage (clap, a second positional to `viola send` included; never from `viola hook`), and `viola send` text over `MAX_FRAME` or not UTF-8 · 10 human-typing · 11 budget-paused · 12 unverified-cli · 13 not-delivered · 14 unknown · 20 wrapper fault · 21 instance unreachable, and `viola list`'s refused strict-modes check of the home, `instances/` or any one instance, which refuses the whole board (`--json` `{"v":1,"error":"instance-unreachable","detail":null}`, no log opened), and `viola plugin install`'s refused `check_path` of the home or an existing `marketplace/` tree dir, run before anything under the home is created, written or opened (the same exit and document; human mode the home-state pair; nothing created, no log opened). `viola hook` always exits 0.
- Prompt text only from stdin or `--file`; warn on a Git Bash rewritten-path argument; `ViolaName` arguments via `value_parser = parse_viola_name`; `--home`/`VIOLA_DIR` canonicalised and strict-modes-checked before any snapshot, `statusline_command` or ledger read — as landed every CLI verb, `run`, `revive` and `mcp` included, resolves the home through `resolved_home` (chunk 2026-10-17-cli-machine-contract): `--home` as given, else the `instance_of` home when `VIOLA_NAME` passes `ViolaName::try_new` and `VIOLA_DIR` is an absolute `<home>/instances/<name>` (a failing pair falls through, never refuses), else `<user home>/.viola`; `canonical_home` then canonicalises a home that exists (on Windows the plain drive form) and keeps `std::path::absolute`'s spelling for one that does not, creating nothing; the `VIOLA_DIR` step and the canonicalisation, `mcp`'s use of them included, are a widening the founder ratified (his own word, relayed verbatim by the operator, 2026-10-19; security-plan §Input Validation), and `list`'s `board::scan` runs `check_path` on the home and `instances/` and `check_instance` per instance before any file under the home is opened. Interim ratified gaps until Epoch 6: `viola hook <event>` shape-checks `VIOLA_DIR` only (`hook statusline` canonicalises its instance directory and runs `check_instance` before its log; its hidden `hook statusline --capture <DIR> [--shell <WORD>]` probe form, called only by Run B's probe settings, runs no instance check, reads no `VIOLA_*` and requires an absolute, existing `<DIR>` instead, its `--shell` word mapped only into the closed `ShellVerdict`); `verify` reads `ledger/stamps.json` before strict-modes — security-plan Decisions Log `2026-09-28`; `run`'s version gate reads it through `read_stamps_strict`; `send`, `wait`, `last`, `answer`, `pause` and `release` read `snapshot.json` without strict-modes after a liveness-only pre-check, and so do `viola mcp`'s `send` / `wait` / `last` / `answer` tools (`viola_state::liveness::live_endpoint`, else `{"error":"instance-unreachable","detail":null}`; the eighth dated gap, the founder's own answer, `inputs#I2` Q1 of chunk 2026-10-17-mcp-server-for-drivers).
- The CLI adds `from` from its own `VIOLA_NAME` when set; the MCP server adds it from its own `VIOLA_NAME` only when it has a name of its own.

## MCP
- Tools exactly `send · wait · last · answer · list`; `release`, `pause`, `link`, `unlink` stay CLI-only. Schemas are advisory — each handler takes the raw argument object, never rmcp's typed deserialisation: `target` through `ViolaName::try_new`, `dialog_id` a `u64`, `after` / `timeout_ms` absent, `null` or a `u64`, `response` through `Response::parse`, a failure being `isError:true` `{"error":"invalid-params","detail":"<field>"}` (a closed field word) with no frame written; then `validate_paste_text` (and on `send` the empty-text check) on `send`'s text and every free-text answer value, a failure being the refusal `not-delivered` with detail `control-character` or `empty-text` (on `send` with one client-side `send-refused` line), before any frame.
- Success: `isError:false` + the channel `ok` payload as `structuredContent`; refusal, unreachable, fault or invalid params: `isError:true` + codes only, text `refused: <code>`; JSON-RPC errors are only the connection's own faults, an unknown tool (`-32602`) and an internal handler fault (`-32603` `internal error`, `data: null`); `tools/list` carries `ttlMs` 0 and `cacheScope` `private` (claude 2.1.287 drops every tool without them). rmcp features exactly `server` + `transport-io`; every call returns below the client's tool-call timeout: MCP `wait` sends `timeout_ms` = `min(given, 50 000)` (`viola_mcp::WAIT_CAP`), 50 000 ms when none is given, below claude 2.1.287's stdio tool-call default (over 50 s, as measured live).

## GUI
- The frontend is deferred to 0.2.0; its technology is not chosen. There is no `ui` subcommand and no listening TCP port; the MCP server is stdio only.
