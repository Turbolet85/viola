# Security Rules

Universal security requirements for viola. Apply to all files. This rule file has no `paths:` frontmatter — it loads unconditionally, so it stays lean; the full contract is `.andromeda/security-plan.md` (tier Minimal with local-boundary elevations).

## Secrets and the NEVER-log floor
- Secrets in v1: inherited `CLAUDE_CODE_MESSAGING_TOKEN` / `_SOCKET` and every R8-stripped `CLAUDE*` value. None may reach a log, diagnostic, event, snapshot, fixture or error body.
- Never commit `.env*`, local `--home` test directories, tokens, cookies or signing material; never hardcode a credential in source or in the `include_str!` plugin files.

## Local trust boundary (IPC + home)
- Windows pipe listener: explicit protected SDDL `D:P(A;;GA;;;<user-SID>)(A;;GA;;;SY)`, `accept_remote(false)`, first-instance, non-inheritable. Client opens with `SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION` — never interprocess's default connect.
- Unix socket: a verified 0700 per-user dir (`$XDG_RUNTIME_DIR/viola/`, `$TMPDIR/viola/`, `/tmp/viola-<uid>/`), never `/tmp` root, never abstract namespace, the socket chmod 0600 after the bind as a secondary control only (never `ListenerOptionsExt::mode`: `Unsupported` on macOS fails the bind), `peer_creds` euid on both sides, `try_overwrite` off.
- Before the FIRST frame of any method (including `hook.event`), verify the server: pid (+ sysinfo start time) against a `snapshot.json` that passed strict-modes in the same process (macOS: euid + dir only, recorded gap). - The hidden `hook <event> --capture <DIR>` (founder-ratified, Decisions Log `2026-09-28`) is `viola verify`'s probe capture only: absolute existing `<DIR>`, stdin through `take(MAX_FRAME + 1)`, raw 0600 write, no `VIOLA_*` read, no obs init, no channel, exit 0 always; its statusline form `hook statusline --capture <DIR> [--shell <WORD>]` (Run B's probe settings only; the founder's own answer to P4 fork 3 of chunk 2026-10-13-owed-ledger-rows) holds the same bounds, writes the payload raw and only the closed `ShellVerdict` (`bin-sh` · `other`, never the word), and prints nothing. - A non-`null` dialog decision requires a `viola verify` stamp for the child's CLI version; `release` carrying `from` → `-32602 release-from-driver`; `from` is self-reported, never identity.

## Input validation
- Shared validators live in `viola-core`; the wrapper re-runs them (client checks and schemars schemas are advisory).
- Home resolution (every CLI verb, `run` and `revive` included, and the hidden `viola mcp` (chunk 2026-10-17-mcp-server-for-drivers); `hook` keeps its own shape check; chunk 2026-10-17-cli-machine-contract): `--home` as given, else the `instance_of` home when `VIOLA_NAME` passes `ViolaName::try_new` and `VIOLA_DIR` is an absolute `<home>/instances/<name>` (a failing pair falls through, never refuses), else `<user home>/.viola`; `canonical_home` canonicalises a home that exists (Windows: the plain drive form) and creates nothing. The CLI verbs' `VIOLA_DIR` step and the canonicalisation, `mcp`'s use of them included, widen what chooses a CLI verb's home: a widening the founder ratified (his own word, relayed verbatim by the operator, 2026-10-19).
- `validate_paste_text` over decoded `char`s: allow LF/CR/TAB, refuse every other C0, DEL and C1 with `not-delivered` / `control-character` — reject, never strip a refused character. After validation the wrapper's `send` types the text with every CR LF pair and every other CR as one LF and without its trailing CR and LF characters (`viola_agent_claude::hook::typed_text`; it holds no CR, only CR and LF are rewritten or removed, and no refused character is typed or removed), and the exact match, the local-command list, `text_bytes` and the paste read that typed text. An empty typed text, the empty text included, is refused `not-delivered` / `empty-text` (exit 13) right after `control-character`: by the client before any frame and by the wrapper before the first wheel read.
- `Read::take(MAX_FRAME)` (16 MiB) before `read_line` / `read_to_end` on every external reader; serde_json default depth (never `unbounded_depth`). In a hook payload each question's `option_details` keeps an option's `description` / `preview` only as strings (else `null`, never refusing the dialog), and the Stop's `background_tasks` is read as `IgnoredAny` elements and carried only as its length (`null` when absent, `null` or not an array); the option text crossing into `events.ndjson`, `hook.dialog`, CLI `wait --json` and MCP `wait` is a boundary widening the founder answered himself (P4 fork Q4 of chunk 2026-10-19-overseer-switch-to-viola).
- `viola revive`: both arms run `viola_state::strict::check_instance` (the home, `instances/`, the instance directory, its `snapshot.json` and `events.ndjson`) before any snapshot or log value is used and, on the start arm, before the wrapper log opens; a refusal is exit 1, no child, no log opened and no line written, printing the state-files `unable:` / `hint:` pair on stderr, or under `--json` exactly `{"v":1,"error":"strict-modes-failed","detail":null}` on stdout with stderr empty (chunk 2026-10-17-cli-machine-contract), the home's mode left as found. The child's cwd is the snapshot's recorded `cwd` (an existing directory, else `cwd-missing`; a widening the founder ratified live on 2026-10-10), never read by program resolution or the version gate. The id after `--resume` is the newest logged id of the closed session-id shape, or an `--id` the log holds, as one argv element of a direct spawn built by `viola_agent_claude::resume_args`; no refusal line holds the recorded directory, a pid or a logged id. The preflight (skipped under `--fork`) reads `claude agents --json` once before its recorded-directory reading (a direct spawn of `claude` from its current directory under the R8 strip, stdout through `take(MAX_FRAME + 1)`, killed at 5 s): a logged id listed live elsewhere is the closed refusal `session-live`, no child; `--json` is accepted on both arms (chunk 2026-10-17-cli-machine-contract): a refused strict-modes check or a preflight refusal prints exactly `{"v":1,"error":"<code>","detail":null}` on stdout (stderr empty, exit 1), `<code>` one of the closed `strict-modes-failed` · `already-live` · `no-session` · `session-live` · `cwd-missing`, and `--list --json` prints `{"v":1,"ok":{"sessions":[{"ts","cause","id"},…]}}` in log order — codes, closed words and session-shaped ids only, never a path or pid; a refusal `run`'s start makes after a passed preflight prints no document (owed to the route entry "Exit-cause code catalogue"); a failed, oversize or malformed read passes (fail open) — the founder's own answer to P4 fork 3 of chunk 2026-10-16-unwrapped-sessions-on-the-board. The logged id on the child's command line is a crossing the founder ratified (live, 2026-10-10, relayed verbatim by the overseer). The check comes before the log because opening a log sets an existing home to 0700 and a check made after it passes a home at 0770 (measured and fixed at chunk 2026-10-10-budget-governor).
- Statusline (two founder-ratified widenings, live, 2026-10-10): `run` reads the user's command at start from `<home>/statusline-source.json`, else for the default home only (`canonical_home(default_home(…))`; a home named by `--home` or reached through `VIOLA_DIR` reads none) `~/.claude/settings.json` (`take(MAX_FRAME)`; a `statusLine` of type `command`, non-empty, no NUL), writes neither file, and records the command only in `snapshot.json`; neither source is on the trusted-file list. `viola hook statusline` without `--capture` (the hidden capture form is taken first and is `viola verify`'s probe capture alone) canonicalises its instance directory and runs `check_instance` BEFORE anything under the home is read or opened (a check made after the log passes a home at 0770); a refused instance returns exit 0 at once with no `config.json` read, no role file opened, no line, no stdin read and no command run. A passed check then runs the command as one argument of `/bin/sh -c` (Unix only; stdout through `take(MAX_FRAME)`, stderr discarded, a 5 s PROVISIONAL bound, the command in no line or span). It stays the only shell-out. `budget.json` is written only by this arm, at 0600 under its lock, only when the payload holds `rate_limits`.
- Budget gate: `config.json`'s `five_hour` / `seven_day` are whole numbers into `Percent` (0–100, defaults 90 / 85), read once at the wrapper's start through `take(MAX_FRAME)` (and by `viola list` at each run, through the same `read_thresholds`); a bad value takes that key's default with one `parse-rejected{parser:"config-json"}` line per key, and no value switches the gate off. The dialog hold `dialog_hold_s` is read once at the wrapper's start right after the thresholds (through `take(MAX_FRAME)`) as a whole number of seconds into `DialogHold` (60–3600, default 60); a bad value takes 60 with one `parse-rejected{parser:"config-json"}` line, no value makes the hold zero or unbounded, and no env var or flag sets it (a boundary widening the founder answered himself, chunk 2026-10-19-dialog-hold-for-the-driver). The gate reads `budget.json` only through `viola_state::budget::read_budget` (`check_path` on the home and the file, a shared lock, `take(MAX_FRAME + 1)`, tolerant parse, `v` = 1); every failure is no reading with no line, and the gate is fail-open. `budget.json` is not on the trusted-file list: the wrapper refusing a driver's `send` on it is a boundary widening the founder ratified (his own answer, 2026-10-13, relayed verbatim by the Viola overseer; it had landed on the operator's word, 2026-10-10, which is no ratification). A `release` with `budget: true` and a string `from` is refused first and lifts nothing.

Never widen an ignore, add a `skip`/`allow` or silence zizmor to reach green.
- `Cargo.lock` committed; `[workspace.dependencies]` pins versions (rmcp `>=3.4.1, <3.5`); rmcp features exactly `server` + `transport-io` in `viola`'s release graph (`scripts/rmcp-features.sh`, CI's lint job, rmcp present); the test-only `viola-e2e` takes rmcp `client` only, never `transport-child-process`.
- `fuzz/` is its own cargo workspace, and its `fuzz/Cargo.lock` (libfuzzer-sys builds C++) sits outside the root `cargo deny` graph by a ratified test-only exemption: never link it into `viola`, never add `fuzz` to the root `[workspace]`. - The release build carries `viola` only: `scripts/release-check.sh` judges the build's own artifact records (never a `target/release/` listing) and refuses any test-only binary and any artifact built with a test-only feature (`test-support`, `fake-agent`).
- Actions pinned by full commit SHA; workflow `permissions: {}`, job `contents: read`; no `rust-cache` in a release workflow.
- `pre-push` runs natively on the Linux dev host and installs nothing: its `tools` stage checks the host against CI's own pins (`cc`, the `rust-toolchain.toml` channel, ci.yml's `test`-job `tool:` line). Every child runs under `/usr/bin/env -i HOME=<passwd home> PATH=<home>/.cargo/bin:/usr/local/bin:/usr/bin:/bin` — no host value crosses, and no other assignment is made; HOME comes from the passwd entry (two PATH-only probes, `id -u` then `getent passwd <uid>`), never the harness's `$HOME`. No other launcher and no uid-0 launch exists (an assignment taking a host value is a boundary widening).
- The only env vars outside `VIOLA_*` any `viola` build reads are the terminal colour facts `NO_COLOR`, `TERM` and `COLORTERM` (every build, `viola list`'s human mode only, only compared and never echoed, deciding only whether and how deep SGR bytes are written; they reach no log line, error or refusal, configure nothing, disable no control and widen no redaction; the founder's own word, chunk 2026-10-17-cli-output-discipline) and the two test seams `FAKE_AGENT_PUMP_DELAY_MS` (capped at 5 s) and `FAKE_AGENT_HOOK_PANIC` (exact `1`, a forced fail-open `hook` panic, named only in `src/cmd/hook/seam.rs`): `cfg(feature = "fake-agent")` only, never in a release build. G2 exempts only a panic line at exactly `src/cmd/hook/seam.rs:<digits>` (founder ratification, Decisions Log `2026-09-28`). Another seam or environment read, a colour fact changing a control or reaching a log line, error or refusal, or another G2 exemption, needs a Decisions Log entry.

## Error handling
- thiserror `Display` impls use fixed messages (no paths, no payloads); channel `-32603` is exactly `"internal error"` / `data: null`, and so is an MCP handler fault; MCP `isError` results carry codes only (`refusal`/`detail`, or `instance-unreachable`, `wrapper-fault`, `invalid-params`), text `refused: <code>`.
- Full detail goes only to `instances/<name>/diagnostics/detail-*.ndjson` (0600) when an instance resolves.
