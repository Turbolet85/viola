# Security Rules

Universal security requirements for viola. Apply to all files. This rule file has no `paths:` frontmatter — it loads unconditionally, so it stays lean; the full contract is `.andromeda/security-plan.md` (tier Minimal with local-boundary elevations).

## Secrets and the NEVER-log floor
- Secrets in v1: inherited `CLAUDE_CODE_MESSAGING_TOKEN` / `_SOCKET` and every R8-stripped `CLAUDE*` value. None may reach a log, diagnostic, event, snapshot, stamp, fixture or error body; the verify stamp's env probe holds names and counts only (names kept by `claude_env_keep` removed before it is written), and the recorded env fixture only its version and the hook-added `CLAUDE*` names.
- Never commit `.env*`, local `--home` test directories, tokens, cookies or signing material; never hardcode a credential in source or in the `include_str!` plugin files.

## Local trust boundary (IPC + home)
- No Windows pipe listener: the IPC endpoint is a Linux Unix socket; the Windows and macOS code stands recoverable at the git tag `multi-os-final`.
- Unix socket: a verified 0700 per-user dir (`$XDG_RUNTIME_DIR/viola/`, and `/tmp/viola-<uid>/` only as a fallback), never `/tmp` root, never abstract namespace, the socket chmod 0600 after the bind as a secondary control only (never `ListenerOptionsExt::mode`), `peer_creds` euid on both sides (the wrapper drops a refused peer in `accept_loop` before any frame; a client refuses a peer whose euid cannot be read), `try_overwrite` off. The directory check (`check_socket_dir`, and `check_endpoint_dir` on a recorded endpoint's parent: owner == `geteuid()`, `mode & 0o077 == 0`, not a symlink, never a chmod) runs before the bind and before any client connect, at the seams and never inside `viola_channel::Client::connect`; `run` and the start of `revive` refuse before any snapshot, child or `Server::bind`, a failed create and a refused check alike: exit 1, `socket-dir-refused`, one `process-exit`.
- Before the FIRST frame of any method (including `hook.event`), verify the server: pid (+ sysinfo start time) against a `snapshot.json` that passed strict-modes in the same process (the socket-directory, pid, start-time and euid checks, none skipped). `viola hook`'s event and dialog paths run `check_instance` on the canonicalised instance (`canonical`, then `trusted`, in `src/cmd/hook.rs`) before the diagnostics level and obs init; a refused or absent instance exits 0 at once with no `config.json` read, no role file, no stdin read, no line, no frame and no SessionEnd append; the `--capture` arm stays ahead of the check. `verify` checks its home tree (`check_home_tree`: the home, `ledger/`, `bin/`, `plugin/`) before its `cli` log, and its `update_stamps` runs `strict::check_stamps` before it creates `ledger/` and again under its lock (a refusal `StampsError::StrictModes` reads and writes nothing, exit 1 with the home pair); `run`'s version gate reads the stamps through `read_stamps_strict` (a refusal is `cli_verified:false`). No dated strict-modes gap remains: every other frame client runs `check_instance` first, then reads the snapshot through `read_snapshot_or_replay` (a replayed or absent one gives no endpoint and so no frame), then the liveness-only pre-check, the socket-directory check on the recorded endpoint (`check_endpoint_dir`), the connect, the peer euid decision (`peer_admitted`) and the server check — CLI `send` (after its text read), `wait`, `last`, `answer`, `pause`, `release`, `link` and `unlink` through `client::refuse_untrusted`, then `live_endpoint` (the snapshot's pid + start time alive, the heartbeat live, an `endpoint` present; else exit 21, `viola_state::liveness::without_endpoint`'s `symlink_metadata`, which opens nothing and writes no line, reading `instance-dead` for an instance directory and `unwrapped-name` for an absent path or a regular file), then `client::connect` (the socket-directory check on the recorded endpoint, the connect, the peer euid decision and the peer pid and its start time against the snapshot's `pid` and `started_at`); `viola hook pre-tool-use|permission-request` past `trusted` writes its `hook.dialog` frame after its payload shape check through `src/cmd/hook.rs`'s shared `connect`; `viola mcp`'s `send` / `wait` / `last` / `answer` tools through the Tokio client after `check_instance` and `viola_state::liveness::live_endpoint` (else `instance-unreachable` with `detail` `without_endpoint`'s reading, `instance-dead` or `unwrapped-name`) then `check_endpoint_dir` (a refusal `socket-dir-refused`) and, after `TokioClient::connect`, the peer euid decision (a refusal `server-verify-failed`) and the server check. On a strict-modes refusal no frame and no line is written: the CLI frame verbs exit 21 with the instance `unable:` / `hint:` pair (under `--json` the `instance-unreachable` document, `detail` `strict-modes-failed`), `hook` exits 0 with no body, MCP returns `instance-unreachable` with `detail` `strict-modes-failed`. On a refused socket directory, before the connect, no frame is written: the CLI frame verbs exit 21 `instance-unreachable` (under `--json`, `detail` `socket-dir-refused`), MCP returns `instance-unreachable` with `detail` `socket-dir-refused` and writes no line, and `hook` fails open (exit 0, no body, one WARN `hook-decision` carrying `socket-dir-refused`). On a mismatch, a refused peer euid, or a check that cannot be made, no frame is written: the CLI frame verbs exit 21 `instance-unreachable` (under `--json`, `detail` `server-verify-failed`), MCP returns `instance-unreachable` with `detail` `server-verify-failed` and writes no line, and `hook` fails open (exit 0, no body, `hook-decision` carrying `server-verify-failed`); no line or output holds a pid, start time, path or endpoint.

## Input validation
- Shared validators live in `viola-core` (the three exceptions: the Hyprland seam's window Address validator lives in the seam crate, the Claude transcript path shape check in the Claude adapter crate, which the hook and the wrapper both call, and the effort-word check, also in the Claude adapter crate beside the claude flag literals); the wrapper re-runs them (client checks and schemars schemas are advisory).
- Home resolution (every CLI verb, `run` and `revive` included, and the hidden `viola mcp` (chunk 2026-10-17-mcp-server-for-drivers); `hook` keeps its own shape check; chunk 2026-10-17-cli-machine-contract): `--home` as given, else the `instance_of` home when `VIOLA_NAME` passes `ViolaName::try_new` and `VIOLA_DIR` is an absolute `<home>/instances/<name>` (a failing pair falls through, never refuses), else `<user home>/.viola`; `canonical_home` canonicalises a home that exists and creates nothing. The CLI verbs' `VIOLA_DIR` step and the canonicalisation, `mcp`'s use of them included, widen what chooses a CLI verb's home: a widening the founder ratified (his own word, relayed verbatim by the operator, 2026-10-19).
- `validate_paste_text` over decoded `char`s: allow LF/CR/TAB, refuse every other C0, DEL and C1 with `not-delivered` / `control-character` — reject, never strip a refused character. After validation the wrapper's `send` types the text with every CR LF pair and every other CR as one LF and without its trailing CR and LF characters (`viola_agent_claude::hook::typed_text`; it holds no CR, only CR and LF are rewritten or removed, and no refused character is typed or removed), and the delivery confirmation, the local-command list, `text_bytes` and the paste read that typed text (delivery is confirmed when the submitted text equals the typed text exactly, or is non-empty and equals it with its trailing run of ASCII space, TAB, CR and LF removed; no other difference, leading trimming included, is tolerated); a paste not finished within its compiled bound is cut, the bracket closed with no CR, and the send refused `not-delivered` / `paste-cut` (exit 13). An empty typed text, the empty text included, is refused `not-delivered` / `empty-text` (exit 13) right after `control-character`: by the client before any frame and by the wrapper before the first wheel read.
- `Read::take(MAX_FRAME)` (16 MiB) before `read_line` / `read_to_end` on every external reader, and `viola mcp`'s stdin through `viola_mcp::stdin::CappedLines` at `MAX_FRAME` per line (an over-long line refused whole, ending the session), and the Claude transcript read without following a symlink, only as a regular file owned by the effective user, from the recorded pre-send offset through `MAX_FRAME`, yielding a count of local-command-stdout tags alone with no byte kept; serde_json default depth (never `unbounded_depth`; `deny.toml` bans the feature, its firing proven by `scripts/deny-probes.sh`). ## Error handling
- thiserror `Display` impls use fixed messages (no paths, no payloads); channel `-32603` is exactly `"internal error"` / `data: null`, and so is an MCP handler fault; MCP `isError` results carry codes only (`refusal`/`detail`, or `instance-unreachable` with `detail` its closed cause, `strict-modes-failed` · `instance-dead` · `unwrapped-name` · `endpoint-lost` · `server-verify-failed` · `socket-dir-refused`, as in CLI `--json`'s exit-21 document, plus `call-deadline` on MCP alone when a frame tool call reaches its call deadline (the CLI's six never carry it), or `wrapper-fault`, `invalid-params`), text `refused: <code>`. A client reads a reply through `reply_of` (CLI `--json`) and `of_reply` (MCP): a `refusal` or a string `detail` only as a code word (`viola_core::is_code_word`; a failing `refusal` reads `unknown`, a failing `detail` null; a word outside the closed list stays visible by design), a fault only through `viola_channel::sanitised_fault`, which closes its `message` and `data` (only two `-32602` bodies keep `data`).
- Full detail goes only to `instances/<name>/diagnostics/detail-*.ndjson` (0600) when an instance resolves. A trust record write or removal ends in one of 14 closed code words, a start's trust step in one of 16 start words; verify's word alone is stamped as the trust-record row's value when nothing was written, a start's is its trust-record line's detail, never a path, key or value. Every product error writer is named in `tests/contract_error_bodies.rs`: `product_error_writers_are_each_named` fails on an unnamed one and `thiserror_messages_interpolate_nothing` on an interpolating `thiserror` message.
