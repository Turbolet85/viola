## Harness contract (§3)

The harness is the agent-driven verification surface. `scripts/agent-run.{sh,ps1}` are thin shims over `cargo run -q -p viola-e2e --bin viola-harness -- <command>`; all logic lives in Rust. See `.claude/rules/verification-harness.md` for path-scoped enforcement.

- **Test runner:** cargo-nextest 0.9.146 (process-per-test, JUnit, `retries = 0`) + `cargo test --doc`; nextest is the runner, and a plain `cargo test` run (`cargo test --bin viola`) is not supported
- **5-command discipline:** boot / run / status / cleanup / logs — each prints one JSON document `{"v":1,"cmd":…,"ok":…}`, exit 0/1/2
- **Status:** `agent-run status` runs `<bin dir>/viola --home <home> list --json` (the bin dir and session `bin/` from `supervise.json`, the session `PATH`, `VIOLA_NAME` / `VIOLA_DIR` / `VIOLA_BIN` removed) and aggregates it (`state: ready|degraded|down`; `pid` and `uptime_ms` are `null`): `ready` when `list` exits 0 and every booted instance is an item `wrapped:true, liveness:"live"`, `degraded` when one is `stale` or absent or the document holds no `items`, `down` when `list` exits non-zero (`list-exit-<code>`), gives no exit code, cannot be spawned or has no `supervise.json` (`list-exit-none`), or exits 0 with no JSON object (`list-exit-0`)
- **PID file:** none as a product file — pids live in `instances/<name>/snapshot.json`; the harness record is `target/agent-run/<session>/session.json`
- **Log format:** JSON-per-line — `events.ndjson` (arch event line) + process logs in `<home>/diagnostics/*.ndjson`; required fields `timestamp level target message event process instance corr` (bound to obs-plan §3)
- **Tempdir convention:** a not-yet-existing home under `target/e2e-home/viola-session-*/home` (harness) or `target/e2e-home/viola-test-*/home` (root rstest chain, `tests/support/home.rs`) — viola creates it, except on Windows x64 where `seed_conpty` first hard-links the ConPTY companions into a root test home's `bin/<key>/conpty/` from `target/conpty-seed/<key>/` (`Wrapper::boot`, piped and outer-PTY starts; never `run_viola_unseeded` or `conpty_sideload`, which keep the product's write; `seed_conpty` makes the home and the seed dir through `viola_state::fs::create_private_dir` first, so a seeded home passes the instance check; its companions are hard links to one shared seed file, so a test that widens a home tree above `bin/<key>/conpty/` starts that home unseeded), and except `tests/chaos_feed_panic.rs`'s `TestHome::outside_scan()` home under the system temp dir, outside G2 / G4 / the secret scan (the founder's ruling, 2026-10-04); kept in CI (`AGENT_RUN_KEEP_HOMES=1`; never under `run --mutants`) until obs gates and the secret scan have read it, a root home's leftover removed only once its recorded owner process is gone (removal deletes `owner.json` last, `remove_owned`), and on a failing test under `AGENT_RUN_KEEP_FAILED=1` (viola-e2e's booted lifecycle tests through a `Booted` drop guard that stops the session first, and removes the home of a passing test); the base `target/e2e-home` is prepared by a keeper before any home is made (`prepare_home_base` in the root chain, `Workspace::ensure_e2e_home` in the harness), a linked base whose filesystem reads less than the 9 GiB headroom floor free (`statvfs`) is refused, and on the Linux dev host it is an operator-set link to an owner-only tmpfs directory under `/tmp`: the path is unchanged, a kept home there does not survive a reboot, and no CI runner has the link

## Universal anti-patterns

- NEVER use `sleep(N)` for synchronization, a retry budget, or `#[ignore]` as a parking place.
- NEVER parse the rendered child screen; verdicts come from hook events, `events.ndjson`, channel payloads and the fake-agent receipt.
- NEVER run the real `claude` or real-CLI `viola verify` in CI; NEVER treat a green fake-agent run as proof of real-CLI behaviour.
- NEVER hand-write stamps, snapshots or `budget.json` in a booted-wrapper test (a reader's own unit cases may plant a malformed state file only by altering the writer's own bytes); NEVER use `std::env::set_var`.
- NEVER write a test that auto-approves a dialog.

## Critical decisions

- `crates/viola-e2e` (test-only, `publish = false`) hosts `viola-harness` and the Tokio clients, keeping the sync root package tokio-free.
- Stamps conflict resolved: `viola verify` against the fake agent is the only writer of `ledger/stamps.json` in tests and CI.
- Branch coverage is enforced as LLVM region coverage; mutation testing covers branch strength.
- hyperfine is the perf gate (criterion does not exit non-zero on regression).
- The spine deadline is `viola_core::SPINE_DEADLINE`; the confirmation window is the compiled `CONFIRM_WINDOW_FALLBACK` = 10 s for every confirmed send but `/compact` on a verified CLI, which waits its own `COMPACT_CONFIRM_WINDOW` (40 s, PROVISIONAL), validated per CLI version by the `confirm-window` ledger row.
