# Security Summary — viola

_Distilled from `.andromeda/security-plan.md` by `/andromeda-setup-project`. wrap-session does not modify._

## Posture

viola is a local-only, single-user tool: no accounts, no public listener, no database, no stored credentials and no regulated data. Its risk is the local privilege boundary. The IPC endpoint is effectively a code-execution interface (`send` types prompts, `answer` can allow PermissionRequest tool calls). Several state files decide what code runs (`statusline_command`, the plugin exec paths, the pinned binaries, the ledger stamps). The plan is a Minimal baseline with targeted elevations for each of these.

**Tier:** Minimal (0), with targeted elevations for the local privilege boundary
**Auth approach:** OS-user ambient trust enforced per OS (IPC endpoints + `~/.viola/`)

## Threat model highlights

- **A foreign OS user connects to the IPC endpoint** → Windows protected SDDL (user SID + SYSTEM), `accept_remote(false)`; Unix 0700 per-user socket dir + socket chmod 0600 after the bind + `peer_creds` euid check.
- **A squatter impersonates the wrapper** → the client verifies the server's pid (+ start time) against a strict-modes-checked `snapshot.json` before the first frame; Windows clients open with SQOS Identification. As built, on Linux and Windows every frame-writing client (the CLI frame verbs, `viola hook`'s event and dialog paths, `viola mcp`'s frame tools) compares the connected peer's pid and start time with the snapshot's `pid` and `started_at` before its first frame and sends no frame on a mismatch or a check it cannot make. Every client first runs the instance's strict-modes check (`check_instance`: the CLI frame verbs and `link` / `unlink` through `client::refuse_untrusted`, `viola hook`'s event and dialog paths through `trusted` before obs init, `viola mcp`'s frame tools before `live_endpoint`), a refusal writing no frame and no line, then reads the snapshot through `read_snapshot_or_replay`, a replayed or absent snapshot giving no endpoint and so no frame; the client euid check and macOS (no peer pid) are owed to "Unix endpoint and home hardening". A squatted name blocks `run` (DoS accepted, no takeover).
- **Bracketed-paste breakout** (`ESC[201~` inside `send.text`) → `validate_paste_text` rejects every C0 except LF/CR/TAB, DEL and C1, client- and wrapper-side.
- **Tampered code-bearing state** → strict-modes check (Unix mode/owner; Windows owner + DACL) at every entry point that reads a trusted file before its first read or open under the home, with no dated gap: `run`, `revive`'s start and `verify` through `check_home_tree` (the home, the instance's files, `ledger/`, `bin/`, `plugin/`, the pinned copy's `bin/<key>/` and `plugin/<key>/`) before their log opens, a refusal exit 1; every frame client (CLI verbs, `viola hook`'s event and dialog paths, `viola mcp`'s tools) through `check_instance` before its snapshot read; `verify`'s `update_stamps` through `check_stamps` before it creates `ledger/` and again under its lock, and `run`'s version gate through `read_stamps_strict`; the diagnostics opens through `check_diagnostics` (a symlink refused, a refusal a failed open); the read rule on the home, the instance directory and `diagnostics/`; a home created outside `%USERPROFILE%` gets the protected user + SYSTEM DACL at creation; pinned exe placed once and never replaced (`place_private_new`: the write handle closed before a no-clobber `persist_noclobber`, so concurrent first starts never exec a copy held open for write) and re-hashed (truncated SHA-256) before reuse, a copy another start placed first included; the ConPTY companions (`bin/<key>/conpty/`) held to the owner/DACL strict-modes check (`check_present`, before the held open) and fully re-hashed against compiled pins through `FILE_SHARE_READ`-only handles held until the spawn, a refused check or a mismatch falling back to the inbox ConPTY; plugin files rewritten each start, and on Unix the instance's `settings.json` statusline override (0600, only for a pinned path of plain characters; none on Windows); single writers for snapshot and stamps; `marketplace/` (whose `viola/.mcp.json` Claude Code runs for MCP in a session that installed the plugin) written only by `viola plugin install`, after `check_path` on the home and each existing `marketplace/` dir (a refusal exits 21, nothing created), each file rewritten whole at 0600, never read back and its command not re-hashed — `marketplace/` off the integrity set.
- **Planted `conpty.dll` in the CWD or on PATH** (a bare-name DLL load) → every `viola` process restricts its DLL search to System32 as the second statement of `main`; the sideloaded `conpty.dll` is pre-loaded only by absolute path.
- **Planted `claude` on PATH** (for `claude agents --json`) → accepted: it can inject display rows only; those rows are never a `ViolaName`/`target` and are escaped of C0/C1 controls before human-mode CLI `list` prints them.
- **Driver LLM prompt-injected into `answer allow`** → accepted: policy is outside viola (R1/R4); viola offers only a closed `behavior` enum and the `unverified-cli` gate.

| Low (operational) | pids, `agent_session_id`, budget percentages, OS username in paths | Typed fields in diagnostics; paths never in external errors |

## Universal anti-patterns

- NEVER add a listener, transport or channel method without a Security Decisions Log entry.
- NEVER let a security refusal block the human — refusals go only to automation, hooks fail open.
- NEVER let an exec-form command viola writes resolve `viola` through PATH — the absolute pinned path only, or, in `viola plugin install`'s `.mcp.json`, the absolute path of the exe that ran the install.
- NEVER answer `hook.dialog` non-`null` without a `viola verify` stamp read through `run`'s strict stamps read; only `viola verify` writes the stamps. The ledger has twenty-four rows (six spine, four screen and timing, four dialog-tier, three framing: `long-paste-wrapper` · `tag-escaping` · `local-command-clear`, the newline row `paste-newline`, the three statusline rows `statusline-override` · `statusline-shell` · `statusline-rate-limits`, the resume row `resume-session`, the agents row `agents-join` and the compact row `local-command-compact`), and a stamp is read over the relied set (`LedgerRow::relied()`: all twenty-four on Unix; on Windows, where the status line is not wrapped, the first eighteen, `resume-session`, `agents-join` and `local-command-compact`), so a decision flows only when every relied row passes (`20 pass  4 fail` on Unix or `17 pass  4 fail` on Windows, or a stamp of the fourteen older ids or of the seventeen written before chunk 2026-10-13-paste-newline-ledger-row all `pass`, or, on every OS, one of the eighteen written before chunk 2026-10-13-owed-ledger-rows, of the twenty-one written before chunk 2026-10-14-resume-and-compact-ledger-rows, of the twenty-two written before chunk 2026-10-16-unwrapped-sessions-on-the-board or of the twenty-three written before chunk 2026-10-18-compact-post-condition-ledger-row, → `cli_verified:false`, `answer` exit 12); the founder's dated gap R2 is closed.
- NEVER let a process other than the instance's wrapper write its `snapshot.json`.
- NEVER let `config.json`, a `VIOLA_*` env var or a flag switch off a control. The two env carve-outs are the test seams `FAKE_AGENT_PUMP_DELAY_MS` (capped at 5 s) and `FAKE_AGENT_HOOK_PANIC` (exact `1`, forced fail-open hook panic; G2 exempts only its exact file path), both only under `fake-agent`, absent from release builds, switching off nothing; the terminal colour facts `NO_COLOR`, `TERM` and `COLORTERM` are read in every build, only by `viola list`'s human mode and only to choose whether and how deep SGR bytes are written — they switch off no control, widen no redaction and are not a configuration channel (the founder's own word, chunk 2026-10-17-cli-output-discipline); another seam or environment read, or a colour fact changing a control or reaching a log line, error or refusal, needs its own Decisions Log entry.

## Critical decisions

- Windows pipe SDDL = user SID + SYSTEM only; the logon SID is rejected — a same-user driver in another logon session (SSH, scheduled task) must still connect.
- `validate_paste_text` allows LF/CR/TAB (multi-line relays are normal), rejects the rest — reject, never strip a refused character. Only allowed characters are rewritten or removed: after validation `send` types the text with every CR LF pair and every other CR as one LF and without its trailing CR and LF characters, and the exact match, the local-command list, `text_bytes` and the paste read that typed text, which holds no CR (the founder's rulings, 2026-10-07T15:21Z for a trailing LF, 2026-10-09 for a trailing CR and CRLF, 2026-10-09T16:51Z for a CR or a CR LF inside). An empty typed text is refused `not-delivered` / `empty-text` (exit 13), by the client before any frame and by the wrapper before the first wheel read.
- `MAX_FRAME` stays 16 MiB, checked against the ledger's measured largest hook payload.
- A driver's `release` is refused as an affordance guard, not enforcement (same-user processes are trusted in v1).
