# Observability Summary — viola

_Distilled from `.andromeda/obs-plan.md` by `/andromeda-setup-project`. wrap-session does not modify._

## Obs tier

**Tier:** Standard (1), with Minimal-tier exporter carve-outs

**Justification (one sentence):** five process roles, the instrumentable crates and six must-trace paths make it Standard-class, but upstream bans egress, new listeners, stdout on four of five roles and Tokio/C crates in the sync graph — so there is no exporter and no reporter, only local JSON files.

## Harness contract (§3)

The obs harness is **bound** to the test harness: tests owns the grepped fields and the `logs` wrapper; obs may add fields, never rename them or remove one the product still emits. See `.claude/rules/observability.md` and `.claude/rules/verification-harness.md`.

- **Logger / library:** tracing facade + tracing-subscriber 0.3.23 `fmt().json().flatten_event(true).with_current_span(false)` (+ `with_span_list(false)`, `with_ansi(false)`, `log_internal_errors(false)`, `MillisUtc`, explicit writer)
- **OTel SDK:** none in v1 (opentelemetry 0.33 / tracing-opentelemetry 0.34 deferred; any future Resource uses `builder_empty()`)
- **Log sink path:** codes-only role files `<home>/diagnostics/{run-<name>,hook-<name>,mcp,cli-<name>,console}.ndjson` (`console` home-level, its lines with no instance key) (`mcp` always writes `mcp.ndjson`, its home and `diagnostics/` checked by strict-modes before the sink opens; no stderr fallback: a file that cannot be opened exits 1 printing nothing); every role or detail file opens only past `check_diagnostics` on the existing `diagnostics/` folder and the file (a symlink, or a folder or file another user may read, is refused as a failed open: the role writer a sink, the detail line dropped); content-bearing detail `<home>/instances/<name>/diagnostics/detail-<process>.ndjson`; 0600 in 0700
- **Log format:** JSON Lines — required `timestamp` (RFC 3339 ms Z), `level`, `target`, `message` (= event name), `event` (closed kebab enum), `corr`, `process` (`run|hook|mcp|cli|console`), `instance` (absent on `console` lines); null = key absence
- **Heartbeat:** the `heartbeat` file touched every 1 s (not logged per tick); no process logs a liveness transition (flip at > 5 s, read by `list`); short-lived readers (`list`) expose `liveness` in `--json`
- **Integrity check:** schema conformance gate G4 against `schemas/diag-line.v1.json` / `diag-detail.v1.json`
- **Status endpoint:** `agent-run status` (tests-owned) over `viola list --json`: the aggregate health snapshot, `state` and `last_error` closed enum
- **Consumption:** `scripts/agent-run.sh logs` (via `viola-harness`) merges `events.ndjson`, role files and detail files, filterable, torn lines marked

## Service identity tagging

- `service.name="viola"` (`viola_core::SERVICE_NAME`, compile-time) → `service_name` on `process-start`
- `service.version=env!("CARGO_PKG_VERSION")` (`viola_core::VERSION`) — same value as `sender` and `writer`
- `deployment.environment` N/A (local-only); `os` (`linux`, from `std::env::consts::OS`, the schema's one word) + `pid` on `process-start`; never read from env vars

## Event vocabulary (closed)

`channel-request` · `channel-response` (corr = JSON-RPC id; `detail` only on a `-32602`, on both sides: `unsupported-version|invalid-params|release-from-driver`, closed by `schemas/diag-line.v1.json`; a refusal's own `detail` stays on `send-refused`, and the word `release-from-driver` here does not replace the event) · `dialog-raised` · `dialog-answered` (corr = dialog_id) · `hook-invoked` · `hook-decision` · `send-issued` · `send-confirmed` · `send-refused` (corr = send cursor; wrapper lines add `conn` + `rpc_id`) · `release-from-driver` · `process-start` · `process-exit` · `panic` · `state-recovered` · `parse-rejected` · `console-frame` (once per draw: required `cols`, `rows`, `fits`; an unread size logs 0x0, not fitting) · `console-key` (once per key read: required `key`, one of `quit|interrupt|unbound`; the key's bytes never reach a line) · `trust-record` (one INFO line per wrapped `viola run` / `viola revive` / `viola adopt` start on a verified CLI, in the run role file, its required `detail` one of 16 closed start words, no path, project key or config value; it never refuses the start). 

## PII scrubbing wire

- `#[instrument(skip_all, fields(..))]` everywhere (gate G1); no `err` / `ret`
- Default-deny: only fields in the obs-plan §6 catalog; veil `#[derive(Redact)]` on every payload type that carries content (`toggle` banned); a payload type with no content field derives neither `Redact` nor `Debug`
- Content-bearing records only in instance detail files; boundary-only logging — never in the PTY pump loop; the session id an operator types to `viola adopt` never appears in any log line, field pair or detail
- Merged phase with security's `logging-redaction-wire`
- The local `viola-harness pre-push` document is never uploaded and carries no absolute path, only codes and counts — the native in-place Linux gate prints neither the repository root nor the passwd home (obs-plan §8 item 5)
- `mutants.out/` is never uploaded; it stays at the repository root (gitignored); on the Linux dev host a directory named `viola-mutants-scratch/` is only the operator's NOCOW `TMPDIR`, printed by no document either. `target/run-archive/<n>/` (each run's JUnit and the `outcomes.json` it read) is never uploaded either — gitignored, outside every upload path (obs-plan §8 item 5); the mutation run's `chunk.diff` at the harness capture root is excluded from the harness upload, so it is never scanned and never uploaded

## Universal anti-patterns

- NEVER write telemetry to stdout, or use print/`dbg!` macros in the hook, run or mcp code paths of the product crates (clippy `print_stdout`/`print_stderr`/`dbg_macro` = deny; exempt: viola-harness, the fake agent and the output modules that own `--json`, human CLI stderr and the hook decision body).
- NEVER call raw `tracing::*!` outside `viola_core::obs` — only `obs_event!`.
- NEVER read the level from `RUST_LOG` / `EnvFilter`; `diagnostics_level` changes volume, never redaction.
- NEVER use tracing-appender `non_blocking`, sentry, an OTLP exporter or a `/metrics` route.
- NEVER log per heartbeat tick; NEVER log a peer the wrapper's `accept_loop` refuses by euid (Unix: dropped on the accept thread, before any frame, the client reading end-of-file); NEVER put a path or pid inside a `detail` code; NEVER write a start's parent or role name into a process-log or detail line (they appear only in `events.ndjson`, the snapshot, the `viola list` board, `list --json` and the MCP `list` result); NEVER copy the window line `{address, workspace, placement, origin}` a start under `--origin` writes into `events.ndjson` after its launch line, and a switch writes again after its own launch line, into a process-log line — it is log-only audit data, waking no wait and opening no span.
