## Installation
- `rustup toolchain install` — installs the toolchain pinned in `rust-toolchain.toml` (1.98.1, components rustfmt + clippy)
- `cargo install --locked cargo-nextest cargo-llvm-cov@0.9.1 cargo-mutants cargo-deny@0.20.2` — test / coverage / mutation / policy tools, each at the version `.github/workflows/ci.yml` pins (CI uses taiki-e/install-action, SHA-pinned)
- `cargo install --locked hyperfine cargo-modules zizmor@1.30.1` (hyperfine and cargo-modules at the versions `.github/workflows/ci.yml` pins) — perf gate, orphans gate + on-demand boundary review, workflow lint (CI installs cargo-modules this way in `lint`: taiki-e has no manifest for it)
- `bash scripts/install-ripgrep.sh`: ripgrep 15.2.0 (PCRE2, sha256-verified) into `target/tools/ripgrep/bin` for G1/G3.
- `jq` for G2, `scripts/release-check.sh` and `scripts/orphans-check.sh`: runner-provided in CI, never installed there (the `test` and `perf` jobs presence-check it; the scripts, `scripts/g2-zero-panics.sh` included, refuse with `tool-missing: jq`). jaq 3.1.1 takes the same filters locally.
- `cargo install --path .` — install `viola` from the repo root; then, optional and only for the MCP verbs in an unwrapped driver, `viola plugin install [--json]` — writes only the local marketplace `viola` under `<home>/marketplace/` (plugin `viola@viola`, its `.mcp.json` registering the MCP server `viola` as the absolute exe path with `["--home", <home>, "mcp"]`, no hooks) and spawns no `claude`; exit 0 with its result (`--json` `{"v":1,"ok":{"marketplace":"viola","plugin":"viola@viola"}}`, no path), 21 when its strict-modes check refuses the home or any existing `marketplace/` tree dir (nothing created, no log opened; under `--json` the `{"v":1,"error":"instance-unreachable","detail":"strict-modes-failed"}` document), 1 for an internal error (under `--json` the `{"v":1,"error":"internal-error","detail":null}` document on stdout, stderr empty), 2 for a clap usage error (`viola plugin` alone)
- `pip install -r scripts/requirements.txt` — code-graph Python deps (duckdb + protobuf)
- `rustup component add rust-analyzer` — the Rust SCIP indexer for the code-graph (already on PATH on the founder's host)
- no TypeScript indexer: the tree tracks no `tsconfig.json`, so `scripts/code-graph.py` detects no ts plane

## Development
- `viola run <name> -- claude [args]` — wrap a live session (Linux only; first live on the Linux dev host); with `config.json` `verify_new_cli` on (off by default), the start, and a revive's, meeting a claude version with no attempted stamps entry runs `viola verify` once as a child after the endpoint bind and gates on its final verdict; on a verified verdict it writes the trust record of an untrusted spawn folder into the Claude config before spawning the child
- The automatic verify, for a person: turn it on by setting `"verify_new_cli": true` in the viola home's `config.json` (`"v": 1`; any other value reads false); it stays off until then. What one spends: one `viola verify` run of the start's resolved `claude` — its print-mode probe on Haiku, its interactive PTY runs (their turns on the account's default model), its `claude agents --json` read and its print-mode sender `verify-sender` inside Run B's cross-session turn, as the `viola verify` bullet below lists — once per claude version (or per newer relied row set), before the session starts; keys typed meanwhile wait in the terminal's buffer, and Ctrl-C or TERM stops the start with no stamp and no session. A red one leaves its version's entry in `ledger/stamps.json` holding the failing rows: the start goes on unverified, and later starts print the earlier-red line and run no verify. It is cleared only by a hand-run `viola verify`, a viola build whose relied row set grows, or a newer claude version. A verify that cannot start, or is stopped, writes nothing and is no attempt; a start that finds another start verifying runs none and starts unverified.
- `viola run <name> --home <dir> -- <fake agent> <args>` — wrap the fake agent in an isolated home
- `viola revive <name> [--id <ID>] [--fork] [-- <child args>]` — restart a dead instance in this terminal, resuming its newest logged session in the recorded directory (refused `session-live`, exit 1, when one `claude agents --json` read lists that session live in another `claude`; `--fork` skips the reading and a failed read passes); `viola revive <name> --list` prints its logged sessions; both arms take `[--json]`: a refused strict-modes check, a preflight refusal or a refusal of the start it shares with `run` prints the exit-1 `{"v":1,"error":"<code>","detail":null}` document on stdout, stderr empty (`strict-modes-failed` · `already-live` · `no-session` · `session-live` · `cwd-missing` · `stale-heartbeat` · `pinned-hash-mismatch` · `squatted-name` · `socket-dir-refused` · `internal-error`), `--list --json` prints `{"v":1,"ok":{"sessions":[…]}}` in log order (an empty chain the `no-session` document), and a `pump_child` error prints no document: the child has held the terminal
- no `viola ui` subcommand: viola has no web or graphical frontend; its view beyond `viola list` is the keyboard-driven terminal fleet console tiled on Hyprland (matrix#v2-14), owed by the 0.2.0 Epoch 6 route entries «Console scaffold», «Fleet console view» and «Console actions». `viola mcp [--home <dir>]` — the stdio MCP server (tools `send · wait · last · answer · list`), hidden from `viola --help` and run by the plugin, never by a person: no argument but the global `--home`, it serves until stdin closes or a stdin line passes `MAX_FRAME` (refused whole, never truncated or skipped, with one `parse-rejected{parser:"mcp-stdin", detail:"oversize", count:1}` line holding no byte of it), which ends the session as a close does (exit 0 once initialized, 1 before `initialize`, both streams empty), and exits 1 with nothing on stdout or stderr and no role file when its home or `diagnostics/` fails `viola_state::strict::check_path` (that exit does not block the CLI's start: the session reaches `idle` and the CLI logs the server's connection as failed, measured on claude 2.1.287 on the Linux dev host)
- `viola verify [--record <dir>] [-- <program> [args…]]` — drive one print-mode probe (Haiku) and six interactive PTY runs (Run A untrusted in an OS-temp dir, Run B trusted in `<cwd>/.viola-verify-<pid>/` with compiled pastes (the probe prompt, a long text, a tag-like text, a text holding one inner LF, `/compact`, `/clear`, then `/mcp disable viola-probe-absent`, the local-command-echo row's probe, skipped with that row failed when no transcript is readable, then `/context`, the local-command-context row's probe, a failing read of it `fail`, never `absent`) and one `claude agents --json` read once its first turn has settled, before the added pastes (held in memory, spawn pair `agents-probe`, no start added; in CI the fake agent's `agents` mode answers it) and one print-mode sender, `verify-sender`, inside Run B's cross-session turn (Run B started with the crossSessionInbound accept settings, the sender addressing it by `uds:<runtime>/cc-socks/<pid>.sock`, never a bare session id; the cross-session-prefix row passes only when the message arrives opening with the CLI's cross-session harness prefix, else fails; no runtime dir runs no turn), Run C's dialogs in `-dialogs/` (among them a compiled prompt raising a question through PermissionRequest, answered by the closed probe id `permission-question-first-option`: the permission-request-question row passes only when that request is raised and the answer reaches the tool's answers), Run D's plan in `-plan/`, then Run E in `-resume/` resuming Run B's first session with `--resume <id>` (input empty, no `--settings`), then Run F in an untrusted temp folder whose trust record verify writes into the Claude config file its child reads (never creating an absent file; a run or revive start writes a record only for its own untrusted spawn folder, on a verified CLI), passing the trust-record row only when the record was written, Run A showed the trust modal and Run F's start shows no modal and the input box; no key into any dialog — the probe hook answers C and D's) against the CLI (default `claude`), check the relied ledger rows (`LedgerRow::relied()`, on every build), print `[NN/MM]` step lines ending `pass`, `absent` or `fail` (`absent` on the browser-tools-prompt row alone, when no run met the CLI's browser-tools prompt; `MM` the relied count; the last `[MM/MM] browser-tools-prompt …`) + the `stamped <ver>  <n> pass  <m> fail` summary on stdout (`<n>` counting every relied row that counts toward verified, an absent browser-tools-prompt among them) and write `ledger/stamps.json`; exit 1 on a failing row; exit 1 with the home-state `unable:` / `hint:` pair, no step line, no summary and no log line when `check_home_tree` refuses its home, `ledger/`, `bin/` or `plugin/` before its `cli` log opens (and the same pair, exit 1, after the step lines, when `update_stamps` refuses `ledger/stamps.json`, with `detail:"strict-modes-failed"` on its `process-exit` under a parsed `VIOLA_NAME`); a run stopped by Ctrl-C or TERM kills its child with no key, removes only the probe dirs it created and its own trust record from the Claude config file, writes no stamp, leaves stdout empty, prints `unable: verify was stopped before it finished` / `hint: run viola verify again to stamp this CLI` and exits 1 (SIGKILL, a crash or a failed handler install leaves the dirs to remove by hand; a SIGKILL also leaves verify's own one-key trust record in the Claude config file, to remove by hand). `--record <dir>` also writes the scrubbed `<dir>/<ver>/<Event>.default.json` fixtures, the `<Event>.<stem>-<n>.json` dialog variants, Run B's `paste-<n>` / `compact-<n>` / `clear-<n>` framing variants, Run E's first SessionStart as `SessionStart.resume-1.json`, Run B's agents read as `Agents.recorded-1.json` (Run B's own row only), the env-names fixture `Env.recorded-1.json` (names only, never a value: `v` 1 plus `added`) and signature-only `Screen.<phase>.json` screens (a footer or modal row whole, the input box's rule row as its rule chars alone and its prompt row as the prompt char alone, every other row empty; a box whose live prompt row holds a home path, the username or an email refuses the recording) when 0 rows fail; an unclean recording is refused naming the file and check code. A hidden `--record-first-screens`, absent from `--help` and passed only by the live rig, makes a failed `--record` verify write a first-screen file of whole scrubbed rows per run short of the input box (Run A's trust excepted), refused whole when unclean, kept locally and never committed. Run it from a folder you trust in Claude Code whose external CLAUDE.md import is answered. Against the real CLI: local only, spends tokens; CI runs it only against the fake agent's `-p/--print` mode and its `--screens --turn-stop --trusted-root --dialogs --framing --transcript --trust-config` interactive modes, under a test-owned user home whose config file is seeded empty and owner-only and named to the fake agent by `--trust-config`, with a short owner-only runtime dir (`XDG_RUNTIME_DIR`) the test owns for the stamp's life (every stamping verify passes `--transcript` beside `--framing`, or Run B's echo probe is skipped and the local-command-echo row fails). The `Mcp.<variant>.json` MCP exchanges are recorded not by `--record` but by the test-only `viola-mcp-tap` (`record` / `fixture`, the same scrub and closed refusal codes; architecture §Occupied Resources → Binary); the recorded Hyprland replies likewise by the test-only `viola-hypr-tap`, under the same scrub
- Stamps file: `ledger/stamps.json` in the Ledger stamps envelope `{"v":1,"written_at","writer":"verify","data":{"versions":{"<ver>":{"verified_at","rows":{…},"measured":{…}}}}}` (arch §Standard Contracts; `measured.env_probe` holds the identity-floor probe's `read`, `added`, `unknown`, `other_count` and `unshaped`, names only, every kept name removed; `measured.cross_session_probe` holds the cross-session probe's `outcome`, `prefix`, `latency_ms`, `sender_tools` and `send_result`, closed words and one number); a version is verified only when its stamp holds every relied row (`LedgerRow::relied()`, on every build) `pass`, or `absent` on `browser-tools-prompt` alone: a seventeen-row stamp written before chunk 2026-10-13-paste-newline-ledger-row reads unverified (`cli_verified:false`) until the next `viola verify`, and so does an eighteen-row stamp written before chunk 2026-10-13-owed-ledger-rows, a twenty-one-row stamp written before chunk 2026-10-14-resume-and-compact-ledger-rows, a twenty-two-row stamp written before chunk 2026-10-16-unwrapped-sessions-on-the-board , a twenty-three-row stamp written before chunk 2026-10-18-compact-post-condition-ledger-row or a twenty-two-row stamp written before chunk 2026-11-17-trust-record-ledger-row; a stamp's `rows` maps each row id to `pass` or `fail`, browser-tools-prompt may also read `absent`, and trust-record holds the trust writer's code word instead when no record was written

## Harness (the agent's 5 commands — `scripts/agent-run.sh`)
- `boot [--session <id>] [--instance <name>[:<args>]]... [--unstamped] [--cli-version <ver>] [--agents-mode recorded|oversize|malformed]` — build, create a home, stamp via `viola verify` against the fake agent (with a short owner-only runtime dir the harness owns for the stamp's life), start wrappers (a stamped session's under a session user home seeded with an empty config), wait for readiness (`--agents-mode` (default `recorded`, an unknown value usage `arguments`) writes the fake agent's `agents-mode` file (0600) beside the session's `bin/claude` copy after the stamp and before `supervise.json`, setting no env var, and is recorded as `agents_mode` in `session.json` and `supervise.json`)
- `run [--unit|--integration|--e2e|--mutants|--coverage|--perf|--fuzz-replay|--all] [--filter <nextest-filterset>] [--file <path>]... [--package <member>] [--local-live]` — invoke suites; one JSON summary. No selector (and no `--local-live`) or `--all` runs unit + integration, then the fake-agent E2E (steps 1 and 2); `--mutants` runs only when named (the epoch-boundary audit's arm)
- `status [--session <id>]` — `viola list --json`
- `cleanup [--session <id>|--all]` — graceful stop, process and endpoint checks, home removal (idempotent)
- `logs [--session <id>] [--instance <name>] [--kind <kind>] [--process run|hook|mcp|cli] [--after <offset>]` — merged ndjson of events + diagnostics
- Internal (forwarded by the shim, not agent-facing): `supervise`, `gate --require <suites> [--artifacts <dir>]` (the per-job verdict; a missing artifact is a breach), `pre-push` (Linux host only, else exit 2 `pre-push-linux-only`: the operator pass's local Linux gate — natively in the working tree, no clone; every child `/usr/bin/env -i HOME=<passwd home> PATH=<home>/.cargo/bin:/usr/local/bin:/usr/bin:/bin`; checks the tools at their pins, then runs `run --coverage` and `gate --require coverage,doctest`; stages `host · tools · linux-tests`, fail-fast, no mutation stage)
- Built today (the grammar grows per chunk; anything else is exit 2 `reason:"usage"`): `boot [--session] [--instance <name>[:<args>]]... [--unstamped] [--cli-version] [--agents-mode recorded|oversize|malformed]` · `run [--unit|--integration|--e2e|--mutants|--coverage|--perf|--fuzz-replay|--all] [--filter] [--file <path>]... [--package <member>] [--local-live]` (`--local-live`: after the selected suites, one `viola verify` against the real `claude` as suite `local-live`; under `CI` exit 2 `live-in-ci`) (`--package` needs `--mutants`: one whole member, `verdict:"package"`, anything but `viola` or a `crates/<member>` declaring `fake-agent` is exit 2 `package-refused`; `--perf` runs only when named, never under `--all`: a missing hyperfine is `reason:"tool-missing"`, `detail:"hyperfine"`; `--fuzz-replay` is Linux-only: exit 2 `fuzz-linux-only` elsewhere; `--mutants` runs only when named, never under `--all`; the run document gains `archived` = `target/run-archive/<n>`, the newest 10 kept) · `status [--session]` · `cleanup [--session|--all]` · `logs [--session] [--instance] [--kind] [--process] [--after]` · internal `supervise`, `schema-check`, `secret-scan`, `gate`, `pre-push`. ## Testing
- `cargo nextest run --workspace --features fake-agent --profile ci -E 'kind(lib) | kind(bin)'` — unit
- `cargo nextest run --workspace --features fake-agent --profile ci -E 'kind(test) & !binary(/^(path[0-9]*|tui|mcp|cross|chaos|contract)_/)'` — integration (the complement of the E2E layer, so a test binary reports in exactly one; nextest rejects an unmatched `binary()` regex, and the root `chaos_`, `contract_`, `cross_`, `tui_` and `path<N>_` binaries match it). The harness runs these with `CARGO_TARGET_DIR=target/harness` and `--features viola/fake-agent`.
- `cargo nextest run --workspace --features fake-agent --profile ci -E 'binary(/^(path[0-9]*|tui|mcp|cross|chaos|contract)_/)'` — fake-agent E2E (`run --e2e`, suite `nextest-e2e`, run third after unit and integration in the default and `--all`; `[0-9]*` admits the numbered Path binaries `path1_run_start` and `path6_budget_harness`; `run --e2e` alone runs no doctest)
- `cargo test --workspace --doc` — doctests (nextest cannot run them); otherwise nextest is the runner: a plain `cargo test` run (`cargo test --bin viola`) is not supported, and under it root-bin cases are known-cause reds (test-plan §2 Runner)
- `cargo llvm-cov nextest --workspace --features viola/fake-agent --profile ci --lcov --output-path target/lcov.info --ignore-filename-regex '(viola-fake-agent|crates[/\\]viola-e2e|tests[/\\]support|fuzz[/\\])' --fail-under-lines 85 --fail-under-functions 95 --fail-under-regions 80` — coverage gate (`run --coverage`; the separator class is kept from the retired Windows target, where llvm-cov reported paths with `\`; JUnit stays at `target/nextest/ci/junit.xml`), then `cargo llvm-cov report --json --summary-only` → `artifacts/llvm-cov-summary.json`
- `cargo build --package viola --features fake-agent` then `NEXTEST_PROFILE=mutants cargo mutants --workspace --features fake-agent --in-diff target/agent-run/chunk.diff --test-tool=nextest --copy-target=true --caught --unviable --build-timeout=400` — `run --mutants` (the epoch-boundary audit's arm, never a chunk or CI gate), both steps with the run's own target dir `target/mutants` (`CARGO_TARGET_DIR=<repo>/target/mutants` for the prebuild, the relative `target/mutants` for cargo-mutants, so each copied tree builds its own test binaries) (the prebuild + copied target dir give the scratch tree the root bins the harness tests spawn; cargo-mutants' output streams live to the harness's stderr, one line per mutant outcome, and each mutant's build is bounded) (diff = working tree + untracked files from `merge-base(<base>, HEAD)`; base = `AGENT_RUN_CHUNK_BASE` when set, else derived: the last master flip before the pending chunk's oldest operator pre-CI commit, `HEAD^` on the wrap push — but the flip itself while a promoted chunk is still uncommitted on top of it; the run document names it as `base`). A diff with no `.rs` path skips cargo-mutants and reports `"verdict":"no-rust-delta"`; one whose `.rs` paths are all test targets (`tests/`, `benches/`, `examples/`) skips it too and reports `"verdict":"test-only-rust-delta"`; any other Rust delta deletes a stale `mutants.out/outcomes.json` first and reports `"verdict":"counted"`. The run keeps the inherited temp dir and writes `mutants.out/` at the repository root; it has no scratch arm
- `bash scripts/agent-run.sh run --mutants --file <path>` (repeatable) — one file's mutants: the scoped inner loop (`verdict:"scoped"`, survivors red)
- `TMPDIR=<repo parent>/viola-mutants-scratch bash scripts/agent-run.sh run --mutants --package <member> [--file <path>]...` — one whole member's mutants, the boundary tier's form (`verdict:"package"`): the same prebuild, then `cargo mutants --package <member> --features fake-agent --test-tool=nextest --copy-target=true …`, no base or diff. On the Linux dev host the `TMPDIR` dir must be NOCOW (`chattr +C`): `/tmp` is a 32 GB quota tmpfs too small for the ~14 GB `target/` copy, and a COW btrfs reflink copy drops the copied `viola-fake-agent`'s exec bit (test-plan §10)
- no Windows leg in the boundary audit: `windows-mutants.yml` left with the Windows code, recoverable at the tag `multi-os-final`
- `cargo +<channel> fuzz run --fuzz-dir fuzz <target> fuzz/corpus/<target> -- -runs=0` — corpus replay (`run --fuzz-replay`, Linux; channel from `fuzz/rust-toolchain.toml`; `fuzz/` is its own cargo workspace)

## Linting & Formatting
- `cargo fmt --all` / `cargo fmt --all --check` — format / format gate (edition from `rustfmt.toml`)
- `cargo clippy --workspace --all-targets --features fake-agent -- -D warnings`: the lint gate. `print_stdout`, `print_stderr` and `dbg_macro` are denied in every product member (`viola-e2e` opts out and denies only `dbg_macro`), and `clippy.toml` `disallowed-macros` bans the tracing level macros. No Windows- or macOS-target clippy stands: the tree holds no Windows or macOS code.
- `bash scripts/lint-probes.sh`: proves every clippy ban fires and every control passes, plus the fail-closed raw-`event!` grep (its last line counts the bans fired and the controls clean; CI runs it on the Linux lint leg).

- `bash scripts/rmcp-features.sh` — the rmcp release-graph assertion (CI lint step `rmcp features (exactly server + transport-io, non-vacuous)`, on `ubuntu-latest`, after `Lint probes`): runs `cargo tree -e features -p viola --edges normal --target all -i rmcp --no-dedupe --prefix depth`; rmcp must be present and the features a non-rmcp package requests exactly `server transport-io` (last line `rmcp-features: server transport-io`)
- `cargo deny check` — advisories, licences, sources, bans over `deny.toml`, the root `Cargo.lock` (weekly in `nightly.yml`: `cargo deny check advisories`)
- `cargo deny --manifest-path fuzz/Cargo.toml check advisories sources` — the separate `fuzz/Cargo.lock` audit (CI `supply-chain` with `--format json` into `target/supply-chain/deny-fuzz.json`; weekly `check advisories` in `nightly.yml`). Run it from the repo root: under `fuzz/` rustup demands the fuzz nightly. `fuzz/` stays outside the root graph by a ratified test-only exemption
- `cargo deny --config deny-sync.toml --manifest-path crates/<crate>/Cargo.toml check bans` — the tokio ban, once per crate in `scripts/sync-crates.txt` as sole root (cargo-deny 0.20: `--config` goes before the subcommand; `check -c` is rejected); then, in the same CI step `Tokio ban per sync crate (sole root)`, `bash scripts/channel-tokio-free.sh`: `viola-channel` (off the list since chunk 2026-10-17-mcp-server-for-drivers, its Tokio client behind its `tokio` feature) must print no `tokio v` line from `cargo tree -p viola-channel -e normal --target all -i tokio --prefix none`, its `--features tokio` control must print one (verdict `channel-tokio-free: ok`)
- `bash scripts/profraw-census.sh <runs> <workers> [<name>]` — the dev-host witness for a corrupt coverage profile: the root bin's start test N times on the newest instrumented test binary, each run's profiles counted under `target/profraw-census/` (last line `profraw-census: runs N · passed N · profiles P · third K · short S`; exit 0 only when every run passed, P equals N and K and S are 0; needs the instrumented binary a `pre-push` coverage run leaves; `4800 48` loads 48 workers for about 2.5 minutes; no CI job, `pre-push` stage or harness command runs either form). Its second form, `bash scripts/profraw-census.sh --case <binary stem> <test name> <runs> <workers> [<name>]`, runs one integration case of the same instrumented build the same way, offers each profile alone to `llvm-profdata merge` and keeps a refused one under `refused/` (last line `profraw-census: runs N · passed N · profiles P · refused R`; exit 0 only when every run passed and R is 0; exit 2 with no instrumented binary or no `llvm-profdata`)
- `bash scripts/deny-probes.sh` — proves every ban fires (its last line counts every probe banned and the control clean: each ban one probe (the serde_json `unbounded_depth` ban's row `serde_json-unbounded-depth` among them), plus probe `channel-tokio-edge` for the `channel-tokio-free.sh` tree form with its channel control; needs the network)

## Troubleshooting
- `cargo clean` — clean build artifacts (also removes `target/e2e-home/` and `target/agent-run/`; on the Linux dev host `target/e2e-home` is a link to the tmpfs backing, so re-make it afterwards with `ln -s /tmp/viola-e2e-home-<uid> target/e2e-home`, or the next start puts a plain directory back on the shared volume with no signal; a start through the link is refused with `e2e-home backing: {free} MiB free, below the {floor} MiB floor` when its filesystem reads less than the 9 GiB headroom floor free, a compiled floor set by no variable, flag or config key)
- `scripts/agent-run.sh cleanup --all` — tear down every harness session
- `scripts/agent-run.sh logs --instance <name> | jq -c 'select(.record.level=="ERROR")'` — errors for one instance
