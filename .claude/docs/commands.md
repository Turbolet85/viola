## Installation
- `rustup toolchain install` — installs the toolchain pinned in `rust-toolchain.toml` (1.98.1, components rustfmt + clippy)
- `cargo install --locked cargo-nextest@0.9.146 cargo-llvm-cov@0.9.1 cargo-mutants@27.1.0 cargo-deny@0.20.2` — test / coverage / mutation / policy tools (CI uses taiki-e/install-action, SHA-pinned)
- `cargo install --locked hyperfine@1.20.0 cargo-modules@0.27.0 zizmor@1.30.1` — perf gate, orphans gate + on-demand boundary review, workflow lint (CI installs cargo-modules this way in `lint`: taiki-e has no manifest for it)
- `bash scripts/install-ripgrep.sh`: ripgrep 15.2.0 (PCRE2, sha256-verified) into `target/tools/ripgrep/bin` for G1/G3.
- `jq` for G2, `scripts/release-check.sh` and `scripts/orphans-check.sh`: runner-provided in CI, never installed there (the `test` and `perf` jobs presence-check it; the scripts, `scripts/g2-zero-panics.sh` included, refuse with `tool-missing: jq`). jaq 3.1.1 takes the same filters locally.
- `cargo install --path .` — install `viola` from the repo root; then, optional and only for the MCP verbs in an unwrapped driver, `viola plugin install [--json]` — writes only the local marketplace `viola` under `<home>/marketplace/` (plugin `viola@viola`, its `.mcp.json` registering the MCP server `viola` as the absolute exe path with `["--home", <home>, "mcp"]`, no hooks) and spawns no `claude`; exit 0 with its result (`--json` `{"v":1,"ok":{"marketplace":"viola","plugin":"viola@viola"}}`, no path), 21 when its strict-modes check refuses the home or any existing `marketplace/` tree dir (nothing created, no log opened; under `--json` the `{"v":1,"error":"instance-unreachable","detail":null}` document), 1 for an internal error, 2 for a clap usage error (`viola plugin` alone)
- `pip install -r scripts/requirements.txt` — code-graph Python deps (duckdb + protobuf)
- `rustup component add rust-analyzer` — the Rust SCIP indexer for the code-graph (already on PATH on the founder's host)
- no TypeScript indexer in 0.1.0: the ts plane has no input (its one input, the tracked `e2e-web/tsconfig.json`, left with the browser leg), so `scripts/code-graph.py` detects no ts plane

## Development
- `viola run <name> -- claude [args]` — wrap a live session (Windows the first target; first live on the Linux dev host)
- `viola run <name> --home <dir> -- <fake agent> <args>` — wrap the fake agent in an isolated home
- `viola revive <name> [--id <ID>] [--fork] [-- <child args>]` — restart a dead instance in this terminal, resuming its newest logged session in the recorded directory (refused `session-live`, exit 1, when one `claude agents --json` read lists that session live in another `claude`; `--fork` skips the reading and a failed read passes); `viola revive <name> --list` prints its logged sessions; both arms take `[--json]`: a refused strict-modes check or a preflight refusal prints the exit-1 `{"v":1,"error":"<code>","detail":null}` document on stdout, stderr empty (`strict-modes-failed` · `already-live` · `no-session` · `session-live` · `cwd-missing`), `--list --json` prints `{"v":1,"ok":{"sessions":[…]}}` in log order (an empty chain the `no-session` document), and a refusal `run`'s start makes after a passed preflight prints no document
- no `viola ui` subcommand: the frontend is deferred to 0.2.0; its technology is not chosen. `viola mcp [--home <dir>]` — the stdio MCP server (tools `send · wait · last · answer · list`), hidden from `viola --help` and run by the plugin, never by a person: no argument but the global `--home`, it serves until stdin closes, and exits 1 with nothing on stdout or stderr and no role file when its home or `diagnostics/` fails `viola_state::strict::check_path` (that exit does not block the CLI's start: the session reaches `idle` and the CLI logs the server's connection as failed, measured on claude 2.1.287 on the Linux dev host; its Windows leg owed to "Windows-only live measurements")
- `viola verify [--record <dir>] [-- <program> [args…]]` — drive one print-mode probe (Haiku) and five interactive PTY runs (Run A untrusted in an OS-temp dir, Run B trusted in `<cwd>/.viola-verify-<pid>/` (on Unix, for shell-plain paths, also one probe `--settings <probe dir>/typed/statusline.json` whose status line the hidden `hook statusline --capture` arm files; none on Windows) with six compiled pastes (the probe prompt, a long text, a tag-like text, a 113-byte text holding one inner LF, `/compact`, `/clear`) and one `claude agents --json` read once its first turn has settled, before the five added pastes (held in memory, spawn pair `agents-probe`, no start added; in CI the fake agent's `agents` mode answers it), Run C's dialogs in `-dialogs/`, Run D's plan in `-plan/`, then Run E in `-resume/` resuming Run B's first session with `--resume <id>` (input empty, no `--settings`); no key into any dialog — the probe hook answers C and D's) against the CLI (default `claude`), check the relied ledger rows (`LedgerRow::relied()`: all twenty-four on Unix; twenty-one on Windows, the first eighteen, `resume-session`, `agents-join` and `local-command-compact`), print `[NN/MM]` step lines (`MM` the relied count; the last `[24/24] local-command-compact …` on Unix, `[21/21] local-command-compact …` on Windows) + the `stamped <ver>  <n> pass  <m> fail` summary on stdout and write `ledger/stamps.json`; exit 1 on a failing row; a run stopped by Ctrl-C or TERM kills its child with no key, removes only the probe dirs it created, writes no stamp, leaves stdout empty, prints `unable: verify was stopped before it finished` / `hint: run viola verify again to stamp this CLI` and exits 1 (SIGKILL, a crash or a Windows close leaves the dirs to remove by hand). `--record <dir>` also writes the scrubbed `<dir>/<ver>/<Event>.default.json` fixtures, the `<Event>.<stem>-<n>.json` dialog variants, Run B's `paste-<n>` / `compact-<n>` / `clear-<n>` framing variants, Run B's status line variants `StatusLine.default-1.json` / `StatusLine.rate-limits-1.json`, Run E's first SessionStart as `SessionStart.resume-1.json`, Run B's agents read as `Agents.recorded-1.json` (Run B's own row only) and signature-only `Screen.<phase>.json` screens when 0 rows fail; an unclean recording is refused naming the file and check code. Run it from a folder you trust in Claude Code whose external CLAUDE.md import is answered. Against the real CLI: local only, spends tokens; CI runs it only against the fake agent's `-p/--print` mode and its `--screens --turn-stop --trusted-root --dialogs --framing` interactive modes
- Stamps file: `ledger/stamps.json` in the Ledger stamps envelope `{"v":1,"written_at","writer":"verify","data":{"versions":{"<ver>":{"verified_at","rows":{…},"measured":{…}}}}}` (arch §Standard Contracts); a version is verified only when its stamp holds every relied row (`LedgerRow::relied()`: all twenty-four on Unix; twenty-one on Windows, the first eighteen, `resume-session`, `agents-join` and `local-command-compact`) `pass`: a seventeen-row stamp written before chunk 2026-10-13-paste-newline-ledger-row reads unverified (`cli_verified:false`) until the next `viola verify`, and so on every OS does an eighteen-row stamp written before chunk 2026-10-13-owed-ledger-rows, a twenty-one-row stamp written before chunk 2026-10-14-resume-and-compact-ledger-rows, a twenty-two-row stamp written before chunk 2026-10-16-unwrapped-sessions-on-the-board or a twenty-three-row stamp written before chunk 2026-10-18-compact-post-condition-ledger-row (and so, on Windows, do a stamp of the eighteen and `resume-session` and one of the eighteen, `resume-session` and `agents-join`; one of the eighteen, `resume-session`, `agents-join` and `local-command-compact` reads verified on Windows only)

## Harness (the agent's 5 commands — `scripts/agent-run.sh` / `scripts/agent-run.ps1`)
- `boot [--session <id>] [--instance <name>[:<args>]]... [--unstamped] [--cli-version <ver>] [--agents-mode recorded|oversize|malformed] [--statusline-echo]` — build, create a home, stamp via `viola verify` against the fake agent, start wrappers, wait for readiness (both built: `--statusline-echo`, which conflicts with `--unstamped`, runs after the stamp and before the wrappers start, writing `<home>/statusline-source.json` (0600) whose command is `<bin dir>/viola-fake-agent[.exe] statusline-echo <home>/fake/statusline.marker`, for Path 6; `--agents-mode` (default `recorded`, an unknown value usage `arguments`) writes the fake agent's `agents-mode` file (0600) beside the session's `bin/claude[.exe]` copy after the stamp and before `supervise.json`, setting no env var, and is recorded as `agents_mode` in `session.json` and `supervise.json`)
- `run [--unit|--integration|--e2e|--mutants|--coverage|--perf|--fuzz-replay|--all] [--filter <nextest-filterset>] [--file <path>]... [--package <member>] [--local-live]` — invoke suites; one JSON summary. No selector (and no `--local-live`) or `--all` runs unit + integration, then the fake-agent E2E (steps 1 and 2); `--mutants` runs only when named (the epoch-boundary audit's arm)
- `status [--session <id>]` — `viola list --json`
- `cleanup [--session <id>|--all]` — graceful stop, process and endpoint checks, home removal (idempotent)
- `logs [--session <id>] [--instance <name>] [--kind <kind>] [--process run|hook|mcp|cli] [--after <offset>]` — merged ndjson of events + diagnostics
- Internal (forwarded by the shims, not agent-facing): `supervise`, `gate --require <suites> [--artifacts <dir>]` (the per-job verdict; a missing artifact is a breach), `pre-push` (Linux host only, else exit 2 `pre-push-linux-only`: the operator pass's local Linux gate — natively in the working tree, no clone; every child `/usr/bin/env -i HOME=<passwd home> PATH=<home>/.cargo/bin:/usr/local/bin:/usr/bin:/bin`; checks the tools at their pins, then runs `run --coverage` and `gate --require coverage,doctest`; stages `host · tools · linux-tests`, fail-fast, no mutation stage)
- Built today (the grammar grows per chunk; anything else is exit 2 `reason:"usage"`): `boot [--session] [--instance <name>[:<args>]]... [--unstamped] [--cli-version] [--agents-mode recorded|oversize|malformed] [--statusline-echo]` · `run [--unit|--integration|--e2e|--mutants|--coverage|--perf|--fuzz-replay|--all] [--filter] [--file <path>]... [--package <member>] [--local-live]` (`--local-live`: after the selected suites, one `viola verify` against the real `claude` as suite `local-live`; under `CI` exit 2 `live-in-ci`) (`--package` needs `--mutants`: one whole member, `verdict:"package"`, anything but `viola` or a `crates/<member>` declaring `fake-agent` is exit 2 `package-refused`; `--perf` runs only when named, never under `--all`: a missing hyperfine is `reason:"tool-missing"`, `detail:"hyperfine"`; `--fuzz-replay` is Linux-only: exit 2 `fuzz-linux-only` elsewhere; `--mutants` runs only when named, never under `--all`; the run document gains `archived` = `target/run-archive/<n>`, the newest 10 kept) · `status [--session]` · `cleanup [--session|--all]` · `logs [--session] [--instance] [--kind] [--process]` · internal `supervise`, `schema-check`, `secret-scan`, `gate`, `pre-push`. Interim fields: `status` → `list` the parsed `viola list --json` document (run from `supervise.json`'s bin dir; `null` when it exits 0 with no JSON object), `pid`/`uptime_ms` `null`, `instances[]` keeping the pid + start-time `alive`, `last_error` `list-exit-<code>` or `list-exit-none`; `cleanup` → `processes_gone`, `endpoint_gone`.

## Testing
- `cargo nextest run --workspace --features fake-agent --profile ci -E 'kind(lib) | kind(bin)'` — unit
- `cargo nextest run --workspace --features fake-agent --profile ci -E 'kind(test) & !binary(/^(path[0-9]*|tui|mcp|cross|chaos|contract)_/)'` — integration (the complement of the E2E layer, so a test binary reports in exactly one; nextest rejects an unmatched `binary()` regex, and the root `chaos_`, `contract_`, `cross_`, `tui_` and `path<N>_` binaries match it). The harness runs these with `CARGO_TARGET_DIR=target/harness` and `--features viola/fake-agent`.
- `cargo nextest run --workspace --features fake-agent --profile ci -E 'binary(/^(path[0-9]*|tui|mcp|cross|chaos|contract)_/)'` — fake-agent E2E (`run --e2e`, suite `nextest-e2e`, run third after unit and integration in the default and `--all`; `[0-9]*` admits the numbered Path binaries `path1_run_start` and `path6_budget_harness`; `run --e2e` alone runs no doctest)
- `cargo test --workspace --doc` — doctests (nextest cannot run them)
- `cargo llvm-cov nextest --workspace --features viola/fake-agent --profile ci --lcov --output-path target/lcov.info --ignore-filename-regex '(viola-fake-agent|crates[/\\]viola-e2e|tests[/\\]support|fuzz[/\\])' --fail-under-lines 85 --fail-under-functions 95 --fail-under-regions 80` — coverage gate (`run --coverage`; the separator class makes the regex match Windows paths; JUnit stays at `target/nextest/ci/junit.xml`), then `cargo llvm-cov report --json --summary-only` → `artifacts/llvm-cov-summary.json`
- `cargo build --package viola --features fake-agent` then `NEXTEST_PROFILE=mutants cargo mutants --workspace --features fake-agent --in-diff target/agent-run/chunk.diff --test-tool=nextest --copy-target=true --caught --unviable --build-timeout=400` — `run --mutants` (the epoch-boundary audit's arm, never a chunk or CI gate), both steps with the run's own target dir `target/mutants` (`CARGO_TARGET_DIR=<repo>/target/mutants` for the prebuild, the relative `target/mutants` for cargo-mutants, so each copied tree builds its own test binaries) (the prebuild + copied target dir give the scratch tree the root bins the harness tests spawn; cargo-mutants' output streams live to the harness's stderr, one line per mutant outcome, and each mutant's build is bounded) (diff = working tree + untracked files from `merge-base(<base>, HEAD)`; base = `AGENT_RUN_CHUNK_BASE` when set, else derived: the last master flip before the pending chunk's oldest operator pre-CI commit, `HEAD^` on the wrap push — but the flip itself while a promoted chunk is still uncommitted on top of it; the run document names it as `base`). A diff with no `.rs` path skips cargo-mutants and reports `"verdict":"no-rust-delta"`; one whose `.rs` paths are all test targets (`tests/`, `benches/`, `examples/`) skips it too and reports `"verdict":"test-only-rust-delta"`; any other Rust delta deletes a stale `mutants.out/outcomes.json` first and reports `"verdict":"counted"`. On a Windows host the command runs with `TMP`/`TEMP` and `--output` set to the host mutation scratch `<repo parent>/viola-mutants-scratch` (guarded: `scratch-refused`; wiped first: `scratch-wipe-failed`), so `mutants.out/` lives there and the document carries `scratch_bytes`
- `bash scripts/agent-run.sh run --mutants --file <path>` (repeatable) — one file's mutants: the scoped inner loop (`verdict:"scoped"`, survivors red)
- `TMPDIR=<repo parent>/viola-mutants-scratch bash scripts/agent-run.sh run --mutants --package <member> [--file <path>]...` — one whole member's mutants, the boundary tier's form (`verdict:"package"`): the same prebuild, then `cargo mutants --package <member> --features fake-agent --test-tool=nextest --copy-target=true …`, no base or diff. On the Linux dev host the `TMPDIR` dir must be NOCOW (`chattr +C`): `/tmp` is a 32 GB quota tmpfs too small for the ~14 GB `target/` copy, and a COW btrfs reflink copy drops the copied `viola-fake-agent`'s exec bit (test-plan §10)
- `gh workflow run windows-mutants.yml --ref build/viola-0.1.0` — the boundary audit's Windows leg (founder ruling C2): the dispatch-only, non-blocking `windows-2025` matrix of ten `mutants (<label>)` jobs, one per matrix item (the root package `viola` is five items, split by file, the fifth `viola-cmd-verify-stop` over `src/cmd/verify/stop.rs`), each running `scripts/agent-run.ps1 run --mutants --package <member> --file …` over that item's Windows-gated files (`tests/contract_windows_mutation_scope.rs` keeps the lists complete and the labels distinct). The harness document judges a job: a missed mutant the Windows build never compiled is left out and named in `mutants.host_excluded`, while cargo-mutants' own lines still say MISSED for it. Dispatched only during the epoch-boundary audit, never a gate. Read it back: the run of the pushed sha (`gh run list --workflow windows-mutants.yml --json databaseId,headSha`), `python -X utf8 <andromeda-tools>/scripts/ci.py conclusion --sha <sha> --name mutants` for the per-job verdicts, then each job's harness document and outcome lines via `gh run view --job <id> --log`. No artifact is uploaded; its survivors become corrective-chunk items like any boundary survivor
- `cargo +<channel> fuzz run --fuzz-dir fuzz <target> fuzz/corpus/<target> -- -runs=0` — corpus replay (`run --fuzz-replay`, Linux; channel from `fuzz/rust-toolchain.toml`; `fuzz/` is its own cargo workspace)

## Linting & Formatting
- `cargo fmt --all` / `cargo fmt --all --check` — format / format gate (edition from `rustfmt.toml`)
- `cargo clippy --workspace --all-targets --features fake-agent -- -D warnings`: the lint gate. `print_stdout`, `print_stderr` and `dbg_macro` are denied in every product member (`viola-e2e` opts out and denies only `dbg_macro`), and `clippy.toml` `disallowed-macros` bans the tracing level macros. Beside CI, a chunk plan may list a check-only Windows-target clippy as a chunk gate entry on the Linux dev host, which does not build the `cfg(windows)` code CI lints: `CARGO_TARGET_DIR=target/wincheck cargo clippy --workspace --all-targets --features fake-agent --target x86_64-pc-windows-msvc -- -D warnings` (nothing linked, the target std installed as host preparation; neither a CI step nor a `pre-push` stage).
- `bash scripts/lint-probes.sh`: proves every clippy ban fires and both controls pass, plus the fail-closed raw-`event!` grep (last line `lint-probes: 4 bans fired, 2 controls clean`; CI runs it on the Linux lint leg).
- `cargo check --workspace --all-targets` — type check
- `cargo check $(sed 's/^/-p /' scripts/sync-crates.txt)` — the listed sync crates compile without tokio (CI job `lint`; each sync crate joins `scripts/sync-crates.txt` with its crate)
- `bash scripts/orphans-check.sh [--probe]` — `cargo modules orphans --deny` per lib/bin target (last line `orphans-check: N/N targets clean`; the probe's `orphans-check probes: 1/1 fired, control clean`); CI job `lint`, all 3 OS
- `cargo modules dependencies --package <crate> --lib` — the on-demand boundary review only: `--acyclic` is not a gate (cargo-modules 0.27.0 reads every type ↔ inherent method as a cycle)
- `bash scripts/rmcp-features.sh` — the rmcp release-graph assertion (CI lint step `rmcp features (exactly server + transport-io, non-vacuous)`, every OS, after `Lint probes`): runs `cargo tree -e features -p viola --edges normal --target all -i rmcp --no-dedupe --prefix depth`; rmcp must be present and the features a non-rmcp package requests exactly `server transport-io` (last line `rmcp-features: server transport-io`)
- `cargo deny check` — advisories, licences, sources, bans over `deny.toml`, the root `Cargo.lock` (weekly in `nightly.yml`: `cargo deny check advisories`)
- `cargo deny --manifest-path fuzz/Cargo.toml check advisories sources` — the separate `fuzz/Cargo.lock` audit (CI `supply-chain` with `--format json` into `target/supply-chain/deny-fuzz.json`; weekly `check advisories` in `nightly.yml`). Run it from the repo root: under `fuzz/` rustup demands the fuzz nightly. `fuzz/` stays outside the root graph by a ratified test-only exemption
- `cargo deny --config deny-sync.toml --manifest-path crates/<crate>/Cargo.toml check bans` — the tokio ban, once per crate in `scripts/sync-crates.txt` as sole root (cargo-deny 0.20: `--config` goes before the subcommand; `check -c` is rejected); then, in the same CI step `Tokio ban per sync crate (sole root)`, `bash scripts/channel-tokio-free.sh`: `viola-channel` (off the list since chunk 2026-10-17-mcp-server-for-drivers, its Tokio client behind its `tokio` feature) must print no `tokio v` line from `cargo tree -p viola-channel -e normal --target all -i tokio --prefix none`, its `--features tokio` control must print one (verdict `channel-tokio-free: ok`)
- `bash scripts/profraw-census.sh <runs> <workers> [<name>]` — the dev-host witness for a corrupt coverage profile: the root bin's start test N times on the newest instrumented test binary, each run's profiles counted under `target/profraw-census/` (last line `profraw-census: runs N · passed N · profiles P · third K · short S`; exit 0 only when every run passed, P equals N and K and S are 0; needs the instrumented binary a `pre-push` coverage run leaves; `4800 48` loads 48 workers for about 2.5 minutes; no CI job, `pre-push` stage or harness command runs it)
- `bash scripts/deny-probes.sh` — proves every ban fires (last line `deny-probes: 13/13 banned, control clean`: the twelve bans one probe each, plus probe `channel-tokio-edge` for the `channel-tokio-free.sh` tree form with its channel control; needs the network)
- `bash scripts/conpty-vendor.sh [--verify|--probe]` — the vendored ConPTY binaries: the default re-vendors `vendor/conpty/<version>/x64/` from the pinned nupkg; `--verify` fetches outside the tree and checks the nupkg SHA-256, the byte-identical files and the Authenticode signer (last line `conpty-vendor: verified <version>`); `--probe` shows its four refusals (last line `conpty-vendor probe: 4/4 refused, control clean`). Pins parsed from `src/conpty.rs`; needs the network; CI `windows-2025` step `ConPTY vendor verification`
- `zizmor .github/workflows/` (CI: `--format=json`) — workflow lint

## Observability gates (obs-plan §9, `shell: bash`)
- G1 bare `#[instrument]`: `rg -n -U --pcre2 --type rust '#\[(tracing::)?instrument\b(?!\(\s*skip_all\b)' .` must exit 1
- G2 zero panics: `bash scripts/g2-zero-panics.sh --probe && bash scripts/g2-zero-panics.sh` over `target/e2e-home/**/diagnostics/*.ndjson` (role files only; exempts only a `panic_location` of exactly `src/cmd/hook/seam.rs:<digits>`; last lines `g2-probe: all cases as expected` / `g2: clean`)
- G3 no abort panic strategy: `rg -n --hidden -g 'Cargo.toml' -g 'config.toml' -g '*.yml' -g '*.yaml' "(panic|_PANIC)\s*[:=]\s*[\"']?abort" .` must exit 1
- G1 and G3 need `rg` on `PATH`: `PATH="$PWD/target/tools/ripgrep/bin:$PATH"` after `scripts/install-ripgrep.sh`.
- G4 schema conformance against `schemas/diag-line.v1.json` / `schemas/diag-detail.v1.json`: `bash scripts/agent-run.sh schema-check`.
- Secret scan before any diagnostics-bearing upload: `bash scripts/agent-run.sh secret-scan` (`id: secret-scan`). The hit report goes to `target/secret-scan/hits.json`. The unscanned uploads (nightly `fuzz/artifacts/`, the `supply-chain` reports) are admissible only by content, per obs-plan §8 item 5.
- Locally, G2, G4 and the scan need kept homes. Clear the homes under `target/e2e-home/` first (the scan reads every home left there; on the Linux dev host that path is a link to a tmpfs directory, so remove its entries, never the link). A local `run --mutants` `chunk.diff` in `target/agent-run/` needs no clearing: the scan skips exactly that file. Then run `AGENT_RUN_KEEP_HOMES=1 bash scripts/agent-run.sh run --integration`.

## Troubleshooting
- `cargo clean` — clean build artifacts (also removes `target/e2e-home/` and `target/agent-run/`; on the Linux dev host `target/e2e-home` is a link to the tmpfs backing, so re-make it afterwards with `ln -s /tmp/viola-e2e-home-<uid> target/e2e-home`, or the next start puts a plain directory back on the shared volume with no signal)
- `scripts/agent-run.sh cleanup --all` — tear down every harness session
- `scripts/agent-run.sh logs --instance <name> | jq -c 'select(.record.level=="ERROR")'` — errors for one instance
