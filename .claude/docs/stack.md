## Stack (architecture.md §Stack and Technologies — verbatim)

| Layer | Technology | Role |
|---|---|---|
| Language / runtime | Rust 1.98.1, pinned exactly by `rust-toolchain.toml` (rustfmt + clippy); workspace `rust-version = "1.96"`, edition 2024 | One native binary `viola` / `viola.exe`. 1.96 is the declared floor (the security toolchain floor; sysinfo 0.39.6 needs 1.95, std `File::lock` 1.89, rmcp 1.88). CI checks the floor in the `msrv` job (`rustup toolchain install 1.96` + `RUSTUP_TOOLCHAIN=1.96`; the pin is untouched). The separate `fuzz/` workspace alone builds on `nightly-2026-09-20` (`fuzz/rust-toolchain.toml`) |
| Backend framework (concurrency model) | Hybrid: std threads for `run`, `hook`, `send`, `wait` and every other CLI verb; Tokio 1.53.3 built only inside `mcp` | No async runtime on the hot `hook` path. The async ecosystem is used only where rmcp requires it |
| CLI parser | clap 4.6.7 (derive; `default-features = false` with `std`, `derive`, `help`, `usage`, `error-context`, `suggestions` — its default set minus `color`, so help and usage output is plain and no colour/terminal crate is in the graph) | Subcommands `run · revive · send · wait · last · list · answer · hook · mcp · verify · pause · release · link · unlink · plugin install` |
| PTY layer | portable-pty `=0.8.1` (pinned) behind viola's own `pty` seam; windows-sys 0.61.2 for the `TerminateProcess` kill fallback, the host console's raw/VT modes (`Win32_System_Console`) and its input read (`ReadConsoleW`, behind `viola_pty::host_stdin()`); libc `=0.2.189` (Unix only) for the host tty's raw mode — both behind `HostTerminal`; windows-sys also restricts every process's DLL search to System32 and pre-loads the sideloaded `conpty.dll` by absolute path (`Win32_System_LibraryLoader`). On Windows x64 the ConPTY host is Microsoft's `Microsoft.Windows.Console.ConPTY` 1.24.260710001 (`conpty.dll` + `OpenConsole.exe`, MIT), vendored under `vendor/conpty/` and embedded — a non-crate binary pair | Hosts the unmodified `claude` in the sideloaded ConPTY (Windows x64; the inbox ConPTY is the fail-open fallback and the host on other Windows targets) or openpty (Unix) |
| Screen model | vt100 0.16.2 | Pre-send readiness and modal detection on `run`'s feed thread, handed a copy of the pump's output after the human's write, and the screen of `viola verify`'s five interactive probe runs. `run` never reads content; `Screen::rows()` is the only row-text exit, read by `verify` alone for its signature-only `--record` screen fixtures |
| Wrapper IPC | interprocess 2.4.4 `local_socket` (sync API; the Tokio flavour, `interprocess/tokio`, only in `viola-channel`'s feature-gated `tokio_client::TokioClient`, used by `viola-mcp` alone, which opens a Windows pipe through the same SQOS + overlapped `client::open_handle`); on Windows the client opens with windows-sys 0.61.2 `CreateFileW(SECURITY_SQOS_PRESENT \| SECURITY_IDENTIFICATION \| FILE_FLAG_OVERLAPPED)` + `Stream::try_from`, never the default connect; the server DACL is converted from SDDL by windows-sys (`Win32_Security_Authorization`); on Unix, libc gives the uid for the per-user socket dir and the socket is chmod 0600 after the bind | One endpoint per `viola run`: a named pipe on Windows, a Unix domain socket elsewhere; the Windows open leaves the server able to identify, never impersonate, the client (measured) |
| Database | None. ndjson append logs + atomically replaced JSON snapshots on the local filesystem | Authoritative audit trail and mutable state (wheel mirror, links, budget readings) |
| ORM / migrations | N/A. Every record carries `v`, readers skip unknown kinds and fields, and a snapshot with an unsupported `v` is rebuilt by replaying the log. Exception: process-log lines carry no `v`; their version is the schema filename (`schemas/diag-line.v1.json`, `diag-detail.v1.json`) | Stands in for schema migration |
| State-file primitives | tempfile 3.27.0 `persist` through one shared helper (`viola_state::fs::replace_private`: the mode is set on the temp file before the write, then `sync_all` and `persist`) for snapshots and every other replaced file, and tempfile 3.27.0 `TempPath::persist_noclobber` after `into_temp_path` closes the write handle (`viola_state::fs::place_private_new`) for the pinned copy's absent-copy write, placed once and never replaced; std `File::lock` on separate `.lock` files opened for write (Windows refuses the lock on an append-only handle); std `OpenOptions::append` (one `write` per line); the strict-modes check and private-dir creation through libc (Unix modes and owner) and windows-sys (owner + DACL, and the protected user + SYSTEM DACL on a home created outside the user's profile, `Win32_UI_Shell` `GetUserProfileDirectoryW`; a DACL that cannot be set fails the creation) | Crash-safe multi-process writes with no C code |
| Content hash | sha2 `=0.11.0` (`default-features = false`; pure Rust, no `cc`) | SHA-256 of the exe bytes truncated to 16 hex for the `bin/` / `plugin/` `<version>-<hash>` keys and the re-hash of an existing pinned copy; on Windows x64 also the full SHA-256 of each held ConPTY companion against its compiled pin; a product dependency of `viola-state` (the root dev-dependency stays for its KAT); `[profile.dev.package.sha2] opt-level = 3` |
| Serialization | serde 1.0.229, serde_json 1.0.151 (feature `preserve_order`, which pulls indexmap), serde_path_to_error 0.1.20 | Channel frames, log events, snapshots, tolerant parsing of external payloads with path-precise drift reports; `preserve_order` keeps a printed document's declared key order (e.g. `{"v":1,"cmd":…,"ok":…}`); serde_json's `unbounded_depth` feature is banned in `deny.toml` (Build system), so every parse of external bytes keeps serde_json's default recursion limit |
| Logging | tracing 0.1.44 (default features off, `std`, `attributes`); tracing-subscriber 0.3.23 (default features off, `fmt,json,registry,std`; the root bin is its only product dependent, `viola-channel` and `viola-state` take it as a dev-dependency for their unit tests' line capture); veil `=0.3.0` (`#[derive(Redact)]`, `toggle` banned) | One-line JSON process logs into the viola home's `diagnostics/`; the line format and levels are owned by the obs plan |
| Domain newtypes | nutype 0.8.0 | `ViolaName` (charset + length cap), `Percent` (0–100), `DialogHold` (whole seconds 60–3600) |
| Timestamps | chrono 0.4.45 | RFC 3339 UTC, millisecond precision. Already in the tree through rmcp |
| Error types | thiserror 2.0.20 (one enum per crate; `viola-pty`'s `PtyError` is hand-written; `viola-agent-claude`'s pre-existing `Refusal` beside `AgentError`, `viola-mcp`'s `ServeError` beside `McpError` and `viola-state`'s `StampsError` beside `StateError` are the three open divergences); anyhow 1.0.104 (bin edge only). Panic detail backtraces are raw, never-symbolised frames (root bin `src/panic_frames.rs`: windows-sys `Win32_System_Diagnostics_Debug` + `Win32_System_LibraryLoader` on Windows, libc `backtrace` + `dladdr` on Unix) | Typed errors that callers can branch on; context chains built at dispatch and recorded only in the owner-only instance detail file |
| Message broker | None. Per-wrapper local sockets (JSON-RPC 2.0 over ndjson) for request/response | Local IPC without a broker or daemon |
| Process liveness | sysinfo 0.39.6 (pid + process start time) + `claude agents --json` | Enriches the primary signal, the heartbeat file |
| MCP server | rmcp 3.4.1 (features `server`, `transport-io`), minor pinned; schemars 1.2.2 (tool input schemas) | stdio MCP server implementing spec 2026-07-28 (compatible with 2025-11-25): tools `send · wait · last · answer · list`. The release graph's rmcp features are exactly `server` + `transport-io` (`scripts/rmcp-features.sh`); the test-only `viola-e2e` takes rmcp `client` alone, never `transport-child-process` (which kills the server 3 s after a close), its E2E owning the `viola mcp` child and awaiting its exit (chunk 2026-10-17-mcp-server-for-drivers) |
| AI/ML serving | N/A | viola calls no model API. It drives the unmodified `claude` CLI on the user's subscription |
| Mobile framework | N/A | A phone view is a later version, behind authentication |

## Security-plan additions
- windows-sys 0.61.2 SID / SQOS / DACL APIs · sha2 `=0.11.0` for the SHA-256 `<hash>` (Decisions Log `2026-09-25`).
- Licence: the project is `MIT OR Apache-2.0` (`[workspace.package]`, `license.workspace = true`; `LICENSE-MIT` + `LICENSE-APACHE`). `deny.toml` allows `MIT`, `Apache-2.0`, `Zlib`, `Unicode-3.0`, plus `0BSD` only per crate for interprocess's `doctest-file` and `recvmsg`.
- Audit: cargo-deny `>=0.20.2` (+ `[advisories]`, `[sources]`, `[[bans.features]]`), zizmor `>=1.30.1`; cargo-audit `>=0.22.2` deferred to v1.x binary scans; `scripts/conpty-vendor.sh --verify` / `--probe` for the vendored ConPTY binaries (nupkg + per-file SHA-256, Authenticode signer; CI `windows-2025` step `ConPTY vendor verification`).

## Observability (obs-plan §3)
- tracing 0.1.44 (every instrumentable crate) · tracing-subscriber 0.3.23 (a product dependency of the root bin only, a dev-dependency of `viola-channel` and `viola-state`; `fmt,json,registry,std`, no `ansi`, no `tracing-log`, no `chrono` feature) · veil 0.3.0 `#[derive(Redact)]` (`toggle` feature banned).
- No OTel SDK, no OTLP exporter, no error reporter (sentry banned), no `tracing-appender`, no in-process metrics.

## Accessibility (a11y-plan §3)
- None of its own in 0.1.0: the cli / tui cases use the tests' assert_cmd, predicates, trycmd and portable-pty; the browser a11y tooling left with the browser leg.

## Frontend (design-system §Surface: web-spa)
- The frontend is deferred to 0.2.0; its technology is not chosen; hand-written `@layer` CSS; installed fonts only (Bahnschrift / Cascadia Mono stacks with DejaVu as the Linux fallback; 0.1.0 renders no page).

## Rationale

For architectural rationale behind these choices, see `.andromeda/architecture.md` Established Decisions section. Each `[Tag]` in that section explains why a specific technology was chosen over alternatives considered during `/andromeda-arch`.

## Version updates

When updating a dependency version:
1. Update `.andromeda/architecture.md` Stack table first
2. Update `[workspace.dependencies]` in the root `Cargo.toml`
3. Re-run `/andromeda-setup-project` to refresh this file and any rule files that reference the tool version (name the leaves to regenerate)
4. Test that hooks and tooling still work
5. Commit as `chore: bump {tool} to {version}`
