# viola-channel

_Crate implementation notes. Primary source: `.andromeda/architecture.md` [Message Broker / IPC], [API Style], §Standard Contracts (channel frames); security §Authentication & Authorization (IPC rows); obs §3 Trace context propagation. Generated by `/andromeda-setup-project`._

## Responsibility
The wrapper channel: JSON-RPC 2.0 over ndjson on interprocess 2.4.4 local sockets — one endpoint per `viola run` (named pipe `\\.\pipe\viola-<h12>` on Windows; `<per-user 0700 dir>/viola-<h12>.sock` on Unix). It provides a sync client and server; behind its `tokio` feature (`tokio = ["dep:tokio", "interprocess/tokio"]`) it holds the Tokio client `tokio_client::TokioClient` (`connect`, `conn`, `request`; landed at chunk 2026-10-17-mcp-server-for-drivers), enabled by `viola-mcp` and, in a package-scoped test build, by the crate's own `fake-agent = ["tokio"]`; without the feature its normal graph stays tokio-free (`scripts/channel-tokio-free.sh`). It owns the endpoint name (hand-written FNV-1a 64), framing with `MAX_FRAME`, the result / refusal / error shapes, the per-OS listener hardening and the connected server's peer pid (`Client::server_pid` / `TokioClient::server_pid`; `SERVER_PID_REPORTED` false on macOS) that every frame-writing client's server check (`viola_state::liveness::verify_server`) compares with the snapshot before its first frame.

## Key integrations

### Consumes from
`viola-core` (`RefusalReason`, `ViolaName`, `MAX_FRAME`, `v`); interprocess 2.4.4; serde, serde_json, thiserror, tracing, veil (as landed); windows-sys 0.61.2 (SID lookup, SDDL conversion via `Win32_Security_Authorization`, SQOS `CreateFileW`); libc (Unix: the uid for the socket dir); tokio `io-util` and `interprocess/tokio` behind the optional `tokio` feature (dev-dependency tokio `rt`).

### Publishes to
The wrapper (`run`) server side; clients `hook`, the CLI verbs, `viola-mcp` (Tokio client) and the tests' raw-frame clients. Tests only: the `test-support` feature (`pub mod test_support`: `JsonFields`; on Windows `canonical_sddl`, `dacl_of`, an independent `user_sid`) — enabled only by the root `[dev-dependencies]`, never in a release build (release-check refuses it).

### Dependencies
Tokio only behind the `tokio` feature; `viola-channel` is not in `scripts/sync-crates.txt` (since chunk 2026-10-17-mcp-server-for-drivers): its normal graph without the feature is proven tokio-free by `scripts/channel-tokio-free.sh` in CI's supply-chain step.

## Internal conventions
- Every `params` carries `v`, `sender` and (additively) `conn = "<process>-<pid>-<t0>-<n>"`; a newer `v` → `-32602` `{supported, wrapper}`.
- Methods: `send · wait · last · answer · pause · release · link · unlink · hook.dialog` (+ notification `hook.event`); integer ids monotonic per connection.
- Windows listener: protected SDDL `D:P(A;;GA;;;<user-SID>)(A;;GA;;;SY)` converted by windows-sys (read back canonical as `(A;;FA;;;…)`, the SID possibly an alias), `accept_remote(false)`, first-instance, `inheritable(false)`. Unix: 0700 per-user dir checked (`lstat`, owner, no symlink) before bind and before connect; socket chmod 0600 after the bind (never `ListenerOptionsExt::mode`: `Unsupported` on macOS fails the bind); `.lock` sibling as the start arbiter; `peer_creds` euid on accept. `try_overwrite` off.
- `Dispatch::dispatch_call(&Call)` (defaulted to `dispatch`) hands a method its request `id` and `conn` / `srv_conn` for its own log lines (correlation, never identity); only `run`'s `Methods` overrides it (for `send`, `wait`, `last`). `ProtocolError::InvalidParams` answers `-32602` `"invalid params"`, `data: null`; `ProtocolError::ReleaseFromDriver` answers the same code and message with `data: {"reason":"release-from-driver"}` (a `release` carrying a string `from`), and both sit in the server's −32602 WARN class. The envelope (`frame::Params`: `v`, `sender`, `conn`) types no method param, so a mistyped `from` reaches the method's `-32602`. `wait`'s `channel-request` lines carry `after` / `timeout_ms` (`u64` only) and its `channel-response` lines an `outcome` (the waking kind or `timed-out`, derived here over `EventKind::WAIT_WAKE`; the client alone adds `instance-unreachable` when the reply never came).
- A frame is one line ≤ `MAX_FRAME` (`\n` counted); oversize → `-32600` + close. Only `hook.event` may be id-less. The server strips `conn` before dispatch; a mis-shaped `conn` is logged as `srv_conn`.
- Client: open (Windows SQOS Identification); `Client::server_pid` / `TokioClient::server_pid` return the connected stream's peer pid through interprocess's `peer_creds().pid()` (Linux `SO_PEERCRED`, Windows `GetNamedPipeServerProcessId` on the SQOS-adopted client end, none on macOS, where `SERVER_PID_REPORTED` is false), writing and logging nothing. Before its first frame every frame-writing client (CLI `send` / `wait` / `last` / `answer` / `pause` / `release` / `link` / `unlink`, `viola hook`'s `hook.event` and `hook.dialog`, `viola-mcp`'s four frame tools) takes its one snapshot read (the CLI frame verbs and `viola-mcp`'s frame tools the liveness-only `viola_state::liveness::live_endpoint` read, `LiveEndpoint`: endpoint, pid, start time from one snapshot read; `viola hook`'s event and dialog paths one shared `read_snapshot` before `Client::connect_by`), then compares that peer pid and its OS start time with the snapshot's `pid` / `started_at` (`viola_state::liveness::verify_server` → `ServerVerdict`); a mismatch or a check that cannot be made writes no frame (CLI exit 21 / MCP `instance-unreachable`, the hook fails open with no body). macOS reports no peer pid and stays the recorded gap (`server_verdict` returns `Matches` with no comparison); its client euid and socket-directory checks are owed to the working-route entry "Unix endpoint and home hardening".
- `Client::notify(method, params)` sends an id-less frame (stamps `v`/`sender`/`conn`, logs `channel-request` with no `corr`); `Client::connect_by(endpoint, process, busy_until)` takes the pipe-busy deadline (`connect` = `connect_by(…, busy_deadline(now))`, 2 s). The wrapper serves `hook.event` (re-validated, appended with `source:"hook"`), `hook.dialog`, `send`, `wait`, `last`, `answer`, `pause`, `release`, `link` (→ `{since, already_linked}`) and `unlink` (→ `{}`), the last two sent to the driven instance's wrapper.
- `channel-request` / `channel-response` log method, `corr` (JSON-RPC id), `conn`, result class, error code, `sender` — never params or bodies; a `Drop` guard in dispatch always logs the response.

## Crate-specific gotchas
- Endpoint names must be stable across toolchains → never `DefaultHasher`.
- macOS socket paths cap at ~104 bytes; the recorded snapshot `endpoint` is authoritative (children may see another environment).
- **SQOS spike passed** (security-plan Decisions Log `2026-09-25`): the client opens with windows-sys `CreateFileW(SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION | FILE_FLAG_OVERLAPPED)` and adopts via `Stream::try_from` — reuse the recipe `tests/channel_sqos_open.rs` pins. Keep `FILE_FLAG_OVERLAPPED` (non-overlapped adoption hangs) and never fall back to the default connect (the server then reads `SecurityImpersonation`). A safe-Rust equivalent was measured: std `OpenOptions::security_qos_flags` + `custom_flags(FILE_FLAG_OVERLAPPED)`.
