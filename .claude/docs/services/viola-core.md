# viola-core

_Crate implementation notes. Primary source: `.andromeda/architecture.md` (§Crate dependency direction, §Conventions); security §Input Validation; obs §3 Logging stack. Generated by `/andromeda-setup-project`._

## Responsibility
The shared vocabulary of every other crate: the normalised event kinds, `RefusalReason` and its closed detail sets, the nutype newtypes `ViolaName` and `Percent`, the protocol `v` constants, the shared validators (`validate_paste_text`), the `MAX_FRAME` constant (16 MiB), the injected `Clock` seam, `SERVICE_NAME` / `VERSION`, and the obs vocabulary (`obs_event!`, `ObsEvent`, `ObsProcess`). It performs no I/O and depends on no viola crate. It does NOT know Claude payload shapes (that is `viola-agent-claude`), and it does not depend on `tracing`: `obs_event!` expands to `::tracing::event!` at the caller.

## Key integrations

### Consumes from
Nothing inside the workspace. Third-party: nutype 0.8.0, serde, serde_json, chrono, thiserror (via `[workspace.dependencies]`).

### Publishes to
Every workspace crate and the root bin: event kinds (kebab-case wire values), `RefusalReason` (`#[serde(other)] unknown`), newtypes, validators, constants, `CoreError`.

### Dependencies
None beyond the workspace-shared third-party crates; tokio is banned in its graph (`cargo deny`).

## Internal conventions
- New event kinds and refusal details are added ONLY here, never with Claude-specific names; `detail` values are kebab-case strings from a closed set per reason.
- `validate_paste_text(&str)` checks decoded `char`s: LF/CR/TAB allowed; every other C0, DEL and C1 → `not-delivered` / `control-character`. Called by the CLI and MCP client side and again by the wrapper (authoritative).
- `ViolaName`: `[a-z0-9-]`, 1–32 chars, starts with a letter; every `instances/<name>` join and every clap/MCP/channel/SSE name goes through `ViolaName::try_new`.
- `ObsEvent` variants equal the `event` enum in `schemas/diag-line.v1.json` (a tests-owned check asserts it); `a11y-violation` is not a variant.
- `CoreError` `Display` strings are fixed messages.

## Crate-specific gotchas
- `detail` for `unknown` is opaque text — readers never treat an unrecognised detail as an error.
- `unconfirmable` is not a refusal detail; it appears only in an `ok` payload.

## Entry points for modification
- **Event kinds / refusals / newtypes:** `crates/viola-core/src/` (module names decided by the implementing chunk)
- **Obs macro + enums:** `viola_core::obs`
- **Tests:** inline `#[cfg(test)] mod tests`; proptest over `validate_paste_text`

## Testing this crate
- **Unit tests:** `cargo nextest run -p viola-core`
- **Property:** proptest `cases: 512` (UTF-8 continuation bytes never trip the C1 check); committed `proptest-regressions/`
- **Mutants:** `cargo mutants --file crates/viola-core/src/<file>.rs --test-tool=nextest` — killed by this crate's own tests
