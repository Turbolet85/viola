# viola-core

_Crate implementation notes. Primary source: `.andromeda/architecture.md` (§Crate dependency direction, §Conventions); security §Input Validation; obs §3 Logging stack. Generated by `/andromeda-setup-project`._

## Responsibility
The shared vocabulary of every other crate: the normalised event kinds, `RefusalReason` and its closed detail sets (`HumanTyping { ManualPause }` among them), the wheel's `WheelCause` (`start` · `human-input` · `manual-pause` · `release`), the nutype newtypes `ViolaName` and `Percent`, the protocol `v` constants, the shared validators (`validate_paste_text`), the `MAX_FRAME` constant (16 MiB), `SPINE_DEADLINE` (1 s, the spine bound the perf gate reads), `DIALOG_DEADLINE` (60 s PROVISIONAL, the dialog hooks' wait, below the `hooks.json` `timeout` of 75), the injected `Clock` seam (`SystemClock` in production; first consumer `run`'s vt100 feed thread), `SERVICE_NAME` / `VERSION`, and the obs vocabulary (`obs_event!`, `ObsEvent`, `ObsProcess`). It performs no I/O and depends on no viola crate. It does NOT know Claude payload shapes (that is `viola-agent-claude`), and it does not depend on `tracing`: `obs_event!` expands to `::tracing::event!` at the caller.

## Key integrations

### Consumes from
Nothing inside the workspace. Third-party: nutype 0.8.0, serde, serde_json, chrono, thiserror (via `[workspace.dependencies]`).

### Publishes to
Every workspace crate and the root bin: event kinds (kebab-case wire values), `RefusalReason` (`#[serde(other)] unknown`), newtypes, validators, constants, `CoreError`.

### Dependencies
None beyond the workspace-shared third-party crates; tokio is banned in its graph (the sole-root `deny-sync.toml` ban; `viola-core` is listed in `scripts/sync-crates.txt`).

## Internal conventions
- New event kinds and refusal details are added ONLY here, never with Claude-specific names; `detail` values are kebab-case strings from a closed set per reason. `EventKind` holds 13 kinds, the dialog kinds `question` / `permission` / `plan` among them; `EventKind::WAIT_WAKE` is the one wake set (`turn-ended`, `question`, `permission`, `plan`, `session-end`) the wrapper's `wait` and the channel's `outcome` both read.
- `validate_paste_text(&str) -> Result<(), NotDelivered>` checks decoded `char`s: LF/CR/TAB allowed; every other C0, DEL and C1 → `not-delivered` / `control-character`. Called by the CLI (and MCP when it lands) client side and again by the wrapper (authoritative). `RefusalReason` and the closed `not-delivered` details `NotDelivered` are kebab-case serde enums with `as_str`; `EventKind` carries the three `send-*` kinds.
- `ViolaName`: `[a-z0-9-]`, 1–32 chars, starts with a letter; every `instances/<name>` join and every clap/MCP/channel/SSE name goes through `ViolaName::try_new`.
- `ObsEvent` variants equal the `event` enum in `schemas/diag-line.v1.json` (a tests-owned check asserts it); `a11y-violation` is not a variant.
- `CoreError` `Display` strings are fixed messages.

## Crate-specific gotchas
- `detail` for `unknown` is opaque text — readers never treat an unrecognised detail as an error.
- `unconfirmable` is not a refusal detail; it appears only in an `ok` payload.
