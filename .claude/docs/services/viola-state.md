# viola-state

_Crate implementation notes. Primary source: `.andromeda/architecture.md` [Database / State Store], [Snapshot writer], [Session Liveness], §Occupied Resources (Filesystem); security §`~/.viola/` access control; obs D-03. Generated by `/andromeda-setup-project`._

## Responsibility
Everything on disk: viola home resolution (`--home` → grandparent of `VIOLA_DIR` → `~/.viola/`; as landed (chunk 2026-10-17-cli-machine-contract) `hook` and every CLI verb, `run` and `revive` included, take the `VIOLA_DIR` step through the root bin's `resolve_home` / `resolved_home` (`src/cmd/mod.rs`), only when `VIOLA_NAME` and `VIOLA_DIR` pass `instance_of`'s shape check, a failing pair falling through to the default, never refusing; `viola mcp` resolves its home through the same `resolved_home`), ndjson append logs (one `write` per line), atomic JSON snapshots (tempfile `persist` through the one helper `fs::replace_private` / `replace_private_shared`), std `File::lock` on `.lock` siblings (opened for write), the `events.ndjson` reader `events::read_from` (each line under `take(MAX_FRAME + 1)` with its start and end offsets; per-read counts `unknown_kinds` · `unknown_fields` · `torn_lines`; a line of an unknown kind is not returned; an over-long line, a non-object line and the unterminated last line count as torn, the last neither returned nor rewritten), the healing append (an append to a log whose last byte is not LF writes one LF and its line in one write, then logs `state-recovered`), liveness (heartbeat + sysinfo pid/start time; `liveness::start_times`, one process-table read; `liveness::live_endpoint(instance_dir)` → `Option<LiveEndpoint>` (`{ endpoint, pid, started_at }`, all from its one `replay::read_snapshot_or_replay` call and only on a real snapshot: a replayed or absent one, or a failed read, gives `None`), shared by CLI `send` / `wait` / `last` / `answer` / `pause` / `release` / `link` / `unlink` and `viola-mcp`'s frame tools; the server identity check (the closed `ServerVerdict` `Matches` · `Mismatch` · `Unverifiable`, the pure `server_verdict`, the joined `verify_server` reading the observed start time through `process_start_time`: the snapshot's pid and start time against the connected server's, made before the first frame by those CLI verbs, `viola hook` and `viola-mcp`'s frame tools; with no peer pid reported, as on macOS, `Matches` with no comparison, the recorded gap)), the classified snapshot read (`snapshot::read_snapshot_classified`) and the log replay (`replay`: library code, read through `read_snapshot_or_replay` by six product readers, each after the instance's strict-modes check: `viola revive`'s preflight (one read for both its collision check and its recorded directory), `viola list`'s `board::read`, `liveness::live_endpoint`, `viola hook`'s `connect`, `hook statusline`'s `serve` and `run`'s collision check; no product code under `src/` calls `read_snapshot`; `replay::session_chain` gives one link per `session-start` line with a string id, with the pass's skip counts, and writes and logs nothing), the optional snapshot field `cwd` (the start's spawn directory; no event carries it, so a replay gives none), the instance check `strict::check_instance` (the home (the read rule), `instances/` (the write rule), the instance directory (the read rule), its `diagnostics/` (the read rule), its `snapshot.json` (the write rule) and its `events.ndjson` (the write rule on Unix, the read rule on Windows), each that exists, a folder before what it holds), `budget.json`, `ledger/stamps.json` reads (`config.json` is read by the root bin, `run::budget::read_thresholds` and `run::dialog::read_hold`, not here), and the home strict-modes check (Unix modes; Windows owner + DACL) with 0700/0600 creation, in two rules — the write rule, and the read rule (`unix_read_verdict`, `windows_read_verdict`: on Unix no group or other bit, on Windows no allow ACE granting a right in `READ_RIGHTS` to a SID `trusted_sid` rejects) —, and beside `check_instance` the checks `check_home_tree(home, name, key)` (the home; with a name `check_instance`'s set; `ledger/`, `bin/`, `plugin/`; with a key `bin/<key>/`, the pinned `viola`, `plugin/<key>/`, its `hooks/` and `.claude-plugin/`; each that exists; refusing as `TreeRefused::HomeLevel` or `TreeRefused::InstanceLevel`; called by `run`'s and `revive`'s starts and by `verify` with no name and no key), `check_diagnostics` (a symbolic link refused; run by `open_role_file` / `write_detail` before anything is narrowed), `check_present` and `check_stamps`.

### Dependencies

## Internal conventions
- Files created with `OpenOptionsExt::mode(0o600)`, dirs 0700; the pinned `bin/<version>-<hash>/viola` is 0700; the temp file's mode is set before any byte is written, then `persist` (`replace_private`), or for the pinned copy's absent-copy write the write handle closed (`into_temp_path`) and `TempPath::persist_noclobber` (`fs::place_private_new` → `Placed { Written, Present }`, `AlreadyExists` being `Ok(Placed::Present)` with the target untouched; no retry); if the mode cannot be set, discard the write.
- `stamps` module (as landed): `update_stamps(home, FnOnce(Option<&[u8]>) -> Vec<u8>)` is the ONE writer path of `ledger/stamps.json` (`strict::check_stamps` on the home before it creates `ledger/` and again under its lock before its capped read, a refusal reading and writing nothing and returning `StampsError::StrictModes` — its error `StampsError` (`StrictModes` · `State`), each variant with a fixed message —; 0700 `ledger/`, the `.lock` sibling held for the read-modify-write, current bytes through `take(MAX_FRAME + 1)` — over the cap reads as absent —, `replace_private` 0600; span `state.ledger_write`); `read_stamps(home)` takes no lock, over the cap is an error, absent is `Ok(None)` (span `state.ledger_read`); `ledger_dir`.
- Strict-modes runs in every process that reads `snapshot.json`, `ledger/stamps.json` or `statusline_command` (`run`'s and `revive`'s starts and `verify` through `check_home_tree`, `verify`'s `update_stamps` through `check_stamps`, `run`'s version gate through `stamps::read_stamps_strict` (the `strict` module's `check_stamps` first, a refusal `cli_verified:false`), `hook`'s event, dialog and statusline paths through `trusted`, the CLI frame verbs `send` / `wait` / `last` / `answer` / `pause` / `release` and `link` / `unlink` through `client::refuse_untrusted`, `viola mcp`'s frame tools through `check_instance`, and on Windows x64 the ConPTY companions through `check_present` before the held-handle re-hash); Windows checks cover inherit-only and generic bits, NULL DACL and non-persistent-ACL volumes, and each existing `events.ndjson` before it is opened.
- On Windows, `replace_private` retries a `persist` refused with raw OS error 5 (a reader holding the target) every 10 ms, re-persisting the same temp file, at most `fs::REPLACE_ATTEMPTS` = 100 attempts; any other error returns at once. The loop sits in the private `replace_private_retrying`, which takes the retry decision (from the raw OS error) from its caller; `replace_private_with` passes `retry_replace(_, HOST_IS_WINDOWS)`, so the product behaves as above and a unit case exercises the attempt bound on every host. `write_snapshot` and `replace_private_shared` inherit it.
- `pin` (Windows, as landed by 2026-09-29-sideloaded-conpty): `Companion { name, bytes, sha256_hex }`, `HeldCompanions { dir, _handles }`, `pin_companions(&Pinned, subdir, &[Companion])` — first the owner/DACL check (`strict::check_present`) on `bin/<version>-<hash>/conpty/` and on each companion that exists (a refusal is `PinError::StrictModes`, writes nothing, and the child runs on the inbox ConPTY with `sideload_fallback` `strict-modes-failed`), then each file written if absent through `replace_private_shared`, then opened with Win32 `FILE_SHARE_READ` only and fully re-hashed; a mismatch is `PinError::HashMismatch` with the file left as found. A held open refused with Win32 error 32 (sharing violation — two concurrent first starts, 5-11 ms measured) is retried under `REPLACE_ATTEMPTS` (`retry_open`, `open_held_waiting`). `pin_key(bytes)` names the pinned copy's key, `<version>-<16 hex>`, in one place, and `pin_bytes(home, bytes)` pins bytes already read (`run`'s start pins the very bytes its home-tree check keyed), an absent copy placed once and never replaced through `pin::place_absent` (`fs::place_private_new` at `DIR_MODE`, no clobber): `Written` is ok, `Present` (a concurrent first start placed it first) re-hashes the copy that stands, equal bytes reused and different bytes `PinError::HashMismatch` with the file left as found; `pin_exe(home, exe)` delegates to it; `verify` unchanged; the private `digest()` backs `file_key`.
- `end_offset(instance_dir) -> Result<u64>` (the `events.ndjson` length under its lock, 0 when absent) and `append_event_at(instance_dir, build: FnOnce(u64) -> EventLine) -> Result<u64>` (the offset read and the line written under one lock hold: a `send`'s `cursor`; after a heal it is the length + 1, the offset the line really starts at).
- `try_append_event(instance_dir, line) -> Result<bool>`: `Ok(false)` with nothing written while `events.ndjson.lock` is held (the hook's SessionEnd fallback, `Source::Hook`).
- `events.ndjson` is never truncated or rotated (offsets are cursors); instance dirs are reused and appended to.
- Readers: over-long lines (> `MAX_FRAME`) count as `torn_lines`; unknown kinds/fields are counted in `skipped`; a reader never writes (the next append heals a torn last line). A snapshot with an unsupported `v` or a parse failure → replay (`state-recovered`) through `replay::read_snapshot_or_replay`, whose six product callers are `viola revive`'s preflight, `viola list`'s `board::read`, `liveness::live_endpoint`, `viola hook`'s `connect` (a replayed or absent snapshot unreachable, so the hook fails open), `hook statusline`'s `serve` (no `statusline_command` in a replayed snapshot) and `run`'s collision check (a replayed snapshot judged by the heartbeat alone); the replay writes no file and recovers `links` from the logged `link` / `unlink` lines through the public rule `replay::apply_link_line` (a pair keeps its first `since` until an `unlink`; a `link` line with no string `ts` reads `since: "unknown"`), which the root bin's `LinkSet` applies as well.
- Symlinks under `instances/` are ignored: `viola list` logs one `parse-rejected{parser:"state-entry", detail:"symlink-ignored"|"malformed", count}` per nonzero scan count, naming no entry.
- Only the instance's wrapper writes its snapshot; only `viola verify` writes stamps; only `hook statusline` writes `budget.json` (under its lock, last-writer-wins): `budget::write_budget` replaces it whole through `replace_private` at 0600 as `{"v":1,"five_hour","seven_day","read_at"}`, and only when the payload held a `rate_limits` object. Its one checked read is `budget::read_budget_stamped(home) -> Option<StampedReading>` (`{reading, read_at}`, `read_at` `"unknown"` when absent or no string; chunk 2026-10-11-the-board-viola-list), with two product paths: `budget::read_budget(home) -> Option<BudgetReading>` (= `read_budget_stamped(home).map(|s| s.reading)`), called by the wrapper's budget gate, and `viola list`. The board read model is `board.rs` (`scan` checks the home, `instances/` and each instance without following a link; `read` gives one `Item` per live or stale instance, takes the replay for an unreadable or newer snapshot, and sums the skip counts of one `read_from` pass per instance; the agents join (`JoinKeys`, `Observation`, `join`, `Item::unwrapped`) folds one `claude agents --json` reading in: a row matching a wrapped item's `child_pid` or `agent_session_id` sets that item's `status` to `idle` or `busy`, and every unjoined row is an unwrapped item; no type holds `endpoint`, `pinned_bin`, `cwd`, `statusline_command`, `pid`, `started_at` or `links`). The read runs: `strict::check_path` on the home and on `budget.json`, a shared lock on `budget.json.lock`, `take(MAX_FRAME + 1)`, a tolerant parse, `v` = 1; every failure is `None` with no line, it never writes, and an absent file creates nothing. The snapshot gains an optional `budget_override_until` (the wrapper's write; `v` stays 1). The snapshot holds an optional `statusline_command`; `SnapshotRead::Present` and `replay::Recovered::Snapshot` hold a `Box<InstanceSnapshot>`.

## Crate-specific gotchas
- Append + exclusive lock on the same file fails on Windows — lock the sibling.
- A bare pid is unsafe (reuse) — always pid + start time.
- **SHA-256 crate:** `sha2 =0.11.0` (`default-features = false`; security-plan Decisions Log `2026-09-25`) for the pinned-exe re-hash; `<hash>` = the first 8 digest bytes as 16 lowercase hex. Take it from `[workspace.dependencies]` as a normal dependency here; `tests/contract_content_hash.rs` holds its KAT today.
