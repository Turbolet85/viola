# viola-state

_Crate implementation notes. Primary source: `.andromeda/architecture.md` [Database / State Store], [Snapshot writer], [Session Liveness], §Occupied Resources (Filesystem); security §`~/.viola/` access control; obs D-03. Generated by `/andromeda-setup-project`._

## Responsibility
Everything on disk: viola home resolution (`--home` → grandparent of `VIOLA_DIR` → `~/.viola/`), ndjson append logs (one `write` per line), atomic JSON snapshots (tempfile `persist` through the one helper `fs::replace_private` / `replace_private_shared`), std `File::lock` on `.lock` siblings (opened for write), the `events.ndjson` reader `events::read_from` (each line under `take(MAX_FRAME + 1)` with its start and end offsets; over-long and non-object lines skipped and counted; an unterminated last line neither returned nor rewritten — torn-line healing is owed to route `:87`), notify 8.2.0 tailing, liveness (heartbeat + sysinfo pid/start time), replay recovery, `budget.json`, `ledger/stamps.json` reads, `config.json` parsing, and the home strict-modes check (Unix modes; Windows owner + DACL) with 0700/0600 creation.

## Internal conventions
- Files created with `OpenOptionsExt::mode(0o600)`, dirs 0700; the pinned `bin/<version>-<hash>/viola` is 0700; the temp file's mode is set before any byte is written, then `persist`; if the mode cannot be set, discard the write.
- `stamps` module (as landed): `update_stamps(home, FnOnce(Option<&[u8]>) -> Vec<u8>)` is the ONE writer path of `ledger/stamps.json` (0700 `ledger/`, the `.lock` sibling held for the read-modify-write, current bytes through `take(MAX_FRAME + 1)` — over the cap reads as absent —, `replace_private` 0600; span `state.ledger_write`); `read_stamps(home)` takes no lock, over the cap is an error, absent is `Ok(None)` (span `state.ledger_read`); `ledger_dir`.
- Strict-modes runs in every process that reads `snapshot.json`, `ledger/stamps.json` or `statusline_command` (not landed yet — Epoch 6 "Home and code-bearing file integrity"; until then, ratified interim gaps: `hook <event>`'s snapshot read, and `verify`'s `update_stamps` reading the stamps, security-plan Decisions Log `2026-09-28` — `run`'s version gate reads them through `stamps::read_stamps_strict`, the `strict` module's `check_stamps` first, a refusal `cli_verified:false`; `send` / `wait` / `last` / `answer` / `pause` / `release`'s liveness-only snapshot reads, the founder's 2026-10-04 rulings; and the Windows x64 ConPTY companions loaded under the held-handle re-hash alone, Decisions Log `2026-09-29`); Windows checks cover inherit-only and generic bits, NULL DACL and non-persistent-ACL volumes, and each existing `events.ndjson` before it is opened.
- On Windows, `replace_private` retries a `persist` refused with raw OS error 5 (a reader holding the target) every 10 ms, re-persisting the same temp file, at most `fs::REPLACE_ATTEMPTS` = 100 attempts; any other error returns at once. `write_snapshot` and `replace_private_shared` inherit it.
- `pin` (Windows, as landed by 2026-09-29-sideloaded-conpty): `Companion { name, bytes, sha256_hex }`, `HeldCompanions { dir, _handles }`, `pin_companions(&Pinned, subdir, &[Companion])` — each file written if absent through `replace_private_shared`, then opened with Win32 `FILE_SHARE_READ` only and fully re-hashed; a mismatch is `PinError::HashMismatch` with the file left as found. A held open refused with Win32 error 32 (sharing violation — two concurrent first starts, 5-11 ms measured) is retried under `REPLACE_ATTEMPTS` (`retry_open`, `open_held_waiting`). `pin_exe` / `verify` unchanged; the private `digest()` backs `file_key`.
- `end_offset(instance_dir) -> Result<u64>` (the `events.ndjson` length under its lock, 0 when absent) and `append_event_at(instance_dir, build: FnOnce(u64) -> EventLine) -> Result<u64>` (the offset read and the line written under one lock hold: a `send`'s `cursor`).
- `try_append_event(instance_dir, line) -> Result<bool>`: `Ok(false)` with nothing written while `events.ndjson.lock` is held (the hook's SessionEnd fallback, `Source::Hook`).
- `events.ndjson` is never truncated or rotated (offsets are cursors); instance dirs are reused and appended to.
- Readers: over-long lines (> `MAX_FRAME`) count as `torn_lines`; unknown kinds/fields are counted in `skipped`; a snapshot with an unsupported `v` or a parse failure → replay (`state-recovered`).
- Tailing only `instances/<name>/events.ndjson` where `<name>` passes `ViolaName::try_new`; symlinks ignored (`parse-rejected{parser:"state-entry", detail:"symlink-ignored"}`).
- Only the instance's wrapper writes its snapshot; only `viola verify` writes stamps; only `hook statusline` writes `budget.json` (under its lock, last-writer-wins).

## Crate-specific gotchas
- Append + exclusive lock on the same file fails on Windows — lock the sibling.
- A bare pid is unsafe (reuse) — always pid + start time.
- **SHA-256 crate:** `sha2 =0.11.0` (`default-features = false`; security-plan Decisions Log `2026-09-25`) for the pinned-exe re-hash; `<hash>` = the first 8 digest bytes as 16 lowercase hex. Take it from `[workspace.dependencies]` as a normal dependency here; `tests/contract_content_hash.rs` holds its KAT today.
