# viola-mcp

_Crate implementation notes. Primary source: `.andromeda/architecture.md` [MCP], §Conventions (MCP), §Standard Contracts (MCP refusal result); security §Input Validation (MCP row), §API Security (MCP transport); obs §3 (`mcp` sink, D-09). Generated by `/andromeda-setup-project`._

## Responsibility
The stdio MCP server `viola mcp` (rmcp 3.4.1, features exactly `server` + `transport-io`, spec 2026-07-28): a thin adapter that maps tools `send · wait · last · answer · list` onto the wrapper channel (Tokio client) and onto the caller-side `list` read. It adds `from` from its own `VIOLA_NAME`. It is one of the two crates allowed to build a Tokio runtime.

## Key integrations

### Consumes from
`viola-core`, `viola-channel[tokio]`, `viola-state`, `viola-agent-claude`; rmcp, schemars 1.2.2, tokio 1.53.1.

### Publishes to
Claude Code driver sessions (the MCP client) via the embedded `.mcp.json` whose command is the absolute pinned `viola` path.

### Dependencies
Tokio allowed: `viola-mcp` is never a root of the `deny-sync.toml` tokio ban, which runs only for the crates in `scripts/sync-crates.txt`.

## Internal conventions
- Tool inputs: `send {target, text}`, `wait {target, after?, timeout_ms?}`, `last {target}`, `answer {target, dialog_id, response}`, `list {}`. `release`, `pause`, `link`, `unlink` are CLI-only (an affordance, not enforcement).
- schemars schemas are advisory: handlers deserialise `target` into `ViolaName`, `dialog_id` into `u64`, `response` into the closed channel enums, and run `validate_paste_text` on `text` and free-text answers.
- Success = `isError:false` + the channel `ok` payload as `structuredContent`; refusal = `isError:true` + `{refusal, detail}` + text `refused: <reason>`; unreachable / fault = `isError:true` + `{"error":"instance-unreachable"|"wrapper-fault","detail":…}`. Only faults on the MCP connection itself are JSON-RPC errors.
- stdout carries MCP frames only; logs go to `<home>/diagnostics/mcp.ndjson` (stderr JSON only if the file cannot be opened). The `rmcp` log target is OFF.
- Every call returns below the MCP client's tool-call timeout (the MCP `wait` default is an arch open item).

## Crate-specific gotchas
- `tools/list` must be exactly the five tools — the MCP E2E asserts it.
- A main-thread panic → `process-exit{detail:"internal-error"}` then exit 1, nothing on stdout; Tokio task panics are contained.
