## Responsibility
The only crate that knows Claude Code. It parses hook payloads tolerantly and maps each hook to a normalised kind. It maps dialog answers to decision bodies (S3 / S7 / S8) and applies the R8 `CLAUDE*` strip. It resolves the npm shim to `claude.exe` and holds the Claude-specific half of the CLI version gate: the capability ledger rows (compiled) with their `viola verify` checks, `parse_version`, the stamp merge and `verified` verdict, and the fixture scrub. The gate's spawn is the root bin's `run::version_gate`; the stamps I/O is `viola_state::stamps`. It keeps the vt100 screen signatures (readiness gate), parses the statusline `rate_limits` and `claude agents --json`, and normalises `prompt-submitted` (removes the long-paste wrapper, then reverses tag escaping; classifies `origin` driver/human/harness). No adapter trait yet: a second agent arrives as a sibling `viola-agent-<name>` crate.

## Internal conventions
- Decision bodies: PreToolUse `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"allow","updatedInput":{…}}}` (questions incl. `annotations`; plan approve); PermissionRequest `decision.behavior` allow/deny + `message` (plan revise). No decision = exit 0 with empty stdout.
- Security-deciding fields map into closed enums even under tolerant parsing; every external reader bounded by `Read::take(MAX_FRAME)`.
- Ledger rows (S3, S7, S8, R8 identity floor, shim resolution, statusline source + shell, harness prefixes, `<pasted_content>` wrapper, modal / input-box signatures, hook tier map, turn end without Stop, dialog concurrency, `claude agents --json` join field, plugin precedence, local commands + post-conditions, tag escaping, largest hook payload) are compiled here, never built from runtime or upstream text.
- `dialog` module (pure, as landed): `DialogKind`, `DialogTool`, `Dialog`, `classify` (one dialog payload → its closed kind / tool; malformed → `AgentError::DialogMalformed`, the hook fails open), `Response::{parse, free_text, to_value}`, `decision_body` (the S3 / S7 / S8 bodies, insta-pinned in `src/snapshots/`; the S7 approve is `allow` + `updatedInput` echoing the tool's own input), backed by the ledger's four dialog rows (`question-answer` · `plan-approve-revise` · `question-notes` · `dialog-concurrency`); `ledger::probe_body` reaches it for `viola verify`'s Run C / Run D answers, never a second mapping.
- `hook` module (as landed): `HookEvent` (9 registered events, the dialog tier `PreToolUse` / `PermissionRequest` included; `from_arg`, `kind()` — an `Option<EventKind>`, `None` for the dialog tier — `is_dialog()`, `as_str` = diag-line `$defs.hook_event`), `normalise(event, bytes) -> Normalised{kind, data, drift}`. A wrong-typed known field → a drift entry `{path, expected:"string"}` and read as absent. Prompt order: classify `harness` on the RAW prefix, no trim (`HARNESS_PREFIXES`: `<agent-message from=` / `<task-notification>` / `<\cross-session-message` / `<cross-session-message` — the escaped cross-session form is the one escaped tag that classifies; as measured on 2.1.287 a real cross-session message arrived unescaped under `from` / `from-name` / `from-mode`, and a `<task-notification>` typed at a prompt's very start arrives as typed and is filed `harness`), then unwrap only the CLI's unescaped same-id pair `<pasted_content id="X">\n…\n</pasted_content id="X">` together with the frame the CLI writes around it (the two newlines directly before the open tag, the one directly after the close tag, and a second after it when text follows that is not the next pair's own two-newline frame; a third before, a second after at the prompt's end and a lone one before stay, an unmatched open tag removes nothing; one id serves every pair of a session), then un-escape `<\` before an ASCII letter or `/` — a typed pair is never unwrapped. A pasted text's last newline never reaches the hook (measured on 2.1.287, wrapped or not), so `text` lacks it and a `send` ending in a newline is not claimed (architecture [Delivery Confirmation], unfixed). The frame beside typed text and between two pairs is unit-held and unprobed (`viola verify` types only lone pastes), and no probe is owed: a shape no `send` relies on needs none (the founder's ruling, 2026-10-07).
- `ledger` module (as landed, pure, no I/O): `LedgerRow`, ten closed rows `shim-resolution` · `spine-hooks` · `session-start-fields` · `prompt-verbatim` · `stop-message` · `largest-hook-payload` · `modal-signature` · `input-box-signature` · `quiet-period` · `confirm-window`; `TypedRun`, `Probes { print, typed }`; `PROBE_PROMPT`; `CAPTURE_EVENTS`; `parse_version` (first line exactly `X.Y.Z (Claude Code)`); `capture_plugin_files` (plugin `viola-verify-probe`, four exec-form `--capture` hooks); `check(row, &Probes)`, `largest`; `merge_stamp` (writes `measured.typed_probe`), `verified` (every row `pass`); `scrub`, `is_clean` (reads through `unclean`), `signature_rows`, `screen_is_clean`, `screen_fault` → `ScreenFault { row, seam, why }`, `unclean` → the closed `Unclean` codes `home-path` · `absolute-path` · `username` · `email`. `verified` returns `Result<bool, AgentError>`: a wrong-shaped envelope is `AgentError::StampsMalformed` ("the capability stamps are malformed"). `AgentError` sits at the crate root; the pre-existing `Refusal` beside it is the one open divergence (arch [Error Handling]). `CASE_INSENSITIVE` and `is_script` are `pub` for `verify`.
- An unlisted CLI version → transport-only: types, runs the wheel, emits events, withholds dialog answers (`unverified-cli`).
- R8 (`plan_strip`, names only): every inherited `CLAUDE*` name (ASCII case-insensitive on Windows, exact on Unix) is removed unless it is in the persistent set (Windows registry `Environment` names, Unix `config.json` `claude_env_keep`); an `IDENTITY_FLOOR` name (11, measured) is removed regardless. Logged as `env_stripped_count` + `env_stripped_known` + `env_kept` — never values.
- `resolve_program`: PATH × PATHEXT on Windows (never the bare name); `claude.cmd`/`.bat` → sibling `node_modules/@anthropic-ai/claude-code/bin/claude.exe` when it is a file, the shim never read; any other `.cmd`/`.bat` → `Refusal::BatchScriptChild`.

## Crate-specific gotchas
- ExitPlanMode approves only through PreToolUse, as `allow` + `updatedInput` set to the tool's own input (a bare `allow` left the plan dialog up on live 2.1.288); PermissionRequest `allow` is ignored for it (measured twice).
- Local commands fire no UserPromptSubmit; `/clear`'s post-condition is SessionStart `clear` + a new `session_id`.
- The fixture recorder rewrites home paths to `~` and usernames to `<user>`; probe prompts are synthetic.
