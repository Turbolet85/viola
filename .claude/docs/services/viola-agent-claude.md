## Responsibility
The only crate that knows Claude Code (test-only exceptions: the live rig in `viola-e2e` reads the key names and the source word of its own captured UserPromptSubmit payload and the cachedChromeExtensionInstalled key name, never a value, and its own captured StopFailure payload's key names, error word (one of the CLI's 13, else `other`) and two text lengths, never a text, and seeds its private Claude config; VH reads the real config's key names and a needle, never a value; the fake agent and the rig read a config's trust record). It parses hook payloads tolerantly and maps each hook to a normalised kind. It maps dialog answers to decision bodies (S3 / S7 / S8) and applies the R8 `CLAUDE*` strip. It resolves the child program (`resolve_program`: a given path as given, a bare name on `PATH`) and holds the Claude-specific half of the CLI version gate: the capability ledger rows (compiled) with their `viola verify` checks, `parse_version`, the stamp merge and `verified` verdict, and the fixture scrub. The gate's spawn is the root bin's `run::version_gate`; the stamps I/O is `viola_state::stamps`. It keeps the vt100 screen signatures (readiness gate), parses, in the pure `agents` module, a `claude agents --json` answer (`parse` into rows or a closed `AgentsFailure`, `oversize` · `malformed`; the read itself is the root bin's `run::agents`), and normalises `prompt-submitted` (removes the long-paste wrapper, then reverses tag escaping; classifies `origin` human/harness; the wrapper sets `driver` only on the in-flight send's own prompt and relabels a CLI-fired scheduled wake `harness`). It also holds the resume shapes `viola revive` launches with (`viola verify`'s Run E is the second caller of `resume_args(id, false)`): `PROGRAM` (`claude`), `RESUME_FLAG`, `FORK_SESSION_FLAG`, `is_session_id` (36 characters, hyphens at offsets 8, 13, 18, 23, ASCII hex elsewhere) and `resume_args(id, fork)`; it is the one product home of the two flag literals. It also holds the pure `marketplace` module, `viola plugin install`'s three documents built by `serde_json` (`marketplace_files`; `NAME` the marketplace `viola`, `PLUGIN_REF` `viola@viola`; its `.mcp.json` registers the MCP server `viola`, no hooks). No adapter trait yet: a second agent arrives as a sibling `viola-agent-<name>` crate, at which point the adapter trait is extracted into `viola-core`.

## Internal conventions
- Decision bodies: PreToolUse `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"allow","updatedInput":{…}}}` (questions incl. `annotations`; plan approve); PermissionRequest `decision.behavior` allow/deny + `message` (plan revise), and for a question first raised by PermissionRequest with no matching armed dialog `decision` `{"behavior":"allow","updatedInput":…}` (the tool's input plus answers and annotations). No decision = exit 0 with empty stdout.
- Security-deciding fields map into closed enums even under tolerant parsing; every external reader bounded by `Read::take(MAX_FRAME)`.
- No status-line interception: no settings layer, no `--settings` at start, no `statusLine` source read and no status-line command run; the crate still holds the `--settings` flag (`SETTINGS_FLAG`) that `viola verify` reads, and the stamps no longer carry the two status-line row ids.
- Ledger rows (S3, S7, S8, R8 identity floor, shim resolution, harness prefixes, `<pasted_content>` wrapper, modal / input-box signatures, hook tier map, turn end without Stop, dialog concurrency, `claude agents --json` join field (row `agents-join` since chunk 2026-10-16-unwrapped-sessions-on-the-board: both `pid` and `sessionId` exposed, relied on every build), local commands + post-conditions, tag escaping, largest hook payload) are compiled here, never built from runtime or upstream text.
- `dialog` module (pure, as landed): `DialogKind`, `DialogTool`, `Dialog`, `classify` (one dialog payload → its closed kind / tool; malformed → `AgentError::DialogMalformed`, the hook fails open; a `question`'s data is `{dialog_id, questions:[{question, header, options:[<label>], option_details:[{description, preview}], multi_select}]}`, `option_details` one per option, each field the option's string or `null`, a missing or non-string value never refusing the dialog, the option text upstream content never written into a human line), `Response::{parse, free_text, to_value}`, `decision_body` (the S3 / S7 / S8 bodies, insta-pinned in `src/snapshots/`; the S7 approve is `allow` + `updatedInput` echoing the tool's own input), backed by the ledger's four dialog rows (`question-answer` · `plan-approve-revise` · `question-notes` · `dialog-concurrency`); `ledger::probe_body` reaches it for `viola verify`'s Run C / Run D answers, never a second mapping.
- `hook` module (as landed): `HookEvent` (10 registered events, `StopFailure` among them, the dialog tier `PreToolUse` / `PermissionRequest` included; `from_arg`, `kind()` — an `Option<EventKind>`, `None` for the dialog tier — `is_dialog()`, `as_str` = diag-line `$defs.hook_event`), `normalise(event, bytes) -> Normalised{kind, data, drift}` (StopFailure (`viola hook stop-failure`) maps to `turn-ended`, not a dialog, its data exactly `last_assistant_message` null, `background_tasks` null, `scheduled_wakes` null and `cause` one of the nine TurnEndCause words, classified from the CLI's error word inside the Claude adapter (a word outside the CLI's known words reads `api-error`); Stop's `turn-ended` data is `{last_assistant_message, background_tasks, scheduled_wakes}`, with no `cause`: `background_tasks` the payload array's length only, no element read or carried, `null` when the key is absent, `null` or not an array; `scheduled_wakes` the Stop payload's `session_crons` array length only, no element read or carried, `null` when the key is absent, `null` or not an array, and on an API-error turn end). A wrong-typed known field → a drift entry `{path, expected:"string"}` and read as absent. Prompt order: classify `harness` on the RAW prefix, no trim (`HARNESS_PREFIXES`: `<agent-message from=` / `<task-notification>` / `<\cross-session-message` / `<cross-session-message` — the escaped cross-session form is the one escaped tag that classifies; as measured on 2.1.287 a real cross-session message arrived unescaped under `from` / `from-name` / `from-mode`, and a `<task-notification>` typed at a prompt's very start arrives as typed and is filed `harness`), then unwrap only the CLI's unescaped same-id pair `<pasted_content id="X">\n…\n</pasted_content id="X">` together with the frame the CLI writes around it (the two newlines directly before the open tag, the one directly after the close tag, and a second after it when text follows that is not the next pair's own two-newline frame; a third before, a second after at the prompt's end and a lone one before stay, an unmatched open tag removes nothing; one id serves every pair of a session), then un-escape `<\` before an ASCII letter or `/` — a typed pair is never unwrapped. A pasted text's last newline never reaches the hook (measured on 2.1.287, wrapped or not), so `text` lacks it. No `send` relies on this: `typed_text(text)` returns a sent text with every CR LF pair as one LF, every other CR as one LF, and without its trailing CR and LF characters, every one of them in any order (a `Cow<'_, str>`, borrowed unless an inner CR is replaced; it holds no CR, and nothing else changes: not a TAB, a space, or an LF that is not at the very end), and the root bin's `send` types and classifies that typed text and matches a `prompt-submitted` text equal to it, or non-empty and equal to it less its trailing run of ASCII space, TAB, CR and LF, the text kept as submitted; the client's `refusal_of` is its second product caller (the founder's rulings, 2026-10-07T15:21Z for a trailing LF, 2026-10-09 for a trailing CR and CRLF, 2026-10-09T16:51Z for a CR or a CR LF inside; architecture [Delivery Confirmation]). An LF typed inside a paste is submitted unchanged (as measured on 2.1.287 at chunk 2026-10-09-inner-cr-and-crlf-in-a-sent-text); every multi-line `send` relies on it, and it is gated by the ledger row `paste-newline` and its `viola verify` probe, Run B's `PROBE_NEWLINE_PASTE` (landed at chunk 2026-10-13-paste-newline-ledger-row, stamped on live 2.1.287 on the Linux dev host). The frame beside typed text and between two pairs is unit-held and unprobed (`viola verify` types only lone pastes), and no probe is owed: a shape no `send` relies on needs none (the founder's ruling, 2026-10-07). StopFailure is registered with no ledger row and no verify probe.

## Crate-specific gotchas
- ExitPlanMode approves only through PreToolUse, as `allow` + `updatedInput` set to the tool's own input (a bare `allow` left the plan dialog up on live 2.1.288); PermissionRequest `allow` is ignored for it (measured twice).
- Local commands fire no UserPromptSubmit; `/clear`'s post-condition is SessionStart `clear` + a new `session_id`; `/compact`'s is a SessionStart `compact` with the session's own `session_id` (row `local-command-compact`, its own 40 s PROVISIONAL `COMPACT_CONFIRM_WINDOW`), so its `send` is confirmed on a verified CLI and `unconfirmable` at once only on an unverified one; a stdout-echo command's is a new `<local-command-stdout>` tag counted in the session transcript past its end recorded before the paste (only a count crosses, never content, the read bounded by `MAX_FRAME`), and it is `unconfirmable` at once with no readable transcript.
- The fixture recorder rewrites home paths to `~` and usernames to `<user>`; probe prompts are synthetic.
