# viola-agent-claude

_Crate implementation notes. Primary source: `.andromeda/architecture.md` [Agent Coverage], [CLI Version Compatibility], [Screen Model], [Delivery Confirmation], [Hook Contract], §Conventions (Hook → kind map); security §Input Validation, §Secret Management; obs D-34. ## Responsibility
The only crate that knows Claude Code. It parses hook payloads tolerantly and maps each hook to a normalised kind. It maps dialog answers to decision bodies (S3 / S7 / S8) and applies the R8 `CLAUDE*` strip. It resolves the npm shim to `claude.exe` and holds the Claude-specific half of the CLI version gate: the capability ledger rows (compiled) with their `viola verify` checks, `parse_version`, the stamp merge and `verified` verdict, and the fixture scrub. The gate's spawn is the root bin's `run::version_gate`; the stamps I/O is `viola_state::stamps`. It keeps the vt100 screen signatures (readiness gate), parses the statusline `rate_limits` and, in the pure `agents` module, a `claude agents --json` answer (`parse` into rows or a closed `AgentsFailure`, `oversize` · `malformed`; the read itself is the root bin's `run::agents`), and normalises `prompt-submitted` (removes the long-paste wrapper, then reverses tag escaping; classifies `origin` driver/human/harness). It also holds the resume shapes `viola revive` launches with (`viola verify`'s Run E is the second caller of `resume_args(id, false)`): `PROGRAM` (`claude`), `RESUME_FLAG`, `FORK_SESSION_FLAG`, `is_session_id` (36 characters, hyphens at offsets 8, 13, 18, 23, ASCII hex elsewhere) and `resume_args(id, fork)`; it is the one product home of the two flag literals. It also holds the pure `marketplace` module, `viola plugin install`'s three documents built by `serde_json` (`marketplace_files`; `NAME` the marketplace `viola`, `PLUGIN_REF` `viola@viola`; its `.mcp.json` registers the MCP server `viola`, no hooks). No adapter trait yet: a second agent arrives as a sibling `viola-agent-<name>` crate.

## Internal conventions
- Decision bodies: PreToolUse `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"allow","updatedInput":{…}}}` (questions incl. `annotations`; plan approve); PermissionRequest `decision.behavior` allow/deny + `message` (plan revise). No decision = exit 0 with empty stdout.
- Security-deciding fields map into closed enums even under tolerant parsing; every external reader bounded by `Read::take(MAX_FRAME)`.
- The pure `statusline` module (as landed; chrono for it, no file, clock or environment read): `reading` (the payload's `rate_limits` into a `BudgetReading`; `resets_at` as epoch seconds or RFC 3339), `user_command` (a `statusLine` of type `command`, non-empty, no NUL), `override_document` and `shell_argv` (`/bin/sh -c`; both `None` on Windows), `SETTINGS_FLAG`, `USER_SETTINGS`, `WRAPPED_HERE` (the status line is wrapped: Unix), `BIN_SH`, `SHELL_FLAG` and `probe_document` (the document behind Run B's probe `--settings`, `typed/statusline.json`). Its three CLI shapes are the ledger rows `statusline-override` · `statusline-shell` · `statusline-rate-limits` (since chunk 2026-10-13-owed-ledger-rows), relied only where the status line is wrapped (`WRAPPED_HERE`, Unix); their Windows legs are owed to "Windows-only live measurements" (architecture, Capability ledger).
- Ledger rows (S3, S7, S8, R8 identity floor, shim resolution, statusline `rate_limits.*`, the settings-override mechanism and the shell (rows `statusline-override` · `statusline-shell` · `statusline-rate-limits` since chunk 2026-10-13-owed-ledger-rows, relied on Unix only), harness prefixes, `<pasted_content>` wrapper, modal / input-box signatures, hook tier map, turn end without Stop, dialog concurrency, `claude agents --json` join field (row `agents-join` since chunk 2026-10-16-unwrapped-sessions-on-the-board: both `pid` and `sessionId` exposed, relied on every OS), local commands + post-conditions, tag escaping, largest hook payload) are compiled here, never built from runtime or upstream text.
- `dialog` module (pure, as landed): `DialogKind`, `DialogTool`, `Dialog`, `classify` (one dialog payload → its closed kind / tool; malformed → `AgentError::DialogMalformed`, the hook fails open), `Response::{parse, free_text, to_value}`, `decision_body` (the S3 / S7 / S8 bodies, insta-pinned in `src/snapshots/`; the S7 approve is `allow` + `updatedInput` echoing the tool's own input), backed by the ledger's four dialog rows (`question-answer` · `plan-approve-revise` · `question-notes` · `dialog-concurrency`); `ledger::probe_body` reaches it for `viola verify`'s Run C / Run D answers, never a second mapping.
- `hook` module (as landed): `HookEvent` (9 registered events, the dialog tier `PreToolUse` / `PermissionRequest` included; `from_arg`, `kind()` — an `Option<EventKind>`, `None` for the dialog tier — `is_dialog()`, `as_str` = diag-line `$defs.hook_event`), `normalise(event, bytes) -> Normalised{kind, data, drift}`. A wrong-typed known field → a drift entry `{path, expected:"string"}` and read as absent. Prompt order: classify `harness` on the RAW prefix, no trim (`HARNESS_PREFIXES`: `<agent-message from=` / `<task-notification>` / `<\cross-session-message` / `<cross-session-message` — the escaped cross-session form is the one escaped tag that classifies; as measured on 2.1.287 a real cross-session message arrived unescaped under `from` / `from-name` / `from-mode`, and a `<task-notification>` typed at a prompt's very start arrives as typed and is filed `harness`), then unwrap only the CLI's unescaped same-id pair `<pasted_content id="X">\n…\n</pasted_content id="X">` together with the frame the CLI writes around it (the two newlines directly before the open tag, the one directly after the close tag, and a second after it when text follows that is not the next pair's own two-newline frame; a third before, a second after at the prompt's end and a lone one before stay, an unmatched open tag removes nothing; one id serves every pair of a session), then un-escape `<\` before an ASCII letter or `/` — a typed pair is never unwrapped. A pasted text's last newline never reaches the hook (measured on 2.1.287, wrapped or not), so `text` lacks it. No `send` relies on this: `typed_text(text)` returns a sent text with every CR LF pair as one LF, every other CR as one LF, and without its trailing CR and LF characters, every one of them in any order (a `Cow<'_, str>`, borrowed unless an inner CR is replaced; it holds no CR, and nothing else changes: not a TAB, a space, or an LF that is not at the very end), and the root bin's `send` types, classifies and matches that typed text; the client's `refusal_of` is its second product caller (the founder's rulings, 2026-10-07T15:21Z for a trailing LF, 2026-10-09 for a trailing CR and CRLF, 2026-10-09T16:51Z for a CR or a CR LF inside; architecture [Delivery Confirmation]). An LF typed inside a paste is submitted unchanged (as measured on 2.1.287 at chunk 2026-10-09-inner-cr-and-crlf-in-a-sent-text); every multi-line `send` relies on it, and it is gated by the ledger row `paste-newline` and its `viola verify` probe, Run B's `PROBE_NEWLINE_PASTE` (landed at chunk 2026-10-13-paste-newline-ledger-row, stamped on live 2.1.287 on the Linux dev host only; its Windows reading owed to "Windows-only live measurements"). The frame beside typed text and between two pairs is unit-held and unprobed (`viola verify` types only lone pastes), and no probe is owed: a shape no `send` relies on needs none (the founder's ruling, 2026-10-07).

`ShellVerdict`, `StatusLineCapture`, `statusline_variants` (`StatusLine.default-1.json`, `StatusLine.rate-limits-1.json`) and the `StatusLine.<k>` file-name helpers; `resume_target` (Run E's target id: the `session_id` of Run B's first SessionStart capture, only when `is_session_id` accepts it) and `resume_variants` (`SessionStart.resume-1.json`); Run B's six compiled paste texts (`PROBE_PROMPT`, `PROBE_NEWLINE_PASTE` (113 bytes, ASCII, exactly one LF at neither end, no CR) and `PROBE_COMPACT_COMMAND` (the list's `/compact`) among them); `FRAMING_TURNS` (in paste order `paste-1` · `paste-2` · `paste-3` · `compact-1` · `clear-1`) and `framing_stem`; - An unlisted CLI version → transport-only: types, runs the wheel, emits events, withholds dialog answers (`unverified-cli`).
- R8 (`plan_strip`, names only): every inherited `CLAUDE*` name (ASCII case-insensitive on Windows, exact on Unix) is removed unless it is in the persistent set (Windows registry `Environment` names, Unix `config.json` `claude_env_keep`); an `IDENTITY_FLOOR` name (11, measured) is removed regardless. ## Crate-specific gotchas
- ExitPlanMode approves only through PreToolUse, as `allow` + `updatedInput` set to the tool's own input (a bare `allow` left the plan dialog up on live 2.1.288); PermissionRequest `allow` is ignored for it (measured twice).
- Local commands fire no UserPromptSubmit; `/clear`'s post-condition is SessionStart `clear` + a new `session_id`; `/compact`'s is a SessionStart `compact` with the session's own `session_id` (row `local-command-compact`, its own 40 s PROVISIONAL `COMPACT_CONFIRM_WINDOW`), so its `send` is confirmed on a verified CLI and `unconfirmable` at once only on an unverified one.
- The fixture recorder rewrites home paths to `~` and usernames to `<user>`; probe prompts are synthetic.
