# viola-pty

_Crate implementation notes. Primary source: `.andromeda/architecture.md` [PTY], §Crate dependency direction; security §Data Protection (handle inheritance), §Input Validation (child executable resolution). Generated by `/andromeda-setup-project`._

## Responsibility
viola's own PTY seam over portable-pty `=0.8.1`: spawn · read · write · resize · wait · kill. It hosts the unmodified `claude` (or the fake agent) in ConPTY on Windows and openpty on Unix. It knows no agent and depends on no viola crate. Child exit is detected on the process handle, never on reader EOF. If 0.8.1's Windows `kill()` misbehaves, the fallback is `TerminateProcess` on `child.process_id()` via windows-sys.

## Key integrations

### Consumes from
portable-pty `=0.8.1`; windows-sys 0.61.2 (Windows only, kill fallback).

### Publishes to
The root bin's `run` pump (`src/run/`) and the tests' outer-PTY driver (`tests/support/outer_pty.rs`, `viola-harness supervise`).

### Dependencies
No viola crate. Tokio banned in its graph.

## Internal conventions
- The seam is a trait the product defines, so consumers are tested with a mockall double whose reader never returns EOF while `wait()` returns an exit status.
- `CreateProcessW` is called with `bInheritHandles = 0`: channel handles never leak into the child. Any replacement (the named candidate is portable-pty-psmux 0.9.7) must keep this.
- The PTY byte stream is user content — never logged; spans log `pty_backend` (`conpty|openpty`), `text_bytes`, `exit_source` (`handle-wait|kill-fallback`).

## Crate-specific gotchas
- ConPTY does not close the output stream on exit — detect exit only via `wait()`.
- 0.9.0 has the Windows garbage-read bug (wezterm#6783); the pin is re-decided on current evidence by the PTY chunk (requirements v1-25).
- `.cmd` / `.bat` children are refused before spawn (portable-pty bypasses std's BatBadBut escaping).

## Entry points for modification
- **Seam trait + portable-pty adapter:** `crates/viola-pty/src/`
- **Kill fallback:** `#[cfg(windows)]` module
- **Tests:** crate `tests/` spawning `viola-fake-agent` through real ConPTY/openpty (no-EOF mode, resize, `.cmd` refusal)

## Testing this crate
- **Unit tests:** `cargo nextest run -p viola-pty`
- **Integration:** real ConPTY / openpty spawn of the fake agent; run on all three CI OSes
- **Chaos:** the `--exit-no-eof` fake mode (a grandchild holds the slave open on Unix; native on ConPTY)
