## Responsibility
The `viola` binary. It holds the clap 4.6.7 dispatch (`src/main.rs`, one module per subcommand in `src/cmd/`) and the `run` wrapper (`src/run/`): the PTY pump, the wheel, the budget governor, the readiness-gate wiring and the channel server dispatch. It also owns the pinned copy + plugin write-out, the obs init (`viola::obs`: `MillisUtc`, `viola_obs_init`, the panic hook, the detail writer, the catch-site reporter `report_internal_error`) and the human/`--json` output modules. It is the only crate with anyhow (dispatch edge and the catch-site reporter) and tracing-subscriber, and it consumes only normalised events.

## Key integrations

### Consumes from
Every workspace member; clap, anyhow, tracing-subscriber, chrono (direct, for `MillisUtc`), windows-sys (Windows only: VT enable, console width, and the registry value-name reader for the R8 persistent set in `src/run/env.rs`).

### Publishes to
Users (human CLI), drivers (`--json`, exit codes), Claude Code (hook decision bodies via `viola hook`, the MCP server via `viola mcp`), the page (`viola ui`).

### Dependencies
The root package also declares `[[bin]] viola-fake-agent` (`required-features = ["fake-agent"]`) — never in `cargo build --release --bin viola`.

## Internal conventions
- `run` start order: collision check → pinned copy (SHA-256 re-hash on reuse) + plugin folder rewrite → version gate (`--version` probe) → exclusive endpoint bind → first snapshot + heartbeat → `wheel` + `budget-gate` events → child spawn (R8 strip, `VIOLA_NAME` / `VIOLA_DIR` / `VIOLA_BIN`, pinned folder first on PATH, `--plugin-dir`). A live endpoint or `stale` heartbeat → exit 1.
- `run` writes nothing to the terminal while the child runs; human bytes are never blocked beyond the current atomic paste (`ESC[200~…ESC[201~` + CR, one write); any human editing key since the last turn boundary moves the wheel to `human`; focus/mouse/resize never do; harness-injected prompts never do.
- Wheel / budget / dialog rules as in arch: `send` during a running turn → `turn-running`; `pause` → `manual-pause`; only CLI `release` returns the wheel; `budget-paused` gates `send` only; a pending dialog is answered `null` at once when the wheel moves to the human.
- Obs init order is fixed: panic hook first → clap → home/instance/role → strict-modes → diagnostics → `config.json` → subscriber → `process-start`. Everything after `set_hook` runs inside one `catch_unwind`; the role is taken from argv before clap (`viola --home <dir> hook stop` is still a hook).
- Output: colour decision order, stdout/stderr split, `[RB]` mirror, cause-specific `hint:` lines, C0/C1 escaping (see `rules/frontend.md`).

## Crate-specific gotchas
- A viola bug must never block the user's session: `viola hook` exits 0 on clap errors, channel failures and caught panics.
- An anyhow chain holding a serde source is replaced by the fixed `internal error` before stderr; the full chain goes to `detail-<process>.ndjson`.
- `plugin.json`'s version comes from `CARGO_PKG_VERSION`; the content hash in `bin/`/`plugin/` keys dev rebuilds (a hook fix applies only to sessions started after the rebuild).

## Entry points for modification
- **Dispatch:** `src/main.rs`, `src/cmd/<subcommand>.rs`
- **Wrapper:** `src/run/` (pump, wheel, governor, gate wiring)
- **Obs init / panic hook / detail writer:** `viola::obs`
- **Fake agent:** `src/bin/viola-fake-agent.rs`
- **Tests:** inline unit tests (exit-code mapping, wheel state machine, thresholds, confirmation matcher, `wait` handler with an injected clock, refusal order); root `tests/{cli,hook,tui,channel,chaos,contract}_*.rs`
