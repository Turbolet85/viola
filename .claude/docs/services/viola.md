_Crate implementation notes. Primary source: `.andromeda/architecture.md` §Crate dependency direction, [Human Takeover / Wheel], [Budget Governor], [Session Liveness] (start order), [Deployment / Distribution], [CLI Conventions]; obs §3 Init order, §7 Panic hooks. ## Responsibility
The `viola` binary. It holds the clap 4.6.7 dispatch (`src/main.rs`, one module per subcommand in `src/cmd/`) and the `run` wrapper (`src/run/`): the PTY pump, the wheel, the budget governor, the readiness-gate wiring and the channel server dispatch. It also owns the pinned copy + plugin write-out, the obs init (`viola::obs`: `MillisUtc`, `viola_obs_init`, the panic hook, the detail writer, the catch-site reporter `report_internal_error`; `open_role_file` and `write_detail` run `strict::check_diagnostics` on an existing `diagnostics/` folder and on the role or detail file before `ensure_private_dir` narrows anything — a symbolic link refused, a folder to the read rule, a file to the read rule on Unix and the write rule on Windows, an absent path passing — and a refusal is a failed open: the writer ends at `std::io::sink`, a detail line is dropped) and the human/`--json` output modules (the `human` module: `src/human.rs`, with its phases under `src/human/` — mirror, escape, board, style (the colour layer: `Depth`, `Tokens`, `Facts`, `decide`, `read`, the Windows VT enable and its restoring guard), wait, verbs, hints —; `src/human.rs` holds the stderr refusal writer `write_refusal` behind `refuse`, the stderr `write_internal_error` (`error: internal error\n`) behind `internal_error`, and the stdout `write_result` behind `result`, each one `write_all`; called by `run`, `revive`, `verify`, `send`, `wait`, `last`, `list`, `answer`, `pause`, `release`, `plugin install` and the `main` catch site; no print macro, no `#[allow]`). `viola verify` (`src/cmd/verify.rs`) drives the one print-mode probe and then the five interactive PTY runs (`src/cmd/verify/typed.rs` and its children under `src/cmd/verify/typed/`: Run A untrusted in an OS-temp dir, Run B trusted in `<cwd>/.viola-verify-<pid>/` (on Unix, for shell-plain paths only, also one `--settings <probe dir>/typed/statusline.json` after its `--plugin-dir` pair, whose status line command `<pinned viola> hook statusline --capture <probe dir>/typed/statusline --shell "$0"` files each status line payload with its shell verdict; none on Windows) with six compiled pastes — the probe prompt, then the long text, the tag-like text, the newline text (`PROBE_NEWLINE_PASTE`, 113 bytes, one inner LF), `/compact` (`PROBE_COMPACT_COMMAND`) and `/clear`, each added one only into a settled input box, waited for after an added text turn and after the `/compact` turn up to `PROBE_DEADLINE` (`box_wait`: 2.1.287 shows a paste hint in the input-box literal's place for 8.0 s after a long paste) — and, once its first turn has settled and before its framing pastes, ONE `claude agents --json` read (`typed::turns::agents_read`: Run B's program, cwd the probe dir, the R8 strip, `VERSION_DEADLINE`, none once a stop is read; its capture kept in memory, never written to the captures dir; no live start added; in CI the fake agent's `agents` mode answers it), Run C's dialogs in `-dialogs/`, Run D's plan in `-plan/`, then last Run E trusted in `-resume/`, resuming Run B's first session with `--resume <id>` (`viola_agent_claude::resume_args(id, false)`, the id Run B's first SessionStart `session_id` through `ledger::resume_target`; empty input, no `--settings`, ended by a kill); no key into any dialog — the hidden `hook --capture --answers` arm in `src/cmd/hook.rs` answers C and D's from `PROBE_ANSWERS`), checks the relied ledger rows (`check_rows` walks `LedgerRow::relied()`: on Unix all twenty-four of `LedgerRow::ALL`, the last `local-command-compact`; on Windows twenty-one, the first eighteen, `resume-session`, `agents-join` and `local-command-compact`, the last `local-command-compact`), prints the step lines and `stamped` summary and writes the stamps through `viola_state::stamps::update_stamps` (its `StampsError::StrictModes` refusal printing the home-state pair, exit 1); before its `cli` log opens it runs `viola_state::strict::check_home_tree(home, None, None)` (the home, `ledger/`, `bin/` and `plugin/`, each that exists), a refusal printing the home pair and exiting 1 with no step line, no summary and no line; a verify stopped by Ctrl-C or TERM (`cmd::verify::stop`: Unix `SIGINT` / `SIGTERM`, Windows `CTRL_C_EVENT` / `CTRL_BREAK_EVENT`, installed by `viola verify` alone, its handler only setting one process-global flag that every wait of the run reads) kills and reaps the running child with no key, starts no later run, writes no stamp and exits 1 (`unable: verify was stopped before it finished` / `hint: run viola verify again to stamp this CLI`, stdout empty), its drop guards removing only the dirs that run created; SIGKILL, a crash, a failed handler install and a Windows close, logoff or shutdown keep the OS default and leave the dirs to be removed by hand; `run::version_gate` reads them at `run` start. The panic detail backtrace is raw, never-symbolised frames (`src/panic_frames.rs`). It is the only crate with anyhow (dispatch edge and the catch-site reporter) and tracing-subscriber, and it consumes only normalised events.

## Key integrations

### Consumes from
Every workspace member; clap, anyhow, tracing-subscriber, chrono (direct, for `MillisUtc`), windows-sys (Windows only: `GetConsoleMode` / `SetConsoleMode` for `src/human/style.rs`'s VT enable on stdout — `ENABLE_VIRTUAL_TERMINAL_PROCESSING` (`0x0004`) alone, never viola-pty's `0x000c`, made only once every no-colour rung has passed in `viola list`'s human mode, the saved mode restored on drop, a failed get or set writing no colour and changing no mode, no dependency or feature added —, the registry value-name reader for the R8 persistent set in `src/run/env.rs`, and `RtlCaptureStackBackTrace` / `GetModuleHandleExW` / `GetModuleFileNameW` for `src/panic_frames.rs`, and `SetConsoleCtrlHandler` (`Win32_System_Console`) for `src/cmd/verify/stop.rs`'s console routine, where Ctrl-C and Ctrl-Break set verify's stop and every other event keeps the OS default); libc (Unix only: `backtrace` + `dladdr` for the raw panic frames, and `sigaction` for `src/cmd/verify/stop.rs`'s `SIGINT` / `SIGTERM` handler, `SA_RESTART`; neither stop role added a dependency or a feature); tempfile (`=3.27.0`, workspace-pinned: `viola verify`'s Run A temp dir only).

### Publishes to
Users (human CLI), drivers (`--json`, exit codes), Claude Code (hook decision bodies via `viola hook`, the MCP server via `viola mcp`).

### Dependencies
The root package also declares `[[bin]] viola-fake-agent` (`required-features = ["fake-agent"]`) — never in `cargo build --release --bin viola`.

## Internal conventions
- `run` start order (before the wrapper log opens, every start, `run`'s and a revived one, checks the home tree: `checked_exe` reads the exe's bytes once and takes their pin key, then `viola_state::strict::check_home_tree` checks the home, the instance's set, `ledger/`, `bin/`, `plugin/`, `bin/<key>/`, the pinned copy, `plugin/<key>/` and its `hooks/` and `.claude-plugin/`, each that exists — a refusal is exit 1 with the home pair, or the instance pair for an instance-level refusal, no log opened, no line and no child —, and the pin step pins those same bytes through `pin_bytes`; the home is canonicalised by `canonical_home` once the wrapper log has created it, before the collision check, the pin and the endpoint bind): program resolution (`.cmd`/`.bat` refusal) → collision check → pinned copy (SHA-256 re-hash on reuse; a mismatch → exit 1 `pinned-hash-mismatch`) + plugin folder rewrite → ConPTY sideload (Windows, span `run.conpty_sideload` {`outcome` `loaded|hash-mismatch|strict-modes-failed|unreadable|load-failed|not-built`, `search_restricted`}: `pin_companions` of `src/conpty.rs`'s embedded `OpenConsole.exe` + `conpty.dll` into `bin/<key>/conpty/`, then the absolute-path pre-load; never a refusal — any other outcome leaves the child on the inbox ConPTY and adds `sideload_fallback` to the `claude-child` `process-start`; the held handles live until `spawn_child` returns) → strip plan → version gate (`run::version_gate`: `--version` with no user args, killed at 5 s, logged as a `version-probe` start/exit pair; the stamps read; `cli_version` / `cli_verified` into the first snapshot and the `claude-child` `process-start`; nothing printed) → exclusive endpoint bind (taken → exit 1 `squatted-name`) → the budget gate at start (span `run.budget_eval`, `trigger: start`: reads `budget.json`, restores no override, writes nothing) → first snapshot (with `endpoint`; its `budget_paused` that verdict) + heartbeat (the per-session settings override, Unix only, is rewritten after the first snapshot and before the spawn) → `wheel` + `budget-gate` events → child spawn (R8 strip, `VIOLA_NAME` / `VIOLA_DIR` / `VIOLA_BIN`, pinned folder first on PATH, `--plugin-dir`) → snapshot rewritten with `child_pid`. A `live` or `stale` name → exit 1 (`already-live`); a `gone` one is taken over at once. The collision check takes its caller's one snapshot read (`replay::read_snapshot_or_replay`): over a replayed snapshot, which holds no `pid` or `started_at`, it decides from the heartbeat alone, a beat at most `STALE_AFTER` old refusing `already-live` and an older one free; a failed read or no snapshot is free. The first snapshot records the spawn directory as `cwd` when it is valid UTF-8.
- `revive` (`src/cmd/revive.rs`) resumes a `gone` instance through the same `start`: first the strict-modes check (`trusted`: `check_instance` before the wrapper log opens; a refusal is the state-files pair and exit 1 with no log opened and no line), on the start arm then the home-tree check (`checked_exe`, then `refuse_tree`: the home, the instance's `check_instance` set, `ledger/`, `bin/`, `plugin/`, and for the running binary's pin key `bin/<key>/`, the pinned `viola`, `plugin/<key>/` and its `hooks/` and `.claude-plugin/`, each that exists; a refusal prints the home-state pair, or the instance-state pair when the refused path is the instance's, opens no log, writes no line and starts no child, and under `--json` is the `strict-modes-failed` document), then a preflight of four readings in a fixed order, stopping at the first refusal (`session-live` is one `claude agents --json` read: a row whose `sessionId` is the logged id about to be resumed refuses, `--fork` skips it, a failed read passes, its `agents-probe` pair in `run-<name>.ndjson`; `already-live` → `no-session` → `session-live` → `cwd-missing`, each one `human::refuse` pair and one `process-exit{exit_code:1}` in `run-<name>.ndjson`), then program `claude` by name on its own `PATH`, child arguments `--plugin-dir <dir>`, `--settings <instance dir>/settings.json` when the start wrote the override, `--resume <id>`, `--fork-session` with `--fork`, then the words after `--`, spawned in the snapshot's recorded `cwd`. It logs as process `run`, replays no launch, and its first record is `wheel{driver, start}`. `--list` prints `<ts>  <cause>  <id>` per logged session; under a parsed `VIOLA_NAME`, once its strict-modes check passed, it writes `process-start` and `process-exit{subject:"self"}` (`exit_code` 0, or 1 `detail:"no-session"` on an empty chain) into the caller's `cli-<VIOLA_NAME>.ndjson`, and with no name opens none. Both arms take `--json` (chunk 2026-10-17-cli-machine-contract): a refused strict-modes check or a preflight refusal prints `{"v":1,"error":"<code>","detail":null}` (`strict-modes-failed` · `already-live` · `no-session` · `session-live` · `cwd-missing`; `client::refused_document`) on stdout in place of its pair, stderr empty, the same exit 1 and the same log lines; `--list --json` prints `{"v":1,"ok":{"sessions":[…]}}` in log order, or the `no-session` document with exit 1; a refusal `run`'s start makes after a passed preflight prints no document (owed to the working-route entry "Exit-cause code catalogue").
- On Windows `viola_pty::sideload::restrict_dll_search()` is the second statement of `main`, in every role (the panic hook is the first): no DLL load of any `viola` process resolves from the CWD or `PATH`.
- The statusline pass-through (`src/cmd/run.rs`, `src/cmd/hook/statusline.rs`): at start `run` reads the user's command from `<home>/statusline-source.json`, else for the default home only (`canonical_home(default_home(user_home))`) the user's `.claude/settings.json`, so a home named by `--home` or reached through `VIOLA_DIR` never reads it, records it as the snapshot's `statusline_command`, and on Unix rewrites `instances/<name>/settings.json` (0600, only for a pinned path of ASCII letters, digits and `_ - . / :`) and passes `--settings`. `viola hook statusline` (with `--capture <DIR>` it takes `viola verify`'s probe capture instead, before the pass-through: no instance check, no `budget.json` write, no command run, nothing printed) canonicalises its instance directory, runs `check_instance` before anything under the home is read or opened (a refused instance: exit 0 at once, no log, no line), reads stdin through `take(MAX_FRAME + 1)`, writes `budget.json` only with a `rate_limits` object, reads the snapshot through `replay::read_snapshot_or_replay` (a replayed one holds no `statusline_command`, so no command runs), then runs the command as one argument of `/bin/sh -c` under `STATUSLINE_DEADLINE` (5 s, PROVISIONAL) and prints its stdout unchanged; always exit 0, empty stderr. On Windows no override is written and no command runs (owed to the route entry "Windows-only live measurements").
- The budget gate (`src/run/budget.rs`, chunk 2026-10-10-budget-governor): one `BudgetGate` per wrapper, no thread and no timer. `read_thresholds` reads `config.json`'s `five_hour` / `seven_day` once at start (defaults 90 / 85; a bad value takes its default with one `parse-rejected` line per key). The pure `decide(reading, thresholds, override_until, now)` crosses a window only when its percentage is known and at or over its threshold and its `resets_at` is a known, parseable, future instant; with both crossed the detail is `five-hour`. Three evaluation points: `start` (the first snapshot's `budget_paused` and record two), a `send`'s arrival (after `human-typing`, before `turn-running`; refusal `budget-paused`, exit 11) and each `turn-ended`. `budget-gate` and the snapshot's `budget_paused` / `budget_override_until` are written only when the triple (paused, window, override end) changes. `release --budget` (`lift`) records `{paused:false, override_until}` only when a pause stands; an override does not outlive its wrapper. Fail-open: no reading, an unknown figure, a passed reset, an unreadable `budget.json` and a bad threshold never pause. `answer`, `wait`, `last`, `pause` and `hook.dialog` do not read the gate. Human lines: `<name>  budget gate lifted until <end>  wheel <holder>` and `<name>  budget gate open  wheel <holder>` (the date form of `<end>` and the open line are the founder's wording).
- The link set (`src/run/links.rs`, chunk 2026-10-10-session-links): one `LinkSet` per wrapper under one lock. `restore` reads the log once at start, beside the wait feed's rebuild and before `server.serve`, through `events::read_from` and `viola_state::replay::apply_link_line`; it appends and logs nothing, and the first snapshot's `links` is the restored set. `record` is called by `send` (after the second wheel and running-turn reads, directly before the send is issued) and by `DialogSlot::answer` (after the kind check, before the answer is taken) when `from` is a name other than the wrapper's own: a pair the set holds writes nothing, a new one appends one `link` line (`source: wrapper`) and writes the set into the snapshot; an error is `-32603`. The served `link` / `unlink` channel methods (`LinkSet::link`, adding the pair through `record`, and `LinkSet::unlink`, removing it through `remove`, its product caller; sharing `driver_of`), sent by `viola link` / `viola unlink` (`src/cmd/link.rs`), read no `from` and answer only after the event line and the snapshot write: a held pair's `link` appends nothing and answers its `since` with `already_linked: true`, a new pair its new `link` line's `ts` with `already_linked: false`; `unlink` answers `{}` whether or not the pair was held, an absent pair appending nothing, a removed one one `unlink` line (`source: wrapper`); a missing, non-string or invalid name, a `driven` that is not the wrapper's own name and a `driver` equal to `driven` are each `-32602` with `data: null` and no line, and a failed record or remove is `-32603`. The module declares no span and emits no `obs_event!` line.
- `run` writes nothing to the terminal while the child runs; human bytes are never blocked beyond the current atomic paste (`ESC[200~…ESC[201~` + CR, one write); any human editing key since the last turn boundary moves the wheel to `human`; only the closed non-editing list never does — focus reports, mouse reports (X10, SGR, urxvt) and terminal replies (DA1, DA2, CPR, DECRPM, kitty flags, OSC, DCS, and seven more after `CSI`, each by exact grammar: `0 n`, `? 997;1 n` and `? 997;2 n`, `4;n;n t`, `6;n;n t`, `8;n;n t`, `48;n;n;n;n t`, `> 4;n m`), founder ruling F-W2, the seven ratified by the founder on 2026-10-08, as measured on foot 1.28.0 at chunk 2026-10-08-first-live-test-and-self-drive; the nearest human keys (`n`, `t`, `m`, their Alt forms, their kitty key events) stay typing — and a resize is no byte; harness-injected prompts never do. On Windows an injected mouse report under the ConPTY's win32-input-mode arrives as typed keys and takes the wheel, and focus reports are swallowed (founder ruling F-W3).
- Wheel / budget / dialog rules as in arch: `send` during a running turn → `turn-running` (the turn lives in memory in `WheelSlot` beside holder and cause: `append_hook_event` marks it on a `prompt-submitted` of any origin and ends it on `turn-ended` / `session-start` / `session-end` before the line is appended; only a `release` that returns a human-held wheel clears it; a human prompt takes the wheel, so the send after it reads `human-typing`); `pause` → `manual-pause`; only CLI `release` returns the wheel; `budget-paused` gates `send` only; a pending dialog is answered `null` at once when the wheel moves to the human.
- Obs init order is fixed: panic hook first → clap → home/instance/role → strict-modes → diagnostics → `config.json` → subscriber → `process-start`. Everything after `set_hook` runs inside one `catch_unwind`; the role is taken from argv before clap (`viola --home <dir> hook stop` is still a hook).
- Output: colour decision order, stdout/stderr split, `[RB]` mirror, cause-specific `hint:` lines, C0/C1 escaping (see `rules/frontend.md`). The colour layer (`src/human/style.rs` `read`, `viola list`'s human mode only, every build) reads, never sets, `NO_COLOR` (present, empty included: colour off), `TERM` (exactly `dumb`: off; containing `256color`: 256 colours) and `COLORTERM` (`truecolor` or `24bit`: truecolor) through `std::env::var_os`, only compared, never echoed, deciding only whether and how deep SGR bytes are written (the founder's own word, chunk 2026-10-17-cli-output-discipline); `COLUMNS`, `CLICOLOR`, `CLICOLOR_FORCE` and `CI` are not read (the board's width is `viola_pty::host_size()`).

## Crate-specific gotchas
- A viola bug must never block the user's session: `viola hook` exits 0 on clap errors, channel failures, a failed server check and caught panics: its event and dialog paths, once their instance check (`trusted`, before the diagnostics level is read and obs is initialised; a refused or absent instance exits 0 at once with no `config.json` read, no role file, no stdin read, no line, no frame and no SessionEnd append) has passed, share one connect (`replay::read_snapshot_or_replay` — a replayed or absent snapshot is an endpoint not reached: the hook fails open with `channel-unreachable` —, then `Client::connect_by`, then `verify_server`), and a serving process whose pid or OS start time is not the snapshot's, or a check that cannot be made, gets no frame — the hook records `server-verify-failed` and exits 0 with no body (the event lost as for an unreachable endpoint, the dialog rendered for the human, SessionEnd falling back to its direct `try_lock` append).
- On Windows a hook fired within milliseconds of the wrapper's exit can still reach the exiting wrapper's pipe (measured 25 ms after the exit line, ci#36532038635; why the pipe outlives the exit is not established). The hook still fails open (exit 0, silent), but its `hook.event` reads as delivered, so `SessionEnd`'s direct-append fallback is skipped in that window. Tests wait for the endpoint to be gone, never for the exit code alone (`gotchas.md`).
- An anyhow chain holding a serde source is replaced by the fixed `internal error` before stderr; the full chain goes to `detail-<process>.ndjson`. A failed or panicked `cli` verb (`role_of` files every first word but `run`, `revive`, `mcp`, `hook` and a leading `-` flag under `cli` (a first word `mcp`, after any `--home <dir>` / `--home=<dir>`, is `Role::Mcp`, whose exit maps like `Other` and which never prints `error: internal error` — `prints_internal_error` stays `Cli`-only), and `revive` followed (after any `--home` pair) by `--list` before a `--` under `cli` too: `send`, `wait`, `last`, `list`, `answer`, `pause`, `release`, `link`, `unlink`, `verify`, `revive --list`, `plugin install`; every other `revive` is a wrapper beside `run`, and its start arm logs as process `run`) prints exactly `error: internal error\n` once, from the `main` catch site and no dispatch arm, with no hint, after its `process-exit{detail:"internal-error"}` line when an instance resolves.
- `verify`'s eight child spawns are each logged as a `process-start`/`process-exit` pair at the call site: the `--version` read as `version-probe`, the print-mode probe as `verify-probe`, each of the five interactive PTY runs (Run A, Run B, Run C, Run D, then Run E) as `verify-pty-probe`, and Run B's `claude agents --json` read as `agents-probe` (obs-plan §6); a child of an interactive PTY run killed at a Ctrl-C or TERM stop closes its pair with `duration_ms` and a `child_exit_status`, the PTY pump's exit code (portable-pty reports a code for a signalled child; a print-mode or `--version` probe child killed at the stop is not measured), a stopped run writes only the pairs it started, and its self exit reads `exit_code:1, detail:"interrupted"`. `run_bounded` itself stays unlogged, because `run`'s version gate shares it and logs its own pair.
- `hook <event> --capture <DIR>` (hidden) is `verify`'s capture arm: no `VIOLA_*`, no obs init, no channel, raw 0600 write, exit 0 always. Its statusline form `hook statusline --capture <DIR> [--shell <WORD>]` (`cmd::hook::capture_statusline`, sole caller Run B's probe settings) files the payload raw at the first free `StatusLine.<k>.json` beside `StatusLine.<k>.shell` holding exactly `bin-sh` or `other` (the word written nowhere), prints nothing and reads no `budget.json` or snapshot.
- `plugin.json`'s version comes from `CARGO_PKG_VERSION`; the content hash in `bin/`/`plugin/` keys dev rebuilds (a hook fix applies only to sessions started after the rebuild).
