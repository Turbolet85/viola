# viola (root bin)

_Crate implementation notes. Primary source: `.andromeda/architecture.md` §Crate dependency direction, [Human Takeover / Wheel], [Budget Governor], [Session Liveness] (start order), [Deployment / Distribution], [CLI Conventions]; obs §3 Init order, §7 Panic hooks. Generated by `/andromeda-setup-project`._

## Responsibility
The `viola` binary. It holds the clap 4.6.7 dispatch (`src/main.rs`, one module per subcommand in `src/cmd/`) and the `run` wrapper (`src/run/`): the PTY pump, the wheel, the budget governor, the readiness-gate wiring and the channel server dispatch. It also owns the pinned copy + plugin write-out, the obs init (`viola::obs`: `MillisUtc`, `viola_obs_init`, the panic hook, the detail writer, the catch-site reporter `report_internal_error`) and the human/`--json` output modules (`src/human.rs` today: the stderr refusal writer `write_refusal` behind `refuse`, the stderr `write_internal_error` (`error: internal error\n`) behind `internal_error`, and the stdout `write_result` behind `result`, each one `write_all`; called by `run`'s start refusals and by `viola verify`; no print macro, no `#[allow]`). `viola verify` (`src/cmd/verify.rs`) drives the one print-mode probe and then the four interactive PTY runs (`src/cmd/verify/typed.rs`: Run A untrusted in an OS-temp dir, Run B trusted in `<cwd>/.viola-verify-<pid>/`, Run C's dialogs in `-dialogs/`, Run D's plan in `-plan/`; no key into any dialog — the hidden `hook --capture --answers` arm in `src/cmd/hook.rs` answers C and D's from `PROBE_ANSWERS`), checks the fourteen ledger rows, prints the step lines and `stamped` summary and writes the stamps through `viola_state::stamps::update_stamps`; `run::version_gate` reads them at `run` start. The panic detail backtrace is raw, never-symbolised frames (`src/panic_frames.rs`). It is the only crate with anyhow (dispatch edge and the catch-site reporter) and tracing-subscriber, and it consumes only normalised events.

## Key integrations

### Consumes from
Every workspace member; clap, anyhow, tracing-subscriber, chrono (direct, for `MillisUtc`), windows-sys (Windows only: VT enable, console width, the registry value-name reader for the R8 persistent set in `src/run/env.rs`, and `RtlCaptureStackBackTrace` / `GetModuleHandleExW` / `GetModuleFileNameW` for `src/panic_frames.rs`); libc (Unix only: `backtrace` + `dladdr` for the raw panic frames).

### Publishes to
Users (human CLI), drivers (`--json`, exit codes), Claude Code (hook decision bodies via `viola hook`, the MCP server via `viola mcp`), the page (`viola ui`).

### Dependencies
The root package also declares `[[bin]] viola-fake-agent` (`required-features = ["fake-agent"]`) — never in `cargo build --release --bin viola`.

## Internal conventions
- `run` start order: program resolution (`.cmd`/`.bat` refusal) → collision check → pinned copy (SHA-256 re-hash on reuse; a mismatch → exit 1 `pinned-hash-mismatch`) + plugin folder rewrite → ConPTY sideload (Windows, span `run.conpty_sideload` {`outcome` `loaded|hash-mismatch|unreadable|load-failed|not-built`, `search_restricted`}: `pin_companions` of `src/conpty.rs`'s embedded `OpenConsole.exe` + `conpty.dll` into `bin/<key>/conpty/`, then the absolute-path pre-load; never a refusal — any other outcome leaves the child on the inbox ConPTY and adds `sideload_fallback` to the `claude-child` `process-start`; the held handles live until `spawn_child` returns) → strip plan → version gate (`run::version_gate`: `--version` with no user args, killed at 5 s, logged as a `version-probe` start/exit pair; the stamps read; `cli_version` / `cli_verified` into the first snapshot and the `claude-child` `process-start`; nothing printed) → exclusive endpoint bind (taken → exit 1 `squatted-name`) → first snapshot (with `endpoint`) + heartbeat → `wheel` + `budget-gate` events → child spawn (R8 strip, `VIOLA_NAME` / `VIOLA_DIR` / `VIOLA_BIN`, pinned folder first on PATH, `--plugin-dir`) → snapshot rewritten with `child_pid`. A `live` or `stale` name → exit 1 (`already-live`); a `gone` one is taken over at once.
- On Windows `viola_pty::sideload::restrict_dll_search()` is the second statement of `main`, in every role (the panic hook is the first): no DLL load of any `viola` process resolves from the CWD or `PATH`.
- `run` writes nothing to the terminal while the child runs; human bytes are never blocked beyond the current atomic paste (`ESC[200~…ESC[201~` + CR, one write); any human editing key since the last turn boundary moves the wheel to `human`; only the closed non-editing list never does — focus reports, mouse reports (X10, SGR, urxvt) and terminal replies (DA1, DA2, CPR, DECRPM, kitty flags, OSC, DCS), founder ruling F-W2 — and a resize is no byte; harness-injected prompts never do. On Windows an injected mouse report under the ConPTY's win32-input-mode arrives as typed keys and takes the wheel, and focus reports are swallowed (founder ruling F-W3).
- Wheel / budget / dialog rules as in arch: `send` during a running turn → `turn-running` (the turn lives in memory in `WheelSlot` beside holder and cause: `append_hook_event` marks it on a `prompt-submitted` of any origin and ends it on `turn-ended` / `session-start` / `session-end` before the line is appended; only a `release` that returns a human-held wheel clears it; a human prompt takes the wheel, so the send after it reads `human-typing`); `pause` → `manual-pause`; only CLI `release` returns the wheel; `budget-paused` gates `send` only; a pending dialog is answered `null` at once when the wheel moves to the human.
- Obs init order is fixed: panic hook first → clap → home/instance/role → strict-modes → diagnostics → `config.json` → subscriber → `process-start`. Everything after `set_hook` runs inside one `catch_unwind`; the role is taken from argv before clap (`viola --home <dir> hook stop` is still a hook).
- Output: colour decision order, stdout/stderr split, `[RB]` mirror, cause-specific `hint:` lines, C0/C1 escaping (see `rules/frontend.md`).

## Crate-specific gotchas
- A viola bug must never block the user's session: `viola hook` exits 0 on clap errors, channel failures and caught panics.
- On Windows a hook fired within milliseconds of the wrapper's exit can still reach the exiting wrapper's pipe (measured 25 ms after the exit line, ci#36532038635; why the pipe outlives the exit is not established). The hook still fails open (exit 0, silent), but its `hook.event` reads as delivered, so `SessionEnd`'s direct-append fallback is skipped in that window. Tests wait for the endpoint to be gone, never for the exit code alone (`gotchas.md`).
- An anyhow chain holding a serde source is replaced by the fixed `internal error` before stderr; the full chain goes to `detail-<process>.ndjson`. A failed or panicked `cli` verb (`role_of` files every first word but `run`, `hook` and a leading `-` flag under `cli`: `send`, `wait`, `last`, `answer`, `pause`, `release`, `verify`) prints exactly `error: internal error\n` once, from the `main` catch site and no dispatch arm, with no hint, after its `process-exit{detail:"internal-error"}` line when an instance resolves.
- `verify`'s six child spawns are each logged as a `process-start`/`process-exit` pair at the call site: the `--version` read as `version-probe`, the print-mode probe as `verify-probe`, and each of the four interactive PTY runs as `verify-pty-probe` (obs-plan §6). `run_bounded` itself stays unlogged, because `run`'s version gate shares it and logs its own pair.
- `hook <event> --capture <DIR>` (hidden) is `verify`'s capture arm: no `VIOLA_*`, no obs init, no channel, raw 0600 write, exit 0 always.
- `plugin.json`'s version comes from `CARGO_PKG_VERSION`; the content hash in `bin/`/`plugin/` keys dev rebuilds (a hook fix applies only to sessions started after the rebuild).

## Entry points for modification
- **Dispatch:** `src/main.rs`, `src/cmd/<subcommand>.rs`
- **Wrapper:** `src/run/` (pump, wheel, governor, gate wiring; `gate.rs` the bounded feed + `Gate`; `send.rs` the `send` method, one in flight, the driver relabel, the hook-event append; `wait.rs` the `WaitFeed` — the append under its lock, the Condvar wake, the newest turn and its start rebuild (which also returns the highest `dialog_id`), `appending_dialog` / `dialog_settled` — and the `wait` / `last` methods; `dialog.rs` the `DialogSlot` — the `hook.dialog` and `answer` methods, one pending dialog, the Condvar await on the injected clock up to `DIALOG_DEADLINE`, the per-tool armed continuation matched on equal `tool_input`; `wheel.rs` the `WheelSlot` — holder + cause under one lock, the synchronous in-memory move, the record worker (the `wheel` event, the snapshot, `run.wheel_transition`, the pending-dialog hand-back) flushed ≤ 2 s at exit before the terminal leaves raw mode, the stdin observer `Observed` and the F-W2 `Classifier`, and the `pause` / `release` methods; `snapshot.rs` the `Snapshots` holder every snapshot write goes through)
- **Wheel verbs:** `src/cmd/pause.rs`, `src/cmd/release.rs` (`viola pause|release <name> [--json]`: the liveness-only `live_endpoint` (exit 21), one request with `from` from `VIOLA_NAME`; exits 0/1/20/21; a driver session's `release` is refused `release-from-driver`, exit 20; `write_paused` / `write_released` in `src/human.rs`)
- **Answer verb:** `src/cmd/answer.rs` (`viola answer <name> <dialog_id> [--file] [--json]`: the response from stdin / `--file` into the closed enums, `validate_paste_text` first (exit 13), the liveness-only `live_endpoint` (exit 21), one `answer` request; exits 0/1/2/12/13/20/21; `write_answered` / `answer_hint` in `src/human.rs`); the dialog hooks `viola hook pre-tool-use|permission-request` read their reply under `DIALOG_DEADLINE + 5 s` and write stdout once
- **Send verb:** `src/cmd/send.rs` (stdin / `--file` under `take(MAX_FRAME + 1)`, client paste check, the liveness pre-check, the readback mirror via `src/human.rs`, `--json`)
- **Wait / last verbs:** `src/cmd/wait.rs`, `src/cmd/last.rs` over `src/cmd/client.rs` (the plumbing the three client verbs share: the `cli` obs start, the liveness-only endpoint, the reply shapes, exit 20 / exit 21 — the latter at WARN); human lines and the message-mode escaper in `src/human.rs`
- **Obs init / panic hook / detail writer:** `viola::obs`
- **Verify / version gate / panic frames:** `src/cmd/verify.rs`, `src/run/version_gate.rs`, `src/panic_frames.rs`
- **Fake agent:** `src/bin/viola-fake-agent.rs` (incl. the `-p/--print` mode `verify` drives)
- **Tests:** inline unit tests (exit-code mapping, wheel state machine, thresholds, confirmation matcher, `wait` handler with an injected clock, refusal order); root `tests/{cli,hook,tui,channel,chaos,contract}_*.rs`

## Testing this crate
- **Unit tests:** `cargo nextest run -p viola`
- **Integration / E2E:** `scripts/agent-run.sh run --integration` / `--e2e`
- **Perf:** `scripts/agent-run.sh run --perf` then `gate --require perf` (hyperfine over the real `target/perf` `viola hook` per row, `max <` `viola_core::SPINE_DEADLINE` (1.0 s); the per-OS CI `perf` job)
- **Forced panic:** the `fake-agent` seam `src/cmd/hook/seam.rs` (`FAKE_AGENT_HOOK_PANIC=1`) drives `hook_fail_open.rs`'s forced-panic and over-4 KiB concurrent cases
